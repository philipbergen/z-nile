# d0405: Busy read keeps pass

## Problem
- A busy answer from `Wallet` (`arcade/src/server/Wallet.luau`) always clears the pass allowance, so a PLAY that is still busy after the portal's 10-second wait (`Play.CHECK_SECONDS`) writes no pass, and a player with nothing to pay with is teleported to the game place and sent back without being offered the purchase.

## Non-goals
- A busy answer given while the read in progress is not late (its store call has run for less than `Wallet.WAIT_SECONDS`, 5 seconds) still clears the pass allowance as today, so `arcade/tests/place/wallet-order.spec.luau:291` and `arcade/tests/acceptance/f0201/wallet.spec.luau:1029` keep passing.

## Solution
- A busy answer keeps the pass allowance when the read in progress for that player and title is late, meaning its store call was not back within `Wallet.WAIT_SECONDS` (5 seconds, the Wallet's own late flag), so a PLAY pressed during a slow store call ends with a pass written or the purchase offered.

## Design
### Short note
- Problem: In `arcade/src/server/Wallet.luau`, `Wallet.read` sets `slot.mayPass = false` unconditionally whenever `slot.reading` is true (`busy`). When an earlier read timed out past `Wallet.WAIT_SECONDS` (5 s), it set `late = true` (local to the read call) and `slot.mayPass = true`, returning `"down"`. Any subsequent read before the slow store call returns gets `"busy"` and clears `slot.mayPass`, preventing `Wallet.pass` from writing the portal pass.
- Change: Track `late: boolean` on `Slot` (default `false`, reset to `false` at read start and read completion, set to `true` when `within(Wallet.WAIT_SECONDS, ...)` times out). In `Wallet.read`'s `if slot.reading then` branch, only clear `slot.mayPass = false` when `not slot.late`. When `slot.reading` is true and `slot.late` is false, `slot.mayPass` is still cleared as today.
- Files: `arcade/src/server/Wallet.luau`, `arcade/tests/place/wallet-order.spec.luau`
- Test: `tests/place/wallet-order.spec.luau`
- Risk: Low. Only changes `slot.mayPass` preservation during an already-late in-flight read; non-late busy reads still clear `slot.mayPass` (`wallet-order.spec.luau:291` and `f0201/wallet.spec.luau:1029` stay green). When the late read eventually finishes, `slot.late` and `slot.reading` both reset to `false` and `slot.downUntil` is set.
