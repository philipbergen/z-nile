# f0199: Shared travel

## Problem
The user, 2026-10-31: "I want to branch out into multiple games, they will each have their own directory in the project: first person snake, first person asteroids. I also want a new project for a landing portal where you can scroll between the games and see the highscores for each, the same cost model remains but it shoudl show 5 robux for each game witha slash through showing it is currently on sale for 1 robux. highscores shoudl show how many revives were used. I want you to design a full fun playable game for both of those two new game ideas. I also want both snake and asteroids to be a two player game, snakes can even be n-player up to a high number just make the wold bigger. Snakes should have maps that once you have reached a certain length the game ends and we move to a new map, the first is empty, then one wall somewhere in the middle, then two, then three and so on. The walls can be vertical and horizontal but do not connect. for asteroids we could have a two player version where each player is attacking the aliens from opposing sides. You can shoot each other's barriers. the aliens would then come in from the side and and split into two groups that move toward either player". Then: "Add a third game first person asteroids." Decided with the user (2026-10-31): the 2-player aliens game is pure Space Invaders (`invaders`); Asteroids is its own game (`asteroids`); one Roblox experience with the portal as start place, replacing pickman's lobby; every board shows revives used; one free game per hour per game.

The approved design is `arcade/.tracker/architecture.md` (c0183). This issue owns these parts of it, as they are said there: **Technical skeleton**, "What moves into arcade", item 2 (Travel), and from **Places and publishing** the place-id attributes every place reads. The rest of it belongs to other issues (c0190's ownership table), listed under Non-goals.

What should happen:
- Travel (teleport request, timeout, cool-down, place-id checks; pickman's `Logic/Travel`) moves into arcade so every place teleports by the same rules, to and from the portal.
- A place learns every other place's id from attributes (`PortalPlaceId`, `PickmanPlaceId`, `SnakePlaceId`, `InvadersPlaceId`, `AsteroidsPlaceId`; 0 means not published).

Each place keeps its own thin adapter that wires arcade's Travel in, as pickman's do; testing a shared one would first need `fakeengine` in the shared harness (arcade-test skill). A later issue may capture it.

## Solution
Pickman's `Logic/Travel` is copied, unchanged in every line, to `arcade/src/shared/Logic/Travel` with its specs (the copy-then-switch rule of `arcade/.tracker/architecture.md`). The experience's place list and the one pure read of the place-id attributes go beside it in a shared config module, `arcade/src/shared/Places.luau` (`Places.read(read)`), so every place's adapter learns every place's id the same way while Travel stays a leaf that names no game. No adapter changes here: c0200 switches pickman, f0187 moves pickman to `PortalPlaceId`, and the portal and the new games wire it in their own issues.

## Design
Decisions relied on (`arcade/.tracker/architecture.md`, binding): "Game Logic never requires arcade Logic. Arcade features are leaves that adapters wire in, and game Logic gets them as parameters (an RNG, a store, a travel status)"; "Every place gets every place id as an attribute (`PortalPlaceId`, `PickmanPlaceId`, `SnakePlaceId`, `InvadersPlaceId`, `AsteroidsPlaceId`; 0 means not published, and the portal shows that card as "coming soon")"; "Pickman migrates one feature at a time: an arcade issue copies the feature and its specs, then a pickman issue switches the adapters and deletes the old copy"; and the experience decision "One Roblox experience. The portal is the start place … Pickman, Snake, Invaders and Asteroids are places in it." From arcade-arch: rule 1, "A library feature is a leaf. It knows no game"; rule 2, "Per-game differences are parameters, never a branch on a game's name"; and the Layout row for `src/shared/` outside Logic, "shared adapters: types, config tables. ModuleScripts only". No product decision in `pickman/.tracker/game-design.md` or any game's is touched: this is library code no player sees until an adapter uses it.

**Part 1, the feature: `arcade/src/shared/Logic/Travel/init.luau` is `pickman/src/shared/Logic/Travel/init.luau` byte for byte** (a feature directory, `--!strict`, pure: no engine words, time as `now`). It maps to `ReplicatedStorage.Arcade.Logic.Travel`, so adapters require it as `@game/ReplicatedStorage/Arcade/Logic/Travel` and Lune specs as `@logic/Travel` from arcade's home (`@arcade/Logic/Travel` from any other home). It is shared, not under `src/server`, because a client screen reads its `Phase` type (pickman's `LobbyView` does today) and it holds nothing secret. It requires nothing and names no place: the place list is part 2's. The public API stays exactly:
```luau
export type Phase = "idle" | "going" | "cooling"
export type Config = { goingSeconds: number, coolSeconds: number, capSeconds: number }
export type Entry = { phase: Phase, deadline: number, cap: number, ticket: number }
export type Travel = { config: Config, entries: { [string]: Entry }, serial: number }
export type Answer = "go" | "busy" | "cooling"
Travel.DEFAULT: Config            -- frozen { goingSeconds = 15, coolSeconds = 3, capSeconds = 60 }
Travel.MAX_PLACE_ID: number       -- 2^53 - 1
Travel.new(config: Config?): Travel
Travel.destination(raw: any): number?        -- a whole place id 1..MAX_PLACE_ID from a number or digits, else nil
Travel.status(t: Travel, id: string, now: number): Phase
Travel.request(t: Travel, id: string, now: number): (Answer, number?)   -- "go" with a ticket
Travel.answered(t: Travel, id: string, now: number, ticket: number?)
Travel.failed(t: Travel, id: string, now: number, ticket: number?)
Travel.left(t: Travel, id: string)
```
The rules (f0061 and f0065, unchanged): one request per player at a time; while the engine call has not returned the player stays `going` up to the 60 s cap; once it returns without an error the timeout counts 15 s from then, never past the cap; a timeout seen at `now` cools down for 3 s from `now`; a reported failure cools down 3 s from the report; a report for a player who is not going, a late one, or one naming an older ticket changes nothing, and a report with no ticket applies to the current request; a player who leaves is forgotten; players are separate; the times come from the config given.

**Part 2, the places: `arcade/src/shared/Places.luau`**, a `--!strict` ModuleScript at `ReplicatedStorage.Arcade.Places` (a config module outside Logic, per the Layout row above; `@game/ReplicatedStorage/Arcade/Places` from an adapter, `@shared/Places` from arcade's specs, `@arcade/Places` from another home's). It is pure (no engine access; the read is passed in) and its one require is `require("./Logic/Travel")`, which resolves on disk to `src/shared/Logic/Travel/init.luau` and in the instance tree from `Arcade.Places` to `Arcade.Logic.Travel` (AC3 proves both). A module outside Logic may require a feature through its `init` (pickman-arch rule 4); no Logic requires `Places`, so no feature gains a dependency.
```luau
export type Name = "Portal" | "Pickman" | "Snake" | "Invaders" | "Asteroids"
-- a published place's id under its name; a place that is not published is nil
export type Ids = { Portal: number?, Pickman: number?, Snake: number?, Invaders: number?, Asteroids: number? }
Places.NAMES: { Name }                  -- frozen: { "Portal", "Pickman", "Snake", "Invaders", "Asteroids" }
Places.attribute(name: Name): string    -- name .. "PlaceId"; raises `Places.attribute: "<name>" is not a place` (level 2) otherwise
Places.read(read: (attribute: string) -> any): Ids
```
`Places.read` calls `read` once for each name of `NAMES`, in order, with its attribute name and nothing else, passes each value through `Travel.destination` (so 0, a missing attribute, `"0"`, a fraction, text, `"0x10"`, `" 7"`, `"1e3"`, 2^53 and above, NaN, infinity or any other type all mean not published, and digits are accepted as the publisher's number would be), and returns a new frozen table holding only the published ids. An adapter calls it once at boot:
```luau
local Places = require("@game/ReplicatedStorage/Arcade/Places")
local ids = Places.read(function(name) return ServerScriptService:GetAttribute(name) end)
local destination = ids.Portal -- nil: not published, the button says so (pickman's `configured` flag)
```
The attributes live on `ServerScriptService`, where the publisher writes them today (`pickman/scripts/lib/beta.luau`, `Beta.project`) and c0210 keeps writing them: server-only, since `ServerScriptService` never replicates, and the destination is never something a client sends (pickman's adapters already say so). Recorded in `arcade/.tracker/architecture.md`, Places and publishing, by this prep.

Implementation notes the prototype settled (see E2): `Ids` is a record of optional fields, not `{ [Name]: number }` (strict Luau rejects `ids.Portal` on a singleton-union indexer); `NAMES` is a typed local `local NAMES: { Name } = {…}` frozen into `Places.NAMES`, and both loops iterate the local (`table.freeze({…} :: { Name })` and iterating the frozen copy both widen the names to `string`); the attribute spelling is one private `attributeOf(name)` used by `Places.attribute` and `Places.read`; the built table is `{ [string]: number }`, returned as `table.freeze(out) :: any`; stylua writes `Ids` one field per line.

### Scalability
Per player: one `Entry` (four numbers) while a request or a cool-down is live, removed on `left` or when the cool-down ends; per server one `serial`. `status` and `request` are O(1); the adapter's once-a-second status sweep is O(players). `Places.read` is five attribute reads at boot, no DataStore request (E3's budget is untouched) and nothing replicated (the ids stay on the server; a client learns only whether its button's destination is configured, as today). The library place gains two ModuleScripts replicated with `ReplicatedStorage.Arcade`, about 4 KB and 2 KB of source, once per client join.

### Maintainability
A new game uses Travel without a change to it: its adapter calls `Travel.new`, `Travel.request` and the reports, and reads its destinations from `Places.read`. Travel names no game (AC3 pins it), so rule 1 holds without an exception; the one module that names the games is the config module `Places.luau`, data and never branched on (no code indexes a place by a literal except the adapter that wants that destination). Adding a sixth place is three edits in that one module (a name in `Name`, a field in `Ids`, an entry in `NAMES`) plus c0210's manifest entry, and it deliberately turns this issue's promoted `arcade/tests/acceptance/f0199/places.spec.luau` red (it pins the five names, their attributes and five ids), so the issue that adds the place carries an `Overrides:` line for it and its chore. Per-place differences (which destination, which remote) stay parameters the adapter passes, per arcade-arch rule 2. The rules have one home after c0200 deletes pickman's copy; until then the two copies must be changed together (Interfaces, c0200).

### Usability
Developer API: the copy keeps pickman's names and signatures, so c0200's switch is a require path; `Places.read` is one call returning typed optional fields (`ids.Portal: number?`), so a not-published place is a nil the type checker makes the caller handle; a misspelled place name is a type error, and at runtime `Places.attribute` raises naming it rather than reading an attribute nobody writes. Player-facing behaviour is unchanged: the same 15 s, 60 s and 3 s waits players have in pickman today, now the same in every place.

### Edge cases
- Not published (attribute 0 or missing, as every checked-in project file has it): the place is absent from the answer, and the adapter shows the destination as not configured (pickman's behaviour).
- Every value is checked by `Travel.destination`, for every place: negatives, fractions, NaN, infinity, 2^53 and above (as numbers or digits), `"0x10"`, `"1e3"`, `" 7"`, `"-5"`, `"12a"`, `""`, non-ASCII digits, booleans and tables are not ids; 1, digits and 2^53 − 1 are.
- Simultaneous reports: a late failure or answer for an older ticket is ignored; a ticketless engine report (`TeleportInitFailed`) applies to the current request.
- A player who leaves mid-request: `left` forgets them, and a later report finds nobody going.
- Frame-rate independence: Travel never counts frames; it reads `now`, so a slow heartbeat only delays when a timeout is seen (at most the sweep interval), and the cool-down counts from when it was seen.
- Reading twice (a place re-reads after the publisher changed an attribute): each call returns a fresh frozen table, so an answer once handed out never changes under its holder.
