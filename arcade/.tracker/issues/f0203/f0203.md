## Problem
The user, 2026-10-31: "I want to branch out into multiple games, they will each have their own directory in the project: first person snake, first person asteroids. I also want a new project for a landing portal where you can scroll between the games and see the highscores for each, the same cost model remains but it shoudl show 5 robux for each game witha slash through showing it is currently on sale for 1 robux. highscores shoudl show how many revives were used. The walls can be vertical and horizontal but do not connect. for asteroids we could have a two player version where each player is attacking the aliens from opposing sides. You can shoot each other's barriers. the aliens would then come in from the side and and split into two groups that move toward either player". Then: "Add a third game first person asteroids." Decided with the user (2026-10-31): the 2-player aliens game is pure Space Invaders (`invaders`); Asteroids is its own game (`asteroids`); one Roblox experience with the portal as start place, replacing pickman's lobby; every board shows revives used; one free game per hour per game.

The approved design is `arcade/.tracker/architecture.md` (c0183). This issue owns these parts of it, as they are said there: **Technical skeleton**, "What moves into arcade", items 4 to 6 (Rng, the Pad and Touch cores, first-person Look). The rest of it belongs to other issues (c0190's ownership table), listed under Non-goals.

What should happen:
- The game-neutral parts of input and first-person look move into arcade: a seeded Rng, the gamepad fold (Pad), the touch zones and swipes (Touch), and first-person free look and smoothing (Look).
- Every game supports keyboard, gamepad and touch for every feature (pickman's rule, f0146), from these cores; each game keeps its own key map.

## Non-goals
- Each game's key map and controls: f0213, f0218 and f0222.
- Pickman switching to them: c0204 (Switch to arcade input cores).
- The Session clock and intent limiter (they move only when Snake needs them: f0212).
- The rest of `arcade/.tracker/architecture.md`: f0197, c0198, f0199, c0200, f0201, c0202, c0204, f0206, f0209, c0210, f0212, f0218, f0222, and c0184 and c0185 (the library's layout, wiring, gate and paths).

## Solution
<!-- The approach in one paragraph. -->
Four new leaf features in the library, `arcade/src/shared/Logic/{Rng,Pad,Touch,Look}`, each a pure fold or function set copied from pickman's game-neutral input and look code (Ghosts' `Rng`, `Pad`, `Touch`, and the look half of `View`) and generalised: every per-game difference (a key map, a button layout, a stream, a tuning) becomes a parameter, and every pickman-specific word (Maze headings, `View.Action`, HUD rectangles) leaves. Pickman keeps its own copies until c0204 switches it; Snake, Invaders and Asteroids build their controls from these from the start (f0213, f0218, f0222). Nothing here has an adapter: arcade has no `src/client/`, and each game's adapters read the engine and call these.

### Rng (`arcade/src/shared/Logic/Rng/init.luau`)
```luau
export type Stream = { multiplier: number, mix: number, offset: number }
export type Generator = { state: number, multiplier: number } -- plain data: two numbers
export type Draw = (n: number) -> number
Rng.MODULUS: number -- 2147483647
Rng.STREAM: Stream -- frozen { multiplier = 48271, mix = 1, offset = 0 } (minimal standard)
Rng.new(seed: number, stream: Stream?): Generator
Rng.int(g: Generator, n: number): number -- advances g, then 1..n
Rng.float(g: Generator): number -- advances g, then [0, 1)
Rng.draw(g: Generator): Draw -- a function drawing Rng.int(g, n) from the same g
```
- **Seeding**: `s = math.floor(seed)`, or 0 when the seed is not a finite number; then `s = s % (MODULUS - 1)` **before** mixing, so a large seed never loses precision; `state = (s * mix + offset) % (MODULUS - 1) + 1`, always a whole number in 1..MODULUS-1.
- **Stepping**: `state = state * multiplier % MODULUS`; `int` returns `state % n + 1`, `float` returns `(state - 1) / (MODULUS - 1)`. The state is never 0 (MODULUS is prime and the multiplier below it).
- **Refusals** (errors naming the function): `int` with an `n` that is not a whole number of at least 1; `new` with a multiplier outside 2..2^21-1 (so `state * multiplier` stays below 2^52, exact in a double), a mix outside 0..2^21-1, or an offset that is not whole or is not below the modulus in size.
- **Pickman's streams are parameters**: Ghosts' `{16807, 1, 0}`, Picks' `{48271, 69621, 7}`, Blaster's `{16807, 48271, 11}` reproduce today's generators exactly for every seed below about 1.29e11 (E1; pickman seeds with `player.UserId`), so c0204 can switch with no behaviour change. Above that, pickman's Picks product loses precision and arcade's stays exact: c0204's to note.
- **How game Logic uses it**: it never requires arcade. A game's Logic takes a `Draw` (declaring the same function type locally) or a seed; its adapter or the server's session builds the generator (`Rng.new(seed, stream)`) and passes `Rng.draw(g)` in. A game that must snapshot its random state keeps the `Generator` table (plain data) in its state and is handed a draw over it.

### Pad (`arcade/src/shared/Logic/Pad/init.luau`)
```luau
export type Dir = "up" | "down" | "left" | "right"
export type Axes = "both" | "horizontal"
export type Steer = { held: Dir? }
export type Tuning = { on: number, off: number, margin: number, axes: Axes,
	lookDead: number, lookYaw: number, lookPitch: number, invert: boolean }
export type Partial = { on: number?, off: number?, margin: number?, axes: Axes?,
	lookDead: number?, lookYaw: number?, lookPitch: number?, invert: boolean? }
Pad.DEFAULT: Tuning -- frozen { on = 0.6, off = 0.4, margin = 15, axes = "both", lookDead = 0.15, lookYaw = 3, lookPitch = 2, invert = false }
Pad.tune(over: Partial?): Tuning -- DEFAULT with `over` laid on, checked, frozen
Pad.isPad(inputType: string): boolean -- "Gamepad1".."Gamepad8"
Pad.track(active: string?, inputType: string, magnitude: number, tuning: Tuning?): string?
Pad.steerStart(): Steer
Pad.steer(s: Steer, x: number, y: number, tuning: Tuning?): (Steer, Dir?)
Pad.look(x: number, y: number, dt: number, tuning: Tuning?): (number, number) -- dyaw, dpitch in radians
```
- **No button map**: pickman's `Pad.BUTTONS`, `Pad.action` and `Pad.CONTINUE` stay pickman's. The cores return directions; each game maps them (pickman: up `Forward`, down `Back`; Snake: left and right turn; Invaders and Asteroids: `Steer.held` is the held move or rotate).
- **`steer`, `"both"`**: pickman's fold, with `Dir` for `Movement.Intent`: released, a tilt `r >= on` engages the dominant axis' sector (a tie goes vertical) and sends it; engaged, `r < off` releases (nothing sent), and with `r >= on` another sector is sent only when the tilt is more than `45 + margin` degrees (plus 1e-9) from the held sector's axis; anything else keeps the sector and sends nothing. A reading that is not finite releases.
- **`steer`, `"horizontal"`** (new, for Snake, Invaders and Asteroids, whose sticks only turn, move or rotate sideways): the fold reads `|x|` alone: released, `|x| >= on` engages `"left"` or `"right"` by its sign; engaged, `|x| < off` releases; `|x| >= on` on the other side changes at once (there is no diagonal between opposites). Up and down are never sent.
- **`look`**: pickman's response, in radians instead of View's mouse pixels: `r < lookDead` (or a non-finite reading, or `dt` not a positive finite number) gives 0, 0; else `a = ((min(r,1) - lookDead) / (1 - lookDead))^2`, `dyaw = -a * (x/r) * lookYaw * dt` (right turns right: negative yaw), `dpitch = a * (y/r) * lookPitch * dt` (up looks up), negated when `invert`. It feeds `Look.turn`. Pickman's `Pad.look` returns `dx/k`, which `View.look` multiplies back by `k`; the two agree to rounding (c0204 compares with a tolerance).
- **`track`**: a gamepad input of finite `magnitude >= tuning.off` takes over; any other input keeps `active`.
- **`tune`** refuses (error starting `Pad.tune`): unless `0 < off < on <= 1`; a margin outside 0..45 (exclusive of 45); axes other than the two; `lookDead` outside 0..1 (exclusive of 1); a negative or non-finite look rate; a non-boolean invert.

### Touch (`arcade/src/shared/Logic/Touch/init.luau`)
```luau
export type Rect = { x: number, y: number, w: number, h: number } -- half-open
export type Use = "swipe" | "look" | "none"
export type Side = "left" | "right"
export type Button = { name: string, rect: Rect }
export type Context = { width: number, buttons: { Button }, left: Use, right: Use }
export type Phase = "begin" | "move" | "end"
export type Event = { id: number, phase: Phase, x: number, y: number }
export type Dir = "up" | "down" | "left" | "right"
export type Finger = { button: string?, side: Side?, use: Use, x0: number, y0: number, x: number, y: number }
export type State = { fingers: { [number]: Finger } }
export type Effect = { kind: "press", name: string } | { kind: "release", name: string }
	| { kind: "swipe", dir: Dir } | { kind: "look", dx: number, dy: number }
export type Area = { Min: { X: number, Y: number }, Max: { X: number, Y: number } }
Touch.MIN_SWIPE = 48; Touch.AXIS_DEGREES = 30; Touch.MIN_TARGET = 44
Touch.empty(): State
Touch.inside(r: Rect?, x: number, y: number): boolean
Touch.zone(ctx: Context, x: number, y: number): (string?, Side, Use) -- button name (nil off buttons), the half, its use
Touch.swipe(dx: number, dy: number): Dir?
Touch.track(state: State, event: Event, ctx: Context): (State, { Effect }) -- never changes `state`
Touch.reset(state: State): (State, { Effect })
Touch.toScreen(none: Area?, x: number, y: number): (number, number)
Touch.screenSize(none: Area?, fallbackW: number, fallbackH: number): (number, number)
```
- **Zones**: a finger is classified once, on `begin`: the first button in `ctx.buttons` whose rectangle holds the point; else the left half (`x < width / 2`, with a positive finite width) or the right half (every other point), used as `ctx.left` or `ctx.right` says. A finger on a half used for `"none"` is not tracked. One finger holds a zone: a second finger on the same button, or on the same half off the buttons, is not tracked.
- **Effects**: a button finger sends `press` on begin and `release` on end (so a game can treat a button as a tap or as held: Invaders' and Asteroids' LEFT, RIGHT, ROTATE and THRUST are held); a look finger sends `look` (`dx`, `dy` since its last point) on each move; a swipe finger sends one `swipe` on end, from its begin point to its end point, by pickman's rule (at least `MIN_SWIPE` long, within `AXIS_DEGREES` of an axis, plus 1e-9; screen-down is `"down"`). A finger keeps its zone after the context changes, so its end always releases.
- **Bad input**: a `begin` or `move` at a point that is not finite is dropped; an `end` always lifts its finger (a button's `release` is sent; a swipe is not). A begin for an id already down, and a move or end for an unknown id, change nothing.
- **`reset`**: every finger lifted at once (the screen goes away, the player respawns or leaves): a `release` for each held button, in ascending finger id, no swipes, and an empty state.
- **Kept generic from pickman**: `toScreen` and `screenSize` (the GUI inset arithmetic). **Left in pickman**: `blocks`, `snapRect`, `hopRect`, `fireRect`, `pickRect`, `buttons` (its HUD layout) and the pickman zone names. A game's adapter places its own buttons (at least `MIN_TARGET` a side) and builds the `Context`.

### Look (`arcade/src/shared/Logic/Look/init.luau`)
```luau
export type Look = { yaw: number, pitch: number } -- radians from the heading; yaw positive left, pitch positive up
export type Arrows = { up: boolean, down: boolean, left: boolean, right: boolean }
export type Dir = "up" | "down" | "left" | "right"
export type Spring = { look: Look, spring: boolean }
export type Tuning = { radiansPerPixel: number, maxPitch: number, turnSeconds: number }
export type Partial = { radiansPerPixel: number?, maxPitch: number?, turnSeconds: number? }
Look.DEFAULT: Tuning -- frozen { radiansPerPixel = 0.004, maxPitch = math.rad(80), turnSeconds = 0.12 }
Look.tune(over: Partial?): Tuning
Look.wrap(a: number): number -- (-pi, pi]
Look.approach(current: number, target: number, maxDelta: number): number
Look.rate(tuning: Tuning?): number -- (pi/2) / turnSeconds
Look.ease(current: number?, target: number, dt: number, tuning: Tuning?): number
Look.mouse(l: Look, dx: number, dy: number, tuning: Tuning?): Look
Look.turn(l: Look, dyaw: number, dpitch: number, tuning: Tuning?): Look
Look.snap(): Look; Look.rest(): Spring; Look.arrows(): Arrows
Look.press(a: Arrows, dir: Dir?, down: boolean): Arrows
Look.quarters(a: Arrows): number?
Look.spring(prev: Spring, look: Look, a: Arrows, dt: number, tuning: Tuning?): Spring
Look.alpha(elapsed: number, rate: number): number
Look.blend(from: number, to: number, alpha: number): number
Look.blendYaw(from: number, to: number, alpha: number): number
```
- From pickman's `View`: `wrap`, `approach` (`approachYaw`), `rate` (`turnRate`), `mouse` (`look`), `snap`, `press`, `quarters` (`arrowQuarters`) and `spring` (`steer`), with the same rules, `Dir` for View's look actions and the tuning for View's constants. `View.aim`, `View.headingYaw` and everything maze-shaped stay pickman's.
- **New**: `turn` (radians, for `Pad.look`); `ease` (the eased turn: `approach(current, target, rate * dt)`, the target when there is no yaw yet; the camera code pickman has in `Camera.luau`); `alpha`, `blend`, `blendYaw` (snapshot smoothing: `alpha = clamp(elapsed * rate, 0, 1)`, not a number gives 1; `blendYaw` goes the short way round, for Asteroids' turning ship and Snake's eased head).
- **Frame-rate independence**: every rate is per second times `dt`; a `dt` that is not a positive finite number moves nothing. A mouse step or turn that is not finite leaves the look as it was (pickman's `View.look` would carry the NaN).
- **`tune`** refuses (error starting `Look.tune`): a `radiansPerPixel` not above 0, a `maxPitch` outside (0, pi/2], a `turnSeconds` not above 0, or any non-finite value.

### Every game on every input (the capture's second outcome)
The capture asks that "every game supports keyboard, gamepad and touch for every feature (pickman's rule, f0146), from these cores; each game keeps its own key map". Each game's controls are its own issue (f0213, f0218, f0222; pickman's exist), so this issue delivers the cores those controls are built from, proves they are enough, and writes the rule where those issues read it:
- **Keyboard**: a key is the game's own map from a key name to an intent (no core is needed, and none holds a key map); the arrow keys' look and spring-back are `Look.press`, `Look.quarters` and `Look.spring`.
- **Gamepad**: the buttons are the game's own map; the stick is `Pad.steer` (one direction a push, or `Steer.held` for a held move or rotate, on `"both"` or `"horizontal"` axes); the look stick is `Pad.look` into `Look.turn`; the driving controller is `Pad.track`.
- **Touch**: every touch control is a named `Touch.Button` (pressed and released, so it can be tapped or held), and each screen half swipes, looks or does nothing (`Touch.Context`).
- **The proof** (AC5, `games.spec`): for pickman, Snake, Invaders and Asteroids, every touch button and half, stick use, look stick and arrow look that each game's design names is driven through the cores and gives the effect the game needs. The cores hold no key or button names (AC5's last case).
- **The rule**, added to `arcade/.tracker/architecture.md` by the executor (implementation step 5; prep leaves the file alone so the prep PR stays inside the issue's folder), before `## Allowed dependencies`: a level-2 heading "Input and look cores (f0203)", then this body, verbatim:

```markdown
Four leaf features in `src/shared/Logic/`, with no dependency on each other or on any game: **Rng** (a seeded Park-Miller generator; the generator is plain data, a `Stream` of multiplier, mix and offset picks its sequence, and `Rng.draw` hands game Logic a `(n) -> number` it can take as a parameter without requiring arcade), **Pad** (the gamepad's generic folds: the stick's sector fold with hysteresis in tilt and angle, `"both"` or `"horizontal"` axes, the look stick's rate in radians, and the driving controller), **Touch** (a fold over finger events into named-button presses and releases, swipes and look steps, with each screen half used for swipes, looking or nothing) and **Look** (free look, the arrows' look and spring-back, the eased turn, and snapshot blending, in radians: yaw positive left, pitch positive up). Each takes its tuning as a parameter (`Pad.tune`, `Look.tune`; the defaults are pickman's accepted values, f0146 and f0104).
- **Every game builds its input from these cores**, and every action it has gets a key, a gamepad input and a touch control (pickman's rule, f0146). The cores hold no key map: each game's adapters keep their own (the key names, the button names, which touch buttons exist and where), and map the cores' directions (`"up" | "down" | "left" | "right"`) and button names onto the game's own intents.
- Game Logic never requires them (Technical skeleton): an adapter folds the input and sends intents, and a game's Logic that needs randomness takes an `Rng.draw` function, or keeps its own state and is passed a draw.
```

### The split and authority
All four are pure Logic: no engine word, time and input come in as parameters, and their results are numbers, directions and names. There is no adapter in this issue: arcade has no `src/client/`, and every game's own client adapters (pickman's `Camera`, `Pads`, `Sticks`, `Controls`; f0213's, f0218's and f0222's) read `UserInputService`, call these folds and send intents. The server stays authoritative: these cores only shape what a client asks for, and `Rng` runs wherever the rules run (the server, for every game here).

### Edge cases
- Empty input: `Touch.empty()`, `Pad.steerStart()`, `Look.rest()` and `Look.arrows()` are the starting values; `Look.ease(nil, ...)` starts at the target; `Look.quarters` of no arrows is nil.
- Bounds: `Rng.int` 1..n, `Rng.float` [0, 1), the state 1..MODULUS-1; pitch within ±maxPitch; angles in (-pi, pi]; blends clamped to 0..1; stick tilts above 1 count as 1 for the look.
- Simultaneous events: one finger per zone; several fingers on different zones at once each send their own effects, in event order.
- A player who leaves or respawns: `Touch.reset` releases every held button; `Pad.steerStart()` and `Look.rest()` restart the folds.
- Frame-rate independence: specs show two half frames equal one frame for `Pad.look`, `Look.ease` and `Look.spring`.

### Scalability
Per frame, one client runs at most one `Pad.steer` and one `Pad.look` (O(1)), one `Look.spring` and one `Look.ease` (O(1)), and one `Touch.track` per touch event (O(buttons + fingers), both under 10). `Rng.int` is one multiply and two modulos. Nothing here replicates: the cores run inside one client's or the server's Lua state, and make no DataStore request. A 24-player Snake arena costs the server one `Rng` call per placement roll, nothing per player per frame.

### Maintainability
A new game uses the cores without changing them: its own button names and rectangles in a `Touch.Context`, its own `Pad.tune({...})` and `Look.tune({...})`, its own map from `Dir` and button names to its intents, and its own `Rng.Stream` if it wants a separate sequence. A behaviour a game needs that a tuning cannot express (another fold, a tuning field) is a change to the core and its specs, made in that game's design, not a branch on a game's name. `MIN_SWIPE` and `AXIS_DEGREES` stay constants until a game needs another value; then they move into a tuning the same way.

### Usability
- For the player: pickman's accepted feel is the default everywhere (the 0.6/0.4 stick with its 15° margin, the squared look response, the 48 px swipe, the 0.12 s quarter turn), so the four games feel alike; touch buttons can be held (press, release), which Invaders' and Asteroids' movement needs.
- For the developer: four small modules, typed in and out, with string-literal unions for every choice (`Dir`, `Use`, `Axes`); tunings are checked once in `tune` and frozen; every fold returns a new state and never changes the one it was given (Touch, Pad, Look); a misuse (`Rng.int(g, 0)`, an impossible tuning) is an error with the function's name, not a NaN later.

## Acceptance criteria

### Checked
- AC1: Rng draws a seeded, plain-data sequence; a stream picks it, exactly (`rng.spec`).

- AC3: Touch folds fingers into button presses and releases, swipes and look steps, one finger a zone (`touch.spec`).

- AC7: the library place holds the four cores as ModuleScripts under ReplicatedStorage.Arcade.Logic, and its requires resolve (`place.spec`, `tests/place/library.spec`).
