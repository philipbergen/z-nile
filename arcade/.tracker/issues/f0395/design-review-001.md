### F1 [high] AC1's escaping case passes an escaper that replaces only the first `&`, `<` and `>` of each text
Where: `acceptance/lines.spec.luau:61-85` (case "every text in a line shows as it is…"); Design §1 "Every text is shown as it is"; AC1 "every text in a line has `&`, `<` and `>` as entities"; Rules and mutants rows Y7–Y12.
Evidence: every hostile text the case uses holds each special character at most once: `"A<B>&C"`, `"<5 & 6>"`, `"&1"`, `"S>"`, `"<r&>"`, `"&lt;"`. On a fresh clone of the prototype I replaced `plain`'s body with `string.gsub(string.gsub(string.gsub(text, "&", "&amp;", 1), "<", "&lt;", 1), ">", "&gt;", 1)` (each escape stops after its first match). Result: `lines.spec.luau: 5 passed, 0 failed`, `client.spec.luau: 2 passed, 0 failed`. A title or price word such as `"R&D & CO"` or `"<<NEW>>"` would then reach a `RichText` label with a raw `&` or `<`, which is the defect §1 says cannot happen. A hand-written escaper (a `string.find` and `string.sub` loop that forgets to advance, or a `gsub` with a count) is a plausible wrong implementation, and no row lists it.
Critique: AC1 states a property ("every text … has `&`, `<` and `>` as entities") that its only case checks on single occurrences, so a wrong implementation passes `check.sh`. The tempting fix is one more literal in the same case, such as a title of `"A&&B"`. That covers `&` only, and leaves `<` and `>`, and the price words and the revive's price, still checked on single occurrences.
Consequences: the new input must keep `&`-first observable (Y8): a doubled `&` next to `<` (`"&&<<"`) separates "`&` first" from "`&` last" just as the current input does. V1 (the pattern-table escaper) and V4 stay correct and must stay green. Nothing else changes: same rule, same files.
Recommendation: in the same case, use hostile texts that hold each of `&`, `<` and `>` at least twice, in the title and in every price field (for example `title = "A<<B>>&&C"`, `odd = { struck = "<<5 && 6>>", price = "&&1", sale = "S>>", revive = "<<r&&>>" }`, with their fully escaped expectations). Add a Rules and mutants row "every occurrence is escaped, not only the first", mutant Y13 (each `gsub` limited to one replacement), to `mutants.py`, and rerun the whole runner so `mutants.out` shows Y13 killed on an assertion and V1 to V4 still green.

## Lesson candidate (for the lead)
- zz-test (or z-design), "escaping cases repeat every character". Rule: a case that pins an escaper or rewriter uses inputs that hold each character it handles at least twice, and next to each other, because an escaper that replaces only the first match passes single-occurrence inputs (f0395 review 001 F1: the first-match-only `plain` passed all nine cases). Check: does every hostile input in an escaping case hold each special character twice or more, and is there a mutant row for "first occurrence only"?
