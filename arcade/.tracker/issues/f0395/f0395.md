# f0395: Test purchase screen strikes the price

## Problem
- The arcade library's test purchase screen (f0201) prints a play's price line as plain text, "5 R$ 1 R$ SALE", with nothing struck.
- The user decided in f0186 (2026-10-31) that "5 R$" is struck through wherever Pickman shows the play price, and ruled on 2026-11-16 (c0202 F1, option a) to keep the struck price through an arcade change.
- The same screen prints that play line for a revive too, and no user decision covers what a revive's price shows there: f0186's G3 ("a continue's price stays its own, nothing struck") is still a guess pending the user (`pickman/.tracker/issues/f0186/f0186.md:30`).

Guess (pending user, 2026-11-16): a revive's price line on the test purchase screen is the new library value `Prices.revive`, "1 R$", alone: nothing struck and no "SALE" (f0186's G3, with the capture's example value); options: (a) "1 R$" alone, as designed; (b) "1 ROBUX", f0186's words for a continue (one value in `Prices` and one expected line in `lines.spec`); (c) the play's line "<s>5 R$</s> 1 R$ SALE" for a revive too (the revive branch and `Prices.revive` go, and c0202's prepared offer case "a revive's test screen strikes nothing" turns red, so c0202 would need its own narrowing); (d) "1 R$ SALE", the sale words without the struck price (one value in `Prices`).

## Non-goals
- Roblox's real purchase dialog is unchanged.
- The lobby's START GAME line is unchanged.
- The portal badge's words (f0205) are unchanged, since the badge draws `Prices` itself.
- This issue does not settle f0186's G3: if the user rules differently on a revive's price, the revive line changes to follow that ruling.

## Solution
- `PaidPlay.testLines(title, "play", prices)` returns the price line with the struck price marked for strike-through (`<s>{struck}</s> {price} {sale}`).
- `TestPurchase`'s line labels render rich text, so the strike shows on every screen that opens it, the portal's play screen (f0208) included.
- A revive's price line comes from a new library value (for example `Prices.revive = "1 R$"`) with nothing struck, on each game's revive screen (f0215, f0219, f0223, and pickman's after c0202); this follows f0186's G3 and is recorded in this issue as a guess pending the user, not as a decision.
- The change stays within `arcade/src/shared/Logic/PaidPlay/init.luau`, `arcade/src/shared/Prices.luau` and `arcade/src/shared/TestPurchase.luau`, and c0202 depends on this issue.

### 1. `arcade/src/shared/Logic/PaidPlay/init.luau` (changed, pure)
```lua
export type Prices = { struck: string, price: string, sale: string, revive: string } -- revive: f0395
-- unchanged signature; the lines are rich text now
function PaidPlay.testLines(title: string, kind: Kind, prices: Prices): { string }
--   kind "play":   { plain("<TITLE>: 1 GAME"), "<s>" .. plain(struck) .. "</s> " .. plain(price) .. " " .. plain(sale), plain(TEST_NOTE) }
--   kind "revive": { plain("<TITLE>: REVIVE: 3 NEW LIVES"), plain(revive), plain(TEST_NOTE) }
local function plain(text: string): string -- private: "&" -> "&amp;" first, then "<" -> "&lt;", ">" -> "&gt;"
```
- **A play's price line** is `<s>{struck}</s> {price} {sale}`: "<s>5 R$</s> 1 R$ SALE" with the shipped `Prices`. Only the struck words sit inside the tag.
- **A revive's price line** is `prices.revive` alone: "1 R$", nothing struck and no "SALE" (the Guess in the Problem). The branch is `kind == "play"` for the struck line and every other kind (the one other, `"revive"`) for its own price; a new `Kind` is a new branch (f0201's Maintainability: "one branch where it is used").
- **Every text is shown as it is** (the consequence of rich text on every line, §3): each text `testLines` puts into a line (the title line, each price word, the test note) passes through `plain`, which turns `&`, `<` and `>` into `&amp;`, `&lt;` and `&gt;`, `&` first, every occurrence, not only the first, so an entity typed into a word shows as typed. The only markup in the lines is the play's one `<s>…</s>`. With today's words (`PICKMAN` … `ASTEROIDS`, `Prices`, `KIND_TEXT`, `TEST_NOTE`) `plain` changes nothing, so the first and last lines are f0201's exactly.
- The line count (three) and order (title, price, note) are f0201's; c0202 reads the price as the second line (c0202 E6).
- PaidPlay stays a leaf: it requires nothing and touches no engine value.

### Authority and what a client could lie about
Nothing changes: the server builds the lines (`Receipts.ask`, server-only) and the client only renders them; a client that sends anything still sends only `"confirm"` or `"cancel"` for a screen the server opened (f0201). Rich text on the labels renders only what this server sent.

### Edge cases
- A word with `&`, `<` or `>` (a future `Prices` edit, a title): shown as typed (`plain`); an entity typed into a word (`&lt;`) shows as typed, not as `<`.
- An empty word (`struck = ""`): §1's template gives `<s></s> 1 R$ SALE`. This is a consequence of the template, not a rule of its own: no case pins it, and a later change that drops an empty tag pair needs no override.
- A malformed line reaching the client (not from this server): f0201 drops non-text lines; a text line with broken markup is shown by Roblox as raw text. Nothing is decided by it.
- The struck price on a revive: none (Guess); the revive line is never a play's (c0202's offer case pins that too).

### Scalability
No new request, remote, instance or message: the same three lines per open screen, a play's seven bytes longer (`<s>`, `</s>`). `plain` is three `gsub`s over a few short strings per screen opened. Nothing per frame.

### Maintainability
The words stay in `Prices`: a revive's price is one value, the play's struck price, price and sale are f0201's three, so a pricing change (the open "permanent sale" item) is one table edit and no code. The markup is built in one place (`testLines`); the client never builds it. A new product kind is one `KIND_TEXT` entry and one branch in `testLines`.

### Usability
- **Player**: in a playtest, the test screen for a play shows the price as the portal's badge does, "5 R$" struck through then "1 R$ SALE"; a revive's shows "1 R$" (Guess), so the screen says exactly what is charged.
- **Developer** (a title's adapters and the portal): nothing to call or pass differently. `Receipts.ask(player, name, kind)` opens the right lines; `PaidPlay.testLines(title, kind, Prices)` is how a spec compares them (c0202). A caller that builds its own `PaidPlay.Prices` table now adds `revive`: none does (c0202, f0205 and f0208 pass the library's `Prices`, or a type of their own, which Luau's width subtyping accepts with the extra field: E2).
