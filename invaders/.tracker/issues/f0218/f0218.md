# f0218: Invaders cannon view

## Problem
The user, 2026-10-31: "I want to branch out into multiple games, they will each have their own directory in the project: first person snake, first person asteroids. I also want a new project for a landing portal where you can scroll between the games and see the highscores for each, the same cost model remains but it shoudl show 5 robux for each game witha slash through showing it is currently on sale for 1 robux. highscores shoudl show how many revives were used. I want you to design a full fun playable game for both of those two new game ideas. I also want both snake and asteroids to be a two player game, snakes can even be n-player up to a high number just make the wold bigger. Snakes should have maps that once you have reached a certain length the game ends and we move to a new map, the first is empty, then one wall somewhere in the middle, then two, then three and so on. The walls can be vertical and horizontal but do not connect. for asteroids we could have a two player version where each player is attacking the aliens from opposing sides. You can shoot each other's barriers. the aliens would then come in from the side and and split into two groups that move toward either player". Then: "Add a third game first person asteroids." Decided with the user (2026-10-31): the 2-player aliens game is pure Space Invaders (`invaders`); Asteroids is its own game (`asteroids`); one Roblox experience with the portal as start place, replacing pickman's lobby; every board shows revives used; one free game per hour per game.

The approved design is `invaders/.tracker/game-design.md`, section **Game design: Invaders (`invaders/`)** (c0183). This issue owns these parts of it, as they are said there: **The field and view** (the camera, the radar and the controls), what the rules show and sound (the march's beat, which speeds up with it), and the game's side of "Pairing"; in `arcade/.tracker/architecture.md`, **Unknowns** E5. The rest of it belongs to other issues (c0190's ownership table), listed under Non-goals.

What should happen:
- The cannon's first-person view and field radar, with every input: A/D or the arrows and Space; gamepad; touch LEFT, RIGHT and FIRE.
- Everything the rules show or sound, from their state: the march's beat speeding up as the formation thins.
- The Invaders place: its project file, the server session that runs each solo game and replicates it to the player, and its arrival: a player from the portal's PLAY, or a party from its 2 PLAYERS in a reserved server, which starts and runs one 2-player match (f0217's rules) replicated to both.
- E5: the party teleport into a reserved server, tested on Beta with the portal as the start place (f0209), its 2 PLAYERS (f0208) and the Invaders place published: the raft's experiments phase first asks the user to create the Invaders place and set `ROBLOX_BETA_INVADERS_PLACE_ID`, so c0210's manifest publishes it before E5 runs; f0222 uses its result.
- Publishing the Invaders place: once the place is playable, the user creates it on Roblox and sets `ROBLOX_BETA_INVADERS_PLACE_ID` (a step this issue's Observed criteria name), and c0210's manifest publishes it from then on; until then the portal's card says "coming soon".
