# c0159: Narrow edge glow pins

## Problem
Decided with the user (2026-10-26) for f0158 "Danger radar ring": "Replace edge glows (Recommended)": the danger ring replaces DangerHud's eight edge glows (f0102); the corner map stays. f0158 is a feature, so the promoted specs that pin the edge glows must be narrowed by a chore that lands first (z-design, Override check). On f0158's prototype (`proto-f0158`), exactly five promoted cases turn red: four because DangerHud no longer calls `Awareness.edgePoint` / `Awareness.glowBox` / `View.ghostColor` for the glows, and one because the ring's screen moves to the core-UI safe area:
- `pickman/tests/acceptance/d0105/adapter.spec.luau` :: "it still draws the radar Awareness computes" (its `Awareness.edgePoint(` needle);
- `pickman/tests/acceptance/f0033/adapters.spec.luau` :: "it draws what Awareness computes: the radar, the indicators and the edge points" (its `Awareness.edgePoint(` needle);
- `pickman/tests/acceptance/f0102/place.spec.luau` :: "it draws the glows Awareness computes, where Awareness puts them, in View's colours";
- `pickman/tests/acceptance/f0102/place.spec.luau` :: "a glow is coloured from its own ghost's name and flash, not by position".
- `pickman/tests/acceptance/f0102/place.spec.luau` :: "the glows have their own screen, in the device's safe area, under the radar, the Flow overlay and the HUD" (its `ScreenInsets = DeviceSafeInsets` needle: decided with the user 2026-10-26, "Centre below top bar" (f0158 G8), the ring's screen is the core-UI safe area; its DisplayOrder rules still hold).

What should happen: each case is narrowed so it no longer requires the edge glows' drawing, keeping every other pin in the file (the radar and indicators needles, the glows' screen rules, the no-arrows case), and `main` stays green before and after f0158 lands. f0158's own specs pin the ring.

## Non-goals
- The ring itself (f0158), and f0102's pure glow specs (box, colors, glows, sectors), which stay as they are: `Awareness.glows`, `edgePoint` and `glowBox` remain in Awareness.

## Solution
- Drop only the `Awareness.edgePoint(` needle from the d0105 and f0033 cases; remove or narrow the two f0102 place cases to what still holds without the glows (e.g. "DangerHud colours nothing by position"); each changed file is pinned whole otherwise (lesson zz-test/narrowing-pins-the-whole-file), with a case that today's and the ring's DangerHud both pass and a regression still fails.
## Design
Decided with the user (2026-10-26) for f0158: "Replace edge glows (Recommended)" (G1) and "Centre below top bar" (G8): the danger ring replaces DangerHud's eight edge glows, the corner map stays, and the ring's screen is the core-UI safe area. This chore only narrows the promoted specs that pin the glows; f0158's own specs pin the ring.
