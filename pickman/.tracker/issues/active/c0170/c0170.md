# c0170: Helper spec tier

## Problem
pickman-test has no tier for specs of a tests/lib helper: a unit spec may require only its feature and @tests/lib/t, so R0059's tests/unit/plain/plain.spec.luau (which requires @tests/lib/plain) breaks the unit tier's rule. Give tests/lib helper specs their own tier (folder, rule, gate selection) and move that spec there (R0059 code review 002 F1).

## Non-goals
- Enforcing the rest of the unit tier's rule (a unit spec requires only its own feature) or any other tier's: only the helper rule that this defect broke, a unit spec requiring a `tests/lib` helper other than `t`, is enforced.
- Moving `tests/unit/smoke.spec.luau` (a spec of `t` itself): it requires only `@tests/lib/t`, so it meets the unit rule; it may move to `tests/helper/t/` later.
- Judging which tiers may load a helper beyond the unit tier (the converse rule: a helper loaded only by its owning tier). A copy of a helper spec in `tests/integration/` is not caught; no contract, integration, runtime or meta spec loads a helper today (design review 005 F2), and the capture asks for the helper tier and the unit tier's defect only.
- Moving sim's own spec, `tests/scenario/harness.spec.luau` (it tests the sim harness through a fixture model): the scenario tier keeps everything driven through `@tests/lib/sim`, and the skill says so. Specs for helpers that have none today (`place`, `fakeengine`, `renamed`); a spec of `fakeengine` would need adapter sources the rule does not allow, which a later issue can widen.

## Solution
- A new tier, `pickman/tests/helper/<helper>/`, for specs of one `tests/lib` helper; R0059's `tests/unit/plain/plain.spec.luau` moves to `tests/helper/plain/plain.spec.luau` (renames only).
- The rule, enforced on the files each require resolves to: `pickman/tests/meta/tiers.luau` decides it purely, and a new case in `pickman/tests/meta/architecture.spec.luau` runs it on the tree's require graph.
- Gate selection needs no new code (E2); the acceptance proves it. pickman-test's tier table and zz-test's list of pickman's tiers name the tier.

## Design
**Depends on R0059** (`depends_on: [c0153]`): `tests/lib/plain.luau` and `tests/unit/plain/plain.spec.luau` exist only on `origin/R0059-frame-roundtrip-tolerance` (PR #159, ready, not merged). The prototype and `experiments/c0170.patch` are cut from its tip, 69282043.

**The tier.** `pickman/tests/helper/<helper>/*.spec.luau`, `<helper>` the name of a `pickman/tests/lib/<helper>.luau` module. A helper spec loads only `tests/lib/<helper>.luau` (at least once), `tests/lib/t.luau` and its own fixtures under `tests/fixtures/<helper>/` (`@lune/` builtins are not files). pickman-test's tier table gains the row (verbatim, pinned by AC2), after the unit row:
`| \`tests/helper/<helper>/\` | one \`tests/lib\` helper's behavior (\`tests/helper/plain/\` for \`tests/lib/plain.luau\`) | only that helper (\`@tests/lib/<helper>\`), \`@tests/lib/t\`, its own fixtures under \`@tests/fixtures/<helper>/\` and \`@lune/\` builtins |`. Its description's tier list becomes "(unit, helper, contract, integration, scenario, place, runtime)"; its helpers sentence becomes "`sim`, `place`, `fakeengine` and `plain` are pickman's helpers" (R0059 added `plain`); its "Choosing a tier" paragraph adds: "A spec of a `tests/lib` helper itself goes in `tests/helper/<helper>/`, never in `tests/unit/`; a spec driven through `@tests/lib/sim` stays in `tests/scenario/` (sim's own `harness.spec` there included). `tests/meta/architecture.spec.luau` enforces the helper tier's and the unit tier's helper rules on the files each require resolves to (`tests/meta/tiers.luau`): a unit spec loads no `tests/lib` helper but `@tests/lib/t` (c0170)." zz-test's "A project's own tiers (pickman's `tests/unit`, …, its `sim`, `place` and `fakeengine` helpers)" gains `helper` after `tests/unit` and `plain` among the helpers, and its earlier "`sim`, `place` and `fakeengine` are pickman's." gains `plain` too (checked by AC4 in check.sh: a pickman spec does not read z-nile's files, design review 001 F4).

**The rule (`pickman/tests/meta/tiers.luau`, pure), over resolved files** (design review 001 F1, F2: a rule over require spellings let a relative `../../lib/plain`, a differently cased alias, or a meta case that handed over only some requires through):
```lua
export type Graph = { files: { string }, deps: { [string]: { string } } } -- graph.build's shape, paths relative to pickman/
function tiers.violations(g: Graph, helpers: { [string]: boolean }): { string }
```
It takes the whole graph and picks the specs it judges itself: every `*.spec.luau` in `g.files` under `tests/helper/` or `tests/unit/`, at any depth (a top-level `tests/unit/smoke.spec.luau` included); any other file, a non-spec module under those folders included, is not judged (design review 002 F2: a caller that handed over chosen specs could hide one). For each judged spec, in `g.files` order, every rule it breaks as `"<file>: <why>"` (its deps are `g.deps[file]`, none if absent):
- `tests/helper/…`: the path must be `tests/helper/<helper>/<name>.spec.luau` (one folder down; else "a helper spec lives in tests/helper/<helper>/"); `<helper>` must be in `helpers` (else "tests/lib has no helper named <helper>"); each dep other than exactly `tests/lib/<helper>.luau`, `tests/lib/t.luau` or one under `tests/fixtures/<helper>/` is one violation ("loads <d>; a helper spec may load only …"; a look-alike `tests/lib/plainx.luau` is another helper); and a spec that never loads `tests/lib/<helper>.luau` is one ("does not load its helper …").
- `tests/unit/…`: each dep `tests/lib/<name>.luau` other than `tests/lib/t.luau` is one violation ("loads <d>; a helper's specs go in tests/helper/<name>/"); no helper is exempt.
- A helper spec's own fixtures are `tests/fixtures/<helper>/…` (with the slash: `tests/fixtures/plainx/` is not plain's), and they never stand for the helper itself.
- **What a spec loads is every file it reaches** (design reviews 003 F3, 004 F1 and F2): its own deps, and the deps of every file under `tests/` outside `tests/lib/` it reaches (a fixture, a sibling module), followed with a visited set (so a cycle ends); a `src/` file, a `tests/lib/` file and a file outside pickman/ (graph.build keeps its leading `../`) are listed but end a path, so a feature's or a helper's own requires are not the spec's. Every listed file is judged by the rule for a direct load: a helper spec may load, directly or through another test file, only its helper, `t` and its own fixtures (else "loads …" or "reaches, through another test file, …"), and must require its helper itself; a unit spec may load no `tests/lib` helper but `t`, and no file outside pickman/.
- **It fails closed** (design review 005 F1): a judged spec that reaches a `tests/` file the graph does not list (any case: a miscased `tests/Lib/plain.luau`, which a case-insensitive disk still opens), or that has a dynamic require (`graph.build`'s `g.dynamic`), is a violation, since neither can be judged. Today the only deps the graph does not list are `scripts/` files, and no spec has a dynamic require, so nothing turns red.
- **A helper** is a `tests/lib` module: `tests/lib/<helper>.luau`, or a folder `tests/lib/<helper>/` with an `init.luau` (any file in it counts as that helper); the meta case's helper set includes such folders (design review 004 F3).

**The meta case** (`architecture.spec.luau`, named "helper specs sit in tests/helper/<helper>/ and load only their helper, t and their fixtures; unit specs load no other helper"): `helpers` from the `.luau` file names in `tests/lib`; then `t.expect(table.concat(tiers.violations(g, helpers), "\n")).toBe("")` with the spec's own `g = graph.build({ "src", "tests" })` handed over whole (the graph library's own reader and resolver, lesson zz-arch/one-reader-per-format; an unresolved require already fails the spec's "every require resolves" case), so a failure lists every violation. `architecture.spec` requires `@tests/meta/tiers` (the meta folder's own module, so zz-test's meta row, "the graph library", needs no change: `tiers` is part of meta).

**Gate selection** (E2): the runner walks every `tests/**/*.spec.luau` in a full run; the affected selector selects a helper spec for its own change (it is a spec file in the graph) and every pickman spec for a change to `pickman/tests/lib/` or `pickman/tests/meta/` (both force pickman's full run). Nothing changes in `z-nile/`'s code. check.sh's AC5 checks the rule, not today's form: the selector names the helper spec for its own path, and for the helper's and the rule's paths answers `ALL` or a list holding the spec (design review 002 F3: a promoted pickman spec would pin z-nile's tool, which a z-nile change never selects it for). AC5 runs the selector from the root with home-relative paths built inside its function (`$h/tests/$1`), so check-paths, which reads an unfinished item's literal paths from its home and compares them with repo-relative Touched modules, sees no literal path that is missing until the work (and R0059) is done (design review 003 F2; the selector prints nothing for absolute paths).

### Scalability
A helper's specs are one folder each; the rule is linear in specs and requires and runs in the meta spec's existing pass (about 0.4 s for the whole file on the prototype).

### Maintainability
The rule lives in one pure module with its own acceptance cases; the meta case only gathers inputs, with the graph library's reader. A new helper needs no rule change, a single file or a folder with an `init.luau` alike: its name is checked against `tests/lib`.

### Usability
A violation names the file, the require and where the spec belongs ("a helper's specs go in tests/helper/plain/").
