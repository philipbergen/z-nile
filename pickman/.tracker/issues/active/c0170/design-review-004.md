### F1 [medium] A unit spec loads a helper past the rule by any require that resolves above pickman's home: the graph keeps `../`, and tiers only knows `tests/lib/`
Where: Design, "The rule" (`tests/unit/…`: each dep `tests/lib/<name>.luau` …; "Loads through other test files count": only files under `tests/` are followed); `tests/meta/tiers.luau` `reached` (`under(d, "tests/lib/")` / `under(d, "tests/")`); `tiers.spec`'s header ("a relative or differently spelled require of the same helper is judged the same").
Evidence: in the probe clone, `tests/unit/Maze/zz_probe.spec.luau` (`--!strict`) requiring `@tests/lib/t`, `@znile/tests/lib/renamed` and `@znile/../pickman/tests/lib/plain`: `lune run tests/run -- tests/meta/architecture.spec.luau tests/unit/Maze/zz_probe.spec.luau` → `11 passed, 0 failed, 2 spec files`. `graph.build({ "tests/unit/Maze" })` gives that spec's deps as `tests/lib/t.luau | ../z-nile/tests/lib/renamed.luau | ../pickman/tests/lib/plain.luau`: `graph.luau`'s `normalize` keeps a leading `..` (c0120), so the same file as `tests/lib/plain.luau` arrives under another name, and `renamed` (which pickman-test calls one of pickman's `tests/lib` helpers, "re-exported from `pickman/tests/lib/`") arrives as z-nile's file, which tiers neither judges nor walks. The same applies to a helper spec (a dep starting `../` is "loads <d>"… only if it is direct; through a fixture it is skipped) and to a fixture's or sibling's require of either form.
Critique: rounds 1 and 3 both found the rule judging something other than "every file the spec loads" (spellings, then direct deps); this is the third form of the same gap, and the design's claim that judging resolved files makes every spelling the same is false for graph.build's resolution. The tempting fix is to add `../pickman/` stripping for the one spelling; that misses `../z-nile/tests/lib/renamed.luau` and whatever the next resolver quirk is.
Consequences: canonicalizing a dep needs the home's name (`pickman`) or an absolute comparison; z-nile's `t` must stay reachable (pickman's `tests/lib/t.luau` requires it, and it is not walked past `tests/lib/`); `affected` shares the same non-canonical names, so the graph quirk is z-nile's and may deserve its own capture; on today's tree no unit or helper spec requires `@znile/` (`grep -rn "@znile" pickman/tests/unit pickman/tests/helper` in the clone: no hits), so a stricter rule turns nothing red.
Recommendation: question the mechanism, not the spelling: tiers judges the spec's whole closure, canonical. (1) Canonicalize every path tiers reads (a dep `../<home>/x` is `x`; the meta case can hand the home's folder name, or tiers can compare `fs`-independent normalized paths it is given); (2) any reached file outside the home (`../…`) is a violation for a unit or helper spec ("loads ../z-nile/tests/lib/renamed.luau; …"), except through `tests/lib/t.luau`, which ends the path as today. tiers.spec cases (synthetic graphs, as graph.build spells them): a unit spec with dep `../pickman/tests/lib/plain.luau` (one violation, naming the helper's folder), a unit spec with dep `../z-nile/tests/lib/renamed.luau` (one), a unit spec → sibling module → `../z-nile/tests/lib/renamed.luau` (one), a helper spec with `../pickman/tests/lib/plain.luau` as its only helper load (passes as its own helper); mutant rows: no canonicalization, `../` deps skipped. Correct tiers.spec's header and the Design's sentence to say what is canonicalized.
Lesson: zz-arch/guards-decide-from-the-tools-resolution

### F2 [medium] A helper spec reaches a feature, or any test module, through its own fixture: the walk collects only `tests/lib/` files, while the Design says it "may reach only its own helper and t through its fixtures"
Where: Design, "Loads through other test files count" ("a helper spec may reach only its own helper and `t` through its fixtures"); pickman-test's new row (may require "only that helper …, `@tests/lib/t`, its own fixtures … and `@lune/` builtins"); `tiers.luau`'s through-fixture loop (`for _, d in reached(g, file)`, where `reached` returns only `tests/lib/` files).
Evidence: in the probe clone, `tests/helper/plain/zz.spec.luau` requiring `@tests/lib/t`, `@tests/lib/plain` and `@tests/fixtures/plain/frames`, where `tests/fixtures/plain/frames.luau` requires `@logic/Maze` and `@tests/unit/Maze/zz_util` (a module under `tests/unit/`): `lune run tests/run -- tests/meta/architecture.spec.luau tests/helper/plain/zz.spec.luau` → `11 passed, 0 failed, 2 spec files`. The same spec requiring `@logic/Maze` directly fails ("loads src/shared/Logic/Maze/init.luau"), so moving the require one file over into the spec's own fixture passes it: the round-3 hole (F3) closed for `tests/lib/` targets only. No tiers.spec case has a helper spec's fixture reaching `src/` or a non-fixture test file, so either reading passes the acceptance.
Critique: the Design's sentence, the pinned row and the code disagree, and the spec doesn't pick one; an executor can't tell whether a fixture may build a feature for a helper spec. The tempting fix is to add `src/` to what `reached` collects; that leaves another test module (a unit sibling, another tier's module) reachable, and decides the open question by accident.
Consequences: forbidding it is the rule the row states (direct and through fixtures alike); allowing it means a helper's fixtures may use Logic, which the row and the "Choosing a tier" sentence must then say, with the walk still forbidding other test modules and other helpers. On today's tree no helper spec has a fixture (`ls tests/fixtures` in the clone: `sim` only, and sim has no helper spec), so either choice turns nothing red. With F1 the walk becomes one closure judged uniformly, which makes this choice one line.
Recommendation: decide it in the Design (recommended: through its own fixtures a helper spec may reach only its own helper, `t` and its own fixtures, the same set as its direct requires; `src/` and `tests/lib/` still end a path for a unit spec's feature and any helper), have `reached` return every file reached rather than only `tests/lib/` ones, and add tiers.spec cases: a helper spec → own fixture → `src/…` (one violation, or none if allowed, pinned either way), → `tests/unit/…` module (one), → another of its own fixtures (none); a mutant row for `reached` collecting `tests/lib/` files only (today's code). Say it in the row or the "Choosing a tier" sentence if fixtures may use Logic.
Lesson: zz-arch/guards-decide-from-the-tools-resolution; z-design/spec-design-correspondence
