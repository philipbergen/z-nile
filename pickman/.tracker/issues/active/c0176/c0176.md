# c0176: Narrow shipped config level pins

## Problem
Promoted specs f0023 session-ghosts, f0100 drops and shots, f0101 airborne build sessions with Session.GAME_CONFIG and pin the classic level 1 (101 steps to the wall at 6,23, the last pellet clearing the level); f0147's ramp in GAME_CONFIG slows level 1 and moves the clear to ten picks, so they must build with GAME_CONFIG minus its ramp

Found by f0147's prep (2026-10-31): on its prototype (f0126, f0109 and f0125 under it) pickman's full gate is red only in these four files, 30 cases: 24 fail in the shared `settled` helper (the player does not reach 6,23 in 101 steps at 21 units a step), the rest pin the last pellet's clear or level-1 timing. f0147 depends on this chore (its Overrides line).

## Non-goals
- f0147's ramp itself, and any new pin of it (f0147's own specs).
- f0125's speeds.spec: c0177.

## Solution
- In each of the four files, the sessions are built with `GAME_CONFIG` less its ramp (a local `table.clone(Session.GAME_CONFIG)` with `ramp = nil`, typed loosely so it loads before f0147 adds the field), so they keep testing the classic level 1 and the last pellet's clear they were written for.
- Every case's assertions stay as they are; only the config each builds changes.

## Design
Product decision relied on (game-design.md, Scoring and rules): "**Levels** (the classic rules, kept for the default config the specs use; the shipped game follows *Levels by picked walls*, f0147)". f0147 puts its ramp in `Session.GAME_CONFIG`; this chore only points the four promoted files that pin the classic level 1 through the shipped config at that config less its ramp. No file in `src/` changes.

**The narrowing** (`experiments/narrow.patch`, cut from origin/main 9bdd8def; base blobs in Implementation step 1).
- In each of the four files, directly after `local t = require("@tests/lib/t")`:
  ```
  -- c0176: the shipped rules less f0147's ramp, so these cases keep the classic level 1 and the last pellet's clear
  local CLASSIC_GAME = table.clone(Session.GAME_CONFIG) :: any
  CLASSIC_GAME.ramp = nil
  ```
  `table.clone` of the frozen config is a plain table. `:: any` lets it load before f0147 adds the `ramp` field, and after it. Today the clone equals `GAME_CONFIG` field for field, so the four files test exactly what they test now.
- Every `Session.new(…, Session.GAME_CONFIG)` becomes `Session.new(…, CLASSIC_GAME)`. The list is a search, not memory (lesson z-design/narrowing-substitutions-found-by-search): `grep -c 'Session.GAME_CONFIG)'` over the base files gives f0023 `session-ghosts.spec.luau` 2 (the `new` helper's `config or Session.GAME_CONFIG`, and the corridor session), f0100 `drops.spec.luau` 1, f0100 `shots.spec.luau` 2, f0101 `airborne.spec.luau` 3: eight calls, all changed. The acceptance asserts the counts. Four of the eight (session-ghosts' corridor session, shots' corridor session and airborne's two two-player sessions) are in cases that pass on the ramp even un-narrowed; they change too, because the capture asks for every session in the four files, and one config per file is simpler to read than two.
- One other use stays: session-ghosts' `t.expect(Session.GAME_CONFIG.ghosts).toBe(true)` reads the shipped config itself, which is what that case is about.
- `pickman/tests/acceptance/c0153/golden.spec.luau`: found by the override grep, not in the capture. It pins f0100's `drops.spec.luau` whole by digest, so that one value moves from `bd7fe073…` to `611b2ed3…` (the narrowed file's, computed from the reviewed patch's text), with a comment saying why. Nothing else in it changes.
- Every case's assertions stay as they are (the capture's second bullet): the patch touches no line inside a case except the eight calls.

**The acceptance** (`acceptance/narrowed.spec.luau`, four kinds of case):
- Whole-file pins (lesson zz-test/narrowing-pins-the-whole-file, c0153's model): the SHA-256 of each of the five changed files' exact text, item ids masked, line endings LF, no other normalising.
- The search, restated: in each of the four files `Session.GAME_CONFIG)` occurs once (the clone), `CLASSIC_GAME)` as often as the base built sessions (2, 1, 2, 3), the two-line clone once, and `CLASSIC_GAME` nowhere else.
- Each changed file's item still runs it: a `check "` line in `done/<item>/check.sh` with `lune run tests/run -- "$A/<file>"`.
- A line joined onto the `-- c0176:` comment changes the pinned text.
- That the files pass is their own runs: AC2 runs f0023's, f0100's, f0101's and c0153's `check.sh` on today's code; on f0147's ramp they were run on the prototype (E2), and f0147's own AC5 runs them again when it lands. No spec here loads f0147's code, which does not exist on main (the user's rule: real-work proofs are one-time, never promoted).

Checklist (chore):
- **No behaviour change**: no `src/` file changes; the four files' 66 cases pass before and after (E1), and AC2 runs their items' checks.
- **Overrides**: the five files, each on the Overrides line with what it still pins.
- **Existing work**: `git worktree list`, 2026-11-14: no prep, raft or prototype branch changes any of the five files (`git diff --name-only origin/main...HEAD` in every `.worktree/prep-*`: none). f0147 (prepared, in R0094, `depends_on` this chore) only runs the four files (its AC5) and pins no text of them; its `experiments/narrowings.patch` was cut before c0153 narrowed `drops.spec` and no longer applies to it, which is why this chore carries its own patch. No sequestered `check.sh` other than f0147's and c0153's names the files (`git grep` in Unknowns).
- **Shared state**: none. **Moves**: none. **Guards**: none touched; the spec only reads.
- **Restated rules**: none. No skill, AGENTS.md line or done `check.sh` label restates what the helper's config is.
