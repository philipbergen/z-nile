# d0410: Finish watch skips deleted

## Problem
Found by R0125 (c0202) when `./zn finish c0202` failed twice, 2026-11-17: `./zn finish`'s watch capture (`watchcmd.capture` in `z-nile/engine/watchcmd.luau`, fed by `layergit.diffPaths`, which is `git diff --name-only <base> HEAD` and so names the paths the layer deleted) treats a deleted path as a changed one. (a) For a spec the layer deleted it writes a `<stem>.watch.txt` beside it, making its folder again (c0202 deletes `tests/unit/Pay/pay.spec.luau`; finish recreated `tests/unit/Pay/pay.watch.txt`, so c0202's place.spec "pickman keeps no copy" failed on `fs.isDir("tests/unit/Pay")` and finish stopped). (b) It lists deleted sources in the ticket's `acceptance/watch.txt` (and in a changed spec's watch), a watch file naming a path that is not a file, which `z-nile/watch-check` refuses. Any layer that deletes a spec or a source cannot finish. It cannot be postponed: it blocks R0125's only layer (zz-rules, Emergent issues).

## Non-goals
- `layergit.diffPaths` itself: its other use in `finish` (the affected selection) should still see deleted paths, since a spec that watched a deleted source is one the change affects.
- `./zn restack` reading a worker commit named `<issue>: <what>` at a layer's tip as the finish commit (seen in the same raft): reported to the lead, not fixed here.
- A deleted spec's own stale sidecar: an author who deletes a spec and leaves its `.watch.txt` leaves an orphan that `watch-check` ignores (`watch.collect` binds a sidecar only when its spec exists) and nothing selects; nothing here deletes it.

## Solution
`watchcmd.capture` keeps only the changed paths that are still files in the tree before it captures anything: a deleted spec gets no watch file, and a deleted source is in no list it writes. Its caller and `diffPaths` are unchanged.

## Design
`watchcmd.capture(member, all)` filters `all` by `fs.isFile` (paths are repository-relative; `finish` runs at the checkout's top, as every other read in `capture` assumes) into `changed`, and the rest of the function is unchanged. A renamed path is named by its new path (`--name-only`), which exists. The existing watch a changed spec already had was rewritten by `./zn commit`'s upkeep when the deletion was committed, so it names no deleted path either.

### Scalability
One `stat` per changed path at finish; no git call added.
### Maintainability
The rule sits where the paths are captured; `diffPaths` stays the plain diff for its other caller.
### Usability
No command line change. A layer that deletes files finishes.
