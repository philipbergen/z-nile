### F1 [medium] The user's "the roll stays even among the six boons" still passes when a jumps roll is re-rolled once (repeat of design-review-004 F2, on the same case)
Where: f0147.md Problem ("Decided with the user (2026-11-01) [...] The roll stays even among the six boons"); levels.spec "with long hops on, a rolled longer-jumps boon still comes up and grants nothing more" (searches seeds 1..120 for one jumps roll); Rules and mutants M63; f0126 boons.spec "each boon is about as likely as the next" (level 1, `longHops` false)
Evidence: mutant Z1 adds `if boon == "jumps" and member.longHops then boon = Picks.roll(member.picks) end` after the roll in `finishPick`. This is the rejected option (b), softened to one re-roll, so jumps comes up 1 time in 36 instead of 1 in 6. Result on levels.spec: `20 passed, 0 failed`. The seed search still finds a seed whose second roll is also jumps. f0126's evenness case rolls on level 1 with `longHops` false, so it never reaches the branch (review 004's Y2b). A probe case, "with long hops on, a pick's roll is the one it would be without them", passes on the prototype in 0.6 s with 7 jumps rolls in 40 seeds, and fails under Z1 (`expected "jumps", got "fastpick"`). It plays seeds 1..40 twice each, on BARE with RAMPED, level 2, once with `longHops = false` and once with `true`, and expects the same `WallPicked.item` both times, plus at least 3 jumps rolls among them.
Critique: the decision has two parts: the jumps roll stays, and the six boons stay even. The case pins the first. An executor who thinks "a dud boon now and then is fine, but not this often" passes AC2. It's the same mechanism review 004 F2 found: the case proves one reachable outcome, not the rule. The new lesson `rejected-options-fail-a-case` says "some seed still rolls longer jumps", which carries the same gap.
Consequences: the same-seed comparison doesn't depend on how the roll is built. It holds for any implementation where `longHops` doesn't change the roll (the walk and the pick's length don't read `longHops`), and it needs no access to the generator's state. It can't tell whether f0126's own roll is uniform, but f0126's case covers that.
Recommendation: replace the seed search's existence test with the same-seed comparison above, or add the comparison as its own case. Keep the existing "grants nothing more" assertions on the first jumps seed. Add a row: "a jumps roll is as likely with long hops on as off", mutant Z1 (one re-roll), with its runner entry. Also add the rule to Edge cases ("a longer-jumps roll from level 2: banner only, the roll unchanged"), so the Design states it outside the Problem line. Amend the lesson's how-to: when a kept decision is a distribution, compare each case with the option off on the same seed, rather than finding one hit.
