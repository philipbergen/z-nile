### F1 [high] camera.spec's stub CFrame has no `Position`, and f0235's Camera change (in prep now) reads `camera.CFrame.Position.Y`: every camera.spec case errors once both are in
Where: `acceptance/camera.spec.luau:63-82` (the shared `frame` table, with only `__mul`, returned by `CFrame.new` and `CFrame.Angles`), `:96` (`assert(services[name], name)`); f0234.md E5 and Maintainability.
Evidence: f0235's `experiments/prototype.patch` adds `eye = camera.CFrame.Position.Y` straight after Camera's one `camera.CFrame =` write, and f0235's Design (line 55) makes it the interface (`Camera.eye()`). In f0234's rig, `camera.CFrame` is that shared `frame` table. `frame.Position` is nil, so the render step raises `attempt to index nil with 'Y'` on its first call. All six AC3 cases call `r.render()`, so all six fail on a runtime error. f0235's own E3 recorded the same failure for the same reason in `tests/place/camera-pad.spec.luau`: 5 cases, "attempt to index nil with 'Y'". That stub was fixed in f0235's design, but f0235's prep cannot see f0234's sequestered camera.spec. f0234's E5 ran d0149's and an f0143-like Camera as correct variants, not f0235's, even though Maintainability names f0235 as the next reader of this code.
Critique: f0235 is claimed on origin/main and depends on nothing. Whichever of the two lands second goes red on the other's spec. If f0234 lands first, its promoted camera.spec blocks f0235. If f0235 lands first, f0234's AC3 can't pass. Neither raft may edit the other's sequestered or promoted spec, so the only way out would be an override chore. The tempting fix is to add `Position = {Y = y}` to the one shared table. That still breaks when anything else in the render step builds a CFrame, because `heights` records every `CFrame.new` call and `render` asserts exactly one per step.
Consequences: the stub has to compose the way Roblox does: `CFrame.new(p) * CFrame.Angles(...)` keeps `p`. If `render` reads the drawn eye from the camera, the `#heights == before + 1` assertion goes, and a check that the step assigned `camera.CFrame` replaces it. The C1 to C7 mutants read the height, so they need a rerun after the stub changes.
Recommendation: (1) give each stub CFrame value a `Position = { X = x, Y = y, Z = z }`, and `X`/`Y`/`Z` fields too (f0235's pin accepts `camera.CFrame.Y`). A product keeps its left operand's `Position`, and an `Angles` value has position 0 and still records its angles. (2) Make `render` clear `workspace.CurrentCamera.CFrame`, run the step, assert it was assigned, and return its `Position.Y`: the eye the camera drew, not the last `CFrame.new` argument. (3) Return an inert stand-in for a service the rig doesn't define, instead of asserting. (4) Add E5(c): apply f0235's Camera and Main hunks from its `experiments/prototype.patch` over f0234's prototype, and run f0234's four specs, f0101/place, f0126/adapters and f0235's `place.spec` ("Camera.eye returns the variable the render step reads back ...") green. Record the result, then rerun `mutants.py`.
Lesson: pickman-test/stub-loaders-fall-back; z-design/mutation-runner-runs-correct-variants

### F6 [low] The no-overlap argument misstates its invariant, and the extension point it offers doesn't carry it

Evidence: the dying and level-clear pauses do carry `hopped` after a death or a clear in the middle of a hop.
