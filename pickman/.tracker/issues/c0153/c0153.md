# c0153: Frame roundtrip tolerance

f0032's frame spec compares the JSON round trip of a frame exactly; Lune's encoder keeps 16 digits, so ghost positions at other speeds come back one ulp off

```
pickman/tests/acceptance/f0013/snapshot.spec.luau:41   t.expect(serde.decode("json", serde.encode("json", snap))).toEqual(snap)
pickman/tests/acceptance/f0018/frame.spec.luau:86      t.expect(serde.decode("json", serde.encode("json", frame))).toEqual(frame)

pickman/tests/acceptance/f0100/drops.spec.luau:193     t.expect(serde.decode("json", serde.encode("json", frame))).toEqual(frame)
```
Every other `serde.decode("json"`/`serde.encode("json"` under `pickman/tests` is an HTTP fixture or a file read (c0003, c0010, c0015, c0051, c0064, f0026), not a round trip of game data.

**`pickman/tests/lib/plain.luau`** (new, pure Lune, required as `@tests/lib/plain`):
- `plain.check(v: any): (boolean, string?)`: true when `v` is plain data: nil, a boolean, a finite number, a string, or a table without a metatable or a cycle that is either a **sequence** (number keys exactly 1..n, no holes) or a **map** (string keys only); the empty table is both. Otherwise false and where, as `<path>: <what>` with the path from `value` (`value.f: a function`, `value.co: a thread`, `value: a table with a metatable`, `value.self: a cycle`, `value.ghosts.1.x: inf is not a finite number`, `value.ghosts: a hole at 2 (number keys must be 1..3)`, `value: a table with both string and number keys`, `value: a boolean key`). Holes, sparse, zero, negative or fractional number keys and mixed tables are what replication and JSON lose (review 001 F4); each is refused by `check`, so `roundTrip` returns false for them instead of raising out of the encoder.
- `plain.equalWithin(a: any, b: any, eps: number, path: string?): (boolean, string?)`: the same types throughout, numbers within `eps` (absolute), compared as `not (math.abs(a - b) <= eps)` so NaN, or a NaN `eps`, is never within (review 001 F3); every key of either side present in the other; other values equal. Otherwise false and the first difference (`value.b: number against nil`, `value.b: missing on the left`, `value.a.b: true against false`).
- `plain.roundTrip(v: any, eps: number): (boolean, string?)`: `plain.check(v)`, then `equalWithin(serde.decode("json", serde.encode("json", v)), v, eps)` inside a `pcall`: plain data the encoder still refuses (a string that is not UTF-8, `"\xff"`) gives `false, "value: the JSON round trip failed: …"`. It never raises.

**The five narrowed cases** (each an Overrides line below): the exact compare becomes
```lua
		-- c0153: plain data, and a JSON round trip within 1e-9 (the encoder keeps about 16 significant digits)
		t.expect({ plain.roundTrip(<snap|frame>, 1e-9) }).toEqual({ true })
```
(a failure prints the reason); the four files that used `serde` only for the round trip require `plain` in its place, and f0032 requires both (its size bound still encodes). Nothing else in the five files changes: `experiments/c0153.patch` is the whole change (helper and five files), and `acceptance/golden.spec.luau` pins each narrowed file whole (review 001 F1, zz-test/narrowing-pins-the-whole-file): the SHA-256 of its exact text with only item ids masked and CRLF made LF, plus a case that each item's `check.sh` still runs it and a case that a check joined onto the comment above it changes the digest. The pins name each file by its full `tests/acceptance/<id>/…` path (a compaction rewrites those) and derive the item folder from it; `renamed.id` is not used, because the compaction map's f0100 is a pre-compaction id and would send today's f0100 to f0011.

### Scalability
A walk over one frame (four ghosts, a play record, an encoded pellet string): microseconds, once per case.

### Maintainability
One helper for "plain data survives a round trip", for every frame or snapshot spec; the tolerance (1e-9 tile) is far below anything a frame means (a unit is 1/120 tile) and far above the encoder's error (about 4e-15 at 28 tiles). A later edit to one of the five files must update its digest in `golden.spec` (its header says how).
