# c0153: Frame roundtrip tolerance

## Problem
f0032's frame spec compares the JSON round trip of a frame exactly; Lune's encoder keeps 16 digits, so ghost positions at other speeds come back one ulp off

## Design
A test-only chore (pickman, no game code changes). One helper and one narrowed assertion.

**`pickman/tests/lib/plain.luau`** (new, pure Lune, required as `@tests/lib/plain`):
- `plain.check(v: any): (boolean, string?)` — true when `v` is plain data: nil, a boolean, a finite number, a string, or a table without a metatable whose keys are strings or numbers and whose values are plain, with no cycle; otherwise false and where (`value.ghosts.1.x: inf is not a finite number`, `value: a table with a metatable`, `value.self: a cycle`, `value.f: a function`).
- `plain.equalWithin(a: any, b: any, eps: number, path: string?): (boolean, string?)` — the same types throughout, numbers within `eps` (absolute), every key of either side present in the other, other values equal; otherwise false and the first difference.
- `plain.roundTrip(v: any, eps: number): (boolean, string?)` — `plain.check(v)`, then `equalWithin(serde.decode("json", serde.encode("json", v)), v, eps)`.

**f0032's frame case** (`pickman/tests/acceptance/f0032/frame.spec.luau`, "the frame carries the same ghosts beside the play record, and everything is plain data"): its `t.expect(serde.decode("json", text)).toEqual(frame)` becomes `plain.roundTrip(frame, 1e-9)` (failing with its reason); the case's other assertions (ghosts equal to the snapshot's, the play record a table, the ghosts under 700 bytes) stay. The case still proves "plain data", more strictly than before: the JSON encoder alone accepts a metatable or an infinite number in some forms, `plain.check` refuses them.

### Scalability
A walk over one frame (four ghosts, a play record, an encoded pellet string): microseconds, once per case.

### Maintainability
One helper for "plain data survives a round trip", reusable by any frame or snapshot spec; the tolerance (1e-9 tile) is far below anything a frame means (a unit is 1/120 tile) and far above the encoder's error (about 2e-15 at 14).

### Usability

## Unknowns & experiments
- **E1. The one-ulp loss** (found by f0125's prep): Lune's JSON encoder writes 13.783333333333333 and decodes 13.783333333333331 (16 digits). Confirmed on f0125's prototype at step 61 (blinky's x, pinky's y).
- **E2. Prototype** (`proto-c0153`): the helper and f0032's change: c0153's spec 6/6 and f0032's frame spec 8/8; and on f0125's prototype (slower ghosts, where f0032 failed) f0032's frame spec 8/8 with the change.
- **E3. Mutation check**: P1 (exact compare), P2 (no cycle check), P3 (metatables accepted), P4 (extra keys on the right ignored), P5 (roundTrip skips the plain check), P6 (NaN or infinity accepted), P7 (f0032 keeps the exact compare) all killed on assertions.
- **E4. The full pickman gate** on the prototype, with c0153's spec promoted to `tests/acceptance/c0153`: 1421/1421 (a strict-mode type error, a mixed list of bad values, fixed by typing it `{ any }`).

## Regression guard
- f0032's frame spec keeps every other assertion of the case and its other cases.
- No other spec uses the exact JSON compare (`git grep -n 'serde.decode("json"' pickman/tests` lists only f0032's case).

Overrides: `pickman/tests/acceptance/f0032/frame.spec.luau` (a chore changes the promoted spec in its own raft): the exact round-trip compare becomes `plain.roundTrip(frame, 1e-9)`.

## Test plan
- `plain.spec` :: the value that came back one ulp off round-trips within the tolerance → AC1
- `plain.spec` :: equalWithin accepts numbers within the tolerance and refuses them beyond it → AC1
- `plain.spec` :: equalWithin refuses a missing key, an extra key, a changed type and a different array → AC1
- `plain.spec` :: check refuses functions, threads, metatables, cycles and NaN or infinite numbers → AC1
- `plain.spec` :: roundTrip refuses what is not plain data → AC1
- `plain.spec` :: f0032's frame case uses the helper, not an exact comparison → AC2
- `f0032/frame.spec` (all its cases) → AC2
