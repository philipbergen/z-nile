# c0164: Main walls behaviour case

## Problem
Replace R0056's text pin `pickman/tests/place/main-walls.spec.luau` (where Main calls `MazeView.edible` and `DangerHud.wallState` in its frame handler) with a behaviour case on f0126's Main harness (`views.spec`): frames with `play.frightened` 0, then above 0, then 0 again, with `overlay.flash` unchanged, turn the walls and the radar green and then blue again (a Main that leaves them stuck green, N6, fails). The case must kill at least what the text pin kills, and also the mutants a text pin can't see: N1 an alias call (`local e = MazeView.edible; e(model, …)` in the flash block only), N2 `MazeView["edible"]`, N3 a direct `model:SetAttribute("Edible", …)` that bypasses MazeView, N4 a shadowed `frame` passed to `View.edible`. Depends on f0126 (R0056 code reviews 002 F2 and 003 F2).

Scope decision (user, 2026-11-01): "Keep both (Recommended)": after four design review rounds each found guard mutants (a Main that skips the colour call when some frame field has a value the behaviour case never sends) that only the text pin kills, the text pin is not deleted: its placement half stays (exactly one `MazeView.edible(` call inside nothing but `if model then`, one `DangerHud.wallState(` call at the handler's top level, no `return` before them), and only its argument-text half goes, replaced by the behaviour case. f0109's promoted place.spec already pins the calls' text, so this costs no refactor freedom.

## Non-goals
- f0109's own place case that finds the two calls' text (its sequestered `place.spec`, promoted with f0109): it stays.
- Any change to Main, MazeView or DangerHud: the behaviour already holds; this chore only changes how it is pinned.

## Solution
- Add one case to `pickman/tests/acceptance/f0126/views.spec.luau` (f0126's promoted spec, once f0126 is done; a chore may change a promoted spec in its own raft) that drives Main's real source through f0126's `mainWorld()` harness, frame by frame, and checks what Main hands `MazeView.edible` and `DangerHud.wallState` each frame.
- Narrow `pickman/tests/place/main-walls.spec.luau` (R0056's, a `tests/place` spec, not promoted) to where the two calls sit, dropping its two argument-text checks (the scope decision above): `experiments/main-walls.patch`.
- Pin both changed files whole.

## Design
**Depends on f0109 and f0126.** `tests/place/main-walls.spec.luau` and Main's `DangerHud.wallState` call come with R0056 (f0109; PR #143, active); the Main harness is f0126's `views.spec` (`mainWorld()`: Main's real source from the built place, every adapter it requires a call recorder), promoted to `tests/acceptance/f0126/` when f0126 is done. The prototype is R0056's tip 867d838b with f0126's `experiments/prototype.patch` applied (`git apply -3`, cleanly) and f0126's acceptance specs copied into `tests/acceptance/f0126/`; there f0126's `views.spec` (10 cases) and R0056's `main-walls.spec` pass (E1).

**The case** (appended as the last case of `views.spec`, exactly as `experiments/views.patch` adds it; its name: "Main turns the walls and the radar green while the ghosts are edible, and blue again after, every frame"):
- **The rule** (design reviews 001 to 003): on every frame, in every phase, Main hands `MazeView.edible` and `DangerHud.wallState` the colour state that frame's play gives (`View.edible(frame.play)`) and the frame's `overlay.flash`, from the play alone, whatever else the frame carries.
- **One script of play states**, in an order the game produces, every `PlayFrame` field set on each (`phase`, `timer`, `frightened`, `lives`, `level`, `score`): ready; playing with `frightened` 0, 6, 6 (nothing changes), 0, 0, 1 (the lowest edible tick: a cutoff above 0 fails it), 6; straight into the level-clear flash (lit, then its dark beat, power zeroed as when the last pellet is eaten under power); ready on level 2; playing 6 straight into a death (`Game.died` zeroes the power); ready; 1; 0; a death with no power; ready; 6 with one life left straight into the last death and game over. Lives only go down, the level only goes up, and a ready comes before each life (design review 003 F2).
- **Run twice, each on a fresh `mainWorld()`**: on bare frames (only `play` and the tick set over the harness's `frame({}, {})`), and on busy frames that also carry holes and marks (`walls`, the same on every busy frame), a ghost (its look following the power), `shots`, a `shot`, a hop (`hopped`, `hopTicks`), a `pick`, a `boon` and a moving, turning, jumping player, the shot, hop, pick, boon, ghost and player changing from frame to frame, at ticks that alternate odd and even. On both passes the level-clear frames have every pellet eaten (`pellets` all `A`), as the game sends them (design review 005 F1: a Main that froze the frame once the pellets were all eaten, or mid-jump, passed until then). A named check first asserts that a busy frame sets `ghosts`, `shot`, `hopped`, `pick` and `boon` where the bare one leaves them nil, and opens more holes, so the second pass is not a copy of the first (design review 003 F1).
- After each frame k of each pass (pushed under `pcall`, so a Main that raises fails on an assertion): `MazeView.edible` and `DangerHud.wallState` have each been called exactly k times (once a frame); the k-th `MazeView.edible` call's arguments are exactly two, the model `MazeView.build` returned (by identity: the same table Main handed `PelletView.build`, design review 001 F3) and the frame's edible state (`frightened > 0`); the k-th `DangerHud.wallState` call's are exactly two, the frame's flash (lit only on the level-clear frame's odd beat) and its edible state.
- So the walls and the radar turn green (true) on the frames above 0 and blue (false) again after, with `overlay.flash` unchanged; and the radar's flash argument follows the level-clear flash.

**Why the two together kill more than the text pin alone.** The text pin read Main's source for one literal `MazeView.edible(model, View.edible(frame.play))` inside nothing but `if model then` and one literal `DangerHud.wallState(overlay.flash, View.edible(frame.play))` at the handler's top, with no `return` before them. The case watches the calls instead, so a call that is aliased (N1), indexed by string (N2), bypassed (N3), fed a stale frame (N4), stuck green (N6) or placed where it does not run every frame fails, while a refactor that keeps the behaviour (a local for the edible state, a helper called every frame) passes. The text pin's `return before` variant (`if not model then return end` ahead of the calls) is never taken (the first frame builds the model), so it is a correct variant here (E2).

**The kept pin** (`tests/place/main-walls.spec.luau`, narrowed by `experiments/main-walls.patch` from R0056's blob 38b8f1cc): its rule keeps exactly one `MazeView.edible(` call, inside nothing but `if model then`, exactly one `DangerHud.wallState(` call, at the frame handler's top level, and no `return` in the handler before them; it drops the two checks that each call's line is exactly `MazeView.edible(model, View.edible(frame.play))` and `DangerHud.wallState(overlay.flash, View.edible(frame.play))`, and its header says so. Its variant case (folded into the flash block, guarded, hidden, doubled, returned past) is unchanged. A guard around either call (`if model and <anything> then`) breaks "inside nothing but `if model then`", so every guard mutant design review 004 listed dies here, whatever field it reads.

**Pinning.** `acceptance/walls.spec.luau`: `main-walls.spec`'s exact text (ids masked, LF) has the SHA-256 of the narrowed file; `views.spec`'s exact text (item ids masked, LF) has the SHA-256 of f0126's sequestered `views.spec` (blob 5a57a554, on origin/main today) with `views.patch` applied, so nothing else in f0126's file moves; and the case is there exactly once and passes on the real Main.
