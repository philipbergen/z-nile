### F1 [high] AC1 passes with four wrong tiers.luau rules: a fixture counted as the helper, a look-alike fixtures folder, top-level unit specs unjudged, and a helper exempted from the unit rule
Where: `acceptance/tiers.spec.luau`; Design, "The rule"; Rules and mutants (no rows for these).
Evidence: `python3 -I $D/rm.py $D/repo` (each a one-line edit of `pickman/tests/meta/tiers.luau` in the reviewer clone, both acceptance specs run, the file restored after each):
- R1, `if d == own then` → `if d == own or under(d, fixtures) then`: `SURVIVED` (12 passed). A `tests/helper/sim/x.spec.luau` that loads only `tests/fixtures/sim/walker.luau` and `t` then passes, though the Design says a helper spec "that never loads `tests/lib/<helper>.luau` is one" violation. tiers.spec's "never loads its own helper" case only tries `{ T }` and `{ plainx, T }`, never a spec that loads its own fixture but not its helper.
- R2, ``local fixtures = `tests/fixtures/{helper}/` `` → `` `tests/fixtures/{helper}` ``: `SURVIVED`. `tests/fixtures/plainx/a.luau` then counts as plain's own fixture. This is the look-alike class T13 kills for `tests/lib/`, left open for `tests/fixtures/`.
- R3, `elseif under(s.file, "tests/unit/") then` → `elseif string.match(s.file, "^tests/unit/[^/]+/") then`: `SURVIVED`. A top-level `tests/unit/x.spec.luau` that loads `tests/lib/plain.luau` is then not judged. Top-level unit specs are real: `tests/unit/smoke.spec.luau` is one, and tiers.spec only tries it with `{ T }`.
- R4, `if name and d ~= T then` → `if name and d ~= T and name ~= "renamed" then`: `SURVIVED`. No unit case loads any helper but `plain` and `sim`, so an implementation that exempts `renamed`, `place` or `fakeengine` passes.
Critique: each is a wrong implementation of a rule the Design states, and AC1 passes it. The tempting fix is one assertion per mutant, which leaves the next helper name or path shape open.
Consequences: R4's fix is to loop over every name in a helpers set. That set must include `renamed`, `place` and `fakeengine` (tiers.spec's `HELPERS` holds `plain, plainx, sim, place, t` today), so the case can't pass by listing only the helpers it tries. R1's case must keep the own-fixture spec's other files allowed, so it tests only the missing helper: exactly one violation, "does not load its helper".
Recommendation: put these in tiers.spec (they are rules of a pure module, so spec cases that run in the gate after `done`). (a) Add `tests/helper/plain/x.spec.luau` with `{ "tests/fixtures/plain/a.luau", T }`: one violation, "does not load its helper tests/lib/plain.luau". (b) Add `{ PLAIN, "tests/fixtures/plainx/a.luau", T }`: one violation naming `tests/fixtures/plainx/a.luau`. (c) Add a top-level `tests/unit/x.spec.luau` with `{ PLAIN, T }`: one violation. (d) For every helper of a `HELPERS` set that also holds `renamed` and `fakeengine`, a unit spec loading `tests/lib/<name>.luau` gives one violation naming `tests/helper/<name>/`. Add R1–R4 as Rules and mutants rows (with ids in `mutants.py`) and run them.
Lesson: zz-test/refusals-tested-on-both-sides

### F2 [medium] The spy on the meta case can't see a call site that drops fixture deps, because no helper or unit spec on today's tree has one (repeat of the mechanism review 001 F1 found a hole in)
Where: `acceptance/layout.spec.luau`, case "the tier case hands tiers every helper and unit spec with the files it loads, and every tests/lib helper"; the meta case's `deps = g.deps[file] or {}`.
Evidence: reviewer mutant R5 (`python3 -I $D/rm2.py $D/repo`): `deps = g.deps[file] or {}` → a filter that drops every dep matching `^tests/fixtures/`. Result: `SURVIVED` (12 passed). The spy compares handed deps with `g.deps` only for files under `tests/helper/` and `tests/unit/`, and today that is `plain.spec` (`tests/lib/plain.luau`, `tests/lib/t.luau`) and unit specs (features and `t`). Under R5, a future `tests/helper/plain/x.spec.luau` that loads `tests/fixtures/sim/walker.luau` (another helper's fixture, the rule's T14 case) is green in every gate.
Critique: this is the second hole in the same spy. Review 001's fix compared every element, but only over the kinds today's tree happens to hold. The tempting fix, adding a fixture-using helper spec to the tree just so the spy sees one, adds a real spec for a test's sake and still leaves out the kinds nobody seeded (a `../z-nile/…` dep, a sibling module under `tests/helper/plain/`).
Consequences: moving the choice of specs into the pure module means the call site does no filtering, so there is nothing at the call site left to mutate. Then the signature changes to `tiers.violations(graph: { files: { string }, deps: { [string]: { string } } }, helpers)`. T7 (only `tests/helper/` walked) becomes a tiers.spec case, and the spy compares the whole graph handed with `graph.build({ "src", "tests" })`. That graph holds fixture deps today (`tests/scenario/harness.spec.luau` → `tests/fixtures/sim/walker.luau`), so a filter of any kind of dep shows up as a difference. The Design's Spec type, its meta-case paragraph, the patch and E4 change with it.
Recommendation: question the mechanism: make `tiers` take the whole graph (`files`, `deps`) and choose the helper and unit specs itself. In tiers.spec, add a synthetic graph seeded with every kind: a helper spec, a unit spec, a top-level unit spec, a scenario and an acceptance spec (not judged), a non-spec module under `tests/unit/`, and deps of each kind (`src/…`, `tests/lib/…`, the spec's own and another helper's `tests/fixtures/…`, `../z-nile/…`). Assert which specs are judged and what is reported. layout's spy asserts that the handed `files` and `deps` equal `graph.build`'s in full, and that the handed deps hold at least one `tests/fixtures/` entry, so the comparison can't go vacuous. Add R5 as a mutants row.
Lesson: zz-test/seed-every-enumerated-case
