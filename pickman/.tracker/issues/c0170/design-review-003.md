### F3 [medium] The unit tier's helper rule is passed by one indirection: a fixture or a sibling module that requires the helper
Where: Design, "The rule" (`tests/unit/…`: each *dep* `tests/lib/<name>.luau` …); Non-goals; the pinned pickman-test sentence "a unit spec loads no `tests/lib` helper but `@tests/lib/t`".
Evidence: in a worktree of the reviewer clone (`$P/probe`, `mktemp -d`), `tests/unit/Maze/zz_probe.spec.luau` requiring `@tests/lib/t`, `@tests/fixtures/sim/walker` (which requires `@tests/lib/sim`, `tests/fixtures/sim/walker.luau:4`) and `./zz_util`, with `tests/unit/Maze/zz_util.luau` being `return require("@tests/lib/plain")`: `lune run tests/run -- tests/meta/architecture.spec.luau tests/unit/Maze/zz_probe.spec.luau` → `11 passed, 0 failed, 2 spec files`. The spec drives sim and plain from `tests/unit/`, which is the defect this issue exists for, and the skill sentence the issue pins says it can't.
Critique: the rule judges direct deps only, and the Design exempts non-spec modules under `tests/unit/` and puts no limit on fixtures for unit specs. When the new rule fires on a unit spec, moving the require into a local helper module or a fixture is the obvious workaround, and it passes. The tempting fix is to judge non-spec modules under `tests/unit/` as if they were specs; that still misses the fixture route (walker exists today) and judges modules that aren't specs by spec rules.
Consequences: closing it needs the rule to follow what a spec loads beyond its direct deps, or to narrow what a unit spec may load directly. (a) Closure: from each judged spec follow deps through every file that is not under `src/` and not under `tests/lib/` (src never requires tests by architecture.spec's own rule; a `tests/lib` file is a helper, reported and not descended into; `t.luau` requires z-nile's `t`), with a visited set (require cycles are possible among test modules), and report each helper reached with its route ("loads tests/lib/sim.luau through tests/fixtures/sim/walker.luau"). The same walk applies to a helper spec's own fixtures (a `tests/fixtures/plain/x.luau` requiring sim loads sim). (b) Direct, narrower: a unit spec's direct deps are only `src/…` files and `tests/lib/t.luau`. On today's tree every unit spec's requires are `@logic`/`@shared`, `@tests/lib/t` and `@lune/` (`grep -rhoE 'require\("[^"]+"\)' tests/unit`), so it holds, but it changes the Non-goal ("the rest of the unit tier's rule … is not enforced") toward the full rule and forbids unit fixtures nobody uses yet. Either changes the Design's rule text, tiers.spec, pickman-test's sentence and E1.
Recommendation: take (a), the rule the skill sentence already states. tiers.spec cases (pure, synthetic graphs): a unit spec → `tests/fixtures/sim/walker.luau` → `tests/lib/sim.luau` (one violation naming both), a unit spec → sibling `tests/unit/Maze/util.luau` → `tests/lib/plain.luau` (one), a unit spec → sibling → `src/…` and `t` only (none), two sibling modules requiring each other (terminates, none), a helper spec → its own fixture → another helper (one), a helper spec → its own fixture → its own helper (none), and a helper reached by two routes reported once per spec or once per route (decide which, and pin it). Mutant rows: the walk not followed (direct deps only, today's code), no visited set (the cycle case must fail by assertion or a bounded error, not hang: give the walk a depth guard or rely on the visited set and pin it), descending into `src/`. Update E1 (rerun on the tree: still clean, since no unit spec loads a fixture or a sibling module today).
