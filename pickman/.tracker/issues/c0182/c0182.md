# c0182: Narrow the touch pins d0149's circles replace

## Problem
d0149 (touch circle controls, decided with the user 2026-10-25 and 2026-10-31) replaces the phone's touch controls: the left-half swipes, the right-half drag look, the snap control and the JUMP button go, and two fixed circles (steer, look; a tap on the look circle hops) with FIRE and PICK discs beside the look circle take their place. Promoted acceptance specs pin the old controls, and an executor may never edit a promoted spec, so d0149 cannot land while they stand (z-design, Override check). Found in d0149's prep (its prototype `proto-d0149`, 2026-10-31), the specs whose cases fail on the new controls:
- f0027 (swipe turns): `place.spec`, `screen.spec`, `swipe.spec`, `track.spec`.
- f0028 (touch look): `hit.spec`, `look.spec`, `place.spec`.
- f0029 (mobile HUD): `button.spec` (the snap control), `jump.spec` (the case that places the snap button against the jump buttons), `phone.spec`, `place.spec`.
- f0110 (touch FIRE and JUMP): `adapters.spec`, `buttons.spec`, `fold.spec`, `hunt.spec`.
- Once promoted: f0126's `touch.spec`, the touch cases of its `controls.spec` and the clearance case of its `parts.spec` (it reads `Touch.snapRect`); f0143's swipe-up boost case in `controls.spec`; f0158's `clear.spec` (it reads `Touch.snapRect` and the JUMP button); c0155's `narrowed.spec` (in its prep, `prep-narrow-button-table-pins`: it runs f0110's `buttons.spec` case through `Touch.snapRect`, `fireRect` and `hopRect`; c0155.md says it must be narrowed if d0149 renames or removes that case; d0149's design review 001 F1).
- f0158's `check.sh` runs `clear.spec` with `F0158_EXACT=1`, which requires each accepted overlap to still happen: its ACCEPTED entries for the snap control, JUMP (`jump2` is Roblox's own button, which stays measured), FIRE and PICK go stale once d0149 moves or removes those controls, so they are removed (d0149's own `clear.spec` owns the touch controls' clearance of the ring from then on). That is an edit to a finished item's `check.sh` or spec, so it lands in a tracker PR before d0149 is readied (z-design/finished-overrides-land-before-ready; d0149's design review 001 F3).

Prep's choice (d0149's prep, 2026-10-31, which owns this chore by the user's 2026-10-25 line; the user may veto): **narrow, keep every file**: each listed file keeps at least one case and every file stays named by its owner's `check.sh`, so no finished `check.sh` changes for a removed file (d0149's design review 001 F4). A file none of whose cases survives (f0027's `swipe.spec`, which pins only `Touch.swipe`) keeps one case that pins what d0149 keeps in its place, or is removed together with its line in the owner's `check.sh`, in a tracker PR before d0149 is readied; c0182's prep names which.

What should happen: each of those cases is removed or narrowed so that it no longer pins the replaced controls, while every rule it pins that d0149 keeps stays pinned (the screen-pixel conversion, the HUD blocks, the radar's place, the FIRE shot's aim and intent, the PICK and boost intents, the ring's clearance of the HUD). `main` stays green after this chore alone: removing or narrowing a pin never fails it. d0149 depends on this chore.

## Non-goals
- d0149's circles themselves, and its own new specs.
- `tests/unit/Touch` and `tests/place/touch-adapters.spec.luau`: not promoted, d0149 rewrites them.
