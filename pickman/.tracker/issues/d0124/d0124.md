# d0124: Hiscores remember top ten

## Problem
Every game over reports all-time #1 whatever the score, and the lobby list never shows a top 10: stored scores are not remembered.

User, 2026-10-21, playing live: "the hiscore list tells me every time regardless of score that it's all time #1, it clearly has no memory and it should list top 10, and doesn't". Every player is affected. Today each run's rank is reported as all-time #1, even when an earlier run scored more, and the lobby's hiscore list does not show the ten best scores. What should happen, as built by f0024 (Hiscore store), f0025 (Hiscore submit) and f0061 (the lobby): each submitted score persists across sessions and servers, the rank reported at game over is the score's real all-time place, and the lobby lists the top 10 scores in order.

Scope decision (user, 2026-10-21): "Keep player best and a global list of top-10, so the number of rows is (10+n_players) in total". Each player's best row stays on every board as today, and the all-time board gains one list of the ten best runs of all players, where one player can hold several places. So "each submitted score persists" means: every run that makes the all-time top 10 stays on that list, and every player's best stays on the per-player boards.
Scope decision (user, 2026-10-21), the top-10 list of runs for today and this week too: "Only all-time". Today and this week stay one best row per player.
Scope decision (user, 2026-10-21), what game over says for a run outside the top 10: "Only within the top 10". The rank line is the run's place on the all-time top-10 list (#1 to #10), and a run that misses it says so ("NOT IN THE ALL-TIME TOP 10"); no place beyond 10 is counted.
Scope decision (user, 2026-10-21), what the lobby shows: "Top-10 runs plus 'your best'". The all-time panel lists the top-10 runs and ends with one line holding the viewer's own best score and level.
Scope decision (user, 2026-10-21), rows already stored: "Keep them as entries (Recommended)". The stored per-player bests start the list, each as one run.
Decided with the user (2026-10-21): the known limit in R0044's Risks is accepted ("Accept the limit (Recommended)"): a run that is not its player's best is not listed if its list write fails three times or it was played on a build without the list; no retry set is built.

## Non-goals
- New hiscore features: daily or weekly boards, friends-only lists, per-level boards.
- The game-over overlay's layout and the return to the lobby (f0065).
- Top-10 run lists for today and this week, and a place beyond 10 (the scope decisions above).
- Removing `Hiscores.drive`'s own all-time read: f0024's promoted specs pin it, and it still writes the per-player boards. Its rank is no longer what a player hears.
- Narrowing the seven promoted cases that pin the per-player-only answer: c0128, which must be done first.
- The lobby's layout: the best line is one more line of the existing `Rows` text.

## Solution
<!-- The approach in one paragraph. -->
- First find where memory is lost on the live game: the write never lands (DataStore access in a published place, the wrong store name or scope, or an `UpdateAsync` whose transform drops the old entries), or the read goes to a different store or the ordered/sorted read returns nothing.
- Check whether the rank is computed against an empty or freshly-created board on each server (`src/server/Ranks.luau`, `src/server/Submits.luau`, `src/server/HiscoreStore.luau`, `src/lobby/server/Boards.luau`).
- Add a regression spec in which two submits in a row, the second one lower, give ranks 1 and 2, and the board reads back both in order.

Prep adds (2026-10-21):
- Both checks above are answered in Design, "Cause": nothing is lost; the boards hold one row per player by R0011's prep decision 2.
- A new store, `HiscoreTop`, holds the all-time top-10 list of runs under one key. The game server writes each run to the per-player boards as today, then to the list together with the per-player bests it read back, and tells the player the run's place on the list or that it missed it.
- The lobby's all-time answer is that list, plus the asker's own best; with no list stored yet it is the per-player board, as today.
- The regression case is `adapters.spec` :: "one player's two runs in a row, the second lower, are places 1 and 2 and the lobby lists both".

## Design
### Cause (found in prep, 2026-10-21)
Nothing is lost. R0011's prep decision 2 is "One row per user id per board. A submit replaces that row only when the new score is strictly greater". The all-time key is the user id (`Hiscores.entryKey`), so one player has one row, holding their best. `Hiscores.drive` then ranks the player's row (`rankOf(rows, attempt.userId)`), not the run. Playing alone, the board has one row and every run is "ALL-TIME #1", and the lobby shows that one row. The write path works on the live game: a rank is only sent when `drive` read the player's own row back from the store. The user confirmed the lobby shows "One row: my best". `tracker/game-design.md` never required one row per player, so the scope decisions above replace R0011's decision 2 for the all-time list only, and the per-player boards keep it.

### Decisions made in prep
- **Merge the per-player bests on every write** (design review 001 F1). `drive` writes the per-player boards first, as today, and its own read of the all-time board afterwards (`DriveResult.rows`, read today and thrown away) goes to `driveTop`. Every list write adds each of those bests, deduped by id only (design review 003 F2 dropped the round-1 rule that skipped a best "covered" by a listed run of its player: with run ids it hid real runs, such as an older run whose list write failed and that a later run ties). So the old rows start the list, and a best written later by a build without the list (another Beta PR's build, an old server still running after a publish, a rollback) joins it on anyone's next run. The run's own new best names the run, so it is the same id and is listed once.
- **A list is never created without the bests.** With no list stored and no bests read (the board could not be read), nothing is written and the player hears nothing (as f0024 pins: no rank when the board cannot be read). The next run tries again. An existing list takes the run even without the bests, which are merged on a later run.
- **One key, one atomic transform.** The whole list (at most ten runs, about 1.5 KB) is the value of one key, written by `UpdateAsync`. The transform always applies to the value the store holds, so two servers' runs never overwrite each other. It returns nil (no write) when the run is already there or does not make the list.
- **A run's id** is `<userId>:<unix>:<run>:<JobId>`, so a retried write that already landed is not listed twice, and two servers never clash.
- **A run has one id from every source, and a best is its companion row whole** (design reviews 002 F1 and 003 F1). The per-player rows a run writes name it: `Attempt`, `Companion` and `Row` gain optional `run` (its list id) and `at` (its instant), `commit` copies them from the attempt and `rows` carries them from the companion, each only when `run` is a non-empty string and `at` is whole. `rows` also carries the companion's own score as `Row.runScore` (whole and >= 0, else nil), because the page score comes from the ordered store and can lag the companion (a write half done, an ordered write that failed, a cached read). `Row.score` stays the page score, which f0024 pins. A best takes its id, instant, score and level from the companion: a row that names its run merges as that run at its own score, and a row without a valid `runScore` is skipped. So when another server merges this run's best before this run's own list write, the two are one id and one score, and the stored copy wins. A cut run that comes back as its best keeps its real instant, so it cannot win a tie it lost (design review 002 F2). A row written before this raft (or by a build without it) names no run, and merges as `best:<userId>:<companion score>:<level>` at 0: a raised best is a new entry beside the older one, which is a real older run, and a merged best is never merged twice.
- **Ties:** score, then level, then the earlier run, then the id. An unnamed best is at 0: right for rows written before this raft, which are older than the list. A row written later by a build without the list is also unnamed and at 0, so on an exact tie of score and level it takes the place of an earlier run (a known limit, R0044 Risks).
- **No write when nothing changes:** the transform returns nil when the list's ids in order would be the same, so a missed run, a retry that landed and an already-merged best cost a read only.
- **The rank heard is the list's**, sent as `(run, rank, missed)`. `missed` is `Hiscores.N` when the run is not on the list. Nothing is sent when the list write failed, or when no list exists and the per-player board could not be read (as today, when the board cannot be read).
- **The best line** shows only on the all-time panel. Boards reads it from the asker's all-time companion row, at most once per `CACHE_TTL` per player present, never twice at once, and forgets it when they leave (design review 001 F2): an in-flight marker is stored before the read, and the result is kept only while the player is present and the marker is still that read's.
- **A list that cannot be read** is a failed all-time read (the f0026 failure path). It never falls back to the per-player board, which would show another board under the same title.

### Data
`HiscoreTop`, scope `all`, key `runs` (a standard DataStore). Value: an array of at most `Hiscores.N` runs, in order:
```lua
{
	{ id = "7:1792108800:1:9b2c-…", name = "Ada", userId = "7", score = 80, level = 3, at = 1792108800 },
	{ id = "best:2:60:1", name = "Bea", userId = "2", score = 60, level = 1, at = 0 }, -- a merged per-player best
}
```
The per-player all-time companion row (`HiscoreEntries`, scope `all`, key `<userId>`) a run writes after this raft:
```lua
{ name = "Ada", userId = "7", score = 80, level = 3, run = "7:1792108800:1:9b2c-…", at = 1792108800 }
```
`run` and `at` are absent on rows written before this raft or by a build without it; code before this raft ignores them, and rewrites a row without them only on a strictly better score (that run never reached the list, so it merges as `best:`). Day and week rows carry them too, unused.

A missing key (nil) means no list yet. Entries that fail `validRun` (an id that is not a non-empty string, a name that is not a string, an `at` that is not whole, or a user id, score or level `Hiscores.valid` refuses) are dropped on every read and write, and so is any id after its first.

### Files and API
`src/shared/Logic/Hiscores/init.luau` (pure) gains:
```lua
export type TopRun = { id: string, name: string, userId: string, score: number, level: number, at: number }
export type TopIo = { update: (transform: ({ TopRun }?) -> { TopRun }?) -> (any, string?) }
export type TopResult = { known: boolean, place: number?, missed: number? }
export type Best = { score: number, level: number }
Hiscores.TOP_STORE = "HiscoreTop"; Hiscores.TOP_SCOPE = "all"; Hiscores.TOP_KEY = "runs"
function Hiscores.runId(userId: string, unix: number, run: number, server: string?): string -- non-string server is ""
function Hiscores.topRun(attempt: Attempt, unix: number, run: number, server: string?): TopRun? -- nil when valid refuses, or unix or run is not whole
function Hiscores.bestRun(row: Row): TopRun? -- nil without a valid row.runScore; the row's run id and instant when it names them; else id "best:<userId>:<runScore>:<level>", at 0; score is always row.runScore
-- Attempt, Companion and Row gain run: string? and at: number?; commit copies them from the attempt, rows from the companion (both only when run is a non-empty string and at is whole); Row also gains runScore: number?, the companion's score (whole and >= 0)
function Hiscores.mergeRun(list: { TopRun }, run: TopRun, bests: { Row }): ({ TopRun }, number?) -- the run, then bestRun of each best (nil skipped); one entry per id, the stored copy winning; new list in order, at most N; the run's place or nil; never mutates
function Hiscores.addRun(list: { TopRun }, run: TopRun): ({ TopRun }, number?) -- mergeRun(list, run, {})
function Hiscores.topRows(list: any): { Row }? -- ranked 1..N; nil when not a table
function Hiscores.readAll(io: Io, unix: number): { Row }? -- drive's all-time read, moved out of drive unchanged
-- DriveResult gains rows: { Row }? (that read's rows, nil when it failed); wrote and rank are unchanged
function Hiscores.driveTop(top: TopIo, io: Io, run: TopRun?, bests: { Row }?, policy: Retry): TopResult
function Hiscores.best(companion: any): Best? -- whole score >= 0 and whole level >= 1
function Hiscores.fresh(at: number?, now: number, ttl: number): boolean -- now >= at and now - at < ttl
function Hiscores.needsRead(held: { at: number, reading: boolean }?, now: number, ttl: number): boolean -- nil held, or not reading and not fresh
```
`driveTop`: a nil run, or one `validRun` refuses, is `{ known = false }`, with no call. It reads nothing itself. For each delay of `attemptDelays(policy)` (the non-zero ones go to `io.wait`): skip when `affords(io, "get", "set")` refuses; otherwise call `top.update(transform)`, and an error goes on to the next delay. The transform records the place, and whether it found nothing to create, from its last call only (`UpdateAsync` may run it again on a newer value), and does not yield or call `io`. On a stored nil with `bests == nil` it returns nil (nothing is created); otherwise it returns `mergeRun(old or {}, run, bests or {})`, or nil when the stored list is a table and the merged ids in order equal the stored ones. After a successful update, the result is `{ known = false }` when nothing could be created, else `{ known = true, place = place, missed = if place == nil then N else nil }`. Running out of attempts is `{ known = false }`.

`src/shared/Logic/Flow/init.luau` gains `RankView.missed` and `RankView.pendingMissed`, `Flow.missLine(top: number?): string?` (`NOT IN THE ALL-TIME TOP <top>` for a whole top >= 1, else nil) and `Flow.hearMiss(view, run, top, gameOver): RankView`, which keeps, shows and drops a miss exactly as `hearRank` does a rank. `hearMiss` clears the rank of the run it sets, and `hearRank` clears its miss. `follow` carries `pendingMissed` into `missed` on the edge into game over, and clears `missed` on close. `shownRank` is `rankLine(rank) or missLine(missed)`. `rankLine` and `hearRank`'s refusals are unchanged (f0026 pins them).

`src/shared/Logic/Lobby/init.luau` gains `Lobby.bestLine(best: any, id: string?): string?` (`YOUR BEST <score> <level>` for id `"all"` and a whole score >= 0 and level >= 1, else nil) and `Lobby.text(p: Panel, highlightRank: number?, best: any, id: string?): string` (`Lobby.lines(p, highlightRank)`, then `"\n" .. bestLine` when there is one).

### Pure/adapter split and authority
Every rule (order, cap, ids, the merge of bests, retries, place, miss, freshness, the lines) is pure Logic with specs. The adapters only open stores and pass the transform, the clock and the job id. Only the server writes. The run comes from the server's own simulation (f0025, unchanged), and the client sends a board id, never a score. The best line shows the asker's own row, which the server reads by the asker's `UserId`.

### Scalability
- **Per run:** `drive`'s existing six updates and its all-time read (now reused, not thrown away), then one list `UpdateAsync`. That adds one standard read and at most one standard write to today's cost, and no read of its own.
- **Per key:** one global key. The documented per-key limit (E2) is 4 MB of writes per minute, which at about 1.5 KB per write is about 2,700 writes a minute, far above any expected rate of game overs. A run that misses the list costs a read only (the transform returns nil).
- **Lobby:** the all-time read is one `GetAsync` instead of a page and ten companions, so it is cheaper. The best is one read per player per 15 s at most, never two at once however fast a client fires the remote, and the state is per player present, cleared on leave (a read that ends after the leave is dropped).
- **Replication:** one remote packet per run (one more number), and one more table on the lobby answer.

### Maintainability
A day or week run list would be one more `(store, scope, key)` from the same functions: `driveTop` takes its `TopIo`, and `topRows` and `addRun` know nothing about the period. N is still `Hiscores.N`. `readAll` is now the one all-time read: `drive` makes it, and its rows feed `driveTop`.

### Usability
A player sees their run's place at game over even when an earlier run of theirs is better: "ALL-TIME #2" after a lower second run, or "NOT IN THE ALL-TIME TOP 10". The lobby lists ten runs, names repeated when one player holds several, and ends with "YOUR BEST <score> <level>". Developer API: `driveTop` mirrors `drive`, the `TopIo` has one function, and `addRun` and `topRows` are pure and total over whatever a store holds.

## Unknowns & experiments
- **E1** Does an `UpdateAsync` whose transform returns nil cancel the write without an error, may the transform run more than once, and must it not yield? **Pass (docs, 2026-10-21)**, `GlobalDataStore` reference: "If the callback returns `nil`, the write operation is cancelled and the value remains unchanged"; "The function will be called as many times as needed until the data is saved"; "The callback function cannot yield". `driveTop`'s transform calls no `io` and remembers its last call, as `drive`'s do.
- **E2** Can one key take every server's list writes? **Pass (docs)**, "Error codes and limits": per-key throughput is 4 MB per minute of writes and 25 MB per minute of reads, over the last 60 s, and a value is at most 4,194,304 bytes. No same-key cooldown is documented. **Fallback**, if Beta shows throttling: skip the update when the score is below a cached tenth place, since the list only rises.
- **E3** Is `game.JobId` a string on a live server? Documented as a string (empty in Studio). `runId` turns anything else into `""`, and `adapters.spec` pins that the job id reaches the id.
- **E4** Prototype (`R0044/experiments/prototype.patch` on `origin/main` fa9cc9bc, which includes R0034/f0065; revised after design reviews 001 to 005): all 80 sequestered cases pass. Format, lint, both type checks and both builds pass. On the affected gate exactly seven promoted cases fail (listed under Regression guard), and every other selected case passes. `promote-check R0044` is OK there and on `origin/main`.
- **E5** With c0128's narrowing prototyped (`R0044/experiments/c0128-narrowing.patch`, the c0128 Solution bullets) beside the prototype, `f0024/adapter` and `f0026/adapters` pass (35 cases), and the narrowed files also pass on `origin/main` without the prototype (35 cases). `scripts/check.sh --full` on the prototype with that patch: see the Verification log.

## Acceptance criteria

### Checked
- **AC1**: the all-time top-10 list of runs keeps the ten best runs of all players in order (score, level, earlier run, id), lets one player hold several places, lists each run id once, and starts from the stored per-player bests.
- **AC2**: Hiscores.driveTop writes a run to the list through the store's transform with drive's retries and budgets, merges every per-player best (its companion row, deduped by run id) on each write, never creates a list without them, and reports the run's place, that it missed the top N, or nothing.
- **AC3**: one player's two runs in a row, the second lower, are heard as places 1 and 2, and the lobby's all-time answer lists both in order.
- **AC4**: game over shows the run's place on the list or "NOT IN THE ALL-TIME TOP 10", through Ranks and FlowView.
- **AC5**: the lobby's all-time answer is the stored list (or the per-player board while none is stored) plus the asker's own best, read at most once per CACHE_TTL per player and never twice at once, and dropped when they leave; day and week are unchanged and carry no best.
- **AC6**: HiscoreStore writes the per-player boards first and hands their all-time bests to the list, keys each run by user, clock, run and job id, hears the list's place, and still writes the per-player boards when the list fails.
- **AC7**: the existing hiscore, flow and lobby specs still pass.

None.

- **O2** (Beta, once the list holds ten runs): a run below the tenth shows "NOT IN THE ALL-TIME TOP 10", and TODAY and THIS WEEK still show one row per player and no best line.
