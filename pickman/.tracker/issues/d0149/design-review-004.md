### F1 [high] "A held thumb by its timer, by finger id" passes AC3 with the wrong finger: a timer that promotes the newest look finger, or ids reused after focus loss, kills the second tap of a double tap
Where: prototype `src/client/Controls.luau:224-233` (the `task.delay` callback's `id`) and `:130`, `:252` (`lastId`, `ids = {}`); d0149.md Design, Controls ("ids are never reused, so a finger lifted … is simply not there"); `check.sh` AC3 label ("a held thumb by its timer, by finger id"); Rules and mutants (no row for "the timer is for its own finger" or "ids are never reused").
Evidence: two mutants of Controls' source, each run against the 22 sequestered adapters cases plus two probe cases:
- X1, the timer holds the newest finger (`Touch.hold(fingers, lastId, controlsNow())`; the same as a shared `lookId` upvalue set on each look press, a natural "the look finger" variable): **all 22 sequestered cases pass**; the probe "a tap (down 100.0, lift 100.1), then a second look finger down at 100.15; the first timer runs at 100.27; the second lifts at 100.3" expects no point and two hops and fails (`expected 0, got 1`: the first finger's timer promoted the second, which then never hops and swings the view a quarter turn right).
- X2, ids restart after focus loss (`lastId = 0` beside `ids = {}`): **all 22 sequestered cases pass**; the probe "look finger down at 100.0, focus lost at 100.05, a new look finger at 100.1 (id 1 again), the old timer runs at 100.27, the new finger lifts at 100.3" fails (`expected 1, got 2`: the old timer promoted the new finger 0.17 s after it went down; no hop).
The sequestered timer cases each have one look finger at a time, or fire the stale timer before the next finger goes down ("a timer firing after focus was lost or the controls moved…" calls `fireTimers()` before `down(2, …)`), so no case has a second finger in the fold when an old timer fires. In play this is a double tap of jump: the second tap lands within 0.25 s of the first press, and X1 turns it into a look.
Critique: the design rests on two facts it states but no case pins: the callback names its own finger, and an id is never handed to a later finger. This is the second hole in the timer mechanism (round 3 found the snapshot; this round the identity). The tempting fix is one double-tap case; X2 enters by a different path (focus loss), which the double tap doesn't reach.
Consequences: the cases need a second look finger in the fold when the first one's timer fires, once after a lift and once after a focus loss (and the re-layout path: `forget()` keeps `ids`, so it can't reuse one, but a variant that also clears `ids` there and resets `lastId` would; one case covers it with the same shape). No new user decision. If the author would rather make the identity pure: Touch.track could emit `{ kind = "wait", id, seconds = TAP_SECONDS }` on a look press and Controls schedule `Touch.hold` with that effect's id, so fold.spec pins "the wait is for this finger"; the adapters cases below are still needed for the scheduling and the id counter.
Recommendation: add adapters cases (a) "a double tap on the look circle hops twice: the first tap's timer never promotes the second finger" (the X1 probe above, with absolute clock values, since `100 + 0.1 + 0.05 + 0.1` is not `100.25` in floating point and the stub's `at <= now` misses it); (b) "after focus loss a new finger's tap still hops: the old timer never promotes it" (the X2 probe); (c) the same as (b) with `relayout(moved)` and a touch on the moved controls instead of the focus loss. Rules rows: "the timer holds its own finger" (X1, killed by (a)); "ids are never reused, even after focus loss" (X2, killed by (b)); run both through mutants.py. Correct AC3's wording if it changes.
Lesson: pickman-arch/timers-read-live-state
