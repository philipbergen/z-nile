### F1 [high] The timer reads the fold before it checks for a re-layout, so a still thumb's timer brings back a finger the re-layout let go, and it points from the moved circle (the prototype ships it; no case catches it)
Where: prototype `src/client/Controls.luau:230` (`fingers, promoted = Touch.hold(fingers, id, controlsNow())`); d0149.md Design, Controls ("folds `Touch.hold(fingers, id, …)` on the fold as it is when the timer fires"; "When `buttons()` returns controls in other places … it first lets every finger go … the fingers still down stay unheard until they lift"); AC3 ("lets every finger go when the controls move"); Rules and mutants (no row for the timer's re-layout check).
Evidence: Luau evaluates the call's arguments left to right, so `fingers` (the old fold, holding finger 1) is read before `controlsNow()` runs `forget()`, which empties the fold and sends `point(nil)`; `Touch.hold` then promotes finger 1 against the moved circle, and the assignment writes the old fold, with finger 1 looking, back over the emptied one. Probe, on the unmutated prototype: look finger down at `L.x + 0.6 r` (right of the centre); `relayout` with the look circle 40 px to the right of the thumb (no touch event between, as for a still thumb when the top bar appears or the screen turns); clock += `TAP_SECONDS`; `frame()`. Output: points `{ "nil", 1 }`: the view is let go, then swung a quarter turn left by a thumb that never moved. A move of 2 px afterwards points again (`1`): the finger is back in the fold and steers the view from the moved centre until it lifts (review 001 F7's phantom, by the timer's path). The 24 sequestered adapters cases pass: every re-layout case sends a touch event (`down(9, 1, 1)`, `down(2, …)`, `move(1, …)`) before the timer runs, so `forget()` has already happened through `onInput`, which reads `controlsNow()` before `Touch.track` (the right order). The same probe also fails the mutant Y1 (the timer passes `buttons()` directly and skips the re-layout check), which no case kills either.
Critique: the executor builds from `prototype.patch`, so this ships. It is the third hole in the timer path (round 3: the press-time snapshot; round 4: the finger's identity; now the order against the re-layout), each from the callback being a second entry into the fold that repeats `onInput`'s prelude by hand. The tempting fix is to swap the order on that one line; the next edit to either path can split them again.
Consequences: one shared step removes the duplication: `onKnobs` after the timer's effects comes for free (today the timer doesn't call it; harmless now because a hold moves no knob, but a later effect that does would be missed). No new user decision; no change to Touch.
Recommendation: in the Design, give Controls one function that every fold goes through, e.g. `local function step(fold: (Touch.State, Touch.Context) -> (Touch.State, { Touch.Effect }))`: `local ctx = controlsNow()` first (it may let every finger go), then `fingers, effects = fold(fingers, ctx)`, `apply(effects)`, `onKnobs(Touch.knobs(fingers, ctx))`; `onInput` calls it with `Touch.track` and the timer with `Touch.hold`. State the order in the Design sentence ("reads the controls, letting every finger go if they moved, before it folds"). Add an adapters case: "a re-layout before a still thumb's timer fires lets it go: the timer points nothing, a later move of that thumb points nothing, and its lift does not hop" (the probe above, with the circle moved so the thumb lands on the other side of the new centre, and asserting no non-nil point after the `forget`'s nil). Rules rows: "the timer checks for a re-layout before it folds" (mutant Y0: the prototype's order, `Touch.hold(fingers, id, controlsNow())`; Y1: `buttons()` without `controlsNow()`), both run through mutants.py and killed by the new case; fix the prototype and regenerate prototype.patch.
Lesson: pickman-arch/folds-reset-when-their-source-changes, pickman-arch/timers-read-live-state
