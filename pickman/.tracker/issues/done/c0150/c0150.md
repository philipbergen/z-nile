# c0150: Narrow key-map and hop-camera pins

## Problem
f0126 (risky wall picks) adds a pick key and a longer hop, and two promoted specs pin the code as it is today, so its sequestered specs cannot land while they stand (z-design, Override check). Promoted specs are never edited during execution, so a chore must narrow them first, keeping `main` green.

- **`pickman/tests/acceptance/f0104/keys.spec.luau`** pins the desktop key map as exactly ten keys (`n == 10`), and lists `F` among the keys that "do nothing". The user chose a new pick key (2026-10-25, f0126: "A new pick key"), which f0126 binds to **F**.
- **`pickman/tests/acceptance/f0101/place.spec.luau`** pins the camera's eye as `View.SCALE.eyeHeight + Hop.rise(hopped, <shown>)`, a call with exactly two arguments. f0126's "longer jumps" boon makes a hop last longer (the user's default, 2026-10-25: "airborne time x1.5, for the rest of the level"), so the camera must pass the hop's length to `Hop.rise` as a third argument.

What should happen: each spec is narrowed to what it was written to protect, so that f0126 can add the F binding and the length argument without a red `main`: the ten f0104 bindings are still pinned, `F` is no longer required to do nothing, and the camera's eye is still `eyeHeight + Hop.rise(hopped, shown…)` at the tick being shown, in one CFrame, with optional further arguments.

## Non-goals
- The pick key and the longer hop themselves: f0126.
- Any other promoted spec.

## Solution
- In f0104's `keys.spec`, keep every pinned binding and the frozen map, require at least the ten keys rather than exactly ten, and drop `F` from the list of keys that do nothing (the other names stay).
- In f0101's `place.spec`, let the `Hop.rise` pattern accept further arguments after the shown tick, and keep everything else the case checks.

## Design
### What f0126 does to the two specs, case by case
f0126 (risky wall picks) binds **F** to `"Pick"` in `View.KEYS` (the user's "A new pick key", 2026-10-25) and passes the hop's length to `Hop.rise` in the camera (`Hop.rise(hopped, shown, hopTicks)`, for its "longer jumps" boon). Against its prototype (f0126 `experiments/prototype.patch`, E2 here) the specs as on `main` fail three cases:

| spec :: case | after f0126 | change here |
|---|---|---|
| f0104 `keys.spec` :: maps exactly the ten keys | `View.KEYS` has eleven keys; the loop asserts every key is one of the ten | rename "maps the ten keys, and may map more"; the `want` loop checks each of the ten through `View.action` **and** `View.KEYS[key]` (the table Controls binds); the loop over `View.KEYS` counts (`n == 10` becomes `n >= 10`) and checks that any key beyond the ten binds an action none of the ten use and that is not a movement intent |
| f0104 `keys.spec` :: other keys do nothing, the old drop and fire keys included | `F` is bound | drop `"F"` from the list; `Q`, `e`, `space`, `w`, `Return`, `LeftShift`, `KeypadEnter` and `""` stay unbound |
| f0101 `place.spec` :: the eye is the standing height plus Hop.rise at the tick being shown | the call has a third argument | the pattern's `%s*%)` after the shown tick becomes `%s*[,%)]`; the captured tick must still be `View.shownTick(prev, snap, View.alpha(os.clock() - arrived))`, and the camera still has exactly one `camera.CFrame =` |

Each file's header gains a "Narrowed by c0150: …" line saying what is no longer pinned and why, so nobody restores it. The other cases of both files are unchanged: f0104's "the arrows and Space no longer move or snap" and "the map is frozen", and f0101's Main, Camera, GhostView and MazeView cases. `experiments/narrowing.patch` is the exact change.

Nothing in `src/` changes.

### What the narrowed specs still limit f0126 (and later keys) to
`W A S D Space E` and the four arrows keep their actions, in `View.action` and in `View.KEYS` alike; any further key binds an action of its own (not one of the ten's, not a movement intent: f0126's `F = "Pick"`); `Q`, `e`, `space`, `w`, `Return`, `LeftShift`, `KeypadEnter` and `""` stay unbound; the map stays frozen. The camera's eye is still `eyeHeight + Hop.rise(hopped, <the shown tick>, …)`, in one CFrame.

### Scalability
No runtime change. The digest spec reads two files and hashes them (well under 0.1 s).

### Maintainability
`acceptance/narrowed.spec.luau` pins each narrowed file whole by the SHA-256 of its exact text (the zz-test lesson narrowing-pins-the-whole-file), with item ids masked (a compaction) and CRLF made LF, and nothing else tolerated: a newline ends a line comment and the spaces inside a string are part of what it asserts, so collapsing whitespace would let a check be joined into a comment or a string's meaning change unseen (design review 001 F3). `stylua` leaves the narrowed files as they are, so the executor's formatting pass changes nothing; a future `stylua` that reformats them turns this spec red, which a chore then answers. It reads the files as text, so only `--full` selects it, and its header says any later change to either file must update the digests (the c0103 arrangement). A digest rather than a golden string keeps the spec short for a 100-line file; a failure says only "changed", and the file's own git diff says how.

### Usability
Developer: f0126 can land without editing a promoted spec, which an executor may never do.

## Unknowns & experiments
- **E1 (run in prep: PASS)**: the narrowed specs (`experiments/narrowing.patch`) pass on `main` at 99c5493a: 9 cases in the two files.
- **E2 (run in prep: PASS)**: on f0126's prototype (F bound, `Hop.rise(hopped, shown, hopTicks)`) the specs as on `main` fail 3 cases and the narrowed ones pass all 9. So exactly this narrowing lets f0126 land.
- **E3 (mutation check, run)**: `experiments/mutants.py` clones the repository into a fresh `$TMPDIR` folder, applies the patch there and runs each mutant in the clone. All 15 are killed on an assertion. Edits to a narrowed file, against `narrowed.spec`: N1 the count weakened to `n >= 4`; N2 a binding (`E = "Fire"`) dropped; N3 `F` asserted unbound again; N4 the unbound check emptied; N5 the frozen case defanged; N6 the camera pattern widened to `.-([%w_]+)`; N7 the one-CFrame count weakened; N8 code hidden after a `--[[ ]]` comment; N9 a check joined into the comment above it; N10 the spaces inside a string changed; N11 the `View.KEYS` check dropped. Code mutants, against the two narrowed specs (what the narrowed assertions must still catch, design review 001 F1, F2, F4): K1 `View.KEYS` exported as another table (F1 to F10 all "Fire") while `View.action` reads the real one; K2 an extra key bound to `Forward`; K3 an extra key bound to `Jump`; K4 the eye at `snap.tick` instead of the shown tick. Without the patch (on `main`), the two digest cases fail and the first case passes.
- **E4**: the digest uses `@lune/serde`'s `hash("sha256", …)`, present in Lune 0.11.1 (`rokit.toml`); checked by running it.
