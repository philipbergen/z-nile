### F1 [low] AC1 and AC2 run the same spec file whole, so each reports the other's failures under its own label
Where: `check.sh` AC1 and AC2 (both `lune run tests/run -- "$A/narrowed.spec.luau"`); c0159.md Test plan and Acceptance criteria.
Evidence: mutant N1 (f0102's `.Rotation` assertion deleted) fails only "each changed file is exactly the narrowed one" (mutants.py output above), and `check.sh` then prints `FAIL AC2: every case of the three specs passes on today's DangerHud, on one that draws f0158's ring …`, which is not what failed. The other way round, a broken ring regression prints `FAIL AC1: … exactly the narrowed ones (each pinned whole)`.
Critique: no wrong implementation passes, because both lines are red together. But a `check.sh` line whose label isn't what its command checks points the executor at the wrong part of the work. The tempting fix is to split the spec into a pins file and a ring file. Done naively, that loses the selection: a pins spec that only reads text is selected by `--affected` only through `--full`, while today's one file requires the three specs and so is selected whenever they change.
Consequences: the split needs the pins file to `require` the three spec modules just to stay selected. That is extra machinery for a label.
Recommendation: keep one spec file and make it one criterion. Replace AC1 and AC2 with a single `check "AC1: d0105's, f0033's and f0102's specs are exactly the narrowed ones and still run by their check.sh files, and every case of them passes on today's DangerHud, on f0158's ring DangerHud and four correct variants, while five ring regressions each fail their case"` and renumber AC3 to AC2 in `check.sh`, Acceptance criteria and the Test plan. No spec change.
Lesson: z-design/spec-design-correspondence
