### F1 [medium] The bound case now stops at the classic tables, so nothing pins f0125's ghost bound on the shipped ramp's levels 22 to 34: a bound that still stops at `Levels.COUNT` passes every spec
Where: c0177.md Design, "The bound case" (and Solution bullet 4); `narrow.patch` hunks `@@ -177` and `@@ -192` (`fast.ramp = nil`, `double.ramp = nil`); the Overrides line ("the too-fast bound").
Evidence: mutant Y3 on the ramp clone changes Session.new's ghost-speed loop `for level = 1, if c.ramp then c.ramp.top else Levels.COUNT do` to `for level = 1, Levels.COUNT do`. The narrowed speeds.spec passes 9/9, f0147's ramp.spec 14/14 and levels.spec 21/21. Every game spec that loads Session passes too: the 186 acceptance (`f*`, `d*`) and unit specs from `lune run z-nile/affected -- pickman/src/shared/Logic/Session/init.luau`, run with f0147's ramp and levels specs (188 files), give 1371 passed and 0 failed. The mutant is not academic. `GAME_CONFIG` with `ghostTuning = 1.25` has a hunting ghost of 123 units on level 34 and 65 on level 21. The prototype refuses it and Y3 accepts it. f0147 states the rule (Behaviour 10, and its Regression guard: f0125's "tuning bound runs to the ramp's top"). Its M37 covers only the player's bound (`far.top = 35`). f0125's bound case was the only one that tested the ghost bound, and the narrowing takes it off the ramp. Y3 is also the likeliest wrong f0147: keep f0125's `checkGhostSpeeds` (`for level = 1, Levels.COUNT do … Session.speeds(c, level)`) and pass the ramp through `Session.speeds`, the "one line" f0147's Regression guard describes.
Critique: Keeping the classic bound is right, and the capture asks for it. But f0125's rule (its design review 001 F3) is "on any level and kind", and on the shipped config that now means up to the ramp's top. The narrowed file runs every other f0125 rule over `levelsOf(GAME_CONFIG)` levels, but not this one. The tempting fix is to keep the ramp on `fast`. That fails: with the ramp, base 96 is refused by the player's bound at level 34, so `fast` would be refused for the wrong reason and `untuned` would turn red.
Consequences: a case on the ramp can only run after f0147. Before f0147 it must not run, because the classic tables accept tuning 1.25 (level 5's ghost is 45), so AC2 on main runs the empty branch. The proof that it kills Y3 is on the ramp prototype (E2), and f0147's AC5 runs it again. A number tied to `Levels.RAMP` (top 34, step 1.05) would drift if the ramp is retuned. Asserting the reason (under a tile on `Levels.COUNT`, over a tile on the ramp's top) makes a retune fail loudly instead of passing for nothing.
Recommendation: after `double` in the bound case, add a branch read as loosely as `levelsOf` is: `if (Session.GAME_CONFIG :: any).ramp then local high = table.clone(Session.GAME_CONFIG) :: any; high.ghostTuning = 1.25; t.expect(Session.speeds(high, Levels.COUNT).ghost <= 120).toBe(true); t.expect(Session.speeds(high, levelsOf(Session.GAME_CONFIG)).ghost > 120).toBe(true); t.expect((pcall(Session.new, classic, 1, high))).toBe(false) end`, with a `-- c0177:` comment. It passes on the prototype (34: 123, 21: 65, 1.2 at 34: 118), and Y3 turns the case red. Then re-cut `narrow.patch`, the digest and step 2's line counts, and keep the `.ramp = nil -- ID:` count at 2. Add the row "the ghost bound covers the ramp's top | speeds :: 'a ghost tuning that would move a ghost more than one tile a tick is refused…' | Y3 (ramp): the ghost bound loops to `Levels.COUNT` | run". Re-run E2, E3 and E4, and say "on the classic tables and up to the ramp's top" on the Overrides line.
