## Problem
f0020–f0023 make ghosts real in Logic, but nothing draws them. Without this the player is chased by invisible enemies. The snapshot from f0013 carries only the player.

## Non-goals
- Ghost behaviour (f0020–f0023). Awareness aids for ghosts out of view (f0033). Sound. Art polish beyond a clear, readable look.

## Solution
The ghosts join the replicated snapshot and frame; `View` interpolates them the way it interpolates the player; a thin client adapter draws one model per ghost, coloured by its look.

## Design
### Files and API
- `src/shared/Logic/Session/init.luau`: `GhostSnapshot`, `Look`, `Snapshot.ghosts`, `Frame.ghosts` (the per-ghost `jumpTick` they report is recorded by f0023's wiring).
- `src/shared/Logic/View/init.luau`: `View.interpolateGhosts`.
- `src/client/GhostView.luau` (new) and `src/client/Main.client.luau` (wiring).
```lua
export type Look = "normal" | "frightened" | "blinking" | "eyes"
export type GhostSnapshot = { name: Ghosts.Name, x: number, y: number, heading: Heading, look: Look, flash: boolean, jumpTick: number }
Snapshot.ghosts: { GhostSnapshot }?      Frame.ghosts: { GhostSnapshot }?      -- present only when the session has ghosts; the snapshot version stays 1
View.interpolateGhosts(prev: Snapshot?, latest: Snapshot, alpha: number): { { x: number, y: number, heading: Heading, look: Look, flash: boolean } }
GhostView.push(snap)   GhostView.start()                                      -- the client adapter
```
- **Snapshot**: the ghosts in `Ghosts.NAMES` order; `x, y` from `Ghosts.position` (tile coordinates plus progress); `heading`; `look = Ghosts.look(set, g)`; `flash = Ghosts.flash(set)` and the ghost itself is `blinking` (so a revived ghost among blinking ones carries no flash); `jumpTick` is the tick the ghost last wrapped through a tunnel or was reset (-1 if never). The `ghosts` key is absent for a session without ghosts: a ghost-less snapshot has exactly the keys `v, tick, maze, player`, as before. `Session.frame` carries the same list beside `play` ("a client ignores fields it doesn't know"). Four ghosts are about 390 bytes of JSON per step (measured), which is 15 times a second.
- **`View.interpolateGhosts`**: for each ghost in the latest snapshot, blend `x, y` from the previous snapshot's ghost *at the same index and name* by `alpha` (clamped to 0..1, NaN as 1) unless the ghost jumped after the previous snapshot (`jumpTick > prev.tick`) or there is no older snapshot or the lists do not line up, in which case it is shown where it is; heading, look and flash come from the latest snapshot.
- **`GhostView`** (adapter): one `Model` per ghost (a body block of 6 x 7 x 6 studs, taller than the 4-stud eye height so a ghost shows over the pellet row, with two eyes and pupils on the front face so a ghost coming toward the player reads differently from one moving away), built lazily from the first snapshot; each frame (`BindToRenderStep`) it blends through `View.interpolateGhosts(prev, snap, View.alpha(os.clock() - arrived))`, moves each model to `View.world(x, y)` facing `View.headingYaw(heading)`, and paints it: classic colours (red, pink, cyan, orange), blue while `frightened`, blue and white by `flash` while `blinking`, only the eyes (body invisible) while `eyes`. Neon material so it reads in a dark corridor. `GhostView.push` moves forward only on a newer snapshot, exactly as `Camera` does. It requires only `@game/ReplicatedStorage/Shared/Logic/Session` and `View`.
- **`Main.client.luau`**: `GhostView.push(snap)` beside `Camera.push(snap)` for every snapshot, and `GhostView.start()` beside `Camera.start()`.

### Pure/adapter split and authority
Everything that can be wrong (positions, looks, flashes, jumps, the blend) is Logic and specified. The adapter only sets `CFrame`, `Color` and `Transparency`. The server owns the ghosts; the client cannot affect them.

### Scalability
15 frames a second, four ghosts: 390 bytes each. Client cost: 4 models of 5 parts, anchored, updated per frame; `interpolateGhosts` allocates one small table per ghost per frame.

### Maintainability
A new look is a value of `Look` and a branch in `paint`; a fifth ghost is a name in `NAMES` and a colour. The blend rule is shared with the player's by design (`jumpTick`).

### Usability
Readable first person: ghosts are tall and bright, eyes show which way a ghost faces, blue means harmless, blinking white means "about to recover", eyes alone mean "safe, going home". Tunnels and resets cut instead of sliding.

## Acceptance criteria

### Checked
- **AC1**: every snapshot and frame carries the four ghosts (position, heading, look, flash, jumpTick) in a fixed order, and a session without ghosts is replicated exactly as before.
- **AC2**: `View.interpolateGhosts` blends by elapsed time, never across a jump, and takes look and heading from the latest snapshot.
- **AC3**: the ghost view is a thin client module that blends only through `View.interpolateGhosts` and is started and fed by the client entry point.
- **AC4**: every existing client, view and place spec still passes.
- **AC5**: the architecture rules hold (Logic is pure, every require declared in `tracker/architecture.md`, every feature has unit specs).

### Judged
None.

### Observed
- **O1** (Studio, on Beta, play a level): four ghosts are visible in the corridors in red, pink, cyan and orange, taller than the pellets and readable in the dark; after eating a power pellet they turn blue, blink white for the last seconds and recover; an eaten ghost shows only eyes and goes home; in the tunnel a ghost wraps without sliding across the maze. A failure is filed as a defect.
