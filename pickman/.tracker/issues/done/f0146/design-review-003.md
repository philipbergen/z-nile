### F1 [medium] Pads' "every input" isn't pinned for processed input: a Pads that skips `gameProcessedEvent`, the usual Roblox guard, passes every check, and on a device it would ignore the very buttons Controls binds
Where: §2 Pads ("It folds every `UserInputService.InputBegan` (magnitude 1) and `InputChanged` of a `Thumbstick1` or `Thumbstick2`"); controls.spec `w.input` (fires `began.fire(obj, false)` / `changed.fire(obj, false)` only); Rules and mutants (no row).
Evidence: on the scratch clone of proto-f0146, I changed both of Pads' handlers to `function(input: InputObject, processed: boolean) if processed then return end seen(...)`. Then `lune run tests/run -- .tracker/issues/f0146/acceptance/controls.spec.luau .tracker/issues/f0146/acceptance/place.spec.luau` → `8 passed, 0 failed, 2 spec files`. Roblox sets `gameProcessedEvent` to true for input that ContextActionService handled. Controls binds ButtonA, ButtonR2, ButtonR3 and the D-pad through `BindActionAtPriority`, so with that guard a second player's button presses never take over. If Roblox's default PlayerModule binds the left stick through ContextActionService as well, the stick's `InputChanged` arrives processed too, and the user's "most recent controller drives" fails outright. The prototype has no guard, so the defect waits for an executor who writes the common idiom. `grep -rn "gameProcessed\|processed" pickman/src` on the prototype finds nothing, so the repo has no convention that would steer them either way.
Critique: the Design says "every", but no case pins it, and the obvious implementation habit breaks it. The tempting fix is to say "processed or not" in the Design and stop there, which still leaves the habit uncaught.
Consequences: the stub's `w.input` takes a `processed` flag. No new rule: Pads ignores the flag. A note in the Design keeps a later edit from adding the guard.
Recommendation: add to §2 Pads: "processed or not (`gameProcessedEvent` is true for every button Controls binds)". Make one takeover step in controls.spec's Pads case fire with `processed = true` (Gamepad2's button, and a stick move). Add row P28 "Pads skips processed input" and run it. A source pin isn't needed.
Lesson: z-design/spec-design-correspondence; zz-arch/guard-what-the-engine-sees
