# Refute 001: f0145 (answers to design-review-001, changes)
The user decided one more reading of G10, recorded in the Problem and in G10: Decided with the user (2026-10-26): "Let them play free". A player the lobby let in because its read failed, whose arrival's write then says "buy", plays that one game free; any other "buy" arrival is sent back to the lobby.

- F1 [high]: fixed. `Session.leave(s, id)` (`Game.allowOffer(play, 0)` then `Game.decline(play)`) is called by `Sessions` on `PlayerRemoving` before parking, so a run left in the last dying pause, an open offer or a held one ends within `LEAVE_STEPS`. New `acceptance/runs.spec.luau` runs the real Sessions and Submits on a stub engine with three leave cases; offer.spec gains a Logic case. Mutants N1 (leave keeps the offer) and N2 (no call in Sessions) are killed.
- F2 [high]: fixed. `PromptProductPurchaseFinished` with `isPurchased` true calls `Session.awaitReceipt`: the offer stays held for at most `Game.RECEIPT_WAIT_TICKS` (450 steps, 30 s), then runs again, and a later receipt stays a held continue (G9). Not bought releases at once. E2 states the ordering. Cases: a close before the receipt then the receipt continues; no receipt resumes after the wait; not bought ends on time. N5 (release on any close) and N6 (never resume) are killed.
- F3 [high]: fixed. `testGrant` honours a confirm only for a test screen this server opened for that player and product (`pending`, cleared on confirm, `cancel` and leaving), and test mode has its own store (`Pay.TEST_STORE`, `Pay.store`). Cases: confirm with no screen (lobby and play place), confirm after cancel, test credits not visible to a live read; the lobby confirm case now opens its screen first. N7 and N8 are killed.
- F4 [high]: fixed. A play-place case confirms during the offer in live mode and checks no continue is granted or used. N9 (the play place granting the confirm directly) is killed.
- F5 [high]: fixed. The stub's `UpdateAsync` can write a competing value just before the transform and call the transform twice, the first time on the stale value. Cases: a receipt another server granted during the write counts once and is not handed on; an arrival racing another server's free start uses a held play. N10 (read then blind write) and N11 (first call's answer kept) are killed.
- F6 [high]: fixed, with the user's decision. `Pay.arrive(how, passed)`: a charge or a failed write plays; "buy" plays only with the lobby's pass (a MemoryStore entry the lobby writes when its read fails, taken once); otherwise the player is teleported back to the lobby with no offer. E1 is now a design rule, not an unverified setting. Cases cover the bounce, the failed write and the pass; N12, N14 and N15 are killed.
- F7 [high]: fixed. runs.spec pins the lives end to end: Submits' call carries them (N3, the sixth argument dropped, is killed) and HiscoreStore's real source writes them into the stored row (N4 is killed).
- F8 [medium]: fixed. `Pay.mode(raw, products)` is live only when both product ids are whole and positive; otherwise test mode, so nothing waits on a screen that cannot open. pay.spec and an adapters case (an ask with a missing id opens the test screen) pin it; N13 is killed.
- F9 [medium]: captured as f0169 (live-paid-play-publish: a live publish sets `PaidPlay`, `PlayProductId` and `ContinueProductId`; the Beta stays test). OC2 cites it.
- F10 [low]: fixed in the design. The claim is dropped: `Session.continue` returns the `Ready "continue"` event to its caller, and the adapter needs none of it because the frame shows the respawn. The design says so.
