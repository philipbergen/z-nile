### F1 [high] A lit dot is never 35% opaque: the farthest dangerous ghost draws at 50%, so the user's G5 "lit 35–85%" is drawn as 50–85%, and AC1 passes
Where: f0158.md The ring ("a lit dot's opacity from `min` (farthest) to `max` (nearest)"), G5, AC1 ("with the user's opacities"); prototype `Awareness.ring` (`brightness = … math.clamp(g.brightness, 0, 1)`); `Awareness.indicators` (`brightness = minBrightness + (1 - minBrightness) * closeness`, `DEFAULTS.minBrightness = 0.3`); acceptance/ring.spec.luau "only dangerous ghosts light a sector…" (hand-built indicators with arbitrary brightness).
Evidence: an indicator's brightness never drops below `DEFAULTS.minBrightness` (0.3), and a ghost beyond `maxDistance` (12) gets no indicator at all. The ring passes that brightness through, and DangerHud draws `lit.min + (lit.max - lit.min) × brightness`. In `review3-comb` I put one `"normal"` ghost on every open tile of `classic` (player at 13, 23) and printed the lit opacity by maze distance: `0 0.850 … 6 0.675 … 11 0.529 12 0.500`. Nothing is below 0.500. ring.spec builds its indicators by hand (`ind(index, sector, distance, brightness, look)`), so it never sees the real 0.3 floor. place.spec computes its expected opacity with the same formula, so it agrees with the 50% floor.
Critique: G5, which the user accepted, is "lit dots 35–85% opaque by closeness". `RING.lit.min = 0.35` is pinned, but no ghost ever produces it, so the faint end of the range the user agreed to is never drawn. The tempting fix is to change the Design's words to "50–85%". That changes a user decision without asking.
Consequences: the ring needs a closeness of 0..1, not the glows' brightness. Taking closeness from `distance / Awareness.DEFAULTS.maxDistance` ties the ring to the cutoff the indicators use, since DangerHud passes no `maxDistance`. Un-mapping `(brightness - minBrightness) / (1 - minBrightness)` ties it to `minBrightness` the same way. Either way `RingDot.brightness` changes meaning (ring.spec's brightness case, the Design's `RingDot` text, place.spec's comment), and the clamp stays for a distance beyond the cutoff or a negative one.
Recommendation: `Awareness.ring` lights a sector at the nearest dangerous ghost's closeness, `1 - clamp(distance / Awareness.DEFAULTS.maxDistance, 0, 1)` (or the un-mapped brightness: pick one and name it in the Design), so the drawn range is exactly 35–85%. Add a ring.spec case built from the real `Awareness.indicators`, not hand-built indicators: a dangerous ghost at maze distance 12 gives brightness 0 (opacity `lit.min`), and one on the player's tile gives 1 (`lit.max`). Add a Rules row "the farthest lit dot is `lit.min`, the nearest `lit.max`" with the mutant "the glows' brightness passed through (today's prototype)". If the author would rather keep 50–85%, escalate to the user: that is a change to G5.
