# f0186: Boards show revives

## Problem
The user, 2026-10-31: "the same cost model remains but it shoudl show 5 robux for each game witha slash through showing it is currently on sale for 1 robux. highscores shoudl show how many revives were used." Asked, the user chose: **every board, pickman's included, shows revives used** (instead of f0145's "lives spent"), and **the free game is one per hour per game** (pickman's free hour is independent of Snake's, Invaders' and Asteroids').

This changes f0145 (Paid play and continues), which is being prepared in another session; it is captured here rather than edited into f0145 mid-prep. What should happen in pickman:
- **Revives on the boards:** a hiscore entry records how many paid revives (continues) the run used, and the boards (and game over) show it; a run with none shows as such. f0145's "lives spent" figure is replaced by this.
- **Free game per game:** pickman's one free game per hour is pickman's own; playing another arcade game doesn't use it.
- **The price shows as 5 R$ struck through, on sale for 1 R$**, wherever pickman shows the play price (the charge stays 1 R$).
- Everything else in f0145 stays: 1 R$ per game after the free one, a revive is 3 new lives for 1 R$, playtests never charge.

## Non-goals
- The shared code itself (hiscores with revives, paid play and receipts in the `arcade` library): arcade issues captured after c0183. This issue is pickman's use of them.
- The portal's cards and boards: portal issues.

## Solution
- If f0145 has not landed its design yet, its prep can absorb this issue (with the user's word); otherwise this is the follow-up that switches the figure.
- Old entries without the field show as no revives.
