# f0187: Game over returns to portal

## Problem
The user, 2026-10-31: "I also want a new project for a landing portal where you can scroll between the games and see the highscores for each". Asked, the user chose one Roblox experience whose start place is the portal, which replaces pickman's lobby place.

Today pickman's game over waits for a tap and teleports back to the lobby (`Returns.luau`, the `LobbyPlaceId` attribute, `ToLobby` and `LobbyStatus` remotes, `Logic/Flow`). What should happen: game over returns the player to the portal (`PortalPlaceId`, set by the N-place publish), with the same overlay, wait and retry rules, and the overlay's wording names the portal (or "the arcade") rather than the lobby.

## Non-goals
- Deleting the lobby place: c0188.
- The publish that writes `PortalPlaceId`: the portal's N-place deploy issue.

## Solution
- Rename `LobbyPlaceId` to `PortalPlaceId` (and the remotes), keep `Logic/Travel`'s rules; once arcade's Travel exists, use it.
