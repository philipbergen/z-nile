Keep titles.spec only if it gives a clearer failure message. ### F3 [medium] c0128's specs name `f0024` and `f0026` literally behind the split path, so the next compaction leaves them pointing at missing files
Where: `titles.spec.luau` and `guards.spec.luau`, `local F24 = ROOT .. "f0024/adapter.spec.luau"` and `F26`
Evidence: `scripts/tracker/compact.luau:42-59` moves every `tests/acceptance/<old>` folder and rewrites only `tests/acceptance/<id>` paths in other files. The two-part spelling (testing skill, "Survive a compaction") stops that rewrite. That is the point of the two parts, but these specs read the real folders, so after a compaction that renumbers f0024 or f0026, `fs.readFile` fails and `scripts/check.sh --full` goes red. The precedent narrowing specs map the id: `tests/acceptance/c0103/narrowed.spec.luau:14` and `c0063/narrowed.spec.luau:13` use `"tests/" .. "acceptance/" .. renamed.id("f0014")`.
Critique: this is a later defect that `promote-check` can't see. The tempting fix is to write the path in one piece. That breaks the skill rule and mixes up the two cases the rule tells apart.
Consequences: with `renamed.id`, any ids inside the pinned titles (for example "f0061's fake engine") are not rewritten in `.luau` files by a compaction, on either side, so the titles stay consistent. A golden (F1) must mask ids, as c0103 does.
Recommendation: build both paths as `"tests/" .. "acceptance/" .. renamed.id("f0024") .. "/adapter.spec.luau"` (and the same for f0026), require `@tests/lib/renamed`, and if F1 is adopted, mask ids in the golden.
