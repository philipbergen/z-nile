# R0095: Start on best level

## Theme
f0148 (Start on any level up to your best, size 450), alone: the server remembers each player's best level reached, the lobby offers the levels 1 to best (arrows either side of START, which says `START LEVEL n`), and the game place starts the run there. It is a raft of its own because it `depends_on` f0147, which is in R0094: grouping it with R0094 would make that raft depend on itself, and the planner left it apart.
Shared surface with R0094's members: `pickman/src/shared/Logic/Game` and `pickman/src/shared/Logic/Session` (f0147's `start` field and `Game.new`, `Session.speeds`), `pickman/.tracker/game-design.md` and `pickman/.tracker/architecture.md`.
User decisions quoted by the design: "3 rafts in order (Recommended)" (f0126, then f0147, then f0148); "Highest reached (Recommended)"; "Your best (Recommended)" for the picker's first choice; "No, keep rows as they are (Recommended)"; "Through the store (Recommended)" (the choice reaches the game place through the player's stored record, not the teleport); "Lobby now, portal later (Recommended)".

## Whole-raft design
One member, so no member-to-member interface. The interfaces it takes from outside the raft:
- **From f0147 (R0094)**: `Game.Game.start` (1 until f0148) and `Game.playAgain` starting on it; the extra life at `extraLifeScore x start`; `Game.new(config?, ramp)` (f0147) which f0148 extends to `Game.new(config?, ramp?, start?)`; `Session.speeds` and the ramp give each level's speeds; `Game.cleared` and `Ready reason = "level"`, which `Bests.reached` listens for. f0148's Design quotes these names and its prototype is built on f0147's; they agree with f0147's Interfaces (`Game.new(config?, ramp)`, `start: number`).
- **From f0145 (paid play and continues, being designed, `depends_on: [d0124, f0148]`)**: the other way: f0145 must land after f0148 and uses `Starts.start(allow?)` and `Sessions.made`. Not a dependency of this raft.
- **Architecture**: f0148 adds the `Best` row to `pickman/.tracker/architecture.md` and no new dependency edge (Lobby and Session do not require Best; the adapters do). No other raft-level change.

## Order & dependencies
One member: f0148. **R0095 must start after R0094 is done.** z-ready refuses it otherwise.

## Experiments phase
None at raft level; f0148 ran its own in prep (E1 to E7, a mutation check of 52 mutants). Its E6 (DataStore timing, the lobby's write against the game place's claim) and E5 (store calls in Roblox) are Phase 1 checks against a live place and are the member's.

## Exit criteria
`./zn done R0095` succeeds: RC0, which is pickman's gate (`--project pickman --affected`), f0148's check.sh and `promote-check R0095`. No raft-level RCn checks are added here.

## Risks & rollback
- **Waits on an unfinished chain**: f0147 -> c0176, c0177 (both `new`). Until they and R0094 are done R0095 cannot be readied.
- **f0148's prototype is built on f0147's prototype**, not on the landed code: if f0147 lands with a different `Game.new` or `Game.start` shape, f0148's executor re-reads it first (its Design names them) and stops and reports on a mismatch.
- **DataStore behaviour** (E6, E5) is proven only in Roblox; the fallbacks are in the design (`Bests.WAIT` to 20 s, a second key). A store that cannot be reached leaves the game as today (level 1, no picker).
- **Rollback**: revert the PR. The `Best` store is a new DataStore key, so a revert leaves stored records unread and harmless; the lobby returns to START GAME and the game place to level 1.
