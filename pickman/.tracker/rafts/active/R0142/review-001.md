### F1 [low] `View.runsKey` formats `-0` bounds from `View.walls` as `"-0"` instead of `"0"`, so numerically equal `Rect` bounds key differently
Where: `pickman/src/shared/Logic/View/init.luau:423` (`parts[i] = \`{r.x0},{r.y0},{r.x1},{r.y1},{if r.marked == true then 1 else 0}\``), together with `View.bounds` (`init.luau:143`, `y0 = -my`)
Evidence: A read-only Lune probe (`./zn run --time 60`) loading `Maze` and `View` on `classic` printed:
`first rect: -12 -0 39 -0`
`runsKey(first): -12,-0,39,-0,0`
`runsKey(+0): -12,0,39,0,0`
`equal? false`
Because `View.bounds` computes `-my` when `wraps(m, false)` is false (`my = 0`), every row-0 run returned by `View.walls(classic)` has `y0 = -0` and `y1 = -0` (and column-0 runs on a non-wrapping maze have `x0 = -0`). `c0228/acceptance/walls.spec.luau:261` already had to normalize `-0` (`{r.x0 + 0},{r.y0 + 0},{r.x1 + 0} -- + 0 turns a -0 bound into 0`), whereas `View.runsKey` interpolates the raw coordinates.
Critique: `MazeView` always feeds `View.walls(m, nil, marked)` on both `build` and `rewall`, so both sides see `-0` identically and no in-game redraw bug occurs today. Still, `View.runsKey` is a public `View` function whose contract (AC1) states that equal runs give equal keys; comparing `View.walls` output with a `Rect` literal constructed with `0` fails key equality even though `-0 == 0` is true.
Consequences: Adding `+ 0` to each coordinate (`r.x0 + 0`, `r.y0 + 0`, `r.x1 + 0`, `r.y1 + 0`) turns `-0` into `0` and leaves every other finite number unchanged; no existing spec or caller breaks.
Recommendation: Optionally normalize `-0` in `View.runsKey` (`{r.x0 + 0},{r.y0 + 0},{r.x1 + 0},{r.y1 + 0}`) and add a non-sequestered unit assertion in `pickman/tests/unit/View/marks.spec.luau` comparing `View.runsKey(View.walls(classic))` with `+0` bounds on row 0 (do not edit `c0228/acceptance/runs.spec.luau`). Candidate lesson (if desired, `when: both`): "Normalize `-0` (`n + 0`) when string-formatting coordinates derived from negated margins (`-mx`, `-my`) into equality keys; check: do `View.walls` row-0 / col-0 bounds format identically to literal `0`?"
