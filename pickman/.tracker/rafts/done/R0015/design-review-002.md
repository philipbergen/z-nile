### F1 [low] The cursor spec accepts an inverted condition: mouse free in play, locked at game over
Where: tracker/issues/f0031/acceptance/place.spec.luau:67-79; f0031.md:91 and AC3 (:210); Rules row F18 (:189)
Evidence: this render-step line passes every f0031 case: `UserInputService.MouseBehavior = if cursor then Enum.MouseBehavior.LockCenter else Enum.MouseBehavior.Default` (with `MouseIconEnabled = not cursor`). `MouseBehavior.Default` is present, `MouseBehavior = Enum.MouseBehavior.LockCenter` doesn't match (the text after `=` is `if`), and `MouseIconEnabled = false` doesn't appear. In play the mouse is then free, `GetMouseDelta` returns nothing and mouse look is dead; at game over the mouse is locked and the button can't be clicked. That is the exact failure round-1 F1 was about, with the polarity flipped instead of the condition removed. No Rules row lists it.
Critique: OC1 step 4/5 would show it on the first Play, which is why this is low and not medium. But AC3 as worded ("uses `MouseBehavior.Default` and has no unconditional `LockCenter`") is met by the wrong code, and the fix is one pattern.
Consequences: pinning the polarity pins the `if … then … else` form the design already prescribes (f0031.md:91). An executor who writes it as an `if` statement with two assignments would fail it, so the pattern has to allow both forms, or the design has to state the expression form as required (it already shows it).
Recommendation: add to place.spec's "Camera no longer locks…" case: `string.find(camera, "if%s+[%w_]+%s+then%s+Enum%.MouseBehavior%.Default%s+else%s+Enum%.MouseBehavior%.LockCenter")` is non-nil, and `MouseIconEnabled%s*=%s*not%s` is nil. State in f0031.md:91 that the expression form is required. Add the row "the cursor is free only when the flag is set | place :: Camera no longer locks… | F21 inverted condition | run".

### F3 [low] "slots returns a fresh copy" means a deep copy, but the documents say "a fresh list"
Where: tracker/issues/f0030/f0030.md:31, :43, AC1 (:169); acceptance/wire.spec.luau:62-72
Evidence: the case mutates an element (`first[1].x = 99`, `first[1].kind = "power"`), so `table.clone(cached)` fails it: the clone shares the slot tables, and `again[1]` comes back as `{ x = 99, kind = "power" }`. The design, the type comment and AC1 all say "a fresh list", which an executor will most naturally implement as `table.clone`. The spec is right (a shared element corrupts the wire order for every later encode just as the shared list would). The text is what's short.
Critique: it isn't a wrong implementation passing, just a likely wasted iteration in execution.
Consequences: a deep copy costs 244 small tables per `slots` call. `encode`/`decode` must therefore read the private cache, not call the public `slots`, or the 26 µs per frame grows. Say so.
Recommendation: reword f0030.md:31/:43 and AC1 to "a fresh list of fresh slot tables (changing it, or any slot in it, changes nothing)", and add "encode and decode use the cached slots directly" to the Pellets section. No spec change.
