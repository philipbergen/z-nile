### F1 [high] c0051 has no `Overrides:` line for the c0015 spec it changes
Where: tracker/issues/c0051/c0051.md, Regression guard (lines 68-70); tracker/templates/issue/doc.md:46 on `main`
Evidence: The prep branch forked at 078823d, before R0016 (55e94b3) added the Override check, the template's `Overrides:` line, and review item 4. The issue changes the pinned behaviour of `tests/acceptance/c0015/publish.spec.luau`: the case "any other failure is final" used to list 429, 500 and 503. The issue names that file only in a Solution bullet, and its Regression guard has no `Overrides:` line. The prep PR has to merge `main` before it lands (`git merge-tree` shows the merge is clean), and after that the issue no longer matches the template, and review item 4 counts a missing line as high.
Critique: The information is all there, but in prose rather than on the line that the Override mechanism, make-prompt and the next reviewer look for. The tempting fix is `Overrides: none`, because "prep already did the edit". That is wrong: the line records that this issue deliberately reverses a promoted spec's pinned behaviour, whoever makes the edit.
Consequences: c0051 is a chore, so it names S without a separate chore and without `depends_on`, per ticket-prep. Nothing else changes.
Recommendation: Merge `origin/main` into the prep branch. Then add to the Regression guard: `Overrides: tests/acceptance/c0015/publish.spec.luau ("any other failure is final": narrowed from 400/401/403/404/429/500/503 to 400/401/403/404 in this prep; c0051 is a chore, so it is changed in its own raft)`. Keep the Solution bullet, or shorten it to a pointer to that line.

### F2 [medium] Touched modules lets the executor edit promoted specs, and nothing would catch it
Where: c0051 Design, Touched modules (`tests/acceptance/c0051`, `tests/acceptance/c0015`); Solution "The executor does not touch it"
Evidence: execute-raft tells a stream to "edit only the issue's Touched modules". This list includes `tests/acceptance/c0015`, which contradicts the Solution's "the executor does not touch it". The code-mode sequestration check only diffs `tracker/**/check.sh` and `tracker/**/acceptance/**`. So if an executor widened or loosened a case in `tests/acceptance/c0015/publish.spec.luau` during execution (for example, dropping the `#naps` assertion to get a red AC7 green), the change would be inside its Touched scope and would pass the sequestration check. `tests/acceptance/c0051` doesn't exist until `tracker.sh done` creates it. It isn't the executor's to touch either.
Critique: Touched modules is the executor's edit permission. Prep has already made the edit, so listing the promoted directories now grants permission for something that should never happen in execution. The tempting fix is to drop only `c0015`. `c0051` should go too, for the same reason.
Consequences: The Affected specs line still has to show the selector input. Keep the paths there, where they describe what runs, not what may be edited.
Recommendation: Touched modules becomes `scripts/lib/opencloud.luau` and `.claude/skills/tracker/SKILL.md` only. Leave the `scripts/affected` invocation in Affected specs as it is. The `Overrides:` line from F1 carries the c0015 record.
