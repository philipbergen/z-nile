### F1 [high] narrowed.spec still passes when keys.spec asserts nothing: the needles pin the assertion lines, not what they loop over (repeat of design-review-001 F1, same mechanism)
Where: tracker/issues/c0103/acceptance/narrowed.spec.luau, cases "it keeps exactly its three cases …" and "it still pins the movement keys …"; c0103 Rules and mutants, E3
Evidence: I applied each mutant to the patched keys.spec in the scratch clone. narrowed.spec reported 4 passed, 0 failed for every one, and keys.spec still passed, so AC1, AC2 and AC3 were all green:
- MA: case 3's `{ "W", "A", "S", "D" }` becomes `{}`. The intent check never runs.
- MB: case 3's `for _, action in View.KEYS do` becomes `for _, action in {} do`. The `View.KEYS` needle is still met by case 1's count loop.
- MC: case 1's `for key, action in want do` becomes `for key, action in {} do`. W, A, S and D are never checked.
- MD: the unbound list is kept as a dead `local _ = { "w", "Return", "LeftShift", "" }` and the loop runs over `{}`.
- ME: `local n = 4`, with the count loop over `{}`.
- MF: case 3's W/A/S/D loop is wrapped in `if false then … end`.
Each needle matches one assertion line, and `cases()` counts `t.expect(` calls. Neither looks at the loop that feeds the assertion, so AC1's claim that the spec "still asserts W, A, S and D, the unbound keys and the shape of the map" can be met by a spec that asserts none of them. None of M1 to M12 covers this.
Critique: Round 1 found the same hole one level up (weakened assertions). The fix added needles for exactly those mutants, and the tempting fix now is to add needles for the six loop headers and forbid `if false`. That is whack-a-mole, and there will be a round 3 (`while false do`, `do return end`, a shadowed `View`, …).
Consequences: The mechanism, a set of independent substrings in a 40-line file, can't express "this assertion runs over these keys". A more exact pin makes every edit of keys.spec fail narrowed.spec. narrowed.spec's header already requires that (any later change to keys.spec must update it), and f0104 is now forbidden to edit keys.spec, so no new rule appears. It must survive `stylua` and a compaction.
Recommendation: Pin the narrowed spec's whole code as a golden text. Normalise it by stripping comments (as `code()` does), collapsing every whitespace run to one space, and replacing ids (`%f[%w][fdcR]%d%d%d%d%f[^%w]`) with `ID`. Then compare it with `toBe` against a literal held in narrowed.spec (the normalised text of the patched file). Keep `cases()` and the "gone" check as readable diagnostics, and drop the "kept" needle list, which the golden subsumes. Add MA to MF as mutants M13 to M18 in Rules and mutants, run them like E3, and re-run M1 to M12. Also check that the golden still matches after `stylua tests/acceptance/f0014` and after reflowing the file (for example, splitting the `want` table differently), so formatting alone can't turn it red.
