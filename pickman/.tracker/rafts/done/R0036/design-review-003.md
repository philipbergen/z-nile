### F1 [high] narrowed.spec breaks `tests/meta/architecture.spec` once promoted, so RC0's promote-check fails and `tracker.sh done R0036` can never succeed
Where: tracker/issues/c0103/acceptance/narrowed.spec.luau:22 (`string.find(line, "require(", 1, true)`); scripts/lib/graph.luau:29 (`REQUIRE_PATTERN = "require%(%s*[\"']([^\"']+)[\"']"`); tracker/rafts/R0036/check.sh (promote-check line)
Evidence: `scripts/tracker.sh promote-check R0036` → `FAIL tests/meta/architecture.spec.luau :: every require resolves … tests/acceptance/c0103/narrowed.spec.luau: require(", 1, true) == nil then … table.concat(kept, ")` and then "promoted acceptance specs would break tests/". The string literal `"require("` is followed by its own closing quote, so the static require scanner reads it as `require("<junk>")` and fails to resolve it. `tracker.sh check c0103` and `--full` stay green because nothing scans `tracker/`, so the defect shows up only at RC0. The executor can't edit a sequestered spec, so execution would stop and escalate. Round 1 ran promote-check before the golden rewrite. Neither round 2 nor its refute re-ran it.
Critique: The tempting fix is the one-character change to `"require%("` (pattern, not plain). I applied it in the scratch clone: promote-check OK, narrowed.spec 2/2 pass.
Consequences: Any literal in narrowed.spec that contains `require(` followed by a quote does the same thing. That includes the GOLDEN, if F2's fix adds the require lines to it.
Recommendation: Fix it together with F2: remove the require-line filter entirely, which removes the literal. If the GOLDEN then holds require lines, split each one so `require(` is never directly followed by a quote (`'local View = requ' .. 'ire("@logic/View")'`). Make it a prep rule for this spec: re-run `scripts/tracker.sh promote-check R0036` after every edit to narrowed.spec, and record the result in E3.

### F2 [medium] The golden ignores require lines, so keys.spec can test a stub instead of `View` or `Movement` and still pass AC1 to AC3

Recommendation: Drop the require filter and add the three require lines to the GOLDEN (split as F1 says). Add mutants M18 (View required from a stub) and M19 (Movement required from a stub) to Rules and mutants and to E3, and run them. Also re-run M1 to M17 and promote-check.
