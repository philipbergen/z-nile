# Response to design-review-001

- F1: fixed: the list now merges the per-player bests on every write, not once. `drive` runs first, as today, and its own all-time read (`DriveResult.rows`, added, read before and thrown away) goes to `driveTop(top, io, run, bests, policy)`, which reads nothing itself. The transform adds the run, then each best as `best:<userId>:<score>:<level>` at 0 unless a listed run of that player covers it (a higher score, or the same score at the same or a higher level), and writes nothing when the ids in order would not change. A list is never created without the bests (no list and an unreadable board: nothing is written, nothing heard, which also keeps f0024's pinned "no rank is heard when the board cannot be read"). `seedRuns`, `needSeed` and the seed read are gone; `bestRun` and `mergeRun` are new, and `addRun` is `mergeRun` with no bests. Consequences: the write order flips (the per-player boards first), so the "list before the per-player boards" case is now "the per-player boards are written before the list, and a first run that is a new best is listed once" (the cover rule makes it hold); new cases: `drivetop` "a best stored without the list (an older build) joins an existing list", "a run that is the player's new best is listed once", "an existing list takes the run even when the bests could not be read", "no list and no bests"; `top` "merging adds each best …", "a best that the run itself, or a better listed run …" (including the same score at a lower level), "a raised best joins beside …", "addRun is mergeRun with no bests"; `adapters` "a best written by a build without the list joins the list on anyone's next run". Rows and mutants: best-id-no-score, best-at-now, no-merge, store-no-bests, merge-ignores-cover, cover-ignores-level, cover-any-run-of-player, create-without-bests, write-when-unchanged, store-top-first. No user decision changes: "Keep them as entries" now covers rows written after the list exists as well. c0128's narrowing is unchanged (the per-player updates stay six); its Problem's quoted `got 8` would now read `got 7`, noted in R0044's Order & dependencies.
- F2: fixed: `Boards.readBest` stores an in-flight marker `{ at, best = the held one, reading = true }` before the `GetAsync`, does nothing while `Hiscores.needsRead(held, now, CACHE_TTL)` is false (new pure function: nothing held, or a finished read that is stale), and stores the result only if `bests[userId]` is still that marker and `player.Parent ~= nil`. The Boards header comment now says what is kept per player. Consequences: a concurrent request is answered with the previously held best (nil the first time), stated in the Design; new cases with a yielding stub `GetAsync`: "requests while a player's best is being read do not read it again, and each is answered" (five requests, one read, five answers) and "a best read that ends after the player left is dropped, and a rejoin reads again"; `top` "a held best is read again only when nothing is held, or a finished read is stale". Mutants: needsRead-ignores-reading, boards-no-inflight-mark, boards-store-after-leave. AC5's wording and check label now say "never twice at once, and dropped when they leave".
- F3: fixed: `top :: a player's best is …` gains `H.best({ score = -5, level = 1 })` → nil, and `drivetop :: no entry, or one that is not a valid run …` passes three invalid run tables (empty id, negative score, half `at`) and expects no `update` call; mutants best-accepts-negative and drivetop-nil-only are killed. The seed rows the finding named are gone with F1; the merge rules have rows instead. A further survivor found while answering (a stale best kept after a failed re-read) got the case `adapters :: a best that cannot be read again is no best: the stale one is not kept` and mutant boards-best-error-kept. Consequences: none beyond those rows. The mutation check is now 50 mutants, all killed on assertions.
- F4: fixed: with F1's order the list write is the submit's last step, and the listener is called right after `driveTop` returns, as soon as the place is known. Consequences: none; total latency is the same as before this raft (today's rank also waits for drive).
