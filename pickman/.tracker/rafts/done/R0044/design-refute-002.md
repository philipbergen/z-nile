# Response to design-review-002

- Round 1 rulings: accepted (F2, F3, F4 fixed; F1's mechanism had the hole below).
- F1: fixed, by the reviewer's first option: a run has one id from every source. `Attempt`, `Companion` and `Row` gain optional `run` and `at`; `HiscoreStore` builds the run's entry first and passes its id and instant on the attempt; `commit` copies them onto the per-player rows it writes and `rows` carries them from the companion (each only when `run` is a non-empty string and `at` is whole); `bestRun` uses them, falling back to `best:<userId>:<score>:<level>` at 0 for a row that names no run. Another server's write that merges this run's new best first now lists it under the run's own id, and "the stored copy wins" dedupes. The second option (the list first with a separate `readAll`) was not taken: it doubles the per-run read and adds two page reads, which breaks f0024's pinned `sizes == { 10, 50 }`. Consequences: f0024's `commit`/`rows` cases compare exact tables but never pass `run`, so they are unchanged (the full gate on the prototype passes); old builds rewrite a raised row without the fields, which then merges as a `best:` entry, correct because that run never reached the list. New cases: `drivetop` "another server merged this run's best before its own write: the run is listed once" (both orders); `top` "a best whose row names its run is that run" (with an empty run and a half `at` falling back), "the per-player row a run writes names that run, and the board's rows carry it" (with an invalid name dropped); `adapters` "the per-player all-time row a run writes names that run and its instant". Mutants: bestRun-ignores-row-id, bestRun-no-validate, bestRun-named-at-zero, commit-drops-run, rows-drop-run, rows-no-validate, store-attempt-unnamed.

Case `top` "a run cut from the list does not come back as its best ahead of the earlier runs it ties"; mutant bestRun-named-at-zero. Only rows that name no run stay at 0, which is right for rows older than the list; the Design's Ties line says so.
- F3: fixed: case `adapters` "while a stale best is read again, requests are answered with the best held before", row and mutant marker-drops-held-best. Consequences: none.
- F4: fixed: R0044's Order & dependencies now says the list is written after the per-player boards with no seed, so c0128's quoted reasons are stale and its seven cases are not. `c0128-narrowing.patch` now touches only the seven cases (35 cases pass with it on `origin/main` and on the prototype), and the Order section notes that c0128's prep must settle its Solution bullet against its Outcome. c0128's Problem is a capture and is left as captured.
