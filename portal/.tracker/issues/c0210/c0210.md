## Solution
One manifest, `portal/experience.json`, lists every place of the experience: its name (arcade's `Places.NAMES`), the variables that hold its Beta place id, the build it publishes and the name of its version in the output; each build is a Rojo project file, an optional runtime folder and the extra id attributes it is told. `portal/scripts/lib/experience.luau` is the manifest's one reader, and `portal/scripts/lib/beta.luau` the pure plan: from the manifest and the environment it decides which places are published (those whose variable is set), to which id, with which attributes (every place's id, paid play's test mode, the build's extra ids), in which order (the games, then the start place). `deploy-beta`, `runtime-test --place <name>` and `cicd` move to `portal/scripts/` and act on the plan; the workflow runs from `portal/` and passes every variable the manifest names. Until f0209 the start place's build is pickman's lobby, so pickman's two places go out as before, to the same ids, with the same attributes; f0209's switch is the start place's one `"build"` line.

```json
    { "name": "Invaders", "env": ["ROBLOX_BETA_INVADERS_PLACE_ID"], "build": "invaders", "output": "invaders_version" },
    { "name": "Asteroids", "env": ["ROBLOX_BETA_ASTEROIDS_PLACE_ID"], "build": "asteroids", "output": "asteroids_version" },
    { "name": "Portal", "env": ["ROBLOX_BETA_PLACE_ID"], "build": "lobby", "output": "lobby_version" }
  ],
  "builds": {
    "pickman": { "project": "../pickman/default.project.json", "runtime": "../pickman/tests/runtime", "attributes": { "LobbyPlaceId": "Portal" } },
    "lobby": { "project": "../pickman/lobby.project.json", "runtime": "../pickman/tests/runtime/lobby", "attributes": { "GamePlaceId": "Pickman" } },

    "snake": { "project": "../snake/default.project.json" },

```
Paths are relative to the manifest's folder (`portal/`). A place names a build rather than a project so that **f0209's switch is one line**: `"build": "lobby"` becomes `"build": "portal"` in the Portal place. The `portal` build exists from now on and is built by AC8, so f0209 inherits a build already proven to build with every attribute; no place publishes it until then. After f0209 the `lobby` build is named by no place, so it is neither built nor published; c0188 deletes it with `pickman/lobby.project.json`. f0187 deletes the `LobbyPlaceId` line of the `pickman` build when pickman reads `PortalPlaceId` (same value: the start place's id). A new game's view issue (f0213, f0218, f0222) edits nothing here: the user sets its variable. A build's `runtime` is added by the issue that adds that place's runtime scripts.

### The reader, `portal/scripts/lib/experience.luau` (pure, zz-arch rules 4–6, 8)
```luau
export type Build = { project: string, runtime: string?, attributes: { [string]: string } } -- attribute -> place name
export type Place = { name: string, env: { string }, build: string, output: string }
export type Manifest = { places: { Place }, builds: { [string]: Build } }
Experience.FILE = "experience.json"
Experience.START_VAR = "ROBLOX_BETA_PLACE_ID"
Experience.PAID_PLAY = "PaidPlay"
function Experience.reserved(): { string }            -- every Places.attribute of Places.NAMES, PaidPlay, each Catalog play and revive attribute
function Experience.parse(text: string): (Manifest?, string?) -- the manifest, or nil and "experience.json: <rule>"
```
It requires `@arcade/Places` (f0199) for the names and `../../../arcade/src/server/Catalog` (f0201, a frozen data table that requires nothing) for the product attributes, so the names have one home each. Every refusal starts `experience.json: ` and names the rule: not a JSON object; an unknown key (top level, a place, a build); `places` not a non-empty list, `builds` not an object; a place name not in `Places.NAMES`, listed twice, or one of `Places.NAMES` missing; `env` not a non-empty list, a variable not matching `^ROBLOX_BETA_[A-Z0-9_]*PLACE_ID$` (so no entry can read a live or any non-Beta variable), or a variable another place reads; not exactly one place reading `ROBLOX_BETA_PLACE_ID`, or that place reading anything else too; a `build` that is no build or that another place publishes (one project never goes to two places); an `output` not `^[a-z][a-z0-9_]*$` or another place's; a build name not `^[a-z][a-z0-9-]*$` or equal to a field's name; a `project` that is absolute or not `*.project.json`; a `runtime` absolute or empty; an attribute name not `^[A-Z][A-Za-z0-9]*$`, one in `Experience.reserved()` (an extra attribute never overrides one the publish writes), or naming no place of `Places.NAMES`; and **a repeated key**: Lune's JSON decoder keeps the last of two equal keys (E3), so each field name's `"<field>":` occurrences in the text must equal the objects that hold it (build and attribute names cannot equal a field's name, so they are not counted twice). Unused builds are allowed.

### The plan, `portal/scripts/lib/beta.luau` (pure)
```luau
export type Value = number | string
export type Target = {
	name: string, build: string, project: string, runtime: string?,
	placeId: string,      -- digits
	variable: string,     -- the variable the id came from
	attributes: { [string]: Value },
	output: string,
}
export type Plan = { targets: { Target }, skipped: { string } }
Beta.MAX_PLACE_ID = 2 ^ 53 - 1
Beta.START_VAR = "ROBLOX_BETA_PLACE_ID"
Beta.PAID_PLAY_MODE = "test"
function Beta.attributes(ids: { [string]: number }): { [string]: Value }
function Beta.plan(env: { [string]: string? }, manifest: Experience.Manifest): Plan?
function Beta.target(plan: Plan, name: string): Target?
function Beta.project(text: string, dir: string, attributes: { [string]: Value }): string -- unchanged but for the value type
```
- **Configured** is `OpenCloud.configFromEnv(env)`, unchanged: the key, the universe and `ROBLOX_BETA_PLACE_ID` set; otherwise `plan` is nil (a green skip). Its refusals (a universe or start id that is not digits) stand.
- **Each place's id**: its variables in order; nil or `""` is unset. Each set one must be a place id (`^[1-9]%d*$`, at most 2^53−1; so `0`, `007`, ` 7`, `-5`, `1e3`, `0x10`, `1.5` and 2^53 are refused, naming the variable, never the key). Two set variables of one place must hold the same text, else both are named and nothing is published; equal, the first variable is the one recorded. None set: the place is skipped, its line `the <Name> place is not published: set <first variable>`.
- **Two places with one id** are refused, naming both variables (no project is ever published into another place's id).
- **Attributes** (`Beta.attributes`, the same for every target, then the build's extras): `Places.attribute(name)` for each of `Places.NAMES`, its id or 0; `PaidPlay` = `"test"`; each Catalog entry's `play` and `revive` = 0. Then each extra attribute of the target's build: the named place's id or 0. Ids are Luau numbers (exact below 2^53; E1 shows Rojo keeps them, and a string stays a String attribute).
- **Order**: the targets are the published games in the manifest's order, then the start place, last, whatever its position in the file: a game is on the new build before the start place that sends players to it.

### The commands (the edge)
- `deploy-beta` (run from `portal/`): not configured → `::warning::… skipped`, exit 0, before any file is read. Then `experience.json` from the current folder (missing → `experience.json is missing in <dir>: run this from the portal's home`, exit 1; refused → the reader's line, exit 1), then the plan (a refusal prints its message, exit 1), then one line per skipped place, then every target is built (in a `mktemp -d` outside the checkout, from `Beta.project`'s copy with `$path`s made absolute against the project file's own folder) before any is published; a missing project or a failed build names the project and exits 1 with nothing sent. Then each is published in order, printing `published the <Name> place (<id>): version <n>`; a failure prints Open Cloud's error and `published before the failure: <output>=<n>, …` and exits 1 with no output written. At the end `<output>=<n>` lines in order, appended to `$GITHUB_OUTPUT` only when all succeeded.
- `runtime-test -- [--place <name>] <version> [files…]` (run from `portal/`): `--place` with no name, or a version that is not a whole number ≥ 1 → usage, exit 2; not configured → warning, exit 0; then the manifest as above; a name no place of it has → `runtime-test: <name> is not a place of experience.json`, exit 2; the plan's refusals → exit 1; a place not published → `::warning::runtime tests of the <name> place are not configured …`, exit 0; files given run as given (relative to the current folder); none given → the build's `runtime` folder's `*.luau`, sorted, each named `<runtime>/<file>`; no `runtime` → `::warning::the <name> place has no runtime scripts; skipped`, exit 0. Without `--place` the place is Pickman (fourth Guess). Results as before (`PASS`/`FAIL` lines, `n passed, m failed, k runtime scripts`).
- `cicd` (run from `portal/`): unchanged but for its two runtime calls, `--place Pickman <version>` and `--place Portal <lobby_version>` (third Guess). Its child environment still clears every inherited `ROBLOX_*` and sets the file's four settings (`ROBLOX_BETA_GAME_PLACE_ID` for Pickman's CICD place), so a variable in the merging shell (`ROBLOX_BETA_SNAKE_PLACE_ID`, say) never reaches a CICD publish: its other places are skipped.
- `deploy.yml`: the deploy step's `working-directory: portal`; its `env` is exactly `ROBLOX_API_KEY` from the secret, `ROBLOX_BETA_UNIVERSE_ID` and every variable the manifest names, each `${{ vars.<VAR> }}` (an unset repository variable is the empty string, which the plan reads as unset: GitHub's documented `vars` behaviour, and what `ROBLOX_BETA_GAME_PLACE_ID` relied on before it was set). The trigger, `if`, concurrency (`beta-deploy`, not cancelled), timeout and the comment are unchanged.

### Fail closed (the first-pass list)
| input | result |
|---|---|
| a place's variable unset or `""` | not published, not built; its id attribute 0 everywhere |
| `0`, malformed, ≥ 2^53, whitespace | refused before any build, naming the variable |
| Pickman's two variables with different ids | refused, naming both |
| two places with one id (a game and the start place included) | refused, naming both |
| a manifest variable that is not `ROBLOX_BETA_…PLACE_ID` | the manifest is refused (no Beta entry can read a production variable) |
| one build for two places | the manifest is refused |
| a variable the manifest does not name (`ROBLOX_BETA_LOBBY_PLACE_ID`) | ignored |
| one place's build fails | nothing is published |
| a publish fails after others | the earlier places are on the new build, the rest on the old one; the log names those published; no output; the next deploy republishes all (every place is told the same ids, which come from the variables, not from what is live) |
| two deploys at once | GitHub runs one at a time (`beta-deploy`, unchanged); the merge's cicd holds its lease (unchanged) |
