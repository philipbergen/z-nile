### F3 [medium] The reader accepts manifests it says it refuses: a repeated attribute key, a field repeated through a `\u` escape, and one project under two build names
Where: Design, "The reader": "a repeated key … each field name's `"<field>":` occurrences in the text must equal the objects that hold it (build and attribute names cannot equal a field's name, so they are not counted twice)", and "a `build` that … another place publishes (one project never goes to two places)"; AC1 "refuses every ambiguous or unsafe manifest"; `acceptance/manifest.spec.luau` "a repeated key is refused".
Evidence: a bounded Lune probe (`./zn run --time 60 -- lune run <scratch>/dup.luau`) ran the prototype's `portal/scripts/lib/experience.luau`, a manifest otherwise identical to the checked-in one, and these variants:
- `"attributes":{"LobbyPlaceId":"Portal","LobbyPlaceId":"Snake"}`: ACCEPTED, and `LobbyPlaceId -> Snake`. Attribute names are never counted.
- `"project":"../snake/default.project.json","project":"../pickman/lobby.project.json"`: ACCEPTED, and Snake's project becomes `../pickman/lobby.project.json`. The escaped key decodes to `project`, so the decoder keeps the last value (E3), while the text count only sees the plain spelling.
- the same with `output`: ACCEPTED, and Snake's output becomes `other_version`.
- `snake` build's project `../pickman/default.project.json`: ACCEPTED. Two places then publish one project. The check is on build keys, not on project paths.

The spec has no case for any of these, so the design's own reader passes AC1.
Critique: the tempting fix is one more count for attribute names. That still misses every escaped spelling.
Consequences: refusing escapes forbids `\` anywhere in the file, which no manifest field needs (paths use `/`). Refusing duplicate projects needs a normal form (`./x` and `x`, and a `<dir>/..` segment) so that `default.project.json` and `../portal/default.project.json` count as the same file.
Recommendation: (a) refuse any backslash in the manifest's text (`experience.json: a backslash escape is not allowed`). (b) Count every key the decoder returned, not only the fields: each build name, each attribute name per build, and each field. Compare it with the occurrences of `"<key>"%s*:` in the text. Build names and attribute names cannot collide with fields or with each other's casing, so the counts stay exact. (c) Either refuse two builds whose normalised project path is equal (`build snake: project … is also build pickman's`), or reword the "(one project never goes to two places)" claim to what is enforced (one build per place) and rely on manifest.spec's checked-in pins. Add a manifest.spec case for each, Rules rows, and run mutants: the backslash check dropped, attribute keys not counted, the project check dropped.
