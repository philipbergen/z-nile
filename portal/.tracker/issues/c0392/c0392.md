# c0392: Narrow c0210 lobby start-place pin

## Problem
- f0209 makes the start place (`ROBLOX_BETA_PLACE_ID`) publish the portal instead of pickman's lobby, which turns red exactly these pins in `portal/tests/acceptance/c0210/lobby.spec.luau`: in both deploy cases the lobby's structure at the start place (`ServerScriptService.Lobby` present, no `Server`), its `GamePlaceId`, the absence of `LobbyPlaceId` on it, the `lobby_version` output line and the lobby project file, and in the runtime case that `runtime-test --place Portal` runs `pickman/tests/runtime/lobby`'s scripts.

## Non-goals
- c0210's other specs and its `check.sh` are not changed (its AC4 runs the narrowed file).
- No pin on the portal at the start place is added here, because f0209 pins that in its own acceptance specs.

## Solution
- Remove from `portal/tests/acceptance/c0210/lobby.spec.luau` only the pins the Problem lists, so the file passes on main both before and after f0209.
- Every other assertion in the file stays as it is, including the Pickman game case's checks (the game's `Server` child, no `GamePlaceId` on the game, the `version=1333` output line, `LobbyPlaceId` and `PortalPlaceId` equal to the start place's id, the publish order, the key never printed, the game's project file unchanged), the `*PlaceId` attributes on the start place and the runtime case's `--place Pickman` half.
- The issue overrides `portal/tests/acceptance/c0210/lobby.spec.luau`, can start only once c0210 is done, and is done before f0209's raft starts.
