# c0392: Narrow c0210 lobby start-place pin

## Problem
- `portal/tests/acceptance/c0210/lobby-start.spec.luau`, run by the AC11 line of c0210's `check.sh`, pins the lobby at the start place (the lobby published after the game and told `GamePlaceId`, the output exactly `version=1333` and `lobby_version=1222`, the lobby project unchanged, `runtime-test --place Portal` running pickman's lobby scripts), so it turns red when f0209 switches the Portal place's build from `lobby` to `portal`.
- Scope decision (user, 2026-11-16): "a". This is the user's answer to design review 001 F1, asked by the session lead: "Which do you want: (a) confirm my rewrite [delete lobby-start.spec.luau and c0210's AC11 line] or (b) your original capture stands [narrow in place]?" So PR #526's rewrite of the Problem, Non-goals and Solution is the scope. `lobby-start.spec.luau` and the AC11 line of c0210's finished `check.sh` are removed. The capture's two kept assertions that lived only in that file (the start place published second to its own id; `PortalPlaceId` and `PickmanPlaceId` on it) are left to f0209's own specs.

## Non-goals
- No pin on the portal at the start place is added here.
- No replacement is added for the removed file's end-to-end pin with the real manifest (the start place published second to its own id, `/places/222/versions`, with `PortalPlaceId` 222 and `PickmanPlaceId` 333 on it), because c0210's AC3 (`deploy.spec.luau`: games first and the start place last, over a fixture experience) and AC8 (`build.spec.luau`: every attribute on every real build) still cover publish order and attributes.
- This chore does not depend on any f0209 spec: f0209 is `design: draft` with no `check` lines in its `check.sh`, so whether it pins the real-manifest case again is left to f0209's own design.

## Solution
- This chore removes `portal/tests/acceptance/c0210/lobby-start.spec.luau` and the AC11 line of c0210's finished `check.sh`, and nothing else, changing that `check.sh` the way lesson z-design/finished-overrides-land-before-ready allows.
- Every other c0210 spec stays byte for byte, including `pickman.spec.luau` (AC4), `way-back.spec.luau` (AC10) and `overrides.spec.luau` (AC12).
- `./zn check c0210` passes with the file gone, both with the Portal place's build as `lobby` and as `portal`.
- The chore overrides `lobby-start.spec.luau`, can start only once c0210 is done, and is done before f0209's raft starts.
