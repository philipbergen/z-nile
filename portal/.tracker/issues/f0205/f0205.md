## Solution
Two pure leaves and a config table carry every rule: `Logic/Carousel` (which card is in front, what each key, wheel roll and swipe does, where each card sits on the screen) and `Logic/Card` (the price badge for a game's state, the states the server sends and the client's defensive read of them, how a read's answer folds into what the server knows and when it reads again, when asks are answered, the card's regions and its text-size model, the preview's turn), with `src/shared/Games.luau` holding one entry per game (its paid-play name and title, its place, its tagline, its preview's parts). Two thin adapters wire them to Roblox. The server's `Cards` reads which places are published once, from the place-id attributes through the arcade's `Places` (f0199), and on each ask (asks closer than a second answered together) answers that player at once, then reads each published game's record through the arcade's `Wallet` (f0201) and answers again with `PaidPlay.status`'s free state as each read comes back; a busy read is read again once, a failed one with a back-off up to a minute. The client's `CarouselView` turns the platform's touch controls off, draws the four cards in a ScreenGui inside the safe insets (title, tagline, a turning 3-D preview in a ViewportFrame, the badge in the arcade's `Prices` words and the portal's own two words, and empty `Buttons` and `Boards` slots for f0208 and f0206), binds the nine keys and the wheel through one ContextActionService action above the default controls and below the test purchase screen, ignores them while the player types, listens to swipes, and tells its play listeners the front card's name on Enter, KeypadEnter or ButtonA. One RemoteEvent, `ReplicatedStorage.Remotes.Cards`, joins them: the client asks with nothing, the server answers with states and never with a place id.

### 1. `src/shared/Logic/Carousel/init.luau` (new, pure, a leaf)
```luau
export type Intent = "prev" | "next" | "play"
export type Carousel = { count: number, index: number, wheelAt: number? }
export type Box = { x: number, y: number, width: number, height: number, shown: boolean, dim: number } -- safe-area pixels
Carousel.KEYS: { [string]: Intent } -- frozen, by KeyCode name: A, Left, ButtonL1 "prev"; D, Right, ButtonR1 "next"; Return, KeypadEnter, ButtonA "play"
Carousel.ACTION = "PortalCarousel"   -- the ContextActionService action name
Carousel.PRIORITY = 2500             -- above the default controls (2000), below the test purchase screen (3000, f0201)
Carousel.WHEEL_GAP = 0.25            -- seconds the wheel must rest before a wheel event moves the row
Carousel.HEIGHT = 0.9; Carousel.ASPECT = 0.75; Carousel.MAX_WIDTH = 0.8  -- the front card: of the area's height; width/height; of the area's width
Carousel.SIDE_SCALE = 0.8; Carousel.GAP = 0.03; Carousel.SIDE_DIM = 0.5 -- a neighbour's size; the gap (of the area's width); its dim
function Carousel.new(count: number): Carousel                       -- the first card in front; count a whole number >= 1, else an error naming "count"
function Carousel.step(c: Carousel, by: number): Carousel            -- a new row moved `by`, wrapping both ways; a non-whole `by` moves nothing
function Carousel.key(name: string): Intent?                         -- KEYS[name]
function Carousel.wheel(c: Carousel, delta: number, now: number): (Carousel, Intent?)
function Carousel.swipe(direction: string): Intent?                  -- "Left" "next", "Right" "prev", else nil
function Carousel.offset(c: Carousel, i: number): number             -- card i from the front, the short way round; an even count's opposite card is +count/2
function Carousel.box(offset: number, width: number, height: number): Box
```
- **The wheel**: `delta` is the InputObject's `Position.Z` (positive rolled up, away from the player): up is "prev", down "next". Every wheel event at a finite `now` records `wheelAt = now`; it moves the row only when the wheel rested before it (no earlier event, `now - wheelAt >= WHEEL_GAP`, or a clock that went back). A zero or non-finite delta moves nothing but still counts as rolling; a non-finite `now` is dropped whole (the row as it was). So one notch, one roll or one trackpad flick moves one card. `wheel` never changes `index`: the caller steps on the intent.
- **The boxes**, in the ScreenGui's own space (its `AbsoluteSize`, which with `ScreenInsets = CoreUISafeInsets` is the core-UI safe area; positions are pixels from its top-left): the front card is `h = HEIGHT × height` tall and `w = min(ASPECT × h, MAX_WIDTH × width)` wide, centred, `dim` 0. A neighbour (offset ±1) is `SIDE_SCALE` of that, vertically centred, its near edge `GAP × width` from the front card's edge, `dim = SIDE_DIM`, shown when any of it is on screen. Every other card is not shown. `ASPECT` 0.75 (design review 001 F5) keeps every text readable on a landscape phone (§2, the text model): on 844 x 390 the front card is 263 x 351 px.
- **The priority** (design review 001 F4): 2000 is `Enum.ContextActionPriority.Default`, at which Roblox's PlayerModule binds its movement, jump and camera actions; at equal priority the action bound last is asked first, and the control module binds again when the input type changes. 2500 puts the carousel strictly above them and strictly below f0201's test screen (3000), so its sink still wins while it is open.
- Nothing mutates the row it is given; every function returns new tables.

### 2. `src/shared/Logic/Card/init.luau` (new, pure, a leaf)
The word `game` is refused in Logic (pickman-arch rule 2): a game here is an *entry* or a *title*.
```luau
export type Shape = "Ball" | "Block" | "Cylinder"
export type Part = { shape: Shape, size: { number }, at: { number }, color: { number } } -- studs from the scene's centre; colour 0..255
export type Entry = { name: string, place: string, title: string, tagline: string, preview: { Part } }
export type State = { published: boolean, free: boolean? } -- free nil: not known yet
export type Kind = "none" | "sale" | "free" | "soon"
export type Badge = { kind: Kind, struck: string, text: string } -- struck is rich text, "" when none
export type Prices = { struck: string, price: string, sale: string } -- the arcade's Prices, passed in
export type Words = { free: string, soon: string }                -- the badge's own words, passed in
export type Region = { top: number, height: number }               -- of the card's height
export type Read = { free: boolean?, busy: number, down: number }  -- the server's knowledge of one title for one player
export type Waits = { busy: number, down: number, most: number }   -- seconds: after a busy read, after a first failure, at most
Card.WORDS = { free = "FREE GAME READY", soon = "COMING SOON" }    -- frozen: the portal's two badge words (F1, ruled "c")
Card.ORDER = { "Title", "Tagline", "Preview", "Badge", "Buttons", "Boards" }  -- frozen, top to bottom
Card.REGIONS: { [string]: Region } -- frozen: Title 0.02/0.08, Tagline 0.10/0.08, Preview 0.19/0.27, Badge 0.47/0.08, Buttons 0.56/0.09, Boards 0.66/0.32
Card.INSET = 0.05    -- each label's and slot's margin either side, of the card's width
Card.BADGE = { struck = 0.4, gap = 0.02, offer = 0.58 } -- frozen: the badge's two labels, of its width
Card.GLYPH = 0.65    -- a bold glyph's width, of its text size (the text-size model)
Card.MIN_TEXT = 12   -- pixels: the smallest text the front card may show
Card.ASK_GAP = 1     -- seconds: asks closer than this are answered together, at the gap's end
Card.SPIN = 0.5      -- radians a second
Card.FRAME = 4       -- every preview part lies within this many studs of the centre on each axis
Card.CAMERA = { fov = 40, distance = 22, height = 3 } -- frozen: vertical degrees; studs back and up, looking at the centre
Card.SHAPES = { "Ball", "Block", "Cylinder" }
function Card.strike(text: string): string            -- "<s>" .. text with & < > escaped .. "</s>"
function Card.badge(state: State?, prices: Prices, words: Words): Badge
function Card.published(entry: Entry, ids: { [string]: number? }): boolean -- ids[entry.place] ~= nil (Places.read's answer)
function Card.states(entries: { Entry }, published: { [string]: boolean }, free: { [string]: boolean }?): { [string]: State }
function Card.parse(raw: any, entries: { Entry }): { [string]: State }
function Card.answer(read: Read?, due: boolean?, reason: string?, waits: Waits): (Read, number?)
function Card.asked(last: number?, now: number): number?
function Card.textSize(text: string, width: number, height: number, wrap: boolean): number
function Card.angle(seconds: number): number           -- SPIN × seconds mod 2π; 0 for a non-finite time
```
- **The badge**: nil state: `none` ("", ""). Not published: `soon` ("", `words.soon`), whatever the free state says. Published and `free == true`: `free` ("", `words.free`). Published and `free == false`: `sale`, `struck = Card.strike(prices.struck)`, `text = prices.price .. " " .. prices.sale` ("<s>5 R$</s>", "1 R$ SALE" with the shipped table). Published and free nil (its read not back): `none`. The view passes the arcade's `Prices` and `Card.WORDS`; were the two words to move to a config table of their own (F1's option b), only that argument would change.
- **The states** the server sends: one per entry given, by `name`, `published = published[name] == true`, and `free = free[name]` only where published (nil otherwise). **The client's read** (`parse`): per entry, `raw[name]` must be a table with a boolean `published` and a `free` that is nil or a boolean, else that entry has no state; a non-table message gives none; names it does not know are dropped; a state not published keeps no free state. It never raises.
- **A read's answer** (`answer`, design review 001 F3): `due` is `PaidPlay.status(record, now).free` when the read gave a record, nil when it did not. A record: `{ free = due, busy = 0, down = 0 }`, no read again. A first busy answer in a row (Wallet's own in-flight flag: another read of the same record under way, a PLAY's for one) keeps `free` as it was (nil stays nil: an empty badge) and reads again after `waits.busy`. Any other answer without a record (down, no reason, or busy a second time in a row) is the sale (`free = false`), `down + 1`, and reads again after `min(waits.down × 2^(down - 1), waits.most)`. It never changes the record it is given. The server passes `waits = { busy = Wallet.WAIT_SECONDS, down = Wallet.RETRY_SECONDS, most = Wallet.READ_SECONDS }` (5, 6 and 60 s: so 6, 12, 24, 48, then 60 s, one store call a minute per player and title in a long outage at most, f0201's down-read bound).
- **Asks** (`asked`, design review 001 F12): nil (answer now) when there was no answered ask, it is `ASK_GAP` old, or the clock went back; else the seconds to the gap's end. The server holds one ask at most per player and answers it then, so a re-ask (f0207's) is never lost.
- **The text model** (`textSize`, design review 001 F5): a label `width` x `height` px gives `text` (n characters) `min(height, width / (GLYPH × n))` on one line; wrapped, the best of one to four lines (`min(height / L, width × L / (GLYPH × n))`). AC2 requires every text on the front card (each title in the Title region, each tagline wrapped in the Tagline region, the struck price and every offer text, sale, `WORDS.free`, `WORDS.soon`, in their badge labels) to be at least `MIN_TEXT` px on all seven screens. With the shipped constants the smallest is 13.7 px (an offer on 320 x 480); on 844 x 390 it is 14.0 (the tagline, two lines). The model approximates GothamBold; OC2 checks the real text.
- Only the fields named here are pinned, field by field, so f0207 can add its own (a `wait` in the state, a `note` in the badge: correct variants CV2 and CV3 of the mutation check).

### 4. `src/server/Cards.luau` (new, server adapter) and `src/server/Main.server.luau`
```luau
Cards.start(): () -- once per server; a second call does nothing
```
Requires: `@game/ReplicatedStorage/Shared/Logic/Card`, `@game/ReplicatedStorage/Shared/Games`, `@game/ReplicatedStorage/Arcade/Logic/PaidPlay`, `@game/ReplicatedStorage/Arcade/Places`, `@game/ServerStorage/Arcade/Wallet` (a server root may reach ServerStorage, portal-arch change 1).
- At start: `remote = ReplicatedStorage.Remotes.Cards` (`WaitForChild`); `ids = Places.read(function(a) return ServerScriptService:GetAttribute(a) end)`, once; `published[entry.name] = Card.published(entry, ids)` for every entry; `waits` from the Wallet's three bounds (§2). The ids never leave this function's tables.
- **The slot**, per Player object, made on their first ask: `reads` (a `Card.Read` per name), `reading` (a read under way, per name), `retry` (the current retry's token, per name), `asked` (`os.clock()` of the last answered ask) and `waiting` (an ask held).
- **An ask** (`remote.OnServerEvent`, whatever arguments come with it): a player whose `Parent` is nil gets nothing. `Card.asked(slot.asked, os.clock())`: nil answers now; a wait holds the ask (one at most: a second within the gap is the same held ask) and answers it when the gap ends, if the player is still there. **Answering**: `slot.asked = os.clock()`, then `remote:FireClient(player, Card.states(Games.LIST, published, free))` with each name's `reads[name].free`, then a read of every published entry not under way for that player.
- **A read**: marks it under way and `task.spawn`s `Wallet.read(player, name)`; when it returns (and the slot is still the player's and they are present): `due = PaidPlay.status(record, os.time()).free == true` for a record, else nil; `reads[name], delay = Card.answer(reads[name], due, reason, waits)`; a new retry token for that name (so any retry waiting for it does nothing when it fires); the server answers again; and when `delay` is set, `task.delay(delay, …)` reads again if the token is still that one and the player and slot are still there. So each game has one retry at most, a read that comes back cancels it, and a leave ends them all. An unpublished entry is never read.
- An answer is sent only while the player's `Parent` is set and their slot is the one the read began with; `Players.PlayerRemoving` drops the slot, so a read that comes back after a leave sends nothing and a rejoin starts afresh.
- `Main.server.luau` starts it once: `require("./Cards").start()`.

### The split and server authority
Everything that decides is pure and unit-tested in Lune (Carousel, Card, the Games table). The adapters only translate: attributes and the Wallet's answers into `Card.states` and `Card.answer`; the server's message, keys, wheel, swipes and the clock into Logic calls and Instances. The server decides what each card says: whether a place is published (attributes the publisher sets, never sent to a client) and whether a free start is due (the player's own record). The client sends one thing, an ask with nothing in it, and anything it adds is ignored. A play is only an intent on the client (its listeners): whether it is free, bought or allowed is f0208's server's, which never trusts the client's card either.

### Edge cases
- No place published (every attribute 0 or missing, as checked in): four COMING SOON cards, no Wallet read, no play.
- A read under way when the player asks again: no second read of that game; the answer says what is known.
- A busy read: what was known stays; one more read after `WAIT_SECONDS`; busy again is a failure.
- A store down: the sale; reads again after 6, 12, 24, 48, then every 60 s, until one succeeds or the player leaves (Wallet holds a failure for `RETRY_SECONDS`, so the retries make no store call inside it).
- A burst of asks: one answer at once, one at the gap's end.
- A player who leaves during a read or with a retry waiting: nothing more is sent or read; their slot is dropped; a rejoin is a new Player object and starts afresh.
- A malformed server message (only possible from a bug): the cards it spoils show an empty badge and play nothing; the rest draw.
- The front card when the server has not answered: badges empty, Enter plays nothing.
- The player typing in the chat: the carousel's keys pass to the text box and move nothing.
- The wheel's clock going back, or a non-finite clock: counted as rested, or dropped.
- Screen turns and insets: every layout is from the safe area's `AbsoluteSize` and redrawn on its change; the boxes fit, and every front-card text is at least `MIN_TEXT` px on, seven screen shapes from 320 x 480 to 2560 x 1080.
- Frame rate: nothing counts frames; the preview's angle is a function of the clock.

### Scalability
Server: at start five attribute reads. Per player at most one answered ask a second (`ASK_GAP`, design review 001 F12): each is one `FireClient` and at most four `Wallet.read` calls (none for a read under way), each answered by one more `FireClient`; so at most five small messages a second per player, however fast a client fires. Retries: one per game at a time, at `WAIT_SECONDS` after a busy answer and at 6 to 60 s while down. The store calls stay Wallet's bound: per player and game at most one `GetAsync` per 60 s while the store answers (the record seen) and one per 6 s while it fails (f0201's Scalability: four cards cost at most 4 reads a minute per player when up); the back-off makes a long outage cost at most one call a minute per player and game. Replicated: one RemoteEvent; a message is four `{ published, free }` pairs (under 200 bytes). Client: four card Frames with about fifteen GuiObjects each and four ViewportFrames of 6 to 9 parts; per frame one `PivotTo` per shown card (at most three).

### Maintainability
A fifth game is one `Games` entry (with its Catalog entry and its place in Places, from their own issues): the carousel's count, the boxes, the server's reads and the badges follow the list, and nothing branches on a game's name. The sale's words are the arcade's `Prices` alone, so the user's open pricing decision changes one table and no code; the portal's other two words are `Card.WORDS`, passed into `Card.badge` as a table, so moving them to a config table of their own is one file and one argument. Tuning lives in named constants (`Carousel.*`, `Card.REGIONS`, `Card.BADGE`, `Card.INSET`, `Card.CAMERA`, `Card.SPIN`, `Card.MIN_TEXT`), and the specs read them by name. The seams the next issues use are listed above and pinned.

### Usability
- **Player**: the front card is large, centred and fully on screen on every shape from a small phone to an ultrawide, and every text on it is at least 12 px by the text model; its neighbours peek in, smaller and dimmed, so it is clear there is more to scroll to; keyboard (A/D, arrows, Enter), mouse (the wheel, one card per roll), touch (a swipe, with no platform thumbstick over the cards) and gamepad (the shoulders, A) all work, each on the press, and none of them while the player types in the chat; the badge never shows a price or a free game the server has not confirmed, and a single busy read never turns a free game into a sale; COMING SOON says plainly what cannot be played.
- **Developer**: the client API is three functions and a listener; the server's is one `start`; the Logic is small typed functions with the game list as data; the play intent carries only a name, and f0208 decides everything else.
