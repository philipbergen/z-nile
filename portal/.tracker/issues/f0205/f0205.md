## Solution
Two pure leaves and a config table carry every rule: `Logic/Carousel` (which card is in front, what each key, wheel roll and swipe does, where each card sits on the screen) and `Logic/Card` (the price badge for a game's state, the states the server sends and the client's defensive read of them, the card's regions, the preview's turn), with `src/shared/Games.luau` holding one entry per game (its paid-play name and title, its place, its tagline, its preview's parts). Two thin adapters wire them to Roblox. The server's `Cards` reads which places are published once, from the place-id attributes through the arcade's `Places` (f0199), and on each ask answers that player at once, then reads each published game's record through the arcade's `Wallet` (f0201) and answers again with `PaidPlay.status`'s free state as each read comes back. The client's `CarouselView` draws the four cards in a ScreenGui inside the safe insets (title, tagline, a turning 3-D preview in a ViewportFrame, the badge in the arcade's `Prices` words, and empty `Buttons` and `Boards` slots for f0208 and f0206), binds the nine keys and the wheel through one ContextActionService action below the test purchase screen's priority, listens to swipes, and tells its play listeners the front card's name on Enter, KeypadEnter or ButtonA. One RemoteEvent, `ReplicatedStorage.Remotes.Cards`, joins them: the client asks with nothing, the server answers with states and never with a place id.

### 1. `src/shared/Logic/Carousel/init.luau` (new, pure, a leaf)
```luau
export type Intent = "prev" | "next" | "play"
export type Carousel = { count: number, index: number, wheelAt: number? }
export type Box = { x: number, y: number, width: number, height: number, shown: boolean, dim: number } -- safe-area pixels
Carousel.KEYS: { [string]: Intent } -- frozen, by KeyCode name: A, Left, ButtonL1 "prev"; D, Right, ButtonR1 "next"; Return, KeypadEnter, ButtonA "play"
Carousel.ACTION = "PortalCarousel"   -- the ContextActionService action name
Carousel.PRIORITY = 2000             -- below the test purchase screen's 3000 (f0201)
Carousel.WHEEL_GAP = 0.25            -- seconds the wheel must rest before a wheel event moves the row
Carousel.HEIGHT = 0.9; Carousel.ASPECT = 0.6; Carousel.MAX_WIDTH = 0.8   -- the front card: of the area's height; width/height; of the area's width
Carousel.SIDE_SCALE = 0.8; Carousel.GAP = 0.03; Carousel.SIDE_DIM = 0.5 -- a neighbour's size; the gap (of the area's width); its dim
function Carousel.new(count: number): Carousel                       -- the first card in front; count a whole number >= 1, else an error naming "count"
function Carousel.step(c: Carousel, by: number): Carousel            -- a new row moved `by`, wrapping both ways; a non-whole `by` moves nothing
function Carousel.key(name: string): Intent?                         -- KEYS[name]
function Carousel.wheel(c: Carousel, delta: number, now: number): (Carousel, Intent?)
function Carousel.swipe(direction: string): Intent?                  -- "Left" "next", "Right" "prev", else nil
function Carousel.offset(c: Carousel, i: number): number             -- card i from the front, the short way round; an even count's opposite card is +count/2
function Carousel.box(offset: number, width: number, height: number): Box
```
- **The wheel**: `delta` is the InputObject's `Position.Z` (positive rolled up, away from the player): up is "prev", down "next". Every wheel event at a finite `now` records `wheelAt = now`; it moves the row only when the wheel rested before it (no earlier event, `now - wheelAt >= WHEEL_GAP`, or a clock that went back). A zero or non-finite delta moves nothing but still counts as rolling; a non-finite `now` is dropped whole (the row as it was). So one notch, one roll or one trackpad flick moves one card. `wheel` never changes `index`: the caller steps on the intent.
- **The boxes**, in the ScreenGui's own space (its `AbsoluteSize`, which with `ScreenInsets = CoreUISafeInsets` is the core-UI safe area; positions are pixels from its top-left): the front card is `h = HEIGHT × height` tall and `w = min(ASPECT × h, MAX_WIDTH × width)` wide, centred, `dim` 0. A neighbour (offset ±1) is `SIDE_SCALE` of that, vertically centred, its near edge `GAP × width` from the front card's edge, `dim = SIDE_DIM`, shown when any of it is on screen. Every other card is not shown.
- Nothing mutates the row it is given; every function returns new tables.

### 2. `src/shared/Logic/Card/init.luau` (new, pure, a leaf)
The word `game` is refused in Logic (pickman-arch rule 2): a game here is an *entry* or a *title*.
```luau
export type Shape = "Ball" | "Block" | "Cylinder"
export type Part = { shape: Shape, size: { number }, at: { number }, color: { number } } -- studs from the scene's centre; colour 0..255
export type Entry = { name: string, place: string, title: string, tagline: string, preview: { Part } }
export type State = { published: boolean, free: boolean? } -- free nil: not known yet
export type Kind = "none" | "sale" | "free" | "soon"
export type Badge = { kind: Kind, struck: string, text: string } -- struck is rich text, "" when none
export type Prices = { struck: string, price: string, sale: string } -- the arcade's Prices, passed in
export type Region = { top: number, height: number } -- of the card's height
Card.FREE = "FREE GAME READY"; Card.SOON = "COMING SOON"
Card.ORDER = { "Title", "Tagline", "Preview", "Badge", "Buttons", "Boards" }  -- frozen, top to bottom
Card.REGIONS: { [string]: Region } -- frozen: Title 0.02/0.08, Tagline 0.10/0.05, Preview 0.16/0.30, Badge 0.47/0.08, Buttons 0.56/0.09, Boards 0.66/0.32
Card.SPIN = 0.5      -- radians a second
Card.FRAME = 4       -- every preview part lies within this many studs of the centre on each axis
Card.CAMERA = { fov = 40, distance = 22, height = 3 } -- frozen: vertical degrees; studs back and up, looking at the centre
Card.SHAPES = { "Ball", "Block", "Cylinder" }
function Card.strike(text: string): string            -- "<s>" .. text with & < > escaped .. "</s>"
function Card.badge(state: State?, prices: Prices): Badge
function Card.published(entry: Entry, ids: { [string]: number? }): boolean -- ids[entry.place] ~= nil (Places.read's answer)
function Card.states(entries: { Entry }, published: { [string]: boolean }, free: { [string]: boolean }?): { [string]: State }
function Card.parse(raw: any, entries: { Entry }): { [string]: State }
function Card.angle(seconds: number): number           -- SPIN × seconds mod 2π; 0 for a non-finite time
```
- **The badge**: nil state: `none` ("", ""). Not published: `soon` ("", COMING SOON), whatever the free state says. Published and `free == true`: `free` ("", FREE GAME READY). Published and `free == false`: `sale`, `struck = Card.strike(prices.struck)`, `text = prices.price .. " " .. prices.sale` ("<s>5 R$</s>", "1 R$ SALE" with the shipped table). Published and free nil (its read not back): `none`.
- **The states** the server sends: one per entry given, by `name`, `published = published[name] == true`, and `free = free[name]` only where published (nil otherwise). **The client's read** (`parse`): per entry, `raw[name]` must be a table with a boolean `published` and a `free` that is nil or a boolean, else that entry has no state; a non-table message gives none; names it does not know are dropped; a state not published keeps no free state. It never raises.
- Only the fields named here are pinned, field by field, so f0207 can add its own (a `wait` in the state, a `note` in the badge: correct variants CV2 and CV3 of the mutation check).

### 4. `src/server/Cards.luau` (new, server adapter) and `src/server/Main.server.luau`
```luau
Cards.start(): () -- once per server; a second call does nothing
```
Requires: `@game/ReplicatedStorage/Shared/Logic/Card`, `@game/ReplicatedStorage/Shared/Games`, `@game/ReplicatedStorage/Arcade/Logic/PaidPlay`, `@game/ReplicatedStorage/Arcade/Places`, `@game/ServerStorage/Arcade/Wallet` (a server root may reach ServerStorage, portal-arch change 1).
- At start: `remote = ReplicatedStorage.Remotes.Cards` (`WaitForChild`); `ids = Places.read(function(a) return ServerScriptService:GetAttribute(a) end)`, once; `published[entry.name] = Card.published(entry, ids)` for every entry. The ids never leave this function's tables.
- **An ask** (`remote.OnServerEvent`, whatever arguments come with it): a player whose `Parent` is nil gets nothing. Otherwise the player's slot (per Player object: `free` and `reading`, by name) is made on their first ask, and the server answers at once, `remote:FireClient(player, Card.states(Games.LIST, published, slot.free))`. Then for every published entry whose read is not under way for that player it marks it under way and `task.spawn`s `Wallet.read(player, name)`; when the read returns, `slot.free[name] = record ~= nil and PaidPlay.status(record, os.time()).free == true` (a nil record, "busy" or "down", is false: the sale), the mark is cleared, and the server answers again. An unpublished entry is never read. Every ask reads again what is not being read (f0207 asks again when its countdown runs out); the store calls stay bounded by Wallet itself (one per `READ_SECONDS` while the store answers, one per `RETRY_SECONDS` while it fails).
- An answer is sent only while the player's `Parent` is set and their slot is the one the read began with; `Players.PlayerRemoving` drops the slot, so a read that comes back after a leave sends nothing and a rejoin starts afresh.
- `Main.server.luau` gains `require("./Cards").start()`.

### 5. `src/client/CarouselView.luau` (new, client adapter) and `src/client/Main.client.luau`
```luau
CarouselView.start(): ()                         -- once; builds the screen, binds the inputs, asks the server; returns at once
CarouselView.onPlay(fn: (name: string) -> ()): () -- a play listener (f0208): hears the front card's name on a play
CarouselView.focused(): string                   -- the front card's name
CarouselView.card(name: string): Frame?          -- that card's Frame (its Buttons and Boards slots are children), nil for another name
```

Requires: `Logic/Card`, `Logic/Carousel`, `Shared/Games` and `@game/ReplicatedStorage/Arcade/Prices`.
- **The screen**: a ScreenGui `Portal` in the PlayerGui, `ResetOnSpawn = false`, `ScreenInsets = CoreUISafeInsets` (no `IgnoreGuiInset`); a full `Backdrop` Frame; a full transparent `Cards` Frame holding one Frame per entry named by its `name`. Each card holds, at `Card.REGIONS` (scale positions, x 0.05, width 0.9; the preview full width): `Title` and `Tagline` TextLabels with the entry's text; `Preview`, a ViewportFrame whose `CurrentCamera` is its own child Camera (`FieldOfView = Card.CAMERA.fov`, at `(0, CAMERA.height, CAMERA.distance)` looking at the centre) and whose `Scene` Model holds one anchored Part per preview part (its shape, size, position and `Color3.fromRGB` colour); `Badge`, a Frame holding `Struck` (a TextLabel with `RichText = true`) and `Offer` (a TextLabel); `Buttons` and `Boards`, empty Frames; and `Dim`, a black Frame over the card.

It draws at start, on every move, on every answer, and when the ScreenGui's `AbsoluteSize` changes (a resize or a turned phone).
- **Input**: one `ContextActionService:BindActionAtPriority(Carousel.ACTION, handler, false, Carousel.PRIORITY, …)` with every key of `Carousel.KEYS` (as `Enum.KeyCode`) and `Enum.UserInputType.MouseWheel`. The handler: a MouseWheel input goes through `Carousel.wheel(row, input.Position.Z, os.clock())` (whatever its state, since the wheel's is Change); any other acts on `Begin` only, through `Carousel.key(input.KeyCode.Name)`; it returns `Sink`. `UserInputService.TouchSwipe` goes through `Carousel.swipe(direction.Name)`, processed or not (a swipe that starts on a button or a board still moves the row; lesson pickman-arch/count-processed-input-when-tracking). "prev" and "next" step the row by -1 and +1 and draw. "play" `task.spawn`s every play listener with `focused()`, only when that card's state is known and published.
- **The test purchase screen** (f0201's consumer rule): the play keys are ContextActionService bindings below 3000, so while f0201's screen is open its sink at 3000 takes Return, KeypadEnter and ButtonA and the carousel plays nothing.
- **The preview** turns on `RunService.RenderStepped`: every shown card's `Scene:PivotTo(CFrame.Angles(0, Card.angle(os.clock()), 0))`; a hidden card's scene is left alone.
- **The server**: in its own thread (`task.spawn`, so the boot never waits: lesson pickman-arch/open-stores-guarded, F13), `ReplicatedStorage:WaitForChild("Remotes"):WaitForChild("Cards")`, then `OnClientEvent` connects (each answer replaces every state with `Card.parse(raw, Games.LIST)` and draws), and only then `FireServer()` with nothing.
- `Main.client.luau` gains `require("./CarouselView").start()`.

### The split and server authority
Everything that decides is pure and unit-tested in Lune (Carousel, Card, the Games table). The adapters only translate: attributes and the Wallet's answers into `Card.states`; the server's message, keys, wheel, swipes and the clock into Logic calls and Instances. The server decides what each card says: whether a place is published (attributes the publisher sets, never sent to a client) and whether a free start is due (the player's own record). The client sends one thing, an ask with nothing in it, and anything it adds is ignored. A play is only an intent on the client (its listeners): whether it is free, bought or allowed is f0208's server's, which never trusts the client's card either.

### Edge cases
- No place published (every attribute 0 or missing, as checked in): four COMING SOON cards, no Wallet read, no play.
- A read under way when the player asks again: no second read of that game; the answer says what is known.
- A store down or busy: the sale; the next ask reads again (Wallet holds a failure for `RETRY_SECONDS`).
- A player who leaves during a read: nothing more is sent; their slot is dropped; a rejoin is a new Player object and starts afresh.
- A malformed server message (only possible from a bug): the cards it spoils show an empty badge and play nothing; the rest draw.
- The front card when the server has not answered: badges empty, Enter plays nothing.
- The wheel's clock going back, or a non-finite clock: counted as rested, or dropped.
- Screen turns and insets: every layout is from the safe area's `AbsoluteSize` and redrawn on its change; the boxes fit seven screen shapes from 320 x 480 to 2560 x 1080.
- Frame rate: nothing counts frames; the preview's angle is a function of the clock.

### Scalability
Server: at start five attribute reads; per ask one `FireClient` and at most four `Wallet.read` calls (none for a read under way), each answered by one more `FireClient`. The store calls are Wallet's bound: per player and game at most one `GetAsync` per 60 s while the store answers and one per 6 s while it fails, whatever the client asks (f0201's Scalability: the four cards cost at most 4 reads a minute per player when up). A client that floods asks gets five small messages per ask and costs the server a table walk each; no DataStore call more. Replicated: one RemoteEvent; a message is four `{ published, free }` pairs (under 200 bytes). Client: four card Frames with about fifteen GuiObjects each and four ViewportFrames of 6 to 9 parts; per frame one `PivotTo` per shown card (at most three). No per-frame allocation besides one CFrame per shown card.

### Maintainability
A fifth game is one `Games` entry (with its Catalog entry and its place in Places, from their own issues): the carousel's count, the boxes, the server's reads and the badges follow the list, and nothing branches on a game's name. The sale's words are the arcade's `Prices` alone, so the user's open pricing decision changes one table and no code; the portal's other badge words are two `Card` constants. Tuning lives in named constants (`Carousel.*`, `Card.REGIONS`, `Card.CAMERA`, `Card.SPIN`).
