## Solution
One pure leaf, `Logic/Board`, carries every rule: what a board shows (tabs, header, rows, revives "—", the your-best line, its notes and layout), the client's defensive read of an answer, when the client asks again, and the server's read policy (`Board.plan`). Each title's boards stay the arcade's (f0197): the portal's server adapter `BoardRelay` opens every card's title with `Boards.open(HiscoreGames[name].prefix)` and serves it on a relay of its own, a table with the two members `serve` uses (`OnServerEvent`, `FireClient`), which no client can reach. In front of the four relays sits one RemoteEvent, `ReplicatedStorage.Remotes.Boards`: a client asks with (title, board id), and `Board.plan` decides per ask whether it may make the arcade read its stores (a **refresh**: `REFRESH` after that board's last one, under a read allowance of 1.5 a minute per player and the engine's request budget above a reserve), merely join the arcade's fresh cache (a **forward**, inside its 15 s cache time), or be answered from the rows this server holds (the **snapshot** per board: the arcade's E3 fallback, which this issue makes the design). The client adapter `BoardsView` fills the `Boards` slot f0205 leaves on every card (`CarouselView.card(name).Boards`) with the tabs, the header, ten row lines, a note and the your-best line, binds the tab keys, and asks for the front card's board (`CarouselView.focused()`) when the front card or tab changes and every 30 s after.

### 1. `src/shared/Logic/Board/init.luau` (new, pure, a leaf: requires nothing)
The word `game` is refused in Logic (pickman-arch rule 2): a game here is a *title*. Every table is frozen.
```luau
export type Id = string -- one of TABS; a string because the Roblox type pass widens a literal union across a require (E9)
export type Row = { rank: number, name: string, score: number, level: number, revives: number }
export type Best = { score: number, level: number, revives: number }
export type Status = "ok" | "failed" | "wait"
export type Answer = { name: string, id: Id, rows: { Row }, rank: number?, status: Status, best: Best? }
export type Line = { cells: { string }, mine: boolean }
export type View = { header: { string }, lines: { Line }, note: string, best: string }
export type Layout = { tabs: number, line: number, view: number, canvas: number } -- pixels in the slot
export type Asked = { name: string, id: Id, at: number, wait: boolean }          -- the client's last ask (os.clock)
export type Snap = { at: number?, failed: boolean, known: boolean, rows: { Row } } -- the server's rows of a board
export type Bucket = { tokens: number, at: number? }
export type Budget = { standard: number, sorted: number }
export type Ask = { snap: Snap?, last: number?, all: boolean, bucket: Bucket, budget: Budget, players: number, now: number, ttl: number }

Board.N = 10; Board.NONE = "—"; Board.LOADING = "LOADING"; Board.EMPTY = "NO SCORES YET"
Board.DOWN = "SCORES UNAVAILABLE"; Board.BEST = "YOUR BEST"
Board.COLUMNS = { Rank 0.1, Name 0.38, Score 0.2, Progress 0.14, Revives 0.18 } -- { name, width }, widths sum to 1
Board.KEYS = { W = -1, Up = -1, ButtonL2 = -1, S = 1, Down = 1, ButtonR2 = 1 }
Board.ACTION = "PortalBoards"; Board.PRIORITY = 2500 -- above the default controls (2000), below f0201's 3000
Board.REASK = 30; Board.WAIT_RETRY = 2                     -- client seconds
Board.TAB_PX = 44; Board.MIN_LINE_PX = 13; Board.MAX_LINE_PX = 28
Board.REFRESH = 30; Board.MARGIN = 2; Board.BEST_GAP = 60  -- server seconds (os.time)
Board.RATE = 1.5; Board.BURST = 4; Board.KEEP = 1          -- refreshes a minute per player; at once; kept for a first answer

function Board.header(progress: string): { string }    -- { "#", "NAME", "SCORE", upper(progress), "REVIVES" }
function Board.cells(row: Row): { string }             -- rank, name, score, level, revives(revives)
function Board.bestLine(best: Best?, progress: string): string
function Board.view(answer: Answer?, tab: Id, progress: string): View
function Board.parse(names: { [string]: boolean }, ...: any): Answer?

function Board.fill(b: Bucket, now: number, players: number): Bucket
function Board.bestRead(last: number?, now: number, ttl: number): "read" | "fresh" | "hold"
function Board.plan(a: Ask): Plan
function Board.status(snap: Snap?): Status

```
- **The view**: `bestLine` is `YOUR BEST {score} · {PROGRESS} {level} · REVIVES {revives(...)}`, or `YOUR BEST —` for nil. `view(nil | wait)` is LOADING with no lines and no best; otherwise one line per row, `mine` when the answer's rank is that row's; the note is "" with rows, else DOWN for a failed answer and EMPTY for an ok one; the best line on the "all" tab only.
- **The client's read** (`parse(names, name, id, rows, rank, status, best)`): nil unless `names[name]`, a board id and a status of ok, failed or wait. Rows: a non-table is no rows; each entry must be a table with a whole rank 1..N, a string name, a whole score >= 0 and a whole level >= 1, else it is dropped; junk revives read 0; sorted by rank, cut to N. A rank is kept only when it is a kept row's. The best only for "all", and only with a whole score >= 0 and level >= 1 (junk revives 0). Never raises.
- **The layout** in a slot `height` px tall: the tab bar is `TAB_PX` (the smallest touch target, pickman's `Lobby.BUTTON_MIN_PX`); `line = clamp((h - TAB_PX) / (N + 2), MIN_LINE_PX, MAX_LINE_PX)` for the header, each row and the best line; `view = max(0, h - TAB_PX - 2 line)`; `canvas = N line`. A height that is not a positive finite number is 0.
- **When the client asks** (`askDue`): a new title or tab, a clock that went back, or `REASK` since the last ask (`WAIT_RETRY` when its answer was a wait); a non-finite time never.
- **The read policy** (`plan`), the arcade's E3 (E3 below for the numbers):
  - A non-finite `now` or `ttl`: answer, the allowance untouched.
  - The allowance is refilled first (`fill`): full (`BURST`) when never filled; re-dated only when the clock went back; else `RATE × max(1, players) / 60` a second, at most `BURST`.
  - `bestRead(last, now, ttl)` (all-time asks only; any other board counts "fresh"): "read" when never read, after a clock that went back, or `BEST_GAP` since `last`; "fresh" inside `ttl - MARGIN` (the arcade still holds that best and reads none); "hold" between.
  - **Forward** when the board's last refresh (`snap.at`) is at most `ttl - MARGIN` seconds ago (`now >= at`, `now - at < ttl - MARGIN`) and the last arcade answer heard for it did not fail (`not snap.failed`): the arcade answers from its cache or adds the asker to the read under way, reading no board. An all-time forward on "hold" is answered instead; on "read" it needs `budget.standard >= RESERVE.standard + 1`, else it is answered; `best = (reads == "read")`.
  - **Refresh** when the board is due (no snapshot, never refreshed, a clock that went back, or `REFRESH` since `snap.at`), the allowance holds `1 + KEEP` tokens for a board that has rows (1 for one with none, so a first answer is never starved by re-reads), and the engine's budget holds `RESERVE + COST` of both kinds: one token taken; `best = (reads ~= "fresh")`.
  - Else **answer** from the held rows.
- `status`: wait before any arcade answer was heard, failed after a failed one, else ok. `rankFor`: the held rank when it was heard at or after the board's last refresh began, else nil.

### 2. `src/server/BoardRelay.luau` (new, server adapter) and `src/server/Main.server.luau`
```luau
BoardRelay.start(): () -- once per server; a second call does nothing
```
Requires: `@game/ReplicatedStorage/Shared/Logic/Board`, `@game/ReplicatedStorage/Shared/Games`, `@game/ReplicatedStorage/Arcade/HiscoreGames`, `@game/ReplicatedStorage/Arcade/Logic/Hiscores` (for `cacheKey` and `CACHE_TTL`), `@game/ServerStorage/Arcade/Boards` (a server root may reach ServerStorage, portal-arch change 1).
- **At start**: `remote = ReplicatedStorage:WaitForChild("Remotes"):WaitForChild("Boards")`. For every `Games.LIST` entry with a `HiscoreGames[name]`, a relay `{ OnServerEvent = { Connect = (fn) -> adds fn to that title's handlers }, FireClient = (_, player, ...) -> heard(name, player, ...) }` and, inside a `pcall`, `Boards.open(prefix).serve(relay :: any)`; a title whose open fails is left out with one `warn` and the others are served (lesson pickman-arch/open-stores-guarded: nothing here may stop the boots after it). `Players.PlayerRemoving` drops the player's slot.
- **State**: per title, a `Snap` per board key (`Hiscores.cacheKey(id, os.time())`, so a new UTC day or week is a new board); per Player object a slot `{ ranks[title|key]: Held, best[title]: Best?, last[title]: number }`; one `Bucket` for the server (starting empty and never filled, so the first fill makes it `BURST`).
- **An ask** (`remote.OnServerEvent`, `(player, rawName, rawId)`): nothing for a player whose `Parent` is nil, a title it does not serve, or a board id that is none. Otherwise it forgets the snapshots of past periods for that title (a sweep), reads the engine's budget (`DataStoreService:GetRequestBudgetForRequestType(Enum.DataStoreRequestType.StandardRead)` and `(…OrderedList)`, E2; inside a `pcall`, a failure being a budget of 0, so nothing is read), and calls `Board.plan({ snap, last = slot.last[name], all = id == "all", bucket, budget, players = #Players:GetPlayers(), now = os.time(), ttl = Hiscores.CACHE_TTL })`, keeping its bucket. **answer**: `remote:FireClient(player, name, id, snap.rows, Board.rankFor(slot.ranks[name|key], snap), Board.status(snap), best)`, where `best` is `slot.best[name]` for "all" and nil otherwise. **refresh** and **forward**: when `plan.best`, `slot.last[name] = now`; a refresh sets `snap.at = now`; then `task.spawn(fn, player, id)` for each of that title's relay handlers (the arcade's `serve` handler), so a read that yields never holds the remote's handler.
- **The arcade's answer** (`relay:FireClient(player, id, rows, rank, failed, best)`, from `serve`): for a board id, at `now = os.time()`, the board's snapshot takes `rows` (a table, else none), `known = true` and `failed = failed == true`; the player's slot, if any, takes `{ rank, at = now }` for that board and, for "all", the best; and, while the player's `Parent` is set, `remote:FireClient(player, name, id, snap.rows, rank, Board.status(snap), best for "all" else nil)`. A player who left hears nothing, but the rows are held for the next asker.
- `Main.server.luau` gains `require("./BoardRelay").start()`, after f0205's `Cards`.

### The split and server authority
Everything that decides is pure and unit-tested in Lune: what a board shows, the client's read, the layout, when the client asks, and when the server may read the stores. The adapters only translate: `BoardRelay` turns asks and the engine's budget into `Board.plan` calls and its acts into forwards to the arcade's `serve` and replies; `BoardsView` turns answers, keys, taps, the slot's size and the clock into Board calls and Instances. The server alone reads the stores (through the arcade's `Boards`, in ServerStorage, which never replicates); a client sends only (title, board id), both validated (a known title, `Board.id`); nothing a client sends decides how often a store is read: the server's allowance, its per-board `REFRESH` and the engine's budget do. Replies carry no user id (f0197's `boardRows`).

### Edge cases
- No player has played a title: the arcade's all-time read falls back to its per-player board (f0197); the board says NO SCORES YET; the best line says YOUR BEST —.
- A store down or busy: the arcade answers failed with the rows it held; the portal holds and shows them (or SCORES UNAVAILABLE without rows), closes its forward window for that board and reads again only after `REFRESH`.
- The engine's budget below the reserve, or unreadable: no read; a first ask is answered wait (LOADING) and the client asks again after `WAIT_RETRY`.
- A flood of asks from one client (or many): reads stay bounded by the allowance, `REFRESH` per board and the budget (E3); answers from the snapshot are one small `FireClient` each and no store call.
- A player who leaves during a read: the arcade does not answer them; the rows still reach the snapshot through any other waiter, and when none, the next ask after `REFRESH` reads again. Residual (accepted, E5): if the refresh's only asker leaves and that read fails, the forward window stays open, and a forward inside it after the arcade's failure wait (2 s, then 4 s) may read once or twice outside the allowance.
- A new UTC day or week: a new board key, so a first ask refreshes it (as the arcade's own cache does); the old key's snapshot is swept.
- A player who rejoins: a new Player object, a new slot; their best is read afresh (inside the budget).
- A malformed answer (only from a bug): dropped whole or row by row by `Board.parse`; nothing raises.
- A long name: cut at the cell's end. A small screen: rows scroll in the board; every line at least 13 px (E3 of f0205's screens, AC1).
- The clock going back: on the server a board is due and the allowance is re-dated; on the client an ask is due.
- Frame rate: nothing counts frames; asks go by `os.clock`, reads by `os.time`.

### Scalability
- **DataStore reads (E3)**: a refresh is at most one sorted read (`GetSortedAsync`, the day or week page, or the all-time page for a title with no list yet) and 12 standard reads (the list `GetAsync`, ten companion rows, the asker's best). Refreshes per portal server are at most `BURST + RATE × players × minutes`: 1.5 a minute per player against the engine's sorted budget of 5 + 2 per player a minute, and each board at most once per `REFRESH`. Standard reads: at most 18 a minute per player from refreshes plus at most 4 best reads a minute per player (one per title per `BEST_GAP`), with the wallet's 4 (f0205), 26 of the engine's 60 + 40 per player. Across the experience (300 + 2 per concurrent user a minute for sorted reads, shared with every place), the portal spends at most 1.5 per portal player plus 4 per server burst. Proven on the real arcade `Boards` by `budget.spec` (1, 4 and 20 players flooding every board every second).
- **Freshness**: a board kept in front shows a new run within `2 × REFRESH` (60 s, `budget.spec`); with few players and many boards wanted, the allowance spreads refreshes (a board with rows waits while `KEEP` is kept for one without).
- **Replicated**: one RemoteEvent; an answer is ten rows of five small fields (under 1 KB); a client asks once per front-card or tab change and every 30 s.
- **Client**: four slots of about 70 GuiObjects each; per frame one `focused()` call and one comparison; drawing only on answers, tab changes and resizes.
- **Server**: per ask a table walk, two budget reads and at most one `FireClient`; memory per player is one slot of at most 12 ranks, 4 bests and 4 times, dropped on leave; snapshots are 12 per server.

### Maintainability
A fifth title is one `Games` entry (f0205) and one `HiscoreGames` entry (f0197): the relay opens it, the view fills its slot and labels its figure, and nothing branches on a title's name. The tuning (tabs, keys, columns, lines, the read policy's numbers) is named constants in `Board`; the read policy is one pure function with its own spec, so a later cross-server cache (a MemoryStore snapshot) replaces the relay's forwards without touching the view. The relay depends on f0197's `serve` contract only through the two members its promoted spec pins (E4).

### Usability
- **Player**: the front card's board is readable on every screen the carousel fits: at least 13 px lines, all ten rows without scrolling on a 720 px screen and above (the slot is 207 px there), scrolling on a phone held sideways (112 px); tabs are 44 px touch targets; the chosen tab is lit on every card, so a player comparing games keeps their tab; revives read as a count, "—" for none, under a REVIVES header; the player's own row is lit; LOADING, NO SCORES YET and SCORES UNAVAILABLE say what is happening; keyboard (W/S, arrows), gamepad (triggers) and touch (tap, drag to scroll) all work.
- **Developer**: the client API is one `start`, the server's one `start`; the Logic is small typed functions; the protocol is one remote with a 2-value ask and a 6-value answer, read defensively.
