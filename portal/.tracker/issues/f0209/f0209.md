## Solution
c0210's manifest makes the switch one line: the Portal place of `portal/experience.json` (the one place reading `ROBLOX_BETA_PLACE_ID`) publishes the `portal` build instead of the `lobby` build. Once no place names the `lobby` build, the lobby is neither built nor published; its build and code stay, unused, until c0188, which is also what makes the rollback that same line set back. The portal's build gains its runtime folder, `portal/tests/runtime/`, whose structure check is what the merge's `cicd` (`runtime-test --place Portal`) runs on the CICD start place: proof, on a real Roblox server, that the start place runs the portal and was told where Pickman is. Pickman's game is told the start place's id as before (`LobbyPlaceId` until f0187, and `PortalPlaceId`), so its game over now leads to the portal; every other game's way back is `PortalPlaceId`, the same id. Nothing else changes in the publish: the same variables, the same order (games first, the start place last), the same output names, no production variable. The documents that say what the start place is (SETUP.md, pickman's game design, pickman-test, portal-test) say the portal.

### 1. The switch: `portal/experience.json` (two lines)
- The Portal place: `"build": "lobby"` becomes `"build": "portal"`. Its name, `env` (`["ROBLOX_BETA_PLACE_ID"]`) and `output` (`"lobby_version"`) stay.
- The `portal` build: `{ "project": "default.project.json" }` becomes `{ "project": "default.project.json", "runtime": "tests/runtime" }`. No `attributes`: the portal reads no extra id (f0208), and `GamePlaceId` stays on the unused `lobby` build.
- The `lobby` build and every other line stay. With no place naming it, the plan never builds or publishes it (c0210: "unused builds are neither built nor published"); c0188 deletes it with `pickman/lobby.project.json`. The `pickman` build keeps `"attributes": { "LobbyPlaceId": "Portal" }` (f0187 removes it), whose value is the start place's id, now the portal's.
- **Against the reader's refusals** (c0210 after its review): the two edits add no backslash, no key twice in one object (`runtime` is new in the `portal` build), and no project under two builds (`default.project.json` stays the `portal` build's alone, `../pickman/lobby.project.json` the `lobby` build's); the rollback (§7) sets back one value and keeps each project under one build. A switch made the other way, by pointing the `lobby` build at `default.project.json`, is now refused by the reader ("one project file under two builds"), which mutant F4 meets.
- **The output keeps its name `lobby_version`** (decided here): it is the start place's version in the deploy's output, read only by `portal/scripts/cicd.luau` and pinned by c0064's `deploy.spec`, c0172's `cicd.spec` and c0210's `manifest.spec`; renaming it would cost three more promoted-spec overrides for a name nobody sees (the PR comment shows Pickman's `version`). c0188, which removes the lobby, may rename it with its own overrides.

### 2. The start place's runtime tests: `portal/tests/runtime/structure.luau` (new)
A runtime script as pickman's are (pickman-test, `tests/runtime/`): strict Luau, requires nothing, reaches Roblox's `game` through `getfenv()`, returns `"PASS"`, and asserts (each failure names what is missing):
- not pickman's lobby: no `ServerScriptService.Lobby`;
- the portal's server: `ServerScriptService.Server` with `Main`, `Cards` (f0205) and `Plays` (f0208);
- the portal's remotes: `ReplicatedStorage.Remotes` with `Cards` and `Play`, and no `Snapshot` (pickman's game has one);
- the library: `ReplicatedStorage.Arcade` and `ServerStorage.Arcade`;
- the publish told it where Pickman is and where it is: `PickmanPlaceId`, then `PortalPlaceId`, each a whole number ≥ 1 (checked in that order, so an untold place names `PickmanPlaceId`);
- paid play's mode is set (`PaidPlay` a string), and `Players.CharacterAutoLoads` is false.
`runtime-test --place Portal <version>` (from `portal/`) runs it through c0210's runner (no change to the runner). The headless twin of it is AC3: the script run with `game` set to the place the deploy builds.

### 3. What the merge's `cicd` and `runtime-test --place Portal` prove

### 6. During the publish
