# c0098: Remap index free

## Problem
`tracker.sh remap` builds its remapped merge base with `git add -A` and `git write-tree` in a scratch worktree, and merges with `git merge-tree --write-tree` (main.luau, `cmd.remap`). c0053's AC9 greps `scripts/tracker/` for the index plumbing names and finds both. R0025's RC7 runs that grep verbatim, so it fails on `main` today. Only the first is index plumbing, but the grep can't tell them apart.

## Non-goals
- Changing what `remap` computes: the remapped merge base, the merge of `origin/main`, the printed map.
- `compact` and `compact.apply`: they work in a checkout (or scratch worktree) with ordinary `git mv`, `git add` and `git commit`, as every working-tree command does. The rule that matters here is c0053's: no private index (no index variable, no `read-tree`, `update-index` or `write-tree` plumbing), which is what lets publish build trees with no index at all.
- Rewriting compact.apply over git objects.

## Solution
In `cmd.remap`, the scratch worktree of the merge base is still built with `compact.apply`. Its tree is then taken from `git stash create` after `git add -A` in that scratch worktree. That command writes a commit object for the worktree's tracked state and prints its sha, and moves no ref (not even the scratch HEAD). It prints nothing when nothing changed, and then the base tree is the merge base's own tree. `git write-tree` goes. The merge drops its `--write-tree` flag: with two commits and `--merge-base`, write-tree mode is git's default (git 2.38 and later; `--merge-base` already needs a newer git), and the output is the same (checked with git 2.54). After both, `scripts/tracker/` names none of the banned words.

## Design
- `cmd.remap`, inside the `pcall` that builds the base: `git add -A` (unchanged), then `git stash create` in `scratch`. A non-empty sha `s` gives `baseTree = rev-parse s^{tree}`. Empty output gives `baseTree = rev-parse <mb>^{tree}`. Failures raise as today, and the scratch worktree is removed either way.
- `git merge-tree --merge-base=<baseTree> HEAD origin/main`, with no `--write-tree`. The output is the same: the tree id on the first line, then conflict lines.
- No other change.

### Scalability
The same: one commit object instead of one tree object.

### Maintainability
The tracker's code no longer names `write-tree`, so the guard against a private index (c0053 AC9) is a plain grep again.
