# c0129: Remove dead play again hook

## Problem
Since R0034 (f0065) the game place has no PlayAgain, so src/server/Submits.luau's Submits.again (comment: 'Session.playAgain accepted: the next run') has no caller; Sessions' Runs type already dropped its again field. Remove Submits.again or reword it, keeping Hiscores.onAgain (pinned by f0025's run.spec) unless a later prep decides otherwise.

## Non-goals
- `Hiscores.onAgain`, `RunState.run` and their unit specs stay as they are (the capture keeps `onAgain`; f0025's `run.spec` and `tests/unit/Hiscores/run.spec` pin it). With no caller, `run` stays 1 on the game place; whether to drop the run counter is a later decision.
- `Session.playAgain` in Logic stays (R0035's `drops.spec` and `airborne.spec` call it).
- f0025's promoted `sessions.spec` keeps its own stub runs with an `again` field: it is a test double, not the adapter, and it is promoted (never edited here).
- No behaviour change: a run still submits once at game over, and a closing server is still held.

## Solution
Remove `Submits.again` and its comment from `src/server/Submits.luau`. Nothing calls it since R0034 (f0065) removed the PlayAgain handler and the `again` field of Sessions' `Runs` type, so this is a pure deletion of eight lines.

## Design
- `src/server/Submits.luau` (server adapter) loses `function Submits.again(s: any)` and the comment above it. Its public table is then exactly `ready`, `step`, `pending` and `close`; their signatures and bodies don't change. `held`, `count` and `BindToClose` don't change.
- The adapter no longer references `Hiscores.onAgain`. `Hiscores` (pure Logic) is untouched: `onAgain` stays exported.
- No server source (`src/server/*.luau`, comments stripped) defines or calls an `again` hook in any of the forms `.again(`, `:again(`, `.again =` or `["again"]`: Sessions already calls only `runs.ready` and `runs.step`. `playAgain` names (Logic's `Session.playAgain`) do not match, since the character before `again` is `y`.
- No client, remote, Logic or place-structure change; no new dependency edge, so `tracker/architecture.md` is unchanged.

### Scalability
Unchanged: Submits keeps one held run per session; removing a function has no cost.

### Maintainability
A function with no caller and a comment that names a flow the game no longer has (play again) misleads a reader into thinking the place can start a second run. Removing it leaves Submits' API matching what Sessions' `Runs` type uses (`ready`, `step`), plus `pending` and `close` for the close hold.

### Usability
No player-visible change.
