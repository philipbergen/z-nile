# c0131: Ref guard empty fetch

## Problem
The ref guard refuses a check.sh flow's fetch that has nothing new (git runs an empty ref transaction, and the guard requires at least one ref), which makes c0127's AC5 (scripts/ci-verify.sh fetches the raft branch) fail whenever the remote-tracking ref is already current; c0122's outcome, delivered here because it blocks R0047's check.sh

## Non-goals
- Trusting an inherited `PICKMAN_FENCE_HOOKS` (c0123).
- Letting spec runs fetch: an empty transaction during a spec run stays refused, like every update there.
- Any other rule of the guard: updates outside `refs/remotes/`, deleted refs, and mixed transactions stay refused.

## Solution
`scripts/lib/git-hooks/reference-transaction` accepts a transaction with no refs (`lines` 0) in a protected repository when it is not a spec run (`PICKMAN_FENCE_SPECS` empty). A fetch with nothing new makes git run exactly such a transaction (`preparing`, `prepared`, `committed`, each with no ref lines; c0122's capture), and it changes nothing. This is c0122's outcome; it is fixed here as an emergent issue because R0047's check.sh cannot pass without it: c0127's AC5 runs `scripts/ci-verify.sh`, whose `git fetch origin <branch>` has nothing new whenever the branch was just pushed, and the guard refused it (R0047 execution, 2026-10-22: `fence: a check tried to change refs in the real repository (…/.git); refused`).

## Design
- One added line before the existing allow line: `[ "$lines" -eq 0 ] && [ -z "$PICKMAN_FENCE_SPECS" ] && chain "$@"`, and the header comment says so. `chain` runs the repository's own hook as today. The existing allow line (every ref created or moved under `refs/remotes/`) and the refusal after it are unchanged.
- Only `prepared` is judged (the hook already passes every other phase through to `chain`), so the case covers all three phases for completeness.

### Scalability
No cost: one integer test.

### Maintainability
The rule stays one script; the comment names the empty transaction and this issue.

### Usability
A `check.sh` can fetch whether or not anything is new, so `scripts/ci-verify.sh` works on a branch that was just pushed (c0127's AC5, c0001's AC3, and c0120's AC16 that worked around it).
