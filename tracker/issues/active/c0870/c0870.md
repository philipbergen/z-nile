# c0870: Compact ids and allocate them from a next-number file

## Problem
Ids step by ten (`tracker.sh new` picks the next multiple of 10), so the four-digit space fills ten times faster than needed, and old gaps are never reused. Allocation today scans the local tree and `origin/main` and publishes a stub by lease push (c0510).

The user's design (2026-10-04, their words, sharpened):
- **Compaction**: a command that renumbers every item, starting from 0001 (issues `f`/`d`/`c`, and rafts `R`), to open up the address space. Every reference is rewritten, as `renumber` does today.
- **Count by one**, not by ten.
- **A next-number file**: a single-line file in the tracker with two entries, `<next number> <random word>`. The random word makes two terminals' writes of the same number differ, so they collide in git instead of merging silently.
- **Allocation**: push `N+1` with a new random word to `main`. If that push collides, someone else took `N+1`: revert your change, pull the new `main`, and repeat until there's no conflict.


User decisions in prep (2026-10-04; and after design review 003: **strictly by one**, no numbers skipped after the compaction, which is a one-off clean slate starting from 1; `tracker.sh sync` stays as it is): this raft holds c0870 and c0880; `f`, `d` and `c` keep one shared number space and rafts keep their own, in **one** file with two lines; compaction **refuses while another branch changes the tracker** (`--force` overrides), and in-flight branches catch up with a `remap` command.

## Non-goals
- Changing the id format (a letter plus four digits).
- The duplicate-id audit itself: c0880 (this raft uses it).
- **Running** the compaction on the real tracker. This issue delivers the command; the user runs it once `main` is quiet (R0270, Risks).
- Rewriting ids outside `tracker/` (code comments such as `-- See c0510.`, skill examples, commit messages, PR titles, fixture literals in specs). They keep the old ids; `tracker/compaction.txt` maps them. Only *paths* to promoted spec folders (`tests/acceptance/<id>`) are rewritten repo-wide, because those folders move.

## Solution
- **`tracker/next`**: `issue <n> <phrase>\nraft <n> <phrase>\n`, `<phrase>` three stamp words joined by hyphens (as `status:` stamps), one fresh phrase per write on both lines, so any two writes conflict in git.
- **Allocation, publishing**: `new issue`, `new raft`, an emergent `new issue --raft`, and `renumber <id>` without `<new>` read `origin/main`'s `tracker/next` inside c0510's `publish.commit` build, take `max(counter, highest id in use + 1)`, and push the raised counter in the same commit as what they create (an emergent issue and `renumber` push only the counter, then work locally). A lost race is a rejected lease push: `publish.commit` already fetches, rebuilds and retries, which is the user's "revert, pull, repeat".
- **Allocation, offline** (`PICKMAN_PUBLISH=0`, no origin, or a check run): `max(local counter, highest + 1)`; `tracker/next` is never written offline, so it only ever moves on `origin/main` (by publish) or in a compaction commit.
- **Legacy**: a tree with no `tracker/next` (every fixture that copies `tracker/templates` only) numbers exactly as today: `new` the next multiple of 10, `renumber` one above the highest. This keeps about 17 promoted and prepared specs valid without edits; the real tracker always has the file (c0880's audit makes a missing one a gate error).
- **`tracker.sh compact [--force]`** and **`tracker.sh remap`**, below.
- `publish.allowed` admits `tracker/next`; an existing `tracker/next` may only be replaced by one that parses and whose counters do not go down.
- **A tree from before a compaction never publishes**: when `origin/main` has a `tracker/compaction.txt` and the local one is missing or differs, every command that publishes (`new`, emergent `new`, `new raft`, `renumber` without `<new>`, `status <id> <to>`, `start`) refuses. The check lives in one helper, `local function publishFresh(build, message)`, the only caller of `publish.commit` in `main.luau` besides `cmd.remap` (which is exempt: it is the way out); `publish-guard.spec` holds every later command to it (review 003 F5). Its message gives the way out per case: `this tree predates the compaction on origin/main: a branch that changed tracker/ runs tracker.sh remap; any other merges origin/main` before publishing anything. Otherwise one stale worktree (old-scheme ids such as `c0890` in its tree) would push the counter back up past them.
- **`tests/lib/renamed.luau`** (`renamed.id(old: string, mapText: string?): string`): maps an id through `tracker/compaction.txt` (read from the checkout when `mapText` is nil; identity for an id not in the map, and when there is no map; errors on a malformed map). It is self-contained: it parses the map format itself and does not require `@scripts/tracker/ids`, because c0640's fence spec copies `tests/lib` without `scripts/` and runs `repo-fence.spec` there (found by the prototype). Specs that pin **real** tracker items use it, so they hold before and after the user's compaction: c0410's `rounds.spec` and `tests/tooling/repo-fence.spec.luau`'s exemptions for c0640.
- The testing skill, in its spec-writing rules: a spec that pins a real tracker item maps its id through `tests/lib/renamed.luau`, and test data that names a `tests/acceptance/<id>` path spells it in two parts (review 002 F4).
- The tracker skill: Numbering, a Compaction bullet (run on a quiet `main`; a busy branch runs `tracker.sh remap` **before merging `origin/main`**, never a plain merge, which nothing detects afterwards; a branch that merged plainly undoes it with `git reset --hard ORIG_HEAD` and then remaps; merge the compaction PR only while `origin/main` **still equals** the sha in `tracker/compaction.txt`'s header, else reset and compact again), Other commands, the direct-push exception ("…and `tracker/next`, whose counters may only go up"), and the "Published or carried" list (an emergent `new issue` and `renumber` without `<new>` push a counter-only commit); the Conflicts rule is unchanged (`renumber <ID>` still names one above the highest, now through the counter).

## Design

### Module map
```
scripts/tracker/ids.luau      NEW  pure: the counter file, allocation by one, the compaction map, reference rewrites
scripts/tracker/compact.luau  NEW  I/O: apply a map to a tree (two-phase renames, rewrites), busy refs
scripts/tracker/main.luau     allocation through ids; cmd.compact, cmd.remap; USAGE
scripts/tracker/publish.luau  allowed() admits tracker/next; existing-file rule for it
scripts/tracker/audit.luau    (c0880) run before and after compaction
.claude/skills/tracker/SKILL.md
```
`ids` requires nothing. `compact` requires `ids`, `store`, `../lib/sh` and `@lune/fs`. `main` requires `ids`, `compact`, `audit`. No `src/` change, so `tracker/architecture.md` is untouched (it covers `src/` only).

### `scripts/tracker/ids.luau` (pure)
```lua
export type Space = "issue" | "raft"
export type Counters = { issue: number, raft: number }
ids.FILE = "tracker/next"
ids.MAP_FILE = "tracker/compaction.txt"
ids.spaceOf(id: string): Space?                 -- f/d/c -> "issue", R -> "raft", else nil (exactly a letter + 4 digits)
ids.parse(text: string): Counters?              -- exactly "issue <n> <phrase>\nraft <n> <phrase>" (+ optional final \n);
                                                --   n: 1..10000, no leading zero; phrase: [a-z]+(-[a-z]+)*; else nil
ids.format(c: Counters, phrase: string): string -- "issue <n> <phrase>\nraft <n> <phrase>\n"
ids.highest(space: Space, list: { string }): number          -- 0 when the space has no id in list
ids.nextFree(space: Space, c: Counters, used: { string }): number  -- max(c[space], highest(space, used) + 1)
ids.plan(list: { string }): { [string]: string }  -- every id -> its compacted id: per space, sorted by
                                                   --   (number, prefix c < d < f), numbered 1, 2, 3 ...
ids.rewrite(text: string, map): string           -- every whole-token id (%f[%w] .. %f[^%w]) in map, one pass
ids.rewritePaths(text: string, map): string      -- "tests/acceptance/<id>" for <id> in map, one pass, only where the
                                                 --   path starts a token: preceded by nothing, whitespace or one of
                                                 --   " ' ` ( [ = : , -- never by a word character, / . } $ or -
ids.formatMap(map, header: string): string       -- "# <header>\n" then "<old> <new>\n" sorted by old (byte order)
ids.parseMap(text: string): { [string]: string }? -- "#" lines ignored; nil on a malformed line, a prefix change,
                                                   --   a repeated old id or two olds onto one new
```
A number that would exceed 9999 is refused by the caller with `no number above 9999 is free` (as `renumber` does today).

### Allocation (`main.luau`)
| command | publishing, origin has `tracker/next` | offline, local `tracker/next` | no `tracker/next` |
|---|---|---|---|
| `new issue` (backlog) | stub + `check.sh` + counter in one `publish.commit`; then merge origin as today | `ids.nextFree` over local ids; counter not written | today's rule |
| `new issue --raft <active>` | `publish.commit` of the counter only, then the local stub in `active/` | as left | today's rule |
| `new raft` | raft doc + member claims + counter in one commit | as left | today's rule |
| `renumber <id>` (no `<new>`) | `publish.commit` of the counter only, then the local rename | `max(counter, store.nextAbove)` | today's rule (`store.nextAbove`) |
`used` is origin's ids plus the local tree's (as today). The publishing build reads origin's counter through `read(ids.FILE)` on the same base sha it lists, so a retry re-reads it. The phrase is `string.sub(stamp("x"), 3)`'s three words, drawn once per build. `renumber` keeps every c0500 rule: no `<new>` needs a readable `origin/main`, an explicit `<new>` is used as given and publishes nothing.

### `tracker.sh compact [--force]`
1. Refuse in the main checkout (`refuseInMainCheckout`), on a dirty tree, and unless `HEAD` equals `origin/main` after `git fetch -q --prune origin` (message names `origin/main`: "compact runs on a fresh worktree cut from origin/main").
2. **Busy refs**: every `refs/remotes/origin/*` except `main` and `HEAD`, and every `refs/heads/*` except `main` and the current branch, whose `git diff --name-only origin/main...<ref> -- tracker tests/acceptance` is not empty. Any busy ref and no `--force`: print each on stderr with `delete merged branches, land open ones, or pass --force`, exit 1, change nothing. With `--force`: go on and print `in flight: <ref>: run tracker.sh remap there before merging origin/main` for each.
3. **Pre-audit**: `audit.run(".")`; any error refuses, printing every problem (warnings are printed and do not refuse).
4. **Plan**: `ids.plan` over every item id (any state).
5. **Apply** (`compact.apply(map, root?)`, root defaulting to the checkout; git runs through `process.exec` with `cwd = root`), shared with `remap`: (a) move every item directory whose id changes, and its `<id>.md`, and every `tests/acceptance/<id>` folder whose id is in the map, first to a temporary name (`<new>.compacting`) and then to the final one, with `git mv`; (b) `ids.rewrite` over every `tracker/**/*.md` and `tracker/**/*.sh` except under `tracker/templates/`; (c) `ids.rewritePaths` over every **other** tracked text file (`git ls-files`, skipping files with a NUL byte, `tracker/templates/`, `tracker/next` and the map file). A file gets (b) or (c), never both: running both double-maps a path that (b) already rewrote.
6. Write `tracker/next` (`ids.format({ issue = issues + 1, raft = rafts + 1 }, phrase)`) and `tracker/compaction.txt` (`ids.formatMap(map, "tracker.sh compact, <date>, from origin/main <sha>")`; the `.txt` keeps it out of every later rewrite).
7. **Post-audit**: any error fails with the problems and `the tree is left as compact wrote it: git reset --hard to discard`.
8. `git add -A` and commit `tracker: compact ids`; print `compacted <n> issues and <m> rafts; map in tracker/compaction.txt`. Nothing is pushed: the user lands it by PR (R0270 Risks: if `main` moves first, the PR conflicts on `tracker/next`; reset to `origin/main` and run it again).

### `tracker.sh remap`
For a branch that was busy during a forced compaction. In a worktree, on a clean tree:
1. Fetch; read `origin/main:tracker/compaction.txt` (`ids.parseMap`); absent or malformed: refuse, naming `tracker/compaction.txt`. If the local `tracker/compaction.txt` equals origin's, refuse: `this branch already has the compaction`.
2. Local items whose id is not an old id in the map (created on the branch after the compaction's base), taken in `ids.plan` order (number, then prefix): they get consecutive numbers from **origin's** counter, starting at `ids.nextFree` over origin's ids only (the branch's own ids are in the old scheme and must not count, or `c0041` would become `c0042` instead of `c0003`), and one `publish.commit` of the counter raises it past the last of them when publishing (offline: from origin's counter value, nothing written). They join the map.
3. `compact.apply(map)` on the branch; commit `tracker: remap ids`; print `old -> new` for every rename.
4. **Merge origin/main itself**, against a remapped merge base (E2): a plain `git merge` pairs renamed documents wrongly (two template stubs that differ only in their ids). So: `git merge-base HEAD^ origin/main`; check that base out in a scratch worktree under `.cache/tracker-remap-base` (removed afterwards), `compact.apply(map, scratch)` there and record its tree (`git add -A`, `git write-tree`); `git merge-tree --write-tree --merge-base=<remapped base tree> HEAD origin/main`; on success `git commit-tree <tree> -p HEAD -p origin/main -m "Merge origin/main after remap"` and `git merge --ff-only` to it. On a conflict keep the remap commit, print the conflicting paths and `merge origin/main by hand`, exit 1.

### Scalability
The tracker holds about 110 items; compaction is O(files x size) string work in one process, well under a second for the item moves plus one `git ls-files` walk. Allocation adds one small blob to each publish. Counting by one leaves 9,889 issue numbers after compaction instead of today's ~910 multiples of ten.

### Maintainability
Every rule that is a function of text lives in `ids` (pure, unit-specced); `compact.apply` is the one place that moves and rewrites, shared by `compact` and `remap`; allocation goes through one helper in `main` (`allocate(space, count, paths, read)`), so the three creating commands and `renumber` cannot drift. The legacy branch is one `if not counters` per caller, deletable once no fixture relies on it.

### Usability
`new` prints exactly what it printed before. `compact` explains every refusal (the busy refs, `origin/main`, the audit's problems) and what to do next; `remap` prints each move. The skill gets one Compaction bullet with the whole procedure.
