# f0180: Hud

## Problem
The player needs to see their score, lives, level and a power-pellet timer, readable in first person and on any screen size.

## Non-goals
- Mobile-specific layout (f0280). Hiscore board (f0250).

## Solution
- A pure `Hud` feature: `Hud.model(play)` turns the frame's `play` record into what the HUD shows, and `Hud.layout(width, height)` gives whole-pixel sizes for any viewport.
- A thin `src/client/HudView.luau` draws them in a ScreenGui:
  - the score top-left;
  - the level top-right;
  - one yellow disc per life bottom-left;
  - a power bar bottom-right that drains through the frightened period and is hidden when no power is active.
- It lays out again when the viewport changes size.

## Design

### Decisions made in prep (author's choices; the user may veto)
- **Contents**: score, level, lives and power. There's no hiscore yet: the hiscores raft (R0110) brings boards, and a HUD best-score slot can come with it.
- **Score as plain digits** (`"12340"`), as the arcade shows it, with no padding or separators.
- **Lives include the one in play**: 3 discs at the start, 0 at game over. The arcade's "spare lives" convention (2 discs) assumes you can see Pac-Man on screen, but in first person you can't, so the count you can lose is clearer. It follows `play.lives`, so the extra life at 10,000 shows as a fourth disc.
- **Power is a share, not seconds**: `frightened / Levels.frightenedTicks(level, Session.TICK_RATE)`, clamped to 0..1, and 0 where the level has no frightened time. A draining bar reads at a glance and needs no unit conversion; game time against real time doesn't matter for a share.
- **Layout from the smaller viewport side**:
  - `textSize = clamp(round(min(w, h) · 0.045), 14, 40)`;
  - `margin = round(textSize / 2)`;
  - `iconSize = textSize`;
  - `barHeight = max(4, round(textSize · 0.4))`;
  - `barWidth = max(0, min(round(w · 0.25), 400, w − 2·margin))`.
  
  A zero, negative, NaN or infinite side counts as 0 (`if v > 0 and v < math.huge then v else 0`, applied before anything else). That gives text of 17 px on a 667×375 phone, 32 on 1280×720 and 40 (the cap) on 1920×1080, with the top band under 15% of the height on all of them. The arithmetic is free; the spec pins the properties, not the constants, so tuning them later needs no chore.
- **Mobile-specific placement** (thumb zones, 44 pt targets) stays with f0280. This issue only guarantees readable text and a band that doesn't eat the view.

### `Hud` (`src/shared/Logic/Hud/init.luau`, new feature)
```lua
export type Model = { score: string, level: string, lives: number, power: number }
export type Layout = { textSize: number, margin: number, iconSize: number, barWidth: number, barHeight: number }
Hud.MIN_TEXT = 14
Hud.MAX_TEXT = 40
function Hud.model(play: Session.PlayFrame): Model   -- pure, fresh table, input untouched
function Hud.layout(width: number, height: number): Layout
```
New feature and new edges **`Hud -> Levels`** and **`Hud -> Session`** (for `PlayFrame` and `TICK_RATE`), added to `tracker/architecture.md` in prep. `tests/meta` requires unit specs for every feature: add `tests/unit/Hud/`.

### Client adapter (`src/client/HudView.luau`, new)
```lua
function HudView.start()                          -- builds a ScreenGui "Hud" (ResetOnSpawn = false) in PlayerGui; lays out on ViewportSize changes
function HudView.show(play: Session.PlayFrame)    -- Hud.model(play) → label texts, life discs (rebuilt only when the count changes), bar fill and visibility
```
`Main.client.luau`: `HudView.start()` at boot, before `ready:FireServer()`, and `HudView.show(frame.play)` for every frame, before `PelletView.show`. The arcade font and yellow/white/blue colours are the adapter's to pick.

### Server authority
None here. The HUD shows the replicated record and decides nothing; it can't send.

### Scalability
O(1) per frame: four text and size writes, and the life discs rebuilt only when the count changes. A layout pass runs only on a viewport resize. Nothing new is replicated, since `play` is already in every frame.

### Maintainability
- A new HUD item (hiscore, fruit, a ghost-combo counter in raft d) adds a field to `Model` and a widget to `HudView`.
- `Model` holds display strings and numbers, so `HudView` never formats. The sizes come from one function.

### Usability
- **Player**: the score and level sit in the top corners, out of the corridor's centre. The lives are countable discs. The power bar drains visibly and disappears at the end of the period, so the player sees how long they're safe. Text never drops under 14 px.
- **Developer**: two pure functions, typed and tested headless.

## Acceptance criteria

### Checked
- **AC1**: `Hud.model(play)`:
  - `score` is plain digits;
  - `level` reads `LEVEL n`;
  - `lives` equals `play.lives`, the one in play included;
  - `power` is `frightened` over the current level's frightened ticks, clamped to 0..1 and 0 where the level has none (180 on L1, 30 on L18, 90 on L4);
  - every field follows the input, and the input is left unchanged.
- **AC2**: `Hud.layout(w, h)`:
  - every size is a whole number of pixels;
  - text is between `MIN_TEXT` 14 and `MAX_TEXT` 40 on any screen, and grows from phone to laptop to desktop;
  - the top band (text plus two margins) is at most 15% of the height on 1920×1080, 1280×720, 667×375, 375×667, 3840×2160 and 800×600;
  - the power bar plus margins fits the width, and the bar is at least 4 px tall;
  - life icons are at least 14 px;
  - portrait and landscape of one screen get the same text size;
  - a zero, negative, NaN or infinite viewport side counts as 0, giving the minimum, not an error.
- **AC3**: The client's `Main` requires `HudView` and calls `HudView.show(<frame>.play)`. `HudView` uses the `Hud` feature (`Hud.model`, `Hud.layout`), re-lays out on `ViewportSize` changes, and never touches a remote.
- **AC4**: `src/shared/Logic/Hud/init.luau` and at least one `tests/unit/Hud/*.spec.luau` exist, and `tests/meta/architecture.spec.luau` passes: `Hud` is a declared feature with unit specs, its edges are declared and acyclic, and Logic stays engine-free.

### Judged
None.
