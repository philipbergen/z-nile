## Problem
Ghosts alternate scatter and chase on a per-level timetable, turn frightened when a power pellet is eaten (random movement, slower, reversing once), and blink before recovering.

## Non-goals
- Eating ghosts, the chain's points and contacts with the player (f0220); the ghost house and eyes (f0210); drawing (f0310).
- Cruise Elroy (R0100 Theme).

## Solution
A pure ghost *set* (the four ghosts of one maze instance plus the mode, the clocks and a seeded generator) that listens for a power pellet; the level table gets the ghost columns (speeds, timetable). A forced reversal happens at every mode change. Ghost colours come from `look`, in the client adapter (f0310).

## Design
### Files and API
- `src/shared/Logic/Ghosts/init.luau`: the set and the modes, added to f0190's navigation.
- `src/shared/Logic/Ghosts/Rng.luau` (new): Park-Miller (`state * 16807 % 2147483647`); `Rng.seed(n)` maps any whole number to a state in 1..2^31-2, `Rng.next(state, n)` returns the next state and a pick in 1..n. One number of state, so a set stays plain data, and every product is below 2^53.
- `src/shared/Logic/Levels/init.luau`: new columns and functions.
```lua
-- Levels
export type Ghost = { speedFactor: number, tunnelFactor: number, frightFactor: number }   -- relative to level 1's player speed
Row.ghost: Ghost    Row.schedule: { number }      -- seconds: scatter, chase, scatter, ...; after the last, chase forever
Levels.GHOST_TUNING = 1                           -- the user's slower-ghosts factor (R0100): the classic tables at 1
Levels.EYES_FACTOR = 2
Levels.ghostSpeed(baseSpeed, level, kind: "normal" | "tunnel" | "frightened" | "eyes", tuning: number?): number   -- whole units, >= 1; memoise nothing here
Levels.schedule(level, tickRate): { number }      -- phase lengths in ticks, each >= 1; cache the result per (level, tickRate) in the implementation
-- Ghosts
export type Name = "blinky" | "pinky" | "inky" | "clyde"      -- from f0190
export type Look = "normal" | "frightened" | "blinking" | "eyes"
export type Input = { player: Maze.Tile, heading: Maze.Heading, level: number, baseSpeed: number, tickRate: number }
export type Event = { kind: string, ghost: Name?, mode: ("scatter" | "chase")?, ticks: number?, x: number?, y: number? }
export type Ghost = { name, tile, heading, progress, status: "house" | "leaving" | "active" | "eyes", frightened: boolean, reverse: boolean }
export type Set = { maze, level, rng, mode: "scatter" | "chase", phase, phaseTicks, frightened, chain, ghosts: { Ghost }, house, tuning, open }
Ghosts.new(m, seed, opts: { start: ("house" | "active")?, level: number?, tuning: number? }?): Set   -- here the default start is "active" (f0210 flips it to "house")
Ghosts.step(set, input: { player: Tile, heading: Heading, level: number, baseSpeed: number, tickRate: number }): { Event }
Ghosts.power(set, ticks)        Ghosts.reset(set, reason, level)       Ghosts.look(set, g): Look      Ghosts.flash(set): boolean
Ghosts.ghost(set, name): Ghost  Ghosts.occupiedTiles(set): { Tile }   -- the tile each ghost occupies, always inside the grid (wrapped through a tunnel), unlike `Ghosts.occupied(walker)` (f0190), which is unwrapped
-- events: ModeChanged{mode}, FrightenedEnded; Wrapped{ghost} and Entered{ghost,x,y} come from the walk
```
- **Starts**: `Ghosts.new` places the ghosts from `Classic.starts`. With `start = "active"` (the only mode in this issue, and the test mode afterwards) the three ghosts that belong in the house are put on the open row above the door instead, Pinky at (12,11), Inky at (13,11), Clyde at (14,11), with their `Classic` headings, all active; Blinky is at (14,11) heading west either way.
- **Speeds** (Table A.1, shares of the arcade maximum; level 1's player is 80%): ghost 75/85/95, tunnel 40/45/50, frightened 50/55/60 for level 1 / 2 to 4 / 5 on. A factor is the share divided by 0.8. Units per tick are `round(base * factor * tuning)`, at least 1 (level 1 with base 30: 28, 15, 19; level 5: 36). **Eyes** always run at `round(base * 2)` (60), whatever the tuning.
- **Timetable** (Table A.2, seconds): level 1 `7, 20, 7, 20, 5, 20, 5`; levels 2 to 4 `7, 20, 7, 20, 5, 1033, 1/60`; level 5 on `5, 20, 5, 20, 5, 1037, 1/60`; then chase for good. Ticks are `max(1, round(seconds * tickRate))` (1/60 s is 1 tick).
- **Step order** inside `Ghosts.step`: (1) the clock: while `frightened > 0` it counts down (and ends with `FrightenedEnded`, clearing every `frightened` flag **without turning any ghost back**: the arcade reverses ghosts on a scatter/chase change and when a power pellet is eaten, not when the blue time ends) and the schedule does not advance; otherwise `phaseTicks += 1` and, when the phase's length is reached, the mode flips, every `active` ghost gets `reverse = true` and `ModeChanged` is emitted; (2) the house (f0210); (3) every non-waiting ghost walks `speed` units with a `decide` that, at a centre, returns the opposite of the arrival heading if `reverse` (clearing it), else a uniformly random allowed exit (seeded) while frightened, else `pickExit` towards the scatter corner (scatter) or `chaseTarget` (chase) with `noUp = true`.
- **Which speed**: `eyes` for eyes; else `tunnel` if the occupied tile is a tunnel tile; else `frightened` if blue; else `normal`.
- **`power(set, ticks)`**: `frightened = ticks`, `chain = 0`, every non-eyes ghost `frightened = ticks > 0`, every active ghost reverses (also where `ticks` is 0). **Blinking**: `look` is `blinking` while `0 < frightened <= flashes * 14` (the level's flashes), `frightened` earlier, `eyes` for eyes, `normal` otherwise; `flash` is true on the white half: `floor((frightened - 1) / 7) % 2 == 0` while blinking, false at any other time (so the first 7 ticks of the blinking are blue).
- **`reset(set, reason, level)`**: back to scatter, phase 1, clocks 0, chain 0 (f0210 adds what a death and a new run do to the house); the starts per `Classic`.

### Pure/adapter split and authority
Pure Logic. Randomness is the set's own seeded state (Session passes its seed in f0220). The server steps it; clients see only looks and positions (f0310).

### Scalability
Four ghosts, one decision per tile each; the timetable is a table lookup (cache `Levels.schedule`, which is cheap but allocates). Wandering draws one number per decision.

### Maintainability
Per-level behaviour is columns of one table (a new level parameter is a column); a new mode would be one more branch of the decision and one flag. Speeds are `kind`s, so a new situation (say "elroy") is a new kind and a factor.

### Usability
Developer: two constants (`GHOST_TUNING`, `EYES_FACTOR`) and `ghostSpeed` are the only knobs. Player: blue ghosts are slower and unpredictable, they blink before they recover so the end is readable, and the user's slower-ghosts factor eases the whole game once chosen.

## Unknowns & experiments
- **E1** Do the integer speeds come out as claimed? **Pass**: 28, 15, 19 at level 1, 32 at level 2, 36 at level 5 for base 30; none reaches 120 on any level.
- **E2** Does a Park-Miller state stay exact in doubles? **Pass**: the largest product is `(2^31 - 2) * 16807`, about 3.6e13, far below 2^53.
- **E3** Is 1/60 s representable? **Pass**: it is `max(1, round(0.5)) = 1` tick at 30 ticks per second.
- **E4** Does the blue clock line up with the run's power clock? **Pass** in the prototype once `power` is applied after the ghosts' step in the tick the pellet is eaten (f0220 owns that wiring and has the spec).

## Acceptance criteria

### Checked
- **AC1**: the Levels table has the ghost speeds, the scatter/chase timetable in ticks and the tuning factor (default classic 1).
- **AC2**: the ghosts alternate scatter and chase on the level's timetable, turn back at the next centre at every change, and aim at their corner or their chase target.
- **AC3**: a power pellet turns the ghosts blue, slower and random for exactly the level's ticks, the timetable stops meanwhile, and they blink at the end.
- **AC4**: the architecture rules hold (Logic is pure, every require declared in `tracker/architecture.md`, every feature has unit specs).

### Judged
None.

### Observed
None (pure Logic). The tuning factor itself is the user's to choose after a Beta playtest.
