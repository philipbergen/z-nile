# c0030: Open Cloud runtime tests

## Problem
- c0020's place tests prove **structure**, not **behavior**. Adapter code, meaning server scripts, remotes and the client camera and input, never runs outside Studio. That leaves any criterion about adapter behavior as Observed, meaning manual.
- Roblox Open Cloud's Luau Execution API runs Luau inside a real server of a published place, and turns those into Checked criteria.
- It needs the Open Cloud key and ids the human provided on 2026-09-28 (see Resources) and a published version to run against, which c0140 provides.

- **Prep result (2026-09-30)**: PASS. One publish (Beta version 5) and one Luau execution worked from a GitHub-hosted runner with the repo's secret and variables, using karma's request shape; details in R0080's *Prep experiment*. The first attempt's WAF 403 was a malformed URL of mine.

## Non-goals
- Deploying to Beta for testers: c0140.
- Runtime tests of gameplay: the tests added here are the harness and a structure check; later rafts add scripts under `tests/runtime/`.
- Running runtime tests locally without the key.

## Solution
- `scripts/lib/opencloud.luau` (from c0140) gains `execute` (run one Luau script in a server of a version and wait for it) and `runSuite` (run a list of scripts and say which passed).
- `scripts/runtime-test.luau`: `lune run scripts/runtime-test -- <version> [files…]` runs every `tests/runtime/*.luau` (or the named files), prints `PASS`/`FAIL` per script and a summary, and exits 1 on any failure.
- `tests/runtime/structure.luau`: the first runtime script, asserting what the published place must contain.
- The `beta` job (c0140) runs the runtime tests after the deploy and the comment, with the version the deploy output; the runtime step carries the key and ids in its own `env` (no other step has them).
- The testing skill gets the new tier, and **the tracker skill's Merging rules gain the `beta` job as a merge condition** (user decision, 2026-09-30; made executable by design review round 2): a missing `beta` check for the head sha means keep waiting like a missing `gate`; a `workflow_dispatch` run never satisfies it (it skips `beta`), so if no `pull_request` run appears in about 5 minutes the ready event is re-fired with `gh pr ready --undo <pr> && gh pr ready <pr>` and `ci-verify.sh` is only for diagnosing `gate`; `beta` must be `COMPLETED`/`SUCCESS` (unconfigured publishing ends `SUCCESS` with a warning); a `CANCELLED` `beta` is looked at with `gh run view <run-id> --json jobs`: a job with no steps was superseded by a newer ready PR and is rerun (`gh run rerun <run-id> --job <job-id>`) as often as needed until 60 minutes have passed since the PR became ready, then `BLOCKED:`; a job whose steps ran was timed out or cancelled by hand and is red. Runtime tests therefore really gate merges. Every ready PR, captures and preps included, now publishes to Beta, so an expired `ROBLOX_API_KEY` blocks all merges until the secret is renewed.

## Design

### Decisions made in prep
- **A runtime script** is a strict Luau file in `tests/runtime/` that runs inside a real Roblox server, so it can't `require` anything, and says it passed by **returning `"PASS"`**: any other return value, an error, a cancelled or timed-out task is a failure with a named message. It reaches Roblox's globals through `local game: any = (getfenv() :: any).game`, because the gate's Lune type definitions don't declare `game` and every file must be `--!strict`.
- **The request shapes** are the ones that worked in prep (E2): create `POST /cloud/v2/universes/<u>/places/<p>/versions/<v>/luau-execution-session-tasks` with `{"script": "<source>"}` (answer 200 with `path` and `state`), poll `GET /cloud/v2/<path>` until `state` is `COMPLETE` (with `output.results`), `FAILED` or `CANCELLED`. A trivial task completed in about 4 s.
- **Timeouts**: poll every 3 s, give up after 120 s, reporting the last state.
- **Failure policy**: Beta is already published when the tests run, so a failing runtime test turns the job red but does not roll Beta back (accepted; last one wins).
- **Same safety rules as c0140**: unconfigured is a skip with a warning; the key is never in a message; the loopback-only `OPENCLOUD_BASE` seam is how the command is tested end to end.

### `scripts/lib/opencloud.luau` additions
```lua
export type Run = { ok: boolean, state: string, results: { any }, detail: string }
function OpenCloud.execute(cfg: Config, version: number, source: string,
	opts: { timeoutSeconds: number?, pollSeconds: number? }?): Run   -- errors on HTTP failures creating or polling; FAILED/CANCELLED/timeout come back as ok = false
export type Script = { name: string, source: string }
export type Suite = { lines: { string }, passed: number, failed: number }
function OpenCloud.runSuite(cfg: Config, version: number, scripts: { Script }, opts: …?): Suite
```
`runSuite` passes a script only when `results[1] == "PASS"`, records any other outcome as `FAIL <name>: <reason>`, and always runs the rest.

### `scripts/runtime-test.luau` (thin)
Skips a leading `--` argument (this Lune passes it through). Needs a whole version ≥ 1 (else usage, exit 2). Unconfigured → warning, exit 0. Files default to `tests/runtime/*.luau` sorted. Prints each line and `N passed, M failed, K runtime scripts`; exit 1 on any failure.

### Docs and workflow
`SETUP.md` names the `luau-execution-sessions` scope and `scripts/runtime-test`; `.claude/skills/testing/SKILL.md` gets the `tests/runtime/` row (what it is, how it runs, that it needs the key and skips without it); `check.yml`'s `beta` job gets the last step (with the three Roblox settings in its `env`): `if: steps.deploy.outputs.version != ''`, `lune run scripts/runtime-test -- "$VERSION"` with `VERSION: ${{ steps.deploy.outputs.version }}`.

### Scalability
One task per script, sequential, about 4 s each; ten scripts add under a minute to a ready PR's CI. The worst case per script is the 120 s timeout, so the `beta` job's 20-minute limit (c0140) covers about six hanging scripts: raise it with the script count.

### Maintainability
Adding a runtime test is adding one file under `tests/runtime/`: no registration. The harness has no game knowledge.

### Usability
A failing runtime test names its script and the reason in the job log. Without the key nothing breaks.

## Acceptance criteria

### Checked
- **AC1**: `OpenCloud.execute` creates a Luau Execution task on the published version with the script as JSON and the key in the header, polls it with pauses, returns the results of a completed task, reports FAILED, CANCELLED and timeouts as not ok with the reason, and raises HTTP failures as errors without the key.
