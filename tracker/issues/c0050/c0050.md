# c0050: Lifecycle spec clone isolation

## Problem
During R0010, the checkout lived in iCloud-synced `~/Documents`, and its `.git` lost tree objects and gained `<hash> 2` conflict copies (R0010 review-001 F1). Two things made that worse or harder to see:
- The c0010 tracker-lifecycle spec (now `tests/acceptance/c0010/`) runs `git clone <root>` into `.cache/tracker-e2e`. A local clone hardlinks object files, so the throwaway clone shares inodes with the real object store, inside the same synced tree.
- SETUP.md doesn't warn against cloud-synced checkouts. When it happens, the symptom is that lifecycle cases fail with "No such file or directory", which points away from the cause.

## Non-goals
<!-- Explicit scope fences. Anything tempting that belongs to another issue. -->

## Solution
- Change the promoted spec `tests/acceptance/c0010/tracker-lifecycle.spec.luau` in this chore (test-infrastructure work is a chore): clone with `--no-hardlinks`, into a temp dir outside the worktree. This counts as rework on c0010's spec.
- Add a SETUP.md troubleshooting row: "unable to read tree" or `bad sha1 file … 2` means the checkout is cloud-synced; re-clone outside `~/Documents` or iCloud.
- Optionally, setup.sh warns when the repo path carries the `com.apple.CloudDocs` xattr.
