# c0050: Lifecycle spec clone isolation

## Problem
During R0010 the checkout lived in iCloud-synced `~/Documents`, and its `.git` lost tree objects and gained `<hash> 2` conflict copies (R0010 review-001 F1). Two things made that worse or harder to see:
- Specs run `git clone <root>` into a throwaway directory. A local clone **hardlinks** the object files, so the throwaway clone shares inodes with the real object store. Seven specs do this (measured in prep): `tests/acceptance/c0010/tracker-lifecycle`, `c0041/worktree`, `c0420/naming`, `c0430/workstreams`, `c0440/launch`, and `tests/tooling/worktree-fetch`.
- `SETUP.md` doesn't warn against cloud-synced checkouts. When it happens the symptom is that lifecycle cases fail with "No such file or directory", which points away from the cause.

## Non-goals
- Moving the throwaway clones out of `.cache/` (they stay inside the repo tree, gitignored). The fix is that they share no object file with the real repository, not where they live.
- Detecting a cloud-synced checkout at gate time (a warning heuristic would be wrong in both directions; `SETUP.md` tells the human instead).
- Specs that clone a clone (`seed`, `origin`): those hardlink only between throwaway copies.

## Solution
A small helper, `tests/lib/clone.luau`, runs `git clone -q --no-hardlinks <source> <dest>` and raises a clear error. The six specs that clone `root` use it. `SETUP.md` gets a Troubleshooting row for the cloud-sync symptom. A structural case in the acceptance spec stops a plain `git clone … root …` from coming back.

## Design

### `tests/lib/clone.luau`
```lua
--!strict
local clone = {}

-- `git clone --no-hardlinks`: a plain local clone hardlinks the object files of `source`, so the
-- throwaway copy would share inodes with the real object store. Raises if the clone fails.
function clone.isolated(source: string, dest: string)

return clone
```
`dest` must not exist. The error names `source` and carries git's stderr.

### Call sites
Each `must(process.exec("git", { "clone", "-q", root, X }), "clone …")` becomes `clone.isolated(root, X)`, with `local clone = require("@tests/lib/clone")` added to the file. The six files: `tests/tooling/worktree-fetch.spec.luau`, `tests/acceptance/c0041/worktree.spec.luau`, `tests/acceptance/c0440/launch.spec.luau`, `tests/acceptance/c0430/workstreams.spec.luau`, `tests/acceptance/c0010/tracker-lifecycle.spec.luau`, `tests/acceptance/c0420/naming.spec.luau`. The specs in `tracker/issues/*/acceptance/` (including this raft's) already pass `--no-hardlinks` directly or are promoted later.

### `SETUP.md`
A Troubleshooting row: symptom `lifecycle specs fail with "No such file or directory", or git reports missing objects`; fix `the checkout is in a cloud-synced folder (iCloud Drive, Dropbox, OneDrive): move it to a plain directory such as ~/code/pickman`.

### Scalability
`--no-hardlinks` copies the object store instead of linking it. Measured in prep: 0.15 s for an isolated clone against 0.21 s for a plain one, with a 2.3 MB object store; each spec clones once.

### Maintainability
One helper with the reason in its comment, and a spec that scans `tests/` and `tracker/` for a `{ "clone" … root … }` literal without `"--no-hardlinks"`, so a seventh copy-paste can't reintroduce the hazard.

### Usability
A developer who hits the cloud-sync symptom finds it by searching the error text in `SETUP.md`.

## Unknowns & experiments

- **E2 (run in prep: PASS)**: does swapping the six call sites keep the specs green? With the prototype applied, `clone.spec.luau`, `worktree-fetch.spec.luau` and `tracker-lifecycle.spec.luau` pass (18 cases); the prototype was then reverted.
- **E3 (run in prep: PASS)**: mutants (table): each dies.
- **Residual**: the cloud-sync symptom itself can't be reproduced in CI; the `SETUP.md` row is documentation, checked by grep.

## Acceptance criteria

### Checked
- **AC1**: `clone.isolated(source, dest)` produces a working copy of `source`'s HEAD whose object files are not hardlinked to `source` (a plain local clone's are), and raises an error naming `source` when the clone fails.
- **AC2**: no spec under `tests/` or `tracker/` passes the repository root to a plain `git clone` (every such clone goes through `clone.isolated` or carries `--no-hardlinks`).
- **AC3**: `SETUP.md` warns against a checkout in a cloud-synced folder (iCloud) and names the "No such file or directory" symptom.
