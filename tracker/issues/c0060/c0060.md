# c0060: Affected changed files spec

## Problem
`scripts/affected.luau`'s `changedFiles` (git diff against the merge-base, the working tree, and untracked files) has no spec. R0010 added `--no-renames`, so that a file moved out of `src/` still selects the specs of its old place, but removing the flag would go unnoticed (R0010 review-002 F1). The function is private to a CLI script, so it can't be called from a spec at all.

## Non-goals
- Changing which files select which specs (`affected`, `FULL_RUN_PATTERNS` and `graph` are untouched).
- Changing the CLI: `lune run scripts/affected`, `-- --base <ref>`, `-- <file> ...` behave as before.

## Solution
Move `changedFiles` into its own module, `scripts/lib/changed.luau`, with a `cwd` parameter so a spec can aim it at a throwaway git repository, and spec it there. `scripts/affected.luau` requires the module.

## Design

### `scripts/lib/changed.luau`
```lua
--!strict
local changed = {}

-- Files that differ from the merge-base with `base` (default origin/main when it exists, else main):
-- committed, staged and unstaged changes, plus untracked files. `--no-renames` lists a moved file
-- at both its old and its new path. `cwd` defaults to the process's directory.
function changed.files(base: string?, cwd: string?): { string }

return changed
```
The body is the current `changedFiles` with a local `git(args, cwd)` that passes `cwd` to `process.exec`; semantics, ordering (merge-base diff, then `HEAD` diff, then untracked; first occurrence wins) and the "git failure means no output" rule are unchanged. Git failures stay silent on purpose: outside a repository `affected` already treats "nothing changed" as a valid answer.

The second diff (`HEAD`) matters when there is no merge-base (the base ref doesn't exist, as in a fresh clone without `main`): then uncommitted changes are still listed. The first draft of the spec didn't cover that, and a mutant removing it survived; a case now pins it.

### `scripts/affected.luau`
`local changed = require("./lib/changed")` and the call becomes `changed.files(base)`; the local `git` helper and `changedFiles` are deleted.

### Scalability
Unchanged: three git invocations.

### Maintainability
A module with one exported function and a documented contract, specced against a real repository, so the `--no-renames` rule and the base selection are executable facts.

### Usability
Nothing visible: this is test coverage and a seam.

### Touched modules
- `scripts/lib/changed.luau`
- `scripts/affected.luau`
- `tests/acceptance/c0060`

### Affected specs
`lune run scripts/affected -- scripts/lib/changed.luau scripts/affected.luau tests/acceptance/c0060` prints `ALL`. New spec: `tracker/issues/c0060/acceptance/changed.spec.luau`. Existing: `tests/tooling/affected.spec.luau` and the `c0020` specs exercise `affected` and must stay green.

## Unknowns & experiments
- **E1 (run in prep: PASS)**: does the extraction keep behaviour? The module and the edited `affected.luau` were created as scratch copies; `changed.spec.luau` passes 9/9, and the scratch files were reverted. Without the module the spec fails to load, as expected.
- **E2 (run in prep: PASS)**: do the mutants die? Five were planted (table); all die. One survived the first version of the spec (the HEAD diff), which is why the no-base case exists.
- **E3 (run in prep: PASS)**: does git's default rename detection apply in the fixture, so the `--no-renames` case is meaningful? Yes: with the flag removed from the merge-base diff, the moved-file case fails.

## Regression guard
`tests/tooling/affected.spec.luau`, the `c0020` acceptance specs (`affected-place`, `place-rules`), and every `scripts/check.sh --affected` run in the repo use `affected`.

## Acceptance criteria

### Checked
- **AC1**: `changed.files(base, cwd)` lists the files changed since the merge-base with `base` (committed, staged, unstaged, untracked), lists a moved file at both paths, omits what changed only on the base after the fork, and still lists uncommitted and untracked files when the base ref doesn't exist.
- **AC2**: with no base argument it uses `origin/main` when that ref exists and `main` otherwise.
- **AC3**: `scripts/affected.luau` takes its changed files from `scripts/lib/changed` and defines no `changedFiles` of its own, and the existing affected specs still pass.
