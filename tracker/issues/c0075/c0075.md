# c0075: Specs run in a bubblewrap jail on Linux

## Problem
On macOS every spec runs in a `sandbox-exec` jail that denies each write outside the checkout's `.cache` and the run's temp folder. On Linux, which is CI and any developer's Linux box, specs run **unjailed**, guarded by environment fences only (`scripts/lib/fence.sh`: git ceiling, ref and push hooks, no network transport for git). `@tests/lib/fixture` checks where a command starts, not what it does (R0021 review 001 F4): `fixture.exec(fx, "sh", {"-c", "cd <real checkout> && git checkout -- ."})` starts in a proven fixture and then rewrites the real working tree. The ref hooks refuse ref updates, not `git checkout -- .`, `git reset --hard` or `git clean -fd`, and nothing catches a plain file write. Only review catches it ("Caught only by review", testing skill). `retrofit.spec` bans raw shell strings, but not shell strings passed through the helper.

## Prep history
This was prepped in R0026 as a **git shim** that resolves which repository a command line would use. It was dropped after three design rounds, and a fourth to seventh found more (`tracker/rafts/done/R0026/design-review-001.md` to `-004.md`, with the answers in `design-refute-*.md`): the shim keeps losing to git's many ways of naming a repository (`commondir`, `extensions.worktreeConfig`, `GIT_COMMON_DIR`, commands git starts itself). The prior notes said the likely right mechanism is a real jail on Linux, the counterpart of the macOS one. **The user chose that on 2026-10-18.** This design is that jail; the shim is gone from it. The jail denies the *write*, so how a command names a repository no longer matters.

## Non-goals
- A jail for `check.sh` files' own commands and for the gate's static stages (format, lint, `rojo build`): they legitimately write the checkout (`sourcemap.json`, `promote-check`) and talk to GitHub. As on macOS, only spec runs are jailed (testing skill, "`check.sh` files").
- A Linux counterpart of the macOS **sweeper**: the pid namespace already does its job (E1, E4: leftovers, `setsid` included, die with the jail).
- Closing host Unix sockets in the **macOS** profile, and those outside `/run` and `/tmp` on Linux (Docker Desktop's under the home folder, `~/.gnupg`, `~/.ssh` control sockets): a follow-up issue (design review round 1 F4, round 2 F6); this raft closes the ones under `/run` and `/tmp` on Linux.
- Reading restrictions: the jail restricts writes, signals, IPC and the network, like the macOS one. Specs read the whole filesystem.
- Making the jail optional (an environment opt-out): the gate scan bans names that switch the guards off, and a Linux host without a usable bubblewrap is told how to get one. If the user wants an opt-out for unsupported hosts, that is a separate decision.
- Windows.

## Solution
`tests/lib/fence.luau` gets a Linux branch in `jail()`: the specs run under `bwrap` with the whole filesystem read-only, `/run` hidden (the host's sockets there) and `/tmp` private, the checkout's `.cache` and the run's temp folder writable, a private `/dev` and `/proc`, and private pid, network and IPC namespaces in a session of their own that die with the run. The launcher records itself in the run's lock. `PICKMAN_TEST_JAIL` says `bwrap`. A host where it cannot start goes through the same "outer sandbox" probes as macOS and otherwise refuses with a message that names the fix. `scripts/linux-jail.sh` installs bubblewrap and, with `--apply-sysctl`, lifts Ubuntu 24.04's user-namespace restriction; CI runs it before the gate. The runner's other pieces change only where a pid namespace makes them wrong (the run's lock).

## Design
Server authority, Logic and the architecture map are untouched: tooling only.

### `tests/lib/fence.luau`
New public functions (pure, so every platform tests them):
```lua
function fence.jailArgv(cache: string, runTemp: string, rebind: { string }): { string }
-- { "bwrap", "--ro-bind", "/", "/", "--tmpfs", "/run", "--tmpfs", "/tmp",
--   <"--ro-bind", p, p for each p in rebind>, "--bind", cache, cache, "--bind", runTemp, runTemp,
--   "--remount-ro", "/run", "--dev", "/dev", "--proc", "/proc", "--unshare-pid", "--unshare-net",
--   "--unshare-ipc", "--new-session", "--die-with-parent" }
function fence.rebindPaths(candidates: { string }): { string }
-- of resolved paths (checkout, git common dir, every PATH entry, $HOME), those under /run or /tmp: once each, none
-- inside another, never "/run" or "/tmp" themselves, never a lookalike such as /tmpfoo
function fence.trialArgv(cache: string, runTemp: string, rebind: { string }): { string }  -- jailArgv + "/bin/sh", "-c", ":"
-- (an absolute command: a NixOS host keeps `true` under /run, which the script's own trial does not rebind)
export type RebindEnv = { here: string, common: string, path: string, home: string }
function fence.rebindPlan(env: RebindEnv, resolve: (string) -> string, exists: (string) -> boolean): { string }
-- the candidates `jail()` hands to rebindFor: the checkout, the git common dir, every ABSOLUTE entry of `path` split on ":"
-- (empty and relative entries skipped), and `home` unless empty (round 4 F1: pinned, so a wrong list can't pass)
function fence.rebindFor(candidates: { string }, resolve: (string) -> string, exists: (string) -> boolean): { string }
-- each candidate that exists, as given and as resolved, through rebindPaths: a NixOS PATH entry is a link into
-- /nix/store (the given path must exist inside); a checkout reached through a link into /tmp (the target must);
-- a folder that does not exist, such as the `<runTemp>/bin` the run's PATH names on Linux, is skipped

function fence.linuxWhy(program: string?, stderr: string, outerJail: string?): string
-- outerJail == "bwrap" (the run is already inside the Linux jail) and a program present: "bubblewrap could not start a
-- jail inside the run's own jail: <first line>" — no sysctl advice (round 4 F2); otherwise as below
-- program nil -> "bubblewrap (bwrap) is not installed; run scripts/linux-jail.sh"
-- stderr has RTM_NEWADDR | "setting up uid map" | "No permissions to create new namespace" |
--   "Creating new namespace failed" -> "bubblewrap cannot create a user namespace here (Ubuntu 24.04:
--   kernel.apparmor_restrict_unprivileged_userns=1); run scripts/linux-jail.sh --apply-sysctl"
-- anything else -> "bubblewrap failed: <first line of stderr>; run scripts/linux-jail.sh" (never the sysctl advice)

export type Fallback = { kind: string, message: string } -- kind: "protected" | "fixture" | "refuse"
function fence.fallback(why: string, open: { string }, leaks: { string }, fixture: boolean): Fallback
function fence.escapePaths(os: string): { string }
-- linux { "/tmp", "/var/tmp", "/dev/shm", "$XDG_RUNTIME_DIR" }; macos { "/private/tmp", "getconf:DARWIN_USER_TEMP_DIR" }; else {}
function fence.leaks(paths: { string }, lookup: (string) -> string?): { string }
-- of those folders (a "$NAME" entry resolved by lookup("NAME"), a "getconf:NAME" entry by lookup("NAME"); unset or
-- missing ones skipped), the ones a probe file can be made in (labels `the folder <dir>`; the probe file removed at once)
function fence.networkClosed(os: string, printed: string): boolean
-- "Operation not permitted" (both); "Network is unreachable" on linux only
function fence.reads(result: { ok: boolean, stderr: string }, jail: string): boolean
-- fence.alive's verdict from a `kill -0` result: ok -> true; refused ("Operation not permitted") -> true only under
-- sandbox-exec or an outer sandbox; never under bwrap, where an outside pid is absent
function fence.recordsPid(lockNamespace: string?, ownNamespace: string?): boolean  -- false only when both are known and differ
function fence.pidNamespace(): string?  -- `readlink /proc/self/ns/pid`, nil without /proc
```
- **Why the root is bound first.** Later mounts cover earlier ones, so every hiding and both `--bind`s come after `--ro-bind / /`. A root bound read-only also makes every other host mount (`/boot`, `/mnt`) read-only inside (E1: mountinfo), and denies renaming away a folder above the checkout, which the macOS profile needs a rule for.
- **Order (round 2 F1, E8).** `--remount-ro /run` comes **after** the rebinds and both `--bind`s: bubblewrap makes each bind's mount point inside the new root as it goes, and on a tmpfs already made read-only that fails (`Can't mkdir /run/pickman-co: Read-only file system`, E8 on `ubuntu-latest`). Remounting afterwards is non-recursive, so the binds made before it keep their modes: the rebind stays read-only, the cache and the run's temp folder (even one under `/run/user/<uid>`) stay writable, and the rest of `/run` is read-only (E8).
- **Hiding `/run` and `/tmp` (design review round 1 F4, user's decision 2026-10-20).** A read-only mount does not stop `connect(2)` on a Unix socket: E4 showed `docker version` working inside the first jail and `/run/docker.sock`, `/run/user/<uid>/bus` and the system bus connectable. With `--tmpfs /run` made read-only, none exists (E4: `docker` fails, `/run` is read-only); `--tmpfs /tmp` gives the run a private, writable `/tmp` that nothing outside sees, with the run's temp folder (under it by default) bound back on top. Anything the run needs that lies under `/tmp` or `/run` would vanish: `jail()` passes `fence.rebindPaths({ here, git common dir, every PATH entry, $HOME })` (each resolved) as `rebind`, bound read-only after the hiding. That covers a checkout on a second disk (`/run/media/…`), NixOS and Guix tools (`/run/current-system/sw/bin`) and a container's `HOME=/tmp/h`. `/var/tmp` and the home folder stay read-only host paths, as they are on macOS. The follow-up issue covers the macOS profile.
- **`--new-session`, kept (round 1 F7).** E4 ran the real `REAPER` with the jail with and without it: INT, TERM and HUP to the launcher stop the jail with exit 130, 143 and 129 and leave nothing, SIGKILL of the launcher leaves nothing, both ways. It `setsid()`s the sandboxed command (`inside pgid 1 sid 1`, against `pgid 0` in the launcher's own group without it), so a group-wide signal from a spec (`kill -TERM 0`) cannot reach the launcher's watchdog or the outer bwrap, and the specs lose the controlling terminal, which closes TIOCSTI on every host whatever `CONFIG_LEGACY_TIOCSTI` is (its upstream default is `y`; the runner's kernel has it off).
- **`jail(here, cache, runTemp)`**, a Linux branch beside the macOS one:
  1. `rebind = fence.rebindPlan({ here, common (the git common dir), path = process.env.PATH, home = process.env.HOME }, realpath, exists)` as above (round 3 F1: the run's `PATH` is `<runTemp>/bin:…` and Linux never makes that folder, so a nested run would otherwise try to bind it and fail); `argv = fence.jailArgv(resolved(cache), runTemp, rebind)` (`resolved` is the existing realpath helper; the run's temp folder is already resolved).
  2. If `command -v bwrap` finds it, the trial `fence.trialArgv(...)` (the jail with `/bin/sh -c :`) runs. On success the prefix is `argv` and the jail is `"bwrap"`; `PICKMAN_REAP_SWEPT` stays `""` (no sweeper).
  3. Otherwise `why = fence.linuxWhy(program, trial stderr, outerJail)`, where `outerJail` is the inherited `process.env.PICKMAN_TEST_JAIL`, read before `enter()` sets it for an outer sandbox (it is `bwrap` when this run is nested in the Linux jail) and the tail of the macOS branch (probe what an outer sandbox leaves open, fixture-of-guarded check, refuse) runs. That tail is **moved into one local function** shared by both OSes, calling `fence.fallback`; the refusal and note texts stay byte for byte (promoted `c0058` specs pin `cannot jail this run`); only the probe labels inside the parentheses change, from the macOS-specific ones to `the folder <dir>` (no promoted spec reads them).
  4. Other operating systems keep `none (not … : environment guards only)`.
- **`escapes(here)`** gets its shared-folder leaks from `fence.leaks(fence.escapePaths(process.os), lookup)`, where `lookup(name)` reads `$NAME` from the environment and a `getconf:NAME` entry through `getconf NAME` (so macOS's `DARWIN_USER_TEMP_DIR` keeps being found, round 2 F4); it judges the network probe with `fence.networkClosed(process.os, printed)`. The home-folder and ancestor probes it already has stay. The probe function is what the spec tests; that `escapes()` calls it is one line, read in review.
- **The run's lock under a pid namespace (round 1 F1).** Inside the jail `echo $PPID` is a number of the jail's own namespace, which another run's `kill -0` reads as some unrelated host process. And the *top* process does not bound the jail's life: `--die-with-parent` ties bwrap to the **launcher** (`perl -e REAPER`), a child of the top, so a SIGKILLed or TERMed top leaves the launcher, the jail and its specs running (promoted `c0058/lock.spec` "a run whose top process was killed keeps the lock while its specs still run" pins that the lock stays held). So:
  - **the launcher records itself**: the top passes `PICKMAN_REAP_LOCK=<lock>` in the launcher's environment (unset for the specs by the same `unset` that clears `PICKMAN_REAP_SWEPT`/`PICKMAN_REAP_CACHE`), and `REAPER`, before it forks, creates `<lock>/pid-<launcher pid>` with `O_CREAT|O_EXCL|O_NOFOLLOW`, only when the variable names a real folder (not a link). The launcher lives in the host namespace exactly as long as the jail, and a stale-lock takeover frees the lock once it is gone. On macOS it is one more live pid, harmless;
  - **only when the jail is `bwrap`**, the top writes `<lock>/pidns` (`fence.pidNamespace()`) right after `takeLock`; on every other path (macOS, an outer sandbox on Linux) the top and the guarded processes share a namespace and everything is recorded (round 2 F3);
  - a guarded process records `pid-<n>` only when `fence.recordsPid(<lock>/pidns content or nil, fence.pidNamespace())`. Without `pidns` (macOS, hand-built locks in `lock.spec`) everything is recorded as now.
  With this, `c0058/lock.spec` needs no override.
- `fence.alive` becomes `probe kill -0, then fence.reads(result, jail)`; its behaviour is unchanged where `sandbox-exec` or an outer sandbox applies.
- The macOS-only `bin/mktemp` shim stays macOS-only: Linux `mktemp` honours `TMPDIR` (E2, E4: `mktemp ok` with `/tmp` hidden).

### `scripts/lib/fence.sh`
`pickman_fence <checkout> specs <jail>` sets no `core.hooksPath` when `<jail>` is `sandbox-exec` **or `bwrap`** (the kernel already denies the writes the hooks would refuse, and a hook in every fixture commit costs a process start). In specs mode it also sets `commit.gpgSign=false` and `tag.gpgSign=false`: fixtures never sign, and a developer's `gpgSign=true` would call an agent whose socket (`/run/user/<uid>/gnupg`) the Linux jail hides, failing every fixture commit (round 2 F2). Comments updated. Everything else, including the unjailed `checks` mode and the `none`/outer-sandbox cases, keeps its hooks.

### `scripts/linux-jail.sh` (new; E3 is a prototype that passes AC4's spec)
`scripts/linux-jail.sh [--apply-sysctl]`, idempotent, bash 3.2-clean:
1. not Linux: say so, exit 0, run nothing;
2. no `bwrap`: `sudo apt-get install -y bubblewrap` (no `sudo` as root); if that fails, `apt-get update` once and again; no `apt-get`: exit 1 naming the way out;
3. the **runner's own trial** (`fence.trialArgv` with no rebind and the same absolute command, around two folders of the script's own under `${TMPDIR:-/tmp}`, removed after): works, exit 0. A host that masks `/proc`, say, fails here, not after the runner has taken its lock;
4. does not work: print bwrap's error; if it is one of the four user-namespace errors `linuxWhy` knows (`RTM_NEWADDR`, `setting up uid map`, `No permissions to create new namespace`, `Creating new namespace failed`) and there is no flag, add the knob (`kernel.apparmor_restrict_unprivileged_userns`) and exit 1, **changing nothing**; any other error: exit 1 with the error as it stands, never the sysctl advice and never the sysctl (round 2 F2);
5. with `--apply-sysctl`, for a user-namespace error only: `sudo sysctl -w kernel.apparmor_restrict_unprivileged_userns=0`, trial again; exit 0 or 1.
The sysctl is host-wide and lasts to the next boot, so a developer machine is never changed without the flag (E1: GitHub's `ubuntu-latest`, 24.04, has it set to 1 and needs it; passwordless `sudo` is there).

### Scalability
- Per run: one `bwrap` start, about 6 ms (E1: ten empty jails in 58 ms), plus the trial start. Per spec: nothing (the workers are inside the one jail). Cost grows with nothing in the game.
- Nested runs (fixture copies of the runner, `c0058`) nest a jail. E2 nested the first argv (no `/run`/`/tmp` hiding, no rebinds, no `--new-session`); the final policy nested inside itself is E5's first check (the nested `c0058` runs on the Linux gate).

### Maintainability
- The policy is **one list** (`jailArgv`) under a spec that pins it argument for argument, instead of a growing model of git's behaviour. A new place a spec may write is one `--bind` and one spec line.
- `fence.fallback`, `fence.linuxWhy`, `fence.escapePaths`, `fence.networkClosed` and `fence.reads` are data-in, verdict-out functions; the macOS and Linux branches share the same tail.

### Usability
- A Linux developer without bubblewrap gets, instead of a silently unjailed run, `cannot jail this run (bubblewrap (bwrap) is not installed; run scripts/linux-jail.sh) …` or, on Ubuntu 24.04+, the sysctl name and the flag; any other bwrap failure is quoted, not misattributed.
- A spec that writes outside `.cache` and the run's temp folder now fails on Linux with `Read-only file system` instead of passing silently, at the line that did it. A spec that writes `/tmp` on Linux succeeds into a private `/tmp` (the macOS jail denies it): such a spec should use `TMPDIR`.
- The developer API is unchanged: specs keep calling `fixture.exec` and `fixture.git`; the helper needs no change.
