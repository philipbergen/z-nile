# c0077: Writers under .cache never follow a symlink

## Problem
Inside the jail a spec can still atomically swap a symlink into the top of `.cache` (R0021 review 006 F1). The jail forbids making or renaming a link there, but not a swap with an existing file. R0021's round-6 fix made the writers in `scripts/` write elsewhere and `mv -f` into place, so that a link would be replaced rather than followed. The review of that fix (c0078's `review-of-round6-fixes.md`, F1 and F4) showed it doesn't hold:
- `mv -f SRC DEST` moves SRC *into* DEST when DEST is a link to a directory. `sh.writeReplacing`, `check.sh`'s definitions download and `build_place` all do this, so a link to `.git/refs/heads` gets files dropped into the shared repository.
- The after-run unlink runs in the top Lune process, which a Ctrl-C or a TERM sent only to it skips. The next `scripts/check.sh` then builds before any unlink runs.
- The definitions download now fails silently: a failure inside the `&&` list escapes `set -e`, and leaves its temp file behind.
- Nothing stops a new writer from writing under `.cache` the old way.

Writers in sequestered `check.sh` files of finished issues aren't run by the gate. Today none of the active ones writes at the top of `.cache` (prep checked).

## Non-goals
- Refusing the swap in the jail itself. Prep proved it impossible without banning every symlink in the folders specs may write to (E1), which breaks c0055's promoted setup spec.
- Readers that follow a link: they only read elsewhere, which can't change the repository.
- The jail's signal rule (c0078), which closes the "spec stops the runner" route to skipping the unlink.
- Detached processes that outlive the run (c0076).

## Solution
One link-safe writer, `scripts/lib/replace-file.pl`, used by every unjailed writer under `.cache`. It creates a sibling temp file exclusively without following links (`O_CREAT|O_EXCL|O_NOFOLLOW`), writes it, and `rename(2)`s it onto the target. A rename replaces a link of any kind and refuses a real directory. The unlink of top-level links also moves where nothing can skip it: into the Perl launcher (after the specs' group is killed) and into `check.sh` (before anything writes under `.cache`). A gate spec checks every `.cache` mention in `scripts/` against a reviewed list, so a new writer needs a reviewer's approval.

## Design
### `scripts/lib/replace-file.pl` (new)
```
perl scripts/lib/replace-file.pl <dest> [<src>]
```
- Content comes from `<src>` (read as bytes) when given, else from stdin.
- `<dest>` existing as a real directory (`-d $dest && !-l $dest`) → exit 1 with `replace-file: <dest> is a directory; refusing`, and nothing written.
- The temp file is `<dir>/.<base>.pickman-tmp.<pid>.<6 random [a-z0-9]>`, opened with `sysopen(..., O_WRONLY|O_CREAT|O_EXCL|O_NOFOLLOW, 0644)`, then `chmod 0644` against the umask. `<dir>` and `<base>` are `dirname`/`basename` of `<dest>`. If the open fails with EEXIST, it retries with new random letters, up to 5 times.
- After writing and closing, `rename($tmp, $dest)`. On any failure (write, close, rename) the temp file is unlinked, and it exits 1 with `replace-file: <dest>: <error>`.
- Exit 0 on success, printing nothing.
- Perl is already a gate requirement: the runner's launcher and the network probe use it.

### Writers that use it
- **`scripts/lib/sh.luau`, `sh.writeReplacing(path: string, text: string)`**: `process.exec("perl", { "scripts/lib/replace-file.pl", path }, { stdio = { stdin = text } })`; it raises `writeReplacing {path}: {stderr}` on failure. The path is relative to the repository root, the cwd of every tracker command and spec. Its callers (focus, claim and board files in `scripts/tracker/main.luau`) don't change. `board --out <a directory>` now fails with that message instead of dropping a `tmp.*` file into the directory.
- **`scripts/check.sh`**:
  1. Right after `mkdir -p .cache`, every symlink directly in `.cache` is unlinked, never followed: `find .cache -mindepth 1 -maxdepth 1 -type l -exec rm -f {} +`. It runs before the definitions download and the build, so a link left by an interrupted run is gone before anything writes.
  2. **Definitions download**: `t=$(mktemp "${TMPDIR:-/tmp}/globalTypes.XXXXXX")`. Then `curl -fsSL -o "$t" <url> || { rm -f "$t"; echo "check.sh: could not download the Luau global types (globalTypes.d.luau)" >&2; exit 1; }`, then `perl scripts/lib/replace-file.pl "$defs" "$t"; rm -f "$t"`. The download goes to the user temp folder, which no spec can write to, and replace-file copies it in. The condition stays `[[ ! -s $defs || -L $defs ]]`.
  3. **`build_place`** (its own spec case since design review 001 F7): `d=$(mktemp -d "${TMPDIR:-/tmp}/check-build.XXXXXX") && rojo build default.project.json -o "$d/check.rbxl" && perl scripts/lib/replace-file.pl .cache/check.rbxl "$d/check.rbxl"; local rc=$?; rm -rf "$d"; return $rc`. The build folder is removed every time (review F4).
- **`scripts/lib/fence.sh`**: the sentinel keeps its exclusive `mktemp "$here/.cache/.sentinel.XXXXXX"`. Only the `mv -f` is replaced, by an inline `perl -e 'rename $ARGV[0], $ARGV[1] or die "rename: $!\n"' "$fresh" "$sentinel" || { rm -f "$fresh"; return 1; }`. That's `rename(2)`, with no dependency on `replace-file.pl`, because fixtures copy `fence.sh` without the rest of `scripts/lib`: c0058's lock and fence specs and `fence-leftovers.spec` do. The first design called `replace-file.pl` here, and every nested run in those fixtures failed (design review 001 F1). The existing refusals (a folder at `.cache/.git`) stay before it.
- `scripts/deploy-beta.luau` doesn't write under `.cache`: no change.

### Unlink that no signal skips
- **`tests/lib/fence.luau`, `REAPER`**: after `kill 'KILL', -$pid`, when env `PICKMAN_REAP_CACHE` is set, it unlinks every entry `$e` of that folder for which `-l "$ENV{PICKMAN_REAP_CACHE}/$e"` holds. That's `opendir` + `unlink`: no recursion and no following. The launcher handles INT, TERM and HUP by forwarding them, so it reaches this point after a Ctrl-C too.
- **`fence.enter()`**: it passes `PICKMAN_REAP_CACHE=<cache>` (physical) to the launcher's environment. Its own unlink loop after the launcher returns stays (belt and braces).

### The reviewed list of `.cache` paths
- **`tests/lib/cachepaths.luau` (new)**:
  - **`cachepaths.scan(files: { [string]: string }, allowed: { [string]: { [string]: string } }): { string }`**: `files` maps a path to its text; `allowed` maps a path to `{ [trimmed line] = reason }`.
    - It returns `"<path>: <trimmed line>"` for every line that contains `.cache` and isn't in `allowed[path]`. Comment lines are skipped: those whose first non-space characters are `--` (Luau) or `#` (shell).
    - It also returns `"<path>: listed but missing: <line>"` for every allowed line not found in that file, the file missing included.
    - It's pure: it reads no files.
  - **`cachepaths.ALLOWED`**: the reviewed list. It holds exactly the final tree's `.cache` lines in `scripts/` (`*.luau` and `*.sh`, `replace-file.pl` excluded by extension), each with a one-line reason saying how it writes safely: through replace-file, a `mkdir -p` of a plain folder the fence checks, a read, or a message. It's a regular library file, so a reviewer sees every change to it.
- **`tracker/issues/c0077/acceptance/cache-paths.spec.luau` (sequestered)**:
  - It tests `scan` on planted texts: a new mention in Luau or in shell is flagged; a commented one isn't; a listed line passes; a listed line that's gone is reported.
  - It then walks `scripts/` itself and requires `scan(files, cachepaths.ALLOWED)` to be empty, with a non-empty reason per entry.

### Scalability
Three writers and a dozen allowlisted lines. The scan reads about 40 files once per run (under 50 ms). replace-file adds one `perl` start per write (about 10 ms); writes happen once per tracker command or gate.
### Maintainability
- One writer implementation, in the one language both shell and Luau can call.
- Its contract (exclusive sibling temp, then `rename(2)`) is stated at the top of the file and in the testing skill (c0078).
- The allowlist turns "remember to use the safe writer" into a review step.
### Usability
- The error messages name the path and what to do.
- `board --out <dir>` now fails clearly instead of writing a stray file.
- A gate whose definitions download fails stops there with a message, not in a later type stage.

## Unknowns & experiments
- **E1 (run in prep)**: can the jail refuse the swap?
  - Method: `sandbox-exec` with three profiles, a deep link swapped into the top via `syscall(488 /* renameatx_np */, …, RENAME_SWAP)`.
  - Result:
    - R0021's create-only rule: swapped.
    - Deny all writes on a top-level symlink: swapped.
    - Deny symlink writes anywhere under the folder: refused.
    - But a link made in the run's temp folder can still be swapped or renamed into `.cache`, so a full ban needs both folders. c0055's promoted setup spec makes symlinks under `.cache/c0055-setup` (its stub tools).
  - Conclusion: no jail rule. The defence is at the writers.
- **E2 (run in prep)**: what do the rename primitives do with links?
  - Lune `fs.move(tmp, path, true)`: onto a link to a directory and onto a link to a file, the path became a regular file and the targets were unchanged; onto a real directory it raised `Is a directory (os error 21)`.
  - Perl `rename`: the same; onto a real directory it fails with `Is a directory`.
  - `mv -f` onto a link to a directory moved the file into it (reproduced from the review).
- **E3 (executor, Phase 1)**: does `O_NOFOLLOW` exist in Perl's `Fcntl` on both macOS and ubuntu runners? Method: `perl -MFcntl=O_NOFOLLOW -e 'print O_NOFOLLOW'` in CI (`scripts/ci-verify.sh`). Fallback: `O_EXCL` alone. With `O_CREAT|O_EXCL`, POSIX already refuses to follow a symlink at the final component, so `O_NOFOLLOW` is belt and braces.
- **E4 (mutation check, run in prep)**: what does the prototype show?
  - Setup: a prototype of this design in a scratch worktree from `main` (`.worktree/proto-r0260`, not landed): `replace-file.pl`, `sh.writeReplacing`, the `check.sh` and `fence.sh` writers, the REAPER unlink, and `cachepaths.luau` with a full `ALLOWED`.
  - Result: both specs pass (14 + 4 cases), and `scripts/tracker.sh check c0077` passes 6/6.
  - 16 mutants, one per `run` row, each applied alone; every one failed a case on an assertion.
  - One survived the first version of the spec: no temp-file cleanup on failure, because every failure case failed before the temp file existed. The case "a source that can't be read fails after the temporary file is made, and leaves none" was added, and it catches it.
  - The rows not run: the exclusive, non-following open (a race that can't be staged) and the same-folder temp file (no observable difference on one filesystem).
- **E5 (run in prep, after design review 001)**: do the round-1 fixes hold?
  - With `fence.sh`'s inline rename (F1), the full gate on the prototype passes, once `repo-fence.spec` has `cachepaths.luau`'s `ALLOWED` entries (implementation step 6). That includes `c0058/lock`, `c0058/fence` and `fence-leftovers`, which the first design broke.
  - The `build_place` case (F7) passes. It catches `cp` in place of the rename, and the build folder being kept.

### Rules and mutants
| rule | spec :: case | mutant it kills | checked |
|---|---|---|---|
| a rename, never a move into a directory | replace-file :: over a link to a directory… | `mv -f "$tmp" "$dest"` | run |
| a link to a file is replaced, not written through | replace-file :: over a link to a file… | `open(my $f, '>', $dest)` (write in place) | run |
| a real directory is refused, untouched | replace-file :: a real directory… | `rm -rf $dest` then rename | run |
| the temp file is removed on failure | replace-file :: a source that can't be read… | no `unlink $tmp` on the error path | run |
| the content comes from stdin or from `<src>` | replace-file :: content comes from stdin… | always reads stdin (the `<src>` argument ignored) | run |
| mode 0644 | replace-file :: content comes from stdin… | `sysopen` 0600 without chmod | run |
| the temp file is opened exclusively and never followed | (none: the race can't be staged deterministically) | `open('>', $tmp)` | reasoned |
| writeReplacing goes through replace-file | replace-file :: sh.writeReplacing over a link to a directory… | `writeReplacing` kept on `mv -f` | run |
| a failed download stops the gate | replace-file :: the gate stops… | `curl … -o "$t" && mv …` (failure inside `&&`) | run |
| no temp file is left after a failed download | replace-file :: the gate stops… | no `rm -f "$t"` | run |
| build_place renames, never writes through | replace-file :: the build lands… | `cp "$d/check.rbxl" .cache/check.rbxl` | run |
| the build folder is removed | replace-file :: the build lands… | no `rm -rf "$d"` | run |
| check.sh unlinks top-level links before writing | replace-file :: the gate removes links… | the unlink missing, or placed after `build_place` | run |
| the launcher unlinks top-level links after the group is killed | replace-file :: after the command ends… | no unlink in REAPER | run |
| it unlinks only links, only at the top | replace-file :: after the command ends… | `unlink` of every entry, or recursion into folders | run |
| the launcher's unlink survives a signal death of the command | replace-file :: …killed by a signal | the unlink only on exit status 0 | run |
| a new `.cache` mention is flagged, in Luau and in shell | cache-paths :: a new .cache mention… | the scan matches only the shell redirection form | run |
| comment lines are skipped, listed lines pass | cache-paths :: a commented mention… | no comment skip (a comment is flagged), or the lines compared untrimmed | run |
| stale entries are reported | cache-paths :: a listed line that is gone… | stale entries ignored | run |
| the real tree is scanned with the list | cache-paths :: every .cache line in scripts/… | ALLOWED holding every line with an empty reason, or the walk skipping `scripts/lib` | reasoned |

## Acceptance criteria

### Checked
- AC1: `scripts/lib/replace-file.pl` replaces whatever is at the path (a link to a directory or to a file) with a regular file, mode 0644, with content from stdin or a source file. It refuses a real directory, writes nothing then, and never leaves a temporary file.
- AC2: `sh.writeReplacing` writes through replace-file: over a link to a directory, the directory is unchanged.
- AC3: `scripts/check.sh` stops with a message when the definitions download fails, leaving no temporary file. It unlinks every symlink at the top of `.cache` before it writes there. Its build lands by rename over a link to a directory, and its build folder is removed.
- AC4: the launcher unlinks the symlinks at the top of the cache folder it was given after the command ends, signal death included, and touches nothing else.
- AC5: `cachepaths.scan` flags every unlisted `.cache` mention, skips comments, and reports stale entries; every `.cache` line in `scripts/` is on `cachepaths.ALLOWED` with a reason, and the list has no stale lines.
- AC6: no `mv -f` is left in `scripts/check.sh`, `scripts/lib/fence.sh` or `scripts/lib/sh.luau`.

### Judged
None.

### Observed
None.

## Implementation steps
1. Write `scripts/lib/replace-file.pl` and run its spec cases (AC1).
2. Switch `sh.writeReplacing` to it, and add the directory-link case to `fence-cache-entry.spec` (AC2).
3. `check.sh`: the unlink after `mkdir -p .cache`, the download through `$TMPDIR` with its own failure exit, and `build_place` with cleanup (AC3).
4. `fence.sh`: the sentinel's `mv -f` becomes an inline Perl rename (no `replace-file.pl`). Run `tests/acceptance/c0058/fence.spec.luau`, `lock.spec.luau` and `tests/tooling/fence-leftovers.spec.luau`: their fixtures copy `fence.sh` alone.
5. REAPER: the `PICKMAN_REAP_CACHE` unlink; `fence.enter` passes it (AC4).
6. Write `tests/lib/cachepaths.luau`, with `ALLOWED` taken from the final tree and one reason per line (AC5). It quotes `fence.sh` lines naming `GIT_CEILING_DIRECTORIES` and `GH_CONFIG_DIR`, which the gate scan bans, so add reviewed `ALLOWED` entries for it in `tests/tooling/repo-fence.spec.luau` ("quotes a fence.sh line in the reviewed .cache list"). Also remove the `fs` import `sh.luau` no longer uses (selene flags it).
7. `scripts/tracker.sh check c0077`, then the full gate.
