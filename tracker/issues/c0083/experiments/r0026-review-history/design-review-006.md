### F4 [medium] The Stop hook drops the old path of a staged rename, so "a renamed file still selects the specs that named it" doesn't hold in the hook
Where: c0083 Design, `scripts/hooks/stop.sh` ("The hook takes every changed path (`git diff --name-only HEAD`, plus untracked files)"); prototype `stop.sh`; AC4 ("also once it's deleted or renamed"); AC6.
Evidence: `git diff --name-only HEAD` detects renames by default. In a scratch repo, after `git mv SETUP.md SETUP2.md`, `git diff --name-only HEAD` prints only `SETUP2.md`, while `--no-renames` prints both paths. No spec names `SETUP2.md`, so the hook's selector call prints nothing, `[[ -z $selection ]] && exit 0` fires, and the turn ends without a gate. A move by plain `mv` shows as a deletion plus an untracked file, and works. So the hook misses exactly the case round 5 fixed, whenever an agent renames with `git mv`. `changed.files` (`check.sh --affected`) already passes `--no-renames`, which is why the later gates catch it. The hook is the only gate that runs every turn.
Recommendation: the design names the command `git diff --name-only --no-renames HEAD` in the hook. Add an AC6 case to the hook fixture: a staged `git mv` of a file that a stand-in spec names, with the stub selector logging its arguments. The log holds the old path, and the gate runs. Add a Rules row with the mutant "hook without `--no-renames`", run on the prototype.
