# c0084: Track spend across the whole lifecycle

## Problem
Spend (time, and lines in `spend.md`) is recorded only during execution, by `tracker.sh commit` in an active raft. Everything before and around it is invisible:
- **Capture**: plain commits, and no record of the time spent.
- **Prep and design**: ticket-prep commits with plain `git commit`. Designing documents, writing `check.sh` files and acceptance specs, and running experiments go unrecorded. Line counts also exclude `tracker/`, so prep-written specs never count.
- **Design review**: each round is a separate reviewer agent run, and its minutes and tokens are recorded nowhere. Neither is the author's time answering it (`design-refute-NNN.md`). R0025 (2026-10-03) took nine design rounds, roughly 70 reviewer-minutes and 1.6M tokens, and none of it shows.
- **Code review**: the reviewer's runtime is deliberately excluded (`--time 0`), and its tokens are not recorded.
- **Delivery**: waiting for CI, merging and landing aren't recorded.

So `tracker.sh metrics` (cost per issue, the rework %) describes only the build step, and the cost of the process around it can't be judged or tuned. The user (2026-10-05): "make sure we track the entire sdlc from issue entry to delivery".

What should happen: every phase, from capture through prep, design review, execution, code review and merge, records its time and agent tokens against the issue or raft it serves. `metrics`, and the board's statistics (c0073), can then show the cost of each phase.

## Non-goals
- Billing-accurate token accounting. Best effort from what each agent reports is enough, as for spend today.
- Changing the rework definition (defect spend against feature spend), except to make clear which phases it covers.

## Solution
Ideas (for ticket-prep):
- **Phase-tagged spend rows**: `spend.md` rows get a phase (`capture`, `prep`, `design-review`, `build`, `code-review`, `deliver`) and an optional `tokens` column. Existing rows read as `build`.
- **A recording command usable outside an active raft**, for example `tracker.sh spend <id> --phase <phase> --time <min> [--tokens <n>] [--note …]`. It is allowed in capture and prep worktrees and appends the row to the item's `spend.md` in the same commit (the tracker does the mechanics; the skills say when to call it).
- **Skills record each phase**:
  - make-issue at capture (and c0072's `land`);
  - ticket-prep after design work and after each design review, with the reviewer's minutes and tokens from the agent's usage report plus the author's answering time;
  - execute-raft per code review round, in place of `--time 0`;
  - the merge step for delivery (CI wait included).
- **Lines**: count prep-written specs and `check.sh` files under the `prep` phase, rather than excluding `tracker/` wholesale.
- **Reporting**: `tracker.sh metrics` reports spend per phase, per raft and per type, and design-review cost per round. Consider feeding c0073's board statistics (time by phase).
- **Override check**: promoted specs and done checks pin `spend.md`'s columns (c0001 lifecycle, `tests/tooling/spend.spec`, `metrics-rounds.spec`) and the `--time 0` wording. Find them in prep.
