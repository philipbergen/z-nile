# c0084: Track spend across the whole lifecycle

## Problem
Spend (time, and lines in `spend.md`) is recorded only during execution, by `tracker.sh commit` in an active raft. Everything before and around it is invisible:
- **Capture**: plain commits, and no record of the time spent.
- **Prep and design**: ticket-prep commits with plain `git commit`. Designing documents, writing `check.sh` files and acceptance specs, and running experiments go unrecorded. Line counts also exclude `tracker/`, so prep-written specs never count.
- **Design review**: each round is a separate reviewer agent run, and its minutes and tokens are recorded nowhere. Neither is the author's time answering it (`design-refute-NNN.md`). R0025 (2026-10-03) took nine design rounds, roughly 70 reviewer-minutes and 1.6M tokens, and none of it shows.
- **Code review**: the reviewer's runtime is deliberately excluded (`--time 0`), and its tokens are not recorded.
- **Delivery**: waiting for CI, merging and landing aren't recorded.

So `tracker.sh metrics` (cost per issue, the rework %) describes only the build step, and the cost of the process around it can't be judged or tuned. The user (2026-10-05): "make sure we track the entire sdlc from issue entry to delivery".

What should happen: every phase, from capture through prep, design review, execution, code review and merge, records its time and agent tokens against the issue or raft it serves. `metrics`, and the board's statistics (c0073), can then show the cost of each phase.

## Non-goals
- Billing-accurate token accounting. Best effort from what each agent reports is enough, as for spend today.
- Changing the rework definition (defect spend against feature spend), except to make clear which phases it covers.

## Solution
Ideas (for ticket-prep):
- **Phase-tagged spend rows**: `spend.md` rows get a phase (`capture`, `prep`, `design-review`, `build`, `code-review`, `deliver`) and an optional `tokens` column. Existing rows read as `build`.
- **A recording command usable outside an active raft**, for example `tracker.sh spend <id> --phase <phase> --time <min> [--tokens <n>] [--note …]`. It is allowed in capture and prep worktrees and appends the row to the item's `spend.md` in the same commit (the tracker does the mechanics; the skills say when to call it).
- **Skills record each phase**:
  - make-issue at capture (and c0072's `land`);
  - ticket-prep after design work and after each design review, with the reviewer's minutes and tokens from the agent's usage report plus the author's answering time;
  - execute-raft per code review round, in place of `--time 0`;
  - the merge step for delivery (CI wait included).
- **Lines**: count prep-written specs and `check.sh` files under the `prep` phase, rather than excluding `tracker/` wholesale.
- **Reporting**: `tracker.sh metrics` reports spend per phase, per raft and per type, and design-review cost per round. Consider feeding c0073's board statistics (time by phase).
- **Override check**: promoted specs and done checks pin `spend.md`'s columns (c0001 lifecycle, `tests/tooling/spend.spec`, `metrics-rounds.spec`) and the `--time 0` wording. Find them in prep.


## Design
Tooling and skills only: no `src/` change, no `tracker/architecture.md` change. Designed against R0025's merged designs (c0067's moves and `currentRaft()`, c0070's `published()`, c0072's `land`), which exist when this starts (`depends_on`).

### The phases
`ledger.PHASES = { "capture", "prep", "design-review", "build", "code-review", "deliver" }`, in lifecycle order. Who records each, and how:

| phase | when | recorded by | lines |
|---|---|---|---|
| `capture` | make-issue, after `tracker.sh land` and before the worktree is removed | `tracker.sh spend <issue> --phase capture --time <m>` | 0 |
| `design-review` | ticket-prep, every round: as soon as the reviewer returns (whatever its verdict), and again after the round is answered when it had findings | `tracker.sh spend <R-id> --phase design-review --time <reviewer minutes> --tokens <reviewer tokens> --note design-review-NNN`, then `… --phase design-review --time <answering minutes> --note design-refute-NNN` | 0 |
| `prep` | ticket-prep, once, right after the prep PR is pushed and opened (before it merges, so before anyone can ready the raft) | `tracker.sh spend <R-id> --phase prep --time <author's prep minutes, design-review answering time excluded>` | the prep branch's own `check.sh`, `acceptance/` and `experiments/` lines |
| `build` | execute-raft, every implementation commit | `tracker.sh commit` (the default phase) | the staged diff, as today |
| `code-review` | execute-raft Phase 4: the review commit and the commits that answer it (stream reviews too) | `tracker.sh commit --phase code-review [--tokens <n>]` | the staged diff |
| `deliver` | execute-raft Phase 5 commits, `done`'s own commit, and once after the merge | `tracker.sh commit --phase deliver`; `done` itself; `tracker.sh spend <R-id> --phase deliver --time <minutes from done to merged>` | the staged diff; 0 after the merge |

Tokens are best effort: the Agent tool's usage report gives a subagent's total tokens and duration (E2). An agent that doesn't know its own tokens leaves `--tokens` out; the cell stays empty and sums as 0.

### The ledger: `scripts/tracker/ledger.luau` (new, pure: no requires)
The one reader and writer of the spend.md format. Start from the prep prototype, `experiments/ledger.luau` (it passes `acceptance/ledger.spec.luau`, mutation-checked).
```lua
ledger.PHASES: { string }
ledger.HEADER: string -- "| # | when | commit | +lines | -lines | minutes | attribution | phase | tokens |\n|---|…|\n"
export type Row = { when: string, subject: string, added: number, removed: number, minutes: number,
	how: string, phase: string, tokens: number? }
export type Totals = { added: number, removed: number, minutes: number, records: number, tokens: number }
export type Ledger = { id: string, title: string, rows: { Row } }
function ledger.isPhase(s: string): boolean
function ledger.parse(text: string): (Ledger?, string?)       -- nil and a reason naming the line
function ledger.sum(rows: { Row }): Totals                     -- minutes summed in tenths, nil tokens as 0
function ledger.byPhase(rows: { Row }): { [string]: Totals }   -- every phase present, empty ones zero
function ledger.render(id: string, title: string, rows: { Row }): string
function ledger.append(text: string?, id: string, title: string, row: Row): string
function ledger.appendOnly(old: string?, new: string, id: string): string? -- nil when allowed, else the reason
```
- **Format** (rendered): `# Spend: <id> <title>`, a blank line, the nine-column header, one row per record numbered from 1, a blank line, `**Total:** +A / -R lines, M agent-minutes, T tokens over N records`, and `<!-- totals: added=A removed=R minutes=M records=N tokens=T -->`. The first seven columns are exactly today's, so a reader of today's columns still finds them in place; `phase` and `tokens` are appended. Tokens print as an integer or an empty cell.
- **Reading old ledgers**: a seven-cell row is phase `build` with no tokens. A row written before this raft can span lines (a multi-line commit message in the commit cell, c0081 and c0082 today, found by E3): a line that starts `| <n> |` and doesn't end with `|` continues until the first line that does, joined with spaces. A bare `# Spend` title, integer minutes and a missing totals line (c0073's fixture shape) are read. Header and separator lines are skipped; any other table line that isn't a 7- or 9-cell row with a count, a `YYYY-MM-DD` date, non-negative integer lines, a number of minutes, a known phase and an integer or empty tokens cell is an error naming the line.
- **Writing**: `render` replaces `|` with `/` and newlines with spaces in the subject and attribution cells, so a row is always one line (the c0081 rows were a writer bug). `append` keeps an existing ledger's id and title and every row (old ones are rewritten as nine cells), and adds the new row; a missing ledger takes the given id and title.
- **appendOnly** (the publisher's rule): the new text parses, names `id`, and equals `render` of its own rows (so the numbering, header and totals are canonical); every old row is equal, field by field, to the new row at its index (minutes compared in tenths); the title is unchanged; and at least one row was appended. An unparseable old ledger is refused with "fix it by pull request".

### `scripts/tracker/spend.luau` (changed)
- `appendRow(issue, share, subject, phase)` writes through `ledger.append` (a ledger that doesn't parse is an error, nothing is committed). It no longer retitles an existing ledger.
- `readTotals(dir)` sums the parsed rows (`ledger.sum`), so old ledgers and new ones read alike. `Totals` gains `tokens`; the field `commits` becomes `records`.
- `Share` gains `tokens: number`. `attribute(issues, stats, minutes, how, tokens?, owners?)`: tokens are split like minutes (by lines added, evenly when there are none) and apportioned with the largest-remainder method, so they sum exactly to the given number. `owners: { [string]: { string } }?` replaces the Touched-modules prefixes when given (the prep line count uses item directories). Existing callers and `tests/tooling/spend.spec.luau` are unchanged.
- `prepStats(items: { store.Item }, raft: store.Item?): ({ FileStat }, { [string]: { string } })`: runs `git diff --numstat origin/main...HEAD -- <paths>` (three dots: the prep branch's own change, the same before and after a squash merge, E1) over each member's `<dir>/check.sh`, `<dir>/acceptance` and `<dir>/experiments`, and the raft's `<dir>/check.sh`; returns the stats and the owner map (a member's own directory); the raft's `check.sh` is unowned, so `attribute` splits it evenly. Documents, reviews and everything outside these paths never count.
- `writeRaft(raft)`: the summary table gains a `tokens` column, the totals line becomes the ledger's, and a second table `| phase | +lines | -lines | minutes | tokens |` lists each phase that has records, summed over the members, in lifecycle order. It stays a snapshot written by `commit` and `done` (the PR body); the post-merge `deliver` rows are on the members only, and `metrics` reads the members.

### `tracker.sh spend <id> --phase <capture|prep|design-review|deliver> --time <minutes> [--tokens <n>] [--note <text>]` (new, `scripts/tracker/main.luau`)
1. **Where**: not `READ_ONLY` (`guardRepoRoot()` runs; the spec runs it from a tooling copy with no `.git`). `refuseInMainCheckout("spend")`. Needs `publishing()`; otherwise fail `spend needs an origin remote (PICKMAN_PUBLISH=0 disables it); inside a raft, record with tracker.sh commit --phase`.
2. **Arguments**: `<id>` is an issue or a raft. `--phase` must be one of the four; `build` and `code-review` fail naming `tracker.sh commit --phase`; anything else fails listing the four. `--time` is required (spend has no commit gap to measure): a non-negative number, an `m` suffix allowed. `--tokens`, when given, is a non-negative integer. `--note` defaults to the phase; it is the row's commit cell.
3. **Targets** (checked inside the publish build, against the origin tree that build reads, so a `ready` landing between a check and a retried push is seen; review 002 F4): an issue is itself, looked up on `origin/main` only (`docPath` over the build's paths; it need not exist in this checkout, review 003 F4); a raft is `store.members(id)` from this checkout (a raft with none, or a raft this checkout doesn't have, fails with "run tracker.sh sync first"), and each member is then looked up on `origin/main`. Every target, and the raft, must be on `origin/main`. **Refused when any of them is active there**: in `active/`, or with an effective status of `active` (`statusLib.effective`, so a legacy claim in the backlog counts). For `capture` and `deliver` the message is `<id> is active on origin/main: inside its raft, record with tracker.sh commit --phase`. For `prep` and `design-review`, whose window has closed (`commit` refuses them too), it is `<id> was readied before its <phase> spend was recorded: record nothing and report it` (review 001 F6). That keeps `spend` and a raft branch from ever writing the same ledger (no merge conflicts); a done item is allowed (deliver).
4. **Shares**: `prep` uses `prepStats` (fetch first) and `attribute(members, stats, time, "spend", tokens, owners)`; the other phases pass no stats (lines 0, an even split). An issue target gets the whole row. Shares with no lines, under 0.1 minutes and no tokens are skipped, as in `commit`.
5. **Publish**: one `publishFresh` call. The build reads each target's `spend.md` beside its document on `origin/main` (any state directory: `docPath` gives the directory) and returns `ledger.append(existing, id, title, row)` for each share (title from the origin document). Message `tracker: spend <id> <phase>`. The call is written `published(publishFresh(…))`: c0070's AC4 requires every `publish.commit` path in `main.luau` to go through `published()` (review 003 F1). Nothing local changes: no file, no commit, no merge (a later `tracker.sh sync` brings the rows). Print one line per share, `<id> <phase> +a/-r m.m min [t tokens]`, and the published sha.

### `tracker.sh commit … [--phase build|code-review|deliver] [--tokens <n>]` and `done`
- `recordAndCommit(raft, message, ids, minutes?, isDone?, phase, tokens?)`. `cmd.commit` validates `--phase` (default `build`; `capture`, `prep` and `design-review` fail naming `tracker.sh spend`; unknown fails listing the three) and `--tokens` (a non-negative integer) **before** staging anything.
- Rows carry the phase and the share's tokens. The trailer is unchanged for a build row without tokens (`Issue: f0010 +5/-0 5.0m`, c0001 reads it); otherwise it appends ` <phase>` when the phase isn't build and ` <n> tokens` when tokens were given: `Issue: f0010 +0/-0 5.0m code-review 777 tokens`.
- The skip rule keeps a share with tokens.
- `done` records its commit as `deliver`.

### `tracker.sh metrics` (changed)
Reads every ledger with `ledger.parse` (a ledger that doesn't parse is reported on stderr and skipped, never fatal). Output, in this order (each table preceded by a blank line and a one-line caption):
1. `| issue | type | raft | +lines | -lines | agent-minutes | tokens |` (the per-issue table gains tokens).
2. The type table, unchanged.
3. **Spend by phase**: `| phase | feature | defect | chore | all | tokens |`, one row per phase in lifecycle order, agent-minutes (`%.1f`) over the counted issues (done, plus active with `--include-active`).
4. **Spend per raft by phase**: `| raft | type | capture | prep | design-review | build | code-review | deliver | all | tokens |`, for each raft with at least one counted member, by raft id.
5. **Design-review cost per round**: `| raft | design rounds | design-review minutes | minutes/round | tokens/round |` for every raft in any state with at least one `design-review-NNN.md`; minutes and tokens from its members' `design-review` rows in any state (a raft in prep is priced too). `minutes/round` is `%.1f`, `tokens/round` is rounded to an integer.
6. The review-rounds table, unchanged (c0043 and `metrics-rounds.spec` read it, and read from its header on).
7. Rework, unchanged formulas, with the added line `Rework counts every phase, capture to deliver.` after `Rework = …`. The user's non-goal allows only making the covered phases clear; every phase is counted because each phase's spend belongs to the issue's type.

### Scalability
- `spend` is one fetch, one `ls-tree`, a `git show` per target and one publish: the same cost as `status`. `prep` adds one `git diff --numstat`.
- `metrics` parses every ledger once: 51 files and 243 rows today parse in well under a second (E3); linear in rows.
- Ledgers grow by a few rows per issue per phase.

### Maintainability
- One module owns the format; `spend.luau`, `publish.luau`, `metrics` and the board read and write only through it. A new phase is one entry in `ledger.PHASES` plus who records it.
- The append-only rule is checked by the publisher itself, so no future caller can rewrite history on `origin/main`.

### Usability
- One command for every phase outside a raft, refused with the right alternative inside one; `commit` keeps its defaults, so build work needs nothing new.
- `metrics` answers "what did design review cost per round" and "where does the time go" directly.
