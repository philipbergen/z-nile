# c0103: Narrow key map

## Problem
The promoted key-map spec (`tests/acceptance/f0014/keys.spec.luau`) must allow later actions beside the movement keys, so new actions can be added without turning main red. The new actions are a jump key (Space), a fire key (E) and arrow-key look, which f0104 binds; f0104 also retires the snap-look key (Space today) and turns the arrow keys from turn intents into look.

## Non-goals
- Binding the new keys or changing the arrow keys (f0104). This chore only makes the spec tolerant, so f0104 and the actions it binds land without a red main.

## Solution
_Captured; design happens in ticket-prep._ Narrow the spec to the keys that stay (W, A, D, S as `Forward`, `Left`, `Right`, `Back`) and let any other key map to an action it does not check; keep the checks that every mapped key resolves to a valid action and that `Controls` binds every key in `View.KEYS`.
