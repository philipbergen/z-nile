# c0103: Narrow key map

## Problem
The developer. `tests/acceptance/f0014/keys.spec.luau` requires exactly nine keys, requires Q to do nothing, and requires every action to be a movement intent or Snap. R0035 needs F = Fire and Q = Drop. Those assertions would fail on main the moment the keys are added, and a feature raft may not edit a promoted spec.

## Non-goals
- Binding F or Q, or any blaster, minimap, or sensor behaviour (R0035).
- Touch controls (R0012).
- Editing `tracker/issues/done/f0014/check.sh`. Its AC5 line keeps running this spec.
- Removing the spec.

## Solution
Narrow the three assertions described in the Design. The nine existing mappings stay, so the spec still fails if W, A, S, D, the arrows, or Space change.

## Design
Edit only `tests/acceptance/f0014/keys.spec.luau`.

1. Replace `t.expect(n).toBe(9)` with `t.expect(n >= 9).toBe(true)`.
2. Replace `{ "Q", "E", "w", "Return", "LeftShift", "" }` with `{ "E", "w", "Return", "LeftShift", "" }`.
3. Replace `action == "Snap" or Movement.isIntent(action)` with `action == "Snap" or action == "Fire" or action == "Drop" or Movement.isIntent(action)`.

Leave the table of nine mappings as it is. Do not add F or Q to `View.KEYS`.

### Scalability
One spec file. No per-frame work and nothing replicated.

### Maintainability
A later action is a one-line addition to the guard, plus a chore if a promoted spec forbids it. The nine mappings stay the regression for the original keys.

### Usability
Players see no change. The developer API of `View.action` is unchanged by this chore.

### Touched modules
- `tests/acceptance/f0014/keys.spec.luau`
- `tracker/issues/c0103/acceptance/narrowed.spec.luau`

### Affected specs
`lune run scripts/affected -- tests/acceptance/f0014/keys.spec.luau` selects that spec (it is the changed file). The new spec is `tracker/issues/c0103/acceptance/narrowed.spec.luau`.

`grep -rlF tests/acceptance/f0014/keys.spec.luau tests/acceptance` finds nothing else that names the file. The folder `tests/acceptance/f0014/` is the area; its other specs (interpolate, look, place, pose, walls) do not read the key table.

## Unknowns & experiments
None. The edit is text in a spec whose current contents were read during prep.

## Regression guard
The nine mappings must still pass, and E, w, Return, LeftShift, and the empty name must still do nothing. AC2 runs the edited spec.
Overrides: tests/acceptance/f0014/keys.spec.luau
