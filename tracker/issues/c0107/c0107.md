# c0107: Board lists rafts and issues by readiness

## Problem
The person using the tracker board cannot see what to do next. The work lists are Active, Waiting, and Done. Waiting shows only rafts with nothing unfinished in front of them, and an issue appears only inside its raft. Ready and not-ready work are not separate groups, and they are not color-coded. A raft row does not say whether that raft is a feature, a defect, a chore, or a mix of those. A row does not offer the command that takes the next step, and there is no copy control that puts that command on the clipboard.

## Non-goals
- Changing what `ready`, `launch-raft`, `ticket-prep`, or `done` do.
- The Stats charts. They stay a separate section, not a work list.
- The Actions artifact that publishes the board.

## Solution
- Two work lists, Rafts and Issues, instead of browsing only by Active and Waiting.
- Each list splits into ready and not ready, with a clear color for each.
- Every raft shows its type from its issues. All one type shows feature, defect, or chore. More than one type shows a mix. The type stays readable beside the ready and not-ready color.
- A raft is ready when prep has merged (`design: ready`, status `prepared`). Its copy command is `/ready-raft <id>`. A readied raft's copy command is `/launch-raft <id>`.
- An issue with no raft is not ready to execute. Its copy command is `/ticket-prep <id>`. An issue already in a raft copies that raft's next command.
- Each row has a copy icon. Activating it writes that command to the clipboard.
