# c0111: Skill lessons

## Problem
Design-review findings are lost once a raft's prep merges: they sit in `design-review-NNN.md` files that no later prep reads. So the same classes of defect come back in every raft. R0039 took all 5 review rounds and 29 findings, and most of them could have been caught in the first draft: promoted specs that go red under a new mechanism, state tied to the wrong process lifetime, pure seams whose call-site inputs are unpinned, and text that contradicts itself. The only record of these lessons is one agent's private memory file, which other agents, the reviewer and the executor never see.

The user wants lessons organized under the skills, not in one file, so they can be searched and used by the pipeline:
- **Harvest at the end of design.** When the design review ends, the prep author turns the recurring findings into lessons, or adds the raft as a new source on an existing lesson. Lessons land with the prep PR.
- **Apply at the start of the next design.** The prep author walks the matching lessons against the draft before the first review round. The reviewer checks them too, and `ready-raft` puts the matching ones in the execution prompt.

## Non-goals
- Turning lessons into enforced script checks. A lesson with several sources is a candidate for its own chore.
- Rewriting past rafts' reviews. Seed only from R0039; older rounds can be mined later.
- Harvesting from code reviews in execution. It may follow the same mechanism, but decide that in prep.

## Solution
- **One file per lesson** under the skill that applies it: `.claude/skills/<skill>/lessons/L<NNNN>-<slug>.md`. Frontmatter: `id`, `title`, `phase` (prep, review, execute or testing), `tags`, `sources` (for example `R0039 design-review-001 F1`) and `check` (the question to ask a draft). Body: the rule, why it matters, and how to apply it.
- **`scripts/tracker.sh lessons [--skill s] [--phase p] [--tag t] [text]`** lists the matching lessons. It is a search, not a gate.
- **ticket-prep:**
  - A new step before `design: reviewed`: walk `tracker.sh lessons --phase prep` against the draft and record which lessons changed the design.
  - A new step after the final review round: harvest. Each finding becomes a new lesson or a new source on an existing one, or is noted as one-off in `design-refute-NNN.md`.
- **review skill:** design mode also checks the draft against the prep and review lessons.
- **ready-raft:** `prompt.md` includes the execute and testing lessons whose tags match the raft.
- **metrics:** report findings per tag across rafts, to show whether lessons reduce review rounds.
- **Seed lessons:** the 12 R0039 lessons, now in the author's private memory (`design-first-pass-checklist`). That memory then becomes a pointer to the repo.
