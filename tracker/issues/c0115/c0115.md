# c0115: Rename skills and write the z-nile README

## Problem
The skills are named for the old steps (`make-issue`, `ticket-prep`, `ready-raft`, `launch-raft`, `execute-raft`, `stop-raft`, `review`, `tracker`, `architecture`, `testing`, `metrics`). An agent cannot see which names are the pipeline and which are only called from inside a step. The one-page map, where it exists, describes that old flow.

Pipeline skills become `z-ticket`, `z-design`, `z-raft`, `z-ready`, `z-run`, and `z-stop`. Skills called only from inside a step become `zz-review`, `zz-rules`, `zz-arch`, `zz-test`, and `zz-stats`. The `zz-` prefix is reserved: a game does not add a skill under it. `z-nile/README.md` opens with the picture of the tracker, the skills, the dispatcher, `.models.toml`, and the board.

## Non-goals
- Creating rafts inside `z-design`, or the recombine command. That is c0116.
- Implementing the dispatcher or the board. Those are c0117 and c0118.
- Deleting the old skill directories. Promoted specs and `renderPrompt`'s `SKILLS_INLINED` read them. This raft does not change `SKILLS_INLINED` or the ready error `ticket-prep makes one`.
- Replacing c0113 in place. c0113 forbids changing skills. This issue writes the new page under `z-nile/`.

## Solution
- Add the new skill files under `.claude/skills/`, which is where the harness looks up a name.
- Leave the old directories in place and byte for byte, except where c0116 edits a new file rather than the old one.
- Point `AGENTS.md` at the new files as well as the old ones.
- Write `z-nile/README.md` so a flowchart comes before the first paragraph.

## Design
New files, one directory each, with `SKILL.md`. The harness reads `.claude/skills/<invoked-name>/SKILL.md`. `AGENTS.md` keeps its old table and adds a table whose paths are the new directories. `renderPrompt` keeps inlining `execute-raft`, `tracker`, `architecture`, `testing`, and `review`. A readied prompt therefore still contains the old tracker text. An agent that follows `AGENTS.md` reads `zz-rules`, which c0116 updates. The copies that must not drift are byte-equal to their source, taken after c0111 has added the `## Lessons` section:

| new path | source | bytes |
|---|---|---|
| `.claude/skills/z-ticket` | `make-issue` | equal |
| `.claude/skills/z-design` | `ticket-prep` | c0116 removes raft creation; not equal |

Each new `SKILL.md` has frontmatter `name:` equal to the directory and a non-empty `description:`. Each copied skill contains the source file's first line that starts with `# `.

`z-nile/README.md` contains a ` ```mermaid ` fence before the first paragraph. A paragraph is the first line outside a fence that is not empty and does not start with `#`. The fence's nodes are You, Tracker files, `.models.toml`, Dispatcher, tracker.sh, Runtime adapter, GitHub, and Board. The prose names tracker, skills, dispatcher, `.models.toml`, and board.
