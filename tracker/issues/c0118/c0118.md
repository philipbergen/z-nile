# c0118: Board per project with review graphs

## Problem
The tracker board is one page of every raft and issue. It cannot show two games without mixing them. It has no picture of the pipeline, and no graph of how many design reviews and code reviews a week of landed rafts took, or which model spent the tokens on those reviews.

The new board lists every project in `projects.toml` as a tab on the left, `z-nile` included. One project is selected. Its columns are ticket, design, raft, rafted, run, and done. Each issue is a card. A raft is a band behind its members. Done cards stay 24 hours, adjustable from 1 hour to 30 days. The page shows copyable `scripts/tracker.sh stop <id>` and `scripts/tracker.sh ready <id>` text. It does not launch a process. Two charts use their own range, 90 days by default, open to all history: review rounds by week, and tokens by model for `design-review` and `code-review`.

## Non-goals
- Replacing `tracker.sh board`. That command and `scripts/tracker/board.luau` stay.
- Reading worktrees, pull requests, or GitHub checks. A later issue can add those fields. This issue reads tracker documents and `spend.md` only.
- Starting a model, or running stop and ready from the page. The actions are command text.
- Calling `gh` or opening a browser from a spec. `view -O` writes the file and does not run `open`.

## Solution
- Build a view per project from tracker items and spend rows. `project:` selects the tab. A missing key is `pickman`.
- Count design-review files and code-review files on rafts that have a done time, in the ISO week of that time.
- Split `design-review` and `code-review` tokens by the model cell. An empty model is `unrecorded`.
- `tracker.sh view` writes the page. `tracker.sh board` stays.

## Design
`scripts/tracker/view.luau`, required as `require("@scripts/tracker/view")`:

```lua
export type Item = {
	id: string,
	project: string,
	status: string, -- the effective word from status.effective
	inRaft: boolean,
	doneAt: string?, -- ISO-8601 UTC, only for a done raft
	raft: string?,
}
export type Review = { raft: string, kind: string } -- "design" or "development"
export type SpendIn = { project: string, phase: string, tokens: number?, model: string? }
export type Input = {
	projects: { string },
	items: { Item },
	reviews: { Review },
	rows: { SpendIn },
	doneAtByRaft: { [string]: string },
}
export type Card = { id: string, column: string, doneAt: string? }
export type Week = { week: string, design: number, development: number }
export type ProjectView = { id: string, cards: { Card }, weeks: { Week }, tokens: { [string]: number } }

function view.column(effective: string, inRaft: boolean): string
function view.week(doneAt: string): string
function view.build(input: Input): { ProjectView }
function view.render(views: { ProjectView }): string
```

`column` uses the effective word, which the reader gets from `status.effective`. `new` is `ticket`. `preparing` is `design`. `prepared` with `inRaft == false` is `raft`. `prepared` with `inRaft == true` is `rafted`. `active` is `run`. `done` is `done`. The column is `rafted`, not `ready`: `z-ready` is the skill that moves a raft to `active`, which is the `run` column.

`week` is the ISO week of the UTC timestamp, Monday start, the week belonging to its Thursday. `2026-12-27T23:59:00Z` is `2026-W52`. `2026-12-28T00:00:00Z` is `2026-W53`. `2027-01-04T00:00:00Z` is `2027-W01`.

`build` is pure. It does not read the repository, the network, or git. One view per id in `projects`, in that order. A card whose `project` is not in the list goes on one extra view whose id is `unknown`, after the listed ids, so a typo is visible. `design-review-*.md` is kind `design`. `review-*.md` is kind `development`. The reader dates a raft's week from the commit that first placed that raft under `tracker/rafts/done/`, not from a spend row's `when`. `weeks` counts a review only when `doneAtByRaft[review.raft]` is set, in `view.week` of that time, and only on the view whose id is the project of the raft item with that id. A review is not copied onto every project. `kind == "design"` increments `design`. `kind == "development"` increments `development`. A review whose raft has no done time counts nowhere. `tokens` sums `tokens` of rows whose phase is `design-review` or `code-review` and whose `project` is that view. A nil or empty model uses the key `unrecorded`. Any other phase is ignored.

`render` returns HTML and does not read the disk. The template is a string in `view.luau`. `z-nile/board/index.html` is that same string written out for a person to read; `render` does not load it. For a view list whose ids are `alpha` and `beta`, the HTML has exactly one `data-project="alpha"` and one `data-project="beta"`. It contains `data-done-hours="24"`, `data-done-min="1"`, `data-done-max="720"`, and `data-chart-days="90"`. It contains the text `scripts/tracker.sh stop` and `scripts/tracker.sh ready`. It embeds the view JSON in `<script type="application/json" id="z-nile-view">`. It does not launch a process.

`scripts/tracker.sh view [--out PATH] [-O]` writes that HTML. The default path is `.cache/z-nile-board.html`. `-O` does not run `open`. The reader fills `Input` from tracker documents, `spend.md`, and `history.read` for the commit that put a raft in `done/`. It does not call `gh`. A raft's project is its members' common `project:`, not a key on the raft. Specs that call `view.build` pass a table. The reader is checked by `tracker.sh view -O` inside a fixture, never against this repository.

### Scalability
One pass over the items, reviews, and rows handed to `build`.

### Maintainability
The page displays `column`, `weeks`, and `tokens`. It does not re-derive them.

### Usability
The left edge lists project ids from `projects.read`. Pickman and z-nile are separate canvases. The done window defaults to 24 hours and the control allows 1 hour through 720 hours.

## Unknowns & experiments
The week examples are the ISO rule this issue checks. The rows stay reasoned. `view.luau` is not in the tree, so there is no function to mutate. "columns", "weeks", "landed reviews", "tokens", and "page" fail today because `require("@scripts/tracker/view")` is missing. "unknown project" fails for the same reason, and its assertion is the card on `unknown` rather than a dropped card. "reader" fails because `tracker.sh view` is missing; the fixture's two commit dates are what makes a spend-row date the wrong week. That is the assertion, not a blanket "the module does not exist."

## Regression guard
The current board page and its specs stay, because `scripts/tracker/board.luau` and `board.html` are not edited.
Overrides: none

## Test plan
- `view.spec` :: each effective status maps to its column, including a stamp through status.effective → AC1
- `view.spec` :: Sunday and Monday, and the 2026/2027 boundary → AC2
- `view.spec` :: a done raft's reviews land in its week, and a raft with no done time adds nothing → AC3
- `view.spec` :: tokens split by model, empty model is unrecorded, build does not count a build-phase row → AC4
- `view.spec` :: render of alpha and beta has one tab each, no gamma, and the done and chart attributes → AC5

### Rules and mutants
| rule | spec :: case | mutant it kills | checked |
|---|---|---|---|
| the six effective words map to ticket, design, raft, rafted, run, and done | view.spec :: columns | map every status to ticket | reasoned |
| ISO week changes at Monday 00:00 UTC and at the year of the Thursday | view.spec :: weeks | use Sunday as the start, or call 2027-01-01 week 1 | reasoned |
| reviews count only for a raft that has a done time, in that ISO week | view.spec :: landed reviews | count a backlog raft's review files | reasoned |
| design-review and code-review tokens split by model; a nil model is unrecorded | view.spec :: tokens | drop the nil-model row, or add a build-phase row | reasoned |
| render has one tab per given id, the 24 hour default, and the bounds 1 and 720 | view.spec :: page | hard-code pickman and z-nile, or omit the bounds | reasoned |
| an item whose project is not listed is a card on a view id `unknown` | view.spec :: unknown project | drop the card | reasoned |
| the reader dates the done commit, and the JSON puts the card, the week, and the tokens on that project | view.spec :: reader | date by the spend row, or put every card on pickman | reasoned |

## Acceptance criteria

### Checked
- AC1: `view.column` maps `new` to `ticket`, `preparing` to `design`, `prepared` without a raft to `raft`, `prepared` with a raft to `rafted`, `active` to `run`, and `done` to `done`. A stamped `preparing-…` status passed through `status.effective` maps to `design`.
- AC2: `view.week("2026-12-27T23:59:00Z")` is `2026-W52`, `view.week("2026-12-28T00:00:00Z")` is `2026-W53`, and `view.week("2027-01-04T00:00:00Z")` is `2027-W01`.
- AC3: A raft with `doneAt` `2026-12-28T00:00:00Z`, one design review, and one development review adds 1 to `2026-W53` design and 1 to development. A review whose raft has no done time adds nothing.
- AC4: A `design-review` row with no model adds its tokens to `unrecorded`. A `code-review` row with a model adds them to that model. A `build` row adds nothing.
- AC5: `view.render` of views for `alpha` and `beta` contains a tab for each, no tab for `gamma`, `data-done-hours="24"`, `data-done-min="1"`, `data-done-max="720"`, `data-chart-days="90"`, and the command text `scripts/tracker.sh stop` and `scripts/tracker.sh ready`. `view.build` with `projects` `alpha` and one item whose project is `gamma` returns views `alpha` and `unknown`, and the card is on `unknown`.
- AC6: `tracker.sh view --out <path> -O` on a fixture whose raft moves into `done/` on `2026-12-28` embeds JSON. The z-nile view has card `c0001`, week `2026-W53` with design 1 and development 1, and `tokens["grok-4.7"] == 12`. The pickman view has card `c0002`, no `c0001`, no weeks, and no tokens. The spend row's `when` is a different week.
- AC7: `tab.spec` runs `tracker.sh view` after `new issue --project z-nile`. The decoded JSON has a view id `pickman` and a view id `z-nile`. The new id is on `z-nile` only.
