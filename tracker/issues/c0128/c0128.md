# c0128: Narrow hiscore adapter pins

## Problem
Two promoted hiscore adapter specs pin today's per-player-only boards, so d0124 (R0044) cannot land while they stand. d0124 keeps every per-player board as it is and adds an all-time top-10 list of runs in a new store, `HiscoreTop` (scope `all`, key `runs`): the game server writes it before the per-player boards, and the lobby's all-time answer reads it and also carries the asker's own best as a fifth value. User decision for d0124, 2026-10-21: "Keep player best and a global list of top-10, so the number of rows is (10+n_players) in total".

On a prototype of d0124 (R0044 prep, 2026-10-21) exactly seven promoted cases fail, and every other selected spec passes (309 of 316 cases):
- `tests/acceptance/f0024/adapter.spec.luau` :: "stores are the shared names scoped by period, budgets are the modern request types": the exact list of six stores gains `HiscoreTop|all`.
- `tests/acceptance/f0024/adapter.spec.luau` :: "each update is preceded by the read and write budgets of its own store": `expected 6, got 8` (the list's update, twice on a first write: once to find no list, once with the seed).
- `tests/acceptance/f0026/adapters.spec.luau` :: "a failed read still answers once, with failed = true and the rows it had, or none", "an error anywhere in the read, opening the store included, is a failed read and the board is not wedged" and "a companion row that cannot be read fails the read: no short board is answered as healthy or cached": a whole-answer `toEqual` of four values meets a fifth (the asker's best).
- `tests/acceptance/f0026/adapters.spec.luau` :: "Boards opens the ordered and the companion store under their own names and the board's scope": `expected "companion|HiscoreEntries|all", got "companion|HiscoreTop|all"`.
- `tests/acceptance/f0026/adapters.spec.luau` :: "a page of 50 after the size-10 fallback is cut to the top N before any companion is read": `gets <= N` counts the list read and the best read too.

**Outcome:** those seven cases are narrowed so they keep pinning what they pinned for the per-player boards and no longer forbid d0124's additions, and `main` stays green before and after d0124 lands. No other case changes, and no case is removed.

## Non-goals
- Any change to `src/`: d0124 (R0044) builds the list, the best line and the missed-rank line, and its own sequestered specs pin them.
- Any other promoted spec, and these files' other cases.

## Solution
- f0024 `adapter.spec` stores case: the six per-player stores are each opened, and any other store opened is `HiscoreTop|all` only.
- f0024 `adapter.spec` budgets case: every update is still preceded by both budgets of its own kind, and the updates to the `Hiscores` and `HiscoreEntries` stores are still exactly six; updates to `HiscoreTop` are not counted.
- f0026 `adapters.spec` three answer cases: compare the first four values of each Board answer (id, rows, highlight, failed), as every whole-answer `toEqual` in the file does after this change.
- f0026 `adapters.spec` opens case: a companion open is `companion|HiscoreEntries|all` or `companion|HiscoreTop|all`; ordered opens stay `ordered|Hiscores|all`.
- f0026 `adapters.spec` page-of-50 case: count only the `GetAsync` calls for the board's thirty row keys, which stay at most N.
