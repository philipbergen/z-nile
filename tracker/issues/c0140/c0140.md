# c0140: Beta deploy on ready

## Problem
Nothing is ever running in a real Roblox server except by hand in Studio. The design says every PR that's ready for review should publish to a private **Pickman Beta** experience, so it can be played on real devices (phones included) and so engine-level smoke tests can run (c0030).

## Non-goals
- Publishing to production. Game features.
- Running tests in the published place: c0030.
- A separate CI experience: the runtime tests run against Beta itself (see the raft, *Prep experiment*).

## Solution
A `beta` job in `.github/workflows/check.yml`, behind the gate (`needs: gate`), that for a PR that is ready for review, from a branch of this repo:
1. installs only the toolchain (`scripts/setup.sh --tools`: the gate has just run),
2. runs `lune run scripts/deploy-beta`, which builds the place with Rojo and publishes it through Open Cloud's Place Publishing API,
3. comments the published version on the PR (one comment, edited on each push).

All the logic is a small Luau library, `scripts/lib/opencloud.luau`, with the HTTP call and the sleep injected, so it is tested without a network; the commands are thin.

## Design

### Decisions made in prep
- **The request** is the one that worked from CI in prep (run 36793719983) and is copied from `../karma`'s `make beta`: `POST https://apis.roblox.com/universes/v1/<universe>/places/<place>/versions?versionType=Published`, header `x-api-key`, `Content-Type: application/octet-stream`, body the `.rbxl` bytes, answer `200 {"versionNumber": N}`. (The first prep attempt put an extra `universes/` in the path and was refused by Roblox's WAF with 403 code 9009: `publish.spec` pins the exact URL.)
- **Busy** (HTTP 409): retry up to 5 attempts, 60 s apart (karma's rule); every other status is final and reported with its status and body.
- **The key never leaves the `x-api-key` header**: no message, error, log line or comment contains it.
- **Not configured is a green skip**, not a failure: any of `ROBLOX_API_KEY`, `ROBLOX_BETA_UNIVERSE_ID`, `ROBLOX_BETA_PLACE_ID` missing or empty prints `::warning::beta publish is not configured ...` and exits 0, so a fork or a fresh clone isn't red. A *mis*configured id (not plain digits) is a failure, since the ids go into a URL.
- **Triggers and safety**: only `pull_request` events, for PRs not in draft, from branches of this repo (`head.repo.full_name == github.repository`), after `gate`. Not on `workflow_dispatch` (that is `ci-verify` proving a draft green) and not on a push to main. One publish at a time: `concurrency: { group: beta-deploy, cancel-in-progress: false }`: a publish in flight finishes, only the newest waiting run survives, so the last one wins.
- **Secrets**: `ROBLOX_API_KEY` (secret) and the two ids (repo variables) are named only in the beta job's `env`. The workflow's permissions stay `contents: read`; only the beta job adds `pull-requests: write`. No `pull_request_target`. PR text (title, body, branch name) never reaches a command line; values go through `env`.
- **The comment** is `Published to Pickman (Beta): version N (commit SHA).`, made with `gh pr comment --edit-last --create-if-none` (gh 2.83 here supports both flags), so a push edits the bot's last comment instead of adding another.
- **Test seam**: `OPENCLOUD_BASE` replaces the API host so the commands can be tested against a local fake of Roblox. It is accepted only for `http://127.0.0.1:<port>` and `http://localhost:<port>`; anything else is an error, so a stray variable can never send the key to another host.
- **Roblox publishes replace what Beta testers play.** Accepted while Beta is small: the user decided on 2026-09-30 to run the runtime tests against Beta itself. Beta was published once during prep (version 5, a bare build of main).

### `scripts/lib/opencloud.luau` (new; c0030 adds `execute` and `runSuite`)
```lua
export type Request = { url: string, method: string, headers: { [string]: string }, body: string? }
export type Response = { statusCode: number, body: string }
export type Http = (Request) -> Response
export type Config = { apiKey: string, universeId: string, placeId: string,
	base: string?, request: Http?, sleep: ((number) -> ())?, retrySeconds: number? }
OpenCloud.BASE = "https://apis.roblox.com"
OpenCloud.MAX_ATTEMPTS = 5
function OpenCloud.configFromEnv(env: { [string]: string? }): Config?   -- nil when not configured; errors "…must be digits" / "…loopback…"
function OpenCloud.publish(cfg: Config, place: string): number           -- the new version; retries 409; errors carry status and body, never the key
```
The real HTTP is `@lune/net`'s `request`; `retrySeconds` defaults to 60 and `sleep` to `task.wait`.

### `scripts/deploy-beta.luau` (new, thin)
Read the environment; unconfigured → warning, exit 0. Otherwise `rojo build -o .cache/beta.rbxl` (a failure prints `rojo build failed` and exits 1 before anything is sent), `OpenCloud.publish`, print `version=N`, and append `version=N` to `$GITHUB_OUTPUT` when set (appending, never overwriting what is there). A failure prints the error and exits 1.

### `.github/workflows/check.yml`
Add the `beta` job after `gate` (full text in the acceptance spec's expectations): `needs: gate`, the `if:` above, `permissions`, `concurrency`, an `env` with the three Roblox settings, then steps: checkout, `scripts/setup.sh --tools`, `id: deploy` running `lune run scripts/deploy-beta`, and (guarded by `if: steps.deploy.outputs.version != ''`) the PR comment. c0030 adds the runtime-test step after it.

### `scripts/setup.sh`
`--tools` runs the existing steps up to and including the Lune type definitions, then exits 0 before the gate; without the flag nothing changes.

### Docs
`SETUP.md` gets a *Beta publishing* section: the secret, the variables, the key scopes (`universe-places` write, and for c0030 `luau-execution-sessions` read and write), what triggers a publish, skip on missing config, no secret for forks, `scripts/setup.sh --tools`, and how to publish by hand.

### Scalability
One publish per ready PR push, serialized. A publish of this place takes about 1 s; the 5 × 60 s busy retries bound the worst case at about 5 minutes. No per-player cost.

### Maintainability
All request logic is one small library with injected HTTP and sleep, and both commands are tested end to end against a loopback fake. Roblox API shape changes touch one function. Production publishing, when decided, is another command over the same library.

### Usability
A PR author sees one comment with the Beta version and a green or red check; nothing to configure per PR. A fork or a fresh clone isn't red.

## Unknowns & experiments
- **E1 (run in prep: PASS, after one correction)**: does a publish from a GitHub-hosted runner with the repo's secret and variables work? One publish to Pickman (Beta), through a one-off workflow on a throwaway branch (deleted): `rojo build` (Rojo 7.7.0 from its release zip) made a 17 KB place; `POST …/universes/v1/10768553777/places/82331952549326/versions?versionType=Published` returned **200 `{"versionNumber":5}` in 1 s**. Attempt 1 had a malformed URL (an extra `universes/`) and got `403 WAF Blocked Request` (code 9009), so nothing was published. No other User-Agent or route was tried.
- **E2 (run in prep: PASS)**: the whole library and both commands against a local fake of Roblox, with the real Rojo and a fixture project: 62 acceptance cases pass, and a 60-mutant check killed all 60 (including the doubled-`universes/` URL, the lost append, the retry rules, the loopback guard and every workflow condition).
- **E3 (run in prep: PASS)**: `gh pr comment --edit-last --create-if-none` exists in gh 2.83.2 (local); the `ubuntu-latest` runner's gh is newer.
- **E4 (not run: executor's Phase 1, fallback below)**: does the beta job's `scripts/setup.sh --tools` run on a fresh Linux runner (rokit install without the gate)? It is `setup.sh`'s existing steps, which CI runs today, so the risk is low; the first real run is the raft's own PR when it becomes ready.
- **Fallback if the comment step fails** (permissions): drop the comment and print the version in the job summary; the criterion that needs the comment is AC4's text check, so it would be revisited with the user.

## Regression guard
- The `gate` job and `check.yml`'s triggers are unchanged (a `workflow.spec` case pins them).
- `scripts/setup.sh` without a flag still ends with the gate (`tools.spec`).
- Existing `tests/tooling` specs and the gate's own checks (format, lint, types, build) must stay green; the new Luau files are strict and typed.

## Acceptance criteria

### Checked
- **AC1**: `OpenCloud.publish` sends the proven request (URL, method, key header, octet-stream body unchanged), returns the version, retries only HTTP 409 up to 5 attempts with the pause (default 60 s), treats every other status and a 200 without a version as errors that carry the status and body, and never puts the key in a message.
- **AC2**: `OpenCloud.configFromEnv` returns nothing when the key or either id is missing or empty, errors on ids that aren't plain digits, and accepts `OPENCLOUD_BASE` only for loopback addresses.
- **AC3**: `scripts/deploy-beta` end to end against a local fake: builds with Rojo, posts a real place file to the right path with the key, prints `version=N` and appends it to `$GITHUB_OUTPUT`; a refusal, a 200 without a version, a failed build or a bad configuration fails without a version line and without the key in the output; unconfigured, it warns and exits 0.
- **AC4**: The `beta` job in `check.yml` runs only after the gate, only for ready PRs from this repo, one at a time without cancelling a publish in flight, names the secrets only in its env, keeps workflow permissions read-only (write on PRs only in the beta job), has no `pull_request_target` and no PR text in commands, and comments the version guarded and in place; the gate job is unchanged.
- **AC5**: `scripts/setup.sh --tools` installs the toolchain and exits before the gate; without it the gate still runs last.
- **AC6**: `SETUP.md` documents the secret, the variables, the key scope, what triggers a publish, the skip, no secret for forks, `setup.sh --tools` and publishing by hand.
