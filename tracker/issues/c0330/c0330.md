# c0330: Check sh after promotion

## Problem
An issue's `check.sh` stops working once `tracker.sh done` has promoted its acceptance specs. The template (`tracker/templates/issue/check.sh`) finds the repo with `git -C "$A/.."`, where `A` is the issue's `acceptance/` directory. After promotion that directory no longer exists, so the script can't find the repo root or `scripts/lib/ac.sh`. `bash tracker/issues/done/c0020/check.sh` exits 127 (`fatal: cannot change to '…/acceptance/..'`, `check: command not found`). A done raft's exit criteria therefore can't be re-run on the merged branch, for example during PR review or later audits. Found in R0030 design-review-001 F5; c0090's `check.sh` already uses the fixed pattern.

## Non-goals
- Changing what any done issue checks. Only how the script locates the repo root and its specs.

## Solution
_Draft ideas; design happens in ticket-prep._
- Template: resolve the script's own directory with `pwd -P` (physical; `tests/run` strips the physical cwd, so a logical `/tmp/...` path breaks spec paths; R0030 design-review-002 F3), resolve the root from it, `git -C "$HERE" rev-parse --show-toplevel`, then `A="$HERE/acceptance"`, falling back to `tests/acceptance/<id>` when it has been promoted (as c0090's check.sh does).
- Apply the same fix to the done items (c0010, c0020, c0040). Sequestration only applies during execution, so a chore may edit them.
- A tooling spec: after `done` in the lifecycle spec's throwaway clone, the item's `check.sh` still runs.
