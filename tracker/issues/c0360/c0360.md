# c0360: Done deferred answer

## Problem
`tracker.sh done` accepts an answer to a review finding only as `- F<n>: fixed ...` or `- F<n>: refuted ...`, and checks nothing else. With agents merging on their own (Phase 6 of execute-raft), a medium or low finding left after review round 3 has to be answered as `refuted: below the merge threshold, filed as <id>`. That is dishonest (the reviewer was not wrong), and the check can't tell it from a real refutation, so it equally lets a **high** finding through under the same words. The execute-raft skill documents this as an "interim form until c0360 adds a real `deferred` answer".

## Non-goals
- Changing what counts as significant: an unresolved high finding, or a Judged criterion ruled fail, still blocks the merge (decided by the reviewer's own file and the skill, not by `done`).
- Checking that the follow-up issue actually addresses the finding (a human or the next reviewer reads it).
- Changing the review file format (`### F<n> [severity] title` is already mandated by the review skill).

## Solution
Add a third answer form, `- F<n>: deferred <id>: <why>`, to the grammar `reviewProblem` accepts. It is valid only when the finding's severity in the review file is `medium` or `low`, `<id>` is an existing issue in the backlog, and `<why>` is non-empty. Anything else about a `deferred` answer is a precise error. `fixed` and `refuted` behave exactly as before. The execute-raft skill's interim form is replaced by the real one.

## Design

### `reviewProblem` in `scripts/tracker/main.luau`
`reviewProblem(raft)` finds the latest `review-NNN.md`; an `approve` verdict resolves it, otherwise every `### F<n>` heading needs an answer line `- F<n>: ...` in `refute-NNN.md`. It currently returns one message listing unanswered ids.

New behaviour, per finding `F<n>` (the heading is `### F<n> [severity] title`; the severity is `string.match(rest, "^%s*%[(%a+)%]")` on the rest of the heading line):
1. No answer line, or one that is not `fixed…`, `refuted…` or a `deferred` form: **unanswered** (as today; `deferred-ish` and any other word is unanswered).
2. `fixed…` or `refuted…`: accepted, any severity (as today).
3. `deferred` (the word alone, or followed by whitespace): must match `^deferred%s+([fdc]%d%d%d%d):%s*(%S.*)$`, else the problem `F<n>: deferred needs "<issue id>: <why>"`.
4. The severity must be `medium` or `low`, else `F<n> is <high|unrated>: only a medium or low finding can be deferred`. A heading with no `[severity]` is "unrated" and can't be deferred, because the rule can't be checked.
5. `<id>` must satisfy `store.find(id)` with `kind == "issue"` and `state == "backlog"`, else `F<n>: <id> is not a backlog issue` (this covers nonexistent ids, active/done issues, and rafts).

Unanswered findings are reported first (message unchanged: `review-NNN.md findings not answered in refute-NNN.md: F1, F2`); if none, the invalid deferrals are reported as `refute-NNN.md: <problem>; <problem>`.

### Skills (documentation)
- `.claude/skills/execute-raft/SKILL.md`, Phase 4 step 7: replace the interim form (the `refuted: below the merge threshold (medium|low), filed as <id>` line and the sentence "This is an interim form until c0360 ...") with: file each remaining medium or low finding with `tracker.sh new issue`, answer it `- F<n>: deferred <id>: <why>`, and quote every such line in the round's PR comment. It is no longer an exception to "only refute when the reviewer is wrong".
- `.claude/skills/tracker/SKILL.md`, `done` row: mention that a medium or low finding may be answered `deferred <id>: <why>` (a backlog issue).

### Scalability
`store.find` per deferred finding: a handful of directory reads. Review files are small.

### Maintainability
The answer grammar lives in one place (`reviewProblem`), and the skill text points at it. Each error names the finding and the reason, so a refusal tells the agent what to fix.

### Usability
An agent that can't fix a medium finding in this PR now says so truthfully, and `done` verifies that the follow-up exists. A high finding can no longer be waved through with the "below the merge threshold" wording.
