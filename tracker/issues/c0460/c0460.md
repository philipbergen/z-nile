# c0460: Publish tracker board to Pages

## Problem
The tracker board (`scripts/tracker.sh board`) only exists as a local HTML page in the gitignored `.cache/`, so it is stale unless someone regenerates it and it can't be viewed from a phone or shared. It should be rebuilt and published automatically every time `main` changes (a merged PR is a push to `main`).

## Non-goals
- Committing the generated HTML to the repo.
- Publishing on pull requests or drafts; only `main` deploys.
- Changing the board's content or layout.

## Solution
_Draft ideas; design happens in ticket-prep._
- A new workflow `.github/workflows/pages.yml` on `push` to `main` plus `workflow_dispatch`, with `permissions: contents: read, pages: write, id-token: write` and a `concurrency` group `pages`.
- Steps: checkout, bootstrap the toolchain as `check.yml` does (`scripts/setup.sh`, or a lighter lune-only install), run `scripts/tracker.sh board --out dist/index.html`, add `dist/.nojekyll`, then `actions/configure-pages`, `actions/upload-pages-artifact` (path `dist`) and `actions/deploy-pages`, with `environment: github-pages`.
- Site URL: `https://philipbergen.github.io/pickman/`.
- **Prerequisite (user action):** repo Settings, Pages, Source: GitHub Actions.
- **Open risk:** the repo is private. Pages from a private repo needs a paid GitHub plan, and the published site is public by default unless the plan offers access control. The board lists the whole backlog and spend, so prep must confirm the plan and the visibility before building this.
- Prep must also check that the board runs on Linux CI and that its vendored marked works offline.
