# c0460: Publish tracker board as an Actions artifact

## Problem
The tracker board (`scripts/tracker.sh board`) only exists as local HTML in the gitignored `.cache/`, so it is stale unless someone regenerates it. It should be rebuilt automatically whenever `main` changes (a merged PR is a push to `main`) and be fetchable without a checkout of the build tooling.

Decision (user, 2026-09-30): the repo is private and GitHub Pages from a private repo needs a paid plan and is public by default, while the board shows the whole backlog and spend. So the board is published as a **workflow artifact**, not to Pages.

## Non-goals
- GitHub Pages, or any publicly reachable copy of the board.
- Committing the generated HTML to the repo.
- Building on pull requests or drafts; only `main` (and manual dispatch).
- Changing the board's content or layout.
- Making `check.yml` or the full gate faster.

## Solution
A workflow `.github/workflows/board.yml`: on push to `main` and `workflow_dispatch`, check out, run `scripts/setup.sh` with `PICKMAN_SKIP_GATE=1` (toolchain only; the full gate stays `check.yml`'s job), run `scripts/tracker.sh board --out dist/board.html`, and upload it with `actions/upload-artifact@v4` as `tracker-board`. `setup.sh` gains the skip switch; the tracker skill says how to download the latest artifact.

## Design
**Workflow** (`.github/workflows/board.yml`), exactly:
```yaml
name: board
on:
  push:
    branches: [main]
  workflow_dispatch: {}
permissions:
  contents: read
concurrency:
  group: board-${{ github.ref }}
  cancel-in-progress: true
jobs:
  board:
    if: github.ref == 'refs/heads/main'
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: scripts/setup.sh
        env:
          GH_TOKEN: ${{ github.token }}
          PICKMAN_SKIP_GATE: "1"
      - run: scripts/tracker.sh board --out dist/board.html
      - uses: actions/upload-artifact@v4
        with:
          name: tracker-board
          path: dist/board.html
          retention-days: 30
          if-no-files-found: error
```
- Read-only token: an artifact upload needs no `actions: write`. No `pages`, `id-token`, or secrets.
- **Main only.** `workflow_dispatch` can be started on any ref, so the job has `if: github.ref == 'refs/heads/main'`: a dispatch on a branch is skipped and can't upload a branch's board that `gh run download` (which takes the newest artifact in the repo) would then hand out as "the" board.
- **Concurrency.** The group is per ref (`board-${{ github.ref }}`), because a workflow-level group is entered even when the job's `if` skips it, so a global group would let a branch dispatch cancel the `main` build. `cancel-in-progress: true` is safe: a newer push supersedes an unfinished build and the newest run always completes. Consequence: two quick merges cancel the first merge commit's run, so OC1 accepts the latest `main` run.
- **No step conditions, no `continue-on-error`**, and the `GH_TOKEN` env on the setup step stays (setup.sh dies on CI without it: "CI: GH_TOKEN missing or invalid"). The spec pins each of these.
- No `fetch-depth`: the board reads only `tracker/` (E2).

**`scripts/setup.sh`**: the final stage becomes
```bash
if [[ -n ${PICKMAN_SKIP_GATE:-} ]]; then
  say "gate (skipped: PICKMAN_SKIP_GATE is set)"
else
  say "gate"
  scripts/check.sh --full
fi
```
An unset or empty variable runs the gate, so every existing use (`SETUP.md`, `check.yml`) is unchanged. The block's shape is fixed on purpose: it starts at the line `if [[ -n ${PICKMAN_SKIP_GATE:-} ]]; then` and ends at the next line that is exactly `fi`, because the acceptance spec cuts it out and **runs** it under `set -euo pipefail` against a stub `scripts/check.sh`, with the variable unset, empty and `1` (text matching could not catch an inverted `-z`). It also asserts that no other `scripts/check.sh` call is in `setup.sh` and that no workflow except `board.yml` mentions the variable. `SETUP.md` gets one line documenting the variable.

**Docs**: the tracker skill's `board` row names `.github/workflows/board.yml`, the `tracker-board` artifact and `gh run download -n tracker-board -D .cache`.

**Retrieval**: the artifact is a zip held by the run; anyone with read access to the repo downloads it from the Actions run page or with `gh run download`. Retention is 30 days (`retention-days`), and every push to `main` makes a fresh one, so the newest is always the current board.

### Scalability
One build per push to `main` (about the time of `setup.sh`: tool downloads, no tests, no gate). Output is one ~0.6 MB file and grows with the number of tracker items. Private-repo Actions minutes are the only cost; `concurrency` bounds parallel runs to one.

### Maintainability
Reuses `setup.sh` (one bootstrap for local, CI and this job) and the existing `tracker.sh board` command, so a toolchain bump needs no edit here. Swapping the destination later (Pages, a release) changes only the last step.

### Usability
Developer-facing: the latest board is one `gh run download` away; failures show as a red run on `main`. The acceptance spec pins the workflow's structure, because Actions can't run locally.

## Regression guard
Overrides: none (no promoted spec pins `setup.sh`'s last stage, the tracker skill's board row, or `board.yml`).
Found with the grep check: `tests/acceptance/c0010/ci-workflow.spec.luau` reads `check.yml` and asserts it runs exactly `run: scripts/setup.sh` with `GH_TOKEN`. `check.yml` is untouched, and `setup.sh` without the variable still runs the full gate, so it stays green (run on the prototype).
At risk: `check.yml` and local `setup.sh` runs must still run the full gate. Guarded by the behavioural `setup-skip-gate.spec.luau` (unset and empty run the gate, an inverted or default-less guard fails it) and by the check that no other workflow sets the variable.

## Acceptance criteria
