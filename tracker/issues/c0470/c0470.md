# c0470: Parallel gate stages

## Problem
`scripts/check.sh` runs every stage serially (stylua, selene, luau-lsp on `src`, luau-lsp on tests and scripts, rojo build, then specs), and `tests/run.luau` runs specs one at a time. CI (`.github/workflows/check.yml`) is a single serial `gate` job. Developers and agents wait for the sum of all stages on every gate run. The first four stages are independent of each other, so they could run concurrently; specs might too. Stage timings haven't been measured yet, so the first step is to find out where the time goes.

## Non-goals
- Changing which specs the `--affected` selector picks.
- Splitting CI into multiple jobs (could follow, if local parallelism proves worthwhile).
- Changing what any stage checks.

## Solution
- Time each gate stage first and record the numbers; only parallelise what is worth it.
- Run the independent static stages (format, lint, both type-check passes) concurrently, with per-stage output buffered so logs stay readable, and keep the current fail-the-gate semantics and exit code.
- Evaluate running specs in parallel in `tests/run.luau` (needs spec isolation, e.g. the lifecycle spec's repo clone: see c0050).
- The rojo sourcemap must still be generated before the `src` type-check.
