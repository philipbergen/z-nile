# c0490: Beta poll transient errors

## Problem
`beta` is now a merge condition (R0080), and `OpenCloud.execute` raises on any non-200 while creating or polling a Luau Execution task, so one transient 429 or 5xx turns `beta` red and blocks the merge, with no retry and no documented recovery (R0080 review-001 F2).

## Non-goals
- `OpenCloud.publish`: it keeps its 409-only retry. A 5xx on publish stays final (the publish is not idempotent in effect: it replaces what Beta testers play).
- Retrying a network-level failure (the injected `request` raising instead of returning a status), and honouring `Retry-After`: `Response` carries no headers, and a fixed pause was enough for the 409 case.
- Changing `runSuite`, `scripts/deploy-beta.luau`, `scripts/runtime-test.luau` or the workflow: they get the retries for free through `execute`.

## Solution
Retry 429 and every 5xx when creating and polling a task, and document in the tracker skill what to do when `beta` is red.
- **Code** (`scripts/lib/opencloud.luau`, the only code file):
  - `OpenCloud.isTransient(statusCode: number): boolean` is true for 429 and 500-599, false for everything else.
  - A private `send(cfg: Config, request: Request): Response` makes the request, and while the answer is transient asks again, up to `OpenCloud.MAX_ATTEMPTS` (5) requests in all, pausing `cfg.transientSeconds or 5` between them (through the injected `sleep`). It returns the last response; the callers' existing `~= 200` check and error text are unchanged.
  - `execute` uses `send` for the creation POST and for each poll GET. The attempt count restarts for every request, and the pause is not added to the task `timeoutSeconds` (that bounds the task, not Roblox's blips).
  - `Config` gains `transientSeconds: number?`. `retrySeconds` stays the 409 (publish) pause.
- **Docs** (`.claude/skills/tracker/SKILL.md`, the Merging section's `beta` bullets): a red `beta` whose log shows `opencloud: ... failed with HTTP 429` or `HTTP 5xx` (the retries ran out) is rerun with `gh run rerun <run-id> --job <job-id>`, at most 3 times; any other red `beta` (HTTP 401/403/404, a `FAIL` line, a failed publish) is a real failure, and `BLOCKED:` once the cause isn't a Roblox blip.

## Design
- **Modules**: `scripts/lib/opencloud.luau` (tooling, Lune; no `src/`). No new dependency edge, so `tracker/architecture.md` is untouched.
- **Public API**: `OpenCloud.isTransient`, `Config.transientSeconds`. `execute`, `runSuite`, `publish` signatures are unchanged.
- **Retry rules**:
  - Transient = 429 or 500-599. 408 and every other 4xx are final.
  - Exhausted retries raise the same error as before, naming the last status and body, so `runSuite` lines read as they do today (`FAIL x: opencloud: creating the task failed with HTTP 503: ...`).
  - A retried creation sends the same body. If Roblox created a task before answering 5xx, the script runs twice; the runtime tests are read-only and return `PASS`, so that is harmless (recorded as risk).
  - No pause after the last attempt.
  - The API key stays out of every message (only the header carries it).

### Scalability
Worst case a request costs 5 attempts and 4 pauses of 5 s, 20 s. A run is a handful of tasks, each polled every 3 s, so a bad Roblox hour adds a bounded 20 s per request, never an unbounded loop. No per-frame or replication cost (CI-only tooling).

### Maintainability
One `send` helper and one predicate hold the whole policy; the next endpoint (for example a datastore call) calls `send` instead of `http(cfg)`. The status classes are data in one function, not branches at call sites. The constants are `MAX_ATTEMPTS` (shared with publish) and one config field.

### Usability
The developer API gains one optional field and one predicate; specs stay fast by injecting `sleep`. For the human, a transient red `beta` now usually never appears, and when it does the skill says exactly how to recognise it from the log and what to rerun.

## Unknowns & experiments
- **E1 (run in prep, PASS)**: do the existing specs still hold with retries? The c0030 execute and suite specs and the c0140 publish spec (22 cases) passed on a prototype. Their "HTTP failure creating or polling" cases keep a 500/403 and now see 5 attempts and a final raise with the same text; the fake `sleep` makes that instant.
- **E2 (cannot be run offline, unproven)**: does Roblox's Luau Execution API ever answer 429 with a pause that 5 s × 4 covers, and are 5xx really short blips? Method: none available without a flood of live calls, and a deliberate 429 would risk the Beta key. Fallback: raise `transientSeconds` (one config default) or `MAX_ATTEMPTS`; the executor's Phase 1 has nothing to run, and the first real transient `beta` run is the evidence.
- **E3 (reasoned)**: a retried creation POST may duplicate a task. Fallback if it ever matters: don't retry the creation on 5xx, only on 429 (one line in `isTransient`'s caller).
- **Mutation check**: a prototype of the Solution ran in the prep worktree (reverted before committing). Rows marked `run` below failed on an assertion of `transient.spec.luau`; `reasoned` rows have a mutant that needs a restructure sed can't make (shared counter, timeout accounting, publish edit) and are judged by reading the case named.

## Acceptance criteria

### Checked
- AC1: `OpenCloud.isTransient` is true for 429 and 500-599 and false for 4xx other than 429 and for 2xx.
- AC2: A transient failure creating or polling a task is retried and the run completes, including through `runSuite`.
- AC3: Retrying is bounded: exactly `MAX_ATTEMPTS` requests per request, then the same error as before; the budget restarts for each request.
- AC4: Non-transient failures (400, 401, 403, 404, 408, 409) are raised at once, with no retry and no pause.
- AC5: The pause between retries is `transientSeconds`, default 5, and independent of `retrySeconds`.
- AC6: Retry pauses do not shorten the task's `timeoutSeconds`.
- AC7: The API key never appears in an error after retries.
- AC8: `publish` behaves as before (5xx final, 409 waits `retrySeconds`).
- AC9: The tracker skill's `beta` bullets say a transient-red `beta` (`HTTP 429`/`5xx` from `opencloud:`) is rerun with `gh run rerun`.

### Judged
- JC1: the doc paragraph (AC9). Pass: it tells the reader how to recognise a transient red `beta` from its log, the exact rerun command, a bound on reruns, and that other failures are not rerun. Fail: it only says "rerun", or invites unbounded reruns.

### Observed
None.
