# c0530: Run setup.sh whole against stub tools

## Problem
`scripts/setup.sh` ends in the only step that runs the full gate in `check.yml` (`scripts/check.sh --full`), and the tools-only mode (`--tools`) skips it. The specs that guard that path read text (`tests/acceptance/c0140/tools.spec.luau`) or run only a slice of the script: R0160's `setup-tools.spec.luau` cuts out the argument check and the lines from the `--tools` test to the gate call and runs them against a stub gate. Code review 003 of R0160 found what a slice cannot see, with mutants that still pass both specs: wrapping the whole stage in `if [[ -z ${CI:-} ]]; then … fi`; `[[ -n ${CI:-} ]] && exec true` before the stage; `exit 256` (the spec's exit allow-list matches the text `exit 2`, but the shell returns 0); deleting `set -euo pipefail` (the spec supplies that line itself, so a red gate would still end with `SETUP OK` and exit 0); an indented `set +e`. Also, the spec leaves 10 temp directories behind per run (no `rm`, no `trap`), a correct `setup.sh` fails the spec if a comment or message contains the word "exit", and the line numbers in its error messages are about doubled. A change that bypasses the gate in CI would go green without running a single spec.

## Non-goals
- Changing `setup.sh`'s behaviour or the `--tools` interface.
- Replacing main's `c0140/tools.spec.luau` (it can stay as the text-level check).

## Solution
_Draft ideas; design happens in ticket-prep._
- A spec that runs the **whole** of `setup.sh` in a sandbox: a stub `PATH` with fake `rokit`, `rojo`, `lune`, `selene`, `stylua`, `luau-lsp`, `git`/`gh` as needed, and a stub `scripts/check.sh` that records its arguments and exits with a chosen code, run with no argument, `--tools` and a bogus argument, with `CI`, `GITHUB_ACTIONS` and a skip variable set. It asserts: the gate runs with `--full` exactly when `--tools` is absent, a red gate makes `setup.sh` exit non-zero without printing `SETUP OK`, an unknown argument exits 2 before any tool runs.
- Remove the slice-based `setup-tools.spec.luau`'s overlap, or keep it as the cheap structural check and fix its leaks (temp dirs removed with `rm -rf`, the exit allow-list matching the executed value, no false failures on the word "exit" in comments, correct line numbers).
- Needs an experiment: how much of `setup.sh` (the tool downloads, `rokit install`, `lune setup`) can be stubbed without editing it, or whether a tiny seam (an env var for the tools directory) is justified, a design decision for ticket-prep.
