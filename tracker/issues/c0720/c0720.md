# c0720: C0360 cleanup flake

## Problem
`tests/acceptance/c0360/deferred.spec.luau :: cleans up` (`fs.removeDir(work)` on its throwaway clone) failed once with `Directory not empty (os error 66)` in a full gate on R0190's final head (2026-10-03, about 65 s gate under several sessions' load), then passed alone 3/3 and in the next full gate. Something is still writing into the fixture while it is removed (likely a git child or background maintenance from the clone's `done` run), so the gate can go red for nothing under load.

## Non-goals
- Changing `tracker.sh done` or the deferred-finding behaviour the spec pins.

## Solution
- Make the cleanup robust: retry the removal briefly, or stop the fixture's background git work (e.g. `gc.auto=0`, `maintenance.auto=false`, as c0041's fixture does) before removing. A promoted spec, so the fix is this chore's own override.
