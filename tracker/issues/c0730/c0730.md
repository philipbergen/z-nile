# c0730: Ready raft

## Problem
`make-prompt` only renders a prompt and copies it to the clipboard. Nothing on `main` shows that a raft has been handed out until `start` claims it, and even then its directories move to `active/` only on the raft's branch. The prompt itself lives nowhere: lose the clipboard and it is gone. A raft's `check.sh` written with backlog paths stops working once the raft moves (R0200's RC1/RC2, 2026-10-02).

What the user wants: a **ready-raft** step, replacing make-prompt, that
- claims the raft;
- moves it and its members to `active/` on `origin/main`, with every path in their `check.sh` files rewritten to the new location;
- writes the prompt next to the raft as `tracker/rafts/active/<R-id>/prompt.md`, which git ignores.

Re-running it on an active raft regenerates the prompt. `start` then only creates the branch and the draft PR.

## Non-goals
- Undoing a ready (c0740, stop-raft), reading the prompt and entering the worktree (c0750, launch-raft), and the board refresh (c0760).
- Rewriting paths in *other* items' `check.sh` files that name a moved item. Raft checks keep resolving members with `tracker.sh find`.
- Removing the legacy `start` path (a `start` on a backlog raft). The skills stop using it, and the promoted specs keep driving it.
- An offline `ready`. It needs an origin, like `status`.

## Solution
- **Move.** A pure `paths` module rewrites the item paths in a `check.sh`. `publish` learns validated whole-directory moves (`Change.from`). `main.luau` gets `ready`, which checks readiness, publishes the move as one tracker-only commit on `origin/main`, pulls the main checkout and renders the prompt into `prompt.md`.
- **Start and branches.** `start` on a readied raft only branches, makes an empty commit, pushes and opens the draft PR. The "current raft" is found by branch, because `main` now carries readied rafts in `active/`. `done` rewrites `check.sh` paths to `done/`.
- **Skills.** The make-prompt skill becomes ready-raft, and the tracker, ticket-prep and execute-raft skills and the prompt template describe the new lifecycle.

## Design

### `scripts/tracker/paths.luau` (new, pure, no I/O)
```lua
-- Every item path `tracker/<issues|rafts>/[active/|done/]<ID>` in `text` whose ID is a key of `dirs`, and whose kind
-- matches the kind in `dirs[ID]`, becomes `dirs[ID]` (for example "tracker/issues/active/c0010"). A path is an ID
-- only when the character after it is not a letter, digit, `_` or `-` (so `c00100` and `c0010-x` are left alone).
function paths.rewrite(text: string, dirs: { [string]: string }): string
```
- IDs are `[fdc]%d%d%d%d` under `issues` and `R%d%d%d%d` under `rafts`, as in `publish.allowed`.
- `rewrite` changes nothing but the state segments of the listed ids. publish's move validation recomputes it, so the module is shared and the two can't disagree. (Review 001 F6: an earlier `normalize` accepted segment changes for ids that weren't moved, so it was dropped.)

### `scripts/tracker/publish.luau`
- `export type Change = { path: string, content: string, mode: string?, from: string? }`. A change with `from` **moves** `from` to `path`: `from` is deleted from the tree and `path` written.
- `publish.itemPath(path: string): (string?, string?)` returns the ID and the path relative to the item directory, for any file inside an item directory (`tracker/<issues|rafts>/[active/|done/]<ID>/<rel>`). `rel` is one or more segments of `[%w%._%-]+` with no `..`. Anything else returns nil. `publish.allowed` is unchanged: it still governs non-move changes (doc and check.sh only, which c0510's spec pins).
- The build's `paths` now list every `itemPath` file on `origin/main` (still nothing outside item directories), so a builder can find every file of a directory.
- **Move validation** (refused with a reason, nothing pushed):
  1. `from` exists on origin, and both `from` and `path` are `itemPath`s (a `from` that isn't, such as `src/x.luau`, is refused before anything is deleted) with the same ID and the same `rel`, in different directories.
  2. Neither side is under `done/`: published moves are backlog ↔ `active/` only. `done/` moves happen on raft branches.
  3. `path` does not exist on origin.
  4. Content:
     - for `rel == "<ID>.md"`, equal to origin's text modulo the status line (the existing `withoutStatus`);
     - for `rel == "check.sh"`, exactly `paths.rewrite(old, dirs)`, where `dirs` maps every id this publish moves to its target directory;
     - for any other file, byte-equal.

     The carriage-return refusal does not apply to moved files, since they are byte-checked against origin.
  5. Mode: `mode` nil takes the source's mode from `ls-tree`. A given mode must equal it.
  6. **Whole directories**: for every source directory of a move, every origin file under it is the `from` of some change in the same publish.
  7. **No second change at a moved path**: every `path` and every `from` occurs once in the publish. No other change, move or not, writes inside a moved source directory, or at a path another move targets.
  8. The diff-tree check counts both `from` and `path` as wanted, and nothing else may change.
- **Tree building**: a Node can be `remove = true`. `makeTree` drops removed entries, and a subtree left with no entries is dropped from its parent, so the old item directory disappears. Sibling files such as `tracker/rafts/active/.gitkeep` are kept.

### `scripts/tracker/main.luau`
- `inMainCheckout(): boolean` is `rev-parse --show-toplevel == mainRoot()`. `refuseInMainCheckout` uses it.
- `currentRaft(): store.Item?` returns the active raft (in this tree) whose `raftBranch` is the current branch. Uses:
  - `activeRaft()` returns it or fails with `not on an active raft's branch (…)`;
  - `raftIsActiveHere()` becomes `currentRaft() ~= nil`;
  - `new issue --raft R` creates an emergent issue only when `currentRaft()` is `R`; otherwise it fails with a message that names `--raft`, whether publishing or not.
- `moveOnOrigin(ids: { string }, to: store.State, status: string, message: string): publish.Result` builds, from the build's `paths`, one move change for every file of each id's directory:
  - the target directory is `store.dirFor(kind, to, id)`;
  - the document gets `withFront(text, "status", status)`;
  - `check.sh` gets `paths.rewrite(text, dirs)`, where `dirs` maps every id in `ids` to its target directory;
  - every other file is unchanged.

  It returns a string (a refusal) when an id is not on origin.
- `renderPrompt(raft: store.Item): string` is the body of today's `cmd.prompt`. It is unchanged: the template, the inlined skills, the architecture map and the workstream plan.
- `promptPath(raftId: string): string` is `{mainRoot()}/tracker/rafts/active/{raftId}/prompt.md`.
- **`sweepPrompts()`** (review 001 F2). A pull that moves a raft out of `active/` leaves its ignored `prompt.md`, and any untracked file such as a Finder `.DS_Store`, in `tracker/rafts/active/<R>/` (E1). The main checkout would then hold `active/<R>` and `done/<R>`, and `store.find` errors `duplicate id` in `list`, `board`, `metrics` and `new raft`.
  - Run in the main checkout after every pull or fast-forward there: `ready`, `stop` (c0740), `sync` in the main checkout (this issue), and c0760's refresh.
  - For each directory `tracker/rafts/active/<dir>` with no tracked `<dir>/<dir>.md` at `HEAD` (`git ls-files --error-unmatch` fails), it removes everything in it (`git clean -ffdxq -- tracker/rafts/active/<dir>`), and then the directory if it is left empty.
  - A raft that is still readied (its document is tracked) is never touched.
- **`cmd.sync`** in the main checkout runs `sweepPrompts()` after its `pull --ff-only`.
- **`cmd.ready(pos)`**, `ready <R-id|issue-id>`, in this order:
  1. Resolve the target. An issue becomes its `raft:`; an issue with no raft fails with `… has no raft: ticket-prep makes one (--single)`. Anything that isn't a raft fails.
  2. `inMainCheckout()`, or fail with `ready runs in the main checkout`. `publishing()`, or fail with `ready needs an origin remote`. The main checkout is on branch `main` and `git status --porcelain` is empty, or fail naming the problem. Then `git pull --ff-only --quiet`, failing with git's message.
  3. Read the raft on `origin/main` (now identical to `HEAD`):
     - in `active/` with an effective status `active`: a **re-issue**, go to step 5;
     - in the backlog with `prepared`: go to step 4;
     - otherwise fail with `<R> is <status> in <dir> on origin/main: only a prepared raft is readied`.
  4. **Readiness**, every check before any push:
     - the raft and every member are `design: ready`;
     - the raft and every member have a `check.sh` with at least one line matching `^%s*check "` (an issue with none is named);
     - every `depends_on` of a member that isn't a member is in `done/` (named when it isn't).

     Then `moveOnOrigin({raft, members…}, "active", stamp("active"), "tracker: ready <R> <title>")`. Inside the build, every member's effective status on origin must be `prepared` (`statusLib.canMove(st, "active")`), or the build refuses. Then `git pull --ff-only --quiet`. If that fails: `readied on origin/main, but pulling the main checkout failed: …; fix it and run ready again (it regenerates the prompt)`.
  5. Write `promptPath(raft.id)` with `renderPrompt(store.get(raft.id))`. Print `prompt for <R> (<ids>): <n> chars -> <path>`, then the plan's last line (`parallel: …`). On a re-issue print `regenerated` instead of `readied`. **No `pbcopy`** anywhere in the tracker.
- **`cmd.start`**, when the raft is `active` in this tree (readied):
  - `origin/main` must show it in `active/` with an effective status `active` (after a fetch). Otherwise fail with `<R> is not readied on origin/main: run tracker.sh ready <R> in the main checkout`.
  - When not on the raft's branch: `refuseInMainCheckout("start")`, the branch must not exist, then `git switch -c <branch>`.
  - `git commit --allow-empty -m "tracker: start <R> <title>"`, push `-u`, and a draft PR when the origin is on GitHub.
  - No claim, no stamp, no move.

  A raft that is in the backlog takes today's path unchanged (claim, move on the branch). When `origin/main` shows it readied (in `active/`) while this tree still has it in the backlog (a worktree made before `ready`), fail with `<R> is readied on origin/main: run tracker.sh sync first` (review 001 F11). Any other state fails as today.
- **`cmd.done`**: when it moves the members and the raft to `done/`, each moved item's `check.sh` is rewritten with `paths.rewrite`, mapping every moved id to its `done/` directory, and staged with the move.
- **`cmd.status`**: the refusal of `status <id> active` keeps the literal text `only tracker.sh start` (c0510's spec, F8), for example `only tracker.sh start or tracker.sh ready claims active`.
- **USAGE**: `ready <R-id|issue-id>`, which claims the raft, moves it to `active/` on `origin/main` and writes `tracker/rafts/active/<R>/prompt.md`. The `start` line becomes "branch, empty commit, push, draft PR (a readied raft; a backlog raft is claimed and moved)". The `prompt` line moves to c0750. Until c0750 lands, `cmd.prompt` stays (minus `pbcopy`) as `prompt <id> --stdout`.
- `READ_ONLY` is unchanged: `ready` runs the repository guard.

### Scalability
- One publish moves N files, with one `hash-object` per file and one `ls-tree`/`mktree` per changed tree level. A raft with 5 issues and about 40 files takes about 1 s.
- `paths.rewrite` is linear in the text.
- `currentRaft` scans the rafts once.

### Maintainability
- Path knowledge lives in one pure module, which publish's validator and `moveOnOrigin` share, so they can't disagree.
- The readiness rules that were prose in make-prompt are now code with specs.
- The legacy start path is isolated in one branch of `cmd.start`.

### Usability
- One command does what make-prompt and the claim did. It is idempotent on an active raft and safe to re-run after a failed pull.
- Every refusal names the item and the fix.

### Rules and mutants
| rule | spec :: case | mutant it kills | checked |
|---|---|---|---|
| rewrite maps any state form of a listed id to its target dir | paths :: rewrite moves a listed id's paths… | only rewrites the backlog form | reasoned |
| rewrite respects the id boundary and the kind | paths :: rewrite leaves unlisted ids… | no boundary check (`c00100` rewritten) or kind ignored | reasoned |
| rewrite changes only the listed ids' segments | paths :: rewrite changes nothing but… | rewrite also edits the text after the id, or unlisted ids | reasoned |
| a move carries the whole directory | publish-move :: …leaves a file… behind | completeness check missing | reasoned |
| ordinary files are byte-identical | publish-move :: …changes any byte… | only docs and check.sh are compared | reasoned |
| a moved doc changes only its status | publish-move :: a moved document… | a moved doc is not compared | reasoned |
| a moved check.sh is exactly `rewrite(old, the publish's moves)` | publish-move :: a moved check.sh… | check.sh skipped; compared byte-exact; segment changes allowed for unmoved ids | reasoned |
| no published move touches done/ | publish-move :: a move into or out of done/… | only "different directories" checked | reasoned |
| `from` must be an item file | publish-move :: a from outside an item directory… | `itemPath` checked on `path` only (deletes `src/x.luau`) | reasoned |
| one change per moved path | publish-move :: a second change at a moved path… | no uniqueness check (item in two directories, or the target overwritten) | reasoned |
| moved files keep carriage returns | publish-move :: a whole-directory move lands… | the `\r` refusal applied to moves | reasoned |
| same id and rel, the target is new | publish-move :: a move onto an existing path… | only `rel` compared; target existence ignored | reasoned |
| mode kept | publish-move :: …changes a file's mode | mode taken from the change unchecked | reasoned |
| the emptied source dir is gone, siblings kept | publish-move :: a whole-directory move lands… | empty subtree left / `.gitkeep` dropped | reasoned |
| non-move rules unchanged | publish-move :: non-move changes keep… | `allowed` widened to every item file | reasoned |
| ready only in the main checkout, only with an origin | ready :: ready refuses outside… | the check is missing | reasoned |
| ready needs a prepared raft | ready :: …not prepared | the status is not checked (draft readied) | reasoned |
| ready needs a clean main checkout on main | ready :: …dirty main checkout | pull without a clean check | reasoned |
| an outside dependency must be done | ready :: …unfinished dependency… | the depends_on check is dropped | reasoned |
| every member has a check | ready :: …no check | the check-line test is dropped, or it counts commented lines | reasoned |
| an issue id resolves to its raft; raftless refused | ready :: ready resolves an issue… | a placeholder raft is created | reasoned |
| one commit, all files, active stamps | ready :: ready moves the raft… | members not moved, or status not stamped | reasoned |
| check.sh paths rewritten | ready :: ready rewrites… | the move without the rewrite | reasoned |
| the main checkout is pulled; prompt.md is written and ignored | ready :: ready pulls… | the prompt is written before the pull (the file is lost or in the wrong place) | reasoned |
| no clipboard | ready :: ready never calls pbcopy | `pbcopy` kept | reasoned |
| a re-issue regenerates without a commit | ready :: ready on an active raft… | re-publishes (a new commit), or refuses | reasoned |
