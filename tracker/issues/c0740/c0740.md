# c0740: Stop raft

## Problem
Once c0730 lands, readying a raft claims it and moves it to `active/` on `origin/main`, with its prompt next to it. There is no way back. A raft readied by mistake, or one the user wants to pull out of execution (even after it was started), stays claimed and in `active/`. The user wants a **stop-raft** command that:
- removes the prompt;
- moves the raft and its members back out of `active/`;
- publishes that change.

Stopping a started raft also gives the claim back, and leaves its branch and PR alone.

## Non-goals
- Closing the PR, deleting the branch or removing the worktree. The user decided these are left to the human; `stop` names them.
- Emergent issues that exist only on the raft's branch. They aren't on `origin/main`, so `stop` doesn't see them.
- Reverting work committed on the raft branch.

## Solution
`tracker.sh stop <R-id>`, run in the main checkout, reverses c0730's move with the same `moveOnOrigin`: the target is the backlog and the status is `prepared-…`. It deletes `prompt.md` and its now-empty directory, pulls the main checkout, and names the raft's branch if it exists. `status` refuses to move a readied item and points to `stop`. A raft claimed by the legacy `start` (still in the backlog, status `active`) gets its claim back through a status-only publish. A new **stop-raft** skill wraps the command.

## Design

### `cmd.stop(pos)`, `stop <R-id>` (`scripts/tracker/main.luau`)
1. The target must be a raft id. Same guards as `ready`: `inMainCheckout()`, `publishing()`, branch `main`, a clean `git status --porcelain`, then `git pull --ff-only --quiet`.
2. Read the raft on `origin/main`:
   - **Readied** (in `active/`): `moveOnOrigin({raft, members on origin…}, "backlog", stamp("prepared"), "tracker: stop <R> <title>")`. The members are the raft's `issues:` that exist on origin. Every one must be in `active/`; a member in `done/` refuses.
   - **Legacy-claimed** (in the backlog, effective status `active`): one publish that stamps `prepared-…` on the raft and its members (the existing `status` give-back logic, reused), with no move.
   - Otherwise: fail with `<R> is <status> in <dir> on origin/main: only a readied or started raft is stopped`.
3. Delete `promptPath(R)` if present (E1 in c0730: a pull leaves an ignored file behind). Then `git pull --ff-only --quiet`, then c0730's `sweepStale(mainRoot())`, which removes `tracker/rafts/active/<R>` and every member's emptied `active/` directory, along with anything left in them, such as a `.DS_Store`.
   - If the pull fails: `stopped on origin/main, but pulling the main checkout failed: …`, and exit non-zero.
   - Remove `.cache/tracker-claim-<R>` if present.
4. After `git fetch --prune origin`, if `refs/heads/<branch>` or `refs/remotes/origin/<branch>` exists, print `<branch> and its pull request <url> are left as they are: close or keep them yourself`.
   - On a GitHub origin, `<url>` comes from `gh pr list --head <branch> --state open --json url -q '.[0].url'`. Without one, or when `gh` fails, the line says `its pull request, if any`. User decision 2: stop names both.
   - Print `stopped <R> (<ids>)`.

### `cmd.status` refuses readied items
`status <id> <to>`, for any `<to>`, refuses when `id` (or, for a raft, any member) is in `active/` on `origin/main`, with `<id> is readied (in active/): use tracker.sh stop <R>`, naming the raft. This is checked inside the build, against origin, before the transition rules, so `new` and `preparing` get the same message.

### USAGE
`stop <R-id>`: give back a readied or started raft, move it out of `active/` on `origin/main`, and remove its prompt.

### Skills
- **`.claude/skills/stop-raft/SKILL.md`** (new, `name: stop-raft`). The description: undo ready-raft, or abort a started raft. It runs `scripts/tracker.sh sync` and `scripts/tracker.sh stop <R>` in the main checkout.
  - It reports the printed branch line. The human decides whether to close the PR (`gh pr close`) and remove the worktree.
  - It never closes or deletes them itself.
  - It explains that ready-raft can re-ready the raft later. A started raft's old branch then still exists, so `start` refuses until the human deletes or reuses it.
- **Tracker skill**:
  - a `stop` row in the lifecycle table;
  - Worktrees item 1 lists `stop` with `ready` as allowed in the main checkout;
  - Sync and claim: `stop` is the way to give back a readied raft (`status` refuses those), and "Whose claim" applies to `stop` too.
- **AGENTS.md**: a row `.claude/skills/stop-raft/SKILL.md` | "undoing ready-raft or aborting a raft".

### Scalability
The same cost as `ready`: one publish, with one `hash-object` per file.

### Maintainability
- `stop` is `ready`'s move run in reverse, through the same `moveOnOrigin` and `paths.rewrite`. A round trip restores every `check.sh` byte for byte, which the spec pins.
- The legacy give-back reuses `status`'s code.

### Usability
- One command, which names what it leaves behind.
- The `status` refusal points to it.

### Touched modules

- `.claude/skills/tracker/SKILL.md`

### Rules and mutants
| rule | spec :: case | mutant it kills | checked |
|---|---|---|---|
| main checkout only; readied or started only | stop :: stop refuses… | the guards are missing | reasoned |
| move back to the backlog, stamped prepared, in one commit | stop :: stop moves… | stamps `new`, or leaves members in active/ | reasoned |
| check.sh paths are rewritten back (round trip is exact) | stop :: a ready and stop round trip… | the move without the rewrite | reasoned |
| prompt.md and the empty dir are removed; main is pulled | stop :: stop removes prompt.md… | the pull without the delete (the stale dir stays, E1) | reasoned |
| branch and PR are left, and named | stop :: stop of a started raft… | deletes the remote branch, or says nothing | reasoned |
| re-readiable | stop :: a stopped raft can be readied again | stamps something `ready` refuses | reasoned |
| status refuses readied items, for every target | stop :: status refuses… | only `prepared` refused | reasoned |
| a member in done/ blocks stop | stop :: stop refuses a raft with a member… | the done member moved back (or skipped) | reasoned |
| the PR is named on GitHub | (no GitHub in fixtures) | the PR line missing | reasoned: the reviewer checks the code |
| a legacy claim is given back without a move | stop :: stop gives back… | a refusal, or a move of backlog dirs | reasoned |

## Acceptance criteria

### Checked
- AC1: `stop` refuses outside the main checkout, for a raft that is neither readied nor started, and for a readied raft with a member in `done/`, and pushes nothing.
- AC2: `stop` publishes one commit that moves a readied raft and its members back to the backlog, stamped `prepared-…`. A ready-then-stop round trip leaves every file except the documents' `status:` line byte-identical to before.
- AC3: after `stop`, `prompt.md` and `tracker/rafts/active/<R>` are gone, and the main checkout is clean and at `origin/main`.
- AC4: stopping a started raft leaves its branch on origin and prints its name. The stopped raft can be readied again.
- AC5: `status <id> <to>` refuses an item in `active/` on `origin/main`, for every `<to>`, and names `tracker.sh stop`.
- AC6: `stop` gives back a legacy-started raft (backlog, `active`) as `prepared`, without moving it.
- AC7: the stop-raft skill exists (`name: stop-raft`), runs `tracker.sh stop` in the main checkout, and says the branch and PR are left to the human. The tracker skill and AGENTS.md list it.
