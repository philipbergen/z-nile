# c0780: Capture lands without a pull request

## Problem
Capturing an issue (the make-issue skill) ends today with the full "Landing a change" procedure: push a branch, open a PR, wait for CI (`gate` and `beta`), merge, pull, and remove the worktree. A capture changes only tracker documents (the issue's Problem, Non-goals and Solution ideas), yet each one costs a PR and several minutes of CI, plus a Beta publish (PR #52 and #53 on 2026-10-03). The user, 2026-10-03: "I don't think PR is required, just run CI locally and push to main."

What should happen: a capture runs the gate locally (`scripts/check.sh --full`) in its capture worktree, then pushes its commit to `main` directly, retrying on a race, and removes the worktree. No PR, and no waiting for GitHub CI.

## Non-goals
- Prep (ticket-prep) PRs, raft PRs, and skill or doc edits keep landing by PR, unless the user widens this later.
- Changing CI itself.

## Solution
A `tracker.sh land` command does the mechanics of landing a capture:
- it merges `origin/main`;
- it runs the gate locally;
- it checks that the capture changes only issue documents;
- it pushes one commit, made on top of `origin/main`, straight to `main`, retrying a lost race;
- it refreshes the main checkout and its board (c0760).

make-issue step 6 runs it. The tracker skill names it as the one exception to "every change lands by PR".

## Design
### `cmd.land(pos, opts)`, `land [-m <message>]` (`scripts/tracker/main.luau`)
1. **Where.** The current branch must start with `capture-` (a make-issue worktree), and the tree must be clean. Otherwise fail with `land is for capture worktrees (capture-<slug>)` or `commit everything first`. It needs `publishing()`.
2. **Sync.** `git fetch origin main`, then `git merge --no-edit origin/main`. A conflict aborts the merge and fails, telling you to resolve and run land again.
3. **Scope.** `git diff --name-only origin/main HEAD` must be non-empty, and every path must be `tracker/issues/<ID>/<ID>.md` or `tracker/issues/<ID>/check.sh` of an issue in the backlog (not `active/` or `done/`). Anything else is refused, naming the path, with nothing pushed. A capture's other work goes through a PR.
4. **Gate.** Run `scripts/check.sh --full` in this worktree, unless `PICKMAN_LAND_GATE` names another command; specs set it to `true` or `false`. A failing gate stops land, and nothing is pushed.
5. **One commit on top of `origin/main`.**
   - `git commit-tree HEAD^{tree} -p origin/main -m <message>`. The message is `-m`, or the subject of the first capture commit (`git log --reverse --format=%s origin/main..HEAD | head -1`), plus the body lines of all of them.
   - `git push origin <sha>:refs/heads/main`, with no force: it is a fast-forward of the `origin/main` that was just fetched.
   - On a rejected push, go back to step 2 (sync and gate again), up to 3 tries.
   - After success, `git reset --hard <sha>`, so the capture branch equals `main`.
6. **After.** The board refresh from c0760 runs (via `published` or `refreshBoard()` directly), which fast-forwards the main checkout. Then print `landed <sha> on main; remove this worktree: git -C <root> worktree remove <path> && git -C <root> branch -D <branch>`.

`land` is not in `READ_ONLY`.

## Acceptance criteria

### Checked
- AC1: `tracker.sh land` in a capture worktree pushes one commit to `main` whose parent is the previous `origin/main` tip and whose tree holds the capture's edits. It merges others' pushes first, retries a lost race, leaves the branch equal to `main`, and fast-forwards the main checkout.
- AC2: it refuses any change outside backlog issue documents (`<ID>.md`, `check.sh`), and pushes nothing.
- AC3: it refuses when the gate command fails, and pushes nothing.
- AC4: it refuses outside a `capture-` branch, on a dirty tree, and with nothing to land.
- AC5: make-issue step 6 runs `tracker.sh land` (no PR), and the tracker skill names `land` in Landing a change and in the direct-push exception.
