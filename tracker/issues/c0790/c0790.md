# c0790: Board statistics and graphs

## Problem
The tracker board (`tracker.sh board`, `.cache/board.html`) lists rafts and issues by state, but shows no numbers about the work. The user (2026-10-03) wants it to render statistics.

**Periods and chunking.** Three views:
- the last month, day by day;
- the last quarter, week by week;
- the last year, month by month.

Bucket edges round down: a week starts on the Monday on or before the date, a month on the 1st, a quarter on Jan 1, Apr 1, Jul 1 or Oct 1, and a year on Jan 1. The views also cover weeks, months, quarters and years as periods.

**Per bucket, for all issues and per type (feature, defect, chore):**
- issues opened, issues closed, and net (opened minus closed);
- time spent;
- lines of code added, removed and net.

**Ratios**, as percentages:
- defects / (defects + features), by number of issues and by time spent;
- chores / (chores + defects + features), by number of issues and by time spent.

**Time in each state** (new, preparing, prepared, active, until done), across all issues and per type.

**As graphs** (the user, 2026-10-05: "a single issue raft that puts the graphs in the board"). The statistics are drawn as charts on the board, with the numbers still available as a table view. This issue left R0250 for its own raft, R0271, to do that.

## Non-goals
- Charts beyond what the board's single self-contained page can carry. The page stays one HTML file with vendored assets only.
- Changing how spend is recorded. The statistics read what `spend.md` and git already hold.
- CI's `tracker-board` artifact layout.

## Solution
A pure statistics module computes every number from three inputs:
- items: id, type, opened day, closed day, and state spells;
- spend rows: issue, type, day, lines and minutes;
- "today".

A history adapter reads the state spells and close days from `git log` of `main`, the only place status moves are recorded. The board model embeds the result. A pure chart module draws it as inline SVG at build time, and the page shows the charts in a Stats section opened by a button outside the three tabs, so the tab cycle is unchanged. The numbers stay available behind a Table toggle. CI's board workflow fetches full history.

## Design
**Definitions** (prep decisions; the user's spec leaves the window starts open, see Usability):
- **Day**: the `YYYY-MM-DD` of a timestamp as written (its own offset). `created:` is already a day.
- **Rounding down**: a week starts on the Monday on or before; a month on the 1st; a quarter on Jan 1, Apr 1, Jul 1 or Oct 1; a year on Jan 1.
- **Views** (buckets, oldest first; each bucket is `[start, stop)`):
  - **month**: one bucket per day, from the same day one month back (clamped to the month's length; 2026-03-31 goes back to 2026-02-28) through today;
  - **quarter**: one bucket per week, from the Monday on or before (today − 3 months, clamped to that month's length like the month view: 2026-05-31 goes back to 2026-02-28) through the week containing today;
  - **year**: one bucket per month, from the 1st of the month containing (today − 12 months) through the current month.
- **Periods** (calendar-aligned, to date): this week, this month, this quarter and this year: from the rounded-down start through today.
- **Today** (one definition, review 006 F10): with history, the day of the last commit in `history.parse`'s log, the last commit on `HEAD` that touches a tracker item document. Without history, or with history but no commit touching an item document, the latest date in the data (`created:`, spend rows). With neither, `""`: then the views are empty lists, `periods` is nil, `durations` is an empty table, and the page says `no dated data` (review 007 F4). It is never the wall clock, so a build is deterministic for a tree (c0400's and c0760's equality checks rely on that). Issues without a valid `created:` are left out of "opened".
- **Per bucket and period**, for `all`, `feature`, `defect` and `chore`:
  - opened: issues whose `created:` falls inside;
  - closed: issues whose move into `done/` falls inside;
  - net: opened − closed;
  - minutes: the sum of the spend rows inside;
  - lines: added, removed and net (added − removed) from the spend rows inside.
- **Ratios** (percent, one decimal, nil when the denominator is 0):
  - defectCount = defects closed / (defects + features closed);
  - defectTime = defect minutes / (defect + feature minutes);
  - choreCount = chores closed / all closed;
  - choreTime = chore minutes / all minutes.
- **Time in state**: for each issue and each state in `new`, `preparing`, `prepared` and `active`, a spell runs from entering the state to entering the next (or `done`). Only spells with both ends known count. The output is n, the mean and the median in days (two decimals), for all issues and per type.

**`scripts/tracker/stats.luau`** (new, pure, no I/O):
```lua
export type Kind = "feature" | "defect" | "chore"
export type Spell = { state: string, from: string, to: string? }  -- ISO timestamps
export type Item = { id: string, type: Kind, opened: string, closed: string?, spells: { Spell } }
export type Spend = { id: string, type: Kind, day: string, added: number, removed: number, minutes: number }
export type Bucket = { start: string, stop: string, label: string }  -- stop exclusive
export type Counts = { all: number, feature: number, defect: number, chore: number }
export type Row = { bucket: Bucket, opened: Counts, closed: Counts, net: Counts, minutes: Counts,
  added: Counts, removed: Counts, netLines: Counts, ratios: Ratios }
export type Ratios = { defectCount: number?, defectTime: number?, choreCount: number?, choreTime: number? }
export type Spread = { n: number, mean: number?, median: number? }
export type Stats = { today: string, history: boolean, views: { month: { Row }, quarter: { Row }, year: { Row } },
  periods: { week: Row, month: Row, quarter: Row, year: Row }?,  -- nil when there is no today
  durations: { [string]: { all: Spread, feature: Spread, defect: Spread, chore: Spread } } }
function stats.floor(day: string, unit: "week" | "month" | "quarter" | "year"): string
function stats.buckets(view: "month" | "quarter" | "year", today: string): { Bucket }
function stats.periods(today: string): { week: Bucket, month: Bucket, quarter: Bucket, year: Bucket }
function stats.row(items: { Item }, spends: { Spend }, b: Bucket): Row
function stats.durations(items: { Item }): { [string]: { all: Spread, feature: Spread, defect: Spread, chore: Spread } }
function stats.compute(items: { Item }, spends: { Spend }, today: string, history: boolean): Stats
```
Dates are handled as integers (days since the epoch, computed from the civil date) and seconds (an ISO timestamp with its offset), never with `os.date`/`os.time`, which depend on the local zone.

**`scripts/tracker/history.luau`** (new):
- `history.LOG_ARGS: { string }` = `{ "log", "--reverse", "--format=@@C %cI", "-p", "--unified=0", "--no-renames", "--", ":(glob)tracker/issues/**/[fdc][0-9][0-9][0-9][0-9]*.md", ":(glob)tracker/rafts/**/R[0-9][0-9][0-9][0-9]*.md" }`, the log of `HEAD` limited to item documents (legacy `<ID>-<slug>.md` names included), not every file under `tracker/` (review 006 F9).
- `history.parse(log: string): { closed: { [string]: string }, spells: { [string]: { Spell } }, today: string? }` (pure):
  - a `+status: <state>…` line in an issue's `<ID>.md` whose state differs from the item's current one starts a spell of that state at the commit's time;
  - a **move** (with `--no-renames`, the commit deletes the document in one directory and adds it in another, so the whole file, old status line included, shows as added). For a move, the directory decides when the status value is unchanged: into `active/` starts `active` (a legacy start). A move whose status value changed (`ready`, `stop`) starts a spell of the new status;
  - **close day** (review 006 F6): the first commit that adds a document of the item (`<ID>.md` or a legacy `<ID>-<slug>.md`) under `tracker/issues/done/<ID>/`, whatever was deleted with it. That covers moves, emergent issues added straight into `done/` by a squash, and legacy names. Later adds inside `done/` (a migration's rename) don't move it. The same commit ends the open spell. An item whose first appearance is already in `done/` (an emergent issue merged by squash) gets a close day and no spell (review 007 F3);
  - `today` is the last commit's day.
- `history.read(root: string?)` returns `nil` (no history) when there is no git, when `root` is not the top of its own repository (`git rev-parse --show-toplevel`, compared physically, so a tree under another repository never reads that repository's history), or when `git rev-parse --is-shallow-repository` says true. Otherwise it runs `git` with `LOG_ARGS` in `root` and parses the output. About 0.13 s on today's tracker (E1).


**`scripts/tracker/chart.luau`** (new, pure; follows the dataviz method: form first, color by job, a validated palette, thin marks, one axis, a legend for 2 or more series, a table view):
```lua
export type Series = { key: string, label: string, values: { number? } }  -- key: a role (feature, defect, chore, net, count, time)
export type Options = { id: string, title: string, unit: string, labels: { string },
  kind: "bars" | "stacked" | "mirror" | "lines" | "hbars", below: { Series }? }  -- below: mirror's series under the baseline
function chart.svg(series: { Series }, opts: Options): string
```
- **Root**: `<svg class="chart" data-chart="<id>" role="img" aria-label="<title>" viewBox=…>`, with `<title>` = the title. Fixed sizes: about 640×200 for bucket charts and 640×(40 + 28 per row) for `hbars`.
- **Marks** (one rect per non-zero value, none for 0 or nil):
  - `<rect class="mark s-<key>">` with `<title><label>, <bucket label>: <value> <unit></title>` (the hover tooltip);
  - 4 px rounded data ends, anchored to the baseline;
  - a 2 px gap between stacked segments and between adjacent bars.
- **Kinds**:
  - `bars`: one series; negative values drop below the baseline (net);
  - `stacked`: the series stack upward per bucket, in series order;
  - `mirror`: `series` stack above the baseline and `below` stacks under it (lines added and removed);
  - `lines`: 2 px paths, where a nil value breaks the path (a new `M`), plus a ≥8 px marker per point (ratios 0–100 %);
  - `hbars`: horizontal grouped bars per label (time in state, with categories = states).
- **Axis**: one y scale, never two. Ticks are nice numbers (1, 2 or 5 × 10ⁿ), the top tick is at least the largest (stacked) total, and a bottom tick sits below 0 when anything is negative. Grid lines are recessive, and `<line class="baseline">` is drawn at 0. Y tick labels are `<text class="tick">N</text>`.
- **X labels**: at most 8, evenly thinned (the month view has 32 buckets), as the day, `W<iso week>` or `Mon YY`.
- **Legend**: `<g class="legend">` with one swatch and label per series when there are 2 or more; none for a single series (the title names it).
- **Color**: never inline. Marks carry `s-<key>`. The page's CSS maps `--series-feature`, `--series-defect` and `--series-chore` to the reference palette slots 1–3 (light `#2a78d6`, `#eb6834`, `#1baf7a`; dark `#3987e5`, `#d95926`, `#199e70`), plus a neutral `--series-net` and the ratio lines' `--series-count`/`--series-time` (slots 7 and 6). Both modes were validated in prep (E3). Text uses the text colors, never a series color. A type's color stays the same under every filter.
- **Empty**: all values nil or zero, or no labels, gives the axis frame and `<text class="empty">no data</text>`.
- **Deterministic**: the same input gives the same bytes, with numbers formatted to at most 1 decimal.
- **Markup shape** (the spec reads it): `class` is each element's first attribute. A mark is `<rect class="mark s-<key>" …><title>…</title></rect>`, a line `<path class="line s-<key>" … d="…">`, the zero line `<line class="baseline" … y1="…">`, and a tick label `<text class="tick" …>N</text>`.

**Charts on the page** (`data-chart` ids):
- For each view `v` in month, quarter and year, and each type filter `t` in all, feature, defect and chore:
  - `v/t/opened`, `v/t/closed` and `v/t/minutes`: `stacked`, with the three types as series for `all` and only `t` otherwise;
  - `v/t/net`: `bars`, net issues (key `net`);
  - `v/t/lines`: `mirror`, added above and removed below, per type.
- `v/ratios-count` and `v/ratios-time`: `lines`, defect % and chore % (keys `count` and `time` per measure, as in Definitions).
- `durations`: `hbars` of the mean days per state, with the types as series and `n` in each tooltip.

That makes 3 × 4 × 5 + 3 × 2 + 1 = 67 SVGs, all built in Lune.
- The view switch and the type filter show and hide them. The page script only toggles `hidden`, guarding every element as before.
- A **Table** toggle shows the numbers (the tables designed above) as the accessible view.
- No external script or CDN. The page stays one self-contained file.

**Board** (`scripts/tracker/board.luau`, `board.html`):
- `board.collect(root)` keeps its contract: `root` is the tracker directory (default `"tracker"`, which c0400's specs pin). History is read from its parent, `history.read(<root>/..)`, so the default gives `"."`; a tracker directory whose parent is not the top of its own repository has no history (review 006 F1).
- `board.collect` adds `stats: stats.Stats` to the Model:
  - items come from every issue (type, `created:`) plus history's close days and spells;
  - spend comes from every issue's `spend.md` rows (`| # | when | commit | +lines | -lines | minutes | attribution |`, where `when` gives the day);
  - `history = false` when `history.read` is nil, and then `closed` and the durations are empty.
- The page gets `<button id="stats-toggle">Stats</button>` outside `<nav>`, and `<section id="stats" hidden>`.
  - The Stats section has a view switch (Month, Quarter, Year) and a type filter (All, Feature, Defect, Chore) in one row above the charts, then the charts above. It also has a Table toggle that shows one table per view (rows = buckets; columns = opened, closed, net, minutes, +lines, −lines, net lines), the four period summaries with the ratios, and the time-in-state table.
  - Without history it shows `history unavailable (shallow or no git): closed and time in state are omitted`.
  - The script guards every new element (`if (!el) return`), so c0400's smoke harness, which provides only the old elements, still runs. The tabs, keys and search are unchanged.
- **CI**: `.github/workflows/board.yml`'s checkout gets `with: { fetch-depth: 0 }`, so the artifact has history.

### Scalability
- `git log` over the tracker takes about 0.13 s today and grows with history. The stats are linear in items × buckets: about 400 issues × 58 buckets is trivial.
- The page carries the precomputed rows, a few tens of KB.

### Maintainability
- Pure numbers in `stats.luau`, with unit specs on every edge (rounding, clamping, empty buckets, zero denominators, open spells).
- Git parsing is pure (`history.parse`) and fed by one command.
- The page only renders.

### Usability
- One button opens the Stats section; the three tab views stay as they are.
- The window interpretation (a month back by day, a quarter back by week from the Monday before, a year back by month from the 1st), plus calendar periods to date, is a prep decision. It is recorded here for the user to adjust.
