# c0810: Fixture helper misses shell commands that leave the fixture

## Problem
`@tests/lib/fixture` checks where a command starts, not what it does (R0210 review 001 F4, fixed in part). A shell command run through `fixture.exec` (`sh -c 'cd <elsewhere> && git …'`) starts in a proven fixture and can then run git anywhere. On macOS the jail still stops writes outside `.cache`, but on Linux (no jail) only review catches it. `retrofit.spec` bans raw shell strings, but not shell strings passed through the helper.

## Non-goals
- Changing the runner's guards (R0210).
- Specs outside the twelve the retrofit scan covers, which have their own rules.

## Solution
- Extend `retrofit.spec`'s scan to shell strings passed to `fixture.exec`: flag `cd`, `-C`, `--git-dir` and `GIT_DIR` inside them.
- Or forbid `sh -c`/`bash -c` through the helper and require script files with fixed content.
- Or have the helper run shell commands with `cd` disabled (`set -o restricted`-like), if a portable way exists.
