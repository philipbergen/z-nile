# c0830: Symlink swap into the top of .cache

## Problem
Inside the jail a spec can still atomically swap a symlink into the top of `.cache` (R0210 review 006 F1). The jail forbids making or renaming a link there, but not a swap with an existing file. The writers in `scripts/` now write elsewhere and rename into place, so a link is replaced rather than followed. Writers in sequestered `check.sh` files, and any new writer, are not covered, and nothing enforces the rename pattern.

## Non-goals
- The writers already fixed in R0210 (`sh.writeReplacing`, `check.sh`'s rojo and globalTypes, `deploy-beta`, the sentinel).

## Solution
- Find an SBPL rule that also denies the swap (`file-write-*` variants for `renamex_np`/`RENAME_SWAP`), with a gate probe.
- A gate scan that flags any direct write to a top-level `.cache` path outside `sh.writeReplacing`.
- Fix the writers in sequestered `check.sh` files through their owning issues, with approval.
