# c0840: Fix and re-review R0210's unreviewed fixes

## Problem
R0210's round-6 fixes and its post-`done` fix were merged without any review, because the user chose to land after round 6:
- writers renaming into place (`sh.writeReplacing`, `check.sh`'s `build_place` and globalTypes download, `deploy-beta`, the sentinel);
- the post-run unlink of top-level `.cache` symlinks and the outer-sandbox symlink probe;
- the watchdog in the runner's `REAPER` launcher;
- the escape-pattern change in `profile`;
- the gate spec spelling the `gh-none` path in two parts.

Every earlier round found new problems in the previous round's fixes, so these are likely to have some too.

**The review has been done** (2026-10-04, a clean Opus subagent; full text in `review-of-round6-fixes.md` beside this document). Verdict: changes. Its findings are this chore's work:
- **F1 [high]**: a symlink to a *directory* at the top of `.cache` is still written through. `mv -f` (in `sh.writeReplacing`, `check.sh`'s `build_place` and its definitions download) moves the new file *into* the linked folder; a file dropped into `.git/refs/heads` that way breaks every git command's ref listing. The post-run unlink runs in the top Lune process, which a Ctrl-C or a TERM sent only to it skips, and the jail lets a spec signal it. Fix: write a hidden temp file next to the target and rename it in without following a link (failing on a directory); unlink in the Perl launcher and at the top of `check.sh` too; spec cases for a link to a directory and a real directory at the path.
- **F2 [medium]**: if the watchdog's `fork` fails, `if (!fork)` is true for `undef` too, so the specs' process loops as the watchdog and never runs: the run hangs, holding the lock.
- **F3 [medium]**: the outer-sandbox link probe counts any `ln` failure as "refused" and uses a predictable name, so a regular file left there makes a permissive sandbox pass. Check for `Operation not permitted`, and use a random name.
- **F4 [low]**: `check.sh` goes on silently when the definitions download fails (a failure inside the `&&` list escapes `set -e`), and leaves its temp file and build folder behind.
- **F5 [low]**: the testing skill describes none of the round-5 and round-6 changes.

No findings on the escape pattern, the sentinel write, `deploy-beta.luau`, the watchdog's stdio, ordering and exit codes, or the `gh-none` split. Not reproduced: a jailed spec stopping the runner's top process (inferred from the profile, not run).

## Non-goals
- New hardening beyond what these fixes claim (c0810, c0820, c0830).

## Solution
- Fix F1–F5 as the review recommends, each with a spec case or a mutant, and a consequence check per fix (c0860).
- Then a fresh review of the fixes.
