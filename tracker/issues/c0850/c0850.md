# c0850: Spec for the run watchdog

## Problem
When a run's launcher is killed (for example a SIGKILL to the run's whole process group), a watchdog in the specs' process group stops the specs (R0210 review 006 F2). No spec covers it; it was seen working once, by accident, during a by-hand check that also killed its own shell. A regression would leave hung specs holding the lock until someone kills them by hand.

## Non-goals
- The reaping at the end of a normal run, which `fence-leftovers.spec` covers.

## Solution
- A tooling spec that starts a copied runner in a fixture, with a probe spec that sleeps, then SIGKILLs only the launcher (not the spec's own shell or group) and requires the probe to be gone within a few seconds and the lock to be taken over by the next run.
- Kill only pids the spec started; never a process group it shares.
