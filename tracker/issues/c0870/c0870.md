# c0870: Compact ids and allocate them from a next-number file

## Problem
Ids step by ten (`tracker.sh new` picks the next multiple of 10), so the four-digit space fills ten times faster than needed, and old gaps are never reused. Allocation today scans the local tree and `origin/main` and publishes a stub by lease push (c0510).

The user's design (2026-10-04, their words, sharpened):
- **Compaction**: a command that renumbers every item, starting from 0001 (issues `f`/`d`/`c`, and rafts `R`), to open up the address space. Every reference is rewritten, as `renumber` does today.
- **Count by one**, not by ten.
- **A next-number file**: a single-line file in the tracker with two entries, `<next number> <random word>`. The random word makes two terminals' writes of the same number differ, so they collide in git instead of merging silently.
- **Allocation**: push `N+1` with a new random word to `main`. If that push collides, someone else took `N+1`: revert your change, pull the new `main`, and repeat until there's no conflict.

## Non-goals
- Changing the id format (a letter plus four digits).
- The duplicate-id audit itself: c0880.

## Solution
- Open for prep: whether `f`, `d` and `c` keep sharing one number space (as today) with rafts on their own, giving two next-number lines or files, or every prefix gets its own counter.
- Reuse c0510's publisher: the next-number file is a tracker-only change pushed with a lease, and a lost race is exactly a rejected lease push, so "revert, pull, retry" is its existing retry loop.
- Compaction is a one-off, done in its own commit on a quiet `main` (no open prep or raft branches), or it renumbers their items too; prep decides how in-flight branches are handled.
- `renumber`, the Conflicts rule and the tracker skill's Numbering text change with it.
