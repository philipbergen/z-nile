# c0057: Board opens by default

## Problem
A developer running `scripts/tracker.sh board` almost always wants to look at the page, but today it only writes `.cache/board.html` and prints the path; the browser opens only with `--open`. `board` should open the page in the default browser by default, and `-O` should suppress that (write and print the path only).

## Non-goals
- Changing the board's content, layout or output path.
- Choosing a browser other than the system default.

## Solution
`board` keeps writing the page and printing its absolute path exactly as today; then it runs the existing opener (`open` on macOS, `xdg-open` elsewhere) on that path **unless `-O` is given**. `-O` is a boolean flag (it takes no value). `--open`, the old opt-in, stays accepted because it now means the default (old scripts and muscle memory keep working); `--open` together with `-O` is a contradiction and is refused before anything is written. CI's `board.yml` passes `-O`, and every spec that runs `board` passes `-O` or puts stub openers first on `PATH`. So that no spec can ever start a real browser, the spec runner `tests/run` itself puts recording `open`/`xdg-open` stubs first on `PATH` for the whole run and fails the run if any was called (design review 001 F1; the user chose the runner as the place, 2026-10-01).

## Design
**`scripts/tracker/main.luau`** (prototype of every change in `experiments/prototype.patch`):
- `flags()`: `-O` joins the boolean flags (`--single`, `--stdout`, `--include-active`, `--open`), so `opts["-O"] = { "true" }` and the next argument is never consumed. Today `-O` would take the next word as its value, which is why the overridden specs put `-O` last (see Regression guard).
- `cmd.board(pos, opts)`, in this order:
  1. the existing argument check (no positional, `--out` not empty and not starting with `-`); its usage text becomes `usage: board [--out PATH] [-O]  (an --out path can't start with -; write ./-x for such a file)`;
  2. **new**: if both `opts["--open"]` and `opts["-O"]`, `fail(...)` with a message naming `-O` and `--open`, before any directory or file is written;
  3. write the page, absolutize a relative path, `print(out)` (unchanged);
  4. `if not opts["-O"] then` run the opener on the absolute `out` (unchanged body: `pcall(sh.run, opener, { out })`; a failure or non-zero exit writes `warning: could not open … ; the page is written` to stderr and the command still exits 0).
- `USAGE`: the board line becomes `board [--out PATH] [-O]` with the description `write the tracker as one HTML page (default .cache/board.html)` and a continuation line `and open it in the browser; -O only writes it`.

**`.github/workflows/board.yml`**: the build step becomes exactly `run: scripts/tracker.sh board --out dist/board.html -O` (trailing, matching the loosened c0048 spec). Nothing else in the workflow changes.

**`.claude/skills/tracker/SKILL.md`**: the `board` row's command column becomes `` `tracker.sh board [--out PATH] [-O]` ``, and the sentence `` `--open` opens it in the browser. `` becomes: `` Then it opens the page in the default browser unless `-O` is given (`-O` only writes it, as CI and the specs do; `--open`, the old opt-in, is still accepted and is the default). `` The row keeps every token `tests/acceptance/c0048/board-docs.spec.luau` pins (`board.yml`, `tracker-board`, `gh run download`, `rm -rf .cache/board-ci`, `-D .cache/board-ci`).

**`tests/tooling/board.spec.luau`** (not promoted, so the executor edits it): the case `board prints the absolute path of a relative --out` gets a trailing `-O`. Its two `--open` cases already stub the openers on `PATH`, and its refusal cases fail before the opener runs, so they stay as they are. The RC1 guard found exactly this one case in the prototype.

**`tests/run.luau`: the browser guard** (new block right after the `AC_LIST` refusal, before `USAGE`):
- If `PICKMAN_OPEN_GUARD` is unset, empty, or names a directory without an `open` stub (a stale or stray value: design review 003 F3), this is the outermost runner: `mktemp -d` a directory, write two stubs `open` and `xdg-open` there (`#!/bin/sh` + `echo "<name> $*" >> "<dir>/opened.log"`, exit 0), then run itself again, `lune run tests/run -- <the same arguments minus "--">`, with `env = { PATH = "<dir>:" .. PATH, PICKMAN_OPEN_GUARD = <dir> }` and stdout/stderr forwarded. Afterwards read `<dir>/opened.log` (empty if absent), remove the directory, and if the log is non-empty print `FAIL a spec started a browser (tracker.sh board without -O, or an unstubbed opener):` and the log, and exit 1; otherwise exit with the child's code.
- If `PICKMAN_OPEN_GUARD` names a live guard directory (the re-run child, its workers, and any runner a spec starts), the runner behaves exactly as today. Every opener call in the whole run therefore lands in the one log.
- Why a re-run: assigning `process.env.PATH` in Lune does not reach child processes (checked in prep, E6), and specs in the in-process mode inherit the runner's own environment, so the stubbed `PATH` has to be the runner's from the start.
- A spec that tests opening (the tooling spec's `--open` cases, `open.spec.luau`) prepends its own stub directory, so its calls never reach the guard's stubs.
- Exit codes and output are unchanged for every run that starts no opener (the summary line is the child's).

**`.claude/skills/testing/SKILL.md`**: a new "Good specs" bullet after **Hard to fake**: `` - **No browsers.** `tests/run` puts recording `open` and `xdg-open` stubs first on `PATH` for the whole run (workers and nested runners included, through `PICKMAN_OPEN_GUARD`) and fails the run if any is called. Run `tracker.sh board` with `-O`; a spec that tests opening puts its own stubs first on `PATH`. A spec that sets `PATH` for a child prepends to it, never replaces it, or the guard's stubs are lost. ``

No `src/` change, no new module, no `tracker/architecture.md` change (no dependency edge).

### Scalability
Unchanged cost for `board`: one page write and, by default, one opener process. The runner guard adds one `mktemp`, two small file writes and one extra `lune` process per `tests/run` invocation (the outermost only): the full gate measured 21.1 s with it and 20.4 s without on the prototype, within noise. Its stubs cost nothing unless called (macOS scans a new executable only when it first runs).

### Maintainability
One flag added to the shared boolean list in `flags()`; the opener code path is the existing one, just with the condition inverted. The rule that no spec starts a browser is enforced permanently by the runner for every way specs are run (the gate, the stop hook's `--affected` run, `tracker.sh check` through `ac.sh`, a direct `lune run tests/run`), rather than by a text scan that a future spec could slip past; the guard lives in one block of `tests/run.luau` and is pinned by `guard.spec.luau`. A future command that wants a `-O` with a value would collide with the global boolean: noted, not expected.

### Usability
Developer-facing: `scripts/tracker.sh board` now shows the board at once, which is what it is run for. `-O` (capital, "no Open") is for scripts, CI and specs. A failing opener (no desktop, an SSH session) only warns, so the command still succeeds and prints the path. The contradiction `--open -O` is refused loudly instead of one silently winning.

## Acceptance criteria

### Checked
- AC1: `tracker.sh board --out P` writes P, prints its absolute path, and runs the opener exactly once with that absolute path.
- AC2: with `-O` (before or after `--out`) the page is written and its path printed, and no opener runs; `-O` takes no value (`-O x` leaves `x` a refused positional argument).
- AC3: `--open` is still accepted and opens; `--open` with `-O`, in either order, exits non-zero, names `-O` on stderr, writes nothing and opens nothing.
- AC4: an opener that fails makes `board` warn on stderr (`warning:`), still write the page, print only the path on stdout, and exit 0.
- AC5: the usage text contains `board [--out PATH] [-O]`, and the tracker skill's `board` row contains `` `tracker.sh board [--out PATH] [-O]` `` and ``unless `-O` ``.
- AC6: `.github/workflows/board.yml`'s build step is `scripts/tracker.sh board --out dist/board.html -O`.
- AC7: the overridden promoted specs (`c0042/cli`, `c0048/board-workflow`), `c0048/board-docs` and `tests/tooling/board.spec.luau` pass.
- AC8: `tests/run` fails any run (in-process or with workers) in which a spec called `open` or `xdg-open` without its own stubs first on `PATH`, naming each call. A run that calls none keeps its summary line, its stderr and its exact exit code (0 clean, 1 for a failing spec, 2 for a bad `--jobs` or `PICKMAN_JOBS`). Its temp directory is removed, also when the guard fails the run, and a stale `PICKMAN_OPEN_GUARD` (no live guard there) does not switch it off.
- AC9: the testing skill has the **No browsers** bullet naming `tests/run`, `-O` and `PICKMAN_OPEN_GUARD`.

## Implementation steps
The order keeps every gate run in between (the stop hook runs one after each turn) from opening a real browser: the guard and the tooling spec's `-O` come before `board` opens by default.
1. `tests/run.luau`: the guard block as in Design. Run `guard.spec.luau`: 8/9 pass; the `tracker.sh board without -O` case still fails until step 4, because `board` doesn't open by default yet.
2. `tests/tooling/board.spec.luau`: trailing `-O` on `board prints the absolute path of a relative --out`, and its header comment's "the `--open` flag" becomes "opening (the default, `--open` and `-O`)". (`-O` is still a valued flag here and is swallowed harmlessly at the end of the arguments.)
3. `flags()`: add `-O` to the boolean flags. Run `open.spec.luau`: the two `-O` cases and `--open is still accepted` now pass (opening is still opt-in, so nothing opens); the default-open, contradiction, failing-opener, usage and workflow cases still fail.
4. `cmd.board`: the new contradiction check (before writing), the usage text, and `if not opts["-O"]` around the opener. Update `USAGE`. Now `open.spec.luau` 8/8 and `guard.spec.luau` 9/9.
5. `.github/workflows/board.yml`: trailing `-O` on the build step.
6. The tracker skill's `board` row and the testing skill's **No browsers** bullet, as in Design.
7. `scripts/tracker.sh check c0057` (9/9), then `scripts/tracker.sh check R0022`.
