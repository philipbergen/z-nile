# c0082: Tracker integrity audit

## Problem
One id in two lifecycle folders disables every tracker command, and nothing in the gate catches it. Re-filed from the parked tracker-hardening prep (its c0055, from the tracker system review's F1), whose ids now clash with `main`.

`store.find` throws `duplicate id …` when an id exists in, say, `tracker/issues/c0053` and `tracker/issues/done/c0053`. Every command that lists items goes through it: `list`, `members` (so every raft check.sh), `new`, `start`, `commit`, `promote-check` and `renumber`. Git reports no conflict, because the paths differ: an emergent issue is created in `issues/active/` and filed in `issues/done/`, while a capture on `main` creates the same number in `issues/`. No spec reads the real tracker, so CI on `main` stays green. Recovery is blocked too: `renumber` calls `store.get(old)`, which throws on the duplicate. Reproduced in the earlier prep: after `cp -R tracker/issues/c0053 tracker/issues/done/c0053`, `list` and `members` both exit 1.

## Non-goals
- Preventing the race itself: c0053 publishes stubs to `main`, and c0081 changes allocation.
- The rest of the parked tracker-hardening set (raft membership, design-ready gate, and so on), which stays parked.
- Rewriting `store.find` or the commands that go through it: they keep refusing a malformed tree (only `list` changes).

## Solution
- **`scripts/tracker/audit.luau`**: a whole-tree audit that reads the folders itself (never `store.find`), never throws on a malformed tree and reports every problem.
- **The gate runs it on the real tree**: this issue's `real-tree.spec`, promoted to `tests/acceptance/c0082/`, runs in every full gate, so CI on every pull request (which checks out the merge with `main`) and every raft's `check.sh` fail on an error. Tracker-only commits published straight to `main` are not gated (`check.yml` ignores `tracker/**` on push); they only add backlog stubs, status stamps and the counter, none of which can make a duplicate, which comes from a merge (an emergent issue filed in `done/` while `main` reused its number).
- **`tracker.sh audit`**: prints every problem and a summary; exit 1 on any error. Read-only, so it may run in the main checkout.
- **`list`** prints every item it can, both copies of a duplicate included, then fails on the problems `store.find` used to throw on.
- **`renumber <item directory> [<new>]`**: moves only that copy, rewriting ids only inside it, so the two copies of a duplicate can be separated.
- c0081's `compact` runs the audit before (refusing on any error) and after.

## Design

### `scripts/tracker/audit.luau`
```lua
export type Problem = { level: "error" | "warning", code: string, path: string, message: string }
audit.run(root: string): { Problem }   -- root: the checkout (reads <root>/tracker); sorted by path, then code
audit.format(p: Problem): string       -- "<level> <code> <path>: <message>"
audit.errors(list: { Problem }): number
audit.ITEM_CODES: { [string]: boolean } -- duplicate, no-document, legacy-name, no-slug: what `list` fails on
```
Requires `@lune/fs`, `./ids` (c0081) and `./store` (only for `store.readFront` and `store.kindDir`-style constants; never `find`, `get` or `all`).

It walks `tracker/{issues,rafts}/{,active/,done/}`; a child is an item folder when its name is a tracker id of either kind; every other name (`active`, `done`, `.gitkeep`, a README) is ignored.
| code | level | path | when |
|---|---|---|---|
| `duplicate` | error | each copy's folder | one id in two or three lifecycle folders of its kind; the message names the other copies |
| `wrong-kind` | error | the folder | an issue id under `rafts/`, or a raft id under `issues/` |
| `no-document` | error | the folder | no `<ID>.md` and no legacy `<ID>-<slug>.md` |
| `legacy-name` | error | the folder | only a legacy `<ID>-<slug>.md` (run `tracker.sh migrate`) |
| `no-slug` | error | the folder | the document has no non-empty `slug:` |
| `id-mismatch` | error | the folder | the document's `id:` names another id (no `id:` line is not a mismatch) |
| `next-missing` | error | `tracker/next` | the counter file is absent |
| `next-malformed` | error | `tracker/next` | `ids.parse` refuses it |
| `next-behind` | warning | `tracker/next` | a counter at or below the highest number in use in its space |
| `shared-number` | warning | the first copy's folder | one number used by two issue prefixes (`c0044`, `f0420`) |

`next-behind` is a warning: allocation already skips used numbers (`ids.nextFree`), and a raft branch whose emergent issue reserved its number on `origin/main` has a stale local counter until it merges `origin/main`, which must not fail its gate.

### Commands (`main.luau`)
- `cmd.audit()`: prints `audit.format` for each problem on stdout, then `audit: <e> errors, <w> warnings`; exit 1 when `e > 0`. Not refused in the main checkout; listed with the read-only commands in the skill.
- `cmd.list`: built on a non-throwing scan (the item folders `audit` walks, each read with `store.readFront`, so one id can yield two rows with their states); prints the same columns as today for every item it can read, sorted by id then state; then, if `audit.run` has problems with `audit.ITEM_CODES`, prints them on stderr and exits 1. The shared-number warning stays.
- `cmd.renumber`: a first argument containing `/` is an item directory: it must be a folder at `tracker/{issues,rafts}/[active/]<id>` holding `<id>.md`, else refuse. A `done/` directory is refused, naming the other copies ("renumber the copy that is not in done/: …"): a done item's specs are promoted under its id in `tests/acceptance/<id>` and its raft lists it, so renaming it would orphan both. `<new>` defaults to the next number (c0081's rules; ids gathered by the same non-throwing scan, so a duplicate does not stop it). The folder and its document are renamed and `ids.rewrite` with `{ [old] = new }` runs over that folder's `.md` and `.sh` files only. With an id instead of a directory, renumber is unchanged (and still refuses a duplicated id, naming `renumber <directory>` as the way out).

### Scalability
One pass over about 110 folders and documents; well under the 0.1 s a spec's setup costs.

### Maintainability
One module answers "is this tree sound?" for the gate, the CLI, `list` and compaction; adding a rule is one row in the table and one spec case. `store` stays the strict reader for every other command.

### Usability
Every problem names its folder and what to run (`migrate`, `renumber <directory>`); `list` still shows the whole backlog while a duplicate is pending.

Mutants run and killed on an assertion: audit stops at the first problem, `next-behind` as an error, `list` throwing on the duplicate (today's behaviour), `renumber <dir>` rewriting tracker-wide, a missing `id:` counted as a mismatch. Rows marked `reasoned` were not run: each is a one-line variant of a run row on the same spec case (the code or comparison it changes is asserted by name or by exact deep-equal of the sorted problem list). Spec fixes from the prototype: the shared-number case passes its own counter (the default one sat below 420 and added a `next-behind` warning), and the legacy document name is built by concatenation (c0044's guard bans the literal).

## Regression guard
At risk: `list` (every raft `check.sh` uses `tracker.sh members`, which stays strict; `list` output columns are unchanged for a sound tree) and `renumber` (the c0052 spec's rules for an id argument are unchanged).
- `tests/acceptance/c0052/renumber.spec.luau` stays green unchanged.
- `tests/tooling/migrate-odd.spec.luau` stays green (migrate is untouched).
Overrides: none (`lune run scripts/affected -- <each Touched path>` prints `ALL`; `grep -rlF` of `tests/acceptance` for `scripts/tracker/main.luau`, `store.luau`, `audit.luau`, the skill path and their basenames lists only specs whose pinned behaviour is unchanged: `c0043/format` (review-file pattern), `c0007/changed`, and the skill specs of c0003, c0048, c0050, c0052, c0057, which pin other sections).
