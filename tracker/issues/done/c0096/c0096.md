# c0096: Compaction spec cache names

## Problem
The id compaction (#64) renamed `c0820` → `c0076` and `c0840` → `c0078` in the jailed-case marker paths of `tracker/issues/active/c0076/check.sh` and `c0078/check.sh` (`.cache/c0076-sweeper`, `.cache/c0078-signals`). It did not rename the `.cache` base folders of their sequestered specs (`sweeper.spec.luau` still writes under `.cache/c0820-sweeper`, `jail-signals.spec.luau` under `.cache/c0840-signals`). So c0076 AC1 and c0078 AC1 report "the jailed cases did not run" even when every jailed case ran and passed, and R0026 can't finish. It can't be postponed: it blocks the raft's `check.sh`.

## Non-goals
- Why the compaction rewrites ids in a `check.sh` path but not in a spec's `.cache` folder name: the testing skill already tells specs that pin ids to survive a compaction; a compaction-tool change is a separate chore if wanted.
- Any other spec or check.

## Solution
By the user's decision (2026-10-05, "Fix the specs"), rename the two specs' `.cache` base folders to the post-compaction ids that the `check.sh` files use: `.cache/c0076-sweeper` and `.cache/c0078-signals`. One line each in the sequestered specs; nothing else changes.

## Design
- `tracker/issues/active/c0076/acceptance/sweeper.spec.luau`: `local base = `{root}/.cache/c0076-sweeper``.
- `tracker/issues/active/c0078/acceptance/jail-signals.spec.luau`: `local base = `{root}/.cache/c0078-signals``.

Each stays the only spec naming its folder (the gate's shared `.cache` literal check).
