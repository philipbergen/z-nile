# c0099: Replace file stub two builds

## Problem
c0077's sequestered `replace-file.spec.luau` stubs `rojo`: on every `build` the stub removes `.cache/check.rbxl` and links it to a victim folder, so the gate's build has to land over a link to a directory. It was written when the gate ran one build. R0024, merged from main during R0026, runs a second `rojo build` (the lobby place) at the same time. When the two stub calls interleave, the second `ln -s` finds `.cache/check.rbxl` already linked to the victim folder and creates its link inside it. The case "the build lands as a regular file over a link to a directory…" then fails intermittently ("expected keep, got build-victim,keep"), though the gate's code wrote nothing there. It failed `done`'s full gate on the done tree, which rolled back. It can't be postponed: it blocks `done`.

## Non-goals
- The gate's build order or concurrency: unchanged.
- What the case asserts: unchanged.

## Solution
By the user's decision (2026-10-06, "Fix the spec's stub"): the stub links `.cache/check.rbxl` only when it builds the game place (`[ "$1" = build ] && [ "$2" = default.project.json ]`). The lobby build no longer touches it, so the case tests what it meant to: the game place's build landing over a link.
