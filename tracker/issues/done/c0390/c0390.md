# c0390: Game alias requires

## Problem
Found in R0040's prep (experiment E6): **no require path from an adapter to shared Logic satisfies both of the repo's require rules.**
- The server adapters live in `src/server` (Roblox: `ServerScriptService.Server`), the client adapters in `src/client` (`StarterPlayer.StarterPlayerScripts.Client`), and Logic in `src/shared/Logic` (`ReplicatedStorage.Shared.Logic`).
- `tests/meta/architecture.spec.luau` requires every require to resolve **on disk** (`graph.resolve`). The promoted c0020 spec `place-rules.spec.luau` requires every require in `src` to resolve **in the Rojo-built DataModel** (`place.resolveRequire`).
- A relative path can't do both. `../shared/Logic/Session` works on disk, but in the place `../` from `ServerScriptService.Server.Sessions` is `ServerScriptService`, which has no `shared`. `../../ReplicatedStorage/...` works in the place but not on disk.
- Nothing crossed Rojo roots before, so this was never exercised. R0040 (a2) is the first raft whose adapters need Logic.

Roblox's require-by-string has a built-in **`@game`** alias for the DataModel root, e.g. `require("@game/ReplicatedStorage/Shared/Logic/Session")`, and luau-lsp resolves it through the Rojo sourcemap. The repo's two resolvers don't know it: `graph.resolve` only knows `.luaurc` aliases, and `place.resolveRequire` returns nil for every alias.

## Non-goals
- Any `src/` change: R0040 adds the first `@game` requires.
- Other aliases in `src/`. Roblox reads no `.luaurc`, so `@logic`, `@shared` and the rest stay test-only, and the c0020 spec that pins `@logic`/`@lune` → nil stays green unchanged.
- Case-insensitive `@Game`. Only the exact prefix `@game/` is recognised; anything else is "not @game".
- Resolving `$path` nodes that point at a single file. The project maps directories only, and a `$path` file would need Rojo's script-naming rules. Such nodes still appear in `gameRoots` but can only match an exact directory mapping.

## Solution
Teach both resolvers `@game/<instance path>`, mapping it through `default.project.json`'s `$path` nodes on disk, and from the tree root in the place. Then write the rule into the architecture skill: `@game/` is how `src` reaches **across Rojo roots**, and nothing else uses it.

## Design

### `scripts/lib/graph.luau`
```lua
export type GameRoot = { instance: string, path: string }
-- instance: "/"-joined instance names from the DataModel, e.g. "ReplicatedStorage/Shared"
-- path: the node's normalized "$path", e.g. "src/shared"

-- Every node of the Rojo project tree that has a "$path", sorted by instance path length, longest
-- first. `project` is a decoded project table; nil reads ./default.project.json and caches that
-- result per process (an explicit project is never cached and never answered from the cache).
function graph.gameRoots(project: any?): { GameRoot }

-- "@game/<seg>/<seg>..." to a repo-relative .luau file, or nil. `roots` nil means
-- `graph.gameRoots()`, looked up through the module table at call time (so a spec can stub it).
function graph.resolveGame(spec: string, roots: { GameRoot }?): string?

-- true for "./…", "../…", "@self/<x>" and "@game/ReplicatedStorage/<x>"; false for anything else
function graph.srcAliasAllowed(spec: string): boolean

-- Every string-literal require in `dir` (recursive, via graph.listLuau; comments stripped with
-- graph.stripComments; specs matched with graph.REQUIRE_PATTERN, so either quote style and spaces)
-- that srcAliasAllowed rejects, in listLuau file order then source order.
function graph.srcAliasViolations(dir: string): { { file: string, spec: string } }

function graph.resolve(from: string, spec: string, game: { GameRoot }?): string?   -- new optional 3rd arg
function graph.build(roots: { string }, game: { GameRoot }?): Graph                 -- passes it to resolve
```
- **`gameRoots`** walks `project.tree`. Keys starting with `$` are properties, not children. Instance paths are the child keys joined with `/`, with the DataModel root itself excluded. Each `$path` is normalized: `./tests/fixtures/graph/` becomes `tests/fixtures/graph`. The sort key is the **instance** path length, never the filesystem path.
- **`resolveGame`**:
  1. The spec must start with exactly `@game/`. `@game`, `@gamer/…` and relative specs return nil.
  2. Split the rest on `/`. Any empty, `.` or `..` segment returns nil. This covers a trailing `/`, `//` and path games, and matches `place.resolveRequire`'s strictness.
  3. Take the **first root, in longest-first order**, whose instance path equals the rest or is a `/`-prefix of it. Map the remainder under its `path`.
  4. If the mapped base ends in `.server` or `.client`, return nil: scripts aren't requireable, and in the place the instance is named without the suffix (design-review-001 F5).
  5. Return `<base>.luau` if it's a file, else `<base>/init.luau` if that's a file, else nil. There's no fallback to a shorter root: the longest mapped node owns its subtree, as in Rojo.
  - Matching is on whole segments: `ReplicatedStorage/Gr` never matches `ReplicatedStorage/Graph/...`.
  - A `Main.server.luau` script is also never found as `@game/.../Main`, because that lookup is `Main.luau`.
- **`resolve`** gets a new branch right after the `@lune/` one: `@game/` specs go to `resolveGame(spec, game)`. Everything else is unchanged.
- **`build`** passes `game` through. `scripts/affected.luau` and `tests/meta` call `build` without it, so they use the real project. That's how adapter → Logic edges reach the meta rules and the affected selector.
- `default.project.json` is already a full-run trigger in `scripts/affected.luau`, so a mapping change reruns everything.

### `tests/meta/architecture.spec.luau` (design-review-002 F2)
Add one case, "src requires use only relative paths, @self/ or @game/ReplicatedStorage/", that calls `graph.srcAliasViolations("src")` (literally, since AC5 checks for that call) and expects no violations, listing any as `file: spec`. All the scanning logic lives in `graph`, where AC5 tests it against real files (design-review-003 F1).

That makes the ReplicatedStorage-only rule part of every full gate, not just the raft checks.

### `tests/lib/place.luau`
`place.resolveRequire(from, spec)` gets one new branch, before `@self/`. For `spec` starting with `@game/`:
1. The start node is the **root of `from`'s instance tree**: follow `Parent` until it's nil. In the Rojo-built place, that's the DataModel.
2. The rest of the spec resolves with the same segment rules as relative paths: an empty or `.` segment → nil, and **`..` anywhere → nil** (there's no leading-`../` exception after `@game/`).
3. The target must be a `ModuleScript`.

Every other alias still returns nil. Update the function's header comment to match.

### Architecture skill (`.claude/skills/architecture/SKILL.md`), rule 5
Amend rule 5's heading, which currently says "relative paths or `@self`", so that it also names `@game/ReplicatedStorage/` (design-review-002 F5). Qualify its bullet "Roblox and Lune resolve them the same way": that holds for relative paths and `@self`, not `@game`, which Lune can't resolve. That's why adapters are never required from `tests/`, and why `graph`/`place` resolve `@game` through `default.project.json` (design-review-004 F1). Then add a bullet containing these three phrases verbatim (AC4 greps them):
- **`across Rojo roots`**: `src` reaches another Rojo root only through Roblox's built-in alias, e.g. an adapter's `require("@game/ReplicatedStorage/Shared/Logic/Session")`. Within one root, use relative paths or `@self`.
- The example path `@game/ReplicatedStorage/Shared/Logic/`.
- **`only into ReplicatedStorage`**: `@game` requires in `src` go only into ReplicatedStorage (design-review-001 F2).
  - `ServerScriptService` never replicates to clients, so a client require there fails at runtime.
  - Running client scripts are clones under `Players.<p>.PlayerScripts`, so a require into `StarterPlayer` loads a second, separate module instance.
  - The resolvers can't tell these apart, so `tests/meta` enforces the rule through `graph.srcAliasAllowed`. Say that in the bullet.
- Also say that Logic never uses `@game`: the engine-word rule in `tests/meta` already rejects the word `game` in Logic files. Say that `tests/place` and `tests/meta` both resolve `@game` through `default.project.json`.
- Keep the existing sentence that `.luaurc` aliases are only for `tests/` and `scripts/`.

### Scalability
`gameRoots` reads and decodes the project once per process (cached). Resolution is a scan of about 3 roots. `graph.build` over `src` and `tests` stays linear in files.

### Maintainability
- The Rojo project stays the single source of truth for where instances live. Moving a folder in `default.project.json` automatically moves what `@game/...` resolves to in `graph`, `place` and luau-lsp alike.
- The injected `game` / `project` arguments exist only so specs can test resolution against fixtures without touching `src`.

### Usability
Adapter authors write the path they'd see in Studio's Explorer. A wrong path fails in three places before Studio does:
- `tests/meta` "every require resolves";
- the c0020 place rules;
- luau-lsp in the gate's `src` type check.

## Unknowns & experiments
- **E1 (run in prep, R0040's E6: PASS)**: Does luau-lsp 1.70.1, the version the gate pins, resolve `@game/ReplicatedStorage/Shared/Logic/<Feature>` from `src/server` and `src/client` through `rojo sourcemap`?

  - Result: yes. It analysed the Logic modules as `game/ReplicatedStorage/Shared/Logic/...`, and the adapters had no unresolved requires and no type errors.
- **E2 (doc check: PASS)**: Does Roblox itself support `@game`?
  - Yes. <https://devforum.roblox.com/t/introducing-require-by-string/3405078> carries a January 8, 2026 update: "We now support the `@game` alias, which allows require-by-string to point to the root of the DataModel", with the example `require("@game/ReplicatedStorage/MyModule")`. Confirmed independently by the design reviewer (design-review-001 F4).
  - luau-lsp resolves it through the sourcemap, which is E1.
  - **Residual risk**: the running engine is first exercised in R0040's Studio playtest (f0120 OC1). Observed criteria don't block a merge, so R0040 can merge before anyone plays it. If `@game` then failed at runtime, the rollback is reverting R0040, since R0050 itself changes no `src`.
  - The human can retire this risk earlier with a one-minute Studio check: a ModuleScript in ReplicatedStorage plus a Script doing `require("@game/ReplicatedStorage/<it>")`.
  - **Fallback**, if Roblox rejected `@game`: map `src/shared` a second time into each script root in `default.project.json`, and use relative paths. Cost: every Logic ModuleScript exists twice, with separate module state on the server copy and the ReplicatedStorage copy (harmless for pure Logic, but a trap for any module cache). It's a chore that touches the c0020 place rules.

## Acceptance criteria

### Checked
- **AC1**: `graph.gameRoots` lists the project's `$path` nodes, longest first, caching only the default project. `graph.resolveGame` maps `@game/…` on whole segments through the longest matching node, without fallback, to `.luau` or `init.luau` files. It returns nil for missing, unmapped, script, malformed or non-`@game` specs (the prefix is case-sensitive).
- **AC2**: `graph.resolve` and `graph.build` follow `@game` requires, using injected roots or `default.project.json`, and report unresolved ones like any other.
- **AC3**: `place.resolveRequire` resolves `@game/…` from the root of the instance tree to a ModuleScript, rejects malformed paths, and still returns nil for every other alias.
- **AC4**: The architecture skill documents `@game/` as the way to require across Rojo roots, and only into ReplicatedStorage.
- **AC5**: `graph.srcAliasAllowed` allows only relative paths, `@self/` and `@game/ReplicatedStorage/`. `graph.srcAliasViolations(dir)` reports every other real require (either quote style, comments ignored, recursive), and `tests/meta` applies it to `src`.
