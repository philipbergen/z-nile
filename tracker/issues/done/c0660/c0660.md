# c0660: Retrofit fixture checks into older git specs

## Problem
Both incidents had one mechanism: a spec ran git in a fixture whose repository was missing, and git found the real one. The second time it was c0640's own spec, run against code that didn't have the guards yet. c0640's specs now check, before every git call, that the target is the fixture they created. The twelve older fixture specs don't:
- `tests/acceptance/c0010/tracker-lifecycle.spec.luau`
- `tests/acceptance/c0041/worktree.spec.luau`
- `tests/acceptance/c0050/clone.spec.luau`
- `tests/acceptance/c0060/changed.spec.luau`
- `tests/acceptance/c0070/done-order.spec.luau`
- `tests/acceptance/c0330/locator.spec.luau`
- `tests/acceptance/c0360/deferred.spec.luau`
- `tests/acceptance/c0420/naming.spec.luau`
- `tests/acceptance/c0430/workstreams.spec.luau`
- `tests/acceptance/c0440/launch.spec.luau`
- `tests/acceptance/c0480/start-depends.spec.luau`
- `tests/tooling/worktree-fetch.spec.luau`

They rely on the runner's guards. On macOS the jail covers everything. On Linux (CI) a write to the real checkout's index or files isn't stopped. And wherever the guards are absent (a branch from before R0210, a prototype of a guard), nothing stops them.

## Non-goals
- Changing what any of these specs asserts.
- New runner guards (c0640).

## Solution
Add one shared helper that runs a command only in a proven fixture repository. Route every git and `tracker.sh` call of the twelve specs through it. Add a static check that keeps it that way, and run the twelve against the unguarded runner in a clone to prove it.

## Design
### Helper (`tests/lib/fixture.luau`, new)
```lua
export type Result = { ok: boolean, code: number, stdout: string, stderr: string }
export type Options = { env: { [string]: string }?, stdin: string? }
function fixture.physical(path: string): string?        -- symlinks resolved; nil if not a directory
function fixture.check(dir: string)                      -- raises unless dir is a fixture repository
function fixture.exec(dir: string, cmd: string, args: { string }, options: Options?): Result  -- check, then run in dir
function fixture.git(dir: string, args: { string }, options: Options?): string                -- check; raises on failure
```
A **fixture repository** is a directory whose physical path lies under **this run's** `.cache` folder (`<pwd -P>/.cache/`: a spec runs at its checkout's root), and is either:
- the top of its own worktree (`git rev-parse --show-toplevel` in it is itself), or
- a bare repository's own git directory (`--is-bare-repository` is true and `--absolute-git-dir` is itself).

Anything else raises `refusing to run in <dir>: it is not a fixture repository under a .cache folder` **before** the command runs:
- a folder whose repository is missing (git would find the enclosing one);
- a subfolder of a fixture;
- the real checkout;
- a repository outside `.cache`, or under some other `.cache` folder.

**Git pointed elsewhere** is refused too, before anything runs: `GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE`, `GIT_COMMON_DIR` or `GIT_OBJECT_DIRECTORY` in `options.env` (any command), and for git, a global `-C`, `--git-dir` or `--work-tree` before its command (`-c <key=value>` is skipped as a pair). A command's own options, such as `commit -C HEAD`, are not global options and pass. The helper names those variables to refuse them, so c0640's scan allowlist gets an entry for `tests/lib/fixture.luau` with exactly those five names ("refused"), and one for this issue's promoted `tests/acceptance/c0660/fixture.spec.luau` with `GIT_DIR` and `GIT_WORK_TREE` (it proves the helper refuses them). Without the second, the first gate after `done` promotes the spec would fail (review 007 F1).

Creating a fixture needs no check, because the new path is named explicitly: raw `git init <path>` and `git clone <src> <path>` stay.

### Retrofit of the twelve specs
- Each spec's own git and tracker helpers (`git(...)`, `run(cwd, ...)`, `tr(...)`, and the like) call `fixture.git` or `fixture.exec`.
- Raw `process.exec("git", …)` is left only for `rev-parse` (finding the root), `ls-files` (listing it) and `init`/`clone` (creating a fixture).
- A process run at the real root that isn't git or `tracker.sh` (`lune run tests/run` refusing under `AC_LIST`, for example) keeps a literal command name.
- No raw shell string (`process.exec("sh" or "bash", { "-c", … })`): a shell command runs through `fixture.exec` in a fixture (c0330's two `bash -c` calls move into one). No `process.create`, and the process module only under the name `process`.
- A failed setup needs no rule of its own: a later case's git call then meets a missing fixture, and the helper refuses it.
- No assertion changes.

### Rule in the documents
The testing skill's **Fixtures** bullet changes to: specs run git and `tracker.sh` in a fixture through `@tests/lib/fixture`; raw git only for `rev-parse`, `ls-files`, `init` and `clone`; no shell strings. It names the specs written before the helper that don't use it yet (c0510's, which R0200 lands first, and c0640's and c0650's, which check each fixture themselves) and says to convert them when next edited (review 007 F5). The "retrofitting is a follow-up" sentence goes.

### Scalability
One `git rev-parse` (two for a bare repository) per fixture command. These specs run perhaps a few hundred, so about a second of CPU spread over the parallel lanes. The jail, not this check, dominated the guards' cost (c0640 E25).
### Maintainability
One helper replaces about a dozen local `git`/`run`/`tr` variants. The static check (`retrofit.spec`) stops raw calls from creeping back into these twelve files, and the testing skill states the rule for new ones. The static check is the real guard against a missed write path: in a normal run every fixture exists, so a raw call behaves exactly like a helper call (review 006 F5), and AC4 is a smoke test, not proof.
### Usability
A broken fixture fails with `refusing to run in …: it is not a fixture repository`, instead of a confusing failure in the real repository, or none at all.

## Unknowns & experiments
- **E1** Does the helper accept every fixture shape the twelve use, and refuse the rest? **Pass** on the prototype (`proto2-c0640`): it accepts a fixture, a worktree of it and a bare fixture, and refuses a folder without a repository (without running anything there), a subfolder, the real checkout and a repository outside `.cache`.
- **E2** Can the static check tell real violations from the allowed raw calls? Its self-test case plants a raw `git commit`, a computed command and a multi-line raw `tracker.sh`, and finds exactly those three. On today's twelve specs it finds 27 violations, which the retrofit removes.
- **E3** Not run in prep: the retrofit itself. The twelve specs are edited during execution. `retrofit.spec` (AC2) proves the routing; AC3 and AC4 show nothing broke, guarded and unguarded (a `$TMPDIR` clone without `origin`, GitHub tokens and ssh agent, with the clone's repository unchanged). AC4 can't catch a missed write path on its own (every fixture exists in a normal run), so it is a smoke test, not the guard.
- **E4** Does the scan see past the easy bypasses? Review 006 listed git in `sh -c` strings, the process module under another name, `process.create`, and `-C`/`--git-dir`/`--work-tree` through the helper. The first three are now scan rules (self-tested: the probe file trips six rules), and the last is refused by the helper itself.
- **Mutation check** on the helper (prototype), all killed:
  - H1 (no `.cache` requirement): the real-checkout and outside-`.cache` cases;
  - H2 (any folder inside a repository): the subfolder case;
  - H3 (`exec` skips the check): the no-repository and real-checkout cases;
  - H4 (bare fixtures unsupported), H5 (`git` doesn't raise) and H6 (stdin dropped): each by its case;
  - H7 (any `.cache` folder): the other-`.cache` case; H8 (git options and variables not checked) and H9 (a `-c` value read as an option): the pointed-elsewhere case.

## Acceptance criteria

### Checked
- AC1: `@tests/lib/fixture` runs commands only in a fixture repository (under this run's `.cache`; the top of its worktree, or a bare repository), refusing anything else, and anything that points git at another repository, before the command runs; it passes env and stdin.
- AC2: the twelve specs use the helper, with raw git only for `rev-parse`, `ls-files`, `init` and `clone`; no raw `tracker.sh`, shell strings, computed commands, `process.create` or renamed process module; the scan is self-tested.
- AC3: the twelve specs pass under the guards.
- AC4: the twelve specs pass against the runner without the guards, in a clone under `$TMPDIR` with no `origin`, GitHub token or ssh agent, and the clone's repository is unchanged (config, refs, HEAD, worktrees, status).
- AC5: the testing skill states the rule (names `@tests/lib/fixture`, and the specs not yet converted), without the "follow-up" sentence.
