# f0014: First person client

## Problem
The player has to *see* the maze from inside it:
- walls built from the maze data;
- a first-person camera that follows the replicated position smoothly, with free look;
- keyboard and mouse input turned into intents.

This is the "opens and plays in Roblox" half of raft a2.

## Non-goals
- Touch controls (raft f).
- The HUD (f0019), pellets drawn (f0030), ghosts drawn (f0032).
- Art polish: plain coloured parts and default lighting.
- Client-side prediction (see f0013 Non-goals).
- Sound.

## Solution
Split the client the same way as the server:
- **A pure `View` Logic feature** holds every decision that could be wrong:
  - world scale;
  - which wall parts to build (merged runs, repeated beyond tunnel edges);
  - heading → yaw;
  - snapshot interpolation that won't slide across a tunnel jump;
  - turn smoothing;
  - free look with a pitch clamp and snap-to-heading;
  - the key map.
- **Three thin client adapters** (`MazeView`, `Camera`, `Controls`) turn `View` results into Parts, the camera CFrame and remote calls.
- **`Main.client.luau`** wires them to the Snapshot and Intent remotes.

## Design

### Decisions made in prep
- **World scale** (`View.SCALE`): tile **8 studs**, wall height **10**, eye height **4**, field of view **80°**. Corridors feel about two people wide, and walls are well above eye level, so you can't see over them.
- **The camera** is `Scriptable`: yaw = smoothed heading yaw + look yaw, then pitch. A quarter turn eases over **0.12 s**, and `Back` over twice that. Pitch is clamped to **±80°**. Mouse sensitivity is **0.004 rad/pixel**.
- **Look is relative to the heading**: turning at a junction turns the view with you and keeps your look offset. **Space** snaps the look back to the heading ("snap look to heading", game design).
- **Keys**: W/↑ Forward, A/← Left, D/→ Right, S/↓ Back, Space Snap. They're bound through `ContextActionService` at high priority and **sunk**, so the default controls never see them.
- **No character**: f0013 turns off `CharacterAutoLoads`. Nothing else is needed for "other players are never visible", because each client only builds its own maze.
- **Tunnels**:
  - `View.walls` repeats the maze periodically for **12 tiles** beyond each wrapping edge, so looking down a tunnel shows the far side, not a wall or the void.
  - The floor spans the same margin.
  - When the latest snapshot's `jumpTick` is newer than the previous snapshot, the camera jumps instead of sliding.
- **Interpolation**: the camera renders between the two latest snapshots, with `alpha = (now − arrival of latest) × 30`, clamped to 0..1. That's one tick (33 ms) behind the server, and smooth at any frame rate.

### `src/shared/Logic/View/init.luau` (pure; no engine types: numbers in, numbers out)
```lua
local Maze = require("./Maze")
local Movement = require("./Movement")
local Session = require("./Session")

export type Rect = { x0: number, y0: number, x1: number, y1: number }   -- inclusive tile range (walls returns one-row rects; bounds may span many)
export type Action = Movement.Intent | "Snap"
export type Look = { yaw: number, pitch: number }                         -- radians, relative to the heading
export type Pose = { x: number, y: number }                               -- tile coordinates

View.SCALE          -- frozen { tileStuds = 8, wallHeight = 10, eyeHeight = 4, fieldOfView = 80 }
View.TUNNEL_MARGIN  -- 12 (the classic row 14 has its first walls 11 tiles in from each edge)
View.TURN_SECONDS   -- 0.12 (per quarter turn)
View.MAX_PITCH      -- math.rad(80)
View.MOUSE_RADIANS_PER_PIXEL -- 0.004
View.KEYS           -- frozen { W, Up = "Forward"; A, Left = "Left"; D, Right = "Right"; S, Down = "Back"; Space = "Snap" }

function View.world(x: number, y: number): (number, number)          -- (x * tileStuds, y * tileStuds): world X, Z
function View.headingYaw(h: Maze.Heading): number                    -- N = 0, W = pi/2, S = pi, E = -pi/2
function View.bounds(m: Maze.Maze, margin: number?): Rect            -- the rendered tile range (maze + margin on wrapping axes)
function View.walls(m: Maze.Maze, margin: number?): { Rect }         -- margin defaults to TUNNEL_MARGIN
function View.interpolate(prev: Session.Snapshot?, latest: Session.Snapshot, alpha: number): Pose
function View.approachYaw(current: number, target: number, maxDelta: number): number
function View.turnRate(): number                                     -- (pi / 2) / TURN_SECONDS, radians per second
function View.look(l: Look, dx: number, dy: number): Look            -- mouse delta in pixels
function View.snap(l: Look): Look                                    -- { yaw = 0, pitch = 0 }
function View.action(keyName: string): Action?                       -- by key name, e.g. "W", "Up", "Space"
```
- **`headingYaw`** follows Roblox's `CFrame.Angles(0, yaw, 0)`, which looks along (−sin yaw, 0, −cos yaw). With world X = tile x and world Z = tile y, that makes the look vector equal `Maze.delta(h)` (AC2).
- **`walls`**:
  - **`bounds`**: the maze **wraps on x** if any tile on column 0 is ghost-passable, and **on y** if any tile on row 0 is. On a wrapping axis the range extends by `margin` on both sides; on the other axis it doesn't. For the classic maze it's `{ x0 = -12, y0 = 0, x1 = 39, y1 = 30 }`. `walls` uses it (design-review-002 F5).
  - For each row `y` in range and each maximal run of `x` in range where `kind(x mod width, y mod height) == "wall"`, emit one `Rect { x0, y0 = y, x1, y1 = y }`.
  - Runs are maximal: two on one row never touch. They're disjoint, and nothing outside the range is covered.
- **`interpolate`**:
  - An `alpha` of NaN counts as 1; otherwise it's clamped to [0, 1].
  - Return the latest position unchanged if any of these holds: `prev` is nil; `latest.player.jumpTick > prev.tick` (a jump happened after `prev`); or `prev.tick >= latest.tick` (stale or out of order).
  - Otherwise lerp `prev.player` → `latest.player` in x and y.
- **`approachYaw`** moves along the shorter arc by at most `maxDelta` and never overshoots. Results are in (−π, π]: wrap with `(a + π) % 2π − π`, and map −π to π.
- **`look`**: `yaw = wrap(yaw − dx·k)` and `pitch = clamp(pitch − dy·k, −MAX_PITCH, MAX_PITCH)`. Mouse right or down gives negative yaw or pitch (turn right, look down).

### Client adapters (`src/client/`, ModuleScripts unless noted; the prototype total was 130 lines)
- **`MazeView.luau`**: `MazeView.build(m: Maze.Maze): Model`.
  - One anchored Part per `View.walls` rect: size `(x1−x0+1)·tile × wallHeight × tile`, centred at `View.world` of the rect centre, with Y = wallHeight/2.
  - One Part per door tile (`Maze.tiles(m, "door")`), pink: size `tile × wallHeight × 1` stud, centred on the tile at Y = wallHeight/2. The door is a thin panel across the house entrance, in the row of walls.
  - One floor Part covering `View.bounds(m)`, converted to studs with `View.world` (a half tile beyond the outer tile centres on each side): its **top face at Y = 0**, 1 stud thick (centre Y = −0.5). The adapter never decides which axes wrap.
  - All parts have `CanCollide`, `CanQuery` and `CanTouch` false (nothing uses physics). They sit in a `Model` named `Maze` under `workspace`.
  - Colours: walls classic blue `(33, 33, 222)`, door `(255, 184, 255)`, floor black.
- **`Camera.luau`**:
  - `Camera.push(snap)`: keeps `prev`/`latest`, ignores `tick <= latest.tick`, and records `os.clock()` on arrival. This relies on f0013's rule that a connected client's session is never replaced, so ticks only increase.
  - `Camera.snap()`: `look = View.snap(look)`.
  - `Camera.start()`:
    - sets `CameraType = Scriptable` and the FOV, and hides the mouse icon;
    - `BindToRenderStep("PickmanCamera", Camera + 1)`, and each frame:
      1. `MouseBehavior = LockCenter`, then `look = View.look(look, GetMouseDelta())`;
      2. `pose = View.interpolate(...)` and `yaw = View.approachYaw(yaw, headingYaw(latest.heading), turnRate()·dt)`;
      3. `CFrame = CFrame.new(world(pose), eyeHeight) * Angles(0, yaw + look.yaw, 0) * Angles(look.pitch, 0, 0)`.
    - On the first snapshot, `yaw` starts at the heading, so the view doesn't spin.
- **`Controls.luau`**: `Controls.start(onSnap: () -> ())`.
  - Binds every key in `View.KEYS` with `ContextActionService:BindActionAtPriority(…, Enum.ContextActionPriority.High.Value, …)`.
  - On `Begin`: `View.action(input.KeyCode.Name)`. `"Snap"` calls `onSnap`; any other action does `Remotes.Intent:FireServer(action)`.
  - It always returns `Sink`.
- **`Main.client.luau`** (the LocalScript):
  - on `Remotes.Snapshot.OnClientEvent`, calls `MazeView.build(Maze.layout(snap.maze))` the first time a maze id is seen, then `Camera.push(snap)`;
  - calls `Camera.start()` and `Controls.start(Camera.snap)`;
  - **then** fires `Remotes.Ready:FireServer()` once, after the snapshot listener is connected (f0013's handshake), so the first snapshot the server sends is at tick 1 of a session the player sees from the start.
  - It builds on the snapshot's `maze` id, so a second layout needs no client change.
- **Requires**:
  - adapters reach Logic only as `@game/ReplicatedStorage/Shared/Logic/<Feature>` (c0041);
  - `Main` reaches its siblings as `./MazeView`, `./Camera` and `./Controls`.

### Scalability
- **Parts**: the classic maze with its 12-tile margins is about 240 anchored, non-colliding parts (about 1,030 wall tiles), built once. Merging runs cuts the part count by more than 4× versus one part per wall tile (AC1).
- **Per frame**: a few arithmetic calls and one CFrame write. No allocation beyond the small `Pose`/`Look` tables.
- **Network**: the client sends only intents (a few per second) and receives its own snapshots (f0013).

### Maintainability
- **Every rule in `View` is data or a pure function**: the key map, scale, margins and turn speed.
- **The adapters contain no branches that decide anything a test could check.** JC1 holds the reviewer to that, and R0004 RC1 caps adapter size.
- **Later render issues** (f0030 pellets, f0032 ghosts) reuse `View.SCALE`, `View.world` and the `Camera` pose. Touch controls (raft f) add another `Action` source beside `Controls`.

### Usability
- **Readability**: blue walls against a black floor, as in the arcade. The eye is at 40% of wall height, and corridors are 8 studs wide.
- **Responsiveness**: turns ease over 0.12 s, not snapping 90°. Look is free, but `Space` recentres. Movement is one tick behind the server, interpolated, so it's smooth at any frame rate.
- **Tunnels**: looking down one shows the other side.
- **For developers**: `View`'s API is numbers in, numbers out, fully specced headless.

## Acceptance criteria

### Checked
- **AC1**: `View.bounds` is the maze's tile range plus `margin` on wrapping axes only, and `View.walls` covers exactly the wall tiles with maximal, disjoint one-row runs. It repeats the maze periodically for `margin` tiles (default 12) beyond each wrapping edge and nowhere else, merges the classic maze to under a quarter of its wall-tile count, and never covers doors, the house or corridors.
- **AC2**: `View.SCALE` is sane, `View.world` maps tile (x, y) to (x·tile, y·tile), and `View.headingYaw(h)` looks along `Maze.delta(h)` under Roblox's CFrame convention.
- **AC3**: `View.interpolate` lerps between two snapshots by a clamped alpha (NaN counts as 1). It shows the latest position when there's no earlier snapshot, when a tunnel jump happened after the earlier one, or when the earlier one is stale.
- **AC4**: `View.approachYaw` turns along the shorter arc without overshooting and stays in (−π, π]. A quarter turn at `turnRate()` takes `TURN_SECONDS` (≤ 0.3 s) within a frame. `View.look` maps mouse right and down to negative yaw and pitch, clamps pitch to `MAX_PITCH` (< 90°), and wraps yaw. `View.snap` recentres.
- **AC5**: The key map is exactly W/Up → Forward, A/Left → Left, D/Right → Right, S/Down → Back, Space → Snap. Other keys map to nothing.
- **AC6**: The client `Main` requires the `MazeView`, `Camera` and `Controls` ModuleScripts, each of them requires the `View` feature, and `Main` fires `Remotes.Ready` (`FireServer`).

### Judged
- **JC1: the client adapters are thin.**
  - **Pass**: every conditional in `src/client/*.luau` is one of these:
    - nil or first-time guards (no snapshot yet; maze already built);
    - the out-of-order snapshot guard in `Camera.push`;
    - the `UserInputState.Begin` check;
    - dispatching `"Snap"` versus an intent.
    Everything that computes a position, angle, geometry or key meaning is a `View` call.
  - **Fail**: any other branch, or maths beyond converting `View` numbers into `Vector3`/`CFrame`/`Color3`. Examples: interpolation, angle wrapping or clamping, choosing which tiles become parts, or a key table in the adapter.

### Observed
- **OC1** (Studio, Play, one player). **Setup**: open an empty place, or delete `Workspace.Baseplate` and `Workspace.SpawnLocation` from a template place, since the Baseplate z-fights with the floor and the SpawnLocation sits in a corridor (design-review-001 F6). Then `rojo serve` and connect.
  1. The view starts inside the maze at the spawn, looking west along the corridor and moving (the session starts on the client's Ready signal, so this is visible).
  2. It stops at the T-junction after about 1 s.
  3. D (Right) turns north there and moves. A buffered A/D before a junction or corner is taken there.
  4. S reverses at once.
  5. The mouse looks around freely without changing the direction of travel, and Space recentres it.
  6. Walls are solid blue with no gaps. The ghost-house door shows as a pink bar and can't be entered.
  7. Driving into the row-14 tunnel shows the far side ahead, and you come out on the other side without a visible slide across the maze.
  8. No character, cursor or default movement is visible. The Output window shows no errors.
  - Note anything that feels wrong (speed, turn smoothing, scale) in the PR for a follow-up tuning issue.
