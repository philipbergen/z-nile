## Problem
When the player and a ghost meet:
- A normal ghost kills the player: lose a life, then reset positions.
- A frightened ghost gets eaten, scoring 200/400/800/1600 in a chain, and turns into eyes.
- Tiles swapped within one tick must still count as a meeting.

## Non-goals
- Hiscores. Drawing (f0032). The danger aids (f0033).
- Putting the ghosts into the replicated snapshot and frame (f0032): this issue wires them into the tick and the events only.

## Solution
The contact rule (`Ghosts.contacts`) and its use in the session step, covering the same-tile and swapped-tile cases. Scoring runs through `Game.addScore` (so the extra life still triggers), death through `Game.died`. A scenario: an idle player is caught within a measured window across 20 seeds.

## Design
### Files and API
- `src/shared/Logic/Ghosts/init.luau`: `contacts`.
- `src/shared/Logic/Session/init.luau`: the wiring. `Session` requires `Ghosts` (new edge `Session -> Ghosts`, declared in `tracker/architecture.md` in this prep).
```lua
Ghosts.contacts(set, prev: { Tile }, playerPrev: Tile, playerNow: Tile): { { name: Name, kind: "kill" | "eat" } }
Session.Config.ghosts: boolean?          -- on only in GAME_CONFIG; a maze with no ghost data has none either way
Session.Event.ghost: Ghosts.Name?        -- new kinds: Caught{ghost}, GhostEaten{ghost, points}, and pass-through GhostReleased, GhostLeft, GhostRevived, ModeChanged, FrightenedEnded (all with `ghost` where it applies)
```
- **The rule**: only `active` ghosts touch the player (eyes and ghosts in the house or leaving never do). With the tiles the ghosts occupied before the step (`prev`, from `occupiedTiles`) and after it, and the player's tile before and after, a ghost *meets* the player when it occupies the player's new tile, or when it now occupies the player's old tile and was on the player's new tile before (a swap). A meeting is a `kill` if the ghost is not blue, an `eat` if it is.
- **In `Session.step`**, per player, in this order (a contract): `Game.step` (a `Ready` event moves the player and **resets the ghosts**: `Ghosts.reset(set, "respawn" | "level" | "run", level)` for the reasons `respawn`, `level`, `again`; every ghost's `jumpTick` is this tick); `if not moving then continue`; player movement and eating (a `PowerStarted` event is remembered, `PelletEaten` events are collected); **`stepGhosts`**: forward each `PelletEaten` to `Ghosts.pelletEaten`; `Ghosts.step` with the player's occupied tile and heading, the level, `config.movement.speed` as the base speed and `TICK_RATE`; forward the ghosts' events (a ghost's `Wrapped` records its `jumpTick`; `Entered` is not forwarded); **then** `Ghosts.power(set, ticks)` if a power pellet was eaten this tick (the ghosts turn blue after their step, so their blue clock and the run's `frightened` counter are equal on every tick and end on the same one); then, **only if the run is still in play** (a level cleared this very tick wins; no `Caught` is reported), the contacts: any kill makes every ghost's `Caught` event and `Game.died` (a kill beats an eating: nothing is eaten that tick); otherwise each eating is `Ghosts.eat` (the chain's points), a `GhostEaten` event and `Game.addScore` (which may give the extra life).
- **Edge cases the rule settles** (each is a choice the user may veto, recorded in `tracker/game-design.md`): a power pellet eaten on the tile a normal ghost reaches in the same tick makes that ghost blue before the contact, so it is **eaten**; a blue ghost met on the very tick the blue time ends is a normal ghost again, so it **kills**; two blue ghosts met in one tick are eaten in the order of the ghosts (blinky, pinky, inky, clyde), 200 then 400; a contact across a tunnel wrap counts like any other. Ghosts stay frozen (blue ones too) through the dying and level-clear pauses, and every flag is cleared by the reset that ends them. The arcade's short freeze when a ghost is eaten is **not built** (the user may ask for it).
- **`Session.playAgain`** resets the ghosts ("run") with the player; `Session.kill` (the server ending a life by hand) is unchanged.
- **Member fields** (private to `Session`, named here because the sequestered specs read them): `member.ghosts: Ghosts.Set?` (nil without ghosts) and `member.ghostJump: { [Name]: number }`, the tick of each ghost's latest position jump; a name is absent until that ghost has jumped, and every ghost gets the tick of a reset.
- **Ghosts are opt-in**: `Session.new` builds a ghost set per player only when `config.ghosts` and `Ghosts.available(maze)`; `GAME_CONFIG.ghosts = true`, `DEFAULT_CONFIG` has none. The server adapter already passes `Session.GAME_CONFIG`, so it needs no change.

### Pure/adapter split and authority
All Logic. The server simulates the ghosts and decides every contact; no client input can move or kill a ghost.

### Scalability
Per tick per player: four ghost steps and four contact tests. The set lives with the member, so cost is linear in players. `contacts` allocates a handful of small tables; `occupiedTiles` is called twice per tick.

### Maintainability
`Session` only wires; every ghost rule stays in `Ghosts` and is covered there. A second maze needs only its `Classic` entry. The step order is documented here and in `Session`'s header comment (the executor updates it).

### Usability
Fairness (pillar 3): a contact is decided by the same grid rule as the player's pellets (`Maze` tiles), swaps count, a power pellet's blue time is exactly the run's, and a ghost never kills in a pause. The `Caught` event names the killer, which a later death screen can use.

## Unknowns & experiments
- **E1** How quickly is an idle player caught? **Run**: tick 428 on all 20 seeds. The seed only matters once a power pellet makes the ghosts wander, so until then the 20 runs are one run (the scenario also pins determinism), 12.3 s of game time after the run goes into play, caught by Clyde (released at tick 328 by the idle timer, chasing from far away). The scenario allows 8 to 20 s.
- **E2** Does the blue clock line up with the run's power clock? **Pass** (the spec compares them on every tick of a whole power period), once `Ghosts.power` is applied after the ghosts' step.
- **E3** Do the existing specs survive ghosts in `Session`? **Pass**: `check.sh --full` (the existing sessions have no ghosts: the flag). The prototype found one adapter rule: `Camera` must keep exactly one `View.interpolate` call (a promoted spec pins it); that is f0033's business, recorded there.
- **E4** What happens to a kill in a tick that clears the level? **Found by a spec**: `Game.died` is a no-op outside play, but a `Caught` event was still emitted; the design now skips contacts unless the run is still in play.

## Acceptance criteria

### Checked
- **AC1**: a normal ghost on the player's tile or swapping tiles with it kills, a blue one is eaten for 200, 400, 800, 1600, a revived ghost kills, eyes and ghosts in the house never touch the player.
- **AC2**: in a session the ghosts only move while the run is in play, a death sends everyone home, a kill beats an eating, the last pellet beats a kill, and the blue time ends with the run's power.
- **AC3**: an idle player is caught 8 to 20 seconds of game time after play starts on every seed, deterministically.
- **AC4**: every existing session, game, pellet and client spec still passes (ghosts are off unless asked for).
- **AC5**: the architecture rules hold (Logic is pure, every require declared in `tracker/architecture.md`, every feature has unit specs).
