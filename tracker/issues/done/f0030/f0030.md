# f0030: Pellet rendering

## Problem
f0016 and f0017 make pellets real in Logic, but nothing draws them. Without this the player can't see what's left to eat, can't find the power pellets, and nothing visibly happens when they eat one. The snapshot from f0013 carries only the player, so the client doesn't even know which pellets are gone.

## Non-goals
- Pellet rules and scoring (f0016, f0017). Score display (f0019). Sound. Art polish beyond a clear, readable look.

## Solution
- Every frame carries the player's pellets as a short code: `Frame.pellets = Pellets.encode(member.pellets)`, one bit per pellet slot of the layout, six bits to a base64url character (41 characters for the classic maze). Each frame is the whole state, so there are no deltas, no "full set on join" message and no resync. A level start or a new run shows every pellet again in its next frame, because `Pellets.reset` already ran.
- `Pellets.slots(maze)` is the wire order (the layout's pellet and power tiles, row-major). `Pellets.decode(maze, code)` turns a code back into a per-slot `{ boolean }` and refuses a code that can't come from that maze.
- Placement and the pulse are pure, in `View`: `View.pellet(slot)` gives the centre and diameter in world studs, and `View.pulse(kind, seconds)` gives the power pellet's size factor in real time.
- `src/client/PelletView.luau` builds one ball per slot under the maze model, shows or hides them from each frame's code (and only when the code changed), and pulses the power pellets on `RenderStepped`.

## Design

### Decisions made in prep
- **A full bitmap every frame, not deltas** (changes the draft idea). RemoteEvents are reliable and ordered, but a delta stream needs a join snapshot, a reset message and a gap story; a stateless code needs none of them. Cost: 41 bytes a frame, 15 frames a second, about 0.6 KB/s per player. Prep measured `Pellets.encode` at about 26 µs (Lune, M-series), so 50 players at 15 frames/s spend about 2% of a core. If that ever matters, `Pellets` can cache the code and drop it on `eat`/`reset`. That's an optimisation, and no spec depends on it.
- **The wire order is the layout's**, not what is left: `slots` comes from `Maze.kind`, so client and server agree on bit positions from the maze id alone. Slots are cached per maze (weak-keyed, like `Maze`'s grids). `slots` returns a **deep copy**, with new slot tables as well as a new list, because a caller may change an element. `encode` and `decode` read the private cache directly, never through `slots`, so a frame doesn't pay for the copy.
- **Bit layout**: slot i is bit `(i - 1) % 6` of character `(i - 1) // 6 + 1`; 1 means still there; unused bits of the last character are 0; the alphabet is base64url `A–Z a–z 0–9 - _`. A full classic maze is `string.rep("_", 40) .. "P"`. It is JSON-safe, so the sim harness and the f0018 round-trip spec keep working.
- **`decode` is strict**: wrong length, a character outside the alphabet, or a set padding bit raises `pellets: …`. The server is the only producer and the maze id pins the layout, so a bad code is a bug, not input to tolerate. The client's `OnClientEvent` handler failing for one frame is visible in the output log, and the next frame recovers.
- **`Session.snapshot` stays the v1 schema**: `pellets` is added to `Frame` only, beside `play` (the extension point f0018 left).
- **Look** (author's choice, the user may veto): pellets are neon balls in the arcade's pellet colour `#FFB8AE`, centred at **3 studs** (the eye is at 4, walls are 10, a tile is 8). A pellet is **1 stud** across and a power pellet **3 studs**. Power pellets pulse between **0.7× and 1×** once every **0.5 s of real time** (presentation stays in real time, like `View.TURN_SECONDS`).
- **Readable down a corridor** (the measurable proxy for "visible down a long corridor"): a power pellet at its smallest spans at least 0.5° from 26 tiles away, the classic maze's longest straight (rows 5 and 29). That is about 7 px at 1080p and an 80° field of view. With the chosen numbers it spans 0.58°.
- **Eaten pellets** get `Transparency = 1`, so the parts are kept and never re-created.

### `Pellets` additions (`src/shared/Logic/Pellets/init.luau`)
```lua
export type Slot = { x: number, y: number, kind: Kind }
Pellets.ALPHABET = "ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789-_"
function Pellets.slots(m: Maze.Maze): { Slot }          -- the layout's pellet and power tiles, row-major (the wire order); a fresh list
function Pellets.encode(p: Pellets): string             -- ceil(#slots / 6) characters
function Pellets.decode(m: Maze.Maze, code: string): { boolean }  -- present[i] per slot; errors "pellets: …"
```
### `Session` change (`src/shared/Logic/Session/init.luau`)
`export type Frame = { v, tick, maze, player, play, pellets: string }`, and `Session.frame` sets `pellets = Pellets.encode(member.pellets)`. Nothing else changes: the eating path, `Pellets.reset` on a new level and on `playAgain`, and death keeping eaten pellets are all R0009's behaviour, now visible.

### `View` additions (`src/shared/Logic/View/init.luau`)
```lua
export type PelletPart = { x: number, y: number, z: number, diameter: number } -- world studs, y up
View.PELLET = { height = 3, pellet = 1, power = 3, pulseSeconds = 0.5, pulseMin = 0.7 }  -- frozen
function View.pellet(slot: Pellets.Slot): PelletPart     -- x, z = View.world(slot.x, slot.y); y = height; diameter by kind
function View.pulse(kind: Pellets.Kind, seconds: number): number
-- power: pulseMin + (1 - pulseMin) * (0.5 + 0.5 * cos(2π · seconds / pulseSeconds)); 1 at 0, pulseMin at half a period
-- pellet, NaN or ±inf seconds: 1
```
New architecture edge **`View -> Pellets`** (for `Slot` and `Kind`), added to `tracker/architecture.md` in prep.

### Client adapter (`src/client/PelletView.luau`, new)
```lua
export type Handle = { maze: Maze.Maze, parts: { BasePart }, power: { BasePart }, code: string? }
function PelletView.build(m: Maze.Maze, parent: Instance): Handle  -- a "Pellets" Model of anchored, non-colliding, non-query Ball parts at View.pellet(slot)
function PelletView.show(h: Handle, code: string)                   -- no-op when code == h.code; else Pellets.decode and set Transparency 0/1
function PelletView.start()                                         -- one RenderStepped connection: power parts sized View.PELLET.power * View.pulse("power", t)
```
`Main.client.luau`: on a new maze, `PelletView.build(m, model)` parents the pellets under the maze model, so destroying the maze destroys them. Every frame: `PelletView.show(pellets, frame.pellets)`, as the **last** per-frame call (after the HUD and overlay lines of f0019 and f0031), so a strict-decode error never stops the rest of the frame. Boot: `PelletView.start()` before `ready:FireServer()`. The handler's parameter becomes `frame: Session.Frame`. `Camera.push(frame)` still type-checks: prep's prototype passed the Roblox type stage.

### Server authority
Unchanged. The server owns which pellets are eaten, and the client only draws the code. The client can't send anything about pellets, and PelletView has no remote.

### Scalability
- **Server**: one `encode` per frame per player, O(slots), about 26 µs on the classic maze.
- **Wire**: 41 bytes a frame, constant whatever has been eaten.
- **Client**: `show` costs O(1) when nothing changed, and O(slots) (244 property writes) once per pellet eaten. The pulse costs 4 size writes a render frame.
- A bigger maze grows all three linearly in its pellet count. N players per maze later just means one code per member, already per player.

### Maintainability
- A new maze needs nothing: slots come from the layout.
- A new collectible kind (fruit, raft "later") adds a `Kind`, a slot kind and a `View.PELLET` size. The wire format only carries presence.
- Sizes and the pulse are data in `View.PELLET`.

### Usability
- **Player**: the pellets line the corridor just below eye level, so the path ahead reads as a dotted line. Power pellets are three times bigger and breathe, so they're findable from across the maze. Eaten pellets vanish within one frame of the server eating them.
- **Developer**: `encode`/`decode` are inverse, strict and typed. `View.pellet` takes the `Slot` that `Pellets.slots` returns, so the two can't drift.

## Acceptance criteria

### Checked
- **AC1**: The wire format: `Pellets.slots` lists the layout's pellet and power tiles row-major with their kind (244 and 4 on the classic maze, unchanged by eating), as a deep copy each call (changing the list or one of its slots changes nothing). `encode` packs one bit per slot (1 = present), LSB first, six to a base64url character with zero padding, so a full classic maze is forty `_` and a `P`. `decode` inverts it and refuses a wrong length, a foreign character or a set padding bit with `pellets:`.
- **AC2**: Every `Session.frame` carries `pellets = Pellets.encode` of that player's pellets: a new player's frame has all of them, the frame after `PelletEaten` lacks exactly the eaten ones, a death keeps them eaten, the next level's and a new run's frames have all of them, each player sees their own, the frame still round-trips through JSON, the v1 snapshot has no `pellets`, and the classic code is always 41 characters.
- **AC3**: `View.pellet` places each slot at its tile's world centre at `View.PELLET.height`, with the pellet (1) or power (3) diameter, clear of the floor and the wall tops, centred below the eye line (a power pellet's top, at 4.5, reaches just past the 4-stud eye, which is intended: it stands out), and inside one tile. A power pellet is at least 2.5 times a pellet. `View.pulse` is 1 for pellets and swings a power pellet smoothly between `pulseMin` and 1 once per `pulseSeconds` (1 at 0, `pulseMin` at half, halfway at a quarter), stays at 1 for NaN or infinite time, and at its smallest still spans 0.5° from 26 tiles away.
- **AC4**: The client's `Main` requires `PelletView` and calls `PelletView.show(<handle>, <frame>.pellets)`. `PelletView` uses `Pellets` and `View` (`Pellets.decode`, `Pellets.slots`, `View.pellet`, `View.pulse`) and never touches a remote.
- **AC5**: `View` requires `./Pellets` (for `Slot` and `Kind`), and `tests/meta/architecture.spec.luau` passes: Logic stays engine-free, and `View -> Pellets` is declared and acyclic.
