# f0100: Maze model

## Problem
The game needs a maze: which tiles are walls, corridors, pellets, power pellets, the ghost house and its door, the player's spawn, and tunnels. It must be authored as text and be queryable by movement, pellets, ghosts and rendering alike, with one set of coordinate and heading conventions that every later feature shares.

## Non-goals
- Rendering (f0130).
- Several layouts: one classic layout ships. The layout table is where the next one goes.
- Ghost start tiles, scatter corners and tunnel slow zones (raft d adds them, as new characters or as data beside the layout).
- Fruit.

## Solution
A pure `Maze` feature: an ASCII format with a strict validating parser, read-only query functions, heading helpers, and the built-in classic 28×31 layout. Pellets and power pellets are authored in the text, not inferred. The door's passability is answered here per agent, so movement (f0110) and ghosts (f0210) share one rule.

## Design

### Conventions (every other feature uses these)
- **Tile coordinates** `{ x, y }` are 0-based: `x` is the column (character index − 1) and `y` is the row (row index − 1), with the origin at the top-left character.
- **Headings** are `"N" | "E" | "S" | "W"`. N is up the text (−y), E is right (+x), S is down (+y), W is left (−x).
  - `Maze.HEADINGS` lists them clockwise from N, and `Maze.exits` uses that order.
  - `left` and `right` are quarter turns (left of N is W), and `opposite` is a half turn.
- **World mapping** (used by f0130): +x → world +X, +y → world +Z, N looks along world −Z.

### Text format
| char | kind | player | ghost |
|---|---|---|---|
| `#` | `wall` | no | no |
| ` ` (space) | `empty` | yes | yes |
| `.` | `pellet` | yes | yes |
| `o` | `power` | yes | yes |
| `P` | `spawn` (no pellet) | yes | yes |
| `-` | `door` | **no** | yes |
| `H` | `house` | **no** | yes |

**Wrap**: every edge wraps.
- `neighbor` steps off one edge onto the opposite tile of the same row (x edges) or column (y edges).
- A **tunnel** is a non-wall edge tile whose opposite edge tile is also non-wall.

### `src/shared/Logic/Maze/init.luau` (the public API)
```lua
export type Heading = "N" | "E" | "S" | "W"
export type Tile = { x: number, y: number }
export type Kind = "wall" | "empty" | "pellet" | "power" | "spawn" | "door" | "house"
export type Agent = "player" | "ghost"
export type Maze = {       -- frozen; the grid itself is private (not a documented field)
	id: string,            -- layout id, or the id given to parse ("custom" by default)
	width: number,
	height: number,
	spawn: Tile,           -- frozen
}

Maze.HEADINGS: { Heading }        -- frozen { "N", "E", "S", "W" }
Maze.DEFAULT: string              -- "classic"

function Maze.parse(rows: { string }, id: string?): Maze          -- validates; errors are "maze: <problem>"
function Maze.layout(id: string): Maze                            -- built-in layout, parsed once and cached; unknown id errors "unknown layout"
function Maze.kind(m: Maze, tile: Tile): Kind                     -- errors "out of bounds" outside the grid
function Maze.passable(m: Maze, tile: Tile, agent: Agent): boolean
function Maze.neighbor(m: Maze, tile: Tile, h: Heading): (Tile, boolean)   -- new table; true if it wrapped
function Maze.exits(m: Maze, tile: Tile, agent: Agent): { Heading }        -- passable neighbours, in HEADINGS order
function Maze.isJunction(m: Maze, tile: Tile, agent: Agent): boolean       -- #exits > 2
function Maze.tiles(m: Maze, kind: Kind): { Tile }                         -- row-major (y, then x)
function Maze.left(h: Heading): Heading
function Maze.right(h: Heading): Heading
function Maze.opposite(h: Heading): Heading
function Maze.delta(h: Heading): (number, number)                          -- N = (0, -1)
```
- **The grid** is a private row-major `{ Kind }` (index `y * width + x + 1`). Keep it out of the exported type, for example in a module-local weak-keyed table or a non-exported field, so no caller depends on it.
- **Read-only**: the returned `Maze` and its `spawn` are `table.freeze`d. `layout` returns the same frozen maze on every call.
- **`Layouts`**: `src/shared/Logic/Maze/Layouts.luau` returns `{ [id]: { string } }`, required as `@self/Layouts`. The module is private to the feature.

### Validation (`parse`), in this order
Each error's message includes the words that AC2 checks, shown here in quotes.
1. No rows, or an empty first row → "empty".
2. A row whose length differs from the first → `row <y> has width <w>, expected <W>` ("width", "row <y>").
3. An unknown character → `unknown character '<c>' at (<x>, <y>)`.
4. Anything but exactly one `P` → `expected exactly one spawn 'P', found <n>`.
5. **Open edge**: a non-wall tile on an x edge whose opposite in the same row is a wall, or on a y edge whose opposite in the same column is a wall → `open edge at (<x>, <y>)`. Walking off it would wrap into a wall.
6. The spawn has no player exit → `spawn at (<x>, <y>) has no exit`.
7. **Reachability**, a BFS from the spawn with wrap:
   - every player-passable tile must be reachable by the player;
   - then every ghost-passable tile must be reachable by a ghost.
   - Otherwise → `tile (<x>, <y>) is unreachable for the <agent> from the spawn`, for the first such tile in row-major order.
- Dead ends are allowed, because movement specs use them; the classic layout has none (AC3).

- It's the arcade board. The area outside the arcade's walls is filled with `#`, so there are no open edges except the tunnel.
- 240 pellets, 4 power pellets at (1,3), (26,3), (1,23), (26,23).
- The spawn is (13,23), with exits E and W. The door is (13,12)–(14,12), and the house has 18 tiles.
- One tunnel, on row 14.
- It's mirror-symmetric except for the spawn pair (13,23)/(14,23). It has no dead ends, 34 player junctions and 30 corners.
- Row 14 has trailing spaces. They're significant, so keep them.

### Scalability
- **Queries**: `kind`, `passable` and `neighbor` are O(1), with one small table allocated for `neighbor`'s result.
- **The rest**: `exits` is 4 lookups; `tiles` is O(width × height) and meant for setup (rendering, pellet init), not per tick.
- **`parse`** is O(tiles), run once per layout, since `layout` caches.
- **Memory**: one frozen 868-entry array per layout, shared by every session on a server.

### Maintainability
- **A new maze** is a new entry in `Layouts.luau`, validated by the same parser.
- **New tile kinds** for later rafts (ghost starts, slow tunnel tiles) are a new character in the table plus a passability rule.
- **One copy of the conventions**: movement, ghosts and rendering all ask `Maze` for passability, neighbours and heading turns.

### Usability
- Parse errors name the problem and the coordinates, so a mistyped layout fails at load with a pointer to the character.
- The API is a handful of pure functions over a frozen value, so callers can't corrupt a shared maze.

## Unknowns & experiments
- **E2 (run in prep: PASS)**: Is the classic layout well-formed as authored?
  - Method: a Python count, then the prototype parser.
  - Result: 31 rows of 28 characters; 240 `.` and 4 `o`; mirror-symmetric except (13,23)/(14,23).
  - The prototype parses it with 0 dead ends, 34 junctions and 30 corners, and the tunnel wraps (27,14) ↔ (0,14).
- **E3 (run in prep: PASS)**: The raft prototype of this design passes all four acceptance specs (the raft total is 168 cases, see R0040). The mutation check caught four plausible wrong implementations here:
  - exits in N,S,E,W order;
  - no open-edge check;
  - out-of-bounds read as wall;
  - (with f0110) half-tile entry off by one.
- **Executor note (strict mode, luau-lsp 1.70.1)**: string-literal tables need annotations.
  - Declare typed locals first: `local HEADINGS: { Heading } = { "N", "E", "S", "W" }`, then `Maze.HEADINGS = table.freeze(HEADINGS)`. Casting a frozen literal (`table.freeze({...}) :: { Heading }`) is an error.
  - Annotate for-in variables over singleton-union arrays (`for _, h: Heading in HEADINGS do`). Unannotated, they widen to `string` (probe run in prep).

No unknowns remain for execution.

## Acceptance criteria

### Checked
- **AC1**: `parse` builds a frozen maze whose `kind`, `passable` (per agent), `neighbor` (with wrap flag), `exits` (N, E, S, W order), `isJunction` and `tiles` (row-major) match the text in the documented coordinates. `layout` returns a cached built-in and rejects unknown ids.
- **AC2**: `parse` rejects an empty maze, unequal widths, unknown characters, zero or several spawns, a spawn without exit, open edges, and tiles unreachable for the player or for ghosts, with messages naming the problem and the row or coordinates.
- **AC3**: `Maze.layout(Maze.DEFAULT)` is the designed classic 28×31 map tile for tile: 240 pellets, 4 corner power pellets, the spawn at (13,23), a 2-tile door, an 18-tile house, a single row-14 tunnel, and no dead ends.
- **AC4**: The heading conventions: `HEADINGS` order, `delta` (N = −y, E = +x), and `left`/`right`/`opposite`.
