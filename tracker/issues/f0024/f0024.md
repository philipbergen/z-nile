# f0024: Hiscore store

## Problem
Scores need to persist across sessions on three boards: all-time top N, daily and weekly, the latter two keyed by UTC period.

## Non-goals
- UI (f0026). Anti-cheat beyond the server being authoritative.
- The GameOver wiring (f0025) and the lobby read (f0026). This issue is the pure feature, the fake, and the game-place adapter shape.

## Solution
`src/shared/Logic/Hiscores/init.luau` is the public API. It computes period keys, the replace rule, the top-N rows and the retry policy. The store is an argument. `src/server/HiscoreStore.luau` is the thin OrderedDataStore adapter and calls that policy. Specs use `Hiscores.fake`. Signatures and the eight prep decisions are in the raft's Whole-raft design; this issue owns the store half.

## Design
The module exports the types in the raft (`BoardId`, `Board`, `Attempt`, `Companion`, `Row`, `PageEntry`, `Page`, `Store`, `Io`, `Retry`, `DriveResult`, and the run and cache types f0025 and f0026 add to the same file). `Io` is `get`, `updateEntry`, `updateScore`, `top`, `budget`, `wait`. Constants this issue sets: `N = 10`, `ORDERED_STORE = "Hiscores"`, `COMPANION_STORE = "HiscoreEntries"`, `LEVEL_CAP = 10000`, `RETRY = table.freeze({ attempts = 3, base = 0.25, cap = 1 })`.

```lua
function Hiscores.dayKey(unix: number): string
function Hiscores.weekKey(unix: number): string
function Hiscores.board(id: BoardId, unix: number): Board
function Hiscores.scope(board: Board): string
function Hiscores.cacheKey(id: BoardId, unix: number): string
function Hiscores.entryKey(userId: string, board: Board): string
function Hiscores.userIdFromKey(key: string, board: Board): string?
function Hiscores.cleanName(raw: any): string
function Hiscores.valid(attempt: any): boolean
function Hiscores.qualifies(stored: Companion?, attempt: Attempt): boolean
function Hiscores.commit(stored: Companion?, attempt: Attempt): Companion?
function Hiscores.pack(score: number, level: number): number
function Hiscores.retryDelay(policy: Retry, n: number): number?
function Hiscores.attemptDelays(policy: Retry): { number }
function Hiscores.spend(left: number, cost: number): (boolean, number)
function Hiscores.pageAttempt(n: number): number?
function Hiscores.scorePage(entries: { any }): Page
function Hiscores.globalName(base: string, scope: string): string
function Hiscores.storeTarget(kind: string, board: Board, useScope: boolean): (string, string)
function Hiscores.rows(pages: { Page }, lookup: (string) -> Companion?, n: number): { Row }
function Hiscores.rankOf(rows: { Row }, userId: string): number?
function Hiscores.lobbyRows(rows: { Row }): { { rank: number, name: string, score: number, level: number } }
function Hiscores.fake(): Store
function Hiscores.submit(store: Store, attempt: Attempt, unix: number): { [string]: boolean }
function Hiscores.top(store: Store, id: BoardId, unix: number): { Row }
function Hiscores.drive(io: Io, attempt: Attempt, unix: number, policy: Retry): DriveResult
```

`dayKey` / `weekKey` error when `unix` is not a finite number. They use civil-from-days arithmetic, not `os.date`. Week start is Monday: `(floor(unix / 86400) + 3) % 7` days back, because 1970-01-01 is Thursday. `board("all", _)` has no `period`. Day and week set `period` to that key. `scope` is `"all"` or `id .. ":" .. period`. `cacheKey` is that scope. `entryKey` is the user id, or `userId .. ":" .. period`.

`valid`: `userId` matches `^%-?%d+$` and is not `""` or `"-"`. `score` is a whole number from 0 through the largest integer whose packed form is still below `2^53`: `floor((2^53 - 1 - 9999) / LEVEL_CAP)`. `2^53 - 1` itself does not fit. `level` is a whole number from 1 through `2^53 - 1`, including levels above 9999. `name` is a string. `qualifies` is false when `valid` is false. Nil stored qualifies. Otherwise the new score must be strictly greater, or equal with a strictly greater level. `commit` returns nil when `qualifies` is false and does not mutate `stored`; otherwise it returns a new companion with `cleanName`. `pack(score, level)` is `score * LEVEL_CAP + min(level, 9999)`. The clamp is the ordered integer's tie-break. Do not "fix" a clamped tie by reading a second page. `cleanName` strips controls, trims, cuts to 20 characters, and uses `"Player"` when the result is empty or the input is not a string. `submit` writes `cleanName` only on the boards where `qualifies` is true. A refused write leaves the stored name.

`retryDelay(policy, n)` is nil outside `1..attempts`. Try 1 waits 0. Later tries wait `min(base * 2^(n-2), cap)`. Default delays are `0, 0.25, 0.5`. `spend` returns false and the same `left` when `cost < 1` or `left < cost`.

`rows` drops a non-positive `n`, a bad entry, a duplicate key (first page wins, even if a later page has a higher score), a nil lookup, a bad level, and a companion whose `userId` is not the key and is not a prefix of the key plus `":"`. Sort score desc, level desc, user id string asc (`"10" < "2"`). Cap at `n`. Rank is the index. Display the page score, not a disagreeing companion score. Do not pad. `top` asks the store for `N` and then `rows(..., N)`. `fake().top` returns one page, ordered by `pack(score, level)` descending then key ascending, truncated to `n`, with the unpacked score in each entry. `rows` still re-sorts an unpacked page, which is what the in-page string-id tie checks. The one-row page is where the pack shows: `fake().top(board, 1)` for two equal scores returns the higher level's key, not the lesser user-id key.

`drive` loops `all`, `day`, `week`. It remembers a committed companion per board. For each delay from `attemptDelays`: wait if the delay is > 0. Until a companion is committed: `spend(budget("get"), 1)` and `spend(budget("set"), 1)`, or continue; `updateEntry` with `commit` as the transform; an error continues; a nil commit breaks that board with no ordered write. Then `spend(budget("get"), 1)` and `spend(budget("setSorted"), 1)`, or continue; `updateScore` with `pack(committed.score, committed.level)`. An error continues and the next try writes that same packed score and does not call `commit` again. Success sets `wrote[id] = true` and breaks. Then always `io.top` of the all-time board, even when a `"sorted"` budget would be 0. Companion reads for that page use `get` and `spend(budget("get"), 1)`; a failure skips the row. `rankOf` the result. An invalid attempt skips the write loop and still calls `top`. `updateEntry` applies the transform before it returns, so a nested drive sees the committed row.

`pageAttempt(1)` is 10, `pageAttempt(2)` is 50, anything else is nil. `scorePage` copies `{ key, value }` to `{ key, score }` and skips an entry that has `score` instead of `value`. `storeTarget("ordered", board, true)` is `("Hiscores", scope)`. Companion base is `"HiscoreEntries"`. `useScope == false` returns `(globalName(base, scope), "global")` where `globalName` replaces every non-alphanumeric with `_`.

`HiscoreStore.submit(userId, name, score, level, run)` calls `Hiscores.once` for that user id and run (a second call does not drive), then `task.spawn`s `drive` with that user id, `unix = os.time()`, and `Hiscores.RETRY`. The spawn is inside `pcall`; failure `warn`s. `budget` maps `get` / `set` / `setSorted` to `Enum.DataStoreRequestType.StandardRead` / `StandardWrite` / `OrderedWrite`. It does not mention `OrderedList` or `RequestType.GetAsync` or `SetIncrement`. Companion `UpdateAsync` uses `Hiscores.commit` and returns the stored entry unchanged when `commit` is nil. Ordered `UpdateAsync` returns `math.max(old or 0, Hiscores.pack(committed.score, committed.level))`. The source contains `UpdateAsync` and `GetSortedAsync(false` and does not contain `SetAsync`. `io.top` uses `GetSortedAsync(false, pageAttempt(1))`, and on error once at `pageAttempt(2)`, maps `scorePage`, and does not advance the page. Opens go through `storeTarget`, scope first. `listen(fn)` stores one callback; `submit` calls it with `(userId, run, rank)` only when `rank ~= nil`. The module does not `FireClient`. The lobby place cannot require this file. `Boards.luau` contains neither `SetAsync`, `UpdateAsync`, nor `HiscoreStore`.

The feature file must not contain the words the architecture spec forbids (`game`, `workspace`, `Instance`, `script`, `Enum`) or `DataStore`, `os.date`, or `os.time`. Callers pass time in.

Add `tests/unit/Hiscores` in the same change as the directory. The architecture spec requires it. Those unit specs may mirror the acceptance cases; the acceptance specs stay under this issue until promotion.

### Scalability
A submit touches three keys, at most three attempts each, then one ordered page of 10 and at most 10 companion reads. It does not scan a maze or step ghosts. `drive` is spawned, so the heartbeat does not wait. `rows` sorts one page, not the whole store. N is fixed at 10. Nothing in this issue replicates.

### Maintainability
A new board id would be a new `BoardId`, a new scope, and one more pass in `submit` / `drive`. Period length is the key function (`dayKey` / `weekKey`), not a branch in the adapter. Store names and budgets are constants and `storeTarget`, so Beta does not grow a prefix. The adapter's only decisions are the enum map, `os.time`, `task.wait`, and `pcall`.

### Usability
Players see a stable row: a worse score cannot erase a name, and an equal score updates only when the level is higher. A score of 0 counts. Studio's negative user ids count. A failed write retries without freezing the overlay (the spawn returns immediately; f0025 relies on that). The developer API is the functions above. `submit` on an invalid attempt returns three falses and writes nothing, so a caller cannot partially store a bad row.

## Test plan

- `replace.spec` :: lower score, equal score with a lower or equal level, equal score with a higher level, name stays, name updates on a level bump, score 0, fraction, `+2`, `2^53 - 1` rejected, max packed score accepted, level 10000 clamps to 9999 → AC2
- `rows.spec` :: eleven scores, best is user `101`, user `111` absent, short page of 4, one-row page, level 7 beats level 1 where the higher level sorts after as a string, `fake().top(board, 1)` returns the higher level's key, duplicate key, page score, user `"15"` vs `"1"`, period key `"5:…"`, user `"10"` before `"2"` → AC3
- `store.spec` :: `N == 10 == Lobby.MAX_ROWS`, separate day scopes, `value` not `score`, page sizes 10 then 50, global fallback name → AC4
- `drive.spec` :: delays `0, 0.25, 0.5`, cap `0, 10, 12, 12, 12`, `commit` of a lower score is nil and the name stays, budget 0 never updates and still calls top, a zero write budget skips the update, sorted budget 0 still ranks, retry after an update error, a losing score does not retry, overlapping drives keep 5000, a failed ordered write retries the packed score and does not recommit, one board down does not stop the others, invalid attempt writes nothing → AC5
