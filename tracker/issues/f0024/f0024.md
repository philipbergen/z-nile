# f0024: Hiscore store

## Problem
Scores need to persist across sessions on three boards: all-time top N, daily and weekly, the latter two keyed by UTC period.

## Non-goals
- UI (f0026). Anti-cheat beyond the server being authoritative.
- The GameOver wiring (f0025) and the lobby read (f0026). This issue is the pure feature, the fake, and the game-place adapter shape.

## Solution
`src/shared/Logic/Hiscores/init.luau` is the public API. It computes period keys, the replace rule, the top-N rows and the retry policy. The store is an argument. `src/server/HiscoreStore.luau` is the thin OrderedDataStore adapter and calls that policy. Specs use `Hiscores.fake`. Signatures and the eight prep decisions are in the raft's Whole-raft design; this issue owns the store half.

## Design
The module exports the types in the raft (`BoardId`, `Board`, `Attempt`, `Companion`, `Row`, `PageEntry`, `Page`, `Store`, `Io`, `Retry`, `DriveResult`, and the run and cache types f0025 and f0026 add to the same file). `Io` is `get`, `updateEntry`, `updateScore`, `top`, `budget`, `wait`; both updates take a transform, `updateEntry(board, key, (Companion?) -> Companion?)` and `updateScore(board, key, (number?) -> number?)`, and return `(value?, err?)`. `budget(op)` takes `"get"`, `"set"`, `"getSorted"` or `"setSorted"`. `Store.set(board, key, packed, entry)` takes the packed ordered integer. Constants this issue sets: `N = 10`, `ORDERED_STORE = "Hiscores"`, `COMPANION_STORE = "HiscoreEntries"`, `LEVEL_CAP = 10000`, `RETRY = table.freeze({ attempts = 3, base = 0.25, cap = 1 })`.

```lua
function Hiscores.weekKey(unix: number): string
function Hiscores.board(id: BoardId, unix: number): Board

function Hiscores.entryKey(userId: string, board: Board): string
function Hiscores.userIdFromKey(key: string, board: Board): string?

function Hiscores.qualifies(stored: Companion?, attempt: Attempt): boolean
function Hiscores.commit(stored: Companion?, attempt: Attempt): Companion?
function Hiscores.pack(score: number, level: number): number
function Hiscores.retryDelay(policy: Retry, n: number): number?
function Hiscores.attemptDelays(policy: Retry): { number }
function Hiscores.spend(left: number, cost: number): (boolean, number)
function Hiscores.pageAttempt(n: number): number?

function Hiscores.globalName(base: string, scope: string): string

function Hiscores.rankOf(rows: { Row }, userId: string): number?

function Hiscores.fake(): Store
function Hiscores.submit(store: Store, attempt: Attempt, unix: number): { [string]: boolean }
function Hiscores.top(store: Store, id: BoardId, unix: number): { Row }
function Hiscores.drive(io: Io, attempt: Attempt, unix: number, policy: Retry): DriveResult
```

`dayKey` / `weekKey` error when `unix` is not a finite number. They use civil-from-days arithmetic, not `os.date`. Week start is Monday: `(floor(unix / 86400) + 3) % 7` days back, because 1970-01-01 is Thursday. `board("all", _)` has no `period`. Day and week set `period` to that key. `scope` is `"all"` or `id .. ":" .. period`. `cacheKey` is that scope. `entryKey` is the user id, or `userId .. ":" .. period`.

`valid`: `userId` matches `^%-?%d+$` and is not `""` or `"-"`. `score` is a whole number from 0 through the largest integer whose packed form is still below `2^53`: `floor((2^53 - 1 - 9999) / LEVEL_CAP)`. `2^53 - 1` itself does not fit. `level` is a whole number from 1 through `2^53 - 1`, including levels above 9999. `name` is a string. `qualifies` is false when `valid` is false. Nil stored qualifies. Otherwise the new score must be strictly greater, or equal with a strictly greater level. `commit` returns nil when `qualifies` is false and does not mutate `stored`; otherwise it returns a new companion with `cleanName`. `pack(score, level)` is `score * LEVEL_CAP + min(level, 9999)`. The clamp is the ordered integer's tie-break. Do not "fix" a clamped tie by reading a second page. `cleanName` strips controls, trims, cuts to 20 characters, and uses `"Player"` when the result is empty or the input is not a string. `submit` writes `cleanName` only on the boards where `qualifies` is true. A refused write leaves the stored name.

`retryDelay(policy, n)` is nil outside `1..attempts`. Try 1 waits 0. Later tries wait `min(base * 2^(n-2), cap)`. Default delays are `0, 0.25, 0.5`. `spend` returns false and the same `left` when `cost < 1` or `left < cost`.

`rows(pages, lookup, n)` takes a getter `(key) -> (Companion?, err?)` and returns `{ Row }?`: nil as soon as a getter returns an error (that row is unknown, so the board is), never a board with the row left out. `rows` drops a non-positive `n`, a bad entry, a duplicate key (first page wins, even if a later page has a higher score), a nil lookup, a bad level, and a companion whose `userId` is not the key and is not a prefix of the key plus `":"`. Sort score desc, level desc, user id string asc (`"10" < "2"`). Cap at `n`. Rank is the index. Display the page score, not a disagreeing companion score. `rows` never unpacks and does not know `LEVEL_CAP`: its pages are already `scorePage` output. Do not pad. `top` asks the store for `N` and then `rows(..., N)`. `submit` calls `store.set(board, key, pack(score, level), committed)`. `fake().top` keeps those packed integers, orders them descending then key ascending, truncates to `n`, and returns `{ scorePage(<the { key, value } entries>) }`, so its page is exactly what the adapters build from `GetSortedAsync`. `rows` still re-sorts an unpacked page, which is what the in-page string-id tie checks. The one-row page is where the pack shows: `fake().top(board, 1)` for two equal scores returns the higher level's key, not the lesser user-id key.

`drive` loops `all`, `day`, `week`. Per board it keeps `kept` (the companion now stored) and `replaced`. For each delay from `attemptDelays`: wait if the delay is > 0. While `kept` is nil: `spend(budget("get"), 1)` and `spend(budget("set"), 1)` (the companion `UpdateAsync`'s `StandardRead` and `StandardWrite`), or continue; `updateEntry` with a transform that records the row it was given (`seen`) and `commit(seen, attempt)` (`made`), and returns `made`. An error continues. Then `replaced = made ~= nil` and `kept = made or seen`, read from the transform's last call, not from `updateEntry`'s return value; a nil `kept` (nothing stored and nothing committed) ends that board. Then `spend(budget("getSorted"), 1)` and `spend(budget("setSorted"), 1)` (the ordered `UpdateAsync`'s `OrderedRead` and `OrderedWrite`), or continue; `updateScore` with `function(old) return math.max(old or 0, pack(kept.score, kept.level)) end`. An error continues, and the next try runs that same ordered transform and does not call `commit` again. Success sets `wrote[id] = replaced` and ends the board. So a `commit` that returns nil writes no companion and is not retried, but the ordered key is still brought up to the stored row (never above it, and never to the losing attempt's pack): an ordered key whose every retry failed is repaired by the next attempt, even a lower one. The write path never calls `io.get`. Then always `io.top` of the all-time board, even when a `"sorted"` budget would be 0. Companion reads for that page use `get` and `spend(budget("get"), 1)`. A refused budget or a `get` error is an unknown row: the getter returns an error, `rows` returns nil, and `rank` stays nil, so no `ALL-TIME #n` is sent rather than a too-good one (review 004 F2). A `(nil, nil)` get is an absent companion and is skipped. Otherwise `rankOf` the result. An invalid attempt skips the write loop and still calls `top`. The spec doubles call the transform on the row they hold and store whatever it returns; they do no max and no commit of their own.

`pageAttempt(1)` is 10, `pageAttempt(2)` is 50, anything else is nil. `scorePage` maps each `{ key, value }` to `{ key, score = floor(value / LEVEL_CAP) }` (`pack(10, 7)` is score 10) and skips an entry without a whole-number `value`, including one that has `score` instead. It is the only place a packed integer becomes a displayed score. `storeTarget("ordered", board, true)` is `("Hiscores", scope)`. Companion base is `"HiscoreEntries"`. `useScope == false` returns `(globalName(base, scope), "global")` where `globalName` replaces every non-alphanumeric with `_`.

`HiscoreStore.submit(userId, name, score, level, run)` always `task.spawn`s `drive` with that user id, `unix = os.time()`, and `Hiscores.RETRY`; it keeps no record of earlier submits (no `Hiscores.once`, no map by user id and run: every visit is run 1, and a process-lifetime dedupe would drop every later visit). Two submits for one user id and run both drive; `commit` keeps the better row. The spawn is inside `pcall`; failure `warn`s. `budget` maps `get` / `set` / `getSorted` / `setSorted` to `Enum.DataStoreRequestType.StandardRead` / `StandardWrite` / `OrderedRead` / `OrderedWrite` through `GetRequestBudgetForRequestType`. `HiscoreStore.pending(): number` counts submits whose drive has not ended: incremented before the spawn, decremented when the spawned function ends (it runs `drive` and the listener inside its own `pcall`, `warn`s on error, and decrements either way) or when the spawn fails. f0025's close handler waits on it. It does not mention `OrderedList` or `RequestType.GetAsync` or `SetIncrement`. `io.updateEntry` is the companion `UpdateAsync(key, transform)` and `io.updateScore` the ordered `UpdateAsync(key, transform)`, with the transform `drive` passed and nothing else: the source does not contain `Hiscores.commit`, `Hiscores.pack` or `Hiscores.once`. `io.get` is the companion `GetAsync`. Every store call is `pcall`'d and returns its error as the `io` error. The source contains `UpdateAsync` and `GetSortedAsync(false` and does not contain `SetAsync`. `io.top` uses `GetSortedAsync(false, pageAttempt(1))`, and on error once at `pageAttempt(2)`, returns `{ scorePage(pages:GetCurrentPage()) }`, and does not advance the page. Opens go through `storeTarget(kind, board, true)`: `Hiscores` and `HiscoreEntries`, scoped by the board. `listen(fn)` stores one callback; the spawned drive calls it with `(userId, run, rank)` only when `rank ~= nil`. The module does not `FireClient`. The lobby place cannot require this file. `Boards.luau` contains neither `SetAsync`, `UpdateAsync`, nor `HiscoreStore`. `adapter.spec` runs this source under a stub `game` of its own (not `tests/lib/fakeengine`): a `DataStoreService` whose `UpdateAsync` stores what the transform returns, `GetSortedAsync` that can fail, an immediate `task.spawn`, and a fixed `os.time`.

The feature file must not contain the words the architecture spec forbids (`game`, `workspace`, `Instance`, `script`, `Enum`) or `DataStore`, `os.date`, or `os.time`. Callers pass time in.

Add `tests/unit/Hiscores` in the same change as the directory. The architecture spec requires it. Those unit specs may mirror the acceptance cases; the acceptance specs stay under this issue until promotion.

### Scalability
A submit touches three keys, at most three attempts each, then one ordered page of 10 and at most 10 companion reads. It does not scan a maze or step ghosts. `drive` is spawned, so the heartbeat does not wait. `rows` sorts one page, not the whole store. N is fixed at 10. Nothing in this issue replicates.

### Maintainability
A new board id would be a new `BoardId`, a new scope, and one more pass in `submit` / `drive`. Period length is the key function (`dayKey` / `weekKey`), not a branch in the adapter. Store names and budgets are constants and `storeTarget`, so Beta does not grow a prefix. The adapter's only decisions are the enum map, `os.time`, `task.wait`, and `pcall`.

### Usability
Players see a stable row: a worse score cannot erase a name, and an equal score updates only when the level is higher. A score of 0 counts. Studio's negative user ids count. A failed write retries without freezing the overlay (the spawn returns immediately; f0025 relies on that). The developer API is the functions above. `submit` on an invalid attempt returns three falses and writes nothing, so a caller cannot partially store a bad row.

## Acceptance criteria
