# f0026: Hiscore board ui

## Problem
Players need to see the boards (all-time, today, this week) and where they rank, from the lobby and after game over.

## Non-goals
- The mobile layout specifics (f0029). Touch targets stay at `Lobby.BUTTON_MIN_PX` (44).
- The lobby teleport (f0065).
- A second full board in the game place. Game over gains one rank line.
- Submitting a score (f0025). This issue reads, and it displays a rank the server already computed.

## Solution
The lobby panel stays `Lobby.panel` for the all-time board. Pure functions switch it to day and week. The game place pushes an all-time rank line into `Flow` without changing `Flow.overlay`. Both remotes are created at runtime. The raft's Whole-raft design has the data flow; the signatures below are this issue's.

## Design
Add to Hiscores (the module f0024 creates; Lobby and Flow still do not require it):

```lua
Hiscores.CACHE_TTL = 15
Hiscores.READ_GAP = 1
function Hiscores.boardId(raw: any): BoardId?
function Hiscores.lookup(
	cache: CacheEntry?,
	now: number,
	ttl: number,
	lastFetch: number?,
	gap: number,
	inflight: boolean,
	fetch: (() -> { Row }?)?
): (CacheEntry?, number?, { Row }?)
```

`boardId` returns `"all"`, `"day"` or `"week"`, or nil. `"ALL"`, a number, and a table (a client-supplied score) are nil. `lookup` is the raft's cache rule: fresh when `now >= at` and `now - at < ttl` (so `now == at + ttl` refetches), gap blocks a refetch, `inflight` on a stale cache does not fetch and does not move the cache or `lastFetch`, `fetch` nil keeps the same cache and moves `lastFetch`, `{}` is stored as a new cache, a non-number or backwards `now` does not fetch. A successful fetch does not mutate the cache it was given.

Lobby, functions only. `panel` is unchanged, including the cap at `MAX_ROWS` and the empty string `"No scores yet"`:

```lua
function Lobby.board(raw: any): ("all" | "day" | "week")?
function Lobby.boardTitle(id: string?): string
function Lobby.boardPanel(rows: { Lobby.Row }?, id: string?): Lobby.Panel
function Lobby.lines(panel: Lobby.Panel, highlightRank: number?): string
```

`board` matches `boardId`. `boardTitle("day")` is `"TODAY"`, `"week"` is `"THIS WEEK"`, and `"all"`, nil, and anything else stay `"HISCORES"`. `boardPanel` calls `Lobby.panel` and then sets `title`. `lines` returns `panel.empty` when it is set; otherwise `` `{rank} {name} {score} {level}` `` per row, prefix `"> "` when `row.rank == highlightRank`.

Flow, functions only. `overlay` is unchanged, including the game-over detail `` `SCORE %d   LEVEL %d` `` with the three spaces the existing spec pins:

```lua
export type RankView = { over: number, rank: number?, pending: number?, pendingRun: number? }
function Flow.rankLine(rank: number?): string?
function Flow.follow(view: RankView, gameOver: boolean, wasOver: boolean): (RankView, boolean)
function Flow.hearRank(view: RankView, run: number, rank: number?): RankView
function Flow.shownRank(view: RankView, gameOver: boolean): string?
```

`rankLine` is `` `ALL-TIME #{n}` `` for a whole number ≥ 1, else nil. It does not know N, so rank 11 is still a line. The server only `FireClient`s a rank when `rankOf` found the player in the top N; an unknown rank sends nothing. `follow` increments `over` on the false→true edge only and clears `rank` on true→false. On false→true it clears `rank` unless `pendingRun` equals the new `over`, and it clears `pending` when the run does not match. `hearRank` ignores a rank `rankLine` rejects. `run == view.over` (and `over >= 1`) sets `rank`, which is how a packet that arrives while the overlay is up still shows, and also how a packet that arrives after dismiss is stored: `over` is still that run. The next edge clears that stored rank, so it is not shown on the next run. `run == view.over + 1` stores one `pending` / `pendingRun` and does not show it. `run == over + 2` returns the same table. `shownRank` is nil unless `gameOver` is true. Client `over` starts at 0, so the first edge is run 1, matching the server. The game-over bit `FlowView` passes is `overlay.banner == "GAME OVER"`, which f0031 and f0065 both already produce. Do not read `overlay.playAgain` and do not add a field to `overlay`.

`src/lobby/server/Boards.luau`: at `start`, `Instance.new("RemoteEvent")`, `Name = "Board"`, parent `ReplicatedStorage.Remotes`, before any yield. On the server event, ignore a nil `boardId`. One shared cache per `cacheKey(id, os.time())`, one in-flight flag per that key, and a per-player `lastFetch`. `lookup` with `CACHE_TTL`, `READ_GAP`, and the flag. `fetch` is one `pcall` of `GetSortedAsync(false, pageSize)` (page attempts 1 then 2), `scorePage`, companion gets, `rows`. Not `drive`. A second request while the flag is set joins the waiter list and does not fetch. When the fetch finishes, every waiter gets one `FireClient(player, id, rows, highlight, failed)`. Success uses `failed = false`, including a cached empty board. A nil fetch keeps the cache and still answers, with `failed = true` and the previous rows, or `{}` when there were none. The file contains neither `SetAsync`, `UpdateAsync`, nor `HiscoreStore`. `Main` calls `Starts.start()` then `Boards.start()`. `Starts` does not require Boards and does not mention `DataStore`.

`src/server/Ranks.luau`: `Instance.new("RemoteEvent")`, `Name = "Rank"`, parent the game place's Remotes, before any yield. `HiscoreStore.listen` resolves the player from the user id and `FireClient`s only when `player.Parent ~= nil`. No `OnServerEvent`, no `FireServer`. Game `Main` calls `Ranks.start()` before `Sessions.start()`.

`LobbyView.start` keeps WaitForChild of `StartGame` and `Status`. It `FindFirstChild("Board")` and, only when that is non-nil, binds `OnClientEvent` and `FireServer("all")`. It must not `WaitForChild("Board")`: the f0061 fake has no Board remote and boots the empty panel (`Title` `"HISCORES"`, `Rows` `"No scores yet"`). Draw with `boardPanel` and `lines`. When the payload's `failed` is true, one `task.delay(READ_GAP)` then `FireServer("all")` again. A payload that is not a failure does not schedule that. Day and week controls are extra instances, at least 44 px, and they `FireServer` only `"day"` or `"week"`. The start button's `:FireServer()` stays empty. Do not add Board to `lobby.project.json`.

`FlowView` keeps `:FireServer()` with no arguments (f0031). `FindFirstChild("Rank")`, not `WaitForChild("Rank")`. `OnClientEvent` calls `hearRank`. `show` passes `overlay.banner == "GAME OVER"` into `follow` and `shownRank` and sets a label from the line. Do not edit `src/client/Main.client.luau` (it still calls `Flow.overlay` and must not mention `Rank`). Do not add Rank to `default.project.json`. f0065's sequestered place spec lists the project remotes and would go red if Rank were one of them.

The lobby and the game place share the DataStores because they are one experience (decision 8). Boards opens them with `Hiscores.storeTarget` and the same names. It does not require `src/server/HiscoreStore.luau`, which is not in the lobby place.

### Scalability
A lobby read is one ordered page of 10 plus at most 10 companion gets, and only when the shared cache is stale, this player is outside the 1 second gap, and no fetch for that key is already in flight. Waiters share that fetch. A fresh cache does no store call. The rank packet is one `FireClient` of two numbers per qualified run, and only while the player is parented. No per-frame store read. The overlay math is a couple of integer compares per `show`.

### Maintainability
Another board id is a `boardId` arm, a title in `boardTitle`, and a button that sends that string. The cache key already includes the period, so a new period rolls over without a new table. `Flow.overlay` stays the phase switch it is; the rank line is a separate function, so f0031's detail string does not grow a rank. Adapters do not format rows or decide freshness.

### Usability
The lobby still opens on HISCORES and "No scores yet" until a board arrives. A failed first read still answers, so the panel can show that empty line and the client asks for `"all"` once more after the gap. A healthy empty board does not keep asking. Day and week are explicit titles, TODAY and THIS WEEK. The player's own row is marked by rank, not by a name the client could fake. Game over keeps SCORE and LEVEL, and adds `ALL-TIME #n` only when the server has a rank for this run. A rank that arrives after the overlay closes is not shown on the next run. A packet that arrives before the overlay is held and shown when the overlay appears. An unknown rank leaves the line blank rather than inventing a place. Buttons stay at least 44 px.

| Garbage is not a board id | lobby :: client score; read :: `boardId(5000)` | coerce a number with `tostring` | reasoned: the spec asserts nil for a number and a table. The function is new, so there is no body to mutate in the repo |

### Judged
None.

### Observed

On the game-over overlay, `ALL-TIME #n` is shown when the score is in the top 10. A score that does not qualify leaves the previous row, and a rank outside the top 10 leaves the extra line blank.
