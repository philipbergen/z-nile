# f0065: Game over returns to lobby

## Problem
The game place hosts the game, and the lobby (R0024, f0061) is where the hiscore list and the start button are. User, 2026-10-02: at game over, "an overlay shows the game results and waits for a tap before teleporting back to lobby". Today (R0015, f0031, built) game over offers PLAY AGAIN inside the game place; there is no way back to the lobby.

## Non-goals
- The lobby, its start button and the teleport into the game place (f0061).
- Hiscore submission and the board (R0011).
- Publishing both places and configuring their ids (c0064).

## Solution
_Draft ideas; design happens in ticket-prep._
- The game-over overlay (Flow, R0015) shows the results (score and level) and a tap-to-continue prompt, which replaces PLAY AGAIN; a tap, a click or Enter sends one payload-free intent to the server.
- The server accepts it only at game over (Logic decides, as for play again), then teleports the player to the lobby with the same `Travel` rules as f0061 (one request at a time, timeout, cool-down). The lobby's place id is configuration on the game place, like the game place's id on the lobby.
- Needs c0063 done (it narrows the promoted specs of f0031 that pin PLAY AGAIN) and f0061 (the lobby exists to go back to). R0015 is built, so it can be prepped now, as its own raft, reading the overlay's code.
