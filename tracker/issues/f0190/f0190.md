## Problem
Ghosts have to move through the maze the classic way:
- At each tile they choose the exit that minimises the straight-line distance to their target tile.
- They never reverse on their own.
- Each of the four has its own target in chase mode: Blinky, Pinky, Inky and Clyde.

## Non-goals
- The mode schedule (f0200), the house (f0210) and collisions (f0220); there is no ghost *state* yet, only the pure pieces a ghost is steered with.
- Cruise Elroy, and the arcade's overflow bug in Pinky's and Inky's target when the player faces up: both are left out on purpose (R0100 Theme; recorded in `tracker/game-design.md`).

## Solution
A pure `Ghosts` feature with the targeting function of each personality, classic tie-breaking (up, left, down, right), a rail walker for whole sub-tile units, and the classic layout's ghost data. Property specs: never an illegal U-turn, always a legal tile.

## Design
### Files and API
- `src/shared/Logic/Ghosts/init.luau` (new): the public API below; later issues add the set, the modes, the house and the contacts to the same file.
- `src/shared/Logic/Ghosts/Classic.luau` (new): per layout id the start tiles and headings (used from f0200), the scatter corners, the no-up junctions, the door column (`exitX`) and the door row (`doorY`). A maze with no entry has no ghosts.
```lua
export type Name = "blinky" | "pinky" | "inky" | "clyde"
export type Walker = { tile: Maze.Tile, heading: Maze.Heading, progress: number }   -- progress: whole units 0..119 toward the next tile
export type Chase = { player: Tile, heading: Heading, blinky: Tile, self: Tile }
export type Opts = { noUp: boolean?, house: boolean? }
Ghosts.NAMES: { Name }                       -- "blinky", "pinky", "inky", "clyde": a fixed order everything else follows
Ghosts.available(m): boolean                 -- does the maze have ghost data
Ghosts.noUpTiles(m): { Tile }                -- classic: (12,11) (15,11) (12,23) (15,23); other mazes {}
Ghosts.scatterTile(m, name): Tile            -- corners: blinky (25,-3), pinky (2,-3), inky (27,31), clyde (0,31); errors "no ghost data"
Ghosts.chaseTarget(m, name, c: Chase): Tile
Ghosts.pickExit(m, tile, heading, target, opts?): Heading
Ghosts.walker(tile, heading): Walker         Ghosts.occupied(w): Tile     Ghosts.position(w): (number, number)
Ghosts.walk(m, w, speed, decide: (Tile, Heading) -> Heading): { Event }   -- Entered{x,y}, Wrapped
Ghosts.tunnel(m, tile): boolean              -- the six tiles at each edge of a row that wraps
```
- **Targets**: Blinky the player's tile; Pinky `player + 4 * heading`; Inky `2 * pivot - blinky` with `pivot = player + 2 * heading`; Clyde the player's tile when `(dx^2 + dy^2) > 64` (more than 8 tiles) and his scatter corner otherwise. Targets may lie outside the maze.
- **`pickExit`**: from the exits of `tile` (passable for a ghost; the door and house tiles only with `opts.house`), drop the reverse of `heading`, drop north on a no-up junction when `opts.noUp`, and take the one whose neighbour (unwrapped, so a tunnel does not change the distance) has the smallest squared distance to `target`; ties go to the first of north, west, south, east. If nothing is left, the reverse (a dead end); if even that is closed, `heading` unchanged.
- **`walk`**: moves `speed` whole units. At every centre it stands on or reaches (`progress == 0`) it calls `decide(tile, arrivalHeading)` exactly once and adopts the result; crossing a tile edge uses `Maze.neighbor` (so tunnels wrap) and records `Wrapped`; `Entered` is reported when the occupied tile (the nearer centre) changes. `speed` must be below `Movement.UNITS` (120), which `Levels.ghostSpeed` guarantees.

### Pure/adapter split and authority
All of it is pure Logic: no engine access, no clock, no randomness. Nothing is replicated (that is f0310). The server's authority comes in with f0220.

### Scalability
`pickExit` looks at four neighbours; `walk` does one decision per tile (about 4 per second per ghost at level 1) and allocates one small list per decision. Four ghosts per maze, one maze per player: far below the budget of a tick (measured 2,500 ticks x 4 ghosts x 20 seeds in the legality spec in about a second).

### Maintainability
A new maze gets ghosts by adding one `Classic` entry (starts, corners, no-up tiles, door column and row); a new personality is one branch of `chaseTarget` plus its name in `NAMES` and its data. Behaviour is table-driven where it can be (corners, no-up tiles, tie order).

### Usability
For the developer: a handful of small pure functions with plain tables, no hidden state; `pickExit` always returns a heading. For the player (it is what makes ghosts feel like Pac-Man): the classic tie order and no-up junctions are what make the four ghosts' paths recognisable.

## Unknowns & experiments
Run in prep on the raft's prototype (`tracker/rafts/R0100/experiments/prototype.patch`):
- **E1** Are the classic no-up tiles junctions with a north exit for ghosts? **Pass**: (12,11) and (15,11) are `empty`, (12,23) and (15,23) are `pellet`, each with exits N, E, W.
- **E2** Does a steered ghost stay legal on the classic maze? **Pass**: 20 seeds x 4 starts x 2,500 ticks with changing targets: no wall, door or house tile, no reversal (the property spec).
- **E3** Does a decision happen exactly once per centre for speeds that do not divide 120? **Pass** for 7, 28, 30, 45 and 120.
- **E4** Do union-typed loops type-check in strict mode? **Fail as written, fixed**: Luau infers `string` for `for _, h in ORDER`; the repository's idiom (annotate the loop variable, `for _, h: Maze.Heading in ORDER do`) fixes it. The executor should follow it.

## Acceptance criteria

### Checked
- **AC1**: each ghost scatters to its own corner and chases as its personality says (Blinky, Pinky, Inky, Clyde), and the classic no-up junctions are the documented four.
- **AC2**: a ghost takes the exit closest to its target in a straight line, ties up-left-down-right, never turns back unless dead end, never up on a no-up junction, never into the door or house unless told.
- **AC3**: walking is whole units along the rails with one decision per centre, wraps through tunnels, never leaves legal tiles, never turns back by itself, and is deterministic.
- **AC4**: the architecture rules hold (Logic is pure, every require declared in `tracker/architecture.md`, every feature has unit specs).

### Judged
None.

### Observed
None (pure Logic).
