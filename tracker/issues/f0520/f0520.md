# f0520: Slow game speed

## Problem
The game is too fast: level 1 runs at 7.5 tiles/s with a 0.8 s turn buffer, which is hard to play in first person. The user wants **everything in game time slowed by 50%** (2026-10-01): movement, the turn buffer, and, as they arrive, the ready/dying/clear pauses, the eating pause and the frightened time all take twice as long in real time.


## Non-goals
- Changing any Logic rule or any tick-pinned spec, including R0090's prepped specs (speeds in units per tick, pauses in ticks): they stay as designed.
- Per-level speed tables (R0090) and ghost speeds (raft d): they scale with game time automatically.

## Solution
_Draft ideas; design happens in ticket-prep._
Slow the **clock**, not the rules. Keep `Session.TICK_RATE = 30` as ticks per *game* second and add a game-speed factor 0.5, so the server steps 15 times per real second (`Session.STEP_RATE`) and the client interpolates over 1/15 s. Only the two consumers change (`src/server/Sessions.luau` creates the clock with the step rate; `src/client/Camera.luau` interpolates with it). The promoted clock spec's `newClock()` default stays 30. Record the new feel in `tracker/game-design.md` (level 1 becomes 3.75 tiles/s in real time) as a user decision.
