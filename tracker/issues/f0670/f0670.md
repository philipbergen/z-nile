# f0670: Game place teleport

## Problem
The experience is a single place that hosts the game. The user wants it split in two: a new place that hosts the actual game, and the current place becoming the lobby, which shows a hiscore list and a "Start game" button. Clicking the button teleports the player to the game place. Today there is no lobby, no second place, and no way to move a player between places.

## Non-goals
- The hiscore storage, submission and board contents (R0110: f0230, f0240, f0250). The lobby only hosts the board; its data and UI belong to those issues.
- Teleporting back to the lobby after game over (to be decided in prep).
- Matchmaking, parties and private servers.

## Solution
_Draft ideas; design happens in ticket-prep._
- Two places in one experience, each built from its own Rojo project (a lobby project and a game project), published by CI to its own place ID, for Beta and production separately.
- The lobby: a screen with the hiscore list and a "Start game" button (client UI), and a server handler that teleports the requesting player with `TeleportService`. The destination place ID is configuration, not hard-coded.
- The game place: what the current place does now, started on arrival (the existing `Ready` handshake).
- Open for prep: teleport failure handling and retry, whether the game place needs the player's display name or anything else passed in teleport data, how Lune tests cover the lobby and teleport logic (a pure decision in Logic, `TeleportService` in an adapter), how Beta and production place IDs are configured, and what shares the code between the two places.
