# R0011: Hiscores

## Theme

These three issues are one feature: the server records a run, and the lobby shows it. Game design, quoted:

> Hiscores: A **global all-time top N**, plus **daily** and **weekly** boards. No personal-best feature for now.

> **Boards:** all-time top N (N **(prep)**, e.g. 50), plus daily and weekly boards keyed by UTC period.
> **Entries:** the player's Roblox display name and user ID, the score and the level reached.
> **Submission:** only the server submits, from its own simulated result, at game over. Clients never send scores.
> **Storage:** behind a Logic-facing interface. A fake store is used in tests, and Roblox's ordered store in the adapter. Beta and production have separate stores, because they are separate experiences.

> The **lobby** (the existing place, the experience's start place) shows a hiscore list and a START GAME button… The hiscore list is an empty panel until R0011 fills it. … At game over an overlay shows the results and waits for a tap, then teleports back to the lobby (f0065, after c0063).

Prep decisions, fixed here (a later veto can change them; execution does not reopen them):

1. **N = 10**, the same number as `Lobby.MAX_ROWS`. Do not change `Lobby.MAX_ROWS`. The "(prep), e.g. 50" is settled at the panel's existing cap.
2. **One row per user id per board.** A submit replaces that row only when the new score is strictly greater, or the score is equal and the level is strictly greater. Otherwise the stored row stays, including its display name. The name is written only when the row is replaced.
3. **Daily key** is the UTC date `YYYY-MM-DD`. **Weekly key** is the Monday of that UTC week, also `YYYY-MM-DD` (Monday-start). All-time has no period. This is the "keyed by UTC period" line.
4. **OrderedDataStore stores an integer only.** A companion DataStore stores `{ name, userId, level, score }` under the same key. Both sit behind one injected store. Specs use the in-memory fake. No spec calls a live DataStore or the network. This is the "Logic-facing interface / fake in tests / ordered store in the adapter" line.
5. **Board ids** are `"all"`, `"day"` and `"week"`.
6. **The server submits once per run** when its own session emits `GameOver`, using the score and level on that event, including if the player has disconnected. The next visit is a new `Ready` and a new run. While a play-again handler is still in this place it may submit again, and f0065 may delete that handler. A failed write retries with a small bounded backoff and never blocks the overlay. The client never sends a score. A remote that accepts a score is out of design. This is "only the server submits… Clients never send scores."
7. **The lobby's existing hiscore panel shows the all-time board** (`Lobby.panel`). The lobby can switch to day and week through a pure function; the adapter draws it. The game-over overlay gains the player's all-time rank as an extra line when the server knows it. There is no second full board in the game place. The lobby teleport is f0065, not this raft. This is "the hiscore list is an empty panel until R0011 fills it" and the overlay sentence, without taking f0065's teleport.
8. **No environment prefix.** Beta and production are different experiences, so they already have different DataStores ("separate stores, because they are separate experiences"). The lobby place and the game place are the same experience and share the stores: the game place writes, the lobby reads.

Personal bests stay out (the table says no personal-best feature).

`src/shared/Logic/Hiscores/init.luau` is the public API. The store is a parameter. The feature directory's callers require the directory, not a child module.

Types the module exports:

```lua
export type BoardId = "all" | "day" | "week"
export type Board = { id: BoardId, period: string? }
export type Attempt = { name: string, userId: string, level: number, score: number }
export type Companion = { name: string, userId: string, level: number, score: number }
export type Row = { rank: number, name: string, userId: string, score: number, level: number }
export type PageEntry = { key: string, score: number }
export type Page = { PageEntry }
export type Store = {
	get: (board: Board, key: string) -> Companion?,
	set: (board: Board, key: string, score: number, entry: Companion) -> (),
	top: (board: Board, n: number) -> { Page },
}
export type Io = {
	get: (board: Board, key: string) -> (Companion?, string?),
	updateEntry: (
		board: Board,
		key: string,
		transform: (Companion?) -> Companion?
	) -> (Companion?, string?),
	updateScore: (board: Board, key: string, packed: number) -> (number?, string?),
	top: (board: Board) -> ({ Page }?, string?),
	budget: (op: string) -> number,
	wait: (seconds: number) -> (),
}
export type Retry = { attempts: number, base: number, cap: number }
export type RunState = { run: number, done: { [number]: boolean }, waited: number, drop: boolean }
export type Submission = { score: number, level: number, run: number }
export type StepEvent = { kind: string, score: number?, level: number? }
export type CacheEntry = { at: number, rows: { Row } }
export type DriveResult = { wrote: { [string]: boolean }, rank: number? }
```

Constants: `N = 10`, `ORDERED_STORE = "Hiscores"`, `COMPANION_STORE = "HiscoreEntries"`, `LEVEL_CAP = 10000`, `RETRY = { attempts = 3, base = 0.25, cap = 1 }` frozen, `LEAVE_STEPS = 45`, `CACHE_TTL = 15`, `READ_GAP = 1`.

Period and store (f0024): `dayKey`, `weekKey`, `board`, `scope`, `cacheKey`, `entryKey`, `userIdFromKey`, `cleanName`, `valid`, `qualifies`, `retryDelay`, `attemptDelays`, `spend`, `pageAttempt`, `scorePage`, `globalName`, `storeTarget`, `rows`, `rankOf`, `lobbyRows`, `fake`, `submit`, `top`, `drive`. `os.time` is not called here. Civil dates are arithmetic (Howard Hinnant `civil_from_days` / `days_from_civil`), so a host zone cannot move the key. `1970-01-01` is Thursday, so days since Monday are `(floor(unix / 86400) + 3) % 7` (Lua `%` is floored, so negative instants work).

Keys: all-time key is the user id string. Day and week keys are `userId .. ":" .. period`. The OrderedDataStore **scope** is `Hiscores.scope(board)` (`"all"`, `"day:YYYY-MM-DD"`, `"week:YYYY-MM-DD"`) because an ordered store cannot prefix-filter. The key still carries the period suffix. Companion key and scope match. `GetSortedAsync` page size is `pageAttempt(1) == 10`, and on error one retry at `pageAttempt(2) == 50`. Map the page field `value` to `score` with `scorePage`. Do not call `AdvanceToNextPage`. If a scope is rejected, `storeTarget(kind, board, false)` is `globalName(base, scope)` with scope `"global"`.

`rows` keeps the first occurrence of a key, skips a missing or mismatched companion (`key == userId` or `key` prefixed by `userId .. ":"`, so `"15"` does not match user `"1"`), sorts by score desc, level desc, user id string asc, and caps at `n`. Ranks are `1..#result`. The displayed score is the page score. A page shorter than `n` is not padded. Do not fetch another page to rescue a tie: the ordered integer already carries the level. `pack(score, level)` is `score * LEVEL_CAP + min(level, 9999)`. A score whose packed value is not an integer below `2^53` is invalid. Levels past 9999 stay on the companion for display and clamp in the integer; two clamped levels tie by user id. `scorePage` unpacks `value` into the displayed score before `rows`. `fake().top` sorts by that packed integer descending, then key ascending, and returns one page of unpacked `{ key, score }`. `rows` of an already-unpacked page does not look at the packing.

`commit(stored, attempt)` returns nil when the row must not change, and does not mutate `stored`. Otherwise it returns a new companion. That function is the companion `UpdateAsync` transform, and the transform does not yield. The ordered `UpdateAsync` stores `math.max(old or 0, pack(committed.score, committed.level))`, not `SetAsync`. Only the score `commit` accepted is packed into that update. If the ordered update fails, retry it with the same packed score and do not run `commit` again. `UpdateAsync` spends a read and a write: `spend` must accept both or the call is skipped. `GetSortedAsync(false, pageSize)` is descending. Page size stays `pageAttempt` 10 then 50.

`drive` re-reads `io.budget` through `spend(budget, 1)`. Ops: `"get"` read, `"set"` companion write, `"setSorted"` ordered write. An update calls `spend` twice, once for each of those, and skips the call if either refuses. It does not ask for a list budget. `Enum.DataStoreRequestType.OrderedList`'s budget query is documented to return 0, so gating the top read on it would hide every board. A failed or nil `io.top` leaves `rank` nil. Writes may still have succeeded. Budget 0 on `"get"` or on the matching write does not call `updateEntry` or `updateScore`, and the non-zero delays still pass to `io.wait`. A failed update retries; `commit` returning nil stops that board without a retry and without an ordered write. Boards are independent. An invalid attempt writes nothing and still calls `top`. The in-memory double applies `commit` inside `updateEntry`, so a second drive cannot publish from a snapshot taken before that call returns.

Run policy (f0025), same module: `once`, `newRun`, `onAgain`, `leave`, `onStep`. The run id is not client-supplied and is not `Session.tick` (`playAgain` does not reset `tick`, and `tick` advances on every step). The adapter holds `RunState`, starting at `newRun()` (`run = 1`) when `Session.new` runs on Ready. A rejoin's Ready creates a new session and a new run; it does not alias a parked one, so two runs for one user id can submit. While a play-again handler exists, it calls `onAgain` only when `Session.playAgain` returns true. f0065 may delete that handler. `once` copies `done` before writing. `onStep` looks only at `event.kind == "GameOver"` (capital G), ignores any `event.run`, and submits the first scored GameOver of that run. A GameOver without score or level sets the "saw over" flag (so a disconnect drops) and does not submit. `onStep` runs only on the events `Session.step` just returned, inside the `Session.advance` loop, including when that loop steps up to five times in one frame. `advance` returning 0 does not move `waited`.

`leave(steps, sawOver)` is `"drop"` when `sawOver` or `steps >= LEAVE_STEPS`, else `"keep"`. `LEAVE_STEPS` is the classic dying pause copied as a number (`Game.CLASSIC_CONFIG.dyingTicks` is 45). Hiscores does not require Game. `onStep` increments `waited` when `here` is false. At 45 steps away with no GameOver, drop without a submit (a disconnect during play is not kept for the whole run). GameOver while away submits, when `once` allows, and drops.

Read policy (f0026), same module: `boardId` returns `"all" | "day" | "week"` or nil. Numbers and tables are nil, not coerced. `lookup(cache, now, ttl, lastFetch, gap, inflight, fetch)` : a fresh cache (`now >= at` and `now - at < ttl`) returns the rows and does not move `lastFetch`. `now == at + ttl` is stale. Stale and inside the gap returns nil rows and does not fetch. Stale and `inflight` does not fetch and does not move the cache or `lastFetch`. Stale, not in flight, and past the gap calls `fetch`. `nil` means failure: `lastFetch` becomes `now`, the previous cache object stays, and the rows result is nil. `{}` is an empty board and is cached. A successful fetch returns a new cache and does not mutate the one it was given. A non-number `now`, or time moving backwards, does not fetch.

Lobby, new functions only (`Lobby.panel` unchanged):

`lines` returns `panel.empty` when set, otherwise one line per row, `` `{rank} {name} {score} {level}` ``, with `"> "` on the highlighted rank. The highlight is a rank the server sends, not a name match.

Flow, new functions only (`Flow.overlay` unchanged, including `` `SCORE {n}   LEVEL {level}` ``):

```lua
export type RankView = { over: number, rank: number?, pending: number?, pendingRun: number? }
function Flow.rankLine(rank: number?): string? -- whole number >= 1 -> `ALL-TIME #{n}`, else nil. Do not cap at N.
function Flow.follow(view: RankView, gameOver: boolean, wasOver: boolean): (RankView, boolean)
function Flow.hearRank(view: RankView, run: number, rank: number?): RankView
function Flow.shownRank(view: RankView, gameOver: boolean): string?
```

`follow` increments `over` only on the false→true edge and clears `rank` on true→false. On false→true it also clears `rank` unless `pendingRun` equals the new `over`, and it clears `pending` when that run does not match. `hearRank` ignores a rank `rankLine` rejects. `run == view.over` and `over >= 1` sets `rank`, including a packet that arrives while that overlay is still up. `run == view.over + 1` stores one `pending` / `pendingRun` and does not show it. Any other run, including `over + 2`, returns the same table. After dismiss, `over` is still the run that just ended, so a late packet for that run looks current and is stored; the next false→true edge clears it because `pendingRun` is not the new `over`. `shownRank` returns the line only while `gameOver` is true. `FlowView.show` passes `overlay.banner == "GAME OVER"` as that bit. The client counter starts at 0 and becomes 1 on the first game over. The server run starts at 1. They meet.

Server adapters, thin:

- `src/server/HiscoreStore.luau` (game place only). `submit(userId, name, score, level, run)` records `Hiscores.once` for that user id and run, then `task.spawn`s `drive` so the heartbeat never waits. `pcall` and `warn` on failure. `budget` maps `"get"` → `StandardRead`, `"set"` → `StandardWrite`, `"setSorted"` → `OrderedWrite`. It does not read `OrderedList` or the legacy `GetAsync` / `SetIncrement` request types. Companion and ordered writes are `UpdateAsync`. The companion transform is `Hiscores.commit`. The ordered transform is `math.max(old or 0, Hiscores.pack(...))`. `GetSortedAsync(false, pageSize)` asks for descending order. The source contains `UpdateAsync` and `GetSortedAsync(false` and does not contain `SetAsync`. `wait` is `task.wait`. `listen(fn)` sets the one callback used when `rank ~= nil`; the callback receives `(userId, run, rank)`. `read` is not required on this module: the lobby cannot require `src/server`.
- `src/server/Ranks.luau` creates `RemoteEvent` named `Rank` under `ReplicatedStorage.Remotes` at `start`, parents it before any yield, and `HiscoreStore.listen`s to `FireClient` only when `player.Parent ~= nil`. No `OnServerEvent`. No `FireServer`. `src/server/Main.server.luau` calls `Ranks.start()` before `Sessions.start()`.
- `src/lobby/server/Boards.luau` creates `RemoteEvent` named `Board` the same way. `OnServerEvent(player, raw)` keeps the request only when `Hiscores.boardId(raw)` is non-nil. One shared cache per `cacheKey`, one in-flight fetch per that key, and a per-player `lastFetch`. `lookup` with `CACHE_TTL`, `READ_GAP`, and the in-flight flag. The fetch is one `pcall`'d `GetSortedAsync(false, ...)` (then the page-size fallback), not `drive`. Waiters do not start a second fetch. When it finishes, every waiter gets one `FireClient(player, id, rows, highlight, failed)`. Success, including an empty board, uses `failed = false`. A nil fetch keeps the previous cache and still answers: previous rows, or `{}` when there were none, with `failed = true`. The file contains neither `SetAsync`, `UpdateAsync`, nor `HiscoreStore`. `src/lobby/server/Main.server.luau` calls `Starts.start()` then `Boards.start()`. It draws `Lobby.boardPanel` and `Lobby.lines`. It `FireServer("all")` when the remote exists. A payload with `failed == true` schedules one `task.delay` of `READ_GAP` and then `FireServer("all")` again. A healthy payload does not. Day and week are further buttons, at least `Lobby.BUTTON_MIN_PX` tall. Extra children are fine. The START GAME `FireServer()` stays argument-free.

Every `:FireServer()` stays `:FireServer()`. Do not `WaitForChild("Rank")`. Do not edit `src/client/Main.client.luau`. Do not add a `gameOver` field to `Flow.overlay`.

`Sessions` keeps the promoted source pins: one `Session.newClock(Session.STEP_RATE)`, `Session.new` ending `Session.GAME_CONFIG)`, `FireClient` of `Session.frame`, no `Session.snapshot(`, no `PlayerAdded`, no `TICK_RATE`, no lowercase `gameover`, no `.phase`. ## Risks & rollback

- A live OrderedDataStore can reject scope or page size 10. The fallbacks are `storeTarget(..., false)` and `pageAttempt(2)`. They are pure and specified; they were not opened against Roblox.
- `OrderedList`'s budget read is documented as 0 and was not confirmed on a server. Gating on it would blank the rank. The design does not gate.
- The rank packet can beat the client's overlay edge. `hearRank` holds one pending run, and only `over + 1`. A packet that arrives after dismiss is cleared on the next edge, so it does not label the next run. A second early packet for `over + 2` is ignored.
- Disconnect during play, more than 45 steps before GameOver, does not submit. That is the bound. The player leaves `sessions` immediately, and the parked session keeps stepping inside `Session.advance` until `onStep` returns `drop`. Counted in steps, not frames, a disconnect at the start of the dying pause still reaches GameOver.
- Runtime remotes exist only after the server script runs. `FindFirstChild` misses them in the f0061 fake, and the panel stays the empty state that spec already requires. In a published place the server script runs first; OC1 is the check that the lobby actually fills.
- f0065 is not in this raft. Do not edit its acceptance spec. Keeping Rank out of `default.project.json` leaves its remote list intact.
- Rollback is reverting the PR. Stores already written in Beta remain; they are not read until this code is present. No migration.
