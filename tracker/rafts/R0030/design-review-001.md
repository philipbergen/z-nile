### F6 [medium] AC9's one-line proof still ignores blank diff lines
Where: `tracker/issues/c0083/check.sh:153-173`; c0083 "exactly one removed line… and one added line"
Evidence: removed and added bodies are filtered with `^-[^-]` and `^\+[^+]`. A deleted or inserted blank line is a diff body of `-` or `+` alone, which neither pattern matches, so `nr` and `na` stay 1 while a second line changed. The exact RC0 strings then match, and the code reviewer is told AC9 proved the diff is one line. The same filter hides a body line whose text starts with `-` (`---` in the diff). Headers are already excluded by that shape; blank lines should not be.
Critique: tightening the RC0 string, which this round already did, does not count lines the filter drops. This is the same diff-grep proof as before: it hides a class of body lines by construction.
Consequences: a blank-line edit fails AC9. That is what "no other line" means. The exact old and new RC0 strings stay. c0080's one-line grep stays a substring check only if its filter uses the same full body count.
Recommendation: after dropping `+++`/`---` headers, count every remaining `+` and `-` body line, blanks included, and require exactly one of each, equal to the RC0 strings. Mutant: "RC0 replaced and a blank line deleted".
