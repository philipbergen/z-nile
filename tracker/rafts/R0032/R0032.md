# R0032: Lobby beta publish

## Theme
One chore, c0064: R0024 (f0061) built the lobby place, but Beta publishes only the game place, to the one place it knows. This raft publishes both places of the Beta experience and runs the runtime tests in each. Nothing else in the backlog is adjacent.

Decisions relied on (quoted from `tracker/game-design.md`):
- **Two places** (2026-10-02): "The **lobby** (the existing place, the experience's start place) shows a hiscore list and a START GAME button, and a click teleports the player to the **game place** ... Both places live in the Beta experience (a repo variable for the game place's id); production stays undecided."
- **Deploy**: "A separate, private **Pickman Beta** experience. Every PR that becomes ready for review is published there (last one wins). Production publishing will be decided later."
No product decision is needed: production publishing is out of scope.

## Whole-raft design
```
env (CI vars)  ->  Beta.plan (scripts/lib/beta, pure)
                     legacy: [game -> ROBLOX_BETA_PLACE_ID]                       (no ROBLOX_BETA_GAME_PLACE_ID)
                     split:  [game -> ROBLOX_BETA_GAME_PLACE_ID, LobbyPlaceId = start id,
                              lobby -> ROBLOX_BETA_PLACE_ID, GamePlaceId = game id]
deploy-beta:   for each target: Beta.project(copy, absolute $paths, attributes) -> mktemp -> rojo build
               then for each target: OpenCloud.publish(placeId)  ->  version=N, lobby_version=M
check.yml:     deploy -> comment (version) -> runtime-test -- $VERSION (game place)
                                          -> runtime-test -- --lobby $LOBBY_VERSION (lobby, only if published)
```
New: `scripts/lib/beta.luau`, `tests/runtime/lobby/structure.luau`. Changed: `scripts/deploy-beta.luau`, `scripts/runtime-test.luau`, the beta job, SETUP.md, the testing skill, and two promoted specs narrowed (c0064's Overrides). No `src/` change and no feature edge: `tracker/architecture.md` is unchanged. Interfaces in c0064's Design.

## Order & dependencies
c0064 alone. Its `depends_on: [f0061]` is done. f0065 (R0034, prepped in parallel) reads the lobby's id from `LobbyPlaceId` on the game place; this raft sets it in split mode, so f0065 needs no publishing change of its own (design review 002 F1). The two land in either order: before f0065, the game place carries an attribute nothing reads yet.

## Exit criteria
- RC0: the full gate, c0064's checks and the promotion dry run pass.
- RC1: end to end, `deploy` and `runtime` specs pass three times in a row (ports and fake servers are not flaky).
- RC2: `default.project.json`, `lobby.project.json` and `src` are untouched relative to `origin/main`.
"Done" == `scripts/tracker.sh done R0032` succeeds.

## Risks & rollback
- **The second place is unverified until Beta** (E7): legacy mode means nothing changes until the owner sets the variable; a 403 points at the key's scope.
- **Partial publish**: a refused lobby after a published game leaves the old lobby, which still points at the same game id. The job is red and says what went out.
- **Promoted specs edited**: only the cases listed under Overrides, by narrowing; `c0064/workflow.spec` pins the exact new shape.
- **Size**: about 290 lines of code and docs (the patch) plus about 700 lines of acceptance specs.
- **Rollback**: revert the PR, and unset `ROBLOX_BETA_GAME_PLACE_ID`; the next publish puts the game back on the start place.
