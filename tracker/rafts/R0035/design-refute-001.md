# Refute 001: R0035 (answers to design-review-001)

- F1: fixed: the arrow look no longer replaces the mouse line. Camera keeps `look = View.look(look, delta.X, delta.Y)` verbatim (the line R0012's f0028 `place.spec` guards and pins), and runs the arrow look after it: `steer = View.steer(steer, look, arrows, dt)`, `look = steer.look`. `View.steer(prev, look, arrows, dt)` turns from last frame's result while an arrow is held, so the other input is ignored, and treats any difference between `look` and last frame's result as another look input that takes over a spring. That covers R0012's `Camera.lookBy` with no change to it. Both rafts' Camera pins now hold on the merged code whichever lands first, so no landing order, chore or override is needed. f0104's `place.spec` pins the mouse line before the steer line; R0035 Risks lists every R0012 pin, plus DangerHud (this raft leaves the radar lines alone) and the HudView lives block (the shot bars copy the Lives frame's rect after it is placed). consequences: `View.steer`'s signature and rules changed. `look.spec` was rewritten: it now has cases for input being ignored while an arrow is held, take-over by a yaw or pitch move during a spring (the touch case F1 asked for), and fresh, untouched arguments. Its rows are L4–L9 (new mutant texts), C3 (mouse line dropped) and C4 (steer dropped). `Camera.snap` goes back to `look = View.snap(look)`. `hunt.spec` was updated for the new signature. Mutation check rerun: all killed.
- F2: fixed: new `shots.spec :: a moving player shoots from the tile it holds before this step's move, not after it`. The player runs west from the spawn with row 23's pellets cleared, so there is no eating pause. It fires north on the step that starts 30 units past the junction (12,23) and moves it on to hold 11; the ghost at 12,21 is eaten. The case also asserts the player did move on. consequences: two new mutants, S12 (shoot after `Movement.step`) and S13 (floored position), both killed by this case; Rules rows added; the rule is stated in f0100's Design and the game-design (prep) line.
- F3: fixed, by option (a). `shoot` records `member.shot = { tick, heading }` on a spend (hit or miss), and `Session.frame` carries a fresh copy as `Frame.shot: Session.Shot?`. BlastView draws only when `frame.shot.tick == frame.tick`, so a pause, an empty blaster or a second fire in a tick draws nothing. `BlastView.fire` and the `fired` hook in `Controls.keys` are gone. consequences: a new frame field (JSON-safe, beside `play`, as `f0018/frame` allows). New `shots.spec` cases: "the frame names the latest shot the server took …" (fresh table, tick and heading) and "a fire the server drops leaves the frame's shot alone: none held, a pause, a second fire in a tick". New mutants S14, S15 and V3, all killed. f0100 `place.spec` now pins `frame.shot`, `.tick == frame.tick`, and the absence of `BlastView.fire` and `.shots`. f0104's `place.spec`, Main and Controls drop `fired`. The beam now comes up to one step later than the key press, which is the price of drawing only what the server did.
- F4: fixed (as a decision put to the user): prep keeps the session seed (`player.UserId`, server adapter unchanged, RC2 kept), and f0100's Design and game-design's (prep) line now say plainly that a player's n-th contact eat rolls the same in every game. The question to the user: keep that, or seed each session freshly in `Sessions.luau`, which is one line and would also vary the frightened ghosts' wander. If the user chooses a fresh seed, it is a separate change: R0035 does not take it, because it would turn RC2 and f0100's `place.spec` server pin into exceptions. A Non-goal records that mazes are solo, so per-member streams are out of scope (each member already has its own generator). consequences: none in code or specs.
- F5: fixed: Glows `DisplayOrder = -1`, documented as under the radar (Danger, 0), Flow (0) and the HUD (1). The overlap with the radar is in f0102's Design, with the numbers. f0102's `place.spec` now requires exactly one DisplayOrder in DangerHud, which must be negative, FlowView's to be higher (or unset), and the HUD's to be 1. consequences: the dying fade dims the glows too, as intended. A new mutant G19 (order 0) is killed, and OC1 checks that the radar stays readable over the corner glow. E6 now also covers the negative DisplayOrder (an Observed engine fact, with the stated fallback).
- F6: fixed: `Awareness.Ghost` gains optional `name` and `flash`, copied into `Indicator` and `Glow`; DangerHud passes them from the snapshot and colours with `View.ghostColor(g.name or "", g.look, g.flash == true)`. consequences: optional fields keep `f0033/awareness` and the radar's callers unchanged. New `glows.spec` case: only inky (index 3) and clyde are lit, glows 1 and 2 carry their names and flashes, and a ghost given without them has none. `place.spec` pins `View.ghostColor(g.name`, `name = g.name`, `flash = g.flash` and no `snap.ghosts[`. New mutants G17 (name dropped) and G18 (`snap.ghosts[i]`), both killed.
