# R0036: Narrow key map

## Theme
One chore, c0103. `tests/acceptance/f0014/keys.spec.luau` pins the key map at exactly nine entries, treats Q as unused, and allows only movement intents and Snap. R0035 adds F (Fire) and Q (Drop). That promoted spec has to be narrowed first, or the feature raft turns main red. Nothing else in the backlog is the same edit.

Decisions relied on (quoted from game-design, Ghost hunter tools, 2026-10-16): "F and Q join the key map. c0103 (R0036) narrows the promoted key-map spec first; R0035 does not start until that chore is done."

## Whole-raft design
No Logic module and no adapter. The only edit is `tests/acceptance/f0014/keys.spec.luau`, three changes, and f0014's `check.sh` line that runs it stays:

- `t.expect(n).toBe(9)` becomes `t.expect(n >= 9).toBe(true)`.
- The unused-key list drops `"Q"` and keeps `"E"`, `"w"`, `"Return"`, `"LeftShift"`, `""`.
- The action guard becomes `action == "Snap" or action == "Fire" or action == "Drop" or Movement.isIntent(action)`.

The nine mappings (WASD, arrows, Space) stay. No new key is bound here. Current `View.KEYS` still passes the narrowed spec: it has nine entries, Q is simply no longer asserted nil, and every current action is still a movement intent or Snap.

## Order & dependencies
c0103 alone. No `depends_on`. R0035's f0100 and f0102 depend on c0103, so this raft is done before R0035 starts.

## Experiments phase
None. The file is the whole change, and the assertions above are the pass/fail test.

## Exit criteria
- RC0: the full gate, c0103's checks, and the promotion dry run pass.
"Done" == `scripts/tracker.sh done R0036` succeeds.

## Risks & rollback
- **Too wide a guard**: allowing Fire and Drop means a third new action still fails the guard until a later chore names it. That is the point.
- **Rollback**: revert the PR. The feature raft must not have started; if it has, it is already past this spec.
