### F1 [high] narrowed.spec still passes when every assertion in keys.spec sits inside a `--[[ … --]]` block comment: the normaliser strips only from `--` to the end of the line (fourth hole in the same pin mechanism)
Where: tracker/issues/c0103/acceptance/narrowed.spec.luau `normalised()`, first line (`string.gsub(fs.readFile(FILE), "%-%-[^\n]*", "")`); c0103 E3 ("comments … ignored"), Rules and mutants rows 2 and 3
Evidence: In the scratch clone, with the patch applied, I wrapped each of the five assertion statements in keys.spec (the `want` loop, `t.expect(n >= 4)`, the unbound loop, the `View.KEYS` name loop, the W/A/S/D intent loop) in a line `--[[` before it and a line `--]]` after it, then ran `stylua` (it leaves the block comments alone). The normaliser deletes the `--[[` and `--]]` lines and keeps the commented code, so the normalised text equals the GOLDEN. Luau, though, treats each block as a comment. Then I also changed `src/shared/Logic/View/init.luau` to `W = "Back", Q = "Fly"`. Result: `narrowed.spec` 2 passed, `keys.spec` 3 passed (with no assertions run), 5/5. Wrapping just the `want` loop (W/A/S/D values unchecked) passes the same way. So AC1 ("is exactly the narrowed spec … pinned token for token") is met by a promoted spec that asserts nothing. This is the exact scenario the golden exists for: a later raft, such as f0104, "fixing" a red keys.spec by disabling it.
Critique: Rounds 1, 2 and 3 each found a way to make keys.spec vacuous that the pin missed (weakened assertions, emptied loops, stubbed requires). Each fix widened the pin. This hole is in the one place the golden still discards text: comments. The tempting fix is to forbid the literal `--[[`, which leaves `--[=[` open.
Consequences: the golden's tolerance should be only what formatting can change (whitespace, a trailing comma, compaction ids). Comments aren't formatting. Two forms hold: (a) strip long comments together with their contents before the line-comment strip, so that commenting code out removes it from the normalised text; or (b) stop stripping comments, so the header lines join the GOLDEN (ids are already masked, and the header is part of the patch). Under (a), dropping `--!strict` (a line comment) still goes unnoticed, which costs only the type check. (b) pins it too, but every header-wording edit then needs a golden update, which the header already demands for any change.
Recommendation: Do (a) at least. I ran it: `local text = string.gsub(fs.readFile(FILE), "%-%-%[(=*)%[.-%]%1%]", "")` followed by the existing `"%-%-[^\n]*"` strip. With that, both block-comment mutants fail on the golden assertion, M1, M2, M8, M9, M13, M14, M16, M18 and M20 still fail, the one-line `want` table still passes, the patched keys.spec still passes 2/2, `stylua --check` is clean and `promote-check R0036` is OK. Prefer (b) if you'd rather the pin have no comment exception at all. Then GOLDEN gains the four header lines, split where needed so no `require(` is directly followed by a quote. Add mutants M21 (one assertion loop inside `--[[ … --]]`) and M22 (every assertion inside block comments, with a wrong View) to E3 and Rules and mutants, rows 2 and 3, marked run. State in E3 exactly what the normaliser tolerates and why nothing else, so a round 5 doesn't find another discarded class. Re-run promote-check after the edit.
