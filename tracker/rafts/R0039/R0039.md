# R0039: Linux spec jail

## Theme
A single chore that gives Linux the jail macOS has. Today specs run in a `sandbox-exec` jail on macOS (every write outside `.cache` and the run's temp folder denied by the kernel) and unjailed on Linux, which is CI and any Linux developer, guarded by environment fences that cannot stop `git checkout -- .` or a plain file write (c0075's problem: a shell command through `fixture.exec` can `cd` into the real checkout).

c0075 was prepped as a git shim in R0026 and failed seven design rounds. The user chose a real Linux jail instead (2026-10-18, this prep). No product decision in `tracker/game-design.md` is relied on or changed: this is test tooling, and the only standing rule it serves is the repository-safety rule in `AGENTS.md` ("No check may ever change the real repository"), whose text this raft updates to say the jail is on both platforms.

## Whole-raft design
One member, `c0075`; no `src/` change, no new dependency edge, no `tracker/architecture.md` change.

```
tests/run ──► fence.enter() ──► jail():  macOS  sandbox-exec -p <profile> sweeper bash …
                                          Linux  bwrap <jailArgv(cache, runTemp, rebindPlan(…))> bash …
                                                 │ trial fails → linuxWhy → fallback(outer sandbox probes | refuse)
 REAPER (the launcher) ──► records itself in <lock>/pid-N (PICKMAN_REAP_LOCK): it lives exactly as long as the jail
 lock: under bwrap the top writes <lock>/pidns; guarded processes record pid-N only in the same pid namespace
 scripts/linux-jail.sh ──► (CI step, before setup.sh)  installs bubblewrap; --apply-sysctl lifts Ubuntu's userns restriction
 scripts/lib/fence.sh  ──► no ref hooks under sandbox-exec or bwrap (the kernel denies the writes); fixtures never sign
```
Interfaces (all in `tests/lib/fence.luau`, typed in the issue): `jailArgv`, `trialArgv`, `rebindPaths`, `rebindFor`, `rebindPlan`, `linuxWhy`, `fallback`, `escapePaths`, `leaks`, `networkClosed`, `reads`, `recordsPid`, `pidNamespace`; the launcher program `REAPER` gains the lock record. The macOS branch is refactored only to share its tail with Linux, with its output unchanged.

## Order & dependencies

## Experiments phase
Run in prep, on GitHub's `ubuntu-latest` (Ubuntu 24.04.5): E1 (the jail's guarantees: PASS, after lifting `kernel.apparmor_restrict_unprivileged_userns`), E2 (nesting, INT/TERM/HUP, parent death: PASS), E3 (`scripts/linux-jail.sh` prototype against AC4), E4 (design review round 1: the real launcher with and without `--new-session`, both pass, and host Unix sockets, which the first jail left open and `--tmpfs /run` closes), E8 (round 2: `--remount-ro /run` must come after the binds under `/run`). For the executor: **E5 first**, the whole suite under the jail on CI (`scripts/ci-verify.sh`), with the stop-and-escalate fallback in the issue. The rest is the implementation.

## Exit criteria
RC0 lines (the full gate; c0075's checks AC1 to AC7; `promote-check`), and RC1: `scripts/linux-jail.sh` runs clean on the host that finishes the raft (prints `not Linux` on macOS). "Done" == `scripts/tracker.sh done R0039` succeeds, and the PR's `gate` job (Linux, jailed) is green, which the merge rule already requires.

## Risks & rollback
- **A Linux host that cannot run bubblewrap** (a container without user namespaces, a distribution that disables them) now refuses to run specs unless an outer sandbox provably protects the repository. This is the intended tightening and the same rule as macOS, but it is the one behaviour change a user will notice. Mitigation: the refusal names `scripts/linux-jail.sh`; the sysctl is never changed without `--apply-sysctl`. An environment opt-out is **not** included; ask the user if wanted.
- **Ubuntu AppArmor** (24.04+) needs `kernel.apparmor_restrict_unprivileged_userns=0` (CI: applied by the script with sudo; a developer machine: told how). A GitHub image change could break the step: the failure is loud (the `gate` job's first step) and the fix is local to the script.
- **Latent Linux-only spec failures** under the jail (E4). Mitigated by running the whole suite on CI first and fixing in the PR.
- **Host sockets** (design review round 1 F4, round 2 F6): those under `/run` and `/tmp` are hidden on Linux; the **macOS** profile leaves them all open, as it always has, and Linux sockets under the home folder (Docker Desktop's) stay reachable: both tracked by the follow-up issue. Handing work to such a daemon from a spec stays on the testing skill's review-only list.
- **Anything a run needs under `/tmp` or `/run`** (checkout, PATH entries on NixOS, `HOME=/tmp/...`) would vanish behind the hiding; `jail()` re-binds it read-only (`rebindPlan`), pinned in AC1.
- **Group signals and TIOCSTI** are closed by `--new-session`, shown compatible with the launcher in E4.
- Rollback: revert the PR; Linux goes back to unjailed.
