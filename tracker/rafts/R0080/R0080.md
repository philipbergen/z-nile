# R0080: Beta deploy

## Theme
Roadmap raft **b**: a ready PR goes live on the private Pickman Beta experience (last one wins), plus engine smoke tests through Open Cloud. It gets later rafts in front of real players, and it's infrastructure, so it's a chore. `tracker/game-design.md` says every PR that becomes ready is published to Beta; production publishing is decided later.

Decisions from `tracker/game-design.md` this raft relies on (quoted):
- **Deploy**: "A separate, private **Pickman Beta** experience. Every PR that becomes ready for review is published there (last one wins). Production publishing will be decided later."
- **Authority**: "The server simulates every maze. Clients send intents and render the replicated state." (the runtime tests check the server side of that in a real server)
- **User decisions (2026-09-30)**: the runtime tests run against Pickman (Beta) itself, not a separate CI experience; the publish route is the request shape of `../karma`'s `make beta`.

## Prep experiment (2026-09-30): PASS, after one correction
Permitted by the user: one test publish to Pickman (Beta) and one trivial Luau execution, through a one-off workflow on a throwaway branch (`experiment/open-cloud-probe`, deleted afterwards).
- **Attempt 1 (run 36790710861)**: `POST .../universes/v1/universes/$U/places/$P/versions` was refused by Roblox's edge (`403 {"code":9009,"message":"WAF Blocked Request"}`). Nothing was published. The cause was **my malformed URL** (a doubled `universes/`), not the runner or the tool. A User-Agent change was (rightly) not tried.
- **The working request**, copied from `../karma`'s `make beta` (the user's pointer): `curl -sS -L -X POST "https://apis.roblox.com/universes/v1/$U/places/$P/versions?versionType=Published" -H "x-api-key: $KEY" -H "Content-Type: application/octet-stream" --data-binary @place.rbxl`.
- **Attempt 2 (run 36793719983, GitHub-hosted ubuntu-latest, Rojo 7.7.0 from its release zip)**: `rojo build` made a 17 KB .rbxl; the publish returned **HTTP 200 `{"versionNumber":5}` in 1 s**; then `POST https://apis.roblox.com/cloud/v2/universes/$U/places/$P/versions/5/luau-execution-session-tasks` with `{"script": "..."}` returned 200 `state: PROCESSING`; polling `GET .../cloud/v2/<path>` reached `COMPLETE` after about 4 s, `output.results[0]` = `ok 2 sss=Server players=0`, logs empty. So a published Rojo build's `ServerScriptService.Server` exists and Luau runs in it.
- **Facts for the designs**: the API key works with both the publish and the execution scopes; a publish replaces what Beta testers play (Beta is now at version 5, a bare build of main at 2973d6c); karma retries HTTP 409 ("Roblox busy") up to 5 times 60 s apart and treats missing config as a green skip; it runs its tests first (`needs: luau-test`) then publishes.

## Whole-raft design
```
 PR ready for review ─▶ .github/workflows/check.yml
                          gate (unchanged: full gate on Linux)
                            └─ needs ─▶ beta (this raft)
                                 scripts/setup.sh --tools          (c0140: toolchain only)
                                 lune run scripts/deploy-beta      (c0140) ── rojo build ──▶ POST …/universes/v1/<u>/places/<p>/versions
                                        └─ outputs version=N  ──▶ gh pr comment (edited in place)       Pickman (Beta) version N
                                 lune run scripts/runtime-test -- N (c0030) ─▶ POST …/luau-execution-session-tasks (tests/runtime/*.luau)
                              both commands use scripts/lib/opencloud.luau (publish, execute, runSuite; HTTP injected)
```
**Interfaces between issues**: c0140 owns `scripts/lib/opencloud.luau` (`Config`, `configFromEnv`, `publish`, the loopback `OPENCLOUD_BASE` seam, the `Http` injection) and the `beta` job; c0030 adds `execute` and `runSuite` to the same file and the last job step, reading the `version` output c0140's `deploy` step writes.

**No new Logic features and no `architecture.md` changes**: everything here is tooling (`scripts/`, the workflow, `tests/runtime`), outside `src/`.

## Order & dependencies
**c0140 → c0030** (c0030 `depends_on: [c0140]`; c0030 also changes the tracker skill's Merging rules to require the `beta` job): the runtime tests need a published version to run against, and they extend c0140's library and job. No other raft blocks it.

## Experiments phase
Run in prep (see the issues): the publish and the Luau execution from a GitHub runner (E1/E1), the library and both commands end to end against a local fake with real Rojo (67 acceptance cases, a 69-mutant check with all killed). A second, read-only probe (user-approved after design review F2; a scratch draft PR, closed and deleted, no publish, Beta unchanged at version 5) proved on a fresh runner: `scripts/setup.sh --tools` works, `lune run scripts/runtime-test -- 5` passes `structure.luau` inside the real server (`(getfenv() :: any).game` works), and `gh pr comment --edit-last --create-if-none` with an Actions token edits in place (one comment). Nothing is left for Phase 1 except the normal red/green loop; the raft's own PR becoming ready is OC1.

## Exit criteria
- `scripts/check.sh --full`, each member's `check.sh` and the promotion check pass (RC0).
- **RC1**: the published version flows `deploy` → PR comment → runtime tests, in that order, in the `beta` job.
- **RC2**: the Roblox API key is named in exactly two places, the `env` of the deploy step and of the runtime-test step, both inside the beta job, and never echoed.
- **RC3**: with nothing configured, `deploy-beta` and `runtime-test` both skip with a warning and exit 0.
"Done" == `scripts/tracker.sh done R0080` succeeds.

## Risks & rollback
- **Beta is replaced on every ready PR push**; the runtime tests run against it. Accepted by the user for now. "Last one wins" means the last to finish the gate, which can occasionally be an older push (the PR comment names the commit); the job's 20-minute timeout bounds how long the shared lock can be held.
- **A failing runtime test turns the job red but Beta has already been published.** Rollback of a bad Beta is the next ready PR, or republishing main by hand (`scripts/deploy-beta` with the three settings).
- **The API key expires** (`ROBLOX_API_KEY` has an expiry): the job then fails with HTTP 401/403 and the message says so; renewing it is a secret update, no code.
- **Roblox's WAF**: refused a malformed request in prep (403 code 9009). If it ever refuses a correct one, the failure shows the status and body; do not work around it (no User-Agent games) without the user.
- **Rollback**: revert the PR; remove the `beta` job and the two scripts; Beta keeps its last published version.
