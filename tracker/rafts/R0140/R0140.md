# R0140: Parallel gate stages

## Theme
Tests and checks run very often, so they must run concurrently and as swiftly as possible, and speed must stay monitored. One chore, c0470, covers it. Product decisions in `tracker/game-design.md` are not touched: nothing under `src/` changes.

The measurements that drive the design (prep, 8-core Mac): the full gate is about 29 s, of which the specs are 27 s and the five static stages 1.8 s serial (1.3 s concurrent). The specs are the bottleneck, so the spec runner is the main change and the gate stages are the small one.

## Whole-raft design
No `src/` module changes and no `tracker/architecture.md` change (no new feature dependency edge).

```
scripts/check.sh --  par.sh  --> stylua | selene | luau-lsp(src) | luau-lsp(tests+scripts) | rojo build   (concurrent, buffered, timed)
        |                                  (all reported, then fail the gate or continue)
        +-- tests (<mode>) --> tests/run  --coordinator--> N lanes --> `lune run tests/run -- --jobs 1 <file>` per spec
                                           merge in sorted order, print `slowest:` then the unchanged summary line
```
Interfaces other code relies on and that stay fixed: the runner's last line `<P> passed, <F> failed, <K> spec files` and exit code, `FAIL <file> :: <case>` lines, the `== <stage>` header texts, `GATE PASSED (<mode>)` as the gate's last line. New: `--jobs N` / `PICKMAN_JOBS`, `par_start` / `par_wait`, `slowest:` and `gate wall time:` lines.

The skills carry the standing rule (testing: a `## Speed` section; execute-raft: record the gate wall time and slowest specs).

## Order & dependencies
Single issue, c0470. No dependency on other issues. It does not depend on c0050 (lifecycle spec clone isolation): the lifecycle spec already owns `.cache/tracker-e2e`.

## Experiments phase
Run in prep, see c0470 Unknowns & experiments: E1 (parallel per-file run, pass), E2 (Lune task concurrency, pass), E3 (`@lune/system`, fail, fallback `sysctl`/`nproc`), E4 (fixtures under `.cache`, pass), E5 (`os.clock` is wall time, pass), E6 (static stages concurrently, pass). Left for the executor's Phase 1: E7 (`perl -MTime::HiRes` on the CI image; fallback in the design), E8 (`rsync` on the CI image, used by AC5; if it is missing, stop and escalate because `check.sh` is sequestered).

## Exit criteria
- RC0: the repo gate passes (full), every member check passes, the acceptance specs survive promotion (generated lines).
- RC1: a full gate run prints the stage times, a `slowest:` line, a `gate wall time:` line, and ends with `GATE PASSED (full)`.
- RC2: the full gate passes three runs in a row (shared-state flakiness would show here), and `PICKMAN_JOBS=1` runs the same suite green (serial fallback intact).

## Risks & rollback
- **Hidden shared state between specs** that the 5 prep runs did not trigger. Mitigations: AC3 (no shared `.cache` dir), AC6 and RC2 (repeat runs at 8 jobs), `PICKMAN_JOBS=1` as an immediate workaround. `.cache/sim` is shared by design (replay files are named per model, seed and tick); a collision would only rewrite an identical file.
- **Rendezvous specs timing out on a very slow CI box** (20 s limit, polling every 50 ms): generous by two orders of magnitude.
- **Fewer than 2 cores**: the default floor of 2 lanes still interleaves (the work is mostly waiting on child processes).
- **`tracker.sh done` and `promote-check` run the runner on file lists**: now concurrent; same summary and exit code.
- Rollback: revert the PR, or set `PICKMAN_JOBS=1` and keep the sequential gate stages.
