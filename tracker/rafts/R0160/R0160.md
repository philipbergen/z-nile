# R0160: Board artifact spec guard

## Theme
Two small process chores, both about trusting the tracker and the gate: **c0450** makes ticket-prep find new issues that override promoted acceptance specs (instead of discovering the clash as a red gate mid-execution), and **c0460** publishes the tracker board as a workflow artifact on every push to `main`. They share no files, only the "tracker process and CI" area, and both are chores (CI and process work is always a chore).

Decisions relied on: none in `tracker/game-design.md` (no game behavior). User decisions of 2026-09-30: the board goes to a **workflow artifact, not GitHub Pages** (the repo is private, Pages from a private repo needs a paid plan and is public by default, and the board shows the backlog and spend); both chores go in **one raft**.

## Order & dependencies
No dependency between the issues; run them in either order (they can be parallel streams). Suggested: c0450 first (text only), then c0460. `scripts/setup.sh` changes under c0460 force a full run of the gate, which both issues need anyway.

## Experiments phase
Run in prep, results are in each issue document (c0450 E1–E2, c0460 E1–E6). Left for execution: none. E3 of c0460 (the workflow on GitHub) can only be proven after merge: OC1. If an experiment fails without a fallback, stop and escalate.

## Exit criteria
- RC0: the full gate, both members' `check.sh`, and the promotion dry-run pass (generated lines).
- RC1: `scripts/setup.sh` is valid shell (`bash -n`).
- RC2: the board builds with the workflow's own command into a fresh directory.
- "Done" == `scripts/tracker.sh done R0160` succeeds. The post-merge observation OC1 (c0460) goes in the final report.

## Risks & rollback
- **A bad workflow runs only on `main`** and can't be tried on the PR. Mitigation: every field that would make it fail is pinned by a spec (token, conditions, runner, concurrency, paths), its inputs follow the documented `upload-artifact@v4` API, and a failed run only affects the board job, not `check.yml`. Rollback: revert the squash commit (one file plus a small `setup.sh` guard).
- **`setup.sh` guard bug** could silently disable the CI gate. Mitigation: a behavioural spec runs the stage with the variable unset, empty and set, another asserts `setup.sh` calls the gate nowhere else, and another asserts no workflow but `board.yml` sets the variable.
- **Doc-text specs are brittle**: a later skill rewrite can break `override-check.spec.luau`; that is fixed through a chore. They aren't selected by `--affected`, only by `--full`/CI.
- **Actions minutes** on a private repo: one extra tool-install run per push to `main`.
