# R0180: Beta poll transient errors

## Theme
Single-issue raft. `beta` (publish to Pickman Beta, then the runtime tests through Open Cloud) is a merge condition since R0080, so a transient Roblox 429 or 5xx must not make it red and block a merge. The user decided (design review F1, 2026-10-01) that the goal covers both halves of `beta`: publish retries 429/5xx as well. It is CI tooling, so it's a chore. No decision in `tracker/game-design.md` is touched; the one relied on is the R0080 one: "Every PR that becomes ready for review is published there (last one wins)."

## Whole-raft design
One module changes: `scripts/lib/opencloud.luau`. `execute` (and through it `runSuite`, used by `scripts/runtime-test.luau`) retries 429 and 5xx via a private `send`, with a per-`execute` cap on total pause time; `publish` (used by `scripts/deploy-beta.luau`) retries 429/5xx too, sharing its `MAX_ATTEMPTS` budget with its 409 retry (60 s pause for 409, 5 s for 429/5xx). Data flow is unchanged: `deploy-beta` -> `publish`, and `runtime-test` -> `runSuite` -> `execute` -> `send` -> injected `request`.

Interfaces (see c0490): `OpenCloud.isTransient(statusCode: number): boolean`, `Config.transientSeconds: number?`, `Config.transientBudgetSeconds: number?`. A doc paragraph in the tracker skill's `beta` bullets says how to recognise and rerun a transient-red `beta`. No `tracker/architecture.md` change: no new dependency edge.

## Order & dependencies
c0490 only. No dependencies. Touches `scripts/`, so the gate runs every spec; it doesn't overlap R0160 (`board`/spec guard) or R0140 (gate stages) files except possibly `.claude/skills/tracker/SKILL.md`, a different paragraph.

## Experiments phase
- **E1 (run in prep, PASS)**: the c0030 and c0140 Open Cloud specs still pass on a prototype.
- **E2 (unproven, offline)**: Roblox's real 429/5xx pattern. Fallback: tune `transientSeconds` or `MAX_ATTEMPTS`.
- **E3 (reasoned)**: a retried creation may run a read-only test script twice, and a retried publish may add a version of the same commit; both harmless ("last one wins").
Nothing for the executor to run first.

## Exit criteria
- RC0 (generated): `scripts/check.sh --full`, c0490's `check.sh`, and the promotion dry run pass.
- RC1: with no key configured, `lune run scripts/runtime-test -- 1` still ends green with its skip warning (the `beta` job on forks and unconfigured machines).
- Done == `scripts/tracker.sh done R0180` succeeds.

## Risks & rollback
- A longer red-to-green wait in `beta` when Roblox is unhealthy. Mitigation: `MAX_ATTEMPTS` per request, a 60 s transient-pause cap per `execute`, and the run-level bound in c0490 Scalability (under the job's 20 minutes for up to 4 runtime scripts).
- A retried creation can duplicate a task, and a retried publish can add a version (E3).
- Prep narrowed one status list in the promoted `tests/acceptance/c0140/publish.spec.luau` (it asserted 429/500/503 final on publish); see c0490 Solution.
- Rollback: revert the PR; nothing persists outside the repo.
