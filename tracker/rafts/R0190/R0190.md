# R0190: Renumber step one

## Theme
A single chore, **c0500**: `tracker.sh renumber` resolves an id collision by moving an item to a new number, and today the Conflicts rule has you compute "the next multiple of 10 above the highest number in both trees", burning ten numbers per collision and leaving a `git ls-tree` recipe to get wrong. The raft makes `renumber <id>` pick one above the highest itself. It is a chore (tracker tooling is always a chore), a `--single` raft.

Decisions relied on: none in `tracker/game-design.md` (no game behavior). Decision taken in prep: with no `<new>` the number advances by exactly one above the highest in the local tree and `origin/main`, as the issue asks.

## Whole-raft design
Tooling only: no `src/` change, no `tracker/architecture.md` change, no new dependency edge.

| path | change |
|---|---|
| `scripts/tracker/store.luau` | new `store.nextAbove(kind, otherIds)`, the number-space rule (reads the local tree through `store.all`, so it fails like `list` on a malformed tree); `nextNumber` untouched |
| `scripts/tracker/main.luau` | `originIds()` adapter (git ls-tree of `origin/main`), `renumber <old> [<new>]`, usage line |
| `.claude/skills/tracker/SKILL.md` | Conflicts bullet |

Data flow: `renumber f0100` reads local ids through `store.all`, origin ids through `git ls-tree -d --name-only origin/main <tracker dirs>`, takes the maximum of that kind plus one, and then runs the existing move-and-rewrite code. Specs build a throwaway git repo (no remote, an `origin/main` ref made with `git update-ref`) and run the CLI in it. A prototype is in `tracker/issues/c0500/experiments/prototype.diff`.

## Risks & rollback
- **Overlap with other work on the same files.** `scripts/tracker/main.luau` is also edited by c0510 (publish tracker state to main; being prepped in `.worktree/prep-publish-state-to-main`, with new `publish.luau` and `status.luau` and edits to `main.luau`), and `.claude/skills/tracker/SKILL.md` likely too. R0160 (c0460, c0480) has merged and is part of the tree c0500 was verified on. The edits here are in different functions or lines (`cmd.renumber`, `USAGE`, one Conflicts bullet), so a git merge should be clean; whichever raft starts second merges `origin/main` first (execute-raft Phase 5) and re-runs the gate. If c0510 reworks `renumber` or the Conflicts bullet (for example by publishing ids at creation, which would make collisions rarer), c0500's design must be revisited: stop and tell the user rather than patch the sequestered specs.
- **A stale `origin/main`** (no fetch) under-counts and can pick a number that exists upstream. `renumber` does not fetch, on purpose; the Conflicts procedure fetches first, and the skill text keeps that step. A collision after a stale pick shows up again as a git `add/add` conflict and one more renumber.
- **Doc-text spec** (`skill-doc.spec.luau`) breaks if the Conflicts bullet is reworded later; fixed through a chore.
- Rollback: revert the squash commit (two scripts and one skill line).
