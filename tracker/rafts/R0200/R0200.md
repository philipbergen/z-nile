# R0200: Publish state to main

## Theme
Several terminals work on this repo at once (prep, capture, execution), and today none can see the others' tracker state until a PR merges. They collide on ids, claim the same issues, and start from a stale `main`. One chore, c0510, makes tracker state visible at once: creation stubs and claims are pushed to `origin/main` as tiny tracker-only commits, items carry a `status`, and every skill syncs before it works.

No product decision in `tracker/game-design.md` is involved (nothing under `src/` changes). The **user's process decisions** this raft implements, from the conversation that captured c0510: a new item is staked on `main` at once with a one-line description; each state change is a small commit pushed to `main`; the states are new, preparing, prepared, active, done (the user's `ready` is the same thing as `design: ready` and is not a separate state); the direct push is limited to tracker state files; skills pull `main` first. The tracker skill's rule "main changes only by PR" gets exactly one documented exception for this.

## Whole-raft design
Single issue; the design is c0510's. Module map (no `src/` change, no `tracker/architecture.md` change because no feature dependency edge changes):
```
scripts/tracker/status.luau   pure rules: states, transitions, effective status, next number
scripts/tracker/publish.luau  adapter: tracker-only commit to origin/main by git plumbing (whitelist, retry)
scripts/tracker/main.luau     commands new, status, sync, start use both
scripts/tracker/store.luau    nextNumber delegates; setFront shares withFront
(the templates do NOT gain a status line: a missing field derives from design)
tests/acceptance/c0041/       one promoted spec replaced by a prepared copy (PICKMAN_PUBLISH=0 in its fixtures)
.github/workflows/check.yml   push ignores tracker/**
.claude/skills/*              Sync and claim section; `tracker.sh sync` first step in six skills
```
Every status write is a stamped `<state>-<three words>` value (the user's decision), so two terminals making the same move conflict in git instead of merging silently. Fixed interfaces: `tracker.sh new` still prints the new document's path; existing commands behave as before when there is no `origin` or `PICKMAN_PUBLISH=0`.

## Exit criteria
- RC0: the repo gate passes (full), every member check passes, the acceptance specs survive promotion.
- RC1: two terminals cannot both claim or start the same item, and a published state move reaches origin (the commands spec, end to end against a bare origin).

## Risks & rollback
- **Rule change**: direct pushes to `main` weaken "everything lands by PR". Mitigation: the whitelist (item documents and `check.sh` only, enforced in code and pinned by spec), documented in the tracker skill; code, designs and reviews never use it.
- **A promoted spec changes**: `tests/acceptance/c0041/worktree.spec.luau` is replaced by the copy prepared in c0510 (`replacements/`), verified byte for byte by AC8; the change only sets `PICKMAN_PUBLISH=0` in its fixtures.
- **A tracker command runs in a directory that lost its `.git`** (it happened during this prep: a spec fixture's `.git` vanished and git used the real repository): every command that is not read-only refuses unless git's repository root is the working directory `tracker.sh` changed into, whatever `PICKMAN_PUBLISH` says, pinned by a commands spec case with an isolated outer repository. The c0510 fixtures also set `GIT_CEILING_DIRECTORIES=<checkout>/.cache`. The spec runner side is c0640's (R0190). Read-only commands are exempt because existing specs run them in `.git`-less sandboxes.
- **Existing draft rafts** (R0100-R0150) have no stored status: they derive `preparing`, so nothing can take their issues, and they are claimed with `tracker.sh status <R-id> preparing`.
- **A prep branch's local `raft:` line** (`tracker: <R> members`) sits beside `depends_on:`, so a capture PR that edits `depends_on` conflicts with it on the prep branch's next sync. This is the loud signal the user asked for, not a silent failure.
- **A direct push is rejected** (protection enabled later, network): `new` and `start` fail closed with git's message; `PICKMAN_PUBLISH=0` restores the old local flow.
- **A published `status:` edit conflicts with a branch edit of the same line**: kept apart by placing `status:` after `created:` and by merging `origin/main` right after each publish; the only branch edits of `status:` are the carried moves.
- **Wasted CI**: tracker-only pushes are excluded from the `push` trigger.
- Rollback: revert the PR; items keep a harmless `status:` line, the effective rule ignores it where it is stale.
