### F1 [medium] After this change the normal gate is blind to a spec that starts a real browser; only this raft's one-time RC1 catches it
Where: R0220.md Risks ("a spec added later is not covered by RC1 ... stated, not enforced"); c0550 Maintainability; `scripts/check.sh`
Evidence: with the prototype and the tooling case `board prints the absolute path of a relative --out` left without `-O`, `scripts/check.sh --full` exits 0 with `GATE PASSED (full)`, and the stub log shows the opener was called with `.cache/board-unit-abs/page.html`. On a developer's Mac without stubs, that is a browser tab per gate run, and agents run the gate many times per raft. The author's own prep shows how easy the slip is: the one unstubbed case was found only by E2, not by reading. Before c0550 the default was safe (opt-in); this raft makes the unsafe behaviour the default and leaves its guard in a sequestered `check.sh` that runs once and then sits in `done/`.
Critique: the tempting fix is a sentence in the testing skill ("specs that run `board` pass `-O`"). That is the same "stated, not enforced" rule; the next spec author (or a promoted spec from another raft) will miss it exactly as prep did.
Consequences: making the guard permanent means the gate itself must put recording stubs first on `PATH` and fail when they are called. That brings: (a) `scripts/check.sh` joins Touched modules (affected = ALL; specs that inspect check.sh output, e.g. c0060/changed, must stay green); (b) the stubs must exit 0 so every offending call is collected, and the temp dir needs a `trap` cleanup; (c) specs that stub their own openers prepend theirs, so they are unaffected (as RC1 already relies on); (d) `lune run tests/run` run directly and `tracker.sh check` (via `scripts/lib/ac.sh`) remain unguarded unless `ac.sh` gets the same wrapper: decide which, and say so in the testing skill; (e) CI's gate on Linux gets the same stubs (harmless, and it then also fails a stray `xdg-open`).
Recommendation: move RC1's mechanism into `scripts/check.sh` (both modes): prepend a mktemp dir with recording `open`/`xdg-open` stubs, and after the run fail with `an opener was called with: …` if the log is non-empty. Add the rule to the testing skill. Replace raft RC1 with a check that proves the guard works: plant a temporary spec (or use a `--spec`-style path) that runs `tracker.sh board --out <tmp>` without `-O`, assert the gate fails and names that path, and remove the plant; keep "the whole gate passes" as RC0 already does. Add rows to c0550's Rules and mutants table (rule "the gate fails when any spec runs an opener"; mutant "check.sh ignores the log"). If the user prefers to keep this raft minimal, ask (do not file silently) whether to file it as a follow-up chore and record the decision in Risks; but the guard is cheap and this raft is exactly where the risk is created.

### F2 [low] The raft's overlap claim with R0200/c0510 is wrong: both edit the same `flags()` line
