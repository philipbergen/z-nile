### F1 [high] R0200's prepped acceptance spec runs `tracker.sh board` without `-O`, so whichever of R0200 and R0220 lands second has a red gate from a sequestered spec it can't edit
Where: `tracker/issues/c0510/acceptance/commands.spec.luau:469` (on `main` since 9fa1499); R0220.md Order & dependencies (says the R0200 overlap is the `flags()` line only); c0550 Regression guard
Evidence: the case that checks read-only commands in a directory without a `.git` runs `tr(lost, { "board", "--out", `{lost}/board.html` })` and asserts only that stderr lacks `repository root`. Its environment is the inherited one plus `GIT_CEILING_DIRECTORIES`, so it gets the runner's guard stubs. On the prototype, the same layout (`scripts/` and `tracker/templates` copied into a directory without `.git`) makes `board` exit 0 and call the opener with `<lost>/board.html`. c0510 keeps `board` exempt from its repository-root refusal ("the read-only commands are exempt"), so after R0200 it still reaches the opener. Two orders:
- If R0220 lands first, R0200's executor runs `tracker.sh check c0510`. The guard then ends that run with `FAIL a spec started a browser … open …/lost/board.html`. The spec is sequestered, so the executor must stop and escalate.
- If R0200 lands first, `tests/acceptance/c0510/commands.spec.luau` is promoted, and R0220's RC0 full gate fails on it. R0220's `Overrides:` line doesn't name it, and promoted specs aren't edited during execution, so this executor must also stop.
R0200 is `design: ready` and not started (no branch or worktree), so this is still cheap to fix in prep.
Critique: the guard works as designed here: it catches exactly the slip it was built for. But the raft names R0200 as an overlap and still misses it, because the override check only greps promoted specs. The tempting fix is a line in Order & dependencies: "R0200's executor adds `-O`". That executor can't, because the spec is sequestered.
Consequences: the spec has to change before either raft executes, in a prep commit. Appending `-O` last is harmless on today's `main` and after R0200 alone, because `-O` is a valued flag with nothing after it (E3's argument, as for c0400/cli). After R0220 it suppresses the opener. The change edits another raft's prepped, sequestered spec. Under "ask before new work" this is the user's call, and R0200's documents should record it, so R0200's code review doesn't flag it as a sequestration breach: its start commit will already contain the change.
Recommendation: ask the user. Then, in this prep, append `"-O"` to that `board` call in `tracker/issues/c0510/acceptance/commands.spec.luau`, with a one-line comment (as in c0400/cli). Name it in c0550's Regression guard: "edits R0200's prepped spec c0510/commands (trailing `-O`, harmless before and after), user OK <date>". Extend E3 to run that case's `board` call on today's `main` with the trailing `-O`, and replace the R0200 sentence in Order & dependencies. If the user declines, then R0220 `depends_on` R0200 being done, and c0550's `Overrides:` names `tests/acceptance/c0510/commands.spec.luau`, edited in a re-prep after R0200 lands. Either way, also grep every in-flight prep's `tracker/issues/*/acceptance` for `board` and record the result (today only c0510 matches).

### F3 [low] Any non-empty `PICKMAN_OPEN_GUARD` switches the guard off, even when it names no live guard directory
Where: c0550.md Design, `tests/run.luau` guard ("If `PICKMAN_OPEN_GUARD` is set … the runner behaves exactly as today"); testing skill **No browsers** bullet
Evidence: on the prototype, `PICKMAN_OPEN_GUARD=/tmp/stale-not-a-dir lune run tests/run -- <plant running board without -O>` prints `1 passed, 0 failed` and exits 0. The opener first on the caller's `PATH` (a real `open` on a Mac) gets the page. The variable leaks into everything a spec starts, so a developer who copies a failing spec's environment to debug it, or a shell that inherited one, silently loses the guard. Separately, a spec that replaces `PATH` instead of prepending (precedent: `tests/tooling/run-lane-error.spec.luau` passes `PATH = "/usr/bin:/bin"`) reaches `/usr/bin/open` with the guard on. So "every opener call in the whole run therefore lands in the one log" overstates it.
Critique: the tempting fix is to unset the variable somewhere. That can't work for a child's environment from inside Lune (E6).
Consequences: c0640 (R0210), which is landing in the same file, already treats a marker that doesn't check out as top-level ("note: ignoring …"). Matching that keeps the two guards consistent when the files are merged.
Recommendation: treat the run as nested only when `PICKMAN_OPEN_GUARD` names a directory that holds the `open` stub; otherwise run as outermost, with a one-line `note: ignoring PICKMAN_OPEN_GUARD=…` on stderr. Add a guard.spec case: a stale value plus a plant that opens → the run fails and names the call. Add a Rules and mutants row (mutant: any non-empty value counts as nested). Add "prepend to `PATH`, never replace it" to the **No browsers** bullet, and change the Design sentence to "every opener reached through `PATH`".
