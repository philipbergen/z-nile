# R0240: Lobby place

## Theme
Split the experience into two places (user, 2026-10-02): "create a new place in the experience, this new place will host the actual game and the current one will show a highscore list and a 'start game' button and once you click the start game you are teleported to new place." This raft builds the **lobby**: a second Rojo project, a start button that teleports to the game place, and an empty hiscore panel R0110 will fill. The current `default.project.json` stays the **game place**, untouched.

One issue, f0670: the lobby's screen, the teleport and the second project belong together, and nothing else in the backlog is adjacent (R0110's board data and UI is the panel's content, not this).

Decisions relied on (quoted):
- **User, 2026-10-02**: the hiscore list in the lobby: "Empty panel now" (the lobby gets a hiscore panel with a typed row interface and an empty state; R0110 fills it later).
- **User, 2026-10-02**: Beta with two places: "Both in Pickman Beta" (a second place in the Beta experience; a new repo variable for its id; production stays undecided).
- **User, 2026-10-02**: at game over "an overlay shows the game results and waits for a tap before teleporting back to lobby". That is f0710, a later raft: it needs the chore c0690, which narrows the promoted play-again specs of R0150's f0300, so it is not a member here (see Order).
- **Authority** (game-design): "The server simulates every maze. Clients send intents and render the replicated state." The lobby follows it: the client sends one argument-free request, the server decides and calls the engine.
- **Platforms** (game-design): "Desktop (keyboard and mouse) and mobile (touch)." The start button is at least 44 px and works through `Activated`.
- **Deploy** (game-design): "A separate, private Pickman Beta experience. Every PR that becomes ready for review is published there (last one wins)." Publishing the lobby is c0700; until it lands Beta publishes the game place only.
- **Hiscores** (game-design): "Beta and production have separate stores, because they are separate experiences." Not touched here.

## Whole-raft design
```
default.project.json   ->  game place   (unchanged)  src/server, src/client, src/shared
lobby.project.json     ->  lobby place  (new)        src/lobby/server, src/lobby/client, src/shared

lobby client (LobbyView)            lobby server (Starts)                    engine
 draws Lobby.panel / Lobby.button     Travel.destination(attribute)
 press -> StartGame:FireServer() --->  Travel.request(id, now) == "go" -->  TeleportService:TeleportAsync(dest, {player})
 <--- Status(phase, configured) <----  Travel.failed / Travel.status       TeleportInitFailed
```
New features: `Travel` (may this player go now: one request at a time, a 15 s timeout after the engine call returns, a 60 s cap, a 3 s cool-down, destination validation) and `Lobby` (the panel and the button, as models). New adapters under `src/lobby`. Tooling: `place.load(project)`, the selector's place rule, a lobby build stage in the gate.

**Architecture changes** (made in this prep): features `Travel` and `Lobby` in `tracker/architecture.md` and the edge `Lobby -> Travel`. The layout table of the architecture skill gets the lobby project and `src/lobby` in f0670's implementation (step 6).

**Interfaces** are in f0670's Design (`Travel`, `Lobby`, the remotes `StartGame` and `Status`, the `GamePlaceId` attribute on `ServerScriptService`, `place.load(project)`). Later work relies on them: f0710 reuses `Travel` for the way back, and c0700 sets `GamePlaceId` in a copy of `lobby.project.json` before building.

## Risks & rollback
- **The teleport is unverified until a real session** (E7): O1 in Studio and O2 in Beta. The timeout, the cap and the cool-down turn any non-answer into a retry, so a wrong guess about the engine costs one line in `Starts`.
- **A wrong id in configuration** teleports to the wrong place or none: the lobby reads 0 as "not set up" and a non-number as none; c0700 owns setting it.
- **Tooling touches every place spec** (`place.load`'s signature, the selector rule). `place.load()` with no argument is unchanged and the gate runs the full suite.
- **Size**: about 850 lines of code, unit specs, tooling and the fake engine (the patch) plus six acceptance specs (about 770 lines): about 1,600 together, a little over the 1,500 guideline, but one cohesive change that a reviewer reads in one sitting (the acceptance specs are most of the second half).
- **Rollback**: revert the PR. Nothing deployed changes: Beta still builds `default.project.json` only until c0700.
