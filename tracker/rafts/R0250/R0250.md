# R0250: Ready raft

## Theme
Handing a raft to an agent today is spread over three tools and a clipboard. `make-prompt` copies a prompt to the clipboard, `tracker.sh launch` starts an AI session in the raft's worktree, and `start` claims the raft and moves it to `active/` only on its own branch. The result: `main` never shows what is in flight, a raft `check.sh` with a backlog path breaks once the raft moves (R0200's RC1/RC2, 2026-10-02), the prompt lives nowhere, and the tracker CLI runs AI sessions, when the user wants the AI session to drive and `tracker.sh` to handle only the mechanics.

This raft replaces that with three skills over CLI mechanics:
- **ready-raft** (c0730, replaces make-prompt): `tracker.sh ready <R-id>` claims the raft, moves it and its members to `active/` on `origin/main` with every `check.sh` path rewritten to the new location, updates the main checkout, and writes the prompt next to the raft as the git-ignored `tracker/rafts/active/<R-id>/prompt.md`. Re-running it on an active raft regenerates the prompt.
- **stop-raft** (c0740): `tracker.sh stop <R-id>` gives the claim back, moves everything back out of `active/` on `origin/main` (paths rewritten back), and removes the prompt. Its branch and PR, if started, are left alone.
- **launch-raft** (c0750): a skill, run in a Claude session, that reads the prompt through `tracker.sh prompt <R-id>` (it fails when the raft isn't readied or the prompt is missing), enters the raft's worktree and executes. `tracker.sh launch` is removed.
- **The board follows main** (c0760): every tracker command that pushes to `origin/main`, and `sync` in the main checkout, refreshes the main checkout's `.cache/board.html`.

All four are tracker tooling and skills: chores, one type.

**User decisions** (2026-10-03, this prep; `tracker/game-design.md` has none that apply, since there is no game behavior):
1. *Ready is the claim.* `ready` stamps `active` and moves the directories. `start` only creates the branch and the draft PR.
2. *Stop also aborts a started raft*: it gives the claim back and moves the raft out of `active/`, and leaves the branch and PR as they are (it names them).
3. *Direct push.* The ready and stop moves are published to `origin/main` as tracker-only commits, like the existing status claims. The direct-push exception grows to cover whole-directory moves.
4. *No clipboard.* The prompt lives only in `prompt.md`.
5. *The board* to refresh is the local `.cache/board.html` in the main checkout. CI's `tracker-board` artifact is unchanged.
6. *No AI launcher in the CLI.* `tracker.sh launch` goes, and the session drives: it is started in the main checkout and `cd`s into the worktree itself. `tracker.sh` handles mechanics only.

### Lifecycle after this raft
```
ticket-prep ──prep PR merges──▶ backlog, prepared
   /ready-raft R  (main checkout): tracker.sh ready R
        publish: raft+members → active/, status active-…, check.sh paths → active/   (one commit on origin/main)
        git pull --ff-only; write tracker/rafts/active/R/prompt.md (ignored); refresh board
   /launch-raft R (a Claude session in the main checkout)
        tracker.sh prompt R --path → Read it → cd "$(tracker.sh worktree R)" → execute-raft
        tracker.sh start R: branch R-slug from origin/main, an empty commit, push, draft PR (no move, no claim)
        … tracker.sh commit … done (active/ → done/ on the branch, check.sh paths → done/) … merge
        Landing step 4: <root>/scripts/tracker.sh sync (pull + board refresh)
   /stop-raft R   (main checkout): tracker.sh stop R
        publish: active/ → backlog, status prepared-…, check.sh paths back; remove prompt.md; pull; refresh board
```

### Interfaces between the issues
- **c0730 provides** these, and c0740, c0750 and c0760 build on them:
  - `paths.rewrite(text: string, dirs: { [string]: string }): string`, shared with publish's move validation
  - `publish.Change = { path: string, content: string, mode: string?, from: string? }`
  - in `main.luau`: `moveOnOrigin(ids: { string }, to: store.State, status: string, message: string): publish.Result` (builds the move changes for every file of each item's directory: the document gets the status, `check.sh` goes through `paths.rewrite`, every other file is unchanged)
  - in `main.luau`: `promptPath(raftId: string): string`, which is `{mainRoot()}/tracker/rafts/active/{raftId}/prompt.md`
  - in `main.luau`: `renderPrompt(raft: store.Item): string`, the old `cmd.prompt` body
  - in `main.luau`: `inMainCheckout(): boolean`
  - in `main.luau`: `currentRaft(): store.Item?`, the active raft whose branch (`raftBranch`) is the current branch
  - in `main.luau`: `sweepStale(root: string)`, run in the main checkout after every pull there. It removes every item directory, of either kind and in any state, whose document is no longer tracked (a stale `prompt.md`, `.DS_Store`), so a move never leaves a duplicate id behind (review 001 F2, review 002 F3)
- **c0740** uses `moveOnOrigin(…, "backlog", stamp("prepared"), …)`, `promptPath` and `sweepStale`.
- **c0750** turns `cmd.prompt` into the reader, using `promptPath`.
- **c0760** runs `sweepStale(root)` after its fast-forward, and adds `published(r: publish.Result)`, which refreshes the board when `r.sha` is set. Every `publish.commit` call site in `main.luau` (`new`, `status`, the legacy `start` claim, `ready`, `stop`) goes through it, and so does `sync` in the main checkout.

### Rules shared by the raft
- **A readied raft is the state "in `active/` on `origin/main` with an `active-…` stamp."** `status <id> <to>` refuses any item in `active/` on `origin/main` and names `tracker.sh stop`. `stop` is the only way back.
- **The legacy start** stays: `start` on a `prepared` raft that is still in the backlog claims it and moves it on the branch, exactly as today. The promoted specs of c0010, c0041, c0070, c0360, c0420, c0430, c0480 and c0510 drive that path, and the skills no longer use it. `stop` gives back such a claim with a status-only publish.
- **The current raft is found by branch**, not by "the only raft in `active/`", because `main` now carries every readied raft in `active/`. `tracker.sh commit` and `focus` use `currentRaft()`. `new issue --raft R` (an emergent issue) requires the current raft to be `R`, and its refusal names `--raft`.
- **Wording**: c0041's AC5 bans 13 phrases in `.claude/skills`, `tracker/templates`, AGENTS.md, SETUP.md and `main.luau` (the match ignores case). Never write any of them:
  - "git switch main"
  - "Commit to main"
  - "straight to main"
  - "direct commits to main"
  - "to main as one commit"
  - "runs on main before any PR"
  - "root is on another branch"
  - "git diff main...HEAD"
  - "ExitWorktree"
  - "wrapping it in a placeholder raft"
  - "which gets a placeholder raft"
  - "creates a placeholder raft"
  - "wrap a single issue with"

  Write "published to `origin/main`" for the direct pushes, and "refuses a raftless issue" for the old placeholder path. c0730's AC10 scans all 13.
- **Promoted wording** that the doc rewrites must keep is listed in c0730's and c0760's Regression guard (review 001 F8).

## Risks & rollback
- **`main` now holds active items.** Anything that assumed "active means my branch" breaks: `activeRaft`, `raftIsActiveHere` and `new --raft` are handled by `currentRaft()`. The board's Active tab now shows readied rafts, which is intended. Other assumptions are caught by the full gate, with fixtures that have two readied rafts on `origin/main` (c0730's spec).
- **Anything that globs `*/active/*`** now sees other readied rafts. CI's dispatched acceptance step is filtered by the branch's raft (c0730). New tooling must select by raft, not by directory.
- **A published move is a bigger direct push** than a status line. publish validates every moved file: same id, same relative path, whole directory, unchanged bytes except the document's status line and the item paths in `check.sh`, mode kept, and nothing else in the tree changes (the existing diff-tree check, extended to the sources).
- **A stale prompt after a merge**: covered by `sweepStale` after every pull in the main checkout. A main checkout that is never synced keeps the stale directory until its next `sync`.
- **Other items' `check.sh` files** that name a moved item are not rewritten. Only the moved items' own files are. Raft checks should keep using `tracker.sh find` (the raft-check-paths rule).
- **R0210 (check isolation) is active** and edits `ac.sh`, `tests/run` and git hooks. The specs here follow its rules: fixtures under `.cache/<unique>`, the `GIT_CEILING_DIRECTORIES` fence, no `GIT_CONFIG_COUNT`, and local bare origins only. Whichever raft starts second merges `origin/main` first.
- **Overlapping prep**: none of the open preps (R0110, R0120) touches the tracker.
- Rollback: revert the squash commit. Rafts readied meanwhile sit in `active/` on `main`: move them back with `git mv` in a PR, or `stop` them before the revert.
