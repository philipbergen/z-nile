# Design refute 001: R0260
Every finding was fixed, in the documents, the specs and `check.sh`, then proven in the prototype (`.worktree/proto-r0260`). The full gate passes there, and RC1 passes there.

- F1: fixed: `fence.sh` keeps its exclusive `mktemp` and only swaps `mv -f` for an inline Perl `rename` (no dependency on `replace-file.pl`); `cachepaths` lists the `mktemp` line; c0830 step 4 runs the c0640 specs and `fence-leftovers`. The full gate now runs on the prototype (raft E6). consequences: the skill's writer sentence names the sentinel's inline rename (c0840). `cachepaths.luau` and `main.luau` need reviewed `ALLOWED` entries in `repo-fence.spec`, which the full gate found; they're now steps in c0830 and c0800.
- F2: fixed: the real prefix passes `-`, so the sweeper uses its parent (the launcher), read once at start. It refuses if that's pid 1, or if its parent changed by sweep time. New case: an orphaned `-` refuses. AC4's static case pins `-`. AC6 interrupts a real jailed run with INT to its group and requires the detached process gone; the `myPid()` mutant fails it. consequences: a SIGKILL of the launcher skips the sweep and the unlink; the testing skill says so (c0840). Specs keep the explicit-pid form, which the interlock still checks.
- F3: fixed: the fast path reads the found repository's `.git/config` with the `read` builtin (bash 3.2), and goes to the slow path on `worktree` or `include`. The slow path resolves the git dir and the work tree in one `rev-parse`. New cases: a fixture whose own config points `core.worktree` at the real checkout is refused (driven from a good fixture, since the helper itself refuses to start in it); `GIT_CONFIG_COUNT` with `core.worktree` doesn't reach the real checkout. consequences: the cost first rose to +34%. Resolving `-C` and the slow path's folders with `builtin cd` (no subshells) brought it to +19%, inside E1's 25% (c0810 E5). Includes are not followed; they just force the slow path, which resolves exactly as git does.
- F4: fixed: an add-only switch, `PICKMAN_DONE_GATE=1`, makes `done` run the gate inside a spec run. `PICKMAN_FENCE_SPECS` stays set in every case, and the spec names no guard variable. consequences: the switch can only add the gate (a row and a mutant: "the switch read as skip" fails AC1 and AC2); it's documented as for specs whose fixture stubs the gate.
- F5: fixed: the static case pins the order in `REAPER`: `waitpid`, then the group kill, then c0830's unlink, then `exit`. The deleted-group-kill mutant now fails it. consequences: the case reads the source, as AC4's fork rule already does. No seam in the launcher was added (that would be a new bypass).
- F6: fixed: `init` and `clone` check every path a repository is made at, on both paths: `init`'s positionals or the folder, `clone`'s destination or the folder, and `--separate-git-dir` and `--template`. Each must resolve under `.cache` through its nearest existing folder, with no `..` in the part that doesn't exist yet. `-C` is applied first. New case: seven refused forms, plus a clone with `-b` still working under `.cache`. consequences: value-taking options skip their value, so a branch name isn't read as a path. A clone's source is only read, so it isn't checked. The 12 converted specs still pass (AC3).
- F7: fixed: a `build_place` case. The stand-in gate gets stubs for `rojo` (writes its `-o`; `build` links `.cache/check.rbxl` to a folder first), `stylua`, `selene`, `luau-lsp` and `lune` (fails at the tests stage). It requires a regular file, an unchanged folder and an empty TMPDIR. Rows: `cp` in place of the rename, and the folder kept; both are caught. consequences: none beyond the stubs, which other cases don't reach.
- F8: fixed: `fence.alive` counts `Operation not permitted` as alive only when jailed. The case adds pid 1 (root), alive with `PICKMAN_TEST_JAIL=sandbox-exec` and dead without. Both mutants are caught. consequences: the unjailed lock code keeps today's behaviour. Inside the jail, nothing a spec judges is another user's.
- F9: fixed: the skill text says what is true. Each `.cache` line in `scripts/` is reviewed; the writers there replace by rename. Writes through a listed variable, and the runner's own writes, are review's to catch. consequences: no new check; the limit is stated where an agent reads it.
- F10: fixed: the testing-skill edit is the raft's last code step, item 7 in the order. c0800 now also updates the tracker skill's `done` row (the new order, and the recovery from an interrupted gate), with AC5 checking that row itself, since the phrases already appear elsewhere in the skill. consequences: AC5 fails until the executor edits the row; prep confirmed it fails for that reason today.
- F11: fixed: experiment c0840 E5.
