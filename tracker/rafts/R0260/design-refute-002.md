# Design refute 002: R0260
Every finding was fixed and proven in the prototype (`.worktree/proto-r0260`). The full gate passes there, and every issue's `check.sh` passes except the four skill-text checks that wait for the executor.

- F1: fixed: the gate decision is a pure function, `gate.doneGate(env)` in the new `scripts/tracker/gate.luau`, which `cmd.done` calls with `process.env`. AC6 tests the four tables (neither variable → full; spec run → promoted; spec run plus the switch → full; switch alone → full) and pins that `main.luau` decides through `doneGate(process.env)` and reads `PICKMAN_DONE_GATE` nowhere else. Both mutants are caught: "the gate only with the switch" (in the function) and "`done` bypasses the function". consequences: the `ALLOWED` entry moves from `main.luau` to `gate.luau`, and the promoted spec needs one for naming the variable as a table key (c0800 step 4). No process's guards are touched.
- F2: fixed, by questioning the mechanism (c0860's rule: two rounds found holes in this shim). An exhaustive model of git's command line can't be complete, so the shim now enforces one bounded rule: every path that names a repository or a work tree must resolve under `.cache`. That covers `-C`, `--git-dir`/`--work-tree` values, `-c core.worktree=`, the five repository variables (for every command), a `.git` symlink, the repository's own config, and the targets of `init`, `clone` and `worktree add`/`move`. New cases: `GIT_DIR=<outside> git init`, `git --git-dir=<outside> init`, a reinit retargeting a stand-in's work tree (its config checked unchanged), `GIT_WORK_TREE=<outside> git clone`, `git worktree add <outside>`, plus `GIT_DIR` and `worktree add` under `.cache` still working. consequences: files git writes to arbitrary paths (`archive -o` and the like) are outside the rule, which c0810 and c0840's skill text now say: review's to catch on Linux, like any spec write. Cost: +12% (c0810 E6).
- F3: fixed: every write in the creation case is aimed at a stand-in repository cloned into the run's temp folder. The `..` case starts from a symlink under `.cache` into that folder (`$base/new/../out/../x`, which the first round's `..` case didn't actually exercise: its start was already outside). The stand-in's `.git` listing and config must be unchanged. The real checkout appears only in read-only probes. consequences: mutants now touch only the stand-in; the real repository was checked untouched after the mutation run.
- F4: fixed: the fast path also resolves `.git` itself (`builtin cd -P`) and requires it under `.cache`. New case: a `.git` symlink into a stand-in, where `git add` is refused and the stand-in's index is unchanged. consequences: the first run of this mutant was masked because the config trigger matched any value containing `worktree`, and this repo's remote URLs contain `.worktree/`. The trigger now matches keys (`worktree =`, `[include…]`), which also takes fixture clones off the slow path.
- F5: fixed: the runner's `bash -c` line begins with `unset PICKMAN_REAP_SWEPT PICKMAN_REAP_CACHE;`, so the launcher's variables reach no spec and no nested launcher. New case: a launcher a spec starts, with no environment changes, gives 137 for a signal death and no sweeper message; today's prefix fails it. consequences: c0820's sentence about unjailed runs is corrected. The REAPER cases in c0830 and c0820 already set what they need explicitly.
- F6: fixed: the raft's diagram and Interfaces now match c0830 (inline rename in `fence.sh`; `deploy-beta` writes nothing), c0840 (`alive` only when jailed; the "only way" claim gone), c0820 (the `-` form; the variables unset) and c0810 (the bounded rule). c0800's Maintainability sentence and Test plan order are corrected. consequences: none.
