## Whole-raft design
Four mechanisms, each owned by one issue, plus two process changes:

```
                         unjailed (top Lune, launcher)              | jailed (sandbox-exec), macOS only
tests/run ─► fence.enter ─► perl REAPER launcher ─────────────────► perl SWEEPER ─► bash ─► lune tests/run (specs)
               │             │  watchdog (c0079): pipe EOF → kill -group     │ after specs: kill every same-sandbox
               │             │  unlink top-level .cache links (c0077)        │ process except its ancestors (c0076)
               │             │  root died by a signal → fail (c0076)         │ interlock: its parent (the launcher) must
               │             │                                               │ be outside the jail; refuses otherwise
               │             └─ profile: + (deny signal)(allow signal (target same-sandbox)) (c0078)
               └─ link probe for an outer sandbox: random name, EPERM only (c0078)

unjailed writers under .cache ─► scripts/lib/replace-file.pl (c0077): O_EXCL|O_NOFOLLOW sibling temp, then rename(2)
   sh.writeReplacing (tracker focus/claim/board), check.sh defs download + build_place
   (fence.sh's sentinel: an inline rename(2), since fixtures copy fence.sh alone)
tracker.sh done ─► promote ─► move to done/ ─► gate.doneGate(process.env): full gate, or (in a spec run) promoted checks ─► ready ─► commit (c0074)
tracker.sh done ─► every "fixed" answer in the latest refute file carries "consequences:" (c0080)
```

Interfaces between issues (the only shared surface):
- `tests/lib/fence.luau` exports, for specs: `fence.REAPER: string` (exists, made public by c0077, the first to need it), `fence.SWEEPER: string` (c0076). Both are Perl programs run as `perl -e <program> …`. Their argument contracts:
  - `perl -e REAPER <command> <args…>`: as today, plus env `PICKMAN_REAP_CACHE=<physical .cache>` (c0077: the unlink after the group is killed) and env `PICKMAN_REAP_SWEPT=1` when the command is the sweeper (c0076: a signal death of the command then fails the run).
  - `perl -e SWEEPER <outside-pid | -> <command> <args…>`: runs the command, then sweeps; exits with the command's status (a signal death as 128+n). `-` (the real run) means its parent, the launcher. It exits 70 without sweeping unless a signal to that pid is refused with `EPERM` (and, for `-`, the parent is not 1 and hasn't changed). It exits 71 if survivors remain after 50 passes.
  - Both `PICKMAN_REAP_*` variables are for the launcher alone; the runner's `bash -c` line unsets them.
- `scripts/lib/replace-file.pl <dest> [<src>]` (c0077): content from `<src>` or stdin. Used by `sh.writeReplacing` (Luau) and `scripts/check.sh`. `fence.sh` uses an inline `rename(2)` instead, because fixtures copy it alone; `deploy-beta` writes nothing under `.cache`. `tests/lib/cachepaths.luau` lists each `.cache` line in `scripts/` with a reason, and c0078's skill text says exactly that, not more.
- `fence.alive(pid)` counts `Operation not permitted` as alive **only when jailed** (c0078): there it means a process outside the jail. Unjailed it means another user's process, which can't hold the lock.

Architecture changes: none. No `src/` module, and no new edge in `tracker/architecture.md`: every change is in `tests/lib`, `scripts/` or skills.

## Experiments phase
Run in prep (results in each issue's Unknowns & experiments):
- **E1 (c0077)**: can SBPL refuse an atomic swap of a symlink into the top of `.cache`? Only by refusing symlinks in every folder specs may write to: the sandbox judges a link by the path where it's made, and a link made in the run folder can be renamed or swapped in. A full ban breaks c0055's promoted setup spec, which builds its stubs from symlinks under `.cache`. So the defence is at the writers.
- **E2 (c0077)**: do `rename(2)` callers replace a link? Lune `fs.move(tmp, path, true)` and Perl `rename` both replace a link to a file or to a directory with the file, and both refuse a real directory (`Is a directory`). `mv -f` moves the file *into* a linked directory (review 006 round-6 F1).
- **E3 (c0076, c0078)**: `(deny signal)(allow signal (target same-sandbox))` refuses `kill -0` and TERM to a process outside the jail, and allows them to the jail's own children, even ones that left the group. Inside the jail `/bin/ps` can't run (setuid), but `kill 0` over pids 2–99999 takes about 40 ms and finds exactly the jail's processes. A sweeper using it killed a double-forked `setsid` process and left an outside process alone. `(deny signal (target others))` is not enough: it allowed signals outside.
- **E4 (c0079)**: `pgrep -P` works inside the jail for the jail's own processes.

- **E5 (all issues, run in prep)**: does each design hold up in a prototype?
  - Setup: every issue's design, prototyped in a scratch worktree from `main` (`.worktree/proto-r0260`, never landed). Each issue's mutation check ran there; the results are in each issue's Unknowns & experiments.
  - Result:
    - Every issue's `check.sh` passes against it, except the three skill-text checks (c0078 AC4, c0080 AC2 and AC3), which fail for the right reason until the executor edits the skills.
    - RC1 passes there and fails on today's code ("process … outlived the run").
  - Prototyping changed three designs and four specs:
    - c0076: `pgrep -a`;
    - new cases: c0077 (unreadable source), c0076 (outside pid gone);
    - a c0076 spec bug, fixed.

- **E6 (after design review 001, run in prep)**: does the prototype hold up after round 1's fixes?
  - The full gate passes on the prototype, once the `ALLOWED` entries c0074 and c0077 call for are in (RC0's main check, which round 1 rightly said prep hadn't run).

## Exit criteria
- RC0: the generated lines (the full gate, every member's `check.sh`, `promote-check`).
- RC1 (macOS): in a real jailed suite in a fixture checkout (this `check.sh` runs outside the jail, so the fixture's run jails itself), one probe spec leaves a process in a session of its own, tries `kill -0` on the run's top process, and swaps a symlink into the top of its `.cache`. Afterwards: the process is gone (c0076), the signal was refused with `Operation not permitted` (c0078), and no symlink is left at the top of `.cache` (c0077). Off macOS it passes without checking: there's no jail.

## Risks & rollback
- **The sweeper kills the wrong processes.** Mitigations: the interlock (exits 70 unless a signal to an outside pid is refused); ancestors are never swept; the membership test is the kernel's same-sandbox rule. Rollback: drop the sweeper from the jail prefix (one line in `fence.enter`); the process group reaping still applies.
- **The signal rule breaks a spec that signals outside the jail.** Prep found none: every `kill` in `tests/` targets a process the spec started. The full gate in RC0 is the check.
- **`done` takes longer:** it now runs the full gate twice (the raft's RC0 before promotion, the full gate after). That's accepted, because that is the bug c0074 fixes.
- **Raft size:** six chores, an estimated 1,200–1,500 changed lines, mostly specs: about the guideline. c0080 could split off cleanly if needed.
- **Rollback** of the whole raft is a revert of its squash merge. No data migration.
