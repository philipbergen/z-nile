### F1 [high] Phase 2B's commit of the stream-review file aborts, so the file never reaches the squash
Where: `.claude/skills/execute-raft/SKILL.md:52`
Evidence: Step 3 now says the stream author commits the review file with plain `` `git add <file> && git commit` ``, and the refute file "the same plain-git way". Neither command passes `-m`. Step 2 of the same phase always does (`git commit -m "<issue>: <what>"`). With `GIT_EDITOR=true` and no commit template, `git add` then `git commit` exits 1 and prints `Aborting commit due to empty commit message` (probed on a throwaway repository; the index was left holding the file, no commit was created). `git merge --squash` merges commits only, so an uncommitted `stream-review-<issue>-NNN.md` or `stream-refute-<issue>-NNN.md` stays in the stream worktree. Step 4 then deletes that worktree. The raft-branch `tracker.sh commit --phase code-review` still records the minutes; it does not add the file.
Critique: Review-001 F1's hole was that the recording command could not run. The replacement spend command can. The command that is supposed to put the review document on the stream branch cannot. Adding `-m` to the sentence the stream author is told to run is the small fix, and it is not enough: that author has already exited, was briefed to `git add -A`, and is continued only in the next sentence, for the refute, which is after the review file was supposed to be committed. A relayed `git add -A` also commits whatever else is still dirty in that worktree, and the later build squash counts those lines.
Consequences: The lead has to make the stream commit, of that one path, with a message, before the raft spend commit. The stream author does not commit review files; their implementation commits stay `git add -A`. Without `-m` the commit aborts again. `git add -A` on the stream puts stray files into the squash. The raft `tracker.sh commit --phase code-review` still requires an empty index and must still run before `git merge --squash`, never while a squash is staged, or the implementation diff is recorded as code-review. The file has to be a commit on the stream before that squash; otherwise the squash never sees it, and removing the worktree deletes the only copy. The squash commit stays the default build phase.
Recommendation: Drop the handoff (this is the second hole in it). In step 3 the lead commits the one file on the stream from the raft worktree: `git -C <stream> add -- <file> && git -C <stream> commit -m "<issue>: stream-review-NNN"`, and the refute file the same way with its own `-m`. Then, still before `git merge --squash`, record the minutes with the existing raft command `scripts/tracker.sh commit -m "<issue>: stream-review-NNN" --phase code-review --time <minutes> [--tokens <n>] --issue <issue>` on a clean raft index. Do not use `git add -A` on the stream for these files, and do not pass `--phase` on the squash commit.
