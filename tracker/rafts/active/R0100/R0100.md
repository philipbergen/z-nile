# R0100: Ghosts

## Theme
Roadmap raft **d**, which turns it into Pac-Man: the four classic ghosts (navigation and personalities, the scatter/chase schedule and frightened mode, the ghost house, collisions and their consequences), the ghosts drawn, and **danger awareness in first person**. It builds on R0040 (maze, movement, session) and R0090 (pellets, power, lives, levels) and extends `Levels` and `Session`. The user asked to keep it as **one raft**, six issues, one PR, although prep estimates the change at about 1,800 lines (the size guideline is 1,500): see Risks.

Decisions from `tracker/game-design.md` this raft relies on (quoted):
- **Pillar 1**: "It's Pac-Man, seen from inside the maze. The classic rules and feel come first, and the first-person view is the twist."
- **Pillar 2**: "Everything that decides an outcome runs in pure Logic, can be simulated headless and is tested in CI. Roblox renders and relays input."
- **Pillar 3**: "Fair and readable in first person. The player can always tell where they're going and where the danger is."
- **Authority**: "The server simulates every maze. Clients send intents and render the replicated state."
- **Ghosts**: "the four classic personalities. Blinky targets the player's tile. Pinky targets 4 tiles ahead. Inky uses a vector from Blinky. Clyde targets the player when more than 8 tiles away, and his scatter corner when closer. Modes: scatter, chase and frightened. Ghosts never reverse, except when the mode changes. Ghosts are released from the ghost house by rule."
- **Points**: "ghosts 200/400/800/1600 within one power period."
- **Levels**: "Speeds, the frightened duration and the mode schedule vary per level, following the classic tables."
- **Collisions**: "player and ghost collide when they share a tile, or when they swap tiles within one tick."
- **Game speed** (user, 2026-10-01): everything is counted in game ticks (30 per game second) and the server steps at half that rate in real time; this raft adds no pacing of its own.
- **Danger aid** (user, 2026-10-01, answering the open decision): **a minimap/radar and edge indicators**, and the indicators must give "some sense of distance not just direction, bigger or brighter as it gets closer".
- **Slower ghosts** (user, 2026-10-01): yes, a tuning factor for the ghost speeds; **the factor is the user's to give later**, so it ships as one constant that defaults to the classic 1 (`Levels.GHOST_TUNING`).

Choices made in this prep that the user may veto (recorded in `tracker/game-design.md`): **Cruise Elroy** (Blinky speeding up near the end of a level) is not built; Pinky and Inky aim exactly ahead, **without the arcade's overflow bug** when the player faces up; ghosts decide at tile centres; eyes run at twice level 1's player speed; the blinking is 14 ticks per flash (7 blue, 7 white); ghost speeds are rounded to whole sub-tile units; the radar turns with the camera so up is where you look; **no pause and no score pop-up when a ghost is eaten** (the arcade freezes the game for about a second); an eaten ghost comes out **dangerous, not blue**, for the rest of that power period (arcade); a power pellet at the contact tile means the ghost is eaten, a blue ghost met on the tick the blue time ends kills, and the end of the blue time does not turn ghosts back; frightened ghosts wander uniformly among the open exits (the arcade's choice is slightly biased).

**What each issue owns**:
- **f0190 Ghost navigation**: the `Ghosts` feature's first half, with no state: `NAMES`, `noUpTiles`, `scatterTile`, `chaseTarget`, `pickExit`, `walker`/`occupied`/`position`/`walk`, `tunnel`, `available`; plus `Classic` (layout data). `Rng` (a seeded generator) is created by f0200, which first needs it.
- **f0200 Ghost mode schedule**: `Ghosts.new`/`step`/`power`/`reset`/`look`/`flash`/`ghost`/`occupiedTiles` and the set, the scatter/chase timetable, frightened mode; and the `Levels` ghost columns (`ghost` speeds, `schedule`, `GHOST_TUNING`, `EYES_FACTOR`, `ghostSpeed`, `schedule()`).
- **f0210 Ghost house**: the release rules (`pelletEaten`, personal and global counters, the idle timer), the way out, eyes and the way back, `Ghosts.eat` (with the chain), `start = "house"` as the default, and the `Levels` columns `dotLimits` and `idleSeconds`.
- **f0220 Ghost collisions**: `Ghosts.contacts` and the wiring in `Session` (config flag `ghosts`, `Caught`/`GhostEaten` events, resets after a death, a level or a new run, the order inside a step).
- **f0310 Ghost rendering**: ghosts in `Session.snapshot`/`frame`, `View.interpolateGhosts`, and the client's `GhostView` with its wiring.
- **f0320 Danger awareness**: the `Awareness` feature, the client's `DangerHud`, `Camera.pose`, and the wiring.

**Interfaces between issues** (the signatures later issues rely on):
```lua
Ghosts.pickExit(m: Maze, tile: Tile, heading: Heading, target: Tile, opts: { noUp: boolean?, house: boolean? }?): Heading
Ghosts.walk(m: Maze, w: Walker, speed: number, decide: (Tile, Heading) -> Heading): { Event }   -- Entered, Wrapped
Ghosts.new(m: Maze, seed: number, opts: { start: ("house" | "active")?, level: number?, tuning: number? }?): Set
Ghosts.step(set: Set, input: { player: Tile, heading: Heading, level: number, baseSpeed: number, tickRate: number }): { Event }
Ghosts.power(set: Set, ticks: number)        Ghosts.pelletEaten(set: Set): { Event }
Ghosts.contacts(set: Set, prev: { Tile }, playerPrev: Tile, playerNow: Tile): { { name: Name, kind: "kill" | "eat" } }
Ghosts.eat(set: Set, name: Name): number     Ghosts.reset(set: Set, reason: "respawn" | "level" | "run", level: number)
Levels.ghostSpeed(base: number, level: number, kind: "normal" | "tunnel" | "frightened" | "eyes", tuning: number?): number
Session.GhostSnapshot = { name, x, y, heading, look: "normal" | "frightened" | "blinking" | "eyes", flash: boolean, jumpTick: number }
View.interpolateGhosts(prev: Snapshot?, latest: Snapshot, alpha: number): { { x, y, heading, look, flash } }
Awareness.indicators(m: Maze, pose: { x, y, yaw }, ghosts: { { x, y, look } }, options: Options?): { Indicator }
Awareness.radar(m: Maze, pose: Pose, ghosts: { Ghost }, radius: number?): { radius, walls, blips }
```
**Data flow in one `Session.step`** (a contract): `Game.step` (phase changes; a `Ready` event resets the ghosts) → player movement and eating (a `PelletEaten` event is later forwarded to the house; a `PowerStarted` event is remembered) → `Ghosts.step` (timetable, releases, every ghost walks) → `Ghosts.power` if a power pellet was eaten this tick (so the ghosts turn blue *after* they moved, and their blue clock equals the run's) → contacts (a level cleared this tick wins; a kill beats an eating; eats pay along the chain). Ghosts only move in ticks where the run is in play.

**Ghosts are opt-in**: `Session.Config.ghosts` is true only in `GAME_CONFIG`, and a maze needs ghost data (only the classic layout has any): every existing session, fixture and promoted spec runs without ghosts exactly as before. A snapshot of a ghost-less session has no `ghosts` field.

**Architecture changes** (made in prep, in `tracker/architecture.md`): new features `Ghosts` and `Awareness`; new edges `Ghosts -> Levels`, `Ghosts -> Maze`, `Ghosts -> Movement`, `Session -> Ghosts`, `Awareness -> Maze`. `Levels` gains ghost columns (no new edge).

## Experiments phase
All run in prep on a scratch prototype of the whole raft (`experiments/` of each issue): see Unknowns & experiments there.
- **E1** the classic no-up junctions are the four tiles with a north exit (pass).
- **E2** a ghost steered by arbitrary targets on the classic maze never stands on a wall, the door or the house and never turns back, over 20 seeds x 4 ghosts x 2,500 ticks (pass, a spec).
- **E3** how fast an idle player is caught: at tick 428 on every seed, which is 12.3 s of game time after play starts (the run goes into play at tick 60), by Clyde; the scenario's bounds are 8 to 20 s.
- **E4** speed of the awareness maths: 0.2 ms for four ghosts' indicators, 0.08 ms for the radar (budget 50x in the spec).
- **E5** the client adapters type-check against the Roblox definitions; they cannot run headless (Observed).
- **E6** the whole existing suite with the prototype: `check.sh --full` passes (the prototype found, and the design now avoids, a second `View.interpolate` call in `Camera`, which a promoted spec forbids).
- **E7** mutation check: see each issue's Rules and mutants.

## Risks & rollback
- **Size**: six issues in one PR, about 1,800 lines with the executor's unit specs, over the 1,500 guideline. Mitigation: the issues are strictly ordered with their own `check.sh`, the review is by issue, and `workstreams` shows no parallel waves, so there is no merge risk inside the raft.
- **Fidelity to the arcade**: integer sub-tile speeds round the classic speed shares (level 1 ghost 28 units/tick, 28.125 in the table), the ghost start tiles and the house paths are the author's, and Cruise Elroy is absent. The game-design file lists each, so the user can veto one.
- **Fairness in first person**: the classic tables with full information may still feel unfair; the radar, the edge indicators and the tuning factor are the answer, and the factor is the user's to set after a Beta playtest.
- **Presentation can only be checked in Studio**: `GhostView` and `DangerHud` are type-checked and their wiring is checked by source specs, but looks (size, brightness, colours, the radar's readability) are Observed.
- **Two rafts edit `Main.client.luau`** (this and R0150): a small text conflict for whoever lands second.
- **`Session` grows** (about +160 lines); the ghost logic stays in `Ghosts`, and `Session` only wires it.
- **Rollback**: revert the PR; nothing persists. Ghosts are opt-in per config, so setting `ghosts = false` in `GAME_CONFIG` switches them all off without a revert.
