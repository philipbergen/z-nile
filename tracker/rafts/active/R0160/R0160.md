# R0160: Board artifact spec guard

## Theme
Three small process chores, all about trusting the tracker and the gate: **c0450** makes ticket-prep find new issues that override promoted acceptance specs (instead of discovering the clash as a red gate mid-execution), **c0480** makes `tracker.sh start` refuse a raft whose issue depends on an unfinished item in another raft (the enforcement c0450's chore route needs), and **c0460** publishes the tracker board as a workflow artifact on every push to `main`. They share almost no files, only the "tracker process and CI" area (c0460 and c0480 both edit the tracker skill, different lines), and all are chores (CI and process work is always a chore).

Decisions relied on: none in `tracker/game-design.md` (no game behavior). User decisions of 2026-09-30: the board goes to a **workflow artifact, not GitHub Pages** (the repo is private, Pages from a private repo needs a paid plan and is public by default, and the board shows the backlog and spend); the chores go in **one raft**; on 2026-09-30 the user also asked for the `start` enforcement chore (c0480) to be added to it.

No `depends_on` between the issues. `tracker.sh workstreams` plans two waves: wave 1 is c0450 and c0460 (independent, may be parallel streams), wave 2 is c0480, after c0460 because both edit the tracker skill file. 

## Experiments phase
Run in prep, results are in each issue document (c0450 E1–E4, c0460 E1–E6, c0480 E1–E2). Left for execution: none. E3 of c0460 (the workflow on GitHub) can only be proven after merge: OC1. If an experiment fails without a fallback, stop and escalate.

## Exit criteria
- RC0: the full gate, every member's `check.sh`, and the promotion dry-run pass (generated lines).
- RC1: the board workflow's setup step is `scripts/setup.sh --tools` (main's tools-only mode).
- RC2: the board builds with the workflow's own command into a fresh directory.
- RC3: the lifecycle specs that drive `tracker.sh start` still pass with c0480 in place (`tests/acceptance/c0010/tracker-lifecycle.spec.luau`).
- "Done" == `scripts/tracker.sh done R0160` succeeds. The post-merge observation OC1 (c0460) goes in the final report.

## Risks & rollback
- **A bad workflow runs only on `main`** and can't be tried on the PR. Mitigation: every field that would make it fail is pinned by a spec (token, conditions, runner, concurrency, paths), its inputs follow the documented `upload-artifact@v4` API, and a failed run only affects the board job, not `check.yml`. Rollback: revert the squash commit (one new workflow file).
- **Doc-text specs are brittle**: a later skill rewrite can break `override-check.spec.luau`; that is fixed through a chore. They aren't selected by `--affected`, only by `--full`/CI.
- **Actions minutes** on a private repo: one extra tool-install run per push to `main`.
