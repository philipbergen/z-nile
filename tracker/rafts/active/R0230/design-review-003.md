### F1 [high] The snapshot still is not "GitHub's documented default runner variables": four always-set documented variables are missing, and a skip on any of them passes 8/8 (repeat of design-review-002 F1, residue)
Where: setup-run.spec.luau `CI_ENV` (lines 174-220) and its comment "GitHub's default runner variables (docs.github.com, ...)"; c0530 AC3 ("GitHub's documented default runner variables and per-step file variables"), Design case 3, the Accepted-risk paragraph and R0230 Risks ("the snapshot covers GitHub's documented defaults").
Evidence: GitHub's "Default environment variables" table lists, as set on every run, `GITHUB_REPOSITORY_ID`, `GITHUB_REPOSITORY_OWNER_ID`, `GITHUB_WORKFLOW_SHA` and `GITHUB_REF_PROTECTED`; none is in `CI_ENV`. Mutants inserted before `say "gate"`:
- `[[ -n ${GITHUB_WORKFLOW_SHA:-} ]] && exit 0`: **8 passed, 0 failed**.
- `[[ -n ${GITHUB_REPOSITORY_ID:-} ]] && exit 0`: **8 passed, 0 failed**.
Both skip the gate on every real `check.yml` run. The user's accepted risk is "a CI-only variable *outside* the snapshot", and its stated justification is that "the snapshot covers GitHub's documented defaults"; that premise is false today, so AC3 as written can be passed by a gate-skipping `setup.sh` inside the scope it claims. This is not a re-opening of the accepted risk; it is the snapshot not reaching the boundary the user accepted.
Critique: the tempting fix is to add the four names. That is right and enough for this raft; the miss came from building the table from memory rather than from the docs page.
Consequences: none new for the four names (plain values, not files). `GITHUB_ACTION_REPOSITORY` and `GITHUB_ACTION_REF` are documented too but set only for steps that run an action, and `RUNNER_DEBUG` and `GITHUB_ACTION_PATH` only conditionally; the comment should say they are deliberately left out, so the next reviewer does not reopen this. A self-maintaining check (on CI, fail if the spec's own environment holds a `GITHUB_*`/`RUNNER_*` name missing from `CI_ENV`) would turn every GitHub addition into a red PR; that is a user decision touching the accepted risk and is not required here.
Recommendation: add `GITHUB_REPOSITORY_ID`, `GITHUB_REPOSITORY_OWNER_ID`, `GITHUB_WORKFLOW_SHA`, `GITHUB_REF_PROTECTED` to `CI_ENV`; make the comment name the docs page, the date it was checked (2026-10-01), and the conditional names deliberately excluded with why. Add rows Z3 (`GITHUB_WORKFLOW_SHA`) and Z4 (`GITHUB_REPOSITORY_ID`) as `run`, and update the mutant count (29) in E3 and R0230 Experiments.

### F2 [medium] "Blank is unset" is true only for today's `${X:-}` reads: the CI case sets names a real runner leaves unset, and a `${X+x}` skip on CI passes 8/8
Where: setup-run.spec.luau `setup()` (lines 116-140, `vars[k] = ""`); c0530 Design "Run" ("every other controlled variable blank ... `setup.sh` reads every variable as `${X:-}`, so blank is unset"); R0230 Whole-raft design.
Evidence: on a real `check.yml` gate step, `GITHUB_TOKEN`, `PICKMAN_SKIP_GATE`, `SKIP_GATE`, `BASH_ENV`, `ENV`, `CDPATH` and `GLOBIGNORE` are unset (the step's `env:` gives only `GH_TOKEN`). In the spec's CI cases they are set to `""`. Mutant `[[ -n ${CI:-} && -z ${GITHUB_TOKEN+x} ]] && exit 0` before `say "gate"`: **8 passed, 0 failed**, while on the real runner it skips the gate. The same divergence holds in reverse for local cases: every `CI_ENV` key is set-but-empty there, unlike on a developer machine. The spec exists to judge future `setup.sh` versions, so its correctness cannot rest on how today's script happens to read variables.
Critique: the tempting fix is a sentence forbidding `${X+x}`/`-v` in `setup.sh`; nothing enforces it, and a text rule is what this raft removed.
Consequences: unsetting needs a process step, since Lune's `env` option only adds or overrides. `env -u NAME` does it on both BSD and GNU `env`, and R0210's gate spec deliberately allows `env -u` (c0640 case 6: "`env -u` is not listed"); none of the controlled names is on R0210's banned list, so the R0210 interaction stays clean. `env` is already resolved by `real()`. A name must never be both given by the case and unset; build the `-u` list from `CONTROLLED` minus the case's keys. The parent's own guards are still inherited, since only controlled names are removed.
Recommendation: run `<real env> -u N1 -u N2 ... <real bash> <repo>/scripts/setup.sh <args>` with `{ env = vars }` holding only `PATH`, `HOME`, `STUB_*` and the case's variables, `-u` for every other `CONTROLLED` name. Reword Design "Run", the spec header and R0230 to "unset" (and drop "blank is unset"). Add row Z5 (`[[ -n ${CI:-} && -z ${GITHUB_TOKEN+x} ]] && exit 0`, killed by the CI case) as `run`, and rerun the E3 parent-environment run (`CI=true RUNNER_OS=Linux GH_TOKEN=realtoken`) to confirm local cases still see none of them.
