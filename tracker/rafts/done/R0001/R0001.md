# R0001: Foundation

## Theme
Both issues make "`check.sh` passes" a trustworthy statement before any gameplay exists.
- **c0001** proves the gate and the tracker run identically on any host, including CI.
- **c0002** extends the gate from pure Logic to what Rojo actually builds for Roblox.

They touch the same area (test infrastructure: `scripts/`, `tests/lib`, CI) and share one risk: an unverified assumption about the environment. Both are chores.

## Whole-raft design
```
scripts/setup.sh ──runs──▶ scripts/check.sh --full ──▶ lune run tests/run
      ▲                                                   ├─ tests/unit, tests/tooling, tests/meta
      │ (CI: .github/workflows/check.yml)                 ├─ tests/place/*        (c0002, via tests/lib/place.luau → rojo build → @lune/roblox)
      │                                                   └─ tests/acceptance/*   (promoted by tracker done)
scripts/ci-verify.sh (c0001) ── gh workflow run + watch ──▶ same workflow, exact HEAD
scripts/affected.luau ─▶ scripts/lib/graph.luau (c0002: PLACE_LIB implicit deps on src/**, default.project.json)
```
- **Interfaces between the issues**:
  - `graph.PLACE_LIB` and `graph.affectedSpecs(g, changed, isSpec)` keep their existing signature; only the behavior extends.
  - c0001's CI runs whatever c0002 adds, so c0002's specs must run on Linux. `rojo build` and `@lune/roblox` both run on Linux.
- **No changes to `tracker/architecture.md`**: neither issue adds game features.

## Order & dependencies
1. **c0002 first.** It's purely local and fully specified.
2. **c0001 second.** Its AC3 (CI green) then also proves on Linux both c0002's place tests and every active acceptance spec, through the dispatch-only acceptance step (F8).

## Experiments phase
Most of this raft's unknowns concern the CI environment and are resolved by c0001's first `scripts/ci-verify.sh` run.
- **c0001**: E1 (setup.sh on ubuntu, including auth) and E3 (the dispatch run appearing). E0 (dispatching a branch) and E2 (the `lune` alias on Linux) were run in prep and PASSED.
- **c0002**: E1 and E2 were run in prep and PASSED. E3 is an accepted risk, deferred to the first relative require, with OC1.
- **Order**: push c0002's work early, then dispatch CI once, to surface E1–E3 before finishing c0001.

## Exit criteria
Implemented by `check.sh`:
- **RC0**: the full repo gate passes, and c0001 and c0002's `check.sh` pass. That includes CI green on this branch's HEAD (c0001 AC3), and the draft PR existing (c0001 AC5).
- **RC1**: after this raft, the gate's place tier runs. `tests/place/` contains at least one spec file, and running them all (`lune run tests/run -- $(find tests/place -name '*.spec.luau')`) reports 0 failures. An empty or missing directory fails (F1).

- **RC2**: `scripts/tracker.sh promote-check R0001` passes. It dry-runs the promotion of every member's acceptance specs into `tests/acceptance/` (type check + `tests/meta`), so problems appear before `done` rather than as a rollback at `done` (design-review-002 F1).

## Risks & rollback
- **Risk**: CI on Linux behaves differently from macOS (paths, `~` expansion, `sed -i`). Mitigation: setup.sh and check.sh must stay POSIX-bash, with no `sed -i ''`. Rollback: revert the workflow file; local gates are unaffected.
- **Risk**: GitHub API rate limits in `rokit install`. Mitigation: `rokit authenticate` in CI.
