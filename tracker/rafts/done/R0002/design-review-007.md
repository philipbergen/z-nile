### F1 [high] `launch` built on Lune's `process.exec` can't give the agent a terminal: stdin is never forwarded, and Ctrl-C kills the launcher while the agent keeps running. The spec can't detect either problem.
Where: c0046 Design, `cmd.launch` step 3 ("stdin, stdout and stderr forwarded"); Rules and mutants; `launch.spec.luau` (the fake agent never reads stdin); `~/.lune/.typedefs/0.10.5/process.luau` (`ExecStdioOptions.stdin: (buffer | string)?`)
Evidence: Lune 0.10.5 has no stdin passthrough. `ExecStdioKind` covers only stdout and stderr, and `stdin` can only be a string or buffer to write. Under a pty, `process.exec("bash", {"-c", "[ -t 0 ] …; read -t 2 line"}, {stdio = "forward"})` gives `fd0 notty, fd1 tty, fd2 tty, read failed`. The table form `{stdin = "forward", …}` and `"inherit"` behave the same (with `inherit`, stdout isn't a tty either). Claude Code's interactive UI needs a TTY on stdin, so `scripts/tracker.sh launch R0002` would not give an interactive session. Signals: when SIGINT goes to the process group of a Lune parent blocked in `process.exec` on a child that traps INT (as Claude Code does: Ctrl-C interrupts a turn), Lune dies immediately and the child keeps running and writing (`lune alive? no`; the child logged `child-got-INT` and then `child-finished`). The shell gets the prompt back while an orphaned agent still owns the terminal. The prototype's five passing cases don't show any of this, because the fake agent only records `pwd -P` and its arguments.
Critique: this is the main use of the command (Usability: "`launch R0002` replaces a two-step incantation"), and it fails the first time a human runs it. The tempting fix is to pump stdin through `process.create`'s writer. That still isn't a TTY (no raw mode, no job control), and it doesn't fix SIGINT.
Consequences: the robust fix is to have `scripts/tracker.sh` handle `launch` in bash and `exec` the command. That brings: (a) the worktree is ensured by calling `lune run scripts/tracker/main -- worktree "$target"` inside `$(…)`, so `ensureWorktree` doesn't need to be extracted, and c0045's `--from` extends `cmd.worktree` exactly as c0045 already says; (b) argument errors (no target, a token after the target that isn't `--`) are reported by bash with a usage line, so `set -u` must not turn a missing `$1` into `unbound variable`; (c) "cannot run <command>" needs `command -v "$1"` before `exec`, because a failed `exec` prints bash's own message and exits 127; (d) exit codes, signals (`128+n`) and the TTY are native; (e) it must work on macOS `/bin/bash` 3.2. I ran a prototype under 3.2 with `set -euo pipefail`: it handled `"" "a b" '"q"' -- '*'` untouched, gave `cannot run nope-xyz: not found` with exit 1, a tty on fd0 under a pty, and exit 44 for `exit 300`; (f) `USAGE` in main.luau still gains the `launch` line, and main.luau gets no `cmd.launch` (or gets one that tells the user to use the wrapper).
Recommendation: move `launch` into `scripts/tracker.sh` as above, and state (a) to (f) in the Design. Add a spec case, `launch forwards stdin to the command`: call `process.exec("bash", {"scripts/tracker.sh", "launch", "capture-demo", "--", "agent"}, {stdin = "hello\n", …})`, with the fake agent running `read -r line` and recording `stdin:$line`, and assert that line. It fails on any Lune-`process.exec` implementation and passes with `exec`. Add Rules rows "stdin reaches the command" (mutant: `process.exec` with `stdio = "forward"`) and "the launcher is replaced by the command" (reasoned; OC1 step: press Ctrl-C once in the launched agent; the agent interrupts its turn and the shell prompt does not come back). Re-run the mutation rows on the new prototype.

### F5 [medium] AC2's pass-through case uses only single-word tokens, so an implementation that joins the arguments into a shell string passes
Where: `launch.spec.luau:163-182`; AC2; Rules row "Arguments after `--` pass through untouched"
Evidence: the arguments tested are `--from origin/main --model x -- y`, which contain no spaces, empty strings, quotes or glob characters. `process.exec(table.concat(args, " "), {}, {shell = true})`, a Lune implementation with `shell = true`, or a bash wrapper that uses `$*` or unquoted `$@` (a likely slip in F1's bash fix) records the same seven lines and passes. Critique: this is a missing edge case on the one property AC2 names ("untouched"). The tempting fix is to add a single argument with a space.
Consequences: an empty string and a `*` catch different mutants (an empty argument dropped, a glob expanded in the worktree). The fake agent's `echo "$a"` already records each on its own line (an empty argument becomes an empty line), so `recorded()` must not drop interior empty lines. It drops only the trailing one today, which is correct.
Recommendation: extend the case with `"two words"`, `""`, `"*"` and `'say "hi"'` after `agent`, and assert them in order in `recorded()`. Add the mutants "join into a shell string" and "unquoted `$@`" to the row, and run them.

### F6 [medium] E3 is left to OC1, but one part of it is already known, and it affects every job the new rule starts: an agent in `.worktree/<id>` also loads the main checkout's `CLAUDE.md`, and it may lose the user's auto-memory
Where: c0046 Unknowns E3, OC1; R0002 Risks ("a session's project memory is keyed by its directory")
Evidence: Claude Code reads `CLAUDE.md` files recursively, from the working directory up toward `/` (its documented memory lookup). A session started in `<repo>/.worktree/R0002` therefore loads `.worktree/R0002/CLAUDE.md` and also `<repo>/CLAUDE.md`, and each `@AGENTS.md` resolves beside its own file. The agent reads two versions of `AGENTS.md`: the branch's and the main checkout's. They differ exactly when a raft edits `AGENTS.md`, which c0005 and c0046 both do in this raft. That's the nested layout's cost, and the sibling layout didn't have it. Separately, the user's auto-memory lives under a per-project key (this session's is `~/.claude/projects/-Users-philipbergen-code-pickman/memory/`). It currently holds working rules such as "ask before new work", "CI work is chore" and "reviewer on opus". If launched sessions get a different key, those rules stop applying to every job, and after c0046 every job is launched this way. The design calls this "worth a follow-up; it doesn't change this design".
Critique: E3 is cheap to run now: one `claude -p` from a scratch `.worktree/x`, asking which memory files are loaded and where the auto-memory directory is (or `/memory` interactively). Its answer could change the docs, or need a user decision, before execution rather than after the first real raft.
Consequences: if both `CLAUDE.md` files load, the tracker skill needs one sentence saying the branch's `AGENTS.md` and skills are authoritative, plus an OC1 check. If memory isn't shared, the user decides whether to move durable rules from memory into `AGENTS.md` or the skills. That is a product decision, so put it to the user now, together with any other questions.
Recommendation: run E3 in prep and record the loaded memory files and the memory directory for a session started in a nested worktree. Add the authoritative-copy sentence to c0046's tracker-skill bullet (and a JC1 rubric line). If memory isn't shared, ask the user now whether to promote the memory rules into `AGENTS.md` or the skills. Keep OC1 for confirmation only.
