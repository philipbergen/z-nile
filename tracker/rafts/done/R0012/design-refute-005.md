# Refute 005: R0012

Round 5 is the final round and it held two highs, so by ticket-prep's rule it goes to the user whatever is answered here. Both are answered in the documents and specs so the user decides with the fixes in hand.

- F1: fixed: f0027 `place.spec`'s Controls case gains a scope pin: the `local a, b = Touch.toScreen(` and `local w = Touch.screenSize(` locals must both lie between the last `function` keyword before the single `Touch.track(` and that call (the same function, no helper between, nothing hoisted to `start`), and `toScreen` must read `<name>.Position.X, <name>.Position.Y` after its inline `GetInsetArea(...)`. f0027's Controls paragraph prescribes that structure. consequences: an executor may not factor the conversion into a helper that returns the pair (stated in the design); the event handler is the one place. On the prototype Controls in a scratch clone the correct path passes, and three wrong ones fail the case on assertions: the width computed once in `start`, the origin cached at start as `toScreen(area, 0, 0)` and added to a raw `input.Position` copy, and a helper returning the pair. No user decision.
- F2: fixed: f0029 `place.spec` gains a case: the text of the `BindToRenderStep("PickmanHud", ...)` callback (from the call to its first `end)`) contains `GetInsetArea(` for None and for CoreUISafeInsets and `Touch.screenSize(`, and no `GetInsetArea(` occurs anywhere else in HudView. f0029's Design, AC3 and R0012 prescribe the callback: both reads, `local sw, sh = Touch.screenSize(...)`, `Hud.safeInset`, the key `(sw, sh, top, bottom, left, right)` against the last one, then `lay(sw, sh, inset)` with parameters of the same names calling `Hud.layout(sw, sh, inset)`; `lay` and `show` read no area. The re-layout key is now the screen size from `Touch.screenSize` plus the four insets, not `ViewportSize`. E5's Phase 1 adds a 180° landscape rotation check. consequences: the existing "Hud.layout(<w>, <h>," pin ties the names, which the design now states; a correct HudView that keeps a separate `lay` passes; checked by running the pin's patterns against a correct source and three wrong ones (areas read at module load, in `start`, and an empty step with the reads in `lay()` on the `ViewportSize` signal), which all fail. No user decision.
