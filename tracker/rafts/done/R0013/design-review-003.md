### F1 [medium] c0008's spec still accepts a `gh pr ready` that runs only when the raft promotes acceptance specs
Where: c0008 Design ("placed immediately before the loop that moves the members to `done/`"); Rules and mutants rows 1 and 2; `done-order.spec.luau` (the fixture always has `acceptance/alpha.spec.luau` when `done` succeeds or rolls back).
Evidence: I moved the designed block (pcall, rollback, fail) into the `if #promoted > 0 then` block of `cmd.done`, right after the `promotedChecks` refusal, which is a natural reading of "after the promotion checks", and deleted the old call after the push, as step 1 says. The spec passes 5/5: the refusal case, the rollback case and the success case all run with a promoted spec, so the ready call is always reached. For a raft whose members have no acceptance specs (a docs-only chore such as c0036 or c0037), that `done` never calls `gh pr ready`. The final push then lands on a draft, CI skips it, and Merging step 3 waits for a `gate` run that never comes. `done` still exits 0. That is the exact failure c0008 exists to remove, and AC1 doesn't limit itself to rafts with specs.
Critique: the tempting fix is to add a second raft to the fixture that has no specs. That needs a second `start`, review and origin branch, which doubles the fixture.
Consequences: the success case is the only one that has to reach the ready call without a promotion. The rollback case must keep its promoted spec, because that is what makes the "no rollback" mutant observable (E3). The opposite mutant (ready only when nothing is promoted) already dies in the rollback case, since `done` then succeeds. Dropping the spec from the success case means it no longer shows promotion and the GitHub path together. The c0001 lifecycle spec already covers promotion.
Recommendation: at the start of the success case, `git rm` `tracker/issues/active/f0010/acceptance/alpha.spec.luau` and commit it with `tr commit`. The case then also asserts `fs.isDir(work .. "/tests/acceptance/f0010") == false`, which proves the run had nothing to promote. Add a row: "`gh pr ready` runs whenever `done` goes through, whether or not anything was promoted | `marks the PR ready while origin still has the previous head …` (no acceptance spec) | ready inside the `if #promoted > 0` block". Re-run the designed code (passes) and this mutant (dies), and record both in E4.
