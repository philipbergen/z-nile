### F1 [low] The recovery line treats an exhausted publish 409 ("Roblox busy") as a real failure that must never be rerun
Where: `.claude/skills/tracker/SKILL.md`, Merging section, the new `beta` bullet ("Any other red `beta` (HTTP 401, 403, 404 or another 4xx ...) is a real failure: never rerun it")
Evidence: `OpenCloud.publish` treats 409 as busy and retryable (`scripts/lib/opencloud.luau:139-140`), and the comment calls it "Roblox answers 409 while it is busy". If Roblox stays busy through 4 pauses of 60 s, the log shows `opencloud: publish failed with HTTP 409: ...`. "another 4xx" covers 409, so the line says never rerun and post `BLOCKED:` (the cause isn't in this PR). The design's line listed only 401/403/404 and didn't decide 409.
Critique: the outcome is safe (a human is asked), but it sends a busy, Roblox-side condition to the human, though the code already calls it transient in kind. The tempting fix is adding 409 to the rerun list.
Consequences: a rerun after a 409 republishes the same build (harmless, "last one wins"), but the `beta-deploy` concurrency group already rules out our own concurrent publishes, so a 409 that persists for 4 minutes may point to a longer Roblox-side problem, and reruns would add up to 3 x 4 minutes of waiting.
Recommendation: optional. Either leave it as it is (a conservative and consistent choice) or name 409 explicitly in one direction, for example "HTTP 409 from publish after its retries: rerun once, then `BLOCKED:`". If the wording changes, keep it on the one line AC9 greps for. No spec change is needed.
