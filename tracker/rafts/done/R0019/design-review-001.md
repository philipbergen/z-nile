### F1 [high] The fixture makes HEAD the origin/main commit, so an implementation that reads HEAD (or a local `main`) instead of `origin/main` passes every case
Where: c0052/acceptance/renumber.spec.luau, `fixture()`; c0052.md Rules and mutants rows 1 and 4
Evidence: `fixture` commits the origin items on the init branch, runs `git update-ref refs/remotes/origin/main HEAD`, and only deletes the working tree, so `HEAD`, the init branch and `origin/main` are the same commit. In the scratch clone, replacing `"origin/main"` in the prototype's `originIds` with `"HEAD"` gives **17 passed, 0 failed**; with `"main"` it also gives **17 passed** (this machine's git initialises `main`), and `"master"` fails 11. In the case "origin/main unknown" there is no commit at all, so `ls-tree HEAD` / `ls-tree main` fail too and the refusal case passes as well. In real use HEAD is your own branch after `git merge --abort`: a HEAD-reading `renumber` ignores the colliding number on origin and picks one that collides again, which is the exact failure this issue fixes. The result of the `main` mutant also depends on the developer's `init.defaultBranch`, so the spec's strength differs between a laptop and CI.
Critique: AC1 ("across the local tree and origin/main") can be passed by a wrong implementation. The tempting fix is to delete HEAD (leave it unborn) after `update-ref`; that kills the HEAD mutant only through the refusal path and still says nothing about a stale local `main`.
Consequences: if local items are committed on a separate branch, `renumber` takes its `git mv` path for tracked documents in these cases (already covered by c0044's naming spec, so harmless); the origin-nil case then has a valid HEAD, which is fine because it asserts the refusal on `origin/main` alone. The fixture also inherits the user's global git config (`commit.gpgsign=true` would make the origin commit fail silently, since `git()` ignores the result, and every case would then fail with a misleading refusal).
Recommendation: in `fixture`, `git init -q -b scratch` (explicit, environment-independent), commit the origin items, `update-ref refs/remotes/origin/main HEAD`, then `git checkout -q --orphan local`, clear the index and tree, write the local items and commit them, so HEAD holds only the local items and is a different commit from origin/main. Add a case "a stale local `main` does not count": a local branch `main` pointing at a commit with a lower number (for example `issues/c0002`) while origin/main holds `c0150`, expecting f0151, and a case where local `main` holds a *higher* number than origin/main and the local tree (expected: it is ignored). Pass `-c commit.gpgsign=false` in `git()` and assert that the origin commit and `update-ref` succeeded (`t.expect(r.ok)`), so a broken fixture fails loudly. Add mutant rows "M13 read HEAD instead of origin/main" and "M14 read local main" to the Rules and mutants table (rule 1), run them on the prototype, and record the counts in Unknowns & experiments.

### F4 [low] Two statements in the documents are no longer accurate
Where: R0019.md Risks ("R0016 (c0048, c0050) … being edited"); c0052 Design/Maintainability and R0019 table ("new pure `store.nextAbove`")
Evidence: R0016 merged to main as 55e94b3; only c0053 remains in flight. `store.nextAbove` calls `store.all(kind)`, which reads the filesystem and raises on a legacy-named document, a missing `slug:` or a duplicate id anywhere in that kind's tree, so it is not pure, and `renumber` without `<new>` now fails on tree problems that the explicit form never touched.
Critique: an executor reading "pure" may write a unit test with no fixture tree, or be surprised that a single bad document blocks the renumber.
Consequences: none if worded correctly; the failure is acceptable because Landing step 0 already runs `tracker.sh list`, which fails on the same problems.
Recommendation: after the merge (F2), drop R0016 from Risks (keep c0053), and call `nextAbove` "the number-space rule, reading the local tree through `store.all`", noting that it fails as `list` does on a malformed tree.
