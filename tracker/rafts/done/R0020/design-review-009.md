### F1 [high] c0440's AC4 can never pass: stylua wrapped the renamed case over two lines, and `cases_pass` requires `it("<name>` on one line
Where: `tracker/issues/c0440/acceptance/launch.spec.luau:226-227`; `tracker/issues/c0440/check.sh` (`cases_pass`, `grep -qF "it(\"$c" "$spec"`; AC4 passes the prefix `"launch rejects an unknown target"`)
Evidence: the case was renamed to `launch rejects an unknown target, a done raft, a stray argument and a bad command, and starts nothing`. At that length stylua (`column_width = 110`) formats it as `it(` on line 226 and the name on line 227. So `grep -qF 'it("launch rejects an unknown target'` finds nothing. Running `check.sh`'s own `cases_pass` against the spec, with a spec output of `7 passed, 0 failed, 1 spec files`, gives `the spec has no case starting "launch rejects an unknown target"` and AC4 rc=1. AC3 passes the same way (rc=0), so only this case is affected. Every other prefix in c0041, c0420, c0430 and c0440 is found. The check and spec are sequestered, so a correct implementation fails `tracker.sh check c0440`, and `done` fails with it. The executor's only way out is to escalate. Prototype run 2 reports the spec's cases, but it doesn't report `tracker.sh check c0440`, which would have caught this.
Critique: the tempting fix is to join the lines by hand. `stylua --check` (part of the gate) would reject that, or the next format run would wrap them again.
Consequences: the case name must fit `\tit("<name>", function()` in 110 columns, so the name can have at most about 90 characters. The Test plan list, the Rules and mutants row and the AC4 prefix must all still match the new name. Any later case name longer than that hits the same trap.
Recommendation: shorten the name and keep the prefix, for example `launch rejects an unknown target, a done raft, a stray argument or a bad command` (the line becomes 103 columns). Update the Test plan bullet and the Rules row to match. Then, on the stacked prototype, re-run `stylua --check` and `scripts/tracker.sh check c0440`: every AC except AC6 (the executor's docs) must pass, and the Verification log should record that. Optionally add a sentence to the testing skill: a case name that `check.sh` greps has to fit on the `it("…", function()` line.

### F2 [low] Loose ends in the hardened `launch` and its record (partly a repeat of design-review-008 F5)
Where: `launch.spec.luau` fake `lune` (`rel) echo relative/path`); c0440 Design block (`! -x $cmdpath`) and Rules row "drop the executable check"; R0020 Experiments phase; c0420 frontmatter; `launch.spec.luau:230`
Evidence and Recommendation, item by item:
- **The absolute-path test isn't pinned by the spec.** A mutant that keeps only `! -d $path` passes the wrapper-only run, because `relative/path` doesn't exist. It would accept a relative path that does exist, such as `.`, which (from the repo root where the wrapper runs) means launching in the main checkout. That is the exact failure c0440 prevents. Make the fake's `rel` mode print `.` instead. The newline test is likewise covered only by `-d`, which is harmless.
- **`! -x $cmdpath` is dead code.** On bash 3.2, `type -P` already fails for a non-executable file on `PATH`, for an absolute non-executable (`/etc/hosts`) and for a directory (`/etc`). The mutant "drop the `-x` test" is equivalent (it survived here), so the Rules row's "drop the executable check" can only mean dropping the whole `type -P` check. Say so, or drop `-x`.
- **Stale wording, repeated from design-review-008 F5:**
  - R0020's Experiments phase still says "pass with all three prototypes". There are four. The refutation's reading (the three specs c0420 updates) fits only the later "three old specs".
  - c0420 still says `design: ready` while its siblings say `reviewed`.
- **A spec robustness nit:** `launch rejects …` calls `fs.removeFile(log)` without checking that the file exists. It errors with `No such file or directory` whenever the earlier cases didn't run the agent, which hides the real failure. Guard it as the new case does (`if fs.isFile(log)`).
