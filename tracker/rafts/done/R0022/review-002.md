### F1 [medium] On macOS the new spec's no-leak assertion can't fail: a mutant that drops the cleanup passes it
Where: tests/tooling/run-guard-relaunch.spec.luau:16-24 (`TMPDIR = tmp` ... `t.expect(#fs.readDir(tmp)).toBe(0)`), tests/run.luau:42 (`process.exec("mktemp", { "-d" })`)
Evidence: the spec checks for leaks by pointing `TMPDIR` at an empty directory and expecting it to stay empty. On macOS, BSD `mktemp -d` with no template ignores `TMPDIR`. A probe (`process.exec("mktemp", {"-d"}, { env = { PATH = "/usr/bin:/bin", TMPDIR = "<cwd>/.cache/.../t" } })`) returned `/var/folders/b1/.../T/tmp.8wdBqm3QOO`, and `t` stayed empty. As a mutation test, the reviewer replaced the `fs.removeDir(dir)` in the new `if not ok then` branch with a comment and ran `lune run tests/run -- tests/tooling/run-guard-relaunch.spec.luau`. Result: `1 passed, 0 failed`, while a guard directory leaked into `/var/folders/.../T` (the reviewer then restored the file and deleted that directory). GNU `mktemp` on the ubuntu CI runners does honour `TMPDIR`, so CI would catch the mutant. On the development platform, though, the half of the fix the spec was added to pin goes untested, and refute-001's claim that the spec "fails without the fix" holds only for the message, not for the cleanup.
Critique: a check that can't fail on macOS lets a regression of the cleanup land, and the local gate stays green. The tempting fix is to change the spec so it looks in `/var/folders` or `$TMPDIR` for new `tmp.*` directories. That races with every other runner on the machine (parallel worktrees, other sessions), and would turn the spec flaky.
Consequences: the better fix is to make the runner honour `TMPDIR` on both platforms by giving `mktemp` an explicit template. That brings three rules. First, the base is `TMPDIR`, or `/tmp` when it is unset or empty, with a trailing `/` stripped (macOS's default `TMPDIR` ends in `/`). Second, a `TMPDIR` that doesn't exist makes `mktemp` fail, and the runner's existing `tests/run: mktemp failed` path already covers that. Third, a distinctive prefix such as `pickman-guard.` makes any directory that still leaks (Ctrl-C, accepted in refute-001) easy to find and delete. On macOS the default location doesn't change, because `$TMPDIR` is the same `/var/folders/.../T/`. With the template in place, the spec's existing assertion becomes real on both platforms. But nothing would show it is real, and that same blind spot is why this round's finding exists.
Recommendation: in tests/run.luau, build the guard directory with `mktemp -d <base>/pickman-guard.XXXXXX`, where `<base>` follows the rules above. Keep the current spec case: it now fails on macOS under the drop-the-cleanup mutant. Add a positive-control case to the same spec, so the leak check can't go vacuous again. Write a fixture spec under `.cache/run-guard-relaunch/` that writes `process.env.PICKMAN_OPEN_GUARD` to a file. Run the runner with `lune` on PATH, `PICKMAN_OPEN_GUARD = ""` and `TMPDIR = tmp`. Expect exit 0, a recorded guard path that starts with `tmp`, and `tmp` empty after the run, which also pins cleanup on the normal path. Mutation-check it locally on macOS: remove the `removeDir` in the error branch and the first case must fail; ignore `TMPDIR` in the template and the second case must fail.

Note (not a finding): the system temp dir holds about 30 leftover `tmp.*` guard directories from 2026-10-01 and 2026-10-02, some with an `opened.log` written by the `proto-c0057` prototype. The reviewer couldn't reproduce a leak from this branch's gate or tracker check, so they most likely come from prototypes, interrupted runs or other sessions.
