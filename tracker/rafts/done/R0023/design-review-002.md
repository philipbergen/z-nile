### F1 [high] The `CI_ENV` snapshot still misses runner variables set on every GitHub run step, and the pass-through case drops exactly those, so a skip on `GITHUB_ENV` or `GITHUB_OUTPUT` survives everywhere (repeat of design-review-001 F1, narrowed)
Where: setup-run.spec.luau `CI_ENV` (lines 175-211) and `NOT_PASSED` (214-235); c0055.md Design case 3 ("every default GitHub runner variable") and 4b; AC3 ("on CI (every default GitHub runner variable ...)").
Evidence: each mutant inserted before `say "gate"`, spec run with `GITHUB_ENV=/dev/null GITHUB_OUTPUT=/dev/null GITHUB_STEP_SUMMARY=/dev/null` exported in the parent (as on a runner):
- `[[ -n ${GITHUB_ENV:-} ]] && exit 0`: **9 passed, 0 failed**.
- `[[ -n ${GITHUB_OUTPUT:-} ]] && exit 0`: **9 passed, 0 failed**.
- control, `[[ -n ${RUNNER_OS:-} ]] && exit 0`: 7 passed, 2 failed (killed, as the refute says).
`GITHUB_ENV`, `GITHUB_OUTPUT` and `GITHUB_STEP_SUMMARY` are set in every `run:` step of `check.yml`'s gate job, so these mutants make the real gate exit 0 before `scripts/check.sh --full`. `CI_ENV` has none of them (it sets only `GITHUB_PATH` in case 3), and `passthrough()` removes them by name. `GITHUB_EVENT_PATH` (always set) and `RUNNER_WORKSPACE` are also absent from `CI_ENV`; they reach only the pass-through case, which cannot fire on CI (F2). AC3's prose ("every default GitHub runner variable") is therefore false and passes with a gate-skipping `setup.sh`.
Critique: round 1 asked for the file-pointing variables to be "pointed at sandbox files"; they were dropped instead, which turned "safe" into "invisible". The tempting fix is to add the two names; the same miss then recurs for the next always-set name.
Consequences: pointing them at sandbox files is safe (setup.sh does not write them; a stub can't reach the real runner files), and lets the spec assert they are left untouched. The snapshot needs an honest scope: the variables GitHub documents as always set for a `run:` step on `ubuntu-latest`, not "every" variable.
Recommendation: in `CI_ENV` add `GITHUB_ENV`, `GITHUB_OUTPUT`, `GITHUB_STEP_SUMMARY`, `GITHUB_STATE`, `GITHUB_EVENT_PATH` (each a file under `ROOT`), `RUNNER_WORKSPACE`, `RUNNER_TRACKING_ID`, `GITHUB_ACTION_REPOSITORY`/`GITHUB_ACTION_REF` (empty strings, as GitHub sets them for `run:` steps); in `passthrough()` override the file variables with the same sandbox paths rather than dropping them. Case 3 then also asserts `GITHUB_ENV`/`GITHUB_OUTPUT` files are empty. Add rows Y (`GITHUB_ENV`), Z (`GITHUB_OUTPUT`), AA (`GITHUB_EVENT_PATH`) as `run`, and reword AC3/case 3 to "GitHub's documented default variables for a `run:` step".
