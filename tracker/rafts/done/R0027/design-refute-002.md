# Refute 002: R0027 (answers to design-review-002)

- F1: fixed: new c0082 audit error `retired-id`. It applies only when `tracker/compaction.txt` exists, and fires on an item folder named with a retired id, or a `raft:`/`issues:`/`depends_on:` token that names one (`ids.retiredIds(map)`: the map's old ids that are not also new ids). Its message says to undo the merge and run `remap`. New cases: three in audit.spec; in remap.spec, a second busy branch (`late-y`, a new item depending on `c0001`) plain-merges `origin/main` cleanly and then fails `tracker.sh audit` with `retired-id` and `remap`. The skill's Compaction bullet says to remap **before merging `origin/main`**, with a skill-doc case. consequences: as the reviewer defined it, the rule would also fire on a *legitimate* item allocated after the compaction whose number an old id once had (e.g. a new c0010 once the counter passes 90), and that turns the real gate red. Handled by a new allocation rule: once a map exists, `ids.nextFree` skips every number a retired id had, in its space and for any prefix (about 80 numbers below 890), so no new item ever carries a retired id and the audit can never fire on a sound tree. Covered by new `ids.retiredIds` and the skip cases in ids.spec, plus Rules rows. It also stops new items reusing numbers that old comments still mean.
- F2: fixed: the stale-tree refusal now covers every command that publishes (`new`, emergent `new`, `new raft`, `renumber` without `<new>`, `status <id> <to>`, `start`), in one helper called before `publish.commit`; `remap` is exempt. remap.spec's stale case also checks that `status c0001 preparing` refuses naming `remap`, with origin unchanged. Rules row added. consequences: none.
