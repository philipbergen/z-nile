# R0030: Sim harness

## Theme
A single-issue raft for c0090, roadmap raft **a1**. Pillar 2 of `tracker/game-design.md` says every game outcome is decided by pure Logic and tested headless. This raft builds the tool that makes such tests read like stories and fail usefully, before any game rule exists, so a2 (maze, movement, session) can be written simulation-first. It's a chore: test infrastructure, with no change in game behavior.

## Whole-raft design
See c0090's Design for the full API. The shape:
```
tests/scenario/*.spec.luau ──uses──▶ tests/lib/sim.luau ──drives──▶ Model { new(seed), step(state, intents, k), observe(state) }
                                            │                              ▲
                                            ├─ Trace (states per time, stamped events)
                                            ├─ replay JSON ─▶ .cache/sim/  │ later: f0110 Movement wrapper,
                                            └─ bench (N worlds, interleaved)  f0120 Session = the game's model
```
- **The contract for later rafts** is the tick semantics: step `k` takes time `k` to `k+1`; intents at `k` are delivered in step `k`; events are visible at `k+1`. f0110 and f0120 must implement their models to match. The testing skill documents it.
- **No changes to `src/` or `tracker/architecture.md`.** The harness is test-only and doesn't depend on any feature.

## Order & dependencies
One issue. Its implementation steps are ordered: core run, then replay, determinism and bench, then the tier and docs. The roadmap has a2 (f0100–f0130) after this raft; f0110 lists c0090 in `depends_on`.

## Experiments phase
All run in prep, all PASS: E1 (`os.clock`), E2 (JSON round trip) and E3 (a prototype satisfying all six acceptance specs, plus a strict type check and a mutation check). The executor has no Phase 1 work.

## Exit criteria
Implemented by `check.sh`:
- **RC0**: the full repo gate passes, c0090's `check.sh` passes (AC1–AC7), and `promote-check` passes.
- **RC1**: `tests/scenario/` exists and contains at least one spec. At least one of them requires `@tests/lib/sim`, and they all pass.
- **RC2**: running the scenario specs and c0090's acceptance specs, including the ones that deliberately fail runs and write replays, leaves `git status --porcelain` unchanged. Replays go only to the ignored `.cache/`.

## Risks & rollback
- **Risk: the CPU budget (AC6) is flaky on slow CI hosts.** The prototype needed about 3 ms against a 500 ms budget, a margin of about 150×. If it still flakes, file a chore; don't loosen the spec during execution.
- **Risk: the tick semantics turn out awkward for f0110 or f0120.** They were chosen to match the classic arcade loop and the server's fixed step. Changing them later means a harness chore plus updating the scenario specs, which are few, since this raft adds only its own.
- **Rollback**: revert the PR. Nothing else depends on the harness yet.
