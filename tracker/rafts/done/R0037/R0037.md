# R0037: Radar clear of chat

## Theme
One defect, d0105. f0033's radar is drawn in the top-right, and a Roblox top-right CoreGui covers it (the user reported the in-game chat). The player cannot read the map.

Decisions relied on (quoted from `tracker/game-design.md`):
- **Danger awareness** (2026-10-01): "A minimap/radar and edge indicators show where ghosts are in first person." The corner is not in that decision. f0033 put the frame in the top-right; this raft moves the frame.
- **Players** (2026-09-29): "Solo mazes. Each player gets their own maze instance (with their own ghosts) inside a shared server." Other players still share the server, so the chat stays on. The user's other option, turning the chat off, is not taken.

## Whole-raft design
```
Hud.layout(width, height) -> margin, barHeight, ...     (unchanged)
Hud.radarBox(width, height, size) -> { x, y, w, h }     (new, pure)
DangerHud render step, every frame, before the snapshot guard:
    radar.Position = fromOffset(radarBox(view.X, view.Y, radarSize))
```
No new feature and no new edge in `tracker/architecture.md`. `DangerHud` is an adapter; it may require `Hud`. The radar's contents, the arrows and `HudView` stay as they are. The power bar stays bottom-right; the radar sits one margin above it.
