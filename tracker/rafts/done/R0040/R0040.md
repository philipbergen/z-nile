# R0040: Barebones game

## Theme
Roadmap raft **a2**: "a maze you can walk through in first person, in Studio". The four issues are one vertical slice, and each is only meaningful with the others:
- the maze (f0100);
- how the player moves through it (f0110);
- the server that simulates it per player (f0120);
- the client that shows it in first person (f0130).

The user kept it as one raft on 2026-09-29, knowing it is about 1,800 changed lines, above the ~1,500 guideline.

**Prerequisite: R0050 (chore c0390, `@game` requires) must be merged to main before this raft starts.** Adapters reach Logic through `@game/…`, which the repo's resolvers only accept after c0390.

Decisions from `tracker/game-design.md` this raft relies on (quoted):
- **Pillar 2**: "Everything that decides an outcome runs in pure Logic, can be simulated headless and is tested in CI. Roblox renders and relays input."
- **Movement**: "Rail movement with free look". "The player always moves along the current corridor at the level's speed and stops at a wall." "There is no free strafing; position is always on a corridor centreline."
- **Corners** (user, 2026-09-29): "Corners are classic: at a corner the player stops unless a turn into it is buffered. There is no automatic cornering."
- **Back** (user, 2026-09-29): "`Back` is a literal reverse of the current heading (arcade), even right after a turn."
- **Cornering grace** (user, 2026-09-29): "a turn arriving one tick after passing straight through a centre where that exit exists is taken there, cutting the corner."
- **Missed turns** (user, 2026-09-29): "a later press for a turn the player just passed straight by is discarded while the player is still nearer that junction than the next one ahead with that exit, so a late press never diverts the player at a later junction. A press nearer the next such junction is buffered for it."
- **Start gate** (user, 2026-09-29): "A session starts only when its client signals it's ready."
- **Turn intents**: "`Left`, `Right`, `Back` and `Forward`, relative to the current heading. A turn intent is buffered and taken at the next tile where that exit exists. `Back` reverses immediately."
- **Look**: "the camera's yaw and pitch are free and never change the heading. A 'snap look to heading' action recentres it."
- **Collisions** are grid rules in Logic: "wall contact means stopping at the tile edge", which this raft reads as the player one tile wide, stopping on the last centre (recorded in the game design), and "pellets are eaten when the player enters a tile" (the `Entered` event).
- **Players**: "Solo mazes. Each player gets their own maze instance … inside a shared server. Other players' mazes aren't visible. Logic should still allow N players per maze later."
- **Authority**: "The server simulates every maze. Clients send intents and render the replicated state."

Prep decisions (now recorded in `game-design.md`):
- the tick rate is **30 Hz**;
- level-1 speed is **7.5 tiles/s**;
- the turn buffer is **0.8 s (24 ticks)**.

**Interfaces between issues** (the full signatures are in each issue):
- **f0100 → all**: `Maze.Maze` (frozen), `Tile {x, y}` (0-based, x column, y row), `Heading "N"|"E"|"S"|"W"`, `passable(m, tile, "player"|"ghost")`, and `neighbor(m, tile, h) → (Tile, wrapped)`. The conventions (−y is N) live only here.
- **f0110 → f0120**:
  - `Movement.spawn(m, h?) → State` and `Movement.step(m, s, intents, config) → { Event }`, where the events are `Entered{x,y}`, `Stopped{x,y}` and `Wrapped`;
  - `Movement.position(s) → (x, y)`;
  - `Movement.isIntent`, `validateConfig`, `DEFAULT_CONFIG`, and `UNITS = 120`.
- **f0120 → f0130**:
  - `Session.Snapshot` v1: `{ v, tick, maze, player = { x, y, heading, moving, jumpTick } }`;
  - `Session.TICK_RATE = 30`;
  - the remotes `ReplicatedStorage.Remotes.Ready` (client → server, once, when listening), `.Intent` (client → server: one intent string) and `.Snapshot` (server → owning client: a Snapshot).
- **f0110 → f0130**: the `Movement.Intent` type, for `View.Action`.

**Architecture changes, made in prep** (`tracker/architecture.md`): the four features, and these `deps` edges:
- `Movement -> Maze`;
- `Session -> Maze`, `Session -> Movement`;
- `View -> Maze`, `View -> Movement`, `View -> Session`.

The graph is acyclic. `Maze` depends on nothing.

**Tick contract** (c0090): `Session` is the game's sim model. Step k takes time k to k+1, intents at k act in step k, and events are stamped k+1. f0120 AC3 and every later raft test the game through it.

**Requires**:
- inside a feature's `init.luau`, sibling features are `./Maze` (not `../Maze`);
- adapters use `@game/ReplicatedStorage/Shared/Logic/<Feature>` (c0390);
- client adapter siblings are `./Camera` etc.

## Risks & rollback
- **Risk: R0050 isn't merged first.** The place specs, the meta rule and RC2 fail at the first adapter. Order step 0 makes this a stop, not a workaround.
- **Risk: Roblox rejects `@game` at runtime** (documented, but not yet run in Studio). It shows at once in the OC playtest as a require error. The fallback is in c0390 and is a follow-up chore, not a change during execution.
- **Risk: the scale or speed feels wrong in first person.** Every such value is a named constant or config. OC1 asks the human to note it, and the fix is a tuning issue. Acceptance specs pass explicit configs and relative bounds, so tuning `DEFAULT_CONFIG` or `View.SCALE` doesn't touch sequestered specs.
- **Risk: latency makes turns feel late** (no client prediction). Turns are buffered and taken at tile centres, which absorbs up to about 0.8 s of press-ahead, and Studio has no latency. Cornering grace covers only one tick, so with network latency a late press becomes a missed turn (discarded, never a wrong turn) rather than a corner cut. If Beta playtests (raft b) feel laggy, file prediction as a feature.
- **Risk: PR size** (about 1,800 lines). Mitigations:
  - the implementation steps commit per issue and per step;
  - reviewers get four well-separated modules;
  - adapter size is capped.
- **Rollback**: revert the PR. Nothing else depends on these features yet, and `tracker/architecture.md`'s edges can stay (unused declared edges are harmless).
