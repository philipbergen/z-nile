### F1 [medium] The lesson `tracker/item-history-spans-moves-and-compaction` tells readers to build the id-crossing walk the user rejected
Where: `.claude/skills/tracker/lessons/item-history-spans-moves-and-compaction.md:11` (How to apply)
Evidence: The text says "use `scripts/tracker/trail.luau` (`trail.read`): the item's three folders, plus, walking back through every commit that changed `tracker/compaction.txt`, the id each one renamed, with `--no-renames`. Match a capture subject against the id the item had at that commit." That is the round 008 to 012 mechanism. The settled design (the user's "Never cross; mark it", design review 013; c0111 The trail; c0111 E8) follows the current id only. `trail.read` (`scripts/tracker/trail.luau`) never walks back through compactions: it *stops* at the newest commit that changed the map and the document and marks it. The lesson's own `check` line says the right thing ("never infer identity across an id change … but mark it instead"), so its body contradicts its check. This is a `both` lesson, so `renderPrompt` puts it in every execution prompt, and design prep reads it in full during the lessons pass. An agent applying "How to apply" to item history (c0114 moves `trail.dirs` and the compaction map path) rebuilds the crossing that took seven review rounds to remove.
Critique: The tempting fix is to delete the sentence. That leaves the lesson with no "how to apply" for the hard part, the compaction case.
Consequences: The rewrite must also stop citing `trail.read` as doing something it doesn't, and should still name the fixture cases (move, legacy name, compaction with a reused number, look-alike file) the capture-cli spec uses.
Recommendation: Rewrite How to apply to the settled rule: read the item's three folders under its current id with `--no-renames` (never `--follow`), start its life at its last absent-to-present document change, stop at the newest commit that changed `tracker/compaction.txt` and its document and mark the result (`(history before <sha> not followed …)`), and mark the other weak answers (`(no capture commit: first add)`, `(ambiguous: …)`). Never match a subject against an older id. Keep the fixture sentence. Then run `scripts/tracker.sh lessons --check`. This is a lead-owned lesson file, not sequestered.
Lesson: ticket-prep/restated-rules-move-together

### F2 [low] A Finder `.DS_Store` in any lessons folder turns `lessons --check` red on macOS
Where: `scripts/tracker/lessons.luau:541-551` (`load`)
Evidence: `load` reports every name in a `lessons/` folder that isn't `<slug>.md` as `…/lessons/<name>: not a lesson file`. When someone opens a lessons folder in Finder, macOS writes `.DS_Store` there. Git ignores it, but `load` reads the filesystem, so `lessons --check` (c0111 AC8, c0119 AC3, the confirm-harvest steps, and through them `done`) fails on the developer's Mac with nothing in git to fix.
Critique: This matches the Design ("a file in a `lessons/` folder that is not `<slug>.md`"), so it isn't a deviation. It is a likely local stumble on the host this project runs on.
Consequences: Skipping all dotfiles also hides a mistyped `.foo.md`. Skipping only names git ignores costs a `git check-ignore` call per name.
Recommendation: Skip only `.DS_Store` (or names starting with `.`). Record it as a Design deviation in c0111's Verification log, and confirm that lessons-cli's "a non-`.md` file is named" case still names its non-dotfile. Or leave it as designed and note it under c0111's Usability.
