# R0170: Slow game speed

## Theme
The user asked (2026-10-01) to slow the game down by 50%, everything in game time, as a small raft now. One issue, f0520, slows the **clock** (steps per real second), leaving every Logic rule and tick-pinned spec, R0090's prepped ones included, untouched.

Decisions from `tracker/game-design.md` this raft relies on (quoted):
- **Movement**: "Level 1 is 7.5 tiles/s, the arcade's 80% (R0040)": this raft changes the real-time pace to 3.75 tiles/s and records that as a user decision.
- **Tick rate**: "Logic runs on a fixed 30 Hz tick (R0040) and is independent of frame rate. Clients interpolate." The rules keep counting 30 ticks per game second; only the server's steps per real second change.
- **Pillar 2**: "Everything that decides an outcome runs in pure Logic": the rules don't change; only two adapters pick the pace.

## Whole-raft design
```
 Session (Logic): TICK_RATE 30 (ticks per second of play)   GAME_SPEED 0.5   STEP_RATE = 15
        │                                                          │
 src/server/Sessions.luau   clock = Session.newClock(STEP_RATE) ───┘  15 steps per real second, one snapshot each
 src/client/Camera.luau     View.interpolate(prev, snap, View.alpha(elapsed))   (View.alpha = elapsed * STEP_RATE)
```
One new Logic function, `View.alpha`, in the existing `View` feature (View -> Session is already declared); no `architecture.md` change.

## Order & dependencies
Single issue, no dependencies. It lands before R0090 executes; R0090's specs count ticks, so nothing in them changes.

## Experiments phase
Run in prep (see f0520): the full gate on a prototype, and a 12-mutant check, all killed. Nothing is left for the executor but the red/green loop.

## Exit criteria
- `scripts/check.sh --full`, f0520's `check.sh` and the promotion check pass (RC0).
- **RC1**: end to end, a level-1 player walking through the server's own clock (`newClock(STEP_RATE)`) covers 3.75 tiles in one real second.
"Done" == `scripts/tracker.sh done R0170` succeeds.

## Risks & rollback
- **Real-time presentation left as is** (design review F3): `View.TURN_SECONDS` and mouse look stay in real time; a key press waits up to 67 ms instead of 33 ms. Recorded in game-design for the user to veto.
- **Smoothness at 15 Hz**: the client interpolates every frame, but a laggy network now feels it twice as much per dropped snapshot; `jumpTick` still cuts teleports. Observed in OC1. Retune by changing `GAME_SPEED`.
- **R0090 and later rafts**: they count ticks, so they slow down automatically; their real-time pauses (2 s ready) become 4 s. If that is too slow they are retuned in ticks in their own rafts.
- **Rollback**: revert the PR (three small edits).
