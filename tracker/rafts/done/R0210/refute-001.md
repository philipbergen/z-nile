# Refute 001: R0210

- F1: fixed: the jail now denies all IP networking (`(deny network-outbound (remote ip))`; unix sockets stay open). A `-c protocol.allow=always` or `-c credential.helper=…` therefore reaches nothing on macOS.
  - **Experiment** in `$TMPDIR`: `git ls-remote https://github.com/…` failed to connect under the profile, and a fixture commit worked.
  - **Where there is no jail** (Linux), the gate scan now bans `protocol.allow`, `protocol.http*`/`ssh`/`git`, `credential.`, `extraheader` (CI's checkout token), `GIT_SSH_COMMAND`, `GIT_ASKPASS` and `SSH_ASKPASS`. Nothing outside the guards names them today.
  - **Proven every run:** the gate's jail case reads the profile through the new `fence.profile` export, and, when jailed by `sandbox-exec`, connects to TEST-NET (192.0.2.1:9), which must fail with `Operation not permitted` (it times out outside the jail). The scan case plants each override (concatenated, so the spec names none) and requires that each is caught.
  - **Mutants:** J7 (no network deny) and S7 (`protocol.allow` not banned) are each killed. Folding the self-test into the existing case keeps the gate at the seven cases AC6 pins.
- F2: fixed: the profile also denies writes to every ancestor of each protected path (`(deny file-write* (literal …))`, up to `/`), for the checkout, the common git dir, the main checkout, outer guards' repositories, `~/.gitconfig` and `~/.config/git`. Other children of those directories stay writable.
  - **Experiment** in `$TMPDIR`: renaming the ancestor and the next level down was refused (`Operation not permitted`), and writing a sibling file and making a sibling folder worked.
  - **Proof in the gate:** a live rename probe would move the checkout if the jail were broken, and `rename(p, p)` is never checked by the sandbox, so the gate's jail case asserts a literal deny for every ancestor of the checkout in the profile. J8 (no ancestor denies) is killed.
- F3: fixed: the identity rule reads every `*EMAIL` value as well as `user.email`, so c0010's and c0070's `GIT_AUTHOR_EMAIL`/`GIT_COMMITTER_EMAIL` are checked. A planted `GIT_AUTHOR_EMAIL = "dev@example.com"` is caught (folded into the identity case), and S8 (env identities not read) is killed. On the second point: in c0010 and c0070 every git and tracker call goes through the `git`/`run`/`tr` helpers, which always pass the identity. The only raw calls left are `rev-parse`, `ls-files`, `init` and `clone`, which write no commit (`retrofit.spec` enforces that list), so no call commits as the person.
- F4: fixed in part: `fixture.exec`/`fixture.git` refuse a global `-c core.worktree=…` (case-insensitive) and any `GIT_CONFIG_*` variable in `env` (the helper's allowlist entry gained `GIT_CONFIG_`). Regression spec: `tests/tooling/fixture-elsewhere.spec.luau` (refusals, plus an ordinary `-c` still passes). A shell script that changes directory inside a fixture is out of the helper's reach by design: it checks where a command starts, not what the command does. That is exactly why the runner's guards stay in place (the jail on macOS, the fence everywhere), and why the testing skill bans raw shell strings in these specs. c0330's `ac.sh` case reads the real root and writes nothing.
- F5: fixed: in `fixtureOfGuarded`, an outer guard counts only when its `PICKMAN_FENCE_REAL_GIT` entry is an existing directory, so a stale or made-up entry proves nothing.
