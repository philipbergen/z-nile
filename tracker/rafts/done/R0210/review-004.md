### F1 [high] Regression from the review-003 F2 fix: a spec can replace `.cache` with a symlink, and the next unjailed `pickman_fence` then runs `rm -rf` on the shared `.git` of every worktree
Where: `scripts/lib/fence.sh:23-28` (`mkdir -p "$here/.cache"`, then `if [[ -L $sentinel || -d $sentinel ]]; then rm -rf "$here/.cache/.git"; fi`, then `printf … >"$sentinel"`); `scripts/lib/ac.sh:11-13` (every `check.sh` calls `pickman_fence "$(pwd -P)"` without the jail); `tests/lib/fence.luau` `profile` (`(allow file-write* (subpath "<cache>"))` also covers the `.cache` entry itself).
Evidence: two steps, both reproduced in a scratch copy under `$TMPDIR`.
1. Under `sandbox-exec` with the jail's rules for a scratch checkout `F` (`(deny file-write* (subpath "/"))`, `(allow file-write* (subpath "/dev"))`, `(allow file-write* (subpath "<F>/.cache"))`), a write to `F/escape` fails as intended. But `rm -rf F/.cache` succeeds (`REMOVED-cache`), and `ln -s <V> F/.cache` succeeds (`LINKED`). A subpath rule matches the path itself, so the entry `.cache` can be unlinked and created again as a symlink. A write through the link is denied inside the jail, but the link stays after the run ends.
2. Unjailed, `source scripts/lib/fence.sh && pickman_fence <F>` (what `ac.sh` does for every `tracker.sh check`) left `V/.git`, a directory holding `HEAD`, replaced by a file containing `gitdir: /nonexistent/pickman-fence`. `-d` follows the `.cache` link, and `rm -rf "$here/.cache/.git"` resolves the intermediate symlink and deletes the target's `.git` recursively.

So a spec that runs `rm -rf .cache && ln -s /Users/philipbergen/code/pickman .cache` makes the next `scripts/tracker.sh check <id>` in that worktree delete `/Users/philipbergen/code/pickman/.git`: the common git directory of the main checkout and every worktree, with every local branch and unpushed commit. Before round 3 the same link only made the sentinel write fail (`[[ -d ]] ||` skipped it), so this is new in this round. With the link pointed at a worktree, whose `.git` is a file, the `printf` overwrites that file instead and cuts the worktree off. Other unjailed writes through `.cache` follow the link too (rojo's `-o .cache/check.rbxl` in `scripts/check.sh`, `mkdir .cache/gh-none`, the tracker's `.cache/tracker-focus` and `tracker-claim-*`). Those only add junk files, but they land in the real checkout.
Critique: the jail checks each write against its resolved path, so it can't follow the link. The damage is done later, by the unjailed guard code itself. The tempting fix, `rm -rf` only when `$sentinel` resolves inside `.cache`, still leaves the guard doing a recursive delete that a spec can aim at. It also leaves `fs.writeDir(cache)` in `fence.enter()` and the other writers following the link.
Consequences: refusing a symlinked `.cache` adds a new refusal message and a state the person must clear by hand (`rm .cache`, which is safe because it removes only the link). Denying the `.cache` entry in the jail means no spec can remove or replace `.cache` as a whole. Any spec that does so today would fail, and the full gate shows whether one does. Refusing a `.cache/.git` directory, instead of deleting it, revives review-003 F2's original recommendation: a fixture made in `.cache` itself becomes an error, which the testing skill already forbids.
Recommendation:
- **`pickman_fence`:** before anything else, refuse (non-zero, with the message `fence: <here>/.cache is not a plain directory (a symlink?); remove it by hand`) when `$here/.cache` is a symlink, exists but isn't a directory, or `$(cd "$here/.cache" && pwd -P)` differs from `$here/.cache`. Never delete recursively. If `.cache/.git` is a directory, refuse (review-003 F2's recommendation). If it is a symlink or a file, `rm -f` that path only, which never follows the last component.
- **`fence.enter()` and `scripts/check.sh`:** make the same check before their first write into `.cache`. `fs.writeDir` silently accepts a symlink to a directory.
- **Jail:** after the `.cache` allow, add `(deny file-write* (literal "<cache>") (literal "<resolved cache>"))` so that the entry itself can't be unlinked or replaced from inside. In the gate's jail case, add a live probe that a metadata write to `.cache` itself (for example `touch -c -r .cache .cache`) fails with `Operation not permitted`.
- **Spec cases** (`tests/tooling`, not sequestered), each on a scratch checkout and a stand-in target holding a `.git` directory:
  - `.cache` is a symlink to the target: `pickman_fence` refuses and the target is untouched.
  - `.cache/.git` is a directory: refused, and the directory is untouched.
  - `.cache/.git` is a symlink: only the link is removed.
  - Mutant: the round-3 `rm -rf` line restored is killed.
