### F1 [high] The guard's wrapper is the new top-level runner, but nothing pins its exit code or stderr, so AC8's "keeps its output and exit code" passes with a wrong wrapper
Where: c0550.md Design (`tests/run.luau`: "Exit codes and output are unchanged for every run that starts no opener"), AC8, Rules and mutants (G7 is the only exit-code row); guard.spec.luau
Evidence: on the prototype, the wrapper was changed to forward only stdout and to exit `if r.code == 0 then 0 else 1`. `guard.spec.luau` still passed 7/7, and so did the six promoted and tooling runner specs (37 passed, 0 failed). But `lune run tests/run -- --jobs 0 x` from a shell now exits 1 and prints nothing, where today it prints `usage: … bad value for --jobs` and exits 2. Why nothing catches it: every promoted spec that pins the runner's contract (`c0470/parallel-runner` "a bad --jobs value exits 2 and names the flag" and "a bad PICKMAN_JOBS exits 2", the `lastLine` summary checks, `c0030/runner-e2e`) starts its nested runner with the inherited environment. That environment carries `PICKMAN_OPEN_GUARD`, so after this raft those specs test only the inner runner and never the wrapper that people, `check.sh`, the stop hook and `ac.sh` actually invoke. G7 kills only "exit 0 on failure", and the failing-spec case asserts only `ok == false` and a stdout token.
Critique: AC8 is a Checked criterion that a wrong wrapper passes, and the promoted runner contract quietly stops covering the real entry point. The tempting fix is one more assertion, `code == 2`, for a bad `--jobs`. That covers one code but not the general rule.
Consequences: the general rule is "the outer runner is transparent when no opener ran": same exit code, same stdout and same stderr as the child. Spec cases for it must clear `PICKMAN_OPEN_GUARD`, as `runner()` already does. That also covers the AC_LIST refusal, which sits before the guard and so never reaches the wrapper: leave it there and don't move it after. Not forwarding output live (capturing and re-printing instead) would also break nothing that is pinned. Whether streaming is required is a design decision: state it.
Recommendation: add guard.spec cases, each run through `runner()` (guard cleared). (a) `--jobs 0 <plant>` exits with code 2 exactly, and `r.stderr` contains `--jobs`. (b) `PICKMAN_JOBS=lots` with two plants exits 2 and names `PICKMAN_JOBS` on stderr. (c) A clean run's last stdout line is the summary, as `c0470` pins for the inner runner. (d) A failing plant exits with code 1 exactly. Add Rules and mutants rows: "the wrapper passes the child's exit code through" (mutant: 0/1 collapse) and "the wrapper forwards stderr" (mutant: stderr dropped). Reword AC8 so it names exit code 2 and stderr. State in Design whether live streaming is required. The prototype's forward mode already meets all of this.

### F2 [medium] The step order and guard.spec case 2 can open a real browser, despite the spec's own header promise
Where: c0550.md Implementation steps 2-4; guard.spec.luau header ("even a broken guard never shows a page") and case `a spec that runs tracker.sh board without -O…`; E7 (G1 "no guard" was run)
Evidence: (a) Step 2 makes `board` open by default, but the guard (step 3) and the tooling spec's `-O` (step 4) come later. Between steps 2 and 4 on the executor's Mac, any full or `--affected` gate opens a real browser tab on `.cache/board-unit-abs/page.html`: `main.luau` selects ALL, and the stop hook runs the gate on its own. (b) Case 2's plant runs `tracker.sh board --out .cache/c0550-guard/page.html` without `-O` and writes a real page. Under a broken guard (G1, G3, or any guard bug during execution), nothing stubs `open`, because the outer AC8/RC0 runner has the same broken guard. The real opener then shows that page. The header's promise holds only for the probe cases, whose paths don't exist.
Critique: the raft exists to stop specs from starting browsers, and its own execution order and mutation testing still do. The tempting fix is to reorder steps only. That fixes (a), but under a broken guard case 2 still opens a page.
Consequences: a backstop stub directory in `runner()` has to come *after* the nested guard's stubs, or it would hide the guard. The nested guard prepends its directory, so passing `PATH = <backstop>:<PATH>` to the nested runner puts the backstop second. The backstop log also gives a direct way to kill G3 (guard stubs last): its log must stay empty.
Recommendation: reorder Implementation steps to: guard block in `tests/run.luau` and the tooling spec's `-O`, then `flags()`, then `cmd.board` and `USAGE`, then workflow and skills. With that order, the tree never has default-open without the guard. In guard.spec, give `runner()` a backstop directory (`{DIR}/backstop` with logging `open`/`xdg-open` stubs) on `PATH`. Each opener case asserts the backstop log is empty when the guard works, and the header comment is corrected to say so. Add the backstop assertion to the Rules and mutants row for G3.
