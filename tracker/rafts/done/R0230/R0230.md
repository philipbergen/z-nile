# R0230: Setup whole run

## Theme
Single-issue raft. `scripts/setup.sh` ends in the only full-gate run in CI's `check.yml`, and the tools-only mode (`--tools`) skips it; R0160's code review 003 showed that the slice-based spec guarding that path misses five ways to bypass the gate outside its slice. This chore replaces it with a spec that runs the whole script for real against stubs (test work, so a chore; the user asked for these issues to be rafted, 2026-10-01). No decision in `tracker/game-design.md` is involved, and `setup.sh` itself does not change.

## Whole-raft design
One new acceptance spec, `setup-run.spec.luau` (written in prep, promoted by `done`), runs `scripts/setup.sh` in a sandbox under `.cache/c0530-setup`: a byte copy of the script in a sandbox repo whose `scripts/check.sh` is a stub gate, `PATH` holding only one multi-call recording stub (linked as every tool `setup.sh` calls) plus links to system basics, an empty `HOME`, and every variable `setup.sh` could read set by the case or unset (`env -u`) (no `env -i`, which R0210 bans; the rest of the environment, guards included, is inherited). The executor deletes the superseded promoted spec `tests/acceptance/c0460/setup-tools.spec.luau`; this prep already removed it from c0460's `check.sh` (the sequestration check forbids `check.sh` edits during execution). No interfaces between issues; no `tracker/architecture.md` change. Details in c0530.

## Order & dependencies
c0530 only, no dependencies. No file overlap with in-flight rafts: R0200 (c0510) and R0220 (c0550) touch the tracker CLI and the spec runner; R0210 (check isolation, in prep) changes how the gate runs specs, which this spec goes through like any other (its run of `setup.sh` inherits the spec's environment, R0210's fence variables included, and uses no name R0210's gate spec bans). Note for R0210's owner: `prep-tracker-hardening` uses the id c0530 for a different issue and must renumber before it lands.

## Experiments phase
All run in prep (see c0530): E1 the whole of `setup.sh` runs against stubs with no seam (8/8 against today's script); E2 one stub script with symlinks, because on macOS the first run of newly written executable files is slow (26 s became 1.4-3.3 s); E3 30 mutants of `setup.sh`, each killed by an assertion, including the five the old spec missed and ten runner-variable skips. **E4 (Linux) is the executor's Phase 1**: `scripts/ci-verify.sh` right after `start` runs the sequestered spec on ubuntu; red means `BLOCKED:`, never an edit.

## Exit criteria
- RC0 (generated): `scripts/check.sh --full`, c0530's `check.sh`, and the promotion dry run pass.
- Done == `scripts/tracker.sh done R0230` succeeds.

## Risks & rollback
- **A Linux-only difference** in the sandbox (a missing basic, a variable the runner sets differently): caught by `ci-verify.sh` right after `start` (E4); the spec is sequestered, so a red run escalates.
- **A CI-only variable outside the snapshot**: a `setup.sh` that skips the gate on it would also skip this spec on CI, and local runs lack the variable. Accepted by the user (2026-10-01): the snapshot covers GitHub's documented defaults, and such a change shows in the `setup.sh` diff at review.
- **Host-probing bypasses** (a `setup.sh` that skips the gate on a path like `/home/runner`, the user id or the date) can't be seen by a sandboxed run, and the old spec's text rules go with it: accepted in prep (design review 001 F2); code review of any `setup.sh` change is the guard.
- **A future `setup.sh` that calls a new tool** fails the spec with "command not found" until the stub knows the name: deliberate (no real tool may run), and the fix is one line in the spec.
- **Coverage between prep and execution**: the slice spec stays in the gate until the raft deletes it; only `tracker.sh check c0460` stops running it once this prep lands.
- Rollback: revert the PR; nothing persists outside the repo.
