# Refute 002: c0134 (design mode)

- F1: fixed (the mechanism changed, the second finding against it): instead of classifying what a comment is, the design now defines the one part that may change positively and compares every other byte. `split.cut` splits with `string.split(text, "\n")` (every byte kept, a last line with no newline included); the header is one contiguous run of plain line comments right after line 1, lines that are exactly `--` or start with `-- ` (never `--[` or `--!`); the body is line 1 plus everything after that run, byte for byte. AC2 diffs the two bodies; header.spec's sample case pins the rule with a `--[[x]] y()` line, a `--!nonstrict` line 1, a code line at the boundary and a last line with no newline. On the prototype the reviewer's M7–M10 each turn AC2 red, M6 and M5 still do, M1 turns AC1 red; the real fix passes 3/3. consequences: the new header is all `-- ` lines, so it is wholly header; a future header that used `--[[` would fail AC2 by design (a block comment may hide code).
- F2: fixed: zz-test/split-checks-share-one-boundary's check now asks for a strict positive pattern for the changeable part, every other byte compared (line 1 and an unterminated last line included), and a mutant at each edge; its "How to apply" says the same. consequences: none.
