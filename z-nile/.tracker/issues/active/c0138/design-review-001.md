### F1 [high] No case has a later compaction that keeps an id an earlier one renamed, so AC2 passes implementations that reset kept ids at the next real compaction
Where: `kept.spec.luau` (fixture, cases), Rules and mutants, AC2. Also the Design's "the change shows on the next compaction" (E3).
Evidence: every cut commit in the fixture that touches a renamed id's document also names it: `compact`, then `again`, which repeats the pairs. No commit is a second, real compaction whose fresh map keeps such an id (`c0020 c0020`). I ran two mutants on the prototype, and both passed `kept`, `renamed`, `c0111 trail`, `c0114 trail-move` and `c0119 capture-cli` (36/36 and 29/29):
- (a) `renames` also reads the parent's version of each listed map (`git show <sha>^:<file>`, appended when it exists), which is a "cumulative map" reading;
- (b) `cutsId` memoises under one fixed key instead of `sha`, so the first cut's answer is reused for every older cut.

Under (a), the next real compaction resets every id that a38f91f9's map renamed, though the new map keeps it. On today's tree that is nearly every item, which is exactly the outcome the Problem asks to stop. Under (b), an item reused in place (c0020) is followed back across its id change to the old item's capture.

I added this commit to a scratch copy of `kept.spec`: `compact2` after `broken`, with map `# ./zn compact 2\nc0004 c0004\nc0010 c0010\nc0011 c0011\nc0020 c0020\nc0030 c0030\n`, rewriting `done/c0020` and `done/c0004` in place. The case asserts that `capture c0020` still starts at `compact`, marked `compact` and not `compact2`, with no "old twenty", and that `capture c0004` is marked `compact` and not `compact2`. With it the prototype passes 13/13; mutant (a) fails 3 cases and (b) fails 2.
Critique: AC2's sentence ("a compaction that keeps an id and rewrites its document in place starts no new life") is passable by both mutants. The scenario the specs miss is the one that will actually happen next. c0118 pins it ("a pair a later compaction's map drops no longer renames: a kept id named only by an earlier map keeps its date"). This design does not state it, and has no case for it. The tempting fix is the one case above.
Consequences: a fourth `compact2` commit moves no other case's answer, because it touches only c0020 and c0004. The `renames` listing case could add `SHA.compact2` -> `` (an empty line: `{}`, not nil), which pins "a whole map of identity pairs names nothing" end to end. The rule also needs a Design sentence ("a pair an earlier map had and this commit's map lacks renames nothing"), so the case follows from the Design.
Recommendation: state the rule in the Design. Add the `compact2` commit and the case to `kept.spec`, plus `compact2` in the `renames` listing case. Add Rules rows for mutant (a), "a map other than the one the commit leaves is read (its parent's, or the file's history)", and mutant (b), "the per-commit memo is not keyed by commit". Re-run E5 with both.
Lesson: zz-test/one-rule-one-function (the other copy of this rule, c0118's `renamedIds`, has this planted case; this copy does not); z-design/spec-design-correspondence

### F3 [medium] E4's "trail and c0118 answer alike" is false for a commit that moves the map and changes it, and the duplicate rule is left with no owner

## Lesson candidates (for the lead)
- **A rule over a series of commits needs a case where a later step gives the opposite answer** (zz-test). A rule decided per commit from that commit's data (a map, a header, a counter) needs a fixture where a later commit gives the opposite answer for the same id (renamed, then kept). Without it, a reader that mixes in older commits, or a memo keyed wrongly, passes. Check: for each per-commit decision, is there an id whose answer flips between two commits that both reach the decision?
- **"X and Y answer alike" claims are checked on the commit classes each reader admits, not only on the answer** (z-design, a note on quote-other-preps-before-promising). Check: do both readers accept the same set of commits (renames, moves, merges) before they compare answers?
