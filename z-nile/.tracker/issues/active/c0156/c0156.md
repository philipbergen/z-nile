# c0156: Whole file pins keep newlines

## Problem
Found 2026-10-25 by R0045's code review 001 F1 (high). The user decided (2026-10-25): "Merge, chore the hole": R0045 (c0128) lands, and this chore closes the hole.

Two whole-file pins of a Luau spec normalise its text with `string.gsub(text, "%s+", " ")` before comparing a digest or text: c0128's `golden.spec` (promoted with c0128 to `pickman/tests/acceptance/c0128/golden.spec.luau`) and c0103's promoted `pickman/tests/acceptance/c0103/narrowed.spec.luau`. Collapsing newlines with spaces lets a Luau line comment swallow the code after it: joining `t.expect(...)` onto the `--` comment line above it turns the assertion into a comment, and both pins (plus c0128's text probes in `guards.spec`) still pass. The reviewer showed it on R0045 at a0a14abc: two assertions deleted that way, `./zn check c0128` 4/4. `golden.spec`'s header claim "comments are kept, so no code can hide in one" is false.

What should happen: both pins normalise with a rule that keeps line breaks where Luau ends something at a newline (collapse horizontal whitespace only and keep one `\n` per line break, or end each `--[^\n]*` comment with a marker before collapsing), their digests or texts are recomputed, and a comment-join mutant is killed by each.

Decided with the user (2026-10-25): c0128's golden.spec pin was fixed in R0045 ("Fix the pin now"); c0156 keeps c0103's narrowed.spec and the CRLF-safe join helper in c0128's golden.spec (R0045 code review 002 F1: its `joined()` mutant builder searches the raw file, so a CRLF checkout gives a false red; it should read through the shared normaliser).

## Non-goals
- Other normalising probes that aren't whole-file pins (`c0015/workflow`, `c0053`, `c0001/ci-workflow`, `c0060/retrofit`, `c0076/sweeper`).
- The narrowing itself (c0128, done).
- The exact-text whole-file pins (c0150's, c0172's, and the in-flight c0153's and c0159's): they tolerate no whitespace, so they cannot have this hole (added at prep).

## Solution
- One shared normaliser (e.g. in `pickman/tests/lib/`) used by both pins, so the rule lives once.
- Overrides: c0128's promoted `golden.spec` and c0103's promoted `narrowed.spec` (a chore changes them in its own raft, z-design's Override check), with their digests recomputed on the current files.
- A comment-join mutant for each pinned file (join an assertion onto the comment line above it), killed on an assertion; add it to c0128's `experiments/mutants.py` record.
- zz-test/narrowing-pins-the-whole-file gains the reviewer's amendment (harvested by R0045).

## Design
State on `origin/main` (0d4323b4 and later): c0128's `golden.spec` was already fixed by R0045 on the user's decision ("Fix the pin now"), so its pin keeps line breaks and its digests (`7f791c55…` f0024, `744eeb0f…` f0026) stay as they are; c0103's `narrowed.spec` still collapses newlines (`string.gsub(text, "%s+", " ")`) and `golden.spec`'s `joined()` reads the raw file. The `Decided with the user (2026-10-25)` line in the Problem is the scope: c0103's pin, the CRLF-safe join helper, one shared normaliser, a comment-join mutant for each pinned file, and the record in R0045's `mutants.py`; the lesson's amendment is already harvested.

**The shared rule: `z-nile/tests/lib/pin.luau`** (new, `--!strict`, pure over texts, requires only `@lune/serde`), re-exported as `pickman/tests/lib/pin.luau` (`return require("../../../z-nile/tests/lib/pin")`, the pattern of `renamed.luau`), so both homes' specs require `@tests/lib/pin`.
```luau
function pin.normalise(text: string): string
function pin.digest(text: string): string          -- serde.hash("sha256", pin.normalise(text)), lowercase hex
function pin.joined(text: string, comment: string): string
function pin.without(text: string, piece: string): string
```
- `normalise` is c0128's rule, moved unchanged (so its two digests do not move): mask item ids (`%f[%w_][fdcR]%d+%f[^%w_]` to `ID`), `\r\n?` to `\n`, runs of spaces and tabs to one space, trailing space before `\n` dropped, a comma before `}` dropped across at most one line break, leading and trailing whitespace of the text trimmed. **Every other line break is kept**, blank lines included. Tolerated, in the doc comment and in AC1's label: ids, line endings, spaces within a line and a line's trailing whitespace, a comma before `}`, the text's outer blank lines. Spaces inside a string literal collapse too, which the Problem allows ("collapse horizontal whitespace only"); this is an accepted risk, not a cut: none of the three pinned files has a string with a run of spaces or a tab (`grep -nE '"[^"]*(  |\t)[^"]*"'` finds none), and every negative probe in them uses a needle without a space, so spacing cannot make a probe vacuous today. A later pin that does hold such a string keeps the exact-text pin (c0150's), or changes this one rule and its digests. `\v` and `\f` are not collapsed (a Luau `--` comment runs through them, R0045 review 002).
- `joined(text, comment)` is the mutant a careless edit makes: it normalises `text` and `comment`, finds the **first** line that ends in the comment, and turns the line break after it into one space (dropping the next line's one indent space). It returns the normalised, joined text. It raises `no line ends in the comment "<comment>"` when none does (a comment on the last line has no line to join), and `the comment "<comment>" is followed by a blank line: no line to join`; a pin that "killed" a join that joined nothing would prove nothing. Reading both texts through `normalise` is R0045 code review 002 F1: a CRLF checkout, an id in the comment or the comment line's indent change nothing.

- `without(text, piece)` is the second careless edit, a deleted assertion: the normalised text with the one occurrence of the normalised `piece` removed. It raises `the text has no "<piece>" to delete` for an empty or absent piece, and `"<piece>" occurs more than once in the text: nothing certain to delete`. Like `joined`, it reads both texts through `normalise` (an assertion line is given as `t.expect(x).toBe(1)`, whatever its indent or line ending).
- **Lexer fact the rule rests on** (E9, `experiments/E9-comment-ends.luau`): a Luau `--` comment ends at LF, CR and CRLF, and runs through VT and FF. So `normalise` makes CR a line break (an edit that turns a line break into CR keeps the pin honest) and keeps `\v` and `\f` as they are, neither collapsed nor a break; a spec case pins each half.

### Scalability
One `normalise` is a constant number of `gsub` passes over a file of at most a few thousand lines; `digest` adds one SHA-256. Each pin reads one file (c0128 two, c0103 one). The join helper does one `find` on the normalised text. A further narrowing chore adds a file and a digest, nothing else; no spec walks a directory.

### Maintainability
The rule lives once (`pin.luau`) and has its own spec (`pin.spec`, one case per rule). The next narrowing chore with a formatting-tolerant pin requires `@tests/lib/pin`; the one that needs exact text (c0150's and c0153's style) keeps its three-line `exact`. Changing the rule later (for example keeping the spaces inside strings, the accepted risk in the Design) is one edit and one recomputed digest per pin, found by `consumers.luau`'s list. The lesson tells designers to use it.

### Usability
For executors: a red pin names its file's case and the digest it expected; a join helper that finds nothing says `no line ends in the comment "…"`. For reviewers: the Rules and mutants table maps each rule to a mutant id that `experiments/mutants.py <clone> <id>` runs alone.
