# c0165: Reuse passed test results

## Problem
From the user (2026-10-26): reuse gate results. If a gate already passed on the exact same code, later steps skip rerunning it. Tests should be tied to the code they test, so a suite (ideally a single test) runs only if its result could have changed, and the fingerprints of passed tests are stored.

Today the full gate runs every spec several times on identical code in one change: the author runs it before review, the reviewer runs it again, then `./zn land` / `done` runs it once more. A full run takes ~216 s idle and 500 s+ under load (c0157's measurements). `z-nile/affected.luau` already picks the spec files a diff can reach through the require graph, but only `check.sh --affected` uses it, and nothing remembers a past pass.

What should happen:
- **Fingerprint per spec**: every spec file gets a fingerprint made of its own content, the content of everything it can reach (the require graph `affected.luau` builds), the shared runner and harness, the tool versions and the gate mode. Ideally the fingerprint is per test inside a spec, not just per file.
- **Reuse**: a pass is recorded under its fingerprint. A later run skips a spec whose fingerprint already passed, reports it as reused, and runs the rest.
- **Store**: results live in a SQLite database at `.claude/.znile_tests.sqlite` (git-ignored), keyed by fingerprint and shared by every worktree of the checkout, so the author's pass serves the reviewer.
- **Concurrent runs wait, they don't duplicate**: when two runs reach the same fingerprint at once (two worktrees, or the author and the reviewer), the second waits for the first's result and uses it.
- **Crash detection**: a `running` row stores its owner's PID (plus the process start id, so a reused PID isn't mistaken for the owner). A waiter sees a crashed or killed run at once, takes the row over and runs the spec itself, instead of waiting forever.
- **The full gate runs only at the merge** (`./zn land`, the PR's merge, `done`). Every step before it (the author's iterations, the review, the pre-PR gate) runs only the affected specs.
- **A merge failure teaches the selector**: when the merge's full gate fails a spec that the affected selection didn't pick for the same change (a graph miss), the tooling finds out how the affected selection missed it (which changed file the spec depends on without a require edge) and records that dependency, so later affected runs select the spec. This replaces zz-test's "Graph miss: file a chore by hand" rule.
- No failed or partial run, different tree or spec can forge a pass. A forced full rerun stays available.

## Non-goals
- Limiting concurrent gates machine-wide, and the tripwire firing on another session's refs: c0157.
- Spec order: c0154 (slowest first).
- Making individual specs faster.
- Fingerprinting the static stages (format, lint, types, rojo build), unless prep finds it cheap to do the same way.
  (Prep: it is cheap at the level of the whole gate, so the Design covers it: a gate that passed on the same content, tools and base is reused whole, static stages included. Stage-by-stage fingerprints stay out.)

## Solution
- Build the fingerprint by hashing the spec plus its transitive requires with `affected.luau`'s graph, so selection and reuse share one reader.
- Specs that read files outside their requires (meta and structural specs, the repo-fence scan, `git ls-files` readers) need declared inputs or must always run, or a reused pass hides a failure (the same risk as a graph miss).
- Per test: record which test names passed under each fingerprint, and narrow a test's inputs only where it can declare them, since Lune has no coverage tracing.
- SQLite schema idea: one row per fingerprint holding the state (`running|passed|failed`), the passing test names, the duration, the owner's PID and start id, and a timestamp. A run claims a fingerprint by inserting a `running` row in one transaction; a second run polls until the row is `passed` or `failed`. A dead owner (the same PID and start-id check as the runner's `tests-run.lock`) frees the row. A `failed` row on the same fingerprint is either reported as the same failure or rerun once to tell a flake apart (prep decides).
- Path: resolve the main checkout's `.claude/` through `git rev-parse --git-common-dir`, so all worktrees share one database. Ignore the file, like `prompt.md` and `.cache/board.html`. Only the runner writes it, from outside the jail (the jail denies specs every write outside `.cache`). The guards stay as they are, and the repo-fence and `cachepaths` reviews must accept this writer.
- The `sqlite3` CLI ships with macOS and Lune has no built-in SQLite, so the runner shells out to it (prep checks Linux and CI), with WAL mode and a busy timeout.
- Learned dependencies: commit them as extra edges that `affected.luau` reads (a `deps` table beside the spec, or one registry file), so every checkout and CI benefits and review sees them; keep them only in SQLite if local is enough. Find the edge by bisecting the changed files against the failing spec, or by diffing the spec's file reads against its require closure.
- Open question for prep: a merge gate that reused fingerprinted passes would catch no graph miss, because its fingerprints come from the same graph. So the merge gate probably runs every spec fresh, and reuse plus the concurrent wait apply to the affected runs before it, unless prep finds a fingerprint that doesn't depend on the graph.
- Steps that change: zz-execute (the author's and the pre-PR gates become `--affected`), zz-review (the reviewer runs the affected specs), `./zn land` / `done` (the full gate), and zz-test's gate-modes table and Graph miss rule.
- `spec-durations.tsv` could move into the same database (an option, not scope).

## Design
The core of the split (Problem, Scope decision 2026-11-03). Three siblings build on it and are not designed here: **c0238** (concurrent runs wait for each other; a crashed run is detected and taken over), **c0239** (the full gate runs only at the merge: gate-modes wording in the skills and templates, `--full --reuse`, the stop hook) and **c0240** (a merge failure teaches the selector). Where the core stops short of one, a line says "cNNNN adds X".

The spec runner (`z-nile/tests/run.luau`) stays the only thing that runs specs, with its jail and guards. A new orchestrator, `z-nile/specs.luau`, sits between the gate and the runner: it decides which spec files to run, runs them through `lune run tests/run`, and keeps results in SQLite. An affected `z-nile/check.sh` calls it. `--full` keeps running each home's specs itself exactly as today (a pin of `c0120/gate-homes.spec`) and runs every spec whatever was recorded. Today it also reads no row and writes none; that is an interim fact, checked once at c0165's `done` by a script (AC15) and pinned by no promoted spec, because c0239 adds its record and `--reuse`.

**What the siblings change, and how the core leaves room (design review 007 F3).** Promoted specs here pin rules, not today's values. The schema version is the constant `resultsdb.SCHEMA` (c0238 and c0240 raise it; a newer db means reuse off, and the newer code migrates an older one: none exists at 1). Two facts that c0238 and c0239 reverse on purpose, "two runs at once both run the spec" (c0238: the second waits) and "`--full` reads and writes no row" (c0239: it records), are checked only by `acceptance/proof-interim.luau`, run by `check.sh` before `./zn done` and inert afterwards, so neither sibling overrides a promoted spec. The pair case that is promoted asserts the rule: both runs exit 0, and the db holds one passed row. Its helper releases the held spec 3 s after it first started, so a run that waits for the first (c0238) cannot hold it until the poll limit.

### Where things run (why the orchestrator is a CLI)
- Only an unjailed process can write the db: the runner's top process (`fence.enter()`) launches the jail and exits with its code, and its coordinator and workers run in a jail that denies every write outside the home's `.cache`. `check.sh` runs unjailed, so the orchestrator it calls does too; it starts `lune run tests/run` from the home as the gate does today, and the runner fences and jails itself as before.
- Results come back in one file per run, `<home>/.cache/spec-results-<orchestrator pid>.json`, named in `PICKMAN_RESULTS`; the runner writes it.
- A spec can write that file (it lies in `.cache`), so a deliberate overwrite can fake a pass in an affected run: the residue the user accepted (`Decided with the user (2026-10-27)`). Everything short of that is closed: only a runner exit of 0 records passes (R33), a failed read turns reuse off (R35), a changed tree records nothing (R31).

### `select.luau` (one rule for selection and fingerprints)
```luau
export type Home = { name: string, prefix: string }        -- prefix "pickman/", "z-nile/"
export type Rules = { homes: { Home }, roots: { string } }  -- roots: every project root ("pickman/.tracker", ...)
export type Inputs = { [string]: { string } }              -- repo-relative spec -> extra inputs (file, folder/, *, ref:<full ref>)
export type Context = {
	rules: Rules,
	graph: graph.Graph,
	inputs: Inputs,
	places: { [string]: { string } }, -- home prefix -> graph.placeInputs(home) (c0185), filled by context.luau for every home: a home with no project file gets c0185's legacy answer (`<home>src`, `default.project.json`, `lobby.project.json`), so isInput equals c0185's affectedSpecs for every home; select treats a missing entry as empty
}
select.rules(reg: projects.Registry): Rules
select.forces(rules: Rules, path: string): ("all" | string)?  -- "all": every project's full run; a name: that project's
select.isInput(ctx: Context, spec: string, path: string): boolean
select.affected(ctx: Context, changed: { string }, only: string?): { string } | "ALL"
select.parseInputs(text: string, homePrefix: string, roots: { string }?): (Inputs?, string?)  -- nil + "line N: <reason>" on the first malformed line
```
`isInput` reads whatever `Inputs` holds; c0240 adds the edges a merge failure teaches.
- `isInput(ctx, S, p)`: a spec with a `*` entry has every `p`. A `p` under a project root is an input only through an `Inputs` entry that itself names a path under that root and that `p` equals or lies under (a broader entry such as `pickman/` never reaches into a root; `spend.md` files and the root itself never are). Any other `p` is an input when `select.forces(p)` is `"all"` or names S's project; `p` is in `graph.closure(S)` or under it as a folder prefix; S's closure holds its home's place library (`<home>tests/lib/place.luau`) and `p` equals or lies under one of `ctx.places[<home>]` (c0185's `graph.placeInputs`: every `*.project.json` directly in the home and every folder they map, the arcade library's two included; a `src/` file no project file maps is in no place; a home with no project file has c0185's legacy answer); `p` equals or lies under one of S's `Inputs` entries; or `p` is S's home's `tests/inputs.tsv` and that file names S.

A home with no `tests/inputs.tsv` has no extra inputs.

### `fingerprint.luau`
```luau
export type Blobs = { [string]: string }  -- repo path -> "<mode> <blob id>" for every file present (tracked + untracked)
export type GitState = { head: string, refs: { [string]: string } }
fingerprint.inputs(ctx: select.Context, spec: string, blobs: Blobs): { string }  -- sorted paths p with isInput(spec, p)
fingerprint.refs(ctx: select.Context, spec: string): { string }  -- sorted full ref names declared by ref:
fingerprint.of(ctx: select.Context, spec: string, blobs: Blobs, tools: string, mode: "affected" | "full", git: GitState): string
fingerprint.digest(blobs: Blobs, tools: string, extra: { string }): string  -- the content digest of a whole gate
```
- `of` is the sha256 (`serde.hash`) of lines in order: `c0165 v1`; `mode <affected|full>` (c0239 gives a full run its own rows); the spec's path; the tools line; one `<path>\t<blob>` per input; one line per `Inputs` entry; for a `*` spec only, `HEAD <commit>`; one `<ref>\t<commit>` per declared ref, sorted (absent: `<ref>\tMISSING`).
- Since the inputs are exactly the `isInput` set, for a spec without a `ref:` entry a modified, added or deleted file changes S's fingerprint exactly when that change alone makes `affected` select S (or `ALL`); a change under a project root changes only specs that name it through an `Inputs` entry; HEAD moves only `*` specs and a declared ref only its spec; unrelated refs never enter. Two exceptions: removing S's own `inputs.tsv` line changes its fingerprint without selecting it (one harmless rerun), and a `ref:` spec is selected by every change set, its fingerprint deciding (design review 006 F5).
- `digest` is the sha256 of `c0165 digest v1`, the tools line, every `extra` entry (mode, projects, base, HEAD when the selection holds a `*` spec, and, always, the union of the selected specs' declared refs), and every `<path>\t<blob>` of `blobs`, excluding a `spend.md` under a project root (`./zn spend` writes it late) and every ignored file.
- The tools line is `uname -sm`, then `--version` of `lune`, `rojo`, `selene`, `stylua`, `luau-lsp` and `git`, then the sha256 of `.cache/globalTypes.d.luau` (the types the gate downloads), joined by ` | `; a tool that fails to answer gives `<name>?`.

### `workspace.luau` (the reads)
- `blobs(root): (Blobs?, string?)`: `git ls-files -s -z` gives mode and blob id of every tracked file; `ls-files -m -z` and `--others --exclude-standard -z` list files that differ from the index; `git hash-object --no-filters --stdin-paths` hashes those without writing any object (an untracked file is `100755` when executable, else `100644`); a deleted file is absent. It fails closed with `nil, reason` when a git call fails, `hash-object` returns another number of ids than paths, or a path holds a newline. On `nil`, `specs run` takes "reuse off: <reason>", `digest` prints nothing (no whole-gate reuse or record), and the re-read after a run counts as changed. Nothing it runs writes to the object store or index; a spec pins the absence of `-w`, `add`, `write-tree`, `update-index` and `GIT_INDEX_FILE`.
- `gitState(root, refs)` reads `git rev-parse HEAD` and only the requested full refs (`rev-parse --verify <ref>^{commit}`; a missing one is absent, not an error). The caller requests the selected specs' `fingerprint.refs`. It never runs an unrestricted `for-each-ref`.
- `tools(root)` returns the tools line. `dbPath(root)` returns `<main checkout>/.claude/.znile_tests.sqlite`: the parent of `git rev-parse --path-format=absolute --git-common-dir`, which must end in `/.git`, else nil and a reason (reuse off). With `PICKMAN_TEST_FENCE` set it also refuses a result without a `/.cache/` segment: a nested orchestrator may write only a fixture's db, never the real checkout's.

### The db (`resultsdb.luau`)
`sqlite3 -batch -bail -noheader -list <db>`, SQL on stdin starting `.timeout 10000`. Every call ends with exactly one `SELECT json_object(...)` (rows as `json_group_array`, the write count as `changes()`), so the output is one JSON line (E8). The binary is `PICKMAN_SQLITE3` when set and not empty, else `sqlite3`. `open` runs `PRAGMA journal_mode=WAL`, creates the db's folder, and reads `PRAGMA user_version`: 0 creates the schema below and sets `resultsdb.SCHEMA` (1 here); `SCHEMA` is ours; a number below it is an older db the code migrates (none exists at 1, so the branch is written when the first version is raised); a number above it is a db a newer version made, and `open` answers nil, "schema N" (reuse off, the db untouched). **Extensible**: c0238 raises `SCHEMA` to add `running` rows and owner columns, c0240 to add a learned-edges table; they change the constant and the migration, and no promoted spec names a number.
```sql
CREATE TABLE IF NOT EXISTS specs(
  fp TEXT PRIMARY KEY, home TEXT NOT NULL, spec TEXT NOT NULL,
  state TEXT NOT NULL CHECK (state IN ('passed','failed')),
  cases TEXT,                               -- JSON [{"name":..,"ok":true}], the file's cases in order
  detail TEXT,                              -- the run's FAIL lines for this file (failed)
  seconds REAL, updated INTEGER NOT NULL);  -- unix seconds
CREATE TABLE IF NOT EXISTS gates(key TEXT PRIMARY KEY, mode TEXT NOT NULL, projects TEXT NOT NULL,
  passed_at INTEGER NOT NULL, summary TEXT NOT NULL);      -- summary: the static stages' report
```
```luau
export type Case = { name: string, ok: boolean }
export type Row = { state: "passed" | "failed", cases: { Case }?, detail: string?, seconds: number?, updated: number }
resultsdb.SCHEMA: number                              -- 1; the version this code reads and writes
resultsdb.open(path: string, binary: string?): (Db?, string?)  -- nil + reason: no sqlite3, unwritable, a schema above SCHEMA
resultsdb.rows(db, fps: { string }): { [string]: Row }
resultsdb.record(db, fp, home, spec, loaded: boolean, cases: { Case }, detail: string?, seconds: number, now: number)
resultsdb.gatePassed(db, key): { passedAt: number, summary: string }?
resultsdb.recordGate(db, key, mode, projects, summary, now)
resultsdb.prune(db, now)                              -- specs rows and gates not updated for 30 days; called by `specs run` step 3 and `gate-record`, with now
```
- `record` is an upsert on `fp`: `passed` when the file loaded and every case passed, else `failed`; the latest result for a fingerprint wins; the same result twice leaves the row as it was (R62).
- Every text value goes in as an SQL string literal with `'` doubled (a spec pins quotes, newlines, `--`).
- **Pruning** keeps the db from growing without bound: `specs run` calls `prune` in the same `sqlite3` call as the records it makes (a run that records nothing adds no row and prunes nothing), and `gate-record` in the call that writes its row; `now` is the orchestrator's clock. Both tables are pruned by either call. (design review 007 F6: the smaller design, not dropping `prune`, because every affected run in every worktree adds rows to one shared db.)
- `open` failing (no `sqlite3`, `.claude/` unwritable as in an outer sandbox, a newer schema) is never a gate failure: the orchestrator prints `reuse off: <reason>`, runs every spec it was given and records nothing.

### `reuseplan`
```luau
reuseplan.decide(row: resultsdb.Row?, fresh: boolean): "reuse" | "run"
reuseplan.records(jail: string, os: string): boolean
```
`decide` is `reuse` for a passed row unless `fresh`, else `run` (no row, a failed row, `--fresh`); c0238 adds `wait` for a row another live run holds. `records` is true for `sandbox-exec`, for the nested-fixture jail text `outer sandbox (a fixture of a guarded checkout)` on macOS, and for an unjailed run on a non-macOS host (`os ~= "macos"` and the jail starts with `none`); false for any other outer sandbox, no jail on macOS, an empty jail. When false the run records nothing, failures included. `jail` is the `PICKMAN_TEST_JAIL` value the runner wrote into its results.

### `specs.luau run` (the orchestrator)
`lune run z-nile/specs -- run --project <name> [--fresh] [--all | -- <home-relative spec>...]`, from the repository root, as `check.sh` runs it; `--all` is every spec file under the home's `tests/` (the selector said `ALL`).
1. Open the db (on failure, "reuse off"). Read the blob map, git state, tools line and context; compute each spec's fingerprint with mode `affected`.
2. `rows`, then `decide` per spec. Each `reuse` prints `reused <spec>` and adds its stored case counts; the rest run.
3. Remove any `<home>/.cache/spec-results-<own pid>.json*` an earlier run with this pid left, then run `lune run tests/run -- <specs>` from the home with `PICKMAN_RESULTS` set, output forwarded as it comes (`stdio = "forward"`, R49). Read the results (cases, `FAIL` text as `detail`, the jail):
   - **Only a runner exit of 0 records `passed` rows.** A non-zero exit records only the files its results show failed; when they show none, it prints `runner exited <code>: <n> results not recorded` and counts the run failed (the browser guard and the tripwire fail a run only through the exit code, after every spec passed).
   - **Only a run in the host's strongest jail records** (`reuseplan.records`; design review 002 F3). Another outer sandbox reads and reuses but records nothing and prints `not recorded: <jail>`, because the guard specs' jailed cases return early there. `check.sh` sets `PICKMAN_GATE_PID` and on exit removes its own `spec-norecord-$PICKMAN_GATE_PID` in every picked home, never another gate's marker (a concurrent weak-jail gate in the same home keeps its own); the orchestrator, which alone knows the run's jail, writes `<home>/.cache/spec-norecord-<PICKMAN_GATE_PID>`; `gate-record` records nothing and exits 0 while that marker exists in any picked home (a gate that records nothing is not a failed gate).
   - A spec whose fingerprint, recomputed from fresh blob and git-state reads after the run, differs from the one it ran under (an input changed during the run) is not recorded; its result still counts.
   - Otherwise each listed file is recorded `passed` or `failed` with its cases and `detail`. A spec the results don't list (killed, crashed runner) is counted failed with `FAIL <spec>: results file missing` (no file) or `FAIL <spec>: no result for it`, and nothing is recorded for it.
   - The records, and `prune(db, now)`, go in one `sqlite3` call. The results file is then removed. A killed orchestrator leaves its file in the ignored `.cache` for the next run with that pid to remove (c0238 adds the runner's lifeline and the sweep of dead owners' files).
4. Print `reuse: <r> reused, <n> ran`, then `<passed> passed, <failed> failed, <files> spec files` (totals over both). Exit 0 only when nothing failed.
- **Two runs at once** that reach one fingerprint both exit with the file's result and leave one row (an upsert). Today both also run it and neither waits; that is interim (c0238 makes the second wait for the first and takes over a crashed one) and checked only by AC15's script.
- **`--fresh`**: `decide` returns `run` for every spec; the run still records. **Reuse off**: run the given specs (or all) in one `tests/run`, record nothing, print `reuse off: <reason>`. **Nested runs**: with `PICKMAN_TEST_FENCE` set, `dbPath` must resolve below `.cache`, to the fixture's own checkout, even on unjailed Linux.
- **Full mode** is not `run`: `check.sh --full` runs each home's specs itself as today, runs every spec, and still prunes `spec-durations.tsv` (the runner gets no file arguments). Today it also reads no fingerprint and writes no row (interim: c0239 records it for `--full --reuse`; AC15).

### Whole-gate reuse (`check.sh --affected`)
- These steps run after `--plan` has exited, so `--plan` still writes nothing. A gate-check counts only when its first stdout line is `reused <passed_at>` and it exits 0; an empty digest (as from a stubbed `lune`, `c0120/gate-homes.spec`) reads as no reuse and no record, so a tool that prints nothing never skips a gate (R28).
- After the fence, the prerequisites and the types download (the tools line hashes `.cache/globalTypes.d.luau`), before the sourcemap and the static stages, and unless `--fresh`, `check.sh` reads `digest=$(lune run z-nile/specs -- digest --mode affected --projects <picked, sorted, comma> [--base <merge-base sha>])` and `gate-check` looks it up in `gates`. On a hit it prints `reused: an affected gate passed on this content at <time>`, the static stages' stored report (every `== <stage>` header and output, so the lint summary is still there), `GATE PASSED (affected)`, and exits 0.
- The digest's extra is the mode, the projects, the base sha, HEAD when the selection holds a `*` spec, and every selected spec's declared refs whatever else the selection holds (the union of their `fingerprint.refs`, the refs `gitState` already reads for the run; design review 007 F2: a `ref:`-only spec's ref must move the digest); an unrelated ref cannot invalidate the gate.
- After the last stage passed, `check.sh` recomputes the digest. If it is unchanged and no `spec-norecord-<gate pid>` marker exists, `gate-record --digest <d> --mode affected --projects <picked, sorted, comma> --summary <file>` writes the row with the static report (and prunes) (`check.sh` runs `par_wait` into a temp file, prints it, fails on its status as before, and on exit removes its own `spec-norecord-$PICKMAN_GATE_PID` in every picked home and no other marker). A tree that changed during the gate, or a weak-jail spec run, records no whole-gate row.
- `--fresh` with `--full` exits 2 (`unknown or conflicting flags`). `--full` reads no `gates` row today (interim: c0239 adds `--full --reuse`, the merge condition).

### Runner results (`tests/run.luau`)
- With `PICKMAN_RESULTS` set to an absolute path under this run's own home's `.cache`, the in-process loop collects `{ file, loaded, cases = { {name, ok} }, detail, seconds }` per file (`detail` is the file's `FAIL` text, empty when it passed) and writes `{ jail = <its PICKMAN_TEST_JAIL, or "">, files = { … } }` as JSON to that path through a temporary file renamed over it. The coordinator gives each worker `PICKMAN_RESULTS=<path>.<index>` and merges the parts after the lanes; a worker that wrote no part makes its file `loaded = false`.
- Any other value is ignored silently and nothing is written (a nested run inherits the orchestrator's value, naming another home's `.cache`: it writes nothing). The runner's output and exit code stay exactly as they are.
