# c0172: Local ci only

## Problem
Move all CI verification to local checks so GitHub Actions only deploys to Roblox, and deliver and merge changes without GitHub CI.

Decided with the user (2026-10-27): this issue does not edit c0117 and does not wait for its ruleset text to change. The live ruleset on `main` is `no-force` (deletion and non-fast-forward only). Delivering and merging without GitHub CI is the skill and workflow change in this issue. c0117's unpublished §8 JSON stays that issue's user step.

Decided with the user (2026-10-28): runtime tests stay a merge condition. The merging machine runs `lune run scripts/cicd` from `pickman/` after the local full gate and before `gh pr merge`. That command reads `~/.config/pickman/cicd.toml`, reserves the CICD places, publishes them, and runs both suites. Actions does not run them.

Decided with the user (2026-10-28): "get it to green local CI and get it merge ready and then merge it." Misclassified `f0171` is withdrawn on this branch so `c0114/classified.spec` passes. This issue still does not edit that spec.

## Non-goals
- The local gate's own stages (format, lint, types, specs). `z-nile/check.sh --full` stays what it is.
- `pickman/scripts/deploy-beta.luau` and `pickman/scripts/runtime-test.luau`: what they publish and how they talk to Open Cloud. The new command runs them. It does not change them.
- c0152's rule for merging when `main` moved by tracker-only commits. On `origin/main` it is `design: draft`. On `prep-merge-past-tracker-only` (`20985fbc`) it is `design: ready`, and when merge-check says no its Design still says "wait for green CI again." This issue does not edit that document. It is re-prepped before it executes, because that sentence would put `green CI` into zz-rules and fail this issue's merge spec.
- c0157 (gate slots and the tripwire), c0165 (reusing passes), c0163 (conflict markers), c0162 (the runner's Lune pin). They change the local gate, not Actions.
- c0117's dispatcher, and its unpublished §8 ruleset. This issue does not edit that document. See Risks.
- A Linux runner, local or hosted. The machine that merges runs the gate.
- Player-facing game code. Nothing under `pickman/src/` changes.

## Solution
Verification is the local full gate: `z-nile/check.sh --full`, every project, on the machine that lands or merges. `./zn land` and `./zn done` already run it, and zz-rules Merging keeps that as the only verification. The merge stops reading GitHub Actions.

GitHub Actions keeps one workflow, `.github/workflows/deploy.yml`. Its one job runs `lune run scripts/deploy-beta` from `pickman/`. It does not run `z-nile/check.sh`, the runtime tests, or a raft's acceptance specs. `.github/workflows/check.yml`, `.github/workflows/board.yml`, `z-nile/ci-verify.sh` and `scripts/ci-verify.sh` are deleted. The board stays the local page `./zn board` writes (and `./zn sync` rebuilds).

## Design
No player-visible behaviour changes. No module under `pickman/src/` is touched, and no spec of the game's behaviour is rewritten. The pickman gate staying green is the record.

**What is verified today, and where.** `.github/workflows/check.yml` has two jobs. `gate` runs `z-nile/check.sh --project "$PROJECT" --full` on `ubuntu-latest` for `pickman` and `z-nile`, and on `workflow_dispatch` also runs the branch raft's sequestered acceptance specs. `beta` needs `gate`, runs `lune run scripts/deploy-beta` from `pickman/`, comments the version on the PR, then runs `lune run scripts/runtime-test`. `.github/workflows/board.yml` builds the tracker page and uploads it as the `tracker-board` artifact. `z-nile/ci-verify.sh` dispatches `check.yml` and waits. zz-rules Merging step 3 polls `statusCheckRollup` until `gate` is `SUCCESS`, then waits for `beta` the same way. Branch protection is not set: `gh api repos/philipbergen/pickman/branches/main/protection` returns 404, so the poll is the only thing that waits. The host this prep ran on is macOS.

**The three outcomes.** The local full gate is the verification that moves off Actions (it already runs locally; the Actions copy goes). The final check is that gate in a clone of the exact head whose parent directories are not a checkout of this repo, because a worktree inside the repo loads the main checkout's `.luaurc`. Actions only deploys: one job, `deploy-beta`, and only for a pull request that is ready for review and from this repo. A push and a manual dispatch start the workflow and skip the job. Deliver and merge do not read Actions.

**Runtime tests.** Today's Merging requires the `beta` job, and that job runs the runtime tests, so a failure blocks the merge. They need a published version, so they cannot be a check that runs before the deploy, and a spec run cannot run them: the jail has no network and cannot read the home directory, which is where the key file lives. Decided with the user (2026-10-28): they stay a merge condition, run by `lune run scripts/cicd` from `pickman/` after the local full gate and before `gh pr merge`. The workflow in this issue does not run them. `deploy-beta.luau` and `runtime-test.luau` are unchanged.

The command reads `~/.config/pickman/cicd.toml` (mode `600`, not in the repo). The only keys are `api_key`, `universe_id`, and `places.cicd` / `places.cicd_game`. `places.cicd` is the lobby build (`ROBLOX_BETA_PLACE_ID`) and `places.cicd_game` is the game build (`ROBLOX_BETA_GAME_PLACE_ID`). Inherited `ROBLOX_*` values are cleared, then those four are set from the file. `GITHUB_OUTPUT` is cleared so a local publish does not write an Actions output file. The key is never printed and never placed on a command line. A missing file exits non-zero. It does not skip.

Before publishing, the command reads the universe and stops if either place is `rootPlace`. It then takes one data-store entry, store `PickmanCicdLease`, key `hold`, for twenty minutes. Create uses `exclusiveCreate` when the entry is absent. Replace uses `matchVersion` of the version just read, and only when `until` has passed or the stored token is already ours. The value is JSON `{"token","holder","until"}`: the token, the holder (hostname and pid), and the deadline. The write sends `content-md5`. A lost compare-and-swap names the holder and does not publish. The store is not `Hiscores` or `HiscoreEntries` (those are shared by every place in the experience). The token is kept in `~/.config/pickman/cicd.lease`, mode `600`. A read of 404, or of 204 with no `roblox-entry-version`, is an absent entry and the take uses `exclusiveCreate`. A read of 204 that carries `roblox-entry-version` is a tombstone: the take POSTs `matchVersion` of that version. `exclusiveCreate` that answers 412 is re-read once: a re-read that carries a version is replaced with `matchVersion` of it, and there is no third `exclusiveCreate`. The command renews the deadline before each suite, for twenty minutes, after the publish and again before the lobby suite. Release runs on the way out, including failure. It does not delete. It POSTs an expired hold (`until` 1) with `matchVersion` of the version just read, and only when the token is still ours or `until` has already passed, and it deletes the token file only after that POST succeeds. The next read of that key is that posted body, HTTP 200, and a passed `until` is replaced. A 204 is a deleted key, not the result of this POST. `status` prints the holder and `until`, not the key and not the token. `release` clears by the same rule. There is no force clear of a live lease.

These places are not the ones GitHub publishes. The repo variables stay on the live start place `82331952549326` and the live game place `108477097003426`, universe `10768553777`. The toml's places, in that same universe, are `places.cicd` `119043028289480` and `places.cicd_game` `84049839292504`. The key needs `datastore.control:create` to create `PickmanCicdLease`, and data-store entry read, create, update and delete on that universe, as well as `universe-places` write and `luau-execution-sessions` read and write. Until the data-store scopes are on the key, the lease call returns 403 and the command stops before publishing.

`pickman/scripts/cicd.luau` is the command. `pickman/scripts/lib/cicdconfig.luau` parses the file and builds the child environment. `pickman/scripts/lib/lease.luau` is the compare-and-swap client. `pickman/scripts/lib/leasefile.luau` writes the token file. Tests drive a loopback Open Cloud, the same shape of seam as `opencloud.luau`. The spec resolves `scripts/cicd` and the child working directory from `git rev-parse --show-toplevel` plus `/pickman`, and it writes lease files under the runner's `.cache/cicd-spec`, so the same file passes from `pickman/` and from `z-nile/` (the full gate's home). The real toml is not a fixture.

**`deploy.yml`, the whole file.** The executor writes this and deletes `check.yml` and `board.yml`.

```yaml
name: deploy
# Publishes the place to Pickman (Beta). It does not run the gate or the runtime tests:
# those are local (z-nile/check.sh --full). A merge does not wait for this workflow.
on:
  push:
    branches: [main]
    paths-ignore: ['pickman/.tracker/**', 'z-nile/.tracker/**', 'z-nile/next']
  pull_request:
    types: [opened, synchronize, reopened, ready_for_review]
  workflow_dispatch: {}

permissions:
  contents: read

jobs:
  deploy:
    if: >-
      github.event_name == 'pull_request' &&
      github.event.pull_request.draft == false &&
      github.event.pull_request.head.repo.full_name == github.repository
    runs-on: ubuntu-latest
    timeout-minutes: 20
    permissions:
      contents: read
      pull-requests: write
    concurrency:
      group: beta-deploy
      cancel-in-progress: false
    steps:
      - uses: actions/checkout@v4
      - run: z-nile/setup.sh --tools
        env:
          GH_TOKEN: ${{ github.token }}
      - id: deploy
        working-directory: pickman
        run: lune run scripts/deploy-beta
        env:
          ROBLOX_API_KEY: ${{ secrets.ROBLOX_API_KEY }}
          ROBLOX_BETA_UNIVERSE_ID: ${{ vars.ROBLOX_BETA_UNIVERSE_ID }}
          ROBLOX_BETA_PLACE_ID: ${{ vars.ROBLOX_BETA_PLACE_ID }}
          ROBLOX_BETA_GAME_PLACE_ID: ${{ vars.ROBLOX_BETA_GAME_PLACE_ID }}
      - if: steps.deploy.outputs.version != '' && github.event_name == 'pull_request'
        run: |
          gh pr comment "$PR" --edit-last --create-if-none \
            --body "Published to Pickman (Beta): version $VERSION (commit $SHA)."
        env:
          GH_TOKEN: ${{ github.token }}
          PR: ${{ github.event.pull_request.number }}
          VERSION: ${{ steps.deploy.outputs.version }}
          SHA: ${{ github.event.pull_request.head.sha }}
```

A push that only touches a project root or `z-nile/next` does not start a run (the same ignore list as today's gate). A push to `main` that is not ignored, and `workflow_dispatch`, start the workflow and skip the job: they do not deploy. A draft, and a pull request whose head is a fork, does not deploy. The job `if`, with its whitespace collapsed, is exactly `github.event_name == 'pull_request' && github.event.pull_request.draft == false && github.event.pull_request.head.repo.full_name == github.repository`. The version comment's `if`, collapsed the same way, is exactly `steps.deploy.outputs.version != '' && github.event_name == 'pull_request'`. The concurrency group stays `beta-deploy` with `cancel-in-progress: false`, so one publish finishes before the next starts. `timeout-minutes: 20` stays. No `needs`, no `continue-on-error`, no `|| true`.
