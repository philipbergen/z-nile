# c0173: C0075 reads the local jail wiring

## Problem
c0075 acceptance/wiring.spec.luau:47 reads .github/workflows/check.yml jobs.gate for the bubblewrap step; c0172 deleted that file, so the case has to read the local jail wiring before c0075 executes.

Decided with the user (2026-11-01): "Follow the Problem" (the case reads the local jail wiring, `SETUP.md`'s Prerequisites section; no workflow is read; the title, which said "read deploy workflow", is changed to match).
Decided with the user (2026-11-01): "In the prep commit" (the edits to c0075's sequestered `wiring.spec` and to c0075.md and R0039.md are made in this issue's prep commit, not in its execution; the prep brief's "don't edit c0075" is lifted for exactly the reviewed patches).

## Non-goals
- The rest of c0075's redesign. c0114 and c0120 promised a re-prep of R0039 and c0075 against the final layout, and it has not happened: `wiring.spec`'s other cases read `scripts/lib/fence.sh` and write `{root}/.cache`, `c0075/check.sh` sources `scripts/lib/ac.sh`, and the document names `tests/lib/fence.luau`-era paths (E5). This chore fixes what c0172 broke (the case that reads a deleted workflow, and the sentences that tell the executor to edit it) and nothing else.
- Where the Linux whole-suite proof runs (c0075's E5, R0039's `RC` lines and Exit criteria still say the PR's CI gate job on `ubuntu-latest`, and `scripts/ci-verify.sh` is gone). c0172 dropped that run on purpose ("the capture is the decision"), so the replacement venue (a throwaway branch workflow as E1 to E8 used, a Linux host of the user's, or reasoning only) is the user's, decided in the re-prep.
- `c0075/check.sh`: its AC6 label still says "CI, the fence's hooks and the documents know the Linux jail". The file is sequestered and its blob id is exempted by `c0120/check-paths`, so any edit would re-expose its stale paths. The re-prep restamps it.
- Adding a jail step, or any other step, to `.github/workflows/deploy.yml`. It runs no spec, and c0172's promoted `deploy.spec` pins that.
- Making `z-nile/setup.sh` run `scripts/linux-jail.sh` (c0075 left `setup.sh` untouched on purpose: the sysctl is host-wide, and a developer machine is never changed without the flag).

## Solution
Replace the one case of c0075's `wiring.spec` that reads `.github/workflows/check.yml` with a case that reads the local wiring: `SETUP.md`'s `## Prerequisites` table must have a row whose Linux cell names `scripts/linux-jail.sh`. That is where a Linux host's owner is told to get the jail, the local counterpart of "CI runs the script before `setup.sh`" (the case checks that the row is there, not that it comes first). Edit the sentences of c0075.md and R0039.md that tell c0075's executor to add a step to a workflow, so they say what the case reads. Three patches and a harness in `experiments/` carry the edits; the harness runs the new case against fixture `SETUP.md` texts, which the case itself cannot do until c0075 has written the row. `check.sh` pins the patched `wiring.spec` by its whole blob id (`f4a841ef…`), so no other case of that file can change (design review 001 F2).

## Design
No game code, no tooling code and no promoted spec changes. The files that change are another item's sequestered spec and two tracker documents, so this is a tooling chore with nothing to ship but text.

**Decided by the capture (Problem):** "the case has to read the local jail wiring". The local wiring is `SETUP.md`: it is what a host's owner follows, before `z-nile/setup.sh` runs the gate (its step 4). The captured title said "read deploy workflow"; the Problem says "read the local jail wiring", and a reading of `deploy.yml` would add nothing: c0172's promoted `z-nile/tests/acceptance/c0172/deploy.spec.luau` ("one job, deploy, with no needs and no gate" and "no step runs the gate, the runtime tests or a raft's acceptance specs") already pins that `deploy.yml` runs no spec, so it needs no jail step, and the new case does not repeat it. The user decided (2026-11-01, "Follow the Problem") that the local wiring is `SETUP.md`'s Prerequisites row and that no workflow is read; the title was changed to match.

### The new case (in `c0075/acceptance/wiring.spec.luau`, replacing "CI makes bubblewrap usable before the gate runs")
Title: `a Linux host's prerequisites name the jail script`. It uses only `fs`, `t`, `root` and `has`, so the harness can compile it alone. The text is `experiments/wiring.patch` (applied with `patch`, E3; the result's blob id is `f4a841ef2b6753547982911295c28f33b8270ac1`, AC1):
- it reads `{root}/SETUP.md` (the checkout's top; the old case read a cwd-relative path, which is wrong from z-nile's home);
- the case checks a row, not an order: the Prerequisites section may sit anywhere in the file (harness scenario 2 passes, on purpose);
- the section is the text from `\n## Prerequisites` up to the next `\n## ` (or the end of the file);
- inside it, a line counts only if it starts with `|` (a table row), and the row counts only if its fourth piece when split at `|` (the Linux cell of `| need | macOS | Linux |`) contains `scripts/linux-jail.sh`;
- the case passes when at least one row counts.
The patch also drops the `serde` require and `stepIndex` (nothing else uses them) and rewords the file's header comment, which said "CI provisions it".

What the row says is c0075's: `SETUP.md` gets a Prerequisites row for the spec jail, whose macOS cell says specs are jailed already and whose Linux cell names `scripts/linux-jail.sh` and its `--apply-sysctl` form. c0075's Documents bullet says so after this chore (`experiments/c0075-doc.patch`).
