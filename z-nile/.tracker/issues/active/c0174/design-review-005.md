An executor who "fixes one more CI sentence" (the Non-goal lists six backstop sentences left as they are) and then follows AC3's own wording ("its merge-base text with the patch applied") by regenerating the patch is a plausible path, not a contrived one. The forward branch exists only for the routes where the executor applies the patch. Critique: the tempting fix is to delete the `elif` branch only. The reverse dry run would still read the patch from the branch, which can shrink it to one hunk the base holds, and AC2 would still run a branch-editable harness. Each AC would then stop proving what its text claims.

Recommendation: make the decided route the only one these checks accept. (1) `exactdoc`: the merge-base text must hold the patch (`patch -R -f -F 0 --dry-run` on it), and the file must equal that text byte for byte; drop the forward-apply branch.
