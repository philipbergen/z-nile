# c0178: Shared fixture images

## Problem
The user (2026-10-31), after a full gate pegged fseventsd at a whole CPU core: "This is not acceptable. Find a better solution. Test has to be thorough and complete but also very fast and efficient."

Measured 2026-10-31: one worktree's `z-nile/.cache` changed 10,711 files in 10 s during a full gate (`find -newer`, so files made and removed inside the window are not even counted); fseventsd ran at about 80-100% of a core and `mds_stores` at about 35%. The z-nile suite is 1265 cases in 183 files, about 1,850 s of spec time and 185-230 s of wall time idle (up to 1,800 s under load); `c0116/claims` and `c0120/finished` take about 175 s each idle and set the floor. c0175's capture ran the full gate three times (about 6 min each) and still lost the race to main.

Every spec builds its fixtures from scratch. `trackerfix.new` (`z-nile/tests/lib/trackerfix.luau`) makes a `seed`, a bare origin and the `main` and `other` clones, each holding `engine.copy`'s ~243 tooling files (`z-nile/tests/lib/engine.luau`, 133 of them lessons) written as loose objects; every `git init` also gets git's 14 sample hooks; 14 or more specs clone the whole real repository with `--no-hardlinks`. Nothing is shared between specs, and fixtures are never removed, so each worktree keeps 160k-218k files in `z-nile/.cache`. `fixture.git` runs `fixture.check` twice, about 7 processes per git call (`z-nile/tests/lib/fixture.luau`); `c0120/finished` launches `lune` about 80 times, `c0116/claims` makes 20 full worktrees.

What should happen: a fixture costs a few files and processes, not thousands, with every spec case kept and every guard still in force.

Decided with the user (2026-10-31): fewer files **and** a fixture volume fseventsd ignores (c0179); every case stays (thorough and complete).

Measured by prep (2026-11-01, load average 18 to 35 on 18 cores, so only the ratios mean anything). One `trackerfix.new` before: 1,184 to 1,343 files and 1,599 to 1,860 inodes under `.cache/<name>`, 79 processes, 4.1 to 6.6 s (2.9 to 4.8 s of it system time), and 2 of 5 runs outside the runner died in `git clone` with "failed to copy file" (git's detached maintenance rewriting the packs under the clone that copies them: the runner's fence already sets `gc.auto=0` and `maintenance.auto=false`, a bare script does not). The eight specs that clone the real repository cost about 2,900 files each (2,584 tracked files checked out); `c0116/claims` ran 6,426 git, bash and lune processes in 147 s (122 tracker.sh commands), 20 of them `git worktree add`; `lune run` itself starts in 10 to 20 ms, so the 88 `lune` launches of `c0120/finished` are about 2 s of its 275.

Decided with the user (2026-11-01), after design review 001:
- Scope decision (user, 2026-11-01): "Fix in c0178" for the working tree the eight repository-cloning specs check out (about 2,900 files each): design `--no-checkout` plus the paths each of those specs reads, in this issue.
- Scope decision (user, 2026-11-01): "Convert them" for the 11 hand-built four-repository fixtures: move them onto `trackerfix.new` / the shared builder, with their overrides.
- Scope decision (user, 2026-11-01): "Drop it": the in-process `c0120/finished` part is removed from c0178 (AC9, the `finished-*` Touched modules and `finished-inprocess.spec` with it); measured saving about 2 s of 275 s for about 700 changed lines; no issue picks it up.
- Decided with the user (2026-11-01): "keep your choice" for the `fixture.check` memo: only the home's physical path is memoised per process, `pwd -P` and `rev-parse` of the directory stay live (a prep choice, marked for the reviewer).
- Decided with the user (2026-11-01): "keep it, with your reason stated" for the clones that copy their packs instead of hardlinking them (a spec that damages a pack through a hardlink would damage every later fixture; the file count is the same).
- Decided with the user (2026-11-01): `noLessons` for worktree-heavy specs is not taken (it conflicts with G7, the user's 2026-10-21 decision).

## Non-goals
- Fixtures off the main disk: c0179.
- Which specs run after a change (c0180's affected selection by command).
- Dropping or narrowing any spec case: every case stays.
- Changing what any spec case proves: a case is kept as it is, or its setup is replaced by a cheaper setup that makes the same state (the promoted specs edited are named in the Regression guard).
- A different default for `trackerfix.new`'s lessons: G7 (c0115, 2026-10-21) keeps the skills' lessons in every fixture; `noLessons` stays the opt-in of the specs that need an exact set.

## Solution
- One image per content: the first spec that needs one builds it, under a lock, as a fully packed bare repository (`git repack -adq`, `pack-refs`) keyed by a hash of its inputs; later specs clone it with `git clone --local` (the pack hardlinked).
- `trackerfix.new` drops `seed/`, clones `main` from the image and makes `other` only when first used; options that change the seed key their own image.
- One `--no-hardlinks` clone of the real repository per run and HEAD, as an image; specs clone that image (c0006's rule covers the real object store only: check).
- `init.templateDir` set to an empty folder in the fixture git environment: no sample hooks.
- `fixture.check` once per call, memoised per physical path in a spec process.
- A passing spec removes the fixtures its helpers registered; a failing one keeps them.
- `c0120/finished` calls `finished.luau` in-process; `c0116/claims` reuses one image for its worktrees.
- The gate prints fixture files written and processes started per home, beside `slowest:`, with the before and after recorded.

## Design
**The rule.** A fixture is made by copying something already built, never by building it again. What is built once is an **image**: a folder named by a digest of what it is built from, published by one rename, shared by every spec of the run and by later runs. A fixture clones or copies an image, and nothing a spec does to the fixture can reach the image.

**Modules** (every one is strict Luau on Lune; the reads are at the edge, the key is a pure digest over bytes):
- `z-nile/lib/image-key.pl` (new, ~55 lines, read-only): `perl image-key.pl <root> [<path>...] [--skip <path>]... [--also <file>]... [--salt <text>]` prints one 40-hex digest of every file's relative path, executable bit and bytes under the paths (a symlink by its target text, never followed; a path that does not exist is an error naming it), then each `--also` file's bytes and each `--salt` text. One process, no `.cache` named in it (so the `cachepaths` list needs no entry).
- `z-nile/tests/lib/images.luau` (new, ~200 lines): `type Spec = { name, root, inputs, skip, code, salt?, build }`, `type Options = { dir?, stale?, wait?, beforeLock? }`, `images.ensure(spec, options?): string`, `images.dir(): string` (**the one place that decides where images live**: `<physical home>/.cache/images`), `images.builds(): number` (a spec seam). `ensure`: the key is read once per process per spec (memoised by name, root, inputs, skip, code and salt); if the image's folder exists it is returned; else a `mkdir <id>.lock` (advisory) is taken, and if it is held the caller polls every 0.2 s until the image appears, the lock is older than `stale` (60 s) or `wait` (180 s) has passed, then builds anyway; after taking the lock it looks again (an image published between the look and the lock is used); a lock whose recorded owner (`owner`: pid and start id, `fence.startOf`) is dead, like a stale one, stops holding callers off: they build and the rename lets one win (a few duplicate builds at worst; no takeover, since a check-then-rename takeover could remove a live lock); the build runs in `mktemp -d <home>/.build.XXXXXX` and is published by `fs.move(build, final, false)`: a lost race discards the build and returns the winner's. A failed build removes its folder and its lock and raises `images: building <id> failed: <cause>`. `ensure` removes nothing. **Pruning is `z-nile/tests/lib/pruning.luau` (`pruning.run(home, keep?, minAge?)`), called once per run by the launcher (`fence.luau`, right after it takes the run's lock and before it starts any spec), when nothing in the run can be using an image** (design review 002 F1: a prune inside `ensure` removed an image another worker had just resolved): of each kind (the whole id minus its 24-hex key, so `seed` never matches `seed-nolessons`) the images beyond the newest `keep` (2) that are older than `minAge` (3600 s), and `.build.*` and `*.lock` folders older than `minAge`. The launcher is outside the jail and removes recursively inside `.cache/images`: Rust's `remove_dir_all` does not follow links, and this is the runner write the zz-test skill says review must check. Clocks: both sides of every age are wall clock (the file's mtime and `os.time()`); a clock step makes a fresh lock look stale (a second build, harmless: the rename lets one win) or a dead one look live (a wait of at most `wait`).
- `z-nile/tests/lib/engine.luau`: `engine.build(root, dest)` is the old `engine.copy` body (it also writes the registry); `engine.image(): string` (the tooling image of this checkout: inputs `zn`, `scripts`, `z-nile`, skipping `engine.STATE`'s entries under `z-nile/`, code `images.luau` and `engine.luau`); `engine.seed(noLessons): string` (the packed bare repository `seed.git` inside the seed image: built by `git init`, `engine.build`, `engine.clearLessons`/`engine.roots`, the `.gitignore`, one commit `seed` as `images@example.invalid`, `repack -a -d`, `clone --bare --no-hardlinks`, `remote remove origin`); `engine.copy(given, dest)`: a `given` other than this checkout's own (a spec's mutated tree) goes through `engine.build` as before and builds no image; this checkout's own is `cp -cR <image>/. <dest>` (`cp -R` where copy-on-write is refused: Linux, another volume), and when `dest/.git/objects/pack` exists the seed image's `*.pack` and `*.idx` are copied into it by one more `cp`, so the caller's `git add -A` writes next to no loose object.
- `z-nile/tests/lib/trackerfix.luau`: `trackerfix.new(name, seed?, opts?)` as above (same signature, same `Fixture` table, `f.other` is still a path); `trackerfix.worktrees(f, names): { string }` (named worktrees only: lowercase, digits, `-`, at most 60 characters; anything else raises naming it); `tr`, `trOk`, `elsewhere`, `stub` unchanged. All its processes go through `tally.exec`.
- `z-nile/tests/lib/fixture.luau`: `fixture.defer(dir, make)` (a helper promises a folder and makes it the first time `fixture.check` is given it; the checks then judge what it made like any other); `fixture.git` calls `fixture.exec` only; every process through `tally.exec`. The guard itself (`check`, `pointsElsewhere`, the refusals and their messages) is unchanged.

**Flow of one fixture** (`trackerfix.new`, warm images): `rm` the old folder; `git clone` the seed image into `main` (identity by `-c`, so no `git config`), write the seeded files, `git add -A`, `git commit --amend --reset-author`; `git clone --bare` `main` into `origin.git`, `git remote remove origin` there, `git remote set-url origin` and `git fetch` in `main`; `other` waits. 15 git processes, no `cp`, no `init`, no `config` (25 processes in all). Cold, the first spec that needs the seed builds it under the lock while the others wait.

### Scalability
A fixture's file count is one working tree of the tooling plus ~65 files of git metadata while `other` is unused (326), two trees plus ~110 when it is used (621), against 1,184 to 1,343 before; its processes are 15 git (six of them guard checks), 9 `pwd -P` and one `perl` (25 against 79 before; one figure everywhere: 25 processes warm). The tooling gets bigger as skills and lessons are added: the fixture follows it linearly, as before, and the images are built once per change of any file they hold, not once per spec. The key costs one `perl` per kind of image per process (22 ms over the ~250 files it walks). Images accumulate one per change of the tooling in a worktree's `.cache` until the next build prunes them (two kept); the keys are the only cost of keeping them. The real-repository image is one bare clone per HEAD.

### Maintainability
One store (`images.ensure`) for every image: a new kind of image is a `Spec` with a build function, nothing else. One place decides where images live (`images.dir()`), one function the key (`image-key.pl`). `swept` and `tally` are one concern each, called from one place (the runner), so a new fixture helper registers its folder and counts its work in two lines. The next project or root changes nothing: the tooling image is the tooling, whatever projects the registry lists.

### Usability
The runner's line `fixtures: N files written, M processes started (by the fixture helpers)` shows the cost of fixtures next to the slowest specs, and says what it counts (a lower bound). A failing spec keeps its fixtures; a passing one leaves none of the folders its helpers (`trackerfix.new`, `clone.isolated`, and `engine.copy` for the fixture folder it copies into) registered, so `.cache` stops filling with the 160k to 218k files; a hand-built fixture folder nobody registers stays until the next run replaces it. Every refusal names the path or the rule: `images: <kind> is not an image name`, `images: the key of <kind> could not be read: <perl's message naming the path>`, `images: building <id> failed: <cause>`, `swept: <path> is not a folder inside <cache> (and outside the images): refusing to register it`, `trackerfix.worktrees: <name> is not a named worktree`. Nothing is added to `./zn`, the main checkout's command list or the usage text.

**Considered, not done.**
- *Alternates* (`objects/info/alternates` into the image): fewer files again, but a fixture then depends on the image existing and an image removed mid-run corrupts fixtures; refused.
- *Hardlinks into the image* (the bullet's `git clone --local`): the packs are immutable and read-only, so a hardlink is safe until a spec truncates or rewrites a pack (`git gc` never does, but a spec that damages its own repository might); the file count is the same either way and the copies cost ~400 KB each, so the clones copy. Deviation from the bullet's mechanism, not its outcome; the open questions say so.
- *Memoising `fixture.check`'s verdict per physical path*: the part that costs is `pwd -P` and `rev-parse`, and `rev-parse` is the part that notices a deleted `.git` (git would then find the real repository above it). Memoising it makes the check blind to exactly the accident it exists for. Memoising only the home's physical path saves one more process a call and is blind only to a renamed ancestor folder, which the jail forbids; it is the user's to accept (open questions).
- *`trackerfix.other` as a function* (and editing the 14 specs that read `f.other`): the sequestered specs of unlanded items read the field too; `fixture.defer` keeps the field and defers the work. (A metatable `__index` was tried first: Lune cannot yield inside a metamethod, so the clone cannot run there.)
- *Lessons dropped from fixtures* (`noLessons` as the default): 138 of a fixture's 262 files are lessons (G7, the user's decision): it would halve every worktree checkout and every fixture; not mine to change (open questions).

**Decisions taken after design review 001** (all built in the prototype and covered by cases; see `design-refute-001.md`):
- *Sweep failure (F5)*: a sweep that cannot remove a folder prints `swept: could not remove <path>: <error>` and the run exits 1 with the file's cases still counted as passed.
- *`other` is the old state (F6)*: the deferred clone resets to the seed commit (`reset --hard <seed>`, `origin/main` at the seed, every other remote ref of the clone deleted), so a terminal that is behind stays behind.
- *The lock (F7)*: waiters check `fs.isDir(final)` and the lock in-process and run `mkdir` only when the lock is gone; waits are measured in milliseconds against a start stamp; the lock holds `owner` (pid and start id, `fence.startOf`); a waiter that finds the owner dead stops waiting and builds (no takeover: a check-then-rename could remove a live lock); the rename publishes one.
- *`trackerfix.worktrees` (F9)*: fresh names only: a name after the first whose `refs/heads/<name>` or `refs/remotes/origin/<name>` exists is refused, naming it.
- *Template folder (F10, round 2 F6, round 3 F1)*: stays writable (a read-only folder cannot be removed by a plain `rm -rf`, and c0194 moves the run folder under `.tmp/`); `run.luau` makes one folder per spec file of a concurrent run (`<template>-<index>`, handed to its worker in `GIT_TEMPLATE_DIR`) and looks at it after that file: anything but the empty `hooks/` and `info/` is named (`FAIL <file>: git template changed: <path>`), removed, and fails the run, so a write is blamed on its writer alone and later files never inherit it.
