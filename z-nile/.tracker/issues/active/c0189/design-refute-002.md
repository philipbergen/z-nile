# Answers to design-review-002 (c0189)

- F1: fixed (the reviewer's first recommendation, not a Guess): `--check` accepts, with exit 0 and the note `hooks: <dest> is an older reviewed copy of origin/main's z-nile/lib/repo-hooks/reference-transaction; run ./zn hooks to update`, an executable copy of our own file whose blob `origin/main`'s history of the source has held (`git log --format= --raw --no-abbrev origin/main -- <source>`, parsed by `hooks.blobIds`, matched against `git hash-object <dest>`; read only when the installed text differs and is ours). A text `origin/main` never held (a hand edit, a branch's copy) is still `differs … run ./zn hooks`, red; a held text that is not executable is red too; `./zn hooks` always installs the newest. `hooks.State` gains `reviewed`, `hooks.Plan` gains `older`. Design: the plan table (two rows), "A legitimate fetch does not turn gates red", Existing work, Risks (the red-window bullet is replaced by "a fix to the hook cannot force itself on gates"), AC2, AC3. Cases: `hooks-plan` "an older reviewed copy…" and "blobIds…", `hooks-command` "origin/main moves…" (green with the note, then updated, then a never-held text red and repaired). Mutants Q1 (any text of ours passes, in both specs), Q2 (a non-executable copy tolerated), Q3 (`--check` red for an older copy), Q4 (a deletion's zero name kept): all killed. Consequences, handled: a hook fix cannot force itself on gates (Risks; `./zn sync` reinstall still not adopted, and AGENTS.md's list unchanged); the no-`origin/main` case (the clone) only has the tree's copy, so `reviewed` is never set there (`from = tree`).
- F2: fixed in the text, the rest is the user's: reproduced (`e12.sh`, E12): `branch -m` sends only the deletion, `branch -c` calls no hook, `pack-refs` sends creations (so gc refuses to pack the renamed ref). The "superset of the tripwire", "nothing the tripwire flags can be created" and Non-goals "one place every … passes through" sentences are corrected (Design, Non-goals) and the limit is in Risks and E2/E12. The zz-test hook bullet gains the instruction "never rename or copy a branch whose tip is a fixture commit: delete it, or look at it with `git worktree add <dir> <branch>`" and `wiring.spec` pins it. Deleting the four old branches is not prep's (they belong to other sessions): G4 puts the options (delete them; accept the limit) to the user with the evidence, recommending (a) by their owners and (b) until then. The merge --no-ff route (fixture commits under an ordinary tip) is named as not covered by any ref hook.
- F3: fixed: a `hooks-command` case sets `refs/remotes/origin/main` to a blob and expects both modes to exit 1 with `hooks: cannot read origin/main:`, the installed hook unchanged and no `.reference-transaction.new`; mutant S5 (a failed `ls-tree` taken as no file) is killed. The same case covers F4. The ref is restored by fetching with the hook moved aside (the fixture's commits carry the fixture identity).
- F4: fixed: the tree's copy is used only when `git remote` lists no `origin`; an `origin` whose `refs/remotes/origin/main` is missing is an error in both modes, `hooks: origin has no main fetched; run git fetch origin main`. `hooks-command` "a read of origin/main that fails, or an origin whose main was never fetched…" deletes the ref and expects the error; mutants S6 (the tree's copy for an origin without main) and S4 (no origin is an error) are killed. Design: "Why `origin/main`", AC3.
- F5: fixed: on the refusal path only, each update is keyed by the commit it peels to (`git rev-parse -q --verify <sha>^{commit}`, the object name itself when it is not a tag), so an annotated tag's ref is named in the message and the remote-tracking hint works for a tag fetched under `refs/remotes/`. `repo-hook.spec` adds `git tag -a` to the refused routes and expects `refs/tags/by-annotated` in the message; mutant H16 (refs keyed by the tag object) is killed. No new rule beyond the message; the peeling runs only when the hook is about to refuse.
