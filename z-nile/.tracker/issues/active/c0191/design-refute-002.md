# Answers to design-review-002 (c0191)
All 14 findings are fixed; none is refuted. Each line: the fix, then the consequences checked (z-design step 5.3).

- F1: fixed: the session rule's targets are now the session's **tool shells**, whatever they run, each with its whole tree (the loop runs in the shell itself; `sleep`, `gh` and `grep` are its children), and `node editor.js`-like children go with their shell. After the session is gone the orphan rule takes an orphaned tool shell and the `sleep`, `tail`, `gh`, `grep`, `watch`, `yes`, `caffeinate` and interpreters of a loop or a killed monitor; a `tmux` and a login shell stay. consequences: the shell's own working folder must be in scope (a shell that `cd`ed elsewhere is kept: the fence of the Non-goals); the orphan names list grows (ORPHANABLE, with the matching CHAIN names); the rules rows and reap.spec's session case were rewritten (shell with loop, MCP server, unknown form, out-of-scope shell, another session) with a second case for the orphans; the pure probe the reviewer ran now yields the shell as the one target.
- F2: fixed: runner-cpu and engine-cpu read what was *asked for* through a stand-in `ulimit` (a function bash reads from BASH_ENV, answering `ulimit -t` with FAKE_LIMIT and recording every `ulimit -t N`); one real case each remains (a CPU burner dies of SIGXCPU; a spinning engine is stopped; the real limit under a lower caller). Defaults of 86400 now fail (mutants t1 and t2 killed). consequences: the stand-in answers only the arguments the Design names (`-t`, with or without a value) and records anything else as nothing; the stand-in file lives in the fixture.
- F3: fixed: no `permissions.allow` entry for `./zn run` or `./zn reap`; the settings case asserts both are absent, with the reason in a comment; the Design says allowing either is the user's decision in their own settings. consequences: each wrapped command asks for a permission unless the user allows it; this is the cost of not widening permissions; it is reported to the lead as a question for the user.
- F4: fixed: a loop is recognised wherever it stands (the keyword is read from the resolved command, after `then`, `do`, `!`, `time`, in `$(...)`, in `bash -c`, in a shell-read here-document body), `for ((;;))` is refused, and the here-document scanner needs a terminator line, ignores `<<<` and `$((1<<2))`, and reads a body a shell consumes as code. The review's remark that coverage is the hole is answered in the Design: it lists what the hook does not cover, calls it a seatbelt, and names the guaranteed layers (runner, CPU limits, reaper). consequences: more rules and cases (eight refused spellings, seven passing); the checks use the same functions as the entry.
- F5: fixed: `while read` passes (it ends at end of input); `yes` is no follower; an absolute path to the gate's tooling passes (suffix match after a folder boundary); the loop refusal tells the agent to put a loop with quotes in a script file (`./zn run --time N -- bash <script>`). The harness's own recommendation of a background `until` wait is exactly the idiom that leaked three loops for 5 days (E11), so it stays refused unless wrapped. consequences: the wrapped form is longer; stated in the refusal.
- F6: fixed: a background call needs at least one bounded command and no command that is neither bounded nor one that ends by itself (`cd`, `echo`, `sleep`, `export`, `true`, `test`, `printf`, ...). consequences: `cd d && echo go` is still refused (nothing bounded); a case for the mixed call.
- F7: fixed, by recording the premise as unknown with a fallback: loops and follows stay allowed in Monitor (they are the tool's canonical use and refusing them would make it unusable); U1 now asks whether an expired monitor kills only its shell or its group; whatever it leaves, `tail`, `grep`, `gh` and `sleep` are now in the orphan rule's names, so the reaper takes them a minute later. consequences: if U1 shows expiry kills the group, nothing changes; if it leaves them, the reaper covers it; the Monitor allowance narrows only to what the experiment shows is stopped.
- F8: fixed: the Design no longer says "by class"; it says "a listed set of forms" and has a plain "does not cover" paragraph (shell scripts by name, `npm`/`npx`, `make`, unlisted interpreters, unreadable text). Fixed in code: `caffeinate -t N <command>` judges the command; `perl -e` with `while (1)`, `1 while`, `for (;;)` or `until (0)` is refused; `bash -c -- '...'` is read. consequences: `perl -ne 'print while <>'` still passes (cases for both sides).
- F9: fixed: the captured "stops the group when its parent dies" is built: the runner polls `getppid` (a parent's death sends no signal) every fifth of a second and stops the group when the process that started it is gone (exit 129); the wait loop is a poll instead of a blocking `waitpid`. consequences: a runner whose parent is gone before it starts is an orphan from the start (it keeps its other limits; the orphan rule takes it); a case starts the runner under a shell that ends after a second; the mutant without the watch is killed.
- F10: fixed: "1..900" in Usability is 3600; the scratch scope text names what it depends on (the slug rule, the temp folder, `claude`, the snapshot folder, whatever the config folder, matched as `/shell-snapshots/`), each failing closed; the temp folder is `getconf DARWIN_USER_TEMP_DIR`. consequences: none.
- F11: fixed: the Design says whichever of c0165 and this issue lands second adds `z-nile/specs` to `TOOLING`, and the lead is told that c0165's reviewed document should say so (this prep cannot edit another prep's files). consequences: none.
- F12: fixed: the end-to-end work folder is unique per run and only that folder is removed; it needs no runner lock because no other run shares it. consequences: none.
- F13: fixed: one TERM for every target's processes, one shared wait of up to two seconds, one KILL for what is left. consequences: per-target reports are made after; "COULD NOT STOP" names the target with a survivor.
- F14: fixed: Rules rows for the `--quiet` summary, the guarded message and the platform decision, marked `reasoned` with the reason (unobservable in a spec run, where `guarded()` is always true and the reaper is not run; read in the diff). consequences: none.
