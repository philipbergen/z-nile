# Answers to design-review-003 (c0191)
Seven findings are fixed and two (F2, F5) are product decisions that only the user can take: they are put to the user (Design, "Open decisions for the user"), with options and costs, and the Design keeps a marked default of each until they answer. None is refuted.

- F1: fixed: `split` reads `2>&1`, `>&2`, `<&3` and `&>log` as parts of their word, so a redirection never makes a command; a redirection left at the start of a command (after `)`) starts nothing; the filters `tail`, `tee`, `head`, `grep`, `sed`, `awk`, `wc`, `sort`, `cut`, `tr`, `cat`, `uniq` and `git`, `gh`, `jq`, `seq`, `uptime`, `diff`, `ls`, `date` and the closers `done`, `fi`, `esac`, `for`, `case` end by themselves; `ci-verify.sh` is bounded like `check.sh`. The rule now is "no command that is neither bounded nor ends by itself" (the reviewer's "one at least must be bounded" refused counted polls of `gh` that are bounded by `seq`). E15 ran the classifier over the reviewer's 859 calls: no gate-shaped background call is refused (28 of 30 background calls were), and the background cases of the spec carry the five forms plus `./zn land > log 2>&1; echo "exit=$?"; tail -3 log`. consequences: the TRIVIAL list grew (a mixed call such as `./zn list 2>&1 | perl -e '1 while 1'` stays refused by the perl rule, and `tail -f log 2>&1` by the follow rule: cases); `lune run p.luau 2>&1` stays refused (case); eleven mutants killed.
- F2: escalated: whether to scan inline Python as `perl -e` is scanned (option a) or keep refusing every `python3` call and accept the measured cost (option b, the current default). The numbers (152 of 859 calls) are in E15. Neither is a cut of captured scope, but it is a product tradeoff the user should take knowingly. consequences: option (a) adds about 40 lines and four cases; option (b) is what the specs pin today.
- F3: fixed: `z-nile/engine/main` and `scripts/cicd` leave `TOOLING` (agents run `./zn`; `scripts/cicd` runs the minutes-long runtime suites, now wrapped in zz-rules' Merging step and pinned); a target passes only under the checkout (absolute) or from a `cwd` inside it (relative), both from the hook's payload (`ZN_CHECKOUT`, `cwd`). consequences: the final merge check, which runs in a clone outside the checkout, has to wrap `lune run scripts/cicd` anyway; `lune run tests/run` from a clone outside the checkout is refused with the wrapper named (the merge procedure runs `z-nile/check.sh --full`, a script, there); an unknown checkout (hook not told) falls back to the path alone. Cases: absolute under and outside the checkout, relative from inside and outside, a worktree path.
- F4: fixed: a job started with a single `&` in a foreground call (`cmd > log 2>&1 &`, `(cmd &)`) is refused unless the call has a `wait`, with `run_in_background` and the wrapper named; Monitor is excepted. consequences: `a & b & wait` and `./zn run -- sh -c 'a & b; wait'` pass (cases); the rule needs the separator each command ended with, so `split` returns it.
- F5: escalated: `/clear` and the session rule (Design, "Open decisions for the user", options (a) and (b)); U2 also asks whether Claude Code keeps a background task across `/clear`. consequences: option (b) is one word in `session-end.sh` and one changed `hooks.spec` case.
- F6: fixed: the sync pin reads the sync command's body (in `main.luau` from `function cmd.sync(` to the next top-level `end`, or all of `cmd/sync.luau`) and requires the call before the first `fetch`; a commented gate line fails the gate pin. The mutants "call moved to another command" and "commented line" were run and die. consequences: none.
- F7: fixed: option values of the prefix commands are skipped (`timeout -s/-k`, `sudo -u/-g/...`, `nice -n`, `env -u/-C`, `xargs -n/-I/...`, `stdbuf`), `env -S 'cmd'` is read as a command line, a here-document piped into a shell is code, the C-style `for` scan skips quoted text, `lune ... --help` passes, `perl -E 'sleep 5 while 1'` is refused, and the refusal suggests wrapping the command's own text, quotes and all. consequences: one case per form (in the refused and passing tables).
- F8: fixed: the survivor case looks at the first or second poll (about 0.3 s), well inside the watchdog's 2 s grace, so the mutant dies on any load; the runner resets `SIGCHLD` to its default (a case runs it under an ignored one and expects 7); a runner whose starter died exits 123, distinct from 129 for a HUP. consequences: Design, usage text and AC1 say 123; the mutant for the parent watch is killed.
- F9: fixed: the Rules row says what it means, step 1 says 18 cases, the runner is "about 150 lines"; the "only lower" test is one shell function, `z-nile/lib/cpu.sh` (`zn_lower_cpu`), sourced by `zn`, both hook scripts, the jail's shell and `bounded.pl`; the `zn` row is `run` (the stand-in `ulimit` kills the unconditional mutant of the default; the lower-only mutant is equivalent for the kernel and covered by the runner and engine cases); the regression sweep was rerun today with `c0114/layout` and `c0120/gate-homes` added: 86 passed, after which the jail's shell was changed to skip a missing `cpu.sh` so the old specs that copy the runner by a fixed list keep passing. consequences: `cpu.sh` is a touched module and a fixture file of three specs; a fixture runner without it runs without the limit.
