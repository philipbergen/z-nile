### F1 [high] The sweep passes a case that never runs its scanner: every raise is swallowed, and the spec pins that as a pass
Where: `prototype.patch` `hostile.luau` driver (`pcall(c[2], text)`) and `finishes`; `acceptance/finishes.spec.luau` "passes scanners … including one that refuses by raising" (`REFUSES` raises on every text); `acceptance/scanners.spec.luau`; `acceptance/tree.spec.luau` raftcheck case; AC3, AC7.
Evidence: in the clone I set two of the six real cases so they never reach their scanner: `call = "m.stripCommentz(text)"` (a typo) and `call = "m.oldNames(nil)"` (a wrong argument). Then I ran `lune run tests/run -- .tracker/issues/c0193/acceptance/scanners.spec.luau` and got `3 passed, 0 failed` in 1.2 s. Each case raised on all 22,765 texts, `pcall` swallowed every raise, and the driver printed `done`. The same hole hits the incident's own scanner. `raftcheck.judge(text, rendered)` (origin/impl-c0117, `raftcheck.luau:83-89`) returns `"its RC0 lines are not the raft template's"` unless `text` starts with the rendered RC0 head. So a case `m.judge(text, rendered)` returns early on every hostile text and never reaches `word()`. The tree.spec conditional case only asks that a case named `raftcheck.judge` exists. The design's claim that this case "is the sweep that would have caught the incident (E1)" holds only if the case puts the head and `check "RC1: ` before each text, and no spec requires that. E1 ran with such a prefix; the design never names it.
Critique: AC7 ("every text scanner … finishes on every hostile text") passes when a scanner is never run: a typo, a renamed function, a changed signature or a guard that returns early. "Refusing is closing" is right for one text. For every text it means the sweep tested nothing. The tempting fix is to fail a case that raises on every text. But the sequestered `REFUSES` fixture raises on every text and is required to pass, so the spec has to change too. And that fix still misses the early-return shape (raftcheck without its head).
Consequences: the driver has to count, for each case, the texts that returned without raising, and report them. `REFUSES` has to refuse only some texts. A case needs a way to get past its scanner's entry guard, which means a new field and a rule for it.
Recommendation: (1) The driver writes `ran\t<case>\t<returned>\t<first error>` per case, and `finishes` fails a case that returned on no text, with `<case>: raised on every text, so the sweep never ran it: <first error>`. Add a Rules row and a finishes.spec case: a fixture that raises on every text fails, and the mutant "count ignored" must fail that case. Change `REFUSES` to refuse only texts that contain a backslash, which keeps "refusing is closing" pinned. (2) Add `prefix: string?` to `Case`. The driver feeds `prefix .. text`, and scanners.texts' needles become per-case prefixes or stay shared. Strengthen tree.spec's conditional raftcheck case: the `raftcheck.judge` case's `prefix` starts with `raftcheck.head(<rendered template>)` and ends with `check "RC1: `. That is a plain data assertion, and it is the shape E1 proved catches the spin. (3) Say in the Design that a case must reach its scanner's loop, and why.
Lesson: zz-test/no-vacuous-pass

### F2 [high] `hostile.bounded` has no limit at all when given less than one second (and none at 0)
Where: `prototype.patch` `hostile.luau` `BOUND` (`alarm $t`), `hostile.bounded(seconds: number, …)`, `hostile.finishes(…, seconds?)`; AC3.
Evidence: perl's `alarm` truncates to whole seconds, and `alarm 0` cancels the alarm. I ran the prototype's exact wrapper on `perl -e 'sleep 3'` under an outer 10 s bound: `seconds=0.5 exit=0 took=3s`, `seconds=0 exit=0 took=3s`, `seconds=1 exit=124 took=1s`. A limit under one second leaves no limit, so a spinning scanner runs until something else kills it. The runner has no per-spec timeout (`grep -nE 'timeout|alarm|kill' z-nile/tests/run.luau`: no hits). Both `seconds` parameters are typed `number`, and the spec writer the zz-test bullet addresses ("runs it in a child with a limit") may well pick `0.5` to keep a fixture fast.
Critique: a guard that fails open on a legal argument breaks zz-arch rule 7, and this guard exists to prevent the 14-hour, 100%-CPU incident. No spec case tries a limit other than 2, 4 or 10, so a wrong implementation passes AC3.
Consequences: refusing values brings a rule ("a limit is a whole number of seconds, at least 1"). Rounding up would quietly change the caller's limit.
Recommendation: `bounded` (and therefore `finishes`) raises unless `seconds` is a whole number ≥ 1, `hostile.bounded: the limit must be a whole number of seconds, 1 or more`, naming the value. Add a finishes.spec case that `bounded(0.5, …)`, `bounded(0, …)` and `bounded(-1, …)` raise without starting anything (assert that before any child would run). Add the mutant "the check removed" to Rules and mutants. Mention the rule in the zz-test bullet.

### F3 [medium] The bounded child outlives its wrapper whenever the wrapper itself is signalled, and a signal death reads as exit 0
Where: `prototype.patch` `BOUND`; Design "Guards" ("no process outlives the call"); Maintainability (c0191 "should use" its runner in place of this one); AC3.
Evidence: the child calls `setpgrp(0, 0)`, so it leaves the caller's process group. The wrapper kills that group only from its own alarm handler or after `waitpid`. I ran the prototype's wrapper with limit 10 on `perl -e 'sleep 8'` and sent the wrapper TERM, INT and HUP in turn. Each time the wrapper died (status 15, 2, 1) and the child was still `ALIVE` 0.3 s later (I killed it). A Ctrl-C, a closed terminal or a parent's TERM therefore orphans a sweep that may be spinning, and its alarm has died with the wrapper. On macOS inside `tests/run`, the jail's sweeper (`fence.SWEEPER`, which ignores INT, TERM and HUP and sweeps afterwards) catches it. There is no jail on Linux ("no jail on $^O"), nor for a run that can't be jailed, nor for a direct call. Separately, `exit($st >> 8)` turns a signal death into 0: a child that killed itself with signal 9 made the wrapper exit 0. `fence.SWEEPER` already has the correct form, `$st & 127 ? 128 + ($st & 127) : $st >> 8`.
Critique: the design sells `bounded` as the fixed model for c0191 (E11's "For c0191"), but it lacks two things c0191's capture requires: stopping "when its parent dies" and a CPU-time limit (`ulimit -t`) that "still applies after the child is orphaned". If c0191 adopts this helper, the gap ships twice.
Consequences: signal handlers in the wrapper cover TERM, INT and HUP, but not SIGKILL. Only a limit the kernel enforces covers a SIGKILLed or vanished wrapper.
Recommendation: (1) The wrapper traps INT, TERM, HUP and PIPE and kills the group with SIGKILL before it exits (128+n). (2) The child sets a CPU limit before it execs (`exec "/bin/sh", "-c", 'ulimit -t "$0"; exec "$@"', $t + 1, @ARGV` or equivalent), so an orphan spinning at 100% dies within about `seconds` of CPU whatever happened above it. (3) Return 128+n for a signal death. Add finishes.spec cases: the wrapper sent TERM leaves no grandchild, and a command killed by a signal returns 128+n. Use `sleep`-style children, not spinners, and a short `ulimit` in the fixture. Add their mutants as rows. Tell c0191's prep that this is the helper to reuse or replace. Two bounded runners must not drift apart.

### F4 [medium] The lint "proves" loops that can spin: another write to the variable, a bound that grows, or an `end` with a trailing comment
Where: Design "What 'proven' means"; `prototype.patch` `loops.find`; AC4.
Evidence: with the prototype's `loops.find` in the clone, each of these is `advances = true`:
- `while i <= n do / i = 1 / i += 1 / end` (reset every pass).
- `while i <= n do / i += 1 / if x then / i -= 1 / end / end` (stepped back inside an `if`).
- `while i <= n do / i += 1 / while true do / i = 1 / break / end / end` (reset by an inner loop).
- `while i <= #q do / table.insert(q, q[i]) / i += 1 / end` (the bound grows as fast as the step).
- `while i < math.huge do / i += 1 / end`.
The fifth shape is a mis-ended body. In `local function f() / while i <= n do / i = nextOf(i) / end -- x / end / local function g() / while i <= m do / i += 1 / end / end`, the loop in `f` is proven. Its `end -- x` is not `ind .. "end"`, so the body runs on into `g` and takes `g`'s `i += 1` as `f`'s step. On the real tree, `z-nile/tests/lib/cleanup.luau:32` (`while head <= #queue and #out < MAX_LISTED do`, a BFS whose queue grows) is proven, though it ends only because the tree is finite and `#out` is capped. The design itself says "a bound that moves away as fast (a queue that grows by the same step) is the list's to argue", but such a loop is proven, so it never reaches the list or a reviewer.
Critique: "unproven means on the list, never wrong" only works if "proven" is sound. Every false proof is a loop that skips the reviewed list, and the list was the reason for the lint. The tempting fix, rejecting any other line that names `V`, would also reject reads of `V`.
Consequences: a tighter proof lists more loops: cleanup's BFS, and any loop that writes its bound. The 26-entry count (E3) changes and the executor's seed needs entries for them. Real loops that index with `V` but never assign it must stay proven.
Recommendation: proven also requires (a) no other assignment to `V` anywhere in the body, at any depth (`^%s*V%s*[-+]?=`, or `V` on the left of a multiple assignment), and (b) a bound that is a literal, or a plain name or `#name` that the body never writes (`name =`, `name[`, `table.insert(name`, `table.remove(name`); any other bound is unproven. `math.huge` and calls count as other bounds. Find the end structurally: the first line at indentation ≤ `ind` must be `end` or `until` (a trailing `-- comment` allowed), otherwise the end is not found and the loop is unproven. Add a loops.spec case for each shape above. The `cleanup.luau` BFS joins the list with its reason. Record the new E3 counts.

### F6 [medium] The hostile alphabet misses characters the swept scanners branch on, and a promoted spec pins its size
Where: Design `hostile.ALPHABET` (12 characters); `acceptance/texts.spec.luau` "the default is every text of up to 4 of the 12 hostile characters, 22621 of them"; E5 and Scalability ("70,161 texts").
Evidence: one-character comparisons in the swept modules, from `grep -oE "== ['\"](\\\\.|[^'\"\\\\])['\"]" <file> | sort -u`:
- `graph.luau`: `- . [ @ / \ \n` and backquote.
- raftcheck on impl-c0117: space, `\\`, `\n`, `\t`, `#`, backquote and `$`.

`[`, `=` and `]` are missing, and those are what `graph.stripComments`' long-bracket branches (`longClose`, `graph.luau:332-341, 345-348, 366-374`) need: no default text contains `[`, so those branches are never swept. The list entries `while i <= n do` and `while j <= n do` in `graph.luau` name `graph.stripComments` as their sweep anyway. `\t` is missing too, and raftcheck's `word()` and `judge` branch on it. E5's 70,161 texts equals 1+16+16²+16³+16⁴ (69,905) plus 256 needle texts, so it looks like a 16-character alphabet was measured at 1.5 s and then cut to 12.
Critique: "the characters that make scanners branch" is claimed and never checked. And texts.spec pins `#ALPHABET == 12` and the total 22621 in a spec that is promoted at `done`. The natural next step, adding a character, then turns the gate red and needs an override chore.
Consequences: a bigger alphabet costs CPU (16 characters: about 70k texts, within `MAX_TEXTS`, about 1.5 s by E5). Per-case extra characters keep the base small, but each `Case` gains a field.
Recommendation: add `[`, `]`, `=` and `\t` to the base alphabet (16), or give `Case` a `chars` field that the driver adds to the base for that case. Then add a scanners.spec case: every one-character string literal compared in a case's module (the grep above, done in Luau over the module's text) is in that case's alphabet, apart from an explicit, reasoned exception list for each case. texts.spec pins the rule, not the set: the incident's characters are in the alphabet, and `#texts == Σ #A^k` for the alphabet given, with no literal 12 or 22621.
Lesson: zz-test/promoted-specs-pin-rules-not-sets
