# c0259: z-nile README describes the target workflow

## Problem
`z-nile/README.md` maps today's parts and pipeline but not the workflow wanted: an engineer end (any AI CLI: capture, sharpen, review designs) and a worker end (any AI CLI, same or another host, wrapped by `./zn work`) sharing only `origin/main`; ranked tickets; autonomous implement, review, test and merge; reviews by different models with same-family as the fallback; a formal escalation (`blocked`, `escalation.md`, `./zn resolve`); and a raft delivered as a stacked PR set (c0248 to c0254).

What should happen: a "How it should work" section, with a diagram, a roadmap table and status labels (exists, designed, new), so the README never claims what is not built. The draft is written (branch `docs-znile-vision`, uncommitted at capture time).

## Non-goals
- Building any of the described features (c0248 to c0254).
- Rewriting the parts that already describe what exists.

## Solution
- A "How it should work" section before "The five parts", a roadmap table and status labels.
(Added in prep, after the captured text.)
- The text is written: `experiments/README.draft.md` in this folder is the whole new `z-nile/README.md`. The executor copies it over `z-nile/README.md` and changes nothing else in the repository; the roadmap's ids are the tickets c0248 to c0254 and c0258, which exist on `main`.
- c0259 owns the README edit. c0248's Problem line "the README edit ... rides in this layer" is superseded: c0248 does not touch the README (a draft's text is not edited by a prep).

## Design

**States** (the legend names *captured* as this section's word for an issue that exists as a draft, each state defined by a tracker fact): *exists* (done, on `main`), *designed* (`design: ready`: prepared, rafted or active), *captured* (a draft issue, no design). The two id-less labels are the engineer end and the claim itself, which exist today.

Rules the text states: a worker end `./zn work` over c0117's dispatcher (*captured*, c0253); `rank:` with `depends_on` as the hard constraint, distinct from `.models.toml`'s `rank` (c0249); the claim as the push to `origin/main` (c0254); merge by the dispatcher (c0252); review by another model family with same-family as the fallback that never blocks (c0251); escalation by `blocked`, six reasons, `escalation.md` and `./zn resolve` with five decisions (c0250); a raft delivered as a stacked PR set, bottom-up, a stack of one (c0248); `./zn land` usage and cheap retry (c0258).
