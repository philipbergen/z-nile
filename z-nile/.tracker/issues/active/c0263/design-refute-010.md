# Answers to design review 010 (round 3 of the split re-prep): c0263

Two highs, three mediums, one low. Round 3 had highs, so z-design's rule allows round 4 (design-review-011); the coordinator decided the two questions (remap; the merge mechanism) and every finding is fixed, with the prototype (`proto-c0263-raft` at e4f0efec, pushed to origin), the specs and the document changed together.

- F1: fixed. A stale record is removed with `git rm -q -f --ignore-unmatch` (no `--cached`, no unlink), which removes the folder it empties. record.spec's UA, DU and UD cases (and the cross-item one) now read the disk the way the engine does: no other folder of the item exists in any state folder, and `./zn find <id>` names the one folder. Mutants: `merge: stale old path kept`, `merge: stale record unlinked, folder kept`, `merge: record written at the old path`.
- F2: fixed, with the mechanism the reviewer recommended. `mergeRef` merges with `--no-commit`, takes the ids of every `*/provenance.md` either side changed since the merge base (`git diff --name-only --no-renames`, old and new paths, plus the unmerged ones), reads each id's record from HEAD, the merge and the base by id, and `provenance.settle` (pure, with its own case) decides: unchanged on one side, the other side's version; changed on both, `union`; changed on one side and absent on the other, or a side that did not only append, stop naming the id and `./zn remap`. The body runs in a `pcall` that aborts the merge. Same id, different path still unites (folder moves); the smaller "abort on any path difference" option was not taken. record.spec has the reviewer's cases (i) main renumbers an item both sides appended to, (ii) a record we added in a folder main renumbered (the missing document is named), (iii) git pairing our row with another item's near-identical record (rows written through a second clone with fixed `when`s), (iv) our side renumbers; and the mutants `merge: examines only unmerged ids`, `merge: a clean merge skips the records`, `merge: a record changed on one side and absent on the other is taken as one-sided`. Consequences: two `git diff --name-only` per merge (cheap), the merge commit is made by `git commit --no-edit` with git's prepared message, a renumber on either side is a stop with a clear message (Limit in Behaviour 5), a compaction is the same stop and `./zn remap` is the way through.
- F3: fixed. `remap` unites records: when `git merge-tree`'s only conflicts are `provenance.md` files, the three stages' blobs (from the conflicted-file info) are united into the tree it commits (`uniteRemapRecords`), with `remap.spec` (the c0081 remap fixture plus a record both sides appended) and the mutant `remap skips the union`. The Open point, "(b) until the user decides", Limit (2) and the zz-rules sentence are gone; the premise is reworded (the outcome is the Scope decision's union of two writers, not a captured list of merges).
- F4: fixed. Cases: main deletes the item's folder while ours appended; a commit holding the item's record in two places; a merge holding the document in two places (the missing-document stop is case (ii)); mutants `merge: ignores locate refusal` and `merge: no-document stop removed`.
- F5: fixed. The docs case pins "unites a `provenance.md` both sides appended", a phrase only the new Phase 5 step 2 has; the docs row is `run` with the mutant `docs: zz-execute step 2 reverted`.
- F6: fixed. Counts (6/3/22/8), the Solution's session variables, step 1's `--3way`, E5's bounded probe, the list of commands that merge for you in zz-rules, E16 on the new prototype's tip, the Test plan.
