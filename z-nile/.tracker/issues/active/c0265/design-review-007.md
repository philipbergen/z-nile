### F1 [high] lost.spec's board case cannot pass: `lost 45m` is never written in the page the Design describes, and c0010's silence is 44 minutes anyway
Where: lost.spec:183-194 (`t.expect(has(html, "lost 45m")).toBe(true) -- c0010: silent 2700 s since its beat at T0`); Design, The board ("`board.collect` puts `heartbeat` … and `minutes` on each item … the page shows a `lost 45m` … badge"); Design, Kinds (`last = max(claim.since, newest beat …)`, `since` = the claim commit's `%ct`); engine/board.html:110-113 (rows and badges are built in the browser: `function badge(s) { return … '<span class="badge s-' + esc(s) + '">' … }`, called from `idLink`/the list renderer on the JSON model); board.luau `render` (the file is the template plus `board.encode(m)`).
Evidence:
- The written file holds the model as JSON (`"heartbeat":"lost","minutes":…`) and the template's JavaScript. Every badge today is text the browser builds at load (`badge(it.stage)`). An executor who follows the Design (two fields on the model, a badge "beside the id") writes `'lost ' + it.minutes + 'm'` in the template. Then the string `lost 45m` is in no byte of `.cache/board-lost.html`, and `has(html, "lost 45m")` is false for a correct implementation.
- Even with the label computed in Luau, the number is wrong. The beat is dated `ZN_NOW = T0`, while `since` is the claim commit's real time, which is later. My probe of lost.spec's own setup measured `claim_ct − T0 = 3`, so `silent = LATE − since = 2697` and `floor(2697/60) = 44`. The `lost` command floors ("minutes floored"), and the board has no other rule. The comment's "since its beat at T0" overlooks the `max` with `since`. The delta is at least the time `fakecli.new` and two `./zn worktree` calls take, so it is never 0.
Critique: the case was written without running it against a prototype of the board's existing render path. board.luau and board.html exist, so a ten-line scratch edit would have shown both problems. Two fixes are tempting: change the literal to `lost 44m`, which is flaky because delta can cross a minute boundary on a slow host, or move the badge into Luau just to satisfy the grep.
Consequences: the case must assert on what the Design fixes, the model, and the expected minutes must come from the same clock the rule uses. Asserting `"minutes":45` has the same delta problem, so the expected value has to be derived: read `since` with the same `git log -1 --format=%ct -S…` on origin, or put the claim's beat after `since` (claim at T0, then `beat c0010` from the main checkout at `T0 + 60`, so `last = T0+60` and the minutes are exact).
Recommendation: in lost.spec, assert on the encoded model. Decode the JSON between the template's DATA markers, or match `"heartbeat":"lost"` and `"minutes":<expected>` on c0010's item, with `<expected> = floor((LATE − last)/60)`, where `last` comes from an explicit beat newer than `since` (or from `since` read off origin). State in the Design that the badge text is rendered by board.html from `heartbeat`/`minutes` (one format, one writer), so the executor does not have to pick. Replay the case on a scratch edit of `board.collect` before the prep commit.
Lesson: zz-arch/clock-before-subprocess, z-design/prove-specs-pass-on-a-prototype
