### F2 [medium] "A protected checkout reads no remote" is pinned for `status`, `lost` and the board, but not for the autobeat or the explicit `beat`. beat.spec's protected case counts neither fetches nor ls-remote, so a fetch made before the guard survives
Where: Design, Automatic beats ("Never from a protected checkout … a nested `./zn lessons` in a `check.sh` or spec flow of the real repository never fetches or pushes"); `./zn beat` ("fetches `origin main` first …") against Guarded checkouts ("run `publishing()` … and refuse"), which never says which comes first; beat.spec:189-212 (asserts only `#beats()` and the entry's text); Rules row "a nested `./zn` in a protected checkout never beats …" (mutants: autobeat not asking `guarded()`, advancing the entry, `beat` not refusing).
Evidence: the autobeat must compare "origin's stamp for the id" with each entry, and the natural way to read it is a fetch. Take an implementation that fetches first and asks `guarded(true)` only before the push. It leaves no beat and does not touch the entry, so it passes beat.spec. Likewise, a `beat` that fetches (as its paragraph says it does "first") and only then calls `publishing()` still prints "protected" and passes. In the real flow, that implementation fetches the real origin from every nested `./zn` that a `check.sh` runs inside an agent's worktree holding entries (the common case: `./zn check <id>` in a prep worktree). That is the remote read round 10 F1 ruled out, and a ref update the fence refuses in the real repository. Round 10 fixed this mechanism one command at a time (status, lost). The same hole is open in the other two paths.
Critique: the tempting fix is a sentence ("beat asks `publishing()` before its fetch"). Without a counter, nothing pins it.
Consequences: one rule for every heartbeat path ("ask `guarded(true)` before the first network call") replaces per-command orderings, and the counters must cover fetch, ls-remote and push. The explicit `beat`'s refusal text stays `publishing()`'s.
Recommendation: state once, in Automatic beats, that every heartbeat path (autobeat, outer-command tick, explicit `beat`, `--watch`, `status`/`lost`/board verdicts) asks `guarded(true)` before its first fetch, ls-remote or `gh` call, and that `beat` asks `publishing()` before its fetch. Give beat.spec lost.spec's counting shim (fetch and ls-remote) and assert both counts unchanged across the guarded `lessons` and the guarded `beat`. Add "a fetch before the guard" to the Rules row's mutants.
