### F2 [medium] `stop` records `unjudged` for a live raft whenever `gh` fails while any other claim is stale, so the owner's own keep path is refused for good
Where: prototype main.luau:5599-5609 (`if okJudge and not (judged :: Judged).beatsError and not (judged :: Judged).prsError then`); `judgeAll` main.luau:1604-1632 (the pull requests are read when any claim in the repository is stale); heartbeat.luau:127-137 (`settle` changes only `stale` verdicts); Design, the `stop` bullet ("`(claim <stamp>, unjudged)` when nothing could be read or the claim never beat").
Evidence: PROBE C. A worktree holding R0011 beats it at AT+100, and c0020 (claimed at T0, never beaten) is stale. With `gh pr list` failing, the main checkout's `stop R0011` at AT+110 writes `tracker: stop R0011 Gh (claim active-indigo-heron-mongoose, unjudged)`. After `ready`, the owner's plain `--adopt` exits 1 with `R0011's claim was taken over (now active-silver-walrus-quiet)`.
Critique: A live verdict is read from the beats alone. The pull requests only settle stale verdicts into lost or parked, so a PR error leaves a live verdict exact. Discarding every verdict on a PR error turns a readable live claim into `unjudged`. A stale claim is almost always somewhere in this repository: every prep whose PR is open and that no one beats reads stale before it is settled. So a gh flake at the owner's stop (rate limit, expired auth, network) strands its worktree, and it must move to c0277's numbered copy. This fails closed, so it is no authority hole, but it costs the user's decided keep path for no reason. A retry of `gh` still strands the owner on a real outage.
Consequences: An unsettled verdict is never `lost` or `parked`, so using it is safe. A stale claim stays `unjudged`, which is right: lost and parked cannot be told apart without the pull requests. Moving the choice into the pure module pins it without a fixture.
Recommendation: Move the choice into heartbeat (for example `heartbeat.stopNote` taking the raft's verdict, or nil, and whether the beats were read). Use the raft's verdict whenever the beats were read, whatever `prsError` says, and write `unjudged` only for unreadable beats, a pcall failure, no verdict for the stamp, or a stale, nobeat or unknown verdict. plan.spec cases:
- a live verdict with a PR error gives `(claim S)`;
- a stale verdict with a PR error gives `(claim S, unjudged)`;
- unreadable beats give `unjudged`.

Add a row for the mutant "a PR error discards every verdict".
