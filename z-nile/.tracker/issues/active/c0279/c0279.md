# c0279: Dispatch stop spec waits on wall clock

## Problem
The promoted spec z-nile/tests/acceptance/c0117/dispatch-cli.spec.luau case 'dispatch stop kills the running step's group, and retry reruns the same step' fails on main whenever the machine is loaded (line 692, expected true, got false: absentAfter(<fakes>/grandchild-stop, 3) gives the killed step's grandchild 3 wall-clock seconds to disappear), so the full gate goes red and every ./zn land refuses: it failed two of three split-capture lands on 2026-11-08 and c0263's gate, with control-cli taking 905 s against 329 s unloaded, while it passes on an idle machine. Make the case prove the kill without a wall-clock wait (or a bound that holds under load), as the user's standing rule that promoted specs wait for nothing requires; nothing else in c0117's dispatcher changes. Scope decision (user, 2026-11-08): "Capture it now". Scope decision (user, 2026-11-08): "Yes, every load-sensitive case in that file": c0279 covers every case of z-nile/tests/acceptance/c0117/dispatch-cli.spec.luau that the load runs show failing under load (at least "dispatch stop kills the running step's group, and retry reruns the same step" and "an agent's git and gh refuse a code push to main and a merge, before the real gh runs"), so one raft clears the gate. (Only the words in the first quotation marks are the user's; the rest of the line is the coordinator's relay of the decision.) Scope decision (user, 2026-11-08): "Widen them to 10 s". The question was "What should happen to those two [stall-testing cases]?" and the option read: "Their stall limit goes to 10 s (tool limit 30 s), so starvation can't trip them. Costs about 33 s more per run of that file, plus one more review round for c0279 before it merges."

## Non-goals
- No change to the dispatcher (`z-nile/engine/`), the supervisor, the wrapper or any `stall_seconds` default: the cases and their fakes are wrong, not the code they test. The prototype needs no engine change.
- No new wall-clock wait in the kill proofs: a wall-clock bound that only a kill that never comes is expected to reach (60 s) is the only kind they add. The stall cases do wait longer, by the user's decision ("Widen them to 10 s": about +33 s per run of the file).
- `control-cli.spec.luau`'s `absentAfter(grandchild-orphan, 5)` has the same shape but is another file: out of the user's scope decision (E5).

## Solution
(captured idea: make the case prove the kill without a wall-clock wait, or with a bound that holds under load.) The load runs (E1) show three cases of `dispatch-cli.spec.luau` failing, all on one cause: the spec's `[dispatch] stall_seconds = 2` is the dispatcher's silence limit, and a fake CLI that does slow work quietly (a `./zn dispatch stop`, a `git commit`/`push`, a `gh`, or only starting up) is killed as `stalled` on a loaded machine; the stop case also waited 3 s for a file its grandchild would touch after 2 s. Two changes, in the spec and its fake (`z-nile/tests/lib/fakecli.luau`):
1. **A stall limit only a real stall reaches.** The spec's root `.models.toml` gets `stall_seconds = 120`, `tool_seconds = 240`; the one issue whose cases test a stall (c0040) gets a closer `.models.toml` with `stall_seconds = 10`, `tool_seconds = 30` (the user's decision, "Widen them to 10 s": a starved dispatcher or fake does not reach 10 s, and the stall fakes stay silent for 20 s, the quiet tool call for 12 s). Every other case ends by its own signal (a quota, a cap, an exit, a stop) and stalls only if it really does.
2. **A kill proved by the process's death.** The `stop` and `cap` fakes start a grandchild that writes its pid and `exec sleep 3600`, and wait (bounded, 60 s) for the pid file before the action. The cases replace `absentAfter(<file>, 3)` with `deadWithin(<pid>, 60)`: a poll of `kill -0` that returns the moment the process is gone ("No such process") and runs long only if the kill never comes (its bound, 60 s, is on the wall clock). After the stop the stop fake goes silent and holds (an hour), so a stop that kills nothing leaves the step to the 120 s stall limit instead of an exit that would look like a stop (M8, M8b).
`FAKE_DELAY` (seconds, default 0) makes every CLI fake slow before its first output and the stop and the push slow inside the step (before `./zn dispatch stop`, before `git push`, before `gh`): only a `check.sh` sets it, to simulate a loaded machine while the promoted spec waits for nothing.

**Changes** (all in `z-nile/tests/`):
- `lib/fakecli.luau`, `script()` modes: (a) `stop)` = `echo '{"type":"system"}'`, `sh -c 'echo $$ > "$FAKE_DIR/grandchild-stop.pid"; exec sleep 3600' &`, a wait of at most 60 s for that file, `sleep ${FAKE_DELAY:-0}`, `./zn dispatch stop "$FAKE_STOP"` as before, then `sleep 3600` (no output); (b) `cap)` = the same grandchild with `grandchild-cap.pid` and the same wait, then its 20 heavy lines and `sleep 20` as before; (c) `push)` = `sleep ${FAKE_DELAY:-0}` before `git push` and before `gh pr merge`, the rest as before; (d) the script's first command after the shebang is `[ -z "${FAKE_DELAY:-}" ] || sleep "$FAKE_DELAY"` (a builtin test: nothing is spawned when the variable is unset; pinned to this exact text), before any output; (e) `tool)` = the quiet tool call lasts `sleep 12` (was 3), over c0040's 10 s stall limit and under its 30 s tool limit.
- `acceptance/c0117/dispatch-cli.spec.luau`: root `[dispatch] stall_seconds = 120`, `tool_seconds = 240`; fixture `pickman/.tracker/issues/c0040/.models.toml` = `[dispatch]\nstall_seconds = 10\ntool_seconds = 30\n`; `absentAfter` is replaced by `deadWithin(pid: string, seconds: number): boolean` (polls `kill -0` (from PATH) every 0.1 s; true only when its stderr says "No such process", so a permission error or a missing `kill` is no death; false after `seconds` of wall-clock time) and `grandchildPid(name)`; the stop and cap cases call `deadWithin(grandchildPid("grandchild-stop" | "grandchild-cap"), 60)`. The exact diff is `acceptance/dispatch-cli.spec.expected.diff` (84 lines), and the prototype branch `proto-c0279`.

Why this holds under any load: no kill proof waits for a clock to prove anything (the stall cases do wait, by decision, and their margin is 10 s of silence, 7 s under AC2's delay, against 2 s before). The kill proofs end the moment the process is gone (about at once, because the kill has happened before the stop returns) and fail only after a 60 s bound that a kill that never comes reaches; the grandchild's `sleep 3600` is an hour (the runner's sweeper stops what a spec leaves), and the bound is measured on the wall clock (`os.time`), so the polling commands' own cost under load is inside it: no load makes the sleep end inside the bound. The 120 s stall limit is a bound a slow fake will not reach under any load seen here; a stuck one does. No claim in this paragraph rests on the fake's startup being fast (E1b).

`deadWithin` reads a pid that the system reused for another process as alive: a rare false red after 60 s, never a false green; the grandchild's hour-long sleep and the immediate kill make a reuse inside the case's seconds implausible.

### Scalability
The kill proofs add no cost in the common case (they end as soon as the process does); the stall cases cost about +33 s per run of the file (3 x (10 - 2) s for the wait, `prose` and `stall` sub-cases, 12 - 3 s for the tool case), and AC2 (the whole file at `FAKE_DELAY=3`) about 2.5 minutes more per check run than a plain run (352 s against 179 to 228 s under load). A broken kill costs up to 60 s per case, once, where it used to cost 3 s: the price of a bound that load is not expected to reach.
### Maintainability
One rule for the next fake: a fake that has to be quiet while it works belongs to an issue whose stall limit is long; a case that tests a stall says so with its own short limit (c0040, in the fixture and the comment above it). The pid-and-`deadWithin` pattern is the one way this file proves a kill. `FAKE_DELAY` is the one knob that proves load insensitivity.
### Usability
A broken kill fails as `expected true, got false` at the `deadWithin` line (60 s later); a stop that kills nothing fails as `expected "stopped", got "stalled"` (M1, M8).
