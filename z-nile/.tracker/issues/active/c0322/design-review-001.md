### F1 [high] The captured outcome "the note goes elsewhere" has no Design and no criterion, and the Problem that held it was rewritten without a decision line
Where: `c0322.md` Problem (line 18), Solution (line 24), Design "The change" (line 33); capture 27f5aaf22
Evidence: The capture's Problem ends: "Either the bind subject stays the plain one and the note goes elsewhere, or the spec's expectation follows the new subject." The idea commit (3290615a3) replaced that whole Problem with a one-line symptom and wrote the Solution as "with the dispatcher's attempts note kept out of the subject field". "Goes elsewhere" is gone, and there is no `Scope decision` or `Decided with the user` line. The design takes the first branch and puts the note nowhere new. `recordAndCommit` printed `session: <note>` before this change (main.luau:4441-4443, added by #318 together with the subject append) and still does. After the change, the bind reading's per-CLI account is in no durable record. That account is `sessions.combine`'s note (sessions.luau:229-273): which CLIs were unmeasured, the `in=`/`out=` split, AI seconds per CLI. The row keeps only summed tokens, summed AI seconds, one model and the `unmeasured` flags. #318 put the note in the subject on purpose, as its only stored copy. Choosing between the capture's two branches is the design's job. Delivering half of the chosen branch is a narrowing.
Critique: Under "Scope is what was captured", the Problem may only gain detail. The prep's step 5 scope check had to catch the idea-step rewrite. The tempting answer is "it is still printed, so it went elsewhere". But stdout is not a record, and that print was already there before the change, so it moves nothing. The other tempting answer is to quote finish's rows, which keep `finish <note>`. Those rows carry a different reading, taken at each layer's finish, not the reading at done.
Consequences: Giving the note a durable home changes something the Chore checklist says is unchanged. The likely home is the bind commit's trailer block, the only text `recordAndCommit` writes besides the row. Its readers then need checking: `d0333/commit-land.spec` (line 347), `tooling/trace-land.spec` (lines 472-477) and `c0239/done` read the bind message; main.luau:2659 looks for `\nVerdict: approve` in it; `stack.spec` pins `stack.bindMessage` alone, which a trailer added by `recordAndCommit` does not touch. The alternative is a user ruling, which needs the user.
Recommendation: Put the captured Problem sentence back word for word, with today's detail after it. Then either (a) record the bind reading's note durably: one `Session: <note>` line, when a reading is given, at the end of the trailers `recordAndCommit` already writes. Add a criterion and a fast case for it: wiring.spec asserts the trailer is built from `reading.note` once, and the slow AC3 run asserts `git log -1 --format=%B` holds `Session: ` and the subject does not. Run the three bind-message readers above on the prototype, and reword the Chore checklist's "the commit message, its trailers … are as they were". Or (b) escalate to the user: "is the existing `session:` print, plus finish's own `finish <note>` rows, the 'elsewhere' the capture meant, or must done's note be kept?" Record the answer as `Decided with the user (YYYY-MM-DD)` in the Problem. Do not choose (b) without the user.
Lesson: z-design/never-narrow-captured-scope

### F2 [high] The promoted whole-file pin of `c0084/commit-phase.spec` collides with active c0306 and prepared c0325, both of which edit that file, and the design names neither collision
Where: `acceptance/unedited.spec.luau` (case 1, `PIN.sha`); `c0322.md` Chore checklist "Existing work" (line 47), Implementation step 1, AC3

The deliver case's own `tr({ "commit", "-m", "layer b", … })` matches c0325's own grep. "Existing work" does not mention c0306. It says c0325 "and this one's do not overlap, so the three merge in any order", which is true of `main.luau`'s hunks and false of this file. Both landing orders fail:

It is read-only, and it must fail closed when `origin/main` is missing.

- Replace step 1's blob equality with that case-2 check, so c0306 landing does not halt c0322.
- Name c0306 (active, R0107, branch R0107/1/c0306) and c0325 in "Existing work", with the cases each one edits.
- Add a z-raft constraint: c0322 never shares a raft with an item that edits commit-phase.spec, or the base becomes the layer below.
- Add a Rules row for "the branch edits commit-phase.spec (say its `rows` helper strips the note)", killed by the check.sh line.

### F3 [high] Which share gets the reading is unguarded: passing `reading` for `rowReading` double-counts the session's tokens on every member's row, and passing `nil` drops them, while check.sh stays green
Where: `prototype.patch` main.luau hunk (`rowReading` and the `sessions.commitRow(…, rowReading, rowFlags)` call); `acceptance/wiring.spec.luau` case 1; Rules and mutants table; Chore checklist "No behaviour change" (line 45)
Evidence: The refactor moves the guard `if reading and not gaveReading` away from the cells it guarded. The guard now only sets `rowReading`, and the call has to pass that name, not the in-scope `reading`. I ran two mutants on the prototype in a clone:
- X2: the call passes `reading` instead of `rowReading`. bind-subject, wiring and unedited all pass, and `c0084/commit-phase.spec` passes too (the fixture's reading is unmeasured, so its tokens are nil).
- X3: the call passes `nil`. Same result.
For done, `recordAndCommit` gives every member a deliver share (the skip applies only to `build`). Under X2, a three-member raft's bind commit records the whole session's tokens and AI seconds three times in `spend.d`, and three times in the `Issue:` trailers (`shownTokens = rowTokens or share.tokens`), so `./zn metrics` triple-counts. Under X3, the bind row loses its measured cells. The Design states the rule ("the reading … for the one row of the commit that carries it, as today"). The Rules table has no row for it, and the Chore checklist cites bind-subject and wiring as proof that "every other cell of that row" is unchanged. Neither one sees the call's arguments.
Critique: This is a wrong implementation, one identifier away from the right one, that passes every check and regresses cost data. The tempting fix is another text probe in wiring.spec for `rowReading,`. That is brittle, and it still leaves "which row carries the reading" untested as behaviour.
Consequences: Moving the choice into the pure layer means `recordAndCommit` must apply its skip before the call. Every share still folds (`foldHomes`), and the trailers read rows by index. `sessions` cannot require `sessionread` (that would be a cycle), so the reading's flags are passed in. c0325's hunk at the top of `recordAndCommit` (`commitIssues`) does not overlap with this one.
Recommendation: Build all of a commit's rows in one pure call, for example `commitRows(message, when, phase, kept: { { added: number, removed: number } }, model, reading, readingFlags): { ledger.Row }`. The reading and `readingFlags` go on the first row only. Every other row gets no reading and `tokens,wall,cpu,ai`. Add a fast case: two shares and a measured reading give row 1 the reading's tokens, AI seconds, model and flags, and row 2 nil tokens, nil AI, the caller's model and `tokens,wall,cpu,ai`; no reading gives every row the bare cells. wiring.spec asserts the single call passes `reading` and `sessionread.flags(reading)`. Add Rules rows for "every row gets the reading" (X2) and "no row gets it" (X3), and run them. At the least, if the per-share call stays, wiring.spec must pin that the call passes `rowReading` and that `rowReading = reading` appears exactly once, inside `if reading and not gaveReading then`, with both mutants run.
Lesson: zz-test/pin-call-site-arguments

### F4 [medium] The fast guard on the subject rule has a hole on the CLI side: folding the note into the message passed to the builder is caught only by the slow AC3 run, which no gate repeats
Where: `acceptance/wiring.spec.luau` case 1; Regression guard (line 317), "from now on a gate sees this rule"
Evidence: X1: the call's first argument becomes `if rowReading then (string.match(message, "^[^\n]*") or message) .. " " .. rowReading.note else message`. The word `subject` never appears, and `reading.note`, the print and `sessionread.flags(reading)` are all still there, so wiring.spec passes and bind-subject passes (the builder is right). Only `c0084/commit-phase.spec` killed it in my run. That spec is slow-tier, and once c0322 is done no gate runs it. So the regression that went red unseen once can go red unseen again, through the CLI rather than the builder. The design's reason for a pure builder ("leaves the rule with only a slow-tier spec, which is how it went red unseen") holds only for the builder half.
Critique: wiring.spec looks only for the word `subject`. A mutant that never names the subject passes it.
Consequences: Tighter text pins in wiring.spec bind future edits of `recordAndCommit`. c0325's planned hunk adds neither `.note` nor a new first argument, so it is unaffected.
Recommendation: In wiring.spec, assert that the builder's first argument is `message` itself (the call text, for example `commitRow(\n\t\t\tmessage,`, or `commitRows(message,` under F3), and that `.note` appears exactly once in the function's code, in the `session:` print. Add Rules row X1, run it, and record that it is killed by wiring.spec.
Lesson: zz-test/one-mutant-per-wiring-point

### F6 [low] The spend-row builder goes into the transcript reader's module
Where: Design "The change" (line 33); `prototype.patch` sessions.luau hunk
Evidence: zz-arch says each engine module other than `main.luau` is one concern. `sessions.luau`'s header defines its concern as "What a CLI transcript holds for one span … Pure over the transcript text". The prototype adds a function that builds a `ledger.Row` from a commit, along with a new `sessions → ledger` edge, and leaves the header unchanged.
Critique: The next reader looking for where commit rows are built looks in `ledger`, `spend` or `costrow`, not in the transcript parser.
Consequences: Placing it in `ledger.luau` with a structural reading parameter (`{ tokens: number?, ai: number?, model: string? }?`, which `sessions.Read` satisfies) adds no edge. The spec then requires `ledger` rather than `sessions`.
Recommendation: Put the builder (or F3's `commitRows`) in `ledger.luau` with the structural parameter. Or keep it in `sessions.luau` and rewrite the module header to name both concerns. Change the Touched modules list and the bind-subject require to match.
