# c0374: Finished spec reads homes right

## Problem
- On main's slow tier, `z-nile/tests/acceptance/c0120/finished.spec.luau` fails with 10 hits, all `./zn (from z-nile)`, because it reads quoted text that done c0264 passes to its `vocabulary` helper and done d0333 passes to `cases` and `check` as paths.

## Non-goals
- The spec's rule stays as it is (a path resolves from its home or was already missing before the move): no Touched-entry rule, no `cd "$ZN_ROOT"` handling, and no dependency on c0371's scanner.

## Solution
- `finished.spec.luau` stops reading quoted text passed to a check's own helper as a path, so it passes on main's slow tier, and it still fails on a finished `check.sh` path that neither resolves from its home nor was missing before the move.

**The change** (one file, `z-nile/tests/acceptance/c0120/finished.spec.luau`: exactly `experiments/prototype.patch`, +76 lines and 2 lines changed, byte for byte; AC2 pins the whole file as its merge base plus these two hunks, so the executor applies the patch and does not write it by hand). Nothing else changes: not `rewrites.luau`, not the case's rule, no other case.
1. A local helper `singleQuoted(text)` before the spec's `return t.spec(…)` line. It walks the text byte by byte and returns `mask[line][column] = true` for every byte inside single quotes (lines split at `"\n"` and columns are bytes in the line, the same coordinates as `Literal.line` and `Literal.first`), or `nil` when the text ends inside a quote or a `$(`. The walk keeps a stack of contexts: `normal`, `double`, `single`, `paren` (a `$(`, closed by `)`). In `single` only `'` ends it (a backslash is no escape there). Elsewhere: a backslash skips the next byte; `'` opens `single` unless the context is `double`; `"` opens or closes `double`; `$(` pushes `paren`, `)` pops it; `#` after whitespace or `;|&(` outside `double` ignores the rest of the line. So `'"'"'` (close, a quoted quote, open), an escaped quote, a comment with an apostrophe, and the quotes inside a `$( )` are read as the shell reads them (lessons zz-test/shell-readers-carry-state-across-lines, measure-hand-written-readers-on-the-corpus: E1). **Known edges** (design review 001 F4): a heredoc body, `$'…'`, a backtick inside double quotes, `\$(` and a `case` pattern's `)` are not modelled. A file where one of them leaves a quote open is reported (rule 3); one where the misreading balances is read wrongly and silently (a heredoc body such as `we don't` / `test -x zn` / `it's done` masks the `zn` between the apostrophes: pinned by the heredoc case of AC1, so a later change to this shows). 53 of the 418 `check.sh` files in the tracker contain a heredoc, and E6 shows the walk reads all 418 as balanced.
2. The loop in the last case reads the file once and calls `singleQuoted`. A literal is a **message** (not checked) when the mask is known, its `path` has no `/` (a file or folder named alone: `./zn` becomes `zn`, `AGENTS.md`) and its first byte is in the mask. Every other literal is judged exactly as before: `not world.now(from/path) and world.before(dir .. path)` is a finding.
3. **Guess (prep) G2.** A file whose walk returns `nil` adds a finding `<file>: its quotes do not balance, so single-quoted text is unknown`, and its literals are all judged as before (the case fails closed).

**What the spec keeps.** The rule (a path resolves from its home, or was already missing before the move) is untouched (Non-goals): `tests/gone.luau` and `src/nowhere/x`, missing before the move, stay allowed; an unquoted `zn` or `./zn` (also after single-quoted text on the same line, and in `"$(./zn find …)"`), and a path with a folder inside single quotes (`bash -c 'test -f src/server'`), still fail the case: the Solution's "still fails on a finished `check.sh` path that neither resolves from its home nor was missing before the move" (the unquoted, folder and unbalanced cases of AC1).

**Why bare names only (Guess (prep) G1, kept after design review 001 F1 as G4).** The capture says "quoted text a check passes to its own helper". The spec cannot tell a check's own helper from `bash -c` (c0371's hit is the second), and c0371's hit is single-quoted text too. Skipping bare names in single quotes is the scanner's own rule for double quotes ("a file named alone is a path only outside double quotes: in quotes it is a message, a case's name or a grep pattern", `rewrites.luau`) extended to single quotes, and it loses the least checking: a path with a folder in single quotes is still read. What it does lose (E6, review F1): besides the 11 hits it masks 5 literals in finished files that resolve today and stay unreported if they go stale: `default.project.json` and `lobby.project.json` in the `bash -c 'git diff … -- …'` pathspecs of `pickman` R0032 (line 18) and R0037 (line 14), and `./zn` in c0115's `bash -c '… cd .. && ./zn busy …'` (line 68); and any later stale bare root file inside single quotes. A folder path inside a helper's single-quoted message (`vocabulary 'run src/server …'`) is also still read as a path, though the capture says helper text is not.
