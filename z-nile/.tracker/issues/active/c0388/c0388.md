# c0388: Board count spec reads every root

## Problem
- `z-nile/tests/acceptance/c0042/cli.spec.luau`'s case 'the real tracker's page shows every raft and issue' fails on origin/main because the board page shows one more raft than the spec counts: the spec counts raft and issue folders in a hand list of two roots (`pickman/.tracker` and `z-nile/.tracker`), and the page also shows R0110 in `arcade/.tracker`, the first raft outside those two roots.
- Detail (prep, 2026-11-17): at capture the difference was one raft (R0110). Today the page shows eight more rafts than the spec counts (arcade's and portal's done and backlog rafts) and, behind that, the issue half fails on the closed `c0268`; the cause is the same hand list.
- The failure turns z-nile's full gate red on main, which blocks every raft whose check runs the full gate or c0042's spec.

## Non-goals
- The board page and the code that renders it do not change, because the page is right.
- R0110 and every other raft and issue folder stay where they are.
- `z-nile/projects.toml` and the set of registered projects do not change.
- No other case in c0042's spec changes what it asserts.

## Solution
- The spec takes its roots from the registry in `z-nile/projects.toml` instead of a hand list, and counts raft folders and issue folders under every registered root's backlog, `active/` and `done/`.
- The case passes on origin/main with R0110 where it is in `arcade/.tracker`.
- The spec file contains no literal list of tracker roots, so a raft or issue in any registered root is counted without editing the spec.

## Design
**Why the spec is red today (read on origin/main ec8aecad1, 2026-11-17).** The case compares the page with the folders on disk. The page (`z-nile/engine/board.luau`) reads every registered root (`z-nile/projects.toml`: pickman, z-nile, arcade, portal, snake, invaders, asteroids) and drops closed (won't do) issues (c0278). The spec's hand list names two roots. Raft folders matching `^R%d%d%d%d$` in backlog, `active/` and `done/`: pickman 1+1+38, z-nile 12+12+49 = 113 (the spec's count); arcade 0+0+4 and portal 3+0+1 add 8 = 121 (the page's count). So today's difference of 8 is arcade's four done rafts and portal's four, not R0110 alone as the capture said; `rafts/retired/` (pickman 1, z-nile 8) is not shown by the page and the registered-root count of 121 confirms it must not be counted. A second red hides behind the first: the issue half checks that every issue folder has a place on the page, and `z-nile/.tracker/issues/c0268` is closed (`wont_do`, c0278), so the page drops it (`m.home` has no c0268; E2). Fixing only the raft half would turn the case red at line 70. **Guess (prep) G1**: the issue half skips closed issues, because the page drops them on purpose; it is detail on the captured 'count issue folders' outcome, not a cut. Arcade's c0224 is closed too.

**The change** is one promoted spec, `z-nile/tests/acceptance/c0042/cli.spec.luau` (**Guess (prep) G2**: the folder reading lives in a helper module so that fixtures can prove it, not inline): the two hand-written lists (about 35 lines) become `local found = ondisk.items(TOP)` with `t.expect(rafts).toBe(#found.rafts)` and a loop over `found.issues` collecting the ids `m.home` lacks into `missing`, asserted with `t.expect(table.concat(missing, " ")).toBe("")` so a failure names them. The spec keeps no literal root and no `fs.readDir`. A new helper `z-nile/tests/acceptance/c0042/ondisk.luau` (a module, not a spec; `experiments/prototype.patch` is the whole change, byte for byte) exports `ondisk.items(top: string): { rafts: { string }, issues: { string } }`: it loads the registry with `projects.load(top, true)` and reads `projects.roots(reg)` (registered, not retired roots), and for each root the `rafts` and `issues` folders in `""`, `/active`, `/done`; a missing folder is skipped; names match `^R%d%d%d%d$` and `^[fdc]%d%d%d%d$`; an issue whose document `<id>/<id>.md` exists and is closed (`closing.isClosed(store.readFront(doc))`) is left out, a raft or issue folder with no document is still listed: the page drops it (it adds a folder only with its document, `board.luau:196`), so the case goes red on a leftover or broken folder, as before this chore (**Guess (prep) G3**). A missing registry makes `projects.load` error: the helper does not guess roots. Two companion edits: `tests/acceptance/c0042/watch.txt` gains `z-nile/engine/closing.luau`, `z-nile/engine/store.luau` and `z-nile/tests/acceptance/c0042/ondisk.luau` (it already names `projects.luau` and `projects.toml`), and `tests/inputs.tsv` gains `tests/acceptance/c0042/cli.spec.luau<TAB>z-nile/projects.toml` (c0118's convention for slow board specs, which already lists this spec's tracker folders for every root; no gate reads `inputs.tsv` today, `lib/context.luau:52`, so the row has no gate effect). After a change to the helper, the registry, `closing.luau` or `store.luau`, the cli spec runs only under `--slow` and in this item's AC1 (14.1 s in review 001's replay); `--affected` catches a helper change through the promoted `roots.spec`, whose finish-written watch names `ondisk.luau`.

**Grows by itself.** A new project root in `projects.toml`, or a first raft in one, changes nothing in the spec (AC2 case 3 proves a root is read the moment the registry names it).

**No behaviour change.** The board page and every engine file stay as they are; the other two cases of the spec and its smoke, model and page siblings stay byte for byte.

**Existing work.** Searched `grep -rlF c0042/cli` over `z-nile/tests` and `z-nile/engine` and every `check.sh`: only `slow.tsv`, `inputs.tsv`, `c0154/durations.luau` (data) name the spec. No prepared, active or mid-prep item runs it besides raft checks that run the full gate (R0100's c0276 AC3 and R0072 RC0, which this unblocks). `./zn lessons` found nothing contrary.

**Shared state.** None: `projects.toml` and the tracker folders are only read.

**Restated rules.** None restates the hand list. The watch and inputs lines above follow the spec's new reads.

**Moves.** None. **Guards.** Reads only; no git, no writes; the spec runs in the runner's jail. The helper fails closed on a missing registry (AC2 case 4).

### Scalability
Reading is proportional to the folders under the registered roots (about 250 directory entries, one document read per issue, 2 ms) and the case stays in the slow tier (5.7 s, dominated by `board.collect`).

### Maintainability
The roots are named once, in the registry. A new project, state folder or closed issue needs no spec edit; the helper's fixture spec pins each rule, so a future change of what the page shows fails there first.

### Usability
For the people who run the gate: the full gate and every check that runs c0042's spec stop being red on main, and the failure no longer drifts with each new raft.
