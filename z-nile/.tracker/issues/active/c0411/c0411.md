# c0411: Rounds spec reads every root

## Problem
- With the `./zn metrics` crash (d0406) fixed, the case 'lists every raft once, sorted by id' in `z-nile/tests/acceptance/c0043/rounds.spec.luau` fails with 'expected deep-equal values', because it builds its expected rafts from a hand-written list of two roots (`pickman/.tracker`, `z-nile/.tracker`) while `./zn metrics` lists the rafts of all seven projects registered in `z-nile/projects.toml`.
- `z-nile/tests/acceptance/c0116/retired.spec.luau`, which runs `rounds.spec` in a clone, is red on main today because of the d0406 crash alone, and with d0406 fixed it stays red because of the hand-written list of two roots.

## Non-goals
- No file other than `z-nile/tests/acceptance/c0043/rounds.spec.luau` changes.
- The `./zn metrics` crash on `idea` and `idea-challenge` spend rows is not fixed here; it stays with d0406.

## Solution
- The case builds its expected list from every registered project's root (`rafts`, `rafts/active`, `rafts/done`, `rafts/retired`), so with d0406 fixed it passes on main and keeps passing when a project root or a raft is added.
- The case still fails when metrics leaves a raft out, lists one twice or lists them out of order.
- With d0406 fixed and this change in place, `z-nile/tests/acceptance/c0116/retired.spec.luau` passes without being edited.

## Design
**What is wrong, read from the code (2026-11-17, origin/main 1d9e5952 plus the d0406 prototype).**
- `./zn metrics` prints the review-rounds table at `z-nile/engine/main.luau:7957`: one row for each raft `store.all("raft")` finds (every registered root's `rafts`, `rafts/active`, `rafts/done`) and each `retiredRafts()` raft (`rafts/retired`), sorted by id. The registry (`z-nile/projects.toml`) holds seven projects: pickman, z-nile, arcade, portal, snake, invaders, asteroids (arcade, portal, snake, invaders and asteroids hold rafts; E1).
- The case (`rounds.spec.luau`, 'lists every raft once, sorted by id') takes the table's ids and compares them with `want`, built by listing eight hard-coded folders (`pickman/.tracker/rafts{,/active,/done,/retired}`, the same four under `z-nile/.tracker`) and keeping the names that match `^R%d%d%d%d$`. The other five projects' rafts are in the table and not in `want`, so `toEqual` fails (E1: red on origin/main plus d0406's prototype).

**The change** (one file, `z-nile/tests/acceptance/c0043/rounds.spec.luau`): exactly `experiments/prototype.patch`, one added `require` and one replaced block, byte for byte. AC1 pins the whole file as its merge base plus these two hunks, so the executor applies the patch and does not write the edit by hand, reword the comments or add assertions:
1. `local projects = require("@znile/engine/projects")` after the `process` require (the same module `tests/lib/deploylist.luau` reads, through the same `@znile` alias).
2. The hand list becomes `local bases: { string } = {}` filled by `for _, root in projects.roots(projects.load(TOP))` and, for each root, `for _, folder in { "rafts", "rafts/active", "rafts/done", "rafts/retired" }` (`table.insert(bases, \`{root}/{folder}\`)`), and the existing `for _, base in bases do` loop keeps its body (`fs.isDir` guard, `^R%d%d%d%d$` filter, `table.sort(want)`, `t.expect(ids).toEqual(want)`). The case keeps asserting the same thing: every raft folder under every registered root appears in the metrics table once, in id order. A project or a raft added later needs no edit; a project added to the registry is read by `projects.load(TOP)` from the checkout the spec runs in (TOP is the checkout's top, as the rest of the file reads it).
3. The three old override comments that described the two-project list go with it; one two-line `-- c0411 override:` comment says what the loop reads (the file's other override comments are c0114, c0116, c0120).

**Roots, not all roots.** `projects.roots` (the registry's current projects) is used, not `projects.allRoots` (which adds the retired legacy root `tracker`, for history readers). **Guess (prep) G1**. `tracker/` holds no rafts, and `retired` rafts live in each current root's `rafts/retired`, which the loop already lists.

### Scalability
The case reads `projects.load(TOP)` once and four folders per project, so a new project adds four `isDir` checks; no list in the spec needs an edit when a project is registered (the `deploylist` pattern, c0183).

The case lists the registry's folders instead of a copy of two of them, so it stays equal to `metrics` as projects come and go; the stale list was the second time a hand-written root list in a promoted spec went wrong (c0114, c0120). The `-- c0411 override:` comment says why the loop exists.

For whoever runs the slow tier (`z-nile/check.sh --slow`, d0298's AC): `c0043/rounds` and `c0116/retired` go green once this chore and d0406 have landed, and stay green when a project is registered.
