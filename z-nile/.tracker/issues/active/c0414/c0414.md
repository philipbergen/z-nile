# c0414: D0297 check text path

## Problem
- R0131 landed d0297 on 2026-11-17 (99c7caad6) while R0133 was in review. Line 23 of `z-nile/.tracker/issues/done/d0297/check.sh` is a failure message, `echo "z-nile/affected.luau has no usage line for --own-acceptance"`, and `z-nile/tests/acceptance/c0120/finished.spec.luau` reads `z-nile/affected.luau` there as a path from the item's home (`z-nile/`), where it does not resolve: `z-nile/.tracker/issues/done/d0297/check.sh: z-nile/affected.luau (from z-nile)`.
- That makes `c0120/finished` red on main's slow tier again, and it stops R0133: c0374's AC1 ("passes on the repository as it is") fails as soon as its layer is restacked on that main. It cannot be postponed (zz-rules, Emergent issues).
- The spec is right by its own rule and by c0374's (the word holds a `/`, so it is read whatever quotes it is in); the message is the mistake (lesson `zz-test/sentences-in-checks-are-grep-patterns`).

## Non-goals
- No other line of d0297's `check.sh` changes, and nothing it checks changes: the `grep` on line 22 still reads `"$ZN_ROOT/z-nile/affected.luau"`.
- `c0120/finished.spec.luau` and c0374's rule are not widened.

## Solution
- The failure message on line 23 names the file as `affected.luau`, which resolves from the home, so `c0120/finished` reports nothing for d0297 and d0297's `check.sh` still passes.

## Design
One word in one line of a finished item's `check.sh`: `echo "z-nile/affected.luau has no usage line …"` becomes `echo "affected.luau has no usage line …"`. **Guess (build) G1**: a finished `check.sh` is edited, which the tracker otherwise never does; the alternative (teaching the spec to skip text after `echo`) widens c0374's approved rule and hides real stale paths.
