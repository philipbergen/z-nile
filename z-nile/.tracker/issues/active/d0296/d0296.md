# d0296: Layer branch breaks clone fixtures

## Problem
Three promoted specs fail whenever the checkout that runs them is on a stack layer branch (`R<NNNN>/<n>/<id>`): `tests/acceptance/c0074/done-gate.spec.luau`, `tests/acceptance/c0080/consequences.spec.luau` and `tests/acceptance/c0120/promote-home.spec.luau`. Each makes its fixture with `git clone` of the checkout and removes `origin`, so the fixture's only branch carries the checkout's layer name. `./zn start` in the fixture then asks `layergit.mainTip` for main: there is no `origin/main`, no `main`, and the current branch parses as a layer with no other branch below it, so it refuses with "no main branch" and every later case of the spec fails.

Who notices: the lead of every raft since rafts land as a stack of layers (#296). A z-nile raft's gate runs the whole z-nile suite on the layer branch, so its `check.sh` RC0 is red through no fault of its own. Found by R0093 (the first raft run on a layer): `z-nile/check.sh --affected` failed these three specs with c0256's change and, on a fresh worktree of `origin/main` (10dd3c85) renamed to `R9999/1/c9999`, without it (`consequences.spec`: 1 passed, 4 failed; 5 passed on the same commit under a plain branch name).

It cannot be postponed: it blocks R0093's `check.sh`.

## Non-goals
- `layergit.mainTip` stays as it is: in a real checkout a layer branch with no main below it is rightly refused.
- The other specs that clone the checkout are not changed: they pass on a layer branch (the gate run above failed only these three).

## Solution
Each of the three fixtures names its own branch `main` right after the clone (`git checkout -q -B main`), so it no longer inherits the name of the branch the spec happens to run on.

## Design
Tests only. In each spec's set-up case, after `git({ "remote", "remove", "origin" })`, one line: `git({ "checkout", "-q", "-B", "main" })`, with a comment naming this issue. Nothing the specs assert changes: under a plain branch name `mainTip` already answered the fixture's HEAD (the current branch is not a layer), and with a branch `main` it answers the same commit.

### Scalability
One more `git` call per spec file.
### Maintainability
A new spec that clones the checkout and runs `start` in the clone needs the same line; the comment in each of the three says why.
### Usability
None: no command changes.

### Touched modules
- `z-nile/tests/acceptance/c0074/done-gate.spec.luau`
- `z-nile/tests/acceptance/c0080/consequences.spec.luau`
- `z-nile/tests/acceptance/c0120/promote-home.spec.luau`

### Affected specs
The three specs themselves.
