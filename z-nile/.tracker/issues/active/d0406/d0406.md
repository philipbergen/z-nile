# d0406: Metrics reads idea spend rows

## Problem
- On main, `./zn metrics` stops with "attempt to index nil with chore" in the spend-by-phase table of `z-nile/engine/main.luau`, because `./zn idea` writes spend rows whose phase is `idea` or `idea-challenge` (for example `portal/.tracker/issues/f0396/spend.d`) and metrics only knows the phases in `ledger.PHASES` and `ledger.EXTRA`.
- Two slow-tier specs are red on origin/main because of it: `z-nile/tests/acceptance/c0043/rounds.spec.luau` runs metrics on the real tracker, and `z-nile/tests/acceptance/c0116/retired.spec.luau` runs rounds.spec in a clone.
- No spec proves that the other readers of spend rows (the board, spend summaries, lessons, rounds) finish on a tracker that holds `idea` and `idea-challenge` rows.

## Non-goals
- The spend-row format does not change.
- A phase other than the known ones and `idea` and `idea-challenge` stays rejected: `ledger.parse` still returns "unknown phase" and `ledger.append` still raises.
- `./zn idea` keeps writing the rows it writes today.

## Solution
- `./zn metrics` and `./zn metrics <id>` finish on a tracker that holds `idea` and `idea-challenge` spend rows.
- Metrics reports those rows' minutes and tokens under their own phases instead of dropping them.
- Both `z-nile/tests/acceptance/c0043/rounds.spec.luau` and `z-nile/tests/acceptance/c0116/retired.spec.luau` pass on main's slow tier.
- The board, spend summaries, lessons and rounds each finish without error on a fixture tracker whose spend rows carry the phases `idea` and `idea-challenge`, and a spec proves it for each reader.

## Design
**Reproduction.** `./zn metrics` on origin/main (2a27cb51f, 2026-11-17) stops with `z-nile/engine/main:7734: attempt to index nil with 'chore'`. The smallest input is one done issue whose `spend.d/*.tsv` holds one row with phase `idea`: `acceptance/idea-phases.spec.luau :: metrics finishes on a tracker that holds idea rows` builds that tracker under `.cache/d0406-idea` and fails on main for this reason (E1).

**Expected behaviour.** c0084 (done): "`./zn metrics` prints spend by phase". The idea stage (PR #299, `./zn idea`) added the two phases to the rows it writes; it is the work this defect reworks. PR #294 gave measured rows their own list, `ledger.EXTRA`, "Measured rows also use these", and that list was not extended.

**Root cause.** `cmd.idea` (`z-nile/engine/main.luau`, its `run` helper) appends rows with `phase = "idea"` or `"idea-challenge"` through `costrow.append`, which checks no list. `cmd.metrics` builds two tables keyed by `ledger.PHASES` and `ledger.EXTRA` only and indexes them with every row's phase:
- the phase table, `phaseMin[row.phase][r.type] += tenths` (line 7734): the crash;
- the raft table, `tenths[row.phase] += n` (line 7792): the same mistake, reached once the first is fixed.
No spec caught it because every metrics spec builds its own fixture with lifecycle phases, and the two specs that run metrics on the real tracker (`c0043/rounds`, and `c0116/retired` through it) are in the slow tier, which no gate on a pull request runs.

**The change** (`prototype.patch` in this folder is the whole of it, about 70 lines of diff):
1. `z-nile/engine/ledger.luau`: `ledger.EXTRA = { "test", "other", "idea", "idea-challenge" }`. `ledger.isPhase`, `ledger.parse` and `ledger.append` read the same set, so they accept the two phases and still refuse any other (Non-goals). **Guess (prep) G1**: the two phases join `EXTRA`, after `test` and `other`, not `PHASES`.
2. `cmd.metrics`, phase table: a row whose phase has no entry gets one made (`{ feature = 0, defect = 0, chore = 0 }`, tokens 0) and its name is kept in a local list `unlisted`; after the loop `unlisted` is sorted and appended to the print order after `EXTRA`. **Guess (prep) G2**: a phase nothing lists is shown under its own name, not dropped and not an error.
3. `cmd.metrics`, phase table: the rule that hides an empty line changes from "`test` or `other`" to "any phase that is not in `ledger.PHASES`", so a tracker with no idea rows prints what it prints today (G1).
4. `cmd.metrics`, raft table: `tenths[row.phase] = (tenths[row.phase] or 0) + n`. The table's columns stay the six lifecycle phases; a row of any other phase counts in `all` and `tokens`, as `test` and `other` rows do today.
5. `metrics <id>` (the stages table) walks `PHASES` then `EXTRA`, so with step 1 it lists `idea` and `idea-challenge`. A phase no list holds that the item's rows carry is appended to that order, sorted by name, so it is a stage line too (design review F6). **Guess (prep) G6**.

**Siblings** (every reader of a spend row's phase, `grep -n "row.phase\|r.phase\|%.phase\]" z-nile/engine`):
- `main.luau` 7734 and 7792: fixed above.
- `main.luau` 7827 (`row.phase == "design-review"`) and 7906 (`row.phase == p`): comparisons, no index; safe.
- `ledger.byPhase`: makes a group for a phase it has not seen (`if not groups[r.phase] then`); safe. `spend.writeRaft` prints only `ledger.PHASES` from it, so a raft's `spend.md` totals include idea tokens and its phase lines do not show them, as for `test` and `other`. **Guess (prep) G3**: left as it is, and proven at these functions.
- `boardview.tokens` (`REVIEW_PHASES[r.phase]`): a lookup that yields nil for other phases; safe. `board.luau` 1159 copies the phase; safe. But `board.luau` 275 and `spend.readTotals` read an item's typed `spend.md` through `ledger.parse`, which refuses a phase `ledger` does not list: on main a `spend.md` holding an `idea` row puts "does not parse: unknown phase idea" on the board page and raises in `readTotals` (design review F3). Step 1 fixes both, and the board and summary cases assert it.
- `buffer.luau` and `costrow.luau` copy the phase cell; `lessons.luau` reads no spend row.
- Writers: `ledger.append` refuses an unlisted phase; `costrow.append` does not and is not changed (Non-goals: "`./zn idea` keeps writing the rows it writes today"; the spend-row format does not change).

**Pure and adapter split.** `ledger.luau` stays pure (a list). The metrics edits are in `cmd.metrics`, which already reads at the edge and prints. No new module, type or signature; no new dependency edge, so `architecture.md` is unchanged.

**The hidden second failure.** With the crash fixed, `c0043/rounds.spec.luau :: lists every raft once, sorted by id` fails: it counts rafts in a hand list of two roots (E3). That case is wrong, not metrics, and a defect does not edit a promoted spec: c0411 (chore) fixes it and lands first. **Guess (prep) G4**: `depends_on: [c0411]`. **Guess (prep) G5** (design review F1, replacing G4's second half): this issue's check runs `rounds.spec` and `retired.spec` together, once, in one line (AC7). `retired.spec` is not the same proof as `rounds.spec`: it retires a raft in a copy of the tree and runs the classification, rounds, lessons and audit checks there. Measured: `rounds.spec` 4 s; `retired.spec` 110 s alone (E3), 281.6 s in c0411's prep on a busy machine, 497 s recorded in `tests/slow.tsv`. Lesson `zz-test/check-sh-never-runs-the-slow-tier` gives way here as its c0302 note allows: the slow specs are the ones this defect turned red, no gate runs them, and the line runs them once.

### Scalability
Two more entries in a four-entry list, and one table lookup per spend row in two loops that already visit every row. The real tracker has about 11,000 rows; `./zn metrics` on it takes the same time with the prototype (E2).

### Maintainability
One list (`ledger.EXTRA`) names the phases a tool may write outside the lifecycle; the metrics tables no longer need a list edit to survive a new phase. A later command that writes a new phase shows up in metrics as a line at the end, which is the prompt to add it to the list.

### Usability
`./zn metrics` prints again. Its phase table gains `| idea | … |` and `| idea-challenge | … |` lines when such rows exist (tokens and typed minutes; the measured wall and cpu seconds are in `metrics <id>`'s stage lines). A tracker with no such rows prints exactly what it printed before.
