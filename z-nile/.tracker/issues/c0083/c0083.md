# c0083: Split harness and game specs into two suites

## Problem
Two kinds of spec live in one suite:
- **game specs**, for the code that ships (`src/`): `tests/unit`, `contract`, `integration`, `scenario`, `place`, `runtime` and the game issues' promoted acceptance specs (`f`/`d` ids);
- **harness specs**, for the tooling around it: the tracker CLI, the gate (`scripts/check.sh`), the spec runner and its guards, setup and the build. That's `tests/tooling` and most chores' promoted acceptance specs (c0001, c0008, c0053, c0058 and others).

Today `scripts/affected` sends any change under `scripts/` or `tests/lib/` to a full run of both (`FULL_RUN_PATTERNS`). A tracker-only change runs every game spec. A game change runs every harness spec too, whenever the gate falls back to a full run. `check.sh --full`, which raft steps use as their gate, always runs both. `tracker.sh done` runs that same command on the moved tree, and `tracker.sh land` runs it before a capture push. The Stop hook already runs `scripts/check.sh --affected`, but only when a changed path matches `^(src|tests)/` (`scripts/hooks/stop.sh`), so a harness-only edit never gates. The harness specs are the slow ones (fixture clones, nested runs, jailed runs), so game work pays for them on every gate.

The user wants (2026-10-04): "put all the build/tracker related tests in a separate test suite and set up so that it doesn't run unless files in the tracker/build harness is being changed", "and vice versa": the game suite doesn't run unless game files change.

## Non-goals
- Speeding up individual specs (c0062 covers the slow c0053 commands spec).
- Changing what GitHub Actions runs, or what `scripts/setup.sh` runs. Actions has one workflow, `.github/workflows/deploy.yml`, which publishes and runs no spec (c0172); the verification is the local gate (c0172). `setup.sh` keeps `--full`. If c0174 is not done when the re-prep of this issue starts, that re-prep also re-preps c0174, its patches and pins rewritten in that prep (or makes it a member of R0030 with them rewritten there).
- The static stages (format, lint, types, build), which stay whole-repo; they're fast.
- Moving specs into `tests/harness/` or `tests/game/`.
- Renaming `gate.doneGate`'s return value `"full"`. That mode means "run the gate". c0074 pins the strings `full gate fails` and `full gate is skipped`.

## Solution
No spec moves. One pure module, `scripts/lib/suites.luau`, decides each spec's suite from where it lives and what it requires. `scripts/affected` selects a change's specs three ways:
- by require, as today;
- by text: the repository paths a spec's source names;
- by suite.

What a change runs:
- **harness change**: the whole harness suite, plus only specs whose text names the change;
- **game change**: every spec `graph.affectedSpecs` returns for the path, plus any spec whose text names the changed path. For `src/shared/Logic/Game/init.luau` that includes `tests/unit/Game/game.spec.luau`. `tests/unit/Pellets/pellets.spec.luau` stays out: it neither requires that file nor names it. `tests/scenario/harness.spec.luau` stays out of that selection: the Game init does not pull it in through the graph. A `src/` change is not the whole game suite. `select` returning only `textAffected` does not pass;
- **mixed change**: the union is over every changed path, not `changed[1]`. `src/shared/Logic/Game/init.luau` together with `scripts/tracker/main.luau` is not `ALL`. It contains every harness spec and every `graph.affectedSpecs` hit of the Game init, including `tests/unit/Game/game.spec.luau`, and it omits pellets. The same holds with the paths reversed. Returning `ALL` for any mixed non-shared list is wrong. A `SHARED` path in either position (`scripts/check.sh` with the Game init) is `ALL`;
- **change to what every spec runs on**: everything, and a change under `tests/meta/` is the same `ALL`;
- **`lobby.project.json`**: the whole game suite, plus only specs whose text names that file, the same union as `default.project.json`. A harness spec that names it is selected. The measured 0 such specs on this tree is not a law;
- **`default.project.json`**: the whole game suite, plus only specs whose text names that file.

The Stop hook asks the selector about every changed path, not only `src/` and `tests/`. By the user's decision (2026-10-04, "Nowhere"), no gate runs both suites unless the change touches both. A script plus a Logic file runs both sides of the union, not one side and not the whole game suite. Pellets stays out unless it names a path or requires it. A `SHARED` path still runs both suites, wherever it sits in the list. Every gate step in the skills, the raft `check.sh` template, `done` and `land` uses `check.sh --affected`. `--full` stays as an on-demand command; `scripts/setup.sh` keeps it; the merge check (zz-rules, Merging) runs it today, which AC8 of this issue's `check.sh` would refuse, and the re-prep settles that with the user.

`scripts/lib/suites.luau` is not added in prep. The acceptance spec requires `@scripts/lib/suites` and fails until execution creates it. The scratch classifier in `experiments/classify.luau` is not that module, and the spec does not require it.

## Design
### Why no spec moves
Moving the promoted folders apart (`tests/harness/`, `tests/game/`) would break hard-coded spec paths:
- in promoted specs: c0060's retrofit list, `repo-fence.spec`'s `ALLOWED` keys, c0058's exemptions;
- in every finished issue's `check.sh` (`A="$PWD/tests/acceptance/<id>"`).

Rules give the same split, with no file moved and no promoted spec overridden for a move. R0025 and c0072 are in `done/`. This prep does not edit their documents. Land's live command is `scripts/tracker/main.luau`, not the historical wording in c0072.md.

### `scripts/lib/suites.luau` (new)
- **`suites.isSpec(path): boolean`**. True when the path matches `%.spec%.luau$`.
- **`suites.of(g, spec): string`**, the first rule that matches:
  1. `tests/meta/` → `"both"`;
  2. `tests/tooling/` → `"harness"`;
  3. the game's test folders, anchored (`^tests/unit/`, `^tests/contract/`, `^tests/integration/`, `^tests/scenario/`, `^tests/place/`, `^tests/runtime/`) → `"game"`, including a file that is not on disk. `tests/scenario/harness.spec.luau` is game. `tests/contract/x.spec.luau`, `tests/integration/x.spec.luau` and `tests/runtime/x.spec.luau` are game even though those files are absent. A path that merely contains `tests/unit` (`pkg/tests/unit/x.spec.luau`, `tests/unitary/x.spec.luau`) is not that folder; with no closure it is harness. A Game-init change does not pull `tests/scenario/harness.spec.luau` in through the graph. `default.project.json`, `lobby.project.json` and `--suite game` include it because it is in the game list;
  4. a feature's or defect's acceptance spec (`tests/acceptance/[fd]NNNN/`) → `"game"`;
  5. otherwise, a chore's acceptance spec: `"game"` if `graph.closure` reaches `graph.PLACE_LIB` or any key `src` or `src/…`, else `"harness"`.
  
  Measured on this tree (E1, re-run 2026-10-20): 145 in the harness suite, 118 in the game suite, 1 in both (`tests/meta/architecture.spec.luau`), 0 uncovered. 262 spec files (145 + 118 − 1).
- **`suites.list(g, name)`**: every spec of `"harness"` or `"game"`, those in `"both"` included, sorted. `list` follows `of` for every spec: `"both"` is in both lists, `"harness"` is in the harness list only, `"game"` is in the game list only. `tests/meta/architecture.spec.luau` is in both. `tests/unit/smoke.spec.luau` is in the game list only. `tests/scenario/harness.spec.luau` is in the game list only. Once that holds, a harness-change case and a project-file case lock selection, and `tests/meta` runs for a harness expansion and for a `GAME` expansion. No new product rule.
- **`suites.textAffected(g, changed): { string }`**: the specs whose text names a changed path, a folder above one, or a path inside a changed folder.
  - A spec's text references are every string literal and every literal piece of an interpolated string, before and after each brace (not the code between the braces, string literals in that code included), after comments are stripped (`graph.stripComments`), split at spaces. A spec file that can't be read has no references.
  - Leading `/` and `./` and trailing `/` are dropped (`{root}/tests` leaves `/tests`). Two sets are kept:
    - the existing references (`fs` raises for a path through a file, so the existence test is a `pcall`), which match a changed folder that holds them;
    - every normalized token, existing or not. A changed path, or a folder above it, that equals a token selects the spec, so a deleted or renamed file still selects the specs that named it.
  - This catches every spec that reads a file as text, runs it, or walks a folder, which the require graph can't see. Examples that hold on this tree: `.github/workflows/deploy.yml` (c0001), `SETUP.md` (c0015's docs spec), `tracker/issues/done/c0008/check.sh` (`repo-fence.spec`; c0640 no longer exists), `tracker/game-design.md` (f0054, and every spec that names the folder token `tracker`), and any spec change (the specs that scan every spec: `repo-fence`, c0049's isolation scan, `tests/meta`).
  - **Tracker item documents** (the user's choice, 2026-10-20, option B of design-refute-005). Every raft commit changes its own items' documents: `spend.md`, reviews, the issue documents' Verification logs. Those words are in about 60 harness specs only as fixture paths or titles (`tracker`, `tracker/issues`). So an item document is matched only by a token equal to it or by a folder at or below its item folder (`tracker/issues/done/c0008`), never by a folder above (`tracker`, `tracker/issues`, `tracker/issues/done`). An item document is a `.md` file under `^tracker/(issues|rafts)/(active/|done/)?[fdcR]NNNN/`: the item's own document, `spend.md`, reviews and refutes (design review 006 F1 narrowed it from "every file except `check.sh` and `acceptance/`"). An existing path inside it still matches by the inside-folder rule. Every other file in an item folder keeps the plain rule: its `check.sh`, every `*.spec.luau` (under `acceptance/` or elsewhere, such as c0053's `replacements/`) and its experiments. The specs that walk those name only the folders above: c0034 `locator`, c0063 and c0103 `narrowed` and `repo-fence` for `check.sh` files, and c0044 `guard` and c0006 `clone` for every spec under `tracker/`. Every other path keeps the plain rule too, `tracker/game-design.md`, `tracker/next` and `tracker/templates/` included.
  - **`TRACKER_TREE_READERS`**, a list in `scripts/lib/suites.luau`: the specs that read the real tree's item documents through a library, without naming them. Today this is only `tests/acceptance/c0082/real-tree.spec.luau`, which runs the audit over the real tree; its only `tracker` token is a title word. `textAffected` includes the list whenever any changed path is under `tracker/issues/` or `tracker/rafts/`, whatever the specs' text says. A new spec of that kind joins the list, and the zz-test skill's Suites paragraph says so. The readers of `check.sh` and acceptance files need no list: they stay selected by the plain rule.
  - Folder references are otherwise deliberately coarse. A spec that names `src` or `tracker` is selected by any change under it, except an item document.
- **`suites.select(g, changed): { string } | "ALL"`**:
  - any shared path → `"ALL"`: one that matches `SHARED`, or one in the runner's require closure (`graph.closure(g, "tests/run.luau")`, today `tests/run.luau` and `tests/lib/fence.luau`);
  - otherwise the union, over every changed path and not `changed[1]`, of `graph.affectedSpecs` (by require), `textAffected` (by text), the whole harness suite if a path matches `HARNESS`, and the whole game suite if a path matches `GAME`. The require graph is an input: a `src/` change's selection includes every `graph.affectedSpecs` hit, and text hits stay added on top. Returning only `textAffected` does not pass. The result is still fewer specs than the whole game suite. `select` of `src/shared/Logic/Game/init.luau` plus `scripts/tracker/main.luau` is not `ALL`: it contains every harness spec and every graph hit of the Game init, including `tests/unit/Game/game.spec.luau`, and it omits `tests/unit/Pellets/pellets.spec.luau`. The reverse order is the same union. `select` of the Game init plus `scripts/check.sh` is `ALL`, and so is the reverse: a `SHARED` path is `ALL` wherever it sits. Returning `ALL` for any mixed non-shared list is wrong.
- **`suites.sideOf(g, paths): { string }`**, the sides a baseline runs. For each path, the first rule that matches:
  1. A spec, including an unpromoted `tracker/issues/<id>/acceptance/<file>.spec.luau` and the same path with `active/` or `done/` before the id. Classify it as `tests/acceptance/<id>/<file>`. A spec that is not under `tracker/issues/` or `tests/acceptance/` is classified by `of`, so the six anchored game folders apply before any closure, including when the file is absent. An `f` or `d` acceptance spec is game even when the file does not exist. A chore acceptance spec whose file exists is classified by reading that file's require closure (rule 5 of `of`), not by the tracker path's folder. A missing chore acceptance spec does not reach `src/` or `PLACE_LIB`, so it is harness. The same path with `active/` or `done/` before the id is that rule, not rule 5: `tracker/issues/active/f0099/acceptance/x.spec.luau` and `tracker/issues/done/f0099/acceptance/x.spec.luau` are game even though the files are absent. `tracker/issues/active/c0099/acceptance/x.spec.luau` is harness, because that path is not a file and so has no `src/` closure. Empty `--which` stays exit 2.
  2. A shared path (`SHARED`, or the runner's require closure) → both.
  3. `GAME`, or `src/…`, or a game test folder (the same six anchored patterns as `of`, including a file that is not on disk), or `tests/acceptance/[fd]NNNN/` → game. `--which tests/scenario/harness.spec.luau` and `--which tests/contract/x.spec.luau` are game. The contract path is absent.
  4. `HARNESS` → harness. This wins over text spillover: `scripts/tracker/main.luau` is harness, not both, even though three game specs name the folder token `scripts`.
  5. Otherwise the sides of the specs `--deps` would select (require and text, no suite expansion). An empty selection adds nothing.
  
  For a tracker acceptance path in rule 1, the closure comes from `g` when `g.deps` holds that path (a synthetic graph), else from the file's own requires; a missing file has none.

  The union is printed `harness` then `game`, one name per line. No paths is not both: the CLI exits 2 and prints nothing.
- **Patterns** (anchored Lua patterns):
  - `SHARED`, what every spec runs on: `tests/run.luau`, `tests/lib/t.luau`, `tests/meta/`, `.luaurc`, `rokit.toml`, the jail and guards (`tests/lib/fence.luau`, `scripts/lib/fence.sh`) and the gate that builds the place (`scripts/check.sh`, `scripts/lib/replace-file.pl`). On top of the patterns, every file in `graph.closure(g, "tests/run.luau")` is shared, so a module the runner starts requiring later (R0039's Linux jail, say) runs everything with no new pattern. A file the runner or the fence runs by path, instead of requiring it, is shared unless the harness specs alone exercise it. Today `scripts/lib/fence.sh` is shared (`tests/lib/fence.luau` runs it) and `scripts/lib/git-hooks/` (which `fence.sh` points git at) is the one exception: it stays `HARNESS`, because the hooks act only on git, which game specs barely run, `repo-fence` covers it, and CI's `--full` runs everything;
  - `HARNESS`: `scripts/`, `tests/lib/fixture.luau`, `tests/lib/clone.luau`, `tests/lib/cachepaths.luau`, `tracker/templates/`, `.claude/`, `selene.toml`, `stylua.toml`. Not `^tests/lib/`. A change to `fixture.luau`, `clone.luau`, `cachepaths.luau`, `selene.toml` or `stylua.toml` runs the harness suite and not `tests/unit/Pellets/pellets.spec.luau`. Every other `tests/lib/*.luau` stays graph plus text: `select` is not `ALL`, and `tests/tooling/board.spec.luau` is out unless `textAffected` includes it. `tests/lib/place.luau` selects `tests/place/structure.spec.luau`. `tests/lib/sim.luau` selects `tests/scenario/harness.spec.luau`. No new pattern: E5's 65 s budget already includes the harness suite, and that run is not paid for a place-loader edit;
  - `GAME`: `default.project.json` and `lobby.project.json`. Not `^src/`. A `src/` change still goes through the graph: every `graph.affectedSpecs` hit is selected, text hits stay on top, and the result is fewer specs than the whole game suite. Both project files use that same union. Dropping lobby's text hits does not pass.

### `scripts/affected.luau`
- `affected(changed)` = `suites.select(graph.build({ "src", "tests" }), changed)`. It replaces today's `FULL_RUN_PATTERNS`, under which any `scripts/` or `tests/lib/` change meant `ALL`. It still takes its changed files from `scripts/lib/changed` (`require("./lib/changed")`); c0007 pins that, and the absence of a local `changedFiles`.
- **`--suite <harness|game>`**: prints `suites.list`. A missing or unknown name prints `unknown suite: <name> (harness or game)` and exits 2.
- **`--which <files…>`**: prints `suites.sideOf`, one suite name per line. No paths exits 2.
- **`--deps <files…>`**: the specs that require or name the files, by `graph.affectedSpecs` and `textAffected` only, with no suite expansion and never `ALL`, including when the path matches `SHARED`. For `tests/lib/fence.luau` and for `scripts/check.sh`, the printed set equals that union. Order is not the rule. Empty output fails. A game reader of the shell file (`tests/acceptance/f0061/lobby-tooling.spec.luau`) is in. Board and pellets are out. The whole game suite fails the equality. The fence's list includes `tests/tooling/repo-fence.spec.luau`. The plain selector still prints `ALL` for those paths. The override check still greps, because `ALL` carries no list. A `scripts/` path that is not `SHARED` otherwise selects the whole harness suite. Inequality with `list(harness)` is not the oracle.
- `--suite`, `--deps` and `--which` are modes. They are not combined with each other. A missing name exits 2. With none of them, explicit paths (or the branch diff, as today) go through `select`.

### `scripts/check.sh`
- **`--suite harness|game`**, validated while reading the arguments: a missing or unknown name exits 2 before any tool runs. The tests stage runs `lune run tests/run -- $(lune run scripts/affected -- --suite <name>)`.
- `--affected` (the default) selects through `scripts/affected`, so by suite and by text. `--full` runs every spec, on demand.

### `scripts/hooks/stop.sh`
- The hook takes every changed path (`git diff --name-only --no-renames HEAD`, so a staged rename lists its old path too, plus untracked files), not only `src/` and `tests/`, and asks `lune run scripts/affected -- <paths>`. It gates (`check.sh --affected`) when the answer isn't empty. With no uncommitted and no untracked path (ignored files excluded, `--exclude-standard`), it exits 0 before calling the selector or the gate: with no paths the selector would fall back to the whole branch diff.
- A failing selector counts as `ALL`: a broken selector must not wave a change through.
- Before this, harness-only edits never triggered the hook. The whole harness suite took 65 s on this tree (E5), inside the hook's 300 s budget.
