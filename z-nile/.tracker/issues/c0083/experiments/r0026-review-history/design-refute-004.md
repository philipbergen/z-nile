# Design refute 004: R0026 (c0083)
Every finding was answered, and the fixes were proven in the prototype (`.worktree/proto-r0260`). The full gate passes there with all seven members, and RC1 passes there.

- F1: fixed, by the user's decision (2026-10-04, "Nowhere"): no gate runs both suites unless the change touches both. Every gate step that ran `check.sh --full` runs `check.sh --affected`, which selects over the whole branch against `origin/main`. That covers the raft template's RC0, the tracker skill's merge condition, execute-raft's steps, the review skill's step, the prompt template, c0074's `done` gate (its spec now expects `--affected`), c0080's pre-review gate and R0026's own RC0. c0083's AC8 checks that no step runs `--full`. consequences: `done` no longer runs both suites, so c0074's original bug (whole-repo scans skipped) is now prevented by c0083's text selection: a promoted spec selects the specs that scan every spec (AC4). `doneGate`'s result is renamed `"gate"`. CI keeps `--full`, out of scope.
- F2: fixed: the Stop hook asks `scripts/affected` about every changed path and gates when it selects anything, harness changes included. A failing selector gates anyway. New case: a fixture with a stub selector and gate (selected → gated, nothing → skipped, selector failure → gated, failing gate → blocked). consequences: the harness suite takes 48 s (c0083 E5), inside the hook's 300 s. Doc-only changes that select nothing still skip the gate.
- F3: fixed: `tests/lib/fence.luau`, `scripts/lib/fence.sh`, `scripts/check.sh` and `scripts/lib/replace-file.pl` are shared and select `ALL`, with cases and mutants. consequences: this raft, which edits them, runs everything, which is right.
- F4: fixed, by questioning the mechanism rather than writing a map: `suites.textAffected` indexes the repository paths each spec names (literals and interpolation pieces that exist in the checkout), and selection includes them. Cases: the workflow, `SETUP.md`, a tracker `check.sh`, and a spec change selecting `repo-fence` and c0049's scan. consequences: folder references are coarse (a spec naming `src` is selected by any `src/` change), so a game change also runs the ~10 harness specs that read `src/`, which is correct. Two prototype bugs were fixed: `{root}/tests` (leading `/`) and `fs` raising on a path through a file.
- F5: fixed: `check.sh --suite` is driven in a fixture copy with stub tools that log every call. A bad or missing name exits 2 with an empty log and no `sourcemap.json`; `--suite harness` calls the selector with `--suite harness` and runs exactly its list. consequences: the real `check.sh` never runs in the real checkout from this spec.
- F6: fixed: the testing skill's "Full run" rule is replaced by the Suites part; AC7 requires the old rule ("force one") gone.
- F7: fixed: `scripts/affected -- --deps <files>` lists the specs by require and text only, and ticket-prep's Override check uses it (AC7); a case pins that it isn't the whole harness suite. consequences: the review skill's item 4 follows if it names the selector.
- F8: fixed: `--suite` with no name exits 2, with a case.
- F9: fixed: the raft's Theme, E7 (the prototype's gate with c0083), and c0074's affected-specs sentence.
