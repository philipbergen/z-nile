### F1 [high] check.sh AC6 fails for the correct implementation: the raft's own code-review files are "added review files"
Where: check.sh `ac6()`, the `git diff --name-status origin/main...HEAD -- '*design-review-*.md' '*/review-[0-9]*.md' '*stream-review-*.md' '*refute-*.md'` line; Implementation steps 7.
Evidence: zz-execute Phase 4 step 3 commits `review-NNN.md` (and step 4 `refute-NNN.md`) into the raft's folder on the raft branch. `./zn done` then calls `reviewProblem(raft)` and `runCheck(raft)` (main.luau `cmd.done`), so it runs this `check.sh` with those files in `origin/main...HEAD`. They are listed as `A`, `[[ -z $changed ]]` is false, and AC6 fails. A raft can't skip the code review, so `done` can never pass. Stream reviews written on the raft branch (Phase 2B) do the same. Step 7's "`./zn check c0112` (expect 6/6)" passes only because it runs before the code review.
Critique: the criterion means "no historical review was edited". It is written as "no review file in the diff", which this branch's own lifecycle breaks. The tempting fix is to exclude `rafts/active/<this raft>/`. But the raft id isn't known at prep and the check is sequestered.
Consequences: an addition can only add findings, which makes coverage harder, never easier, so additions need no guard. A rename shows up when a compaction lands mid-raft and the branch remaps. That rename comes in by the merge of main, though, and the three-dot diff doesn't show it.
Recommendation: judge only changes to files that exist at the merge base: `git diff --name-status --diff-filter=DMRT origin/main...HEAD -- <same pathspecs>` must be empty. Run AC6 in prep on a clone with a committed `review-001.md` and `refute-001.md` in a raft folder (it must stay green) and with an edited old review (it must go red). Add the second case to the Rules table as `run`.

### F5 [medium] The worker can't pass the validator on a line that needs a `when-change`, though the brief tells it to report one
Where: worker-brief.md "list it in `report.md` under `when-change` … The lead edits it" and "Fix every problem it prints … end only when it prints `ok`"; backfill-check.sh (runs `./zn lessons --check` on the overlay and never applies `when-change`); Existing work (f).

Record a validator mutant: a design-step line naming a build lesson, red without the file and `ok` with it.
