# c0113: Skills readme

## Problem
The rules live in eleven skills under `.claude/skills/`. Nothing on one page says which skill to read, or how an issue moves from capture to done. An agent has to open every skill to see the state machine.

Decided with the user (2026-10-21): "Close c0113 as superseded." c0115 supersedes it with `z-nile/README.md` and deletes `.claude/README.md`; c0113 joins c0115's raft when that raft is formed, and `./zn done` closes it with c0115 (the tracker has no other way to retire an item).

## Non-goals
- Changing any skill, the tracker, or the commands.
- Copying every rule out of the skills. The page points at them.

## Solution
- Add `.claude/README.md`: one page with a skill table, the command sequence, and a state diagram of `new` → `preparing` → `prepared` → `active` → `done`, including `stop` and a released claim, and the separate `design:` field.

## Design
Superseded by c0115. Every ask of the Solution above is covered by `z-nile/README.md`, which c0115 writes, and none is left open:
- a skill table: its "## Skills" table names every skill and its step;
- the command sequence: its "## The flow" section, steps 1 to 5;
- the state diagram of `new` → `preparing` → `prepared` → `active` → `done`, with `z-stop` (`active --> prepared`) and a released claim (`preparing --> new: release the claim`): its `stateDiagram-v2` block;
- the separate `design:` field: "`design:` is separate from status, and only z-design changes it".

The page this item added, `.claude/README.md`, is deleted by c0115 (the user's decision, recorded there). Nothing else changes for c0113. Its check runs c0115's README spec, whose case "covers every ask of c0113" pins the four points.
