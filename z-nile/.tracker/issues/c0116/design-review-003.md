### F1 [high] The record hashes only the issue's document: a redesign of its `check.sh` or acceptance specs inside the rafting window passes the carried move and `ready`
Where: §1 "What was grouped is recorded" ("a hash of each prepared member's document"); §2 `raftplan.designHash(text)`; `recordGrouped` (`git show origin/main:<doc>`); G16.
Evidence: reproduced (`rv3.spec.luau` T1). A runs `new raft chore chk c0010 c0020`, writes Theme, Order and `design-review-001.md`. B runs `status c0020 preparing`, adds `check "AC2: NEW CRITERION"` to c0020's `check.sh` and a new `acceptance/new.spec.luau`, runs `status c0020 prepared` and lands. A syncs; the carried `status R0010 prepared` **succeeds**; A lands; `./zn ready R0010` **succeeds** ("readied R0010 … (c0010, c0020)"), and the readied `active/c0020/check.sh` holds the new criterion that no coherence review read.
Critique: third round on the "a redesign inside the window" mechanism. The record is the right shape; its coverage is not. An issue's design is its document plus its sequestered contract (`check.sh`, `acceptance/**`), and z-design's own cycle also writes design-review, refute and harvest files in the issue folder (§6). The tempting fix (hash `check.sh` too) leaves the acceptance specs and the issue's own review files out.
Consequences: hashing the whole folder would count files that change for other reasons: `spend.md` (`./zn spend <id>` after the landing) would refuse a raft that nothing redesigned. A new file kind in the issue folder later must be classified as design or not.
Recommendation: `designHash` covers the issue folder's design files as they are on `origin/main`: the document without `status:` and `raft:`, `check.sh`, every file under `acceptance/`, and `design-review-*`/`design-refute-*`/`harvest.md` (any z-design round changes one), sorted by path, each path and its bytes; `spend.md` and `prompt.md` left out. Say the rule once in §1 ("what the hash covers"), with the list. Spec cases in claims.spec: T1 as written (expect the carried move refused, naming c0020 and both hashes), and the same with only an acceptance spec changed; a plan.spec case that a `spend.md` change keeps the hash. Mutants: the hash over the document only (today's code); `spend.md` hashed.
Lesson: architecture/locks-detect-change
