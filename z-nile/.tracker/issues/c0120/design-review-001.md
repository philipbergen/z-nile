### F1 [high] A check.sh's own fixtures under a home's `.cache` are outside the git ceiling: a missing fixture repository resolves to the real one
Where: §3 steps 2 and 5 ("fences the **root** as before", then `cd` to the home); prototype `z-nile/lib/ac.sh` (one `pickman_fence "$(pwd -P)"` at the root, then `cd "$_ac_home"`); testing skill "Fence" bullet ("git never looks above `<checkout>/.cache`") and "Allowed writers" (now naming `pickman/.cache/`).
Evidence: `pickman_fence <root>` exports `GIT_CEILING_DIRECTORIES=<root>/.cache` and writes the sentinel only in `<root>/.cache`. A pickman `check.sh` now runs from `pickman/`, so the testing skill's `.cache/<unique name>` convention puts its fixture in `pickman/.cache/<name>`, which no ceiling covers. Reproduced in a scratch repository: with `GIT_CEILING_DIRECTORIES=<repo>/.cache`, `git -C pickman/.cache/fx rev-parse --show-toplevel` prints the real repository's root; with `<repo>/pickman/.cache` added it fails (`not a git repository`). The ref guard still refuses ref updates there, but `git add`, `checkout -- .`, `reset --hard`, `clean -fdx` or `rm` in a fixture whose `init` failed would act on the real index and working tree. The only thing that stops it today is a `pickman/.cache/.git` sentinel left on disk by an earlier pickman spec run, which a fresh worktree or a cleaned `.cache` doesn't have. No unfinished pickman `check.sh` uses `.cache` today, so nothing is broken yet, but the guard's stated reach shrank silently, and the next pickman `check.sh` written to the skill's rule is exposed.
Critique: the design rejects fencing the home because a `check.sh` run inside a spec run (c0034's list mode) can't write a sentinel in `pickman/.cache`. That argument covers the sentinel only. The ceiling is an environment variable and needs no write. The tempting fix is "call `pickman_fence "$home"` too", which fails closed inside the root's jail and breaks c0034's list mode, the thing the design was avoiding.
Consequences: a second fence call must not write inside a jail, and must still put the sentinel in place where nothing else protects `.cache` itself (Linux, and check.sh runs outside a spec run). The testing skill's Fence bullet and the "Caught only by review" list must say that a home's `.cache` is fenced for check.sh files too.
Recommendation: in `ac.sh`, after the root's fence and before `cd`, add `<home>/.cache` to `GIT_CEILING_DIRECTORIES` for every non-root home. When `PICKMAN_FENCE_SPECS` is unset (not inside a spec run), also run the full `pickman_fence "$ZN_ROOT/$home"` in checks mode, so the home's sentinel exists. Inside a spec run, skip the sentinel: on macOS the jail already denies the write, and on Linux the outer run's own fence of the home applies. Spec cases in `homes.spec`: (1) a pickman `check.sh` whose check runs `git -C .cache/c0120-nofixture rev-parse --git-dir` in an existing folder with no repository fails, and its stderr does not name the real repository (red under the current prototype); (2) `GIT_CEILING_DIRECTORIES` seen by that check names both `<root>/.cache` and `<root>/pickman/.cache`; (3) c0034's list mode still lists every finished pickman `check.sh` (no regression). Add a Rules-and-mutants row ("home's .cache not in the ceiling") and update the testing skill's Fence bullet.

### F2 [medium] gate-homes runs the real tree's gate with the new `--plan` flag, so a wrong `--plan` runs the real gate from inside a spec
Where: `acceptance/gate-homes.spec.luau` (cases "the plan of the real tree…" through `plan(root, …)`, and "--project keeps one project's stages…": `process.exec("bash", { "pickman/check.sh", "--plan" })` and `z-nile/check.sh --plan --project nope` in the real checkout); Rules-and-mutants M23 ("no early exit").
Evidence: `--plan` is new in c0120 (`impl-r43`'s `z-nile/check.sh` has no `plan`). Under M23, or any implementation that does its `.cache` link sweep, `mkdir`, sourcemap or build before the plan exit, these cases run the real gate in the real checkout from a spec. On macOS the jail denies the writes and the case goes red, which is acceptable. Unjailed (Linux, and CI's dispatch step, which runs this raft's sequestered specs) it writes `pickman/sourcemap.json` and `pickman/.cache/check*.rbxl`, and starts both suites again from inside the running one. The testing skill allows only reads against the real repository from a spec, and lists `sourcemap.json` as a writer "written by check.sh files, never by specs". The fixture case "--plan writes nothing" already exists and kills M23. The real-tree cases depend on that fixture case having passed first, and spec order guarantees nothing.
Critique: the tempting fix is to keep the real-tree cases and trust the fixture case. That makes a rule of the testing skill hold only when the code under test is right.
Consequences: a copy of the real tree's registry, gate and project files in `.cache` gives the same plan. `stubbed()` already builds one (`engine.copy(root, dir)`). The registry pin ("the shipped registry") stays in `registry-home.spec`, which reads files only.
Recommendation: run every `--plan` call from a `.cache/c0120-gate/real` copy made by the existing `engine.copy(root, dir)`, with the stub tools on `PATH` and a guard that fails the case if `calls.log` or any `.cache` appears in it. Keep the expected stage lines as they are. Under M23 the case then goes red in the copy, never in the checkout.

### F3 [medium] check-paths asserts floors on live unfinished-item counts, so the promoted spec goes red as the backlog shrinks
Where: `acceptance/check-paths.spec.luau:224-225` (`homes.pickman >= 10`, `homes.root >= 5`), and `:241` (`(items())[1]`, which errors when no unfinished item is left).
Evidence: the counts are of unfinished items' `check.sh` files in the real tree. c0120's specs are promoted to `tests/acceptance/c0120` and run in every gate. Once R0012, R0035 and R0041 and their members are done, `homes.pickman` falls below 10, and some unrelated raft's `done` gate goes red. That raft can't fix it, because the spec belongs to c0120, a chore.
Critique: the floor is there to show the scan is not vacuous, a fair aim (lesson testing/no-vacuous-pass). But a floor on live data is the wrong tool, and `impl-r43` has just removed the same floor from `c0114/classified` for this reason.
Consequences: non-vacuity has to be shown on a fixture instead. The live loop then only asserts that each `check.sh` it reads is clean, and that the scan read every unfinished `check.sh` it found (`checked == found`), with no floor.
Recommendation: move the "reads pickman's files from `pickman/`, the root's from the root" proof to a fixture with one seeded item per home, including a planted vanished path that must be reported. Drop the floors, and guard `items()[1]` (skip when empty). Add a mutant row for the case: `homeOf` always `"."`, which the fixture kills.
Lesson: testing/no-live-counts-in-promoted-specs

### F4 [medium] Guess 4's chosen option (R0012 done before c0120 is readied) is enforced nowhere, so the move can break a prepped raft
Where: Guess 4 ("(a) R0012 is done before c0120 is readied. This is the choice."); §12; Implementation steps 1 (it names only R0034); AC16 (`busy` sees active rafts and branches, not backlog rafts); the decision "Prepped rafts move with the tree".
Evidence: R0012 is `backlog` today (`./zn list`). Its RC1 builds `"$(git rev-parse --show-toplevel)/$(scripts/tracker.sh find "$1")/acceptance/$2"`, which after c0120 resolves to `<root>/.tracker/rafts/R0012/…` and fails (§12). AC11 doesn't see it, because the path is computed. Nothing in Phase 1, `./zn busy` or `check.sh` refuses c0120 while R0012 is unfinished. The ready person follows §8's commands, and those pass with R0012 in the backlog.
Critique: a guess that picks an ordering has to come with the check that enforces it. Otherwise the decided outcome (prepped rafts survive the move) silently fails for R0012, and R0012's executor discovers it, unable to edit the sequestered file.
Consequences: whichever option the user picks needs a mechanical trace. With (a), a Phase 1 line and a refusal. With (b), a restamp that AC11's `RESTAMPED` exemption covers by content, as for R0030 and R0039. With (c), a sanctioned sequestered edit, against the decided line.
Recommendation: escalate to the user, with options (a), (b) and (c) as Guess 4 lists them. Option (a) costs R0012's execution before c0120. Option (b) costs a re-prep of R0012 (about half a day) and two more `RESTAMPED` blob ids. Option (c) needs the user to amend the "no sequestered file changes" decision. Whatever the answer, put it in Implementation step 1 as a check (for (a): `./zn find R0012` is under `done/`), and in AC11's fixture or exemption list for (b).

### F6 [low] `ac.sh` identifies the check.sh by `$0`, so a sourced check.sh silently runs from the root
