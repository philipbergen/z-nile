### F1 [high] Inside any spec run, a failed home fence is ignored whatever its cause, and it leaves the check.sh with git's ref guard and spec guards switched off
Where: §3 step 5; prototype `z-nile/lib/ac.sh` (`if ! pickman_fence "$ZN_ROOT/$_ac_home" 2>/dev/null; then if [[ ${PICKMAN_FENCE_SPECS:-} != 1 ]] …`); `z-nile/lib/fence.sh` `pickman_fence` (it unsets `GIT_CONFIG_COUNT` first and re-exports it only on its last line).
Evidence: the design says the waiver is for "a home's `.cache` that the jail refuses". The code waives *every* failure whenever `PICKMAN_FENCE_SPECS=1`, which every spec run sets, jailed or not, and it discards the fence's message. Those failures include the refusals the fence exists to make: a symlinked `.cache` (review 004 F1) and a sentinel that is a folder (review 003 F2), both "Stop and report this". `pickman_fence` also unsets `GIT_CONFIG_COUNT` before its first check and sets it again only at the end, so an early `return 1` drops the root fence's `core.hooksPath`, `gc.auto`, `credential.helper=` and `protocol.allow=never`. The `GIT_CONFIG_KEY_n` values stay set but are ignored. I reproduced this in the scratch clone, with `pickman/.cache` a symlink to a folder outside the clone. `PICKMAN_FENCE_SPECS=1 bash pickman/.tracker/issues/f9999/check.sh` ran its checks (exit 0), printed `COUNT=unset`, created its fixture folder through the link, and `git update-ref refs/heads/zz-escaped HEAD` **succeeded in the clone's real repository**. With a plain `.cache` the same command is refused: `fence: a check tried to change refs in the real repository … refused`. On macOS, c0034's list mode takes this path for every pickman `check.sh`: the jail refuses the write, so `GIT_CONFIG_COUNT` is unset there too. The kernel then protects the repository, and the shell code outside `check` (`./zn members`, `find`) runs without the git guards. Unjailed (Linux, CI), any failure of the home fence reaches the same state with nothing behind it. The waiver's ceiling also depends on statement order inside `pickman_fence` ("exports it before its first write"). No case pins that, so moving the symlink check above the `export`, a natural edit, silently removes the ceiling on this path.
Critique: this is the second hole in the same mechanism, the home fence. The mechanism reuses the full `pickman_fence`, a function with side effects that can fail partway, and then treats "it failed" as "the jail refused". The tempting fix is to save and restore `GIT_CONFIG_COUNT` around the call. That leaves the waiver wider than the jail and keeps a symlinked `.cache` silent.
Consequences: telling "the jail refused" apart from every other failure needs a marker the runner already provides (`PICKMAN_TEST_JAIL=sandbox-exec`, together with `PICKMAN_FENCE_SPECS=1` and `PICKMAN_TEST_FENCE`, the triple `fence.sh`'s own `jailed` waiver uses). The ceiling has to be set by code that can't fail and doesn't depend on that order. The refusals that are reads (a symlink or file at `.cache`, a folder sentinel) must still refuse, even inside the jail.
Recommendation: split the home fence into two steps. (1) A ceiling-only step: add `<home>/.cache` to `GIT_CEILING_DIRECTORIES` in `ac.sh`, or in a small `pickman_fence_ceiling` in `fence.sh`. It touches no other variable and cannot fail. Always run it. (2) The read-only refusals: a symlink or file at `<home>/.cache`, or a folder sentinel, refuse in every mode. (3) The sentinel write through the full `pickman_fence`. Waive its failure only when the runner's three jail markers are set and `.cache` passed (2), and never pass `2>/dev/null`. In every other case refuse. After a waived failure, `GIT_CONFIG_COUNT` and the hooks must equal the root fence's: restore them, or make `pickman_fence` set `GIT_CONFIG_COUNT` before any early return. Spec cases in `homes.spec`, in the fixture:
- with `PICKMAN_FENCE_SPECS=1` and no jail marker, a fixture whose `pickman/.cache` is a symlink refuses, and nothing is written through the link;
- the same inside the real jail (the runner's markers);
- with the fixture's `pickman/.cache` made unwritable (`chmod 555`) under the jail markers, the check.sh runs, `GIT_CEILING_DIRECTORIES` names `pickman/.cache`, `GIT_CONFIG_COUNT` equals the root fence's, and `git update-ref` in the fixture (the "real" repository of that check.sh) is refused by the ref guard.

Add Rules-and-mutants rows for "waiver for any failure in a spec run", "`GIT_CONFIG_COUNT` left unset after the waiver" and "ceiling exported after the first check", each killed. The testing skill's Fence bullet should say exactly when the home's sentinel is skipped.
Lesson: architecture/guard-no-is-explicit
