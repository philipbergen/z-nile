### F3 [medium] `HOME` still chooses git config through `~/` paths inside the account's own config; Boundaries (b) says it chooses none
Where: Design part 3, "Boundaries, stated" (b) ("None of them is used to choose… the git config files (the account database and `GIT_CONFIG_GLOBAL` decide those)") and (f); `cleanenv.sh:27-29`.
Evidence: git expands a leading `~/` in config paths (`include.path`, `includeIf … path`, `core.excludesFile`, `core.attributesFile`) from `$HOME`, not from the file's owner. A fixture standing in for the account's file, `[include] path = ~/.gitconfig.local`, read with `GIT_CONFIG_GLOBAL` pinned to it: `HOME=<account-like>` gives no `core.fsmonitor`; `HOME=<evil>` gives `file:<evil>/.gitconfig.local  <evil>/fsm`, and `git status` printed `FSMONITOR-RAN` twice. This host's `~/.gitconfig` has no `~/` include, so the route is closed here, but a `~/.gitconfig.local` include is a common setup.
Critique: on any account whose config includes a `~/` path, the admitted `HOME` picks a config that names programs git runs. That is the route round 5 F1 closed for the top-level file. Boundary (f) trusts the account's files, but here the variable chooses which file.
Consequences: `HOME` cannot be reset (specs set it to fixtures under an active fence). The options are to refuse or to state it. Refusing: when the pinned global config (or a file it includes) has a `~/`-relative path and the caller's `HOME` is not the account's home, the cleaner refuses with a message naming the line. The check reads the config's include lines, so it needs one reader (`git config --file <gcg> --get-regexp '^include'` under `HOME=<account home>`, absolute `/usr/bin/git`). Stating it: SETUP.md asks for absolute include paths.
Recommendation: choose one and say it in Boundaries (b)/(f) and SETUP.md (pinned by `wording.spec`). If the cleaner refuses, add a `cleanenv.spec` case with a fixture account config whose include is `~/…`, `HOME` moved: refused, and `HOME` equal to the account's home: passes. ### F5 [medium] With no script to restart, an imported function is used before it is dropped, and the refusal the Design promises never fires
Where: `cleanenv.sh:23-26` (`eval "echo ~$acct"`, `read`, `compgen` run before the function loop at line 44), `:91-93` (`bad` is set only for a name in `compgen -e`); Design part 3 "The shell reader…" ("With no script to restart (an inline `bash -c 'source ac.sh'`…) it unsets the valid names in place and refuses only when an imported-function carrier… is present"); `z-nile/lib/ac.sh` (`[[ -f $0 ]] || pickman_clean_env`).
