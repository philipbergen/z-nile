### F1 [high] Nothing pins what the runner registers: a runner that registers the whole `.cache/.tmp` passes every spec, which is the user's "Exclude .cache/.tmp" decision undone
Where: `z-nile/tests/lib/fence.luau` `fence.enter` (`writeWhole(`{lock}/folders`, `{runTemp}\n`, myPid())`); Rules and mutants (every row about the registry mutates a reader: A1, A2, B1, B2, B8 to B12, B14; none mutates the writer); AC3 ("a run's `PATH` folders are kept only inside a folder the runner registered for this run… a folder in `.cache/.tmp`… gain no folder"); the Problem's `Decided with the user (2026-11-01): "Exclude .cache/.tmp"` ("there only the run's own folders are kept, and the runner names them").
Evidence: in the clone, the one line changed to `writeWhole(`{lock}/folders`, `{cache}/.tmp\n`, myPid())`, then `lune run tests/run -- --jobs 2` on `cleanenv`, `launchers`, `entries`, `inherited-hooks`, `c0005/worktree`, `c0194/callers`, `c0194/runner`: `86 passed, 0 failed, 7 spec files`. Why: `cleanenv.spec` writes its own registry (`{base}/.cache/tests-run.lock/folders` naming `REG`) and reads the live one only through `facts.trust`, whose planted folders sit in `<home>/.cache/c0123-cleanenv`, outside `.cache/.tmp`; `launchers.spec`'s end-to-end probe plants `pickman-stub.agent` in the *fixture's* `.cache/.tmp` (`{fx.main}/.cache/.tmp/…`), which no runner registers either way. With that mutant every agent folder made by `mktemp -d -t pickman-stub` in the home's `.cache/.tmp` (the c0194 place for every agent's scratch trees) is believed whenever any run of that home is live, which is round 7's hole back.
Critique: the mechanism has two halves, a writer and readers, and only the readers are pinned. The decision the user made is about what the runner names ("the runner names them"), so the half that carries the decision is the one with no case and no Rules row. The tempting fix is a case that greps `fence.luau` for `{runTemp}`; it pins text, not behaviour, and would pass a runner that writes `runTemp` and then a second line.
Consequences: a behavioural case needs a live run to read. Every spec already runs under one, and its `TMPDIR` is that run's folder (`fixture.stubDir` relies on it), so the spec can read the live registry: `<home>/.cache/tests-run.lock/folders` (reading is allowed in the jail). Under `--jobs` the workers share the run folder, and a nested guarded run writes no registry (it returns before `takeLock`), so the file has exactly one line. Compare canonically (`/bin/pwd -P` on both, F1 of review 008), not as text. A second, end-to-end half: a folder that is a sibling of the run folder in the home's `.cache/.tmp` cannot be made from inside the jail (the profile closes the rest of `.cache/.tmp`), so it has to be shown with a nested runner copy in a fixture (c0058's pattern): plant `<fx home>/.cache/.tmp/pickman-stub.agent`, run a fixture spec that starts an entry script with it on `PATH`, expect it dropped.
Recommendation: add a Rules row "the runner registers exactly its own run folder, once, after it takes the lock" with a case in `cleanenv.spec` (or `launchers.spec`): the live `tests-run.lock/folders` has one line whose canonical path equals the canonical `TMPDIR`; and the fixture-runner case above. Mutants: the runner registers `{cache}/.tmp`; `{cache}`; `ROOT`; its run folder plus a second line. Record the run in Unknowns & experiments.
Lesson: z-design/spec-design-correspondence; zz-test/seed-every-enumerated-case (candidate new lesson below)

### F2 [medium] A killed run's registry keeps its folders believed until the next run of that home, and killed runs are routine here: a standing guard folder again passes forged `GIT_CONFIG_*` and `GIT_SSH_COMMAND` to every launcher
Where: Boundaries (e) ("a registered folder that outlives its run (a killed run leaves its lock, and so its registry line, until the next run takes the lock over), through which a forged `GIT_CONFIG_*` could pass until then"); `cleanenv.sh` and `cleanenv.luau` `registered` (every line of every `tests-run.lock/folders` is believed, with no owner test); `fence.luau` (`{runTemp}/.pickman-owner` holds the owner's pid and start id, and `fence.holds` already judges it to clear strays).
Evidence: in the clone, `bounded.pl 6 lune run tests/run -- tests/acceptance/c0005/worktree.spec.luau` (killed, as every timed-out command in this project is) left `z-nile/.cache/tests-run.lock/{folders,pid,start-*}` and the run folder with `bin`, `pickman-guard.HsrO6b` and `pickman-stub.c0005-gh`. An entry script with the prologue, started as `env -i HOME=… PATH=<that guard>:<that stub>:/usr/bin:/bin GIT_CONFIG_COUNT=1 GIT_CONFIG_KEY_0=core.fsmonitor GIT_CONFIG_VALUE_0='touch <marker>' GIT_SSH_COMMAND=evil`: `COUNT=1 … SSH=evil`, `git config core.fsmonitor` printed the forged command, and the marker file was created by the launcher's own `git status`. With `PATH=/usr/bin:/bin` the same script dropped all of them.
Critique: this is round 8 F3's effect (a launcher's own git runs a program an inherited variable chose) through a narrower door that the design accepts in (e) as if it were the same class as forging the registry. It is not: forging needs a file write into `.cache`; this needs only a variable, after an event that happens on its own (a timeout, a Ctrl-C, a killed agent). The user's decision says "there only the run's own folders are kept", and a dead run has none. The tempting fix, clearing the lock on a signal, cannot cover `SIGKILL`, which is what `bounded.pl` sends.
Consequences: the cleaner must ask whether the registering run is alive, the same question the runner already answers for strays with `.pickman-owner` and `fence.holds` (pid alive and its start id unchanged, so a reused pid does not count). In the shell reader that is `kill -0` and an absolute `/bin/ps -o lstart= -p` (no `PATH` use); in the Lune reader `fence.holds`' logic, moved into `cleanenv.luau` or shared so both readers decide alike (one rule, one function: add it to the agreement case). Inside the jail `kill -0` on the outer runner fails with EPERM, which must read as alive, as `fence.alive` already does (review 001 F3 of the lock work); a lock with no readable owner reads as dead. Cost: one `ps` per registry line, only while a lock exists.
Recommendation: believe a registry line only while the run that wrote it holds it (the run folder's `.pickman-owner` pid alive with the same start id), in both readers; rewrite Boundary (e) to drop the killed-run residue. Cases: a registry whose owner record names a dead pid (or a live pid with another start id): its guard, bin and stub folders are dropped and the fence names with them, both readers; the live owner: kept; an EPERM probe reads as alive. Mutant: the owner test removed in each reader.
Lesson: z-design/accepted-risks-checked-and-decided
