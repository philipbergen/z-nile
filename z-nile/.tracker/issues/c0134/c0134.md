## Design
A comment-only fix to a promoted spec, in its own chore (z-design: a chore changes a promoted spec in its own raft).

`z-nile/tests/acceptance/c0131/accept.spec.luau` (promoted by R0047's `done`) opens with a header copied from before c0131's one spec was split in two: it says the guard "refuses everything it refused before: an empty transaction during a spec run, any update outside refs/remotes/, and a deleted ref", which is what `refuse.spec.luau` (AC2) tests, not this file. The file tests AC1 only: an empty transaction from a check.sh flow is accepted in every phase, and a fetch that creates or moves a remote-tracking ref is still accepted.

The new header (lines 2 to 6, before `local fs = …`), exactly:
```
-- c0131 AC1: the ref guard (z-nile/lib/git-hooks/reference-transaction since c0114) accepts an empty ref transaction (a
-- fetch with nothing new) in a protected repository from a check.sh flow, in every phase, and still accepts a fetch that
-- creates or moves a remote-tracking ref. What the guard still refuses is refuse.spec.luau's (c0131 AC2). The hook is
-- driven directly, as git calls it, in a fixture repository under .cache that the environment names as protected
-- (PICKMAN_FENCE_REAL_GIT), so nothing outside the fixture is involved.
```
Nothing below the header changes: no code, no case, no other comment. `refuse.spec.luau`'s header, which describes both halves of c0131, is left as it is (outside the capture: it is accurate for the file that tests the refusals).

No behaviour change: the guard, both c0131 specs and every other spec run exactly as before (AC3; the full gate).

## Unknowns & experiments
- **E1. Does the new header pass the acceptance and leave the file's behaviour alone?** Prototype in a scratch clone (2026-10-25): the header above applied, `./zn check c0134` 3/3; c0131's two specs pass (6 cases). **PASS.**
- **E2. Mutation check** (all run on that prototype; rerun after design review 001 with the shared reader): M1 header left as it is today, M2 one refusal left in the header, M3 the pointer to refuse.spec.luau dropped, M4 the second acceptance dropped: each fails header.spec on an assertion. M5 a body edit (an assertion weakened): header.spec stays green (as it should) and AC2 is red; M6 a code line inserted between the header and the first `local` (`_G.c0134_mutant = true`, design review 001 F1): AC2 is red. After design review 002, with the positive rule: M7 line 1 replaced by code, M8 line 1 replaced by `--!nonstrict`, M9 a header line `--[[c0134]] _G.c0134_mutant = true`, M10 a code line appended with no trailing newline: AC2 red for each. After design review 003: M11 `body.luau` that can't run (a wrong `$A`) with a body edit, M12 the local `origin/main` ref moved to HEAD over a committed body edit: AC2 red for each (the old form, `diff <(…) <(…)` and the local ref, passed both). All killed.
- **E3. AC2's base** is the merge-base of HEAD with origin's main tip as `git ls-remote origin refs/heads/main` reports it, which must be a commit this checkout has (else AC2 refuses: `git fetch origin`). The local `refs/remotes/origin/main` is never read: one `update-ref` moves it (design review 003 F2, lesson zz-review/sequestration-reference-not-a-ref); offline, AC2 refuses rather than guess. AC2 judges a branch's own change to the body only: on main, and on any later branch, the base is HEAD or already holds the change, so it has nothing to compare and passes, and says `base is HEAD: nothing to compare` when that is so (design review 001 F2; pinning the body to a fixed sha instead would pin another spec's body for good, lesson zz-test/promoted-specs-pin-rules-not-sets).
- **E4. What may change, defined positively** (design reviews 001 F1 and 002 F1): `acceptance/split.luau` (`split.cut`) splits the file with `string.split(text, "\n")`, so every byte is kept, a last line with no newline included. The header, the only part that may change, is one contiguous run of plain line comments right after line 1: lines that are exactly `--` or start with `-- ` (never `--[`, which can hide code behind a block comment, or `--!`, which changes the file's mode). Everything else is the body, byte for byte: line 1, every line from the first that is not a plain comment, and the end of the file. header.spec reads the header with it; check.sh AC2 prints both bodies through `acceptance/body.luau` and diffs them. So every byte is either in the header, which AC1 judges, or compared.
- Lessons that shaped the design: zz-test/narrowing-pins-the-whole-file (the code below the header is pinned whole by AC2, not by a promoted digest, so no promoted spec pins another spec's body forever: zz-test/promoted-specs-pin-rules-not-sets), zz-test/no-vacuous-pass (header.spec's first case checks the header reader on a sample, so an empty header can't pass by accident).
