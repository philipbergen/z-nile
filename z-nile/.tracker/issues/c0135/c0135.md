# c0135: New issue refuses a used slug

## Problem
`new issue` lets you create a second backlog issue with the same slug as an existing one of the same kind; c0133 duplicated c0132 this way.

This is tracker tooling (the z-nile project, not the game). On 2026-10-22, c0133 was captured 10 seconds after c0132, with the same title and slug `sweeper-killed-under-load` and the Problem `x`. Nothing stopped it. R0043's promoted spec (c0114's `classified.spec.luau`) requires that slugs are unique within a kind, so the duplicate had to be withdrawn by hand (user decision 2026-10-23) before R0043 could land.

**Outcome:** `new issue` refuses a slug that another item of the same kind already uses, and creates nothing.

`./zn audit` should also report a duplicate slug as an error (`slug-duplicate <kind> <slug>: <id>, <id>`), beside the `new` refusal, so a duplicate that arrives by merge or from another engine is caught too (lesson tracker/audit-what-new-refuses; R0043 code review 007 F3).

## Non-goals
<!-- Explicit scope fences. Anything tempting that belongs to another issue. -->

## Solution
<!-- The approach in one paragraph. -->
- Before allocating an id, look up every item of the same kind (issues or rafts) in every lifecycle folder, and refuse when one already has the slug. The error names that item's id.

## Design
**Redesign (2026-11-19).** The design below was written 2026-10-23..26 and reviewed three times; the issue then sat in R0061, which could not run, and main moved about 2,200 commits. A refresh on 2026-11-18 rebuilt the prototype on today's tree; design review 004 (2026-11-19) found more, and this text folds it in. It changes how the design is built, not what it asks for or what the user decided (G1, G2). What changed and why:
- **The origin check is one `git grep` on `base`, and the publisher is not touched** (review 004 F4). The first refresh gave `publish.commit`'s build callback a read-only `listed` argument and read every item document through it (E2, E3); at 441 documents that is 4.7 s per `new`, and it grows with the tracker. The callback already has `base` (the sha every read names), and `closing.grepHits` already wraps `git grep` on it (close's dependents, c0278). One `git grep -l -E '^slug:[[:space:]]*<slug>[[:space:]]*$' <base> -- <roots>/issues/ <roots>/rafts/` finds the only documents that can clash (0.07 s, E3), `audit.sluggedFromTree` decides which are items of the kind, and `rafts/retired/` is inside the pathspec, so `publish.luau` and `listed` drop out. This stays inside G2 (no batched read in the publisher) and gives back most of the lease window G2's second sentence worries about.
- **watch-net is a writer of items too** (review 004 F1), so "exactly three places make an item" was wrong. The writers are re-derived below, and watch-net's slow-tier defect now takes a free slug through the same function as `raft-plan`'s new rafts (`slugs.free`).
- **Landing order** (review 004 F2): c0263 and c0282, in the active raft R0099, seed several rafts with one slug and audit their fixture, so they fail on this audit (checked, E8). This issue `depends_on: [c0263, c0282]`, lands after R0099, and gives each of their seeded rafts a slug of its own in their promoted copies, as its own override.
- **A slug refusal offers no offline route** (review 004 F3): the generic "(PICKMAN_PUBLISH=0 creates it locally instead)" hint is not printed for it, because the offline path cannot see an owner that exists only on origin/main.
- `raft-plan`'s taken set holds raft slugs only, and a case now says so (review 004 F5). Implementation step 5 runs `--affected`, not the full gate (F6).
- Seven project roots are registered (pickman, z-nile, arcade, portal, snake, invaders, asteroids); the rule is unchanged ("every root"), and the spec registers a third root in its fixture so a case reads past the first two.
- An issue closed as won't do (`./zn close`, c0278) stays in its backlog folder with `status: closed-…` and keeps its slug; it is an item like any other, and a case pins it.
- A started raft now gets layer branches (`R0040/1/c0010`); the branch `<id>-<slug>` exists only for a raft cut before layers (`raftBranch`, still read by `currentRaft` and `stop`). The raft audit hint says so; the emergent-issue case uses a layer branch in its raft worktree (a raft worktree is detached until a layer starts).
- `raftplan.commands`' `Op` gained `single`, so the spec's ops are typed `{ raftplan.Op }`. The suffix search is a bounded `for` loop, because d0413's promoted loop scan (`loops.spec`) fails any other loop in `raftplan.luau` (the first prototype's `while` did exactly that); it lives in the new pure module `z-nile/engine/slugs.luau`, which `raftplan.luau` and `watchcmd.luau` share.
- Code review 001 of R0061 (F1-F5) is folded in: `slugClashes` walks keys in first-met order and then sorts, so the sort is observable; the clash order and "a document counts only when named after its folder" are cases of the acceptance spec rather than a separate tooling spec; the doc comments stay with their functions.

**The rule.** A slug names one item of its kind (issue or raft), in every project root and every state: backlog, `active/`, `done/`, and `retired/` for rafts (c0116). An issue and a raft may share a slug. A closed (won't do) issue is still in the backlog. This is the rule c0114's promoted `classified.spec.luau` already holds the real tree to (`bySlug`: per kind, every root, retired rafts included since c0116's override), because compaction and the classification key items by kind and slug. One id in two folders is one item twice, which audit already reports as `duplicate`; it is not a slug clash.

**Every writer of an item, re-derived** (2026-11-19: `grep -n 'writeFile(.*\.md' z-nile/engine/*.luau`, the `{TEMPLATES}/issue|raft/doc.md` renders, and every writer of a `slug:` line). Five places write an item document or a `slug:` line, and each obeys the rule:
1. `cmd.new issue`, a backlog capture (`main.luau`, inside the publish callback): refused by `slugRefusal`, below.
2. `cmd.new issue --raft`, an emergent issue (local write after `reserveOnOrigin`): refused by `slugTakenHere` and, inside the reservation, by `slugRefusal`.
3. `cmd.new raft`, publishing (the callback) and offline (`fs.writeFile(`{dir}/{id}.md`, …)`): refused by `slugRefusal` and `slugTakenHere`.
4. watch-net (`watchcmd.luau`), two functions. `writeDefect` (a watch-miss defect, slug `watch-miss-<spec>`) is safe: `defectExists` greps every state of the checkout for the slug, as a substring, before it writes. `writeSlowDefect` (slug `slow-tier-red`) was not: `openDefect` treats a defect in `done/`, or closed as won't do (`isOpenDefect`, c0278), as not open, so the next red slow tier filed a second issue with the same slug, which watch-net pushes straight to main. It now takes its slug from `slugs.free("slow-tier-red", <the issue slugs of its checkout>)` (`slow-tier-red`, then `-2`, `-3`, …), and `openDefect` matches `slow-tier-red` and `slow-tier-red-<n>` through `audit.sluggedLocal`, the one reader. watch-net judges the checkout it pushes onto (origin/main at its fetch); a push that races another machine's rebases onto the new main, and two machines filing a defect both change `z-nile/next` (the counter), which conflicts and aborts the rebase, so the second does not push a duplicate.
5. `migrate` (`store.setFront(new, "slug", slug)`): adds the slug a legacy file name carried to a document that has none; if that makes a duplicate, audit reports it.
`fold`, `unfold`, `recombine`, `idea`, `land`, `close`, `renumber` and `compact` move, edit or renumber existing items and keep their slugs; `approve`, `ready`, `status` and `stop` edit other lines.

**One rule, one function** (`z-nile/engine/audit.luau`, pure, next to the tree scan it reads) and **one free-slug function** (`z-nile/engine/slugs.luau`, pure):
```luau
export type Slugged = { kind: string, slug: string, id: string, path: string }
function audit.slugOwner(items: { Slugged }, kind: string, slug: string): Slugged?   -- nil for an empty slug
export type Clash = { kind: string, slug: string, ids: { string }, paths: { string } }
function audit.slugClashes(items: { Slugged }): { Clash }   -- distinct ids only, sorted by kind then slug, ids sorted
function audit.sluggedFromTree(paths: { string }, roots: { string }, read: (string) -> string?): { Slugged }
function audit.sluggedLocal(root: string): { Slugged }      -- audit.scan's reach, reading each document's slug
function slugs.free(base: string, taken: { [string]: boolean }): string   -- base, else base-2, base-3, …; bounded
```
`sluggedFromTree` takes every `<root>/<issues|rafts>/<state>/<id>/<id>.md` of a path list (the states are audit's own `STATES`, so a state added there is read here too) and reads its frontmatter with audit's existing `front` reader. `sluggedLocal` is `audit.scan` over `projects.load`'s roots, so it reads every registered root.

**Refusals in `new`** (`z-nile/engine/main.luau`), at every place an item is created, before anything is written or published. Two helpers: `slugTakenHere(kind, slug)` (the items of this checkout, `audit.sluggedLocal(".")`) and `slugRefusal(kind, slug, roots, read, base)` (the refusal text or nil: this checkout's items first, then origin/main's at `base`, by one `git grep` as above, through `audit.sluggedFromTree`; design review 001 F3: both items exist when `new` runs, so it checks both). A `git grep` that fails refuses (a guard fails closed: `closing.grepHits`):
- `new issue` (a backlog capture, publishing): inside the `publish.commit` build callback (so the check sees the origin/main the publish commits on, and a race with another terminal's capture is caught on retry), `slugRefusal`; a hit returns `slug <slug> is taken by <id> (<path>): choose another`, which fails the publish with nothing pushed. The error printed is `new: <that text>`, with no "PICKMAN_PUBLISH=0 creates it locally instead" line: a flag the callback sets chooses the message, as the missing-registry case chooses its own (review 004 F3).
- `new issue --raft <R>` (an emergent issue, publishing): `slugTakenHere` first; then `reserveOnOrigin`, which reserves the number in its own publish callback, takes the same check on origin's tree (its new optional `check` argument, given `roots`, `read` and `base`), so an issue captured on origin/main after the raft's branch was cut is seen.
- `new issue` offline (`PICKMAN_PUBLISH=0`): `slugTakenHere` only, the only tree known; a hit fails with `new: slug <slug> is taken by <id> (<path>): choose another`, no folder written.
- `new raft`, publishing: as the backlog issue, with kind `raft` (its failure already prints `new raft: <reason>` and no hint); offline: `slugTakenHere`, checked before the member checks so the slug message is what a refusal says.

**The origin check is a grep, not a listing** (review 004 F4; replaces the first design's `listed` argument and E2's fix). The build callback is given `base` already, and a grep on it needs no new publisher argument: `publish.allowed`, `validateMoves` and the callback's return are untouched, and `rafts/retired/`, which `paths` never holds, is inside the pathspec. The pattern is `^slug:[[:space:]]*<slug>[[:space:]]*$`, which takes what `audit.front` takes (padding around the value); a hit is only a candidate, since `sluggedFromTree` reads its frontmatter and decides kind, state and folder name. `new` validates the slug (`^[a-z][a-z0-9%-]*$`) before this, so it holds no regex character.

**`raft-plan --apply`** (`z-nile/engine/raftplan.luau`; design review 001 F2): it builds `new raft <type> <first issue's slug> …` for each new raft, and a slug can now be refused (a raft emptied, retired or done keeps its slug, G1). `raftplan.commands(ops, slugOf, projectName, taken?)` takes a fourth, optional argument, the set of every **raft's** slug (from `audit.sluggedLocal`; an issue's slug never counts, since an issue and a raft may share one), and gives a new raft `slugs.free(<its first issue's slug>, <taken and the plan's earlier slugs>)`: that slug, or with `-2`, `-3`, …, distinct within the plan. So the plan is built whole before anything runs, and a plan never stops halfway on a slug (a capture another terminal publishes in between is still refused by `new raft` itself, on origin's tree). c0116's and f0399's promoted plan specs call it with three arguments, unchanged.

**Audit** (`audit.run`): for each clash among `audit.sluggedLocal(root)`, one error at the clash's first path. The line is the capture's format with audit's level and path in front, as every audit line has (design review 001 F5): `error slug-duplicate <path>: <kind> <slug>: <id>, <id> (<hint>)`, the hint per kind (design review 003 F1). For issues: `edit slug: in all but one; branch and worktree names need not follow`: an issue's derived names (`prep-<slug>`) are only names. For rafts: `edit slug: in all but one, never in a raft that has its <id>-<slug> branch (one cut before layer branches): the branch name is derived from it`: a raft cut before layer branches is found by that branch (`raftBranch`: `currentRaft`, `stop`), so only a raft without it may take a new slug. No command changes a slug: the fix is a hand edit of one document's `slug:` line (design review 002 F3). `slug-duplicate` is not one of `audit.ITEM_CODES`, so `list` and `store.find` keep working on such a tree (it can be listed and fixed). It does block two commands: `compact` refuses on any audit error (`auditErrors(noSkip)`, before and after) and `remap` fails on an audit error in the remapped tree, so a duplicate stops both until a slug is edited. That is intended: compaction renumbers every item and keys the classification by kind and slug, so it must not run on a tree where the key is ambiguous. The gate reads the real tree through c0082's `real-tree.spec` (and the dispatcher's merge backstop runs `audit` over the merged tree), so a duplicate that arrives by merge is caught.

**Emergent issues and branch-only items** (design review 002 F2): an emergent issue lives on its raft branch until the raft lands (only the counter is published), so a capture on main meanwhile can take its slug, and two streams' emergent issues in one raft can too. The gate's audit reports it as `slug-duplicate` when the branch merges main, and the raft renames its own emergent issue's `slug:` (its `new issue` checked everything it could see).

**Landing order** (review 004 F2). c0263 and c0282 (raft R0099, active) have sequestered `record.spec` fixtures that seed three to five rafts with `slug: landed` and run `audit` in their setup. Nothing of theirs is edited here: this issue lands after them (`depends_on: [c0263, c0282]`; z-raft puts it in a raft that starts after R0099 is done). Once R0099 is done their specs are promoted copies, `z-nile/tests/acceptance/c0263/record.spec.luau` and `c0282/record.spec.luau`, and this chore changes their `raftDoc` helper (`slug: landed-{id}`, marked `-- c0135 override`) in its own raft. If R0099 does not land first the two specs go red on this issue's audit; if this issue lands first they go red in R0099, whose executor may not edit them: hence the order. Other orders are the user's to rule on.

**Skills** (restated rules): zz-rules gains a **Slugs** bullet after Duplicate ids, exactly: "A slug names one item of its kind, in every project root and every state (retired rafts included): `new issue` and `new raft` refuse a slug another item of the same kind uses, and `./zn audit` reports a shared one (`slug-duplicate`). An issue and a raft may share one. Two copies of one id with one slug are one item twice: remove the stray copy rather than renumbering it." (design review 001 F4: renumbering such a copy would leave two ids with one slug). z-ticket step 2 ("Create the shell") gains, after its last sentence: "When `new issue` refuses the slug as taken, the error names the item that has it: if that item is the same work, it is a duplicate (step 5); otherwise choose another slug."

**Existing work** (lesson z-design/new-rules-migrate-existing-work): the real tree has no shared slug today (c0114's classification spec, AC6; `./zn audit` with the prototype, 0 errors). Open branches that capture an item get the check when they publish; a branch that adds a duplicate by hand is caught by the gate's audit. Promoted specs whose fixtures give every item the same slug are overridden (Regression guard), and so are the in-flight ones above once they are promoted.

No behaviour change for players; for agents, `new` refuses what used to need a hand withdrawal (c0133).

### Scalability
One `git grep` on origin/main's base per `new issue` and `new raft`: 0.07 s over 441 documents, whatever their number (E3; the first design's one `git show` per document was 4.7 s and growing, 2.55 s at 191 documents when G2 was decided), plus one read per hit (almost always none). Audit reads each local document once more (its scan already reads them for `no-slug`): about 0.1 s. watch-net reads its checkout once more.
### Maintainability
One rule in one module, used by `new` (both paths, both kinds) and `audit`; one free-slug function used by `raft-plan` and watch-net; the tree reader shares audit's `STATES` and `front`, so a new state folder or frontmatter rule is picked up in one place.
### Usability
The refusal names the item that holds the slug and its path, so the capturer can tell a duplicate from a coincidence (z-ticket step 5), and offers no route around itself.
