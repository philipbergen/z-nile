# c0135: New issue refuses a used slug

## Problem
`new issue` lets you create a second backlog issue with the same slug as an existing one of the same kind; c0133 duplicated c0132 this way.

This is tracker tooling (the z-nile project, not the game). On 2026-10-22, c0133 was captured 10 seconds after c0132, with the same title and slug `sweeper-killed-under-load` and the Problem `x`. Nothing stopped it. R0043's promoted spec (c0114's `classified.spec.luau`) requires that slugs are unique within a kind, so the duplicate had to be withdrawn by hand (user decision 2026-10-23) before R0043 could land.

**Outcome:** `new issue` refuses a slug that another item of the same kind already uses, and creates nothing.

`./zn audit` should also report a duplicate slug as an error (`slug-duplicate <kind> <slug>: <id>, <id>`), beside the `new` refusal, so a duplicate that arrives by merge or from another engine is caught too (lesson tracker/audit-what-new-refuses; R0043 code review 007 F3).

## Non-goals
<!-- Explicit scope fences. Anything tempting that belongs to another issue. -->

## Solution
<!-- The approach in one paragraph. -->
- Before allocating an id, look up every item of the same kind (issues or rafts) in every lifecycle folder, and refuse when one already has the slug. The error names that item's id.

## Design
**The rule.** A slug names one item of its kind (issue or raft), in every project root and every state: backlog, `active/`, `done/`, and `retired/` for rafts (c0116). An issue and a raft may share a slug. This is the rule c0114's promoted `classified.spec.luau` already holds the real tree to (`bySlug`: per kind, every root, retired rafts included since c0116's override), because compaction and the classification key items by kind and slug. One id in two folders is one item twice, which audit already reports as `duplicate`; it is not a slug clash.

**One rule, one function** (`z-nile/engine/audit.luau`, pure, next to the tree scan it reads):
```luau
export type Slugged = { kind: string, slug: string, id: string, path: string }
function audit.slugOwner(items: { Slugged }, kind: string, slug: string): Slugged?   -- nil for an empty slug
export type Clash = { kind: string, slug: string, ids: { string }, paths: { string } }
function audit.slugClashes(items: { Slugged }): { Clash }   -- distinct ids only, sorted by kind then slug, ids sorted
function audit.sluggedFromTree(paths: { string }, roots: { string }, read: (string) -> string?): { Slugged }
function audit.sluggedLocal(root: string): { Slugged }      -- audit.scan's reach, reading each document's slug
```
`sluggedFromTree` takes every `<root>/<issues|rafts>/<state>/<id>/<id>.md` of a tree listing (the states are audit's own `STATES`, so a state added there is read here too) and reads its frontmatter with audit's existing `front` reader.

**Refusals in `new`** (`z-nile/engine/main.luau`), at all four places an item is created, before anything is written or published:
- `new issue`, publishing: inside the `publish.commit` build callback (so the check sees the same origin/main the publish commits on, and a race with another terminal's capture is caught on retry), `audit.slugOwner(audit.sluggedFromTree(listed, roots, read), "issue", slug)`; a hit returns `slug <slug> is taken by <id> (<path>): choose another`, which fails the publish with nothing pushed.
- `new issue`, local (an emergent issue, or `PICKMAN_PUBLISH=0`): `audit.slugOwner(audit.sluggedLocal("."), "issue", slug)` before the id is allocated; a hit fails with `new: slug <slug> is taken by <id> (<path>): choose another`, no folder written.
- `new raft`, publishing and local: the same, with kind `raft`.

**The listing for the publish path** (`z-nile/engine/publish.luau`): `publish.commit` hands its build callback `paths`, the files it may write, which never include `rafts/retired/` (`publish.allowed` and `itemPath` don't accept it, by design). So a retired raft's slug is invisible there. The callback gains a fifth, read-only argument `listed`: every file under the roots on origin/main (the `ls-tree` listing `commit` already reads). Nothing the callback returns changes, and every written path is still validated exactly as before (`publish.allowed`, `validateMoves`): the publisher's guard is untouched. Other callbacks ignore the extra argument.

**Audit** (`audit.run`): for each clash among `audit.sluggedLocal(root)`, one error at the clash's first path, `slug-duplicate <path> <kind> <slug>: <id>, <id> (choose a new slug for all but one)` (audit.format adds the level and path). `slug-duplicate` is not one of `audit.ITEM_CODES`, so `list` and `store.find` keep working on such a tree (it can be listed and fixed).

**Skills** (restated rules): zz-rules gains a **Slugs** bullet after Duplicate ids, exactly: "A slug names one item of its kind, in every project root and every state (retired rafts included): `new issue` and `new raft` refuse a slug another item of the same kind uses, and `./zn audit` reports a shared one (`slug-duplicate`). An issue and a raft may share one." z-ticket step 2 gains: "When `new issue` refuses the slug as taken, the error names the item that has it: if that item is the same work, it is a duplicate (step 5); otherwise choose another slug."

**Existing work** (lesson z-design/new-rules-migrate-existing-work): the real tree has no shared slug today (c0114's classification spec, AC6; `./zn audit` on the prototype, 0 errors). Open branches that capture an item get the check when they publish; a branch that adds a duplicate by hand is caught by the gate's audit. Promoted specs whose fixtures give every item the same slug are overridden (Regression guard).

No behaviour change for players; for agents, `new` refuses what used to need a hand withdrawal (c0133).

### Scalability
The publish callback reads one document per item on origin/main: 191 today, measured at 2.55 s of `git show` calls on this machine (E3), added to every `new issue` and `new raft`. Audit reads each local document once more (its scan already reads them for `no-slug`): about 0.1 s.
### Maintainability
One rule in one module, used by `new` (both paths, both kinds) and `audit`; the tree reader shares audit's `STATES` and `front`, so a new state folder or frontmatter rule is picked up in one place.
### Usability
The refusal names the item that holds the slug and its path, so the capturer can tell a duplicate from a coincidence (z-ticket step 5).
