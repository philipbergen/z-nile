### F1 [high] watch-net is a fourth place that makes an item, and it files a second `slow-tier-red` once the first is closed or done
Where: c0135.md Design, "The rule" ("The places an item can be made are exactly three, all in `cmd.new`"); z-nile/engine/watchcmd.luau:681-771 (`openDefect`, `writeSlowDefect`); Touched modules
Evidence: `writeSlowDefect` writes `z-nile/.tracker/issues/<id>/<id>.md` with the fixed `slug: slow-tier-red` whenever `openDefect` finds no open one, and `openDefect` treats a defect in `done/` or one closed as won't do (`watchcmd.isOpenDefect`, c0278) as not open. So the second red slow tier after the first `slow-tier-red` defect is fixed or closed writes a second issue with that slug, and watch-net pushes it straight onto main. c0278's promoted `readers.spec.luau` pins this behaviour: "watch-net files a new slow-tier-red defect when the open one is closed" seeds a closed `slug: slow-tier-red` document and expects two such documents on origin. This design says a closed issue keeps its slug (it pins that with c0012 `closed-one`), and its audit adds `error slug-duplicate`, which c0082's `real-tree.spec` runs over the real tree in every gate. So the first such watch-net push turns main red for everyone (c0114's `classified.spec` would already fail on it too), and none of the four `new` refusals is on that path. `writeDefect` (watch-miss) is safe: `defectExists` greps every state.
Critique: the design counts the item-creating paths from `cmd.new` alone and never reads the engine's other writers, so the rule has a writer that breaks it. The tempting fix is to correct the sentence and leave watch-net to the audit. But then the tool itself puts the duplicate on main, and the only signal is a red gate on someone else's PR.
Consequences: guarding watch-net adds `z-nile/engine/watchcmd.luau` to Touched modules and a Rules row. It also needs `openDefect` to see a suffixed open defect: today it greps `-F "slug: slow-tier-red"`, which only matches `slow-tier-red-2` because the match is a substring. And the two promoted watch specs must be re-read for what they pin: c0278 `readers.spec` counts `git grep -l "slug: slow-tier-red"` hits (a substring, so a suffixed slug still counts), and `tests/tooling/watch-map.spec` expects one document after the "already open" run.
Recommendation: make watch-net's slow defect take its slug through the one rule. Read the watch-net worktree's items (`audit.sluggedLocal(dir)`) and choose `slow-tier-red`, or the first free `slow-tier-red-<n>`. Share one pure helper with raft-plan's suffix rule, so "a free slug" is one function. Make `openDefect` match `^slug: slow-tier-red(-%d+)?$` explicitly rather than by substring. Rewrite "The rule" to name watch-net's two writers: `writeDefect`, which never duplicates, and `writeSlowDefect`. Add a slugs.spec case built like c0278's `c0278-watch` fixture: seed a closed `slow-tier-red` and a done `slow-tier-red-2`, make the slow tier red, run `./zn watch-net`, and assert that the new defect's slug is `slow-tier-red-3` and that `./zn audit` reports no `slug-duplicate`. Add a Rules row whose mutant is the constant slug. Run c0278 `readers.spec` and `tooling/watch-map.spec` on the prototype, and name either one on Overrides if it pins the old slug. This adds scope, not a cut. Record it as a guess if the lead reads it as beyond the capture.

### F3 [medium] The publish-path refusal tells the capturer to set PICKMAN_PUBLISH=0, and the offline path cannot see the owner the refusal named
Where: z-nile/engine/main.luau (prototype applied) 1186-1191 and 1231: `new: could not publish to origin/main: {r.reason}\n(PICKMAN_PUBLISH=0 creates it locally instead)`; c0135.md "Refusals in `new`"

### F4 [medium] G1 weighs one read per document (4.7 s, growing with every item) against `cat-file --batch` only; a single `git grep` on `base` is the option the publisher already provides, and it is not offered
Where: guesses.md G1; c0135.md Scalability, E3, G2; z-nile/engine/publish.luau:17-21 (`base`: "so a build that greps the tree (close's dependents, c0278) sees the same one")
