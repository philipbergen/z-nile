# c0137: Finished .claude scans pass vacuously from z-nile/

## Problem
Five finished checks read .claude from z-nile/, a folder that doesn't exist since c0120's home rewrite, so they pass vacuously: c0044 check.sh:56, c0067:56 and R0025:15 run grep -rn… over .claude with || true (grep exits 2 and the error is swallowed), and c0067:44's [ ! -e .claude/skills/make-prompt ] is always true. A fifth: c0069 check.sh:41 (`bad=$(grep -rnF "./zn launch" .claude ../AGENTS.md ../SETUP.md ./templates scripts || true)`), found by c0115 design review 012 F3. Found with `git grep -nE '(^|[ "(])\.claude([ /"]|$)' -- 'z-nile/.tracker/*/done/*/check.sh'` at c0120's done tree; rerun it before the prep. Found by c0115 design review 011 F4; not c0115's regression.

## Non-goals
- c0115's own finished-file rewrite (the skills' move, its rules 1 to 3): c0115 carries the scans over `../.claude/skills`; these five read `.claude` from the wrong folder, a defect of c0120's home rewrite.

## Solution
- Rewrite the five operands to what they read before c0120's move (the repository's `.claude`, or the skills' real folders after c0115), the same finished-file rewrite exception the user decided for c0114 and c0120.
- Plant a phrase for each scan and see it go red.

## Design
Four finished checks read `.claude` relative to `z-nile/`, their project home since c0120 (`z-nile/lib/ac.sh` cds there), where no `.claude` exists. Three are banned-phrase greps whose `|| true` swallows grep's "No such file" (exit 2), and one is an existence test that is always true, so none of them can fail on the folder they were written to search. Before c0120 they ran from the repository root, where `.claude` held the skills (real folders until c0115). Since c0115 the skills' real folders are `z-nile/skills/` and `pickman/skills/`; `.claude/skills/<name>` are links, which `grep -r` does not follow (c0115 §8 rule 2 rewrote its own bare `.claude/skills` operands to the real folders for that reason).

The capture named a fifth, c0069 `check.sh:41`; c0115 deleted that criterion (c0069 AC5, G12/G13), so four remain. Found again on main at 0c540ce1 with the capture's own search, `git grep -nE '(^|[ "(])\.claude([ /"]|$)' -- 'z-nile/.tracker/*/done/*/check.sh'` (the other hits are c0113 and c0115 labels and c0115 AC12's `cd .. && ./zn busy .claude/skills …`, which runs from the root and is right).

The four rewrites, exactly (old → new); nothing else in these files changes:
1. `z-nile/.tracker/issues/done/c0044/check.sh` (AC9): `… -e "-<slug>.md" .claude scripts ./templates ../SETUP.md ../AGENTS.md || true)` → `… -e "-<slug>.md" skills ../pickman/skills scripts ./templates ../SETUP.md ../AGENTS.md) || [ $? -eq 1 ] || { echo "a folder this scan reads is missing"; exit 1; }`.
2. `z-nile/.tracker/issues/done/c0067/check.sh` (AC10, the clipboard grep): `… -e "clipboard" .claude ./templates scripts ../AGENTS.md || true)` → `… -e "clipboard" skills ../pickman/skills ./templates scripts ../AGENTS.md) || [ $? -eq 1 ] || { echo "a folder this scan reads is missing"; exit 1; }`.
3. `z-nile/.tracker/issues/done/c0067/check.sh` (AC10, the old skill gone): `[ ! -e .claude/skills/make-prompt ] || { …` → `[ ! -e skills/make-prompt ] && [ ! -e ../pickman/skills/make-prompt ] && [ ! -e ../.claude/skills/make-prompt ] || { …` (the real folders, and the links folder, where a stray link or real folder of that name would sit).
4. `z-nile/.tracker/rafts/done/R0025/check.sh` (RC1): `… -e "./zn launch" .claude ../AGENTS.md ../SETUP.md ./templates scripts || true)` → `… -e "./zn launch" skills ../pickman/skills ../AGENTS.md ../SETUP.md ./templates scripts) || [ $? -eq 1 ] || { echo "a folder this scan reads is missing"; exit 1; }`.

Each grep's `|| true` also goes (design review 001 F1): it swallowed grep's exit 2 (a missing operand), which is how c0120's move made them vacuous unseen. Exit 1 (no match) is still fine; any other status stops the check with `a folder this scan reads is missing`. So the next move that takes a folder away turns these checks red instead of silent.

Not widened (design review 001 F2; decided with the user, 2026-10-25: "don't widen"): the four lines read what their phrases are about today, the skills and docs. The root `scripts/` and `.claude/settings.json`, which these lines read from the root before c0120, are left out, and so is c0067's other grep (line 63, the 13 phrases), which already reads the real folders since c0115's rewrite and is not vacuous.

`.claude` itself now holds only `settings.json`, the links and Claude Code's own state (`worktrees/`, a lock), none of which these phrases are about, so it is not scanned: scanning `../.claude` recursively would also walk `.claude/worktrees` (whole checkouts) and still miss the skills behind the links.

These are edits to finished `check.sh` files, the exception the user decided for c0114 and c0120 (finished files are rewritten when a move breaks them) applied to a defect of c0120's home rewrite. They land in this prep PR, on main before z-ready (G1, decided with the user), so no execution branch edits a finished file and c0115's finished AC14 never sees them on a branch.

**c0067 AC10's stale names** (design review 002 F1; decided with the user, 2026-10-26: "Rewrite to the new names"): on main, c0067 AC10 is red before it reaches its clipboard grep, on statements that name skills c0115 renamed. The prep rewrites them to today's names, so the whole criterion passes and the fixed scan runs: `^name: ready-raft$` → `^name: z-ready$`; the loop key `/launch-raft` → `/z-run`; `ready-raft/SKILL.md` in AGENTS.md → `z-ready/SKILL.md`; `/ready-raft` in z-design → `/z-ready`; and their messages (`ready-raft: …` → `z-ready: …`, `ticket-prep: next step` → `z-design: next step`). The criterion's later 13-phrase grep (c0005's banned phrases) then found "straight to main" in the lesson zz-arch/guards-trust-only-origin, where it describes an attack; that sentence is reworded ("could then land files on main without review"), meaning unchanged, so the criterion passes as a whole.

After this prep the three criteria the four lines sit in (c0044 AC9, c0067 AC10, R0025 RC1) pass whole on today's tree, as `./zn check` runs them (scans.spec's whole-criterion case), and the lines fail when a banned phrase or a `make-prompt` skill appears in either skills folder.
