# c0142: Remote dispatch runtimes

## Problem
c0117's capture names six dispatch runtimes: `claude-cli`, `grok-cli` and `cursor-cli` (local), and `claude-cloud`, `grok-bot` and `cursor-app` (remote). The user split the three remote runtimes out of c0117 into this issue (Scope decision (user, 2026-10-25), c0117's G8: "Split into a follow-up"), after the CLIs' own help and one free probe showed that none of c0117's command lines for them works:

- `claude-cloud`: `claude --cloud <prompt> -p …` is refused: "Error: --cloud cannot be combined with --print. Starting a new cloud session with --cloud is interactive only: drop --print, or drop --cloud to run locally. To message an existing cloud session instead, pass its ID: `claude -p "message" --cloud <session-id>`". A step can only message a cloud session that already exists (claude 2.1.310).
- `grok-bot`: `grok agent headless` takes no prompt and no options beyond the relay's (`--grok-ws-url`, `--grok-ws-origin`, `--leader-socket`): it serves the Grok WebSocket relay. The per-step route is `grok agent stdio` (ACP over stdio), which runs locally (grok 1.0.62).
- `cursor-app`: `agent worker` is a long-running self-hosted Cloud Agent worker that Cursor's cloud agents claim and send tool calls to (`--idle-release-timeout`, `--pool`, …); it can't be given one prompt and exit. The per-step route is a Cloud Agent API call (agent 2026.10.19).

What should happen: each remote runtime the user still wants runs one dispatched step and returns its token count, as c0117's local adapters do, through the route that works, or is dropped with the user's decision. Every remote run that can't report a token count fails its step rather than record zero (c0117's rule).

## Non-goals
- The local runtimes (`claude-cli`, `grok-cli`, `cursor-cli`): c0117.

## Solution
- `claude-cloud`: create the session once (interactively, or through whatever non-interactive route exists by then), then message it per step with `claude -p "<prompt>" --cloud <session-id> --output-format stream-json`; probe whether that streams and reports usage.
- `grok-bot`: an ACP client over `grok agent stdio` (the same `usage` updates as `grok -p`), or drop it, since it is local.
- `cursor-app`: one Cloud Agent API call per step, with its token count read back.
- Each adapter joins c0117's `models.RUNTIMES` and `adapters`, with c0117's quota, stall and cap rules.
