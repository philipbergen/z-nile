# c0165: Reuse passed test results

## Problem
From the user (2026-10-26): reuse gate results. If a gate already passed on the exact same code, later steps skip rerunning it. Tests should be tied to the code they test, so a suite (ideally a single test) runs only if its result could have changed, and the fingerprints of passed tests are stored.

Today the full gate runs every spec several times on identical code in one change: the author runs it before review, the reviewer runs it again, then `./zn land` / `done` runs it once more. A full run takes ~216 s idle and 500 s+ under load (c0157's measurements). `z-nile/affected.luau` already picks the spec files a diff can reach through the require graph, but only `check.sh --affected` uses it, and nothing remembers a past pass.

What should happen:
- **Fingerprint per spec**: every spec file gets a fingerprint made of its own content, the content of everything it can reach (the require graph `affected.luau` builds), the shared runner and harness, the tool versions and the gate mode. Ideally the fingerprint is per test inside a spec, not just per file.
- **Reuse**: a pass is recorded under its fingerprint. A later run skips a spec whose fingerprint already passed, reports it as reused, and runs the rest.
- **Store**: results live in a SQLite database at `.claude/.znile_tests.sqlite` (git-ignored), keyed by fingerprint and shared by every worktree of the checkout, so the author's pass serves the reviewer.
- **Concurrent runs wait, they don't duplicate**: when two runs reach the same fingerprint at once (two worktrees, or the author and the reviewer), the second waits for the first's result and uses it.
- **Crash detection**: a `running` row stores its owner's PID (plus the process start id, so a reused PID isn't mistaken for the owner). A waiter sees a crashed or killed run at once, takes the row over and runs the spec itself, instead of waiting forever.
- **The full gate runs only at the merge** (`./zn land`, the PR's merge, `done`). Every step before it (the author's iterations, the review, the pre-PR gate) runs only the affected specs.
- **A merge failure teaches the selector**: when the merge's full gate fails a spec that the affected selection didn't pick for the same change (a graph miss), the tooling finds out how the affected selection missed it (which changed file the spec depends on without a require edge) and records that dependency, so later affected runs select the spec. This replaces zz-test's "Graph miss: file a chore by hand" rule.
- No failed or partial run, different tree or spec can forge a pass. A forced full rerun stays available.
Scope decision (user, 2026-11-03): "Split it". c0165 had grown to a 600-line design and needed a sixth review round. Its captured outcomes are split, none dropped or narrowed: c0165 keeps **Fingerprint per spec**, **Reuse**, **Store** and **No failed or partial run, different tree or spec can forge a pass / a forced full rerun stays available**; **Concurrent runs wait** and **Crash detection** move to c0238; **The full gate runs only at the merge** moves to c0239; **A merge failure teaches the selector** moves to c0240. c0238, c0239 and c0240 depend on c0165. The prior design for all of it is on branch `prep-reuse-test-results` (commit a03b4995); c0165's prep is redone for its reduced scope.

Scope decision (user, 2026-10-26): "The full gate at merge runs all for real so we can find out if dependency graph has gaps" (asked whether the merge's full gate may reuse fingerprinted passes: it may not; every spec runs).
Scope decision (user, 2026-10-26): learned dependencies go "DB now, and printed to commit": the edge goes into the SQLite db at once, and the gate prints the line to add to a committed file that the selector reads; the gate itself never edits the repository.

A spec that deliberately overwrites the results file the runner writes (in `.cache`, the one place specs may write) can fake a pass, but only for pre-merge affected runs (author, reviewer, RC0) and for `record --full`'s per-spec rows, which only affected runs of the same mode would read (none: fingerprints carry the mode). Failed, crashed and partial runs and changed trees still can't produce a pass. The merge's full gate always runs fresh, so a forged pass never reaches `main`.

## Non-goals
- Limiting concurrent gates machine-wide, and the tripwire firing on another session's refs: c0157.
- Spec order: c0154 (slowest first).
- Making individual specs faster.
- Fingerprinting the static stages (format, lint, types, rojo build), unless prep finds it cheap to do the same way.
  (Prep: it is cheap at the level of the whole gate, so the Design covers it: a gate that passed on the same content, tools and base is reused whole, static stages included. Stage-by-stage fingerprints stay out.)

## Solution
- Build the fingerprint by hashing the spec plus its transitive requires with `affected.luau`'s graph, so selection and reuse share one reader.
- Specs that read files outside their requires (meta and structural specs, the repo-fence scan, `git ls-files` readers) need declared inputs or must always run, or a reused pass hides a failure (the same risk as a graph miss).
- Per test: record which test names passed under each fingerprint, and narrow a test's inputs only where it can declare them, since Lune has no coverage tracing.
- SQLite schema idea: one row per fingerprint holding the state (`running|passed|failed`), the passing test names, the duration, the owner's PID and start id, and a timestamp. A run claims a fingerprint by inserting a `running` row in one transaction; a second run polls until the row is `passed` or `failed`. A dead owner (the same PID and start-id check as the runner's `tests-run.lock`) frees the row. A `failed` row on the same fingerprint is either reported as the same failure or rerun once to tell a flake apart (prep decides).
- Path: resolve the main checkout's `.claude/` through `git rev-parse --git-common-dir`, so all worktrees share one database. Ignore the file, like `prompt.md` and `.cache/board.html`. Only the runner writes it, from outside the jail (the jail denies specs every write outside `.cache`). The guards stay as they are, and the repo-fence and `cachepaths` reviews must accept this writer.
- The `sqlite3` CLI ships with macOS and Lune has no built-in SQLite, so the runner shells out to it (prep checks Linux and CI), with WAL mode and a busy timeout.
- Learned dependencies: commit them as extra edges that `affected.luau` reads (a `deps` table beside the spec, or one registry file), so every checkout and CI benefits and review sees them; keep them only in SQLite if local is enough. Find the edge by bisecting the changed files against the failing spec, or by diffing the spec's file reads against its require closure.
- Open question for prep: a merge gate that reused fingerprinted passes would catch no graph miss, because its fingerprints come from the same graph. So the merge gate probably runs every spec fresh, and reuse plus the concurrent wait apply to the affected runs before it, unless prep finds a fingerprint that doesn't depend on the graph.
- Steps that change: zz-execute (the author's and the pre-PR gates become `--affected`), zz-review (the reviewer runs the affected specs), `./zn land` / `done` (the full gate), and zz-test's gate-modes table and Graph miss rule.
- `spec-durations.tsv` could move into the same database (an option, not scope).

Prep additions (2026-10-26):
- The orchestration lives in a new CLI, `z-nile/specs.luau`, run by `z-nile/check.sh` outside the jail, not in the runner: only an unjailed process can write the db (the jail denies every write outside the home's `.cache`), and the runner's top process never returns from `fence.enter()`. `fence.luau` gains only an export of its own-pid helper.
- The fingerprint's inputs are, by construction, exactly what the selector reads: one predicate, `select.isInput(spec, path)`, decides both, so "a change selects S" and "a change alters S's fingerprint" can never disagree.
- "Exact same code" is a content digest of the working tree (git blob ids of every tracked and untracked file, read without writing objects), so `done`'s run on an uncommitted done tree matches the committed final head.

## Design
The spec runner (`z-nile/tests/run.luau`) stays the only thing that runs specs, and its jail and guards stay as they are. A new orchestrator, `z-nile/specs.luau`, sits between the gate and the runner. It decides which spec files to run, runs them through `lune run tests/run`, and keeps the results in a SQLite database. `z-nile/check.sh` calls it instead of calling the runner directly.

### Where things run (why the orchestrator is a CLI)
- Only an unjailed process can write the db. The runner's top process (`fence.enter()`) launches the jail and then exits with the jail's code: it never returns to the runner's code. Its coordinator and workers run inside the jail, which denies every write outside the home's `.cache` (`fence.luau` `profile()`).
- `z-nile/check.sh` runs unjailed, so the orchestrator it calls runs unjailed too. It writes the db, and it starts `lune run tests/run` from the home exactly as `run_specs` does today. The runner then fences and jails itself as before.
- Results come back through one file per run, `<home>/.cache/spec-results-<owner pid>.json`. The orchestrator names it in `PICKMAN_RESULTS`, and the runner writes it.
- A spec can write that file, since it lies in `.cache`, the one place the jail lets it write. A deliberate overwrite can fake a pass in an affected run, and a per-spec row of `record --full`, which no run reads, since fingerprints carry the mode. This is the residue the user accepted (`Decided with the user (2026-10-27)` in the Problem). The merge's full gate runs every spec for real, so a forged pass never reaches `main`. Everything short of a deliberate forgery is closed: only a runner exit of 0 records passes (F1), a failed read turns reuse off (F4), and a changed tree records nothing (R31).

### `select.luau` (one rule for selection and fingerprints)
```luau
export type Home = { name: string, prefix: string }        -- prefix "pickman/", "z-nile/"
export type Rules = { homes: { Home }, roots: { string } }  -- roots: every project root ("pickman/.tracker", ...)
export type Inputs = { [string]: { string } }              -- repo-relative spec -> extra inputs (file, folder/, *, ref:<full ref>)
export type Context = { rules: Rules, graph: graph.Graph, inputs: Inputs }
select.rules(reg: projects.Registry): Rules
select.forces(rules: Rules, path: string): ("all" | string)?  -- "all": every project's full run; a name: that project's
select.gateProjects(rules: Rules, changed: { string }): { string }  -- path homes + forced projects, registry order
select.isInput(ctx: Context, spec: string, path: string): boolean
select.affected(ctx: Context, changed: { string }, only: string?): { string } | "ALL"
select.parseInputs(text: string, homePrefix: string, roots: { string }?): (Inputs?, string?)  -- nil + reason on any malformed line
```
- `gateProjects` ignores project-root documents. For every other changed path it adds the path's home (if it has one) and the project `forces` names (a path under no home, such as an old-root `src/x.luau` or a root `scripts/` file, has no home but still gets its `forces`) (`"all"` adds every project), deduplicates, and returns registry order. It needs no graph or inputs. Thus a shared harness path selects both projects, an old root selects z-nile, and a pickman-only source edit selects only pickman.
- `isInput(ctx, S, p)`:
  - A spec with a `*` entry has every `p` as an input.
  - A `p` under a project root is an input only through an `Inputs` entry (declared or learned) that itself names a path under that root and that `p` equals or lies under. A broader entry (`pickman/`) never reaches into a root. `spend.md` files and the root itself never are.
  - Any other `p` is an input when at least one of these holds:
    - `select.forces(p)` is `"all"` or names S's project;
    - `p` is in `graph.closure(S)`, or lies under it as a folder prefix;
    - S's closure holds a place library and `p` is under that home's `src/` or is one of its two project files;
    - `p` equals, or lies under, one of S's `Inputs` entries;
    - `p` is S's home's `tests/inputs.tsv` and that file names S.
- `affected(ctx, changed, only)` returns `"ALL"` when `forces` matches as it does today (an `"all"` path, or the project asked for with `--project`, or any project without it). Otherwise it returns every spec S for which some changed path satisfies `isInput(ctx, S, path)`, plus every spec with a `ref:` entry in its `inputs.tsv` lines, even when no path changed: selection is stateless and can't see a ref move, so such a spec is always selected and its fingerprint (which holds the ref) decides between reuse and a run.
- On today's rules and an empty `Inputs`, its output is the current `affected.luau` output for every case `tooling/affected.spec`, `c0120/graph-homes.spec` and `c0120/old-roots.spec` pin.
- `inputs.tsv` format: `#` comment and blank lines are skipped. Every other line is `<home-relative spec path>\t<input>`, where input is a repo-relative file, a folder ending `/`, `*`, or `ref:<full ref>`. `*` means every blob plus HEAD: any path change (under a root, a `spend.md` included) selects the spec, and its fingerprint holds every blob plus HEAD. Unrelated branch, tag and remote-ref movement does not invalidate it. `ref:refs/...` adds that one named ref to the spec's fingerprint, and a spec with such a line is selected in every affected run of its project, so ref creation, movement or deletion reruns it through its fingerprint while a still ref reuses the pass. A ref declaration is valid only under `refs/` and follows `git check-ref-format`'s component rules (no empty or dot-leading component, `..`, `@{`, control characters, space, `~`, `^`, `:`, `?`, `*`, `[`, backslash, or `.lock` suffix). The spec path must end in `.spec.luau`. A path input must not be absolute, contain `..`, be a project root itself (one of `roots`, which the callers pass as `rules.roots`, or any path ending in `.tracker`), or be a `spend.md`. A path under a root is allowed: it names tracker files a spec reads as text. A line breaking any rule makes `parseInputs` refuse the whole file with the line number. `affected.luau` and `specs.luau` then exit 2, so the gate fails closed.
- Example (`pickman/tests/inputs.tsv`):
  ```
  # extra inputs per spec: <spec, relative to pickman/>\t<input, relative to the repository>
  tests/acceptance/c0063/narrowed.spec.luau	pickman/.tracker/issues/done/f0031/acceptance/
  ```
  The files ship with the declarations of every spec that reads outside their requires today (design review 002 F2), copied exactly from this issue's `declared/pickman.tsv` (79 lines) and `declared/z-nile.tsv` (230 lines, 15 of them `*`, including c0165's own promoted `docs.spec` reads of `AGENTS.md`, `.gitignore` and `.github/workflows/check.yml`). They came from an audit of all 401 spec files, recorded in Unknowns & experiments (E9) with its searches. AC13 pins that every line of the two lists is in its home's `inputs.tsv`.
  - The classes it found: architecture and fence scans (`src/`, `tests/`, the tracker's `issues/` and `rafts/`); specs that read other specs or source files as text (the narrowed and golden specs); docs and skills pins of root files (`AGENTS.md`, `SETUP.md`, `.github/workflows/`, `pickman/skills/`); fixtures seeded from root files (`.gitignore`, `.claude/`, `pickman/.tracker/architecture.md`); real tracker scans (board, metrics, lessons, layout); and fixture folders read by graph and spend specs.
  - `*`: the 15 z-nile specs that clone the real HEAD, run `done` in a clone (which runs the architecture specs there), read the whole working tree, or read git history (`tracker-lifecycle`, `c0005`, `c0008`, `c0038`, `c0044/naming`, `c0045`, `c0046`, `c0050`, `c0074`, `c0080`, `c0115/layout`, `c0116/promote`, `c0120/finished` and `promote-home`, `tooling/worktree-fetch`). The six narrowed declarations are `c0042/cli` and `c0043/rounds` (both tracker issue/raft trees), `c0116/retired` (both tracker trees plus `pickman/skills/`), `c0120/layout` (`pickman/`, its two decision documents and both tracker item trees), `c0120/old-roots` (the retired and old game roots plus both tracker item trees), and `tooling/board` (both tracker trees). `c0120/finished` stays `*` because its real-tree case uses HEAD history and HEAD's tree. E9's named-ref audit found no shared-ref read among the 15, so no `ref:` declaration ships; refs created inside their own fixtures derive from the fixture content and need none.
  - The cost: those 15 are selected in every affected gate that runs z-nile's specs. Unchanged blobs and HEAD reuse them; unrelated refs moving costs nothing. Any edit reruns them. The specs with tracker-folder entries also rerun on most changes. The measured floor and the stop-hook decision are in E6 and Scalability.
  - New specs: zz-test's **Declared inputs** rule (Wording) says a spec that reads outside its requires declares it. Review checks it, and the full gate learns what it missed (as a file, or the author widens it to a folder or `*`).

### `fingerprint.luau`
```luau
export type Blobs = { [string]: string }  -- repo path -> "<mode> <blob id>" for every file present (tracked + untracked)
export type GitState = { head: string, refs: { [string]: string } }
fingerprint.inputs(ctx: select.Context, spec: string, blobs: Blobs): { string }  -- sorted paths p with isInput(spec, p)
fingerprint.refs(ctx: select.Context, spec: string): { string }  -- sorted full ref names declared by ref:
fingerprint.of(ctx: select.Context, spec: string, blobs: Blobs, tools: string, mode: "affected" | "full", git: GitState): string
fingerprint.digest(blobs: Blobs, tools: string, extra: { string }): string  -- the content digest of a whole gate
```
- `of` is the sha256 (`serde.hash("sha256", …)`) of a text built from these lines, in order:
  - `c0165 v1`;
  - `mode <affected|full>`, the gate mode of the run: a full run's rows never serve an affected run;
  - the spec's repo path;
  - the tools line;
  - one `<path>\t<blob>` line per input;
  - one line per `Inputs` entry of the spec;
  - for a `*` spec only, `HEAD <commit>`;
  - one `<ref>\t<commit>` line per declared ref returned by `fingerprint.refs`, sorted; an absent ref contributes `<ref>\tMISSING`.
- Because the inputs are exactly the `isInput` set, these hold:
  - a modified, added or deleted file changes S's fingerprint exactly when that change alone makes `affected` select S (or `ALL` for S's project);
  - a change under a project root changes only the fingerprints of specs that name that path through an `Inputs` entry;
  - a `*` spec additionally changes fingerprint when HEAD moves, and any spec changes when one of its declared refs moves; unrelated refs never enter a fingerprint;
  - one exception: removing S's own `inputs.tsv` line changes S's fingerprint (its entry lines go), while the new file no longer names S, so the selector doesn't pick it. The cost is one harmless rerun.
- `digest` is the sha256 of `c0165 digest v1`, the tools line, every `extra` entry (mode, projects, base, the learned-inputs text, and affected-mode git state when required below), and every `<path>\t<blob>` of `blobs`. Two kinds of path are excluded: a `spend.md` under a project root (a path under `tracker/`, `.tracker/` or `*/.tracker/` whose last segment is `spend.md`), which `./zn spend` writes after `done`, and every ignored file. The full digest stays content-only: `done` runs before its commit, and CI covers the final head.
- The tools line is `uname -sm`, then `--version` of `lune`, `rojo`, `selene`, `stylua`, `luau-lsp` and `git`, then the sha256 of `.cache/globalTypes.d.luau` (the types the gate downloads), joined by ` | `. A tool that fails to answer gives `<name>?`.

### `workspace.luau` (the reads)
- `workspace.blobs(root): (Blobs?, string?)` builds the blob map (an untracked file's mode is `100755` when it is executable, else `100644`):
  - `git ls-files -s -z` gives the index's mode and blob id for every tracked file;
  - `git ls-files -m -z` and `git ls-files --others --exclude-standard -z` list the files that differ from the index;
  - `git hash-object --no-filters --stdin-paths` hashes those without writing any object (no `-w`);
  - a deleted file is absent from the map;
  - it fails closed: it returns `nil, reason` when any of its git calls fails, when `hash-object` returns a different number of ids than it was given paths, or when any path holds a newline. A missing path in the `hash-object` batch (a file deleted between the two reads) fails the batch, and so the whole read. On `nil`, `specs run` takes "reuse off: <reason>", `record --full` records nothing, `digest` prints nothing (no whole-gate reuse or record), and R31's re-read after a run counts as changed.
  - Nothing it runs writes to the repository's object store or index. A spec pins the absence of `-w`, `add`, `write-tree`, `update-index` and `GIT_INDEX_FILE` in the file.
- `workspace.gitState(root, refs: { string }): (GitState?, string?)` reads `git rev-parse HEAD` and resolves only the requested full refs with `git rev-parse --verify <ref>^{commit}`; a missing requested ref is absent from the map, not an error. Any other failure turns reuse off. The caller builds the requested set from the selected specs' `fingerprint.refs`; per-spec post-run recomputation and the whole-gate digest reread use that same set. It never runs an unrestricted `git for-each-ref`.
- `workspace.tools(root)` returns the tools line.
- `workspace.dbPath(root)` returns `<main checkout>/.claude/.znile_tests.sqlite`. The main checkout is the parent of `git rev-parse --path-format=absolute --git-common-dir`, and the result must end in `/.git`. Any other result gives nil and a reason (a bare or odd layout), which turns reuse off. When `PICKMAN_TEST_FENCE` is set, it also refuses a result without a `/.cache/` segment: a nested orchestrator may write only a fixture's db, never the real checkout's, including on unjailed Linux.

### The db (`resultsdb.luau`)
`sqlite3 -batch -bail -noheader -list <db>`, with SQL on stdin starting `.timeout 10000`. Every call ends with exactly one statement that returns one value, `SELECT json_object(...)`, with rows as `json_group_array(json_object(...))` and the write count as `changes()`, so the output is always exactly one JSON line, `[]` for no rows (E8). `PRAGMA journal_mode=WAL` runs in its own call at `open`, and its output is ignored. The binary is `PICKMAN_SQLITE3` when that is set and not empty, else `sqlite3` on `PATH`. The orchestrator passes it to `open`, as a seam for hosts and specs. The first `open` creates the schema below, in `PRAGMA journal_mode=WAL`:
```sql
CREATE TABLE IF NOT EXISTS meta(k TEXT PRIMARY KEY, v TEXT NOT NULL);           -- ('schema','1')
CREATE TABLE IF NOT EXISTS specs(
  fp TEXT PRIMARY KEY, home TEXT NOT NULL, spec TEXT NOT NULL,
  state TEXT NOT NULL CHECK (state IN ('running','passed','failed')),
  owner_pid INTEGER, owner_start TEXT,      -- the claiming run (running), or the recording run
  cases TEXT,                               -- JSON [{"name":..,"ok":true}], the file's cases in order
  detail TEXT,                              -- the run's FAIL lines for this file (failed)
  seconds REAL, updated INTEGER NOT NULL);  -- unix seconds
CREATE TABLE IF NOT EXISTS gates(key TEXT PRIMARY KEY, mode TEXT NOT NULL, projects TEXT NOT NULL,
  passed_at INTEGER NOT NULL, summary TEXT NOT NULL);      -- summary: the static stages' report
CREATE TABLE IF NOT EXISTS learned(home TEXT NOT NULL, spec TEXT NOT NULL, input TEXT NOT NULL,
  found_at INTEGER NOT NULL, PRIMARY KEY (home, spec, input));
```
```luau
export type Owner = { pid: number, start: string }
export type Row = { state: "running" | "passed" | "failed", pid: number?, start: string?, cases: { Case }?,
  detail: string?, seconds: number?, updated: number }
export type Case = { name: string, ok: boolean }
resultsdb.open(path: string, binary: string?): (Db?, string?)  -- nil + reason: no sqlite3, unwritable, schema not '1'
resultsdb.rows(db, fps: { string }): { [string]: Row }
resultsdb.claim(db, fp, home, spec, owner: Owner, expect: Row?): boolean
resultsdb.record(db, fp, home, spec, owner: Owner, cases: { Case }, detail: string?, seconds: number, now: number,
  expect: Row?)  -- expect: full mode's compare-and-swap against the row it read
resultsdb.release(db, fp, owner: Owner)
resultsdb.gatePassed(db, key): { passedAt: number, summary: string }?
resultsdb.recordGate(db, key, mode, projects, summary, now)
resultsdb.learned(db): { [string]: { [string]: { string } } }  -- home -> spec -> inputs
resultsdb.learn(db, home, spec, input, now)
resultsdb.prune(db, now)                              -- specs rows not updated for 30 days, gates for 30 days
```
- `claim` with `expect == nil` is an insert that fails if the row exists. With `expect` set it is a compare-and-swap, `UPDATE … WHERE fp=? AND state=? AND owner_pid IS ? AND owner_start IS ?`. It returns true only when `changes()` is 1, so two claimers of one fingerprint never both win (E3).
- `record` writes `passed` when the file loaded and every case passed, and `failed` otherwise. It writes only when the row is absent or is `running` with this owner. A full run, which claims nothing, passes `expect` from a `rows` read and writes through the same compare-and-swap. It never overwrites a row that a live other owner is running.
- Every text value goes in as an SQL string literal with `'` doubled, which no path or case name can escape (a spec pins quotes, newlines and `--`). Numbers are written with `%d` or `%.3f`.
- `open` creates the db's folder (`.claude/`) when it is missing.
- `open` failing (no `sqlite3` on `PATH`, `.claude/` unwritable, as in an outer sandbox, or a corrupt or newer schema) is never a gate failure. The orchestrator prints `reuse off: <reason>` and runs every spec it was given, records nothing and learns into nothing (it still prints learned lines).

### `reuseplan.decide`
```luau
export type Action = "reuse" | "run" | "wait"
reuseplan.decide(row: resultsdb.Row?, fresh: boolean, holds: (pid: number, start: string?) -> boolean): Action
```
| row | fresh | holds | action |
|---|---|---|---|
| nil, `passed` or `failed` | true | - | `run` (claim: insert or compare-and-swap) |
| `running` | either | true | `wait` (fresh never steals a live owner) |
| `running` | either | false | `run` (take over: compare-and-swap on the dead owner's pid and start id) |
| nil | false | - | `run` (claim: insert) |
| `passed` | false | - | `reuse` |
| `failed` | false | - | `run` (claim: compare-and-swap) |

`holds` is `fence.holds(fence.aliveOuter(pid), start, fence.startOf(pid))`, the lock's own start-id rule with an orchestrator-safe liveness probe. The new `fence.aliveOuter` export counts every EPERM from `kill -0` as alive, even outside the runner's jail; the runner's existing `fence.alive` behavior is unchanged. If `startOf` cannot be read, `holds` stays true and the wait timeout is the safe fallback. Results-file sweeping uses `aliveOuter` too.

```luau
reuseplan.records(jail: string, os: string): boolean
```
Whether a run's results may be recorded: true for `sandbox-exec`, for the nested-fixture jail text `outer sandbox (a fixture of a guarded checkout)` on macOS, and for an unjailed run on a host that isn't macOS (`os ~= "macos"` and the jail starts with `none`). False otherwise: any other outer sandbox, no jail on macOS, or an empty jail. When it is false, the run records nothing, not even failures, and releases its claims. `jail` is the `PICKMAN_TEST_JAIL` value the runner wrote into its results. A gone pid, or a pid reused by another process (its start id differs), no longer holds.

### `specs.luau run` (the orchestrator)
`lune run z-nile/specs -- run --project <name> [--fresh] [--all | -- <home-relative spec>...]` (affected mode) and `lune run z-nile/specs -- record --project <name> --full --results <file>` (full mode), both run from the repository root, as `check.sh` runs them.
- **Owner**: its own pid (`fence.myPid()`) and start id (`fence.startOf`).
- **Lifeline**: the orchestrator never starts the runner directly. It starts an inline perl supervisor (as `fence.luau`'s `REAPER` is inline), which first leads a **process group of its own** (`setpgrp`), so a kill of the orchestrator's group, even with SIGKILL, never reaches it. The supervisor then forks the runner into that group. It polls once a second whether the orchestrator is still its parent (`getppid` unchanged); when it isn't, it sends TERM to every other member of its group, waits 2 s, sends KILL, and exits. When the runner ends first, the supervisor exits with its code. So a runner outlives its orchestrator by at most about 3 s, whether the orchestrator's pid or its whole group was killed. Killing only the supervisor's own pid can still orphan the runner; that residual gap is named, not hidden. The supervisor's KILL can also skip the fence launcher's `.cache` symlink cleanup; `check.sh`'s next-start unlink covers it. The runner's lock is then held only by dead processes, which the lock's takeover already handles. On start, the orchestrator removes every `<home>/.cache/spec-results-<pid>.json*` whose pid no longer holds (`fence.aliveOuter`). (Design review 002 F1: a supervisor in the orchestrator's own group died with it, orphaning the runner.)
- **Affected mode** (no `--full`; `--all` stands for every spec file under the home's `tests/`, used when the selector says `ALL`):
  1. Open the db; on failure, go to "reuse off". Read the blob map, git state, tools line and context (graph, `inputs.tsv`, the db's learned inputs), and compute each spec's fingerprint.
  2. `rows`, then `decide` per spec. Each `reuse` prints `reused <spec>` and adds its stored case counts. Each `run` claims, and a lost claim becomes `wait`.
  3. Run the claimed specs: `lune run tests/run -- <specs>` from the home, through the lifeline above, with `PICKMAN_RESULTS` set. The runner's output is forwarded as it comes (`stdio = "forward"`), so a long run shows its progress. Then read the results file, which holds every file's cases, its `FAIL` text (its `detail`) and the run's jail (below):
     - **Only a runner exit of 0 records `passed` rows.** A non-zero exit records only the files its results show failed. When the results show no failure, the orchestrator prints `runner exited <code>: <n> results not recorded` and counts the run failed: the browser guard and the tripwire fail a run only through the exit code, after every spec passed.
     - **Only a run in the host's strongest jail records anything** (design review 002 F3): `sandbox-exec` on macOS, the unjailed default (`none …`) elsewhere, or the exact nested-fixture jail text. A run in another outer sandbox reads rows and reuses, but records nothing and prints `not recorded: <jail>`, because the guard specs' jailed cases return early there. When `check.sh` sets `PICKMAN_GATE_PID`, it also writes `<home>/.cache/spec-norecord-<gate pid>`; `gate-record` refuses while that marker exists, and `check.sh` removes it.
     - A spec whose fingerprint, computed again from fresh blob and git-state reads after the run, differs from the one it was claimed under (its inputs changed during the run) is released and not recorded; its result still counts.
     - Otherwise each listed file is recorded `passed` or `failed`, with its cases and `detail`.
     - A claimed file the results don't list (the run was killed, or the runner crashed) is released and counted failed, with `FAIL <spec>: results file missing` (no file) or `FAIL <spec>: no result for it` (a file that doesn't list it).
     - The results file is then removed.
  4. Waiting: print `waiting for pid N: <spec>` once per waited spec, then poll every second with one db read for all of them and one liveness check per distinct owner (not per spec), and print `still waiting (<s>s): <n> spec files, pids <list>` every 60 s. A row that becomes `passed` is reused (`reused <spec> (waited for pid N)`). A row that becomes `failed` counts as a failure and prints its stored `detail` with `failed in pid N`. A row whose owner no longer holds, or that was released, is claimed, and step 3 runs it. The wait stops after `PICKMAN_REUSE_WAIT` seconds (default 1800). A spec still waited on then prints `gave up waiting for pid N after <s>s: running <spec> unclaimed`, is run without a claim, and its result is not recorded.
  5. Print `reuse: <r> reused, <w> waited, <n> ran`, then the runner's summary form: `<passed> passed, <failed> failed, <files> spec files`, totals over all three. Exit 0 only when nothing failed.
- **Full mode** is not `run`: `check.sh --full` keeps running each home's specs itself, exactly as today (`(cd <home> && lune run tests/run --)`, every spec, a promoted pin of `c0120/gate-homes.spec`), with `PICKMAN_RESULTS=<home>/.cache/spec-results-<check.sh pid>.json` added. It keeps the runner's exit status instead of letting `set -e` stop the gate, then calls `lune run z-nile/specs -- record --project <name> --full --results <that file> --digest <d> --projects <picked, sorted, comma> --exit <the runner's exit code>` from the root (the projects, to compute the same digest; the exit code, so only an exit of 0 records passes). `record --full` does three things:
  - it records, from a runner exit of 0 only (a non-zero exit records only failures) and only when `reuseplan.records` allows the run's jail, every listed file's result, without claiming and never over a live other owner's `running` row, and only when the content digest it computes equals `--digest <d>`, the digest `check.sh` read before the specs ran (a tree that changed during the run records nothing and says so). A weak jail writes the same no-record marker as affected mode, so the companion `gate-record` cannot bypass the jail condition;
  - it learns (below) when anything failed;
  - it removes the results file.
  The gate then exits with the runner's status. A full run never reads a fingerprint's result and never waits, and it still prunes `spec-durations.tsv`, because the runner gets no file arguments.
- **`--fresh`** (affected): `decide` runs nil, passed and failed rows, but waits for a live running owner rather than stealing it. It still claims, so a concurrent reusing run waits for it, and it still records.
- **Reuse off**: run the given specs (or all of them) in one `tests/run`, record nothing, and print `reuse off: <reason>`.
- **Nested runs**: when `PICKMAN_TEST_FENCE` is set, the orchestrator is inside a spec run (a fixture's gate), and `dbPath` must resolve below `.cache`, to the fixture's own main checkout. A path outside `.cache` turns reuse off even on unjailed Linux, so a nested orchestrator cannot write the real checkout's db.

### Learning a missed dependency (full mode)
After a full run with failed spec files `F` for project `n`:
1. `changed = changes.files(nil)`, the same change set and base that `--affected` uses (merge base with `origin/main`, else `main`; the working tree; untracked files). If it is empty (CI on `main`), stop.
2. `sel = select.affected(ctx, changed, n)`. If `sel == "ALL"`, stop: every spec was selected, so nothing was missed. The misses are `F \ sel`. A failed spec that was selected is an ordinary failure and learns nothing, but it still gets trial (b) below, report only, so a red `main` is told from a failure the change caused (user decision 2026-11-03: red `main` shows at `done`).
3. For each miss S, the candidates are the changed paths, sorted, except every `spend.md` (paths under a project root included, since specs read tracker files as text). None of them is an input of S, or S would have been selected. With no candidate left, it prints `not learned: <home>/<S>: no candidate outside spend.md`. Trials run in one clone per gate, `<root>/.cache/learn-<pid>`:
   - `git clone -q --no-hardlinks --no-checkout <root> <dir>`, then `git -C <dir> remote remove origin` (the trials need no remote, and none points at the real repository) and `git -C <dir> checkout -q --detach <base>`;
   - each trial runs with `PICKMAN_FENCE_REAL_GIT=<the real repository's common dir>`, so the trial runner's ref guard also names the real repository where no jail covers it (Linux);
   - a candidate is applied by copying the working-tree file over, or deleting it if it was deleted;
   - each trial is `lune run tests/run -- <S>` from `<dir>/<home>`, whose runner fences and jails the clone itself.
   The plan (`learn.plan`) is:
   - (a) all candidates applied: S must fail, or it is `not reproduced in a copy`;
   - (b) the base alone: S must pass, or it is `fails on the base too: not a graph miss`. A failed spec that was selected gets (b) alone, within `PICKMAN_LEARN_BUDGET`; if it fails on the base it prints `fails on the base too: main is red` and nothing is learned, and if it passes on the base nothing is printed;
   - (c) the base plus one candidate at a time, at most `PICKMAN_LEARN_MAX` trials per miss (default 16). The whole gate also has a budget, `PICKMAN_LEARN_BUDGET` trials in all (default 40, trials (a) and (b) included). A miss whose plan would exceed what is left is not tried, and prints `not learned: <home>/<S>: learning budget spent`. In the trials: every candidate for which S fails is an input. If none fails alone, or the cap is hit, every candidate is an input, and the line says `unbisected`.
4. Each input is recorded with `resultsdb.learn`, so the next affected run in every worktree selects S for it. The gate also prints, for the author to commit:
   ```
   graph miss: <home>/<S> depends on <input>
     add to <home>/tests/inputs.tsv:  <S>\t<input>
   ```
   A miss that teaches nothing prints `not learned: <home>/<S>: not reproduced in a copy` or `not learned: <home>/<S>: fails on the base too: not a graph miss`.
   The clone is removed. The gate's result is unchanged: S failed, so the gate fails.
5. `learn.luau` is pure: `misses(failed, sel)`, `selectedFailures(failed, sel)` (the failures `misses` leaves out: all of them when `sel` is `"ALL"`), `plan(candidates, max, budget?)` and `inputs(results)`. `plan` returns the trials and the budget left. A plan that doesn't fit is empty and spends nothing: all of (a), (b) and every (c) trial when the candidates are within `max`, else (a) and (b) alone. A nil budget means no total cap, and `nil` comes back. The adapter steps live in `specs.luau`.
- Changes stay out of the real repository: the clone is read from the real repository and lives under `.cache`. Nothing writes the real worktree, its index, refs or objects. A `.cache` clone is not a worktree, so the tripwire's worktree check doesn't apply.

### Whole-gate reuse (`check.sh`)
- These steps run after `--plan` has exited, so `--plan` still runs and writes nothing. A gate-check counts only when its first stdout line is `reused <passed_at>` and it exits 0. An empty digest, as from a stubbed `lune` (`c0120/gate-homes.spec`), reads as no reuse and no record. A tool that prints nothing therefore never skips a gate.
- After the fence, the prerequisites and the types download (the tools line hashes `.cache/globalTypes.d.luau`, which the first gate on a checkout downloads), before the sourcemap and the static stages, and when `--fresh` is not given, `check.sh` reads `digest=$(lune run z-nile/specs -- digest --mode <m> --projects <picked, sorted, comma> [--base <merge-base sha>])`. The base is affected mode's.
  - `--affected`: `gate-check` looks the digest up in `gates`. If a gate passed there before, it prints `reused: an affected gate passed on this content at <time>`, then the static stages' report stored with that row (every `== <stage>` header and its output, so the lint summary zz-execute Phase 4 reads is still there), then `GATE PASSED (affected)`, and exits 0. The digest's extra includes HEAD when the selection holds a `*` spec and the union of every selected spec's declared refs; an unrelated ref cannot invalidate the gate.
  - `--full --reuse`: the same with mode `full`. Only a full gate that ran every spec writes a `full` row. Its digest stays content-only, so `done`'s pre-commit run matches the committed head; CI covers git-state-dependent specs on that final head.
  - `--full` without `--reuse`: it never reads `gates`. This is what `land`, `done`, CI and `setup.sh` run, and their command lines stay as they are.
- At the end, after the last stage passed, it computes the digest again. If it is unchanged and no `<home>/.cache/spec-norecord-<gate pid>` marker exists, `gate-record --digest <d> --summary <file>` writes the row with the static stages' report. `check.sh` sets `PICKMAN_GATE_PID=$$` for the orchestrator and recorder, runs `par_wait` into a temp file, prints it, fails on its status as before, and passes the file. It removes every marker on exit. A tree that changed during the gate, or a weak-jail spec run, records no whole-gate row.
- The digest's `extra` is the mode, the projects, the base sha (affected), the learned-inputs text from `inputs.tsv` and the db because a new learned edge changes what affected selects, and affected-mode HEAD/ref state when the selection holds a `*` spec.
- `--reuse` without `--full`, or `--fresh` with `--full`, exits 2 (`unknown or conflicting flags`).

### Runner results (`tests/run.luau`)
- When `PICKMAN_RESULTS` is set to an absolute path under this run's own home's `.cache`, the in-process loop collects a record for every file it ran: `{ file, loaded, cases = { {name, ok} }, detail, seconds }`, where `detail` is that file's `FAIL` text (empty when it passed). It writes `{ jail = <its PICKMAN_TEST_JAIL, or "">, files = { … } }` as JSON (`serde.encode("json", …)`) to that path, through a temporary file renamed over it.
- The coordinator gives each worker `PICKMAN_RESULTS=<path>.<index>` and, after the lanes, merges every part into `<path>`. A worker that wrote no part makes its file `loaded = false`.
- Any other value is ignored without a word, and nothing is written. A nested run inside a spec inherits the orchestrator's value (Lune can't clear a variable for its children), which names another home's `.cache`, so it writes nothing and prints nothing. A wrong value set by hand shows as every claimed file counted failed, with `results file missing`. The runner's printed output and exit code stay exactly as they are.

### Scalability
- Fingerprints: `git ls-files -s` lists the ~2,300 relevant files in about 10 ms (E4). `isInput` over 390 specs and 2,300 paths is about 900k checks against precomputed closure sets, well under a second in Lune (E6 measures it on the prototype).
- The `*` floor is measured, not waved away: `c0120/finished` has recorded 132–149 s idle and 256–754 s under load; `c0116/retired` has recorded 30–564 s. One spec file is one lane, so either can exceed the stop hook's 300 s timeout. Per-spec HEAD-plus-declared-ref fingerprints make identical runs reusable, but do not remove the rerun on an actual edit. Author→reviewer reuse now survives pushes, fetches and unrelated worktree commits for every `*` spec and for the affected whole-gate digest; only HEAD or a ref the spec actually declared can invalidate it. Design choice (2026-10-31): the stop hook derives one project list through `select.gateProjects` and invokes one affected gate with that union. Pickman-only edits avoid z-nile's floor; z-nile edits retain it and can still exceed the hook timeout under load. Shared tooling and old roots keep their forced coverage, and no required spec is dropped from the all-project affected or fresh full gates.
- The db holds one row per fingerprint. Pruning after 30 days keeps it to thousands of rows. Batch reads and writes go through one `sqlite3` call per phase, not one per spec.
- Learning runs only on a full-gate failure that the selector missed, and is capped at 16 one-spec trials per miss.

### Maintainability
- One predicate (`isInput`) feeds selection and fingerprints, and AC1 pins that the two agree, so a new rule in the selector can't leave the fingerprint behind.
- One reader per format: `select.parseInputs` for `inputs.tsv`, `context.luau` for the inputs (`inputs.tsv` through `select.parseInputs`, plus the db's learned rows), `resultsdb` for the db, and the runner's JSON results read only by `specs.luau`. Pure modules (`select`, `fingerprint`, `reuseplan`, `learn`) are tested in process. The adapters (`resultsdb`, `workspace`, `specs.luau`) are tested against a db and a repository under `.cache`.

### Usability
- Every reuse decision is printed: `reused <spec>`, `reused <spec> (waited for pid N)`, `reuse off: <reason>`, and the whole-gate `reused: … at <time>`.
- `--fresh` forces a fresh affected gate, and a full gate is always fresh unless `--reuse` is given.
- A graph miss prints the line to commit. Deleting the db is always safe: it costs only reruns.

## Acceptance criteria

### Checked
- AC1: one predicate decides both selection and fingerprints: for every seeded change kind, a change alters a spec's fingerprint exactly when it makes the selector pick that spec, and the moved rules give the old CLI's output on every pinned case.
- AC2: a spec's fingerprint changes for its own file, a file it requires, a place library's src, a forcing file of its project, an `inputs.tsv` or learned entry (file and folder, a tracker path under a root included), the tools line and the gate mode, and stays the same for undeclared tracker documents, `spend.md`, another project's forcing file and unrelated files; HEAD additionally changes a `*` spec, a declared ref changes its declaring spec, and unrelated refs change neither.
- AC3: `reuseplan.decide` gives the table's action for every row, and a gone or reused pid doesn't hold.
- AC4: the db claims by insert or compare-and-swap (one winner of two), records only into its own or an absent row, round-trips any text, and `open` returns nil with a reason for a missing sqlite3 or a wrong schema.
- AC5: through the gate, a second affected run on the same content reuses every spec and runs none; an edit reruns exactly the specs that change selects; two concurrent runs run each spec once and both report every result, a failure included; a fresh run waits for a live owner, and EPERM never makes a live owner look dead; a killed owner's spec is taken over and its runner dies with it; only a runner exit of 0 records passes, a claimed spec with a missing or omitted result counts failed, and stale results files are swept; a weak-jail run records neither spec rows nor a whole-gate row; with reuse off (no sqlite3, a failed blob read) every spec runs and the gate's result is unchanged.
- AC6: with `PICKMAN_RESULTS` set, the runner writes every file's cases and results, in process and concurrently, marks a crashed worker's file not loaded, and its printed output and exit code are unchanged.
- AC7: `check.sh --full` runs every spec even when every fingerprint passed; `--full --reuse` skips only on a full record of the same content digest, done's staged tree included; a gate whose tree changed while it ran records nothing; an affected whole-gate digest includes HEAD for a `*` selection and every selected declared ref, but no unrelated ref; the digest ignores `spend.md` and ignored files and changes for anything else; the workspace reads write nothing to git and fail closed, and a nested db path outside `.cache` is refused.
- AC8: on a seeded graph miss, a tracker file's included, the full gate fails, records the dependency in the db, prints the `inputs.tsv` line, and the next affected run (`--learned`) selects the spec while a bare `affected` doesn't; a spec that also fails on the base is not learned; learning considers only failures the selector didn't pick, within a total budget; a spend-only miss or an insufficient budget runs no trial and prints its reason.
- AC9: `inputs.tsv` parses comments, blank lines, files, folders, `*` and full `ref:` declarations, and refuses the whole file on a malformed line or ref.
- AC10: the skills, the prompt template, the raft template, `AGENTS.md` and `.gitignore` say the new gate modes and name the db; Phase 0 runs no gate; the stop hook makes one affected gate call for the selector-derived project union, keeps pre-c0114 fallback, and propagates a gate failure.
- AC11: no promoted spec changes except the six Overrides and c0165's own folder.
- AC12: each of the four template Overrides changes only its RC0 line, to `--affected`, and the two selector Overrides change only by `"--graph-only"` placed right after `"--"` in their one `affected` helper; each keeps everything else it pins byte for byte.
- AC13: every line of `declared/pickman.tsv` and `declared/z-nile.tsv` is a line of `pickman/tests/inputs.tsv` and `z-nile/tests/inputs.tsv`, and each home's file parses.
