# Refute 002: c0165 (design review 002)

- F1: fixed (the mechanism changed, as the finding asked). The supervisor now leads a process group of its own (`setpgrp` first), so no kill of the orchestrator's pid or group reaches it. It forks the runner into its group, and kills the rest of that group about 3 s after its parent is gone (R45). The hold is now a marker, not a sleep: `hang.spec` holds only while `hang.marker` exists and its run has `C0165_HOLD=1`, for at most 600 polls of 0.1 s. Two cases now assert, while the marker still holds, that the runner (the pid its spec logged) is gone within 8 s: one after `kill -9 -- -<orchestrator group>`, one after `kill -9 <the orchestrator pid the db row names>`. In both, the next run then takes the spec over. consequences: a runner killed by the lifeline skips its own cleanup, so its lock is held only by dead processes (takeover handles it) and its run recorded nothing.
- F2: fixed: both homes' `inputs.tsv` ship the declarations of every spec that reads outside its requires today, from an audit of all 401 spec files (E9, its searches pasted): 79 pickman lines and 199 z-nile lines. The audit also found a class that no path's content shows, 21 z-nile specs that clone the real HEAD, run `done` in a clone, or read git history. Those get a new entry, `*` (always run: any change selects the spec, and it is never reused), R52. The lists live in the issue's `declared/` folder, and AC13 pins every line in its home's file and that each file parses. zz-test gains the **Declared inputs** rule for new specs (Wording, docs.spec). gate-learn has a case where a declared folder entry selects its scanner for a file added later and changes its fingerprint (R46), and the `*` case. consequences: the 21 `*` specs run in every gate that runs z-nile's specs, and the specs with tracker-folder entries rerun on most changes. That cost is stated in the Design, and it is the price of not reusing what these specs' inputs don't show. The `*` parse rule and its isInput case are in select.spec.
- F3: fixed: the runner writes its `PICKMAN_TEST_JAIL` into the results file, and `reuseplan.records(jail, nested, os)` decides whether to record. A nested run (a fixture's own db), `sandbox-exec`, and an unjailed run off macOS record; an outer sandbox on macOS (or no jail there) reads and reuses but records nothing, and prints `not recorded: <jail>` (R47). plan.spec pins the function's table and results.spec pins the jail field. consequences: a session in the main checkout (an outer sandbox) gets reuse but adds no rows, and runs that do record are ones in which the guard specs' jailed cases actually run.
- F4: fixed: gate-reuse "a whole-gate record is scoped by its projects and its base". The same content is not reused for every project after a pickman-only record, nor for `--base HEAD` after a record against the default base (R48).
- F5: fixed: every overlap is now made by markers. `gatefix.together` holds both runs' specs on `hold.marker` and removes it only once either run prints `waiting for pid`. `gatefix.owner` holds the owner on `hang.marker` with `C0165_HOLD=1`, which the waiter doesn't have. No case rests on a sleep. Each hold is bounded (60 s), so a wrong implementation fails a case instead of hanging the suite.
- F6: fixed: the runner's output is forwarded live, `detail` comes from the results file (a new per-file field, pinned by results.spec), a wait prints `waiting for pid N: <spec>` at once and `still waiting (<s>s): …` every 60 s (R49). The concurrent case depends on the wait line, since its marker release waits for it.
- F7: fixed: the wait loop reads the db once per poll for every waited spec, and checks each distinct owner once (R50, reasoned: a cost, not a result).
- F8: fixed: zz-test's "Affected selection" gains the **Declared inputs** sentence (the format, the root rule and `--learned`), pinned in the Wording list and docs.spec.
- F9: fixed: gate.spec is split by mechanism into gate-reuse, gate-wait, gate-full and gate-learn, with the fixture builder in a shared `gatefix.luau` beside them (required as `./gatefix`, as c0154's specs require their `durations.luau`). Each file has its own `.cache/c0165-gate-<name>` folder. The runner runs the four in parallel lanes, so none holds the gate open for the whole sum.
- F10: fixed: the learning clone drops its `origin` (`git remote remove origin`), and each trial runs with `PICKMAN_FENCE_REAL_GIT` naming the real repository (R51). gate-learn's seeded-miss case asserts that the fixture's refs are unchanged by learning.
- F11: fixed: affected-mode step 3 is rewritten as ordered steps (the run, the results read, the exit-0 rule, the jail rule, the re-fingerprint, the records, the missing results). `cachepaths.luau` is in the Modules table. The AC1 sentence in the Regression guard says what the case does. R30 is split into R30a (reasoned, the timeout) and R30b (run, nothing recorded over the live owner).
