# Refute 001: c0166

- F1: fixed: a design or code review keeps the lessons of the skills that mode exercises (`z-design`, `zz-review` and `zz-test` for design; `zz-execute`, `zz-review` and `zz-test` for code and stream; `z-raft` and `zz-review` for a raft), and `@item` on `acceptance`, `check-sh`, `checks`, `fixtures`, `mutants`, `mutation` and `specs` matches the item folder, which `--for` adds to the query. E1's "about a third" pass condition is retired. E3 replayed harvested design-review lessons on repository-relative Touched lists: 115 of 118, 97.5 percent, above the 90 percent bar. The three misses are zz-arch lessons. Adding zz-arch to every design review would keep 123 of 129 on a maze review, so that fallback is not taken. Consequences: a maze design review keeps 98 of 129, 82 of them the exercised skills. That is the cost of outcome (a). The fallback if a later count falls under 90 percent is to add the missed skill to that mode and record the new maze count, not to drop a captured outcome.

- F2: fixed: c0117's pin includes the closing backtick. The backticked command stays `` `./zn lessons --when design --full` `` and `` `./zn lessons --when build --full` ``. A following sentence names the filtered command, and the executor runs that one. The Chore checklist states the pin with the backtick. Overrides stays none. Consequences: whichever raft lands second, the pin and the filtered command are different sentences, so neither has to edit the other's spec.

- F3: fixed: a Touched path whose first segment is neither a project name in `projects.toml` nor a root-level file the area table names (`AGENTS.md`, `zn`) warns `warning: <id> Touched path <p> is not repository-relative; no path filter` and the item is not filtered. `buildLessons` uses the same rule and does not warn. Consequences: one bad path opens the filter for the whole item, which keeps lessons instead of dropping them.

- F4: fixed: a loop is one issue's design reviews, one raft folder's own design reviews, one member's design reviews, or one raft folder's code reviews. Counts are not summed. `--rounds` exits 1 only when one of those loops is at least 5 without a bullet and note for that loop. R0061 and R0062 are not reported. Consequences: a member that itself reaches 5 is still reported, on its own line.

Consequences: none beyond the case. The old "check rewritten" label is gone, so a report that always says rewritten no longer matches.

- F6: fixed: the comparison is ledger source counts against `git merge-base HEAD origin/main`. `./zn lessons --uncovered <id>` reports a stale check, `./zn lessons --stale` reports only that and an unparseable lesson, and `z-nile/check.sh` runs `--stale`. `./zn commit` uses the same function. The z-design sentence names `--uncovered` and `--stale`, not a refusal that prep cannot run. Consequences: the gate walks the delta once per run.
