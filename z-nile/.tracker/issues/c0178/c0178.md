# c0178: Shared fixture images

## Problem
As captured (2026-10-31): spec fixtures are built from scratch per spec (four repos, ~243 tooling files each as loose objects); build packed images once and clone them, to cut file churn and processes.

The user (2026-10-31), after a full gate pegged fseventsd at a whole CPU core: "This is not acceptable. Find a better solution. Test has to be thorough and complete but also very fast and efficient." And (2026-11-24), after 40-second jobs took 5 to 15 minutes while several workers gated: "why have we built a bottleneck into the process? Can that not be removed".

Measured (c0179, merged as #791, 2026-11-24): one full gate (`z-nile/check.sh --full`, 385 s) makes **1,929,894 file events** under its worktree, **1,927,831 (99.9%) under `z-nile/.cache`**: the Lune spec fixtures. `fseventsd` spends about 124 CPU-seconds on one gate, Spotlight more. A volume's markers (`no_log`, `never_index`) do not make a file cheaper (c0179 E3, E4); fewer files and detaching a volume instead of removing its files do (c0179 E8: removal is half of all events).

What should happen: a fixture costs a few files and processes, not thousands, with every spec case kept and every guard still in force.

Decided with the user (2026-10-31): fewer files **and** a fixture volume fseventsd ignores (c0179); every case stays (thorough and complete).

## Non-goals

## Solution
1. **Clone, never rebuild** (slice 1, this ticket's contract now): `trackerfix.new` makes its fixture by one whole-tree `clonefileat(2)` of this run's packed template (built once per run, lessons choice and tooling state), rewrites the nine files that name the template's path and checks them, and then gives the fixture its own identity and seeded files with one amended seed commit, so a spec sees what it sees today.
2. **The volume** (was slice 2): deferred to its own ticket, decided with slice 1's full-gate and slow-tier numbers (design review 005 F20, G9). Its experiments stay below as evidence.
3. **The user's 2026-11-01 scope** (the ten hand-built fixtures; the repository-cloning specs), the captured "and processes", and how the ticket is split and rafted are the owner's (Open to the human). Until the owner answers, slice 1 is built and merged as progress and the ticket stays open: slice 1 has criteria and a `check.sh` of its own that can pass alone (AC1 to AC6).

## Design

### What the experiments decided (summary; the numbers are in Unknowns & experiments)
- The fixture helper to cut is `trackerfix.new`, and only it: its fixtures (plain, and inside `netfix.world`) hold **98.9%** of the entries the suite leaves under `z-nile/.cache` (E1). 94 spec files under `z-nile/tests` build one: **47 fast tier, 47 slow tier** (`z-nile/tests/slow.tsv`). They are found by the helpers that build one, `trackerfix.new` itself and every helper that calls it (`git grep` over `z-nile/tests/lib`: `netfix.world` and `fakecli.new`; no helper calls either), then their callers: the pattern `trackerfix\.new\(|netfix\.world\(|fakecli\.new\(`. (The 2026-11-24 count, 87 = 43 + 44, missed `fakecli.new`: code review 001 F1.) The repository-cloning and hand-built four-repository specs are slow tier, outside the full gate's 1.93 million.
- A trackerfix fixture is about 7,983 entries; 61% loose objects, 37% the three checkouts (E2). Building it costs about 10,450 file events (E9: 8,941 a fixture on average over ten with lessons and five without).
- One `clonefileat` of a template, plus the rewrite, costs about 40 events per fixture (E2); the whole of slice 1's fixture (clone, rewrite, refresh, identity, amended seed commit, push, fetch, reset) costs about 170 events cold (E9: 169 a fixture over fifteen, the two templates 11,811 together) (E9); it works inside the spec jail (E4), never shares an inode or a write with its template (E3), fails across volumes (`EXDEV`, E6) and on a full volume with `ENOSPC` leaving no destination (E10).
- With slice 1 (packed template, index refresh, packed pushes into the origin) the steady-state events of the three heaviest spec files fall by 77%, 61% and 58% (E5).
- Processes: a fixture starts 88 processes today and about 76 (74 measured with the simulation, plus the tooling key and the after-clone `find`) with slice 1's simulation (E9, counted by shims on `PATH`); the cut of processes is not this slice's (Open to the human, question 2).

### Slice 1: `trackerfix.new` from a per-run template
**Shared and per case.** What is shared is one **template** per (run, lessons choice, tooling state); everything else is per case, as today. **No spec may write into a template it did not build**; `trackerfix.TOOLING` and `trackerfix.template` exist so a spec that must damage a template builds a private one (design review 005 F1).
- *Where and named how*: `<home>/.cache/fixture-templates/<run>-<lessons|nolessons>-<key>`, where `<home>` is `fixture.physical(".")` as for a fixture's base, `<run>` the basename of the run's own temp folder when it matches `pickman-run.<letters and digits>` (fresh per run, the same for every worker of the run, a nested run having its own) and `proc-<pid>` otherwise (no sharing outside a runner), and `<key>` the first 12 hex digits of the tooling key. Build folders are `<template>.build.<pid>-<n>`, folders being removed `<template>.gone.<pid>-<n>`, the copy markers `<run>.copied.<pid>`: this grammar is all the sweep ever touches.
- *What it holds*: `origin.git`, `main` and `other` exactly as `trackerfix.build` makes them (today's builder, kept) for a fixture named `fixture-template` with no seeded files, except: the seed's objects are packed (`git repack -adq` and `git prune-packed` in the seed before the bare clone), the seed folder is not kept (no spec or engine file reads `<base>/seed`: design review 005's probe of 151 files), the bare origin has `receive.unpackLimit=1` in its local config (pushes land as one pack; the checkouts' own configuration is untouched), and `.fixture-stamp` at its top, written last.
- *The tooling key*: one `perl` walk (`File::Find`, `Time::HiRes::lstat`, `Digest::SHA`) of what `engine.copy` copies from `trackerfix.TOOLING`: `zn`, `scripts/` and `z-nile/` without its top-level `.tracker`, `next`, `compaction.txt`, `tests` and `.cache`; each entry's relative path, mode, size and mtime (no file is read; about 1,000 `lstat`s). Called on every `trackerfix.new`, so a tooling file changed after the template was made gives the next fixture a new template, as a fixture today copies the tooling at its own time (G2).
- *Who builds it, when*: lazily, the first `trackerfix.new` that needs it in any worker of the run, inside the jail: `trackerfix.build("fixture-templates/<build name>", nil, opts)` semantics into `<template>.build.<pid>-<n>`, pack, drop the seed, set the origin's limit, rewrite the build's own nine path-naming files to the final path, then the **build check** (design review 005 F8): `grep -rlF -e <build path>` over the build must find nothing and `grep -rlF -e <final path>` must find exactly `trackerfix.REWRITE`, else the build is removed and `trackerfix: template <final> names its path in <files>: the rewrite list is <list>` is raised. Then `.fixture-stamp` is written, last, and the build is published by `fs.move(build, final, false)`; a worker that loses the rename removes its build and uses the winner's.
- *The sweep* (F9 c): the first template a process resolves first sweeps `<home>/.cache/fixture-templates`, only if `perl -e 'exit(-d $ARGV[0] && !-l $ARGV[0] ? 0 : 1)'` says it is a real folder: every entry of the grammar whose `<run>` is not this run's (and every `.gone.` entry) is renamed to `<entry>.gone.<pid>-<n>` (a rename that fails because another worker won it is skipped) and the renamed folder is removed (`fs.removeDir` in a `pcall`); copy markers of other runs are removed. Nothing outside the grammar is touched. `trackerfix.new` refuses a name whose first segment is `fixture-templates` (in any letter case) or that has an empty, `.` or `..` segment: `trackerfix.new: <name> is a reserved or malformed fixture name`.
- *Never handed to a spec, and checked after each clone* (F9 a, b, d): no `Fixture` field names it. After every clone, `find <template> -mindepth 1 ! -path <template>/.fixture-stamp -cnewer <template>/.fixture-stamp -print` (stats, no reads; change times, which every write and every mode change move; the stamp itself is left out, its own change time can follow its modification time) must print nothing, and the stamp must exist; otherwise the fresh fixture is removed and `trackerfix: template changed: <first path> (something wrote into <template> after it was built); every later fixture of this run from it refuses` is raised. A clone does not change its source's times (design review 005 P1: 0 entries newer after two clones); a `git status` in a template checkout rewrites its index and does trip it, and no code runs git in a published template. The stamp the clone copies into the fixture is removed from it.

**The clone step.** One helper, `z-nile/tests/lib/fxclone.luau`: `fxclone.tree(src: string, dst: string, opts: { copy: boolean?, simulate: string? }?): (string, string?)` returns `"clone"` or `"copy"` and, for a copy that was a fallback, the reason. It refuses a `src` that is a link or not a folder and a `dst` that exists (link or not): `fxclone: <path> ...`. On macOS (`process.os == "macos"`, and in the helper `$^O eq "darwin"`, else it exits without the call: failing closed, never calling 462 elsewhere) one `perl` runs `syscall(462, -2, $src, -2, $dst, 0)` (`clonefileat`, both folders `AT_FDCWD`). On `ENOTSUP` or `EXDEV` (a volume that cannot clone, or another volume) it removes any partial destination and copies with `cp -Rp`, returning `"copy", "<errno text>"`; on any other error it removes any partial destination and raises `fxclone: clonefileat <src> <dst> failed: <errno text>` (E10: a full volume is `ENOSPC` and leaves none). On Linux it is one `cp -a --reflink=auto src dst` (a reflink where the file system has one: btrfs, XFS with reflink, bcachefs, ZFS 2.2 and later; a copy elsewhere), on any other system `cp -Rp`; a failed copy removes its partial destination and raises. `copy = true` takes the copy path on any system (a seam); `simulate = "<errno name>"` makes the macOS path behave as if the call had failed with that error (a seam for the fallback and its line). `man 2 clonefile` says cloning directories with these functions is "strongly discouraged" (E11 says what was checked).

**One line when a fixture was copied on macOS** (F13): when `fxclone.tree` falls back, `trackerfix.new` appends `<reason> <base>` to `<home>/.cache/fixture-templates/<run>.copied.<pid>`. At its end the run's coordinator (and an in-process run) reads every `<run>.copied.*` of its run, prints one line `fixtures: <n> fixture tree(s) were copied, not cloned (<first reason>): the clone saving is lost for them`, and removes the markers. Off macOS nothing is written (a copy is the normal path there). `z-nile/tests/run.luau` gains about 15 lines for it.

**The rewrite list** (exact, E3), `trackerfix.REWRITE`: `main/.git/config`, `main/.git/logs/HEAD`, `main/.git/logs/refs/heads/main`, `main/.git/logs/refs/remotes/origin/HEAD`, the same four under `other/.git/`, and `origin.git/config`. One `perl` replaces the template's path with the fixture's in each (through a sibling temp file and `rename(2)`). Then, in-process and before any git runs in the fixture (F8): each of the nine is read and must not hold the template's path, and the `url` of `[remote "origin"]` in `main/.git/config` and `other/.git/config` must equal `<base>/origin.git`; otherwise the fixture is removed and `trackerfix: <file> of <base> still names <template>` or `... remote origin is <url>, not <base>/origin.git` is raised. So a missed rewrite can never push into the template.

**After the clone** (all through `fixture.git`/`fixture.exec`): `git update-index -q --refresh` in `main` and `other` (exit status ignored: it reports files whose stat data it refreshed); the identity in `main` and `other`; the seeded files written into `main`, `seal.stamp(main, name)`, `git add -A`, `git commit -q --amend --reset-author -m seed`; `git push -q -f origin HEAD:main`; in `other`, `git fetch -q origin` and `git reset -q --hard origin/main`.

**Seams** (F10), each used by this ticket's spec: `trackerfix.build(name, seed?, opts?): Fixture` (today's builder, unchanged: the reference a cloned fixture is compared with, and what the template build runs); `trackerfix.TOOLING: string` (the checkout whose tooling is copied and keyed, default `engine.TOP`; a spec sets it to a private tooling made with `engine.copy`, which changes the copy source and the key together, so it gets private templates); `trackerfix.template(noLessons: boolean): string` (this run's template for the current `TOOLING`, built if needed); `trackerfix.changed(template: string): string?` (the first path the after-clone check would name, or nil); `trackerfix.forget()` (this process forgets the templates it resolved and that it swept, as a fresh worker would); `trackerfix.builds(): number` (templates this process built); `trackerfix.REWRITE: { string }` (the rewrite list; a spec may shorten it to see the build check refuse); `trackerfix.SKIP_REWRITE: string?` (a fault seam: the rewrite leaves out this one relative path, so the per-clone check is seen to refuse before any push); `trackerfix.SIMULATE: string?` (passed to `fxclone.tree` as `simulate`, so a run's fallback and its line are seen); `trackerfix.REWRITE_TO: string?` (a fault seam added in job 2: the clone's rewrite writes this path instead of the fixture's, so the remote comparison is seen to refuse). Each seam is a module field a spec sets and restores; nothing in the runner sets one.

**Cleanup.** No change: a fixture stays after its run and the next `trackerfix.new` of the same name removes it, as today; an earlier run's templates go at the first fixture of the next run.

### Scalability
A fixture costs one `clonefileat` (2 file events however large the tooling grows), one rewrite, the after-clone `find` (about 2,200 `lstat`s), the tooling key (about 1,000 `lstat`s) and its seeded commit; the template is built once per run per lessons choice per tooling change, with one more `grep` over it.

### Maintainability
One place copies a fixture tree (`fxclone.tree`), one list names the files to rewrite (`trackerfix.REWRITE`, checked at every build and every clone), one builder (`trackerfix.build`) for templates and for the reference.

### Usability
Nobody does anything new. A run prints one new line only when a fixture was copied, not cloned, on macOS.

## Deferred: a per-run volume (own ticket, to be decided with slice 1's full-gate and slow-tier numbers)
Not built in this ticket (G9, design review 005 F20 option (a)). Kept here: the experiments E6 and E7 (below) and what was designed (git history: `0d0575356`, "Slice 2"). With slice 1 on disk, light-path makes 51,305 events in its steady state; on a per-run RAM disk mounted over the home's `.cache` and detached instead of emptied it made 23,744 (E7), the removal half that slice 1 leaves (54%, 51% and 37% of the three heavy files). Its ticket's design must answer, before any of it is built:
- F14: a volume is stale only when no record of the lock on it still holds (the workers' pid records live there), judged before any detach; otherwise the run waits, then sweeps again; a stale volume that will not detach refuses the run; check lines for a second run during a held volume run and for a killed top with a held spec (`c0058/lock`'s case "a run whose top process was killed keeps the lock while its specs still run").
- F15: the switch is a runner flag the top process never forwards, and `fence.luau` refuses a volume in any process started inside a spec run, whatever the markers say (fourteen spec files start a top-level runner in a fixture copy).
- F16: R0070's c0194 moves the run's temp folder to `<home>/.cache/.tmp/pickman-run.X`, under the mount point: state the order for both worlds and run c0194's specs on a merged prototype.
- F17: a lifeline started before the mount that detaches when the top process's pipe closes and the lock on the volume has no holder; `./zn reap` finds every `znfx-<pid>-<key>` device with a dead owner from `hdiutil info` and `diskutil`, mounted or not; worktree removal sweeps first.
- F18: the pure module in `z-nile/lib/` (shared by the runner and the engine, copied into fixtures), `cachepaths.luau` and the reaper's usage in its Touched modules, and `reap --auto` in a check run reads no mounts.
- F19: every `hdiutil`, `diskutil` and `newfs_apfs` call under a time limit (fallback before the mount, refusal after), the device read from a plist, the carry-out copying only a regular file under a size limit without following links, and the order of detach, snapshot and lock removal written out.
- F20: which runs make a machine's file events (`./zn finish` and `./zn check` run specs through `z-nile/specs.luau`, not `z-nile/check.sh`), a prototype run of the full suite and the nested-run specs on a real volume, and the designed sequence run once.
- F23: "the gate puts nothing there first" is wrong (the static stage builds `<home>/.cache/check.rbxl`); the switch needs no `hdiutil` argument; the size estimate leaves out the lifeline, the limits, the reaper's command line and the zz-test text.

## Risks and what review should watch
- **Shared state between cases.** The template is shared by every fixture of a run; a write into it is refused at the next clone (loud, naming the path); no spec writes into a template it did not build (F1).
- **A spec that relied on a fresh build's side effect**: the differences listed under "The spec-facing interface". Design review 005's probe found no reader; AC4 and AC5 compare every case of the 87 files.
- **Order dependence**: the first fixture of a run builds the template (about 2.7 s instead of 0.8 s); no spec asserts timing.
- **Stale templates after the tooling changes mid-run**: the key changes and a new template is made; an edit that keeps size and mtime is missed.
- **EXDEV and other volumes**: a fallback copy is loud (one line per run) and costs what a copy costs (about 2,200 entries a fixture).
- **The syscall**: macOS only, decided twice (`process.os` and `$^O`); `man 2 clonefile` discourages it for folders (E11).
- **Kernel memory**: no measurable change between modes per spec file (E5, E9); AC4 compares the zone per suite.
