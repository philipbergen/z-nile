### F1 [medium] The new origin case pushes into the real repository on purpose, and its last assertion compares the real repository's refs with themselves
Where: `acceptance/clone-image.spec.luau` "a clone's origin is the source, so a push from a fixture cannot reach the image" (lines 207-227: `fixture.exec(dest, "git", { "push", "-q", "origin", "HEAD:refs/heads/c0178-pushed" })` with `origin` = `TOP`, then line 226 `t.expect(out("git", { "for-each-ref" }, TOP)).toBe(out("git", { "for-each-ref" }, TOP))`); Rules row "a clone's origin is its source, never the image"; zz-test "Specs never touch the real repository" ("Against the real repository, only read: `rev-parse`, `ls-files`, … and cloning *from* it")
Evidence: since round 3, `clone.isolated` sets the clone's `origin` to `source`, and for this checkout that is `TOP`, the real repository. The case then commits as `c0178@example.invalid` and pushes `refs/heads/c0178-pushed` to it. It passes today only because the jail (macOS) or the pre-push and reference-transaction hooks (Linux, outer sandbox) refuse the push (`pushed.ok` is false; 11 passed on my copy). This is the only promoted-to-be spec that aims a ref-creating write at the shared repository. Line 226 evaluates the same command twice and compares the results, so it asserts nothing about the push. It can also fail with no push at all: any branch, fetch or commit that another session makes in the shared git directory between the two `for-each-ref` calls turns the case red. The mutant the row names ("origin left at the image") is already killed by line 68's `remote.origin.url == TOP` and by this case's own URL. With origin at the image, the push succeeds and `pushed.ok` is true.
Critique: a write attempt is not a read. If a guard regresses (c0117, c0118 and c0121 are changing `fence.sh` now), this case does more than fail: it creates a fixture-authored branch in the git directory every session shares. The tripwire then reports `REPOSITORY CHANGED` and every agent must stop for the user, which is the 2026-09-30 incident class the zz-test rules exist to prevent. Proving that the guards refuse a push is `repo-fence.spec`'s job, with probes that are harmless if they succeed. Round 3's recommendation asked for this push. The tempting fix is to keep the push and correct line 226 to a before/after comparison. That keeps both the deliberate write and a race with every other session's ref updates.
Consequences: without the push, the case proves the property by configuration: the clone has no remote, push URL or `insteadOf` that names an image. A spec that pushes to the image path on purpose is still possible, but nothing in the Design promised to refuse that.
Recommendation: drop the push and line 226. Assert that `git config --get-regexp '^remote\.'` in `dest` lists only `remote.origin.url <TOP>` and the fetch refspec, and that nothing in it, `remote.origin.pushurl` included, names a path under `images.dir()`. Keep the image's `for-each-ref` before/after around a read-only `git fetch -q origin` in `dest`, which reads `TOP` and must leave the image as it was. The Rules row keeps its mutant "origin left at the image" and its kill (the URL). Add the mutant "origin set to the source, push URL left at the image" (`remote set-url --push origin <image>`), killed by the `pushurl` assertion.
Lesson: zz-test/guard-needs-its-own-case (proving the guards is the fence spec's job; this case leans on them for its own safety)
