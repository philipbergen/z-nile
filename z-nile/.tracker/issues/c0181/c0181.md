# c0181: Lessons codified and consolidated

## Problem
The user (2026-10-31), asked whether fixtures could copy lessons only where needed: "Can we have a consolidation process that combines lessons as we go to keep it tight, coherent, and complete?", and then: "I'd also like lessons to turn into checks when they are written, there's probably not a 1-1 opportunity to codify a lesson into a check but a significant portion should be. If it can be codified as a test it can be much less verbose in the lesson, limiting content and search".

Today a lesson is prose only (133 lesson files under `z-nile/skills/*/lessons/`, plus the projects'): each step reads them with `./zn lessons --full` and asks each one's check question by hand, nothing enforces them, they grow without merging, and every spec fixture copies all of them (c0115).

What should happen: when a lesson is written, its rule becomes a check the gate runs wherever it can be codified, and the lesson then shrinks to a short pointer to that check; a significant portion of the existing lessons are codified the same way; overlapping lessons are combined as they accumulate, keeping the set tight, coherent and complete (no source or rule lost).

## Non-goals
- The fixtures' lesson copy itself stays (c0115); it shrinks as lessons do.

## Solution
- At every place a lesson is written (z-design's harvest, zz-execute's harvest, a lead's note), ask first whether the rule can be checked mechanically: a lint over texts run in `check.sh`'s static stage, or a spec case; `harvest.md` records `codified <path>` or `not codifiable: <why>`.
- A codified lesson keeps its frontmatter plus `enforced_by: <check>` and one line of why; the check's failure message names the lesson and how to fix it; `./zn lessons` shows enforced lessons as one line (or hides them).
- A backfill sweep of the existing lessons, reporting the share codified.
- Consolidation as we go: a new lesson that overlaps an old one is merged into it, keeping every source id; `./zn lessons consolidate` lists clusters to merge.
- Guards: every `enforced_by` exists, runs in the gate and fails on a fixture that breaks its rule.
- Reconcile with R0040, c0112, c0136 and c0166.
