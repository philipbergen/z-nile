### F1 [high] The new required fields of `Lesson` (and `Item.dir`) break the type check of promoted c0111 specs, so `Overrides: none` is false
Where: Design, "The state" ("the Lesson type gains `enforcedBy: {string}`, … `distinct: {string}`, `merged: {string}`"); Implementation step 2 (`Item.dir`); Regression guard; AC11.
Evidence: z-nile/tests/acceptance/c0111/metrics-lessons.spec.luau:16-29 returns a table literal typed `lessons.Lesson` with exactly today's nine fields. c0111/harvest.spec.luau:85-226 and metrics-lessons.spec.luau:50-61 build `{ lessons.Item }` literals as `{ id, reviews, harvest }`. In strict mode, a literal that lacks a non-optional field doesn't convert to the sealed type, so `enforcedBy`, `distinct`, `merged` (and a required `dir`) are type errors in those promoted files. The gate type-checks them: check.sh puts the `z-nile` home in LUNE_DIRS and runs `luau-lsp analyze` over it, ignoring only `.tracker/` and `.cache/`. `./zn done` also type-checks the project's `tests/` and rolls back (zz-test, sequestration). AC11 runs these specs through `lune run tests/run`, which never type-checks, so AC11 passes and the merge's `--full` (or `done`) fails. The prototype (E6) only ran specs, which is why nobody saw it. c0181's own policy.spec builds an untyped Item (`{ id = "c0999", reviews = {}, harvest = text }`) and passes it to `lessons.sources`, so once promoted it fails the same way if `dir` is required.
Critique: The tempting fix is to edit the c0111 literals. That is an override of promoted specs, which this chore says it doesn't have.
Consequences: Optional fields mean every reader handles nil (`l.enforcedBy or {}`). `parse` still always fills them, so format.spec's `toEqual({})` holds.
Recommendation: Type the new list fields and `Item.dir` as optional (`enforcedBy: { string }?`, `distinct: { string }?`, `merged: { string }?`, `dir: string?`), and say so in the Design. Add a check.sh line to AC11 that type-checks the promoted lesson specs and the new modules the way the gate does: `luau-lsp analyze --base-luaurc=.luaurc --platform=standard` over `tests/acceptance/c0111`, `tests/acceptance/c0119` and `engine/`, with the cached definitions. Add a Rules row for it ("a hand-built Lesson or Item still type-checks": mutant, a required field).

### F2 [high] `item:` baseline keys go stale at the next `./zn compact` or `renumber`, so the fix for design-review-001 F7 still turns main red (repeat of design-review-001 F7)
Where: Design, Lints ("`item:<id>` … an item's folder moves at `ready` and `done`, and compaction renumbers, so a path key for an item goes stale"); Chore checklist, Existing work (d); E3.
Evidence: The keys live in lint modules, `z-nile/lints/<slug>.luau`. `compact.apply` rewrites ids only "in the .md and .sh files under every project root (c0114); elsewhere only acceptance paths are" (compact.luau:40-43). `renumber`'s `rewriteUnder` rewrites `.md` and `.sh` under the roots only (main.luau:2762-2775). After `./zn compact`, c0083 gets a new id. `allow = { ["item:c0083"] = … }` then names no folder, which `lint.baseline` reports as a problem, and the lint runner fails closed, so the compaction PR's gate is red. The same happens for each of the 14 pickman issues E3 baselines. The Design names compaction as the reason path keys fail, but `item:` keys fail at the same event.
Critique: This is the second hole in the baseline mechanism: the first was lifecycle moves, this one is renumbering. The natural patch, "teach compact and renumber to rewrite `z-nile/lints/*.luau`", widens a rewrite set that promoted compaction specs pin. It also puts an item's state in tooling code.
Consequences: A key that follows the item through every move and renumbering has to live where the existing move and rewrite already go: inside the item's folder, or in a `.md` under a project root.
Recommendation: Move per-item baselines out of the lint modules into the item's own folder, for example `<item folder>/lint-allow.md` with lines `- <lesson id>: <reason>`. Read it through `lessons.luau` or a new one-reader module, and have `lint.run` honour it for that item's files. `ready`, `done` and `compact` move it and rewrite it with no code change, because it is a `.md` under a root. Keep `allow` in the `Def` for repository paths only. Cases: an allow file clears the item's hits in backlog and `active/`; a compaction-renumbered fixture (`compact.apply` on a two-item tree) keeps the hit cleared; an allow line naming a lesson whose lint no longer hits in that folder is a problem. Or, if the keys stay in the lint modules, design the compact and renumber rewrite of `item:` keys, with its override check against the compaction specs. One of the two must be chosen in the Design.
