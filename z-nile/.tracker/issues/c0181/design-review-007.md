### F5 [medium] `./zn clean` is designed to refuse the main checkout, which is where worktrees are removed; its overlap with `worktree-prune` is not designed
Where: Shared tools ("`prove` writes an item's `proof.md` and `clean` removes a worktree, so both refuse it"); `./zn clean <worktree name>`; "The worktree-removal text in the skills says to use it".

Consequences: a command that runs in the main checkout must still refuse to remove the main checkout itself or the worktree it is called from. Two removal commands with different "landed" tests (done/ on origin/main against content equality with origin/main) need one sentence that says which to use when.
Recommendation: `clean` runs from the main checkout (like `worktree-prune`), refuses a name that is the main checkout or the current worktree, and is not in the refusal sentence.
