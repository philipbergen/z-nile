# Answers to design-review-001 (c0189)

- F1: fixed: `./zn hooks` and `--check` take the reference text from `origin/main`'s copy of `z-nile/lib/repo-hooks/reference-transaction` (`git ls-tree` and `git show` on the local remote-tracking ref), never from the running tree; a repository with no `origin/main` ref (the Merging clone, a repository with no remote) uses its own tree's copy; a repository whose `origin/main` has no such file yet gets a new plan action `none` (prints one line, exit 0, writes nothing), so this chore's own branch passes its own gate stage before it lands; a failed read of `origin/main` is an error. Design: "`./zn hooks [--check]` and `hooks.plan`" (the `from` field, the table, "Why `origin/main`…"), Gate/setup/clone paragraph, Existing work, Guards, Risks, AC2, AC3, steps 3 and 9 (no install in the worktree; `./zn sync` then `./zn hooks` after the merge). Reproduced by specs, not only argued: `hooks-command.spec` "linked worktree … never its unmerged edit" (an uncommitted edit in a second checkout is not installed and both checkouts' `--check` agree), "origin/main moves to a new hook text", "origin/main has no hook file", "a clone with no origin/main". Mutants S1 (reads the working tree), S3 (falls back to the tree), S4 (no ref is an error), N1 (no `none`): all killed. Consequences, each handled: (a) a hook change turns every gate red from its first fetch until someone runs `./zn hooks`: named in Risks and in the message; the reviewer's optional `sync` reinstall is not adopted (it would put the git directory among what `sync` edits; the one-line fix is idempotent and any session may run it); (b) the stage's guard stays `[[ -f z-nile/lib/repo-hooks/reference-transaction ]]` (a tree without the file has no stage), and `none` makes the stage pass while origin/main lacks the hook; (c) the Merging clone: its sentence now says why the clone installs its own tree's copy; (d) fixtures keep testing the tree's file (`repo-hook.spec` copies it); (e) one new fixture-spec consequence found by the prototype: a fixture whose commits carry the fixture identity cannot be fetched into a hooked fixture, so the spec moves the hook aside for its two fetches (`fetchOrigin`) — the hook doing its job.
- F2: fixed in part, the rest is the user's: the evidence is reproduced (`e11.sh`, E11): a push of an old fixture-tip branch reaches the remote and only the local tracking update is refused, then every `git fetch origin` fails.
