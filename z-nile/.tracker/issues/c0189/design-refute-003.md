# Answers to design-review-003 (c0189)

- F1: fixed: the history read is `git log --first-parent --format= --raw --no-abbrev origin/main -- <source>`, so "reviewed" means a text main itself held, not a merged branch's work-in-progress commits; the Design defines it ("\"Reviewed\" means a text main itself held") and states its dependency on the merge-commit flow (a PR merged by rebase would put intermediate commits on the chain) and that a shallow or rewritten main only makes `--check` red. Case: `hooks-command` "only a text main itself held counts as reviewed" (a branch commits a weak text, then a final one, merged with `--no-ff`; the weak text installed by hand is red; the final text, after a later change on main, is an older reviewed copy). Mutant F1m (history without `--first-parent`): killed.
- F2: fixed: the reference is read with `git cat-file blob origin/main:<source>` and its raw stdout (untrimmed) is installed, so the installed file's blob id is always one origin/main holds; the spec's `originText()` reads the raw blob too. Case: `hooks-command` "the installed bytes are the blob's…" runs the source with no final newline and with a trailing blank line, installs it, then pushes another change and expects `--check` green with the note. Mutant F2m (the trimmed `git show` plus one newline, the prototype as it was): killed. Consequence: none beyond the case; the Merging clone's tree path already read raw bytes.
- F3: fixed in the documents and the message; the rest is the user's: E1 is re-run (the search, its output and the branches are in Existing work and E1): `proto-f0147` is back with 10 fixture commits under an ordinary tip and a live worktree, `proto-f0143-deps` holds 3, `proto-wall-picks-base3` is checked out in another worktree.
