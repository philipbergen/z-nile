# c0192: Lesson bound every probe

## Problem
zz-review: every command an agent runs outside the spec runner (a probe, an experiment, a scratch lune run) has a time limit and dies with the agent, because code review cr4's raftcheck probes hung and ran 14 h at 100% CPU on three cores after the session ended; check: does every command I start outside tests/run stop on its own within a minute, and when I stop?

## Non-goals
- The mechanism (bounded runner, hook, reaper) is c0191; this lesson is its short rule, kept brief because c0191 checks it (c0181).
- It also applies to z-design experiments and zz-execute probes: add a note there, or one lesson tagged for all three, as the prep finds best.
- c0181's mechanism (the lesson's `enforced_by:` field, the `codify` harvest form, the cap on a lesson's size, the policy stage that runs in the gate, consolidation of overlapping lessons) is c0181's. This issue does the c0181 question for this one lesson, green in either landing order (design review 001 F1): the executor writes `z-nile/tests/meta/bound-every-probe.spec.luau`, one case named `[zz-review/bound-every-probe] …`, which is the lesson's enforcing ref in the gate from the day it exists. **If c0192 lands first**, c0181's backfill converts the lesson (its ref is that case). **If c0181 lands first** (it is `design: ready` with `depends_on: [c0136]`, nothing orders it against this issue), the executor writes the lesson with `enforced_by` naming that case, `enforced: part`, and a `- codify` harvest line (Design 7).
- Rewording `z-design/probe-free-cli-lines-in-prep` ("under an alarm" becomes `./zn run`) is c0191's step 6, pinned by its AC6. This issue does not touch that lesson.
- The rule sentence, the hook's message and the mechanism's description are c0191's words; this lesson repeats the sentence word for word and nothing else of the mechanism.

## Solution
One new, short lesson, `zz-review/bound-every-probe`, `when: both`, whose rule is the sentence c0191 pins in `AGENTS.md` and four skills, whose body points at c0191's checks as its enforcement, and whose `check` keeps the captured question. Its `harvest.md` note makes the incident its source. One meta spec case (`z-nile/tests/meta/bound-every-probe.spec.luau`, executor-written) holds in the gate what the lesson says: the hook logic refuses a bare probe and names the wrapper, `AGENTS.md` still carries the sentence, the lesson repeats it word for word and every path it names exists. `check.sh` pins the lesson's shape and wording once, at `done` (it is text, so no promoted spec holds it: c0181 will turn its paragraph into a field), the same facts as sequestered twins of the meta case, and that the lessons tooling accepts the lesson.

## Design
The captured outcome is the lesson. Per c0181 the first question is what a machine can hold of the rule, and c0191 has already answered it: the runner `./zn run` (AC1), the PreToolUse hook that refuses a bare probe (AC2), the reaper at session end, `sync` and the gate (AC3, AC4), the CPU limits (AC5) and the sentence pinned in five places (AC6). The one thing this issue adds is a case that ties the lesson to those checks, so that c0181's policy has a ref to accept and the pins outlive `done` (Design 5 to 7). What a machine cannot hold is whether an agent wrote its probe through the wrapper where the hook cannot read the line (a shell script run by name, `npm`, a program in another language: c0191 says so plainly); that stays in the lesson's check question, which a reviewer asks.

### Decisions
1. **A new lesson, not a sharpened one.** `z-design/probe-free-cli-lines-in-prep` is about *when* to probe (free, in prep, before a paid run); c0191 rewrites its one line that mentions an alarm. `zz-arch/children-need-a-lifeline` is about supervisors the tool's own code builds (a lifeline, an identity check before a kill). This lesson is about the commands an agent runs itself. Folding the rule into either would put it in front of the wrong reader (a prep brief reads the first, a code author the second) and hide it from an agent that only runs a probe. A note on `children-need-a-lifeline` or `probe-free-cli-lines-in-prep` is not needed: neither's rule changed.
2. **Under `zz-review`, with `when: both`.** The incident was a code review's probes and the captured Problem opens "zz-review:". The lessons pass reads by `when`, not by skill: `./zn lessons --when design --full` runs in z-design step 5.1 and in design review (zz-review design item 10), and `--when build` in code review (item 10) and in the raft prompt (z-ready lists the build lessons of z-nile's skills). One `both` lesson therefore reaches z-design experiments, zz-execute probes and both review modes, which is the third option the Non-goals allow; no note in z-design or zz-execute is needed, because c0191 puts the rule sentence into both skills. AC4 checks the lesson is listed for both.
3. **Short, and it points at the checks (c0181).** Thirteen lines and about 1,150 bytes of body: the rule (AGENTS.md's sentence, word for word), one **Enforced by** line, **Why** (the incident, and why an `alarm` then `exec` is no bound), **How to apply** (the command; a longer limit is the one the step names, never an open one (review 001 F4); the exit codes 124 and 125; never get round the hook). Pinned: at most 16 lines and a body of at most 1,200 bytes (c0181's cap for a partly enforced lesson), so the lesson stays valid in either landing order.
4. **Enforced by names six paths, each pinned to exist (AC3):** the meta spec (below), `z-nile/lib/bounded.pl` (the runner), `scripts/hooks/pre-bash.sh` (the hook), `z-nile/engine/reap.luau` (the reaper), `AGENTS.md` and `z-nile/tests/acceptance/c0191/docs.spec.luau` (the spec that pins the sentence in five places; the path c0191's acceptance folder promotes to at its `done`).
5. **The enforcing ref is a meta case, written by the executor (review 001 F1, the shape c0193 uses).** `z-nile/tests/meta/bound-every-probe.spec.luau`, one case, `[zz-review/bound-every-probe] a bare probe is refused and the wrapped one passes, and the lesson carries the AGENTS.md rule and names files that exist` (reference text: `experiments/ref-meta-spec.luau.txt`, proven in prep against c0191's reference `boundcmd`, E7). It asserts: `boundcmd.check("lune run probe.luau")` is refused and its `say` names `./zn run --time`; `boundcmd.check("./zn run --time 60 -- lune run probe.luau")` passes; `AGENTS.md` holds the sentence from `Run every probe` to the first `when you do.` after it (absent is a failure, never a pass: zz-test/no-vacuous-pass); the lesson holds that sentence word for word; and every backticked path on the lesson's **Enforced by** line (at least five) is a file.
