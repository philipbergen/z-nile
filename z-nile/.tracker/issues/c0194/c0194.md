# c0194: Temp trees under repo

## Problem
The user, 2026-11-01: "why is mds_stores running, I've added code/pickman to spotlight privacy, are these trees being built somewhere else" and "It needs to be a sub of pickman, like pickman/.tmp/..." and then "change it to .cache/.tmp".

**What happens now.** Temporary trees go to the macOS per-user temp folder (`$TMPDIR`, `/var/folders/<..>/T/`), outside the repository, so excluding `~/code/pickman` from Spotlight doesn't cover them. On 2026-11-01 that folder held:
- 61 `tmp.*` folders, 14 GB in all;
- 34 of them full repo clones (`repo/`, `gate.log`, `game.rbxl`): agents' experiment and prototype clones made with `mktemp -d` and never removed, some from 2026-10-28;
- 26,434 `.luau` files in Spotlight's index, so `mds`/`mds_stores` kept indexing every clone and every suite run in them.
The tooling itself also writes there:
- the spec runner's per-run temp folder (`z-nile/tests/lib/fence.luau:830`, `pickman-run.XXXXXX`, and it points `TMPDIR` there for every spec);
- `./zn`'s remap scratch worktree (`z-nile/engine/main.luau:3084`, `tracker-remap-base.XXXXXX`);
- `z-nile/lib/par.sh:34` (`par.XXXXXX`).

**What should happen.**
- Every temporary tree the tooling, the gate or an agent makes lives under `.cache/.tmp/`, never in the system temp folder: an agent's scratch clone in the main checkout's (`~/code/pickman/.cache/.tmp/<kind>.<random>`), a run's in its own checkout's `.cache/.tmp/`.
- `.cache/` is already ignored by git and inside the user's Spotlight exclusion; `.cache/.tmp/` also gets a `.metadata_never_index` marker and, with c0179, stays out of fseventsd.
- Nothing builds a tree outside the repository any more. The skills name `.cache/.tmp/` as the place for an experiment's or prototype's scratch clone; c0189's "scratch clone" wording points there too.
- Temporary trees don't pile up: each one is removed when its run or experiment ends, and stale ones (no live process, older than a limit) are found and removed, reported like c0191's reaper.

Decided with the user (2026-11-01): "Jail the clone" (design review 001 F2). A scratch clone for unguarded-code runs stays under `.cache/.tmp/` and those runs go through `./zn tmp jail`, a minimal `sandbox-exec` profile that lets the command write that clone (and its `TMPDIR`, inside it) and nothing else. This also settles the merge gate's clone: it stays under `.cache/.tmp/`, made isolated by `./zn tmp verify`.
Decided with the user (2026-11-01): "Make them work jailed" (design review 003 F1). Inside `./zn tmp jail` the clone's spec runner must run its nested runs, `fence-leftovers` and the lock specs, so the jail is the spec jail's own rule set applied to the clone (it writes `/dev`, its `TMPDIR` and the clone's `.cache` folders, not its sources or git directory) and the runner there takes the clone for a fixture of a guarded checkout; from now on guard-prototype cases run in the jailed clone.
Decided with the user (2026-11-01): "c0194 first" (design review 001 F3). c0194 lands before R0039 (c0075); its executor edits c0075's sequestered `jail-argv.spec` to add the `--ro-bind <cache>/.tmp` carve, declared on a conditional Overrides line; c0075 stays prepared; z-raft orders c0194 before R0039.

## Non-goals
- Claude Code's own session scratchpads (`/private/tmp/claude-501/…`): the harness sets them, and Spotlight doesn't index them (0 indexed files on 2026-11-01). The skills still send repo clones to `.cache/.tmp/`, not there.
- Fixture trees elsewhere under each worktree's `.cache/`: they stay where they are (c0178, c0179 make them cheaper).
- Process leaks themselves: c0191. This issue may share its reaper.

## Solution
Ideas from capture; z-design decides.
- **One helper** for a fresh temp folder (Luau and sh), for example `<checkout>/.cache/.tmp/<kind>.XXXXXX`, created exclusively and never through a link (like `.cache` writers, c0077). The runner, `./zn` remap and `par.sh` use it. Every `TMPDIR` the runner hands to specs points inside it.
- **The jail.** It already lets specs write inside the checkout's `.cache` (not the `.cache` entry itself, review 004 F1), so a run's temp under `.cache/.tmp/` needs no new hole. But the runner today keeps the run's temp deliberately outside `.cache` (`fence.luau:827`: "a spec's `mktemp -d` must land outside .cache", review 004 F2). The prep finds why (for example `.cache` sweeps, the tripwire's `.cache` checks, or specs that list `.cache`), and shows by experiment that `.cache/.tmp/` keeps every guard as tight, or designs the nearest equivalent with the user.
- **Agents' `TMPDIR`.** Set it for every session in the repository, for example `setup.sh` writing `env.TMPDIR` into `.claude/settings.local.json`, or a checked-in hook. Then a plain `mktemp -d` from any agent or subagent lands in `.cache/.tmp/` too. Docs: z-design experiments, zz-execute Phase 1, zz-test and AGENTS.md, in the same words.
- **Index marker:** `.metadata_never_index` in `.cache/.tmp/` (check it works for a folder, not only a volume root); `./zn`'s board refresh, `sync` and any `.cache` cleanup never remove a live temp tree.
- **Cleanup:** removal at the end of each run (as today), and a stale sweep (no process with a working directory inside, older than a limit) at gate start and from c0191's reaper. A one-off sweep of today's `$TMPDIR` leftovers: report them to the user first, since some belong to other sessions.

## Design

Prep findings first, because two of the captured Solution's premises do not hold as written, and the design below keeps every captured outcome anyway.

**F1. Why the runner kept its temp outside `.cache` (the question the capture asked).** Found in R0210's history (`git log -S'outside .cache'`: commit `116646a0`; `tracker/rafts/done/R0210/review-004.md` F2 and `refute-004.md` F2, at that commit).
- The jail first allowed the per-user temp folder (the ordinary shell's `$TMPDIR`) for specs. Review 004 F2 (high): that folder is also where unjailed agents keep their clones, prototypes, restore copies and tool caches, so "a jailed spec can rewrite such a scratch script, a restore copy, or a file in a prototype or c0660 clone between its creation and its unjailed run. That code then runs with the person's keychain."
- The fix (refute 004 F2): the jail allows only a fresh per-run folder, and "a spec's `mktemp -d` still lands outside `.cache`, as c0660's spec requires". Two separate reasons are in that sentence:
  1. **The hole.** Nothing outside the jail may run from a folder a spec can write. A fresh, per-run folder (removed at the end) is such a folder; a shared one is not. This is what the jail's profile comment ("`mktemp` is pointed there too, review 004 F2") and the user-temp-folder probes (`fence.luau` `escapes`, `repo-fence.spec`) pin.
  2. **A spec's own premise.** `c0060/fixture.spec` ("a repository outside any .cache folder is refused", "under another .cache folder than this run's is refused") builds its "outside" repositories with `mktemp -d`, and `fixture.check` takes any path under this run's `.cache/` for a fixture.
- Neither reason needs the run's folder to be outside the repository. Reason 1 needs it to be fresh and closed to every other tree; reason 2 needs temporary trees not to count as fixtures. Both are kept (below), by experiment (E5, E6, E7).
- **What the captured text got wrong, and what stays.** The "tripwire's `.cache` checks" and "`.cache` sweeps" the capture guessed at are not the reason: the tripwire's `snapshot` reads the git config, branch, HEAD, worktrees registered under a `.cache` and fixture-authored refs, none of which a plain temp folder changes, and no sweep removes `.cache` contents (`check.sh` unlinks only top-level links; E8).

**F2. Setting `TMPDIR` does not move a plain `mktemp -d` on macOS.** The capture's Solution says "Then a plain `mktemp -d` from any agent or subagent lands in `.cache/.tmp/` too". Measured (E3): `TMPDIR=<dir> mktemp -d`, `mktemp` and `mktemp -t x` all print `/var/folders/…/T/…`; macOS `mktemp` ignores `TMPDIR` unless it is given a template, which is exactly why the 61 trees in the capture were there although agents' environments had a `TMPDIR`. The runner has always worked round it with a `mktemp` stub first on the specs' `PATH`. The design therefore ships that stub for agents too (`z-nile/bin/mktemp`) and puts it first on `PATH` in the same SessionStart hook that sets `TMPDIR`. Proved end to end in a real `claude -p` session and its subagent (E4): both `mktemp -d` calls landed in `.cache/.tmp/`.

**F3. A clone under the checkout loads the checkout's configuration; the merge gate's clone must not (c0172).** Merging step 2 says the merge gate's clone goes in `$(mktemp -d)` "only when that directory's parent directories are not a checkout of this repo; if `$TMPDIR` is inside this checkout, stop". Reason (c0172 design review 002 F1, `design-refute-002`): "a directory under the repo, including `.worktree/` and `.cache/`, still loads the parent `.luaurc`", so the run is not the check CI-alone would make. Measured (E1, E2): Lune 0.10.5 and luau-lsp both resolve an alias defined only in a `.luaurc` above the file that requires it, and Rokit merges every `rokit.toml` up the path. With agents' `TMPDIR` in `.cache/.tmp`, the rule as written would always stop. The design keeps its purpose and replaces its mechanism (section "Merging").

### The folder: `<checkout or project home>/.cache/.tmp/`
- Everything temporary the tooling, the gate, the runner or an agent makes lives here, in a tree of its own: `<kind>.XXXXXX`. The main checkout's root folder holds agents' scratch trees and merge clones, and, because a session's `TMPDIR` points there, what any worktree's gate makes (`check-build.*`, `par.*`, `globaltypes.*`, `tracker-remap-base.*`); a home's folder (`z-nile/.cache/.tmp`) holds that home's runs' folders (`pickman-run.*`) and nothing else; a gate started with no session `TMPDIR` makes its trees in its own checkout's root folder (`tmp.place`).
- `.cache/.tmp` itself holds dot-files, made and refreshed by `tmp.root` (the runner writes the marker of a home's folder itself, exclusively, since fixtures copy the harness alone) and never by a spec: `.metadata_never_index` (empty, the Spotlight marker; the user's exclusion of `code/pickman` is the real cover, E9), `.git` (the same one-line sentinel `fence.sh` writes into `.cache`, `gitdir: /nonexistent/pickman-fence`, so a git command run in a non-repository below fails instead of finding the checkout), `.luaurc` (the isolation file below) and, per tree, `.pickman-owner` inside the tree.
- A `.cache` or `.tmp` that is a symlink or a file refuses with "is not a plain folder (a symlink or a file); refusing. Stop and report this." (same words and same reason as `fence.sh`: a link would turn every write below into a write elsewhere). The dot-files are written by `z-nile/lib/replace-file.pl` (rename, never through a link); nothing here deletes recursively except the stale sweep and `leftovers --remove`, through `tmp.remove(root, name)`: `sh -c 'cd -P -- "$1" && [ "$(pwd -P)" = "$1" ] && exec rm -rf -- "$2"'`, so a `.cache` or `.tmp` swapped for a link after the check makes it refuse instead of deleting elsewhere (review 001 F11). It deletes only direct children whose names are plain (`^[%w][%w._-]*$`), are not links, and are not in use.

### Public API, `z-nile/lib/tmp.luau` (one owner; pure rules first, reads and writes at the edge)

- **The command line** `z-nile/lib/tmpcli.luau`, reached as `./zn tmp …` (the `zn` wrapper execs it before the engine, so it works from any folder): `new <kind> [--owner <pid>]`, `root`, `verify <tree>`, `sweep [--dry-run]`, `jail <tree> -- <command>…`, `rm <tree>`, `leftovers [--remove <name>…]`, each with `--dir <checkout or home>` (`verify`, `jail` and `rm` take everything from the tree and ignore it). Exit 1 with `tmp: <why>` on stderr for a refusal. `verify <tree>` prints `isolated` (exit 0) or `not isolated: <why>` (exit 1); its root is the `.cache/.tmp` that holds the tree, never one computed from where the command runs (review 002 F1: `new` follows the session's `TMPDIR` into the main checkout, `ZN_TOP` is the worktree, and a verify aimed at `ZN_TOP` refused every merge). `sweep` prints one `tmp: removed|would remove <path> (idle N h)` line per tree on stderr and nothing on stdout (the SessionStart hook discards both, the gate shows stderr), asserted by a `tmp.spec` case with `lsof` stubbed on `PATH` (review 001 F4). `jail` runs `sandbox-exec` with `tmp.jailProfile` on a tree made by `new` (`tmp.jailPlan` refuses anything else, a link included): the command runs **in the tree** as its working directory, may write `/dev`, its `TMPDIR` and the `.cache` folders `prepareCaches` made in the tree (the spec jail's rules, not the clone's sources or git directory), reaches no network but loopback and signals only its own processes (the spec jail's two signal rules); its `TMPDIR` is `<tree>/.jail-tmp`; its environment adds the `.cache` that holds the tree's `.tmp` to `GIT_CEILING_DIRECTORIES` and this checkout's git directory to `PICKMAN_FENCE_REAL_GIT`, so a spec runner started in the clone takes it for a fixture of a guarded checkout instead of refusing to start inside a sandbox it cannot nest in (review 002 F2); the exit code is passed on. `rm <tree>` removes one tree made by `new` through `tmp.remove`, and refuses anything else. An empty or missing tree argument refuses with `tmp: …` (never a stack trace).
- **Shell:** `z-nile/lib/tmp.sh` (sourced). `pickman_tmp_new <kind>` is **shell, with no Lune**: the gate calls it before its tools are known to work (`c0077/replace-file.spec` runs the gate with a stubbed `lune`), and its trees need no isolation. The folder is `TMPDIR` when that is inside a `.cache/.tmp`, else this checkout's `.cache/.tmp`; a `.cache` or `.tmp` that is a link or a file refuses (`fence.sh`'s rule and words), the Spotlight marker is written exclusively if missing, and the tree is a fresh `mktemp -d` with no owner record (a tree left behind is swept by the day rule). It is the one deliberate second maker (beside `tmp.new`), pinned by `callers.spec` (no Lune on `PATH`, a decoy `TMPDIR`, a link refused, the marker). `pickman_tmp_sweep <dir>…` calls the command line.
- **`tmp.place`** decides where a tree goes, so that no caller computes a path: an explicit `dir` is `tmp.root(dir)`; otherwise a `TMPDIR` that is exactly some `…/.cache/.tmp` is `tmp.root` of that checkout (an agent's session), a `TMPDIR` below one (`…/.cache/.tmp/pickman-run.X`, the runner's folder, the only place a jailed spec may write) is used as it is after the same link check, and anything else is the folder of the command: `ZN_TOP` (the checkout of `./zn`), else the current folder (a project home when run from one, such as `deploy-beta` from `pickman/`: its trees then sit in that home's `.cache/.tmp`, which the sweep and the outer-sandbox rule cover as a home's folder). The `TMPDIR` rule is why `par.sh`, `check.sh` and `remap` need no change when they run inside a spec run or an agent's session.

### The isolation file (Merging, and every clone an agent keeps there)
`.cache/.tmp/.luaurc`, rewritten by `tmp.root` whenever the folders above change it, contains `languageMode: "nonstrict"` (Luau's default) and, for every alias any `.luaurc` above `.cache/.tmp` names (lowercased, the match is case-insensitive, E1), the same alias pointed at `./.isolated-no-such-folder`. Trees below set their own `.luaurc` aliases nearer, which win; an ancestor-only alias resolves to nothing. `tmp.neutralizer` refuses (names the file and key) any ancestor key other than `languageMode` and `aliases`, and a `.luaurc` that is not strict JSON: it cannot reset what it does not know (fail closed). Example for this checkout: `{ "languageMode": "nonstrict", "aliases": { "logic": "./.isolated-no-such-folder", "lune": …, "scripts": …, "shared": …, "tests": …, "znile": … } }`.
`tmp.verify <tree>` answers `isolated` only when the tree is a direct child of a `.cache/.tmp` (a deeper tree or one elsewhere refuses; the root comes from the tree), that folder's `.luaurc` equals what `tmp.neutralizer` would write now, and `tmp.rokitLeaks` is empty: no `rokit.toml` above `.cache/.tmp` names a tool (under `[tools]`) that the `rokit.toml` files between the tree and `.cache/.tmp` do not (a manifest in the `.tmp` folder itself is nobody's own; review 002 F7). When an ancestor `.luaurc` has a key the isolation cannot reset, `tmp.root` does not refuse: it removes the isolation file and goes on (the gate's trees need none), and `verify` says `not isolated: <file> sets "<key>"…`, so only the merge clone stops. A manifest line it cannot read refuses with the line. It is not a promise about anything else CI-alone would not have (system-wide files, the person's home); those never differed from before.

### Merging, reconciled (zz-rules step 2 and its restatements)
Step 2 becomes: the clone goes in `dir=$(./zn tmp new gate)` (under the checkout's `.cache/.tmp/`, or `TMPDIR`'s if that is one), `git clone --no-hardlinks --no-checkout` of this checkout into `$dir`, `git remote remove origin`, `git checkout --detach` the exact head, and `./zn tmp verify "$dir"` must print `isolated` before the gate runs (any other answer is a stop: post `BLOCKED:` with it). `PICKMAN_FENCE_REAL_GIT` is still appended and the gate still spawned there; step 3 (`$dir/pickman`) is unchanged. The clone is removed with `./zn tmp rm "$dir"` after step 3 and the merge (Landing step 4 gains it, first in its chain; an agent never needs a bare `rm -rf` of a variable, and `rm` refuses anything but a tree made by `new`; review 002 F5). Experiment E2b ran this on the prototype: clone, `verify` printed `isolated`, `lune run z-nile/roots` ran in the clone; E2c ran it the way Merging runs it (a session `TMPDIR` in the main checkout, the command started from a worktree), which first failed (review 002 F1) and is pinned by a `tmp.spec` case.
- **The sentences that change** (pinned today by `c0172/merge.spec`, see Overrides): zz-execute's "in a clone of the exact head whose parent directories are not a checkout of this repo" and zz-rules' worktree paragraph's "The final check is …" become "… under the checkout's `.cache/.tmp/` that `./zn tmp verify` calls isolated"; the worktree rule's "The one exception is … a clone outside the repo that is not a worktree" (zz-rules and SETUP) becomes "a clone under the checkout's `.cache/.tmp/` that is not a worktree".
- **What it costs.** A head that drops a Rokit tool the checkout still pins makes `verify` refuse until the checkout's `rokit.toml` drops it too (merge the toolchain change first, or have the user decide); an alias dropped the same way never refuses, it simply no longer resolves in the clone (which is the CI-alone answer).

**Unguarded-code runs are jailed (Decided with the user, 2026-11-01: "Jail the clone").** Trees are nearer to the checkout, so a clone made for "Running specs against unguarded code" (zz-test) would no longer be contained by distance. `./zn tmp jail <tree> -- <command>…` runs such a command under `tmp.jailProfile`: it may write `/dev`, its `TMPDIR` and the clone's `.cache` folders, not its sources or git directory (so a relative path that climbs out of the clone, or into its sources, is refused by the kernel, and nothing reaches this checkout's `.cache` or the checkout), with no network but loopback. macOS only, like the spec jail; elsewhere the run is unguarded and review catches it (zz-test, "Caught only by review"), with every fixture path absolute. ### Agents' sessions: `TMPDIR` and the shim
- `.claude/settings.json` gains a `SessionStart` hook running `scripts/hooks/session-tmp.sh`. It prints nothing on stdout (a SessionStart hook's stdout goes into the model's context), is **fail-open** (on any failure it says `session-tmp: <why>; TMPDIR left as it was` on stderr and exits 0: the session works as today), and writes nothing without `$CLAUDE_ENV_FILE`. It is the checked-in route, not `settings.local.json` (a `env` block cannot expand `$CLAUDE_PROJECT_DIR`: the docs say values are literal).
- A session started in the main checkout keeps `CLAUDE_PROJECT_DIR` there when it enters a worktree, so its scratch is the **main** checkout's `.cache/.tmp` (the capture's wish); a session started in a worktree gets that worktree's.
- `z-nile/bin/mktemp` (POSIX sh, 24 lines): no template, or `-t <prefix>`, creates `"$TMPDIR/<prefix or tmp>.XXXXXXXXXX"` with the flags given (`-d`, `-q`, `-u`); a template, and so `-p <dir>` (whose dir is the first non-option), is passed through; a `TMPDIR` that is unset or not a folder falls back to the system temp folder with a warning; a `TMPDIR` outside any `.cache/.tmp` is used with a warning. `fence.MKTEMP_SHIM` embeds the exact text (the runner writes it into each run's `bin/`, replacing its old inline stub; `shim.spec` pins them equal).
- **Not covered, and said so:** a command that calls `/usr/bin/mktemp` by absolute path or a tool that asks the OS for the user temp folder directly; Claude Code's own `sandbox` setting, which per its docs sets `TMPDIR` for sandboxed commands (precedence over a hook's export is undocumented; the shim then warns); a session started before the hook exists (restart it once). `./zn tmp leftovers` is the audit that finds what still escapes.
