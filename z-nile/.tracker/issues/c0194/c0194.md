# c0194: Temp trees under repo

## Problem
The user, 2026-11-01: "why is mds_stores running, I've added code/pickman to spotlight privacy, are these trees being built somewhere else" and "It needs to be a sub of pickman, like pickman/.tmp/..." and then "change it to .cache/.tmp".

**What happens now.** Temporary trees go to the macOS per-user temp folder (`$TMPDIR`, `/var/folders/<..>/T/`), outside the repository, so excluding `~/code/pickman` from Spotlight doesn't cover them. On 2026-11-01 that folder held:
- 61 `tmp.*` folders, 14 GB in all;
- 34 of them full repo clones (`repo/`, `gate.log`, `game.rbxl`): agents' experiment and prototype clones made with `mktemp -d` and never removed, some from 2026-10-28;
- 26,434 `.luau` files in Spotlight's index, so `mds`/`mds_stores` kept indexing every clone and every suite run in them.
The tooling itself also writes there:
- the spec runner's per-run temp folder (`z-nile/tests/lib/fence.luau:830`, `pickman-run.XXXXXX`, and it points `TMPDIR` there for every spec);
- `./zn`'s remap scratch worktree (`z-nile/engine/main.luau:3084`, `tracker-remap-base.XXXXXX`);
- `z-nile/lib/par.sh:34` (`par.XXXXXX`).

**What should happen.**
- Every temporary tree the tooling, the gate or an agent makes lives under `.cache/.tmp/`, never in the system temp folder: an agent's scratch clone in the main checkout's (`~/code/pickman/.cache/.tmp/<kind>.<random>`), a run's in its own checkout's `.cache/.tmp/`.
- `.cache/` is already ignored by git and inside the user's Spotlight exclusion; `.cache/.tmp/` also gets a `.metadata_never_index` marker and, with c0179, stays out of fseventsd.
- Nothing builds a tree outside the repository any more. The skills name `.cache/.tmp/` as the place for an experiment's or prototype's scratch clone; c0189's "scratch clone" wording points there too.
- Temporary trees don't pile up: each one is removed when its run or experiment ends, and stale ones (no live process, older than a limit) are found and removed, reported like c0191's reaper.

## Non-goals
- Claude Code's own session scratchpads (`/private/tmp/claude-501/…`): the harness sets them, and Spotlight doesn't index them (0 indexed files on 2026-11-01). The skills still send repo clones to `.cache/.tmp/`, not there.
- Fixture trees elsewhere under each worktree's `.cache/`: they stay where they are (c0178, c0179 make them cheaper).
- Process leaks themselves: c0191. This issue may share its reaper.

## Solution
Ideas from capture; z-design decides.
- **One helper** for a fresh temp folder (Luau and sh), for example `<checkout>/.cache/.tmp/<kind>.XXXXXX`, created exclusively and never through a link (like `.cache` writers, c0077). The runner, `./zn` remap and `par.sh` use it. Every `TMPDIR` the runner hands to specs points inside it.
- **The jail.** It already lets specs write inside the checkout's `.cache` (not the `.cache` entry itself, review 004 F1), so a run's temp under `.cache/.tmp/` needs no new hole. But the runner today keeps the run's temp deliberately outside `.cache` (`fence.luau:827`: "a spec's `mktemp -d` must land outside .cache", review 004 F2). The prep finds why (for example `.cache` sweeps, the tripwire's `.cache` checks, or specs that list `.cache`), and shows by experiment that `.cache/.tmp/` keeps every guard as tight, or designs the nearest equivalent with the user.
- **Agents' `TMPDIR`.** Set it for every session in the repository, for example `setup.sh` writing `env.TMPDIR` into `.claude/settings.local.json`, or a checked-in hook. Then a plain `mktemp -d` from any agent or subagent lands in `.cache/.tmp/` too. Docs: z-design experiments, zz-execute Phase 1, zz-test and AGENTS.md, in the same words.
- **Index marker:** `.metadata_never_index` in `.cache/.tmp/` (check it works for a folder, not only a volume root); `./zn`'s board refresh, `sync` and any `.cache` cleanup never remove a live temp tree.
- **Cleanup:** removal at the end of each run (as today), and a stale sweep (no process with a working directory inside, older than a limit) at gate start and from c0191's reaper. A one-off sweep of today's `$TMPDIR` leftovers: report them to the user first, since some belong to other sessions.
