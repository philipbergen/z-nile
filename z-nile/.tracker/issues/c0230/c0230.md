# c0230: Lesson fast tests

## Problem
zz-test: a test is fast and cheap on a shared machine; a proof that needs real work (a CPU spinner, a big fixture, a sleep) is a check.sh-only script run once to prove the implementation and never promoted, because c0191's runner-cpu spec burned a core on every full gate; check: does this spec burn CPU, wait, or write many files, and if so is it a one-time proof outside the promoted suite?

Decided with the user (2026-11-01): "You can use it to prove that your implementation works and then it gets removed. I'm not running that. Make a lesson, fast tests are important".

## Non-goals
- c0181's checks for lessons in general, and c0178's cheaper fixtures: this lesson is the rule they serve.

## Solution
Ideas from capture; z-design decides.
- A zz-test lesson, short (c0181): a test on a shared machine is fast and cheap; it does not burn CPU, sleep for seconds, or write thousands of files.
- A proof that needs real work is a `check.sh`-only script (c0156's pattern), run once by the executor to prove the implementation and never promoted, so it is not in the full suite.
- Enforcement as a check (c0181): the runner reports spec files slower than a budget or that start a CPU-bound child, and c0178's `fixtures: N files written, M processes started` line is the cost signal.
