# c0242: Declare the slow whole-repo specs' inputs

## Problem
c0165 (reuse of passed spec results) fingerprints a spec by what it reads. A spec that reads the whole repository is declared `*`, so any edit changes its fingerprint and it reruns in every affected gate. Two of those 27 specs are slow: `c0120/finished` (about 147 s idle, 256 to 754 s under load) and `c0116/retired` (about 80 s idle). One spec file is one runner lane. After c0165 lands, a pickman-only edit followed by a stop or an affected gate runs both, where today it runs no z-nile spec.

Decided with the user (2026-11-03), c0165 design review 009 F4: asked which trade to take for the `*` floor, the user chose "Declare the two slow ones": c0165 ships with `*` for them and records the floor; this chore declares their real inputs.

What should happen: `c0120/finished` and `c0116/retired` declare the inputs they really read (every root's `done/` folder and the paths their `check.sh` files name, and for `retired` the tree it copies), restructuring either spec where its reads can't be declared, so that an edit outside those inputs reuses their pass. Every case of both specs stays (thorough and complete). A declaration that misses a read is a forged pass, so each is audited the way c0165's declared inputs are (its audit data and AC14).

## Non-goals
- Narrowing the other 25 `*` specs, and c0165's own audit machinery.
- Making the specs faster in themselves.

## Solution
- Re-read both specs against the files they read (c0165's `acceptance/audited.tsv` and E9 hold the audit), declare exactly those inputs in each home's `inputs.tsv`, and split a spec where one part reads the whole tree and another does not.
