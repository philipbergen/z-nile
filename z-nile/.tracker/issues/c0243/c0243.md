# c0243: Linux spec portability

## Problem
On a GNU/Linux host the full gate (`z-nile/check.sh --full`) fails two z-nile acceptance specs, which blocks `./zn land` and the merging machine's final check. Both specs assume a macOS host; the behavior they test is correct on Linux:

- `z-nile/tests/acceptance/c0172/cicd.spec.luau` ("the token file is mode 600", line 399) shells out to `stat -f %Lp <path>`. On macOS/BSD `stat -f` formats the output; on GNU coreutils `-f` instead selects the fileSYSTEM, so the spec compares the expected mode against a filesystem dump (observed 2026-11-04 on linux aarch64: expected `"600"`, got the `stat -f` filesystem report for the spec's fixture volume).
- `z-nile/tests/acceptance/c0076/sweeper.spec.luau` ("the launcher form refuses, and stops nothing, when its parent is already gone", line 185) forks, lets the parent exit, and expects the orphaned sweeper to see `getppid() == 1`. On Linux an orphan reparents to a subreaper ancestor when one registered `PR_SET_CHILD_SUBREAPER` (a systemd user session, a session supervisor), not necessarily to PID 1. The sweeper then skips the parent-1 refusal and its interlock refuses with `no jail on linux; nothing swept` (exit 70 — the refusal itself is correct off-macOS), so the spec's `no launcher above me` assertion fails.

What should happen: both specs pass on an unjailed GNU/Linux host exactly as on macOS, still asserting the production behavior (the lease file is mode 600; the launcher-form sweeper started with no launcher above it refuses and sweeps nothing).

## Non-goals
- The bubblewrap Linux spec jail (c0075, raft R0039): a prepared, separate issue. It sequesters writes; it does not make macOS-isms portable.
- Changing the sweeper's or the cicd tooling's production behavior — both are correct on Linux; only the specs' host assumptions are wrong.
- Auditing every spec for other BSD-only commands: this ticket is the two known failures; further host assumptions get their own tickets.
- The gate, the jail, `check.sh` mechanics: unchanged.

## Solution
- The cicd spec reads the file's mode through a portable means: lune's fs API if it exposes permissions, otherwise a platform branch (`stat -c %a` on Linux, `stat -f %Lp` on macOS), still asserting mode 600.
- The sweeper spec's orphan case no longer depends on the orphan's reparent target: it pins the observable contract (exit 70, nothing swept, no launcher found) whichever refusal the sweeper reaches first, and still exercises the parent-1 fast path where the host provides it.
- `z-nile/check.sh --full` runs green on the GNU/Linux aarch64 host, and the macOS jail run stays green.
