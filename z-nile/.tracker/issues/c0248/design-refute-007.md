# Refute 007: c0248 (answers to design review 007)

- F1: fixed: a stamp already on a new review or refute is accepted when it is true, a commit's own (its `Commit:` names a commit whose `git patch-id --stable` is its `Patch:`), and the file is committed as it is, with no `Inputs:` check; `completion.layer` then judges it current when that patch is the finish's (a clean restack between the dispatch and the commit) or a stale round with findings to answer and a next round, as outcome 1 says. Any other stamp is refused. AC4 commits a round 2 stamped with a commit of the same change and another sha, as it stands, and the layer is complete; a round 2 whose `Patch:` does not belong to its `Commit:` is refused. Rules row and mutant `untrue-stamp-kept`. Consequences: an author who writes a true stamp of some commit asserts no more than an `Inputs:` line naming that commit would; a true stamp of an older change makes the round stale, never current.
- F2: fixed: a round the layer's history had and HEAD lacks is committed when it is restored (its text equals what the deleting commit removed); any other file of that number is refused, and the refusal names the restore, `git checkout <deleting sha>^ -- <path>`, or the next round. AC4 deletes the committed review with plain git, refuses a fresh `review-001.md` with that exact restore command, restores it with that command and commits it. Rules rows and mutants `fresh-readd-accepted` and `restore-refused`, now `run`. Consequences: the dispatcher's and zz-review's numbering need no change: after a restore the folder holds the round again.
