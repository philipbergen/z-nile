### F1 [medium] No case covers an unfinished layer above an older finish, so an implementation that judges only the finish commit passes AC8
Where: c0248.md outcome 4, the bullet "A layer above a landing that holds an older finish of the layer below"; AC8; acceptance/layers-land.spec.luau, the R0040 case; Rules and mutants, the row "a layer above a landing that holds an older finish of the layer below is judged against main's tip".
Evidence: In the R0040 case, layer 2 is finished (`layer(wt, "R0040", "c0100", "e2")` runs `finish`) and reviewed before layer 1's fix lands. So the only shape exercised is `F1old, F2 (c0100: …), review`: `rebaseUpstream`'s `<issue>: ` row. The other shape the design covers through the row rule's `tracker: start <R>` row is never run: layer 2 still being built (`F1old, S2, c0100 work`) when layer 1 is fixed (for example by the landing's final review, zz-execute Phase 5 step 3) and lands with `done --through c0090`. Take the mutant `above-landing-finished-only`: `aboveLandingBase` asks only whether the parent of the layer's finish commit (`layerFinishSha`-style, the reasoning the design itself gives for `workread`) is on main, and returns the fork when the layer has no finish commit. It passes every case in layers-land and on-landed, because each layer there is finished when it is judged above a landing (R0040, AC8 kept and deleted, AC12; AC9's new layer is cut from main). On the unfinished layer it returns the fork `M1`. `finish c0100`'s ancestor check passes, `diffPaths(M1)` includes layer 1's old files, and the first finish of layer 2 squashes `F1old` into `c0100: …`. That is the defect the bullet exists to prevent, and AC8's "`./zn finish` … refuse it naming `./zn restack <R>`" is met by a wrong implementation.
Critique: The prescribed implementation, which calls `stack.rebaseUpstream` with its row rule, is right. But nothing pins the `tracker: start` half for this caller, and the obvious shortcut (look at the finish commit's parent) is the one the document already uses as an argument for `workread`. The fix the author will be tempted to make is to add a sentence saying "unfinished layers too" with no case.
Consequences: A second variant needs a layer 2 that is started, has a work commit, is not finished, and then a fix and `done --through` on layer 1. That adds no raft, since R0040's two members are enough if the case is reordered, but it changes R0040's sequence. The finished shape must stay covered too, or `above-landing-fork-only`'s kill moves. After `restack`, the unfinished layer then needs `finish` and a review before its `complete` assertion. The `trace`/`done` refusals in the unfinished state name the restack through the same ancestor test (`main` is not an ancestor of the tip) before any finished check, so they need no new words.
Recommendation: Extend the R0040 case, or add one sibling case on a new raft if the order cannot be shared. Cut layer 2 and commit one `c0100 work` commit without finishing. Fix, re-finish, review and `done --through c0090` layer 1. Then assert that `finish c0100` refuses naming `./zn restack R0040` with HEAD unchanged. Then `restack R0040` and assert no `c0090` commit above `origin/main`. Then `finish c0100`, review, and assert `2 R0040/2/c0100 c0100 complete`. Keep the finished-layer assertions as they are, for example as the case's second half with layer 2 finished before a second fix of layer 1, or in the sibling. Add the Rules and mutants row "the layer's own first commit is found by its `tracker: start` commit too, so an unfinished layer above an older finish is refused at its first finish", with mutant `above-landing-finished-only` killed by the new assertion, run on the prototype and recorded in E14. Update AC8's criterion and the check.sh/Test plan label if the case name changes.

### F3 [low] `ready --on` a partly landed base raft refuses saying its landed layer "is not finished"
Where: c0248.md outcome 4 ("every caller") and the Public surface; prototype `f0399.readyOnMembers` (main.luau around line 6989), which r3 merged to d0331's `layerOneBase`.
Evidence: c0248 is what makes a partly landed active raft possible. `readyOnMembers` walks every ordered member of the base raft D from layer 1, with `below = layerOneBase(D, <layer 1's tip>)`, and then each layer's tip. If D's layer 1 has landed and its branch is kept, the fork of its tip with main is that tip itself. `layerFinished(layer1, tip1)` then counts 0 commits and is false, and `ready R --on D` fails with "--on D: D's layer for c0010 is not finished …". If the branch was deleted, `have[1]` is nil and it fails the same way. No `landed` skip applies here, as it does in `rows`, `startLayer`, `restack` and `workread`.
Critique: The command fails closed, so nothing is lost. But it names the wrong cause, and the person is sent to finish a layer that has landed. This is r2's code, not r3's delta. It is reported because the brief lists `ready --on` among the places that judge a layer.
Consequences: Accepting a partly landed D (skip landed members, start the walk at the lowest unlanded layer with `aboveLandingBase`) is a behaviour change to f0399's `--on` rule and needs `buildBase` (D's top layer) and `done`'s "built on an unlanded raft" refusal to stay as they are. Refusing in clear words is the smaller change.
Recommendation: In `readyOnMembers`, refuse a base raft with a member landed on `origin/main` in words that say so ("--on D: D is partly landed (c0010); …"). Otherwise, skip landed members and judge the lowest unlanded layer with `layergit.aboveLandingBase`. Either way, add a line to outcome 4's "Stopped and readied again" bullet and a `layers-land` assertion on a raft after its `done --through` (R0010 after its first landing, or R0050).

Upstream: zz-review
