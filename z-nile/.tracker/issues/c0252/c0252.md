# c0252: Dispatcher merges a green PR autonomously

## Problem
c0117's chain stops at a merge as a human gate. For autonomous delivery the dispatcher itself should merge a layer (c0248) once its own checks pass: CI green, the layer below merged, the full gate run once at the merge, review approved with no open high finding, no regression, and `main` moved only by tracker-only commits (c0152). The agents' bot credential still cannot merge; only the dispatcher merges, with its own credential.

What should happen: the dispatcher merges layers bottom-up, retargets the next layer, and escalates (`blocked`, c0250) instead of merging when a check fails.

Part of the z-nile vision (z-nile/README.md, section How it should work). To be delivered in the raft **R-vision** as one **stacked PR set**, one layer per ticket in this order: c0248, c0249, c0250, c0251, c0252, c0253, c0254.

Scope decision (user, 2026-11-08): "humans approve the design, humans interact (plan mode) over the idea". c0264's Design: the README's Autonomous delivery line says an item is designed, reviewed and merged "with no human in the loop"; this issue must reword it to "a worker drafts, a person approves" and add a person-approval gate, so the README stays true.

## Non-goals
- Branch protection setup on GitHub itself (a step for the user).
- Merging anything the dispatcher did not run.

## Solution
- Merge preconditions as one pure function over the PR state, each check a named reason in the escalation.
