# Refute 001: c0253 (answers to design-review-001.md)

The review found one root cause behind most of its highs: the supervisor called `modelstep.launch` itself, outside the dispatcher, and so lost every duty the dispatcher performs around a model step. The redesign takes the captured Solution at its word ("a thin loop over the engine's `next` and the dispatcher"): the supervisor runs `./zn next` and, for what it prints, `./zn dispatch <id> --worker` as a child of the main checkout's engine (one implementation: the dispatcher keeps its per-item lock, its lifeline, its tripwire watermark and its run state; the supervisor stays model-free and restartable; the child starts with the starter's markers cleared). The dispatcher gains a worker mode for what Q3, Q8 and Q9 need. The prototype was re-cut on `proto-c0252` merged with `origin/main`, plus c0249's `next` and c0275's `claimBeat`; the v1 modules `workedge` (session launcher) and most of `supervise` and `workloop` were rewritten. Every Rules row, case and criterion below is in the revised document; the mutation check was rerun on all of it.

- F1: fixed: every session is now the dispatcher's own model step, so the wrapper first on `PATH` with `ZN_REAL_*`, the publish broker, the agent credential, `guardStart`/`vetMain`/the snapshot and the tripwire after each step all apply (`session.spec` logs the first `PATH` entry, the broker and the token of a real `./zn work --once` over the fake CLIs: AC6, E3); the loop runs no `ready`, `stop`, `block`, `done` or `lander` itself, so there is no command run with the person's credential between steps that a session could have poisoned; the loop runs `<main>/zn`, never a branch's. Who may land (d): the loop lands nothing and the run gate lands under `auto_merge`; a bot host marks itself in `~/.config/zn/host.toml` (`[work] land = false`, unreadable counts as false) and the supervisor passes `--no-run` (G5, options and cost stated; AC8). consequences: new Rules rows (`--no-run` passed, dropped gate, fail-closed host file, wrapper/broker/token end to end); the broker and the tripwire need no serving or pinning code of ours (the dispatcher's); c0252's G7 `done`-under-`ZN_HEADLESS` request is now consumed by the chain's own run gate, so `ZN_HEADLESS` is no longer a credential heuristic of ours.
- F2: fixed: the supervisor resolves the main checkout (`git worktree list`'s first entry) and refuses anywhere else (`supervise.refusal`, `command.spec` runs it in a fixture worktree); it runs that checkout's `zn`, keeps the locks, the state file and the stop file there, and reads `.models.toml` for the `--cli` check from `origin/main` with `git show` (`command.spec`: a working-tree edit that adds kimi changes nothing). The dispatcher reads item facts and settings its own way (from origin, c0117's rule), so the loop reads none. consequences: G4 becomes "per clone" and says so; Rules rows "refuses outside the main checkout" (`S15`) and "reads origin/main not the working tree" (`E08`).
- F3: fixed: one measured row per session is the dispatcher's own row writer (`record`, pending in the run state until the merge, then `deliver`). `dispatch.spec` asserts one row per session (123 tokens, the model) for the sessions of a raft's z-run step, including the quota-spent one; a new Outcomes row and AC6 name it. consequences: none of the three places (raft buffer, prep branch, rafting branch) is ours to choose: the dispatcher's rule applies to each.
- F4: fixed: (a) the supervisor never gives a claim back with `./zn stop`: every let-go is a block, and the blocks are the dispatcher's, written by c0252's pure `landcheck.escalation` (and c0250's `review-exhausted`), run as `./zn block` in the raft's worktree by the chain's `z-block` step with its exit status checked (c0252's code); (b) there is no skip list, so no starvation: `next` skips a blocked item, and the loop takes the next raft (`loop.spec`: "a blocked item is counted and the next raft is taken", with a fake `next` that prints R0010 then R0020); (c) no `ready`/`stop` cycle across runs, because nothing is stopped; (d) a draft's or a rafting pick's give-back is the chain's; (e) a crash or a stall is the dispatcher's `failed`/`lost` outcome (exit 1): the loop runs `retry` once and a second failure stops the worker with the claim held, so nothing is counted as no progress (`loop.spec`: a first failure is retried; a second stops, naming the item). Not adopted, because the finding is closed without it: the reviewer's "no progress" detector (two unchanged action lines) is not needed, because the dispatcher already caps a raft that moves nothing (c0252's `merge_retries` and `MERGE_RERUN_CAP`, then a block with its own reason `red-gate`; c0250's review rounds, then `review-exhausted`); G7's old claims ("no model to write a note", "the dispatcher's own rule") are withdrawn. The reason `design-gap` (or a new c0250 reason, which means approving c0250 again) is recorded in G7 as the alternative if the user wants the supervisor itself to block a no-progress raft. Checks before claiming: the dispatcher refuses a start with no agent credential or no installed CLI before any step (c0117), so a failed start never reaches a claim. consequences: Rules rows for exit-code mapping, retry once, blocked counted and next taken, two blocked in a row; AC4 reworded.
