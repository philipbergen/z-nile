# c0254: Workers on several hosts claim without clashing

## Problem
Workers on several machines share only `origin/main` and GitHub. Two of them must not take the same item, and the board and spend must say who did the work.

What should happen: the claim is the push of the status change to `origin/main`; a rejected push means the worker takes the next item; a stale claim (a worker that died) is released after a timeout and its worktree is not reused by another host; spend rows record host, CLI and model; the board shows which worker holds what.

Part of the z-nile vision (z-nile/README.md, section How it should work). To be delivered in the raft **R-vision** as one **stacked PR set**, one layer per ticket in this order: c0248, c0249, c0250, c0251, c0252, c0253, c0254.

Scope decision (user, 2026-11-08): "humans approve the design, humans interact (plan mode) over the idea". c0264's Design: this issue must reword the README's claim line "a lost race means taking the next item" to follow c0253's raft claim, and make the `preparing` claim a worker drafting the design for a person to approve.

Decided with the user (2026-11-11), idea interview Q1: "Rafts + design drafts" (a worker carries rafts from rafted to merge (z-ready, z-run, reviews, merge); when no raft is claimable it drafts the design of a confirmed idea and stops it at the person's `./zn approve`; a person rafts, so z-raft can ask the rank).

Decided with the user (2026-11-11), idea interview Q2: "Takeover replaces it" (c0254 drops its own timeout release of a stale claim; a lost claim on any host goes through c0274's takeover; c0254 keeps the push race, the worker's identity (host, CLI, model) on spend and the board's who-holds-what).

Decided with the user (2026-11-11), idea interview Q3: "Push every commit" (workers push their layer branch after every commit, so a taker on any host recovers all committed work; uncommitted files on a dead host are lost).

Decided with the user (2026-11-11), idea interview Q4: "Keep one raft" (c0248 to c0254 stay one raft, R-vision, delivered as one stack in that order; it starts only when every member's outside dependency is done: c0257, c0260, c0261, c0263, c0283 and the heartbeat raft c0265, c0274, c0275, c0277).

Decided with the user (2026-11-11), idea interview Q5: "Same as rafts" (a design draft follows the raft rules: a prep branch is pushed after every commit, so a taker on any host gets the draft, and a discarded prep worktree is kept until the prep's PR merges or the prep is stopped, then removed; `./zn reap` lists leftovers).

## Non-goals
- A queue server or daemon: none; git is the lock.
- Remote (cloud) runtimes (c0142).
- Taking over a lost claim and continuing from its pushed branch: c0274. Recovering the rest on the old worker's host: c0277.

## Solution
- Builds on the existing `status <id> preparing` claim and `release --force`.

## Idea
Workers on several machines share only `origin/main` and GitHub. There is no queue server or daemon: git is the lock. Two workers must not take the same raft, and the board and spend must say who did the work.

- **The claim is a push.** A worker claims a raft (c0253), or an issue whose design it drafts, by pushing the status change to `origin/main`, building on the existing `status <id> preparing` claim and `release --force`. A rejected push means it takes the next raft. A worker's `preparing` claim means it drafts the design for a person to approve (Q1, and the user's 2026-11-08 scope decision). The README's claim line, "a lost race means taking the next item", follows c0253's raft claim.
- **A dead worker's claim is taken over, not timed out** (Q2). A claim whose worker died reads lost through the heartbeat (c0265) and is taken over through c0274's takeover, on any host. The taker continues from the pushed branch (c0274), and c0277 recovers the rest on the old worker's host. c0254 has no timeout release of its own; this replaces the captured "a stale claim is released after a timeout". The lost worker's worktree is not reused by another host.
- **Every commit is pushed** (Q3, Q5). Workers push their layer branch after every commit, and a prep branch is pushed after every commit too, so a taker on any host continues from all committed work. Uncommitted files on a dead host are lost.
- **Who did the work.** Spend rows record the worker's identity (host, CLI and model), which c0280 reads. The board shows which worker holds what.

**R-vision stays one raft** (Q4): c0254 is its seventh and last layer.

Not here: a queue server or daemon, remote (cloud) runtimes (c0142), the takeover and continuing from the pushed branch (c0274), and recovery on the old worker's host (c0277).
