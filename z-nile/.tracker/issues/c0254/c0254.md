# c0254: Workers on several hosts claim without clashing

## Problem
Workers on several machines share only `origin/main` and GitHub. Two of them must not take the same item, and the board and spend must say who did the work.

What should happen: the claim is the push of the status change to `origin/main`; a rejected push means the worker takes the next item; a stale claim (a worker that died) is released after a timeout and its worktree is not reused by another host; spend rows record host, CLI and model; the board shows which worker holds what.

## Idea
Workers on several machines share only `origin/main` and GitHub. There is no queue server or daemon: git is the lock. Two workers must not take the same raft, and the board and spend must say who did the work.

- **The claim is a push.** A worker claims a raft (c0253), or an issue whose design it drafts, by pushing the status change to `origin/main`, building on the existing `status <id> preparing` claim and `release --force`. A rejected push means it takes the next raft. A worker's `preparing` claim means it drafts the design for a person to approve (Q1, and the user's 2026-11-08 scope decision). The README's claim line, "a lost race means taking the next item", follows c0253's raft claim.
- **A dead worker's claim is taken over, not timed out** (Q2). A claim whose worker died reads lost through the heartbeat (c0265) and is taken over through c0274's takeover, on any host. The taker continues from the pushed branch (c0274), and c0277 recovers the rest on the old worker's host. c0254 has no timeout release of its own; this replaces the captured "a stale claim is released after a timeout". The lost worker's worktree is not reused by another host.
- **Every commit is pushed** (Q3, Q5). Workers push their layer branch after every commit, and a prep branch is pushed after every commit too, so a taker on any host continues from all committed work. Uncommitted files on a dead host are lost.
- **Who did the work.** Spend rows record the worker's identity (host, CLI and model), which c0280 reads. The board shows which worker holds what.

**R-vision stays one raft** (Q4): c0254 is its seventh and last layer.

Not here: a queue server or daemon, remote (cloud) runtimes (c0142), the takeover and continuing from the pushed branch (c0274), and recovery on the old worker's host (c0277).

### What exists, what a layer below brings, what this issue adds
- **Exists on main.** The claim is already the push: `status <id> preparing` and `ready` publish through `publish.commit`, a lease push (`--force-with-lease` on the base it built on) that rebuilds from a fresh `origin/main` and retries when rejected, so a second claim of one item is refused by the same rules (`statusLib.canClaim`/`canMove`) and publishes nothing. `./zn worktree <name>` makes a worktree that tracks `origin/<branch>` when only the remote has it. `costrow.writer` names a spend file `<host>-<hash>.tsv`. `./zn work status` prints each active raft's holder.
- **A layer below brings.** c0253's supervisor and the dispatcher's worker mode (`./zn dispatch <id> --worker`, the exit codes `supervise.afterDispatch` reads); c0325's `ZN_MODEL` and the model cell; c0265/c0274/c0275/c0277 (R0100, not on main): the heartbeat, the takeover (`stop` then `ready` for a raft, `status <id> preparing` for an issue), the claim memory `.cache/tracker-stamp-<id>` that `beat --adopt` writes, the discard marker and the sweep. c0254 uses them and rebuilds none of them; where the prototype needs one of their functions it copies it verbatim and says so.
- **Missing, and added here.** (1) A race is lost before the claim step, at the push, and after it, and today only a refused push is told from a failure. (2) An issue's claim happens inside a model session. (3) A branch is pushed only with an upstream. (4) Nothing stops a worker whose claim was taken over from pushing onto the taker's branch, or from `finish`/`restack`. (5) A spend row says neither its CLI nor its host except by file name. (6) The board cannot say who holds a claim made on another host. (7) Nothing on a lost host marks, keeps or removes the lost worker's worktree.

### 1. The claim is the push; a rejected push means taking the next raft (AC1)
The race has three points where another host can get there first. For each pick kind (`./zn next`'s `lost|raft|rafting|draft`, c0249) this is what happens at each.
- **Before any step (the pick was read some seconds ago).** The supervisor passes the pick's kind (`./zn dispatch <id> --worker --pick <kind>`). On the run's first facts the dispatcher asks `origin/main` (`xhost.pickHeld`): a **draft** must still be `new` (or carry the stamp this run recorded); a **raft** must still be prepared in the backlog (or carry our stamp); a **rafting** issue must still be prepared, with no preparing raft on origin listing it that is not ours; a **lost** pick is `ok` here, because its takeover is itself a lease push that decides (c0274 refuses a claim restamped since the verdict). Otherwise `dispatch.next` returns `stop(EXIT.taken)` before any step, and no session starts. This replaces c0253's reading of the stopped chain as a failure (exit 1, retried, then the worker stopped holding an item it never claimed).
- **At the push.** In worker mode an issue is claimed by the script step `claim` (`./zn status <id> preparing`, run in the issue's `prep-<slug>` worktree) before z-design starts; a raft's claim is the `z-ready` step, as today; a rafting claim is `raft-plan --apply`'s `new raft`, which now refuses an issue that a preparing raft on origin lists (`H.raftHolding`, inside the publish build, which runs again on every lease retry; G11), so two hosts rafting one approved issue meet at the lease; a **lost** pick is taken over by c0274's own commands: `claim` for an issue (c0274 judges the lost claim inside `status … preparing`), `z-stop` then `z-ready` for a raft.
- **After it (a step that failed, or a run that resumes).** A failed `claim`, `z-ready` or `raft-plan` step is judged on `origin/main`, never by its exit code or its prose (`dispatcher.claimVerdict`, `xhost.claimOutcome`): **ours** when the commit that set origin's current stamp carries this attempt's token (the dispatcher sets `ZN_ATTEMPT=<token>` in a claim step's environment and the claim commit's `Worker:` trailer records it), or the stamp is the one the worker's checkout remembers: the claim landed and a later part failed (a `ready` whose main-checkout pull failed, a push that landed and reported failure), so the step is **adopted** (its history entry becomes ok) and the chain goes on, the dispatcher's beat keeping the claim alive; **lost** when the item left the state the worker picked it in under a stamp that is not its own: the run ends with `dispatch.EXIT.taken = 6`, `dropLostAttempt` removes the failed step from the run state and the worktree and branch the claim step made when they are clean and hold nothing beyond `origin/main` (the item may come back to this worker when its holder releases it), and the supervisor takes the next pick; anything else is a failure with today's handling. A rafting step is lost only when a preparing raft that is not this run's lists the issue.
- **Ownership is the stamp.** After a won or adopted claim the dispatcher reads the stamp on `origin/main` and records it (`st.claim = { id, stamp }` in the run state, and `.cache/tracker-stamp-<id>` in the worktree the work happens in: c0274's claim memory, written by the dispatcher because `ready` runs in the main checkout, which remembers nothing, and the dispatcher's beat is `--adopt --stamp S`, which writes none). A worker's chain runs a claimed item only while origin shows that stamp (`xhost.stillMine`); a run state whose history says `claim ok` but whose stamp origin no longer shows is `taken` (a supervisor that restarts holding an item another host took over ends with exit 6 and clears `held`, and never beats the taker's claim). A worker's active raft with no recorded stamp is `taken`, so a raft host A readied never reaches a model on host B.
- **The model's own claim.** z-design's step 1 says to claim. A claim this checkout already holds is an idempotent success (`status <id> preparing` finds the stamp in its memory and publishes nothing: "already claimed by this checkout"), the worker's z-design prompt says the issue is already claimed (stamp given) and to skip step 1, and the skill says the same.
- **The loop.** `workloop` records the lost item, does not count it as an item taken (`--max-items`, `--once` keep their meaning), and asks `./zn next` at once; the same item lost twice with nothing between them waits one idle period (`lastLost` is cleared by any other result). A raft the previous run held that comes back `taken` is no longer held. The summary gains one line, `claimed by another worker first: …`, only when a race was lost.
- **Not here.** No timeout, no restamp, no takeover of its own: a claim held by a dead worker is c0274's.

### 2. The lost worker's worktree is not reused by another host (AC2)
- **By construction.** A worktree lives in the clone that made it. A taker on another host builds its own from `origin/<branch>` (`./zn worktree <name>`, c0277's `worktree --takeover`, which has the same branch of `addWorktree`), and gets every pushed commit and none of the lost host's unpushed or uncommitted ones.
- **A stale start is brought forward, never discarded (F6).** A host that lost a claim race may hold a `prep-<slug>` worktree its claim step made. `dropLostAttempt` removes it when it holds nothing; and `./zn worktree <layer or prep name>` now fast-forwards a clean local branch that is an ancestor of `origin/<branch>` (the worktree at its path, or the branch before a worktree is made), keeps one that is ahead, and refuses a diverged one naming the commands to compare it (`git log <b>...origin/<b>`). Nothing local is ever discarded.
- **The lost worker cannot move the taker's work (F3, F4, F5).** Every engine push of a layer or prep branch (`./zn commit`, and `finish` and `restack`, which force-push with a lease) asks the same facts (`H.branchPushFacts`) and `xhost.pushDecision`. A worker whose claim this checkout remembers (c0274's `.cache/tracker-stamp-<id>`, else c0116's) and origin shows under another stamp (`taken`) or not at all (`ended`) is refused with **c0274's own words and its stop line**: `<id>'s claim was taken over (now <stamp>): this checkout's work is no longer the claim's; stop here (./zn lost lists lost work to pick up)` (or `<id>'s claim ended: …`), never with advice to continue on the taker's branch. A numbered copy c0277's takeover made (its `.cache/fresh` marker, or a worktree marked discarded) that remembers **no** claim on an item under a live claim on origin is refused too (`holds no claim on it`); a person's own worktree that never claimed the item is not a copy and pushes as it always did, and an item nobody claims is a person's to push. `finish` and `restack` stop first, before any fetch, on `taken`/`ended`; a checkout that never adopted a claim is refused at the push only.
- **The lease ref is never refreshed by the per-commit read (F5).** `finish` and `restack` lease on `refs/remotes/origin/<branch>`, and any fetch of that branch empties the lease (a probe of the review: a lost lead's `finish` overwrote the taker's commit). The read of origin's copy at each commit goes into a private ref, `refs/zn/seen/<branch>`, with `--refmap=` so git does not also update the remote-tracking ref (without it git does, "opportunistically": found while building the layer spec). The taker's commit survives the lost lead's `finish` and `restack` because they are refused first (the claim rule), and because the lease still means what this checkout last saw.
- **What is left on the lost host** is §7.

### 3. Every commit is pushed (AC3)
- `H.pushAfterCommit` replaces the old `push()` (pushed only with an upstream). After a `./zn commit` on a layer branch (`R####/<n>/<id>`) or in an issue's prep worktree (`prep-<slug>`), `xhost.pushDecision` returns `push` (the branch has an upstream), `push-new` (the first push, with `-u`), `refuse` or `skip`. The push is always `git push origin HEAD:refs/heads/<branch>`, the branch's own name, whatever `push.default` and the upstream (a failed `start` leaves `origin/main` as upstream) say: the remote ref is never `main`. The count of commits origin has and the worktree lacks is read from the private ref (§2); a branch origin cannot be read for, or cannot be compared, is not pushed. Any other branch keeps today's rule (pushed only with an upstream).
- **Preps.** `./zn commit -m <msg>` in a `prep-<slug>` worktree stages everything, commits and pushes; it records no spend row (prep spend is `./zn spend --phase prep`, as before). The z-design skill says to commit at named checkpoints (the Design draft, `check.sh` and the specs, the experiments and prototype patch, the review file, the answers), so a taker on another host gets the draft from its first commit, not from the last (F14).
- **A refusal or a failure is never silent (F10).** The commit stands whatever happens to the push (its spend row is written and its files are committed); the exit status follows the push, the step that cannot be undone having been done: `0` pushed or skipped by rule, **`7`** refused (under a claim, or over another worker's commits), **`8`** failed (git's words are printed: "not pushed: …; the next ./zn commit retries"). Under dispatch a refusal is also written to `.cache/push-refused`; after the step the dispatcher reads it and ends the run with `dispatch.EXIT.pushRefused = 7` naming the problem, which the supervisor reads as a stop naming it (zz-arch: exit status follows the step that cannot be undone).

### 4. Spend rows record host, CLI and model (AC4)
- The model cell is c0325's (`--model`, else `ZN_MODEL` for the authoring phases). c0254 adds `host` and `cli` as two trailing cells of a `spend.d/<writer>.tsv` row (`buffer.HEADER_WHO`; written only for a row that has them, read by cell count, so an old header and old rows are unchanged), and `Line.cli`, a fifteenth cell of a measure-buffer line that names its CLI.
- **The identity comes from the step, never from the process that folds the row (F8).** A dispatched step's rows are folded by the dispatcher's own process, so the dispatcher passes the attempt's CLI with the row: `Row.cli = attempt.cli` (the measured row of a z-design, z-raft, z-run or review step), and a code review's row is printed on the `record:` line as `--phase code-review --model <m> --cli <cli>` and folded by the author's `./zn commit --cli`, so it carries the reviewer's CLI, not the author's. `costrow.plan` stamps `host` (the machine, sanitised exactly as the file name: `xhost.hostPart`) on every row it writes, and takes the CLI from the environment (`ZN_CLI`, else the CLI's markers, else `unknown`) only for a row with none of its own **and** only for the authoring phases `capture`, `prep` and `build`, as c0325 does for the model: a reviewer's row is never labelled with the author's CLI.
- **A claim runs as the worker that follows it.** The dispatcher runs a worker's claim step (`claim`, `z-ready`, `z-stop`, `raft-plan`) with `ZN_CLI` and `ZN_MODEL` set to the first try of the step that follows it (z-design after a claim, z-run after a ready, z-raft after raft-plan): the person's CLI first, as the step itself will order its tries (`dispatcher.nextIdentity`); when nothing resolves, the worker's own CLI, else `unknown`, and no model. So the claim's trailer names the worker whose session follows, not the dispatcher's environment.
- Typed `spend.md` rows (the older format) keep their columns.

### 5. The board shows which worker holds what (AC5)
- **The record.** Every claim commit carries a `Worker:` trailer for **each item it stamps**: `Worker: <id> <stamp> host=<h> cli=<c> model=<m> attempt=<token>` (`-` for no model; the attempt only under a dispatcher). `status <id> preparing` (the raft and each member it moves), `ready` (the raft and its members), and every rafting claim (`new raft` over the raft and its members, `fold`, `unfold`, `recombine`) go through `H.withWorkers`. It sits in git history on `origin/main`, travels with the claim, and is made by the tool that publishes the claim, with the worker's identity (§4).
- **The reader.** `board.readFacts` reads the newest 500 trailers in one `git log` (no network) and `xhost.holders` names, per item, the newest trailer whose stamp is the item's current stamp. A claim since taken over, given back or finished has a different stamp, so it names nobody. The card's Run block gets a `held by` row (`host (cli, model)`), and `./zn work status` prints `worker <host (cli, model)>` on each active raft's line (the ready commit's trailer). With no trailer (a claim made before c0254) nothing is shown.

### 7. The lost host's leftover (Q5, AC7)
c0277's marker is written by a takeover on the **taker's** host, never on the lost host's disk, so a worktree that host A held for a prep or raft host B took over is never marked there, and c0277's sweep (which reads marked worktrees only) never removes or lists it (c0277's Non-goal names several hosts as c0254's, and c0277's lookup, `staleMember`, discards such a worktree only when someone asks for it again). So c0254 designs the lost host's side, with c0277's own rules:
- **Marking.** `./zn sync` in the main checkout (the same command that fast-forwards it and sweeps stale files) calls `H.lostHostSweep`: for every local layer or prep worktree it compares the claim the worktree remembers (`.cache/tracker-stamp-<id>`, else c0116's) with the stamp origin shows; when the claim is over (`heartbeat.staleMember`, c0277's rule: at least one claim it remembers is over and none is still its own) the worktree is **marked discarded**, with no numbered copy (a copy is made by the taker on its own host). A host's own claims (`held`) are never marked.
- **Keeping and removing.** A marked worktree is kept while the claim it was discarded for is live on origin (listed as "holds the discarded work of <id> (its claim is still live)"). When the work has ended (origin shows no claim: the prep merged or was given back, the raft merged or was stopped) it is removed if it holds no uncommitted file and every commit is on an origin ref or its content is already in `origin/main` (a squash-merge rewrites shas, so recovery is judged by content, as c0277 does); otherwise it is **kept and listed** ("the work of <id> ended, kept: …"), never removed.
- **Listing.** `./zn sync` prints the marked, removed and left-over worktrees, and `./zn reap` lists the leftovers (the user's rule), calling the same function without removing.
- **In the prototype** the marker is a stand-in, `.cache/discarded` (items, date, the claim it remembered, the stamp now), and the sweep rules are re-implemented from c0277's text, because R0100 is not on main. **At execution** (c0277 is in `depends_on`) the call site stays — which worktrees to mark and when — and the marker, the sweep and the listing become c0277's own `hb.discard` (called with no copy) and `hb.sweepDiscarded`; the spec cases observe the outputs (`discarded worktree`, `removed discarded worktree`, `leftover worktree`) and the directory, not the marker's file.

### Scalability
One `git ls-remote` and one single-branch fetch per `./zn commit` on a layer or prep branch, and one `git log -n 500` of trailers per board build or `work status`. N hosts racing for one item cost N lease pushes, of which one lands; the losers publish nothing and start no session. The sweep is one `git worktree list` and, for a candidate, a few local git reads per `./zn sync`. The trailer scan is bounded by the 500 newest claim commits, so an item whose claim is older shows no holder (G4's cost, stated). The tsv grows by two short cells per row.

### Maintainability
All of the decisions are in one pure module (`xhost`), each rule a function over plain facts with a spec, and each edge reads facts and calls one function. The claim states have one reader (`heartbeat.holds`), the host name one sanitiser (`xhost.hostPart`, used by `costrow.writer` too), the trailer one writer and one reader, the push one function for every engine push of a layer or prep. The dispatcher's change is five small functions and one block in the chain; the supervisor's is one branch and one flag.

### Usability
A person running two workers on two hosts sees a lost race as one line in the summary (`claimed by another worker first: R0010`) and the worker going on to the next raft, not as a failure and a stopped worker. The board card says `held by <host> (<cli>, <model>)`; `./zn work status` says `worker <host (cli, model)>`. A lost worker is told c0274's words and to stop (never to continue on the taker's branch), by a nonzero exit that a headless session cannot miss; `./zn sync` and `./zn reap` say what is left on its host.

## Regression guard
- The gate's `--affected` run is the wide net (E6). **AC8** names what must not regress and runs it: c0253's acceptance specs wherever they are (its folder while it is sequestered or active, `tests/acceptance/c0253` once done) and the tooling specs that read the code this changes: `spend`, `board`, `work`, `dispatch-texts`, `dispatch-guards`, `measure`, `claim-taken`, `status-fresh`, `worktree-fetch`, `stack-land`, `start-pr-reuse`. A regression criterion that passes before the work is normal (c0252's AC15 does): it is what keeps the layer honest. In the prep tree (`origin/main`, which does not hold c0253's code) AC8 fails because c0253's own specs cannot pass without the layer below; it passes on the prototype, which stands on c0253's.
- New regression cases in the specs: a plain dispatch of the same facts goes to `z-design` (no claim step, no pick check), a run that lost nothing prints the summary it printed before, a branch that is neither a layer nor a prep keeps today's push rule, a hand-readied raft's `finish`/`restack` are not stopped by a checkout that holds no claim.
Overrides: c0253's sequestered specs (promoted by the time this layer executes, and changed in this issue's own raft; each keeps what it pins): (1) `loop.spec`'s fake world records a dispatch call without the new `--pick <kind>` (ten cases pin the rest of the line); (2) `pure.spec`'s "AC1: a pick is run by one dispatcher call, in the documented argument order" gains `--pick raft`; (3) `dispatch.spec`'s "AC5: with every CLI out past the cap the raft is blocked with quota …" first gives the hand-readied raft back (`./zn stop R0010`) and runs `./zn dispatch R0010 --worker --pick raft --cli claude`, because a worker now runs only a raft whose claim it made.
