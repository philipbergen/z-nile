# Refutations and fixes: design review 001 (c0254)
Answered once, in one revision, by the designer (2026-11-16). Every fix is in `c0254.md` (the Design sections named), the specs of `acceptance/` and the prototype `proto-c0254`. The consequence step of each fix (new rules, state, edge cases, decisions) added the Rules and mutants rows and spec cases named, and the guesses G1 to G15 in the Design.

- F1: fixed: the whole race window is mapped per pick kind (Design §1). The supervisor passes `--pick <kind>`; on a run's first facts the dispatcher asks origin (`xhost.pickHeld`) and `dispatch.next` ends a worker's run with `EXIT.taken` before any step when a draft is no longer new or ours, a raft is no longer prepared in the backlog or ours, or a rafting issue is listed by a raft that is not ours; a lost pick is taken over by c0274's own commands (`claim`; `z-stop` then `z-ready`) whose lease decides. Ownership is the stamp the claim step recorded (`st.claim`, and `.cache/tracker-stamp-<id>`), never the run state's history; a restarted supervisor holding an item another host took ends `taken` and clears `held`. A rafting claim is exclusive through the raft's claim: `new raft` and `fold` refuse an issue a preparing raft on origin lists (inside the publish build), and a refused `raft-plan` is a lost claim step (G11). Cases: `pick :: AC1` (pickHeld per kind, stillMine, `dispatch.next` for a draft, a raft, by history, plain, lost issue and raft, owned), `race :: AC1` (two clones both `new raft` one issue), `chain :: AC1` (a draft and a raft claimed first end with exit 6 and no session; the race lost between the pick and the claim step, made to happen by a post-checkout hook, ends with exit 6; a plain dispatch is exit 1). Rules rows R2a to R3f, R11, R21. consequences: c0253's sequestered specs pin the argument list, so three of its cases change (Overrides, Regression guard); `next` still offers a rafting issue another host is rafting until that raft merges (G11, c0249's interface is untouched).
- F2: fixed: a failed claim step is judged `ours` as well as `lost` or `failed` (`xhost.claimOutcome`, Design §1). The dispatcher gives a claim step an attempt token (`ZN_ATTEMPT`), the claim commit's `Worker:` trailer records it, and the verdict reads the trailer of the commit that set origin's current stamp (`ctx.claimAttempt`), with the checkout's remembered stamp as a second source; `ours` adopts the step (its history entry becomes ok, the chain goes on and the dispatcher's beat keeps the claim alive), and the dispatcher records the stamp that landed in the run state and in c0274's claim memory of the work worktree (`recordClaim`, G13). The reviewer's recommendation is followed, with the stamp recorded after a won claim as the lead directed. Cases: `pick :: AC1` (ours by token with no memory; another token and no token are lost; a rafting step; recordClaim writes both records), `pure :: AC1`. Rows R1c, R1d, R12, R17. consequences: the trailer grows an `attempt=` field (parseTrailer is strict about it, a spec pins junk); no write to the main checkout (c0274 forbids it); the verdict makes one more read of `origin/main`'s log.
- F3: fixed: the push rule reads c0274's claim memory (`H.stampMemory`: `.cache/tracker-stamp-<id>`, else c0116's `tracker-claim-<id>`) and the dispatcher writes it at claim for rafts and issues alike (G13), so a layer's worktree holds the claim it works under. Layer-branch cases are real now: `layer :: AC2, AC3` (host A's raft layer is pushed; host B takes the raft over and pushes on top; A's next commit stands, is refused and exits 7; `finish` and `restack` are refused). G10 is restated with its true cost (below). Rows R27, R28, R22, R39. consequences: the existing in-session flow (a person readies by hand and never adopts) holds no memory, so the stranger rule is narrowed to a numbered copy (F4) rather than refusing every unheld push, which broke three promoted specs (E6).
- F4: fixed: the refusal is c0274's own words and stop line (`xhost.lostText`: "<id>'s claim was taken over (now <stamp>): this checkout's work is no longer the claim's; stop here (./zn lost lists lost work to pick up)", or "… claim ended: …"), pinned verbatim, and it never says to continue. A numbered copy that remembers no claim (c0277's `.cache/fresh` marker) is refused when the item is under a live claim (`holds no claim`), for prep and layer alike, and exits 7. Not adopted, because the finding is closed without it: the finding's wider rule, "restrict the unheld push to a branch origin does not show under a live claim for any checkout", is not adopted: a person's own worktree that never claimed the item (an in-session worker before c0274's `beat --adopt`, two promoted specs: `tests/tooling/stack-land`, `d0333/commit-land`) holds no memory and has always pushed; refusing it broke those specs in the first affected run (E6) and would stop every hand-readied raft's first commit. The narrower rule covers the scenario the finding builds on (the copy). Cases: `pick :: AC2` (exact text, ended text, no "continue"; copy refused, non-copy pushes), `race :: AC2` and `layer :: AC2` (a numbered copy refused with exit 7, the taker's tip kept). Rows R22 to R24. consequences: G10 restated: a copy made by a takeover on the lost host is the one case an unheld push is refused.
- F5: fixed: the lease ref is never refreshed by the per-commit read. Origin's copy of the branch is read with `git ls-remote` and fetched into a private ref, `refs/zn/seen/<branch>`, with `--refmap=` (G8): without it git updates `refs/remotes/origin/<branch>` "opportunistically" even for a refspec on the command line, which the first layer spec showed. `finish` and `restack` stop first on a claim taken over or ended (`H.refuseLostLayer`), before any fetch. The reviewer's probe is a spec case: `layer :: AC2: host A's finish and restack are refused …, and the taker's commit survives` (origin still has the taker's file) and `AC2, AC3: … origin keeps the taker's tip` (the remote-tracking ref is unchanged, the private ref is the taker's tip). Rows R25, R26 (today's fetch). consequences: a ref namespace of our own in the clone (private); `finish`'s own full fetch (existing) refreshes the lease ref by itself, so the claim refusal is what protects the taker, not the lease: said in §2.
