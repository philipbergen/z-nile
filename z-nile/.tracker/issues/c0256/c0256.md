# c0256: Dispatch retry passes answer

## Problem
dispatch: a headless step that stops with questions.md gets the user's answer back when the run is retried

c0117 (`./zn dispatch`) stops a step that needs the user with `.cache/dispatch/<id>/questions.md`; the user answers and retries, but c0117 defines no input that carries the answer into the re-run step. c0247 (z-ticket confirms intent) needs it: a headless z-ticket (`dispatch new "<words>"`) writes its restatement as a question and stops, and the user's approval or correction must reach the retried step.

Decided with the user (2026-11-05), c0247 design review 001 F1: "Restate via questions.md": headless z-ticket writes the restatement to questions.md and stops "needs the user"; the user approves or corrects it with `dispatch retry`.

Scope decision (user, 2026-11-08): "Widen c0256". c0256 hands the re-run step the full list of restatements and corrections with their dates and the user's reply, not only the latest question and reply. (Decided during c0260's prep, which depends on c0256 for it.)

## Non-goals
- The wording of z-ticket's confirmation is c0247's. This chore only gives a retried step the user's answer.

## Solution
- `./zn dispatch retry <id>` accepts the user's answer to the questions.md the step wrote (a file or text) and hands it to the re-run step with the question, so the step reads both.
- It works for any step that stops with questions, not only z-ticket.
- Detail from c0247 design review 002 F1: `dispatch new` keeps the original words so a retry can re-run the step; a step that stops with `questions.md` is recorded as "needs the user", never as a failure ("z-ticket made 0 issues"); the retry of a `new` run names its id; and the reply reaches the re-run step together with the question.
- On `dispatch retry` (and when a re-run step starts), the dispatcher hands the re-run step every restatement and every correction of the capture so far, each with its date, in order, together with the user's reply to the latest question; the re-run step reads them from the state folder the dispatcher names in its prompt. c0260's capture record copies them, dated, into `## Ask (verbatim)` and records the restatement and the reply as `### Q1` of `## Interview`. A dispatched capture's ask is dated from the first message, not from the retry. (Needed by c0260, which depends on c0256 for it.)
