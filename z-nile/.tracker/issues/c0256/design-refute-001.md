# Answers to design review 001

All eleven findings are fixed in the design, the specs and the prototype; none is refuted, and no outcome the Problem asks for was cut. Each reviewer probe (P1 to P8) became a case.

- F1: fixed: a plain retry now takes what the user wrote into `questions.md` as the answer (the whole edited file, stored verbatim; zz-rules line 177 stays true); a flag together with an edit is refused; `NO_REPLY` is told to the step as "your question stands unanswered", not "settled"; the stop message says all three ways to answer; consequences: a new rule (edited file vs. the copied question, byte for byte), so cases `what the user writes into questions.md is their answer` and `an edited questions.md together with --answer is refused` (retry.spec), the no-reply prompt case (exchange.spec) and mutants C15, C16, M26.
- F2: fixed: a question file records the step that asked it (`step:` line, strict); the prompt has three forms: the step that asked the latest question is told it is a re-run, any other step is told the history settles other steps' questions and not its own, and a no-reply re-run is told its question stands; c0260's z-design confirmation therefore sees the capture's conversation as others' and is not told the capture's approval answers it; consequences: the format gained a strict field (parse refuses a question without it and any other kind with it: M17, M18), the prompt gained a pure rule (M24, M25), and Existing work says how c0260's stop reads; cases in exchange.spec and capture.spec (z-design's prompt), mutant C29.
- F3: fixed: the slot `new` is saved as finished (`ok`, "captured as <id>", seal dropped) before the run moves to the issue; every stop of a capture names `new` (the facts carry the display id); `retry new` re-runs a capture that has its ask (failed ones included) and, without an ask, clears the slot (a c0117-era waiting capture is set aside as `answered-N.md`) and refuses an `--answer`; consequences: the slot's state, the retry's two meanings and the migration of c0117-era runs are all pinned: two captures in a row, a failed capture retried by name, a waiting capture left by c0117 cleared, an abandoned exchange set aside (capture.spec), mutants C27, C28, C31; the lesson z-design/slot-state-proven-by-two-runs.
- F4: fixed: every exchange file is written with `sh.writeReplacing` after the reader has refused a link at the folder, at any entry and at `questions.md` (`readlink`, since `fs.isFile` follows links); the dot-name temporary is gone; consequences: one reader behind every use (`exchangeRead`) and a spec that plants a link at the final name, at the folder and at `questions.md` and checks a decoy file byte for byte (mutants C17, C18, C19); the remaining window (between the read and the write) is a `reasoned` row; the lesson zz-arch/writers-under-cache-replace-links.
- F5: fixed: the dispatcher keeps a seal (sha256 of each file it wrote) in `state.json` and compares it at every read (after each step, at a retry, at a step start): a step that rewrote, added or removed a message fails with the file named; consequences: a seal can strand the user (setting the folder aside leaves the seal reporting every file as removed, the dead end review 001 F3 warns about), so a damaged exchange is refused with the way out named, `retry <id> --forget-exchange`, which sets the folder aside (never deletes it) and drops the seal; a flag only the user passes (a new boolean option in `main.luau`); cases: the forged-record case ends with the refused retry and the forget, the seal cases (M19 to M21), mutants C20, C32, C33.
- F6: fixed: a model step started by hand while `questions.md` waits starts nothing (exit 3, names the retry), as `dispatch <id>` already stops; the retry sets the question aside first, so its own start is allowed; consequences: no promoted spec starts a step by hand while a question waits (grep in the Design); case in step.spec, mutant C25.
- F7: fixed: the exchange is checked after `record`'s inputs exist: a refusal marks the step `failed` with the reason, its spend is written as for any step, and the question is set aside as `questions-refused-N.md` so the chain stops on the failure and the next run says why (never "lost"); consequences: one more file name in a run folder; cases `a step that rewrites…` and `a step that leaves a stray file and a question…` (spend rows counted), mutants C21, C22.
- F8: fixed (option c, no scope cut): a nested step's stop tells its author to write the questions into its own `$ZN_DISPATCH_DIR/questions.md` and stop; the user's answer reaches the re-run author, which dispatches its review again; consequences: the nested message no longer names a retry that refuses; case `a review the author started that needs the user tells the author to ask`, mutant C26. The reviewer's option (a) (moving the question up and sharing the exchange with nested folders) adds shared state between two runs' folders for a case the skills say should not occur (a reviewer writes `review.md`); option (b) leaves "any step" short. If the user prefers (a), it is a follow-up.
- F9: fixed: rows and cases for the set-aside exchange (C30), the stray/dateless refusals at step start (the reader parses every file: `exchangeRead`; C14), the three prompt forms (M24 to M26) and every new rule; `mutants.py` counts a mutant killed only when the spec's own summary shows failed cases with a `FAIL … ::` line (not on a load error, a timeout or the sweeper's exit 71); consequences: none beyond the cases.
- F10: fixed: the answer is written first, then `questions.md` is set aside; a retry that finds an answer recorded and `questions.md` still waiting only finishes the move and refuses a new `--answer` ("already recorded"); an answer the exchange cannot take is refused before anything moves; the Accepted note is replaced by a case; consequences: one more state, pinned by `a retry that died after storing the answer is finished by the next one`, mutant C23.
- F11: fixed: an answer over 64 KiB, blank or with a NUL byte is refused with the reason, and `--answer-file` must be a regular file; consequences: the limit is a constant (`exchange.LIMIT`), pinned at the boundary (65536 accepted, 65537 refused: M22), the NUL rule (M23) and in retry.spec (C24).
