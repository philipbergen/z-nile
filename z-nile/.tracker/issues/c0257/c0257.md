# c0257: Omarchy board app

## Problem
The only views of the tracker are `./zn list` in a terminal and the browser page `./zn board` writes. On an Omarchy desktop the user wants a native app: an icon in the omarchy-shell bar (with the active ticket count) that opens a tiled window showing every ticket and raft and what is going on with each. Tickets and rafts sit in stage columns. Each card shows its type, project, pipeline stage, raft, blockers and open pull requests. Dragging a card reprioritizes it. One click opens a ticket in a chosen AI CLI, in a new terminal with full interaction, to dive into the details. The app lives in the repo, in `z-nile-omarchy/`, next to `z-nile/`.

What exists (built 2026-11-05, running from `~/.config/omarchy/plugins/znile.board/`), and what this issue lands:
- A bar icon with the active count. A click toggles the window and a right click refreshes it.
- Columns New, Preparing, Prepared and Active, with Done behind a toggle, and a Tickets/Rafts switch. The header holds a stage bar, a 30-day opened/closed chart, and project, type and blocked filters, plus a search.
- Cards show:
  - the type letter in a coloured circle, the id and the project
  - a five-step pipeline and the status
  - the raft, and the blockers. Outside dependencies block, while in-raft ones only order the tickets ("after …"). A raft card says "k of n tickets blocked".
  - open PRs, matched by the ids in each PR's branch and title, with a ticket also showing its raft's PR
  - the next command
- Every id is a link: clicking one jumps to that card.
- The details popup opens beside the card. It has a big view and a GitHub file link. The description renders as markdown, with HTML and images neutralized and inline code styled. Wide code scrolls sideways, and a copy box holds the next command.
  - It never draws what crashes Qt 6.12 (the whole shell segfaults in `QSGBatchRenderer::prepareAlphaBatches` when it lays such markdown out again, d0389): inline code is coloured monospace with no background tint, and a markdown table is shown as a code block. Found when the user reported c0278, c0141 and c0083 crashing the shell; reproduced and bisected in a standalone qml probe (12 of the 26 tickets probed crashed, none after).
- A dive-in opens the chosen installed AI CLI (Claude, Grok, Kimi, …) in a new terminal in the repo, in its ask-first mode, seeded with a discussion-only prompt.
- Dragging reorders within a column for the session. A `rankCommand` setting will persist it once znile has priority. Until then, a lower ticket number means a higher priority.
- Touchpad scrolling follows the fingers. The theme's colours are followed live.
- An `unblocked` chip beside `blocked` shows only items with nothing open in their way (a ticket with no outside blocker, a raft with no blocked ticket), with its count. The two are a pair: turning one on turns the other off. Added by the user (2026-11-15): "The app needs a button for "unblocked" just like it has for "blocked"".
- Esc steps back one level from wherever the keys are, the search box included: the big view goes back to card size, a card-size popup closes, then the search clears, then the window closes. Clicking a card or its popup takes the keys back from the search box. Added by the user (2026-11-16): "If a ticket is in full screen esc should go back to card size, esc at card size should close".
- A `needs approval` chip, with its count, shows only tickets whose design is ready, not yet active, with no `./zn approve` record (`approval.md` beside the document, which fetch.sh lists as `approved`), and rafts holding such a ticket. A record whose hash no longer matches is `./zn approve --check`'s to find, not the chip's. Added by the user (2026-11-16): "I need a button for "Needs approval"".
- A ticket card shows how many guesses are waiting for the user's review: each `Guess (pending user, <date>)` marker in its whole document (z-design's form; a ruled guess is rewritten as the decision, and a marker quoted in backticks is a mention, not a guess). A raft card names its tickets that have them. Added by the user (2026-11-16): "Can you also show on the card which tickets have guesses I haven't revieweed".

## Non-goals
- Priority itself, which is being worked on elsewhere. The app only calls the `rankCommand` hook.
- `./zn board --json`. The app lifts the JSON the board page already embeds and switches to `--json` when it exists.
- The browser board's own work: per-project tabs (c0118) and a live server with actions (c0121).
- Registering `z-nile-omarchy/` as a project with its own gate home. It holds QML and shell scripts, no Luau.

## Solution
- Commit the plugin as `z-nile-omarchy/znile.board/`, an omarchy-shell plugin (manifest, QML, `Model.js` with its node tests, `fetch.sh`, `prs.sh`, `agents.sh`). Install it by symlinking that folder into `~/.config/omarchy/plugins/`.
- Data is read only through `./zn board`, with no second tracker parser.
- All tracker text is untrusted. It is drawn as plain text, or as markdown made inert by `Model.safeMarkdown`. Every external command takes one value per argument and none goes through a shell.
