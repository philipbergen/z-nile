# c0258: Land prints usage and retries cheaply

## Problem
`./zn land --help` ignores the flag and runs the whole local full gate (6 to 11 minutes). A capture also loses the race to `main` again and again: with several sessions publishing tracker state, `land` reports "lost the race to main 3 times: run land again" after each full gate, and a rerun repeats the full gate. On 2026-11-05 two attempts (about 17 minutes) failed this way, and a third run found the change already landed ("nothing to land") because an earlier run had pushed it after all.

What should happen: `land` (and every `./zn` subcommand that takes `-h`/`--help`) prints usage and exits; when `main` moved only by tracker-only commits (the publisher's classes, touching none of the capture's files) since the gate passed, `land` merges and pushes without rerunning the full gate (the zz-rules Merging rule of c0152); on a lost push race it re-checks "already landed" before reporting a loss.

## Non-goals
- Changing what the full gate checks.
- Merging PRs (c0152 owns the rule for PRs); this is the capture landing.

## Solution
<!-- The approach in one paragraph. -->
`./zn` reads `-h` and `--help` itself before any command runs: `./zn -h` prints the whole usage, and `-h`/`--help` after any command prints that command's entries from the usage text and runs nothing (no repository guard, no handler); the shell front (`zn`) lets `approve --help` through, and the bounded runner answers `./zn run --help` itself. `land` decides what to do after each push with a new pure module, `landrace`: a push that reports a failure while `origin/main` holds its commit has landed; a lost race merges the new `main` and pushes again, running the gate again only when `main` moved by more than tracker state (`trackerstate.checkEach`, the broker's and the tripwire's rule) or changed one of the capture's files since the gate last passed; a branch whose own commits `origin/main` already holds the changes of says "already landed" and exits 0, also when it has merged that `main` since. One land makes up to ten pushes; a publish broker that gives no answer stops it at once, and giving up names the last push's error. The fold of the gate's spend row is undone before each merge (git refuses to merge over the staged row, which today fails every lost race) and redone after it.

## Design
### Where main is today (read on this branch's base, e92389cc)
- #291 (2026-11-10) already made `land` run `z-nile/check.sh --static` (about 4 s here) instead of the full gate, and a lost race already merges the new `main` and pushes again without the gate, for up to 3 pushes, whatever moved `main`. So the Problem's "6 to 11 minutes" per attempt is gone; what is left is below.
- `flags` (main.luau) treats `--help` and `-h` as options that take the next argument, and no handler reads them, so `./zn land --help` runs land, and `./zn new issue c x --help` creates an issue. `./zn -h` prints the usage and exits 1 (an unknown command). `./zn approve <id> --help` is refused by `zn` itself under the dispatcher or without a terminal. `./zn run --help` is refused by the runner as an unknown option.
- A live bug (experiment E1): the gate's row is folded into the index (`costrow.writeFiles` stages it) before the first push, and a lost race then runs `git merge`, which refuses ("Your local changes ... would be overwritten by merge"). Every real land has a folded row, so today every lost race ends in "merging origin/main failed".
- No "already landed" check: a branch whose change an earlier land pushed merges to an empty diff and is refused as "nothing to land" (exit 1), which reads as a failure. In the 2026-11-05 case the branch had also merged the `main` holding its landed commit (a lost race's `take(now)`, or `./zn sync`), so its merge base had moved past its own commit and even a diff from the merge base reads nothing (design review 001 F2).

### Decisions this relies on
- zz-rules, Merging, step 4 (c0152): "A re-run is required only when `git diff --name-only <the main you gated> <the main you merged>` names a path that selects a spec for this pull request ... Commits that touch only tracker documents (a project root, or `z-nile/next`) select none and need no re-run." The capture's version of it is the Problem's own: "when `main` moved only by tracker-only commits (the publisher's classes, touching none of the capture's files) since the gate passed". So the judge is `trackerstate` (the one definition every guard that lets tracker-only changes reach `main` uses: the git wrapper, the broker, the tripwire), from the `main` the gate last passed on, not the selector.
- `trackerstate.luau`'s header: "Like every guard here it catches honest mistakes ... it is not a boundary" — the regate rule decides only whether to run the gate again; the push itself is still judged by whoever judges it today (the broker under the dispatcher, the server otherwise). No game-design decision applies: this is tooling.

### 1. Help (`-h`, `--help`)
- **`z-nile/engine/usage.luau`** (new, pure, `--!strict`):
  - `usage.wantsHelp(opts: { [string]: { string } }): boolean` — true when `opts["-h"]` or `opts["--help"]` is set. It reads the result of `flags`, so a value another option takes (`land -m -h`, `new ... --desc --help`) is never help.
  - `usage.of(text: string, name: string): string?` — the entries of `name` in `text` (main.luau's `USAGE`): every line that starts with exactly two spaces and whose first word is `name` (the whole word, never a prefix: `work` is not `workstreams` or `worktree`), with its continuation lines (three or more spaces), in text order, under a first line `usage: ./zn <name> ...`. Nil when there is none.
- **`z-nile/engine/main.luau`**:
  - `flags` adds `-h` and `--help` to its boolean options (`opts[a] = { "true" }`), so neither takes the next argument.
  - The bottom dispatch: `./zn -h` and `./zn --help` print `USAGE` and exit 0. An unknown command (with or without `--help`) still prints `USAGE` and exits 1. For a known command, `flags(rest)` moves above the repository guard; when `usage.wantsHelp(opts)`, it prints `usage.of(USAGE, name) or USAGE` and exits 0 before `guardRepoRoot` and the handler. So help runs nothing, in any checkout, and needs no per-command code.
  - `USAGE`'s first line gains `(./zn <command> -h prints that command's entries)`.
- **`zn`**: the `approve` branch skips its dispatch and terminal refusal when an argument is `-h` or `--help` (as for `--check`), so `approve --help` reaches the engine's help. `run` is not touched here: it never reaches the engine.
- **`z-nile/lib/bounded.pl`**: among the runner's own options (before `--` or the command), `-h` or `--help` prints `usage: ./zn run [--time S] [--cpu S] [--report FILE] [--] <command> [args...] (S: whole seconds, --time 1..<max>, default <default>)` on stdout and exits 0. After the command, every argument is the command's (`./zn run --time 5 -- echo --help` prints `--help`).
- Every command the engine defines has a `USAGE` entry (pinned: `usage.spec` lists every `function cmd.<name>(` and `cmd["<name>"] = function` in main.luau and asks `usage.of` for each).

### 2. `land` after each push
- **`z-nile/engine/landrace.luau`** (new, pure, `--!strict`):
  - `landrace.TRIES = 10`: the pushes one land makes.
  - `export type Step = "landed" | "no-answer" | "unmoved" | "give-up" | "regate" | "again"`.
  - `export type Facts = { attempt: number, max: number, pushed: boolean, answered: boolean, moved: boolean, contains: boolean, trackerWhy: string?, touched: { string } }` (`answered` is false when the publish broker gave no answer in its wait).
  - `landrace.next(f: Facts): (Step, string?)`, in this order: `pushed` or `contains` → `landed`; not `answered` → `no-answer`; not `moved` → `unmoved`; `attempt >= max` → `give-up`; `trackerWhy` → `regate`, `main moved by more than tracker state: <trackerWhy>`; `touched` not empty → `regate`, `main changed this capture's <paths, ", ">`; else `again`.
  - `landrace.touched(own: { string }, changed: { string }): { string }` — the paths in both, whole paths only, sorted, each once.
  - `export type Start = "land" | "already" | "nothing"`; `landrace.start(own: number, left: number): Start` — `left > 0` → `land`; else `own > 0` → `already`; else `nothing`. `own` counts the paths the branch's own commits change (below), `left` what the merged branch still changes against `origin/main`.
- **`z-nile/engine/broker.luau`**: `broker.NO_ANSWER = "no answer from the dispatcher's publish broker"`, the start of `broker.request`'s answer when none came in `broker.WAIT_SECONDS` (the message itself is unchanged: `<NO_ANSWER> in 600 s`).
- **`cmd.land`** (main.luau), the reads and writes around it (the scope, approval and stale-tree checks stay as they are):
  1. `git fetch origin main`; `base` = `origin/main`; `own` = the number of distinct paths `git log --no-merges --format= --name-only <base>..HEAD` names, read before any merge: what the branch's own commits that `origin/main` lacks change. Not a diff from the merge base: a branch that merged the `main` holding its landed commit (a lost race, `./zn sync`) has its merge base past its own commit, and that diff reads nothing (design review 001 F2). The same `own` serves every `take`.
  2. `take(at)`: merge `at` (a conflict aborts and fails as today), `refuseStale()`, then `left` = the paths of `git diff --name-status --no-renames at HEAD`; `landrace.start(own, left)` = `already` returns true at once. Otherwise `approvedDrift(at)` and `captureScope(diff, at)` as today (a branch with no change at all still fails there: "nothing to land: this branch has no change against origin/main").
  3. `take(base)` true: `git reset --hard base`, print `already landed on main: origin/main <base> holds every change of this branch; remove this worktree: git -C <main> worktree remove <root> && git -C <main> branch -D <branch>`, exit 0. No gate, no push.
  4. Run the gate (`PICKMAN_LAND_GATE` or `z-nile/check.sh --static`; a failure: `the gate failed: nothing was pushed`). `gated` = `base`. The capture's paths = `git diff --name-only base HEAD` plus the folded row files. `fold()`: plan and write the cost rows (`costrow.plan`, `costrow.writeFiles`), as today.
  5. For `attempt` 1 to `TRIES`: `commit-tree` on `parent` (first `base`), push it (the broker under the dispatcher, else `git push origin <sha>:refs/heads/main`); `answered` is false only when the broker's answer starts with `broker.NO_ANSWER`. When the push failed: fetch, `now` = `origin/main`, `moved` = `now ~= parent`, `contains` = moved and `git merge-base --is-ancestor <sha> <now>`; when answered, moved, not contains and `attempt < TRIES`, `trackerWhy` = `trackerstate.checkEach(git, gated, now, rootsAt, true)` (`rootsAt(ref)` = `projects.roots(projects.at(ref))`, as the broker judges) and `touched` = `landrace.touched(capture paths, git diff --name-only gated now)`. Then `landrace.next`:
     - `landed`: write the buffer (`costrow.writeBuffer`), `git reset --hard <sha>`, fetch, print `landed <sha> on main; remove this worktree: ...` (after a push that reported a failure: `landed <sha> on main (the push reported a failure; origin/main holds the commit); remove this worktree: ...`), kick the watch net, exit 0.
     - Anything else first undoes the fold (`costrow.restore`, `git reset`), so the tree and index are HEAD's again (the E1 fix).
     - `no-answer`: fail `<the broker's answer>: run land again (its start check finds a push that landed late)`. Not retried: each try would wait another 600 s, and a late push is found by the next run (`contains` or the start check).
     - `unmoved`: fail `the push failed (origin/main did not move): <git's output>`.
     - `give-up`: fail `lost the race to main 10 times: run land again (last push: <the last push's output>)`.
     - Otherwise `take(now)` first, before any regate (the gate runs on the merged tree); true → as step 3 with `now` (main took the capture's own change meanwhile: a duplicate land, a broker that pushed after it gave up).
     - `regate`: print `<why>: running the gate again`, run the gate (a failure pushes nothing and leaves the tree clean: the fold is undone), and `gated` = `now`.
     - `fold()` again; `parent` = `now`; next attempt.
  - The regate judgement is always from `gated` (the `main` the gate last passed on) to `now`, so two tracker-only races in a row never regate, and a race after a regate is judged from the regated `main`, not the first.
- **Fails closed**: `trackerstate.checkEach` returns a reason for any git failure or an unreadable registry, which is a regate: every doubt runs the gate. The ten-push bound and the gate's own bound (`check.sh`) bound the command.
- **Server authority**: none here (tooling). The push is judged as today: under the dispatcher by the broker (`broker.request` from `cmd.land`, unchanged), whose answer is `pushed`.

### Scalability
- Help: no git call and no file read beyond the engine; one Lune start (`./zn run --help`: one perl start).
- Per lost race: one fetch, two `rev-parse`, one `merge-base --is-ancestor`, `trackerstate.checkEach` over the first-parent commits of `gated..now` (each: `rev-parse`, `diff-tree`, two full-tree `ls-tree`, a `cat-file` per sequestered file it changes, and `projects.at`'s registry read), one `diff --name-only`, the merge, the stale/approval/scope checks and the fold. Measured (E4): about 50 git calls per lost race (514 over ten), about 3 s each in the spec, where a bash stand-in sits in front of every git call and makes a race push of its own; it grows with the commits per race and the tree size (the full-tree `ls-tree`). At most ten pushes, and the gate runs at most once plus once per non-tracker move. Under the dispatcher each push is a broker round trip (the dispatcher fetches, judges and pushes); one that gets no answer waits `broker.WAIT_SECONDS` (600 s) once and ends the land, so the worst case is one 600 s wait, not ten.

### Maintainability
- A new command needs only its `USAGE` entry for help (the usage spec fails without one). A new reason to regate is a `Facts` field and a line in `landrace.next`, tested in process. What counts as tracker state stays in `trackerstate` alone (one reader), and the registry is read through `projects.at`.

### Usability
- Lines printed (exact): `usage: ./zn <name> ...` plus the entries; `already landed on main: origin/main <sha> holds every change of this branch; remove this worktree: ...`; `landed <sha> on main (the push reported a failure; origin/main holds the commit); remove this worktree: ...`; `main moved by more than tracker state: <sha>: <why>: running the gate again`; `main changed this capture's <paths>: running the gate again`; `lost the race to main 10 times: run land again (last push: <output>)`; `no answer from the dispatcher's publish broker in 600 s: run land again (its start check finds a push that landed late)`. A branch whose own commits cancel out (an edit and its revert) also says `already landed`, exit 0: `main` lacks nothing it has. Every refusal still names its rule (`nothing to land`, `the gate failed`, `the push failed (origin/main did not move)`).
- Exhaustive lists it joins: `flags`' boolean options (`-h`, `--help`), `USAGE`'s header, `zn`'s approve exemption, `bounded.pl`'s option loop. `READ_ONLY` and the guard are untouched: help returns before them.

## Acceptance criteria

### Checked
- AC1: `./zn -h` and `./zn --help` print the whole usage and exit 0, and `-h` or `--help` after any command prints that command's entries (`usage: ./zn <name> ...`) and exits 0 having run nothing (no merge, gate, push or new item; `approve` is not refused; `./zn run --help` is the runner's own); a `-h` or `--help` that is another option's value, or an argument of the command `./zn run` bounds, is not help; an unknown command still exits 1; every command the engine has has a usage entry, and the usage names `-h`.
- AC2: after a lost race, `land` merges the new `main` and pushes again without running the gate when `main` moved, since the gate last passed, by tracker state alone and changed none of the capture's files; otherwise it runs the gate again on the merged tree first, saying why, and a failing rerun pushes nothing and leaves the tree clean; a race whose `main` already holds the capture's change says `already landed` with no second gate run; the gate's spend row is in the commit it pushes after a race.
- AC3: one land makes at most ten pushes with one gate run when every move was tracker state; a failed push while `main` did not move is a push failure; a publish broker that gave no answer stops the land at once; after the tenth lost race it fails with `lost the race to main 10 times: run land again (last push: ...)`, having pushed nothing of its own and left the tree clean, and run again it lands.
- AC4: a push that reports a failure while `origin/main` holds its commit has landed (`landed <sha> on main (the push reported a failure; ...)`, exit 0, the branch at `main`); a branch whose own commits' changes `origin/main` already holds, also after it merged that `main`, prints `already landed on main: origin/main <sha> ...` with the removal command, exits 0, and runs no gate and no push; a branch with no change of its own still fails with "nothing to land".
- AC5: zz-rules' "Landing a change" step 2 states the regate rule, the ten pushes, the landed and already-landed outcomes and `-h`/`--help`, the skill no longer says "a lost push retries the push, not the gate", and the z-ticket lesson `confirm-landed-before-removing` counts `already landed on main` as landed and says land gives up after ten lost races.
