# c0258: Land prints usage and retries cheaply

## Problem
`./zn land --help` ignores the flag and runs the whole local full gate (6 to 11 minutes). A capture also loses the race to `main` again and again: with several sessions publishing tracker state, `land` reports "lost the race to main 3 times: run land again" after each full gate, and a rerun repeats the full gate. On 2026-11-05 two attempts (about 17 minutes) failed this way, and a third run found the change already landed ("nothing to land") because an earlier run had pushed it after all.

What should happen: `land` (and every `./zn` subcommand that takes `-h`/`--help`) prints usage and exits; when `main` moved only by tracker-only commits (the publisher's classes, touching none of the capture's files) since the gate passed, `land` merges and pushes without rerunning the full gate (the zz-rules Merging rule of c0152); on a lost push race it re-checks "already landed" before reporting a loss.

## Non-goals
- Changing what the full gate checks.
- Merging PRs (c0152 owns the rule for PRs); this is the capture landing.
