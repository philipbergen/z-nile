# c0260: Capture interview and idea review

## Problem
User (2026-11-07): "we also need better z-ticket command that really challenges the idea and writes it out both the verbatim given by the user and each question asked and its answer and then with all that kept on the ticket write out a clean fully formed idea and reviews that in a clean adversarial agent to make sure that the written out idea actuall corresponds to what the user did, then confirm the idea as it now stands with the user. Then z-design takes over (as it stands today), writing acceptance tests as code and a design and reviewing back and forth."

z-ticket today sharpens the user's words into a Problem and lands it. It asks nothing about the idea, keeps no record of the user's own words or of any exchange, and nothing checks the Problem against what the user said. The idea stage is one of the two places a human works (README, Intent; c0264), so it has to be thorough. What should happen:
- **Verbatim.** The user's ask is kept on the ticket word for word, every message of it, dated.
- **Interview.** z-ticket really challenges the idea: it asks the questions that expose gaps, conflicts, edge cases and unstated assumptions. Every question and its answer is kept on the ticket, in order.
- **Clean idea.** From the verbatim ask and the interview, all kept on the ticket, z-ticket writes a clean, fully formed idea.
- **Idea review.** A clean adversarial agent (fresh context, the sharp model, c0261) checks that the written idea matches what the user said: nothing dropped, nothing added, nothing bent. Its findings are answered before the user sees the idea.
- **Confirmation.** The user confirms the idea as it now stands, and the confirmation is recorded on the ticket. Only a confirmed idea goes to z-design, which takes over as it is today.

## Non-goals
- Changing z-design, which takes over as it is today.
- The basic restatement and approval before the stub is created: that is c0247 (being prepared). This issue builds on it.
- Which model is sharp (c0261) and who is recorded as having confirmed (c0263).

## Solution
- New sections on the issue doc: `## Ask (verbatim)`, `## Interview` (Q and A pairs), `## Idea`, `## Idea review`, and a confirmation line with who and when.
- The idea review is a zz-review mode (`--mode idea`) whose reviewer sees only the verbatim ask, the interview and the idea.
- The full-force review (c0262) reads these sections as "the original ask".
