# c0260: Capture interview and idea review

## Problem
User (2026-11-07): "we also need better z-ticket command that really challenges the idea and writes it out both the verbatim given by the user and each question asked and its answer and then with all that kept on the ticket write out a clean fully formed idea and reviews that in a clean adversarial agent to make sure that the written out idea actuall corresponds to what the user did, then confirm the idea as it now stands with the user. Then z-design takes over (as it stands today), writing acceptance tests as code and a design and reviewing back and forth."

z-ticket today sharpens the user's words into a Problem and lands it. It asks nothing about the idea, keeps no record of the user's own words or of any exchange, and nothing checks the Problem against what the user said. The idea stage is one of the two places a human works (README, Intent; c0264), so it has to be thorough. What should happen:
- **Verbatim.** The user's ask is kept on the ticket word for word, every message of it, dated.
- **Interview.** z-ticket really challenges the idea: it asks the questions that expose gaps, conflicts, edge cases and unstated assumptions. Every question and its answer is kept on the ticket, in order.
- **Clean idea.** From the verbatim ask and the interview, all kept on the ticket, z-ticket writes a clean, fully formed idea.
- **Idea review.** A clean adversarial agent (fresh context, the sharp model, c0261) checks that the written idea matches what the user said: nothing dropped, nothing added, nothing bent. Its findings are answered before the user sees the idea.
- **Confirmation.** The user confirms the idea as it now stands, and the confirmation is recorded on the ticket. Only a confirmed idea goes to z-design, which takes over as it is today.

### What main lacks, and this issue builds (verified by reading `cmd.idea`, `idea.challengePrompt`, `captureScope` and by the acceptance specs failing on main)
1. **The verbatim ask and every question and answer are kept nowhere.** `--text` takes only the rough idea. Built: `## Ask (verbatim)` and `## Interview`, written by `./zn idea <id> --record <file>`.
2. **The challenge never gets what the user said.** `idea.challengePrompt(doc)` sees only the author's draft, so it cannot find a dropped, added or bent word. Built: the author and the challenger are given the Ask and the Interview, and the challenger is told to check the idea against them.
3. **No recorded confirmation.** Built: `## Confirmation`, written by `./zn idea <id> --confirm "<words>"`.
4. **No dispatched-capture path.** Worse, `./zn land` refuses what `./zn idea` writes: `captureScope` (`main.luau` ~2314) allows a capture to change only a draft issue's title, `depends_on` and sections, and refuses a new `idea-review-NNN.md` (a file of the folder that is not the document) and the `idea:` line moving to `challenged`; so z-ticket step 6 cannot land an idea-stage ticket (spec `land.spec` :: "AC6: land pushes the document with its Ask and Interview, the idea line and the idea review and refute in one commit" fails on main). Built: land carries them; `--unattended` records the dispatched form; a dispatched run never lands a `Confirmed` line; z-design confirms an unattended capture before designing.
5. **No agent-filed exemption.** Built: `./zn new issue … --filed-by <source>`.
6. **Only tickets created after c0260 lands** are judged (the user's decision): the mark `capture: required` and the claim gate.

### The pieces

`idea.recordText`, `idea.apply`, `openlist` and the three splices below all use them. `check(doc, reviews)` judges the record: the three sections (`## Ask (verbatim)`, `## Interview`, `## Confirmation`) once each and in order, a record that is still growing has the first ones only; every message is `### Message YYYY-MM-DD` inside a fence (an unclosed fence is an error); `### Qn` blocks number from 1 without gaps, each with `Question:` and `Answer:` (`Options:` optional); the Confirmation is one line, or an `Unconfirmed (unattended, …)` line then a `Confirmed (<who>, …)` line, each `… after round N: <words>`, N the highest `idea-review-NNN.md`, the numbers having no gap;
