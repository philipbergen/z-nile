# Design refute 001: c0261

The user dropped the tier vocabulary after round 1 (Decided with the user, 2026-11-07: real model names tied to each command and activity; no cheap, sharp or wait names, no `[tiers.<cli>]` tables, no `tier` key), so the design was rewritten. Each finding of design-review-001.md is answered against the new design; the next round is round 1 of the new design (design-review-002.md).

- F1: fixed: the new `wait` phase is gone (no phase, no tier column; the wait step's row takes the gate's phase); the Override search and AC11's pattern name both alias spellings (`(engine|scripts/tracker)/(dispatch|dispatcher|models|ledger)`) and the list was run on the prototype; consequences: none (the c0084 specs no longer change).
- F2: fixed: `dispatch.waitCommand` is a loop with its own clock (deadline below the runner's bound, `sleep 30`, exits 0, 2, 3), the prompt names the tool timeout, the `seconds` are a constant with E5 per CLI, and AC4 runs the loop against a fake `gh`; consequences: exit 2 stops the chain with the failed check named (executor, step 7), and `wait_minutes` is a new `[dispatch]` setting with its parse case (executor).
- F3: fixed: `dispatch.next` starts `z-wait` at a gate that only waits for green CI, once per head (`waitedHead`), AC5; consequences: a new Fact and Action field and a run-state entry; waiting for a human's merge is put to the user (Q2), default not.
- F4: fixed: `dispatch-activities-cli.spec` (fake CLIs) pins the model each activity starts, `--final`, the refused final stream and `--dry-run`'s activity; the chain's execution of `z-wait`, the metrics table's wiring and `wait_minutes` stay `reasoned` rows with executor tests-first steps (Implementation step 6); consequences: `z-wait` has no SKILL.md, the dispatcher builds its prompt (stated in the Design).
- F5: fixed: the final-round procedure is rewritten (rounds on the way until the rule would stop or the next round is round 5, then final; every round after the first final one is final; round 5 always final; the raft review always final), AC9 pins the new sentences, not the old; consequences: one extra round for an issue that would have stopped, marked **(prep)** for the user.
- F6: fixed: the cost per model is `ledger.byModel` and a by-model table in `./zn metrics` (AC6); no tier or column exists, so no misattributed tier either; consequences: the metrics wiring is the executor's, with a case in Implementation step 6.
- F7: refuted: there are no tiers any more; any activity's table may be set by a human-merged `.models.toml`, which is the intent ("model tied to each activity"); the final-review rule is a property of the final-review activities (`models.FINAL_REVIEWS`), enforced at resolve.
- F8: fixed: resolution is by activity key, and a plain `zz-review` pin keeps c0117's rule through the fallback (AC2's pin case and AC10's dispatcher case); consequences: none.
- F9: fixed: the exact model names are pinned only on the check line that sets `ZN_C0261_EXACT`; the promoted specs pin rules (every activity has a model on every CLI, finals obey the rule and rank above the way, real names); consequences: c0175's CLIs fail the "every CLI has a table" rule at once.
- F10: fixed: `depends_on` is empty (c0248 is not used and c0260's mode is not needed); the shape of a mode entry (`activity`, `final`) is stated for c0260 and c0262, and c0262's agent-on-Opus reading is reported to the coordinator.
- F11: fixed: the user answered (real model names tied to activities, no tier tables); the Problem records it.
- F12: fixed: the sweep covers zz-review's two lines, zz-execute's three, z-raft, z-design, the README's two places and AGENTS.md; AC9 has absence checks for the old sentences; the Agent tool's `model: "sonnet"/"opus"` stays the interactive form (that tool takes only those words).
- F13: fixed: `--dry-run` prints `activity=` and the CLI spec pins it.
- F14: fixed: E1 records each probe as the `./zn run --time N -- …` line that ran it.
