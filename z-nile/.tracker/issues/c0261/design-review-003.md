### F5 [medium] Exit 4 still fires for blocks that are not real: a green PR whose mergeability GitHub is still computing, and a `gh` error read as a failed check
Where: prototype `dispatch.luau` `gate()` (lines 329-361) and `waitCommand`; Design, Waiting (the first two bullets: "Exit 4 stays … for reasons that are not waiting for a human"); the user's "without human go all the way to merge".
Evidence:
- Probe: `dispatch.next(facts{ pr = { green = true, mergeable = false, conflicting = false } })` prints `stop 4 the prep PR #7 is not mergeable`. GitHub computes `mergeable` lazily and answers UNKNOWN on the first read after main moves. During a 10-60 minute wait, other preps merge into main, so the re-read after a passing wait is exactly when UNKNOWN is likely. The chain then stops for a human with `waitedHead` set.
- In the poll, any rc other than 0 and 8 without "no checks" in its output is exit 2 ("a failed check"). `gh pr checks` also exits 1 on an API or network error, and the wrapper exits 1 on a refusal (`wrap.luau:30`). One transient error ends the wait as a failure, and the chain stops with exit 4.
- `Pr.green` is false for a FAILURE and a PENDING rollup alike, so a PR whose check already failed starts a model session only to learn that (probe: red PR gives `step z-wait`).
Critique: the Design lists exit 4's remaining reasons as real blocks; these three are not.
Consequences: a tri-state merge state on `Pr` (MERGEABLE / CONFLICTING / UNKNOWN) replaces two booleans that 002 F7 and F4 above have both had to patch. A failed-vs-pending split needs `parsePr` to read each rollup entry's conclusion and status.
Recommendation: give `Pr` one `mergeState` field read by `parsePr` (cases as F4), and make the gate wait when `mergeState ~= "CONFLICTING"` and (not green or `mergeState == "UNKNOWN"`). A green PR whose state is still UNKNOWN takes the same per-head wait, whose poll re-reads `gh pr view <n> --json mergeable`. Stop at once with exit 4 when a rollup entry already failed. In the loop, treat rc 1 without a failing check in gh's output as "not yet", up to a few times. Add a case and a row for each.
