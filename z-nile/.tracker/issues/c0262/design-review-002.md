### F1 [high] The human's `./zn resolve <R> approve` changes the view it approves, so an approved ticket is never on course: it is reviewed again, and a further off-course verdict blocks it again
Where: c0262.md, Design, `finalview.state` ("a review ruled `approve` counts as on course"), `finalview.viewId`, `finalread.files` (the base document is origin/main's copy); AC14; verdict.spec "AC14: the human's approve of the blocking review puts the ticket on course on that view"; Rules and mutants row M51 (reasoned).
Evidence: c0250's resolve of an active raft with `approve` has `plan.decided = true` and writes `escalation.decidedLine(...)`, `Decided with the user (<date>), resolve approve: "<words>" (the option: ...)`, into the Problem of the note's `Layer:` member on origin/main (`main.luau` ~8221 and ~8283, `targetId = layerId`). `finalread.files` builds `ask.md` from origin/main's copy of that document, and `finalview.ask` adds every `Decided with the user (` line to "The user's later decisions"; `viewId` hashes `ask.md`. So the view after the resolve is not the view review 002 judged. A probe case on the mutation copy (TWICE-style reviews, the second's view taken from `assemble(input())`, the current view from the same input whose base gains that one Decided line) printed `SAME-VIEW? false` and `STATE review-again`. Then: `work next` says `final-review-ticket`; `dispatch` files 003 (`again` is true for `review-again`); a 003 off course gives off = 2 (001 and 003; 002 is approved, not counted) and `blocked` again; on a raft with `layers: reviewed` the completion rule refuses the layer meanwhile (`final ~= "on-course"`). The pure AC14 case passes only because it hands `state` the same view id the approved review carries, which the real route never does.
Critique: AC14's first clause ("`approve` puts it on course") and zz-review's new text ("`approve` puts it on course") are false on the one path that produces an approve. The tempting fix is to drop resolve lines from `ask.md`; that hides the human's own words from every later reviewer of the ticket.
Consequences: whatever is excluded from the id must be exactly what the resolve wrote for that note, or a later real change to the ask (a new `Scope decision` line) would no longer re-open the review. An approve also stays bound to the layer: a rebuild after it must still be reviewed again (the existing `review-again` with `latest = on-course`, which `done` does not refuse).
Recommendation: keep the line in `ask.md`, and compute the view id over the ask without the Decided lines that `./zn resolve` wrote for a note `finalread.rulings` already reads (match the `, resolve <decision>: ` form `escalation.decidedLine` produces, dated on or after the note's `When:`), or record in the review's state the view id at the time of the ruling; state which in `finalview.viewId`'s contract. Cases: view.spec AC2 "a resolve's own Decided line leaves the view id alone; a new Scope decision line changes it"; verdict.spec keeps the pure AC14 cases; and the real route in fixture.spec (F2), where `./zn final` must print `on-course - the human approved final-review-002.md` after a real `./zn resolve R0010 approve`.

### F4 [medium] A gap's `Measured against:` quote is accepted whatever it says, so a review that quotes nothing in the view routes a redo
Where: c0262.md, `finalview.parse` and `finalview.problem`; AC4; Problem, "A clear verdict says whether we stayed on course, with each gap named against the ask or the design".
Evidence: `parse` sets `measured[i]` true for any non-empty quote not starting with `<`; `problem` checks only that flag. A review with `Gap: design` and `Measured against: "x"` (verdict.spec's own fixture text uses `"x"`) is read, is off-course, and sends the ticket back to z-design. Nothing compares the quote with `ask.md`, `design.md` or `design-changes.patch`, which `finalread` has in hand when it builds the view.
Critique: the captured outcome is that each gap is named against the ask or the design; the check is a presence check a wrong review passes. This is a Checked proxy the design can make measurable. The tempting fix is to compare the quote byte for byte, which fails on wrapped lines and smart quotes.
Consequences: the check needs the view, so it belongs in the edge (`finalread.state`, and the dispatcher's unplaced-review check), not in the pure `parse`; a pure helper `finalview.quoted(review, files)` can take the files. The match rule needs whitespace and quote-mark normalisation and a minimum length, and a `Gap: design` quote should come from `ask.md` (the ask the design missed), a `Gap: implementation` quote from `design.md` or `design-changes.patch`.
Recommendation: add `finalview.quoted(text, files): string?` (normalised substring match, the file each Gap kind must quote from), make `problem` report an unmatched quote, call it in `finalread.state` and in the dispatcher's placement check, and pin it in verdict.spec AC4 ("a quote that is not in the view is not read"; "a design gap quoting only design.md is not read") with a mutant row.

### F5 [medium] The limited view's central claim (the reviewer's CLI loads no repository instructions) is left to the executor, and E7's fallback can drop the role's own model
Where: c0262.md, Unknowns & experiments E7 ("executor, Phase 1; not run in prep"); "Who is bound"; `[roles.final-review]` (`claude-fable-5-2`, the user's 2026-11-13 Scope decision).

The lesson this repeats asks "what did a real run of each runtime in its role chain load?" at design time.
Critique: whether the outcome "fresh context, none of the trail" holds is decided by this experiment, and the fallback it names can silently cut a captured outcome during execution. The tempting fix is to keep E7 for the executor with a softer criterion.
Consequences: the pass criterion must separate repository files (any `CLAUDE.md` or `AGENTS.md` of a checkout, and project memory, which are the trail's carriers) from the user's own global file, which carries no ticket's trail; the fallback must never change the role's model without the user.
