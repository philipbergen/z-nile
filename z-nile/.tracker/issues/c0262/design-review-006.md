### F1 [medium] The worker is told "the new issue is captured" after a `split`, but `./zn resolve split` has already captured it, so a worker following the text files a duplicate
Where: c0262.md, the `work.luau` bullet "after `split` the same, and the new issue is captured"; `work.finalStep`'s block text ("After split, the same, and the new issue is captured."); zz-execute 4a ("after `split` the same, and the new issue is captured"); work.spec AC8 line 108 and docs.spec AC12 line 63 pin the sentence.
Evidence: c0250's decision table (origin/main c0250.md line 267): `split` on an issue makes "a new backlog issue of the item's type (as `./zn new`, `idea: unchallenged`), titled by `--title`", and the item "gains `Scope decision (user, <date>): "<the user's words>" (split into <new id>)`". The stand-in's `cmd.resolve` does it ("-- split's new issue": reserves the id, renders the issue doc and `check.sh`, adds them in the resolve commit, and refuses a `split` without `--title`). The worker's sentence sits in a run of instructions ("it is re-prepped as a redesign (copy ... first), and {r.id} is readied again without it ... After split, the same, and the new issue is captured"): "the same" is three actions the worker takes, so "and the new issue is captured" reads as a fourth. A worker that runs `./zn new issue ...` for it adds a second backlog issue for the same carved-out scope, with no Scope decision line pointing to it. Round 4's text ("After split, the new issue is captured and {issue} re-prepped") had the same reading, and round 4 did not flag it.
Critique: the text is the only thing the worker reads at the block; it must say who did what. The tempting fix is to drop the clause; but then the worker is not told the split's new issue exists, and the re-prep may redesign the carved-out part back into the ticket.
Consequences: the sentence must name the new issue, which the worker can find in the ticket's Problem (the Scope decision line ends `(split into <new id>)`); the re-prep (z-design) then designs only what the split left. Nothing else changes: the new issue is a separate backlog item with its own pipeline.
Recommendation: in the Design, `finalStep` and 4a say "after `split` the same; `./zn resolve` has already captured the new issue (the ticket's Scope decision line names it): capture nothing, and the re-prep designs only what is left"; change the pins in work.spec AC8 and docs.spec AC12 to that wording (for example `has(twice.why, "capture nothing")`), and extend M72's row (or add one) with the mutant "the split sentence tells the worker to capture the new issue" (run).
