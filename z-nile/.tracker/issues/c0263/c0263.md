# c0263: Ticket provenance

## Problem
User (2026-11-07): "tickets need authors (whose idea, take it from git, then who approved the design, who unblocked a blocked ticket and so on)."

Nothing on a ticket says who had the idea or who decided anything. User decisions are prose lines (`Scope decision (user, …)`), and the design has no explicit human approval. With workers carrying tickets from raft to merge (c0253), the human acts at only a few points, and each of those should be on the record. What should happen:
- **Author:** whose idea it was, taken from git (the author of the ticket's capture commit).
- **Design approved by:** the human who approved the design. Design approval is an explicit human step before `prepared`, since design is a human stage (README, Intent; c0264).
- **Unblocked by:** whoever resolved a block (c0250), each time.
- **And so on:** who confirmed the idea (c0260), who set the rank, who rafted it, and which worker (host, CLI, model) delivered each layer (c0254).
- The board shows them.

Decided with the user (2026-11-08), Q1 storage, "Derive from git, store only the rest": what git knows (the idea's author, who made each status change) is read from history by `./zn who`; only what git cannot tell (a human's approval when a bot pushed it, and decisions) goes in ONE append-only record per ticket. Not five frontmatter keys. (Supersedes the earlier "(c) frontmatter keys" answer of 2026-11-07.)
Decided with the user (2026-11-08), Q2 approve, "Prepared is refused without it": `./zn status <id> prepared` refuses until a human has run `./zn approve <id>`; a redesign after a stop needs a fresh approval; the human is the git author of the approve commit; under the dispatcher the prep gate stops and waits for the user, not auto-merge. (Supersedes the 2026-11-07 reading of "approved the design" as the design reviewer's `Verdict: approve`.)
Decided with the user (2026-11-08), Q3 dependencies, "Land first, define a small record API": c0263 does not depend on c0250, c0260, c0254 or rank; it defines a small record function that those tickets call when their event happens (blocked/unblocked, idea confirmed, rank set, layer delivered); events whose tickets do not exist yet are simply not recorded until they exist.
Decided with the user (2026-11-08), Q4 worker identity, "Read c0254's spend rows": c0263 only reads host, CLI and model that c0254 puts on spend rows, and the dispatcher starts passing them; until c0254 exists, delivered-by records the actor grammar the user chose (`human:<git name>` or `agent:<model, version, effort>`) without host.
Decided with the user (2026-11-08), Q5 readings, "Confirm all": rafted is the rafting PR merge, one entry per ticket layer; delivered is the raft PR merge; unblocked is a `status <id> new` after a stop; `release` is not stamped; an interactive session without `--actor` records `agent:unknown` plus the effort; back-fill uses the git author for engine publishes (no trailer).
Decided with the user (2026-11-08), approve and agents, "Refuse in any agent session": `./zn approve <id>` is refused in any agent session; "a human ran it must be true, not just reported". The `--said` evidence path is gone.
Decided with the user (2026-11-08), the existing prepared issues, "Grandfather those prepared now": a frozen list of the issue ids that are prepared when c0263 merges passes without an `approved` row; any other prepared issue without an approval is refused as an error (fold, new raft, ready, raft-plan, audit); a hand-edited `status: prepared` no longer slips through.
Decided with the user (2026-11-07), still standing: the actor is `human:<git name>` or `agent:<model id>` "including agent-model-version-effort": for an agent the model, its version and its effort are recorded (for example `agent:claude-opus-5-5 effort high`), from the dispatcher's `.models.toml` spec or the session's trailer. "rafted" is the rafting PR merge "with layers in case there are multiple tickets": a rafting PR or raft PR can hold several tickets, so provenance is recorded per ticket (a layer per ticket inside the PR), not once per PR; the same holds for "delivered". "yes, back-fill existing done and backlog items from git where possible, in addition to items from now on."
Scope decision (user, 2026-11-08): "Split it and prototype first, like c0265" (c0263 keeps the record: provenance.md, ./zn record, the append-only publish rule, audit, the union of two writers; ./zn who and deriving from git moved to c0280, the unblocked/rafted/delivered rows to c0282, ./zn approve and the prepared gate with the frozen list and the dispatcher's prep gate to c0283, the board to c0284; one raft, delivered a layer at a time in depends_on order).

## Non-goals
- Access control: recording who did something is not permission to do it.
- Worker identity on spend rows (c0254); c0280 reads it.
- `./zn who`, deriving the idea's author and the status changes from git, the merge entry and the worker: c0280.
- The `unblocked` row on `status <id> new`, the `rafted` rows of `new raft`/`fold`/`recombine`/an emergent issue and the `delivered` rows of `done`, with `ZN_ACTOR`/`ZN_VIA` per dispatcher attempt and the rafting gate's allowance: c0282.
- `./zn approve`, the refusal of `status <id> prepared` without it, the refusal in any agent session, the frozen grandfather list and the dispatcher's prep gate: c0283.
- The board's provenance section: c0284.
- (prep) Frontmatter keys, and a back-fill that writes into old documents: the 2026-11-08 Q1 decision derives instead (c0280).

## Solution
- Derive what git knows (the author, the committer of each status change) instead of storing it twice. Store only what git can't tell: a human's approval when a bot pushed it, and the decisions.
- `./zn approve <id>` records the design approval; `./zn who <id>` prints the history.

Prep's detail, below the captured bullets. One record per ticket, `provenance.md` in its folder (a raft's folder too, for events on a raft), append-only rows with no row numbers (so two appends merge). This issue is the layer that holds the record itself; the layers above it write rows and read them (c0280 to c0284, one raft, in `depends_on` order): `who` merges what git says (read at the time, never stored) with the record's rows; `approve`, the lifecycle commands and the dispatcher append rows; the board shows them. A row written in a PR rides the PR; one that is published is built from `origin/main`'s file; the engine's own merges union the file when both sides appended (Behaviour 5).

**The record file** (`provenance.md`, written by `provenance.render`, read by `provenance.parse`): a header line `# Provenance: <id>`, a blank line, the table header `| when | event | actor | detail |` and its separator `|---|---|---|---|`, then one line per event, `| <when> | <event> | <actor> | <detail> |`. `<when>` is `YYYY-MM-DD HH:MM` in UTC; `<actor>` is the stored grammar below without the ` (from git)` suffix; `<detail>` is `key=value` parts joined by `; `, empty when there is none (the cell is then a single space: `|  |`), with `|` written `/` and newlines written as spaces. Events (closed list): `approved`, `unblocked`, `confirmed`, `ranked`, `rafted`, `delivered`. Example:
```
# Provenance: c0263

| when | event | actor | detail |
|---|---|---|---|
| 2026-11-08 09:00 | approved | human:Philip Bergen | design=1a2b3c4d5e6f; said="yes, approved" |
| 2026-11-08 09:30 | rafted | agent:claude-opus-5-5 effort high | raft=R0100; via=dispatch:raft-plan |
```

**Actor grammar** (the user's, 2026-11-07), the stored form: `human:<name>`, or `agent:<model> effort <level>`; a value read from git ends ` (from git)` (` (from git, first add)` for an idea taken from a first add; c0280 produces these); `unknown` when nothing says. `<model>` is `provenance.modelId(text)`: lower-case, each run of non-alphanumeric characters one `-`, trimmed, so `.models.toml`'s `grok-4.7` and git's `Grok 4.7` are both `grok-4-7`; the version is part of the model id; `<level>` is the spec's `effort` or `unknown`.

**The live actor** (a command that records), in this order: `--actor "<value>"`, else `ZN_ACTOR` (only `human:<name>` or `agent:<model> effort <level>`, nothing else, refusing the command before it changes anything; c0282 makes the dispatcher set it), else, when `CLAUDECODE` or `AI_AGENT` is set and non-empty, `agent:unknown effort <CLAUDE_EFFORT|unknown>`; else `human:<name from git var GIT_AUTHOR_IDENT>`, or `unknown` when git has no identity.

## Design

### Behaviour (every outcome this layer owns, each with a Checked criterion)
1. **The record file and its pure module (AC1, AC2).** `provenance.md` in an item's folder (an issue's or a raft's, in the backlog, `active/` or `done/`); `z-nile/engine/provenance.luau` is the only code that reads or writes its text (format in the Solution). **`parse` reads exactly the grammar and refuses everything else, naming the line**: line 1 `# Provenance: <id>`, line 2 empty, line 3 the table header, line 4 its separator, then one line per row of exactly four cells (a `|` cannot be inside a cell), one final newline; a row with a fifth cell, no leading bar, an indentation, a prose line, a blank line, a missing final newline, an unknown event or a bad actor is refused, and no line is ever skipped (`parsers-refuse-ambiguity`: design-review-005 F13 and 008 F2 were both about a line filter that kept the rest). `render` is the inverse of `parse` (an empty detail is the row `|  |` and round-trips), and `record` appends one row (`|` in a detail is written `/`, a newline a space), refusing an event outside the list and an actor that is not a live form. `isValid` is the stored grammar (`human:<name>`, `agent:<modelId> effort <level>`, `unknown`, each with the optional ` (from git)` / ` (from git, first add)` suffix); `isLive` is the form a command may record (no suffix, no `unknown`, no `none`); `modelId` gives one spelling per model; `hint(env)` is the one definition of an agent session for every layer (`CLAUDECODE`, `AI_AGENT` or `ZN_DISPATCH` set and non-empty; the effort is `CLAUDE_EFFORT`), so c0283's refusal of `approve` calls the same function; `resolve` takes the flag, then `ZN_ACTOR`, then the hint, then the git name (`unknown` with no identity) and refuses a given value that is not live.
2. **`./zn record <id> <event> [--actor A] [--detail k=v]` (AC3).** It calls `refuseStale()` and publishes one appended row, built from `origin/main`'s file (`read` of the publish builder, never the worktree's), in one commit `tracker: <id> record <event>`, and then merges `origin/main` (`mergeOrigin`). **Which events on which item**: a backlog issue or raft takes `unblocked`, `confirmed` and `ranked` (`provenance.PUBLISHED`); an active issue or raft (a worker blocks while it holds a raft: c0250 blocks whole rafts) takes `unblocked` only; a done item takes none (its record is written in a pull request, never published). It refuses every other event name, an actor that is not live, an id that is not on `origin/main`, the main checkout and an offline repository (`PICKMAN_PUBLISH=0` or no origin, as `spend` does), each before it publishes anything. c0250 (unblock), c0260 (confirm) and the rank ticket call it when their event happens (Q3 of the Problem); c0282 and c0283 write `rafted`, `delivered` and `approved` themselves, in a PR. **The live actor** (`liveActor`, the adapter) reads `--actor`, `ZN_ACTOR`, `CLAUDECODE`, `AI_AGENT`, `ZN_DISPATCH`, `CLAUDE_EFFORT` and `git var GIT_AUTHOR_IDENT`, and hands them to `provenance.hint` and `provenance.resolve`; the record cases drive each source on its own through `./zn record` (E5: a Claude Code session sets `CLAUDECODE`, `CLAUDE_EFFORT` and `AI_AGENT`; the `grok` and `agent` CLIs of `.models.toml` could not be probed here, so a dispatched step, which any CLI runs under, counts through `ZN_DISPATCH`).
3. **Where a published write may land (AC4).** `publish.allowed` learns the name `provenance.md` (in an issue's or a raft's folder, one level, like `spend.md`); the validator in `publish.commit` accepts a `provenance.md` as a create or an append only (`provenance.publishProblem`: it parses, its header names the folder's id, every old row is unchanged in all four cells and in place, at least one row is new), only when the item's document is on `origin/main`, and only when every new row's event is published (`unblocked`, `confirmed`, `ranked`); in `active/` (an issue or a raft) only `unblocked` rows, and in `done/` none. An `approved`, `rafted` or `delivered` row is never published: it is written in a PR. The direct-push rule for a document stays "only `status:`" (`c0053/publish.spec:167` pins the substring `status: line`).
4. **`audit` (AC5).** `audit.run` reports, as an `error` of kind `provenance`, a `provenance.md` that does not parse, has an unknown event or a bad actor, or whose header names another id than its folder's; absence is fine, and a raft's record is fine.
5. **Two writers, one file (AC6).** The record is written by published commits on `main` and by commits a PR carries, so two appends between merges conflict in git (E8). Every `git merge` of `origin/main` the engine makes (`mergeOrigin`, so `sync`, `record` and the other published commands; `raftingStart`, so `fold`, `recombine` and `new raft`; `land`) goes through one function, `mergeRef(ref)`. On a conflict whose every unmerged path is a `provenance.md` it replaces each by `provenance.union(base, ours, theirs)` of the stage-1/2/3 blobs and commits; on a conflict in any other file it aborts the merge (no `MERGE_HEAD`, the tree as it was) as it does today. **`union` refuses (nil and why) a side that does not parse, or that does not extend the common version**: a branch that edited or removed an old row would otherwise have the edit silently reverted or its new row dropped, so the merge aborts and the message names the row to restore (rows are only appended; `renumber` and `compact` rewrite an id in old rows on a branch, and a sync after one stops with this message, resolved by hand: a rare, announced, whole-tree operation). **The folder-move case.** A record added in an item folder the other side moved (`ready` moves a backlog item to `active/`, `done` to `done/`) is git's `CONFLICT (file location)`, not a content conflict: git leaves our added file at the new path with only our stage (E14), or with both stages when the other side added one too, so `mergeRef` takes a path with our stage only as it is and unites one with both. No git option is used for it: `merge.directoryRenames=true` would also carry every other file added in the folder (a review file in a raft folder `stop` moved) silently along, where today the sync stops and names the folder, and the record case pins that stop. The union orders the rows base first, then the target branch's (`origin/main`'s) new rows, then ours, minus ours that equal one of theirs taken as a multiset: after a sync `origin/main`'s record is still a prefix of the PR's, which a gate that compares them needs (c0282's rafting gate); `git merge-file --union` puts ours first and is not used. **Limits, stated.** `remap` merges `origin/main` itself (`git merge-tree` against a remapped base, then `commit-tree`) and does not unite a record both sides appended: it stops, as it does for any conflict, and its messages (pinned by `tooling/remap-once`) keep telling the user to merge by hand. The engine's other advice to run `git merge origin/main` (the failure texts of `mergeOrigin`, `land` and the depends-on refusal) now says `./zn sync`.
6. **`trail`** stops counting `provenance.md` as an item's document (`trail.isDoc`), or a record added to a folder would change what `trail.read` takes for the item's life (`./zn capture`, and c0280's `who`).
7. **Docs (AC7).** zz-rules (a Provenance section, the item layout, the direct-push exception, the merge instruction) and the README name `provenance.md`, `./zn record`, `--actor`/`ZN_ACTOR`, the session variables and the union through `./zn sync`; the other layers add their own commands to the same text.

### Interfaces
`z-nile/engine/provenance.luau` (new; pure; requires no module; strict):
```

type Row = { when: string, event: string, actor: string, detail: string }
provenance.EVENTS: { "approved", "unblocked", "confirmed", "ranked", "rafted", "delivered" }
provenance.PUBLISHED: { "unblocked", "confirmed", "ranked" }      -- what ./zn record may publish
provenance.modelId(text: string): string
provenance.human(name: string): string
provenance.agent(model: string, effort: string?): string        -- "agent:<modelId> effort <effort|unknown>"
provenance.isValid(value: string): boolean                       -- the stored grammar, with the optional " (from git)"
provenance.isLive(value: string): boolean                        -- human:<name> or agent:<model> effort <level>, no suffix
provenance.hint(env: { [string]: string? }): Hint                   -- the one agent-session test: CLAUDECODE, AI_AGENT or ZN_DISPATCH set and non-empty; effort = CLAUDE_EFFORT
provenance.resolve(flag: string?, env: string?, hint: Hint, gitName: string?): (string?, string?)
provenance.parse(text: string): ({ Row }?, string?)              -- exactly the grammar; refuses anything else, naming the line
provenance.render(id: string, rows: { Row }): string
provenance.record(text: string?, id: string, event: string, actor: string, detail: string, now: string): (string?, string?)
provenance.appendOnly(old: string?, new: string, id: string): string?     -- every cell of every old row unchanged, in place
provenance.publishProblem(old: string?, new: string, id: string, allowed: { string }): string?  -- appendOnly + the new rows' events
provenance.union(base: string?, ours: string, theirs: string): (string?, string?)  -- the base's rows, theirs' new rows, then ours' new rows minus theirs' (a multiset); nil and why when a side does not parse or does not extend the base
provenance.problems(path: string, text: string): { string }      -- audit
```

### Scalability
One small file per ticket, appended; the union reads three blobs of one file; audit parses a file per item that has one.
### Maintainability
One module, one event list, one guard rule per file kind mirrored on `spend.md`, one merge function for every merge of `origin/main`. `main.luau` gets call sites, not logic (zz-arch: pure over texts, reads at the edge).
### Usability
`./zn record` names the events it takes when it refuses one; forgetting `--actor` records `agent:unknown` in an agent session, never the user as a bot's work; a conflicting record is united by `./zn sync` with no hand work.

### Edge cases
- Empty or missing `provenance.md`: no rows; audit accepts absence.
- A malformed `ZN_ACTOR`/`--actor`, or one that is `none`/`unknown`/carries the suffix: the command refuses before it changes anything.
- Two rows identical (same minute, actor, detail) are both kept; the union keeps a row repeated in the base repeated, and a row both sides appended once.
- A `|` or a newline in a detail is stored as `/` or a space.
- `git var GIT_AUTHOR_IDENT` fails (no identity): the human is `unknown`.
- Offline (`PICKMAN_PUBLISH=0` or no origin): `record` refuses as `spend` does.
- A merge that conflicts in the record and in a document aborts and leaves the tree as it was; so does one where a side's record does not parse or edited a row of the shared version (the message names the row).
- `renumber` and `compact` rewrite an id in old rows on a branch: a sync after one stops with the union's message and is resolved by hand (stated limit).

## Acceptance criteria

### Checked
- AC1: the agent-session hint is `CLAUDECODE`, `AI_AGENT` or `ZN_DISPATCH` set and non-empty, and `./zn record` records the actor from each source (the flag, `ZN_ACTOR`, a session, the git name) as `resolve` orders them. The stored actor grammar accepts `human:<name>`, `agent:<model> effort <level>`, `unknown` and each with ` (from git)`, refuses anything else, gives one spelling per model, and `resolve` takes the flag, then `ZN_ACTOR`, then an agent-session hint, then the git name (`unknown` with no identity), refusing a given value that is not a recorded form.
- AC2: `provenance.md` is exactly its grammar (fixed lines, four-cell rows, a final newline): `parse` refuses every other line, naming it, and skips none; rows are unnumbered, in a closed event list and the stored grammar; `render` and `parse` are inverse; `record` appends one row and cleans a `|` or newline in a detail; `appendOnly` and `publishProblem` accept only appended rows of the allowed events with every old cell in place; `union` orders base, then the target's new rows, then ours, without doubling a shared row, and refuses a side that does not parse or does not extend the base.
- AC3: `./zn record <id> unblocked|confirmed|ranked` publishes one appended row, built from `origin/main`'s file, on a backlog issue or raft and (`unblocked` only) an active issue or raft, and refuses a done item, any other event, a bad actor, an unknown id, the main checkout and an offline repository before it publishes anything.
- AC4: the publish validator (through `publish.commit`) accepts a `provenance.md` as a create or an append of published events only and refuses an edit, a removal, a reorder, an unparsed create, another id's header, a record with no document beside it, an `approved`/`rafted`/`delivered` row, in `active/` (an issue or a raft) anything but `unblocked` rows, and in `done/` any row, naming the file.
- AC5: `./zn audit` and `provenance.problems` refuse a malformed record, an unknown event, a bad actor and a header naming another id, and accept absence and a record in a raft's folder, and find a malformed one in a backlog item, a raft, an active raft or issue and a done issue.
- AC6: the engine's merges of `origin/main` (`sync`, `fold`, `land`) unite a conflict confined to `provenance.md` (main's rows first) and abort, leaving the tree as it was, on any other conflict, on a record that does not parse and on one that edited or removed a row of the shared version; a record added where the other side moved the folder follows the folder and is united there, and any other file added there stops the sync as before.
- AC7: zz-rules and the README document `provenance.md`, `./zn record`, `--actor`/`ZN_ACTOR`, the session variables (`CLAUDECODE`, `AI_AGENT`, `ZN_DISPATCH`) and that `origin/main` is never merged with plain `git merge` (`./zn sync` unites the record).
- AC8: the real tree's `./zn audit` and `./zn lessons --check` pass and the promoted specs this layer does not override stay green.
