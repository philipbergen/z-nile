### F2 [high] (the mechanism behind review-005 F10) The derived `rafted` entry picks the readier or the raft PR's merge, not the rafter, for every done and active item that has no stored row
Where: table row `rafted` ("the newest life commit, not the move to `done/`, whose subject names the ticket's current raft id as a word"); Behaviour 7; AC8 ("takes the rafting-PR commit of the current raft (not the move to `done/` …)"); `acceptance/provenance.spec.luau:225-249` (the pure life); E11
Evidence: on `origin/main`, `git log --no-renames --name-status` of the done items c0237 and c0239 shows each life ending in `R0082: Lobby tooling pattern (#235)` / `R0086: Full gate at merge (#261)`, which is `D …/active/<id>/<id>.md` plus `A …/done/<id>/<id>.md`. Every one of those subjects names the current raft id as a word.

- Probe: the prototype's `select` on a life of `{A done/…, D …/c0010.md}` (one sha, "R0011: demo (#1)", Cy), then "tracker: raft R0011 again" (Fay), returns `rafted: human:Cy (from git)`.
