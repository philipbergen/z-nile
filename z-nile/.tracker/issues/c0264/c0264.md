# c0264: Readme states znile intent

## Problem
The z-nile README states the intent: humans at idea and design, workers carry rafts to merge, cheap on the way and sharp at the end

Scope decision (user, 2026-11-07): "humans approve the design, humans interact (plan mode) over the idea". Decided with the user (2026-11-07): option (b): a person approves the design and a worker may draft it; the idea phase is an interactive conversation with a person in plan mode.

## Non-goals
- Building any of what the intent names: the interview (c0260), the model tiers (c0261), the final review (c0262), provenance (f0263), the heartbeat (f0265). Those are their own issues; this one only states the intent.
- New roadmap rows or state labels for those issues: each issue's own PR adds its row (the README rule: "A feature's PR changes its own roadmap row").
- Fixing the pre-existing staleness of c0259's finished `check.sh` (its AC7 says c0117 *designed* while the tracker says it is done). It is not run by the gate; the README's c0117 labels are not this issue's.

## Solution
Add a short `## Intent` section to `z-nile/README.md`, between the opening account of z-nile and `## How it should work`. No other line of the README changes.

## Design
The whole change is one inserted section in `z-nile/README.md`. The patch, prototyped and measured in prep, is `experiments/readme.patch` (`git apply`); the README must carry the section below **word for word** (AC4, which holds the same text in the sequestered `check.sh`).

```
## Intent
z-nile is built so that people spend their time on ideas and designs, and workers do the rest, cheaply until the last step and sharply at it.
- **Humans at the idea and the design.** A person talks the idea through with the AI in plan mode, settles what is asked and approves the design; a worker may draft the design. `z-ticket` captures the idea, `z-design` sharpens it into a prepared issue and its design review. Nothing is designed past a person's ask.
- **Workers from the raft to the merge.** Workers carry a prepared issue's raft to its merge: raft, ready, run, review, gate, merge. They stop and escalate only when blocked (Escalation to the human), and a person comes back only for that.
- **Cheap on the way, sharp at the end.** The steps on the way run on cheap models; the final review, the one that decides whether the work merges, runs on the sharpest model. Rigor does not move: the checks, the gate and the review rounds still run.

This section is the aim and carries no status label. How it should work, below, labels each part as exists, designed or captured; where its plans for Autonomous delivery and the worker end have a worker design, they mean drafts that a person approves.
```

**Where.** `## Intent` is its own `##` section, not a `###` of `## How it should work`: c0259's promoted spec requires every `###` there to carry an `exists`/`designed`/`captured` label, and its legend says the labels are that section's. An aim is not a feature, so it carries none (AC3). c0115's promoted spec (the README's first block after the title is the mermaid picture) and c0183's (the sentence "A game is a project: pickman is one, in `pickman/`." stays) are untouched because the section goes after the opening account.

**What stays untouched, and why.** Other README lines let a worker design (the worker end's "design, raft, ready, run...", Autonomous delivery's "an item is designed, ... with no human in the loop", the dispatcher's chain, `claimable`). They are the sections c0249, c0252, c0253 and c0117 own, and rewriting them would change those issues' scope, which only the user does (design review 001 F3, F4). The Intent's last sentence says what the user decided: those plans mean drafts that a person approves. 

The sweep (`grep -nE "preparing|claimable|\(ticket, design|run next step|design, raft|designed|design-review" z-nile/README.md`, run on `main`), every hit with its ruling: line 38 (picture, "run next step") and line 115 (dispatcher chain includes design): tooling capability, left; line 55 (`claimable`) and line 59 (a worker claims with `status <id> preparing`): the rank and claim rules of c0249 and c0254, left to them; the worker-end and Autonomous delivery sentences: left, reconciled by the Intent's last sentence; the legend, roadmap and `designed` labels: status words, not a worker step. None is rewritten here; the Intent's last sentence reads them as drafts a person approves.
