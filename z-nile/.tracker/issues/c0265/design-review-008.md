### F2 [medium] race.spec's "ends before its bound" has less than a second of margin: a correct `--watch` often exits in the bound's own second and fails `os.time() - started < 8`
Where: proofs/race.spec.luau:153-160 (`ZN_BOUNDED_DEADLINE = started + 8`, `ZN_BEAT_EVERY = 1`, `t.expect(os.time() - started < 8)`); heartbeat.proto `watch` (`now + every >= deadline` → `stop-bound`); Design, `beat --watch` ("exits 0 … on `stop-bound` (the next tick would pass the bound)").
Evidence: ticks come every `p = 1 + c` seconds, where `c` is a tick's work: a fetch, an `ls-remote`, a `git grep`, a push and the stamp read, about 0.2-0.3 s locally. The loop stops at the first tick whose `now` is at least `started + 7`. That tick falls anywhere in `[started+7, started+7+p)`. The process then needs `e` more seconds to exit (the stop tick's own fetch, Lune's exit, the bash wrapper). The assertion needs it gone before `started + 8`, so it fails whenever the stop tick lands in `[started+8−e, started+7+p)`. That window covers `(c+e)/p` of the cases, roughly a quarter. A loop on a fixed cadence (`c` = 0) still fails `e` of the time. The proof runs once, before `done`, so one unlucky run blocks `done` for a correct implementation, and the executor is tempted to touch sequestered code.
Critique: a `<` on whole seconds, with one second of slack, cannot hold against a stop rule that only decides once per period. The off-by-one mutants this assertion seems to guard ("runs to the bound") are already killed by heartbeat.spec's pure `watch` case (`NOW + 95` stops, `NOW + 94` beats).
Consequences: with `<= started + 8` (that is, `< 9`) the case still fails a loop that ignores the bound: that loop never exits, and the runner's limit fails the case. It also still shows that the process ended on its own, in the second its bound falls in. Off-by-one mutants stay with AC1.
Recommendation: change the assertion to `os.time() - started <= 8`, with the comment "it ended by its bound's second; the exact stop is heartbeat.spec's". Or keep `< 8` and set the bound to `started + 9`, which leaves a full period of slack. Move the Rules row's mutant for this case to "a loop that never stops".
Lesson: zz-test/count-calls-in-poll-loops
