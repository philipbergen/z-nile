### F1 [high] `proofs/` is outside the sequestered set, so AC4 and AC5 can be passed by changing the proofs during execution, and no guard would see it
Where: check.sh AC4/AC5 (`lune run tests/run -- "$0/proofs/dispatch.spec.luau"`, `…/race.spec.luau`); Affected specs ("real-time proofs: run once by `check.sh`, never promoted"); engine/trackerstate.luau:151 (`return rel == "check.sh" or string.sub(rel, 1, 11) == "acceptance/"`); zz-review code mode item 2 (the sequestration diff covers only `**/check.sh` and `**/acceptance/**`); zz-execute:33 ("The sequestered acceptance specs … Don't modify").
Evidence: AC4's only check is `proofs/dispatch.spec.luau`, and AC5's only check is `proofs/race.spec.luau`. Neither file is sequestered. trackerstate's sequestered set, which the merge gates, `done` and the code review's sequestration diff all use, is the item's `check.sh` and `acceptance/`. An executor whose dispatcher beats only once, before the step, can change script.sh's poll in dispatch.spec (for example `-ge $((start+2))` to `-ge $start`) and pass AC4. An executor whose `--watch` dies on the first failed push can delete the failed-tick case and pass AC5. Every guard stays green. Round 8 F2 already names the pressure: a flaky one-time proof blocks `done`, so the executor is tempted to touch it. These are the only proofs of AC4 and AC5, which are the capture's "a beat built into … long `./zn` commands" and the dispatcher's beat. So a criterion can be passed by a wrong implementation.
Critique: the tempting fix is a sentence in zz-execute ("don't edit proofs/"). That is a rule with no check. Moving the proofs into `acceptance/` would sequester them, but `done` would then promote them, which is exactly what the user's rule forbids.
Consequences: pinning the proofs from the sequestered `check.sh` sequesters them without promoting them. The pin then has to change whenever prep edits a proof (prep may edit `check.sh`). Before `done` a mismatch must fail AC4/AC5 and name the file. After `done` the checks are skipped already. `git hash-object` gives the same answer on macOS and Linux and needs no `shasum`.
Recommendation: in check.sh AC4 and AC5, before running the proof, compare `git hash-object "$0/proofs/<name>.spec.luau"` with a literal hash written in check.sh, and fail with `proofs/<name>.spec.luau changed since prep (it is pinned here)`. Say in Affected specs that the proofs are pinned by check.sh. Add a Rules row ("a proof is pinned": mutant "an edited proof passes"). Prep checks it once by editing a proof and seeing AC4 fail.
