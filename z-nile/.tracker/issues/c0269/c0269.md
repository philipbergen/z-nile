# c0269: Rename done gate spec titles

## Problem
Rename the promoted c0074/done-gate case titles and c0080/consequences comment that still say done runs the full gate; carry with c0241's requote of the c0074/done-gate digest (found by R0086 review 001 F2)

Detail (prep, 2026-11-08): since R0086 (c0239), `./zn done` runs the affected gate (`doneGate({})` answers `affected`, the stub sees `args: --affected`). Five places still say `full`: in `z-nile/tests/acceptance/c0074/done-gate.spec.luau`, the header comment, the spec title and two case titles; in `z-nile/tests/acceptance/c0080/consequences.spec.luau`, one header comment. A reader of a red run sees a name that states the old rule. R0086 could not rename them: its AC8 allowed only named substitutions. The sentence "carry with c0241's requote" is about order: c0180 (preparing) pins a digest of `c0074/done-gate.spec.luau` in its `narrowings.luau`, so this chore must be done before c0241 re-preps c0180 (see Existing work); c0269 hands over the order (c0241 `depends_on: [c0269]`), not a digest.

## Non-goals
- Any change to what `done` does, to the assertions of either spec, or to a case's body: only the five strings below change.
- Other promoted specs: a search of `z-nile/tests`, `pickman/tests` and `arcade/tests` for `done runs/skips the full gate` finds exactly these five places (E1).
- Requoting c0180's `narrowings.luau` digest: c0241 (it re-preps c0180 against what landed).
- c0083's contradicting AC9 (it pins `full gate fails` and four `toBe("full")` lines that c0239 already removed): c0083's own re-prep.

## Solution
- Rename the stale words in the two promoted specs by five exact substitutions (the Design lists them) and nothing else.
- (prep) Pin the result twice: the new texts and the absence of the old ones in every spec file of `z-nile/tests`, and, by the base-plus-substitutions rule, that no other byte of either file changed.

## Design
This is a chore that changes two promoted specs and adds one line to `z-nile/tests/inputs.tsv`. It changes no behaviour of `done`, `land` or the gate, and no code under any `src/`.

Decisions it relies on (quoted): c0239's Problem, "A: done affected, merge full" (the rule the new words state), and the R0086 review 001 F2 recommendation, "a chore to rename the c0074 case titles and the c0080 comment to the affected gate, carried with c0241's requote of the `c0074/done-gate` digest".

### The five substitutions (each `old` occurs exactly once in its file at the base)
| file | old | new |
|---|---|---|
| `z-nile/tests/acceptance/c0074/done-gate.spec.luau` | `` `tracker.sh done` runs the full gate on the final tree `` | `` `tracker.sh done` runs the affected gate on the final tree `` |
| same | `t.spec("c0800 done runs the full gate after promotion"` | `t.spec("c0800 done runs the affected gate after promotion"` |
| same | `it("done runs the full gate on the promoted, moved tree, then commits"` | `it("done runs the affected gate on the promoted, moved tree, then commits"` |
| same | `it("the gate decision: full, unless inside a spec run without the switch"` | `it("the gate decision: affected, unless inside a spec run without the switch"` |
| `z-nile/tests/acceptance/c0080/consequences.spec.luau` | `(so done skips the full gate, c0800)` | `(so done skips the gate, c0800)` |

The inner `skips` in c0080 says "the gate" and not "the affected gate": inside a spec run `done` skips the gate whichever mode it would have run (R0086 used the same wording for the message, `done: inside a spec run, so the gate is skipped`).

### The pin on the files (AC4)
`acceptance/narrow.py` reads each file as bytes at the merge base with the published main: the tip is read from the remote with `git ls-remote origin refs/heads/main` (it writes no ref; red when the remote can't be read, with the network needed at `done`, or the tip is not fetched: "fetch origin main first"), and the base is `git merge-base HEAD <tip>`. The local `origin/main` ref is never the base: the branch's author can write it (design reviews 002 F3 and 003 F3; zz-review/sequestration-reference-not-a-ref). `check.sh` prints the URL `origin` resolves to, outside `check`; a swapped `origin` is review's to catch. `narrow.py` applies exactly its named substitutions (failing unless each `old` occurs exactly once and its `new` not at all; it runs at `./zn done`, before the change lands, and is red afterwards: a finished `check.sh` is not rerun), and requires the result to equal the file on HEAD byte for byte (zz-test/narrowing-pins-the-whole-file), so a deleted assertion, an added case, a reworded comment or a changed line ending is red. It also pins `z-nile/tests/inputs.tsv`: every row it has at the merge base is still there, unchanged (a row deleted or edited is red; rows main or raftmates add are fine), and the one row below is added. It looks at these files only, not at the rest of `tests/acceptance/` (design review 001 F3: a whole-branch clause is red by construction beside a raftmate with Overrides); a red result on a file another item in the same raft changes prints "c0269 must not share its raft: split the raft".

It prints nothing on success. It does not hand a digest to anyone (design review 001 F2): c0180's `narrowings.luau` pins the digest of the file *after c0180's own narrowing*, computed by `narrowed.spec` with its own normaliser, which a number printed here would not equal.

**Rafting.** c0269 must not share a raft with an item that also changes `c0074/done-gate.spec.luau` or `c0080/consequences.spec.luau`: c0123 (prepared), c0179 (in prep) and c0180 (preparing; c0241 re-preps it). `raft-plan` is mechanical and does not read this line: the backstops are z-raft's raft-mode coherence review of a raft holding several issues (its Order & dependencies must carry it) and `narrow.py`'s message when the raft's `done` goes red. If the user prefers a mechanical guard, `solo: true` needs their decision line (an option in the hand-off report); it is not set here.

### The pin on the words (AC1, AC2)
The exact new and old texts are `check.sh` claims about today's files (AC1: `grep -F` for each of the five new texts and `! grep -F` for each old one), not a promoted case: a promoted case would pin another item's case titles forever (design review 001 F5). `acceptance/titles.spec.luau` (promoted, AC2) scans every `.spec.luau` under `z-nile/tests` (hidden folders skipped) for the stale phrases `done runs the full gate`, `done skips the full gate`, `the gate decision: full` and ``tracker.sh done` runs the full gate`` in a title, a comment or a string, also wrapped across comment lines (a phrase built by concatenation is out of reach: this spec builds its own that way), so a new spec that repeats the old rule is red too. The scan is a pure function `stale(text)` tested on planted texts (one per form: title, line comment, string) so it can't pass by finding nothing (zz-test/absence-scans-cover-every-form, no-vacuous-pass). The stale phrases are built by concatenation in the spec so it does not match itself once promoted.

The spec walks `z-nile/tests/` without requiring them, so `z-nile/tests/inputs.tsv` gains one row, `tests/acceptance/c0269/titles.spec.luau<TAB>z-nile/tests/` (a folder entry); the spec pins that row and `narrow.py` pins that nothing else of the file changed (zz-design/declare-what-full-runs-covered).
