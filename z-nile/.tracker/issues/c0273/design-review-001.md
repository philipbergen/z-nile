### F1 [medium] The design names the wrong callers of `projectsIn`: its fail-closed case tests a function no gate path runs, and the live caller has no fail-closed case
Where: c0273.md, Design, "Inventory of the readers" item (2) ("behind `graph.placeInputs` (the selector's place inputs)"); Checklist, "Who else meets the new refusals" ("Graph's error for a commented `.jsonc` reaches `z-nile/affected` (the gate's selection fails and the gate stops)"); Test plan `AC3: a commented *.project.jsonc stops graph's lister with an error naming it`; AC3.
Evidence: since #293 ("Select specs from a committed watch map") selection no longer reads the graph. `z-nile/lib/context.luau:16` says "`graphOnly` is accepted and ignored: the require graph is no longer an input of selection". `z-nile/affected.luau` does not require `graph` (its requires are changed, context, fs, process, projects, select, stack, stdio, store, watch). Outside `graph.luau`, `graph.placeInputs` is reached only through `graph.affectedSpecs`, and only specs call that: `tests/tooling/affected.spec`, pickman's `c0002/affected-place.spec` and `f0061/lobby-tooling.spec`. So a commented `snake/lobby.project.jsonc` does not stop `z-nile/affected` or the gate's selection. The gate code that does reach `projectsIn` is `currentPlaces()`, through `graph.serverFile` and `graph.srcAliasViolations` (`places = places or currentPlaces()`, graph.luau:594). pickman's `tests/meta/architecture.spec` case "src requires: ./, ../, …" runs it, and every home runs that spec through its wrapper, from its own folder. The jsonc.spec case for a commented file calls only `pcall(graph.placeInputs, …)`. The server-file case uses a `lobby.project.jsonc` that decodes. Suppose `currentPlaces` gets a guard of its own (`local ok, list = pcall(projectsIn, ".")` with `{}` on error), or skips the entries it cannot decode. That implementation passes all of AC3: `placeInputs` still raises, and the server-file case has no commented file. Yet the server-file rule would then ignore a commented place silently. A lobby that replicates `src/server` would leave a `@game/ServerStorage` require allowed in a file the lobby replicates.
Critique: this is the defect lesson new-refusals-reach-every-caller warns about: the design lists who meets the new refusal, and the list is wrong. Lesson pin-fail-safes-where-they-act applies too: the design states that "the selector and the server-file rule fail closed", but the case for it runs where the fail-safe no longer acts. The quick fix is to delete the sentence about `z-nile/affected`. That would leave AC3 still pinning the dead path and the live one still unpinned.
Consequences: correcting the caller list changes what the README's "the selector … read[s] both names" can mean. It is true only for `HOME_FULL`, which forces the static run, because spec selection is by watch map. A `.jsonc` change selects a spec only once a watch file names it, the same as a new `.json` today (zz-test Places), so the selector needs nothing new. The pickman-arch sentence the design edits (line 19) still says "the selector (`graph.placeInputs`) from every `$path`", which has been stale since #293. That is not this rule, so it is not this issue's to fix, but the lead should capture it so the edit does not seem to confirm it.
Recommendation: (a) Rewrite inventory item (2) and the "Who else meets the new refusals" bullet with the real reach. Graph's error for a commented `.jsonc` reaches `currentPlaces`, and through it the "src requires" case of every home's `tests/meta/architecture.spec` (via `srcAliasViolations`). `placeInputs` and `affectedSpecs` reach only the specs named above. `z-nile/affected` and the gate's selection are not reached; they select by watch map. (b) In jsonc.spec's server-file case (or a new AC3 case), add a third fixture folder `bad/` holding `default.project.json` and `notes.project.jsonc` = `COMMENTED`. Run the same probe there and assert that the process fails (`r.ok == false`) and that its stderr contains `notes.project.jsonc is not a Rojo project`. The `answer` helper asserts `r.ok`, so this needs a variant that returns the result. (c) Add a Rules row: rule "the server-file rule fails closed on a commented `*.project.jsonc`", mutant "`currentPlaces` catches `projectsIn`'s error, or skips an entry it cannot decode", marked run once the case kills it on the prototype. Keep the `placeInputs` case: it pins the shared lister.
