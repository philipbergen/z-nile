## Idea
c0265 gives the beat (`./zn beat`). An agent that must remember to run it will forget, and a claim that is worked but not beaten reads lost after 15 minutes. c0275 makes the beats automatic. It is one layer of the heartbeat raft (c0265, c0274, c0275, c0276, c0277), delivered a layer at a time in depends_on order.

- **A claim beats from the moment it is made.** Every claim publish gives the first beat.
- **A working session keeps its claim alive.** An agent's own `./zn` commands in its worktree beat its claim, throttled to one beat per interval.
- **Long commands beat.** Long `./zn` commands beat while they run (c0265's capture: "a beat built into ... long `./zn` commands").
- **The dispatcher beats** the item a model step works on, while the step runs.
- **A waiting session keeps its claim alive** (Q1). A claim starts a bounded background `./zn beat --watch` (under `./zn run`). It stops when the session ends or the worktree goes away. So an interactive session (the user's own `/z-run` or z-design) that thinks for a long time or waits for the person still beats.
- **A discarded worktree stops beating.** Once c0277 discards a worktree, no automatic beat comes from it: not the background beater, not the `./zn` commands run there, and not the dispatcher's (c0277's capture gives this to c0275).
- **Safe.** A beat never fails the command it rides on, and never runs inside a check or spec flow of the real repository.

Not here: the beat itself, its storage and the verdicts (c0265); which claim a checkout owns and what an old owner is told (c0274, to which an automatic beat is bound); z-work's own loop (c0253, which calls the same beat); and the board (c0276).
