## Idea
c0265 gives the beat (`./zn beat`). An agent that must remember to run it will forget, and a claim that is worked but not beaten reads lost after 15 minutes. c0275 makes the beats automatic. It is one layer of the heartbeat raft (c0265, c0274, c0275, c0276, c0277), delivered a layer at a time in depends_on order.

- **A claim beats from the moment it is made.** Every claim publish gives the first beat.
- **A working session keeps its claim alive.** An agent's own `./zn` commands in its worktree beat its claim, throttled to one beat per interval.
- **Long commands beat.** Long `./zn` commands beat while they run (c0265's capture: "a beat built into ... long `./zn` commands").
- **The dispatcher beats** the item a model step works on, while the step runs.
- **A waiting session keeps its claim alive** (Q1). A claim starts a bounded background `./zn beat --watch` (under `./zn run`). It stops when the session ends or the worktree goes away. So an interactive session (the user's own `/z-run` or z-design) that thinks for a long time or waits for the person still beats.
- **A discarded worktree stops beating.** Once c0277 discards a worktree, no automatic beat comes from it: not the background beater, not the `./zn` commands run there, and not the dispatcher's (c0277's capture gives this to c0275).
- **Safe.** A beat never fails the command it rides on, and never runs inside a check or spec flow of the real repository.

Not here: the beat itself, its storage and the verdicts (c0265); which claim a checkout owns and what an old owner is told (c0274, to which an automatic beat is bound); z-work's own loop (c0253, which calls the same beat); and the board (c0276).

### What the layers above may change (the layer rule)
`./zn done` runs every member's `check.sh` on the final tree, and sequestered specs are not edited during execution. So this layer's cases pin only what c0276 and c0277 keep, read from their hand-offs (`c0265/experiments/split/c0276/design.md`, `c0277/design.md`; and c0277's captured document):
- **Kept by every layer, and pinned here**: the first beat of every claim publish (and that it runs inside the claim command, before it returns, so c0276's board refresh after a publish reads it); the throttle mark `.cache/tracker-beats/<id>` (its name, and its content `<stamp> <epoch> <sha>`), which c0277's discard deletes; the commands that never autobeat (`beat`, `run`, `reap`, and the read-only ones), which c0277 names as its own exemptions; that an old owner is told once on stderr and its mark dropped; the dropped branch at give-back, `release`, `stop` and `done`; the beater's command (`./zn run --time 3600 -- ./zn beat <id> --watch`, with `--session <pid>` when a `claude` session is found) and its pid file `.cache/tracker-beater/<id>`; `ZN_DISPATCH=1` starting no beater; the dispatcher's `beat <id> --adopt --stamp <S>`.
- **c0277 (discard and recover) may**: refuse every command in a discarded worktree with its own text (the autobeat exempts `beat`, `run` and `reap` for the reason c0277 gives: the session-end reaper of a session whose folder is the discarded worktree must still run), delete the old worktree's marks, add its `.cache/discarded` check to the places that decide a loop has nowhere to beat from: `goneNow` in `cmd.beat` (which calls `heartbeat.gone`) and the loop of `dispatcher.claimBeat` (which must stop itself: `ctx.memoryIn` returning nothing would only make it fall back to the stamp the step started with), refuse before `hb.begin` runs (or delete the marks first, as its hand-off says: the order is c0277's to state), and create numbered copies in which the taker claims with c0274's `status <id> preparing` (whose first beat this layer gives). This layer's cases never mark a worktree discarded, and the old owner is a worktree that merely ran a command after the takeover. The stop of a discarded worktree's beats needs no other fact than the one this layer already uses: a takeover restamps the claim, so the old stamp is refused by the stamp binding (`beat`, `--watch`, the dispatcher's `--stamp`) and dropped by the autobeat.
- **c0276 (board)** reads verdicts only. Pinned here: the first beat lands before the claim command returns, so any read that follows a publish sees the claim live. Nothing here touches the board.
- **Orders c0274 fixed and this layer keeps**: the drop of `stop`'s branch runs after `stop`'s verdict read (pinned: the subject says `lost 32m`, which only the branch's last beat gives; the claim's landing time would give a longer silence), and the first beat after a takeover runs after `hb.swapBranches` (pinned: the taker's branch is beaten, never the old stamp's, and its mark holds the sha the swap wrote). c0274's memory file name and content, its refusal prefixes, the takeover subject and `done` dropping the work memory are untouched.
- **Not pinned, because an upper layer changes it**: the text a discarded worktree shows; whether the beater loop's stop for a discarded worktree is spelled with `goneNow` or a second check.

### The change
Pure (`z-nile/engine/heartbeat.luau`, no I/O, no clock):
```
heartbeat.plan(stamp, epoch, beats, claimed, now, remembered?)         -- the one lease rule: the sha this checkout last wrote, else the sha seen, else "" (create only)
type Mark = { stamp, epoch, sha }
heartbeat.markText(m): string / markParse(text): Mark?                   -- "<stamp> <epoch> <sha>"; a damaged file is no mark
heartbeat.due(last?, now, every): boolean                                -- none made, a full interval old, or dated past the skew allowance
heartbeat.markAfter(stamp, now, before?, wrote?): Mark                   -- an attempt advances the epoch, failed or not, and keeps the sha it knew
heartbeat.leaseOf(mark?, stamp): string?                                 -- the mark's sha, only for the same stamp
heartbeat.beaterStart(BeaterFacts): boolean                              -- not dispatched, not the main checkout, not protected, none running, not a spec run unless one asks
heartbeat.beaterArgv(root, id, session?): { string }                     -- ./zn run --time 3600 -- ./zn beat <id> --watch [--session <pid>]
heartbeat.beaterRunning(pidFileText, now, alive): boolean
heartbeat.sessionPid(chain): number?                                     -- the nearest `claude` ancestor
heartbeat.gone(sessionAlive?, worktreeThere, memoryThere): string?      -- why a loop has nowhere to beat from: session ended / worktree gone / no longer holds the claim
heartbeat.watch(..., gone?)                                              -- gains "stop-gone", after "stop-restamped" and before "stop-bound"
heartbeat.stampIn(status?): string?; dispatchStamp(started?, remembered?): string?; dispatchOutcome(ok, stderr): "beat"|"lost"|"none"|"failed"
```
`reap.luau`: `reap.isBeater(command)` and the orphan rule's `underBeater` (a process that is a beater or runs below one is not orphaned).

Engine edge (`z-nile/engine/main.luau`; every new function is in the table `hb`, declared above the claim commands because they call it, and `hb.MARKS`, `hb.BEATER_DIR`, `hb.DAEMON` are table fields: no new top-level local, the chunk is at Luau's 200):
- **The first beat of a claim** (`hb.firstBeat(id, stamp)`): after every claim publish and, for a takeover, after `hb.swapBranches`: `status <id> preparing` (an issue's, a raft's, a takeover's), `new raft`, `fold` and `unfold` (when they publish, not on a resume), `recombine` (the keeper; the other raft's mark is dropped), `ready` (from the main checkout: a ref push only, no mark, no beater) and the legacy `start`. It runs inside the command, before `mergeOrigin()` can exit, is best effort in `pcall`, and a failure is said as `beat: <id>: <message>` on stderr while the claim stands and the command exits 0. In a worktree it writes the mark whether or not the beat landed, so a claim whose first beat failed is beaten by the worktree's next command after an interval, and it starts the claim's beater.
- **The throttle mark** (`hb.readMark/writeMark/dropMark/markIds`, `hb.MARKS = ".cache/tracker-beats"`): one file per claim, `<stamp> <epoch> <sha>`, written with `sh.writeReplacing`; the main checkout writes and reads none. `hb.attempt(id, stamp)` is the one beat attempt with a mark (in the main checkout it neither reads nor writes one): it leases on the mark's sha for that stamp (`hb.beatOnce` gained a `remembered` argument and returns the sha it wrote or saw), writes the mark after the attempt (a failed one advances it too), writes it only while the worktree's memory still names the stamp (a give-back that ran meanwhile is not undone by a late write), and drops it when the claim is lost. `cmd.beat` (explicit, `--adopt`, `--watch`'s ticks) goes through it, so every beat of every path keeps the same mark.
- **Every `./zn` command in a worktree** (`hb.begin`, called once before the handler, `hb.finish` after; `hb.autobeat` is its body): except `beat`, `reap` and the `READ_ONLY` commands (`run` never reaches the engine: `zn` starts the runner before Lune), for each mark: `hb.ensureBeater(id)`; if the mark is not due (`heartbeat.due`) nothing else happens, with no network call; else one fetch of `main` for all marks, then per claim `heartbeat.holds(mark.stamp, main's stamp)`: `taken` or `ended` drops the mark and says once on stderr `<id>'s claim was taken over (now <stamp>): stop working it` or `<id>'s claim ended` (the words `--watch` uses; an item whose claim changed kind, a prep that ended normally and the item readied later, is `ended`, `heartbeat.lostKind`) and beats nothing; `held` beats it. An unreadable `main` is a failed attempt: the mark advances, one line is said. It reads the marks folder first (a worktree with no claim pays one directory read and prints nothing), then asks `hb.mayBeat()` (`publishing(true)`: the engine's own fence answer, quiet, false in a checkout a check protects, the one reader, failing closed), so a nested `./zn` in a check or spec flow of the real repository never fetches or pushes and says nothing new; fixtures are unguarded and beat. The whole of it is in `pcall`: a beat never fails the command.
- **Long commands** (`check`, `done`, `land`, `dispatch`) in a worktree that holds marks also run `hb.autobeat` in a `task.spawn` task every interval while they run (the capture's "a beat built into ... long `./zn` commands"); `hb.finish` cancels it. The command's own `process.exec` calls yield, so the task runs (E3). A nested `./zn` inside them never beats (`guarded`). The gate script `z-nile/check.sh` run directly is not a `./zn` command and has no tick: a long gate runs under `./zn done`/`land`.
- **The background beater** (`hb.ensureBeater(id)`, the user's Q1): for a claim held in a worktree it starts, detached, `./zn run --time 3600 -- ./zn beat <id> --watch --session <pid>` (`heartbeat.beaterArgv`) with its output in `.cache/tracker-beater/<id>.log` and `<pid> <deadline>` in `.cache/tracker-beater/<id>`; a command line, not an environment marker, because the reaper cannot read `perl`'s environment on macOS. It is detached by a small `perl` (one fork and `setsid`; the child waits until its parent, the starter, is gone, comparing `getppid()` with the starter's own pid `$$`, and exits if that never happens, then `exec`s the runner, because `./zn run` stops its command when its starter dies, E1 and E1d) so it outlives the command that started it. It starts with `ZN_MEASURED=1` in its environment, so that `./zn run` does not add its hour as a measured run to the claim's spend (zz-test, the spend buffer). It starts only when `heartbeat.beaterStart` says so: not under `ZN_DISPATCH=1` (the dispatcher beats for a headless step), not in the main checkout, not in a protected checkout, none running (the pid file's pid answers `kill -0`, is a runner of `beat --watch` where the process table can be read, and its hour has not passed; `hb.beaterAlive`), the worktree still remembers the claim (`held`: a beater started without the memory is refused at once, and would be again at every command), and in a spec run only when the spec sets `ZN_BEATER=1`. One start at a time per claim: a lock folder made with `mkdir` (atomic; taken over when more than a minute old, an engine that died while starting) is held from the check to the pid file. It is tried at each claim publish, at each `beat` run in the worktree that holds the claim (an adoption included), and at each `./zn` command's autobeat, so a beater that ended at its hour is back at the next command. **Its loop** is c0265's `beat --watch`, which now goes through `hb.attempt` and ends on three more facts, checked every five seconds (local facts only: `kill -0`, the folder first, then the memory file): `--session <pid>` ended (the nearest `claude` ancestor of the process that started it, found with `ps` under `LC_ALL=C`; none for another CLI or where `ps` is unreadable, as in a spec's jail, and then the hour and the worktree bound it), its worktree gone (removed or moved: the folder test comes before anything that spawns git, and the main-checkout question is asked once before the loop), or its worktree no longer holding the claim (`cm.read(id, home)` empty: a claim-ending command ran there). A restamped claim and its bound stop it as before. **The reaper** (`reap.isBeater`, `underBeater`) leaves a beater and what runs below it alone while it lives: without that, `./zn reap` (which `sync` runs with `--auto`) stops a detached beater once it is a minute old (E1). **A session end stops the session's beaters** (`reap.beaterSession`, one clause of `reap.decide` beside the tool-shell rule): `/clear` ends a session and keeps its `claude` process (the SessionEnd hook runs `./zn reap --session-end` for it), so the beater's own `kill -0` never fires; the session-end reaper stops a beater whose command line carries `--session <the ending session's pid>`, and none tied to another session or to none. A later conversation in the same process gets its beater back at its next `./zn` command.
- **The dispatcher** (`dispatcher.claimBeat`, called around `runner.run` in `modelStep`): while a model step works the item `id` of the step (nothing for a step with no id), every interval one child, `<main>/zn run --time 60 -- <main>/zn beat <id> --adopt --stamp <S>` (with `ZN_MEASURED=1` in its environment), one at a time in a task of its own (E3 of c0265: a `process.exec` in a task does not stall the supervising loop). `S` is `heartbeat.dispatchStamp(started, remembered)`: the stamp the step's worktree remembers (`ctx.memoryIn`, an optional field of `Ctx` whose real value is `cm.read(id, dir)`: one reader of the memory), else the claim `main`'s document showed when the step began (`heartbeat.stampIn`). The child's answer is classified by `heartbeat.dispatchOutcome`: `lost` (taken over mid-step) stops the beats and says so once; `none` (the step has not made its claim yet) is ignored; any other failure is said once per step on the run's stderr. Under `ZN_DISPATCH=1` nothing else beats for the step, and the claims the step makes still get their first beat and their worktree's autobeat.
- **Ends of a claim**: `hb.ended(id, stamp)` (a mark, its beater's pid file, and `hb.dropBranch(stamp)`) after `status <id> new` and a rafting give-back (`cm.drop` beside it), `hb.dropBranch` after `release` (for every stamp it gave back) and after `done` has landed on `main` (the work stamp this checkout adopted), and `hb.ended` in `stop` **after** its verdict read. `hb.dropBranch` deletes `hb/<stamp>` with a lease on the sha read, only when no claim on `origin/main` still holds that stamp, best effort and silent (the pruner is the backstop). `done` drops the marks of the raft and its issues beside `cm.drop`.
- **Shared refs** (`z-nile/lib/sh.luau`): the beaters, the long-command tick and the dispatcher's child fetch `main` into refs every worktree shares, so a command's own fetch can meet their lock. `sh.run` now tries a `git fetch` that fails with `cannot lock ref` once more after a second (a second failure is the answer), one place for the ~25 fetches of `main.luau` rather than a private ref for the heartbeat (which `originTree`, `claimStampOf` and `originRoots` would each have to read).
- **Skills and docs**: `zz-rules` (the Heartbeat paragraph gains **Automatic beats**), `z-design`, `z-raft`, `z-run`, `zz-execute` (the sentence "keep your claim alive" now says the claim keeps itself alive, nobody starts a loop, and `./zn beat <id>` is for seeing a refusal; each keeps `./zn beat` and `--time 3600`, which c0265's AC5 pins), `zz-test` (the reaper sentence), the README roadmap row `automatic heartbeats | c0275 | exists`, and the reviewed `.cache` list (`z-nile/tests/lib/cachepaths.luau`: two lines, `hb.MARKS` and `hb.BEATER_DIR`).

- **Restated rules**: `zz-rules`, `z-design`, `z-raft`, `z-run`, `zz-execute`, `zz-test` and the README change with it, and AC4 pins each phrase.
- **Moves**: none.
- **Guards**: `hb.mayBeat()` asks the engine's own fence answer before any network call of an automatic beat (first beat, autobeat, tick, branch drop); the explicit `beat` refuses in a protected checkout as c0265 made it; the beater is never started there; the heartbeat branch pushes are branch pushes (the fence's `decidePush` judges only `main`); the commit is authored by the checkout's own identity (c0265's tripwire rule); every network call goes through the bounded wrapper. The detached beater is a process the spec runner's sweeper stops at the end of a run; the proofs end theirs.

### Assumptions to veto
- **The session is a `claude` session.** "Stops when the session ends" is implemented for the CLI whose process is known (`claude`, the nearest ancestor by name) and for any CLI as "its worktree is gone or no longer holds the claim, or its hour is up". A session of another CLI (grok, agent, kimi, codex) that ends leaves its beater beating until its worktree changes or its hour passes, at most an hour. Adding a CLI is one name in `heartbeat.sessionPid`.
- **One hour, then the next command.** The beater is `./zn run --time 3600`, the longest a command may run. A session silent for more than an hour after its last `./zn` command loses its beater, and its claim reads lost 15 minutes after the last beat; its next command restarts it. The alternative (the beater restarting itself) defeats the bound.
- **Zombie and reused pids**: the session's end is `kill -0` failing, so a session process left as a zombie by a parent that never reaps it keeps the beater beating up to its hour; a pid reused by another process the same.
- **A beater is a detached process, not a child of the session**: it is stopped at a session end by the reaper's `--session` clause (and by its own `kill -0` when the `claude` process exits), spared the orphan rule by its command line only.
- **A taker's first beat is a no-op on the wire** (the swap created the branch with the same epoch); the first beat still runs for its mark and its beater.

### Scalability
A beat is three fetches (the beat branches, `main`, `main` again inside `hb.beatOnce`) and one push of a one-commit pack, per claim per interval, as c0265's explicit beat; the autobeat shares one fetch of `main` across a worktree's claims and makes none inside the interval. With claims held, per claim a file read and a `kill -0`. A command costs one directory read when the worktree holds no claim (about 0.13 s of git calls were saved by reading the folder before asking where the checkout is). A background beater is a sleeping engine that wakes every five seconds for local checks (a `kill -0` and two folder tests; no git) and every five minutes for a beat; one per claim held in a worktree, none in the main checkout. The dispatcher adds one bounded child per interval per step.
### Maintainability
`heartbeat.luau` stays the one place the beat's format, the lease, the mark, the beater's command and the stop rules are decided; `main.luau` has one throttle mark (`hb.markFile`), one attempt (`hb.attempt`), one first beat, one place a claim's local state ends (`hb.dropMark`), one reader of the claim memory (`cm.read`, now with an optional folder for the dispatcher), one start of the beater (`hb.ensureBeater`) and one `begin`/`finish` pair on the dispatch path; the siblings add to these, never a second mark or a second loop. The names are `hb.*` (the dispatcher's own stall beat is `keepBeating`/`holdBeat`: this layer's is `claimBeat`).
### Usability
Nobody starts a loop or runs `./zn beat`: a claim beats from the moment it is made and stays alive while its worktree runs commands, while its session thinks or waits, and while the dispatcher's model works; the skills say so in one sentence. An old owner is told once, in words that say what to do; a failure to beat is said with the item named and never fails what the person asked for.
