# c0279: Dispatch stop spec waits on wall clock

## Problem
The promoted spec z-nile/tests/acceptance/c0117/dispatch-cli.spec.luau case 'dispatch stop kills the running step's group, and retry reruns the same step' fails on main whenever the machine is loaded (line 692, expected true, got false: absentAfter(<fakes>/grandchild-stop, 3) gives the killed step's grandchild 3 wall-clock seconds to disappear), so the full gate goes red and every ./zn land refuses: it failed two of three split-capture lands on 2026-11-08 and c0263's gate, with control-cli taking 905 s against 329 s unloaded, while it passes on an idle machine. Make the case prove the kill without a wall-clock wait (or a bound that holds under load), as the user's standing rule that promoted specs wait for nothing requires; nothing else in c0117's dispatcher changes. Scope decision (user, 2026-11-08): "Capture it now". Scope decision (user, 2026-11-08): "Yes, every load-sensitive case in that file": c0279 covers every case of z-nile/tests/acceptance/c0117/dispatch-cli.spec.luau that the load runs show failing under load (at least "dispatch stop kills the running step's group, and retry reruns the same step" and "an agent's git and gh refuse a code push to main and a merge, before the real gh runs"), so one raft clears the gate.

## Non-goals
- No change to the dispatcher (`z-nile/engine/`), the supervisor, the wrapper or any `stall_seconds` default: the cases and their fakes are wrong, not the code they test. The prototype needs no engine change.
- No new wall-clock wait, and none longer: a bound that only a kill that never comes can reach (60 s) is the only kind this issue adds.
- The cases that test a stall (`a stall after the CLI's own wait message is quota...`, `a tool call quiet past the stall limit...`) keep their 2 s stall limit, because the stall is what they prove; their residual load sensitivity is named in E5.
- `control-cli.spec.luau`'s `absentAfter(grandchild-orphan, 5)` has the same shape but is another file: out of the user's scope decision (E5).

## Solution
(captured idea: make the case prove the kill without a wall-clock wait, or with a bound that holds under load.) The load runs (E1) show three cases of `dispatch-cli.spec.luau` failing, all on one cause: the spec's `[dispatch] stall_seconds = 2` is the dispatcher's silence limit, and a fake CLI that does slow work quietly (a `./zn dispatch stop`, a `git commit`/`push`, a `gh`, or only starting up) is killed as `stalled` on a loaded machine; the stop case also waited 3 s for a file its grandchild would touch after 2 s. Two changes, in the spec and its fake (`z-nile/tests/lib/fakecli.luau`):
1. **A stall limit only a real stall reaches.** The spec's root `.models.toml` gets `stall_seconds = 60`, `tool_seconds = 120`; the one issue whose cases test a stall (c0040) gets a closer `.models.toml` with `stall_seconds = 2`, `tool_seconds = 30`. Every other case ends by its own signal (a quota, a cap, an exit, a stop) and stalls only if it really does.
2. **A kill proved by the process's death.** The `stop` and `cap` fakes start a grandchild that writes its pid and `exec sleep 120`, and wait (bounded, 60 s) for the pid file before the action. The cases replace `absentAfter(<file>, 3)` with `deadWithin(<pid>, 60)`: a poll of `kill -0` that returns the moment the process is gone ("No such process") and runs long only if the kill never comes. After the stop the stop fake goes silent and holds 120 s, so a stop that kills nothing ends in a stall, not in an exit that looks like a stop.
`FAKE_DELAY` (seconds, default 0) makes the stop and the push slow inside the step (before `./zn dispatch stop`, before `git push`, before `gh`): only a `check.sh` sets it, to simulate a loaded machine while the promoted spec waits for nothing.

## Design

- **Restated rules**: none restated in skills or AGENTS.md; the spec's header comment (kill at the cap and on a stall) stays true.
- **Moves / Guards**: none; no guard, publisher or gate code changes (`./zn dispatch stop` runs through the same wrapper).

**Changes** (all in `z-nile/tests/`):
- `lib/fakecli.luau`, `script()` modes: (a) `stop)` = `echo '{"type":"system"}'`, `sh -c 'echo $$ > "$FAKE_DIR/grandchild-stop.pid"; exec sleep 120' &`, a wait of at most 60 s for that file, `sleep ${FAKE_DELAY:-0}`, `./zn dispatch stop "$FAKE_STOP"` as before, then `sleep 120` (no output); (b) `cap)` = the same grandchild with `grandchild-cap.pid` and the same wait, then its 20 heavy lines and `sleep 20` as before; (c) `push)` = `sleep ${FAKE_DELAY:-0}` before `git push` and before `gh pr merge`, the rest as before.
- `acceptance/c0117/dispatch-cli.spec.luau`: root `[dispatch] stall_seconds = 60`, `tool_seconds = 120`; fixture `pickman/.tracker/issues/c0040/.models.toml` = `[dispatch]\nstall_seconds = 2\ntool_seconds = 30\n`; `absentAfter` is replaced by `deadWithin(pid: string, seconds: number): boolean` (polls `/bin/kill -0` every 0.1 s; true only when its stderr says "No such process", so a permission error or a missing `kill` is no death; false after `seconds`) and `grandchildPid(name)`; the stop and cap cases call `deadWithin(grandchildPid("grandchild-stop" | "grandchild-cap"), 60)`. The exact diff is `acceptance/dispatch-cli.spec.expected.diff` (71 lines), and the prototype branch `proto-c0279`.

Why this holds under any load: no case waits for a clock to prove anything. The kill proofs end the moment the process is gone (about at once, because the kill has happened before the stop returns) and fail only after a 60 s bound that a kill that never comes reaches; the grandchild's `sleep 120` outlives that bound by a margin that cannot shrink with load, because load only slows a process, it cannot make `sleep` shorter (a sleep that ended by itself would need 120 s of the case's 60). The 60 s stall limit cannot be reached by a fake that is slow, only by one that is stuck. No claim in this paragraph rests on the fake's startup being fast (the measurement in E1b shows the startup is not the cause).

### Scalability
No added cost in the common case (the proofs end as soon as the process does). A broken kill costs up to 60 s per case, once, where it used to cost 3 s: the price of a bound that load cannot reach.
### Maintainability
One rule for the next fake: a fake that has to be quiet while it works belongs to an issue whose stall limit is long; a case that tests a stall says so with its own short limit (c0040, in the fixture and the comment above it). The pid-and-`deadWithin` pattern is the one way this file proves a kill. `FAKE_DELAY` is the one knob that proves load insensitivity.
### Usability
A broken kill fails as `expected true, got false` at the `deadWithin` line (60 s later); a stop that kills nothing fails as `expected "stopped", got "stalled"`.
