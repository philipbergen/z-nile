# c0280: Provenance who from git

## Problem
Scope decision (user, 2026-11-08): "Split it and prototype first, like c0265" (c0263 Ticket provenance was split into c0263 (the record: provenance.md, ./zn record, the append-only publish rule, the union of two writers) and this issue and its siblings; one raft, delivered a layer at a time in depends_on order; this issue depends on c0263, which its prep writes into depends_on). Carried from c0263's capture (User, 2026-11-07): "tickets need authors (whose idea, take it from git, ...)": ./zn who <id> prints a ticket's history, oldest first: the Author (whose idea, the author of the ticket's capture commit, taken from git), each status change, the merge, and the worker of each delivered layer read from the ticket's spend rows (host, CLI and model once c0254 adds them), together with the rows c0263's record stores. Decided with the user (2026-11-08), Q1: "Derive from git, store only the rest": what git knows is read from history by ./zn who, never stored. Decided with the user (2026-11-07): "yes, back-fill existing done and backlog items from git where possible" (met by deriving: old items need no write). Decided with the user (2026-11-08), Q4: "Read c0254's spend rows". Decided with the user (2026-11-08), Q5 readings: "Confirm all" (back-fill uses the git author for engine publishes).

## Non-goals
- The record itself, `./zn record`, the append-only publish rule, audit of `provenance.md`, the union of two writers in the engine's merges and `remap`: c0263 (this issue reads its rows through `provenance.parse` and never writes one).
- The rows the lifecycle commands append (`unblocked` on `status <id> new`, `rafted`, `delivered`), `ZN_ACTOR`/`ZN_VIA` per dispatcher attempt: c0282. This issue prints such rows when they exist and derives the same facts from git when they do not.
- `./zn approve`, the approval gate, the frozen list and the dispatcher's prep gate: c0283. An `approved` row prints like any stored row; nothing is derived for it (a bot may push the status).
- The board's Provenance section and its one history read per build: c0284. This issue only exports the reader it will call (Behaviour 6).
- Worker identity on spend rows (host, CLI): c0254. The worker is read from the columns that exist (the model today).
- Storing anything git already knows, and any write into old documents (the Q1 decision: derive, store only the rest).

## Solution
- `./zn who <id>` prints a ticket's history, oldest first: the idea's author (the capture commit's author, from git), each status change (the author of its `tracker: <id> <status>` commit and an agent trailer), the rafting, the delivery and the merge (from git), the worker of a delivered layer (from the ticket's spend rows), and the rows `provenance.md` stores. Nothing git knows is stored; an old done or backlog item answers with no write (the user's back-fill, met by deriving).

Prep's detail, below the captured bullet. The derivation is pure (`provenance.select`, `provenance.merge`) over the item's commits as `trail.read` returns them, so `who` and the board (c0284) cannot disagree: both call `who.entries` (Behaviour 6). Git is read in three places only, all in `who.luau`: the item's life (one `git log` through trail), the authors' emails of the whole log (one `git log --format=%ae`), and the document's `raft:` after each of its commits (one `git show` per commit, `who` only).

## Design

### Decisions this layer relies on (quoted)
- Q1 (2026-11-08), "Derive from git, store only the rest": what git knows is read from history by `./zn who`, never stored.
- (2026-11-07) "yes, back-fill existing done and backlog items from git where possible" (met by deriving).
- Q4 (2026-11-08), "Read c0254's spend rows": the worker (host, CLI, model) is read from the ticket's spend rows, never stored.
- Q5 (2026-11-08), "Confirm all": back-fill uses the git author for engine publishes (they carry no trailer); `release`'s give-back is not a recorded event.
- The user's actor grammar (2026-11-07): `human:<git name>` or `agent:<model> effort <level>`; a value read from git ends ` (from git)`.
- "Split it and prototype first, like c0265" (2026-11-08): this layer was prototyped first (branch `proto-c0280`, on `proto-c0263-raft`).

### Behaviour (every outcome this layer owns)
1. **The log carries who (AC2).** `trail.Commit` gains optional `author`, `email` and `trailers` (additive). `trail.FORMAT` is `--format=@@%H %ct %s%n@A%an%n@E%ae%n@T%(trailers:key=Co-Authored-By,valueonly,unfold,separator=%x1f)`: one header line, then three tagged lines (`@A` author, `@E` email, `@T` the Co-Authored-By values separated by the unit separator, empty when none), then `--name-status`'s change lines. A change line (`M\tpath`) and these tags cannot be confused and no commit body is read, so a body line that looks like a change line cannot misparse. `trail.parse` reads the tags (a log without them gives commits without the fields) and every caller of the log (`trail.read`'s `changes`) uses `trail.FORMAT`; `capture`'s output is unchanged. `trail.isDoc` already refuses `provenance.md` (c0263). `trail.cut(commits, cuts)` is the pure cut `read` applies (`life`, then `since` the newest compaction cut), extracted so that `read` and the board share one definition of an item's life.
2. **Who a commit's actor is (AC1).** `provenance.fromTrailer(line)` reads a `Co-Authored-By: Name <email>` line (the key in any letter case) as `agent:<modelId(Name)> effort unknown (from git)`, and any other trailer, or a name-less value, as nil. `provenance.fromCommit(author, trailers, people)`: the agent of the **last** trailer value whose lower-cased email is not in `people` (every author email of the log, lower-cased: a person is whoever commits, so a co-author who is a person, even under another name, is not an agent; E4), else `human:<author> (from git)`. A value with no email counts as an agent. The engine's own `tracker: <id> <status>` publishes carry no trailer, so a give-back an agent ran reads as the human git shows (Q5, stated).
3. **What an item's life says (AC3).** `provenance.select(life, id, state, raft, people, raftAt): Derived`, over the item's commits newest first (the document's and `provenance.md`'s changes; a record change has `doc` false), where `state` is the folder it is in now, `raft` its `raft:` now and `raftAt` the document's `raft:` after each commit that touches it:
   - `idea`: `trail.capture`'s commit: the author, `human:<name> (from git)`; when no commit names the item (a renumbered item) its first add, `human:<name> (from git, first add)`. A trailer is never read for the idea.
   - `statuses`: one entry per commit whose subject is exactly `tracker: <id> <word>` with `<word>` not `new`, as the event `status:<word>`, the actor by Behaviour 2. A move (a delete and an add of one sha) is one entry.
   - `unblocked`: one entry per commit whose subject is `tracker: <id> new` **that did not also change the item's `provenance.md`** (per commit, not per event), printed as `unblocked` and never also as a status line. A commit that appended a stored row is covered by that row.
   - `rafted`: the oldest document commit at which `raft:` became the value it has now and stayed so to now (not a ready, a restamp or the move to `done/`, which keep the value; an unfold, which empties it, breaks the run), detail `raft=<R-id>`; none when `raft:` is empty. A commit that only deletes a path of the document is skipped.
   - `delivered` and `merged`, for a `done` item: the oldest commit that **added** (`A`) the document under `done/<id>/`: `delivered` with the actor by Behaviour 2 (so an agent trailer on the squash is read) and detail `raft=<R-id>`, and `merged` with the commit's author alone, trailers ignored (a squash is authored by the user with the agent as co-author).
4. **The merge (AC4).** `provenance.merge(derived, rows, worker): { Entry }` lists the derived entries and the stored rows (`source` `git` or `record`) oldest first by their date to the minute; at the same minute a derived entry comes before a stored one, then the order they came in. **A stored `rafted` or `delivered` row wins over the git fallback of its event only when it names the same raft** (its detail has the derived entry's `raft=` part; with no raft on the derived entry, any stored row of the event): a stored row for an earlier raft is history and the current raft's git entry stays. Every `delivered` entry, derived or stored, gets `worker=<…>` joined to its detail with `; ` when a worker is known. `provenance.workerRow(rows)` is the newest `deliver` spend row that has a model, else the newest `build` row that has one; `provenance.workerOf(row)` joins the row's host, CLI and model that exist with `/` (c0254 adds host and CLI; the model column exists today), nil with none.
5. **`./zn who <id>` (AC5).** Prints `provenance.line` of each entry: `<when>  <event>  <actor>  <detail>  (git | record)`, parts joined by two spaces, the detail left out when empty, and no other line. It takes an issue or a raft id; refuses (exit 1) an id the tree does not hold, an id with no history, a `provenance.md` that does not parse (naming the file, before it prints anything: `parse` refuses, nothing is skipped) and a `spend.md` that does not parse. It reads the **checkout's own history** (`HEAD`; a worktree shows its branch's commits, the main checkout main's), its `provenance.md` and `spend.md` from the working tree, and the item's `state` and `raft:` from its document there, so one read is consistent with itself. It writes nothing and runs in the main checkout (like `capture`). Existing done and backlog items need no record and no write. The usage text lists it; zz-rules lists it among the read-only commands and in the commands table.
6. **The shared reader (AC6).** `z-nile/engine/who.luau` (new; the edge): `who.want(name)` (the document and `provenance.md`), `who.life(id, head)` (`trail.read` with that `want`), `who.people(head)` (every author email of `head`, lower-cased, one `git log`), `who.raftAt(life)` (one `git show` per commit that touches the document), and `who.entries(life, id, state, raft, people, rows, spend, raftAt)`, which is `provenance.merge(provenance.select(…), rows, workerOf(workerRow(spend)))`. `cmd.who` passes `who.raftAt(life)`; c0284 passes an empty `raftAt` (the board leaves out the derived `rafted`, which needs a read per commit), so with `{}` `select` gives no `rafted`. `store.parseFront(text)` is `readFront` over a text (one frontmatter reader, used for a document read from git).
7. **Docs (AC7).** zz-rules (the commands table, the read-only list, the Provenance section) and the README name `./zn who` and what it derives; the usage text lists `who <id>`.

### Interfaces
`z-nile/engine/provenance.luau` (c0263's; pure over texts, requires `./trail` for the `Commit` type and `trail.capture`):
```
type Commit = trail.Commit
type Entry = { when: string, event: string, actor: string, detail: string, source: "git" | "record" }
type Derived = { idea: Entry?, statuses: { Entry }, unblocked: { Entry }, rafted: Entry?, delivered: Entry?, merged: Entry? }
type Spend = { phase: string, model: string?, host: string?, cli: string? }
provenance.fromTrailer(trailer: string): string?
provenance.fromCommit(author: string, trailers: { string }, people: { [string]: boolean }): string
provenance.select(life: { Commit }, id: string, state: string, raft: string, people: { [string]: boolean }, raftAt: { [string]: string }): Derived
provenance.merge(derived: Derived, rows: { Row }, worker: string?): { Entry }
provenance.workerRow(rows: { Spend }): Spend?
provenance.workerOf(row: { model: string?, host: string?, cli: string? }?): string?
provenance.line(e: Entry): string
```

### The split
Pure and unit-tested: `provenance.fromTrailer`/`fromCommit`/`select`/`merge`/`workerRow`/`workerOf`/`line`, `trail.parse`/`cut`. Adapter (thin): `who.luau` runs git and `main.luau`'s `cmd.who` reads the item's files and prints. The wiring is checked through the command (`who.spec`), because an unwired caller passes every pure case.

### Scalability
`who` runs three git commands: `git log` over the item's three folders under every root (as `capture` does), `git log --format=%ae` (O(commits), 0.1 s for 1,900), and one `git show` per commit that touches the document (about ten for a typical item, up to a few dozen); the pure functions are O(commits x entries). The board's O(items x lines) trap is c0284's (E9, moved there): this layer gives it the pieces that make one read enough.
### Maintainability
One reader per format: `trail` for the log (the new fields go through its `parse`), `provenance.parse` for the record, `ledger.parse` for spend, `store.parseFront` for a document's frontmatter. The next event the record learns (c0282, c0283) needs no change here: a stored row prints, and a git fallback joins the table only when git can tell it.
### Usability
One line per event in a fixed shape; a refusal names the file (`who: <path>: <why>`); a derived value says `(from git)` (and `first add` when it is weaker), so a reader can tell git's word from the record's.

### Edge cases
- No record, no spend: git entries only. An item with a record and no git history of its own (a prep worktree's uncommitted add): `who` fails with "no history" (the life is read from `HEAD`).
- A reused number: only the current life (`trail.read`'s cut), nothing of the first leaks in; a life that starts at a compaction commit is cut there.
- Two agent trailers: the last. A person's trailer beside an agent's: the agent. A trailer with a person's email under another name: a person. An email in other letter case matches.
- A `new` commit whose same sha also changed `provenance.md`: covered by the stored row; any other `new` commit prints.
- `raft:` emptied by `unfold` after a rafting: no run, so none; refilled later: the later commit.
- A squash that moves a file through `active/` into `done/`: the delete and the add of one sha are one entry; the delivery is the `A` under `done/`.
- A stored `rafted` row for an earlier raft and a current rafting by git: both print.
- Same-minute entries: derived before stored.
- Names with unusual characters in git (`|`): printed as they are; `who` stores nothing.

## Acceptance criteria

- AC1: `provenance.fromTrailer` reads a `Co-Authored-By` line (any key case) as `agent:<modelId> effort unknown (from git)` and nothing else; `provenance.fromCommit` gives the last agent trailer whose email is no commit author's (a person under any name or letter case is not an agent), else `human:<author> (from git)`.
