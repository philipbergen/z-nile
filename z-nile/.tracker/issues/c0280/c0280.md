## Non-goals
- The record itself, `./zn provenance record`, the append-only publish rule, audit of `provenance.md`, the union of two writers in the engine's merges and `remap`: c0263 (this issue reads its rows through `provenance.parse` and never writes one).
- The rows the lifecycle commands append (`unblocked` on `status <id> new`, `rafted`, `delivered`), `ZN_ACTOR`/`ZN_VIA` per dispatcher attempt: c0282. This issue prints such rows when they exist and derives the same facts from git when they do not.
- `./zn approve`, the approval gate, the frozen list and the dispatcher's prep gate: c0283. An `approved` row prints like any stored row; nothing is derived for it (a bot may push the status).
- The board's Provenance section and its one history read per build: c0284. This issue exports the reader it calls (Behaviour 6), whole: the board shows what `who` shows.
- Worker identity on spend rows (host, CLI): c0254. The worker is read from the columns that exist (the model today).
- Storing anything git already knows, and any write into old documents (the Q1 decision: derive, store only the rest).

## Solution
- `./zn who <id>` prints a ticket's history, oldest first: the idea's author (the capture commit's author, from git), each status change (every change of the document's `status:` word, with the author of the commit that made it and an agent trailer), the rafting, the delivery and the merge (from git), the worker of a delivered layer (from the ticket's spend rows), and the rows `provenance.md` stores. Nothing git knows is stored; an old done or backlog item answers with no write (the user's back-fill, met by deriving).

Prep's detail, below the captured bullet. The derivation is pure (`provenance.select`, `provenance.merge`) over the item's commits on the published mainline as `trail.read` returns them, so `who` and the board (c0284) cannot disagree: both call `who.entries` (Behaviour 6). Git is read in four places only, all in `who.luau` and `trail.luau`: the item's life (one `git log --first-parent` through trail), the authors' emails of the whole log (one `git log --format=%ae`), the Co-Authored-By values of each merge commit's second parent (one `git log -1` per merge, a handful per item), and the document's status word and `raft:` after each of its commits (**one** `git cat-file --batch` for any number of commits, so the board reads every item's in one process).

### Behaviour (every outcome this layer owns)
1. **The log carries who (AC2).** `trail.Commit` gains optional `author`, `email`, `trailers`, `parents` and `sideTrailers` (additive; `sideTrailers` is set by `who`). `trail.FORMAT` is `--format=@@%H %ct %s%n@A%an%n@E%ae%n@P%P%n@T%(trailers:key=Co-Authored-By,valueonly,unfold,separator=%x1f)`: one header line, then four tagged lines (`@A` author, `@E` email, `@P` the parents, `@T` the Co-Authored-By values separated by the unit separator, empty when none), then `--name-status`'s change lines. A change line (`M\tpath`) and these tags cannot be confused and no commit body is read, so a body line that looks like a change line cannot misparse. `trail.parse` reads the tags (a log without them gives commits without the fields); `capture`'s output is unchanged. `trail.isDoc` already refuses `provenance.md` (c0263). Three pure functions share a life between `read` and the board: `trail.cut(commits, cuts)` (the last life, started at a later commit in `cuts` that changed the document; the note names the map), `trail.lifeOf(commits, id, cuts, want)` (copies the commits with the id set, cuts, and keeps the files `want` accepts), and `read` calls `lifeOf`. `trail.read` takes an optional `firstParent`: with it the log walks the mainline only, and a merge commit carries its diff against its first parent (so a `--no-ff` landing shows the move into `done/` that it made; E1b).
2. **Who a commit's actor is (AC1).** `provenance.fromTrailer(line, people?)` reads a `Co-Authored-By: Name <email>` line (the key in any letter case) as `agent:<modelId(Name)> effort unknown (from git)`; any other trailer, a name-less value, or (with `people`, every commit author's lower-cased email of the log) a value whose email is a commit author's is nil: a person is whoever commits, so a co-author who is a person, under any name, is not an agent (E3). A value with no email counts as an agent. `provenance.agentOf(values, people)` is the agent of the **last** value that is not a person's; `provenance.fromCommit(author, trailers, people)` is `agentOf(…)` else `human:<author> (from git)` (one rule: `fromCommit` calls `fromTrailer`). The engine's own `tracker: <id> <status>` publishes carry no trailer, so a give-back an agent ran reads as the human git shows (Q5, stated).
3. **What an item's life says (AC3).** `provenance.select(life, people, fronts, mark): Derived`, over the item's commits newest first (the document's and `provenance.md`'s changes), where `fronts` is the document's `status:` word (the part before the first `-`) and `raft:` after each commit that added or modified it, keyed `<sha>:<path>`, and `mark = { note, cut }` is what a cut or ambiguous life carries (Behaviour 5). The document's commits are read as steps, one per sha (a move is a delete and an add of one sha; a commit that only deletes a path is no step), each with its folder (`backlog`, `active` or `done`, from the path):
   - `idea`: `trail.capture`'s commit: the author, `human:<name> (from git)`; when no commit names the item (a renumbered item) its first add, `human:<name> (from git, first add)`. In a **cut** life (`mark.cut`) the idea is the commit that starts the followed history, `(from git, first add)`, with the mark's note as its detail: nothing before it is followed and nothing else is derived from it as a fact. A trailer is never read for the idea.
   - **status changes (F1)**: at each step whose status word differs from the previous step's, one entry, `status:<word>`, with the actor of that commit by Behaviour 2, whatever the subject (a prep PR's squash, a ready that moves the document, a raft's move of its members, a `release` give-back). A step that keeps the word (a restamp, a `tracker: R0065 members` that only changes `raft:`) is no entry, and neither is the first step (that is the idea) or the step that first brings the document into `done/` (that is the delivery).
   - `unblocked`: a change **to** `new` made by a commit whose subject is `tracker: <fdcR-id> new` (the item's own `status <id> new`, or a raft's give-back of its members) is `unblocked`, once per commit, and not at all when the same commit also changed the item's `provenance.md` (the stored row covers it: per commit, not per event). Any other change to `new` (a `release`) is a status line.
   - `rafted`: the oldest step at which `raft:` became the value it has now and stayed so (not a ready, a restamp or the move to `done/`, which keep the value; an unfold, which empties it, breaks the run), detail `raft=<R-id>`; none when `raft:` is empty, and none when the run reaches back to the commit that starts a cut life (an earlier life made it).
   - `delivered` and `merged` (the **arrival rule**, c0118's `doneAt` restated over the life): the first step whose folder is `done` after a step whose folder is not (a move between roots keeps the folder, a compaction's re-add as the first step has no step before it: neither is an arrival). `delivered` has the actor by Behaviour 2 and detail `raft=<R-id>`. `merged` (**Decided with the user, 2026-11-12**) names the agent trailer of the same commit and nothing else: the agent of its Co-Authored-By values **and, for a merge commit, of its second parent's** (`sideTrailers`: the top layer commit of a `--no-ff` landing, which `./zn finish` committed with the agent's trailer); with none, the actor is `unknown`. The step is the first-parent commit that brought the document into `done/` (Behaviour 5): the binding merge commit of `./zn done`, a true merge of an older PR, or a squash.
4. **The merge (AC4).** `provenance.merge(derived, rows, worker): { Entry }` lists the derived entries and the stored rows (`source` `git` or `record`) oldest first. Derived entries order by their commits' time to the second, then the order they came in (`Entry.at`); a stored row has only its minute, so against it the minute decides, a derived entry before a stored one in the same minute. **A stored `rafted` or `delivered` row wins over the git fallback of its event only when it names the same raft** (its detail has the derived entry's `raft=` part; with no raft on the derived entry, any stored row of the event): a stored row for an earlier raft is history and the current raft's git entry stays. Every `delivered` entry, derived or stored, gets `worker=<…>` joined to its detail with `; ` when a worker is known. `provenance.workerRow(rows)` is the newest `deliver` spend row that has a model, else the newest `build` row that has one; `provenance.workerOf(row)` joins the row's host, CLI and model that exist with `/` (c0254 adds host and CLI; the model column exists today), nil with none.
5. **`./zn who <id>` (AC5).** Prints `provenance.line` of each entry: `<when>  <event>  <actor>  <detail>  (git | record)`, parts joined by two spaces, the detail left out when empty, and no other line. It takes an issue or a raft id.
   - **History**: the published mainline: `origin/main` (`HEAD` in a checkout with no `origin/main`), first-parent. A worktree's own unpublished commits are not history, and a branch's `done` commit is no merge. The item's life is `trail.read`'s (the three folders under every root, a reused number a new life, a compaction cut); the cut or ambiguity is **printed** as `capture` does, as the detail of the `idea` entry (`history before <sha> not followed: it changed <map file>`, `ambiguous: two items held this id at once`).
   - **Files**: `provenance.md` and an issue's `spend.md` are read from the working tree. A raft's `spend.md` is a roll-up of its issues (`| issue | type | …`), not a ledger, and names no worker: it is not read. A raft has no `raft:`, so no rafter; its idea is always a first add (`tracker: new raft …` names no id); its status changes, delivery and merge are derived as an issue's.
   - **Refusals** (exit 1, naming the file or id, before anything is printed): an id the tree does not hold; an id with **no history** on the mainline (an item whose document only exists in the working tree, or in a branch); a `provenance.md` that does not parse; an issue's `spend.md` that does not parse.
   - It writes nothing and runs in the main checkout (like `capture`). Existing done and backlog items need no record and no write. The usage text lists it; zz-rules lists it among the read-only commands and in the commands table.
6. **The shared reader (AC6).** `z-nile/engine/who.luau` (new; the edge): `who.want(name)`, `who.head()`, `who.life(id, head)` (`trail.read` first-parent, side trailers set, the mark; nil and why when there is no history), `who.people(head)` (one `git log`, lower-cased), `who.fronts(commits)` (**one** `git cat-file --batch` for the document changes of any number of commits, parsed with `store.parseFront`), `who.sideTrailers(life)`, `who.mark(notes, ambiguous)` and `who.entries(life, people, rows, spend, fronts, mark)`, which is `provenance.merge(provenance.select(…), rows, workerOf(workerRow(spend)))`. `cmd.who` and the board (c0284) both call them: the board parses one log over every root (`trail.parse`), builds each item's life with `trail.lifeOf` (so the id, the cut and the file filter are `read`'s), calls `who.fronts` once for all of them and `who.people` once, and prints the same entries as `who`. `store.parseFront(text)` is `readFront` over a text.
7. **Docs (AC7).** zz-rules (the commands table, the read-only list, the Provenance section) and the README name `./zn who` and what it derives; the usage text lists `who <id>`.

### The split
Pure and unit-tested: `provenance.fromTrailer`/`agentOf`/`fromCommit`/`select`/`merge`/`workerRow`/`workerOf`/`line`, `trail.parse`/`cut`/`lifeOf`. Adapter (thin): `who.luau` runs git and `main.luau`'s `cmd.who` reads the item's files and prints. The wiring is checked through the command (`who.spec`), because an unwired caller passes every pure case.

### Scalability
`who` runs a constant number of git commands: `git log --first-parent` over the item's three folders under every root (as `capture` does), `git log --format=%ae` (O(commits), 0.1 s for 1,900), one `git cat-file --batch` for the item's document commits, and one `git log -1` per merge commit in the life (a handful); the pure functions are O(commits). The board's O(items x lines) trap is c0284's (E9, moved there): this layer gives it a reader that is one process for any number of items.
### Maintainability
One reader per format: `trail` for the log (the new fields go through its `parse`; the life is `lifeOf`), `provenance.parse` for the record, `ledger.parse` for spend, `store.parseFront` for a document's frontmatter. The next event the record learns (c0282, c0283) needs no change here: a stored row prints, and a git fallback joins the table only when git can tell it.
### Usability
One line per event in a fixed shape; a refusal names the file (`who: <path>: <why>`); a derived value says `(from git)` (and `first add` when it is weaker), so a reader can tell git's word from the record's; a cut life says so.

### Edge cases
- No record, no spend: git entries only. An item that exists only in the working tree or a branch: refused, "no history".
- A reused number: only the current life, nothing of the first leaks in; a life that starts at a compaction commit is cut there, marked, and derives no rafter, delivery or status from the cut commit.
- Two agent trailers: the last. A person's trailer beside an agent's: the agent. A trailer with a person's email under another name or in other letters: a person (Eve's only commits are another item's). A trailer with no email: an agent.
- A `new` change by a `tracker: <id> new` commit that also changed the item's record: covered by the stored row; any other change to `new` prints as a status.
- `raft:` emptied by `unfold` after a rafting: no run, so none; refilled later: the later commit.
- A move between roots after the delivery, or a compaction's re-add under `done/`: no delivery.
- A `--no-ff` landing: the delivery and the merge are the merge commit (it carries the move), their actor the second parent's agent trailer; no trailer anywhere: `delivered` names the author, `merged` is `unknown`.
- A stored `rafted` row for an earlier raft and a current rafting by git: both print.
- Same-minute derived entries: by the commit's time, then the log's order; a derived entry before a stored one in that minute.
- A raft: its roll-up `spend.md` is not a ledger and is not read.
- Names with unusual characters in git (`|`): printed as they are; `who` stores nothing.

## Acceptance criteria

### Checked
- AC1: `provenance.fromTrailer` reads a `Co-Authored-By` line (any key case) as `agent:<modelId> effort unknown (from git)` and nothing else, a value whose email is a commit author's (in any letter case) is a person, a value with no email an agent; `fromCommit` gives the last agent trailer, else `human:<author> (from git)`.
