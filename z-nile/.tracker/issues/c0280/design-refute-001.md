# Refute 001: c0280 (answers to design-review-001)
Answered once, in one revision (z-design step 5: one reviewer, one round). Decisions applied: every change of the status word is a status change, a `release` give-back prints `status:<word>`, `merged` names the landing commit's agent trailer (Decided with the user, 2026-11-12), the board shows exactly `who`'s entries with one batched git process. The prototype was rebased onto main's `origin/proto-c0263-raft` (ca1dd5b3) first and rebuilt.

- F1: fixed: `statuses` are read from the document's `status:` word after each commit of the life (`who.fronts`: one `git cat-file --batch`), one entry at each change whatever the subject, with the author and agent trailer of that commit; a restamp, a `tracker: R0065 members` and the first step are none; the step that first brings the document into `done/` is the delivery; a change to `new` by a `tracker: <fdcR-id> new` commit (the item's own, or a raft's give-back of its members) is `unblocked`, covered by a record change in the same commit; any other change to `new` (a `release`) is `status:new`. Spec cases: a prep-PR-shaped squash with an agent trailer (`status:prepared`), a ready that moves the document (`status:active`), a raft give-back (`unblocked` on the member), a release (`status:new`), a restamp and a members commit (no line), a status change that also moves the document (one entry). consequences: `select`'s signature drops `state`/`raft`/`raftAt` and takes `fronts` and a `Mark` (the rafter and the folder come from the same fronts); `who.fronts` reads the document once per commit (one process); a Rules row and a mutant for each case (`restamp is a status change`, `first word is a status change`, `release give-back is an unblock`, `unblock only by the item id`, `no unblocked`).
- F2: fixed: `who.life` returns `trail.read`'s notes and `trail.ambiguous`, printed as the `idea` entry's detail (`history before <sha> not followed: it changed <map>`); in a cut life the commit that starts it gives the marked idea and nothing else, the rafter is none when its run reaches back to that commit, and a re-add under `done/` as the first step is no arrival. The delivery is the first step whose folder is `done` after a step whose folder is not, so a move between roots (done to done) is none: c0118's `doneAt` rule restated over the life in the one condition `prevArea ~= nil and prevArea ~= "done"`; it is not shared as code with `history.apply` (a 400-line state machine over a `-p` log of many items, which cannot take a life of commits), and the same shapes are pinned in both places by cases (consequence: if `doneAt`'s rule changes, this one is revisited; the c0118 specs and `who.spec` name the shapes). The mutants `delivered newest done add` and `delivered any change under done` were not equivalent alone on real history (E6 said so wrongly); the arrival rule replaced them, and `delivery without a previous area` and `a root move is a delivery` are the new rows. consequences: a `who.spec` fixture with a cut life, a compaction commit that changes the map, a delivery and a later root move.
- F3: fixed: for a raft no ledger is read (its `spend.md` is a roll-up), a raft has no rafter, its idea is a first add, its status changes, delivery and merge derive as an issue's, its stored rows print; stated in Behaviour 5 and the Edge cases; `who.spec :: a raft is answered from git and its record ...` runs `who R0020` on a done raft with a roll-up `spend.md` and a record row; mutants `who: a raft's roll-up read as a ledger` and `who: raft kind fixed to issues`. consequences: none beyond the row.
- F4: fixed: `who` reads the published mainline first-parent (`origin/main`, else `HEAD`): a merge commit then carries its diff, so the commit that brings a document into `done/` is the merge commit of a `--no-ff` landing (#296's `./zn done` binds with one), a true merge of an older PR, or a squash; a branch's own done commit is no merge and a worktree before the merge shows none. The actor: Decided with the user (2026-11-12), "The agent trailer": `merged` is the landing commit's agent trailer, and for a merge commit its second parent's (`sideTrailers`, one `git log -1` per merge), with none `unknown`; `delivered` has the same trailers and falls back to the author. consequences: `trail.Commit` gains `parents` (log tag `@P`) and `sideTrailers`; `trail.read` gains `firstParent`; cases: a `--no-ff` merge whose layer commit carries the trailer (`who.spec`, `provenance-cases`), a worktree commit `origin/main` lacks (not history), a landing with no trailer (`merged  unknown`); mutants `trail: mainline not first-parent`, `trail: parents not read`, `side trailers not read`, `second parent trailers ignored`, `merged names the author`, `head is this checkout`. c0282's hand-off sentence about a squash's trailer is stale after #296; the layer section says what it pins instead.
- F5: fixed: derived entries order by the commit's time to the second (`Entry.at`), then log order; a stored row has only its minute, so against it the minute decides, derived first. Case: a `new` between two status commits in one minute; mutant `merge derived by kind within a minute`. consequences: `Entry` gains the optional `at` (c0284 reads the four fields only).
- F6: fixed (decision 4): the reader is whole and exported: `who.fronts(commits)` is one `git cat-file --batch` for any number of commits, `trail.lifeOf(commits, id, cuts, want)` builds an item's life as `read` does (id set, cut, file filter), `who.people` once, `who.entries`; so the board prints exactly `who`'s entries and AC6 has no exception. The three differences the reviewer named (id unset, filter after the cut, a simplified log) are `lifeOf`'s and `firstParent`'s. consequences: c0284 names no exception; the mutant `trail: lifeOf leaves the id unset` is killed through `who`.
- F7: fixed: the layer section names c0136 and c0138 (R0068, active, landing first) and c0181 (R0074, prepared, after c0136) as other writers of `trail.luau` with their landing order; `trail.cut` takes only the cut commits that start the id's life (c0138's per-id narrowing is applied by `read` and the board before the call, the identity until it lands); the cut comment takes c0138's wording when the second of the two merges; Implementation step 6 runs c0138's `kept`, `renamed` and `docs` specs on the merged tree. consequences: c0138's specs cannot be run here (its change is not on main), so this is the executor's step, stated as such.
