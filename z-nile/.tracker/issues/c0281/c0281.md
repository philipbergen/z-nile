# c0281: Board round rule spy pin

## Problem
tests/tooling/board-review.spec: replace the source pin on board.luau's round-file filter with a spy on boardview.rounds that asserts every file of the raft's folders reaches it, because code reviews 002 F2 and 003 F1 of R0083 each found one more spelling of a filter (name:sub, a single-quoted pattern in a helper) that the source pin let through; check: does the mutant that filters the files before boardview.rounds, in any spelling, turn a spec red?

## Non-goals
- No change to `z-nile/engine/board.luau` or `z-nile/engine/boardview.luau`: the board already hands `boardview.rounds` every entry (R0083 fixed that); this chore changes how the rule is pinned, not the rule.
- The metrics counters in `z-nile/engine/main.luau` (the two other callers of `boardview.rounds`) and the promoted source pins on them in `tests/acceptance/c0118/metrics.spec.luau` and `view.spec.luau` stay as they are: the capture names board-review.spec and board.luau's filter only.
- The other cases of board-review.spec (F1's captions, F2's problems note) are not touched.

## Solution
Replace the F3 case of `z-nile/tests/tooling/board-review.spec.luau`, which scans board.luau's source for one spelling of a filter after another, with a case that observes the call: a spy installed on `boardview.rounds` (the module table board.luau calls through at call time, which Lune hands the spec as the same table) records each list it is given and answers with values no rule could give, and the case asserts that each raft's list holds every entry of its folder, its members' folders and the folders of the rafts retired into it, and that the raft's rounds are the spy's answer for that list. Any pre-filter, in any spelling and anywhere in board.luau, then drops an entry the spy would have seen, and any count of board.luau's own gives rounds the spy never answered. The spy is put back before the case asserts. The zz-arch lesson that told callers to "pin the caller's source for the pattern" says the spy instead.

## Design
Decisions this relies on: none from `pickman/.tracker/game-design.md` (tooling only, no player-visible behaviour). From c0118 (R0083, done) §6 and its code review 001 F3: "which of them are review rounds is `boardview.rounds`' alone" (the comment on `reviewFiles`, z-nile/engine/board.luau:757); and from R0083 code review 003 F1's Recommendation, which this chore carries out.

**Why a spy works here (E1):** board.luau requires `./boardview` once and calls `boardview.rounds(files[raft.id])` through the module table at call time (board.luau:1133). Lune caches a module by its resolved path, so the spec's `require("@znile/engine/boardview")` is the same table (R0083 code review 003's probe: `rawequal` → true; confirmed again by the prototype, whose spy sees every call). Replacing the field before `board.collect` therefore intercepts the board's call, and a board that captured the function at load time (`local roundsOf = boardview.rounds`) makes the spy see no call, which the case fails on.

**The case** (prototype in `experiments/prototype.patch`; the executor may apply it as it is). Name: `"F3: every entry of a raft's folder, its members' and its retired rafts' reaches boardview.rounds, which alone counts"`. It runs after the existing cases (the fixture they built stays) and adds, under `{TRACKER}`:
- `rafts/done/R0010/`: `review-001.md`, `review-x.md`, `notes.md`, `review-001.md.bak`, `check.sh` (beside the setup's `R0010.md`);
- `issues/done/c0011/` (R0010's member): `design-review-002.md` and a folder `acceptance/` holding one file (beside the setup's `c0011.md`, `spend.md`, `design-review-001.md`);
- `rafts/retired/R0009/` (`retired: R0010`): `R0009.md`, `review-001.md` (the same name as R0010's: both paths must reach the rule, which dedups by path), `scratch.txt`;
- `rafts/retired/R0008/` (`retired: R0009`, so the keeper chain is followed through R0009 to R0010): `R0008.md`, `design-review-001.md`;
- `rafts/active/R0020/` (a second raft, no members): `R0020.md`, `review-001.md`, so one raft's list can't absorb another's;
- a backlog raft `rafts/R0030/` (`R0030.md`, `design-review-001.md`, `notes.md`), its backlog member `issues/c0031/` (`raft: R0030`; `c0031.md`, `design-review-001.md`) and a raft retired into it, `rafts/retired/R0029/` (`retired: R0030`; `R0029.md`, `review-001.md`): the board walks the backlog, active and done folders (`scan`, board.luau:188), and a fold's keeper is usually a backlog raft, so a filter by state is a pre-filter too (design review 001 F1).

The expected list of each raft is every entry `fs.readDir` lists in its folders, as `<folder>/<name>` (the form `reviewFiles` writes), sorted: R0010 → R0010's, c0011's, R0009's and R0008's folders; R0020 → its own; R0030 → R0030's, c0031's and R0029's. The case first asserts that R0010's expected list holds `notes.md`, `acceptance`, R0009's `review-001.md` and R0008's `design-review-001.md`, and R0030's holds its `notes.md`, c0031's `design-review-001.md` and R0029's `review-001.md` (so the fixture can't go vacuous). The spy keeps each list as a sorted set: `boardview.rounds` dedups by path, so a board that hands a path twice is correct and must stay green (design review 001 F3):

```luau
local calls: { { string } } = {}
local own = boardview.rounds;
(boardview :: any).rounds = function(paths: { string }): (number, number)
	local set, copy = {}, {}
	for _, p in paths do
		if not set[p] then
			set[p] = true
			table.insert(copy, p)
		end
	end
	table.sort(copy)
	table.insert(calls, copy)
	return 1000 + #calls, 2000 + #calls
end
local ok, m = pcall(board.collect, TRACKER, nil, FACTS)
(boardview :: any).rounds = own
if not ok then
	error(m, 0)
end
```

Then `#calls >= 3` (commented: board.luau calls `boardview.rounds` through the module table when it counts; a function captured at load hides the call from the spy). For R0010, R0020 and R0030 in `m.rafts`: `k = raft.rounds.design - 1000`; `calls[k]` exists, `raft.rounds.code == 2000 + k`, and the list compares as text, `shown(raft.id, calls[k])` `toBe` `shown(raft.id, want[raft.id])`, where `shown` is the raft's id, a colon and one path per line (so a failure prints `expected <want>, got <got>` with the raft and both lists; `toEqual` would print a table address); all three rafts are seen. Last, the real rule counts R0010's list as 3 design rounds (c0011's two, R0008's one) and 2 code rounds (R0010's and R0009's) (`own(want.R0010)`), so the fixture means what it says. Every assertion is a `t.expect` (the mutation check counts a kill only from an assertion's `expected …` message).

**What goes:** the F3 source scan (`has(src, "review%-")`, the `reviewFiles` body scan, the double-quoted literal scan) and its two helpers `readSource` and `code`, which nothing else uses. `has(src, "boardview.rounds(")` goes too: the spy is a stronger proof of the call. The header's F3 line says what the case pins now. `local boardview = require("@znile/engine/boardview")` joins the requires (the watch file already names `engine/boardview.luau`).

**The restated rule:** `z-nile/skills/zz-arch/lessons/one-reader-per-format.md`'s R0083 code review 001 F3 note ends "Hand it everything, and pin the caller's source for the pattern." It becomes "Hand it everything, and pin it with a spy on the shared function that sees every input (c0281): a pin on the caller's source for the pattern let one spelling after another through (R0083 code reviews 002 F2 and 003 F1)." The zz-test lesson source-text-pins-read-the-code already says this (its R0083 code review 003 F1 note), so it is unchanged. No skill, AGENTS.md line or engine comment restates the old pin otherwise (`grep -rn "pin the caller's source\|round-file pattern" z-nile/skills z-nile/README.md z-nile/engine pickman/skills AGENTS.md`: only that lesson line).

**The acceptance** (`acceptance/mutants.luau`, run only by check.sh): copies `engine/`, `lib/`, `vendor/`, `tests/lib/`, the spec and both `.luaurc` files into `$TMPDIR/c0281-mutants.XXXXXX` (mktemp outside the repository, as zz-test lesson check-scripts-copy-trees-outside-the-repo asks of a check script; every write checked to be under that prefix; removed on every exit, an error included, through `xpcall`), and runs the copied spec through a small runner there, once unmutated and once per mutant of the copy's `board.luau`. The runner reports LOADFAIL when board.luau does not load (a mutant that does not compile kills nothing), a PASS or FAIL line per case, and whether `boardview.rounds` is the module's own function again after the cases. Each mutant is an exact text replacement of an anchor that board.luau on main holds exactly once (`reviewFiles` as it is, the raft's own call, the members' call, the retired call, the keeper `while` line, the `boardview.rounds(files[raft.id])` line, the `./boardview` require); a missing or doubled anchor fails the check rather than passing it. A rename is a count-checked replace of every occurrence (`replaceAll`, failing closed when the count moves, as `replaceOnce` does for one). A mutant is killed when it loads and some case fails with an `expected …` assertion message. Six equivalents (behaviour kept) must leave every case green: two add what the old pin forbade (an unused literal `"^review%-%d+%.md$"`, a no-op `string.match` in `reviewFiles`), three respell what a source pin would require (the call as `boardview["rounds"](files[raft.id])`, `reviewFiles` renamed `entriesOf` at its 4 occurrences, its loop written with an index), and one hands the rule the members' paths twice. That is what shows the source pin is gone in whole and in part, not merely joined by a spy (design review 001 F2): a spec that kept `has(<board.luau>, "boardview.rounds(")` beside the spy fails AC3 on the index spelling (run). It spells `require` through a variable, as the spec's HARNESS does, because the repository's require scanner reads literal require text (promote-check's architecture spec failed on it before that).

**Server authority / pure split:** not applicable (tooling spec; no game code). The spy is the spec's only seam and is restored before any assertion, inside the case that installs it.

### Scalability
The case adds 21 small files to a fixture the spec already builds and one `board.collect` (the other cases already call it four times, two through `board.build`); the spec ran 5 cases in about 3 s through `tests/run` before and after (E5). The mutation run is check.sh's alone: 23 runs of the copied spec (one base, 16 mutants, 6 equivalents) take well under a second each, and the whole `./zn check c0281` about 40 s on this host (E2); they never run in the gate.

### Maintainability
The pin no longer depends on how board.luau is written: any refactor of `reviewFiles` or the round loop that keeps the data flow stays green (AC3), and any new spelling of a filter is red without a new forbidden string (AC2). It does depend on the board calling `boardview.rounds` through the module table at call time and on `Raft.rounds` holding its answer, which is the rule itself. The anchors in `mutants.luau` are board.luau's lines on main today; open work that edits board.luau was checked against them (E6).

### Usability
A failure names the raft and prints the list the board handed the rule beside the expected one, one path per line (`expected R0010:\n…, got R0010:\n…`), so a dropped entry reads directly; a board that captured the function fails on `#calls >= 3`, whose comment says so, and a board that counts by itself fails on `calls[k] ~= nil`, whose comment says "the rounds are boardview.rounds' answer".
