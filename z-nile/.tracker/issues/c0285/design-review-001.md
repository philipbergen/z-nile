### F2 [medium] "Their documents" is undefined, and two real PRs carry a later commit that touches only the item's folder
Where: `ref-merging.md.txt` ("When no later commit of the pull request changes their documents (`git log <capture sha>..<head> -- <their documents>` prints nothing)"); the lesson's "If no later commit changes their documents".
Evidence: `gh pr view 317` lists two commits, `tracker: new c0304 Workstreams stale cases | tracker: spend c0304 capture`. Open #387 lists three: `tracker: new c0352 … | Merge commit 'a289ab1c…' into capture-… | tracker: spend c0352 capture`. A spend commit writes `spend.md` in the item's folder. A merger who reads "their documents" as the item's files takes the second branch for both PRs, which is a needless split today and a needless merge commit after F1. A merger who reads it as `<id>.md` squashes them. `./zn capture` prints only the item document (`trail.isDoc` excludes `spend.md`, `harvest.md`, `prompt.md` and `trace.md`), so only that file decides whether a squash would show `./zn capture` the wrong text.
Critique: the promoted spec pins the sentence verbatim, so a later definition needs an override. #387 meets the ambiguity at its merge.
Consequences: with the definition, a later commit that touches only `spend.md` or the idea-review files leaves the squash branch, which is right. A sync merge of `origin/main` into the branch shows up in `git log <capture sha>..<head> -- <doc>` only when main changed that document, and then the second branch is right anyway.
Recommendation: define the term once in the paragraph and once in the lesson: "their documents: the item documents the capture commit changed (`git show --name-only --format= <capture sha>`, not `spend.md`, reviews or other files), the text `./zn capture` prints". Give #317 and #387 as the example (a spend commit after the capture: squash with the subject). Pin the definition phrase in `merging-docs` and add a mutant row that drops it.
