# c0288: C0260 spec stall limit holds under load

## Problem
c0260's sequestered spec z-nile/.tracker/issues/c0260/acceptance/dispatch.spec.luau sets stall_seconds = 5 in its fixture's models config, the same short limit that made c0117/dispatch-cli.spec.luau fail under load until c0279 (R0089, merged 2026-11-09) raised it to 120 s: on a loaded machine (load 47 to 97 on 18 cores) a fake step that is quiet while it works is killed as stalled. c0260 is prepared (#257), so the spec would be promoted as is when its raft runs. Found by R0089's code reviewer. What should happen: c0260's dispatch spec stays green on a loaded machine; only a case that tests the stall itself keeps a short limit, as c0279 did for c0040.

## Non-goals
- No engine change: the runner's stall detection (`z-nile/engine/runner.luau`), the `[dispatch]` defaults (`models.STALL_SECONDS = 300`, `TOOL_SECONDS = 900`) and the root `.models.toml` are untouched. The fixtures' limits are wrong, not the code they test.
- No change to c0260's design, code, `check.sh` or documents, and no edit of c0260's specs beyond their limit lines (AC2).
- Other items' fixtures with short limits are their own items' and are not changed here. `grep -rn "stall_seconds = " */.tracker --include='*.luau'` over unfinished items (origin/main, 2026-11-15) finds: c0256's six acceptance specs and c0282's `dispatch.spec.luau` at 3 s, c0250's `dispatch-block.spec.luau` and c0262's `dispatch.spec.luau` at 30 s, and two one-time proofs, `active/c0275/proofs/dispatch.spec.luau` (10 s) and `active/c0277/proofs/discard.spec.luau` (20 s). The prep PR's body lists them for the user, and the new lesson `zz-test/fixture-stall-limit-only-a-stuck-step-reaches` asks every future fixture the question.
- No load-simulation knob added to c0260's stubs (c0279's `FAKE_DELAY`): the proof that the limit holds under load is prep's experiment E2, run once on c0260's prototype (the user's rule: real-work proofs are one-time and never promoted).

## Solution
(captured idea: c0260's dispatch spec stays green on a loaded machine; only a case that tests the stall itself keeps a short limit, as c0279 did for c0040.)

Since the capture, c0260's re-prep (#336, 2026-11-14) removed `dispatch.spec.luau` (the idea review run through `./zn dispatch zz-review --mode idea`, `stall_seconds = 5`) and moved the idea review into `./zn idea`, whose model calls run through the same runner (`engine/modelstep.luau` → `engine/runner.luau`) under the same `[dispatch] stall_seconds` from the fixture's `.models.toml`. Its successors are the three specs that start model stubs, and they set `stall_seconds = 30`: `loop.spec.luau` (twice: `ROLES` and `WITH_FALLBACKS`), `record.spec.luau` and `provenance.spec.luau` (once each). 30 s is the same bet at longer odds: the runner charges every tick it is starved to the step as silence (`quiet += dt`, c0279 E1b), and E2 shows a stub silent for 35 s fails every case at 30 s. No c0260 case tests a stall (`grep -n -i "stall\|no output"` over its specs finds only the four limit lines), so every limit becomes at least 120 s, c0279's limit "only a real stall reaches", and no case keeps a short one.

**Route (design review 001 F1 to F4; the user's ruling is asked under Open to the human, F1).** A raft may not change another item's sequestered specs (zz-execute Phase 3 step 4: the sequestration diff lists only `R100` renames, repository-wide), and the user sent c0260 back to z-design on 2026-11-15 (R0093). So the four lines belong in c0260's redesign, whose own prep PR may change its own sequestered files and whose own approval and coherence review cover them. c0288 is the check that it happened and the backstop if it did not: it `depends_on: [c0260]`, so it runs once c0260 is done, and its raft verifies AC1 on the promoted specs; only if the redesign left a short limit does its layer change the promoted copies (`tests/acceptance/c0260/`), a chore's override of promoted specs in its own raft, with no exception to any rule. AC2 then pins the shape of that change (limit lines only), not today's blobs, which the redesign moves.

**Change** (only if AC1 is red once c0260 is done; `z-nile/tests/acceptance/c0260/`): every `stall_seconds = <n>` or `tool_seconds = <n>` line in a c0260 spec with n < 120 that is not marked `# tests a stall` becomes `<name> = 120`. On today's specs that is `sed -i '' 's/^stall_seconds = 30$/stall_seconds = 120/' loop.spec.luau record.spec.luau provenance.spec.luau` (loop lines 21 and 45, record 16, provenance 16). The marker is the one way a case that tests a stall keeps a short limit, as the capture allows; only c0260's own design may write it (AC2 refuses an added one). A TOML comment after the value parses (E6).

**Why 120 s and not the default.** Dropping the line would give the default 300 s, which also holds, and AC1 and AC2 accept it; 120 s is the value c0279 set for c0117's dispatch spec and c0248's and c0306's dispatch specs already use, so one fixture convention holds across the tooling's specs, and a stub that hangs costs a run 120 s, not 300 s. `tool_seconds` is not set by these fixtures and stays the default 900 s (no stub makes a tool call).

### Scalability
No cost in a green run: the stubs print at once (one call sleeps 2 s, the beat case), so no case waits for the limit; the runs took about the same at both limits (loop 79 s at 30 s and 69 s at 120 s, record 37 s at both; E1, E3). A stub that hangs now costs up to 120 s per call before it fails instead of 30 s: the price of a bound load cannot reach.
### Maintainability
One rule for the next fixture, in the new zz-test lesson: a fixture's stall limit is 120 s; only a case that tests a stall gets a short limit, marked, and a stub silent well past it (c0279's c0040). AC1 fails closed on any limit it cannot read (a limit inside a Luau string, M5), so a short limit in any c0260 spec, in any form, is red at c0288's check. The floor is passed from `check.sh` (F5): a later change to it changes the approved contract.
### Usability
A failure reads as the runner's own message (`idea: no output for 120 s`, stalled); AC1 prints each short or unreadable limit by file and line, and AC2 each change that is not a limit line.
