### F1 [high] Every skill still tells the lead not to write a new file for a note, so the capture's outcome depends on agents ignoring the instruction they read
Where: Design, `z-nile/skills/zz-rules/SKILL.md (Items)`, the paragraph after the bullet ("The shared `## Lessons` paragraph of every skill … stays as it is"); Checklist, Restated rules; AC4.

The Design keeps this sentence because it "does not say where a note goes" and the Restated-rules entry says it contradicts nothing. But once a note is a file, the sentence says the opposite of the new rule: when a lesson fits, do not write a new file. That points to the old habit, appending to `<slug>.md`. The habit is strong. 42 lessons on main carry appended notes (`grep -rlE '^\*\*Also:\*\*|^Note \(|^\*\*Note\*\* \(' z-nile/skills/*/lessons */skills/*/lessons | sort -u | wc -l`; the Non-goal says 28). `z-design/restated-rules-move-together.md` alone changed in 8 commits on main since 2026-11-09. AC4 and `notes-docs.spec` read only zz-rules Items, so they pass while all 25 copies of the instruction keep the conflicts coming. The stated cost of fixing it is also overstated. The Design says c0136 and c0181 both rewrite that paragraph, so an edit here would add 25 conflicts. But c0136 inserts its paragraph *before* the role bullets and says "The role bullets are unchanged, so the c0111 pins hold" (`active/c0136/c0136.md:106`). Its `docs.spec` pins only its own line (`acceptance/docs.spec.luau:91-104`). `c0111/skill-docs.spec` pins substrings that this sentence is not part of, plus "identical in every skill". An edit of the lead bullet's last sentence meets neither of them.
Critique: the capture asks that "two branches that each append notes to one lesson merge cleanly". The design achieves that only for notes written as files. The one sentence every lead reads at the moment it adds a note now steers it back to appending. This is the restated-rule defect: the rule moved, and a restatement that now contradicts it stays. The tempting fix is to mention notes in z-design 5.3 only. But the paragraph in all 25 skills would still say "writes a new file only when none does".
Consequences: the fix touches 25 `SKILL.md` files (one script, one text, as c0136 does for its lead-in). Touched modules gains them. Skill paths select no specs. `c0111/skill-docs.spec` still passes: the paragraphs stay identical, and its pinned substrings ("writes it in `<skills folder>/…/lessons/<slug>.md`", "as `- note <what happened>: <lesson ids>`") are untouched. c0136 does not conflict: its paragraph sits before `- **A subagent**`, not next to the lead bullet. c0181 adds a bullet to the same paragraph (`c0181/c0181.md:137`). If that bullet goes directly after the lead bullet, each file has a one-time conflict, resolved by keeping both, and Existing work must say so.
Recommendation: rewrite the lead bullet's last sentence identically in every skill, for example: "It adds a note to an existing lesson when one fits (a file of its own in the lesson's notes folder, never a paragraph at the end of its file: zz-rules skill, Items), writes a new lesson only when none does, and commits both with its work." Add a `notes-docs.spec` case that walks every skill folder through `skills.folders(projects.load(TOP))`, as c0111's spec does. It asserts that each `## Lessons` section contains the new sentence and no longer contains "writes a new file only when none does". Add a Rules-and-mutants row: "one skill keeps the old sentence" is killed by the case. Widen AC4 and its `check.sh` label to "and every skill's Lessons paragraph says a note is a file in the lesson's notes folder". Rewrite the Design paragraph that keeps the old sentence, and the Restated-rules entry. In Existing work, name c0181's bullet and its one-time resolution.

### F2 [medium] The prep gate's new allowance accepts any `*.md` in a notes folder, including names the format refuses and instruction files
Where: Design, `z-nile/engine/dispatch.luau`; Checklist, Guards; AC3; `prototype.patch` (`^[^/]+/skills/[^/]+/lessons/[^/]+/[^/]+%.md$`).
Evidence: with the designed pattern, `dispatch.isLesson` returns true for `z-nile/skills/zz-rules/lessons/a-lesson/also.md`, `…/lessons/a-lesson/CLAUDE.md`, `…/lessons/a-lesson/AGENTS.md` and `…/lessons/Not-A-Slug/x.md`. `lessons.check` refuses every one of them (`not a note file …`, `notes with no lesson …`). Nothing between a prep PR and main runs `lessons --check`. The prep gate (`dispatcher.judgePr`, dispatcher.luau:1280-1287 and 1514) consults only `isLesson`. `trackerstate.check`'s `CONFIG` list is `.gitattributes`, `.gitmodules`, `.models.toml` (trackerstate.luau:53). `z-nile/check.sh` and the gate never run `./zn lessons --check` (grep finds no caller), and a skill path selects no spec. So a dispatched prep that writes a misnamed note lands green. From then on, every prep's harvest step (z-design 5.3: "Then run `./zn lessons --check`") fails on main's state until someone repairs it. A `CLAUDE.md` in a notes folder is also loaded by Claude Code as instructions whenever a session reads a file in that folder. Today's one-level pattern already admits `lessons/CLAUDE.md`, so this hole exists now. The design spreads it to one new folder per lesson (405 today).
Critique: the guard is wider than the format it guards. Two rules for "is this a note file" now disagree: the gate's pattern and `noteName` with `check`. The tempting fix is to call `lessons.noteName` from `dispatch.luau`. But that gives dispatch a new `require` of a module that reads the filesystem, and the Design promises no new requires.

That fails closed, and its own harvest `--check` will have named the real problem first. The c0115 override's scan (which calls `isLesson`) then skips misnamed notes, which `--check` refuses anyway. Day-range validity (month 13) stays `check`'s job. The pattern checks the shape only.
Recommendation: make the note level `^[^/]+/skills/[^/]+/lessons/[a-z0-9][a-z0-9%-]*/%d%d%d%d%-%d%d%-%d%d%-[a-z0-9][a-z0-9%-]*%.md$`, the shape of `noteName`, with no require. Add AC3 cases for `…/lessons/a-lesson/CLAUDE.md`, `…/lessons/a-lesson/also.md` and `…/lessons/Upper/2026-11-09-a.md`, each refused. Add a row: the mutant "the prototype's `[^/]+%.md` note level" is killed by them. Optionally narrow the lesson level to `[a-z0-9][a-z0-9%-]*%.md` too (it closes `lessons/CLAUDE.md`; every lesson slug on main is kebab, because `parse` refuses others). If you take it, add a case for it.
