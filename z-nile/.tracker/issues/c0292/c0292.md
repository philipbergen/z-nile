# c0292: Lesson prep specs pass format and lint

## Problem
z-design: a prep's sequestered specs and check.sh scripts pass the gate's format and lint steps (stylua --check, selene) before the prep commit, because the full gate lints every .luau in the issue folder: c0261's prep PR #259 reached its merge gate on 2026-11-09 with all 12 acceptance specs unformatted, invalid '\{' escapes in plain strings and an unused require, and the merge gate failed at format and lint; check: did 'stylua --check' and 'selene' run clean over the issue's folder (acceptance/, experiments/) on the prep commit?

## Non-goals
- A tool that enforces the rule (a `./zn status <id> prepared` refusal, or `promote-check` or the dispatcher's prep gate running the two stages). The capture asks for the lesson; such a check is a new rule for every prep in flight (E3 found three open prep branches it would refuse today) and is its own captured issue: **c0359** (`Prep gate merges unlinted folders`, captured by this prep on 2026-11-15 after design review 001 F1; its idea challenge, design and priority are the user's). c0181 (R0074) is where lessons gain enforcing refs (AC9 covers the order where it lands first).
- Fixing the three open prep branches that fail the stages today (c0230's #397, c0301's #399, f0339's #408; E3): they are other leads' branches. This prep names them in c0359 and in its result, because the dispatcher's prep gate would merge them as they stand (Existing work).
- A lint for `check.sh` scripts. The gate has none (no shellcheck stage), and stylua and selene read only `.luau`, so a `check.sh` passes the two stages as it stands (E2); the lesson says so.

## Solution
One new, short lesson, `z-design/prep-specs-pass-format-and-lint` (`when: design`), whose `check` is the captured question word for word, plus one sentence in z-design step 4 (before the mutation check and the review, so the review reads linted specs) and one in step 6 (the step that makes the prep commit), each giving the command, because a rule the gate enforces on a step is written in that step's skill (lesson `z-design/rules-on-a-step-live-in-its-skill`). A `harvest.md` note makes the capture its source. `check.sh` pins the lesson's words, the step-6 sentence, the mechanisms the lesson describes, and runs the two stages over this issue's own folder.

## Design
The captured outcome is the lesson; there is no code. The design work is to say exactly what the gate reads and what it fails on, and why nothing earlier in a prep catches it, each proved (E1, E2), and to put the command where the prep reads it.

### Decisions
1. **A new lesson under z-design, not a note on an existing one.** The capture opens "z-design:" and its moment is the prep commit. The two nearest lessons are different rules: `zz-test/format-tracker-specs-by-path` (`when: both`) is *how* to run stylua (by the folder's path, because `stylua .` skips dot-folders) and says nothing of selene, experiments or the prep commit; `z-design/rerun-skipped-checks-after-edits` is the general "rerun what the runner skips after each edit", whose c0118 note even suggests `./zn promote-check` as the alternative, which runs neither stage. The new lesson names the first and does not restate it. Neither existing lesson changes.
2. **What the gate reads and fails on (E1, E2, read from `z-nile/check.sh`).** The full gate's static stages are `stylua --check "${LUAU_DIRS[@]}"` and `selene --quiet "${LUAU_DIRS[@]}"` from the repository root, and `z-nile/roots --luau-dirs` lists every project root's `.tracker` by name (stylua skips hidden folders). So every `.luau` under an issue folder, `acceptance/` and `experiments/` alike, is read. **selene exits 1 on a warning alone** (E2b: one `shadowing` warning, which `selene.toml` sets to `warn`), and stylua itself rewrites `"\{"` to `"{"`, so both of the incident's escape problems fail. The stages read no `.sh`, `.md` or `.luau.txt` (E2a), so a `check.sh` or a reference text passes as it stands. **What refuses a failing folder, by merge path (design review 001 F1).** A person's merge runs the gate first (an `--affected` run on a prep branch picks z-nile's static stages: `sel.staticProjects` names a tracker path's project), and that is where the incident was stopped. The dispatcher's prep and raft gates do not: with `auto_merge = ["prep", "raft"]` (`.models.toml`), `dispatch.luau`'s `gate()` merges a PR that is not a draft, is green, mergeable and passes the tracker-state judgement, and `dispatcher.parsePr` reads green from `statusCheckRollup` alone, whose one check (`.github/workflows/deploy.yml`) runs no gate. So a dispatched prep whose folder fails lands on `main`, and every later gate that reads `z-nile/.tracker` (each z-nile `./zn land`, `done`, the watch net, the next `--full`) goes red on another item's files. The lesson says so, and c0359 is the captured fix.
3. **Why nothing earlier catches it.** `tests/run` runs specs; `./zn check` runs `check.sh`; `./zn promote-check` runs `luau-lsp analyze` and the architecture meta spec (`promotedChecks`, `z-nile/engine/main.luau`). No engine module and not `tests/run.luau` names stylua or selene (AC6 pins that, so the lesson's claim is rechecked at `./zn check` and `done`). The Claude Code edit hook (`scripts/hooks/post-edit.sh`, wired in `.claude/settings.json` to PostToolUse `Edit|Write|MultiEdit`) formats and lints a `.luau` only when that editor tool wrote it (it reads the tool's `file_path`): a file a shell command, a copy (`cp` of a reference text), a merge or a subagent's shell wrote is never seen. No other CLI runs it, and the design role falls back to kimi, grok and agent (`.models.toml` `[roles.design]`), so a prep that falls back runs no hook at all (design review 001 F6). That is the gap the incident fell through.
4. **The command, from the repository root**: `d=$(./zn find <id>); stylua "$d"; stylua --check "$d" && selene --quiet "$d"`, until both exit 0, after writing the specs (before the mutation check and the review, so a selene finding such as an unused local, often a value a case computes and never asserts, is fixed where the review reads it: design review 001 F3), right before the prep commit, and again after any later change to a `.luau` in the folder (a refute round, a merge of `origin/main`). From the root, `./zn find` prints the repository-relative folder (`z-nile/.tracker/issues/c0292`) and the root's `stylua.toml` and `selene.toml` are the gate's (the homes' copies are identical today). Formatting first, then checking, follows zz-test's lesson (stylua's wrapping is not always idempotent: run the check again).
5. **Two sentences in z-design.** In step 4, a new bullet right before **Mutation check** (text: `experiments/ref-skill-step4.txt`): "- **Format and lint the folder** before the mutation check and the review: `d=$(./zn find <id>); stylua "$d"; stylua --check "$d" && selene --quiet "$d"` from the repository root, until both exit 0 (step 6 runs it again on the committed bytes; lesson z-design/prep-specs-pass-format-and-lint)." In step 6, a new first sub-bullet under **Commit**, before "Ask the user before merging…" (text: `experiments/ref-skill-step6.txt`): "Before the prep commit, run the gate's format and lint stages over the issue's folder from the repository root, `d=$(./zn find <id>); stylua "$d"; stylua --check "$d" && selene --quiet "$d"`, until both exit 0, and again after any later change to a `.luau` there: the full gate reads every `.luau` in it, and nothing earlier in a prep does (lesson z-design/prep-specs-pass-format-and-lint)." Step 6 is where the commit is made, after step 5's last spec edits, so the check runs on the bytes that are committed. No promoted spec pins step 4's Mutation check bullet or step 6's Commit bullet (grep for its phrases over `z-nile/tests`), and the specs that read z-design's text pass with the sentence in (E4).
6. **Short.** 11 lines, a body of 1,185 bytes (round 1's three additions, F1, F3 and F6, cost 152 bytes; the Why's fix-commit clause was cut to stay under the cap).
