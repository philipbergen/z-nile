# c0299: Approve finds the worktree

## Problem
- `./zn approve <id>` today works only when run inside the worktree whose checkout has the design, so each approval needs the person to cd into a prep worktree whose path an agent has to hand them (c0261's re-approval on 2026-11-12 waited on `.worktree/prep-c0261-redesign`).
- z-nile has no rule for which worktree an approval belongs to: `cmd.approve` reads the item in the current checkout and requires only `design: ready`, which is true in every worktree branched from main after the prep landed.

## Non-goals
- The refusals without a terminal on stdin and while `ZN_DISPATCH` is set do not change.
- What an approval records (the contract hash, the `approval.md` row, the commit of only that file) does not change.
- `./zn approve <id> --check` and `./zn approve <id> --publish` keep today's behaviour and still act on the current checkout.
- No approval is ever recorded in the main checkout.

## Solution
- A worktree is a "candidate" for an issue when it is a linked worktree under `.worktree/`, the issue is `design: ready` in its checkout, and `./zn approve <id> --check` run there does not pass (no approval row, or the latest row no longer matches the contract).
- `./zn approve <id>`, run from the main checkout or any worktree, records the approval in the one candidate worktree for that issue exactly as if run there, and prints that worktree's path.
- `./zn approve <id>` refuses when no worktree is a candidate for the issue, and when more than one is it refuses and names each candidate.
- `./zn approve <worktree>`, where the argument is a name under `.worktree/` (for example `prep-c0261-redesign`) or a worktree's path, run from the main checkout or any worktree, approves the one issue that worktree is a candidate for and prints that issue's id.
- `./zn approve <worktree>` refuses when the named worktree is a candidate for no issue, and when it is a candidate for more than one it refuses and names each issue.
- A re-approval after a contract change made in one prep worktree is found by `./zn approve <id>` with no refusal, because every other worktree still holds main's matching approval row and so is not a candidate.
- The zz-rules approve row states the candidate test and both argument forms.
