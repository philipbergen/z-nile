# c0301: Trace none claims and tests only tickets

## Problem
- `deriveClaims` (`z-nile/engine/trace.luau:367`) derives a claim from the "None." under a ticket's `### Judged` or `### Observed`, as R0093's trace shows with `c0256:AC9: None.`, `c0256:AC10: None.`, `d0296:AC3: None.` and `d0296:AC4: None.`.
- A "None." claim's row passes `./zn trace <R-id> --check` only by citing lines that do not support it: the "None." line itself as design, any green check line as test, and any changed source line as code.
- The code cell is checked only against the whole stack's changed sources (`z-nile/engine/trace.luau:1126`), never against which ticket changed the file.
- When the stack changed any source file, the check refuses `none` and refuses a spec path as a code cell, so a tests-only ticket's claims (R0093's d0296, three `.spec.luau` fixes) pass only by citing a source line another ticket changed.
- No raft has landed through trace yet (found by R0093 code review 001 F3 on 2026-11-12).

## Non-goals
- The check does not judge whether a cited line actually supports its claim; that stays with the reviewer.
- Code cells of source-changing tickets are not checked against which ticket changed the cited source file.
- The design and test cell rules, and the rule that `none` is valid only when the stack changed no source file, do not change.
- R0093's own `trace.md` is not rewritten by this ticket.
- (Added in prep) A `### Judged` or `### Observed` body that says "None" with more text (a reason, or a pointer to another item's playtest, such as "None. The Beta play-through is f0026 OC1.") is still a claim: the capture names only a whole body of "None.".
- (Added in prep) A ticket whose layer changed neither a source file nor a spec file (skills or documents only) keeps today's code-cell rule.
- (Added in prep) R0100's and R0101's `trace.md` (active and filled, with "None." rows) are not rewritten by this ticket either; Existing work, in the Design, says what happens to them.

## Solution
- A `### Judged` or `### Observed` subsection whose whole body is "None." derives no claim from `deriveClaims`, and the check reports no missing claim for it.
- A claim of a ticket whose stack changes are all spec files passes the check with a code cell citing a spec file that is in that ticket's Touched modules and that the stack changed.
- A tests-only ticket's claim whose code cell cites a source file fails the check with a finding naming the row.
- A claim of a ticket that changed a source file still fails the check when its code cell cites a spec file.
- `./zn trace <R-id> --check` passes for a stack that pairs a source-changing ticket with a tests-only ticket and has "None." subsections, with every code cell citing only files its own ticket changed.

## Design
Two rules change in `z-nile/engine/trace.luau`, the pure module behind `./zn trace`, and one adapter line in `traceProblems` (`z-nile/engine/main.luau`) feeds the second. Both rules are pure: texts and layer records in, claims and findings out. Nothing here touches a game, so no player behaviour changes (`pickman-arch` does not apply); the tooling rules are zz-arch's.

**Rule 1: an empty Judged or Observed derives no claim.**
- `collectOutcomes(body, keepPrepLines): { Outcome }` (local) is today's `extractOutcomes` loop, unchanged in what it reads, that also records for each outcome the `###` heading it sits under (lowercased, the `#`s and spaces dropped, `""` before the first) and that heading's position in the body (`group`). `extractOutcomes` becomes the texts of `collectOutcomes`, so every reader of Problem and Solution reads exactly what it reads today.
- `trace.isNone(text: string): boolean`: the text, lowercased and trimmed, with one pair of surrounding parentheses and one trailing period dropped, is `none`. So "None.", "None", "none.", "NONE" and "(none)" are empty, and "None. The playtest is f0029 OC1." or "None: no runtime change." are not.
- `trace.acItems(body: string?): { { text: string, index: number } }`: every outcome of `## Acceptance criteria` with its position among all of them (1..N, as today), except an outcome that is the only one under its `###` heading, whose heading is exactly `judged` or `observed`, and whose text `isNone`. That outcome is dropped and keeps its position: the next criterion's number does not move. R0093's trace showed `c0256:AC9: None.` and `c0256:AC10: None.` when c0256 had eight criteria; it has thirteen now, its two "None." are items 14 and 15, and after the change its claims are AC1 to AC13 and nothing else, and a ticket whose Judged is "None." and whose Observed has `OC1` keeps `OC1` at the number it has today.
  - Why keep the number: `trace.parse` keys a row by its claim id alone (`parseClaimId`), not its text. Renumbering would let an old table's `AC9: None.` row stand for a different criterion that slid into AC9, and the check would accept its cells. Keeping the number turns every old "None." row into `unknown claim`, which the check already reports.
- `deriveClaims` takes its AC items from `acItems` (the explicit `AC<N>` rule and the duplicate fallback are unchanged, with `i` the item's kept position). A ticket whose only criteria are empty Judged and Observed subsections has no AC item and is refused as today: `ticket <id> is missing ## Acceptance criteria`.
- `trace.extractAcs(body)` becomes the texts of `acItems`, so `tests/lib/seal.luau`'s `ensureSections` (its only other caller) decides "this fixture needs an AC1" from the same reading the claims use.
- The check: with no claim derived, `trace.check`'s "missing claim" loop has nothing to report for the "None.", and a row that still names it is `row <id>:AC<n>, claim: unknown claim <id>:AC<n>` (the existing finding). `./zn trace <R-id>` prints no row for it, since the skeleton lists `deriveClaims`.

**Rule 2: a tests-only ticket cites its spec files.**
- `trace.layerFiles(layers: { LayerHistory }?): { [string]: { [string]: boolean } }`: each ticket's layer files, the files of every commit of its layer (`LayerCommit.files`, which `traceProblems` already reads with `git diff-tree` for the stale rule).
- `trace.isSpecFile(path: string): boolean`: a `*.spec.luau` outside a `.tracker/` folder. A sequestered acceptance spec (`<root>/issues/<id>/acceptance/*.spec.luau`) is the ticket's contract, not its change: a layer that only adds or deletes one is no tests-only ticket, and no code cell cites one as a spec file. (The prototype's first cut counted them, and `c0008/done-order.spec.luau` turned red: its f0010 layer only deletes its own sequestered spec, E3.)
- `trace.testsOnly(layers: { LayerHistory }?): { [string]: boolean }`: a ticket is tests-only when its layer files include at least one spec file (`isSpecFile`) and no source file. "Source file" is `watch.isSource` (`z-nile/lib/watch.luau`), the same test that builds `changedSources`: tracker files, `.md`, skills, lessons and watch files are neither, and a helper under `tests/` (`tests/lib/*.luau`) is a source file, so a ticket that changed one is not tests-only. With no layers (`input.layers == nil`, the pure callers that pass `finishedIssues` instead) no ticket is tests-only, which is today's rule: the safe direction.
- `CheckInput.changedFiles: { string }?` (new): every path the stack changed. `traceProblems` passes `diffList`, the `git diff --name-only <main tip> <top tip>` it already computes and filters into `changedSources`, plus every spec file in `deleted` (below). nil means no spec file counts as changed.
- `CheckInput.filesAtBase: { [string]: FileMeta }?` (new, design review 001 F1): every spec file the stack deleted, as it was at the stack's base. `traceProblems` lists them with `git diff --name-only --no-renames --diff-filter=D <main tip> <top tip>` (its own list: `diffList` pairs a deleted file with a similar added one as a rename and names only the new path, which the prototype's `land.spec` showed, E3) and reads each `isSpecFile` path with `git show <main tip>:<path>`. A path that list names always exists at the base. nil means no deleted spec can be cited.
- Touched modules: `raftplan.touchedModules(text: string): { string }?` (new, in `z-nile/engine/raftplan.luau`, beside `raftplan.overlaps`) is the text half of today's `touchedModules` in `main.luau`, moved without change: the backticked path at the head of each bullet under `### Touched modules`, trailing slashes dropped, nil when there is none. `main.luau`'s `touchedModules(item)` becomes `raftplan.touchedModules(fs.readFile(item.doc))`, so z-raft's plan, the workstreams and the trace read the section with one function. Two other readers stay as they are (design review 001 F3): `spend.ownedPaths` (`z-nile/engine/spend.luau`) reads it wider for spend attribution (any heading level, every backticked path with a `/`, comments stripped), and the prepared c0141 adds `checkpaths.owned` in c0120's promoted test library, which reads a document's entries by one home convention. Unifying the three is not this ticket's capture. The trace reads the section from `issue.docText`, the ticket's document at the top layer's commit (not the capture, which predates the Design).
- An entry is matched as written (from the repository's top) or under the ticket's home (design review 001 F2): pickman's and the games' documents mostly write `tests/unit/Maze` for `pickman/tests/unit/Maze`, as the template's own example does. `inTouched(path, touched, home)` is true when `path` equals or is under, by whole components, the entry or `<home>/<entry>`; the root's home (`.`) adds nothing. `issue.home` is already in `IssueDoc`. A z-nile entry starts with `z-nile/`, so its joined form never exists; and neither form can match another home's path, since both are compared by whole components.
- The code cell of a claim of a tests-only ticket, when it is not `none`: each `file:line` must exist at the commit (as today), or, for a path absent at the commit that `filesAtBase` holds, at the stack's base; be a spec file (`isSpecFile`); be in `changedFiles`; and either be one of the ticket's own layer files or be in its Touched modules (`inTouched`). The findings, in that order, each naming the row:
  - `row <cid>, code: <path>:<n> does not exist at commit` (today's), or `row <cid>, code: <path>:<n> does not exist at the stack's base (the stack deleted it)` for a deleted spec's missing line
  - `row <cid>, code: ticket <id> changed no source file; <path> is not a spec file it touched`
  - `row <cid>, code: <path> was not changed by this stack`
  - `row <cid>, code: <path> is neither changed by ticket <id>'s layer nor in its Touched modules`
  - Captured S2 says "a spec file that is in that ticket's Touched modules and that the stack changed", so a spec file another layer changed and this ticket names in its Touched modules passes. S5's "every code cell citing only files its own ticket changed" is the own-layer half, and a spec the ticket's own layer changed passes even when its Touched modules do not name it: the layer is the record of what the ticket changed, and a ticket's Touched modules may name a folder or nothing (most fixture tickets, see Existing work). Neither half lets a tests-only ticket cite a source file (S3) or a spec another layer changed that its Touched modules do not name.
  - A layer that only deletes spec files is tests-only (design review 001 F1): an Overrides chore that removes a promoted spec is one. It cites the deleted spec at a line the file had on `main`, which is "a spec file that the stack changed" in S2's words. The base text is read only for a path absent at the commit, so a spec that still exists is always checked at the commit. A spec that a lower layer added and this layer deleted is in neither the stack's diff nor `deleted`, so it gets `was not changed by this stack`: S2 promises only a spec the stack changed.
- `none` keeps its rule for every ticket (Non-goals): valid only when the stack changed no source file. So in a stack that changed no source file a tests-only ticket may write `none` or cite its spec file, and in a stack that changed one its `none` is refused with today's message.
- Every other ticket's code cell keeps today's rule, with one clearer message: a spec-file reference (`isSpecFile`), which today reads `<path> was not changed by this stack` even when the stack changed it, now reads `row <cid>, code: <path> is a spec file, not a source file this stack changed`, whether the spec still exists or the stack deleted it (the spec-file test comes before the existence test in this branch). It still fails (captured S4).
- Order of the branches in the code-cell check: empty cell; tests-only and not `none` (rule 2); the stack changed no source file (today: `none` expected); `none` in a stack that changed a source file (today: refused); references (today, plus the spec-file message).

**Restated rules.** The rules are written in three places besides the code, and each moves with it: the `trace` row of the zz-rules command table (`z-nile/skills/zz-rules/SKILL.md`), the final-mode trace bullet of `z-nile/skills/zz-review/SKILL.md`, and the contract comment at the head of `trace.luau` (items 2 and 4). The new wording is pinned by AC4.

### Scalability
- `testsOnly` walks each layer's commit file lists once (the lists the stale rule already holds), and the code cell reads a ticket's Touched modules once per row; a raft of tens of tickets and hundreds of rows costs microseconds. No new git call: `diffList` is already computed.
- A new claim kind or a new subsection rule goes in `acItems`, the one place the AC section is read.

### Maintainability
- One reader per format where this ticket reads one: AC items (`acItems`, used by `deriveClaims` and `extractAcs`), Touched modules for the plan, the workstreams and the trace (`raftplan.touchedModules`; spend's wider reader and c0141's convention reader stay, Rule 2), spec files (`trace.isSpecFile`, used by the trace and `seal.trace`), source files (`watch.isSource`).
- `trace.luau` stays pure: it requires `./raftplan` and `../lib/watch`, both pure (texts in, texts out), and no `@lune` module itself (`raftplan` loads `@lune/serde` for its design hash, a pure function). z-nile keeps no architecture map with a `deps` block, so no map changes; the two edges are pure module to pure module.
- The Python port's contract (the comment at the head of `trace.luau`) states both rules.

### Usability
- A lead fills fewer rows: no row for an empty Judged or Observed, and a tests-only ticket cites the spec it fixed instead of borrowing another ticket's source line.
- Each finding names the row, the cell, the path and what would pass ("not a spec file it touched", "neither changed by ticket <id>'s layer nor in its Touched modules", "a spec file, not a source file", "does not exist at the stack's base (the stack deleted it)"), so the fix is in the message.
