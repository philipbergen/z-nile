# c0305: Dispatcher waits on cheap model

## Problem
Carried from c0261 (Model tiers), which the user retired on 2026-11-12 ("Retire, file leftovers": #299, the roles table, already names a real model for every stage, so c0261 was closed and what main still lacks was filed as new tickets). c0261 was designed on the pre-#299 .models.toml; its prototype proto-c0261 (be21970f, base 10dd3c85) is a reference only. What should happen: the dispatcher no longer stops at a prep or rafting gate just to wait. When that gate's PR has only its checks, or GitHub's merge computation, left to wait for, a bounded wait step polls it on the cheapest model of the CLI (a wait role in .models.toml; c0261 proposed claude-haiku-5-5, grok-4.5 at low and composer-2.5) and the gate merges once it is green and mergeable; a draft, a conflict, a failed check or anything a human must judge still stops the chain. Decided with the user (2026-11-07): "wait is a model activity the dispatcher uses for steps that only poll/babysit (CI, a review, a merge gate)". Decided with the user (2026-11-07): "I still dont understand why this is a challenge for you; in every text I write *without human* go all the way to merge." Decided with the user (2026-11-08): "Accept the blocking wait" (a lead waits for its nested review in one blocking command: no wait model for that). Decided with the user (2026-11-08): "c0252 builds it" (the run PR's own merge is c0252's; this builds the wait it needs).
