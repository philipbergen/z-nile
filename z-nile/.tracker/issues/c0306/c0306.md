# c0306: Refuse reviews on cheap models

## Problem
Carried from c0261 (Model tiers), which the user retired on 2026-11-12 ("Retire, file leftovers": #299, the roles table, already names a real model for every stage, so c0261 was closed and what main still lacks was filed as new tickets). c0261 was designed on the pre-#299 .models.toml; its prototype proto-c0261 (be21970f, base 10dd3c85) is a reference only. What should happen: ./zn status <id> prepared refuses an issue whose design review, and ./zn done a raft whose final review of the stack, was not recorded on a model of a final-review kind for its CLI. Items whose first review predates the landing are exempt, so work in flight is not locked out. Decided with the user (2026-11-08): "Commands refuse". Decided with the user (2026-11-08), as relayed: the rule judges by kind of model, not by exact ids (any Opus, any kimi-k3, any grok-...-xhigh), so a model upgrade in .models.toml does not lock out items in flight. Decided with the user (2026-11-12): "Expensive layer reviews" (every review but a stream review runs on the expensive model, a layer's code review included). Decided with the user (2026-11-12): "Honour system (Recommended)" (for an interactive review the refusal accepts the model id the lead types: the rule guards against forgetting, not cheating). Related: c0251 (the cross-model review pool).
