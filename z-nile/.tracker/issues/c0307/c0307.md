# c0307: Metrics show cost per model

## Problem
- `./zn metrics` prints no table of cost per model, so the tokens and minutes each real model id spent across every issue's spend rows (`spend.md` and `spend.d`) cannot be read from it.
- `./zn spend --model <id>` does not keep the typed model when the transcript reading measured a different one, so an interactive reviewer's row is often recorded under the author's model (#294).

## Non-goals
- No tier column or invented model alias is added to spend rows, `.models.toml` or the metrics table: the real model id on each spend row is the only record.
- Existing spend rows are not rewritten, so a row recorded under the wrong model before this change stays as it is.
- No code from the prototype `proto-c0261` (be21970f) is merged: it is a reference only.

## Solution
- `./zn metrics` prints one row per model id over every issue's spend rows (`spend.md` and `spend.d`), with rows that name no model under `none`, and the columns tokens, AI minutes, wall minutes, typed minutes and rows.
- The AI minutes cell of a model row is the sum of `ai` over only that model's spend rows that have an `ai` value, and it is `?` when none of them has one.
- The wall minutes cell of a model row is the sum of `wall` over only that model's spend rows that have a `wall` value, and it is `?` when none of them has one.
- No cell in the AI minutes column ever includes a `wall` value, and no cell in the wall minutes column ever includes an `ai` value.
- A cell that summed fewer spend rows than the model row's rows count ends with `+`, in both the AI minutes and the wall minutes column.
- The typed minutes cell of a model row is the sum of the `minutes` field over all of that model's spend rows.
- A spend row written by `./zn spend --model <id>` records `<id>` as its model even when the transcript reading measured a different model.
