# c0312: Dispatched review refuses before it runs

## Problem
- `./zn dispatch zz-review <id>` runs the whole reviewer before it checks the one-round rule, so a refused review costs a full run (c0264's re-prep on 2026-11-12: 14.7 minutes and 253k tokens, then `review.md` was deleted), and a re-prep the user asked for gets no dispatched review at all because an earlier prep's `design-review-NNN.md` counts against it.

## Non-goals
- A second dispatched review within the same prep, layer or landing is still refused: the one-round rule and c0248's definition of an existing code or final review do not change.

## Solution
- The dispatcher decides whether the review may land before it starts any model, using the same rule as the landing check (c0248's included). It refuses at once with the reason when this prep, layer or landing already has its review, and for a re-prep the user asked for it counts only the review files of the current prep, so c0264's re-prep runs one dispatched review that lands as `design-review-009.md`.
