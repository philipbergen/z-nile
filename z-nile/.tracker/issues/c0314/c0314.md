# c0314: Open list check agrees

## Problem
./zn approve and ./zn status <id> prepared apply the same open-list rule ./zn ready does (openlist.problem: a refuted finding, a high not answered fixed, or a failed Judged criterion must be a ruled bullet under ## Open to the human), and the refute parser either accepts the severity tag an author copies from the review's heading (- F1 [high]: fixed:) or every command refuses it with the expected form, so a design never reaches ready before the mismatch is seen. Seen 2026-11-13: c0264's design-refute-009 wrote '- F1 [high]: fixed: ...'; openlist.answerKind (pattern '- F1:') read all eleven as unanswered, so ./zn ready R0092 refused with 'open to the human (F1, F4)' after the user had approved c0264 and R0092's rafting PR had merged; approve and status prepared check only openlist.pending (bullets carry a ruling) and let it through. The fix took two more PRs (#333, #334), because R0092's grouped hash covers the refute file and fold refuses a member origin/main still lists.
