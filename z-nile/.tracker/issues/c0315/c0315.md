# c0315: Scanner hang proof tests

## Problem
- On origin/main the two hang cases (`spins` and `witspin`, each starting a real spinner and waiting for a real three-second limit) exist only in R0072's sequestered `z-nile/.tracker/issues/active/c0193/acceptance/finishes.spec.luau`, and nothing under `z-nile/tests` contains "did not finish within".
- When R0072 lands, it promotes that spec to `z-nile/tests/acceptance/c0193/finishes.spec.luau`, so the permanent suite will then contain two cases that spin and wait for real limits.

## Non-goals
- No change to scanner behaviour, to `z-nile/lib/bounded.pl`, or to any file under `z-nile/.tracker/issues/active/c0193/` or `z-nile/.tracker/rafts/active/R0072/` while R0072 is active.
- No change to which tier runs the promoted spec or the scanner sweep, because origin/main has no record of a slow-tier move and the idea no longer claims one.

## Solution
- This issue depends on R0072 and starts only after R0072 is done; it edits only the promoted copy `z-nile/tests/acceptance/c0193/finishes.spec.luau`.
- The `spins` and `witspin` cases in the promoted spec use a stand-in runner that immediately supplies the timeout exit and breadcrumbs, and still assert the case name, the stopped text block or witness, and the exit 124/125 wording.
- The real-spinner versions of both cases become proof-only development scripts that no promoted spec and no gate tier runs.
- One cheap unmocked case remains in the promoted spec, proving that `hostile.finishes` passes its `--time` limit to `bounded.pl`.
- After the change, no promoted spec under `z-nile/tests` starts a spinner or waits for a real limit, and each hang-reporting rule and mutation that the two cases covered is listed against the case or script that now covers it.
