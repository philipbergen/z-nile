# c0322: Commit phase bind subject

## Problem
- On main, `z-nile/tests/acceptance/c0084/commit-phase.spec.luau`'s case 'done records its own commit as deliver, and the raft summary shows each phase' fails in the slow tier: the last spend row of the first issue has the subject "R0010: bind f0010, f0020 claude unmeasured; grok unmeasured; agent unmeasured; kimi unmeasured" where line 284 expects "R0010: bind f0010, f0020".
- As captured (2026-11-14), word for word: "c0084/commit-phase's case 'done records its own commit as deliver, and the raft summary shows each phase' is red on main in the slow tier since #318: the bind commit's subject gains the dispatcher's attempts note, so line 284 expects "R0010: bind f0010, f0020" and gets "R0010: bind f0010, f0020 claude unmeasured; grok unmeasured; agent unmeasured; kimi unmeasured" (found by c0248's and c0250's preps, 2026-11-13; d0303 covers the other slow reds). Either the bind subject stays the plain one and the note goes elsewhere, or the spec's expectation follows the new subject." The idea step dropped the last sentence; prep puts it back (design review 001 F1). This design takes its first branch whole: the subject stays plain, and the note goes to the bind commit's trailers.
- Detail added by prep: the note is not the dispatcher's. It is the note of the session reading that `./zn done` takes with `sessionread.running()` (`sessions.combine`: which CLIs were unmeasured, or each one's tokens and AI seconds).

## Non-goals
- This issue does not fix the other slow-tier reds (d0303 covers them), and it does not change the wording of the attempts note or which agents it lists.

## Solution
- The deliver row that `done` records for the bind commit has exactly the subject `<raft>: bind <ids>`, with the dispatcher's attempts note kept out of the subject field, so that case passes with its line-284 expectation unedited.

## Design
### Root cause
`recordAndCommit` in `z-nile/engine/main.luau` builds the spend row of every tool commit. Since #318 it takes the running session's reading from `./zn done` (its only caller that passes one) and, besides filling one row's tokens, AI seconds and model from it, appends the reading's note to that row's subject (`subject ..= " " .. reading.note`). #318 put the note there as its only stored copy: the command also prints it (`session: <note>`), but a print is not a record. Nothing reads the note back out of a subject (searched every `.subject` reader in `z-nile/engine/`).

It stayed red unseen because `c0084/commit-phase.spec.luau` is slow-tier (`z-nile/tests/slow.tsv`): no affected or full gate runs it, and no fast spec pinned the row's subject.

### The change
- `z-nile/engine/ledger.luau` (the pure owner of the spend row's format) gains two functions and two types.
  - `ledger.Share`: an issue's share of a commit (`id`, `added`, `removed`, `minutes`, `how`, `tokens?`). `spend.luau`'s `Share` becomes an alias of it (`export type Share = ledger.Share`; `spend` already requires `ledger`, and `ledger` requires nothing of the engine), so the CLI's shares pass to both functions unchanged.
  - `ledger.Reading`: what a session reading gives a row (`tokens?`, `ai?`, `model?`); `sessions.Read` has those fields.
  - `ledger.commitRows(message: string, when: string, phase: string, shares: { Share }, model: string?, reading: Reading?, readingFlags: string): { Row }`: one row per share, in order. Every subject is the first line of `message` and nothing else. The reading is the commit's, not each share's: its tokens, AI seconds and model go on the first row only, with `readingFlags` as that row's unmeasured cells; every other row is bare (`tokens,wall,cpu,ai`), as today. A model the caller names wins over the reading's, on every row. `minutes` is 0 and `how` is `measured`, as today.
  - `ledger.commitTrailers(phase: string, shares: { Share }, rows: { Row }, note: string?): { string }`: the `Issue:` line of each share, formatted exactly as `recordAndCommit` formats it today, then, when `note` is given and not empty, one last line `Session: <note>`.
- `recordAndCommit` keeps its loop that folds every share and skips the build shares that get no row, but only collects the kept shares there. Then one `ledger.commitRows` call on the commit's own `message`, with `reading` as the command got it and `sessionread.flags(reading)`, builds every row; one `ledger.commitTrailers` call with `reading.note` builds the trailers. It builds no subject and no trailer text of its own, and still prints `session: <note>`.
- The note's new home is the commit: `./zn done`'s binding commit ends with `Session: <note>` after its `Issue:` lines. That is the capture's "the note goes elsewhere" (design review 001 F1): a stored copy, with the commit it measured, where `git log` shows it. A commit with no reading (`./zn commit`) gets no such line.
- Nothing else changes. `./zn finish` writes its own row, whose subject is `finish <note>`: a different reading, taken at each layer's finish, which this issue's Non-goals leave alone; it is pinned as it is. `./zn spend` appends a note to its own `--note` text; also unchanged.

`experiments/prototype.patch` is the whole change as prep prototyped it (cut on `origin/main` at 47a69f3aa).

Decided by prep (guesses for the approval session, not rulings):
- The rows and trailers are built by pure functions rather than by deleting the three lines in place. The deletion makes the slow spec pass but leaves the rule with only a slow-tier spec, which is how it went red unseen, and it drops the note's only stored copy.
- The note's home is a commit trailer rather than a new cell of the row: the row's format (`buffer.HEADER`, twelve cells) and every reader of it stay as they are.

### Who reads the bind commit's message
The `Session:` line is new text in a message other code reads, so each reader was checked on the prototype: `main.luau` looks for `\nVerdict: approve` in it (unaffected: the line is in the trailer paragraph, after the body); `d0333/commit-land.spec` (fast) checks subjects and an `Issue:` trailer: 6 passed; `tooling/trace-land.spec`, `tooling/stack-land.spec` (slow) and `c0239/done.spec` read bind subjects and bodies: green in E5 and E6; `stack.spec` pins `stack.bindMessage` alone, which this does not touch. No engine code parses the trailer lines at all: the only `Issue: ` in `z-nile/engine/` is the line that writes them.

### Chore checklist
- **No behaviour change for players**: no game file changes. For the tooling: the subject of the row `./zn done` records is plain, and its binding commit gains one `Session:` trailer. Every other cell of every row, every `Issue:` trailer and the printed `session:` line are as they were (`bind-subject.spec`, whose trailer case pins the `Issue:` lines' exact text; `wiring.spec`).
- **Overrides**: none. `c0084/commit-phase.spec.luau` is the spec that was red; this issue does not edit it.
- **Existing work**: no prepared, active or mid-prep item pins the note in a subject (searched every unfinished item's `acceptance/` and `check.sh` for `unmeasured;` and `reading.note`: no match). - **Shared state**: the branch touches no counter or registry. It appends two specs' inputs to `z-nile/tests/inputs.tsv`.
- **Restated rules**: none restate the subject. z-work step 9 says `./zn finish` and `./zn done` "write that row" and that an unreadable session "says unmeasured": still true, in the row's `unmeasured` cell, in finish's subject and now in done's `Session:` trailer. zz-stats' caveat speaks of cells. - **Moves**: the `Share` type's definition moves from `spend.luau` to `ledger.luau` (six lines, with the alias left behind); no file moves.
- **Guards**: none touched.

### Scalability
No git call, file read or process is added or removed. Two function calls per commit replace a per-share table literal and string format.

### Maintainability
A future caller that records a commit's rows (a new command that binds or lands) calls `ledger.commitRows` and `ledger.commitTrailers`, and cannot put the note in a subject, or the reading on every row, by habit. A new measured cell is added in `commitRows` and its one fast spec; the row format's one reader and writer stays `ledger` and `buffer`.

### Usability
No command line, usage text or message changes. `./zn done` still prints `session: <note>`. What a person sees differently: the bind row's subject cell wherever rows are listed (`./zn metrics`, `./zn who`, `spend.d/<writer>.tsv`) is `R0010: bind c0010` with no note after it, and `git log` of a binding commit shows a last trailer `Session: <note>`.
