# c0325: A challenge drops the model that actually wrote the text

## Problem
- Nothing in `z-nile/engine/models.luau` can tell whether a challenger try is the model that actually wrote the text: the only comparison (`resolveRole`'s `authorModel`, read by `models.tries`) uses the author role's first choice with its effort appended, so a fallback author (e.g. kimi after Claude's quota ran out) or the same model at another effort is never matched.

A challenge never runs on the model that wrote the text, as zz-review and .models.toml say ("a challenge is never run by the model that wrote the text"). Today models.resolveRole sets authorModel = models.id(the author role's first spec), and models.id appends the effort (claude-sonnet-5-5-high), so models.tries drops a challenger try only when both model and effort equal the author role's FIRST choice. Every author role and its challenger share the fallbacks kimi, grok and agent, so when the author fell back (e.g. Claude quota out) the challenger can fall back to the very model that wrote the text, and a same model at a different effort is never dropped either; this holds for code-review (author implementation) as well as idea-challenge (author idea). What should happen: the exclusion compares models without their effort, and against the model that actually wrote the text (the author step's recorded model, its fallback included), wherever it is known. Found by the Opus review of c0260's idea loop (design-review-011 F3, 2026-11-14); checked on main: models.luau lines 501-507, 566-576, 587-589.

Decided with the user (2026-11-15), asked during c0251's design (Q2): "Soft, never blocks (Recommended)". A review by the exact model that wrote the text is allowed as the last, flagged fallback, and never blocks the chain (c0251's family tiers replace the hard stop). So this issue keeps only its other half: compare models without their effort, and against the model that actually wrote the text (the author step's recorded model, its fallback included), wherever it is known, which c0251 reads to order its review pool. It is designed before c0251, which depends on it.

(Restored by c0325's capture, 2026-11-15, word for word from the text before `./zn idea c0325`, which rewrote the Problem and dropped them; c0324.)

Decided with the user (2026-11-15), design review 001 F1: "c0325 adds it". Almost no record says who wrote a text today: interactive build, deliver and prep spend rows carry no model, `spend` never measures the session (d0328), and a dispatched step's rows sit on the dispatcher's local branch. So c0325 also makes every authored step record its model where the item travels (the idea, design, raft and build steps), and reads it per review mode. That needs d0328 fixed first, or a typed `--model` on those steps. c0251 orders its pool by that reader.

## Non-goals
- This issue adds no drop and no stop on the new match, and does not remove the existing drop and error in `models.tries`; c0251's family tiers replace those with the flagged last fallback, per the 2026-11-15 ruling.
- This issue does not order, tier or flag the review pool; that is c0251's.

## Solution
- `models` gains one pure match that c0251 reads to order its review pool: given a challenger try and the author step's recorded model (fallback included, or the author role's first choice where no record exists), it answers whether they are the same model with effort ignored.
- `models.tries` does not call the new match: its drop (`:570`) and its "only model left is the author's" error (`:574-577`) stay on today's comparison, so for every input it returns the same tries or the same error as before this issue.
- `models` gains `modelOf` (a record to a bare model) and a `bareModel`; a new pure module `authorship.luau` answers, per review mode, which models wrote the text and how sure the tool is (`recorded`, `assumed`, `unknown`), and whether a challenger try runs one of them with effort ignored. A new edge module `authorread.luau` reads the item folders' `spend.d` and the live author, and hands both to it.
- Every authored step records its model where the item travels, in the spend row's model cell (and, for a commit, the `Issue:` trailer): `./zn spend`/`./zn commit` take `--model <id>`, or `ZN_MODEL` that the dispatcher sets for each attempt; a marked item refuses the omission.
- `models.tries` still does not call the new match (unchanged, AC8).

## Design
**What it builds on.** `models.resolveRole`/`models.id`/`models.tries` (`models.luau:460-520, 566-589`); `costrow.readMeasured` (`costrow.luau:204`), the one reader of `spend.d`; `modelOption`, `cmd.commit`, `cmd.spend` (`main.luau:4390, 4533, 6320-6600`); `dispatcher.modelStep`'s env (`dispatcher.luau:~866-955`); c0306 (typed `--model` wins on `spend`; `ledger.isModel` accepts `[…]`; the `reviews: judged` mark and `reviewmodel.judged(front)`). Decisions it relies on: 2026-11-15 "Soft, never blocks" (this issue adds no drop and no stop); 2026-11-15 design review 001 F1 "c0325 adds it"; 2026-11-12 "Honour system" (an interactive record is the model the lead types).

**1. The record, per authored step** (one grammar: a model id with no effort, as the toml writes `model`; `ledger.isModel` shape).

| step | written by | row phase, in the item's `spend.d` | model comes from |
|---|---|---|---|
| idea | `./zn idea` (unchanged) | `idea`, subject `<id> ok` | `models.id(spec)` of the attempt (exists today); an idea row is `<model>-<effort>`, so the reader must cut the effort (3) |
| design | `./zn spend <id> --phase prep` | `prep` (item) | `--model`, else `ZN_MODEL` (dispatched), else (a marked item) refused |
| raft | `./zn spend <R-id> --phase prep` (z-raft gains this line at PR open, as z-design step 6 has) | `prep` (raft/members, E1) | same |
| build | `./zn commit` (phase `build`) | `build`, plus the `Issue:` trailer | same |

A phase `capture` row (z-ticket) takes the same flag. Reviewer rows (`design-review`, `code-review`, `deliver`) are never an author's row and never take the env default (c0306's trap: it must not record the author's model as the reviewer's).

**Writer, dispatched.** In the attempt loop, after `adapters.STEP_ENV` is merged (`dispatcher.luau:951`), `env.ZN_MODEL = spec.model` (a fallback attempt sets its own model; the next attempt overwrites). A nested `./zn dispatch zz-review` sets its own for its child. `main.luau`'s `modelOption` falls back to `process.env.ZN_MODEL` only when phase is `capture`, `prep` or `build` and no `--model` is typed; a typed `--model` always wins (c0306). A non-model-id `ZN_MODEL` is an error.

**Writer, interactive.** The lead types `--model <its id>` on its `spend --phase prep|capture` and `commit` calls. In a **marked** item (c0306's mark) a `spend --phase prep|capture` or `commit --phase build` with no `--model`, no `ZN_MODEL` and, for `spend`, no measured model, is refused: "`<phase>` records the model that wrote the work: --model <your model id>". Unmarked items, other phases and reviewer rows behave as today.

**2. The reader** (`z-nile/engine/authorship.luau`, pure; `z-nile/engine/authorread.luau`, the edge).

```luau
-- authorship.luau (pure)
export type Provenance = "recorded" | "assumed" | "unknown"
export type Writer = { model: string, step: "idea" | "design" | "raft" | "build" }
export type Authorship = { writers: { Writer }, provenance: Provenance, via: string }
export type Input = {
  live: string?,                      -- the model that is starting the review (a record or an env id)
  rows: { [string]: { ledger.Row } },  -- step -> that step's rows already read from the item folders
  authorModel: string?,               -- Resolved.authorModel of the challenge role (idea path: the real writer)
  firstChoice: { [string]: string? }, -- step -> the writing role's first-choice model, from the toml
  known: { string },                  -- every `model` of every role and fallback of the loaded toml
}
authorship.STEPS = { idea = {"idea"}, design = {"design"}, raft = {"raft"}, code = {"build"},
                     stream = {"build"}, final = {"idea","design","build"} }  -- mode -> steps
authorship.ROLES = { idea = "idea", design = "design", raft = "raft", build = "implementation" }
authorship.of(mode: string, inp: Input): Authorship
authorship.isAuthor(spec: models.Spec, a: Authorship): boolean   -- spec.model vs each writer, effort ignored
-- models.luau (pure additions)
models.bareModel(model: string): string               -- one trailing [...] removed
models.knownModels(layers: { Layer }): { string }     -- every role's and fallback's model, bare
models.modelOf(recorded: string, known: { string }): string
-- authorread.luau (edge)
authorread.read(mode: string, dirs: { string }, layers: { models.Layer }, live: string?, authorModel: string?): Authorship
```

`authorship.of`, in order, per step `s` in `STEPS[mode]`:
1. `live` (when given): one writer for the first step of the mode, `recorded`, `via = "live"`.
2. else the models of `rows[s]` whose phase is the step's (`idea`: phase `idea`, subject ending ` ok`; `design`/`raft`: phase `prep`; `build`: phase `build`), each cut by `modelOf`, de-duplicated; any row with a model: `recorded`, `via = "row"`. All writers count (several attempts, several layers, a draft and its answer on two models give several writers; `isAuthor` is true if the challenger equals any).
3. else `authorModel` (read through `modelOf`) when set: `assumed`, `via = "authorModel"` (it is the default stand-in on any role with `author`, and what the idea path overwrites with the real writer: the idea path also passes `live = wrote`, so it is `recorded`).
4. else `firstChoice[s]`: `assumed`, `via = "role"`.
5. else no writer: `unknown`.
Overall provenance: `recorded` only when every step of the mode got a recorded writer; `unknown` when some step is unknown; otherwise `assumed`. `final` therefore reports `assumed` when idea and design were recorded and build was not. Each `Writer` keeps its step, so c0251 can order by step.

`models.modelOf(recorded, known)`: the longest `m` in `known` (compared as `bareModel(m)`) such that `recorded == m`, or `recorded` is `m` followed by an optional one `[...]` marker and then end or `-<any effort word>`; the answer is `bareModel(m)`. No such `m`: `bareModel(recorded)`. This recognises a record by every model the toml names (not only the author role's tries: F2, F5, F6), at any effort word including a hyphenated one or one no role uses now, and never by splitting at the last hyphen. Documented limit: a model unknown to the toml that shares a known model's name plus `-word` is read as that model.

`authorship.isAuthor(spec, a)`: `models.bareModel(spec.model)` equals some `w.model`. Both sides are normalised with the same function (F3): `claude-opus-5-5[1m]` and `claude-opus-5-5` are one model; `[1m][2m]` keeps `[1m]`.

`authorread.read` (edge): `dirs` are the item folders of the mode in the checkout the review starts from (design/idea: the issue; raft: the raft; code: each member of the raft; stream: the stream's issue; final: all members), read with `costrow.readMeasured`, `layers` the loaded `.models.toml` walk (`models.walk`, as `dispatcher.resolve` loads it), `live` from the caller: under dispatch `process.env.ZN_MODEL` (the author step's env, inherited by the review it starts), interactively the id the lead types when it starts the review (c0251's command passes it; this issue gives no command for it). `firstChoice[step]` from `models.resolveRole(layers, authorship.ROLES[step])`. `idea` mode is the one that sets both: `challenge.authorModel = wrote` (existing) and `live = wrote`. Reading works for both a dispatched review (cwd is the author's worktree, `dispatcher.luau:789`) and an interactive one in a worktree, because the rows are in tracked item folders, not in the dispatcher's local state.

What each way of working answers: dispatched step: `recorded` (env, exact, the fallback included); `./zn idea`: `recorded`; interactive step in a marked item: `recorded` (typed); interactive in an unmarked/legacy item with no row: `assumed` (the role's first choice; it can name the wrong model: that is what the flag says), or `unknown` when the toml has no such role.

**3. The match, fixed per F2 to F6** (see `modelOf`, `bareModel`, `isAuthor` above): F2 (the writing role is an input, `ROLES`, not `Resolved.author`; so design, raft and final modes work; the raft role needs no `author` key), F3 (both sides normalised), F4 (`authorModel` read before the first choice, empty counts as none), F5 (any effort word), F6 (the mutant row below), F7 (provenance), F8 (every probe and mutation run bounded: `./zn run --time 120 -- lune run <script>`).

**4. What does not change.** `models.tries` and its drop/stop (`models.luau:566-579`) are untouched. The idea path, `resolveRole`, `Resolved` (no new field), the tracker commands' output, `spend` rows of every phase when `--model` is given or absent in an unmarked item.

### Scalability
- The pure modules read nothing. The edge reads each folder's `spend.d` once per call: a handful of small TSV files per item, at most about 10 members for a raft. No git, no network.

### Maintainability
- One function recognises a record (`modelOf`), one normalises (`bareModel`), one answers (`isAuthor`), and one reads the format (`costrow.readMeasured`, reused). The mode-to-step table is one constant that c0251 reads. No second record format is added.

### Usability
- A lead in a marked item types `--model <its id>` on its authoring commits and prep spends; the refusal names the flag. A dispatched step records itself through `ZN_MODEL`. c0251 shows the provenance (`assumed`, `unknown`) where its flag needs it.
