### F1 [high] Nothing designs where "the model that actually wrote the text" is read, though the ruling gives c0325 exactly that
Where: c0325.md Problem (ruling paragraph), Solution line 32, Design §1 (lines 38-40) and §3 (line 53); c0251.md line 35.
Evidence: c0251's record of the ruling says "c0325 shrinks to reading who really wrote the text, which c0251 needs". c0325's own restatement keeps "against the model that actually wrote the text (the author step's recorded model, its fallback included), wherever it is known", and the capture names code-review (author implementation) as a case. The Design reads nothing. `isAuthor` takes `recorded` as an argument, and §1 lists the shapes a record takes but not where any record is found. After this issue the only caller that has the writer is still the idea path (`challenge.authorModel = wrote`, main.luau:6885), which was already wired. For code-review, the writer is known only in the dispatched z-run step's per-attempt rows (`model = models.id(spec)`, dispatcher.luau:836-1026). Those rows are published through the `zn-dispatch` worktree (dispatcher.luau:408-416), and c0306 (c0306.md:75) ruled them out as unreachable from a prep worktree. No section says which row is the author step's when one step made several attempts, when a raft's layers ran on different fallbacks, or when a draft and its answer were written by different models. Interactive work records nothing: every `deliver`, `build` and `prep` row in the tree's spend.d files (2, 4 and 22 rows) has an empty model column. c0251's Design is still a template. So "wherever it is known" has no design and no acceptance criterion in either issue.
Critique: the issue ships a comparator and calls the outcome done, while the part the ruling names ("reading who really wrote the text") falls between c0325 and an undesigned c0251. The fix the author will be tempted to make is one sentence: "c0251 supplies `recorded`". That moves a captured outcome to another issue without the user, and the two documents' restatements of one ruling already disagree about who reads.
Consequences: a reader brings its own rules, which someone has to own: which phase and outcome counts as the author step's row (the attempt that ended the step `ok`), how a layer's rows are told apart (the `branch` and `head` columns), how a text with several writers is matched (match against each writer, true if any), and what the answer is where nothing is recorded (F7). Moving the reader to c0251 instead means c0251's Problem gains the outcome and c0251 needs its own reader design.
Recommendation: escalate to the user: (a) keep the full scope here: c0325 adds a pure reader over the parsed spend rows (through the existing row parser, one reader per format) that returns the writer model or models of an item's author step: the attempt that ended `ok`, per layer, every writer of a revised text, nil where nothing is recorded. It gets spec cases for a fallback attempt after a failed one, two layers on two models, a draft and an answer on two models, and a step with no row, plus the read of the dispatcher's rows from wherever they land (est. +80-150 lines and one more experiment on where those rows live); or (b) the user rules that c0251 reads the record and c0325 only matches, and that line goes into both Problems as `Decided with the user (YYYY-MM-DD)`, with c0251's text naming the reader as its outcome.
Lesson: z-design/inherited-decisions-agree

### F2 [high] A known record is ignored for every review role that names no `author`, and the raft role can never name one
Where: Design §2, line 50 ("a role with no `author` ... is never matched"); AC2; match.spec "AC2: a role with no author never matches, with a record or without".
Evidence: on the prototype with the repository's real .models.toml, `isAuthor(<opus try>, resolveRole("design-challenge"), "claude-opus-5-5-high")` is false, and so is `isAuthor(<kimi try>, resolveRole("final-review"), "kimi-code-k3.1-pro-high")`, though in each case the record names the challenger's own model. Adding `author = "raft"` to `[roles.raft]` makes `resolveRole` error "raft: author is itself; a challenge cannot name its own role". Raft-mode review runs on that role (models.roleFor). Three of the five review roles (design, raft, final), and the case c0251's Q1 names ("an Opus-written design is reviewed first by a model that is not Opus"), cannot get a true answer from the match, whatever record c0251 passes. AC2 pins that false.
Critique: the match is keyed on the toml's `author` key, which exists to drive `tries`' hard drop, the thing the ruling retires. Its one reader orders every review pool. The tempting fix is "c0251 sets `r.author` by hand", as the idea path overwrites `authorModel`. That is an undocumented contract on a public field, and it still fails for raft, where writer and challenger are the same role.
Consequences: the match needs the role that wrote the text as an input, separate from the challenge role, so the review mode to writing role map (design → design, raft → raft, code/stream/final → implementation, idea-challenge → idea) becomes a rule someone owns. Name it, here or in c0251. For raft the writer and the challenger are one Resolved, and recognising a record against its own tries must work. `tries` and the toml comment on design-challenge stay as they are.
Recommendation: make the writer role an argument, e.g. `models.isAuthor(spec, recorded, writer: Resolved?)`, where `r.author` is only the default for roles that name one, and recognise records against `writer`'s tries. Replace AC2's "a role with no author is never matched, with a record or without" with cases where design-challenge with a design-step record is true, the raft role recognising its own try's id is true, final-review with an implementation fallback's record is true, and no record with no writer gives F7's "unknown". Keep AC4 as is.
Lesson: z-design/fallbacks-name-the-modes-they-cover

### F3 [high] The `[...]` marker is stripped from the record only, so the same model string is judged two models
Where: Design §2 lines 46 and 51; AC3; match.spec.luau:171-194 (the case "AC3: a record that is an author try's id is cut to that try's model and keeps its marker").
Evidence: match.spec.luau:190-193 pins `isAuthor(<try model "claude-opus-5-5[1m]">, marked, "claude-opus-5-5[1m]") == false`: an identical model string on both sides answers "not the author". Lines 178-181 pin a plain `claude-opus-5-5` try against a recognised record `claude-opus-5-5[1m]-high` as false, while lines 162-169 pin a plain try against the bare record `claude-opus-5-5[1m]` as true. So the same pair of models is "same" in one direction and "different" in the other, against the Design's own reason for stripping ("the same model with a longer context window, so it shares the same blind spots"). The Design's sentence "removed from both sides only on a bare record" (line 51) also disagrees with the prototype, which strips the record side only. On a scratch copy that strips one trailing marker from both sides, the spec goes red at line 181. This is reachable before c0251 can read it: c0306 (prepared, and in c0251's depends_on) makes `ledger.isModel` accept `[` and `]`, and `.models.toml` validates its ids with that function (models.luau:237), so a role may name `claude-opus-5-5[1m]` and a lead may type it.
Critique: a sequestered spec, promoted later, would pin a wrong answer on identical strings. The tempting fix is to drop the `[1m]` stripping, which brings back the false negative for a typed `[1m]` record.
Consequences: normalising both sides means a 1M-context challenger of a plain-window author's text (and the reverse) counts as the author, which the Design's reason already says is right. A role may then name both forms, and c0251's family prefixes are not affected.
Recommendation: one function, e.g. `models.bareModel(model)`, that strips one trailing marker, applied to the model `modelOf` resolves (recognised or bare) and to `spec.model` alike. Cases: identical bracketed strings are true; a `[1m]` try against a plain record, and a plain try against a recognised `[1m]-high` record, are both true; `claude-opus-5-5[1m][2m]` keeps `[1m]`.
Lesson: zz-test/grammar-cases-from-real-producers

### F4 [medium] With no `recorded`, `isAuthor` ignores `r.authorModel`, the field where the idea path stores the model that wrote the text
Where: Design §2 line 49; AC2; main.luau:6884-6885.
Evidence: `./zn idea` resolves idea-challenge and then sets `challenge.authorModel = wrote`. On the prototype, after `ic.authorModel = "kimi-code-k3.1-pro-medium"` (a kimi-written draft; the tree holds such a row, `idea kimi-code-k3.1-pro-medium`), `isAuthor(<kimi try>, ic, nil)` is false and `isAuthor(<claude-fable-5-2 try>, ic, nil)` is true. That is the opposite of the truth. AC2's case leaves `authorModel` at the first choice's id, so the spec cannot tell "reads r.authorModel" from "reads r.author's first choice".
Critique: two fields now hold "who wrote it", and the match reads the one the only existing writer of real records doesn't set. A caller that trusts the Resolved (c0251 in the idea flow) gets a wrong answer with no error.
Consequences: reading `r.authorModel` through `modelOf` gives today's answer when it holds the default (the first choice's id is recognised, so its model comes back) and the right answer when a caller set the writer. An empty `authorModel` must count as none, like an empty `recorded`.
Recommendation: with `recorded` nil or empty, use `r.authorModel` (through `modelOf`) before the first-choice stand-in. Add a case where `authorModel` is set to a fallback's id, `recorded` is nil, the fallback's model is true and the first choice's model is false, plus the empty-string case.
Lesson: zz-test/pin-call-site-arguments

### F5 [medium] A `<model>-<effort>` record that is not one of the author role's current tries is never matched, and the Design calls that failing closed
Where: Design §1 line 40 ("which never carries an effort"), §2 line 46, line 62 (Guards).
Evidence: on the prototype, after the real toml's `[roles.implementation]` effort moves from `high` to `xhigh`, an existing record `claude-sonnet-5-5-high` gives `modelOf` = `claude-sonnet-5-5-high`, and `isAuthor(<sonnet try>, ...)` is false. The kimi fallback that wrote at `high` (`kimi-code-k3.1-pro-high`) is no longer matched by a kimi challenger either, though every role shares `[fallback.kimi]`. A record typed with an effort, `claude-opus-5-5-xhigh`, which `ledger.isModel` accepts (`^[%w][%w%._%-]*$`), is likewise never matched. An unrecognised record compared "as a bare model" can only equal a toml model that ends in its effort word, which none does, so it acts as "no author": the fail-open the Guards bullet says cannot happen. Stored rows outlive toml edits: a final review reads records written over the days its layers took, and 23 of the tree's 26 `idea` rows say `claude-fable-5-2-medium`.
Critique: the recognition rule is exact only for the toml as it stands at the read. The tempting fix, splitting at the last hyphen, is M1 and is rightly refused.
Consequences: a sturdier rule strips a trailing `-<e>` for any effort `e` the walk names (every role's `effort`, longest first), and only when what is left is a model some spec in the walk names. Any remaining ambiguity (two readings that are both models) is matched as either, true if any. An effort no longer named anywhere stays unrecognised, and the Design must say what is answered then, not call it fail-closed.
Recommendation: adopt that rule, or keep the current one and rewrite line 62 to state the fail-open and its cases. Either way, add cases for a record at an effort the author role no longer has, a typed `<model>-<effort>` id, and a record of a model at the author's effort that is no author try. That last case also settles F6.
Lesson: z-design/new-rules-migrate-existing-work

### F7 [medium] With no record, the stand-in "author role's first choice" comes back as a fact, and in this repository's main path it names the wrong writer
Where: Solution line 32; Design §2 line 49; AC2.
Evidence: interactive rows carry no model (F1's tally), and interactive z-work and prep are the main way work is done here. The commits carry `Co-Authored-By: Claude Opus 5.5` (e.g. 025ed65a0). For such a layer, `isAuthor` compares with implementation's first choice `claude-sonnet-5-5`, so an Opus code review of Opus-written code is "not the author". c0251 needs to flag fallback reviews and cannot tell this guess from a record, because both are a bare `boolean`.
Critique: the stand-in was right for `tries`' old hard drop, which only needed a likely author. A pool order that flags reviews has to know when the writer is unknown. The tempting fix is to read the session trailer here, which is c0263's actor grammar (`agent:<model> effort <level>`, not landed) and a third record shape §1 doesn't list.
Consequences: an "unknown" answer is a new state that c0251's tiers and flags must handle, so name it in c0251's text, and F4's `authorModel` must count as known only when a caller set it.
Recommendation: make the stand-in visible, e.g. `isAuthor(...)` returns `(boolean, known: boolean)`, or a separate `models.writer(...)` returns nil when nothing is recorded. Say in the Design, per way of working (dispatched step, `./zn idea`, interactive session), what the answer is. Add cases for no record (stand-in compared, `known` false) and a record (`known` true).
Lesson: z-design/live-defaults-checked-in-their-session
