# c0330: Trace takes claims from a stub capture's Problem

## Problem
Decided with the user (2026-11-14), answering how to fix the trace gate for tickets captured with an empty Solution: "Tooling ticket first (Recommended)" (option text: "File and fast-track a chore: when a ticket's captured Solution is empty (only the template), the trace takes its claims from the captured Problem's outcomes alone. R0092, R0099 and R0100 wait for it, then rebuild trace.md and land. One small extra raft before the three."). Restored by the coordinator after `./zn idea` dropped it (c0260 fixes that drop); idea review F1 and F2 refine "alone" and the readied-raft outcome, see idea-refute-001.md.

- `./zn trace <R-id>` refuses a ticket whose captured document has an empty `## Solution` with "ticket <id> is missing captured ## Solution" (`trace.deriveClaims`, `z-nile/engine/trace.luau:367-433`).
- `./zn done` refuses a raft that holds such a ticket, because its trace is refused.
- `./zn new --desc` writes the captured Problem and leaves the captured Solution as the template comment.
- 26 of 46 designed tickets were captured that way (counted by R0092's executor, 2026-11-14), among them c0264 (R0092), c0280 (R0099) and c0274 (R0100).
- R0092 is blocked at done on c0264 with every review passed.

## Non-goals
- `./zn new --desc` is not changed: it still leaves the captured Solution as the template comment.
- No captured Solution is written or backfilled for the 26 tickets captured without one.
- The refusals for a missing captured `## Problem` and for missing `## Acceptance criteria` are not changed.
- This change does not fill in P or AC coverage in any raft's `trace.md`, so whether R0092, R0099 and R0100 pass `./zn trace --check` and land stays those rafts' own work.
- The trace check's rules for P and AC rows are not changed.

## Solution
- `trace.deriveClaims` returns no S claims and no "missing captured ## Solution" error for a ticket whose captured `## Solution` holds only the template comment or nothing.
- Such a ticket keeps its P claims from the captured Problem's outcomes and its AC claims from its acceptance criteria, with the same ids and row labels as today.
- A ticket whose captured `## Solution` has outcomes still gets one S claim per outcome, as today.
- A ticket whose captured document has no `## Problem` outcomes is still refused with "ticket <id> is missing captured ## Problem".
- `./zn trace <R-id>` writes a `trace.md` skeleton with no S rows for such a ticket, and `./zn trace --check` neither expects S rows for it nor reports a Solution refusal.
- An already-readied raft holding such a ticket, when its trace skeleton is rebuilt on the main that carries this change, gets a skeleton with no S rows and no Solution refusal for that ticket.

## Design
The whole change is one loop in `trace.deriveClaims` (`z-nile/engine/trace.luau`, the `local solutions = ...` block): the branch that appended "ticket <id> is missing captured ## Solution" is deleted, and the loop that makes one S claim per outcome stays. `extractOutcomes` already drops the template comment (a line starting `<!--`, even over several lines), so a Solution that is only the template, empty, or a missing section gives `#solutions == 0` and the loop emits nothing. A second edit is needed so that c0330's own `./zn done` passes (E3): `extractOutcomes` ends the captured part at a `Decided with the user` line (`isPrepAdditionLine`), and c0330's capture has that line as the first and only text of its Problem, so its captured Problem has no outcome and the trace would refuse it with "missing captured ## Problem". `extractOutcomes` takes an optional `keepPrepLines`, and `deriveClaims` asks for it only when the first read of the Problem gave no outcome, so a Problem that is only a decision line has that line as P1. A Problem with an outcome before the line reads as it does today (AC8). This adds no refusal and removes none.

Nothing else changes: the P block (still refused with "missing captured ## Problem" when it has no outcome), the AC block (still refused when it has none), `trace.skeleton`, `trace.check`, `main.luau`'s `./zn trace` and `./zn done` paths all call `deriveClaims` and take its claims and errors as they are, so they treat both kinds of ticket alike with no code of their own.

Decided with the user (2026-11-14), quoted from the Problem: "when a ticket's captured Solution is empty (only the template), the trace takes its claims from the captured Problem's outcomes alone." The idea review's refinement stands (idea-refute-001.md F1, F2): such a ticket keeps its AC claims, and a readied raft's outcome is a skeleton with no S rows and no Solution refusal, not a promise that the raft passes `--check`.

Edits, with the restated rules that move together with the engine (checklist: restated rules):
- `z-nile/engine/trace.luau`: delete the refusal, a comment says why; add the `keepPrepLines` fallback for a Problem with no other outcome; the header contract (CLI paragraph and "Stable claim names" paragraph) says a captured `## Solution` is optional and yields S claims only when it has outcomes.
- `z-nile/skills/zz-rules/SKILL.md`, the `trace` row of the command table: says a ticket captured with only the template under `## Solution` gets no S claims and is not refused, and that a missing captured `## Problem` or `## Acceptance criteria` fails naming the ticket and section. Pinned by AC6.
- `z-nile/tests/tooling/trace.spec.luau`, the case "derives stable P, S and AC claims ...": its `noSolution` block asserted the refusal; it now asserts no error and no S claim. That is the only spec that pins the old refusal (`grep -rF "missing captured" z-nile/tests`). `trace-land.spec.luau` builds tickets that all have a Solution and is unchanged.

Checklist answers (chore):
- **No behaviour change**: for a ticket with Solution outcomes, claim ids, row labels, order, skeleton and check are byte for byte as today (AC2, and `trace.spec` and `trace-land.spec` unchanged cases). The refusals for a missing Problem and a missing Acceptance criteria stay (AC3).
- **Overrides**: no promoted spec under `z-nile/tests/acceptance` pins the refusal (grep for `missing captured`, `engine/trace` and `trace.luau` over `tests/acceptance` found none). The one pinning spec is the tooling spec `trace.spec`, edited in this raft as above; it is not promoted, so the `Overrides:` line below is `none`.
- **Existing work**: every ticket captured with a stub Solution and not yet done stops being refused: c0264 (R0092), c0265, c0274, c0275, c0276, c0277 (R0100), c0280 (R0099) all derive with `errors=0` (E1). A readied raft's `trace.md` skeleton written before this change has no S rows for them already when its executor removed them (R0092's does); a skeleton that has S rows for such a ticket is now stale ("unknown claim") and is rebuilt with `./zn trace <R-id>`. Tickets with Solution outcomes are unchanged. The ones that wait (R0092, R0099, R0100) pass the Solution part and then stand on their own P and AC coverage, and R0092 also needs `./zn restack R0092` on the new main (E1).
- **Shared state**: none; no counter, map or registry is touched.
- **Moves**: none.
- **Guards**: nothing near the repository guards, the publisher or the gate; the change only removes a refusal, and the two refusals that fail closed on a missing Problem or criteria stay.

### Scalability
One refusal fewer in a loop over a raft's tickets; the cost is unchanged. A ticket with no S claims has fewer rows, so a raft's table is shorter.

### Maintainability
The rule lives in one place, `deriveClaims`; `skeleton`, `check`, `done` and the `--check` path derive from it, so they cannot disagree about which tickets have S rows. The contract comment and the zz-rules row restate it and AC6 pins both, so wording and code move together.

### Usability
A worker no longer has to write a Solution into a ticket that was captured as a one-line `--desc` to get past `./zn done`; the trace asks for P and AC rows, which is what the ticket's Problem and criteria actually say. The error for a missing Problem or criteria is unchanged.
