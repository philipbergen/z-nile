# c0330: Trace takes claims from a stub capture's Problem

## Problem
Decided with the user (2026-11-14), answering how to fix the trace gate for tickets captured with an empty Solution: "Tooling ticket first (Recommended)" (option text: "File and fast-track a chore: when a ticket's captured Solution is empty (only the template), the trace takes its claims from the captured Problem's outcomes alone. R0092, R0099 and R0100 wait for it, then rebuild trace.md and land. One small extra raft before the three."). ./zn trace <R-id> (#297, z-nile/engine/trace.luau around line 390) refuses a ticket whose captured document has an empty ## Solution with "ticket <id> is missing captured ## Solution", so ./zn done refuses the raft. ./zn new --desc writes the Problem and leaves the Solution as the template comment, and 26 of 46 designed tickets were captured that way (R0092's executor counted, 2026-11-14), among them c0264 (R0092, blocked at done with every review passed), c0274 and c0280 (rafts R0100 and R0099). What should happen: a captured Solution that holds only the template (or nothing) yields no Solution claims and no refusal, and the ticket's claims come from its captured Problem's outcomes; a captured document with no Problem still refuses; trace.md and ./zn trace --check treat both kinds alike; a raft already readied rebuilds its trace skeleton on the new main and passes.
