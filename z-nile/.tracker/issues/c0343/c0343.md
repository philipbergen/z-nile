# c0343: Trace accepts spend ledger

## Problem
- A commit made with `./zn commit` after the top layer's finish commit rewrites the raft's `spend.md`, and `trace.staleReason` reports it as "touches non-tracker file …/spend.md after finish".
- Running `./zn finish` again after committing `trace.md` folds `trace.md` into a new finish commit, so `./zn trace <R> --check` reports that the table names a commit that is not the top layer's finish commit.
- After the final-review commit, `./zn work next` tells the worker to finish the top layer again, although only tracker files were committed after its finish commit.
- No sequence of the allowed commands gets a finished, reviewed and gated raft through `./zn done`; R0101 is held on this.

## Non-goals
- Restack dropping or failing to replay a layer's earlier commits is c0300's, and this issue does not change `./zn restack`.
- Finish refusing layer one when main has moved is d0331's, and this issue does not change what `./zn finish` accepts as a layer's base.
- Which files `./zn commit` rewrites, and what `spend.md` records, do not change.

## Solution
- After the final review, the worker commits `trace.md` and the final-review files with `./zn commit`, and `./zn trace <R> --check` passes.
- `./zn done` then lands that raft with no further finish.
- `./zn work next` does not ask for another finish of the top layer when only tracker files, the raft's `spend.md` among them, were committed after its finish commit.
- A commit after the finish commit that touches any file outside the tracker set still makes `./zn trace <R> --check` report the table stale.
- A spec drives the whole sequence (finish, final-review commit, `trace.md` commit, trace check, done) with the real `./zn commit`, on a raft whose `spend.md` that commit rewrites.
