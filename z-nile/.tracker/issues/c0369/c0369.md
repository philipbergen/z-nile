# c0369: Approve publishes by default

## Problem
- Today `./zn approve <id>` only records the approval locally, and ready (which reads `approval.md` on origin/main) does not count it until a second manual command, `./zn approve <id> --publish`, is run.
- The user asked on 2026-11-15 for that extra step to go ("./zn approve f0211 should absolutely publish, why would I want an extra manual step").

Scope decision (user, 2026-11-15): "Add to that chore the problem that I must be in the right worktree directory. That's also completely automatable and should not be my problem". Added outcomes (the same problem c0299, "Approve finds the worktree", captured on 2026-11-13; its outcomes are carried here so one chore makes approve a single command from anywhere):
- `./zn approve <id>`, run from the main checkout or from any worktree, finds where the design to approve is (the one worktree under `.worktree/` whose checkout holds the issue `design: ready` with no matching approval, or `origin/main` when the design has merged and no worktree holds a newer one), records the approval there, makes it count as the Solution says, and prints where it recorded it.
- When more than one place could be meant, it refuses and names each; when none is, it refuses and says so.
- The person never has to be told a worktree path or change directory to approve.

## Non-goals
- Ready still reads approvals only from `approval.md` on origin/main.
- `./zn approve` never merges, or changes the state of, a prep pull request.
- `./zn approve` does not retry a failed publish or push on its own.
- What an approval records and who may approve stay as c0283 left them.

## Solution
- When the design it approves is already on origin/main, one `./zn approve <id>` records the approval and publishes `approval.md` to origin/main (what `--publish` does today), so ready counts it at once with no second command.
- When the design is on an unmerged prep branch, one `./zn approve <id>` commits `approval.md` to that branch, pushes it so the prep pull request carries it, and prints that the approval counts when that pull request merges.
- When the publish or push fails, the approval stays recorded locally, and the command prints that it does not count yet and names the one command that retries it, `./zn approve <id> --publish`; it counts once that retry succeeds.
- `--publish` stays as that retry and `--check` behaves as it does today.
- The c0283 approve specs this changes are listed under Overrides, and the issue depends on c0283 being done.
