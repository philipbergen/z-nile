# c0369: Approve publishes by default

## Problem
./zn approve <id> needs a second manual command, ./zn approve <id> --publish, before the approval counts (ready reads approval.md on origin/main), and the user asked why (2026-11-15: "./zn approve f0211 should absolutely publish, why would I want an extra manual step"). What should happen: one ./zn approve <id> records the approval and makes it count without a second command. When the design it approves is already on origin/main, it publishes approval.md to origin/main itself (what --publish does today). When the design is on an unmerged prep branch, it commits approval.md and pushes that branch so the prep PR carries it, and says so. If publishing or pushing fails, the approval stays recorded locally and the command says which one command retries it. --publish stays as that retry and --check is unchanged. Changes c0283's approve behaviour and its specs (Overrides); depends on c0283 being done.
