# c0371: Check paths reads homes right

## Problem
- z-nile's full gate is red on main on `tests/acceptance/c0120/check-paths.spec.luau` since preps f0201 (#392) and c0292 (#414) merged on 2026-11-15, although both `check.sh` files are right.
- The spec refuses a path read from the item's home (arcade's `src/shared/Logic/PaidPlay/init.luau`, `tests/unit/PaidPlay`) when the Touched entry that covers it is written as a repo path (`arcade/src/shared/Logic/PaidPlay`).
- The spec reads a command after `cd "$ZN_ROOT"` from the item's home, so c0292's `(cd "$ZN_ROOT" && lune run z-nile/roots -- --luau-dirs)` is reported as `z-nile/roots` and `z-nile/roots.luau` missing from `z-nile/`.
- The spec reads quoted text searched for by a helper other than `grep` or `rg` as a path (c0292's `has "$L" ... "`tests/run`"`).
- The red spec blocks every finish whose watch selects it (R0099's c0263 layer).

Scope decision (user, 2026-11-15): "c0371 absorbs c0141 (Recommended)": unfold c0141 from R0062 into c0371, and c0371 adopts c0141's module, API and per-issue reading, and adds its own other rules.
Scope decision (user, 2026-11-15): "Full scope (Recommended)": the search-helper rule detects a check's search helpers from their definitions in the same check.sh (has, g, words, has_all) and reads their quoted arguments as text across line continuations.
Scope decision (user, 2026-11-15): "Capture its own issue (Recommended)": finished.spec's misreadings are c0374, not c0371.

## Non-goals
- finished.spec's misreadings of check.sh files are c0374 ("finished-spec-reads-homes-right"), not c0371.
- No `check.sh` of f0201, c0292 or any other item is edited to make the spec pass.
- No path is looked up from a second place when it is missing from where its command runs, so c0120 AC11 keeps reporting every case it reports today.
- The way items write their Touched entries does not change.
- d0362 is not reopened, since it no longer reproduces after #388.

## Solution
- A path in a check that is missing from where its command runs passes when a Touched entry covers it, whether that entry is written as a repo path or as a path from the item's home.
- A path in a command that follows `cd "$ZN_ROOT"` in the same command list or subshell is looked up from the repo root, and every other path is looked up from the item's home only.
- Quoted text passed to a check's own search helper, as c0292's `has` is, is not read as a path.
- A path that is missing from where its command runs (the item's home, or the repo root after a cd there) and is covered by no Touched entry is still reported, even when it exists somewhere else in the repository.
- The spec's fixture still reports z-nile's `test -f src/server` although `pickman/src/server` exists, and reports a z-nile check that runs `git diff --quiet -- scripts/…` with no cd when that path is missing from `z-nile/`.
- `tests/acceptance/c0120/check-paths.spec.luau` passes on main with f0201's and c0292's `check.sh` files unchanged, and z-nile's full gate is green.

**The reader's other rules (c0371's part).** All in `checkpaths.luau`; `experiments/checkpaths.diff` is the prototype's diff against c0141's prototype module, and the prototype is green on today's main (c0120's spec 4/4 on the live tree, c0141's two specs 5/5, c0371's homes spec 16 cases).
1. `literals(text): { Lit }`, `type Lit = { path: string, root: boolean }`; `scan` looks a literal up from `if lit.root then "." else home`, compares `repoPath(from, path)` with the owned entries, and reports `<path> (from the repository root)` or `(from <home>)`. c0120's first case reads `lit.path`.
2. **The quoting** (`quoting(text)`), one pass over the whole text: `ctx[i]` is 0 at the top level and a fresh number inside each single-quoted string (a `bash -c '…'` script is a context of its own; the `'"'"'` and `'\''` idioms continue the same script), `dq[i]` is true inside double quotes of that context. **A comment (a `#` that begins a word, at the top level outside quotes) changes nothing** (review 002 F1: an apostrophe in the template's own line 6, "its project's", is in 198 of the 240 live check.sh files). A backslash escapes the next byte outside single quotes, and inside a script every byte but `'`.
3. **Root cd (rule R).** A word after `cd "$ZN_ROOT"`, `cd "$ZN_ROOT/<sub>"` (then `<sub>/` is the prefix) or `cd "$(git rev-parse --show-toplevel)"` is read from the repository root. The reading is a slot: a **top-level cd** (context 0) holds to the end of the file, for the words after it and for every script it starts (a child runs where its parent does), until the group that holds it closes; a cd **inside a script** holds in that script only. A group closes at a `)` outside quotes, a `)` that closes a `$(` inside double quotes, or a `}` closing a `{` counted after the cd; **every byte of every line is read in order, the bytes after a line's last word and lines with no words included** (review 002 F2). Parentheses in quotes are not counted. A literal `cd <dir>` after a root cd goes on from the root (`<dir>/` appended). Every other path is read from the home only.
4. **Search helpers (rule H, full scope).** `searchHelpers(text)` finds the functions the check.sh defines (`name() {` on one line or to the closing `}` line) whose body runs `grep`, `egrep` or `rg`, or calls such a function (c0292's and c0256's `has`, c0264's `words` and `has_all`, `g() { grep -qF -e "$1" "$2" … }`). In command position, a call of one makes the quoted words of its arguments text until the command ends (`;`, `&&`, `||`, `|`, a closing parenthesis, a line end not continued by a backslash); quoted means inside double quotes the call is not in, or inside a single-quoted string (c0264's `words "$F" 'a `tests/run` b'`). A bare word argument is still read, and a function that does not search is no helper. Cost, taken on purpose: a quoted literal file path given to a helper is not read (a check passes its files as variables).
5. **Command position** (rules H, E, G): the first word of a command (after `;`, `&&`, `||`, `|`, `(`, a backtick, or a line start not continued by a backslash; **a continued line whose gap holds an operator also starts a command**), after `then do else if elif while until ! { } time xargs env command exec`, **after `check` (the command it runs follows its label)**, or after `-c`. `grep` and `rg` get the same condition as echo (their pattern rule was keyed on the bare word, so `foo "grep" tests/gone.md` marked the next word).
6. **Code spans (rule S).** The words between an opening and a closing backslash-backtick of one **double-quoted** argument are text; the ticks are paired in order and an unpaired last tick opens nothing.
7. **Echo and printf (rule E).** In command position, the message (the first argument after options, to its closing quote) is text, **stopping at a `$(` or a backtick** (the words inside a substitution are commands), and **a message of one word is a value and is read** (`echo tests/acceptance/c0077/x.spec.luau` returns a path; c0099's spec locator). Found by the prototype, not in the capture: c0292's `echo "z-nile/roots --luau-dirs no longer lists z-nile/.tracker"` was the fourth misreading that kept the live scan red.
8. **A `for` list that is only matched (rule L).** The words of `for NAME in WORDS; do BODY done` are text when BODY uses `$NAME` only as text to match: inside a glob pattern (`*"$NAME"*`), as grep's **pattern** (the first non-option word, or the word after `-e`; **its file operand is a use**), or in an echo/printf message. The body ends at the loop's own `done`, found by words outside quotes with nested `for`/`while`/`until` counted, **and a loop that never uses its variable is read as files**. c0193's `for f in z-nile/engine/scan.luau …; do case "$E" in *"$f"*) …; esac; done` (active raft R0072, contract approved) is covered by the rule, not by an edit: with c0141's reading its four words are no longer exempt by equality with its Touched entries.
9. Restated rules: `z-nile/skills/zz-test/SKILL.md` line 78 gains: "The scan reads a command after `cd "$ZN_ROOT"` from the repository root, to the end of the group or script that holds the cd (a top-level cd holds for the scripts it starts); the quoted arguments of a search helper the check defines (a function that runs grep or rg), a word inside a code span, an `echo` or `printf` message in command position, and the list of a `for` loop that only matches text are prose, not paths." `z-nile/tests/inputs.tsv` gains `tests/acceptance/c0371/check-paths-homes.spec.luau<TAB>*` (the spec's live case reads the whole tree). AC6 pins the phrases and the line.

**No behaviour change** for players or for the gate outside the scan. **Existing work.** Every rule makes the scan report less except R, which reads a path after a root cd from the root, and the position and loop rules, which read a few words main marked or exempted (review 002 F4 to F6 ran them: R0016's `check "…" grep …` and `| grep` continuations are still marked; a one-word echo and an echo with `$(…)` are read as main reads them). The live tree passes (E1); the finished corpus's three real cases of an apostrophe in a label are reported again (case F1). Open worktrees: E5. **Shared state:** `tests/inputs.tsv` is shared (one line added; the executor re-reads main). **Guards:** the scan only reads and fails closed (a missing path is reported; text the reader cannot place stays a path). **Moves:** the scanner's move is its own commit.

### Scalability
One pass over the text for the quoting, one over its lines; the loop and helper lookups scan from a word on, bounded by the file (a few KB). The live scan takes 0.2 s.

### Maintainability
One module, one reader; the three specs of the item and c0120's spec all run on it. Every rule is a small mark in one word loop with its case and mutant in the homes spec; the quoting and the per-slot root reading are the only states carried across words.

### Usability
A check.sh author writes shell naturally: multi-line scripts with a cd to the root, search helpers with quoted text, messages that name files, a `for` over files to find in a text, Touched entries in either convention. The report names where a path was looked up.
