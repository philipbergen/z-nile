# c0371: Check paths reads homes right

## Problem
- z-nile's full gate is red on main on `tests/acceptance/c0120/check-paths.spec.luau` since preps f0201 (#392) and c0292 (#414) merged on 2026-11-15, although both `check.sh` files are right.
- The spec refuses a path read from the item's home (arcade's `src/shared/Logic/PaidPlay/init.luau`, `tests/unit/PaidPlay`) when the Touched entry that covers it is written as a repo path (`arcade/src/shared/Logic/PaidPlay`).
- The spec reads a command after `cd "$ZN_ROOT"` from the item's home, so c0292's `(cd "$ZN_ROOT" && lune run z-nile/roots -- --luau-dirs)` is reported as `z-nile/roots` and `z-nile/roots.luau` missing from `z-nile/`.
- The spec reads quoted text searched for by a helper other than `grep` or `rg` as a path (c0292's `has "$L" ... "`tests/run`"`).
- The red spec blocks every finish whose watch selects it (R0099's c0263 layer).

Scope decision (user, 2026-11-15): "c0371 absorbs c0141 (Recommended)": unfold c0141 from R0062 into c0371, and c0371 adopts c0141's module, API and per-issue reading, and adds its own other rules.
Scope decision (user, 2026-11-15): "Full scope (Recommended)": the search-helper rule detects a check's search helpers from their definitions in the same check.sh (has, g, words, has_all) and reads their quoted arguments as text across line continuations.
Scope decision (user, 2026-11-15): "Capture its own issue (Recommended)": finished.spec's misreadings are c0374, not c0371.

## Non-goals
- finished.spec's misreadings of check.sh files are c0374 ("finished-spec-reads-homes-right"), not c0371.
- No `check.sh` of f0201, c0292 or any other item is edited to make the spec pass.
- No path is looked up from a second place when it is missing from where its command runs, so c0120 AC11 keeps reporting every case it reports today.
- The way items write their Touched entries does not change.
- d0362 is not reopened, since it no longer reproduces after #388.

## Solution
- A path in a check that is missing from where its command runs passes when a Touched entry covers it, whether that entry is written as a repo path or as a path from the item's home.
- A path in a command that follows `cd "$ZN_ROOT"` in the same command list or subshell is looked up from the repo root, and every other path is looked up from the item's home only.
- Quoted text passed to a check's own search helper, as c0292's `has` is, is not read as a path.
- A path that is missing from where its command runs (the item's home, or the repo root after a cd there) and is covered by no Touched entry is still reported, even when it exists somewhere else in the repository.
- The spec's fixture still reports z-nile's `test -f src/server` although `pickman/src/server` exists, and reports a z-nile check that runs `git diff --quiet -- scripts/…` with no cd when that path is missing from `z-nile/`.
- `tests/acceptance/c0120/check-paths.spec.luau` passes on main with f0201's and c0292's `check.sh` files unchanged, and z-nile's full gate is green.

**What c0371 changes** (all in `z-nile/tests/acceptance/c0120/checkpaths.luau`, `experiments/checkpaths.diff` is the prototype's diff against c0141's prototype module, 46f7d115; the spec's first case reads `lit.path`):
1. `literals(text): { Lit }` with `type Lit = { path: string, root: boolean }`; `scan` looks a literal up from `if lit.root then "." else home` and reports `<path> (from the repository root)` or `(from <home>)`.
2. **The quoting** (`quoting(text)`): one pass over the whole text gives every byte its context (`ctx`: 0 at the top level, a fresh number inside each single-quoted string, so a `bash -c '…'` script is a context of its own) and whether it is inside double quotes (`dq`). Backslash escapes the next byte outside single quotes.
3. **Root cd (rule R, F2).** A word after `cd "$ZN_ROOT"`, `cd "$ZN_ROOT/<sub>"` (then `<sub>/` is the prefix) or `cd "$(git rev-parse --show-toplevel)"` is read from the repository root, over the following lines, until (a) a `)` outside quotes (or a `)` that closes a `$(` inside double quotes) or `}` closes the group that held the cd, or (b) the script (single-quoted context) that held it ends; a top-level cd lasts to the end of the file. Parentheses inside quotes are not counted. A literal `cd <dir>` after a root cd goes on from the root (`<dir>/` is appended). Every other path is read from the home only.
4. **Search helpers (rule H, F3 full scope).** `searchHelpers(text)` finds the functions the check.sh defines (`name() {` on one line or to the closing `}` line) whose body runs `grep`, `egrep` or `rg`, or calls such a function (c0292's and c0256's `has`, c0264's `words` and `has_all`, the `g() { grep -qF -e "$1" "$2" … }` shape). In command position, a call of such a function makes the quoted words of its arguments text, until the command ends (`;`, `&&`, `||`, `|`, a closing parenthesis, a line end not continued by a backslash); quoted means inside double quotes the call is not in, or inside a single-quoted string (c0264's `words "$F" 'a `tests/run` b'`). A bare word argument is still read as a path, and a function that does not search (`typecheck() { lune run "$1"; }`) is not a helper. Cost, taken on purpose: a quoted literal file path given to a helper is not read (a check passes its files as variables).
5. **Code spans (rule S, F5).** Every word between an opening and a closing backslash-backtick (a Markdown code span inside a quoted argument) on a line is text.
6. **Echo and printf (rule E, F4).** The message (the first argument after options, to its closing quote) of an `echo` or `printf` in **command position** is text. Command position: the first word of a command (after `;`, `&&`, `||`, `|`, `(`, `` ` `` or a line start not continued by a backslash), after `then`, `do`, `else`, `if`, `elif`, `while`, `until`, `!`, `{`, `}`, `time`, `xargs`, `env`, `command`, `exec`, or after `-c` (`bash -c 'echo "…"'`). `grep` and `rg` get the same condition (their pattern rule was keyed on the bare word, so `foo "grep" tests/gone.md` marked the next word). Found by the prototype, not in the capture: c0292's `echo "z-nile/roots --luau-dirs no longer lists z-nile/.tracker"` was the fourth misreading that kept the live scan red.
7. **A `for` list that is only matched (rule L).** A word in `for NAME in WORDS; do BODY done` is text when BODY uses `$NAME` only as a pattern to match (`*"$NAME"*` in a `case` or `[[ ]]`, a `grep` pattern) or in an `echo` message: c0193's `for f in z-nile/engine/scan.luau …; do case "$E" in *"$f"*) …; esac; done` names four engine files only to see that a lesson names them. With c0141's reading they would be read as `z-nile/z-nile/engine/scan.luau` (a Touched entry written as a repo path covered them by equality before) and the live scan reports them (E2). c0193 is in active raft R0072 with an approved contract, so its `check.sh` is not edited: a rule covers it. A loop that opens `"$f"` as a file is still read.
8. `z-nile/skills/zz-test/SKILL.md` line 78 gains the sentence below (the restated rule); `z-nile/tests/inputs.tsv` gains the line `tests/acceptance/c0371/check-paths-homes.spec.luau<TAB>*` (the spec's live case reads the whole tree: lesson z-design/declare-what-full-runs-covered); c0120's spec has no edit but its first case (`got` from `lit.path`) and its header comment.

The sentence for zz-test: "The scan reads a command after `cd "$ZN_ROOT"` from the repository root, to the end of the group or script that holds the cd; the quoted arguments of a search helper the check defines (a function that runs grep or rg), a word inside a code span, an `echo` or `printf` message in command position, and the list of a `for` loop that only matches text are prose, not paths." AC4 pins its phrases.

**No behaviour change** for players or for the gate outside the scan. **Existing work:** every rule makes the scan report less except R, which reads a path after a root cd from the root. The live tree has none that turns red (E4); open worktrees: E5 (68 stale trees report only plain missing paths of older states, none through R, H, S, E or L). c0293, c0283 and the others on the E5 list are older trees, not new reds. **Shared state:** `tests/inputs.tsv` is shared (a line added; the executor re-reads main). **Guards:** the scan reads only; it fails closed (a missing path is reported, a quoting it cannot read leaves words as paths).

### Scalability
One pass over the text for the quoting, one over its lines for the words; the loop and the helper lookups scan the text from a word on, bounded by the file (check.sh files are a few KB). The live scan took 0.2 s with it.

### Maintainability
One module, one reader, both c0141's and c0371's specs on it. The rules are small marks in one word loop (text marks first, path reading after); each has its case and mutant in c0371's spec.

### Usability
A check.sh author writes shell naturally: multi-line scripts with a cd to the root, search helpers with quoted text, messages that name files, a `for` over files to find in a text. The report names where a path was looked up (`from the repository root`).
