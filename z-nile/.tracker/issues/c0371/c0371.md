# c0371: Check paths reads homes right

## Problem
- z-nile's full gate is red on main on `tests/acceptance/c0120/check-paths.spec.luau` since preps f0201 (#392) and c0292 (#414) merged on 2026-11-15, although both `check.sh` files are right.
- The spec refuses a path read from the item's home (arcade's `src/shared/Logic/PaidPlay/init.luau`, `tests/unit/PaidPlay`) when the Touched entry that covers it is written as a repo path (`arcade/src/shared/Logic/PaidPlay`).
- The spec reads a command after `cd "$ZN_ROOT"` from the item's home, so c0292's `(cd "$ZN_ROOT" && lune run z-nile/roots -- --luau-dirs)` is reported as `z-nile/roots` and `z-nile/roots.luau` missing from `z-nile/`.
- The spec reads quoted text searched for by a helper other than `grep` or `rg` as a path (c0292's `has "$L" ... "`tests/run`"`).
- The red spec blocks every finish whose watch selects it (R0099's c0263 layer).

Scope decision (user, 2026-11-15): "c0371 absorbs c0141 (Recommended)": unfold c0141 from R0062 into c0371, and c0371 adopts c0141's module, API and per-issue reading, and adds its own other rules.
Scope decision (user, 2026-11-15): "Full scope (Recommended)": the search-helper rule detects a check's search helpers from their definitions in the same check.sh (has, g, words, has_all) and reads their quoted arguments as text across line continuations.
Scope decision (user, 2026-11-15): "Land with known edges (Recommended)": the reader models only the shell forms the Design names; each unmodelled form is a listed known edge, checked against the live and finished corpora (experiment E8), and the Design no longer claims the scan fails closed.
Scope decision (user, 2026-11-15): "Capture its own issue (Recommended)": finished.spec's misreadings are c0374, not c0371.

## Non-goals
- finished.spec's misreadings of check.sh files are c0374 ("finished-spec-reads-homes-right"), not c0371.
- No `check.sh` of f0201, c0292 or any other item is edited to make the spec pass.
- No path is looked up from a second place when it is missing from where its command runs, so c0120 AC11 keeps reporting every case it reports today.
- The way items write their Touched entries does not change.
- d0362 is not reopened, since it no longer reproduces after #388.

## Solution
- A path in a check that is missing from where its command runs passes when a Touched entry covers it, whether that entry is written as a repo path or as a path from the item's home.
- A path in a command that follows `cd "$ZN_ROOT"` in the same command list or subshell is looked up from the repo root, and every other path is looked up from the item's home only.
- Quoted text passed to a check's own search helper, as c0292's `has` is, is not read as a path.
- A path that is missing from where its command runs (the item's home, or the repo root after a cd there) and is covered by no Touched entry is still reported, even when it exists somewhere else in the repository.
- The spec's fixture still reports z-nile's `test -f src/server` although `pickman/src/server` exists, and reports a z-nile check that runs `git diff --quiet -- scripts/…` with no cd when that path is missing from `z-nile/`.
- `tests/acceptance/c0120/check-paths.spec.luau` passes on main with f0201's and c0292's `check.sh` files unchanged, and z-nile's full gate is green.

**The reader (c0371's part).** The reader models only the shell forms named here (user's ruling: "Land with known edges"); every other form is in **Known edges** below, and the Design does **not** claim the scan fails closed: text the reader cannot place is read as main reads it, a path. All in `checkpaths.luau`; `experiments/checkpaths.diff` is the prototype's diff against c0141's prototype module. The prototype is green on today's main (c0120's spec 4/4 on the live tree, c0141's two specs 5/5, the homes spec 22 cases).
1. `literals(text): { Lit }`, `type Lit = { path: string, root: boolean }`; `scan` looks a literal up from `if lit.root then "." else home`, compares `repoPath(from, path)` with the owned entries, and reports `<path> (from the repository root)` or `(from <home>)`. c0120's first case reads `lit.path`.
2. **The quoting** (`quoting(text)`), one pass over the whole text: `ctx[i]` is 0 at the top level and a fresh number inside each single-quoted string (a `bash -c '…'` script is a context of its own; the splices `'"'"'`, `'\''` and `'"$X"'` continue the same script); `dq[i]` is true inside double quotes of that context; a `$(` opens a level of its own, inside which quotes are quotes again, and its `)` closes it. **A comment** (a `#` that begins a word at the top level outside quotes), **a heredoc body** (from the line after `<<WORD`, `<<-WORD`, `<<'WORD'` to the line that is the word), and **a `$'…'` string** change no state. A backslash escapes the next byte outside single quotes, and inside a script every byte but `'`.
3. **Root cd (rule R) and directory frames.** A word after `cd "$ZN_ROOT"`, `cd "$ZN_ROOT/<sub>"` (then `<sub>/` is the prefix) or `cd "$(git rev-parse --show-toplevel)"` is read from the repository root, over the following lines. Directories form **frames**, as in bash: a `(` outside quotes (a subshell, or a `$(` level) pushes a copy of the current frame and its `)` pops it; a single-quoted script starts from a copy of the top-level frame (a child runs where its parent does) and keeps its own stack; a cd changes the top frame only; a literal `cd <dir>` after a root cd goes on from the root (`<dir>/` appended) and ends with its frame. **A brace group pushes nothing: its cd holds after the `}` (bash runs it in the current shell).** A function body (`name() {`) restores the frame at its `}`. A `)` that ends a `case` pattern pops nothing. **Every byte of every line is read in order, the bytes after a line's last word and lines with no words included.** A cd inside a double-quoted string is not a cd to the root (known edge). Every other path is read from the home only.
4. **Search helpers (rule H, full scope).** `searchHelpers(text)` finds the functions the check.sh defines (`name() {` to its matching `}`) whose body passes a positional parameter (`$1`…, `"$@"`, `"$*"`, or the variable of `for w in "$@"`) as the **pattern** of `grep`, `egrep` or `rg`, or as an argument to another such function (c0292's and c0256's `has`, c0264's `words` and `has_all`, `g() { grep -qF -e "$1" "$2" … }`). A function that greps its own output (`passes() { … | grep -q " 0 failed"; }`) or names grep in a message is none. In command position, a call of a helper makes the quoted words of its arguments text until the command ends (`;`, `&&`, `||`, `|`, a closing parenthesis, a line end not continued by a backslash); quoted means inside double quotes the call is not in, or inside a single-quoted string (c0264's `words "$F" 'a `tests/run` b'`). A bare word argument is still read. Cost, taken on purpose: a quoted literal file path given to a helper is not read (a check passes its files as variables).
5. **Command position** (rules H, E, G, L): the first word of a command (after `;`, `&&`, `||`, `|`, `(`, a backtick, or a line start not continued by a backslash; a continued line whose gap holds an operator also starts a command), after `then do else if elif while until ! { } time xargs env command exec nice nohup sudo`, after `check` (its label is blanked wherever `check` stands, so the command it runs follows), after `-c`, after `timeout <n>`, and after `NAME=value` assignments that precede a command (`LC_ALL=C grep …`). `grep` and `rg` get the same condition as echo (their pattern rule was keyed on the bare word, so `foo "grep" tests/gone.md` marked the next word).
6. **Code spans (rule S).** The words between an opening and a closing backslash-backtick of one **double-quoted** argument are text; the ticks are paired in order and an unpaired last tick opens nothing.
7. **Echo and printf (rule E).** In command position, the message (the first argument after options, to its closing quote) is text, **stopping at a `$(` or a backtick**, and **a message of one word is a value and is read** (`echo tests/acceptance/c0077/x.spec.luau` returns a path). Found by the prototype, not in the capture: c0292's `echo "z-nile/roots --luau-dirs no longer lists z-nile/.tracker"` was the fourth misreading that kept the live scan red.
8. **A `for` list that is only matched (rule L).** The words of `for NAME in WORDS; do BODY done` are text when BODY uses `$NAME` (or `${NAME}`) only as text to match: inside a glob pattern (`*"$NAME"*`), as grep's **pattern** (the first non-option word, or the word after `-e`; **its file operand is a use**), in an echo message of several words, or in a printf **format** (`echo "$f"` and `printf '%s\n' "$f"` print a value and are uses). The body ends at the loop's own `done`: a keyword (command position, same context, outside quotes and comments), with nested `for`/`while`/`until` counted; a loop that never uses its variable is read as files. c0193's `for f in z-nile/engine/scan.luau …; do case "$E" in *"$f"*) …; esac; done` (active raft R0072, contract approved) is covered by the rule, not by an edit: with c0141's reading its four words are no longer exempt by equality with its Touched entries.
9. Restated rules: `z-nile/skills/zz-test/SKILL.md` line 78 gains: "The scan reads a command after `cd "$ZN_ROOT"` from the repository root, to the end of the subshell, command substitution, script or function body that holds the cd (a top-level cd holds for the scripts it starts); the quoted arguments of a search helper the check defines (a function that passes a positional parameter to grep or rg), a word inside a code span, an `echo` or `printf` message in command position, and the list of a `for` loop that only matches text are prose, not paths." `z-nile/tests/inputs.tsv` gains `tests/acceptance/c0371/check-paths-homes.spec.luau<TAB>*` (the spec's live case reads the whole tree). **Known edges (user's ruling).** The reader is hand-written and models the forms above; review rounds do not prove such a reader, so it is measured against the corpus (E8: 463 check.sh files, 241 live and 223 finished; against main's reader it loses 35 literals, 13 of them would-be reports, all prose or the three intended fixes below, and gains 0; no check.sh edited). An unmodelled form fails open or as main did:
- a function that cds to the root, called later (`toroot() { cd "$ZN_ROOT"; }` then `toroot`): the call is not followed; the later words are read from the home (as main).
- a cd inside a double-quoted script (`bash -c "cd …"`): not a cd to the root; words read from the home (as main). A plain splice `'…'$X'…'` (no double quotes) ends the script's context.
- a `case` pattern's `)` after a `;;`, `in` or at a line start is told by a text test; other shapes pop a frame early (the rest of that frame read from the home).
- backtick command substitutions are not frames; `$((…))`, `eval`, `source`, `find -exec`, `xargs sh -c` are not followed.
- heredocs inside `$(…)` or inside a script, and `<<` with trailing text on the terminator line; `$'…'` inside double quotes.
- search helpers are found only as `name() {` in the same file; `function name {`, sourced helpers, a pattern held in a variable (`pat=$1; grep "$pat"`), or a helper reached through `eval` are not; a quoted literal file argument of a helper is not read.
- command position: introducers other than the list (`timeout -s KILL 10 grep`, `env -i`, `sudo -u x`).
- rule L: `select`, a `for` list spanning lines, the variable reached through indirection or another name.
- code spans over more than one line.
- a root reading after a `(` inside `[[ x =~ (a|b) ]]` regexes that are unbalanced.
E8 shows the corpus result for the reader as a whole; per form, the corpus has no case where the form changes a report (the 13 would-be reports lost are: c0193's four words (rule L), c0292's four (rules R, E, H: its root cd and its echo message and its `has` arguments), c0083's three (restamped, exempt anyway; rule L and H), d0297's one and R0013's one (echo messages)). The Design's earlier "fails closed" is withdrawn.

**No behaviour change** for players or for the gate outside the scan. **Existing work.** The live tree passes (E1); the finished corpus's reports are unchanged except the 13 above (E8); E5 over open worktrees. **Shared state:** `tests/inputs.tsv` is shared (one line added; the executor re-reads main). **Guards:** the scan only reads and fails closed in one sense only: a path missing from where its command runs, which the reader reads as a path, is reported; text it misreads is a Known edge. **Moves:** the scanner's move is its own commit.

### Scalability
One pass over the text for the quoting, one over its lines; the loop and helper lookups scan from a word on, bounded by the file (a few KB). The live scan takes 0.2 s.

### Maintainability
One module, one reader; the three specs of the item and c0120's spec all run on it. Every rule is a small mark in one word loop with its case and mutant in the homes spec; the quoting pass and the frame stacks are the only states carried across words. A hand-written reader is measured against the corpus (E8), not proved by review.

### Usability
A check.sh author writes shell naturally: multi-line scripts with a cd to the root, search helpers with quoted text, messages that name files, a `for` over files to find in a text, Touched entries in either convention. The report names where a path was looked up.
