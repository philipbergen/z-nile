# c0371: Check paths reads homes right

## Problem
z-nile's full gate is red on main on tests/acceptance/c0120/check-paths.spec.luau ('every unfinished item's check.sh ... names only paths that exist from its home') since preps f0201 (#392) and c0292 (#414) merged, 2026-11-15 10:26-10:30 PST; both checks are right and the spec misreads them three ways. (1) The Touched-modules exemption compares a path read from the item's home (arcade's src/shared/Logic/PaidPlay/init.luau, tests/unit/PaidPlay) with Touched entries written as repo paths (arcade/src/shared/Logic/PaidPlay), which is how almost every item writes them, so an item's check naming the files its own work creates is refused outside the repo root. (2) A command after cd "$ZN_ROOT" is still read from the home: c0292's (cd "$ZN_ROOT" && lune run z-nile/roots -- --luau-dirs) is reported as z-nile/roots and z-nile/roots.luau missing from z-nile/. (3) Quoted text a check searches for with a helper other than grep/rg (c0292's has "$L" ... "\`tests/run\`") is read as a path. It blocks every finish whose watch selects the spec (R0099's c0263 layer, 2026-11-15). What should happen: the three cases pass, a missing path is still caught, and main's full gate is green again. d0362 (same spec, c0283's zn find fallback) no longer reproduces since #388 prefixes $PWD.
