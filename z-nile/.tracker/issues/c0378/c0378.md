# c0378: Checkpaths reader three rules

## Problem
- After a cd to the repo root, c0371's check-paths reader keeps the root reading across any later cd whose argument is neither a root form nor a literal folder (`cd -`, `cd "$OLDPWD"`, `cd "$VAR"`, `cd "$(…)"`), so it reports a path that main's reader does not.
- c0371's reader reads a root cd inside backticks as a root cd, so it reports a path that main's reader does not.
- c0371's reader reads a function written as `function name {`, or as `name()` with the brace on the next line, as a brace group and not a function body, so it reports a path that main's reader does not.

## Non-goals
- This does not change any Known edges entry other than the three that describe these shapes.
- This does not change c0371's own design or its landing, which keeps its Known edges list as ruled.
- This does not add any of the shapes to the corpus of check.sh texts, since none appears in today's 585 distinct texts.

## Solution
- A cd whose argument is neither a root form nor a literal folder resets its frame to the item's home, for every such argument including `cd -`, `cd "$OLDPWD"`, `cd "$VAR"` and `cd "$(…)"`.
- A root cd inside backticks is not read as a root cd, so the reader reports what main's reader reports for it.
- `function name {` and `name()` with the brace on the next line are both read as function bodies.
- Each of the three rules has a spec case and a mutant that the case fails for.
- c0371's E8 corpus comparison still shows no report gained or lost against main.
- The reader's Known edges list no longer carries the entry for any of the three shapes, and the cd entry is removed whole, not shortened.
