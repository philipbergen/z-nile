# c0381: Checkpaths reader review edges

## Problem
c0120's check-paths reader (z-nile/tests/acceptance/c0120/checkpaths.luau, c0371) misreads four shell shapes that R0112's code review 001 found (F2, F3, F4) and that c0371's Known edges do not list: (1) a search helper's call ends at a $( or backtick inside its own argument, so later quoted arguments are read as paths (has "$(./zn find c0292)/c0292.md" "tests/run is named" reports tests/run; main reads it the same way); (2) a cd "$ZN_ROOT" inside a heredoc body moves the top-level frame, so a later home path is read from the root; (3) $(( 1 << 2 )) is taken for a heredoc start, which freezes the quoting; (4) a quoted lone { inside a function body is pushed as a brace group, so the function's root cd survives its }, and grep -q "^$f$" in a for loop counts as a use although the Design calls a grep pattern text. None is in the corpus E8 reads. What should happen: each shape is read as bash runs it, or is added to the Known edges with its outcome, with a case and a mutant each.
