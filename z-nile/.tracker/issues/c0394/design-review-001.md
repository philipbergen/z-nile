### F1 [high] Restack conflicts in the user's own T2:T1 flow: the folder `start` carries clashes with the stub in T1's finish commit, and E6's fallback cannot avoid it
Where: Design §2 **start** ("brings the folder as that layer's first commit … `restack` drops the commits above that have become empty"); Unknowns E6; `part-land.spec.luau:376-407`; `main.luau` `cmd.finish` (`git reset --soft base`, squashing the whole layer) and `cmd.restack` (`git rebase --onto`, "stop at the first conflict").

E6's fallback (a `tracker: carry` commit on the upper layer that removes the folder) comes after the finish commit, and the replay conflicts on the finish commit first. Critique: The mechanism that makes "in front" work is unproven, and its recorded fallback fails. The tempting fix is "resolve with `-X theirs`", which would also silently overwrite real conflicts in T1's own code.
Consequences: Any fix changes what a layer's history may hold. A move rewrites layer 1, so its checks rerun and its pull request diff changes. Recommendation: Pick one mechanism and prove it in prep with the probe above (it runs in seconds). Record it as E6's result and add a Rules row for it. Options:
