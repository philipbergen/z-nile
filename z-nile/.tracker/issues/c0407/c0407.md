# c0407: Commit phase spec session note

## Problem
- The promoted case 'done records its own commit as deliver, and the raft summary shows each phase' in `z-nile/tests/acceptance/c0084/commit-phase.spec.luau` fails on origin/main's slow tier because it expects the deliver row's subject to be exactly `R0010: bind f0010, f0020`, while `done` has since #318 appended the session note to the first row's subject.

## Non-goals
- No file other than `z-nile/tests/acceptance/c0084/commit-phase.spec.luau` changes, and every other case in that file stays as it is.

## Solution
- The case passes on origin/main's slow tier by accepting the deliver row's subject only when it equals `R0010: bind f0010, f0020` exactly or that subject followed by one space and the note `done` prints as `session: <note>`, while still asserting that the row's phase is deliver and that the raft summary shows each phase.

## Design
**What #318 changed, read from the code (2026-11-17, origin/main).**
- `cmd.done` (`z-nile/engine/main.luau`, ~4775-4800): it prints `session: {reading.note}` on stdout when a session reading exists, and gives the reading to the first spend row it writes (`gaveReading`), appending it to that row's subject as `subject ..= " " .. reading.note` when the note is not empty. The note comes from `sessions.combine` (`z-nile/engine/sessions.luau:230-270`): `"<cli> unmeasured"` or `"<cli> tokens=…"` per CLI, joined by `"; "`. So the deliver row of the first issue (`f0010`) reads `R0010: bind f0010, f0020 claude unmeasured; grok unmeasured; agent unmeasured; kimi unmeasured` on this machine, and the case's `toBe(`{raft}: bind {a}, {b}`)` at line 284 fails (E1). The code is right; the promoted case is stale.
- The note's text depends on which CLIs the machine finds, so the case cannot hard-code it. It reads it from `done`'s own stdout instead.

**The change** (one file, `z-nile/tests/acceptance/c0084/commit-phase.spec.luau`): exactly `experiments/prototype.patch`, 9 lines added and 2 removed, byte for byte. AC2 pins the whole file as its merge base plus these two hunks, so the executor applies the patch and does not write the narrowing by hand:
1. Case `done records its own commit as deliver, and the raft summary shows each phase`: `must(tr({ "done", raft }), "done")` becomes a two-line `-- c0407 override:` comment, `local doneOut = must(tr({ "done", raft }), "done")` and `local note = string.match(doneOut, "session: ([^\n]*)")` (the `session: <note>` line `done` prints).
2. The same case's `t.expect(ra[#ra].subject).toBe(`{raft}: bind {a}, {b}`)` becomes: `subject` is `{raft}: bind {a}, {b}`, plus `" " .. note` when `note` is not nil and not empty; the assertion is `toBe(subject)`.
Every other line stays: the case still asserts that the last row of `f0010` is phase `deliver`, and that the raft summary has the header, `code-review`, `build` and `deliver` rows, not `777` or `1001`, and no `capture` row. The other six cases are untouched (AC1 runs all seven, AC2 pins the bytes).

**Why tied, not either-or.** The captured Solution accepts the plain subject or the plain subject plus one space and the printed note. **Guess (prep) G2**: the case accepts exactly the one of the two that matches what `done` printed so an engine that prints a note and drops it from the row fails (M2), and one that appends without the space fails (M1). When `done` prints no session line (no reading) the subject must be the plain one, as before #318. **Guess (prep) G1**: the suffix is the note alone, not the whole `session: <note>` line, because that is what `done` appends.

**No behaviour change.** No engine file changes: `cmd.done`, `sessions.combine` and the ledger keep their behaviour. The six other cases of the file pass on main today (E1) and stay byte for byte (AC2); after the change all seven pass (AC1).
