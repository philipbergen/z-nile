# c0440: Hook refuses cd then command

## Problem
- On 2026-11-21 a builder's command of the form `cd <folder>; <command>` twice ran its command in the original folder because the cd failed: once it started a gate in the main checkout, and once a script wrote 40 fake events and started a daemon in the main checkout's real live state.

## Non-goals
- The hook does not try to work out whether a command after a refused operator was meant to run in the original folder (for example after a subshell or `cd x || exit`): it refuses those too.

## Solution
- The command hook that already refuses unbounded and background commands also refuses a command line in which, read the way the shell reads it, any of the four operators ";", newline, "||" or a single "&" joins two commands anywhere after a cd, whether or not it comes straight after the cd.
- A command line with a cd is allowed only when every command after the cd is joined to it by an unbroken chain of "&&" steps, such as `cd x && make && ./zn gate`.
- A pipe inside one "&&" step is allowed, because the whole pipeline is skipped when the cd fails: `cd x && make | tail -5` is allowed.
- The refusal wins over "&&": `cd x && make; ./zn gate` and `cd x && make || ./zn gate` are both refused, because `./zn gate` would still run in the original folder when `cd x` fails.
- One of those operators inside quotes or inside a here-document body is not a separator: `cd x && git commit -m "fix; tidy"` and `cd x && cat > f <<EOF` followed by its body lines are both allowed.
- The refusal message says to use "&&" throughout or an absolute path.
