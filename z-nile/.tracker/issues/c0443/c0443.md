# c0443: Readme md points to html

## Problem
- `z-nile/README.md` still holds the full reference text, because documentation specs and `check.sh` files (landed ones and those of 31 unlanded tickets) check phrases in it and AGENTS.md calls it the map, so it is not the few short sentences and link to `z-nile/README.html` the owner asked for.

The owner's statement of the intent (2026-11-22), captured at their request ("please capture that, it was great clarity how I just wrote that"): "I am really excited about workers being able to optimistically forge ahead and me just approving or disapproving in the end, automaticaally picking up tickets, maturing idea nd design, rafting them and following the dependencies from the bottom. so that I can just sit with the UI and go through approvals. Moving the multitasking pain to the agents, my time looking linear, working through a theme at a time, a raft at a time, an idea and a design at a time". This is the measure for this ticket: the workers carry the parallel work and never wait on the owner; the owner's time is one linear pass through approvals, a theme, then a raft, then an idea and a design at a time. The same day the owner ranked dead or hung workers low ("manually fixing that is cheap").

## Non-goals
- This does not rewrite or restyle README.html's content, reword the reference text, or change what any other ticket's spec or `check.sh` asserts: the only changes to README.html are to its lines that say where the reference text lives, and the only change to another ticket's specs and `check.sh` files is the path of the file they read.

## Solution
- `z-nile/README.md` becomes a few short sentences and a link to `z-nile/README.html`; the reference text moves whole to one other file that the specs and skills read; AGENTS.md and every line in README.html that names README.md as the home of the reference text (its file list entry and its footer) point to that file; every phrase a spec or `check.sh` pins today is still pinned there; and this ticket itself repoints every acceptance spec and every `check.sh` of an unlanded ticket that reads `z-nile/README.md` to the new file (the active tickets c0121, c0257, c0265 and c0274–c0277, and the 24 backlog tickets c0175, c0178, c0247–c0254, c0256, c0258, c0260, c0262, c0263, c0267, c0280, c0282–c0284, c0316, c0394, f0339 and f0417), so that afterwards no spec or `check.sh` of any ticket, landed or not, reads the reference text from `z-nile/README.md`.
