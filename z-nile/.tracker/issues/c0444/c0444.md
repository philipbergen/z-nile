# c0444: House style for pages

## Problem
- The board page (`./zn board`, written to `.cache/board.html`) and the published board use their own colours and fonts, not those of philip-bergen.com.
- Some pages z-nile shows a person use purple, which the owner does not want; one case is the board's mixed-raft type colour `#7c3aed` (`z-nile/engine/board.html:32`).
- The board's chips show grey text on light grey, which the owner cannot read.
- No rule says which colour each status value gets, where a status value is one of five kinds: a risk level (`easy`, `normal`, `risky`), a stage (`new`, `preparing`, `prepared`, `active`, `done`), a type (`feature`, `defect`, `chore`, mixed), a row's readiness (ready, not ready, done) or a worker state (`working`, `idle`, `waiting`, `lost`).
- Because no such rule exists, a page moved to the site's colours can lose the distinct status colours the owner wants kept, or pick different ones from another page.
- `z-nile/README.html` and `z-nile/.tracker/issues/f0425/mockup/index.html` have a light theme, a warm dark theme and a theme button, but the board page, the published board and `z-nile/.tracker/issues/f0339/explainer.html` do not.
- No script checks the contrast of the text and background pairs these pages use, so legibility is judged by eye.

## Non-goals
- No page's content, structure, links or commands change; the only changes are colours, fonts, the layout shift the new fonts cause, and the theme button and dark theme added to the three pages that lack them.
- No status value is added, removed or renamed, and no page gains a status kind it does not show today (the board gains no risk chips).
- The theme button of `README.html` and the theme button and saved choice of the f0425 mockup are not removed and keep their behaviour.
- No page follows `prefers-color-scheme`, and no third theme is added.
- The philip-bergen.com site itself is not changed.

## Solution
- The site's colours and fonts are used by the board page, the published board, `README.html`, `z-nile/.tracker/issues/f0425/mockup/index.html`, `z-nile/.tracker/issues/f0339/explainer.html` and every page z-nile builds later for a person, the app included.
- No colour on these pages is purple, the board's mixed-raft type colour and its chart series colours included.
- One written table names the colour, per theme, of every status value of the five kinds: risk level (`easy`, `normal`, `risky`), stage (`new`, `preparing`, `prepared`, `active`, `done`), type (`feature`, `defect`, `chore`, mixed), row readiness (ready, not ready, done) and worker state (`working`, `idle`, `waiting`, `lost`).
- Within one kind, every value's colour differs from every other value's colour in that kind; two values of different kinds may share a colour.
- Every page that shows a status value shows it in the table's colour for that theme, so the board's stage badges, type colours, row markers and `lost` worker chip and the mockup's risk chips and worker cards all follow the one table.
- The board page, the published board and the explainer are light by default whatever the reader's system asks for, and each has a theme button that switches to the same warm dark theme `README.html` has.
- In both themes, normal text has at least 4.5:1 contrast against its background, a status chip's or badge's text included, and large text (24px and up, or 18.66px bold and up) has at least 3:1.
- A script, run by the gate, lists every text and background pair the pages use in each theme and fails when a pair is below its ratio.
- The same script fails when a page gives a status value a colour other than the table's, or when two values of one kind share a colour.
