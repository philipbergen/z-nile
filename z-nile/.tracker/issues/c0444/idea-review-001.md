# Idea review 001

## Findings

- F1: Two Solution sentences don't answer any Problem sentence, so the Solution is bigger than it needs to be. The Problem lists four things: colours and fonts that don't match the site, purple, text that is hard to read, and no contrast script. Nothing in it says the states (easy, normal, risky and the rest) look alike or differ from page to page. Nothing says a person needs a dark theme. Either drop the status-colour and dark-theme sentences, or add the problem each one solves.
- F2: "Bright" status colour can't be judged true or false. It also pulls against the last Solution sentence: bright yellows and greens used as text, or behind ink on the light gold-e background (#f8f7f4), often fall below 4.5:1. Say what a status colour must meet instead, for example "each one differs from the others and passes AA against what sits on it or behind it." "WCAG AA contrast ratio" is also two numbers, 4.5:1 for normal text and 3:1 for large text, so say which pairs get which.
- F3: The non-goal "does not change … what it does" isn't a real fence while the Solution gives every page a dark theme. If light is the default, a person can only reach dark through a new switch or a rule that follows the system setting, and either one changes what the page does. New fonts can also change the layout, which the same non-goal rules out. Say how the dark theme is reached and narrow the non-goal to match.
- F4: The list in the first Solution sentence doesn't match "every page." The app is still only a mockup (`z-nile/.tracker/issues/f0425/mockup/index.html`), so "the app" can't be checked yet. `z-nile/.tracker/issues/f0339/explainer.html` is a page z-nile shows a person, but it isn't on the list. Name the actual files, or say the rule applies to pages built later.
