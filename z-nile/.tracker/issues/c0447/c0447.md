# c0447: Engine to go steadily

## Problem
- The engine is Luau run by the Lune interpreter: about 41,600 lines in `z-nile/engine`, 1,946 lines in the 8 Luau files of `z-nile/lib` (beside its shell and perl helpers) and 171 lines in the 22 Luau files under `scripts/`, and nothing records which command or module moves to Go next or in what order.
- Nothing defines how a moved command is proven to behave the same as its Luau form.
- Specs in every spec tree name an engine Luau path (`@znile/engine`, `@znile/lib` or `@scripts/`) and break when that module is deleted: 62 of the 111 files in `z-nile/tests/tooling`, 131 of the 283 in `z-nile/tests/acceptance`, 1 of the 3 in `z-nile/tests/meta`, 24 in the game projects' `tests/` folders and 196 in the `.tracker` folders.
- More specs in those trees name no engine Luau path themselves and load one only through a test helper (12 in `z-nile/tests/tooling` by the earlier count), so a count of specs that name a path is still too low.
- Game specs are among them: `pickman/tests/meta/architecture.spec.luau` and `pickman/tests/place/main-walls.spec.luau` require `@znile/lib/graph`, `portal/tests/acceptance/f0205/place.spec.luau` requires `@znile/lib/select`, and `pickman/tests/acceptance/c0064/plan.spec.luau` requires `@scripts/lib/beta`.
- Seven helpers in `z-nile/tests/lib` name engine Luau: `seal`, `netfix`, `loops`, `fakecli`, `deploylist` and `cachepaths` by `require`, and `scanners` as strings (`@znile/engine/{paths,ids,skills,raftcheck,boundcmd,trace}` and `@znile/lib/graph`) that `hostile.luau` loads at run time, so a closure over static `require`s misses it.
- No one can see how much of the engine has moved to Go and how much is left.

## Non-goals
- It does not rewrite in Go the specs that reach no engine Luau: they stay in Luau and run against both forms.
- It does not change any command's behaviour, output, exit codes or files written as part of a move.
- It does not remove the embedded interpreter of f0427 before the last command has switched.
- It does not convert the game projects' source Luau (`src/` of `pickman/`, `arcade/`, `portal/`, `snake/`, `invaders/`, `asteroids/`), or any game spec that reaches no engine Luau.
- It does not convert the spec runner or the test helpers that reach no engine Luau (`@tests/lib/engine`, the fixture-copy helper, among them).

## Solution
- The engine moves to native Go one command or module at a time, until the Go program needs no Luau interpreter, no perl and no shell helper.
- "Engine Luau" means every Luau file under `z-nile/engine`, `z-nile/lib` and `scripts/`, and every rule and count below uses that one definition.
- "Every spec" means every spec file in `z-nile/tests/tooling`, `z-nile/tests/acceptance`, `z-nile/tests/meta`, each registered project's `tests/` folder and every `.tracker` folder, and every rule and count below uses that one set.
- A file "names" an engine Luau module when the module's alias path (`@znile/engine/…`, `@znile/lib/…`, `@scripts/…`) appears anywhere in it, as a `require` argument or as any other string.
- A spec "reaches" an engine Luau module when the module is named by the spec, or by any file in the transitive closure of what the spec names, followed through `z-nile/tests/lib` helpers, the projects' own test helpers and other engine modules.
- A helper that loads a module from a path it builds at run time takes that path only from alias strings written out in full in a spec or helper file, and the reach check fails on any run-time load in a spec or helper that it cannot trace to such a string.
- Each move keeps the command line, the output, the exit codes and the files written exactly as they are.
- Every spec that reaches no engine Luau module and runs an engine command runs against both the Luau engine and the Go program.
- Before a switch, every spec that reaches a module the switch deletes (game project specs and tracker acceptance specs included) is replaced, case for case, by a spec that runs on both forms or by a Go unit test of the Go form.
- A game spec that uses an engine Luau module as a library (`@znile/lib/graph`, `@znile/lib/select`, `@scripts/lib/beta`) is changed, before the switch that deletes that module, to get the same result from the Go program's command line or from a copy of the module the game project owns, and its cases stay.
- Before a switch, every test helper that reaches a module the switch deletes is changed to no longer name it, or is deleted together with the last spec that uses it.
- A command switches to its Go form only when all its both-form specs pass on both forms, its replacement Go unit tests pass, and no remaining spec or test helper reaches a module the switch deletes.
- A check in the gate computes the reach of every spec and helper and fails when any of them reaches an engine Luau path that does not exist, so a switch that deletes a still-reached module cannot pass.
- The reach check has a spec that proves it fails for a deleted module named only as a string in a helper, and for one required only by a game project spec.
- The change that switches a command deletes its Luau form and the replaced specs, so there are never two live implementations of one command and the gate passes with no spec broken or skipped.
- No spec case is removed without a named replacement that covers it, and the switching change lists each removed spec beside its replacement.
- One command prints every engine command marked Luau or Go, the Luau lines left in each of `z-nile/engine`, `z-nile/lib` and `scripts/`, the count of specs that still reach engine Luau per spec tree (split into naming it and through-helper), and the helpers that still name it.
- The order favours what the omarchy run needs first and what removes a perl or shell dependency.
