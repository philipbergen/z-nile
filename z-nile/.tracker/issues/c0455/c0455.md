# c0455: Lessons staging inbox and prune

## Problem
- Every review finding defaults to minting or citing a lesson file, growing the corpus to 646 files (~303 with only 1 harvest source) that reviewers and fixtures repeatedly load and dilute.
- Deleting any historically cited lesson file today fails `./zn lessons --check` on `done/` and `retired/` `harvest.md` entries, blocking incremental lesson pruning and graduation (`c0456`, `c0457`, `f0461`, `c0462`, `c0463`).

Decided with the user (2026-11-27): supersede monolithic `c0181` (`R0074`, size 17,000) with incremental lesson graduation: turn `lessons/` into a bounded staging inbox where one-off findings record `one-off: <reason>` by default, new lesson files are created only for shipped escapes or recurring mistakes (2+ items), and lessons with 3-5+ citations graduate into code or skill checklists via a tombstone ledger.

## Non-goals
- Folding the top ~20 judgment lessons into skill checklists (`c0456`) or building the mechanical linters (`f0461`, `c0462`, `c0463`).
- Blindly deleting foundational pre-harvest `from:` lessons without auditing each one individually.

## Solution
- Add a graduated/archived lesson tombstone ledger (`z-nile/skills/graduated.tsv`) read by `z-nile/engine/lessons.luau` so historical `done/` and `retired/` `harvest.md` citations remain valid under `./zn lessons --check` while new harvests refuse retired lesson IDs.
- Update harvest rules in `z-nile/skills/` so review findings default to `one-off: <reason>` unless a mistake shipped as a defect or recurred across at least two items, and add `./zn lessons --graduate` to list lessons at or above the graduation threshold.
- Prune the ~303 single-source harvest lesson files into the archived ledger (auditing the 92 `from:` lessons separately so foundational rules are preserved).
