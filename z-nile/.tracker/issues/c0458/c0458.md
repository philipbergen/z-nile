# c0458: Collapse reviews and tighten caps

## Problem
- `z-nile` runs separate per-layer `code-review` (`review-NNN.md`) and stack `final-review` (`final-review-NNN.md`) passes plus mandatory `design-review` on `normal` tickets with loose round caps, inflating review token spend and turnaround despite a 3.7% shipped rework baseline.
- `[activities.final-review]` is pinned to `ONE_SETTING` (`all = "ultra"`) in `models.luau` and `.models.toml`, which would force every unified post-build review onto scarce `ultra` (`gemini-4-carbon-high` / `claude-fable-5-2`) quota and block non-`ultra` workers on `easy` and `normal` tickets.

Decided with the user (2026-11-27): supersede multi-stage 5/9/9 review plans (`f0417`, `c0262`, `d0442`) with one unified risk-scaled post-build adversarial review (`final-review`: `easy = light` [max 1 round], `normal = heavy` [max 2 rounds], `risky = ultra` [max 3 rounds]), cap `idea` challenge at 1 round, and require `design-review` only for `risky` tickets (optional for `normal` [max 2 rounds], skipped for `easy`).

## Non-goals
- Retiring the `z-raft` stage (`f0464`) or changing pre-code human approval gating (`f0465`).
- Weakening `trace.md --check` or adversarial review severity standards on `final-review-NNN.md`.

## Solution
- Update `rounds.DEFAULT` in `z-nile/engine/rounds.luau` and `.models.toml` defaults to `idea = 1`, `design = { easy = 1, normal = 2, risky = 3 }`, and `code = { easy = 1, normal = 2, risky = 3 }`.
- Remove `"final-review"` from `ONE_SETTING` in `z-nile/engine/models.luau` and configure `[activities.final-review]` in `.models.toml` with `easy = "light"`, `normal = "heavy"`, and `risky = "ultra"`.
- Merge per-layer `code-review` into the unified post-build `final-review` across `work.luau`, `dispatch.luau`, `main.luau`, `z-design`, `zz-execute`, and `zz-review`, and require `design-review` at `status prepared` only when `risk: risky`.
