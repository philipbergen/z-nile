# c0458: Collapse reviews and tighten caps

## Problem
- `rounds.DEFAULT` in `z-nile/engine/rounds.luau` caps the idea challenge at 3 rounds, and caps design and code reviews at 2, 5 and 9 rounds for `easy`, `normal` and `risky`.
- A raft off the light path gets two adversarial passes after it is built: a per-layer `code-review` (`review-NNN.md`) that runs every item of zz-review Code mode (`z-nile/skills/zz-review/SKILL.md:114`), and a whole-stack `final-review` (`final-review-NNN.md`).
- A light-path raft of one easy ticket gets only the `final-review`, which then also applies some of Code mode's checks: correctness, regressions and the Overrides check, repository safety, bounded commands and Judged criteria (`work.luau:347`, zz-review Final mode item 4).
- The rule that every `normal` and `risky` ticket needs a passing `design-review` comes from z-design step 5 alone; the engine has only three related checks: it refuses a latest `design-review-NNN.md` that is unsettled (`main.luau:1708`, `readycheck.luau:76`), it refuses to ready an easy ticket off the light path that has no design review (`readycheck.luau:235`), and it has `./zn work next` answer `draft` for such a prepared ticket (`work.luau:736`, worded at `:806`).
- `dispatch.REVIEW_MODES` accepts `--mode code` and `--mode stream` (`dispatch.luau:51`, `:53`); `models.roleFor` and `models.activityFor` resolve both modes to `code-review` by default (`models.luau:992`, `:1283`), and `WRITER_OF` maps `code-answer` to the writer's setting (`models.luau:115`).
- As of 2026-11-27, `./zn metrics` puts the shipped rework rate at 3.7% by lines added, 11.1% by issues and 8.5% by agent time, all under the 20% target in zz-stats.
- On 2026-11-27, `./zn metrics` lists single dispatched `design-review` runs on this machine that each cost between 96,927 and 366,117 tokens and took between 2.1 and 19.4 minutes.
- `[activities.final-review]` in `.models.toml` is `all = "ultra"`, and `ONE_SETTING` (`z-nile/engine/models.luau:99`) holds it to that one setting, so today every raft's final review needs `ultra` quota and an `ultra` worker, an easy raft's only review included.

## Non-goals
- This ticket does not retire the `z-raft` stage (`f0464`) or change the human approval required before code starts (`f0465`).
- This ticket does not remove or loosen `./zn trace <R-id> --check`, which the lead and `./zn done` run, or the severity standards that `final-review-NNN.md` findings are judged by.
- This ticket does not drop any item of zz-review Code mode: every item moves into the final review, for every raft.
- This ticket does not change the 20% rework target or how `./zn metrics` computes any rework figure, and it keeps the `code-review` spend phase.

## Solution
- `rounds.DEFAULT` becomes `idea = 1`, `design = { easy = 1, normal = 2, risky = 3 }` and `code = { easy = 1, normal = 2, risky = 3 }`, and no `[rounds]` table is added to `.models.toml`.
- The per-layer code review step is removed from `work.luau`, `dispatch.luau`, `main.luau`, `workgraph.luau` (its `review` action) and zz-execute, so every raft, whatever its number of tickets, gets exactly one adversarial `final-review` on its whole stack after it is built.
- zz-review's Code mode section stays as the list of checks that Final mode applies to `git diff origin/main...HEAD` for every raft, and no longer runs one layer at a time; every item is kept: Correctness, Sequestration, Weak tests, Design adherence, Architecture rules, Performance, Judged criteria, Repository safety, Everything in the first round, Lessons, the ruling-line check (11a), Bounded commands, plus the light path's regressions and Overrides check (`work.luau:347`).
- The final reviewer fills in `trace.md` as it does today and records the Code mode checks in `final-review-NNN.md` beside it.
- For every ticket in the raft whose design has no passing `design-review-NNN.md` (an easy ticket's short note, or a `normal` ticket whose designer skipped the now-optional review), the final review also judges that design with zz-review Design mode's checks, and it may raise the ticket's level with a `Level:` line as the light path allows today.
- `dispatch.REVIEW_MODES` drops `code` and `stream`, so `./zn dispatch` refuses `--mode code` and `--mode stream`; the stream-review handling in `dispatch.luau` (`:157`, `:258`, `:283`), `dispatcher.luau` (`:1149`, `:1593`) and zz-review's Stream mode section is removed.
- The `code-review` activity is removed from `models.luau` (`ACTIVITIES`, `PAIRS`, `ROLE_OF`, and the `code-review` fallback of `roleFor` and `activityFor`, which then return nil for a `zz-review` mode other than `design`, `raft` and `final`) and from `.models.toml` (`[activities.code-review]`, `[roles.code-review]`), so `./zn model code-review --for <id>` exits 2 as "not an activity or an alias".
- `code-answer` is removed from `WRITER_OF`, so `./zn model code-answer --for <id>` exits 2, while `final-answer` still uses the writer's setting.
- `code-review` stays in `ledger.PHASES` as the spend phase that the final review's files are committed under (`dispatcher.luau:525`).
- The model and round cap of a raft's `final-review` come from the highest `risk:` among its tickets, so a raft of one `easy` and two `normal` tickets gets one `heavy` review capped at 2 rounds.
- As a separate cut, `"final-review"` is removed from `ONE_SETTING` and `[activities.final-review]` is set to `easy = "light"`, `normal = "heavy"` and `risky = "ultra"`, which moves an easy raft's only review from `ultra` to `light` and a normal raft's from `ultra` to `heavy`.
- z-design step 5 requires a passing `design-review` only for a `risk: risky` ticket; a `normal` ticket's designer may still start one, and the existing refusal of an unsettled latest `design-review-NNN.md` makes that review binding, with no new front-matter field.
- A prepared easy ticket that is off the light path and has no design review is no longer sent back to design: the `draft` branch at `work.luau:736` and its wording at `:806` are removed, so `./zn work next` answers `rafting` when the ticket is sized and `fix` otherwise.
- `./zn ready` no longer refuses an easy ticket with no design review when it is off the light path: the check at `readycheck.luau:235` is removed.

### Scalability
Fewer review runs per raft (one instead of one per raft plus per-layer rounds): each review round on this machine costs 100k to 366k tokens and 2 to 19 minutes (Problem). Round caps shrink worst-case rounds from 9 to 3. No data structure grows.
### Maintainability
Two review pipelines become one: `code-review` activity, stream mode, `code-answer`, per-layer walk states and their spec fixtures disappear; Code mode survives as one list of checks (one definition, applied by one mode). Old files stay readable so history does not need a migration.
### Usability
The worker's walk loses the "review round N of M" loop between layers and trace; an easy ticket is no longer bounced to full design. An easy raft's only review runs on `light` instead of `ultra` (quota), a normal raft's on `heavy`.
