# Idea review 002

## Findings

- F1: Problem bullet 2 is false in both sentences. An easy ticket on the light path gets no `code-review`; its `final-review` is its only review (`work.luau:347` and `:792`, zz-review Final mode item 4), so not "every built ticket gets two". And `./zn status <id> prepared` does not require a design review to exist: `designOpen` (`main.luau:1708`) returns nil when the folder has no `design-review-NNN.md`, as does `openProblem` (`readycheck.luau:76`). The requirement for `normal` and `risky` is z-design step 5's, and the engine's only existence check is for an easy ticket off the light path (`readycheck.luau:235`).
- F2: `design_review: wanted` is not the smallest solution. The gate already accepts a `normal` ticket with no review and already refuses one whose latest `design-review-NNN.md` is unsettled, so starting a review is already the opt-in and no new front-matter field is needed. The same bullet's "It runs none for `risk: easy`" cannot be checked: `status prepared` runs no review, and the sentence does not say what becomes of `ready`'s refusal of an easy ticket off the light path with no design review (`readycheck.luau:235`).
- F3: Solution bullet 2 does not say whether Code mode's checks survive. Today Final mode applies them (correctness, regressions and the Overrides check, repository safety, bounded commands, Judged criteria) only on the light path; for every other raft they live in the per-layer review being removed. A reader cannot tell whether this is a collapse or a deletion, and non-goal 2 fences only the trace check and severity standards. "That review runs the `trace.md --check`" is also not checkable as written: the reviewer fills `trace.md`, and `./zn trace <R-id> --check` is run by the lead and by `./zn done` (zz-execute Phase 5, steps 3 and 5).
- F4: "The `.models.toml` defaults" in Solution bullet 1 name something that does not exist. `.models.toml` has no `[rounds]` table; the limits come only from `rounds.DEFAULT` through `models.rounds`. Adding a table that repeats the defaults would be a second copy, not the smallest change.
- F5: The file list in Solution bullet 2 leaves the `code-review` activity standing. It is still in `models.luau` (`ACTIVITIES` line 94, `PAIRS` line 104), `[activities.code-review]` and `[roles.code-review]` in `.models.toml`, `workgraph.luau:17` and `dispatcher.luau:525`. `code-review` is also the spend phase the final review's files are committed under (`./zn commit --phase code-review`, `ledger.PHASES`). The sentence does not say whether `./zn model code-review --for <id>` still answers afterwards, or whether the spend phase stays.
- F6: Problem bullet 5 presents as a consequence of the fold something that is already true. With `all = "ultra"`, every raft's final review, `easy` and `normal` included, already needs `ultra` quota and an `ultra` worker today. So un-pinning `final-review` is not needed to make the fold possible; it is a separate cut that drops an easy raft's only post-build review from `ultra` to `light`, and the Problem should state it as that.
