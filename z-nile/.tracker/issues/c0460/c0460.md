# c0460: Behavioral acceptance and build mutants

## Problem
- Writing internal module unit specs and `### Rules and mutants` tables during `z-design` over-pins internal implementation shapes in sequestered `acceptance/` specs and inflates prep time before any code exists.
- Recording `### Rules and mutants` inside `## Test plan` during `zz-execute` would mutate `contract.luau`'s hashed `Test plan` section and invalidate pre-code `approval.md` (`f0465`) on every build.

Decided with the user (2026-11-27): keep sequestered `acceptance/` specs in `z-design` strictly for public and behavioral contracts (`inputs -> outputs`, CLI and state invariants), and move internal unit specs and `Rules and mutants` verification to `zz-execute` outside the hashed approval contract.

## Non-goals
- Removing sequestered `acceptance/` specs or `check.sh` from `z-design`.
- Building the `./zn check-design` CLI linter (`f0461`).

## Solution
- Update `z-design`, `zz-execute`, `zz-test`, and `zz-review` so `z-design` writes only public/behavioral sequestered `acceptance/` specs and `check.sh`, while `zz-execute` writes internal unit specs red-first alongside code and records mutant verification in `<issue-dir>/mutants.md` (or `## Verification log`), outside `contract.luau`'s hashed `## Test plan` section.
- Update post-build `final-review` (`zz-review`) and `./zn finish` checks to verify build-time unit test and mutant coverage without staling pre-code `approval.md`.
