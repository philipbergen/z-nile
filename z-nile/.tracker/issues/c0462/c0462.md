# c0462: Spec runner no vacuous pass

## Problem
- The shared spec runner (`z-nile/tests/lib/t.luau` and `z-nile/tests/run.luau`) allows an `it(...)` block that executes zero assertions to pass silently (`zz-test/no-vacuous-pass`), requiring manual reviewer vigilance on every spec file.

## Non-goals
- Editing or breaking immutable legacy promoted specs under `tests/acceptance/<id>/` that assert exclusively via local `error(...)` helpers (`at()`, `absent()`).

## Solution
- Track per-case assertion counts in `z-nile/tests/lib/t.luau` and `z-nile/tests/run.luau` (counting `t.expect` and registered assertion helpers such as `fixture.exec`), failing any `it(...)` case that runs zero assertions across `tests/unit/`, `tests/tooling/`, `tests/meta/`, game non-promoted suites, and newly written `acceptance/` specs while grandfathering existing `tests/acceptance/<id>/` folders so `--full` and `--slow` stay green across all 7 project homes.
- Graduate `zz-test/no-vacuous-pass` into `z-nile/skills/graduated.tsv`.
