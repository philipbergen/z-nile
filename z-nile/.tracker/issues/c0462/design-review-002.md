### F1 [high] A stray `ZN_VACUOUS_PARENT` still turns the check off for a whole gate: `ZN_MEASURED == "1"` does not mark a nested run
Where: c0462.md, The rule as built §3 point 6 ("A runner honors an inherited value only when `ZN_MEASURED == "1"` … A person who exports the variable in a shell has no effect"); `vacuous.inherited`; design-refute-001 F1 ("a stray variable is ignored outside a measured run").
Evidence: every entry point turns `ZN_MEASURED` on before any case runs. `z-nile/check.sh:47` re-execs the gate as `env ZN_MEASURED=1 "$0" "$@"`, and `run.luau:97-150` re-execs an unmeasured run as `env ZN_MEASURED=1 lune run tests/run`. Both pass on the rest of the caller's environment (Lune's `env` option adds to what the child inherits, which point 6 relies on). So `export ZN_VACUOUS_PARENT=c0049; z-nile/check.sh --full` (or a bare `lune run tests/run`) reaches every runner process with `ZN_MEASURED=1` and a listed id. `inherited` returns `c0049`, and no case anywhere is checked. The run then passes vacuous cases with one off line per process. Review 001 F1 asked that the outermost run drop an inherited value, and its Consequences said the carrier "must not become a switch that a stray environment variable can flip for a whole real run". The design replaced that with a test that every gate passes. The fixture cannot show the hole either: its outer runs inherit `ZN_MEASURED=1` from the spec's worker, and no case starts a run with the variable already set. `vacuous.inherited` is pure, so its spec pins a rule that does not separate a shell from a parent case.
Critique: the tempting fix is to also require `PICKMAN_TEST_FENCE` or another variable the gate sets. Any variable the gate sets at its top has the same flaw.
Consequences: the value must be dropped exactly where an unmeasured process becomes a measured one. Today that is two places: `check.sh:47` and `run.luau`'s re-exec. A worker's `ZN_MEASURED = "1"` (`run.luau:432`) inherits from a coordinator that is already clean, and nothing else sets `ZN_MEASURED` (`git grep ZN_MEASURED`). That makes `z-nile/check.sh` a touched module. A person who sets `ZN_MEASURED=1` by hand skips the lock and the measurement, and the check with it. That is a visible weakening (the off line) and should be stated as one, not claimed away.
Recommendation: in both re-execs, start the child with `env -u ZN_VACUOUS_PARENT ZN_MEASURED=1 …`. Add `z-nile/check.sh` to Touched modules. Replace the "has no effect" sentence with the true statement: dropped at the gate's and the runner's outermost re-exec, and honored only below them. Add a fixture.spec case: copy `z-nile/lib/bounded.pl` into the fixture, then run the copied runner with `ZN_MEASURED=""`, `ZN_GATE_QUEUE=off` and `ZN_VACUOUS_PARENT=c9999` and `--require-assertions` on `tests/probe/vac.spec.luau`. It must fail naming the case, with no `started by exempt` line. Add a mutant row: "the re-exec keeps an inherited `ZN_VACUOUS_PARENT`". Pin `check.sh`'s `-u` with a text case, or a run of a fixture copy of `check.sh` if that is cheap.
