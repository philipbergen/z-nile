### F1 [medium] The new `has(r.stderr, "bounded:")` assertion can never fail: Lune's inherited stdio sends the grandchild's stderr to the caller's stdout
Where: `acceptance/fixture.spec.luau:200` (`t.expect(has(r.stderr, "bounded:")).toBe(false) -- a missing helper names itself here`); review 003 F1 Recommendation, which prescribed it; refute 003 F1.
Evidence: `run.luau:144-154` re-executes through `bounded.pl` with `stdio = "inherit"`. A probe under `./zn run --time 60`: an outer Lune script `process.exec`s a middle Lune script, which `process.exec`s `perl -e 'print STDERR qq(child-err\n); print qq(child-out\n)'` with `stdio = "inherit"`. The outer script got `stdout = "child-out\nchild-err\ncode 0\n"` and `stderr = ""`. The fixture run showed the same thing. In the rebuilt fixture, `bounded.pl`'s own line ("bounded: the caller's CPU limit of 120 s is lower than --cpu 3600: it stays") was not in the file that held the copied runner's stderr. Only `gate: ZN_GATE_QUEUE=off…` was there, because the runner writes it itself with `stdio.ewrite`. So every `bounded:` message from the copied runner's re-execution, `cpu.sh is missing` included, lands in `r.stdout`. `r.stderr` never holds one. The assertion passes whatever happens. It is the "assertion that cannot fail" that `zz-test/no-vacuous-pass` names, inside the issue that makes the runner enforce that lesson. The case itself still stands, because `r.ok == false` and the `makes none` line carry it.
Critique: the tempting fix is `has(r.stdout, "bounded:")`. That turns the case red under any caller whose CPU limit is below 3600 s. `bounded.pl:63-66` prints `bounded: the caller's CPU limit of N s is lower than --cpu 3600: it stays` whenever `ulimit -t` is lower. In this dispatched session `sh -c 'ulimit -t'` prints `1800`. `check.sh:47`'s `bounded.pl --time 3600` cannot raise that limit, so a dispatched executor's gate and `./zn check c0462` would see the line and fail AC2 on a sequestered spec it may not edit. Round 3 could not have seen this. It came from round 3's own recommendation.
Consequences: whatever replaces the assertion must not depend on the caller's CPU limit, on the order of the inherited output, or on a message that names a path, because the fixture path differs per checkout. Once a red run is diagnosed through the exit code, the case also separates "a case failed" (the runner's exit 1, `run.luau:527,584`) from every refusal around it: `bounded.pl`'s missing helper and usage errors (exit 2), a `require` of a missing `measure.pl` (perl dies, not exit 1) and the runner's own missing-list exit 2.
Recommendation: replace line 200 with `t.expect(r.code).toBe(1)`, which holds only when the copied runner ran its cases and one failed, and drop the `r.ok` line it makes redundant. Keep the comment's intent in words: "exit 2 means a helper or the list refused, not the drop". As the gate runs it, in a session where `ulimit -t` is below 3600, rerun the case's command on E5's scratch fixture and record in E5 that its exit code is 1 with a stub check, and 2 with `cpu.sh` removed. Add a row or extend the E5 row: mutant "the case accepts a refusal as the failure". If the stderr assertion is kept in any form, it must read `r.stdout` and match only `is missing`, never the `bounded:` prefix.
Lesson: zz-test/no-vacuous-pass
