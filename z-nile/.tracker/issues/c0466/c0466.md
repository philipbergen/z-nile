# c0466: Automate spend and preflight hooks

## Problem
- Agents still type `./zn spend` by hand at five points, and a forgotten call leaves that stage with no row in the item's `spend.d/*.tsv` files. The points are the capture (`--phase capture` after `./zn land`, z-idea), the prep (`--phase prep`, z-design), a returned subagent review (`--note design-review-NNN`, z-design and z-raft), an answered round (`--note design-refute-NNN` in z-design, the `--begin`/stop span in z-raft:44) and the deliver step (`--phase deliver`, zz-execute Phase 6).
- The zz-execute Phase 6 `./zn spend <R-id> --phase deliver` runs after the merge, so its row is committed on the merged branch and pushed nowhere (`main.luau:7623`), while `./zn done`'s binding commit already writes a `deliver` row on every member before the merge (`main.luau:5671`).
- A layer that passes `./zn finish` can still fail the gate's static block at any step its builder skipped while running by hand the steps `zz-execute/a-builder-runs-every-static-step-and-guard-before-reporting` lists. This includes steps the lesson does not list: `./zn skills --check`, the rojo build, and the Go format, vet, test and build stages (`z-nile/check.sh:302-326`).

## Non-goals
- The explicit `./zn spend` and `./zn check` commands stay for the callers and promoted specs that call them directly; only their raft-round subject prefix changes.
- This issue adds no session reader for any CLI, and agy's reader is f0459's.
- Rows already in the tracker are not rewritten, and an unprefixed raft-round row written before this change is not matched by the skip rule.
- The rows `./zn finish` and `./zn done` write are unchanged, and `./zn dispatch zz-review` changes only its raft-mode subject.
- This issue does not create `z-nile/skills/graduated.tsv` or define its row format; c0455 does both.

## Solution
- The `./zn` commands a stage already runs write that stage's row in the item's `spend.d/<writer>.tsv`, and the row is on origin/main once the item's change reaches main. Each command closes the open span: `./zn land` of a capture writes `capture`; `./zn model design-answer --for <id>` writes `design-review-NNN` for the round just filed; the next `./zn model design-review --for <id>` or `./zn status <id> prepared` writes `design-refute-NNN`; opening the prep PR writes `prep`.
- Each automatic row holds only its own stage's span: from the item's previous mark in this checkout (`./zn new` or `./zn status <id> preparing` opens the first one) to the command that writes the row. So rows of one item written in one session never overlap, and the `prep` row holds only the design work outside the review rounds.
- The span is read with `sessionread.span`, the same reader the typed `./zn spend` uses (`main.luau:7717`). The row is measured for every CLI that reader reads (claude, grok, agent and kimi today, plus agy once f0459 lands). A CLI it cannot read still gets the row with the reader's `unmeasured` note, and that counts as recorded.
- A row for a raft's own round file has a subject that starts with the raft id (`R0158 design-review-001`, `R0158 design-refute-001`) on every member. This holds whether the row comes from the automatic write, from a typed `./zn spend <R-id> --note <file>`, or from `./zn dispatch zz-review <R-id> --mode raft` (`dispatcher.luau:1259`). So no raft round row shares a key with a member's own round.
- An automatic row is skipped when any `spend.d/*.tsv` file of the item, from any writer, holds a row with the same phase whose subject starts with the same key (the round's file name, or the raft id plus that file name), whatever reading notes follow the key (`main.luau:7727`, e.g. `design-review-001 claude unmeasured; …` or `design-review-001 (declared)`). For `capture` and `prep` the key is empty, so any row of that phase matches.
- z-idea, z-design and z-raft no longer tell an agent to type `./zn spend` or `./zn spend --begin` at those points, and zz-execute Phase 6 no longer has a `./zn spend --phase deliver` step, because the `deliver` row from `./zn done`'s binding commit is that stage's row.
- Before its own specs, `./zn finish` runs `z-nile/check.sh --static` and then the listed steps `--static` does not run: watch-check, `zn --help`, and the guard specs scanning-loops, c0193 tree, c0077 cache-paths, repo-fence and gatequeue. It stops at the first failure and names it. The lesson then graduates into `z-nile/skills/graduated.tsv` in c0455's row format, and c0466's `depends_on` lists c0455, f0459 and f0464.
