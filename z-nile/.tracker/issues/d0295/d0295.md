# d0295: Raft order names non members

## Problem
A raft whose Order & dependencies section names an issue that is not its member makes ./zn start refuse: since #296 (stacks), stack.order reads every [fdc]NNNN id in that section as a layer, so R0090's Order (which named c0264 and c0260 to say R0090 merges before their rafts) was refused with 'c0264 is in R0090's Order and is not a member' (2026-11-12, R0090/1/c0261, PR #303). z-raft tells the author to write cross-raft order in the Order section (lesson z-raft/cross-raft-order-written-in-both, 'For each X before Y, does Y's raft document say it'), so following the skill produces a raft that cannot start. What should happen: a raft can state an order against other rafts and their issues without those ids being read as its layers, and z-raft, its lessons and stack.order agree on where that order is written; z-raft's own checks (status prepared) refuse an Order that start would refuse, before the raft is readied.
