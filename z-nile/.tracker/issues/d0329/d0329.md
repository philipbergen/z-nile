# d0329: Check names the wrong failing criterion

## Problem
- When one case of a building spec is red, a check.sh that looks up each criterion's cases in the `--out` record (the fixtureSpec pattern, as in c0250's and c0306's checks) reports every criterion of that spec as "did not pass: <its first case>", because `z-nile/specs.luau` writes the record only when the whole run passes.

## Non-goals
- A green run's `--out` record stays byte-for-byte what it is today, and done and the trace accept no record from a red run as a pass.

## Solution
- After a run of a building spec with one red case, a check.sh using the fixtureSpec pattern reports as failed only the criteria whose own cases failed, and names the case that failed.
