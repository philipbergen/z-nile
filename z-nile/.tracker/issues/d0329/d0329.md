# d0329: Check names the wrong failing criterion

## Problem
lune run z-nile/specs -- run --out FILE writes the passing case names only when the whole run passes (z-nile/specs.luau: if outFile ~= nil and code == 0). A check.sh that runs a building spec once and looks up each criterion's cases in that record (the fixtureSpec pattern, in c0250's and c0306's checks among others) therefore reports every criterion of the spec as 'did not pass: <its first case>' when any one case is red, and their comment 'the runner writes each passing case's name to the --out file' is true only for a green run. Nothing passes falsely, but the criterion named is wrong, and in a prep's mutation check it hides which case killed the mutant. Found by c0306's prep (2026-11-14); lesson zz-test/out-records-only-a-green-run says how to read it meanwhile. What should happen: either the runner records a red run's passing cases too, marked so that no reader takes them for a green run's record (who reads --out, done and the trace among them, is for the design), or the check.sh pattern reads the runner's own per-case results instead. Not in scope: changing what a green run records.
