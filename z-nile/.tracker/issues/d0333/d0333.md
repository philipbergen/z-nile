# d0333: Commit after finish unfinishes the layer

## Problem
- After `./zn finish`, a `./zn commit` of the raft's trace.md or final review files rewrites the raft's `spend.md`, which no post-finish list (`layergit.isPostFinishPath`, trace's `isTrackerFileOf` and `isAllowedAfterTrace`) accepts, so `./zn trace <R>` prints "not finished", `./zn trace <R> --check` calls the table stale, and `./zn done` refuses.

## Non-goals
- No path other than the raft's own `spend.md` is added to any of the three post-finish lists (`layergit.isPostFinishPath`, `isTrackerFileOf`, `isAllowedAfterTrace`), and a post-finish commit that changes code, specs or any other tracker file still unfinishes the layer.

## Solution
- A raft that finishes its last layer and then commits trace.md, its final review and its final refute with `./zn commit`, as zz-execute Phase 5 says, stays finished under `./zn trace <R>`, passes `./zn trace <R> --check` and lands with `./zn done`, with no plain `git commit`, no second finish and a spend row recorded for each of those commits.
