# d0333: Commit after finish unfinishes the layer

## Problem
- After `./zn finish`, a `./zn commit` of the raft's trace.md or final review files rewrites the raft's `spend.md`, which no post-finish list (`layergit.isPostFinishPath`, trace's `isTrackerFileOf` and `isAllowedAfterTrace`) accepts, so `./zn trace <R>` prints "not finished", `./zn trace <R> --check` calls the table stale, and `./zn done` refuses.
- Decided with the user (2026-11-14): "Keep d0333 (Recommended)". c0343 (Trace check accepts the spend ledger), captured later the same day by another terminal for the same failure (R0101 was held on it), is the duplicate; this issue covers its outcomes, `./zn work next` no longer asking for another finish included.

## Non-goals
- No path other than the raft's own `spend.md` is added to any of the three post-finish lists (`layergit.isPostFinishPath`, `isTrackerFileOf`, `isAllowedAfterTrace`), and a post-finish commit that changes code, specs or any other tracker file still unfinishes the layer.

## Solution
- A raft that finishes its last layer and then commits trace.md, its final review and its final refute with `./zn commit`, as zz-execute Phase 5 says, stays finished under `./zn trace <R>`, passes `./zn trace <R> --check` and lands with `./zn done`, with no plain `git commit`, no second finish and a spend row recorded for each of those commits.

## Design
**Reproduction.** `acceptance/commit-land.spec.luau` builds a one-ticket raft in a fixture, finishes its layer, and then commits `trace.md`, `final-review-001.md` and `final-refute-001.md` with `./zn commit`, as zz-execute Phase 5 says. On main today (bc35f7c41) it fails at the first of those commits: `./zn trace R0010` says "c0010 is not finished: ./zn finish c0010", and `./zn trace R0010 --check` says "table is stale (commit … touches non-tracker file pickman/.tracker/rafts/active/R0010/spend.md after finish)". That is the reported reason. On real work it was R0102 on 2026-11-14 (final-review-001 F1): its executor restacked, finished again and made the one remaining commit with plain `git commit`.

**Expected behaviour.** zz-execute Phase 5 step 3: "Verify `./zn trace <R-id> --check` passes and commit `trace.md` and the final review files with `./zn commit --phase code-review --model <reviewer model>`", and its hard rule in every prompt: "Commit only with `./zn commit`." A raft that does exactly that must stay finished and land. The defect reworks c0239 (the trace table and its stale rule; `layergit.isPostFinishPath` came with it) in R0092's stack work.

**Root cause.** `cmd.commit` (`z-nile/engine/main.luau`, `spend.writeRaft(raft)` before its `git add -A`) rewrites `<raft-dir>/spend.md` on every commit: the snapshot gains the new row's totals. Three rules judge the commits after a finish commit by the paths they touch, and none of them lists that file:
- `layergit.isPostFinishPath(path, raftId)` (`z-nile/engine/layergit.luau:118`), read by `layergit.layerFinishSha`, so by `./zn finish`, `start`, `stack`, `restack`, `trace`, `done` and `./zn work`: it takes `spend.d/` rows, the raft folder's `trace.md`, `<R-id>.md`, `review-NNN.md`, `refute-NNN.md`, `final-review-NNN.md`, `final-refute-NNN.md`, and issue documents.
- `isTrackerFileOf` (`z-nile/engine/trace.luau:437`), read by `trace.staleReason` for every commit after the top layer's finish commit: the same raft files, and the raft's own issue documents.
- `isAllowedAfterTrace` (`z-nile/engine/trace.luau:463`), read by `trace.staleReason` for every commit after the newest commit that touches `trace.md`: `spend.d/` rows, `<R-id>.md`, `final-review-NNN.md` and `final-refute-NNN.md`.

**Why no spec caught it.** `tests/tooling/trace-land.spec.luau` and `tests/tooling/stack-land.spec.luau` make their post-finish commits with plain `git commit` of one named file, so `spend.md` never changes there, and `tests/tooling/trace.spec.luau`'s pure cases list only the files the rule already took. No fixture used the command the protocol prescribes (lesson zz-arch/allow-lists-accept-what-the-prescribed-command-writes, written from R0102).

**The fix.** Each of the three rules takes one more name in the raft's own folder: `spend.md`. The capture offers two ways ("either the post-finish rules take the raft's spend.md, or commit no longer rewrites it after finish"); this is the first. The second was rejected: `spend.md` is the raft's running totals, and a commit that records a row but leaves the snapshot behind makes the file wrong until `done` rebuilds it, and `./zn metrics --include-active` reads it.

```luau
-- z-nile/engine/layergit.luau, isPostFinishPath, and z-nile/engine/trace.luau, isTrackerFileOf
			name == "trace.md"
			or name == "spend.md" -- d0333: every `./zn commit` rewrites the raft's snapshot
			or name == `{raftId}.md`
-- z-nile/engine/trace.luau, isAllowedAfterTrace
			name == `{raftId}.md`
			or name == "spend.md" -- d0333
			or string.match(name, "^final%-review%-%d+%.md$") ~= nil
```

`experiments/prototype.patch` is the change as a diff from bc35f7c41 (two files, three added lines). No signature changes, no new function, no new state. `name` is the path's one segment below the raft's own active folder in all three rules, so another raft's `spend.md`, a `spend.md` in a subfolder and a file that only ends in `spend.md` are still refused (AC1, AC2). The two header comments that restate the rule also gain the name: the block above `trace.staleReason` (`trace.luau:66-72` and `:482-484`) and the one above `layergit.layerFinishSha`.

**What a `./zn commit` writes after the finish**, measured in the fixture (`git diff-tree` of each commit): the file committed, the issue's `spend.d/<host>-<id>.tsv` row file, and `<raft-dir>/spend.md`. Nothing else: `watchcmd.upkeep()` changes a watch file only when a source file moved, and no source file changes in these commits.

**Still refused.** A post-finish commit that changes code, a spec, a `check.sh`, the raft's `harvest.md` or any other tracker file still unfinishes the layer (AC5 runs it with `./zn commit` in the fixture; `./zn trace` says "c0010 is not finished" and `./zn done` refuses). After the table, an issue document still makes it stale, as today.

**Siblings.** The same three rules refuse two other things the protocol asks for; neither is this issue's (Non-goal: no path but the raft's `spend.md`):
- zz-execute Phase 5 step 4 harvests the final review's findings after the table (`harvest.md`, and often a lesson file under a skill). Captured as **d0344**. c0316's draft design (new, not prepared) already describes the same gap for `harvest.md` ("The final review's findings are harvested after the trace"); whoever designs d0344 should fold it there or close it against c0316.
- `./zn work next` never moves past a review whose verdict is `changes`, even when its refute resolves it and `./zn done` accepts it. Captured as **d0345**. It is not a path rule, but it stopped the same raft at the same step.

No skill names the three lists' members one by one (`grep -rn 'post-finish\|tracker files' z-nile/skills/*/SKILL.md z-nile/README.md z-nile/templates` finds only that row).

### Scalability
Three string comparisons on paths already being read. No new git call.

### Maintainability
The three rules stay three lists; this issue adds the same one name to each and pins each with a pure case, so a later edit that drops it from one is named by the spec. Merging them into one helper is c0316's `isLedgerFile` and out of scope here (smallest change).

### Usability
An executor follows zz-execute Phase 5 as written and lands: no second `./zn finish`, no plain `git commit`, and the three commits keep their spend rows.

## Regression guard
Must stay green: `tests/tooling/trace.spec.luau` (AC6; its pure `staleReason` case lists what the rule took before), and the slow-tier `tests/tooling/trace-land.spec.luau`, `tests/tooling/stack-land.spec.luau` and `tests/tooling/stack-fix.spec.luau` (E4; they are not in `check.sh`, by the lesson zz-test/check-sh-never-runs-the-slow-tier: step 3 runs them once).
