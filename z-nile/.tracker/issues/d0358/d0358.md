# d0358: Dispatched claim memory stale

## Problem
Under ./zn dispatch, `./zn status <id> preparing` remembers the stamp it replaced: publish.commit pushes through the broker, which does not move the local origin/main, so rememberClaim (main.luau setStatus, after mergeOrigin) writes the document's pre-claim status (c0272's prep, 2026-11-15: its .cache/tracker-claim-c0272 holds new-lynx-silver-marble while origin/main has preparing-marble-raging-sunny; c0272 design review 001 counted 22 of 50 worktree memories holding a new-… stamp). Every rule that compares a remembered claim with the stamp (the carried raft move's 'a claim this checkout made', release) then refuses a dispatched session's own claim. What should happen: the memory holds the stamp the publish pushed.
