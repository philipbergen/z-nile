# d0379: Work end skips phase six

## Problem
- After a raft lands, `./zn work next <R>` prints `<R>: end - <R> landed. Stop. Tell the person to start a fresh session (or /clear) and run z-work again.` from `work.forRaft` in `z-nile/engine/work.luau`, and the line does not mention zz-execute's Phase 6.
- Neither branch of z-work step 6 mentions Phase 6: the raft-named branch says "say so and stop", and the no-raft branch says to say one line and run `./zn work next` with no raft.
- On R0101 (2026-11-15) the worker read both as "stop at once", so Phase 6 (watch-kick, spend, final report, worktree cleanup) did not run for that raft.

## Non-goals
- This issue does not change what any Phase 6 step in zz-execute does, or the order of those steps.
- This issue does not change when `./zn work next` prints `end`, the `--released` count, or the rule that stops a session with no raft named.
- This issue does not change the line or the z-work step 6 behaviour for a raft that was released without landing.

## Solution
- The `end` line that `work.forRaft` prints for a landed raft tells the worker to finish zz-execute's Phase 6 for that raft before it does anything else, and no longer puts a bare "Stop." ahead of that instruction.
- z-work step 6 says, for a worker that was given a raft, that it runs zz-execute's Phase 6 for the landed raft before it says so and stops.
- z-work step 6 says, for a worker that was given no raft, that it runs zz-execute's Phase 6 for the landed raft before it says its one line and runs `./zn work next` with no raft.
- R0101's skipped Phase 6 steps (watch-kick, spend, final report, worktree cleanup) are each run, or each recorded in the issue's verification log as already done or no longer possible, with the reason.
