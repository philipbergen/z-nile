# d0398: Reap spares outer session

## Problem
- When a command run inside a Claude session starts a nested claude session (`./zn idea`, `./zn dispatch zz-review`), the nested session's SessionEnd hook runs `./zn reap --session-end` and stops the outer session's tool shells, which die with exit 144.
- `~/.local/state/z-nile/reaped.log` records those outer-session commands as "started by the session that is ending", for example on 2026-11-16 at 13:20:28, 13:20:37, 13:20:55 and 13:21:15 PST with cwd in three other worktrees and the main checkout.
- On 2026-11-16 `./zn dispatch zz-review R0117 --mode raft` was killed about a minute in four times, and `./zn idea` was killed twice for f0396 and three times for c0397 before any challenge ran.
- After those kills `.cache/dispatch/R0117/state.json` still said outcome running for a process that was dead.

## Non-goals
- The change does not alter the time limits of `./zn run`.
- The change does not alter the PreToolUse hook.

## Solution
- A nested session's SessionEnd reap leaves the outer session's tool shells, its subagents' shells and their children running, in every worktree.
- A session's session-end reap still stops every process that session itself started, as the c-issues on leaked processes require.
- `./zn idea` and `./zn dispatch zz-review` run to completion when started from inside a Claude session that has other commands running.
- A dispatch state left as running by a step whose process is dead is reported as dead, not running.
