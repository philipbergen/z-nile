### F1 [high] The captured outcome "c0116/retired.spec passes on main's slow tier" has no acceptance criterion, and c0411 counts on this issue's check to run it
Where: d0406.md Solution bullet 3, Acceptance criteria (AC7), Implementation step 3; guesses.md G4; c0411.md Design ("Order and how the three captured outcomes are checked")
Evidence: The capture says "Both `z-nile/tests/acceptance/c0043/rounds.spec.luau` and `z-nile/tests/acceptance/c0116/retired.spec.luau` pass on main's slow tier." AC7 and check.sh run only `rounds.spec`. `retired.spec` appears only in Implementation step 3 ("Record the result in the Verification log"), which nothing checks. G4 says "retired.spec only reruns rounds.spec in a clone, so rounds.spec passing is the same proof". That is not what the spec does. Its header and the case `on a clone holding a retired raft, the classification, rounds, lessons and audit checks pass` (retired.spec:114-169) retire a raft in a copy of the tree and then run `c0114/classified.spec`, `c0043/rounds.spec`, `lessons --check` and `audit` there. That tree is different (a raft in `rafts/retired`) and the checks are different, so `rounds.spec` passing on the real tree does not prove it. c0411's draft goes the other way: it says "After both items have landed, d0406's own check (its AC that `rounds.spec` and `retired.spec` pass on the slow tier) is where the passing run is checked." The result is that neither issue checks retired.spec. The guess drops part of a captured outcome, and no `Scope decision` or `Decided with the user` line covers it.
Critique: Under item 11 this is high: a captured outcome is left without a criterion. The author will be tempted to keep G4 and add a sentence saying the Verification log records the run. A log entry is not a check: `./zn check d0406` and `done` would still pass with retired.spec red.
Consequences: Running retired.spec in check.sh costs its run time at every `finish`, restack and `done`. The time is measured three ways: about 110 s here, 281.6 s in c0411's E6, and 497 s in `z-nile/tests/slow.tsv`. That goes against lesson zz-test/check-sh-never-runs-the-slow-tier, but its c0302 note lets one check line run a slow spec once when no gate runs it, provided the measured seconds are stated beside the line. retired.spec also runs rounds.spec inside its clone, so with both lines the rounds proof runs twice. d0406 is a defect and c0411 a chore, so they cannot share a raft. This issue is therefore a raft of its own, and its check runs at its own finish and done only, with no restacks under other layers.
Recommendation: Add AC8: "`z-nile/tests/acceptance/c0116/retired.spec.luau` passes (after c0411)". Give it a check.sh line that runs it once by name, with its seconds measured with the prototype and c0411's patch, stated beside the line and in the design, per the c0302 note. Run AC7 and AC8 in one `lune run tests/run -- <rounds> <retired>` invocation that both read, so each spec is paid once per check. Correct G4's "same proof" sentence and the step 3 timing. If that cost is not acceptable, escalate to the user: the options are (a) AC8 in check.sh at the measured cost, (b) the user records a `Scope decision` that rounds.spec stands in for retired.spec, or (c) another proxy the user accepts. Whichever is chosen, c0411's sentence naming d0406's check has to match it (c0411's prep, not this one, edits that).

### F2 [high] E2-mutants.sh rewrites engine files in whatever directory it is run from, with no fixture of its own
Where: experiments/E2-mutants.sh (the `mutant` function: `cp "$2" "$2.keep"`, `perl -0pi -e … "$2"`, `mv "$2.keep" "$2"`); d0406.md E2 ("then `experiments/E2-mutants.sh`")
Evidence: The script is kept so that a resumed prep can rerun it. It edits `engine/ledger.luau` and `engine/main.luau` by relative path in the current directory. The only guard is a header comment ("Run from z-nile/ of a scratch worktree"). Its substitutions match only the prototype's text. That text is what the executor's raft worktree holds after Implementation step 1, and what the main checkout holds once d0406 lands. Run from either `z-nile/`, it rewrites tracked engine files in place for the length of each mutant's spec run. If it is stopped between `perl` and `mv` (its own caller's time limit, ^C), the mutant stays in place and a `.keep` file is left beside it. Only the inner `lune run` goes through `../zn run --time 280`. The script itself, its perl edits and its restores are bounded by nothing, and E2's record does not name the bounded command the script ran under.
Critique: Item 9 says any path from a script in the issue to the real repository is high, and the main checkout is never edited. The author will be tempted to add a check that the toplevel sits under `.worktree/scratch-`. A guard on a given path is exactly what the lesson warns about: it is satisfied by any directory that looks right.
Consequences: Copying the sources into a fixture means the spec runner has to work in that copy. It needs the home's `.luaurc`, `tests/` and the engine, the way `c0116/retired.spec` builds its copy with `git init` and the tree's files. The copy has to be removed afterwards, and its writes stay under `.cache`.
Recommendation: Make the script build its own throwaway copy before it writes anything: a fresh `git init` repository under `z-nile/.cache/d0406-e2/` (or a `mktemp -d` outside every checkout), filled from `git ls-files` of the worktree it was started in, with `prototype.patch` and the acceptance folder applied. Run every mutant in that copy only, remove it at the end, and refuse to start when the patch does not apply to the copy. Make the usage line, and E2's record, say the script runs under `../zn run --time <s> -- bash experiments/E2-mutants.sh`, then rerun it and update E2-results.txt.

### F3 [medium] The board and summary-reader cases pass with the ledger left unchanged, even though both readers refuse the fixture's spend.md on main
Where: acceptance/idea-phases.spec.luau, cases `the board is written from the same tracker` and `the readers a raft's spend summary uses return and total the idea rows`; AC6; the last row of the Rules and mutants table ("they guard, they do not reproduce")
