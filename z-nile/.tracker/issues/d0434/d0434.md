# d0434: Restack stops on conflict

## Problem
- `./zn restack <R-id>` aborts the rebase at the first conflict and leaves the layer's branch unchanged, so the worker must rebase the whole layer by hand outside zn.
- A `./zn restack <R-id>` run after a hand rebase that exists only on the local branch takes the layer's tip from `origin`, finds it not stacked, and `git reset --hard`s the local branch to it, discarding the hand rebase.
- When a restack has stopped on a conflict, `./zn work next` does not name continuing it as the raft's action.

Decided with the user (2026-11-21, who resolves): "zn restack conflict shoudl be handled by the ai skill around it". So a conflict during a restack is not a stop for the person: the engine leaves the rebase in progress and names the conflicted files, and the skill the worker follows (zz-execute, through z-work) tells the worker to resolve the conflicts itself, rerun what the resolved files affect, and continue the restack with the one command. Only a conflict the worker cannot resolve with confidence (two sides that both changed the same behaviour on purpose) goes to the person, as a question that names the files and both intents.

## Non-goals
- zn does not resolve conflicted files itself or pick a side for the worker.
- It does not reuse resolutions through git's rerere or any other store of past resolutions.
- A restack run in which no layer conflicts and no layer's local branch holds commits that `origin`'s branch lacks leaves the same branches and pushes as today.
- It does not change when a restack is required or how often main moves during a landing.

## Solution
- When a layer's rebase conflicts, `./zn restack <R-id>` leaves that rebase in progress in the raft's worktree, exits non-zero, and prints the layer, each conflicted file and the exact command that continues.
- After the worker has resolved and staged the conflicted files, one zn command continues the in-progress rebase, runs that layer's `check.sh`, pushes the layer when it passes, and only then restacks the remaining layers, without restarting any layer already rebased in that run.
- Restack takes a layer's tip from the local branch in the raft's worktree whenever that branch holds any commit that `origin`'s branch for the layer lacks, and from `origin` otherwise.
- When the local tip it takes is not based on the current tip of the layer below (for example, a hand rebase onto a main that has since moved, or a layer above one that restack just moved), restack rebases that local tip onto the layer below and never rebases `origin`'s tip for that layer.
- When `origin`'s branch for a layer holds a commit whose change is on neither the local branch nor the layer below, restack exits non-zero, names the layer, and changes no branch for it or any later layer.
- Restack never runs `git reset --hard` on a local branch holding commits that `origin`'s branch lacks.
- Restack skips a layer as "already stacked" only when `origin`'s branch for that layer is itself at the stacked tip.
- When a layer's stacked tip is on the local branch but not on `origin`'s branch, whether from a hand rebase, a rebase restack just made from the local tip, or a continued resolution, restack runs that layer's `check.sh` and pushes the layer when it passes, before it restacks the next layer.
- When that `check.sh` fails, restack exits non-zero, names the layer, pushes nothing for it or any later layer, and leaves the local branch as it is.
- After any restack or continue run that exits zero, `origin`'s branch for every layer of the raft is stacked on the layer below, so `./zn done` does not reply "run ./zn restack".
- A conflict resolution counts as kept once it is a commit on the layer's local branch or is staged in the in-progress rebase, and no restack run removes either without the worker's explicit abort command.
- While a raft's worktree has a restack rebase in progress, `./zn work next` names the continue command as that raft's action.

## Design
Risk reason (risky): it rewrites published layer branches and decides which tip a restack trusts; a wrong choice discards or republishes work.

- **Cause of R0138's reset.** `layergit.layerTip` returns `origin/<layer>` before the local branch; `cmd.restack` took it, judged "already stacked" on it, then `checkoutLayer` + `git reset --hard <origin tip>` overwrote the hand-rebased local branch. Now `restackplan.source` takes the local tip whenever it holds a commit origin's lacks; the only reset left is of a branch that holds nothing origin lacks.
- **Modules.** `engine/restackplan.luau` (pure: `source`, `decide`, `trusted`, `lease`, `emptied`, `movedSince`, marker text, messages); `engine/restackcmd.luau` (git edge, modes start/continue/abort); `cmd.restack` in `main.luau` is a few lines; `workread.restackStopped` + `work.luau` answer `work next`.
- **Marker** `<worktree git dir>/zn-restack.state`: written when a run starts (raft, back, start commit, per layer `orig` local tip and `judged`, origin's tip after the run's fetch), rewritten as branches move (`left`, also for layers taken as they are, so `--abort` works after a `--continue`), `conflict <layer> <own commits>` and `file` lines added at a stop, removed at the end. A crash anywhere leaves `--continue` and `--abort` usable.
- **Walk.** Each layer: tip = local if it holds a commit origin lacks, else origin's. Diverged (both have extra commits): local is taken only if origin's tip is `refs/zn/pushed/<layer>`, the tip this clone itself pushed (written by `start`, `finish` and restack after their push succeeded); otherwise (a fresh clone, a layer someone else pushed, a tip merely fetched or reset to) exit 1 naming both shas and what to do (fetch, rebuild on origin's tip, or ask), nothing changed. No reflog, no pre-fetch tip. Stacked + on origin: skip. Stacked, local ahead: check.sh. Not stacked: `rebase --onto` (rerere off); a rebase or resolution that leaves fewer own commits stops with "emptied ... stop and ask". Every layer runs its check.sh; red stops with nothing pushed.
- **Publishing (G1, decided by the lead).** Nothing is pushed until every layer is restacked and has passed its check; then all moved layers go in one `git push --atomic`, each `--force-with-lease=<ref>:<the origin tip the run judged after its fetch>`, kept in the marker so `--continue` uses the same value, never the current remote-tracking ref; `refs/zn/pushed/<layer>` is written only after the push succeeded. `restacked` is emitted once, after the push.
- **Conflict.** The rebase stays in progress on that layer; exit 3 (0 success, 1 every refusal); message names layer, files, `--continue`, `--abort`. A plain restack then refuses and names both commands. `work next` answers `restack` with the resolve-and-continue note.
- **Continue.** Refuses naming `unmerged: <file>` and `conflict marker: <file>:<line>` (markers looked for only in the recorded conflicted files), then `GIT_EDITOR=true git rebase --continue`, then the walk again (the continued layer is local-ahead: checked; the layers above rebased); one more stop repeats. With no rebase in progress it refuses a dirty worktree.
- **Abort.** Refuses (naming them, changing nothing) a branch that is neither at its `orig` nor at its `left` sha, and a dirty worktree when no rebase runs; else aborts the rebase, returns to the start branch (or commit), restores local branches (deletes only ones the run created). Nothing was pushed, so origin needs nothing.
- **Skills.** zz-execute Phase 5 step 2 and z-work step 3 tell the worker what to do (specs by name via `z-nile/affected`, red check after continue, empty resolution, repeat, unattended = questions.md, never skip/drop/force-push).

### Scalability
One walk is a few git calls per layer, as before.
### Maintainability
Decisions are pure and spec'd without git; main.luau gains no top-level local.
### Usability
The conflict message prints the layer, each file and both commands; `work next` names the action.

## Acceptance criteria

### Checked
- AC1: When a layer's rebase conflicts, `./zn restack <R-id>` leaves that layer's rebase in progress in the raft's worktree, exits 3, prints the layer, each conflicted file and the continue and abort commands, pushes nothing for any layer and emits no `restacked`.
- AC2: A restack run while one is in progress refuses with exit 1, names `--continue` and `--abort`, and leaves the marker, the stopped commit and any staged resolution as they were.
- AC3: While a restack is stopped on a conflict, `./zn work next <R-id>` answers `restack`, names the conflicted file, the `--continue` command, the specs command and the empty-resolution rule.
- AC4: `--continue` refuses while a path is unmerged, and while a conflict marker is staged in a conflicted file, naming each, and leaves the rebase in progress.
- AC5: After the resolution `--continue` finishes the rebase, restacks the layers above on it with trees equal to a by-hand rebase (a Markdown `=======` underline in another file does not block it), pushes every moved layer together, emits `restacked` once, removes the marker and returns to the starting branch; a following restack says already stacked.
- AC6: `--abort` restores every layer's local branch, the worktree and the starting branch exactly as before the run, origin was never touched (also when a layer below the conflict was already restacked locally), and a following `--continue` says no restack is in progress.
- AC7: A layer whose local branch was hand rebased onto the layer below keeps its tip and the layer above it is restacked on it and pushed; when the hand rebased layer's check.sh is red nothing is pushed.
- AC8: A restack that stopped on a conflict, whose rebase the worker then continued by hand, is finished by a plain restack that keeps that rebase.
- AC9: When origin's branch for a layer holds a commit that the local branch was never based on, restack exits 1 naming the layer and both tips and changes no branch.
- AC10: When a restacked layer's `check.sh` fails, restack exits 1 naming the layer, pushes nothing for any layer and leaves the local branch as it was.
- AC11: zz-execute and z-work tell the worker to resolve a restack conflict itself, run the specs by name with the command that lists them, continue with one command, repeat if a later layer stops, recover from a red check, stop and ask on an empty resolution or an unclear owner's side, and never skip, drop or force-push by hand.
- AC12: Origin's layer re-finished with the same subject but other content by someone else, while the local branch is stale, is refused and not overwritten.
- AC13: A push to a layer from another clone between the stop and `--continue` is not overwritten: the final push fails its lease, origin keeps that commit and nothing is emitted.
- AC14: A rebase or resolution that leaves a layer with fewer own commits than it had stops with "emptied ... stop and ask" and pushes nothing.
- AC15: `--continue` and `--abort` with no rebase in progress refuse a dirty worktree and discard nothing; a restack that stopped mid-walk (a red check) leaves a marker so `--abort` restores the layers it had moved locally, and nothing was pushed.
- AC16: `--abort` refuses a branch that moved since the run left it, names it, changes nothing and deletes nothing.- AC17: A layer someone else fast-forwarded before the run is built on by it, and its first push succeeds with their commit included and `refs/zn/pushed` noted.
- AC18: A re-finish by someone else, fetched into this clone before the run, is not overwritten by a stale local copy (exit 1, both tips named, origin unchanged).
- AC19: After an abort, a local amend does not overwrite a commit the first run had only fetched.
- AC20: After a conflict, a resolution, a continue and a later red check, `--abort` restores every branch.
- AC21: A diverged layer this clone did not push (no `refs/zn/pushed`) is refused, naming both tips and what to do.
- AC22: A layer this clone pushed and then amended locally is trusted: restacked and pushed.
- AC23: Someone pushes and a fetch follows between the stop and `--continue`: the final push fails its lease and origin keeps their commit; nothing is noted as pushed.
- AC24: A marker with no conflict recorded and a rebase in progress is treated as a stopped restack (`restack`, `--continue`, `work next`).
