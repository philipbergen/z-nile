### F1 [high] (known issue b, confirmed and wider) After a conflict and `--continue`, restack refuses the layer its own run rebuilt, in the clone that pushed everything through zn
Where: `z-nile/engine/restackcmd.luau:265-275`; `z-nile/engine/main.luau:195-199` and `:4972` (`./zn commit` pushes the layer and writes no ref), `:6383`, `:6428` (`./zn approve` the same); spec `reset()` line 150; `guesses.md` G2; `d0434.md` Solution bullets 2 and 5.
Evidence: a diverged layer is trusted only when origin's tip equals `refs/zn/pushed/<layer>`. Only `start`, `finish` and restack write that ref. Probe: on layer 2, `./zn commit -m "R0010: extra work on layer 2"` (exit 0, origin's layer 2 moves, the ref stays at the old tip); layer 1 is amended; `./zn restack R0010` exits 3; the file is resolved and staged; `./zn restack R0010 --continue` exits 1: "origin's branch (25aed6f...) holds a commit that your local branch (cf9c011...) was never based on, so it is someone else's work". The marker of that run holds `judged R0010/2/c0020 <that same origin tip>`: the run took it itself. The same refusal comes with the ref deleted (a clone that never pushed the layer), after a red check followed by the plain restack AC26 allows, and after exit 75 followed by the restack its message asks for (AC30 expects exit 0 there; the probe got 1). A second `--continue` and a plain restack repeat it. The refusal's advice, followed literally (`git rebase origin/R0010/2/c0020`), replays layer 1's commit "fix layer 1" into layer 2 and stops on a conflict in `pickman/src/shared.luau`. The spec cannot see any of this: `reset()` writes `refs/zn/pushed/<layer>` by hand for layers it pushed with plain git.
Critique: Solution bullet 2 (one command continues, checks, pushes and restacks the rest) is unmet for every layer whose last push was a `./zn commit` or a `./zn approve`, which is every layer that carries a review or approval commit. Solution bullet 5 refuses a commit "whose change is on neither the local branch nor the layer below"; the code never looks at changes, and here every change of origin's tip is on the local branch. G2 puts the cost at "a clone that never pushed the layer must rebuild by hand once"; the probe shows the rebuild does not end, and that the clone did push it. The tempting fix is to write the ref in `commit` and `approve` and stop there.
Consequences: writing the ref on every zn push closes the same-clone case and leaves the fresh clone, the hand `git push`, and every layer pushed before the change. A rule that trusts by what the run did needs its own limits: it must end with `--abort` (AC19), must not hold once origin moved, and must not hold for a branch that no longer contains what the run left. It also changes what `finish` may publish (F2, F3).
Recommendation: two rules, both with cases. (1) The run vouches for the tip it took itself: when a layer is taken from origin and rebased, the marker records that origin tip; on any later walk under that marker a diverged origin tip equal to it is trusted while the branch still contains the tip the run left; a plain restack that replaces a stopped run's marker carries the record when the branch is still where that run left it; `--abort` ends it. (2) Every push of a layer zn makes writes the ref (`commit`, `approve`), and the Design lists them. Spec: the fixture stops planting the ref by hand, or these states get cases of their own: the `./zn commit` probe above, the deleted-ref conflict, the red check then plain restack, exit 75 then restack; AC21 (hand rebase, no ref, no marker) and AC19 stay refusals. The refusal's advice gets a case that follows it literally. The owner rules on the rule itself first (see F2: it is the same question).
Lesson: z-design/next-run-reads-a-killed-rewrite

### F5 [medium] (known issue d, confirmed) `--continue` does not notice that a layer the run resolved and pushed is back at its old tip, and pushes a second resolution over the first
Where: `z-nile/engine/restackcmd.luau:455-505` (no comparison of a branch with the marker's `left` or `pushed`), `:349` (the lease is the run's own push, so it passes); Solution bullet 11.
Evidence: probe. Layer 2 conflicts, is resolved ("merged") and pushed by `--continue`; layer 3 conflicts. Critique: bullet 11 says no restack run removes a kept resolution without the worker's abort. Here a restack run replaced it on origin with no word that the branch was not where the run left it. `--abort` has this test (`movedSince`); `--continue` has none.

Recommendation: on `--continue`, and on a plain restack that finds a marker, refuse a layer the marker says the run pushed (or resolved) whose branch is back at its `orig` tip and is not the pushed tip: name the layer, both shas and the command that puts it back, change nothing. This belongs in d0434 with F4 (bullet 11); the question of worktrees that run an older engine may follow.
