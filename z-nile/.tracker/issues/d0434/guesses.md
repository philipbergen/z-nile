# guesses
- G1 (design, 2026-11-21, decided by the lead for the owner): The captured Solution says a layer is pushed when its check.sh passes, before the next layer is restacked. Example: layers 1, 2 and 3 all move and layer 3 conflicts; pushing per layer would leave layers 1 and 2 on origin and 3 not. Chose: nothing is pushed until every layer is restacked and has passed its check; then all moved layers are pushed together in one `git push --atomic`, each with a lease against the origin tip recorded before the run's fetch. `--abort` then restores everything and origin never shows a half-moved stack. Why: a half-moved stack on GitHub is worse than one late push, and AC1 ("pushes nothing") and AC6 ("origin exactly as before") hold as written. The other option is the Solution's per-layer push, where abort cannot undo what was pushed. The Solution sentence is not edited; this is listed under Open to the human.
- G2 (design, 2026-11-21): When the local branch and origin's branch have both moved (a diverged layer), is origin's tip a rewrite of the local branch or someone else's work? Example: layers are one commit with a fixed subject, so a subject says nothing. Chose: origin's tip is trusted when it is the tip this run knew before it fetched, or a tip in the local branch's reflog (the local branch was at it and was rewritten here); otherwise the restack stops naming both shas and changes nothing. Why: a subject or patch id cannot tell a worker's own resolved commit from a re-finish by someone else, but history can. Cost: a local branch whose reflog was expired next to a changed origin is refused and the worker decides by hand.
- G3 (design, 2026-11-21): The conflict exit code is 3. Chose 3 because 1 is every refusal and 2 is used by other commands for usage.
- G4 (design, 2026-11-21): `--continue` does not `git add` for the worker; a resolved file left unstaged still counts as unmerged and is refused, naming it. Why: the ticket says "after the worker has resolved and staged".
