# guesses
- G1 (design, 2026-11-21, OVERRULED by the owner 2026-11-22): The captured Solution says a layer is pushed when its check.sh passes, before the next layer is restacked. The lead had chosen to push nothing until every layer was restacked and checked, then one `git push --atomic`. Asked "during a restack, are layers pushed one at a time as each passes, or all together once the whole stack is done?", the owner answered verbatim: "1 yes push early, you may push before each review and when ready." New rule: each layer is pushed on its own when its check.sh passes, with a lease against the origin tip recorded after the run's fetch, before the next layer is restacked; `refs/zn/pushed/<layer>` is written after each push succeeds. `--abort` restores the layers not yet pushed and leaves the pushed ones (it never force-pushes origin back); a later plain restack goes on from them.
- G2 (design, 2026-11-21): When the local branch and origin's branch have both moved (a diverged layer), is origin's tip a rewrite of the local branch or someone else's work? Example: layers are one commit with a fixed subject, and a fetch or a `reset --hard` puts someone else's tip into this clone's remote-tracking ref and even into the local reflog, so neither a subject, a pre-fetch tip nor a reflog says who wrote it. Chose: trust only what this clone pushed itself: zn writes `refs/zn/pushed/<layer>` (the tip it pushed) after every push of a layer it makes (`start`, `finish`, restack's push of each layer, only once the push succeeded), and a diverged origin tip is trusted only when it equals that ref. With no ref (a fresh clone, a layer someone else pushed) the restack stops naming both tips and says to fetch and rebuild on origin's tip, or ask. Why: it is the one record that only this clone's own push can write. Cost: a clone that never pushed the layer must rebuild by hand once. This adds one ref name to what zn writes in a repository (zz-rules, One layer per ticket).
- G3 (design, 2026-11-21): The conflict exit code is 3. Chose 3 because 1 is every refusal and 2 is used by other commands for usage.
- G4 (design, 2026-11-21): `--continue` does not `git add` for the worker; a resolved file left unstaged still counts as unmerged and is refused, naming it. Why: the ticket says "after the worker has resolved and staged".
