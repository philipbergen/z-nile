# Refute 001: d0434 (answers to review-001, the code review of d0434-fixes)

Ruled by the coordinator for this round: the branch must never make restack lose a commit that main's engine keeps; when in doubt, behave as main does.

- F1: fixed: the carry is removed altogether (`restackplan.carried` and its cases are gone; G10 is withdrawn). A plain restack over a stopped run's marker starts its record from where it finds each branch, as on main: no carried `orig`, no carried `pushed`. `--abort` now prints every branch it moved, with the tip it was on and the tip it is on now. Cases: `restack-guard.spec` "--abort after a plain restack keeps a commit the worker made on a pushed layer between the runs" (probes A and A2: the worker's commit is still the branch's tip, main's outcome); the move lines in that spec's F4 case and in AC32. consequences: review 001 F6's dead end (a plain restack between a refused push and `--abort` loses the first run's record) is back as on main; the way on the refusal names (`--abort`, then a plain restack, with nothing in between) works, and a plain restack that fails before writing its marker no longer removes it (F7). What `--abort` should put back after several stopped runs is put to the owner (`## Open to the human`, review-001 F2).
- F2: fixed as ruled, open to the owner: with no carry, `--abort` after a plain restack goes back to where the last run found each branch, as on main, so a resolution a red check kept stays on its branch. Cases: AC33 (probes B, B2, E) and `restack-guard.spec` "--abort after a plain restack keeps a resolution a red check kept on its branch" (probe B, which kills the carried-`orig` mutant in the gate). The question the reviewer escalated (the start of the first stopped run, or of the last) is under `## Open to the human` (review-001 F2), with both options and their costs. consequences: AC26's "loses nothing" holds again; the Design's Start paragraph is rewritten.
- F3: fixed: the stray test is narrowed to the undo: a layer the run moved (`left` differs from `orig`) whose branch is back at its `orig` tip is refused, whatever `refs/zn/pushed` holds (`restackplan.strayed(now, orig, left)`). Every other tip (a hand rebase, an amend, a fix on top, a finished layer) is the worker's change and goes through the walk as on main. The rebase recipe and the message's second half are removed. Cases: `restack-stray.spec` "a layer the worker rebased by hand during a stop, or fixed and finished, is the worker's change" (probe D3, and probe G's route through `./zn finish`) and AC32's third part (probe D: an amend made while the rebase is in progress): `--continue` exits 0 and the worker's tip is on origin. consequences: the two pure rows the reviewer named changed sides; F8's argument about `refs/zn/pushed` is gone with the exception.
- F4: fixed: a branch back at `orig` is strayed whatever `refs/zn/pushed` holds (the exception is gone). Case: `restack-stray.spec` "--continue refuses a resolved layer the run did not push that is back at its old tip, though refs/zn/pushed is that tip" (probe C: exit 1, both tips named, no rebase started); pure row `strayed("o", "o", "l")`. consequences: none.
- F5: fixed: with no carry, a run's `orig` for the branch it starts on is that branch's tip, never empty; and `--abort` never deletes the branch the worktree ends on. Case: AC33's third part (probe E: the branch, HEAD and a clean worktree stay). consequences: none.
- F6: fixed: for a layer back at `orig` the message names first `git branch -f <layer> <left>` (or, for the branch checked out in this worktree, `git switch --detach && git branch -f <layer> <left> && git switch <layer>`) then `./zn restack <R> --continue`, which keeps a staged resolution; second `--abort` then a plain restack, saying that the abort discards a resolution not yet continued. The sentence about where `--abort` puts a layer is corrected (a pushed layer on the tip it pushed, the others where it found them). Each stray gets its own command. Cases: `restack-stray.spec`'s first case and AC32 follow the first way with a resolution staged (exit 0, the resolution in origin's layer 2), then the second (`--abort` puts the pushed layer on the tip it pushed and names the move). consequences: the message tells the worker to move a ref by hand, limited to a branch that is exactly at `orig`, whose commits the run already rebuilt (recorded as G12).
- F7: fixed: `start` no longer removes the old marker; the new marker replaces it when written, so a start that fails before that leaves the stopped run's record whole. Case: `restack-guard.spec` "a refused push names --abort then restack; a plain restack that cannot fetch leaves the stopped run's marker, so that way still works" (probe F: the marker byte for byte, then `--abort` and a plain restack finish with their commit kept). consequences: none.
- F8: fixed: `restack-guard.spec` runs the `--abort` way the refusal names (in `restack-stray.spec`'s first case: the layer ends on the pushed tip), a dirty plain restack over a stopped run's marker leaves it byte for byte, and fix, `./zn finish`, `--continue` exits 0. One Rules row per rule with its own mutant, each run alone (Verification log). consequences: the guards are two files now (`restack-guard.spec`, `restack-stray.spec`, sharing `tests/lib/restackfix.luau`), so the gate grows by the longer one.
- F9: fixed: both guard watch files name `z-nile/tests/lib/trackerfix.luau`, `fxclone.luau`, `fixture.luau`, `restackfix.luau`, `z-nile/engine/stack.luau` and `z-nile/lib/sh.luau` beside the three restack modules. `main.luau` waits for the owner's tier ruling (design-review-001 F7, F8). consequences: none.
- F10: fixed: (1) `start` reconciles a stopped run's marker, this raft's or another's, before anything else, and no longer removes either. (2) Each stray gets its own command in the message. (3) The pins on "`--continue` does not fetch" and the planted `refs/zn/pushed` stay until the owner rules on design-review-001 F6 and F1 (c); the open bullets say these pins change with the ruling.
