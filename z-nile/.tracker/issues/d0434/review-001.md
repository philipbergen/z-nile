### F1 [high] A carried `pushed` line makes `--abort` take a layer off a commit the worker made after the stopped run, and nothing else holds that commit
Where: `z-nile/engine/restackplan.luau:192-195` (`carried`), `:227-229` (`restoreTo`); `z-nile/engine/restackcmd.luau:435-442`, `:593-601`; `d0434.md:57` (Start); `guesses.md` G10.
Evidence: the `pushed` line is carried whenever origin's tip still equals it, whatever the local branch holds; `orig` is carried only while the branch is where the stopped run left it. Probe A (merged engine): run 1 rebases and pushes layer 1 (Y1) and stops red at layer 2. The worker commits a fix on layer 1 (A1, local, not pushed) and runs `./zn restack R0010`, which stops at layer 1 (its check is red; probe A2: its check did not start, exit 75). The marker then reads `orig R0010/1/c0010 A1`, `left ... A1`, `pushed ... Y1`. `./zn restack R0010 --abort` exits 0, prints "R0010/1/c0010 stay as pushed", and layer 1 is at Y1: `git for-each-ref --contains A1` lists nothing ("NO ref holds it (reflog only)"). The run had started on layer 1, so this is `git reset --hard` (`restackcmd.luau:599`). The same probe on main's engine: the marker has no `pushed` line, the abort prints "nothing had been pushed", layer 1 stays at A1. By reading (`restackplan.luau:421-427`), a conflict at layer 1 in run 2 reaches the same abort, and its stop message lists layer 1 as "already pushed ... (each passed its check.sh)".
Critique: this is new with the branch and it is the outcome the ticket exists to end. Solution bullet 6: "Restack never runs `git reset --hard` on a local branch holding commits that `origin`'s branch lacks." A local amend of a layer this clone pushed is a flow the ticket allows (AC22), and the stop messages offer `--abort` as the safe way back. The tempting fix is to special-case `restoreTo`.
Consequences: narrowing the carry leaves a layer the worker moved with no `pushed` line in the new marker, so an abort no longer names it as pushed; that is true to the branch (its tip is not the pushed one).
Recommendation: carry the `pushed` line under the same condition as `orig`: only while the branch is still where the stopped run left it (`old.left[name] == now`), and origin still holds that push. Tried here as a one-condition change: probes A and A2 keep the worker's commit, and `restack-guard.spec`, `restackplan.spec` and AC6, AC13, AC20, AC23, AC25, AC27, AC28, AC33 stay green. Cases: a pure row (`carried` with the branch moved and origin still at the push returns no `pushed`), and probe A as a case in `restack-guard.spec` (the worker's commit is still the branch's tip after the abort).
Erred: z-design
