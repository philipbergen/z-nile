# d0439: Idea run stops other commands

## Problem
- While `./zn idea` runs in the background of an AI CLI session, every other command that session starts ends within one to fifteen seconds with the observed exit code 144, and neither what ends those commands nor why is confirmed.

## Non-goals
- Other `zn` commands that start a nested AI session, and commands of sessions other than the one that started the idea run, are not covered until a problem is observed there.

## Solution
- What ends the commands and why it happens are confirmed and recorded in the issue, whether or not a signal is involved, and a check proves that a `./zn idea` run never ends a command of the session that started it.

## Design
<!-- Modules and paths, public types and signatures, data flow, pure Logic vs adapter split,
     client/server authority. Must agree with the raft's whole-raft design and the project's architecture.md (in its root, as pickman/.tracker/). -->
- Cause (confirmed 2026-11-21, by the code and a dry run). The SessionEnd hook (`scripts/hooks/session-end.sh`) runs `./zn reap --session-end`, which takes for the ending session the nearest ancestor of the reaper whose program name is `claude` (`z-nile/engine/reap.luau` `reap.sessionRoot`, `reap.name`) and stops every tool shell that is a direct child of it (`reap.decide`, the SESSION END rule), except the reaper's own ancestors (`opts.self`). `./zn idea` (and `./zn dispatch`) start the nested CLI by its resolved real path (`modelstep.luau`/`dispatcher.luau` `resolveBin`: `Cwd::realpath`, then `argv[1] = bin`), and the runner's supervisor execs `argv[1]` as argv[0] (`runner.luau` SUPERVISOR `exec { $ARGV[0] } @ARGV`). The native install keeps the CLI at `~/.local/share/claude/versions/<version>`, so the nested session's process is listed as `.../versions/2.1.330 -p ...`, named `2.1.330`, not `claude`. When a nested call ends, its own SessionEnd hook walks past it to the OUTER session's `claude` and stops all of the outer session's other tool shells (TERM, two seconds, KILL); the shell running the idea script survives because it is an ancestor of the reaper. Evidence: `~/.local/state/z-nile/reaped.log` holds "started by the session that is ending" lines on 2026-11-21 (00:55, 10:28-10:30, 10:38, 11:17) for tool shells of sessions that went on; a dry run (`./zn reap --session-end --dry-run` under a parent whose argv[0] was `.../versions/2.1.330`) listed every other tool shell of the calling session, a bounded victim included, and the same run under a parent named `claude` listed none.
- Reach. Only the session that is an ancestor of the nested call loses commands (its main thread and its subagents, which share its process): a session in another terminal or of another account is never an ancestor, so the session rule cannot select its shells. Every command that starts a nested CLI through the runner has it: `./zn idea`, `./zn dispatch` (every step, and an author's nested `./zn dispatch zz-review`), so `./zn work` run from a Claude Code session too. `./zn approve`'s walk starts `claude` by name and is not affected.
- Fix: the CLI runs under its own name. `runner.Request` gains `program: string?`, the file to execute; `argv[1]` stays the name it runs as. The supervisor takes the program as a fourth argument and runs `exec { $prog } @ARGV`. `modelstep.drive` and the dispatcher's step pass `program = bin` instead of overwriting `argv[1]`. The resolved file is still the one executed, so the check-run guard (only a CLI under `.cache` may start) is unchanged. The hook, the settings and the reaper's rules are unchanged: a nested session's end now stops only its own tool shells, and a `/clear` of the outer session still stops the outer session's.

### Scalability
- Nothing grows: one more supervisor argument.
### Maintainability
- One rule in one place (the runner): what a process listing shows is the CLI's name, whatever file was resolved.
### Usability
- Parallel workers and a session's own background commands survive the session's nested model calls.
