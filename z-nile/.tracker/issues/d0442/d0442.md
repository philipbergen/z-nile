# d0442: Done without code review

## Problem
- On the normal path `./zn done` reads a raft's approval, trace and `final-review-NNN.md` but not the `review-NNN.md` files in the raft's folder; it reads them only for a raft that took the light path and is no longer light.
- A raft on the normal path whose folder holds no `review-NNN.md` therefore lands when its final review approves.

## Non-goals
- The round numbers in f0421 stay maximums with one round as the aim, and this issue changes neither.
- `rounds.next`, `rounds.latest` and `openlist.unanswered` are not changed.
- The light path's own review rule (f0420 step 3) is not changed.
- No check is added to any command other than `./zn done`.
- Review files are not tied to layers: the code review stays one series per raft.

## Solution
- `./zn done` refuses a raft on the normal path when the raft's folder holds no `review-NNN.md`, and the refusal names the raft and says to run the code review.
- `./zn done` accepts the code review of a raft on the normal path exactly when `rounds.next` returns `settled` for `rounds.latest` of the raft's `"code"` files at `rounds.max(limits, "code", level)`, where `level` is `rounds.highest` of its tickets' levels, and it adds no condition to f0421's rule.
- `./zn done` refuses such a raft when `rounds.next` returns any other step (`file`, `answer`, `rule` or `malformed`), and the refusal names the latest round's file and that step.
- `./zn done` accepts a raft whose final round's serious findings are all answered "fixed" with no guess recorded, because `rounds.next` returns `settled` for it.
- `./zn done` accepts a raft that settled at `review-001.md`.
