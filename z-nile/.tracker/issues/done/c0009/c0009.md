# c0009: Renumber scoped to item

## Problem
`tracker.sh renumber <old> <new>` rewrites every `<old>` in `tracker/`. The rule for ID conflicts exists precisely because two different items share an ID, so renumbering one of them also rewrites references to the *other* one, including review records. On 2026-09-29, renaming c0004 to c0005 had to be done by hand for this reason.

## Non-goals
- Automatic conflict detection on merge.

## Solution
_Draft ideas; design happens in ticket-prep._
Only rewrite the renumbered item's own directory, plus explicit `--also <path>` references such as its raft's `issues:` and member docs. Never touch review or refute files. Add a spec using two items that collide.
