# c0059: Adapt R0020 to the repository guards

## Problem
R0020 (c0053, publish tracker state to main) lands **before** R0021. That is the user's decision, recorded in R0020.md and confirmed on 2026-10-01. So when R0021 executes, R0020's code and specs are already on `main`, written before the guards existed:
- `tests/acceptance/c0053/commands.spec.luau` and `publish.spec.luau` set `GIT_CEILING_DIRECTORIES` themselves, which replaces the runner's fence chain instead of keeping it. c0058 lets them through for now with an allowlist entry (a `GIT_CEILING_DIRECTORIES` entry, "removed by c0059").
- The publisher pushes tracker state to `origin/main` whenever a tracker command runs in a checkout with an origin. c0058 deliberately lets a `check.sh` push to the network, because `scripts/ci-verify.sh` needs GitHub. So a `check.sh` whose own commands run a tracker command at the real root would publish real tracker state. (Specs a check starts run in specs mode, where git has no network transport at all.) That is a check changing the real repository's remote.

The second user request this answers, quoted: "file a chore on r210 to update r200 and r190".

R0019's part (c0052's fixture identity) was fixed in R0021's prep, because R0019 hasn't started: its sequestered spec now commits as `t@example.invalid`. Nothing about R0019 is left here.

## Non-goals
- R0020's behaviour outside a check, and its acceptance criteria.
- How the publisher builds its commit. R0020's re-prep moved that to `git mktree`, with no index, at the user's request ("Redesign the publisher"), so `scripts/tracker/publish.luau` names no git variable.
- Retrofitting c0053's specs onto `@tests/lib/fixture` (c0060 covers the twelve older specs).

## Solution
- Remove c0053's own ceiling from its two promoted specs.
- Narrow their allowlist entries to the hook names.
- Make the publisher refuse to publish from a repository the guards protect.

## Design
1. **c0053's specs** (Overrides): in `tests/acceptance/c0053/commands.spec.luau`, `fenced(env)` no longer adds `GIT_CEILING_DIRECTORIES`: it returns `table.clone(env or {})` (a hand-written copy trips selene's `manual_table_clone`), and its comment says the runner fences git inside `.cache` (c0058). In `publish.spec.luau`, the `git()` helper passes no env. Nothing else changes, and no assertion changes.
2. **Allowlist** (`tests/tooling/repo-fence.spec.luau`, `ALLOWED`):
   - c0053's two entries keep only `GIT_DIR`, `GIT_INDEX_FILE` and `GIT_WORK_TREE`, with the reason "fixture hook". Their fixture `pre-push` hooks start with `unset GIT_DIR GIT_INDEX_FILE GIT_WORK_TREE`, so that their own git calls reach the right repository.
   - This issue's own promoted spec, `tests/acceptance/c0059/adapt.spec.luau`, gets `GIT_CEILING_DIRECTORIES` (it asserts c0053 names none), `GIT_CONFIG_` (planted, to prove the scan flags it) and `PICKMAN_TEST_FENCE` (it runs a copied gate as a top-level run). Without the entry, the first gate after `done` promotes it would fail (review 007 F1).
   - The publisher needs no entry: it names no guard variable (see 3).
3. **The publisher stays local inside the guards** (`scripts/tracker/main.luau`, `scripts/lib/fence.sh`):
   - **Where:** in `publishing()`, which already decides `PICKMAN_PUBLISH=0`, so a refused publish behaves exactly as that: the command succeeds and works locally, HEAD and `origin/main` are untouched. (Inside `publish.commit` there is no local path, review 007 F3.)
   - **How it decides:** a new function in the guard's own script, `pickman_guarded <dir>` in `scripts/lib/fence.sh`. It resolves the repository's common git dir (`git rev-parse --path-format=absolute --git-common-dir`, then `pwd -P`) and exits 0 when that dir is one of the colon-separated entries of `PICKMAN_FENCE_REAL_GIT`. `main.luau` runs `bash -c '[ -f scripts/lib/fence.sh ] && source scripts/lib/fence.sh && pickman_guarded "$PWD"'` at most once per command (memoised) and, when it succeeds, prints `not publishing: <dir> is protected by the repository guards (a check run)` once to stderr. So no tracker file names a guard variable, and the gate needs no exception (the function's name avoids the scanned `pickman_fence_` prefix).
   - **Elsewhere:** fixtures in specs, and a person's or an agent's own tracker commands outside any check, are unaffected, because the variable is unset or doesn't list them.
4. **Testing skill**: under "Specs never touch the real repository", one sentence: tracker commands run by a check never publish tracker state; the publisher says `not publishing` and goes on as with `PICKMAN_PUBLISH=0`.

### Scalability
One `rev-parse` and a string scan per publish, only when `PICKMAN_FENCE_REAL_GIT` is set.
### Maintainability
- The refusal reuses the guards' own list of protected repositories, rather than a second marker.
- The allowlist names each exception with its reason in one table.
- Once c0053's entries hold only the hook names, any new bypass in those files fails the gate.
### Usability
A check that runs a tracker command sees why nothing was published. Nothing changes outside checks.
