# c0097: Spec isolation run lock

## Problem
Once `tracker.sh done R0026` promotes them, c0076's `sweeper.spec.luau` and c0078's `jail-signals.spec.luau` read the run's lock at `.cache/tests-run.lock/pid` to find the top process outside the jail. `tests/acceptance/c0058/lock.spec.luau` (and R0026's new live signal case in `tests/tooling/repo-fence.spec.luau`) name the same path. c0049's `spec-isolation.spec.luau` fails the gate on any `.cache/<dir>` named by two spec files. So the full gate that c0074 makes `done` run on the done tree fails, and R0026 can't finish. It can't be postponed: it blocks `done`.

## Non-goals
- The isolation rule for real fixture folders: unchanged.
- Renaming the lock.

## Solution
By the user's decision (2026-10-05, "Exempt tests-run in c0049"): the lock is the runner's own, not a fixture, and specs only read it. Add `tests-run` to c0049's `SHARED_BY_DESIGN`, beside `sim`, with the reason, and a scanner case for it.

## Design
`tests/acceptance/c0049/spec-isolation.spec.luau`: `SHARED_BY_DESIGN` gains `["tests-run"] = true`; the header comment says why; a new case `ignores the runner's lock, which specs only read` plants two files naming it and expects no collision.
