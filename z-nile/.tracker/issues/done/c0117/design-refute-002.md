# Refute 002: c0117 (answers to design-review-002.md)
Prototype: `proto-c0117` rebased onto `proto-c0116` 5fa0a8d (c0116's final): simulation, then the edits. The user decided F4 on 2026-10-21 ("Persisted watermark"), recorded as a `Decided with the user` line. Each finding came from a mechanism added in round 1, so each answer questions the mechanism (z-run 4a), not the hole.

- F1: fixed, by replacing the mechanism: one definition of tracker state, `z-nile/engine/trackerstate.luau`, which the wrapper, the broker, the tripwire and the watermark all call. It reads `git diff-tree -r --raw --no-renames --no-abbrev` (a rename's source is a deletion it judges; both sides' modes), allows only paths under `<root>/` (with the slash) or exactly `z-nile/next`, only modes 100644 and 100755 (no symlink, no submodule), and no `.gitattributes` or `.gitmodules` anywhere. The tripwire no longer exempts broker pushes: it re-vets every commit since the watermark with the same function. trackerstate.spec covers a rename out of a root (pure and through git), `z-nile/nextgen/` and `tracker-x/` siblings, symlink and submodule modes, git configuration files, and the broker refusing code. consequences: the wrapper's and the broker's verdicts now agree by construction (one function, one spec); the tripwire's broker exemption is gone, so a mutant restoring it is equivalent while the two share the function (reasoned row); M91–M93.
- F2: fixed: the shared check, with `sequestered` (the broker, the wrapper, the tripwire and the watermark all pass it), refuses any change to an existing `check.sh` or anything under an `acceptance/` folder that isn't a pure move (the same blob and mode deleted at one path and added at another, as `ready` and `stop` move item folders); a new item's own stub is an addition and passes. consequences: a skill step that must edit a sequestered file from inside a step can't; none does today (design and run edit them in a PR, which the watermark vets as a PR merge), so no escalation; M94.
- F3: fixed: the broker never forces. It fetches `main` fresh, refuses any commit that is not a fast-forward of it ("rebuild it on main and ask again"), and pushes with a plain `git push` (a `main` that moved since refuses it); the request's `base` is ignored. `publish.commit` already rebuilds and retries on a refused push. trackerstate.spec: a rewind to an older commit is refused and origin's `main` is unchanged. consequences: the lease is the ancestor check plus git's own non-fast-forward refusal; M95.
- F4: decided by the user (2026-10-21): "Persisted watermark". The dispatcher keeps the last vetted commit of `main` in a file outside the repository and every worktree (`$ZN_WATERMARK_DIR`, else `$XDG_STATE_HOME/zn-dispatch`, else `~/.local/state/zn-dispatch`, a folder named for the repository, `main-seen`) and vets every commit since it with the shared function at the start of every run, before every step and after every step; an unvetted commit stops the chain (exit 5) until the user runs `./zn dispatch vet`. It detects a late push after the fact and never prevents one (said in §5, zz-rules and the decision). control-cli: a direct code push between runs stops the next run until `vet`, tracker state pushed elsewhere passes, and a detached process's late push after a step is caught by the next run. consequences: a code commit on `main` that GitHub reports as a pull request's merge is vetted (otherwise every human merge would stop the chain: Guess G20); a first run with no watermark trusts `main` (said plainly); M97–M99.
- F5: fixed: settings, caps and models are read from the tracked `.models.toml` files at `main` fetched once per run (`models.walkAt`, the pinned commit), never the working tree; a working-tree `.models.toml` on the walk that `main` doesn't have is an error. The tripwire's check of the main checkout now compares `git status --porcelain --untracked-files=all` and `git diff HEAD`, so a new untracked file or a further edit to a dirty one trips it. dispatch-cli: an uncommitted closer file is refused before anything starts. consequences: a `.models.toml` a prep PR adds takes effect only after that PR merges (the safe direction, in §1); M100.
- F6: fixed: `Facts.pr` gains `head` (`headRefOid`) and `files`; `dispatch.prFiles` lets a prep PR carry only the issue's own folder and skill lessons and a rafting PR only its project root's documents; an unknown file list or head never merges; the merge is `gh pr merge <pr> --squash --match-head-commit <head>`, so a push to the branch after the check voids it. control-cli: a prep PR carrying `src/x.lua` waits at the gate; the merge is pinned. consequences: a prep that changes `architecture.md` waits for a human (fail closed; noted in §6); M101, M102.
- F7: fixed: each top-level run serves a broker folder of its own (`<id>/broker`), its requests bound by a run token (`ZN_PUBLISH_TOKEN`); a server claims a request by rename (one wins) and never raises (the whole serve is under `pcall`); a nested step inherits its author's folder and token. trackerstate.spec: two servers on one folder answer each request once and refuse another run's; dispatch-cli: the step's broker is the run's own folder. consequences: a nested review's publishes reach its author's dispatcher; M96.
- F8: fixed, as the user's decision requires (fail closed): the cursor adapters count a model call at each distinct `model_call_id` and, when a turn carries none, at the turn's start (the first `thinking` or `assistant` line after a `user` line or a finished tool call); three turns in a row with no `model_call_id`, a line type agent doesn't print, or a non-JSON line stops the step as `cap-unknown`. `cursor-app`'s stream stays unproven: E9, with an escalating fallback. adapters.spec and control-cli cover the blind stream (stopped as `cap-unknown`), the unknown line type and the non-JSON line. consequences: a new outcome `cap-unknown` (the chain stops on it); `NO_ID_TURNS = 3` is a guess (G16); M103, M104.
- F9: fixed in §8: the ruleset gains `{ "type": "update" }`, so only bypass actors (the admin role: the dispatcher's merges and the user's tracker pushes) can update `main`, and the bot can't merge its own green PR through the API either; E10 now asserts the bot's direct API merge is refused, and that the admin's tracker pushes still land. The alternative (one approval from the user) is offered in §8 as the user's choice.
- F10: fixed: the stale stop marker is cleared before the state says `running`, never after; the runner no longer clears it and, finding one, returns `stopped` before starting the CLI; `stop` on a `running` state whose run lock is held writes the marker and says "stop requested" instead of marking it lost. control-cli covers the stop while starting. consequences: none; M105.
- F11: fixed: a nested step's folder is `<step>-<mode>-<id>-<n>`, claimed with a plain `mkdir` (no `-p`) and retried at `n+1`, so two at once get two folders. consequences: c0118's interface names the new folder form; M106.
- F12: fixed: the broker waits 600 s (one value, §5 and G19), and G14 says `size: 4100`, as the front matter and Size do (remeasured: review 002 added about 400 lines).
