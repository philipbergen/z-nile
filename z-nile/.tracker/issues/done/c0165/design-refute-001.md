# Refute 001: c0165 (design review 001)

- F1: fixed: only a runner exit of 0 records `passed` rows, in `specs run` and in `record --full`. A non-zero exit records only the files its results show failed. When the results show no failure, it prints `runner exited <code>: <n> results not recorded` and counts the run failed (R33). New gate.spec case: a fixture spec that calls `open` (answered by the browser guard's stub) passes, but the run fails, no `passed` row exists, the next run runs it again, and the same holds through `check.sh --full`. consequences: a tripwire or browser-guard failure now costs a rerun on the next gate, which is the intent. No pass is lost for any other reason, because those runs exit 0.
- F2: fixed: `z-nile/affected` reads learned rows only with `--learned`, which `check.sh`'s selection call passes. A bare call, which promoted specs and reviewers run at the real checkout, reads `inputs.tsv` only (R34). gate.spec: AC8's after-call passes `--learned`, and a bare call prints nothing. The tracker-file miss case shows both. The Modules table and `context.luau` (`learned = true` only when asked) say so. consequences: the selection call in `check.sh` gains one flag, and promoted specs that run `affected` keep the committed answer on every machine.
- F3: fixed by a user decision (`Decided with the user (2026-10-27)` in the Problem: "Accept the residue"). Only a deliberate overwrite of the results file can fake a pass, and only for pre-merge affected runs. The merge gate runs fresh. The "never in a full run" sentence is replaced by the exact residue: affected runs, plus `record --full`'s rows, which nothing reads, since the mode is in the fingerprint (F6). consequences: F1, F4 and R31 close every way short of a deliberate forgery, as the Design now says.
- F4: fixed: `workspace.blobs` returns `nil, reason` on any failed git call, an id count that differs from the path count, or a path holding a newline. Then `run` takes reuse off, `record --full` and `gate-record` record nothing, `digest` prints nothing, and R31's re-read counts as changed (R35). Cases: digest.spec, a newline path gives nil and the map comes back once it's gone; gate.spec, a `git` wrapper that fails `hash-object` gives `reuse off:`, and every spec runs twice. consequences: "reuse off" now has two causes, and its reason says which.
- F5: fixed: a path under a project root may be an input, but only through an `Inputs` entry (declared or learned) that itself names a path under that root. A broad entry like `pickman/` never reaches into a root, and the root itself and every `spend.md` never are inputs (R36, which restates R3). `parseInputs` accepts the Design's example and refuses the root itself and `spend.md`. Learning's candidates now include changed root paths except `spend.md`, and print `not learned: …: no candidate outside spend.md` when none is left. Cases: select.spec (AC1's property with a declared root folder and its spend.md, AC2 moves, AC9 accept and refuse), gate.spec (a tracker-file miss is learned). consequences: affected selection now picks a spec for a root path it declares, which is what declaring means. With no declarations, the old outcome "project roots select nothing" holds, as the moved-rules case pins.
- F6: fixed: `mode <affected|full>` is a fingerprint line (R37), as the capture says, and AC2 has a case. consequences: full-mode rows are now a record of cases only (scope decision 3). No affected run reads them, so the F3 residue shrinks to affected runs.
- F7: fixed: the gate speed comes from `done`'s full-gate output and goes in the `Ready to merge` PR comment (Phase 5 step 5), never into a tracked file after `done`. The Wording and docs.spec pin it, and pin that the "Verification log" phrasing is gone. consequences: nothing tracked changes between `done` and the merge condition except `spend.md`, which the digest leaves out.
- F8: fixed: a new gate.spec case. A staged `git mv` and a staged edit pass `--full`, then a `spend.md` is written and everything is committed, and `--full --reuse` is reused with nothing run. An edit of another tracker document after that runs again (R44). consequences: none.
- F9: fixed: the zz-test "Exit criteria" sentence (`--affected`) and the AGENTS.md wording ("and the gate writes its results db, `.claude/.znile_tests.sqlite`") are in the Wording list and pinned by docs.spec. consequences: none.
- F10: fixed: AC12's reverse substitution is limited to the lines that call the template's gate (`z-nile/check.sh" --project <p> --affected`), and its positive grep requires that line. The false comment is replaced. It was checked on the prototype's four narrowed files against `origin/main`: all four are byte-identical. consequences: none.
- F11: fixed: four cases and rows. A waiter whose owner's spec fails (R41). A gate whose tree changes while it runs records neither a gates row nor `record --full` rows, and says `records nothing` (R42). A runner that quits before writing results gets its claims released and counted failed with `results file missing` (R43). The failed-row path is covered too. consequences: none.
- F12: fixed: a lifeline. The orchestrator starts the runner through an inline perl supervisor that puts it in its own process group and kills that group about 3 s after the orchestrator is gone (it polls `getppid`). The orchestrator also sweeps `spec-results-<pid>.json` files whose pid no longer holds (R38). New case: only the orchestrator is killed (the pid its db row names); the next run takes the spec over and passes, and the orphaned runner, which records its pid, is dead 5 s later. Runs nested inside a spec take no runner lock, so the case tests the process, not the lock. consequences: the runner's own cleanup (lock removal, snapshot) doesn't run when the lifeline kills it, which leaves a lock held only by dead processes, which takeover already handles. The tripwire's second snapshot is skipped for that killed run, which recorded nothing.
- F13: fixed: a total budget, `PICKMAN_LEARN_BUDGET` (default 40 trials), on top of the per-miss cap. `learn.plan(candidates, max, budget?)` returns the trials and the budget left, and an empty plan when they don't fit. A miss not tried prints `learning budget spent` (R39, plan.spec case). consequences: learning after a large miss stops early, and the misses not tried are still named.
- F14: fixed: `isInput` is restated as two parts: root paths only through an explicit entry, and any other path through at least one of the listed rules.
- F15: fixed: the exception is stated. Removing S's own `inputs.tsv` line changes S's fingerprint but doesn't select it, so the cost is one harmless rerun. consequences: none.
- F16: fixed: `gates` stores the static stages' report (`summary`, from `par_wait`'s output), and a reused gate prints it before `GATE PASSED` (R40). store.spec pins the round trip, and gate.spec pins a reused affected gate showing `== lint (selene)`. consequences: the schema gains a column (schema 1 is unreleased).
