# c0185: Cross home gate

## Problem
The user, 2026-10-31: "I want to branch out into multiple games, they will each have their own directory in the project: first person snake, first person asteroids. I also want a new project for a landing portal where you can scroll between the games and see the highscores for each, the same cost model remains but it shoudl show 5 robux for each game witha slash through showing it is currently on sale for 1 robux. highscores shoudl show how many revives were used." Then, on the plan: "Add a third game first person asteroids."

The games share code through the `arcade` library (c0183): each place's `*.project.json` maps `"$path": "../arcade/src/shared"` to `ReplicatedStorage.Arcade` and `"../arcade/src/server"` to `ServerStorage.Arcade`, and adapters require `@game/ReplicatedStorage/Arcade/...` (server roots also `@game/ServerStorage/Arcade/...`). Today the gate can't follow that:
- `graph.srcAliasAllowed` (`z-nile/lib/graph.luau`) allows only `@game/ReplicatedStorage/`;
- `graph.affectedSpecs` re-runs a home's place specs only for `src/` and `lobby.project.json` (hard-coded), so an arcade change would not re-run the games' place specs;
- `z-nile/affected.luau` HOME_FULL matches only `default.project.json`;
- `pickman/tests/lib/place.luau` hard-codes its script roots;
- nothing stops game Logic from requiring arcade Logic, which resolves in Lune (filesystem) but not in Roblox (instance tree).

What should happen: a change under `arcade/` selects every dependent game's specs (unit, through `@arcade`, and place), the place harness lives in `z-nile/tests/lib/` and reads its script roots from each project file, `@game/ServerStorage/` is allowed from server roots only, and `tests/meta/architecture.spec` fails a Logic require that resolves outside its home.

## Non-goals
- Scaffolding the homes: c0184.
- Moving any pickman feature into arcade: arcade and pickman issues captured after c0183.
- Any arcade feature, game, portal or library code. The library keeps its one identity module (c0184); the first feature that needs a server-side Lune alias or a second library root asks for it.
- Moving `sim` or `fakeengine` into the shared harness (a game that needs one asks, as this chore does for `place`), and pickman's lobby: `lobby.project.json`, its place specs and the legacy answer for a home without a project file (which still names it) go with c0188.
- The N-place deploy manifest and scripts (the plan's Z3, a portal issue): this chore only shows that `Beta.project`'s copy of a project file with a library `$path` builds (E1c).

## Solution
- Experiments: E1, whether `rojo build`, `serve`, `sourcemap` and `luau-lsp analyze` accept a `$path` outside the home (and `Beta.project`'s absolute-path copy); E2, whether Roblox honours anything that would let Logic require across roots (expected not, so arcade features stay leaves that adapters wire in).
- (Prep, after the captured bullet.) Both pass (Unknowns & experiments), and the rest is five small mechanisms, all in z-nile except the wiring the homes carry: the `arcade` alias in every home's `.luaurc`; the library's two folders mapped in every home's default place, with the home rule widened for exactly those two `$path`s; the place harness in `z-nile/tests/lib/` reading its script roots from the project file, re-exported by every home, with one generic place spec per home; the graph and selector following every `$path` of a home's project files (and `@game/ServerStorage/` from server roots); and one cross-home rule in pickman's structural spec, which every home runs.

### 1. The `arcade` alias
Every home's `.luaurc` gains `"arcade": "../arcade/src/shared"`: pickman, portal, snake, invaders, asteroids and arcade itself (the same line everywhere, so a spec copied from the library into a game, c0183's "copy the feature and its specs" step, keeps its requires). A spec reaches a feature as `@arcade/Logic/<Feature>`, which is the Roblox path `ReplicatedStorage.Arcade.Logic.<Feature>` without its service. No alias in the root `.luaurc` (c0184 removed the root's aliases into a game for the same reason: a home that left one out would resolve it through another's folders), none for `src/server` (server-side library code is judged by the place tier, E2/Design 3, not loaded by a Lune unit spec). `graph.aliases` and Lune resolve it from the requiring file's own `.luaurc` chain, and `luau-lsp` finds the nearest `.luaurc` (E3).

### 2. The library in every place
- Each game's `default.project.json` (pickman, portal, snake, invaders, asteroids) maps `ReplicatedStorage.Arcade` = `../arcade/src/shared` and `ServerStorage.Arcade` = `../arcade/src/server`, beside its other nodes; arcade's own file already maps them as `src/shared` and `src/server`.
- **(Prep choice, marked: pickman is mapped too.)** The plan says "each place", and pickman is where the first features move (A1 to A4 each have a pickman switch chore). The built pickman place gains an empty `ServerStorage.Arcade` folder and a `ReplicatedStorage.Arcade` folder holding arcade's `Info` module; nothing requires them, and `place.scripts` lists only the home's own nodes, so c0002's "only from the three script roots" still holds unchanged. Its cost while kept: every change to the library also runs pickman's place tier and the acceptance specs that load its place (43 pickman specs of the 48 `lune run z-nile/affected -- arcade/src/shared/Info.luau` selects, measured on the prototype), until pickman's first switch chore uses the library; f0197, f0199 and f0201 already `depends_on` this chore, so it starts with the arcade build-out. Cost if overruled: pickman's two lines go and its first switch chore adds them; the home rule then needs an exemption for pickman (one constant). `lobby.project.json` is not mapped (it retires with c0188).
- **The home rule (`z-nile/tests/lib/home.luau`, c0184's) is widened, not overridden** (it is code, its fixtures are `homes.spec`'s and stay green as they are, E4): a `$path` may leave the home only as the library's two folders, each **at its own node** and in any project file of the home: `arcade/src/shared` at `ReplicatedStorage/Arcade` and `arcade/src/server` at `ServerStorage/Arcade` (the folders compared collapsed, `collapse("snake/../arcade/src/shared")` being `arcade/src/shared`; each a folder whose real path is inside the library's real home). The server folder anywhere else, say under `ReplicatedStorage` or `StarterPlayerScripts`, would replicate to every client: the rule reads "maps the library's arcade/src/server at ReplicatedStorage/Leak, which is not its node" (design review 001 F2). Any other folder of the library (`../arcade/tests`, `../arcade/src`) or of another home still reads "outside the home", in either form of the `$path` (Design 4's walker reads the `optional` table too), and a folder that holds a project of its own (`default.project.json`, which Rojo follows through that project's mappings) is refused as a nested project. The rule also requires `.luaurc` alias `arcade` (`../arcade/src/shared`), the default place's two mappings (the nodes above; the library's own file maps them from inside its home), and the place tier's two wrappers (Design 3). One constant, `LIBRARY_HOME = "arcade"`, beside `RULES_HOME`.
- **(Prep choice, marked: pickman's lobby place is not mapped.)** `lobby.project.json` retires with c0188, and mapping it now would ship the library into a place that is going away. Cost if overruled: two lines in `lobby.project.json`, which the rule, the selector and `serverFile` already accept at the same two nodes (a second project file mapping both is a clean case of `library.spec`; a lobby server file requiring `@game/ServerStorage/Arcade/...` is a clean case of AC6's fixture, which has a second place). Who pays otherwise: the first pickman switch chore that moves a lobby adapter (`Boards`, `Starts`) before c0188 lands, which is c0198 (Boards) and c0200 (Travel), now captured; f0061's lobby place spec fails loudly if it forgets.

### 3. The shared place harness and the place tier
- `pickman/tests/lib/place.luau` moves to `z-nile/tests/lib/place.luau` in a renames-only commit, then is edited. It runs from the home (the project file and `.cache` are the home's, as before). `place.load(project?)` also decodes the project file, takes `graph.gameRoots` of it and remembers, for the built DataModel, the instance path of every node whose `$path` stays inside the project file's own folder (`graph.insideFolder`: its `.` and `..` segments applied, none climbs out; `src/../../arcade/src/shared` does not). `place.scripts(game)` lists the `LuaSourceContainer`s under those nodes (sorted, no duplicates; the node itself counts); for a DataModel `load` did not build it errors, naming the rule. `SCRIPT_ROOTS` is gone. So pickman's two places keep their answers (default: Shared, Server, Client; lobby: Shared and the two Lobby roots), a home with a new root needs no edit here, and the library's scripts are not the game's: they are judged by arcade's own place spec, where they sit in the home's roots. `resolveRequire`, `requireSpecs` and the build are unchanged.
- Every home (the six) gets `tests/lib/place.luau`, `--!strict` and `return require("../../../z-nile/tests/lib/place")` (pickman's old file becomes this), and `tests/place/library.spec.luau`: `local place = require("@tests/lib/place")` and `return require("../../../z-nile/tests/lib/placespec")(place)`. `z-nile/tests/lib/placespec.luau` is `(place) -> Spec`: the home's default place has `ReplicatedStorage.Arcade` and `ServerStorage.Arcade` folders (the build accepted the mapping), and every string require of every script in the home's own roots resolves on the instance tree (`@game/ReplicatedStorage/Arcade/...` and `@game/ServerStorage/Arcade/...` included). The spec takes the home's re-export so that its closure names the home: `graph.affectedSpecs` finds a home's place specs by `<home>/tests/lib/place.luau` in their closure, which the shared file alone could not say.
- A spec never requires the shared file itself: Design 5's second rule fails it (a spec that skips the re-export would not be selected when the home's place changes).
- **The home rule requires both files in every home** (exact lines once comments go, as for the other wrappers), so a new project is held to the place tier like the rest of the scaffold.

### 4. The graph and the selector (`z-nile/lib/graph.luau`, `z-nile/affected.luau`)
```lua
function graph.srcAliasAllowed(spec: string, fromServer: boolean?): boolean   -- + "@game/ServerStorage/" when fromServer == true
function graph.serverFile(file: string, places: { { GameRoot } }?): boolean  -- one list of mappings per place
function graph.srcAliasViolations(dir: string, places: { { GameRoot } }?): { { file: string, spec: string } }
function graph.mappings(project: any): { GameRoot }                           -- every "$path" of a project and its node, both forms
function graph.insideFolder(path: string): boolean                           -- a "$path" that stays in its project file's folder
function graph.placeInputs(home: string): { string }                          -- home is "" or "<dir>/"
function graph.affectedSpecs(g, changed, isSpec, inputsOf: ((string) -> { string })?): { string }
```
- **`@game/ServerStorage/` from a server root only.** `srcAliasAllowed(spec)` keeps its one-argument meaning (c0041's cases pass unchanged); with `fromServer = true` it also allows `@game/ServerStorage/`. `serverFile` says whether a file is a server file: at least one place maps it, and in **every place that maps it** the node that owns it (the longest mapped path within that place) is under `ServerScriptService` or `ServerStorage`. The places are every `*.project.json` directly in the home (read through `graph.mappings`, a file that is not a project an error naming it), so a pickman lobby's `src/lobby/server` is a server file by the lobby's project file, while a folder one place keeps on the server and another replicates is not (a ServerStorage require would fail in the second; design review 002 F2). A client-visible node nested in a server folder is not a server file, and `srcAliasViolations` asks `serverFile` per file, so a client or shared file requiring `@game/ServerStorage/...` is listed, and so is any file requiring `ServerScriptService` or `StarterPlayer` (unchanged). `ServerStorage` and `ServerScriptService` never replicate, so the client case fails at runtime; the resolvers cannot tell, which is why the meta spec enforces it.
- **One reader of a project's mappings** (design review 001 F3). `graph.mappings(project)` walks the tree once and returns `{ instance, path }` for every `$path`, in Rojo's two forms (a string, or the `optional` string of a table), the tree node itself included (instance ""). `gameRoots` (so `resolveGame`, `serverFile` and `place.scripts`), `placeInputs` and the home rule all read through it, and `graph.insideFolder` is the one "stays inside" test (`place.luau` and `home.luau` had a copy each). `gameRoots` now lists `optional` roots too (no promoted spec uses the form) and still leaves out the tree node.
- **A home's place inputs.** `placeInputs(home)` reads every `*.project.json` directly in the home and returns the repo-relative files themselves and every `$path` they map, resolved against the home and collapsed: `snake/` with `../arcade/src/shared` gives `arcade/src/shared`. A home with no project file gets the legacy answer (`<home>src`, `default.project.json`, `lobby.project.json`: what c0120 named, which its synthetic-graph case still pins); a file that is not JSON with a `tree` is an error naming it (the selector cannot say what the place maps, and the build refuses it too: it fails closed, zz-arch 7). `affectedSpecs` marks each place library `<home>/tests/lib/place.luau` changed when a changed file is one of its home's inputs or lies under one (`f == p` or `f` starts with `p/`), so a change in `arcade/src/` selects the place specs of every home that maps it and none of a home that does not, and a file under `src/` that no project file maps selects nothing (it is in no place). `inputsOf` is the injection seam for specs.
- **`affected.luau`.** `HOME_FULL` matches `[^/]*%.project%.json$` where it matched `default%.project%.json$`: any Rojo project file directly in a home forces that project's full run (a project file in a sub-folder is no place of the home). `--project` is unchanged. A change under `arcade/` also selects, through the graph (the library's `src` and `tests` are in it as a registered home), the unit specs of every home that reaches it through `@arcade` or an adapter's `@game` require.
- **Where a library change is verified.** `z-nile/check.sh --affected` with no `--project` (the stop hook, `./zn done`) selects per project, so the dependents run. `arcade/check.sh --affected` runs the library's own selection; zz-test says so.

### 5. The cross-home rules (`z-nile/tests/lib/crosshome.luau`, pure, and two cases in pickman's structural spec)
- `crosshome.logicOutside(deps, logic): { string }`: every Logic file's resolved require that starts with `../` (it left the home; the graph is built from the home), as `"<file> -> <target>"`. A relative path into another home resolves on disk (Lune, the graph) and not in Roblox's instance tree; the spelling that resolves in the tree (`../../Arcade/...` between sibling roots) does not resolve on disk and the graph reports it unresolved (E2). `@arcade/...` from Logic is an alias, which src may not use at all (`srcAliasAllowed`), and resolves outside the home too. Only Logic is judged: an adapter reaches another home by `@game`, a spec by `@arcade`, and both are fine.
- `crosshome.placeBypass(deps, shared, wrapper): { string }`: every file but the home's re-export that requires the shared place harness (`../z-nile/tests/lib/place.luau` seen from a home).
- `pickman/tests/meta/architecture.spec.luau`, which every home runs from its folder (c0184 Design 5), gains the two cases (and a shorter title for the alias case), once. They stay one line each over `g.deps`. c0163's change to the same file (its deps reader) touches `declaredDeps` only: the two merge by hand, and the correct variant, c0163's prototype reader beside these cases, passes pickman's and snake's spec and the AC6 fixture (E5).

### Scalability
`placeInputs` reads each place library's home's project files: six homes, a few KB each, once per `affected` run (and per `affectedSpecs` call in a spec). `serverFile` is linear in the roots (five) per file in `srcAliasViolations`. A library change selects every dependent home's place specs: pickman's place tier is about 50 files, each building its place once (about 0.3 s), which is what a change to pickman's `src/` costs today. The home rule adds two file reads and a `realpath` per `$path`. Nothing grows with the items. A seventh home costs its alias, two mappings and two wrappers, all checked.

### Maintainability
The next place or root plugs in at its project file: `place` and the selector read it, nothing is edited. The next home plugs in through the home rule, which names what is missing (the alias, the mapping, a wrapper). The library's source tree is the only thing a game may map from outside (`LIBRARY_HOME`). One reader per format: a project's mappings are read by `graph.mappings` alone, and `gameRoots`, `placeInputs`, `place.luau` and the home rule all use it, with `graph.insideFolder`; a folder's project files are listed, decoded and validated in `graph.luau` by one private function (`projectsIn`, used by `placeInputs` and the server-file rule; design review 003 F2), and the home rule lists and decodes a home's project files itself, on purpose: it reports every broken file as a problem and never raises, which a function that raises cannot do (design review 004 F2); `home.luau` requires `z-nile/lib/graph`, a library, not an engine file, so c0120's rule that a home's check selects on its own files still holds. The structural rules stay in pickman's meta spec once, with their pure bodies in `crosshome.luau`.

### Usability
A violation names the file and the require (`src/shared/Logic/Rng/init.luau -> ../arcade/src/shared/Logic/Rng/init.luau`); the home rule says `default.project.json does not map ServerStorage.Arcade to arcade/src/server` or `which is outside the home`; a malformed project file names itself. The developer API is `place.load()` / `place.scripts()` as before, `@arcade/Logic/<Feature>` in a spec, `@game/.../Arcade/...` in an adapter.
