# Answers to design-review-001 (c0191)
All 21 findings are fixed; none is refuted. Each line: the fix, then the consequences checked (z-design step 5.3).

- F1: fixed: the hook now covers the whole captured class, not interpreters alone. It runs on `Bash|Monitor`; refuses by rule `loop` (`while`/`until`), `follow` (`tail -f/-F/--follow`, `watch`, `yes`, `gh ... watch`), `unbounded` for `caffeinate` without `-t`, and `background` for a `run_in_background` call in which nothing is the gate, a check, a `./zn` command or the wrapper; a Monitor command may loop and follow (its timeout ends it) but not start an interpreter or a detacher; `--time` and `--cpu` go up to 3600 so a long poll has a wrapper (a sleeping poll costs no CPU). The Problem names "a background job", so this is the captured outcome and needs no Scope decision; the three live loops of another session are named in Existing work as not retroactive. consequences: a refused loop must have a wrapper that works for waits of up to an hour (3600 and the CPU default of `--time`, covered by "the largest limits are accepted"); the settings case now pins the `Bash|Monitor` matcher and a hook `timeout` of at most 10; new Rules rows (loops/follows/caffeinate, Monitor and background, entry fields); the refused table grew to 40 commands and the passing one to 32, plus two new cases; the reference prototype and `ref-settings.json.txt` changed; U1 now also asks whether Monitor's payload has `tool_name: "Monitor"` and `tool_input.command`, with the fallback that `guard-bash` reads the field it has; the Monitor expiry orphan (E4) is the same leak the Monitor interpreter rule now refuses.
- F2: fixed: every setter of a CPU limit only lowers: `bounded.pl` (`c=$(ulimit -t); if unlimited or $1 < $c then ulimit -t`), the jail's shell (`{ c=$(ulimit -t); [ ... -le "$6" ] || ulimit -t "$6"; }`), `zn`'s engine limit and both hook scripts. `bounded.pl` says so on stderr when the caller's lower limit stays and reports the 125 against the effective limit. consequences: 1200 is a ceiling, not a guarantee, under a lower caller: AC5's default case expects `min(1200, the limit the spec itself has)`, plus a case where a lower inherited limit stays and a higher is lowered; the engine's default is 1800 (not the reviewer's 600) so the runner's 1200 is still what it gets under `./zn check` and a gate run through `./zn`; E10 recorded; c0153's wrapped mutation run now works (named in Existing work).
- F3: fixed: `reap-e2e.luau` gates itself. After the dry run it reads every `would stop pid N ... cwd <folder>` line and goes on to the signalling steps only if there is at least one and every folder is under the throwaway root; otherwise it prints FAIL and stops (E14 ran both dangerous mutants: neither signalled anything). `reap.checkOptions` refuses `--under` with pid <= 1 or not a `claude` process, `--min-age` < 60, and a root that is empty, relative, `/`, the home folder or has `..`, unless a root is named (exit 2); the Rules rows are `run`. consequences: AC4 needs `--min-age 0` and a non-claude `--under`, which stay allowed with an explicit throwaway `--root`; the decoy children are covered by the cwd test (a shim's child shares its folder).
- F4: fixed: `zn` gives its engine `ZN_ENGINE_CPU` (default 1800 s) before `exec lune run`, lower-only (engine-cpu.spec: default, override, bad value, lower inherited, a spinning stub engine stopped). `TOOLING`'s comment now says which entries are jailed (`tests/run`), which go through `zn` (`z-nile/engine/main`) and which are short tooling with no limit (`affected`, `roots`, `cicd`, `scripts/affected`). consequences: children of an engine command inherit 1800 too (the gate under `./zn land` runs its workers at the lower of 1800 and the runner's 1200); measured: the heaviest engine command, `./zn metrics`, took 16 s with its children (E13). The 1800 reaches every engine child, an accepted consequence recorded here.
- F5: fixed: the scope is the main checkout plus prefixes (`<tmp>/claude-<uid>/<slug of the main checkout>` followed by `/` or `--`; the runner's `<TMPDIR>/pickman-run.*` and `pickman-guard.*`), computed by the edge and passed in `Options.scratch`. consequences: Claude's slug rule (`/` and `.` become `-`) is now something the reaper depends on; if it differs, the process is kept (fail closed). reap.spec cases: another project, a similar repository name, another uid, `/Users/me/code/claude-2/x`, a worktree session's folder, the runner's folders and look-alikes, and an explicit root replacing all.
- F6: fixed: a process with a legit git (maintenance, fsmonitor) at or above it is never a leak, for all three rules; the deadline rule names programs (TARGETS and INTERPRETERS) and skips `.app/Contents/` commands. consequences: ancestor walk per candidate (the table is in memory); "any program" is replaced by a list, so a `setsid`'d system binary under `./zn run` is not found by the deadline rule (it was invisible anyway: macOS hides the environment of system binaries, E5); reap.spec cases for `git gc`, `git pack-objects`, a marked maintenance process, an application bundle, `vim`.
- F7: fixed: `reap.checkOptions` (see F3), pure and specced on both sides (11 refused forms, 4 accepted). consequences: none beyond F3's.
