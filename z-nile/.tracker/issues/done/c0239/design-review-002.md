### F1 [high] The stop hook asks `scope` about fewer paths than its gate selects from, so the scoped call can run less than the unscoped one (repeat of review-001 F5, the mechanism)
Where: Design "Stop hook" ("compute the changed paths (as now), ask `lune run z-nile/specs -- scope <paths...>`"; "a forcing path (... `zn`, the root's `scripts/` or configs ...) ... give `ALL`, and the hook runs exactly what the unscoped call runs"); Scalability ("never narrower"); `acceptance/stop.spec.luau` AC7.
Evidence: (1) The hook's "changed paths" are `git diff --name-only HEAD` plus untracked files, filtered to `^(src|tests|z-nile|<homes>)/` (stop.sh lines 30 to 33). Root `scripts/`, `zn`, `.luaurc`, `rokit.toml`, `selene.toml` and `stylua.toml` never match that filter, so they never reach `scope`. The probe above shows an uncommitted `scripts/check.sh` dropped and `pickman/src/A.luau` alone passed on. `scope` then answers `pickman` and the hook runs `--affected --project pickman`. The unscoped `--affected` would have seen `^scripts/` (`SHARED_FULL` in `z-nile/affected.luau`) and run every project's specs. The Design's own list of forcing paths that "give `ALL`" can't happen through the hook. (2) The gate's `--affected` selects from the merge-base with `origin/main` plus the working tree (`z-nile/lib/changed.luau` lines 13 to 38). The hook sends only the uncommitted part. A branch that committed `z-nile/lib/x.luau` and then edits `pickman/src/A.luau` gets `pickman`, and z-nile's specs, which the unscoped gate runs, are skipped. (3) AC7's own fixture shows the problem: `hook()` writes the stub `scripts/check.sh` after `gatefix.make` commits the base, so every case runs with an uncommitted forcing path. The first case still expects `--affected --project pickman`, so a hook that does not narrow fails it. The second case, `hook(dir, { "z-nile/lib/select.luau" })`, overwrites the fixture's real `select.luau` with `-- edit`, so the real `scope` CLI crashes and the case passes through the failure fall-back, not the `ALL` answer its comment claims.
Critique: The rule is "the scoped call is never narrower", and the hook breaks it in the two most common shapes of a session: a tooling edit next to a game edit, and an edit after a commit. The fix the author will reach for is adding the root folders to `gated`. That still leaves (2), and it changes what triggers the hook.
Consequences: Asked over the whole branch change set, a raft worktree always holds its own tracker documents (`spend.md`, the raft and issue files), and rule (4) ("no changed path outside that project's `src/` and `tests/`") would then answer `ALL` every time. Rule (4) has to treat paths under a registry root the way the selector does (they select nothing), and only after checking that no stage of the unscoped gate reads them (a tracker or lessons audit stage would make them `ALL`). This also makes the scoped call fire less often, which adds to F6.
Recommendation: Keep the hook's filtered list as the trigger only. For the answer, call `lune run z-nile/specs -- scope` with no paths, and specify that `scope` with no paths reads its change set exactly as `z-nile/affected` with no paths does (`lib/changed`: the merge-base with `origin/main`, else `main`, plus the working tree and untracked files), which is the set the gate's `--affected` selects from. State rule (4)'s handling of registry-root paths and why it is safe. In stop.spec: commit the stub `scripts/check.sh` into the base through `gatefix.make`'s `setup`. Use a new file (`z-nile/lib/zz-probe.luau`) for the forcing case, not the fixture's `select.luau`. Add cases: an uncommitted `scripts/x.sh` beside `pickman/src/A.luau` → `--affected`; a commit on `work` touching `z-nile/lib/zz-probe.luau`, then an uncommitted `pickman/src/A.luau` → `--affected`; in AC6, `scope` with no arguments on a `work` branch whose only commit edits `pickman/src/A.luau` → `pickman`. Add a Rules row: "scope reads the gate's change set | stop :: committed forcing change, uncommitted root `scripts/` | scope over the uncommitted gated paths only".

### F3 [high] AC8's per-line regex lets an Override delete its assertions, and it never sees a removed comment line (repeat of review-001 F9)
Where: check.sh `only_lines` and `overrides_narrow`; Checklist "Overrides" ("each only by the strings named").
Evidence: `only_lines` checks only that every `+`/`-` line of the diff matches a pattern. Deleting a line produces a `-` line and no `+` line, and that passes. In `c0074/done-gate.spec.luau`, deleting line 183 `t.expect(has(log(), "args: --full")).toBe(true)`, line 182 (`"full gate fails"`) or line 222 (`has(seen, "args: --full")`) matches `(--full|...|full gate|...)` and passes AC8. Those are the lines that pin "done ran its gate" and "it failed and rolled back". In `c0114/docs` and `c0120/docs`, deleting the RC0 `at(...)` literal line passes too. Also, `grep -Ev '^(\+\+\+|---) '` drops every removed line that starts with `-- ` (a Luau comment shows up as `--- …` in the diff), so comment changes are invisible. The c0172 pattern `^[+-][[:space:]]*"[0-9a-f]{64}",$` accepts a change to any digest in the table, not only `c0120/docs`'s.
Critique: Round 1 asked for "only the named substitution"; a filter over changed lines can only say "only lines of this kind", and a deletion is a line of that kind. This is the second round that finds a hole in this mechanism, so the mechanism is the problem, not the regex.
Consequences: An exact pin has to survive c0165's earlier edits to the same files (c0165 rehashes `c0172/narrowed` and may touch `c0114`/`c0120` specs), so it derives from the merge base, never from a hash recorded now.
Recommendation: Replace `only_lines` with a substitution check. For each Override, take `git show "$(git merge-base HEAD origin/main)":<file>`, apply the Design's named fixed-string substitutions with a sequestered script (beside `rehash.py`: for `c0114/docs`, `c0120/docs` and `c0120/promote-home` the two RC0 replacements; for `c0074/done-gate` the listed `args: --full`→`args: --affected`, `full gate fails`→`affected gate fails`, `full gate is skipped`→`gate is skipped`, `"full"`→`"affected"` in the `doneGate` lines, and the titles and header comment if the Design renames them, listing each), and require the result to equal HEAD's file byte for byte. For `c0172/narrowed`, run the substitution on the merge-base file, replacing only the `c0120/docs` digest with `rehash.py`'s digest of HEAD's `c0120/docs.spec.luau`, and compare byte for byte. Name every changed c0074 line in the Design (today it says "in its two cases", while lines 2, 115, 213, 231 and 236 to 238 also say "full"). Add a self-check fixture case to check.sh: a copy where one c0074 assertion is deleted must fail.
