# c0244: Bound command homes

## Problem
R0075 review-001 F1: engine/boundcmd.luau TOOLING names pickman/tests/run by hand, so lune run <home>/tests/run for the five arcade homes is refused as unbounded; take every registered home's runner from the registry

## Non-goals
Any other hand-named pickman path (c0184 and review 001's search found no other in live tooling); changing which commands the seatbelt refuses.

## Solution
`boundcmd.Context` gains `homes: { string }?`, and `<home>/tests/run` joins `tests/run`, `z-nile/tests/run` and `pickman/tests/run` as the gate's own tooling for each home of the registry. `guard-bash.luau` fills `homes` from `projects.load(ZN_CHECKOUT)`; if the registry cannot be read it stays nil and today's list decides, so the hook still fails open on a crash and only over-refuses on a bad registry.

## Design
- `z-nile/engine/boundcmd.luau`: `Context.homes`, copied into `CTX` by `check`; `homeRunner(t)` (a home that is empty, `.`, `..` or has a `/` adds nothing) is consulted after `TOOLING[t]` for a relative target; an absolute target already matches by the `/tests/run` suffix under the checkout.
- `z-nile/guard-bash.luau`: reads the registry in a `pcall`, passes each project's `home`.
- No behaviour change for a path that was allowed before. Overrides: none (the c0191 specs pass unchanged). Scalability: one registry read per Bash call (about 1 ms). Maintainability: the hand list shrinks to the tooling's own entries. Usability: `lune run snake/tests/run` is no longer refused.
- Touched modules: `z-nile/engine/boundcmd.luau`, `z-nile/guard-bash.luau`, `z-nile/tests/acceptance/c0244`.
