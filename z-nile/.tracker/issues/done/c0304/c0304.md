# c0304: Workstreams stale cases

## Problem
- Two promoted cases in `z-nile/tests/acceptance/c0045/workstreams.spec.luau` ('worktree --from bases the new worktree on the ref' and 'stream review files are not review rounds') fail on unmodified main since #296, because the first bases on a branch `R0010-demo` that a raft worktree no longer makes and the second is refused by done's published-layer-tip check before it reaches the review check.

## Non-goals
- No file other than `z-nile/tests/acceptance/c0045/workstreams.spec.luau` changes, so no tooling behaviour (including #296's detached raft worktrees and done's published-tip check) is altered.

## Solution
- Both cases are narrowed to set up what #296 makes (a ref that exists; a local layer tip that is the published one) while still asserting that `--from` bases the new worktree on the ref's tip and that done refuses with 'no review-NNN.md' when only stream review files exist, and both pass on main with every other case in the file unchanged.

## Design
**What #296 changed, read from the code (2026-11-15, origin/main af1d8397).**
- `cmd.worktree` (`z-nile/engine/main.luau:4244`): a raft id gives a worktree on the raft's latest layer branch, or, before `start` has opened one, a detached worktree at `origin/main` ("It does not create the old R####-<slug> branch"). The first narrowed case runs before any `start`, so `.worktree/R0010` is detached and no `R0010-demo` branch exists: `--from R0010-demo` fails at `unknown ref R0010-demo` (`main.luau:4276`), at spec line 332.
- `cmd.done` (`main.luau:5010`): before `reviewProblem` it refuses unless `HEAD` is `layergit.layerTip(topLayer)`, which prefers `origin/<layer>` over the local branch (`layergit.luau:110`). The fixture's `start R0010` (squash-merge case) pushed `R0010/1/f0010` to the fixture's `origin.git`; the squash case's commits and the stream case's own commit are local only, so `done` stops at `… done checks the commit it lands` and the assertion at spec line 392 is false.
- `reviewProblem` (`main.luau:4666`) now counts only `final-review-NNN.md` (`layergit.latestReview`, `layergit.luau:311`); with none its refusal is `no final-review-NNN.md (no review-NNN.md may stand in for the final review): run the final review first`, which still holds the substring `no review-NNN.md` the case asserts. So once `done` reaches the review check, the case's existing assertions hold unchanged (E2 M0).

**The change** (one file, `z-nile/tests/acceptance/c0045/workstreams.spec.luau`): exactly `experiments/prototype.patch`, 6 lines added and 2 changed, byte for byte. AC2 pins the whole file as its merge base plus these three hunks (design review 001 F1), so the executor applies the patch and does not write the narrowings by hand, reword the comments or add assertions:
1. Case `worktree --from bases the new worktree on the ref`: after `local tip = …` and its `tip ~= origin/main` assertion, the case makes the ref itself, a branch at the raft work's tip without checking it out (`git(wt1, { "branch", "raft-tip", tip })`: worktrees share refs, so `main/` sees it, and `wt1` stays detached for the later cases), and both `--from` lines name `raft-tip` instead of `R0010-demo`. Every other line stays, so the case still asserts that `worktree ws-f0010 --from <ref>` prints the worktree's path, that the new worktree is on branch `ws-f0010`, that its `HEAD` is the ref's tip (not `origin/main`), and that running it again prints the same path. The name `raft-tip` is deliberately not the old `R<NNNN>-<slug>` shape that `layergit.oldShapeRefusal` looks for (on origin only, and the branch is never pushed, but a reader should not mistake it for a raft branch).
2. Case `stream review files are not review rounds`: after its `stream review files` commit, the case pushes the layer to the fixture's origin (`git(wt1, { "push", "-q", "origin", "HEAD" })`: `wt1` is on `R0010/1/f0010`, whose upstream `start` set), so the local tip is the published top layer and `done` reaches the review check. Every other line stays: `done` still fails, its stderr still holds `no review-NNN.md`, and `metrics` still prints `| R0010 | 0 | 0 | none |`. No assertion is added: the existing `no review-NNN.md` assertion already fails for a `latestReview` that counts stream review files (E2 M2) and for a `done` that stops at the tip check (E2 M4), so an extra `no final-review-NNN.md` assertion would only pin the message's wording.
3. Each change gets a two-line `-- c0304 override:` comment saying what #296 made (the file's existing override comments are `-- c0120 override:`), worded as in the patch.

**The pin and a moved base.** AC2 (`acceptance/narrow.py`) builds the expected file from the merge base (with origin's main, read with `git ls-remote`) by three anchored substitutions, each anchor's count asserted in the base first: (a) after the one `t.expect(tip ~= git(main, { "rev-parse", "origin/main" })).toBe(true)` line, the two comment lines and the `raft-tip` branch line; (b) the two `{ "worktree", "ws-f0010", "--from", "R0010-demo" }` become `raft-tip`; (c) after the one `git(wt1, { "commit", "-qm", "stream review files" })` line, the two comment lines and the push. The file must equal that byte for byte. The anchors name no line number and no other case's text, so an edit main makes elsewhere in the file (c0178's, below) moves the base and the expected file together (E2 N15).
