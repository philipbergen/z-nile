# d0383: Watch net dead behind leftover worktree

## Problem
- On 2026-11-15, `./zn watch-kick` run from R0101's worktree after `./zn done` printed "watch-net: started, log at .cache/watch-net.log" and exited 0, although the net it started exited at once with `git worktree add -q .worktree/watch-net watch-net` failing (128) in `.cache/watch-net.log`.
- `ensureWorktree` in `z-nile/engine/watchcmd.luau` uses the relative path `.worktree/watch-net`, so a kick from a raft's worktree tries to add a second worktree on the `watch-net` branch, which git refuses because `<root>/.worktree/watch-net` holds that branch.
- zz-execute Phase 6 step 1 has the worker run `./zn watch-kick` from the raft's worktree (stacked delivery, since #296 on 2026-11-11), so every raft's kick after a merge fails this way.
- The last "watch-net: the suite passed" commit on origin/main is from 2026-11-12 14:54, and nothing reported the three days without a pass, because `z-nile/watch-passed` records only the commit of the last pass and nothing in `z-nile/engine/watchcmd.luau` prints its age.
- In those three days main went red in the fast tier (c0120/check-paths, since #392 and #414 on 2026-11-15) and stayed red in the slow tier (c0084/commit-phase).
- Scope decision (user, 2026-11-19): "Only source commits count": design review 001 (F8) showed that the captured stale rule fires on a healthy net, because a net run after tracker-only commits ends "nothing to do" and records no pass. The "no pass since" line is printed when a commit on origin/main that changes something outside the tracker folders is more than 24 hours newer than the last "watch-net: the suite passed" commit; a commit that changes only tracker files does not count as newer.

Ruled (user, 2026-11-24), shipped: no: "those defects seem like something was done wrong, or not yet implemented more than the functionality was actually broken, they don't count"

## Non-goals
- A net that exits after it has created or reused its worktree is not reported by the kick that started it; only the "no pass since" line shows it.
- This issue does not remove, recreate or move the main checkout's standing net worktree `<root>/.worktree/watch-net`.
- This issue does not fix the red specs themselves (c0120/check-paths and c0084/commit-phase).
- This issue does not change what the net runs or when zz-execute tells the worker to kick it.

## Solution
- A `./zn watch-kick` run from any worktree of the repository starts a net that runs in `<main checkout>/.worktree/watch-net`, reusing that worktree when it exists, and never adds a second worktree on the `watch-net` branch.
- `./zn watch-kick` returns only after the net it started has either created or reused its worktree or exited, and if the net exited first, the kick prints the net's error line on its own stderr and exits non-zero.
- When origin/main has a commit more than 24 hours newer than the last "watch-net: the suite passed" commit, `./zn watch-kick` prints on its stdout a line "watch-net: no pass since <date of that commit>", and the board (`.cache/board.html`) shows the same line.
- The 24-hour limit is one named constant in `z-nile/engine/watchcmd.luau`, and the kick and the board both read it from there.

## Design
A working prototype is `experiments/prototype.patch` (13 files, +721/-53, made in `.worktree/proto-d0383` on fc9817e0b after design review 001; E2 to E8). The documents are the contract; the executor may start from the patch.

### Defect checklist
- **Reproduction**: `experiments/repro.spec.luau` (passes on main, it documents the defect; output in `experiments/repro-output.txt`): a fixture with an origin, a main checkout holding the standing `.worktree/watch-net` on branch `watch-net`, and a raft's worktree. `./zn watch-kick` from the raft's worktree prints "watch-net: started, log at .cache/watch-net.log", exits 0, and its log holds `git worktree add -q .worktree/watch-net watch-net failed (128): fatal: 'watch-net' is already used by worktree at '…/main/.worktree/watch-net'`. The failing-first proof is the acceptance specs on the unmodified engine: 21 of 24 cases that load fail and one file cannot load (E3).
- **Expected behaviour**: zz-test, "The net": a landing's kick starts a net that runs the fast suite on main and then the slow tier, and reports a red by a defect. It reworks the stacked delivery of 2026-11-11 (#296), after which the worker kicks from the raft's worktree.
- **Root cause**: three things, each enough to keep the net from passing. (1) `ensureWorktree` in `z-nile/engine/watchcmd.luau` uses the relative path `.worktree/watch-net`, so from any worktree but the main checkout it tries to add a second worktree on the `watch-net` branch, which git refuses. (2) The kick starts the net detached and returns at once, so a failed start is only in a log nobody reads, in a worktree that is deleted minutes later, and nothing shows how old the last pass is. (3) The detached net is an orphan process inside the repository, and `./zn reap`, which every `./zn sync` and gate start runs, stops orphans older than a minute (design review 001 F2; the old shell form leaves the same orphan). No spec caught any of it because the existing ones kick from the main checkout and never run a reaper beside a net.
- **Siblings**: `WT` is the only relative worktree path a command creates from the current directory (`./zn worktree` and the layer commands resolve through `mainRoot()`). `./zn land` calls the same `watchcmd.kick` and gets the fix with it. The dispatcher kicks from the main checkout after a merge and now meets the one-net lock (§3).
- **Regression guard**: the four acceptance specs are permanent once promoted. At risk, all run by AC5: the watch, watch-map, board, board-review specs, `c0077/cache-paths` (new `.cache` names), `c0191/reap` and `bounded-review` (the reaper's rule), `c0193/tree` and `tests/meta/scanning-loops` (new bounded loops), `c0070/board-refresh`, `c0278/readers` (a promoted spec that runs a nested net), `lock-start-ids` and `c0127/reuse` (the start-id script).
- **Smallest change**: what the net runs and repairs is not touched (Non-goals). The reaper's exemption and the one-net lock are added because without them the kick this issue repairs starts a net that is killed within minutes or collides with another (design review 001 F2, F3); they are detail of the captured first outcome ("starts a net that runs"), not new outcomes.

### 1. The net runs in the main checkout, from flags only (`z-nile/lib/watch.luau`, `z-nile/engine/watchcmd.luau`, `z-nile/engine/main.luau`)
Commands: `./zn watch-kick [--wait S] [--start S]` and `./zn watch-net [--ready FILE] [--start S]`. `--start` (default 120) is the net's own limit on getting its worktree; `--wait` (default start + 30) is the kick's backstop. Both are flags: no environment variable is read or set, so nothing of the kick reaches the specs the net runs (design review 001 F1: a variable would be inherited by every spec in the net's suite, and a promoted spec that runs a nested net would write the outer kick's marker and fail).
Pure, in `lib/watch.luau`: `watch.mainCheckout(porcelain: string): string?` (the first `worktree` line of `git worktree list --porcelain`, as the engine's `mainRoot()` reads it), `watch.netDir(main: string): string` (`<main>/.worktree/watch-net`), `watch.filesDir(main: string): string` (`<main>/.cache/watch-net`).
`ensureWorktree()` uses `watch.netDir(...)` in place of the relative `WT`: it reuses that worktree when it exists and creates it there when it does not, so it never adds a second worktree on the `watch-net` branch. Each of its steps (fetch, `git worktree add`, fetch in the worktree, rebase) runs through `startStep(label, dir, args)` under `<ZN_TOP>/zn run --time <seconds left>` against one deadline, `--start`; when the limit passes the net prints one line, `watch-net: no worktree after <s> s (<step>)`, and exits 1. Every failure of the start is one line through `fail()`.

### 2. The kick knows whether its net started (`z-nile/lib/watch.luau`, `z-nile/engine/watchcmd.luau`, `z-nile/engine/reap.luau`)
Files, all in the main checkout's `.cache/watch-net/` (a raft's worktree is deleted minutes after its kick; design review 001 F7): per kick `<10-digit epoch>-<kick pid>.log`, `.ready`, `.exit`, `.pid` (no name is shared between kicks, F6; `watch.pruneKicks` keeps the newest 20 kicks' files), and the shared `lock`, `rerun` and `guard/` of §3.
The kick runs `bash -c <reap.NET_SCRIPT> zn-watch-net-kick <checkout> <log> <ready> <exit> <start>`, where `reap.NET_SCRIPT` is `cd "$1" || exit 1; ( ./zn run --time 3600 -- ./zn watch-net --ready "$3" --start "$5" > "$2" 2>&1; echo $? > "$4.tmp"; mv "$4.tmp" "$4" ) > /dev/null 2>&1 & echo $!`. The script text exists once, in `engine/reap.luau`, because the reaper recognises the net by it (§4). A `cd … &&` in front of the group would keep the caller's pipes open for the net's whole run (E4). The script prints the group shell's pid and the kick writes it to `<id>.pid`. `watchcmd.net(opts)` writes the `--ready` file right after `ensureWorktree()` returns.
Pure: `watch.startState(ready: boolean, code: number?, alive: boolean): "ready" | "exited" | "gone" | "waiting"`, `watch.errorLine(log: string): string?` (the last non-empty line).
`watchcmd.kick(opts: { wait: number?, start: number? }?): boolean` polls in a counted loop, `for _ = 1, wait * 5 + 5 do … task.wait(0.2) end`, leaving it on a state or when `os.time()` passes the deadline (wall clock; `os.clock()` is CPU time). No `while` loop is added, so `tests/lib/loops.luau`, the reviewed list of loops the scan cannot prove, is not touched (F4). It returns:
- `ready`: prints `watch-net: started, log at <absolute path>`, true;
- `exited` with code 0 and a last log line that starts "watch-net: already running" (§3): prints that line, true;
- `exited` otherwise: the net's last log line on stderr, false;
- `gone` (the shell's pid is dead, by `kill -0`, with neither file): `watch-net: the net ended before it had its worktree, log at <path>` on stderr, false;
- the backstop: `watch-net: no word from the net after <wait> s, log at <path>` on stderr, false. The net is left to its own start limit.
It never returns true without the marker or the already-running line, so the captured "returns only after the net … has either created or reused its worktree or exited" holds in every case (F5; guess G1 is withdrawn). On every path it then prints §5's line on stdout when there is one. `cmd["watch-kick"]` exits 1 when `kick()` returns false. `./zn land` calls `kick()` as before and ignores what it returns (guess G5).

### 3. One net per repository (`z-nile/lib/watch.luau`, `z-nile/lib/procstart.luau`, `z-nile/engine/watchcmd.luau`)
Before this fix only kicks from the main checkout reached the standing worktree; now every landing's does, and a second net's fetch and rebase would rewrite the files under the first net's running suite (F3).
Pure: `watch.lockText(pid, start)`, `watch.parseLock(text)`, `watch.lockHeld(text, liveStart)` (held only by the process that wrote it: the pid is alive and its start id is the recorded one, so a reused pid does not hold it), `watch.again(requested, round, max)`.
`lib/procstart.luau` (new): `procstart.startOf(pid): string?`, the start id of a process, by the same script the spec runner uses for its own locks (`ps` is denied inside the runner's jail). The script text also stays in `tests/lib/fence.luau`, whose fixtures copy only the runner's files; a case pins the two texts equal (guess G9).
Edge, in `watchcmd.luau`: `takeLock(dir, mine): number?`, `finishRound(dir, mine, round): boolean`, and `mutexed(dir, section)`, a `guard/` directory made with `mkdir` around take, give back and request, so two nets that start together cannot both take the lock and a request recorded while the holder ends is not lost (it waits in a counted loop of 100 steps, 10 s, and then takes the guard over).
`watchcmd.net` takes the lock before `ensureWorktree`. A net that finds it held writes `rerun`, prints `watch-net: already running (pid N); a rerun is requested` and exits 0. The holder, at the end of a round, runs once more when `rerun` exists, removing the request as it takes it, for at most `MAX_ROUNDS = 4` rounds in a counted loop, and removes the lock at the end; `fail()` releases it too. A new net deletes a leftover `rerun` when it takes the lock. A lock text that does not parse counts as free, and a net that ends by an error does not rerun (guesses G7, G8).

### 4. The reaper leaves the net alone (`z-nile/engine/reap.luau`)
`reap.NET_SCRIPT`, `reap.NET_ARGV0 = "zn-watch-net-kick"`, `reap.NET_MAX_AGE = 3600 + 600`, `reap.isNet(p: Proc): boolean`, and a local `underNet(p, byPid)`; `decide` skips a process that is the net's shell or below it. A process is the net's shell when its program is bash and its arguments are exactly `-c <the whole NET_SCRIPT text> zn-watch-net-kick /…`, and it is no older than `NET_MAX_AGE` (the net's own `--time 3600` plus ten minutes): a net that outlives its deadline is an ordinary orphan again, and the reaper stays the backstop. Nothing else is exempt: not `sh`, not another script, not a `./zn run` orphan, not a net's child whose shell has gone. A net that a spec's fixture kicks has the same shape and is exempt for the same bounded time (guess G6).

### 5. The age of the last pass (`z-nile/lib/watch.luau`, `z-nile/engine/watchcmd.luau`, `z-nile/engine/trackerstate.luau`, `z-nile/engine/board.luau`, `z-nile/engine/board.html`)
By the user's scope decision of 2026-11-19, "newer" counts only a commit that changes something outside the tracker folders.
Pure: `watch.lastPass(log: string): (number?, string?)` (from lines `<committer epoch>\t<sha>\t<subject>`, the newest whose subject is exactly "watch-net: the suite passed"), `watch.newestSource(log: string, tracker: (path: string) -> boolean): number?` (from `git log --format=%x01%ct --name-only`, the committer time of the newest commit with a path for which `tracker` is false), `watch.noPassLine(passed: number?, newestSource: number?, limit: number): string?`: "watch-net: no pass since YYYY-MM-DD" (the pass commit's committer date, UTC; guess G3) when `newestSource - passed > limit`; nil at exactly the limit, below it, or when either is unknown (no pass commit in the history: no line, guess G2).
One reader of "tracker file": `trackerstate.under(path, roots)`, the publish guard's own rule, made public (the registry's roots through `projects.roots(projects.load(dir))`, and `z-nile/next`); `judge` keeps calling it.
`watchcmd.NO_PASS_LIMIT_SECONDS = 24 * 3600` is the one constant. `watchcmd.noPassLine(dir)` reads `origin/main` locally: `git log -n 20 --grep='^watch-net: the suite passed$'`, then `git log --first-parent -m --no-renames --name-only --format=%x01%ct <pass sha>..origin/main` (`-m --first-parent`, so a `--no-ff` landing shows what it changed).
The board: `board.readFacts` (which already reads git) fills `Facts.noPass` with `watchcmd.noPassLine(dir)`; the pure model carries `Model.noPass`; `board.html` gains `<div id="notice">{{NOTICE}}</div>` before the stats, rendered `<p class="note" id="no-pass">…</p>` when there is a line. The placeholder order check becomes MARKED < NOTICE < STATS < DATA. The board never calls `watch.noPassLine` itself (F10).

### 6. The words that describe it (`z-nile/skills/zz-test/SKILL.md`, `z-nile/skills/zz-execute/SKILL.md`, `AGENTS.md`)
zz-test "The net" and zz-execute Phase 6 step 1 say what the kick now does: it returns once the net is known to have started, from any worktree; what it prints; exit 1 and a line on stderr mean the net did not start (reported in the final report, the merge is not undone); "already running"; the no-pass line; where the log is; that the reaper leaves the net alone (the two replaced sentences are in the patch; F11). AGENTS.md's list of ignored files `./zn` writes in the main checkout gains: "the watch net's lock, rerun request and each kick's log, ready, exit and pid files in `.cache/watch-net/` (written by `./zn watch-kick` and `./zn watch-net`, from any worktree)".

### 7. What the five code reviews changed (R0138)
Sections 1 to 6 are the design as prepared. The build's code reviews (review-001 to review-005 in the raft's folder) changed it in these ways, and where a sentence above disagrees, this section is what the code does:
- **Flags**: `./zn watch-kick [--wait S] [--start S] [--limit S]` and `./zn watch-net [--ready FILE] [--start S] [--limit S]`. `--limit` is the time the net's rounds may use, at most and by default `reap.NET_SECONDS` (3600; `watch.netLimit` clamps it). A value that is not a positive whole number counts as not given (`watch.waitSeconds`). Guess G14.
- **The net does not live in its kicker's worktree** (review 001 F1): it reads the main checkout once at its start, gives every git call an explicit cwd there or in the standing worktree, and from its second round runs the standing worktree's own `zn`. Round 1 uses the kicker's `zn`, which is safe because the kick does not return before the marker. The rounds are wrapped so any throw gives the lock back and the net still exits 1 with the error in its log.
- **A rerun that does not fit goes to a fresh net** (review 001 F2, review 002 F2): `watch.again(requested, round, max, rounds, left)` lets a further round run in the same net only when the longest round so far plus `watch.ROUND_MARGIN_SECONDS` (300) fits in the time left. Otherwise, or when the rounds are used up with a request pending, the net gives the lock back, runs `<netDir>/zn watch-kick` and prints `watch-net: the rerun goes to a fresh net: <kick line>`; the fresh net takes the lock, removes the request and starts from the newest main with its own full time. If that kick fails the net prints `watch-net: the rerun could not be handed to a fresh net: <kick line>; the next landing's kick runs it` and exits 1.
- **The net is independent of what kicked it** (reviews 002 to 004): the kick runs `perl -e 'setpgrp(0, 0); exec @ARGV or die' bash -c <reap.NET_SCRIPT> zn-watch-net-kick …` (`reap.NET_DETACH`), so the net has its own process group and a `./zn run` around the kick does not kill it when that command ends or passes its deadline. `reap.NET_SCRIPT` begins `unset ZN_BOUNDED_DEADLINE; ulimit -St "$(ulimit -Ht)" 2>/dev/null; cd "$1" || exit 1;`. The net's tree runs with SIGINT and SIGQUIT ignored (bash does that to a background list) and is stopped by TERM and KILL.
- **Two kicks that start no net**, each with one line on stderr and exit 1, before any file is made: a kick inside a dispatched step (`ZN_DISPATCH` or `ZN_PUBLISH_BROKER` set; `watch.stepKick`): `watch-net: not started: a dispatched step cannot push the net's records to main; the dispatcher starts the net after its own merge` (guess G17 replaces G16); and a kick under a hard CPU limit below the spec runner's 1200 s (`lib/cpulimit.luau`): `watch-net: not started: this command runs under a CPU limit of N s per process, the net needs 1200 s: …` (guess G15).
- **The reaper**: a process below a net is exempt from the orphan rule only; the "past its `./zn run` deadline" rule still stops it. The net's own shell is skipped whole while it is young.
- **The kick's failure output**: a net that ends before its marker gives two stderr lines, the net's last log line and `watch-net: log at <absolute path>`. The lock's guard, when it cannot be taken over, fails closed with one line.
- **Three sentences of sections 1 to 6 that no longer hold** (final review 001 F3): §1's "no environment variable is read or set": the kick sets none and the net's suite inherits nothing of it, but the kick now reads `ZN_DISPATCH`, `ZN_PUBLISH_BROKER` and its hard CPU limit to decide the two refusals; §2's "on every path it then prints §5's line" is true of every way out of the kick, the refusals included, since the final review's F1; §3's `finishRound(dir, mine, round): boolean` now takes the rounds' durations and the time left and answers "again", "handoff" or "done".
- **Regular specs added by the reviews** (`z-nile/tests/tooling/`, each under 30 s alone): `watch-net-quick` (the pure rules, the script's cleared deadline and raised soft limit, the dispatched-step refusal), `watch-net-bounded` (a kicker under `./zn run` that ends or passes its deadline; the CPU refusal), `watch-net-handoff`, `watch-net-survives` (the kicker's worktree removed mid-run; a throwing round), `watch-net-guard`, `watch-net-reaper-deadline`. Their mutants are in the Verification log entries of each review.

### Scalability
The kick gains a wait of a second or two and two `git log` reads (the second bounded by the commits since the last pass); the board one more read per build; the reaper one string compare per process. The per-kick files are pruned to the newest 20 kicks.

### Maintainability
Every decision is a pure function in `lib/watch.luau` with its own cases; `watchcmd.luau` holds the git reads, the lock's file steps and the one constant, which the board reads through `watchcmd.noPassLine`. The net's shell line exists once, in `reap.luau`, where the kick and the reaper both read it, so the exemption cannot drift from the command. "Tracker file" has one reader. Known duplication, left as it is: the start-id script in `lib/procstart.luau` and `tests/lib/fence.luau`, pinned equal by a case (G9).

### Usability
A person or a worker who kicks the net sees one of: "started, log at <path>", "already running", or an error line with exit 1. The log is still there after the raft's worktree is gone. Anyone who opens the board, or kicks, sees "watch-net: no pass since <date>" when source commits have sat on main for more than a day with no passing run.

## Acceptance criteria

### Checked
- AC1: a watch-kick from any worktree starts the net in the main checkout's standing worktree, returns only once the net is known to have started, reports a failed, killed or silent net on stderr with a non-zero exit, keeps its files per kick in the main checkout, and passes no variable to the net's suite.
- AC2: at most one net runs per repository: a second kick prints "watch-net: already running" and exits 0, a stale or reused-pid lock is taken over, and a rerun request is honoured exactly once.
- AC3: the reaper leaves the detached net's tree alone while it is younger than its own limit, and no other orphan.
- AC4: when a commit on origin/main that changes something outside the tracker folders is more than 24 hours newer than the last pass commit, watch-kick prints "watch-net: no pass since <date>" and the board shows it; tracker-only commits never count; the limit is one constant.
- AC5: the specs at risk pass: watch, watch-map, board, board-review, cache-paths, the reaper's, the two loop scans, board-refresh, readers, lock-start-ids and reuse.
