### F5 [medium] A page that fetches from the web passes the "nothing fetched" check
Where: Design §1 ("Inline `<style>` and `<script>` are allowed"); explainer.check's `external`; AC1
Evidence: each of these passes `explainer.check` and fetches or navigates when it renders: `<script type="module">import "https://cdn.example/mermaid.mjs"</script>`, `<script>fetch("https://x")</script>`, `<svg onload="...">`, `<meta http-equiv="refresh" content="0;url=https://x">`, and CSS `background-image: image-set("bg.png" 1x)`, which has no `url(`. The scan only reads attribute values, `url(` and `@import`. An agent that wants drawn diagrams is likely to load a CDN script, and the explainer.spec "fine" list asserts that `<script>` passes.
Critique: AC1 says "nothing fetched" and the captured Solution says "self-contained". A page that breaks both passes `./zn explain`.
Consequences: blocking scripts closes the dynamic hole in one rule. The page needs no script, since the diagrams are inline SVG. A plain `://` backstop would also flag inline SVG's `xmlns="http://www.w3.org/2000/svg"`, so `xmlns` values must be exempt.
Recommendation: refuse `<script`, every `on<name>=` attribute and `http-equiv="refresh"`. Treat `image-set(` like `url(`. As a backstop, refuse any `://` outside `xmlns`/`xmlns:*` attribute values. Move `<script>const n = 1;</script>` to the refused list, add `<svg xmlns="http://www.w3.org/2000/svg">` to the fine list, and add Rules rows: script allowed, handler allowed, refresh allowed, `://` text allowed, image-set unchecked. Update §1, the template comment and f0339's page (choice 3's cons: no scripts).

### F8 [medium] A page written at approval time never reaches main through `approve --publish`, and nothing says so
Where: Design "Existing work" (prepared items without a page); `cmd.approve --publish`; publish.allowed (publish.luau:100)
Evidence: the 16 waiting items, and any dispatched prep whose PR merged without approval, are approved from a worktree of main. The draft's "the page then lands with that branch's PR" relies on the person remembering a PR nothing asks for.
Critique: the Solution is that z-nile records one page per ticket. Here the record silently stays off main.
Consequences: making `explainer.html` publishable widens tracker state (publish.allowed, trackerstate, the broker's view of what an agent may push to main), which is a trust decision for the user. A warning changes nothing in the gates.

Add an approve-page or approve-publish case for both "warns" and "silent once the page is on main", and add one sentence to the zz-rules approve row. Do not widen publish.allowed without the user.
