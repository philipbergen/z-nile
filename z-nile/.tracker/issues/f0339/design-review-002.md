### F1 [medium] Moved into c0369's count step, the page warning fires on every approval of an unmerged prep, telling the person to push a branch the same command then pushes
Where: Design section 4, "The warning before it publishes or pushes"; AC2's last clause; `acceptance/approve-page.spec.luau:334-355`; Rules R32, R33
Evidence: the warning now runs "right after it finds the place's `approval.md` ... (and before it publishes or pushes)" and fires "when the worktree has a page that `origin/main` lacks or holds differently". Under c0369 the normal z-design flow is: the person runs `./zn approve <id>` from anywhere, c0369 records in `.worktree/prep-<slug>` and pushes `prep-<slug>` so the prep pull request carries the approval. That prep's page is new (z-design writes it in the prep), so origin/main always lacks it, and every such approval prints `warning: <page> is not on origin/main as it is here: push this branch and land it by pull request, or main keeps no page` right before c0369 prints `pushed prep-<slug>: the approval counts when its pull request merges`. The same happens on a raft's layer branch. Before the re-prep the warning ran only in `--publish`, the step that publishes to origin/main: the case the design names ("a legacy item approved from a worktree of main, or a dispatched prep merged before its approval"). The spec pins the warning only on a branch that is not on origin and pins no silence on the prep push, so the noisy version passes AC2.
Critique: a warning that fires on the normal path teaches people to ignore it. The tempting fix is to warn only when c0369 publishes.
Consequences: the publish path is the one where the page can be lost; a branch c0369 does not push (not on origin) is the other place where the warning is true; the prep push and the layer branch carry the page with their pull request, so the warning is false there. That is three cases in c0369's `count`, each needing a case here.
Recommendation: warn before c0369 publishes to origin/main and before it reports a branch it does not push because it is not on origin; say nothing before it pushes `prep-<slug>` or a branch already on origin, or on a raft's layer branch. Cases in `approve-page.spec`: the existing one (branch not on origin: warns), a held approval of main's design whose worktree's page differs from main's (publishes: warns), and a `prep-<slug>` worktree with an origin (pushes: silent, R33's mutant "always warns" dies there). Run R32 and R33 on c0369's prototype merged with f0339's patch (both exist), so they are `run` rather than `reasoned`.
