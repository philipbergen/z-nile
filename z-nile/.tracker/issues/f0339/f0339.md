## Non-goals
- The page does not walk through the change line by line or replace the ticket's design text: detail beyond the high-level list of changes is left to asking an AI to walk through it.

## Solution
- z-nile records one self-contained HTML page per ticket that explains the idea and design in simple words, with a diagram of the system before, a high-level list of what changes where (which files get which functions and types), a diagram of the system after, and the pros and cons behind each choice, and the approve command opens that page rendered in the system's default app for `.html` files (the default browser, via `open` on macOS) and then waits for a y/n answer at the prompt.

## Design
Prep's detail; the captured Solution bullet above is unchanged. The page is written by whoever designs the ticket (z-design, a person or a dispatched design step), checked by z-nile, and shown by `./zn approve` before it asks.

Binding decisions this relies on (z-nile/README.md, Intent and Provenance): "People work at the idea and the design ... z-design turns the confirmed idea into a design with acceptance tests as code, reviewed back and forth, and a person approves it." and "A person approves a design with `./zn approve <id>`, which records the person and a hash of the design sections, the acceptance specs and `check.sh` in the issue's `approval.md`; `ready` and `done` refuse a design that changed since." This issue keeps both: the approval and its hash are unchanged, and the person now reads the page before the approval is recorded. z-nile has no product-decision file and no `architecture.md`; the one new module joins zz-arch's Layout as an engine concern (`z-nile/engine/`), and no new dependency edge leaves the engine.

### 1. The page and its shape
- One file per issue, `<issue-dir>/explainer.html`, committed with the issue (it moves with the folder to `active/` and `done/`). It is **not part of the contract**: `contract.build`, `approval.md`'s hash and `ready`/`done`/`land` never read it, so every approval recorded today still holds, and a page fix never asks for a re-approval.
- The page names the contract it explains: exactly one `<meta name="zn-contract" content="<64 lowercase hex>">`, the hash `contract.hash(approval.collect(...))` gives today. A design edit after the page was written makes it stale, and z-nile says so (the approver reads the design they approve, not an older one).
- Five sections, `<section id="idea">`, `"before"`, `"changes"`, `"after"`, `"choices"`, each once and in that order (the `id` may stand anywhere in the tag: `<section class="card" id="idea">` counts, `data-id` does not): the idea in plain words; a diagram of the system before (an inline `<svg>` in `before`); the high-level list of what changes where (`changes` names every path of the issue's `### Touched modules`, with the functions and types each gains); a diagram of the system after (an inline `<svg>` in `after`, not the same picture as `before` once whitespace between tags is dropped and the rest collapsed); and each choice as a `class="choice"` block holding a `class="pros"` and a `class="cons"` list (whole-word classes: `choices` and `prose` are other classes).
- **Filled in.** The template marks every placeholder with the class `zn-fill` (`explainer.FILL`), and a page that still has an element with that class is refused (a comment or text that only names `zn-fill` is not a class).
- **Self-contained: nothing is fetched and nothing runs.** Inside every tag, every `src`, `href`, `srcset`, `poster`, `action`, `formaction`, `data`, `background` and `xlink:href` value starts with `#` or `data:` (or is empty); no tag has an `on<event>=` handler; no `<meta http-equiv="refresh">`. Everywhere, every CSS `url(` and every quoted value inside `image-set(` starts with `#` or `data:`; there is no `@import` and no `<script>` at all (the diagrams are inline SVG, so the page needs none). As a backstop, when none of those rules found anything, a `://` anywhere outside an `xmlns`/`xmlns:*` value (inline SVG's namespace) is refused as a web address. A link to the web, even an `<a href>` or a URL in prose, is refused: the page reads the same offline, and one rule is simpler to check than a list of tags.
- Matching is on the lowercased text, so `ID="Before"`, `ONCLICK=` and single quotes are the same page. Plain words, the diagrams' truth and the pros and cons' honesty are not machine-checkable: the design reviewer reads the page against the Design (zz-review design mode item 13), the code reviewer rules JC1, and the human reads it before answering.

### 2. `z-nile/engine/explainer.luau` (new, pure)
```luau
explainer.FILE = "explainer.html"
explainer.SECTIONS = { "idea", "before", "changes", "after", "choices" }
explainer.DIAGRAMS = { "before", "after" }
explainer.ATTRS = { "src", "href", "srcset", "poster", "action", "formaction", "data", "background", "xlink:href" }
explainer.FILL = "zn-fill"
function explainer.check(path: string, html: string, hash: string, touched: { string }): { string }
function explainer.accepts(answer: string?): boolean
```
- `check` returns every problem, each starting `<path>: `, empty when the page holds. Its messages, which the specs pin: `has no <meta name="zn-contract" content="<hash>">: ...`; `has <n> zn-contract meta tags: ...`; `its zn-contract "<v>" is not a sha256 ...`; `explains contract <12 hex>, but the contract is now <12 hex>: update the page for the design as it is, then set its zn-contract to <hash>`; `has no <section id="<name>">`; `has <n> <section id="<name>">: ...`; one `its sections are out of order: they are idea, before, changes, after, choices`; `<section id="<name>"> has no inline <svg> diagram`; `the before and after diagrams are the same picture: ...`; `<section id="changes"> does not name <path> (a Touched module)`; `<section id="choices"> has no class="choice" block: ...`; `choice <i> in <section id="choices"> has no class="pros|cons" list`; one `still holds the template's placeholder text (class="zn-fill"): fill it in and drop the class`; and for each fetch or script one of `fetches <attr>="<value>"`, `fetches url(<value>)`, `fetches image-set("<value>")`, `fetches @import`, `runs a <script>`, `runs an event handler (on<x>=)`, `refreshes to another page (http-equiv=refresh)` or `names a web address (<text>)`, each followed by `: the page is self-contained (inline styles and <svg>, data: URIs, no scripts)`.
- A section's body runs from its opening tag to the first `</section>` after it (sections do not nest). A `class="choice"` block runs to the next one or the end of `choices`.
- `accepts` is true only for `y` or `yes`, in any case with surrounding spaces and line ends ignored; `n`, an empty line, `ye`, `yes please` and `nil` (the terminal closed, no line) are not.

### 3. `./zn explain <issue-id>` (new command, `z-nile/engine/main.luau`)
Read-only, runs anywhere (the main checkout, a worktree, under `ZN_DISPATCH`), so the designer, a dispatched design step and the reviewer can all run it. It prints the page's repo-relative path, then `contract <64 hex>` (the hash the meta must name), then either `ok` (exit 0) or one `- <problem>` line per problem (exit 1). A missing page is one problem: `<id> has no explainer page (<path>): z-design writes it from z-nile/templates/explainer.html, and ./zn explain <id> checks it`. A raft id is refused (`explain takes an issue (<id> is a raft)`), and so are an unknown option (`usage: explain <issue-id> (unknown option <k>)`) and a missing id (`usage: explain <issue-id>`). It joins the usage text beside `approve`; it is not in `READ_ONLY` (that set is for `.git`-less sandboxes, which it doesn't need) and needs no main-checkout list (it writes nothing).

### 4. `./zn approve <issue-id>` (changed: the recording path, and one warning before it publishes or pushes)
**On c0369's one-command approve** (re-prep of 2026-11-17). c0369 finds the place first (the prep worktree, the worktree the command runs in, an active issue's raft worktree, or its own detached worktree of origin/main) and starts the engine there; every step below runs in that run, so the page that is checked, opened and recorded is the one in the place's checkout, and the terminal the person typed in is the one the question is asked on (c0369 inherits it). c0369's refusals (`ZN_DISPATCH`, no terminal) come before placement and before everything here.

**main.luau's local limit.** Its top level has 199 `^local ` lines on today's main, and Luau allows 200 locals in one scope (zz-arch lesson `main-luau-local-limit`). This adds exactly one: `local pageIO = {}`, a table holding `pageIO.open(path): (boolean, string)` (the system's opener: `open` on macOS, `xdg-open` elsewhere; the board's existing choice, which `cmd.board` now calls, its warning text unchanged), `pageIO.readLine(): string?` (one line from `/dev/tty` through the same `perl` approach `stdinIsTerminal` uses; `nil` when there is none or it closes) and `pageIO.problems(item, hash): { string }` (the missing-page problem, or `explainer.check(path, text, hash, touchedModules(item) or {})`, reusing `main.luau`'s Touched-modules reader). `explainer` is required inside `pageIO.problems`, `cmd.approve` and `cmd.explain`, as `cmd.approve` already requires `readycheck`, so it takes no top-level local. The prototype's `main.luau` has 200 `^local ` lines and compiles; any prep that lands first with another top-level local must make room (its own table, or this one).

`--check` is unchanged, and so are the refusals before this point (`ZN_DISPATCH`, no terminal, the main checkout, not an issue, not `design: ready`, an unruled open bullet, no `check.sh`, no git identity). Then, in this order:
1. `approval.collect` as today; the page path joins the paths of the dirty check, so an uncommitted or untracked page is refused with today's message, `commit the contract first (<path>), then ./zn approve <id>` (the person must see the page that is on the branch).
2. `hash = contract.hash(parts)`. The page is checked (`pageIO.problems`). Any problem refuses with `<id>: the explainer page does not hold:` and one `- <problem>` line each, before anything is opened or asked.
3. The page is opened by its absolute path with `pageIO.open`. On success it prints `<id>: opened its explainer page, <absolute path>`. If the opener is missing or fails, it warns on stderr, `warning: could not open <absolute path> with <opener>; open it yourself and read it before you answer`, and still asks: a Linux box without `xdg-open` can still approve, and the path is in front of the person.
4. Only then it writes `Approve <id>, contract <first 12 hex>? [y/N] ` and reads one line with `pageIO.readLine`, so the answer is typed at the terminal the refusal checked, not piped into stdin. The opener has returned before the question is written (`sh.run` waits for it), so the page is shown first, and the spec sees that order in the one stream `script` records.
5. Not `explainer.accepts(answer)`: refuse with `<id>: not approved (<the answer trimmed, or "no answer">); nothing recorded` (exit 1), nothing written or committed.
6. `y`: collect again; if the contract paths (page included) are dirty or the hash differs from step 2, refuse with `<id>: the contract changed while the page was open (<path or "a new commit">); nothing recorded. Run ./zn approve <id> again`. Otherwise record exactly as c0369 does (`approval.append`, write `approval.md`, commit only it as `tracker: approve <id>`, print `approved <id> <hash> in <place>`), and c0369's step that makes it count follows.

**The warning before it publishes or pushes.** c0369's step that makes an approval count (run after every recording, for an approval the place already holds, and by `--publish`, the retry) still publishes `approval.md` and nothing else (`publish.allowed` is not widened: what an agent may push to `main` is the user's trust decision). It warns only where the page would not reach `origin/main` with the approval: before it publishes `approval.md` to `origin/main` (the page is not published with it), and before it reports a branch it does not push because that branch is not on origin. Before it pushes `prep-<slug>` or a branch already on origin, and on a raft's layer branch, it says nothing about the page: the page goes with the branch's pull request (f0339 design review 002 F1). There, it compares the place's page with `origin/main:<page>` and, when the worktree has a page that `origin/main` lacks or holds differently, warns on stderr: `warning: <page> is not on origin/main as it is here: push this branch and land it by pull request, or main keeps <the old page | no page>`. It says nothing when the two are the same or the worktree has no page. So a page written at approval time (a legacy item approved from a worktree of main, or a dispatched prep merged before its approval) is not silently left off `main`.

## Unknowns & experiments
Every probe below ran through `./zn run --time <s>`.
- **E1: does `script` hand a typed answer to the child?** Method: `printf 'y\n' | script -q /dev/null sh -c 'read a; echo got=[$a]'`, `(sleep 1; printf 'y\n'; sleep 1) | script ...`, and `yes y | script ...` (`./zn run --time 30`). Result (run): a pipe that ends at once loses its line (macOS `script` sends end-of-input first: `got=[]`, even with a `sleep 0.5` in the child); a pipe kept open delivers it; `yes y |` delivers it with no wait (0.006 s) and needs no sleep. `script`'s own exit code is then 1 (`write master: Input/output error` once the child is gone), so the spec echoes `zn-exit=$?` inside `script` and reads it. `script ... < /dev/null` gives the child no line (the "no answer" case). Fallback: none needed.
- **E2: can Lune read the answer from the terminal?** Method (`experiments/E2-stdin-read.luau`, `experiments/E2-tty-read.luau`, each run as `./zn run --time 30 -- bash -c 'yes n | script -q /dev/null lune run <probe>; lune run <probe> </dev/null'`): one probe reads with `stdio.readLine()`, the other runs `perl -e 'open(my $f, q{<}, q{/dev/tty}) or exit 2; my $l = <$f>; ...'`. Result (run): both work under `script`; the `perl` read gets `n` from `/dev/tty`, and with no terminal it exits 2 (read as no answer). The design reads `/dev/tty`, the same device `stdinIsTerminal` opens, so a piped stdin can't answer for the person. Fallback: `stdio.readLine()`.
