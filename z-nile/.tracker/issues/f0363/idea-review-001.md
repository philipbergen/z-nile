# Idea review 001

## Findings

- F1: The ready sentence drops "same-project". It says readying a raft "whose member depends on a same-type prepared issue outside it" prints the same prompt. That prompt names the command that would put the two issues in one raft. If the dependency is the same type but in another project, that command breaks "No raft holds issues of … more than one project", and the earlier sentence says that dependency must instead be done first. So for a cross-project, same-type dependency, the ready prompt would tell the reader to run a command that is refused.
- F2: The keep-apart record doesn't come from any Problem sentence, and it brings back the third Problem. Once a pair is recorded apart, "the prompt for that pair is not printed again". That covers ready too, so readying the dependent's raft goes back to the bare refusal that names no remedy. The idea doesn't say what ready prints for a recorded pair. It also doesn't say why this mechanism is needed in the smallest fix rather than leaving the prompt advisory.

## Verdict

revise
