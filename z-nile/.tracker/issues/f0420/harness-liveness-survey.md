## Failure cases
Claude: a long model call or a long quiet tool (a 10-minute build) writes nothing, so a silent file looks hung (false idle); a session waiting at a prompt is silent too, so a short mtime window cannot tell idle from hung. Hook stamps fix this: PreToolUse sets busy, PostToolUse and Stop set settled. A running command or subagent keeps a child process, which covers the quiet-tool case.
Cursor: only the SQLite WAL moves, and a checkpoint can pause it; the id is not exposed to children, so match by cwd and pid. Hook support in the CLI is unverified.
Grok: best documented. Stop is a gate and fires again on continuation rounds (D), so key on UserPromptSubmit plus idle_prompt (fires about a minute after settling). Quiet thinking before the first update gives false idle for seconds.
Kimi: wire.jsonl also records request traces, so mtime may move without work (U). SessionHeartbeat proves the process is alive, not that a turn is running; pair it with TurnStarted/Stop.

## Not verified
No resume-attach behaviour was tested for any harness (docs say nothing for Kimi, Grok or Cursor; Claude not checked). Kimi's env var, Cursor's and Codex's hook coverage in the CLI, and all Codex and Gemini file paths are unverified. Child-process and lock-file behaviour was not probed (no live session was touched); no pid files showing busy versus waiting were found beyond Claude's sessions/<pid>.json and Grok's active_sessions.json, whose contents I read only as key names.

## Recommendation
Generic check for every harness: the recorded pid is alive with the same start time (guards pid reuse), and either it has running child processes or the newest mtime under the harness's session folder is under a threshold (say 120 s). Only "pid dead" is a certain answer; "silent for N minutes with no children" is a strong abandon signal that cuts the 30-minute expiry only when combined with the claim's age.
Upgrade where it is cheap: a hook stamp. zn writes .cache/liveness/<worker> on PreToolUse, PostToolUse, UserPromptSubmit and Stop (Claude, Grok, Kimi all document these; Kimi adds SessionHeartbeat). Start with Grok and Claude, which have id env vars and the best docs; treat Cursor, Codex and Gemini as pid-plus-mtime only until tested.
Note: the existing scripts/hooks use only PreToolUse, PostToolUse and SessionEnd (names grepped from settings.json); post-edit.sh, pre-bash.sh and session-end.sh were not opened.
