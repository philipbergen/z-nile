# f0424 code review 001: refutations and fixes

- F1: fixed: a worker's `seen` now moves only on `claims`, `workers`, `status` and `claim` replies and on a wait's own return, never on beat, emit, poke, register, release, gone or stop (`TestWaitNotSwallowedByLaterOps` covers beat, emit, poke and register in the gap); consequences: a new worker's `seen` still starts at its own registered event, and the Design's wake rule says so.
- F2: fixed: `register` no longer reads `ZN_WORKER` (it uses `--worker` or builds `<cli>-<pid>@<host>[.<as>]`), proved by `TestRegisterIgnoresZNWorker` and `TestRegisterAsBuildsID`; consequences: none for the other ops, which still default `--worker` from `ZN_WORKER`.
- F3: fixed: `wire.Call` hands each event line to the client as it arrives and the client writes it to stdout at once, so a follow prints while it runs and then exits 75 (`TestFollowPrintsWhileRunning`, `TestFollowStreamsAndHangupLeaksNothing`); consequences: `Call` takes a line callback, and any line with an `ok` key now ends a call, so `events` against another repository's daemon reports the dir mismatch.
- F4: fixed: the AC24/AC25 spec moved to `z-nile/tests/tooling/live-gate.spec.luau` with a sorted `live-gate.watch.txt`, and the file under `acceptance/` is gone; consequences: the Test plan names the new path, and the spec now also covers the gate without Go.
- F5: fixed: `live.Validate` refuses ids (worker, as, unit, activity, cli, session, needs, `can` entries, limit classes) that do not match the id pattern and free text over 500 bytes or with control characters, as `usage` naming the field (`TestValidation`); consequences: exit 2 for those, and the Design lists the rule.
- F6: fixed: a storage failure is refused `storage`, the client exits 3 naming `events.jsonl` (`TestStorageFailureIsUnavailable` with a 2-block file-size limit, `TestStorageFailureRefused`); consequences: exit 3 now also means a storage failure in the Design's exit table.
- F7: fixed: a `wait` is refused `gone` at once when its own worker is removed (`TestWaiterToldWhenItsWorkerIsGone`); consequences: `wait` can exit 1, and the Design table says so.
- F8: fixed: `gobuild.sh` keeps the build id in `<out>.id`, hashes only non-test sources, `go.mod` and `go env GOVERSION`, and skips the build and rename when the id is unchanged (`TestGobuildSkipsUnchangedBuild`); consequences: the gate's build line reads "up to date" on a second run.
- F9: fixed: added cases for a changed `--can` on a repeat register, an own waking event, EPERM alive, a timed 3 s dead-pid release with the default tick, a register of a pid ps does not know, a loose state directory chmod, the `/tmp` fallback from a long `TMPDIR`, and idle exit under a `--follow` reader, and the rig now clears the timing variables and points `ZN_LIVE_DIR` at a throwaway path; consequences: several tests are parallel, and pids in the core tests moved to 101 and up because pids below 2 are now refused.
- F10: fixed: with no usable Go a full gate or a change under `z-nile/go/` fails with one line naming SETUP.md, any other change skips with one line, and `GOTOOLCHAIN=local` (in the new `z-nile/lib/goenv.sh`) turns an older Go into "Go 1.24 or newer is needed (SETUP.md)"; consequences: `--plan` exits 1 where the gate would fail, and the earlier amendment (always skip) is replaced by the design's rule.
- F11: fixed: `Do` revives a lost worker on any op that names it except `gone` and `stop`, and `register` revives it before a changed-field event (`TestAnyOpRevivesLostWorker`); consequences: reads such as `claims --worker w` now append a `revived` event.
- F12: fixed: a `// step 5:` comment sits at the event slice in `core.go`, and the Design's step 5 says the in-memory events are trimmed to the current segment with older `--since` reads from the store; consequences: none (no behaviour change).
- F13: fixed: a temporary Accept error is retried with backoff (`TestAcceptRetriesTemporaryErrors`), the client retries a refused connection while the socket file exists within its 2 s budget (`TestDialRetriesWhileSocketFileExists`), and a stopping daemon closes the listener first, cancels waiters with a `closed` reply and lets in-flight requests finish before exit (`TestShutdownCancelsWaits`); consequences: the client maps `closed` to exit 3 and a dead daemon's stale socket now costs the 2 s budget before exit 3.
- F14: fixed: pids below 2 or above the platform maximum are refused `usage`, an unknown or zombie pid is refused at register, and the periodic `ps` call now carries the process state so a zombie is dead (`TestPidRules`, `TestProcsStartAndUnknown`); consequences: the Prober is now `Alive` plus `Procs` (start and zombie), and the Design says a reused pid or zombie is caught on the 60 s interval.
- F15: fixed: silence is measured on a monotonic clock and a tick that arrives later than three tick intervals gives every worker a fresh interval (`TestClockJumpAndSleep` with an injected clock); consequences: `live.Config` gains `Mono` and `TickEvery`.
- F16: fixed: `shutdown` and the dir/proto refusals carry `seq`, `events` names a dir mismatch, the dir advice no longer suggests `shutdown`, an oversize request gets a `usage` reply (`TestOversizeRequestAnswered`, `TestRefusalsCarrySeqAndNameTheDir`), release defaults to `done`, `--session` defaults from the CLI's environment variable, and the Design table lists exit 1 for `wait` and `register` and says `./zn live build`; consequences: none beyond the Design edits.
- F17: fixed: a failed `ps` or unknown pid at register is an error, send errors are handled, `storeFail` is gone, the tests use `exec.LookPath("go")`, `claim` replies copy values, `ZN_LIVE_TICK` and `ZN_LIVE_CHECK` are flags only (`--tick-every`, `--check-every`), the client refuses a socket owned by another uid, and the Design documents `ZN_LIVE_ROOT`; consequences: the owner check cannot be tested without a second user, so it is untested.
