# f0425: App approvals view

## Problem
An app view where the owner works through approvals: the queue, each ticket explained, each guess with its options, approve or send back

Decided with the user (2026-11-21): "an optional rich experience where you can visually appealing stay on top of everything (settings, workers, tributaries, rafts, and tickets, stats) there should be a really vibrant stats view that shows you live stats as they are trending for your repo that updates every time a step forward is recorded" and "everything except look at code"; of the approvals mockup: "the mockup looks very good, let's keep building that and the app so we can keep improving on it, we can build the experience for stats and workers" (`mockup/index.html` now has Workers and Stats views beside Approvals, on simulated data, and the app is built on from that mockup).

Decided with the user (2026-11-21, tickets and rafts): "The tickets are an interesting one to mock, one comment on send back there needs to be a mesage collected with instruction and there needs to be a link to open that ticket in an ai cli so I can talk through it. That really goes for all of it, any item on the board including stats should be linkable directly to an AI cli with context so that we can talk about it. How do we model the rafts and tickets?" Three decisions: a send-back collects the stage it goes back to and a required instruction message; every item (ticket, raft, guess, worker, queue entry, stat, event, tributary) has a route and can be opened in an AI CLI with its context (`zn talk <ref>`); the mockup models a ticket as a staged unit of intent (idea, design, rafted, code, review, approval, landed) and a raft as an ordered stack of tickets on one branch and one pull request (`mockup/index.html` now has Tickets and Rafts views).

Decided with the user (2026-11-21, colours): "both mock and html should use the color scheme from philip-bergen.com" and "I like the bright collors on risky/normal and all those things, I just don't really like the pruple". `mockup/index.html` and `z-nile/README.html` now use the site's gold-e scheme (light by default, a warm dark by the theme button) and its fonts (Instrument Serif titles, Geist, Geist Mono); the status and chart colours stay bright, with the purple ones replaced (waiting is lime, series 1 is cobalt).
