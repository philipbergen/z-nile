# f0429: Public board

## Problem
- The board is today only an ignored local file (`.cache/board.html`) on the owner's machine, so nobody else can open it.
- No step publishes the board after a tracker change, so any copy shared by hand goes stale with the next change.
- No committed file records which worker carries an active raft: the claim is a random `active-…` stamp and the carrier's name is kept only in the ignored `.cache/work/`.

## Non-goals
- The page is read-only: nobody can change, comment on or approve a ticket from it.
- No way to mark a note or a ticket private is added: whatever is committed to the tracker repository is published, and keeping something private means not committing it there.
- Moving the tracker into its own repository is f0428, and keeping GitHub issues up to date is f0430; neither is done here.
- The board's columns, Flow bands and tributary counts, and the local `.cache/board.html`, stay as they are: the only additions to the page are the worker name and the link that opens a ticket's committed file.
- The ignored `.cache/work/` carriers file and the claim stamp stay as they are: the committed worker line is only a name for the board, not a new claim or heartbeat.

## Solution
- The board of the tracker repository (f0428) is a web page at a public address that anyone can open without a GitHub account or sign-in.
- The page shows every ticket and raft in the same six columns (ticket, design, raft, ready, run, done) and the same Flow bands as the local board built from the same commit, with no new grouping.
- The commit that makes a raft active writes the name of the worker that carries it into the raft's committed file, and the commit that releases or finishes the raft removes it.
- Each raft in the run column, and each ticket in that raft, names its worker on the page, read from that committed line, and shows "no worker recorded" when the line is absent.
- Every ticket shown on the board can be opened from it and read in full, where "in full" means the ticket's file exactly as committed in the tracker repository.
- The page is built only from files committed to the tracker repository, so anything not committed there (ignored files such as `prompt.md` and `.cache/`, commit metadata, and anything on the owner's machine) never appears on it.
- After every push to the tracker repository's main branch the published page matches that commit within ten minutes, with no command run by the owner.
- A publish whose pages would contain an access token or an absolute path from the machine that built them fails and leaves the previous page in place.
