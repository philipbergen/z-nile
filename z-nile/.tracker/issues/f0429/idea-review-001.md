# Idea review 001

## Findings

- F1: The third Solution sentence relies on "a note marked private", but the tracker has no way to mark a note private. Nothing in the zz-rules skill, the other skills or the README defines one; the only uses of "private" there are about git refs and temporary paths. So a reader can't tell which notes the sentence covers, and can't find it true or false. It also clashes with the second sentence, which says every shown ticket "can be opened and read in full". Any ticket that held a private note could not be shown in full. The idea has to either define how a note gets marked private, or drop that part and say what is left out of the full ticket.
