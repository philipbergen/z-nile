# f0430: Github issue bridge

## Problem
- A ticket for work on the host repository cannot be started from one of that repository's GitHub issues, and it keeps no record of the issue it came from.
- Someone reading the original issue cannot tell that the ticket's raft has been readied for implementation, or where to follow that work.
- Someone reading the original issue cannot tell when the raft's implementation pull request opened or when the ticket reached done.

## Non-goals
- zn does not post an update for any step other than z-ready claiming the ticket's raft, the raft's implementation pull request opening, and the ticket reaching done.
- zn does not post an update when a raft is stopped.
- zn does not block, fail or delay readying a raft, opening a pull request or finishing a ticket because GitHub cannot be reached or refuses a post.
- zn does not run a background process to retry owed updates; it retries only when a later posting step runs.
- zn does not copy later changes to the issue (edits, comments, labels, closing) back into the ticket.
- zn does not close, label, assign, unlock or edit the original issue; it only adds its updates.
- zn does not use a GitHub App, a bot account or a stored token; it uses only the person's gh sign-in.
- zn does not move the tracker to its own repository or publish the board here; those are f0428 and f0429, which this ticket depends on.

## Solution
- A ticket can be started from an issue of the host repository, and the ticket records which issue it came from.
- zn posts one short "started" update to that issue when z-ready claims the ticket's raft, which tells the reader the issue is being worked on and links to the ticket on the public board.
- zn posts one short "pull request opened" update to that issue when the implementation pull request of the ticket's raft opens, which links to the ticket on the public board.
- zn posts one short "done" update to that issue when the ticket reaches done, which links to the ticket on the public board.
- zn posts no update when the ticket's design (prep) pull request or its rafting pull request opens or merges.
- zn records on the ticket each of the three updates as owed when its step happens and as posted once GitHub has accepted it, and never posts an update that is recorded as posted.
- A post that fails (gh signed out, network down, GitHub refusing the comment, the issue locked) never blocks or fails the step that caused it: the step completes, the update stays recorded as owed, and zn prints a warning that names the ticket, the issue and the owed update.
- Each time zn later runs a step that posts an update for any ticket, it first retries every owed update of every ticket, oldest first, so a ticket's updates reach its issue in the order started, pull request opened, done.
- `./zn status` lists every ticket that still owes an update, with the updates owed, including tickets that have already reached done.
- When a raft is stopped and readied again, zn posts no second "started" update, and it posts no second "pull request opened" update if the raft's implementation pull request is opened again.
- A ticket that reaches done and owes no update has exactly three updates on its issue, however many times its raft was stopped and readied again; a ticket that still owes one has fewer, and its record says which are missing.
- Every read and post goes through the gh program under the person's own GitHub sign-in.
- zn posts only to a repository the settings name, and refuses to post anywhere else.
