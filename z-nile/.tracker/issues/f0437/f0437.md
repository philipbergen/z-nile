# f0437: The app on the live daemon

## Problem
- The Approvals, Workers, Stats, Tickets and Rafts views exist only as f0425's mockup with simulated data, and nothing serves any view with the real tracker or the live daemon's real state.
- There is no board view and no settings view in an app at all, real or simulated.
- No view updates when a step forward is recorded, although the live daemon already emits an event for each one (f0424).
- A person can start and watch a worker or a dispatch run only from a terminal of their own, never from an app.

## Non-goals
- The app has no view or control for browsing, opening or reading the repository's code files or diffs; code that a run prints in its embedded terminal is not ruled out.
- The command line loses no command and keeps working with the app not running.
- The live daemon's own knowledge of workers, claims and events (f0424) is used as it is, not redesigned.
- The control on every item that starts `zn talk` with that item's context is f0432's deliverable, and this ticket neither builds nor changes it.

## Solution
- One command starts the app, served by the live daemon, and opens it in a browser or window.
- The app shows the real tracker and the real live state in the views approvals, workers, stats, tickets, rafts, the board and settings, with no simulated data left in a delivered view.
- Every view updates by itself when the live daemon records a step forward, without a reload.
- A worker or a dispatch run can be started from the app and watched in an embedded terminal, which shows that run's own output unchanged, including any code the run prints.
- Every item shown in a delivered view has a place where f0432's talk control can sit, and this ticket adds no talk control of its own.
- The app is built view by view from the mockup, each view replacing its simulated data with real data.
