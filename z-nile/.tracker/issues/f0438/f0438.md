# f0438: Pictures in ideas

## Problem
- `./zn idea <id> --text` takes text only, so a person cannot give a picture, a PDF, a Markdown file or an HTML mockup with an idea, at capture or later.
- A ticket's folder has no agreed place for such a file, so when one is copied in by hand and committed, the board, the briefs and `./zn idea` cannot tell that it belongs to the idea.
- The board and the approval walk show an idea's text and none of the files that belong to it.
- The worker that designs or builds a ticket is not handed any file that belongs to its idea.

## Non-goals
- Showing attached files in the app is not part of this idea: that view belongs to f0437, which builds the app and can read the files from the agreed place.
- Whether an approval covers the attached files stays an open question for the owner after this idea is done, and nothing here changes what an approval records.
- Removing or replacing an attached file is not part of this idea.
- No file type beyond PNG, JPEG, GIF, WebP, PDF, Markdown and HTML is accepted, so SVG, HEIC, TIFF, BMP and AVIF files are refused.
- No tool for drawing or editing a picture or mockup is added.

## Solution
- A person can attach one or more files to an idea when capturing it and to an idea captured earlier, and a file is accepted only when it is a PNG, JPEG, GIF or WebP image, a PDF, a Markdown file or an HTML file.
- A file of any other type, SVG included, is refused with a message that names the accepted types, and nothing is added to the ticket's folder.
- Each attached file is kept in one agreed place in the ticket's folder, where the tooling finds it as the idea's file, and moves with the ticket through every lifecycle directory.
- The board and the approval walk each show or link every attached file beside the idea's text.
- The brief given to the worker that designs the ticket, and the one given to the worker that builds it, each name every attached file.
