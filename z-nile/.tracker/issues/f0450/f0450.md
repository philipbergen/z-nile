# f0450: Rework counts shipped defects

## Problem
`./zn metrics` reports Rework = defect / (defect + feature) on all done defects, so a problem found and fixed inside a feature that was still open counts as rework. Today 13 done defects against 48 features give 21.3% by issues, over the 20% target, although ten of the thirteen are tooling defects and several fixed work that was not finished. No unfinished ticket covers this (searched every `.tracker/issues` outside `done/` for "rework": f0446 only describes the figure, d0149 and the others mention it in passing).

Decided with the user (2026-11-24): "I want defects to count only when they ship, we've treated this session as one big body of work and it hasn't really shipped any defects imo"

Asked what "shipped" means, the owner chose "Fixes finished work". Decided with the user (2026-11-24): "Fixes finished work": a defect counts only if the ticket or raft it fixes was already marked done when the defect was found. Problems found and fixed inside a feature that is still open never count.

What should happen: the three rework measures (lines, issues, agent time) are shipped defects / (shipped defects + features); the old all-defects figure stays visible on one line; the defects left out and the defects with nothing recorded about what they fix are each listed.

## Non-goals
- The board's per-period "Defect %" and "Defect time %" (`board.luau`, `chart.luau`, `stats.row` ratios): they are a share of what closed in a period, not the rework figure, and have no `Item.fixes`. Kept as they are (listed in Verification log).
- Recording `fixes:` on open or not-yet-captured defects other than through `./zn new issue d --fixes`.
- Guessing what an old defect fixes: where its Problem does not state it plainly it stays unrecorded and is listed for the owner.
- Chores stay out of the figure, as before.

## Solution
A defect names what it fixes in a frontmatter key `fixes: [<id>, ...]` (issues or rafts). `./zn metrics` counts a defect as shipped when any id it fixes was already done on or before the day the defect was captured (`created:`). A new pure module `z-nile/engine/rework.luau` decides it; `cmd.metrics` reads the facts and prints.

## Design
### What defect tickets carry today
The 13 done defects carry `type`, `raft`, `depends_on`, `emergent`, `created` and prose; no key names the ticket a defect fixes. `depends_on` means "must be done first" (a fix often depends on nothing, and d0412 depends on c0202, the thing it fixes, but d0298 depends on three unrelated tickets), `raft:` names the raft that fixes it, harvest lines are not on the defect. So a new key is needed.

### Key
`fixes: [f0033, R0044]` (ids of issues or rafts, read with `store.readFront` and `store.idList`). `./zn new issue d <slug> --fixes <id>[,<id>...]` writes it (for a defect only; the stub otherwise has no `fixes:` line). z-idea step 3 asks for it. The capture rule (`CAPTURE_KEYS`) lets a capture edit it. `./zn audit` reports an error for a `fixes:` id that names no item (`unknown-fixes`); a defect with no `fixes:` is not an audit finding (the old defects would fill every audit with warnings): `./zn metrics` reports it.

### Dates
- Capture date: `created:` (recorded in the file; a defect with none counts as shipped).
- Done date of the fixed ticket: no date is recorded in the document (`status:` carries no date), so it is read from git history, `history.read`'s `closed` (the commit day the issue first arrived in `done/`), and for a raft its `doneAt` (UTC instant, shown as a UTC day). One rule: `rework.doneDays(closed, doneAt)`.
- Compared as days: done day <= captured day counts as done first (same day counts: the stricter reading). A defect fixing several ids counts when ANY was done first. A fixed id that is not done, or has no recorded done day, was open.
- No readable history (`history.read` nil, as in a copy with no git): every defect counts, and a line says so.

### Three classes (`rework.classify`)
- `shipped`: some fixed id done first, or no capture date.
- `open`: it names fixed ids and none was done when it was captured. Not counted.
- `unrecorded`: no `fixes:`. Counted as shipped (the stricter reading) and listed until someone records what it fixes.

### Report
```
Rework = shipped defects / (shipped defects + features). Target: under 20%.
Rework counts every phase, capture to deliver.
  by lines added:  ...
  by issues:       ...
  by agent time:   ...
  all defects (the figure before f0450): lines ..., issues ..., agent time ...
  defects not counted, their work was still open when they were captured: N: d0412 (fixes c0202), ...
  defects with no fixed ticket recorded: N: d0410, ... (counted as shipped until recorded)
```
`rework.lines(...)` builds the text from the rows (pure); `cmd.metrics` adds no top-level local (the module is required inside the function). `zz-stats/SKILL.md` and the README state the new formula.

### Scalability
One `history.read` (cached by HEAD) per metrics run.
### Maintainability
One pure module with three functions; reads at the edge in `cmd.metrics`.
### Usability
One extra line shows the old figure; the listings name every defect left out or unrecorded.

### Rules and mutants
| rule | spec :: case | mutant it kills | checked |
|---|---|---|---|
| a defect whose fixed id was done on or before its capture day is shipped | classify :: done first | `<=` written `>=` | yes |
| any fixed id done first is enough | classify :: any of several | `all` instead of `any` | yes |
| a fixed id not done is open and not counted | classify :: still open | treat missing day as done | yes |
| no `fixes:` is unrecorded and counted | classify :: unrecorded counted | drop unrecorded from the count | yes |
| the report divides shipped by shipped plus features, and shows the old figure | lines :: figures | divide by all defects | yes |
| unknown `fixes:` id is an audit error | audit :: unknown-fixes | no audit check | yes |
| `new issue d --fixes` writes the key | new :: fixes flag | flag ignored | yes |

## Acceptance criteria

### Checked
- AC1: a defect is shipped when a fixed id was done on or before its capture day, and not counted when it was open; a defect with no `fixes:` is unrecorded and counted.
- AC2: `./zn metrics` prints the shipped formula, the old all-defects line, the not-counted line and the no-fixed-ticket line.
- AC3: `./zn audit` errors on a `fixes:` id that names no item; `./zn new issue d --fixes` writes the key.
