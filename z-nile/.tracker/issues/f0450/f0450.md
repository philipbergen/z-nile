# f0450: Close work already on main

## Problem
- The owner asked, verbatim: "How much is missing before we can go back to really using the system and not this session where the safe is disabled". To the proposal to close the hand-built tickets properly (design caught up, remainder split off, final review, approval, done), the owner said, verbatim: "excellent, go ahead".
- The evidence is three read-only audits of origin/main 3e7b197e3, made on 2026-11-24 and kept at z-nile/.tracker/issues/f0450/evidence/audit-A.md, audit-B.md and audit-C.md, plus the tracker files and the `git log` of origin/main cited below.
- Thirteen z-nile tickets had code merged straight onto main outside a readied raft, and none of them is done in the tracker: f0420, f0421, f0424 and c0435 (audit-A.md lines 7-9), f0422, f0423, f0425 and f0437 (audit-B.md lines 7 and 12), and f0427, f0428, c0436, c0179 and d0426 (audit-C.md lines 8-27).
- d0434 is also not done. It was merged as 66ba58e98 (#756), and z-nile/.tracker/issues/d0434/d0434.md lines 6 and 10 hold an empty `raft:` and `design: draft`. Its folder has no `approval.md`.
- c0178 is also not done. Its slice 1 was merged as 3e7b197e3 (#795), and z-nile/.tracker/issues/c0178/c0178.md holds `raft: R0061` (line 6) and a `prepared-…` status (line 13). Unlike the other fourteen, its folder has an `approval.md`.
- "Rework counts shipped defects" was built the same way, but only on the branch rework-shipped, which is not merged into origin/main.
- One ticket's code can span several merged commits: f0420's came in 680c79ab5 (#703), 8e5fbbbe9 (#710), ca8d1c24d (#748) and 9e0b75761 (#758), and each of their subjects begins with `f0420:`.
- audit-C.md lines 16-17 name two ways to close merged code: (a) a closing raft whose final review judges the merged commits by hand, with `none` in every code cell, or (b) an engine change that lets the trace cite merged code. Line 19 says no engine rule or skill names either way.
- The engine recognises a closing layer only as "the stack changed no source file" (z-nile/engine/trace.luau lines 1148-1151), and then requires `none` in every code cell. So `./zn trace --check` passes without looking at any code (audit-B.md line 9, audit-A.md line 14).
- When a closing raft's review fix changes a source file, trace.luau lines 1152-1156 refuse `none`, and line 1166 accepts only a path the stack itself changed, without checking which commit wrote the cited lines. So a code cell cannot cite merged code in a file the stack did not change.
- The code review of a closing layer is given `git diff origin/main...HEAD`, which holds no code, and nothing checks that a reviewer read the merged commits (audit-A.md lines 15 and 301).
- A pushed guess can never be changed or removed (zz-rules SKILL.md, the `guess` row), and no command moves one to another ticket. So when a part-built ticket is split, the unbuilt part's guesses stay on the ticket that closes, and the owner's approval of that ticket covers them (audit-C.md line 20; audit-B.md line 11).
- A split can make more than two tickets: audit-C.md lines 121-123 plan f0427 as the original plus two new tickets, and audit-A.md line 76 says f0420's outcome 11 can be its own ticket.
- z-design requires the owner's scope line for every outcome a split moves (z-design SKILL.md line 10; audit-B.md line 10). But no command checks a split, and no command refuses a close whose split lacks that line.
- An outcome sentence that is only half built has to appear on more than one ticket of its split, each with a `Scope decision (user, …)` line. The cases are f0423 S1 and S2 and f0437 S2 (audit-B.md line 10), and f0420's Scope decision and Decided lines (audit-A.md line 78).

Decided with the user (2026-11-24): "a". Asked whether c0435 and f0425, built by hand straight onto main, should (a) be closed now by reviews that judge the merged commits by reading them, the trace's code column `none` and each review's record naming the commits and pull requests it read, or (b) be closed only after a closing route whose trace cites named commits is built; this ticket stays the later improvement.

## Non-goals
- This idea does not decide whether the listed tickets wait for this change, or close first by audit-C.md option (a) with `none` in every code cell; the owner decides it.
- This idea does not do any listed ticket's own prep under the existing rules (audit-A.md lines 85-86). That prep covers recording its inline guesses with `./zn guess` (audit-A.md line 12), writing its check lines and missing specs, and running fresh review rounds in place of review files that were never committed (audit-A.md line 11).
- This idea does not change how `./zn done` checks approval: it already refuses an unapproved ticket in a raft readied with `Lands: approved` (z-nile/engine/main.luau lines 5477-5490 and 7086-7088).
- This idea does not decide whether each ticket gets its own closing raft or the closes are grouped; the owner decides it.
- This idea does not decide whether a split uses the reverse form, where a new ticket takes the built part and closes and the old id keeps the unbuilt part; the owner decides it.
- This idea does not decide how "Rework counts shipped defects", whose code is only on the unmerged branch rework-shipped, gets onto main or is closed; the owner decides it.

## Solution
- A raft is a closing raft exactly when its raft file has a `Closes:` line listing one or more commits, and `./zn ready` refuses a `Closes:` commit that is not on origin/main.
- `./zn ready` refuses a closing raft whose `Closes:` line leaves out any commit on origin/main that changed a source file and whose subject begins with a member ticket's id followed by `:` or a space.
- In a closing raft, the changed-source set that `./zn trace --check` checks code cells against (built at z-nile/engine/main.luau line 5342) also holds every source file a `Closes:` commit changed. Code cells cite those files at the stack's head, and each cell is checked as trace.luau lines 1158-1168 check it today.
- `./zn trace --check` fails any code cell of a closing raft that is `none`.
- In a closing raft, the briefs for the code review and the final review hold the diff of every commit on its `Closes:` line.
- Each code-review and final-review file of a closing raft has a `Read:` line listing the commits that review read. `./zn done` refuses a closing raft unless the `Read:` line of its last code-review file and the `Read:` line of its last final-review file each list every `Closes:` commit.
- A split of a part-built ticket is recorded as a `Split:` line on every ticket of the split, each line naming the ids of all the other tickets, so a split may make any number of tickets.
- `./zn audit` reports an error for a split unless each Solution sentence the original ticket held before the split appears on exactly one ticket of the split, or else appears on several tickets, each of which has a `Scope decision (user, …)` line quoting that sentence.
- A split moves a guess in two steps: it appends a line `G<n> moved to <id>` to the original's `guesses.md`, leaving the guess's own line as it is, and it records the same Open and Chose text on the other ticket with `./zn guess`. The original's approval walk then leaves out a moved guess, and `./zn audit` reports an error for a moved line whose target ticket holds no guess with that Open and Chose text.
- `./zn done` refuses a closing raft that holds a ticket with a `Split:` line unless that ticket has a `Scope decision (user, …)` line naming every ticket id of its split.
