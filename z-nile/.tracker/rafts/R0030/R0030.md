# R0030: Suite split

## Theme
One chore: split the spec run into a harness suite and a game suite, without moving any spec.

The user's decision (2026-10-04) is binding: "put all the build/tracker related tests in a separate test suite and set up so that it doesn't run unless files in the tracker/build harness is being changed", and "vice versa" for the game suite. "Nowhere" (the same day): no gate runs both suites unless the change touches both. A mixed change is the union of every path. A script plus a Logic file runs the harness suite plus that file's graph hits, not `ALL`, and pellets stays out. A `SHARED` path is `ALL` wherever it sits in the list. `--full` stays on demand, and `scripts/setup.sh` and GitHub CI keep it.

The user's decision (2026-10-20, on design review 005): option B. An item's `check.sh` and `acceptance/` files stay on the plain text rule; only the other files in an item folder (documents, `spend.md`, reviews) use the narrow rule; only c0082's `real-tree` stays on a list (`TRACKER_TREE_READERS`). The user also approved a sixth design round beyond the five-round cap.

## Whole-raft design
One new module, `scripts/lib/suites.luau`, and the callers that today force a full run.

```
changed paths
    │
    ▼
suites.select(graph, paths) ── any shared path ──► "ALL"   (SHARED, or the runner's require closure)
    │  union over every path, not changed[1]
    ├── graph.affectedSpecs (require)
    ├── suites.textAffected (string literals, deleted paths included; an item document only by the item
    │                         and below, plus TRACKER_TREE_READERS; check.sh, specs, other files plain)
    ├── HARNESS path ► suites.list(harness)
    └── GAME path   ► suites.list(game)     lobby.project.json and default.project.json
                                            src/ stays on the graph, not a whole-suite pattern
```

A script plus a Logic file is that union, not one side and not `ALL`. Pellets stays out.

A path is shared when it matches `SHARED` or is in `graph.closure(g, "tests/run.luau")`, so a module the runner starts requiring later (R0039's jail) runs everything with no new pattern.

Public surface, all pure, all in `scripts/lib/suites.luau`:
- `isSpec(path): boolean`
- `of(g, spec): "harness" | "game" | "both"`
- `list(g, name): { string }`
- `textAffected(g, changed): { string }`
- `select(g, changed): { string } | "ALL"`
- `sideOf(g, paths): { string }` (`harness`, `game`, or both)

`scripts/affected.luau` calls `select` instead of `FULL_RUN_PATTERNS`, and gains `--suite`, `--deps` (the printed set equals `graph.affectedSpecs` union `textAffected`, never `ALL`; order is not the rule) and `--which` (`sideOf`; no paths exits 2). `scripts/check.sh` gains `--suite`, refused before any tool runs. `scripts/hooks/stop.sh` asks the selector about every changed path, a staged rename's old path included. `scripts/tracker/main.luau` is the land default and the done argv, both `--affected`. The mode `gate.doneGate` returns stays `"full"` (run the gate). c0074's two `args: --full` assertions become `args: --affected`; its fail/skip messages stay.

No new edge in `tracker/architecture.md`. This module is not a Logic feature.

The issue design's today → becomes table is the skill and template edit. The two documents agree: no spec moves, and R0025 and c0072 are not edited (both are in `done/`).

## Risks & rollback
- **Sequestration.** The RC0 edits, the c0080 grep and the c0037 grep are the only changes this raft makes to sequestered `check.sh` files. Phase 3 and the code reviewer's item 2 name those exceptions, in words that do not contain `check.sh --full` (AC8 greps for it). Any other such diff is a stop. The binding record is this raft, not a done raft. c0037 is not a promoted spec and is not an Override.
- **Template drift.** A `new raft` from a worktree branched before this lands publishes the old RC0 (a direct push, and CI ignores `tracker/**`). There is no promoted tripwire. That one raft runs both suites until a later prep's design-mode item 2 sees the old RC0. That is one raft, not every PR's CI. Do not teach `new raft` to render the template from `origin/main`. Do not add a selector-miss exception. Red on `origin/main` stays `BLOCKED:`.
- **Selector miss.** Under Nowhere, every local gate uses the same selection, so a miss shows up in CI's `--full`, possibly after `done`. Fix it forward on the PR's branch. Do not treat it as `BLOCKED` unless the fix would touch a promoted spec or a sequestered file, or its `review-fix` round has a high finding. Red on `origin/main` stays `BLOCKED:`. The RC0 repair is not a selector-miss exception.
- **c0074.** Changing done's argv without the two `args:` lines turns a promoted spec red. c0083 changes those two lines itself. Leaving `toBe("full")` or the fail/skip messages out turns it red the other way.
- **This raft's gate is ALL.** It edits `scripts/check.sh`, which is `SHARED`.
- **Rollback.** The module and the flags are additive. Reverting the commit restores `FULL_RUN_PATTERNS` and the old gate commands. The RC0 edits revert with it; a raft already readied from the new template would need its RC0 put back by hand, which is the same one-line diff in reverse.
