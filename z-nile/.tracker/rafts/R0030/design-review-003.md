### F1 [medium] The changed-folder text rule has no row, and `--deps .github/workflows` can print nothing while the spec passes
Where: c0083 `suites.textAffected` ("a folder above one, or a path inside a changed folder"; "the existing references … which match a changed folder that holds them"); Rules and mutants table (no row); ticket-prep Override check and Affected specs (now `--deps <path>` per Touched path, and Touched paths are often folders)

Replacing it with `if false then` leaves `suites.spec.luau` at 15 passed, 0 failed. Every `select`, `textAffected` and `--deps` input in the spec is a file. The author will be tempted to add one folder assertion to the AC4 case.

The grep in the Override check still backs this up, so it is a quiet under-report, not a missed override.
Recommendation: add a row "an existing path inside a changed folder selects its readers" with mutant "a changed folder matches only tokens equal to or above it". In the AC4 case (or AC5's `--deps`), `suites.textAffected(g, { ".github/workflows" })` contains `tests/acceptance/c0001/ci-workflow.spec.luau`, and a synthetic stand-in reader that names `gone-folder/sub/file.md` (absent) is not selected by the folder `gone-folder/sub`: the inside-folder rule is for existing references only, as the design says.

### F3 [medium] The Stop hook's clean-tree exit is neither designed nor pinned, and without it the hook gates the whole branch on every stop
Where: c0083 `scripts/hooks/stop.sh` ("takes every changed path … and asks `lune run scripts/affected -- <paths>`. It gates … when the answer isn't empty"); `scripts/affected` ("With none of them, explicit paths (or the branch diff, as today) go through `select`"); `suites.spec.luau:593-661`
Evidence: with no explicit paths the plain selector falls back to `changes.files(base)`, the whole branch diff. The design says the hook asks the selector about the changed paths and gates when the answer is non-empty; it does not say that no changed paths means exit 0. The prototype keeps today's `[[ -z $changed ]] && exit 0`, but the fixture keeps the untracked `scripts/tool.sh` for every `stop()` call, so the tree is never clean and deleting that line passes every case. Without it, a raft session whose work is all committed calls `lune run scripts/affected --` with no paths, gets the branch selection (`ALL` on this raft, since `scripts/check.sh` is `SHARED`), and runs `check.sh --affected` on every stop.
Critique: today's hook has the early exit for its `src|tests` filter; once the filter goes, the early exit is the only thing between "nothing uncommitted" and the branch diff. The author will be tempted to call this an implementation detail.
Consequences: the rule is "no uncommitted or untracked path: exit 0 without calling the selector or the gate". Ignored files stay out (`--exclude-standard`), so the main checkout's `prompt.md` and `.cache/board.html` keep the hook quiet there.
Recommendation: add the sentence to the hook design and AC6. In the hook case, after the rename step, commit everything (`stub.log`, `bin/` and `home/` are ignored) and run `stop({ STUB_SELECT = "tests/tooling/x.spec.luau\n" })`: exit 0, and the log contains neither `lune` nor `gate`. Mutant: "the hook asks the selector with no paths". Add the row.
