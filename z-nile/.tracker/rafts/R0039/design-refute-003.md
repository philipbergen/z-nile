# Answers to design review 003 (R0039)

- F1: fixed: the wiring is now a pure, pinned function. `fence.rebindFor(candidates, resolve, exists)` takes each candidate that exists, as given and as resolved, through `rebindPaths`; a candidate that does not exist is skipped (the run's `PATH` names `<runTemp>/bin`, which Linux never makes, so every nested runner would otherwise have failed its trial: that was the hole); a NixOS entry that is a link into `/nix/store` is bound as given (bubblewrap binds the link's target at the given path inside), and a checkout reached through a link into `/tmp` is bound by its target. A spec case with stubbed `resolve`/`exists` covers the missing `bin`, the NixOS link, a checkout through a link and an ordinary path; mutants (missing kept, resolved dropped, given dropped) all killed. `jail()` step 1 calls it with the real `realpath` and an existence check. consequences: the existence check runs once per candidate per top-level run (a handful of stats); the executor's E5 run (nested `c0058` runs on CI) is where the wiring is exercised for real, and is listed as the first thing to read.
- F2: fixed: the trial command is absolute, `/bin/sh -c :`, in `fence.trialArgv`, in the script's trial and in `TRIAL_PATTERN` (all pinned), so neither depends on `PATH` or on a rebind the script cannot compute. The script and the runner now run the same command; the remaining difference (the script passes no rebind) cannot make it succeed where the runner fails, only the other way round, and a host that needs a rebind to start would show it in E5. consequences: `/bin/sh` is assumed on every Linux host the runner supports (also true on NixOS).
- F3: fixed: `lock-pidns.spec`'s header says the launcher holds the lock; implementation steps 2 and 4 list `rebindPaths`, `rebindFor`, `leaks` and the `gpgSign` entries.
