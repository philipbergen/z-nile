# R0040: Skill lessons

## Theme
Folded into R0042. c0111's `raft:` is R0042. This directory keeps the design reviews and `harvest.md`, because the lesson sources name R0040. The issue itself is a member of R0042. **R0040 is never readied**: it has no members and stays at `new` and `design: draft` (given back by R0042's prep, 2026-10-20), so the board does not show it as Ready.

A single chore: lessons learned from reviews become files under the skills that apply them, searchable with one command and read at both ends of every phase. Today every raft's design-review findings are written once and never read again, so the same classes of defect cost rounds in raft after raft (R0039: 5 rounds, 29 findings, most of them avoidable in the first draft). The user asked for this on 2026-10-20: each skill keeps its own lessons, the end of design (and of the code review) harvests findings into them, the start of the next design applies them, and everything already learned is backfilled (c0112, the next raft). This is workflow tooling, and no product decision in `tracker/game-design.md` is relied on or changed.

## Whole-raft design
One member, `c0111`. No `src/` change, no dependency edge, and no `tracker/architecture.md` change.
```
reviews and notes (design-review-NNN.md, review-NNN.md, `- note …`) ──harvest──► <item>/harvest.md ──names──► .claude/skills/<skill>/lessons/<slug>.md
                                                                   │                                 │
scripts/tracker/lessons.luau (pure: parse, findings, parseHarvest, check, sources, uncovered, select, index; load reads)
                                                                   │
scripts/tracker.sh lessons [filters] | --full | --tags | --check | --uncovered [<id>…]      (read-only)
renderPrompt (ready) ──► prompt.md "## Lessons": the build lessons' index
skills: every SKILL.md ends with the same "## Lessons" paragraph (read at the start; new lessons routed by role)
        z-design 5.1 lessons pass, 5.3 harvest each round, 5.5 confirm · zz-execute Phase 4 harvest, Phase 5 confirm · zz-review item 10, `Lesson:` line
```
The interfaces are typed in c0111's Design.

## Order & dependencies
Single issue, nothing before it. c0112 (lessons backfill) depends on it and is prepped after this raft lands, because it writes this format and turns full coverage into a gate invariant. No other open raft (R0011, R0012, R0030, R0034, R0035, R0038, R0039) changes `scripts/tracker/main.luau`'s `renderPrompt` or the prompt template. Any of them may edit a skill doc, which merges as text.

## Experiments phase
Both unknowns were settled in prep (c0111 E1, E2), and the mutation check ran on a prototype. Nothing is left for the executor's Phase 1. The prep also dogfooded the mechanism: R0040's design reviews are harvested into `harvest.md` and lessons, checked with the prototype's `lessons --check` and `--uncovered R0040`.

## Exit criteria
The RC0 lines (the full gate, c0111's AC1 to AC8, and `promote-check`), plus:
- RC1: at least one design (or both) lesson is sourced from R0040's own design reviews, which shows the harvest ran end to end (`lessons --when design --full` prints a `sources:` line naming `R0040 design-review-`).
- RC2: the prompt that `ready` would write carries the build lessons. This is covered by AC5 in a fixture, because the real `ready` publishes.

"Done" == `scripts/tracker.sh done R0040` succeeds.

## Risks & rollback
- **Rafts prepped before this lands** (R0012, R0030, R0035) have unharvested design reviews. Their executor's confirm step (zz-execute Phase 5 step 3) harvests them before `done`: roughly 20 to 40 findings of extra work each. A prep that is mid-round when this lands does the same at z-design 5.5. This was the user's choice on 2026-10-20 (design review 5 F1), over making them wait for c0112 or exempting old rounds. c0112 then backfills the done items and turns full coverage into a gate.
- **Lesson sprawl** (too many, overlapping lessons). The harvest step prefers adding a source to an existing lesson. Source counts make the weak ones visible, and JC1 rejects restated findings.
- **A bad lesson file** never breaks `ready` or the listing (they skip it with a warning). `--check` and AC8 catch it, and c0112 puts `--check` in the gate.
- **Prompt size** grows by one line per build lesson (c0111 Scalability).
- **Lessons applied in this prep** (from the R0039 checklist, before the mechanism exists):
  - "Run the promoted specs against the new mechanism" moved enforcement out of `done` and `status … prepared`, which would have turned three promoted specs red.
  - "Pin the call site's inputs": AC5 pins `renderPrompt`'s `when = "build"` and, since design review 1 (F2), its `sources` (a harvested fixture with exact counts and order). AC4 pins how `cmd.lessons` passes words and options.
  - "Read your own documents for stale text" was done before round 1.
- Rollback: revert the PR. The lesson files are inert Markdown.
