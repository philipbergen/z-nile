## Risks & rollback
- Size: about 5,800 changed lines (c0114 Size) plus 681 pure renames, one PR (the user's choice). The moves are their own commit, all `R100`, and the edits follow it (c0114 JC1).
- The execution window: while this raft runs, origin keeps counting in `tracker/next`. The branch never touches that file, so no merge of main conflicts on it, the PR's own after `done` included; its engine reserves there while origin has no registry. The first publish after the landing (Phase 6's `./zn spend R0043 --phase deliver`) moves the counter to `z-nile/next` and writes the tombstone, in its own lease push (c0114 §5, §11, AC13).
- Old trees: sessions in worktrees from before c0114 (R0034's, open preps) keep their stop hook, because it calls `scripts/check.sh`, which both sides of the move have; old engines refuse to number against the tombstone once the first publish after the landing has written it, and number on the live old counter until then (E5).
- Lessons that shaped the design: architecture/guards-trust-only-origin (publish roots from origin's registry), architecture/guard-no-is-explicit (the publisher's one `unguarded` answer, design review 001 F1), architecture/one-reader-per-format and parsers-refuse-ambiguity (`projects.luau`), tracker/item-history-spans-moves-and-compaction (the trail across roots, no `--follow`), tracker/main-checkout-tools-span-the-move (the stop hook, F2), ticket-prep/new-rules-migrate-existing-work (forwarders, the in-flight list), ticket-prep/design-the-execution-window (the counter while this raft runs, design review 002 F1), testing/no-vacuous-pass (list mode proven before live check.sh files are listed, F6), ticket-prep/spec-design-correspondence (F3, F9) and prove-specs-pass-on-a-prototype (every spec and mutant run).
- Open branches: an old branch merging after this lands sees `CONFLICT (file location)`; the tracker skill says how to resolve it. Once origin has moved the counter, the old file is a tombstone, so a stale engine refuses to allocate ids instead of colliding (E5).
- Rollback: reverting the PR alone is not enough, because the counter move is its own commit on main, outside the PR. A rollback PR must:
  1. revert this PR's squash commit;
  2. write `tracker/next` from `origin/main`'s `z-nile/next` as read just before the rollback merges (redo the copy if main moves while the PR is open; never use the pre-move file, which would hand out reserved numbers again), and delete `z-nile/next`;
  3. move every item created under `z-nile/.tracker/` since the landing back under `tracker/`, keeping its id.

  The restored old engine then numbers from `tracker/next` again. Design review 004 F2.
