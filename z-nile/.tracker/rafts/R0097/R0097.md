# R0097: Real repository refuses fixture commits

## Theme
Two chores that harden the real repository's git against fixture identities and inherited environment: **c0189** (Real repository refuses fixture identity commits, size 470) and **c0123** (Fence trusts only its own ref guard hooks, size 1,200). Total size 1,670 changed lines (470 + 1,200). c0123 `depends_on` c0189 (and c0194), so it is a later layer in c0189's raft. Before this stacking, each had a raft of its own: c0189 was unfolded from R0072 at d0298's rafting (2026-11-12) because folding it there changed R0072's record and the dispatcher allows one review round, and c0123 was unfolded from R0077 for the same kind of reason (it held c0160 behind other rafts). c0123's raft (now retired) waited for this one, so stacking removes that wait.

User decision (2026-11-15), asked whether to stack c0123 on c0189 in one raft at 1,670 lines: "Yes, one raft (Recommended)".

- **c0189** adds a `reference-transaction` hook to the real repository's common hooks folder (`z-nile/lib/repo-hooks/reference-transaction`, POSIX sh). The hook refuses any ref update to a commit authored or committed under `@example.invalid`, so a prototype branch cannot trip every running gate. `./zn hooks` installs it (`z-nile/engine/hooks.luau`, `cmd.hooks` in `engine/main.luau`, `replace-file.pl`'s `--mode=`, `sh.writeReplacing`'s mode), `./zn hooks --check` becomes a static stage of `z-nile/check.sh`, and the prototype rule and the retry-once rule are restated in the skills and `AGENTS.md`.
- **c0123**: `pickman_fence` keeps an inherited `PICKMAN_FENCE_HOOKS` whenever it holds an executable `reference-transaction`, so a caller can switch the ref and push guard off. c0123 pins the guard's own hooks by digest (`z-nile/lib/fence.sh`), adds an allow-listed environment (`z-nile/lib/cleanenv.sh`, `.list`, `.luau`) that every launcher applies, makes every entry script and hook privileged (`#!/bin/bash -p`, `#!/bin/sh -p`), and edits about twenty promoted and tooling specs it overrides.

**Shared surface** (common Touched paths of the two designs): `z-nile/engine/main.luau`, `z-nile/check.sh`, `z-nile/setup.sh`, `z-nile/lib/repo-hooks` (c0189 creates it; c0123 edits the hook's first line only), `z-nile/tests/tooling/repo-fence.spec.luau`, `z-nile/tests/acceptance/c0055/setup-run.spec.luau`, `z-nile/skills/zz-test/SKILL.md`, `z-nile/skills/zz-arch/SKILL.md` and `SETUP.md`.

## Risks & rollback
- **One merge of two layers.** The raft is one branch and one pull request, one commit per member (c0189, then c0123); it merges whole or not at all, so a defect in c0123 holds back the hook too.
- **No `approval.md`.** Neither c0189 nor c0123 has one in its folder (checked 2026-11-15). The design reviews and the user decisions above are the record; c0189's G1, G3 and G5 are still pending the user.
- **The hook runs on every git in the real repository.** A wrong hook blocks every session's commits, branch moves and fetches. Its refusal is a single explicit "no" (it refuses when it cannot read the commits), and `./zn hooks` never overwrites a hook it does not recognise. The gate's new static stage goes red in every checkout whose hook is missing or stale until `./zn hooks` runs. The PR text and the report say so (c0189 Implementation step 9).
- **A stale installed hook after c0123's layer.** The first line of `reference-transaction` changes from `#!/bin/sh` to `#!/bin/sh -p`, so every installed copy differs and `./zn hooks --check` stays red until a person runs `./zn hooks` once. The PR text says so (c0123.md, the paragraph on c0189's hook).
- **c0123 is large and wide** (about 1,200 lines over about 70 files: it rewrites the prologue of every entry script and edits about twenty specs). A launcher that misses the allow-list breaks every gate, so the one `--full` at the merge runs in a clone (zz-rules Merging), with c0194's code merged under it. Together the raft is about 1,670 lines.
- **The installed hook is outside the PR** (`<git common dir>/hooks/reference-transaction`). A revert of the PR leaves it installed, and a person removes that one file. c0189's design states no rollback of its own, so this is this raft's reading.
- Rollback: revert the PR (the hook, `hooks.luau`, `cmd.hooks`, `replace-file.pl --mode=`, the gate stage, the restated rules, and c0123's cleanenv files, digest pin, `-p` prologues and spec edits), then remove the installed hook by hand. A person reruns `./zn hooks` if only c0123's layer is reverted by hand, to reinstall the `#!/bin/sh` copy.
