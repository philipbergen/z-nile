## Risks & rollback
- **The hook runs on every git in the real repository.** A wrong hook blocks every session's commits, branch moves and fetches. Its refusal is a single explicit "no" (it refuses when it cannot read the commits), and `./zn hooks` never overwrites a hook it does not recognise. The gate's new static stage goes red in every checkout whose hook is missing or stale until `./zn hooks` runs. The PR text and the report say so (c0189 Implementation step 9).
- The installed copy is outside the PR (`<git common dir>/hooks/reference-transaction`). A revert of the PR leaves it installed, and a person removes that one file. c0189's design states no rollback of its own, so this is this raft's reading.
- Rollback: revert the PR (the hook, `hooks.luau`, `cmd.hooks`, `replace-file.pl --mode=`, the gate stage and the restated rules), then remove the installed hook by hand.
