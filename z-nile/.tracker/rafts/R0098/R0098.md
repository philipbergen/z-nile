# R0098: Fence trusts own ref guard hooks

## Theme
One chore, **c0123** (Fence trusts only its own ref guard hooks, size 1,200), rafted alone at d0298's rafting (2026-11-12). `raft-plan` folded it into R0077 beside c0160. The coherence review (R0077 design-review-001 F2) found that the two share no wait and that grouping held c0160 behind R0078, R0070 and c0189's raft, so c0123 was unfolded and given a raft of its own.
`pickman_fence` keeps an inherited `PICKMAN_FENCE_HOOKS` whenever it holds an executable `reference-transaction`, so a caller can switch the ref and push guard off. c0123 pins the guard's own hooks by digest (`z-nile/lib/fence.sh`), adds an allow-listed environment (`z-nile/lib/cleanenv.sh`, `.list`, `.luau`) that every launcher applies, makes every entry script and hook privileged (`#!/bin/bash -p`, `#!/bin/sh -p`), and edits about twenty promoted and tooling specs it overrides.
User decisions its design quotes: "All in c0123" (scope, 2026-11-01), "Exclude .cache/.tmp" (2026-11-01) and "Accept" (2026-11-01): every fenced check gets the fixed `PATH` directories and git's global config pinned.

## Risks & rollback
- **c0123 is large and wide** (about 1,200 lines over about 70 files: it rewrites the prologue of every entry script and edits about twenty specs). A launcher that misses the allow-list breaks every gate, so the one `--full` at the merge runs in a clone (zz-rules Merging), with c0194's and c0189's code merged under it.
- **A stale installed hook turns the gate red everywhere.** After this raft lands, the first line of `reference-transaction` differs from every installed copy, and c0189's static stage (`./zn hooks --check`) reports it until a person runs `./zn hooks` once (c0123.md, the paragraph on c0189's hook). The PR text says so.
- A rename in c0189's `wiring.spec` or hook path before this raft runs turns c0123's two override edits into misses. The executor rereads both files on `main`.
- Rollback: revert the PR. That also reverts the two edits to c0189's hook and `wiring.spec`, and a person reruns `./zn hooks` to reinstall the `#!/bin/sh` copy.
