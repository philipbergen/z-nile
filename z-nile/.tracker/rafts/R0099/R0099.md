## Theme
Five chores that build one thing, a ticket's provenance, as the user split it: "Split it and prototype first, like c0265", then "one raft, delivered a layer at a time in depends_on order" (c0263, 2026-11-08, quoted by every member). The fix keeps c0284's AC3 and c0280's "one `git cat-file --batch`" true as written: `who.fronts` streams one process (`process.create`, the keys written from a `task.spawn`, stdin closed, stdout read to the end); the probe returns 20,000 keys in a fraction of a second, and the prototype commit `who.fronts streams one git cat-file --batch` makes `c0057/open.spec` pass again (7 cases). No member's design text changes (Whole-raft design, Executors never edit a member's design). The same limit applies to any other `process.exec` with a large stdin (`who.sideTrailers`' `git log --no-walk --stdin` takes one key per merge, 8 today): the executor streams it the same way if it ever passes about 3,000 keys.

## Risks & rollback
- **A member's spec red on a main that moved** (the cause of R0090's block and of c0282's re-prep, #342). Mitigation: this record is from a prototype merged with `origin/main` of 2026-11-14 (E3). The executor's first step is `./zn check <id>` for the layer it starts, on a branch that has merged `origin/main`; a red spec that is the main's own goes to the lead (zz-execute), never edited.
- **The history read deadlocks `process.exec`** (E1b). The prototypes of c0280 and c0284 send every document revision's key to one `git cat-file --batch` through `process.exec`; an executor who copies them as they stand gets a board build that never returns on the real tree (the gate's `c0057/open.spec` hangs). The read is streamed, not chunked, so the "one `git cat-file --batch`" of c0280 and c0284 stays true. RC3 to RC5 run the real tree under `./zn run --time 120`, so a stall fails with exit 124 instead of hanging, and RC5 counts the `cat-file --batch` processes of a real board build (exactly one).
- **R0096 not landed.** c0282's AC7 runs `c0116/claims.spec`, red on plain main. If R0096 is not in `done/` by the time the last layer's `done` runs, the raft is stuck at AC7, not wrong: wait, or stop and report (Order & dependencies).
- **Two names for one list** (E1). If an executor writes a second list instead of the alias, RC2 fails.
- **Docs paragraph collisions.** Every layer extends the same zz-rules paragraph and README line. The docs specs pin fragments, so they pass on a paragraph that contradicts itself (lesson merged-text-read-against-captures): the executor reads the whole Provenance paragraph after each layer.
- **The 200-local cap has one register left on this raft's stack** (E2). R0100 cannot land beside it without moving names into tables, and the same holds for this raft if R0100 lands first.
- **The heartbeat raft (R0100) lands first or second.** Interfaces to the heartbeat raft names the hunks; the second to land merges, recounts `main.luau`'s locals and re-runs its own members' checks. The rows contract (a refused give-back writes no row) is the one thing the heartbeat takeover must keep.
- **Rollback.** Each layer is one commit of one PR; a layer that fails its check is fixed in place. The raft is released with `./zn stop R0099` before it starts, or its PR is closed; no state outside `provenance.md` files is written (a rolled-back `done` removes its `delivered` rows).
- **Nothing migrates.** No `provenance.md` exists until a later layer writes one; `audit` accepts absence.
