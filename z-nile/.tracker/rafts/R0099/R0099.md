# R0099: Provenance

## Theme
Five chores that build one thing, a ticket's provenance, as the user split it: "Split it and prototype first, like c0265", then "one raft, delivered a layer at a time in depends_on order" (c0263, 2026-11-08, quoted by every member). The members are Ticket provenance (c0263, the record: an append-only `provenance.md` per ticket and `./zn provenance record`), Provenance who from git (c0280, `./zn who <id>`), Provenance lifecycle rows (c0282, the lifecycle commands write `unblocked`, `rafted` and `delivered` rows), Design approval gate (c0283, `./zn approve` refused in an agent session and an `approved` row) and Board shows provenance (c0284, the board's item view shows `who`'s entries). The total size is about 2,380 changed lines, over z-raft's cap of about 1,500; the grouping is the user's, by argument, and grouping by argument overrides the cap. The members are layers of one design, so each is delivered as its own layer of one PR (zz-rules, the stack rules), the next building on the previous.

Shared surface (their common Touched paths): `z-nile/engine/provenance.luau` (all four upper layers add to c0263's module), `z-nile/engine/main.luau` (all five), `z-nile/engine/trail.luau` (c0263, c0280, c0284), `z-nile/engine/who.luau` (c0280, c0284), `z-nile/engine/dispatcher.luau` and `z-nile/engine/publish.luau` (c0282; c0263), `z-nile/skills/zz-rules/SKILL.md` and `z-nile/README.md` (all five, one Provenance section and one Provenance line that each layer extends).

## Risks & rollback
- **A member's spec red on a main that moved** (the cause of R0090's block and of c0282's re-prep, #342). Mitigation: this record is from a prototype merged with `origin/main` of 2026-11-14 (E3). The executor's first step is `./zn check <id>` for the layer it starts, on a branch that has merged `origin/main`; a red spec that is the main's own goes to the lead (zz-execute), never edited.
- **The history read outgrows one process** (E1b). `who.fronts` must read in chunks; an executor who copies the prototype of c0280 or c0284 as it stands gets a board build that never returns on the real tree (the gate's `c0057/open.spec` hangs). RC3 and RC4 run `./zn who` and `./zn board` on the real tree, which fail (by the gate's bounded time) when the read is not chunked.
- **R0096 not landed.** c0282's AC7 runs `c0116/claims.spec`, red on plain main. If R0096 is not in `done/` by the time the last layer's `done` runs, the raft is stuck at AC7, not wrong: wait, or stop and report (Order & dependencies).
- **Two names for one list** (E1). If an executor writes a second list instead of the alias, RC2 fails.
- **Docs paragraph collisions.** Every layer extends the same zz-rules paragraph and README line. The docs specs pin fragments, so they pass on a paragraph that contradicts itself (lesson merged-text-read-against-captures): the executor reads the whole Provenance paragraph after each layer.
- **The heartbeat raft (R0100) lands first or second.** Interfaces to the heartbeat raft names the hunks; the second to land merges, recounts `main.luau`'s locals and re-runs its own members' checks. The rows contract (a refused give-back writes no row) is the one thing the heartbeat takeover must keep.
- **Rollback.** Each layer is one commit of one PR; a layer that fails its check is fixed in place. The raft is released with `./zn stop R0099` before it starts, or its PR is closed; no state outside `provenance.md` files is written (a rolled-back `done` removes its `delivered` rows).
- **Nothing migrates.** No `provenance.md` exists until a later layer writes one; `audit` accepts absence.
