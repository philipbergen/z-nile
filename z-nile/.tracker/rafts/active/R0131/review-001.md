### F1 [low] The "a comment is not a use" scan misses the flag inside a Luau string that contains ` -- `
Where: z-nile/tests/tooling/own-acceptance-callers.spec.luau:13-23 (`uses`); the same rule is AC2's `count` in the sequestered `acceptance/cli.spec.luau:123-134`
Evidence: the Luau branch strips `%s%-%-%s.*$` from every line, whether or not the ` -- ` sits inside a string literal. A bounded probe of the function copied verbatim (`./zn run --time 30 -- lune run <scratch>/uses.luau`): `{ "run", "z-nile/affected", "--", "--own-acceptance" }` counts 1, but `sh.run("bash", { "-c", "lune run z-nile/affected -- --project z-nile --own-acceptance" })` counts 0, because ` -- --project z-nile --own-acceptance" })` is stripped as a trailing comment. The shell form of a selector call always has ` -- ` before its flags, so a Luau gate, hook or forwarder (`scripts/affected.luau`, `z-nile/specs.luau`, anything under `z-nile/lib`) that ran the selector through a shell string with the flag would pass the scan. Today no such call exists (no `bash -c`/`sh -c` selector call in the scanned Luau files), so nothing is wrong now.
Critique: the spec is the permanent `--affected` guard for R10 ("no gate, hook or forwarder passes the flag"), and it is blind to the most natural non-array spelling of the call. The tempting fix is to drop comment stripping in Luau files; that reintroduces V4's false positive (a comment naming the flag, as `affected.luau`'s own header and the new zz-test text do).
Consequences: stripping a trailing comment only outside string literals needs a quote-aware rule (a `--` preceded by an odd number of unescaped `"` or `'` on the line is inside a string); long strings `[[...]]` spanning lines stay out of reach of a line scan, which is acceptable for a guard. The sequestered AC2 `count` keeps the hole and must not be edited in execution; the tooling spec is the one the executor owns.
Recommendation: in the tooling spec only, treat a Luau ` -- ` as a comment start only when the text before it has an even number of `"` and of `'` characters (same for ` # ` in shell lines), and add a second case that runs `uses` on inline texts: the array argv counts 1, `"lune run z-nile/affected -- --own-acceptance"` inside a string counts 1, `x() -- names --own-acceptance` counts 0, `# --own-acceptance` counts 0. Lift `uses` to module scope so both cases share it. Record the narrower AC2 rule as a known edge in the Verification log; no change to the sequestered spec.
