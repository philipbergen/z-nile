# R0021: Check isolation

## Theme
Three chores, made urgent by two incidents. On 2026-09-30, two test suites running at once in one worktree deleted each other's fixtures. Fixture git commands then ran against the real repository: they removed `origin` and all branch tracking for every session, committed an agent's work onto a fixture branch, and left fixture branches and a fixture worktree behind. On 2026-10-01 it happened again, from c0058's own spec run against the runner without the guards. The user's requirement, quoted: "There must not be a way that any check ever breaks the main git repo, that needs to be clear in review and skill definitions." The user also asked for the two follow-ups to be in this raft: "file a chore on r210 to update r200 and r190, file the follow up chore in the raft too".
- **c0058**: the guards themselves (jail, environment guards, lock, tripwire, gate spec) and the rule in the documents.
- **c0060**: the twelve older fixture specs run git and `tracker.sh` only through a fixture helper that refuses anything but a fixture repository, so they are safe even without the guards.
- **c0059**: R0020 (c0053), which lands first (the user's decision, R0020.md, confirmed 2026-10-01), is adapted: its specs drop their own fence, and its publisher never publishes from a repository the guards protect (a check must not push tracker state to `origin/main`). R0019's one conflict, a non-fixture identity in its sequestered spec, was fixed in this prep. Product decisions in `tracker/game-design.md` are not touched: nothing under `src/` changes.

## Whole-raft design
No `src/` change and no `tracker/architecture.md` change.

```
person / hook / check.sh / tracker.sh done
   |                                   check.sh: ac.sh -> scripts/lib/fence.sh pickman_fence (env guards)
   v
tests/run -- (no valid marker) --> tests/lib/fence.luau: refuse a fixture identity; lock .cache/tests-run.lock (every guarded pid)
                                   snapshot (config, branch, HEAD, .cache worktrees, fixture refs)
                                   [macOS] sandbox-exec jail: no write to the checkout, its main checkout or .git, except .cache
                                   bash: fence.sh pickman_fence <checkout> specs + marker -> exec lune run tests/run -- args
                                   snapshot, unlock, REPOSITORY CHANGED -> fail
tests/run -- (valid marker: worker, nested run) --> record pid, run specs
env guards: ceiling at .cache + sentinel .cache/.git; GIT_DIR & co. unset; gc off
            unjailed only: core.hooksPath -> scripts/lib/git-hooks (reference-transaction: no ref update in the
            real repo but a check's fetch; pre-push: no push into it), each chaining to the repo's own hook
            specs: no GitHub credentials, no ssh, protocol.allow=never (local and file:// only)
tests/tooling/repo-fence.spec.luau: proves the guards are on; no file names a bypass (ALLOWED: per file, per name,
            with a reason); fixtures commit as @example.invalid
tests/lib/fixture.luau (c0060): runs git and tracker.sh only in a fixture under this run's .cache, never pointed
            elsewhere; the twelve older fixture specs use it
c0053 (c0059): its specs lose their own fence; tracker commands publish nothing from a guarded repo
            (publishing() in main.luau asks pickman_guarded in fence.sh)
```
The rule is stated in AGENTS.md as non-negotiable, and in the testing, review (design and code mode, **high**), execute-raft (stop condition) and ticket-prep skills.

Interfaces that stay fixed: the runner's output and summary line, its exit code, and `AC_LIST` refused first. New interfaces: the `waiting for another test run (pid N) …` line, the `REPOSITORY CHANGED` report, and `PICKMAN_TEST_LOCK_WAIT`.

## Risks & rollback
- **A false tripwire** from concurrent work elsewhere: the snapshot leaves out what other sessions change legitimately (`branch.*` config, other worktrees' HEADs, worktrees under `.worktree/`, gh's `gh-resolved`). A commit or pull in the same checkout during a run descends from the old HEAD, so it doesn't trip it either. A local fixture identity in the repository makes the run refuse to start: it shows where the value comes from and says to stop and report.
- **The jail blocks a legitimate write**: no spec writes outside `.cache` today (the full gate passes jailed). A future spec that needs to is wrong by the rule; `check.sh` files, which do write the checkout, are not jailed.
- **`sandbox-exec` disappears** in a future macOS: it is deprecated but shipped, and verified on 26.6. Without it, a run refuses to start (fails closed, saying `sandbox-exec is missing`) unless something else provably protects the repository.
- **Runs inside another sandbox** (for example, a sandboxed agent shell) can't be jailed again, because macOS doesn't nest sandboxes. They refuse to start unless that sandbox already denies writes to the repository, or the run is proven, by probes, to be a fixture of a jailed outer run (an ancestor in `GIT_CEILING_DIRECTORIES` proves nothing). Agents with a sandboxed shell must run specs with that sandbox off.
- **A stale lock** after a killed run: taken over once every recorded process is gone. A lock or takeover that is never claimed is taken over after 2 s.
- **A long wait**, if a run in the same checkout hangs: bounded by `PICKMAN_TEST_LOCK_WAIT` (default 240 s, under the Stop hook's 300 s), with a message naming the pids.
- **A mutant that makes nested runs lock** deadlocks every run until the wait limit. It is caught, but slowly (c0058 Unknowns, L-nested).
- **R0021 waits for R0020's execution** (its `start` refuses until c0053 is done). Until then, the guards don't exist; agents keep to the interim rules (one suite per checkout, unguarded runs only in a `$TMPDIR` clone).
- **c0053's specs under the guards** passed on the combined prototype (c0058 E30), with R0020's prototype code. Phase 1 re-runs them on the real landed code; a failure there is a stop, not a weakened guard.
- **The twelve retrofitted specs** keep every assertion; AC3 (guarded) and AC4 (unguarded, in a `$TMPDIR` clone) both run them.
- **Rollback**: revert the PR. The repository is then unprotected again, so prefer fixing forward.
