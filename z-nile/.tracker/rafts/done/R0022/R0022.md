# R0022: Board opens by default

## Theme
Single-issue raft. `scripts/tracker.sh board` is almost always run to look at the board, so it opens the page in the default browser unless `-O` is given (the user's request, 2026-10-01). Developer tooling, so a chore. Because opening becomes the default, the spec runner gains a permanent guard so that no spec can start a real browser (design review 001 F1; the user chose `tests/run` as the place, 2026-10-01). No decision in `tracker/game-design.md` is involved (nothing under `src/` changes).

## Whole-raft design
One command changes: `cmd.board` in `scripts/tracker/main.luau` runs its existing opener unless `-O` (a new boolean flag in `flags()`); `--open` stays accepted as the default; `--open` with `-O` is refused before writing. Callers that must never start a browser pass `-O`: `.github/workflows/board.yml`, the promoted `c0042/cli` spec and one case of `tests/tooling/board.spec.luau`. The tracker skill's `board` row documents it. `tests/run.luau`, when it is the outermost runner (no `PICKMAN_OPEN_GUARD`), puts recording `open`/`xdg-open` stubs first on `PATH`, re-runs itself with that environment, and fails the run if any opener was called; the testing skill states the rule. Data flow of `board` is unchanged (`store`/`board.collect` → `board.render` → file → opener). No `tracker/architecture.md` change. Details and the exact texts are in c0057.

## Order & dependencies
c0057 only, no dependencies. It overlaps in-flight R0020 (c0053, publish state to main), which also edits `scripts/tracker/main.luau` and `.claude/skills/tracker/SKILL.md`. Most of that is in other functions and rows (`new`, `start`, `status`, `sync`), but **both rafts edit the same line of `flags()`**: the boolean-flag list (c0053's prototype splits it over several lines and adds `--fetch`; this raft adds `-O`), so whichever lands second gets a textual conflict there. Resolve it by keeping every flag from both sides (`--single`, `--stdout`, `--include-active`, `--open`, `--fetch`, `-O`) in c0053's multi-line form, rerun `scripts/check.sh --full`, and note it in c0057's Verification log (dropping `-O` is caught by `open.spec.luau`, mutant M3). **R0020's own sequestered spec** `tracker/issues/c0053/acceptance/commands.spec.luau` ran `tracker.sh board --out …` without `-O` (its read-only-commands loop): after this raft that call would open a browser and the guard would fail R0020's run, so whichever raft landed second would go red (design review 003 F1). With the user's approval (2026-10-01) this prep appends a trailing `-O` to that one call, harmless before and after either raft (today a trailing `-O` is swallowed as a valued flag). No other in-flight prep runs `board`. R0021 (check isolation, c0058, in prep) changes how the gate runs specs and is likely to edit `tests/run.luau` too: whichever lands second merges the guard block with its changes and reruns `guard.spec.luau`. The other in-flight preps carry their own unlanded ids R0021 and c0055 to c0630; this raft was numbered R0022 to stay clear of R0021.

## Experiments phase
All run in prep (see c0057): E1 a prototype passes both specs and the full gate (no measurable slowdown); E2 the runner guard catches a spec that runs `board` without `-O` (it found the one tooling case); E3 both overridden promoted specs pass on today's `main` and after the change; E4 11 `board` mutants and E7 10 guard mutants each killed by an assertion (2 more reasoned); E6 Lune's `process.env` assignments don't reach children, hence the guard's re-run. Nothing is left for the executor's Phase 1.

- Done == `scripts/tracker.sh done R0022` succeeds.

## Risks & rollback
- **A spec starts a real browser** on a developer's Mac on every gate run, if it runs `board` without `-O` or stubs. Mitigation: the runner guard fails such a run on every gate, hook and `tracker.sh check` run, and names the call.
- **The guard itself misbehaves** (a leftover temp directory, a changed exit code, an extra process per run): pinned by `guard.spec.luau` (clean runs keep their summary and exit code, failing specs still fail, the directory is removed); its cost is one extra `lune` start per outermost run.
- **Two promoted specs change** in the prep commit (c0042/cli gets a trailing `-O`; c0048/board-workflow accepts the step with or without ` -O`), both green before and after (E3), named on c0057's `Overrides:` line.
- **Scripts that relied on `board` not opening** now open a browser. CI (`board.yml`) is fixed here and specs go through the guarded runner. The done check files of c0048 (AC5), R0016 (RC2) and R0006 (RC1) also run `board` without `-O`, outside the runner: rerunning one of them by hand opens a tab (one per run). They are sequestered history and stay as they are (design review 003 F2).
- Rollback: revert the PR; nothing persists outside the repo.
