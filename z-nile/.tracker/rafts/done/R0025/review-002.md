### F1 [medium] Membership agreement is checked only in `ready`. The carried `status R prepared` and the legacy `start` still accept a raft whose `issues:` and `raft:` disagree, and `stop`'s legacy give-back releases a different set from the one it prints (repeat of review-001 F1, other paths)
Where: scripts/tracker/main.luau:2618-2643 (the only agreement check); main.luau:888 (`setStatus` builds its targets from `issues:`); the legacy `start` claim (main.luau, after line 1800, which claims `store.members`); main.luau:2764 (stop's legacy branch: `setStatus(raft.id, "prepared")`) vs main.luau:2797 (`print(stopped … ids)`, where ids is now the union)
Evidence:
1. *Prep.* Ticket-prep adds c3 to R by setting `raft: R` and forgets the `issues:` line. ticket-prep line 16 says only "an issue added during prep is claimed first", and no skill mentions that the two fields must agree. `status R prepared` (carried) stamps only the `issues:` list. The prep PR lands, and the drift shows up only at `ready`, after merge, which refuses. The only fix is a second prep PR.
2. *Legacy start.* `start R` on a prepared backlog raft, from a worktree that was never readied, takes the legacy path. That path is still live (c0005's worktree spec pins it) and has no agreement check. It claims `store.members(R)`: R, c1, c2 and the unlisted c3, all stamped active. `stop R` then takes the `raft.state == "backlog" and st == "active"` branch. `setStatus` releases R, c1 and c2 (the `issues:` list), yet the command prints `stopped R (c1, c2, c3)`. c3 stays stamped active. Critique: Round 1 found a hole in raft membership, and the fix plugged it at one command.
