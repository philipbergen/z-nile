### F1 [high] Line charts also draw bars for the first series
Where: `scripts/tracker/chart.luau:355-370` (the branch taken for every kind that is not `mirror`, `stacked` or `hbars`), then the line path at `374-401`.
Evidence: `kind == "lines"` is not excluded from the bar branch. On the input from chart.spec's "a nil value breaks a line" (`Defect %` values `{ 10, nil, 30, 40 }`), `chart.svg` returns 3 `<rect class="mark ser-defect">` bars plus the path and 3 circles. A two-series ratio chart draws bars for the first series only (`10` and `20` become marks; the chore value `5` does not). The spec counts circles and `M` commands, not rects, so it passes. On today's board the month/year ratio SVGs happen to contain no marks, because every defect ratio in range is `0` or nil and the bar branch requires `v ~= 0`. The first non-zero defect bucket will paint bars under the defect line and none under the chore line.
Critique: The design's `lines` kind is a 2 px path with one circle per non-nil value, not a bar chart. Patching the spec to allow the rects would lock the wrong picture in. Deleting the bar branch without moving the tooltip drops the only `<title>` the defect series has (circles are `<circle class="point ser-…" …></circle>` with no title).
Consequences: Zero stays a point (only nil breaks the path) and must not grow a bar. Point tooltips have to use the same one-decimal `tip` text as rects, including `0`. Nested `<title>` inside the circle does not change the spec's `<circle` count. The second series, which today has neither a bar nor a tooltip, gains a tooltip only if the title is drawn per series, not only for `series[1]`.
Recommendation: Draw marks in that branch only for `kind == "bars"`. For `lines`, put the existing tooltip on each circle. Do not edit the sequestered spec; the circle count and the "no paint attributes" case stay valid as they are.

### F2 [high] `.chart-fig { display: inline-block }` overrides `hidden`, so all 67 charts stay on screen
Where: `scripts/tracker/board.html:58`. The attribute is set in `scripts/tracker/board.luau:293-311` and toggled in `board.html:216`.
Evidence: The rendered page has 67 figures, 59 of them with the `hidden` attribute and 8 without, which is the month/all set AC10 checks. There is no author `[hidden]` rule. The HTML rendering spec's UA rule is `[hidden]:not([hidden=until-found i]):not(embed) { display: none; }` with no `!important`, so an author `display` wins. `.chart-fig { display: inline-block }` therefore shows every figure, including those marked `hidden`. `showStats` only adds and removes the attribute, which does not change the used `display`. Opening Stats shows every view and type at once, and the Month/Quarter/Year and type buttons do not hide anything. `#stats` and `#stats-tables` do not set `display`, so the section and the table panel do hide.
Critique: AC10's "eight visible" check looks at the attribute string, so a wrong screen still passes. Moving the hide into the click handler alone leaves the initial HTML showing all 67 charts, because `showStats` is not called on load.
Consequences: The attribute remains the only state. A class toggle beside it would drift from the attribute the spec reads. The eight figures that are not hidden must stay `inline-block`.
Recommendation: Add `.chart-fig[hidden] { display: none; }`. Specificity (0, 2, 0) beats `.chart-fig`. Leave the attribute, the initial markup and the click handler as they are. Do not edit the sequestered spec.

### F3 [high] Tables print binary minute sums, and a nil defect ratio as a bare %
Where: `scripts/tracker/board.luau:336` (bucket tables) and `:352-358` (periods). Sums are the raw doubles from `stats.row` (`stats.luau:252-257`).
Evidence: `board.collect("tracker")` on this tree, then the Periods table: this week is `58.2` minutes and defect cell `%` (defect count ratio is nil: 0 features and 0 defects closed). Critique: These are the cells JC1 asks a first-time viewer to read. Chart tooltips already round to one decimal, so the table and the tooltip disagree. Consequences: Rounding the stored minute totals to one decimal (half away from zero, the `roundTo` already in `stats.luau`) makes the table, the tooltip and the ratio share one tenth. The row spec's minutes are 60, 30, 10, 20, 5 and stay exact; its ratios stay 66.7, 25.0, 0.0 and 33.3. A ratio of `0` must stay `0%`. Nil must not become `%` or a new word. Bucket charts read the same totals, so their scale moves only by that one-decimal correction, not by a second rounding.
Recommendation: In `stats.row`, round each minutes total to one decimal before `percent()`. In the tables, print minutes with that one decimal, trailing `.0` dropped. Append `%` only when the ratio is a number; a nil cell is empty. Do not edit the sequestered spec.
