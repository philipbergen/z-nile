Where: `z-nile/.tracker/issues/done/c0115/check.sh:34-35`; zz-review Code mode item 2; zz-test "Sequestered"
Evidence: `git diff --find-renames=100% --name-status origin/main...HEAD -- '*/.tracker/**/check.sh' …` lists `M z-nile/.tracker/issues/done/c0115/check.sh` (the only non-R100 entry; no mode change in `git diff --summary`). The precedent for a non-move override of a finished file is the prep PR (R0031's prep da511fa6 edited `done/c0035/check.sh`; R0033's prep f5ee13a8 likewise), where the design review sees the sequestered text. Removing the clause on main would have kept main green (main's `layout.spec` passes without it), so nothing forced it into execution.

Authorizing it in place keeps one PR but leaves c0115's AC14 red on this branch until the squash lands (nothing in the gate or `done R0050` runs c0115's `check.sh`, so it blocks nothing), and needs a recorded decision so the next reviewer can verify it.
Recommendation: escalate to the user (zz-execute stop conditions), with the options: (a) the user authorizes this one edit as c0116's designed override, recorded in c0116.md's Verification log as a dated user line (as c0115 recorded "the user's authorized sequestered edit (2026-10-25)" in aa6d0fdb), noting c0115 AC14's transient red; or (b) the same one-line change lands on main first through a reviewed tracker PR (`tracker: c0116 override of c0115 AC3`, as R0031's and R0033's preps did), and this branch merges main so the listing shows only R100. ### F2 [medium] `recombine` with a repeated id retires the other raft while it still has a member; audit stays silent
Where: `z-nile/engine/main.luau` `cmd.recombine` (`moving` built from `pos[3..]`; `local retire = #moving == #otherIds`)

Critique: the count stands in for "every member of the other raft moves". The tempting fix is to dedupe `moving`; that fixes this input but leaves the retirement decided by a count.
Consequences: deciding retirement by set (every id in `otherIds` is in `moving`) and refusing a repeated id is local to `recombine`. The silent audit is the larger gap (lesson zz-rules/audit-what-new-refuses): any route that leaves an issue whose `raft:` names a raft no finder sees (a hand edit, a merge, a retire) lands unseen. An audit error for "issue's `raft:` names a raft that is retired or missing" must not fire for done issues whose rafts were compacted away, so it needs scoping to backlog and active issues.
Recommendation: in `recombine`, refuse a repeated id ("<id> is named twice") and compute `retire` as "no member of the other raft is left", i.e. from the same `left` list the partial branch builds; add an `audit` error for a backlog or active issue whose `raft:` names no backlog, active or done raft (retired included as an error target). Cases: `recombine R0010 R0020 c0021 c0021` refused with nothing published, and an audit fixture with an issue naming a retired raft. These are new engine cases in a non-sequestered spec (a tooling spec), not edits to c0116's acceptance specs.
Lesson: zz-rules/audit-what-new-refuses
