A rafting PR waits on its gate while main moves (here a z-ready, a recombine elsewhere, `./zn new raft` in another root's worktree); the window is the PR's whole life, not seconds.
Critique: this is the fifth hole in `judgePr`'s rafting rules, and the first that is about time rather than shape: every rule asks "where was this item at the base?", and the base is the PR's, not main's. zz-arch/merge-gate-checks-what-it-merges prescribes `merge-base(main, head)..head`, which is right for *what the PR carries* and wrong for *what the merge does*. The tempting fix (require the merge base to equal fresh main) never merges in this repo, where main gains a tracker commit every few minutes (spend rows): every rafting PR would be behind. The other tempting fix (re-read `lifeOnBase` at main instead of base) breaks the base..head diff it judges, because main's paths are no longer the PR's base paths.
Consequences: judging what the merge does needs main's tree at judgment time, a merged tree, and a rule for a conflict (refuse: GitHub won't merge it either). Main can still move between the judgment and `gh pr merge` (seconds; `--match-head-commit` pins the head only, GitHub has no base pin): that residual race must be stated, and is caught after the fact if the dispatcher judges the real merge commit against its parent with the same rules (as `vetMain` does for tracker state) and stops (exit 5) when it fails.
Recommendation: question the mechanism (F2 shows the same): judge two changes, both required: (1) `base..head` as today (what the PR carries), and (2) `main..M`, where `M = git merge-tree --write-tree <fresh main> <head>` (refuse when it conflicts, or when it exits nonzero), with every place (`lifeOnBase`, the other-root test, issue life and document) read at fresh `main`, so an item main moved since the base is judged where it is now. Simplest form of (2): for each item (root, kind, id) the PR touches, refuse when `git diff --name-only base main` touches any folder of that id in any root or lifecycle (main changed it since the base: "rebase the rafting PR"), and refuse a new raft id present in any root at `main`. After `gh pr merge`, judge the merge commit against its first parent with the same function and stop with exit 5 when it fails (the race). Cases (dispatch-guards, each exit 4, no merge logged): P1, P5, P2 as above; and one that must still merge: PR #34 cut before main gains an unrelated spend row on another issue.
Lesson: zz-arch/merge-gate-checks-what-it-merges
