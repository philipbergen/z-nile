### F1 [medium] The fake gh answers `pr view <n> --json mergeCommit` with a bare sha whatever the rest of the arguments say, so a dispatcher that drops `-q .mergeCommit.oid` passes every spec and would stop every real unattended merge with exit 5
Where: fakecli.luau's gh (`if [ "$1" = pr ] && [ "$2" = view ] && [ "$5" = mergeCommit ]; then cat "$FAKE_DIR/mergecommit-$3"`); `dispatcher.afterMerge` (`{ "pr", "view", tostring(number), "--json", "mergeCommit", "-q", ".mergeCommit.oid" }`, then `string.match(commit, "^%x+$")`).
Evidence: mutant N5 (the call without `"-q", ".mergeCommit.oid"`): `6 passed, 0 failed` on dispatch-guards; AC10 cannot catch it either, since it goes through the same fake. The real gh without `-q` prints `{"mergeCommit":{"oid":"aa85b94b…"}}` (PR 242, run above), which fails `^%x+$`, so on GitHub every merge would print "its merge commit could not be read from GitHub" and stop the chain. The same holds for a wrong filter (`.mergeCommit.sha` gives `null`, which is no hex): the fake applies no filter, so the specs cannot tell a right filter from a wrong one.
Critique: the fail-closed design is right, but it makes a wrong argument expensive (every real merge stops) while the fake makes it invisible. The tempting fix is to match `-q .mergeCommit.oid` exactly in the fake, which pins the spelling, but the fake still hands back a shape the real gh never prints for any other spelling.
Consequences: if the fake prints the real JSON, the dispatcher must parse it (one more reader of gh output, and `null` must be handled as "not merged / unknown"); every spec that merges through fakecli (dispatch-guards, AC10's control-cli) goes through the new parse, so `./zn check c0117` must be rerun.
Recommendation: drop `-q` and decode the JSON in the dispatcher (`serde.decode("json", …)`; `mergeCommit` null or missing, or an `oid` that isn't 40 hex, is the existing stop), and make the fake print exactly what the real gh prints: `{"mergeCommit":{"oid":"<sha>"}}` after a squash, `{"mergeCommit":null}` otherwise (nosquash, never merged), and fail like the real gh (exit 1) on a `pr view … --json` field list it doesn't know. Cases: #97 keeps its stop with the `null` answer; add one assertion that a `-q`-less, JSON-parsing call is what runs (mutant N5 killed by the parse, and a mutant reading `.sha` killed by the shape). Then `./zn check c0117`.
Lesson: zz-test/stand-ins-answer-only-named-arguments
