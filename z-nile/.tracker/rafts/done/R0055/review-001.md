## Other attacks, found sound (for the record)
- **Report order** stays path order: `outcomes[index]` is keyed by position and read with `for _, o in outcomes`. A Lune experiment stored n = 2…260 entries in 40 random permutations each (10 360 tables) and iterated them in index order every time (scratch `order.luau`). schedule.spec's "reports in path order" case pins it end to end.
- **Every file runs exactly once per listing**: `order` returns a permutation of positions. The comparator is a strict total order: `parse` admits only `[%d%.]+` through `tonumber`, so no NaN, and an all-digit overflow is `inf`, which still orders. Duplicates fall back to tie-by-position.
- **Atomic write**: Lune 0.11.1's `fs.move(tmp, rec, true)` behaves as a rename. A reader looped over the target while a writer ran 4000 temp+move cycles (1.4 s inside a 6 s, 235 396-read window): 0 missing reads and 0 torn reads. The temp name uses `math.random`, which is seeded per process (three runs printed three different values), plus monotonic `os.clock`.
- **Jail and repository safety**: the coordinator runs inside the jail. The profile allows writes under `<home>/.cache`, where both the record and its temp file sit as regular files (no symlink is created). `.cache/` is gitignored (`.gitignore:2`). A failed write is swallowed by `pcall` and costs only the order. No git, no write outside `.cache`, and none of the guards in review item 8 is touched.
- **Racing runs**: two suites in one checkout queue on `.cache/tests-run.lock`, and each home has its own record. Every nested runner in the promoted specs runs either in a fixture copy or on `.cache/…` paths (searched: `for f in $(grep -rl '"tests/run"' z-nile/tests pickman/tests); do grep -nE '"tests/[a-z]' $f …; done`, all hits fixture-relative). So no nested run writes the real record mid-gate, and in any case it would only merge.
- **Corrupted or partial record**: `parse` refuses the whole record on any malformed line, a repeated path or no line at all, and the runner falls back to path order and then replaces it. A torn-but-well-formed last line would only name a path that doesn't exist, which the next full run drops. The atomic write prevents a torn record anyway.
- **CI** (G2): no `actions/cache` in `.github/workflows`, so CI always starts with no record and keeps path order.
