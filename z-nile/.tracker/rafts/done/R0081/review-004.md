### F1 [medium] An untracked nested git repository (or any present path that is neither a file nor a link) is still dropped from every digest, so its content never moves a gate (repeat of review-003 F2, Recommendation part)
Where: `z-nile/lib/workspace.luau:80-84` (`else blobs[path] = nil -- deleted`); refute-003 F2 ("a folder cannot be listed by `ls-files`"); `z-nile/skills/zz-arch/lessons/digests-hash-paths-as-git-stores-them.md` ("treat a path that is neither as unreadable")
Evidence: in the scratch clone, `mkdir z-nile/zz-nested && git -C z-nile/zz-nested init` with a file in it. `git ls-files --others --exclude-standard -z` lists `z-nile/zz-nested/` with its trailing slash. `test -L "<clone>/z-nile/zz-nested/"` exits 1 and `fs.isFile` is false, so the path is dropped. `lune run z-nile/specs -- digest --mode affected --projects z-nile` printed `1de0dc89…f390` in three states: before the folder existed, with `z-nile/zz-nested/a.luau` holding `local   x=1` plus a `b.luau`, and after `rm -rf` of the folder. Meanwhile `stylua --check z-nile` went from exit 0 to a failure printing `Diff in z-nile/zz-nested/a.luau`. selene and luau-lsp take the same folders (`check.sh:195-203`). `gate-check` keys on that digest (round 3 showed record-then-check printing `reused: …`), so an affected gate recorded before the nested folder appeared is reused while its format stage would fail.
Critique: the refute rests on a claim that is false: `ls-files --others` lists a nested repository as `dir/`. The repo's own new lesson says such a path is "unreadable" (reuse off), and the code calls it "deleted". The Design's rule is that every read fails closed. The tempting fix is to recurse into the folder and hash its files.
Consequences: recursion has to choose whose ignore rules apply (the outer repo's or the nested repo's `.gitignore`) and could walk a large clone on every gate. A blanket "neither file nor link → nil" also turns reuse off for a tracked file replaced by a folder (a typechange that `-m` lists), whose files `--others` already lists one by one. Reuse would then be off for no reason.
Recommendation: tell the two sources apart. A path from `ls-files -m` that is now a folder counts as deleted, because its files arrive through `--others`. A path from `--others` that ends in `/` (a nested repository), and any present path that is neither a regular file, a link nor (for `-m`) a folder (a FIFO, a socket), returns `nil, "<path>: a nested repository or special file; reuse off"`. Then `specs run` prints `reuse off: …` and `specs digest` prints nothing, so the gate runs. Pin it in `tests/tooling/reuse-e2e.spec.luau` (unsequestered, runs `specs` in a fixture): (a) an untracked nested repository under the fixture's `pickman/src` makes `specs digest` print nothing, and `specs run` prints `reuse off:` and runs every selected spec; (b) a tracked file replaced by a folder holding one file gives a digest different from both the original and the plain deletion. Align the lesson's "How to apply" with the code.
Lesson: zz-arch/digests-hash-paths-as-git-stores-them
