### F1 [medium] A node name with a `/` aliases an instance path: the server library put in a root Folder named `ServerStorage/Arcade` passes the net, the reader and the default-place line
Where: z-nile/tests/lib/home.luau:96 (`collect` joins Rojo's names with `/`), :313-314 (the node test on that string), :216-217 and :350 (the reader's node and default-place tests on graph's `/`-joined instance, graph.luau `walkMappings`)
Evidence: a fixture home `pong` (scratchpad copy of this branch's `home.luau` and `graph.luau`, run with `./zn run --time 60 -- lune run probe.luau`) whose `default.project.json` maps `ReplicatedStorage.Arcade` correctly and puts `"ServerStorage/Arcade": { "$className": "Folder", "$path": "../arcade/src/server" }` as a child of the DataModel tree. Real Rojo 7.7.1 builds it (`rojo build` exits 0; the rbxlx holds a Folder named `ServerStorage/Arcade` under the DataModel) and `rojo sourcemap --include-non-scripts` prints `{"name":"ServerStorage/Arcade","className":"Folder","children":[{"name":"Secret",...,"filePaths":["../arcade/src/server/Secret.luau"]}]}`. `home.problems` returns 17 lines, all `missing <scaffold file>`: no `makes Rojo put`, no `maps the library's`, and no `default.project.json does not map ServerStorage.Arcade to arcade/src/server`. The place it accepts has no `ServerStorage.Arcade` at all; the library's server code sits in a non-service Folder at the DataModel root.
Critique: c0246's net is the user's chosen mechanism (2026-11-08, "3") for closing the reader-vs-Rojo class "by construction", and its library test is "by Rojo's instance path". But it encodes that path as one `/`-joined string, and an instance name may itself contain `/`, so two different places print the same string. This is the same kind of hole the issue was opened for (a spelling the format allows that the reader reads as something else), now in the new net as well as in c0185's reader. The fix the author will be tempted to make is to compare `r.instance` more carefully in the net only (e.g. check the first segment is a service); that leaves the reader's `maps the library's` line and the default-place line fooled by the same key.
Consequences: the cheapest closure is a rule, not a better comparison: no node of what Rojo builds may have a `/` in its name. That needs (1) a line in the net for any sourcemap node whose `name` contains `/`, once per project file (the reader's tests then cannot be fooled either, because the home fails before anything trusts the joined string); (2) the real tree holds none (`homes.spec` "the rule holds on the real tree" must stay green; `git ls-files '*.project.json' | grep -v '\.tracker' | xargs grep -nE '"[^"]*/[^"]*"[[:space:]]*:'` finds no key with a `/` today); (3) a decision on wording; and (4) the Rules and mutants table gains a row. A file name cannot hold a `/`, so only a project-file key (top level, nested, or `syncRules`-loaded) produces one, and Rojo's own sourcemap sees all three.
Recommendation: in `rojoReads`'s `collect` (or beside it), record every node whose `name` contains `/` and report `<file> makes Rojo build a node named <name>, whose / makes its instance path ambiguous`, once per project file. Add a case to `z-nile/tests/tooling/home-rojo-failclosed.spec.luau` (non-sequestered; `paths.spec` cannot be edited): the fixture above gives exactly one such line, and the same home with the key spelled as `ServerStorage` > `Arcade` gives none. Run the mutant (the check dropped) and record it killed in the Rules and mutants table.
