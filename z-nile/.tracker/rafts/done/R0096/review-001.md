### F1 [low] A guesses-only approval resealed across a rewrite reads as a stale "contract" once the added guess is gone, where it read "holds" before the rewrite
Where: z-nile/engine/approval.luau `approval.reseal` (the `standing == "guesses"` branch and its comment, "names only guesses, as before"); d0298.md Design §1, `approval.reseal`.
Evidence: probe on 53852d579 (scratch clone): an approval of {design D0, check.sh} with no guesses part, then a guesses.md added (standing `guesses`). Before any rewrite, removing that guesses.md again gives `approval.standing` = `holds`. After a rewrite D0 -> D1 and `reseal(text, parts(D1, check, G), "guesses")`, removing the guesses.md gives `stale`, and `contract.changed` = `{"contract"}`: the row keeps the old `hash` (of D0) while every part hash now matches, so the whole-hash shortcut fails and no part explains it. Every other reader agrees before and after the rewrite (question (b) below): the divergence is only this state.
Critique: the comment and Design §1 say the row answers "exactly as before the rewrite"; that holds for every state f0399 allows (guesses only ever added: `f0399.guessesKept` refuses a removed or changed guess at `approve`, `finish` and `done`), but not for a guess removed afterwards, which a non-dispatched `ready` would now refuse as "contract changed since approval: contract" where it took the raft before. The tempting fix, recomputing the hash exactly when the row recorded no guesses part (the approved contract is then the new parts minus guesses), would break carry.spec's sequestered `row.hash == before610.hash` assertion for c0610.
Consequences: an exact hash for the no-guesses-part case changes a sequestered AC1 assertion, so it is the human's call; keeping the old hash leaves one documented state where the answer differs, which the guesses-only-added rule already refuses elsewhere.
Recommendation: keep the behaviour (it fails closed, and the state is one f0399 forbids), and correct the comment in `approval.reseal` to say where the answer differs: "the same answer as before for every state f0399 allows; if the guess added since approval is later removed, the row reads `contract` (stale) instead of `holds`, and `./zn approve` records a new row". If the author wants the exact hash for a row with no guesses part, escalate (it changes carry.spec's c0610 assertion).
