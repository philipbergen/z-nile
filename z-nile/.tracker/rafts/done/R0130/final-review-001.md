### F2 [low] The raft's top layer is chosen by two copies of one rule: `approveplace`'s private `topLayer` and `layergit.layersOf`, which the design says are the same layer
Where: z-nile/engine/approveplace.luau:348-369 (`topLayer`, used by `load` to judge an active issue) and z-nile/engine/main.luau:6257 and 6477 (`layergit.layersOf(raftId)`'s last, used to refuse and to push); c0369.md:91 ("`<top>` is `layergit.layersOf(<R>)`'s last, the layer `load` judged")
Evidence: `topLayer` runs the same `for-each-ref` over `refs/heads` and `refs/remotes/origin` and keeps the highest `stack.parse` position. That is today's `layergit.layersOf` logic, copied. The two agree now, because the refs are shared across worktrees, so `load` (cwd the raft worktree) and the placed run (the same cwd) see the same list. `approveplace` could call `layergit.layersOf` directly: layergit requires only fs, process, sh, stack, stdio and store, so there is no cycle.
Critique: design review 004 F1 was the bug this split invites: the layer `load` judged and the layer `count` pushed came apart. The design closed it by naming one function. The code keeps two. A later change to `layersOf` (for example, ignoring origin-only layers of a landed raft) would make `load` judge one layer while `cmd.approve` refuses or pushes another, and no spec here would notice, because every fixture makes them agree. The tempting fix is to leave it because it is identical today.
Consequences: calling `layergit.layersOf` from `approveplace` adds a require edge from approveplace to layergit, which is acyclic. `layersOf` runs git in the process's cwd, not in `path`. That is equivalent for refs, which every worktree of one repository shares, but the code should say so in a comment. The local-or-origin ref choice (`topRef`) stays in `load`.
Recommendation: replace `topLayer`'s selection with `layergit.layersOf(raft)`'s last element and keep only the local-or-origin ref choice in `approveplace`. Run approve-raft.spec and place.spec, which pin the active-issue placement. No new case is needed, since behaviour is unchanged. If the layer is not reopened, harvest it as a note for the next change to either function.
