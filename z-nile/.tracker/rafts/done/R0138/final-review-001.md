### F1 [medium] A kick that is refused, or that cannot start its shell, prints no "no pass since" line, though the Design says every path does and the captured outcome has no exception
Where: z-nile/engine/watchcmd.luau:1203 to 1206 (the dispatched-step refusal), 1210 to 1213 (the CPU refusal) and 1242 to 1245 (`started.ok` false): each returns false before line 1285, the only place the kick prints the line. d0383.md:64, "On every path it then prints §5's line on stdout when there is one"; d0383.md:35, the third captured outcome; d0383.md:92 (section 7's bullet on the two refusals says nothing about the line).
Evidence: with origin/main holding a source commit more than 24 hours past the last pass commit, `ZN_DISPATCH=1 ./zn watch-kick` prints the refusal on stderr, exits 1 and prints nothing on stdout; so does a kick under `./zn run --time 60`. The `exited`, `gone` and backstop paths do reach line 1285 and print it. The refusals were added by guesses G15 and G17 in review rounds 3 and 4; neither guess, refute nor section 7 says the stale line is dropped on them, and no case kicks a refused kick over a stale history (the acceptance case at watch-net-stale.spec.luau:157 kicks a kick that starts).
Critique: the third outcome reads "When origin/main has a commit more than 24 hours newer than the last pass commit, `./zn watch-kick` prints on its stdout a line", with no condition on whether a net starts, and the line exists for the case where the net is not running. A refused kick is one more kick after which nobody learns how old the last pass is. The harm is small in practice (the refusal itself exits 1 with a reason), which is why this is medium and not high. The tempting fix is one sentence in section 7 saying a refused kick prints no line: that writes an exception into a captured outcome, which a guess cannot do.
Consequences: printing the line on the refusal paths means a read of git (two `git log` calls) before the refusal returns. That keeps "before any file is made" true, since `watchcmd.noPassLine` only reads. It needs the main checkout or the kicker's folder as its `dir`: use the same `root` the other paths use, read before the refusals, and a kick outside a repository must still fail with its one line. A step's `./zn land` then shows the stale line in each dispatched step's output when main is stale; that is true and is what the outcome asks. The order on screen is the refusal on stderr, then the line on stdout, as on the other failing paths.
Recommendation: give the three early returns the same tail as the other paths: one local function that prints `watchcmd.noPassLine(root)` when there is one, called before each `return false` and at line 1285. Add one case to a regular spec (watch-net-quick, beside "a kick made inside a dispatched step starts no net and makes no folder"): a fixture whose origin/main has a pass commit and a source commit 24 h plus a minute later, kicked with `ZN_DISPATCH=1`; it expects exit 1, the refusal on stderr, the no-pass line on stdout and still no `.cache/watch-net` folder; its mutant is the early return without the tail. Add the sentence to section 7's refusal bullet. If the author would rather not print it there, escalate to the user: the options are (a) print it on every path, as captured, at the cost above, or (b) a `Scope decision` line that a refused kick prints only its refusal.

## What was asked beyond the checklist

(2) "returns only after the net ... created or reused its worktree or exited; if the net exited first, its error line on stderr and non-zero": delivered, and wider than captured in the right direction (a killed shell and a silent net are failures too; G11 withdrew G1's exit 0, so nothing here returns true on a guess). (3) the no-pass line on the kick's stdout and the board: delivered on every path that starts a shell, not on the three early returns (F1). (4) one named constant read by both: delivered (`watchcmd.NO_PASS_LIMIT_SECONDS`, the board through `watchcmd.noPassLine`).

The user's scope decision, "Only source commits count": implemented as quoted. `watch.newestSource` takes the newest commit after the pass with a path for which `trackerstate.under` is false, by committer time; `watch.noPassLine` fires only above the limit; no pass commit means no line (G2). A net's own repair commit changes watch files, which are not tracker state, so it counts as a source commit; that is within the quoted rule.

Do the two refusals narrow "any worktree"? No. Both are about the kicker's process, not the folder it stands in: one reads two environment variables, the other the hard CPU limit, and a kick with the same environment and limit behaves the same from every worktree. I checked the claim G15 rests on: `./zn` itself lowers its engine's limit to 1800 s, above the 1200 s floor, and the net's own `./zn run --time 3600` keeps that, so a worker's kick, `./zn land`, the dispatcher's kick after its merge and the net's own hand-off kick are never refused; only a kick someone wraps in `./zn run --time` below 1200 with no `--cpu` is, and the refusal says what to do. G17's claim (a step lands tracker state only, the dispatcher's own kick has neither variable) was checked in review 005 and I did not repeat it. What the refusals do touch is the plain sentence "a kick ... starts a net": they are two exceptions to it, decided in the build as guesses. They do not need the user's ruling before this lands, because each replaces a net that would have reported a false red or failed at its push with an honest exit 1, which is the captured Problem's own point; they do need to reach the user as guesses (`./zn guesses`, G15 and G17), described as "two kicks that now start no net", and not be folded into "detail". The one thing in them that does need either a fix or a ruling is F1.

The other guesses. G11 (the kick fails at its backstop) widens outcome 2, as design review F5 asked. G14 (`--limit`) adds a flag that can only lower the net's time (`watch.netLimit` clamps it); it is in the usage text, so a person can shorten a real net, never lengthen it. G10 (a 34 s spec in the fast tier) took 35 s alone here; it narrows nothing.

What the net runs and repairs is untouched: `runOnce` (watchcmd.luau:937 to 979) is the old `net` body line for line, with the main checkout passed in and the marker written; `sincePassed`, `applyRepairs`, `recordPass`, `runSlow` and `pushMain` are not in the diff.
