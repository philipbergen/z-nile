### F1 [high] A raft's own tracker documents select about 60 harness specs, so every game raft's gate still runs most of the harness suite
Where: c0083 `suites.textAffected` (rule: "A changed path, or a folder above it, that equals a token selects the spec"; "Folder references are deliberately coarse"); `HARNESS` (only `tracker/templates/` under `tracker/`); Scalability ("`src/shared/Logic/Game/init.luau` selects 72 specs"); Usability and "Nowhere" ("No step runs both suites unless the change touches both"); AC2's game-change and mixed cases
Evidence: every raft branch commits tracker documents: `tracker.sh commit` writes `spend.md`, the reviews write `review-NNN.md`, the issue doc gets its Verification log, and `done` moves the item folders. `changed.files` takes the whole merge-base diff, so RC0, the Phase 3/4/5/6 gates, the Stop hook's gate and `done`'s gate on the moved tree all select over those paths too. On the prototype:
- `lune run scripts/affected -- src/shared/Logic/Game/init.luau` gives 72 specs.
- The same path plus `tracker/rafts/active/R0099/spend.md` and `tracker/issues/active/f0099/f0099.md` gives 132 specs. 70 of them are in the 145-spec harness suite, including the three slowest specs (c0072 `land` 26.6 s, c0067 `ready` 23.6 s, c0084 `spend-command` 22.9 s).
- Running just those 70 harness specs took 58 s (544 cases). E5 puts the whole harness suite at 65 s. The Game-init selection alone ran in 15 s.
- A capture or prep edit to one issue doc (`tracker/issues/c0099/c0099.md`) selects 60 specs.

The hits are noise. c0072's land spec names `"tracker"` in a fixture (`git(wt, { "add", "tracker" })`) and `` `{wt}/tracker/issues/…` ``, whose literal piece normalizes to `tracker/issues`. Others pick up the word `tracker` from a spec title. None of those specs read the real file that changed. AC2 can't see this: its game cases pass `src/` paths only, never the documents a real raft branch carries.
Critique: the user's decision (game work does not run the harness suite) and the design's own numbers (72 specs, fewer than the game suite) hold for a lone `src/` path, which no real gate ever sees. In practice a game raft pays 58 of the 65 s the raft exists to save. Prep sessions, which never gated before, now run a 60-spec gate on every stop. The author will be tempted to call tracker documents harness changes. The design already decided otherwise: `HARNESS` lists only `tracker/templates/`. Changing that call is the user's decision, not a fix.
Consequences: this is the third round to find a hole in text selection (review-003 F1: the inside-folder rule was untested), so the fix should change the mechanism, not add one more case:
- A rule that drops one-segment tokens (`tracker`, `src`) still leaves the fixture piece `tracker/issues`.
- Excluding `tracker/` from text selection outright drops real readers: `repo-fence` walks `files("tracker", …)` for every `check.sh`, `tests/acceptance/c0063` and `c0103` read done `check.sh` files, f0054 reads `tracker/game-design.md`, and c0082's `real-tree` audits the whole tree (F2).
- Item documents are the one kind of path every branch changes, so that is where the rule belongs.
Recommendation: make text selection treat a path inside a tracker item folder (`tracker/issues/[active/|done/]<id>/…`, `tracker/rafts/[active/|done/]<R>/…`) differently, and leave `check.sh` and `acceptance/**` as they are:
- **The other files in an item folder** (`*.md`, `spend.md`, `review-*`, `experiments/`) select only a spec that names that exact path or a folder at or below the item folder, plus the named real-tree readers from F2. Never a token above the item folder.
- **`check.sh` and `acceptance/**`** keep today's rule, so `repo-fence` still runs for them.
- **Spec cases:**
  - `select` of the Game init plus `tracker/rafts/active/R0099/spend.md` and `tracker/issues/active/f0099/f0099.md` is not `ALL`. It contains every graph hit of the Game init and none of `tests/acceptance/c0072/land.spec.luau`, `tests/acceptance/c0084/spend-command.spec.luau` and `tests/acceptance/c0067/ready.spec.luau`. Its harness-only specs are exactly the Game init's own text hits plus the real-tree readers.
  - `tracker/issues/active/c0099/check.sh` still selects `tests/tooling/repo-fence.spec.luau`.
  - `tracker/game-design.md` still selects f0054's docs spec.
- **Rows and record:** add a Rules row with the mutant "item documents match tokens above the item folder". Update E2's `tracker/issues/done/c0008/check.sh` row: it is a `check.sh`, so it keeps today's rule; add a row for a document. Re-measure Scalability on a raft-shaped change list, not a lone path.

### F2 [medium] The one spec that audits the real tracker tree is selected for tracker changes only because its title contains the word "tracker"
Where: c0083 `textAffected` ("split at spaces"; this "catches every spec that reads a file as text, runs it, or walks a folder"); `tests/acceptance/c0082/real-tree.spec.luau`; `done`'s gate on the moved tree, now `--affected`
Evidence: `real-tree.spec.luau` runs `audit.run(root)` over the real `tracker/` (duplicate ids, folders without their document, lost counter files). Its source names no tracker path. Its only `tracker` token is the prose word in `t.spec("c0880 the real tracker tree passes the audit", …)`. In the prototype copy, `--deps tracker/rafts/active/R0099/spend.md` lists it. After changing the title to "the real tree passes the audit", that count goes from 1 to 0. Until now this spec ran on every raft through `--full` (RC0 and `done`'s done-tree gate). After this raft, a `done` move that leaves a duplicate id, or a branch that loses a counter file, is caught only while a title word happens to match. A miss surfaces only in CI, after `done`.
Critique: the design's claim that text selection catches every spec that walks a folder doesn't hold for a spec that walks the tree through a library call. The author will be tempted to add the literal `"tracker"` to that spec. That is a promoted spec, so the edit would need an override, and it relies on the same noise F1 removes.
Consequences: whatever F1 does to tracker item documents, this reader has to stay selected for them. A list of real-tree readers needs an owner: a new spec that audits the real tree would have to join it.
Recommendation: add a named reader rule to `scripts/lib/suites.luau`. Any spec whose closure contains `scripts/tracker/audit.luau` and that runs on the real root, or simply an explicit `TRACKER_TREE_READERS` list holding `tests/acceptance/c0082/real-tree.spec.luau`, is selected by any change under `tracker/issues/` or `tracker/rafts/`. State the rule under Patterns. Add the case "`select` of `tracker/issues/active/f0099/f0099.md` contains `tests/acceptance/c0082/real-tree.spec.luau`", with the row's mutant "real-tree selected only by text". The case must still pass if that spec's title changes, so it should assert on the rule (for example, run on a synthetic graph whose reader spec has no `tracker` token), not on today's title.
