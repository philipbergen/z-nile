### F1 [high] Nothing tests that `load` reads `active/`, so AC4 passes with an implementation that skips it, and AC8's coverage check then passes without checking anything
Where: c0111.md Design, Module, **load** (line 115); Rules and mutants (no `load` row); lessons-cli.spec.luau SEED; c0111 check.sh AC8
Evidence: I changed the prototype's `{ "", "/active", "/done" }` to `{ "", "/done" }`, and lessons-cli.spec still passes (10 passed, 0 failed). The fixture seeds items in the backlog (`tracker/rafts/R0010`, `R0030`) and in `done/` (`c0020`), but nothing under `active/`. During execution R0040 sits in `tracker/rafts/active/R0040`, which is exactly where AC8 runs (`done` runs check.sh before it moves anything). With that mutant, `lessons --uncovered R0040` prints `R0040: no reviews` and exits 0, which the Design itself says "is not an error". So "R0040's own reviews are fully harvested" passes with no harvest at all. `--check` only catches this if some harvested lesson has no `from`. The executor's own harvest step (execute-raft Phase 5) would also read "covered" for every active raft. None of `load`'s other rules has a row either: the item-id pattern, the exclusion of `stream-review-*` and of subfolders, the "not a lesson file" problem, and treating a missing folder as empty. The CLI spec happens to cover some of these, but no row records it.
Critique: The obvious fix is to add an `active/` item to the CLI fixture. On its own that leaves the "no reviews" escape hatch open for any future id that `load` fails to find.
Consequences: Treating a missing id as an error would break the approve-only case the Design protects (`R0030`). The real distinction is between an item that has review files and an item that `load` never found, and the CLI can tell them apart only if `load` reports which folders it saw.
Recommendation: Add a `load` row (or several) to the Rules and mutants table: reads `active/`; skips `stream-review-*` and subfolders; reports a non-`.md` file in `lessons/`; treats a missing folder as empty. In lessons-cli.spec, seed `tracker/rafts/active/R0050/design-review-001.md` with an uncovered F1, and assert `--uncovered R0050` exits 1 and lists it. Also make `--uncovered <id>` tell "not a reviewed item" apart from "no such item": `<id>: no reviews` only when `find` locates the item, and exit 2 with `<id>: no such item` otherwise. Add a spec case for each, plus a row.

### F4 [medium] Harvesting only after the final round leaves R0040's AC8 red during code-review rounds 2 and later, and c0112's coverage gate will turn the whole gate red the same way
Where: c0111.md The skills, execute-raft (line 149) and ticket-prep 5.5 (line 148); c0111 check.sh AC8; review skill Code mode item 1

### F5 [high] The skills' new "record a lesson when you finish" sends agents to write where no change can land: the main checkout, a capture, and the reviewer's write-only run
Where: c0111.md The skills (line 145: "Every … SKILL.md … says where its new lessons go"); prototype text: "When you finish, if the user corrected you …, record it as a lesson in `.claude/skills/<s>/lessons/<slug>.md`"
Evidence:
- `ready-raft`, `stop-raft` and `launch-raft` run in the main checkout. AGENTS.md: "the main checkout is never edited". Following their new Lessons section breaks a non-negotiable rule.
- `make-issue` runs in a capture worktree, which lands only through `tracker.sh land`, and `land` refuses anything but draft backlog issue documents (tracker skill, Landing a change step 2; `captureScope` in main.luau). Its lesson file can never land.
- `review` is told "Write only review-NNN.md … don't leave other files in the tree" (review skill, Visible record). The new section tells the same agent to write a lesson file when it finishes.
- `metrics` is read-only.
- AGENTS.md also requires "no code without a tracker issue". A skill or doc change "is still tracked work: it has an issue" (tracker skill, Worktrees).
Critique: One instruction is written into eleven skills, and only the prep and raft worktrees can carry its output. The tempting fix is to say "in a worktree", which needs an issue and a PR for every one-line lesson.

### F6 [medium] harvest.spec asserts message wording the Design never specifies, so a correct implementation can fail a sequestered spec
Where: harvest.spec.luau "check names broken references…" (`t.expect(has(p, "testing/pin")).toBe(false)`); lessons-cli.spec.luau (`--check` and `--uncovered` output read from stdout); c0111.md Design, **check**, The command
Evidence: The broken ledger has `- design-review-002 F1: testing/pin` and `- design-review-001 F7: testing/pin`. A natural problem text quotes the entry, for example `R0010/harvest.md: design-review-002 F1 (testing/pin): no such review`. ### F7 [low] `findings` doesn't read headings "the way `tracker.sh done` reads them"

Evidence: `done` treats `### F1: claim` and `### F1x` as F1. `findings` rejects both, because it requires a space, `[` or the end of the line. Recommendation: Drop "the way `tracker.sh done` reads them" and state the stricter rule, or have `findings` accept `:` as well and add that to the harvest.spec case. Say which in the Design.
