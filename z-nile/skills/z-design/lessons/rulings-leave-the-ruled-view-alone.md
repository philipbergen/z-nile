---
title: A ruling written into a judged text must not move what it rules on
when: design
tags: [rulings, hashes, review]
check: When a human's ruling is recorded into a text the rule hashes or judges (a Decided line in the ask, a note in the document), does the identity it rules on still match after the ruling lands, and does a case run the real ruling command rather than hand the pure rule the identity it would have had? And when an edge adds a refusal in front of a pure state the rulings lift (a quote check, a read problem), does every ruling lift that refusal too?
---
c0262's state counted an `approve` ruling as on course on the reviewed view, and its pure case passed. The real `./zn resolve approve` writes a Decided line into the ticket's Problem, which the view's `ask.md` and so its id hash: the approve changed the view it approved, and the ticket was reviewed again (design review 002 F1 of c0262's re-prep for R0093). The real route also moved the ticket's folder on main, which the reader then missed.

Apply it: list what each recording command writes, and where, before the rule that reads the ruling back; leave the recorder's own lines out of the identity (or record the identity at the ruling); and pin it with one fixture that runs the real block and resolve.

Round 3 of the same prep found the second half: the edge's new quote check returned `invalid` before the rulings were read, so the human's retry could not lift it; the edge now hands the pure state a per-review problem, which the rulings lift like any other.
